# Hifadhidata na Taarifa za Siri kwenye Hosts za Linux

{{#include ../../banners/hacktricks-training.md}}

Sifa za kuingia za hifadhidata na programu mara nyingi huhifadhiwa karibu na huduma zinazozitumia. Chunguza mchakato, socket au port ya ndani, usanidi na faili ya sifa za kuingia kabla ya kujaribu kubaini ikiwa akaunti inaweza kusoma data au kutekeleza operesheni yenye upendeleo.

## Tafuta huduma za data za ndani na sifa za kuingia

```bash
ss -lntup
ss -lnx
ps -eo user,pid,args | grep -E '[m]ysqld|[m]ariadbd|[p]ostgres|[r]edis-server|[m]ongod'
find /etc /opt /var/www /home -type f \( -name '*.env' -o -name '*config*' -o -name '.my.cnf' -o -name '.pgpass' \) -ls 2>/dev/null | head -100
```

Kagua application configs zinazosomeka, deployment files, service environment files na backups ili kutafuta connection strings au keys. Unix socket ya mchakato wa DB inaweza kuwa na sheria tofauti za ufikiaji na TCP listener yake. Ruhusa za database hutofautiana na ruhusa za OS: nenosiri la DB lililopatikana huruhusu tu roles zilizokabidhiwa akaunti hiyo ya DB, isipokuwa njia nyingine ithibitishwe. Katika PostgreSQL, sera za row-level security zinaweza kuficha rekodi kwa role moja, huku role yenye haki za kusimamia sera ikiweza kubadilisha mwonekano huo; tofautisha ufikiaji wa data na usimamizi wa sera. Tumia miongozo mahususi ya huduma kwa [MySQL/MariaDB](../../network-services-pentesting/pentesting-mysql.md), [PostgreSQL](../../network-services-pentesting/pentesting-postgresql.md), na [Redis](../../network-services-pentesting/6379-pentesting-redis.md).

Automation script inayosomeka katika home ya akaunti nyingine inaweza kuwa na credential iliyopachikwa, hata kama jina la faili halitaji passwords. Kwa mfano, Python script inaweza kuzindua `su` na kuingiza maandishi halisi kwenye kidokezo cha nenosiri kupitia [`pexpect.sendline`](https://pexpect.readthedocs.io/en/latest/api/pexpect.html); [`su`](https://man7.org/linux/man-pages/man1/su.1.html) bado hutekeleza sera yake ya uthibitishaji. Thibitisha kuwa user wa sasa anaweza kupita kwenye directory na kusoma script husika, kuwa maandishi hayo ni nenosiri la akaunti lengwa, na kuwa credential hiyo bado inafanya kazi kabla ya kuichukulia kama njia ya kubadilisha akaunti. Script haihitaji kufanya kazi kwa mafanikio ili maandishi yake yafichue secret. Matokeo ya uchunguzi tulivu yanapaswa kuonyesha path na ruhusa bila kuchapisha thamani au kujaribu kuingia.

SQLite application database inayosomeka inaweza kuwa na majina ya watumiaji na password hashes bila huduma yoyote ya database inayosikiliza. Kagua schema na ruhusa za faili kabla ya kuchukulia hash kama mwongozo wa ukaguzi wa offline. Nenosiri la application lililopatikana huruhusu ufikiaji wa akaunti ya OS au local-admin-panel tu ikiwa matumizi yake tena yamethibitishwa kivyake; muundo wa hash au jina la mtumiaji linalolingana si uthibitisho wa matumizi tena.

Apache OFBiz inaweza kutumia embedded Derby database chini ya `runtime/data/derby/<database>/`. Faili ya Derby ya `service.properties` huashiria directory ya database; directory ya jirani ya `seg0` huwa na mafaili ya jedwali. Kagua ruhusa za directory nzima ya database kabla ya kuchunguza rekodi za application kama `USER_LOGIN`. Marker inayosomeka haithibitishi kuwa majedwali yanasomeka, kuwa nenosiri linaweza kupatikana, au kuwa credential ya application inafanya kazi kwa akaunti ya Unix. Usijumuishe yaliyomo kwenye database na password hashes kwenye matokeo ya kawaida ya enumeration. Tazama [hati za Derby kuhusu directory ya database](https://db.apache.org/derby/docs/10.4/devguide/cdevdvlp40724.html) na [OFBiz login API](https://nightlies.apache.org/ofbiz/stable/javadoc/org/apache/ofbiz/common/login/LoginServices.html).

TeamCity huhifadhi data ya server yake kwenye data directory inayoweza kusanidiwa (mara nyingi `.BuildServer`). Kagua ruhusa za `config/projects/<project>/pluginData/ssh_keys`, `config/database.properties`, `system/buildserver.*` wakati embedded HSQLDB inatumika, na `backup/TeamCity_Backup_*.zip`. SSH keys zilizopakiwa na mipangilio mingine salama zinaweza kusimbwa kwa njia fiche, kwa hivyo path inayosomeka pekee haithibitishi kuwa private key inaweza kutumika. Database au backup inaweza kuwa na watumiaji wa application na password hashes; kuzitumia kwa akaunti ya Unix kunahitaji ushahidi tofauti wa matumizi tena kwa nenosiri. Wakati wa enumeration, rekodi paths na haki za ufikiaji badala ya kuchapisha keys, hashes au safu za database. Tazama hati za TeamCity kuhusu [data-directory](https://www.jetbrains.com/help/teamcity/teamcity-data-directory.html), [SSH-key](https://www.jetbrains.com/help/teamcity/ssh-keys-management.html), na [backup](https://www.jetbrains.com/help/teamcity/manual-backup-and-restore.html).

Duplicati backup server huhifadhi usanidi kwenye `Duplicati-server.sqlite`. Data directory yake inaweza kuwa chini ya home ya service account, `/var/lib/Duplicati`, au container volume, na `--server-datafolder` au `DUPLICATI_HOME` zinaweza kuibadilisha. Database inayosomeka ni mwongozo muhimu kwa sababu inaweza kuwa na connection credentials na server signing material, lakini usakinishaji mpya zaidi unaweza kusimba sehemu nyeti kwa njia fiche na kuzuia ufikiaji wa directory. Linganisha ruhusa zake na akaunti halisi ya server pamoja na ufikiaji wowote wa UI au ServerUtil ulioidhinishwa. Ikiwa server hiyo inaendeshwa kama root huku host `/` ikiwa imeunganishwa ndani ya container yake, kurejesha backup na kutumia job hooks kwa njia iliyoidhinishwa kunaweza kuvuka mpaka wa filesystem ya host; listener ya loopback au jina la faili la database pekee halithibitishi udhibiti. Tabia ya kuingia ya matoleo ya zamani inayotumia nonce haipaswi kudhaniwa kwa matoleo ya sasa, ambayo hutumia [muundo tofauti wa authentication](https://docs.duplicati.com/technical-details/server-authentication-model). Tazama hati za Duplicati kuhusu [server database](https://docs.duplicati.com/database-and-storage/the-server-database) na [ServerUtil](https://docs.duplicati.com/duplicati-programs/command-line-interface-cli-1/serverutil) kwa maelezo mahususi ya toleo.

Kwa PostgreSQL, kagua `pg_policies` na `pg_class.relrowsecurity` ili kutofautisha query iliyochujwa na rekodi zinazokosekana. Kubadilisha au kuzima sera kunahitaji umiliki unaofaa wa jedwali au haki za kiutawala. Akaunti ya matengenezo iliyovuja kivyake inaweza kuwa na haki hizo hata kama akaunti ya application haina. Redis listener isiyohitaji uthibitishaji ni ugunduzi tofauti: thibitisha kama inafungamana na loopback pekee na kama protected mode au ACLs zinazuia muunganisho wa sasa kabla ya kuichukulia kama chanzo cha secret.

## Kagua hifadhi za key na tokenisitiri

```bash
find /home /root -maxdepth 4 -type f \( -name 'id_*' -o -name '*.ppk' -o -name '*.p12' -o -name '*.pfx' -o -name '*.kdb' -o -name '*.kdbx' -o -name '*.gpg' -o -name '.git-credentials' \) -ls 2>/dev/null
find /home /root -maxdepth 4 -type d -name '.gnupg' -ls 2>/dev/null
printenv SSH_AUTH_SOCK KRB5CCNAME GNUPGHOME 2>/dev/null
```

Private key ya SSH, agent socket, Kerberos cache, GPG keyring, au PKCS#12 bundle ina manufaa tu ikiwa mtumiaji wa sasa anaweza kuifikia na passphrase au policy yoyote inayohitajika inaruhusu matumizi yake. Kagua umiliki na ruhusa kwanza. Kurasa za [users and sessions](../user-information/user-and-session-triage.md), [Linux AD](../user-information/linux-active-directory.md), na [post-exploitation](../post-exploitation/README.md) zinaeleza njia zinazohusika za kufikia vitu hivyo. Historia ya Git, backups za zamani, na historia ya shell pia zinaweza kuhifadhi secrets hata baada ya config ya sasa kusafishwa. `.git` directory inayosomeka inaweza kuhifadhi source iliyofutwa na credentials zilizowekwa kwenye commits za awali hata kama working tree haina kitu; kagua ufikiaji na historia mwenyewe badala ya kumwaga maudhui yake wakati wa automated enumeration.

Picha ya boot inayosomeka ndani ya `/boot` ni njia nyingine ya kupata archive. [Initramfs boot scripts and copied helpers](https://manpages.debian.org/testing/initramfs-tools-core/initramfs-tools.7.en.html) zinaweza kuwa na custom logic inayotoa key kwa [`cryptsetup --key-file=-`](https://manpages.debian.org/testing/cryptsetup-bin/cryptsetup.8.en.html). Kagua ruhusa za ufikiaji wa picha hiyo na upitie tu boot script na helper inayohusika katika nakala ya offline iliyoidhinishwa. Passphrase ya kufungua disk iliyopachikwa au iliyotokana na nyingine si moja kwa moja nenosiri la akaunti ya Unix: thibitisha inputs za helper, boot path halisi, na matumizi tena ya credential tofauti kabla ya kuchukulia kuwa ni njia ya kuingia kwenye akaunti. Enumeration ya kawaida haipaswi kufungua picha hiyo, kuendesha helpers zake, au kuchapisha keys zinazoweza kutumika.

Vault CLI [kwa kawaida huhifadhi token yake ya uthibitishaji kwenye `~/.vault-token`](https://developer.hashicorp.com/vault/docs/commands/token-helper), ingawa custom token helper inaweza kuihifadhi mahali pengine. Path inayosomeka ni dalili tu ya credential: thibitisha uhalali wa token na policy kabla ya kudhani kuwa inaweza kufikia secret engine yoyote. Kwa [Vault SSH one-time passwords](https://developer.hashicorp.com/vault/docs/secrets/ssh/one-time-ssh-passwords), token lazima iwe na ruhusa ya kutoa credentials kwa role ambayo user na CIDR yake vinajumuisha akaunti na host inayolengwa; host hiyo pia lazima iwe imesanidiwa SSH verification helper na ikubali login. Role inayotaja `root` au token file pekee haithibitishi ufikiaji wa root. Passive enumeration inapaswa kuripoti file path bila kusoma token au kuomba OTP.

[KeePass 1.x hutumia `.kdb`, huku KeePass 2.x ikitumia `.kdbx`](https://keepass.info/help/v2/version.html). Chukulia jina la file linalolingana kuwa huenda ni vault iliyosimbwa kwa njia fiche, kwa kuwa bidhaa nyingine zinaweza kutumia kiambishi tamati cha `.kdb`. Vault inayosomeka haionyeshi entries zake bila master password au key file inayohitajika; SSH key iliyohifadhiwa kama attachment ni dalili tofauti ambayo ufikiaji wa host yake lazima uthibitishwe. [KeePass hukubali files za aina yoyote, zikiwemo picha, kama key files](https://keepass.info/help/base/keys.html), lakini file iliyo karibu nayo ni mgombea tu hadi jukumu lake, vipengele vyote vinavyohitajika vya master key, na login yoyote ya akaunti yenye ruhusa za juu zaidi vithibitishwe kivyake.

Support archive inaweza kuwa na KeePass vault pamoja na process memory dump. Kwa [KeePass 2.x kabla ya 2.54, CVE-2023-32784](https://nvd.nist.gov/vuln/detail/CVE-2023-32784) inaweza kufanya master password iweze kurejeshwa kutoka kwenye dump inayohusika; vault iliyosimbwa kwa njia fiche au dump isiyohusiana haitoshi pekee yake. Kagua entries za archive na ruhusa za ufikiaji mwenyewe bila kutoa files zote kwa wingi au kuchapisha secrets wakati wa enumeration ya kawaida. PuTTY private keys zinaweza kupatikana kama files za `.ppk` au kama maandishi ya `PuTTY-User-Key-File` ndani ya vault entry; thibitisha kivyake akaunti iliyokusudiwa kwa key, usimbaji wake, na host inayokubali key hiyo.

HTTP archive ya `.har` inayosomeka inaweza kuhifadhi maombi na majibu ya browser, yakiwemo authentication headers, cookies, na form fields. Huenda imehifadhiwa moja kwa moja au ndani ya support attachment. Kagua umiliki na ufikiaji kwanza, kisha chunguza entries zinazohusika tu; jina la file pekee halithibitishi kuwa lina credential inayoweza kutumika tena. Automated enumeration inapaswa kuorodhesha path ya archive bila kuchapisha thamani zilizorekodiwa. [Nyaraka za Microsoft Edge](https://learn.microsoft.com/en-us/microsoft-edge/devtools/network/reference#save-all-network-requests-to-a-har-file) zinaeleza chaguo la kusafirisha data nyeti.

Kwa database backups zilizosimbwa kwa njia fiche, linganisha archive inayosomeka, private-key material inayopatikana, na hitaji lolote la passphrase kabla ya kufikia hitimisho. Pale ambapo imeidhinishwa, kurejesha passphrase ya key iliyolindwa na kukagua data ya backup iliyofunguliwa ni hatua mbili tofauti za mwongozo. Credential ya database `root` si credential ya Unix `root`; matumizi tena ya password kati ya akaunti hizo yanahitaji uthibitishaji tofauti ulioidhinishwa. Mipaka ya uaminifu ya filesystem katika web applications pia inaweza kufichua akaunti inayomiliki vifaa hivi; tazama [Django file-cache review](../../network-services-pentesting/pentesting-web/django.md#cache-manipulation-to-rce).

Root ya container na root ya host ni identities tofauti. Private SSH key inayosomeka tu baada ya kuwa root ndani ya container inaweza kuthibitisha utambulisho kwenye akaunti ya host ikiwa host inaikubali, lakini jina la file la key au maoni ya public-key hayathibitishi ufikiaji huo. Vilevile, custom password generator inayopatikana karibu na rekodi yenye timestamp ya kubadilisha password ni dalili tu ya uchanganuzi wa mwongozo: non-cryptographic generator inayotumia muda kama seed inaweza kuwa na dirisha dogo la seed zinazowezekana, lakini timezone, usahihi wa saa, tabia ya library, na mabadiliko ya baadaye ya password huathiri uundaji upya. Thibitisha credentials zinazowezekana tu ikiwa umeidhinishwa; usichukulie candidates zilizozalishwa kuwa ni passwords zilizothibitishwa.

Service account ndani ya container inaweza kusoma provisioning script ya zamani katika home directory inayoonekana kuwa na ruhusa za juu ikiwa directory inaweza kupitiwa na ruhusa za file zinaruhusu usomaji. Nenosiri la application-admin lililopachikwa ni dalili ya credential exposure, si ufikiaji wa host-root: kagua kama script na credential hiyo vilikuwa vinatumika, thamani hiyo ni ya akaunti gani, na kama akaunti tofauti ya host bado inakubali password hiyo hiyo. Wakati wa passive enumeration, rekodi file path na ruhusa za ufikiaji bila kuchapisha secret au kujaribu uthibitishaji kwenye host.

Ikiwa bundle ya `.p12` au `.pfx` inayosomeka ina password iliyofichuliwa kwenye application configuration, ichunguze kwa `openssl pkcs12 -info -in bundle.p12 -noout`. Ikiwa bundle ina private key inayoweza kutolewa, `openssl pkcs12 -in bundle.p12 -nocerts -nodes -out extracted.key` huiandika key hiyo bila usimbaji fiche. Linda file la matokeo na uliondoe baada ya uchanganuzi; tumia key iliyorejeshwa kwa service au ciphertext inayolingana nayo tu. Bundle pekee haimaanishi kuwa private key yake ina manufaa kwa application nyingine.
