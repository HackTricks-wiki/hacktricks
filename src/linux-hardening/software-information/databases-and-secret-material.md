# Βάσεις δεδομένων και μυστικό υλικό σε Linux Hosts

{{#include ../../banners/hacktricks-training.md}}

Τα διαπιστευτήρια βάσεων δεδομένων και εφαρμογών βρίσκονται συχνά δίπλα στην υπηρεσία που υποστηρίζουν. Εντοπίστε τη διεργασία, το τοπικό socket ή port, τις ρυθμίσεις και το αρχείο διαπιστευτηρίων, πριν ελέγξετε αν ένας λογαριασμός μπορεί να διαβάσει δεδομένα ή να εκτελέσει μια προνομιούχα ενέργεια.

## Εντοπισμός τοπικών υπηρεσιών δεδομένων και διαπιστευτηρίων

```bash
ss -lntup
ss -lnx
ps -eo user,pid,args | grep -E '[m]ysqld|[m]ariadbd|[p]ostgres|[r]edis-server|[m]ongod'
find /etc /opt /var/www /home -type f \( -name '*.env' -o -name '*config*' -o -name '.my.cnf' -o -name '.pgpass' \) -ls 2>/dev/null | head -100
```

Ελέγξτε αναγνώσιμα αρχεία ρυθμίσεων εφαρμογών, αρχεία ανάπτυξης, αρχεία περιβάλλοντος υπηρεσιών και αντίγραφα ασφαλείας για συμβολοσειρές σύνδεσης ή κλειδιά. Ένα Unix socket διεργασίας DB μπορεί να έχει διαφορετικούς κανόνες πρόσβασης από τον TCP listener της. Τα δικαιώματα DB διαφέρουν από τα δικαιώματα του OS: ένας ανακτημένος κωδικός πρόσβασης DB παρέχει μόνο τους ρόλους που έχουν εκχωρηθεί σε αυτόν τον λογαριασμό DB, εκτός αν αποδειχθεί κάποια άλλη οδός. Στο PostgreSQL, οι πολιτικές ασφάλειας σε επίπεδο γραμμής μπορούν να αποκρύπτουν εγγραφές από έναν ρόλο, ενώ ένας ρόλος με δικαιώματα διαχείρισης πολιτικών μπορεί να αλλάξει αυτήν την προβολή· διακρίνετε την πρόσβαση στα δεδομένα από τη διαχείριση πολιτικών. Χρησιμοποιήστε τους ειδικούς οδηγούς για [MySQL/MariaDB](../../network-services-pentesting/pentesting-mysql.md), [PostgreSQL](../../network-services-pentesting/pentesting-postgresql.md) και [Redis](../../network-services-pentesting/6379-pentesting-redis.md).

Ένα αναγνώσιμο script αυτοματοποίησης στον home κατάλογο άλλου λογαριασμού μπορεί να ενσωματώνει διαπιστευτήριο, ακόμη κι αν το όνομά του δεν αναφέρει κωδικούς πρόσβασης. Για παράδειγμα, ένα Python script μπορεί να εκκινεί το `su` και να στέλνει μια κυριολεκτική τιμή στο prompt κωδικού πρόσβασης μέσω του [`pexpect.sendline`](https://pexpect.readthedocs.io/en/latest/api/pexpect.html)· το [`su`](https://man7.org/linux/man-pages/man1/su.1.html) εξακολουθεί να εφαρμόζει την πολιτική ελέγχου ταυτότητάς του. Επιβεβαιώστε ότι ο τρέχων χρήστης μπορεί να διασχίσει τον κατάλογο και να διαβάσει το συγκεκριμένο script, ότι η κυριολεκτική τιμή προορίζεται για κωδικό πρόσβασης του λογαριασμού-στόχου και ότι το διαπιστευτήριο εξακολουθεί να ισχύει, προτού το θεωρήσετε μετάβαση σε άλλον λογαριασμό. Το script δεν χρειάζεται να εκτελεστεί επιτυχώς για να αποκαλύψει ένα μυστικό μέσω του κειμένου του. Η παθητική έξοδος πρέπει να εμφανίζει τη διαδρομή και τα δικαιώματα, χωρίς να εκτυπώνει την τιμή ή να επιχειρεί σύνδεση.

Μια αναγνώσιμη βάση δεδομένων SQLite εφαρμογής μπορεί να περιέχει ονόματα χρηστών και hash κωδικών πρόσβασης, χωρίς να υπάρχει ενεργή υπηρεσία βάσης δεδομένων που ακούει. Εξετάστε το schema και τα δικαιώματα αρχείου προτού θεωρήσετε ένα hash ως στοιχείο για offline έλεγχο. Ένας ανακτημένος κωδικός πρόσβασης εφαρμογής παρέχει πρόσβαση σε λογαριασμό OS ή τοπικό admin panel μόνο εφόσον επιβεβαιωθεί ξεχωριστά η επαναχρησιμοποίησή του· η μορφή του hash ή το ταίριασμα ονόματος χρήστη δεν αποδεικνύει επαναχρησιμοποίηση.

Το Apache OFBiz μπορεί να χρησιμοποιεί ενσωματωμένη βάση δεδομένων Derby στον κατάλογο `runtime/data/derby/<database>/`. Το αρχείο `service.properties` της Derby υποδεικνύει τον κατάλογο της βάσης δεδομένων· ο γειτονικός κατάλογος `seg0` περιέχει αρχεία πινάκων. Ελέγξτε τα δικαιώματα ολόκληρου του καταλόγου της βάσης δεδομένων προτού εξετάσετε εγγραφές εφαρμογής, όπως το `USER_LOGIN`. Ένας αναγνώσιμος δείκτης δεν αποδεικνύει ότι οι πίνακες είναι αναγνώσιμοι, ότι μπορεί να ανακτηθεί κωδικός πρόσβασης ή ότι ένα διαπιστευτήριο εφαρμογής λειτουργεί για λογαριασμό Unix. Μην συμπεριλαμβάνετε τα περιεχόμενα βάσεων δεδομένων και τα hash κωδικών πρόσβασης στη συνήθη έξοδο απαρίθμησης. Δείτε την [τεκμηρίωση καταλόγου βάσης δεδομένων Derby](https://db.apache.org/derby/docs/10.4/devguide/cdevdvlp40724.html) και το [API σύνδεσης OFBiz](https://nightlies.apache.org/ofbiz/stable/javadoc/org/apache/ofbiz/common/login/LoginServices.html).

Το TeamCity διατηρεί τα δεδομένα του server του σε έναν ρυθμιζόμενο κατάλογο δεδομένων (συχνά `.BuildServer`). Ελέγξτε τα δικαιώματα στα `config/projects/<project>/pluginData/ssh_keys`, `config/database.properties`, `system/buildserver.*` όταν χρησιμοποιείται η ενσωματωμένη HSQLDB και `backup/TeamCity_Backup_*.zip`. Τα μεταφορτωμένα SSH keys και άλλες ασφαλείς ρυθμίσεις μπορεί να είναι κρυπτογραφημένα, επομένως το ότι μια διαδρομή είναι αναγνώσιμη δεν αποδεικνύει ότι υπάρχει αξιοποιήσιμο ιδιωτικό κλειδί. Η βάση δεδομένων ή το αντίγραφο ασφαλείας μπορεί να περιέχει χρήστες εφαρμογής και hash κωδικών πρόσβασης· η χρήση τους για λογαριασμό Unix απαιτεί ξεχωριστά στοιχεία για επαναχρησιμοποίηση κωδικού πρόσβασης. Κατά την απαρίθμηση, καταγράψτε διαδρομές και δικαιώματα πρόσβασης αντί να εκτυπώνετε κλειδιά, hash ή γραμμές βάσης δεδομένων. Δείτε την τεκμηρίωση του TeamCity για τον [κατάλογο δεδομένων](https://www.jetbrains.com/help/teamcity/teamcity-data-directory.html), τα [SSH keys](https://www.jetbrains.com/help/teamcity/ssh-keys-management.html) και τα [αντίγραφα ασφαλείας](https://www.jetbrains.com/help/teamcity/manual-backup-and-restore.html).

Ο server αντιγράφων ασφαλείας Duplicati διατηρεί τις ρυθμίσεις του στο `Duplicati-server.sqlite`. Ο κατάλογος δεδομένων του μπορεί να βρίσκεται στον home κατάλογο του λογαριασμού υπηρεσίας, στο `/var/lib/Duplicati` ή σε volume container, ενώ τα `--server-datafolder` ή `DUPLICATI_HOME` μπορούν να αλλάξουν τη θέση του. Μια αναγνώσιμη βάση δεδομένων αποτελεί σημαντικό στοιχείο, επειδή μπορεί να περιέχει διαπιστευτήρια σύνδεσης και υλικό υπογραφής του server, αλλά οι νεότερες εγκαταστάσεις ενδέχεται να κρυπτογραφούν ευαίσθητα πεδία και να περιορίζουν την πρόσβαση στον κατάλογο. Συσχετίστε τα δικαιώματά της με τον πραγματικό λογαριασμό server και με οποιαδήποτε αυθεντικοποιημένη πρόσβαση μέσω UI ή ServerUtil. Αν αυτός ο server εκτελείται ως root με προσαρτημένο το host `/` στο container του, οι εξουσιοδοτημένες λειτουργίες επαναφοράς αντιγράφων ασφαλείας και τα job hooks μπορούν να διασχίσουν το όριο του filesystem του host· ένας listener loopback ή ένα όνομα αρχείου βάσης δεδομένων από μόνο του δεν αποδεικνύει έλεγχο. Δεν πρέπει να θεωρείται δεδομένη για τις τρέχουσες εκδόσεις η συμπεριφορά σύνδεσης παλαιότερων εκδόσεων που βασιζόταν σε nonce· χρησιμοποιούν διαφορετικό [μοντέλο αυθεντικοποίησης](https://docs.duplicati.com/technical-details/server-authentication-model). Για λεπτομέρειες ανά έκδοση, δείτε την τεκμηρίωση της Duplicati για τη [βάση δεδομένων server](https://docs.duplicati.com/database-and-storage/the-server-database) και το [ServerUtil](https://docs.duplicati.com/duplicati-programs/command-line-interface-cli-1/serverutil).

Για το PostgreSQL, εξετάστε τα `pg_policies` και `pg_class.relrowsecurity` για να διακρίνετε ένα φιλτραρισμένο ερώτημα από εγγραφές που λείπουν. Η αλλαγή ή απενεργοποίηση μιας πολιτικής απαιτεί τα κατάλληλα δικαιώματα ιδιοκτησίας πίνακα ή διαχειριστή. Ένας ξεχωριστός λογαριασμός συντήρησης που έχει γίνει leak μπορεί να έχει αυτά τα δικαιώματα, ακόμη κι αν ο λογαριασμός της εφαρμογής δεν τα έχει. Ένας listener Redis χωρίς έλεγχο ταυτότητας αποτελεί διαφορετικό εύρημα: επαληθεύστε αν δεσμεύεται μόνο στη loopback και αν το protected mode ή τα ACL περιορίζουν την τρέχουσα σύνδεση, προτού τον θεωρήσετε πηγή μυστικών.

## Εξέταση αποθηκευτικών χώρων κλειδιών και token

```bash
find /home /root -maxdepth 4 -type f \( -name 'id_*' -o -name '*.ppk' -o -name '*.p12' -o -name '*.pfx' -o -name '*.kdb' -o -name '*.kdbx' -o -name '*.gpg' -o -name '.git-credentials' \) -ls 2>/dev/null
find /home /root -maxdepth 4 -type d -name '.gnupg' -ls 2>/dev/null
printenv SSH_AUTH_SOCK KRB5CCNAME GNUPGHOME 2>/dev/null
```

Ένα ιδιωτικό κλειδί SSH, ένα socket agent, μια cache Kerberos, ένα keyring GPG ή ένα πακέτο PKCS#12 είναι χρήσιμα μόνο αν ο τρέχων χρήστης έχει πρόσβαση σε αυτά και η χρήση τους επιτρέπεται από τυχόν απαιτούμενο passphrase ή πολιτική. Ελέγξτε πρώτα την ιδιοκτησία και τα δικαιώματα. Οι σελίδες [χρήστες και συνεδρίες](../user-information/user-and-session-triage.md), [Linux AD](../user-information/linux-active-directory.md) και [post-exploitation](../post-exploitation/README.md) εξηγούν τις αντίστοιχες διαδρομές πρόσβασης. Το ιστορικό Git, τα παλιά αντίγραφα ασφαλείας και το ιστορικό του shell μπορούν επίσης να διατηρήσουν μυστικά, ακόμη κι αφού καθαριστεί μια ενεργή διαμόρφωση. Ένας αναγνώσιμος κατάλογος `.git` μπορεί να διατηρεί διαγραμμένο πηγαίο κώδικα και παλαιότερα διαπιστευτήρια που είχαν γίνει commit, ακόμη κι όταν το working tree είναι κενό· ελέγξτε την πρόσβαση και εξετάστε το ιστορικό χειροκίνητα, αντί να το απορρίπτετε μαζικά κατά την αυτοματοποιημένη απαρίθμηση.

Μια αναγνώσιμη εικόνα εκκίνησης στο `/boot` αποτελεί άλλη μία πιθανή πηγή αρχειοθετημένου υλικού. Τα [boot scripts και οι αντιγραμμένοι helpers του initramfs](https://manpages.debian.org/testing/initramfs-tools-core/initramfs-tools.7.en.html) μπορεί να περιλαμβάνουν προσαρμοσμένη λογική που παρέχει ένα κλειδί στο [`cryptsetup --key-file=-`](https://manpages.debian.org/testing/cryptsetup-bin/cryptsetup.8.en.html). Ελέγξτε τα δικαιώματα πρόσβασης της εικόνας και εξετάστε μόνο το σχετικό boot script και helper σε εξουσιοδοτημένο offline αντίγραφο. Ένα ενσωματωμένο ή παράγωγο passphrase ξεκλειδώματος δίσκου δεν είναι αυτομάτως κωδικός πρόσβασης λογαριασμού Unix: επιβεβαιώστε τις εισόδους του helper, την πραγματική διαδρομή εκκίνησης και την ξεχωριστή επαναχρησιμοποίηση διαπιστευτηρίων προτού το θεωρήσετε μετάβαση σε λογαριασμό. Η συνήθης απαρίθμηση δεν πρέπει να αποσυσκευάζει την εικόνα, να εκτελεί τους helpers της ή να εμφανίζει πιθανά κλειδιά.

Το CLI του Vault [αποθηκεύει συνήθως το token ελέγχου ταυτότητας στο `~/.vault-token`](https://developer.hashicorp.com/vault/docs/commands/token-helper), αν και ένας προσαρμοσμένος token helper μπορεί να το αποθηκεύει αλλού. Μια αναγνώσιμη διαδρομή είναι απλώς ένδειξη πιθανού διαπιστευτηρίου: επαληθεύστε την εγκυρότητα του token και την πολιτική του προτού συμπεράνετε ότι παρέχει πρόσβαση σε οποιοδήποτε secret engine. Για τους [κωδικούς πρόσβασης μίας χρήσης SSH του Vault](https://developer.hashicorp.com/vault/docs/secrets/ssh/one-time-ssh-passwords), το token πρέπει να είναι εξουσιοδοτημένο να εκδίδει διαπιστευτήρια για έναν ρόλο του οποίου ο χρήστης και το CIDR περιλαμβάνουν τον προβλεπόμενο λογαριασμό και host· στον host πρέπει επίσης να έχει ρυθμιστεί ο helper επαλήθευσης SSH και να γίνεται αποδεκτή η σύνδεση. Ένας ρόλος που ονομάζει `root` ή ένα αρχείο token από μόνο του δεν αποδεικνύει πρόσβαση root. Η παθητική απαρίθμηση πρέπει να αναφέρει τη διαδρομή του αρχείου χωρίς να διαβάζει το token ή να ζητά OTP.

[Το KeePass 1.x χρησιμοποιεί `.kdb`, ενώ το KeePass 2.x χρησιμοποιεί `.kdbx`](https://keepass.info/help/v2/version.html). Αντιμετωπίστε ένα αρχείο με αντίστοιχο όνομα ως πιθανό κρυπτογραφημένο vault, καθώς και άλλα προϊόντα μπορεί να χρησιμοποιούν την κατάληξη `.kdb`. Ένα αναγνώσιμο vault δεν αποκαλύπτει τις εγγραφές του χωρίς τον απαιτούμενο κύριο κωδικό πρόσβασης ή αρχείο κλειδιού· ένα κλειδί SSH αποθηκευμένο ως συνημμένο είναι ξεχωριστή ένδειξη, της οποίας η πρόσβαση στον host πρέπει να επαληθευτεί. [Το KeePass δέχεται αυθαίρετα αρχεία, συμπεριλαμβανομένων εικόνων, ως αρχεία κλειδιών](https://keepass.info/help/base/keys.html), αλλά ένα κοντινό αρχείο είναι απλώς υποψήφιο μέχρι να επιβεβαιωθούν ανεξάρτητα ο ρόλος του, όλα τα απαιτούμενα στοιχεία του κύριου κλειδιού και τυχόν σύνδεση σε λογαριασμό με υψηλότερα προνόμια.

Ένα αρχείο υποστήριξης μπορεί να περιέχει τόσο ένα KeePass vault όσο και ένα dump μνήμης διεργασίας. Για [KeePass 2.x πριν από την έκδοση 2.54, το CVE-2023-32784](https://nvd.nist.gov/vuln/detail/CVE-2023-32784) καθιστά δυνητικά ανακτήσιμο τον κύριο κωδικό πρόσβασης από ένα αντίστοιχο dump· ένα κρυπτογραφημένο vault ή ένα άσχετο dump από μόνο του δεν αρκεί. Εξετάστε χειροκίνητα τις εγγραφές του αρχείου και τα δικαιώματα πρόσβασης, χωρίς μαζική εξαγωγή ή εμφάνιση μυστικών κατά τη συνήθη απαρίθμηση. Τα ιδιωτικά κλειδιά PuTTY μπορεί να εμφανίζονται ως αρχεία `.ppk` ή ως κείμενο `PuTTY-User-Key-File` σε μια εγγραφή vault· επιβεβαιώστε ξεχωριστά τον λογαριασμό για τον οποίο προορίζεται το κλειδί, την κρυπτογράφησή του και τον host που το αποδέχεται.

Ένα αναγνώσιμο αρχείο HTTP archive `.har` μπορεί να διατηρεί αιτήματα και αποκρίσεις του browser, συμπεριλαμβανομένων των authentication headers, των cookies και των πεδίων φορμών. Μπορεί να έχει αποθηκευτεί απευθείας ή μέσα σε ένα συνημμένο υποστήριξης. Ελέγξτε πρώτα την ιδιοκτησία και την πρόσβαση και, στη συνέχεια, εξετάστε μόνο τις σχετικές εγγραφές· ένα όνομα αρχείου από μόνο του δεν αποδεικνύει ότι περιέχει επαναχρησιμοποιήσιμο διαπιστευτήριο. Η αυτοματοποιημένη απαρίθμηση πρέπει να αναφέρει τη διαδρομή του αρχείου χωρίς να εμφανίζει τις καταγεγραμμένες τιμές. Η [τεκμηρίωση του Microsoft Edge](https://learn.microsoft.com/en-us/microsoft-edge/devtools/network/reference#save-all-network-requests-to-a-har-file) εξηγεί την επιλογή εξαγωγής ευαίσθητων δεδομένων.

Για κρυπτογραφημένα αντίγραφα ασφαλείας βάσεων δεδομένων, συσχετίστε το αναγνώσιμο αρχείο, το προσβάσιμο υλικό ιδιωτικού κλειδιού και τυχόν απαίτηση passphrase προτού καταλήξετε σε συμπέρασμα. Όπου υπάρχει εξουσιοδότηση, η ανάκτηση του passphrase ενός προστατευμένου κλειδιού και η εξέταση των αποκρυπτογραφημένων δεδομένων του αντιγράφου ασφαλείας είναι ξεχωριστά χειροκίνητα βήματα. Ένα διαπιστευτήριο `root` βάσης δεδομένων δεν είναι διαπιστευτήριο Unix `root`· η επαναχρησιμοποίηση κωδικού πρόσβασης μεταξύ αυτών των λογαριασμών απαιτεί ξεχωριστή, εξουσιοδοτημένη επαλήθευση. Τα όρια εμπιστοσύνης του συστήματος αρχείων σε web εφαρμογές μπορούν επίσης να εκθέσουν τον λογαριασμό που κατέχει αυτό το υλικό· δείτε την [εξέταση της file cache του Django](../../network-services-pentesting/pentesting-web/django.md#cache-manipulation-to-rce).

Το root ενός container και το root του host είναι ξεχωριστές ταυτότητες. Ένα ιδιωτικό κλειδί SSH που είναι αναγνώσιμο μόνο αφού αποκτήσετε root μέσα σε ένα container μπορεί να πιστοποιηθεί σε έναν λογαριασμό του host, αν ο host το αποδέχεται, αλλά το όνομα αρχείου του κλειδιού ή το σχόλιο του δημόσιου κλειδιού δεν αποδεικνύει ότι υπάρχει τέτοια πρόσβαση. Παρομοίως, ένα προσαρμοσμένο πρόγραμμα δημιουργίας κωδικών πρόσβασης που εντοπίζεται δίπλα σε μια χρονοσημασμένη εγγραφή αλλαγής κωδικού πρόσβασης αποτελεί μόνο ένδειξη για χειροκίνητη ανάλυση: ένας μη κρυπτογραφικός generator με seed που βασίζεται στον χρόνο μπορεί να έχει μικρό εύρος πιθανών seed, αλλά η ζώνη ώρας, η ακρίβεια του ρολογιού, η συμπεριφορά της βιβλιοθήκης και οι μεταγενέστερες αλλαγές κωδικού επηρεάζουν την ανακατασκευή. Επαληθεύστε πιθανά διαπιστευτήρια μόνο όταν υπάρχει εξουσιοδότηση· μην θεωρείτε τους παραγόμενους υποψήφιους κωδικούς επιβεβαιωμένους.

Ένας λογαριασμός υπηρεσίας μέσα σε ένα container μπορεί να έχει τη δυνατότητα να διαβάσει ένα παλιό script provisioning σε έναν ονομαστικά προνομιούχο home directory, αν ο κατάλογος επιτρέπει τη διέλευση και τα δικαιώματα του αρχείου το επιτρέπουν. Ένας ενσωματωμένος κωδικός πρόσβασης διαχειριστή εφαρμογής αποτελεί ένδειξη έκθεσης διαπιστευτηρίου, όχι πρόσβαση root στον host: ελέγξτε αν το script και το διαπιστευτήριο ήταν ενεργά, σε ποιον λογαριασμό αντιστοιχεί η τιμή και αν κάποιος ξεχωριστός λογαριασμός του host εξακολουθεί να δέχεται τον ίδιο κωδικό πρόσβασης. Κατά την παθητική απαρίθμηση, καταγράψτε τη διαδρομή του αρχείου και τα δικαιώματα πρόσβασης χωρίς να εμφανίζετε το μυστικό ή να επιχειρείτε έλεγχο ταυτότητας στον host.

Αν ένα αναγνώσιμο πακέτο `.p12` ή `.pfx` έχει κωδικό πρόσβασης εκτεθειμένο στη διαμόρφωση της εφαρμογής, εξετάστε το με `openssl pkcs12 -info -in bundle.p12 -noout`. Αν το πακέτο περιέχει ιδιωτικό κλειδί που μπορεί να εξαχθεί, η εντολή `openssl pkcs12 -in bundle.p12 -nocerts -nodes -out extracted.key` αποθηκεύει αυτό το κλειδί χωρίς κρυπτογράφηση. Προστατέψτε το αρχείο εξόδου και διαγράψτε το μετά την ανάλυση· χρησιμοποιήστε το ανακτημένο κλειδί μόνο για την υπηρεσία ή το ciphertext με το οποίο όντως αντιστοιχεί. Ένα πακέτο από μόνο του δεν συνεπάγεται ότι το ιδιωτικό του κλειδί είναι χρήσιμο για διαφορετική εφαρμογή.
