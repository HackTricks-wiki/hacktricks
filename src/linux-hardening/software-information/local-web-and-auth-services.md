# Τοπικές υπηρεσίες Web και ελέγχου ταυτότητας

{{#include ../../banners/hacktricks-training.md}}

Ένα Linux shell παρέχει μια εικόνα των υπηρεσιών Web και ελέγχου ταυτότητας από την πλευρά του host: ορίσματα διεργασιών, listeners, αρχεία μονάδων, ρυθμίσεις, logs και διεπαφές που είναι προσβάσιμες μόνο τοπικά. Χρησιμοποιήστε αυτή την εικόνα για να συνδέσετε μια προσβάσιμη υπηρεσία με τον λογαριασμό και τα αρχεία που πράγματι χρησιμοποιεί.

## Χαρτογράφηση της τοπικής στοίβας Web

```bash
ss -lntup
ps -eo user,pid,args | grep -E '[a]pache|[n]ginx|[p]hp-fpm|[j]enkins'
systemctl list-units --type=service --state=running 2>/dev/null
find /etc/apache2 /etc/httpd /etc/nginx -maxdepth 3 -type f 2>/dev/null | head -80
```

Ελέγξτε τα ονόματα virtual host, τα document root, τις διαδρομές proxy, τους καταλόγους upload, τις ρυθμίσεις εκτέλεσης PHP και τα αρχεία ρυθμίσεων που περιέχουν διαπιστευτήρια. Ένας listener loopback μπορεί να είναι προσβάσιμος μέσω proxy ή SSH tunnel. Για να δοκιμάσετε ένα συγκεκριμένο virtual host σε τοπικό listener, στείλτε την προβλεπόμενη κεφαλίδα `Host` ή χρησιμοποιήστε το `curl --resolve` με τη σωστή διεύθυνση και θύρα. Η απαρίθμηση virtual host μπορεί επίσης να αποκαλύψει ονόματα που απουσιάζουν από την προεπιλεγμένη απόκριση. Ελέγξτε αν το Apache επιτρέπει παρακάμψεις μέσω `.htaccess` και αν οι διαδρομές upload μπορούν να εκτελέσουν PHP, πριν θεωρήσετε ότι ένας εγγράψιμος κατάλογος upload επιτρέπει εκτέλεση κώδικα. Ένας αναπτυγμένος JavaScript source map μπορεί να αποκαλύψει διαδρομές πηγαίου κώδικα ή client-side μυστικά· αντιμετωπίστε τις τιμές που ανακτώνται ως ενδείξεις και επαληθεύστε τα πραγματικά δικαιώματά τους. Για ελέγχους ειδικούς στον ιστό, δείτε τα [Apache](../../network-services-pentesting/pentesting-web/apache.md) και [Nginx](../../network-services-pentesting/pentesting-web/nginx.md).

Για Apache με [mpm-itk](https://mpm-itk.sesse.net/), ένα ενεργό `AssignUserID` μπορεί να εκτελέσει ένα virtual host με διαφορετικό χρήστη και ομάδα. Αν ένας λογαριασμός με χαμηλότερα δικαιώματα μπορεί να γράψει ένα script στο `DocumentRoot` αυτού του host, ελέγξτε αν μια προσβάσιμη διαδρομή το εκτελεί πράγματι με την εκχωρημένη ταυτότητα. Επιβεβαιώστε ότι το module είναι φορτωμένο, την αποτελεσματική ρύθμιση του virtual host (συμπεριλαμβανομένων παρακάμψεων ταυτότητας που βασίζονται σε εκφράσεις), τα δικαιώματα εγγραφής και αναζήτησης στον κατάλογο, τον script handler και την πρόσβαση στον listener. Μια επισημασμένη οδηγία ή ένας εγγράψιμος κατάλογος από μόνα τους δεν αποδεικνύουν εκτέλεση μεταξύ χρηστών.

Ένας home directory που δημοσιεύεται μέσω web server μπορεί να εκθέσει αντίγραφα ασφαλείας με αρχεία ταυτότητας SSH, ακόμη κι όταν ο ενεργός κατάλογος `.ssh` είναι ιδιωτικός. Για παράδειγμα, η ρύθμιση `homedirs_public` του [Nostromo](https://www.nazgul.ch/dev/nostromo_man.html) επιλέγει έναν υποκατάλογο που εξυπηρετείται από τους καταλόγους home των χρηστών. Η εύρεση μιας διαδρομής σε αρχείο είναι απλώς ένδειξη: επαληθεύστε την αποτελεσματική αντιστοίχιση του server, την τοπική αναγνωσιμότητα ή την εξουσιοδότηση HTTP, τα περιεχόμενα του αρχείου, τη φράση πρόσβασης του ιδιωτικού κλειδιού και αν ο αντίστοιχος λογαριασμός δέχεται πράγματι το κλειδί. Μην εξάγετε αρχεία ούτε να εμφανίζετε υλικό κλειδιών κατά τη συνήθη απαρίθμηση host.

Ένα αναγνώσιμο αντίγραφο ασφαλείας μιας τοπικής web εφαρμογής με υψηλότερα δικαιώματα μπορεί να αποκαλύψει τη λογική αυθεντικοποίησης και ανάγνωσης αρχείων, ακόμη κι όταν ο ενεργός πηγαίος κώδικας δεν είναι προσβάσιμος. Συγκρίνετε το αντίγραφο ασφαλείας με την αναπτυγμένη υπηρεσία πριν βασιστείτε σε αυτό. Ειδικότερα, αξίζει να εξεταστεί ένα cookie που δημιουργείται κρυπτογραφώντας κείμενο ελεγχόμενο από τον καλούντα, ακολουθούμενο από ένα μυστικό και μια σημαία ρόλου, αν η εφαρμογή χρησιμοποιεί ντετερμινιστικά blocks ECB, επιστρέφει νέα cookies για κείμενο που έχει επιλεγεί από τον καλούντα και αργότερα διαχωρίζει την αποκρυπτογραφημένη τιμή με βάση έναν μη escaped οριοθέτη. Το [NIST εξηγεί την ανεξάρτητη και επαναλήψιμη αντιστοίχιση block του ECB](https://csrc.nist.gov/news/2022/proposal-to-revise-sp-800-38a)· αυτή η ιδιότητα μπορεί να υποστηρίξει σύγκριση με επιλεγμένη είσοδο, αλλά από μόνη της δεν παρέχει υψηλότερο ρόλο. Επιβεβαιώστε την ενεργή διαδρομή, τις προϋποθέσεις συνεδρίας, τον ακριβή parser και τη ροή δεδομένων, την ταυτότητα της υπηρεσίας και μια ξεχωριστή προνομιούχα ενέργεια ή διαδρομή ανάγνωσης αρχείων. Η παθητική απογραφή πρέπει να αναφέρει μεταδεδομένα αντιγράφων ασφαλείας και την ιδιοκτησία του listener, χωρίς να διαβάζει τα περιεχόμενα του αρχείου ή να στέλνει probes αυθεντικοποίησης.

Η ίδια προσέγγιση ελέγχου πηγαίου κώδικα εφαρμόζεται σε μια προνομιούχα τοπική υπηρεσία **μη HTTP**, όπως ένα προσαρμοσμένο interface που βασίζεται σε SSH. Αν ένα προσβάσιμο αντίγραφο ασφαλείας πηγαίου κώδικα δείχνει μια εντολή που δέχεται διαδρομή αρχείου επιλεγμένη από τον καλούντα, ελέγξτε την πύλη αυθεντικοποίησής της, τον τρόπο επίλυσης της διαδρομής και αν επιβεβαιώνει ότι το επιλυμένο αρχείο παραμένει κάτω από τον προβλεπόμενο κατάλογο πριν το ανοίξει. Στη Go, το [`filepath.Join`](https://pkg.go.dev/path/filepath#Join) καθαρίζει μια διαδρομή, αλλά δεν επιβάλλει τον περιορισμό εντός του καταλόγου. Επιβεβαιώστε ότι το αντίγραφο ασφαλείας αντιστοιχεί στο εκτελούμενο build, ότι ο listener είναι προσβάσιμος, ότι ο λογαριασμός με χαμηλότερα δικαιώματα μπορεί να χρησιμοποιήσει την εντολή και ότι η διεργασία μπορεί να διαβάσει τον στόχο· η κατοχή αναγνώσιμου κλειδιού SSH είναι ξεχωριστό ζήτημα πολιτικής σύνδεσης. Αναφέρετε τις διαδρομές των αρχείων πηγαίου κώδικα του archive και την ιδιοκτησία της υπηρεσίας, χωρίς να εξάγετε περιεχόμενα ή κλειδιά σε αυτοματοποιημένη έξοδο.

Ένα pool PHP-FPM που ακούει σε TCP loopback μπορεί να είναι προσβάσιμο από άλλο τοπικό λογαριασμό, ακόμη κι αν ο ιστότοπός του απαιτεί αυθεντικοποίηση. Το [PHP προειδοποιεί ότι ένας client που μπορεί να συνδεθεί στο FastCGI μπορεί να ελέγξει ρυθμίσεις αιτήματος, συμπεριλαμβανομένου του `auto_prepend_file`](https://www.php.net/manual/en/install.fpm.php). Εξετάστε τις ρυθμίσεις `listen` και `listen.allowed_clients` του pool μαζί με τον ενεργό listener, το UID των worker, μια υπάρχουσα διαδρομή script και τυχόν περιορισμούς `security.limit_extensions` ή `php_admin_value`. Τα αρχεία ρυθμίσεων του pool μπορεί να περιέχουν διαπιστευτήρια σε οδηγίες `env[...]`, επομένως η αυτοματοποιημένη απογραφή πρέπει να αναφέρει τις διαδρομές τους και όχι τα περιεχόμενά τους. Ένα αρχείο ρυθμίσεων ή μια θύρα από μόνα τους δεν αποδεικνύουν διαδρομή εκτέλεσης μεταξύ χρηστών· δείτε τον [οδηγό FastCGI](../../network-services-pentesting/9000-pentesting-fastcgi.md) για λεπτομέρειες του πρωτοκόλλου.

Για ένα προνομιούχο τοπικό API, εξετάστε την εξουσιοδότηση καθώς και την εκτέλεση κώδικα. Ένας ρόλος βάσης δεδομένων που μπορεί να αλλάξει ο λογαριασμός με χαμηλότερα δικαιώματα μπορεί να ξεκλειδώσει μια διαδρομή API, αλλά το επόμενο όριο εξαρτάται από την υλοποίηση της διαδρομής. Για παράδειγμα, η συγχώνευση JSON αιτήματος σε ένα αντικείμενο JavaScript και η μετέπειτα κλήση του [`child_process.exec`](https://nodejs.org/api/child_process.html) αξίζουν έλεγχο για [ροή δεδομένων από prototype pollution σε εκτέλεση](../../pentesting-web/deserialization/nodejs-proto-prototype-pollution/prototype-pollution-to-rce.md). Επαληθεύστε την πραγματική βιβλιοθήκη/έκδοση συγχώνευσης, την επικύρωση εισόδου, την προσβάσιμη διαδρομή, την ταυτότητα της διεργασίας και τις επιλογές της child process· ένας listener Node που ανήκει στον root ή το όνομα μιας ευάλωτης εξάρτησης αποτελεί απλώς ένδειξη.

Τα file-backed CMS μπορεί να αποθηκεύουν επαληθευτές κωδικών πρόσβασης διαχειριστών εκτός των συμβατικών αρχείων ρυθμίσεων `.php`. Παραδείγματα είναι το `data/database.js` ή το `data/settings/pass.php` ενός site. Ελέγξτε την ιδιοκτησία και την αναγνωσιμότητα του αρχείου πριν από μη αυτόματο έλεγχο, και μην περιλαμβάνετε hashes σε αυτοματοποιημένη κοινόχρηστη έξοδο. Ένας κωδικός πρόσβασης εφαρμογής που μπορεί να ανακτηθεί αποτελεί ξεχωριστό όριο προνομίων από έναν λογαριασμό Unix: επαληθεύστε κάθε ισχυρισμό επαναχρησιμοποίησης για τον συγκεκριμένο λογαριασμό και την επιτρεπόμενη μέθοδο αυθεντικοποίησης.

Ο controller αυθεντικοποίησης μιας εφαρμογής μπορεί επίσης να περιέχει κυριολεκτικό κωδικό πρόσβασης σύνδεσης στον πηγαίο κώδικα αντί σε αρχείο ρυθμίσεων. Αν ένας χρήστης με χαμηλότερα δικαιώματα μπορεί να διαβάσει τον αναπτυγμένο controller, εξετάστε τοπικά τη σύγκριση αυθεντικοποίησης και μην περιλαμβάνετε την τιμή σε κοινόχρηστη έξοδο απογραφής. Επιβεβαιώστε ότι η διαδρομή κώδικα είναι ενεργή, ότι ο κωδικός πρόσβασης ισχύει για την εφαρμογή και ότι ένας ξεχωριστός λογαριασμός Unix με υψηλότερα δικαιώματα δέχεται πράγματι τον ίδιο κωδικό πρόσβασης, πριν ισχυριστείτε τοπική κλιμάκωση προνομίων. Ένα όνομα αρχείου controller αποτελεί απλώς ένδειξη προς εξέταση.

Το Dolibarr αποθηκεύει ρυθμίσεις σύνδεσης βάσης δεδομένων, συμπεριλαμβανομένου του `dolibarr_main_db_pass`, στο `htdocs/conf/conf.php` ([αναφορά ρυθμίσεων](https://wiki.dolibarr.org/index.php/Configuration_file)). Ένα αναγνώσιμο αρχείο αποτελεί ένδειξη διαπιστευτηρίων· μόνο η ξεχωριστή, επαληθευμένη επαναχρησιμοποίηση κωδικού πρόσβασης λογαριασμού ή κάποιο άλλο δικαίωμα βάσης δεδομένων θα μπορούσε να το μετατρέψει σε τοπική κλιμάκωση προνομίων. Ελέγξτε πρώτα τα δικαιώματα και αποφύγετε την εκτύπωση της τιμής σε αυτοματοποιημένη έξοδο.

Το αρχείο ρυθμίσεων του πακέτου GitLab για Linux είναι συνήθως το `/etc/gitlab/gitlab.rb`, αν και οι αναπτύξεις μπορεί να διατηρούν αναγνώσιμα αντίγραφα και αλλού. Το [GitLab τεκμηριώνει](https://docs.gitlab.com/omnibus/settings/smtp/) ότι αυτό το αρχείο μπορεί να περιέχει `gitlab_rails['smtp_password']`, αν και οι κρυπτογραφημένες ρυθμίσεις SMTP μπορεί να αποθηκεύουν τον κωδικό πρόσβασης εκτός του αρχείου απλού κειμένου. Αντιμετωπίστε ένα αναγνώσιμο αρχείο ρυθμίσεων ως ένδειξη διαπιστευτηρίων: επαληθεύστε ότι είναι ενεργό, ότι τα διαπιστευτήρια είναι τρέχοντα και ότι ένας συγκεκριμένος λογαριασμός με υψηλότερα δικαιώματα τα αποδέχεται πριν ισχυριστείτε επαναχρησιμοποίηση κωδικού πρόσβασης. Ξεχωριστά, το [GitLab εκτελεί το `gitlab.rb` ως κώδικα Ruby με δικαιώματα root κατά το `gitlab-ctl reconfigure`](https://docs.gitlab.com/omnibus/settings/configuration/)· ένα εγγράψιμο ενεργό αρχείο ή ένα συμπεριλαμβανόμενο `from_file` απαιτεί πραγματική διαδρομή επαναρύθμισης με προνόμια, προτού αποτελεί εύρημα εκτέλεσης. Μια προεπισκόπηση ρυθμίσεων μπορεί να εκθέσει τιμές διαπιστευτηρίων· αντιμετωπίστε την έξοδό της ως ευαίσθητη και κοινοποιήστε αντί γι' αυτήν τις διαδρομές και τα δικαιώματα.

Μια self-hosted εγκατάσταση Mattermost μπορεί να αποθηκεύει το `SqlSettings.DataSource` στο `/opt/mattermost/config/config.json`· το [Mattermost τεκμηριώνει](https://docs.mattermost.com/deployment-guide/server/troubleshooting) τόσο αυτή τη συνήθη διαδρομή όσο και τις αναπτύξεις που αποθηκεύουν την ενεργή ρύθμιση σε βάση δεδομένων. Ένα αναγνώσιμο αρχείο μπορεί να εκθέσει διαπιστευτήριο βάσης δεδομένων της εφαρμογής, αλλά δεν αποδεικνύει πρόσβαση στη βάση δεδομένων ή πρόσβαση root στο Unix. Επαληθεύστε την ενεργή πηγή ρυθμίσεων, τα πραγματικά δικαιώματα του ρόλου βάσης δεδομένων, τυχόν κωδικό πρόσβασης εφαρμογής που ανακτήθηκε ξεχωριστά και αν αυτός ο κωδικός πρόσβασης λειτουργεί για συγκεκριμένο λογαριασμό Unix με υψηλότερα δικαιώματα. Η μορφή των password hash μπορεί να αλλάζει μεταξύ εκδόσεων Mattermost· κατά την απογραφή, καταγράψτε τη διαδρομή ρυθμίσεων και τα μεταδεδομένα πρόσβασης, χωρίς να εκτυπώσετε τη συμβολοσειρά σύνδεσης ή να υποβάλετε ερωτήματα στη βάση δεδομένων.

```bash
curl -i -H 'Host: admin.example.local' http://127.0.0.1:8080/
ffuf -w wordlist.txt -u http://127.0.0.1:8080/ -H 'Host: FUZZ.example.local' -fs 1234 # replace 1234 with the default response size
grep -R 'sourceMappingURL' /var/www /opt 2>/dev/null | head
```

Φιλτράρετε τα αποτελέσματα virtual host σε σχέση με το προεπιλεγμένο μέγεθος απόκρισης ή κάποιο άλλο σταθερό σημείο αναφοράς, ώστε να μη φαίνεται έγκυρο κάθε όνομα που μαντεύεται. Ένα source map είναι χρήσιμο μόνο αν έχει όντως αναπτυχθεί ή είναι με άλλον τρόπο αναγνώσιμο.

Οι reverse proxies μπορούν να αλλάξουν τις κεφαλίδες client που εμπιστεύεται μια εφαρμογή. Συγκρίνετε άμεσα και μέσω proxy αιτήματα προτού υποθέσετε ότι οι κεφαλίδες `X-Forwarded-For`, `X-Forwarded-Host` ή παρόμοιες καθορίζουν την ταυτότητα του καλούντος. Εξετάστε από κοινού τις ρυθμίσεις του proxy και της εφαρμογής.

Αν η PHP αντιγράφει το `$_SERVER['HTTP_X_FORWARDED_FOR']` σε μια συμβολοσειρά που περνά στη [`system()`](https://www.php.net/manual/en/function.system.php), εξετάστε αν η προσβάσιμη διαδρομή αιτήματος επιτρέπει κεφαλίδα που παρέχεται από τον καλούντα και αν τα shell metacharacters φτάνουν σε αυτή τη συμβολοσειρά χωρίς τροποποίηση. Μια εντολή όπως η `sudo iptables` στην αρχή **δεν** κάνει τις επόμενες εντολές που χωρίζονται με shell να εκτελούνται ως root· αυτές εκτελούνται με την ταυτότητα του web worker, εκτός αν ξεχωριστός ενεργός κανόνας sudo επιτρέπει privilege escalation. Επιβεβαιώστε την ταυτότητα του worker, την ακριβή άδεια `sudo -l` και την απαίτηση πιστοποίησης, καθώς και το όριο ορισμάτων της εντολής, προτού ισχυριστείτε ότι υπάρχει διαδρομή προς root. Εξετάστε τον κώδικα και την πολιτική χωρίς να στείλετε probe injection κατά τη συνήθη απαρίθμηση του host.

## Διαπιστευτήρια σύνδεσης σε access logs

Αν μια εφαρμογή υποβάλλει φόρμα σύνδεσης με `GET`, το όνομα χρήστη και ο κωδικός πρόσβασης μπορεί να γίνουν query parameters στο URI του αιτήματος. Ένα αίτημα `POST` μπορεί επίσης να περιέχει query string· η χρήση του `POST` δεν αποκρύπτει ένα μυστικό που τοποθετήθηκε κατά λάθος στο URI, συμπεριλαμβανομένου ενός κωδικού πρόσβασης που καταχωρίστηκε σε άσχετο πεδίο φόρμας. Η [συνηθισμένη γραμμή αιτήματος στο access log του Apache](https://httpd.apache.org/docs/2.4/logs.html) καταγράφει τη μέθοδο και το URI, μαζί με το query string, όταν η ρυθμισμένη μορφή χρησιμοποιεί το `%r`. Επομένως, ένας λογαριασμός με δικαίωμα ανάγνωσης αυτών των logs, για παράδειγμα μέσω της ομάδας `adm` σε ορισμένα συστήματα Linux, μπορεί να εντοπίσει ένα πιθανό διαπιστευτήριο. Ελέγξτε την πραγματική μορφή log και τα δικαιώματα και, στη συνέχεια, επιβεβαιώστε ότι η τιμή είναι μυστικό, ότι ο λογαριασμός την αποδέχεται και ότι παρέχει πρόσβαση πέρα από ένα όριο προνομίων. Μην υποθέτετε ότι έγινε καταγραφή του σώματος του αιτήματος και μην αντιγράφετε πιθανές τιμές σε κοινόχρηστη έξοδο.

Εξετάζετε μόνο αναγνώσιμα access logs και μην εμφανίζετε τιμές διαπιστευτηρίων σε κοινόχρηστη έξοδο εντολών. Οι μεγάλες γραμμές αιτημάτων μπορεί επίσης να περιέχουν referrer και user agent, επομένως ένα φίλτρο σύντομων γραμμών μπορεί να αποκρύψει ακριβώς το αίτημα που αναζητάτε. Οι συνήθεις τοποθεσίες των access logs για Apache, httpd και Nginx είναι οι `/var/log/apache2/access.log`, `/var/log/httpd/access_log` και `/var/log/nginx/access.log`. Τα rotated logs μπορεί να περιέχουν παλαιότερα διαπιστευτήρια. Η [πρόσβαση σε log files μέσω LFI](../../pentesting-web/file-inclusion/README.md#read-access-logs-to-harvest-get-based-auth-tokens-token-replay) είναι μια σχετική διαδρομή προς τα ίδια δεδομένα.

Τα authentication logs εφαρμογών μπορούν επίσης να αποκαλύψουν έναν κωδικό πρόσβασης που καταχωρίστηκε κατά λάθος στο πεδίο **username** μιας αποτυχημένης σύνδεσης. Πρώτα επιβεβαιώστε ότι το log είναι αναγνώσιμο και ότι η μορφή του καταγράφει το υποβληθέν όνομα χρήστη· εξετάστε τοπικά μόνο ένα μικρό σχετικό τμήμα και μην αντιγράφετε πιθανά διαπιστευτήρια σε κοινόχρηστη έξοδο. Ένα όνομα χρήστη που μοιάζει με κωδικό πρόσβασης είναι ένδειξη, όχι απόδειξη έγκυρου κωδικού ή υψηλότερου προνομίου. Επιβεβαιώστε τον λογαριασμό για τον οποίο προορίζεται και τυχόν επαναχρησιμοποίηση στο συγκεκριμένο service ή Unix account προτού ισχυριστείτε ότι υπάρχει μετάβαση.

Ένας εγγράψιμος web login handler χρειάζεται ξεχωριστή εξέταση όταν ένας προγραμματισμένος client με διαφορετική ταυτότητα υποβάλλει διαπιστευτήρια σε αυτό το endpoint. Επιβεβαιώστε δικαίωμα εγγραφής στον **ενεργό** handler, το πραγματικό πρόγραμμα και τη διαδρομή αιτήματος του client, ποιανού διαπιστευτήριο στέλνει και αν ο κωδικός πρόσβασης της εφαρμογής είναι ανεξάρτητα έγκυρος για λογαριασμό λειτουργικού συστήματος με υψηλότερα προνόμια. Μια εγγράψιμη σελίδα ή μια επαναλαμβανόμενη διεργασία από μόνη της δεν αποδεικνύει αυτή τη μετάβαση. Η παθητική απογραφή πρέπει να καταγράφει δικαιώματα διαδρομών και μεταδεδομένα εργασιών, χωρίς αλλαγή του handler ή συλλογή κωδικών πρόσβασης.

Τα EVE JSON logs του Suricata μπορούν επίσης να καταγράφουν τις εντολές FTP `USER` και `PASS` με το `command_data`, όταν είναι ενεργοποιημένη η καταγραφή συμβάντων FTP. Ελέγξτε αν είναι αναγνώσιμα τα `/var/log/suricata/eve*.json*`, συμπεριλαμβανομένων rotated ή συμπιεσμένων αρχείων, προτού εξετάσετε τοπικά ένα μικρό σχετικό τμήμα. Ένα αναγνώσιμο αρχείο EVE είναι απλώς μια ένδειξη: επιβεβαιώστε ότι καταγράφηκαν συμβάντα FTP, ότι τα δεδομένα περιλαμβάνουν αξιοποιήσιμο διαπιστευτήριο και ότι αυτό παρέχει πρόσβαση πέρα από ένα όριο προνομίων. Αποφύγετε την εμφάνιση του `command_data` σε κοινόχρηστη έξοδο απαρίθμησης. Το Suricata τεκμηριώνει τα [πεδία συμβάντων FTP](https://docs.suricata.io/en/suricata-8.0.2/output/eve/eve-json-format.html) και τις [παραλλαγές περιστροφής EVE και ονομάτων αρχείων](https://docs.suricata.io/en/suricata-7.0.15/output/eve/eve-json-output.html).

## Δημιουργημένη ρύθμιση Apache και piped logs

Το [remco](https://github.com/HeavyHorst/remco) μπορεί να παρακολουθεί ένα backend κλειδιού/τιμής, να αποδίδει ένα template σε αρχείο ρυθμίσεων Apache και να εκτελεί μια εντολή επαναφόρτωσης. Εξετάστε την ταυτότητα της διεργασίας remco που εκτελείται, την πηγή και τον προορισμό του ρυθμισμένου template, τα πρόθεματα κλειδιών που παρακολουθούνται και αν μια τιμή του backend εισάγεται απευθείας σε οδηγία Apache, όπως η `ServerName`. Ένας τοπικός listener του backend από μόνος του δεν αποδεικνύει ότι ο τρέχων χρήστης μπορεί να γράψει σε κλειδί που παρακολουθείται· επιβεβαιώστε την πιστοποίηση και τα δικαιώματα του backend προτού ισχυριστείτε ότι υπάρχει privilege escalation.

Μια μη escaped νέα γραμμή σε εγγράψιμη τιμή backend μπορεί να μετατρέψει την τιμή μίας προβλεπόμενης οδηγίας σε πρόσθετες οδηγίες Apache. Τα [piped logs του Apache](https://httpd.apache.org/docs/2.4/logs.html#piped) είναι ιδιαίτερα ευαίσθητα: τα `CustomLog` ή `ErrorLog` με εντολή `|` ξεκινούν ένα helper με την ταυτότητα του γονικού httpd, συχνά ως root· το `|$` ζητά από τον Apache να χρησιμοποιήσει shell. Εξετάστε τη δημιουργημένη ρύθμιση και τη διαδρομή επαναφόρτωσής της χωρίς να αλλάξετε δεδομένα backend ή να επανεκκινήσετε την υπηρεσία κατά την απαρίθμηση. Κρατήστε ιδιωτική την πλήρη εντολή piped, επειδή τα ορίσματά της μπορεί να περιέχουν μυστικά.

## Πιστοποίηση και ταυτότητες υπηρεσιών

Το αρχείο ελέγχου του Monit είναι συνήθως το `~/.monitrc` ή το `/etc/monitrc`, αλλά η παράμετρος `monit -c` μπορεί να επιλέξει διαφορετική διαδρομή. Ένα αναγνώσιμο αρχείο μπορεί να περιέχει εγγραφές `set httpd` και `allow user:password` για το web interface του, συχνά στην τοπική θύρα 2812. Ελέγξτε τον ιδιοκτήτη και τα δικαιώματα του αρχείου προτού το εξετάσετε και μην εμφανίζετε τιμές κωδικών πρόσβασης σε κοινόχρηστη έξοδο απαρίθμησης. Τα διαπιστευτήρια web παρέχουν μόνο τον ρυθμισμένο ρόλο Monit· οι χρήστες μόνο για ανάγνωση δεν μπορούν να εκτελέσουν ενέργειες ελέγχου. Για ξεχωριστό privilege escalation μέσω Unix account απαιτείται επιβεβαιωμένη επαναχρησιμοποίηση κωδικού πρόσβασης ή προνομιούχα ενέργεια Monit που μπορεί όντως να εκκινήσει ο πιστοποιημένος ρόλος. Δείτε την [τεκμηρίωση του αρχείου ελέγχου και της πιστοποίησης του Monit](https://www.mmonit.com/monit/documentation/monit.html).

Για το Webmin, το `/etc/webmin/miniserv.conf` προσδιορίζει τις ρυθμίσεις του server και το `/etc/webmin/webmin.acl` καταγράφει σε ποιες λειτουργικές μονάδες μπορούν να έχουν πρόσβαση οι χρήστες· το [Webmin τεκμηριώνει τα όρια εκχώρησης δικαιωμάτων λειτουργικών μονάδων](https://webmin.com/docs/development/creating-modules/). Ένας Unix κωδικός πρόσβασης ή ένα αναγνώσιμο αρχείο ACL δεν παρέχει από μόνο του συνεδρία Webmin. Επιβεβαιώστε την πραγματική αντιστοίχιση πιστοποίησης, τον προσβάσιμο listener, τον πιστοποιημένο λογαριασμό, τα ενεργά δικαιώματα της λειτουργικής μονάδας Package Updates, τον εγκατεστημένο κώδικα ή τη διόρθωση του κατασκευαστή και την ταυτότητα της διεργασίας Webmin. Σε επηρεαζόμενες εκδόσεις έως και την 1.910, το [CVE-2019-12840](https://nvd.nist.gov/vuln/detail/CVE-2019-12840) επέτρεπε σε λογαριασμό με δικαιώματα σε αυτή τη λειτουργική μονάδα να εκτελεί εντολές μέσω του handler ενημερώσεων. Κατά την παθητική απαρίθμηση, αναφέρετε τις διαδρομές ρυθμίσεων και τα δικαιώματα χωρίς να εμφανίζετε διαπιστευτήρια ή να επιχειρείτε ενημέρωση.

```bash
find /etc/pam.d /etc/sssd /etc/postfix -maxdepth 2 -type f -ls 2>/dev/null
systemctl cat sssd postfix jenkins 2>/dev/null
getent passwd
```

- Το [PAM](pam-pluggable-authentication-modules.md) διέπει τον έλεγχο ταυτότητας ανά υπηρεσία· διαδρομές πολιτικών ή modules με δικαίωμα εγγραφής μπορούν να αλλάξουν τη συμπεριφορά σύνδεσης.
- Η ρύθμιση LDAP/SSSD μπορεί να αποκαλύψει endpoints καταλόγου, identities σύνδεσης και κανόνες πρόσβασης. Ένας κωδικός πρόσβασης σύνδεσης που ανακτήθηκε μπορεί να επιτρέψει ερωτήματα LDAP πέρα από τον τρέχοντα λογαριασμό OS· δοκιμάστε το ακριβές identity σύνδεσης και τα ACL του καταλόγου. Ελέγξτε τα δικαιώματα αρχείων πριν επιθεωρήσετε secrets· τα [Linux Active Directory](../user-information/linux-active-directory.md) και [FreeIPA](freeipa-pentesting.md) καλύπτουν τη χρήση tickets και καταλόγων.
- Τα aliases του Postfix μπορούν να προωθήσουν τα εισερχόμενα μηνύματα σε τοπικές εντολές. Αν ένας χρήστης με χαμηλότερα δικαιώματα μπορεί να αλλάξει το σχετικό script, η παράδοση αλληλογραφίας μπορεί να εκτελέσει τον κώδικά του με το identity παράδοσης. Ελέγξτε τους χάρτες aliases και την ιδιοκτησία των scripts πριν ισχυριστείτε ότι αυτή η διαδρομή είναι εφικτή· δείτε το [SMTP and mail service testing](../../network-services-pentesting/pentesting-smtp/README.md).
- Τα Jenkins και άλλες υπηρεσίες CI μπορεί να εκτελούν jobs με ισχυρό τοπικό λογαριασμό. Εξετάστε τον χρήστη της υπηρεσίας, τις διαδρομές job/workspace με δικαίωμα εγγραφής και το τοπικό interface διαχείρισης πριν δοκιμάσετε ένα pipeline ή plugin. Εξετάστε επίσης τα **credentials που είναι διαθέσιμα σε ένα job** και τον λογαριασμό με τον οποίο μπορούν να κάνουν authenticate: ένα Pipeline που χρησιμοποιεί το [SSH Agent step](https://www.jenkins.io/doc/pipeline/steps/ssh-agent/) μπορεί να αποκτήσει πρόσβαση σε host ως ο χρήστης του SSH credential, ακόμη κι όταν το ίδιο το Jenkins εκτελείται με λιγότερα δικαιώματα Unix. Επιβεβαιώστε ότι το τρέχον identity του Jenkins έχει `Job/Create`, `Job/Configure` ή κάποια άλλη αποτελεσματική δυνατότητα να αλλάξει το Pipeline, ότι το credential βρίσκεται εντός του scope αυτού του job και ότι ο λογαριασμός SSH του target δέχεται το key, προτού ισχυριστείτε privilege escalation σε host. Το όνομα εμφάνισης ή το ID ενός credential από μόνο του δεν τεκμηριώνει καμία από αυτές τις προϋποθέσεις. Το Jenkins προειδοποιεί ότι οι δημιουργοί jobs και, συχνά, όσοι ρυθμίζουν jobs μπορούν να χρησιμοποιήσουν αυθαίρετα τα credentials που είναι διαθέσιμα στο scope τους· επομένως, το [credential scope](https://www.jenkins.io/doc/book/security/credentials/) και το [Pipeline trust](https://www.jenkins.io/doc/book/security/securing-org-folders-and-multibranch-pipelines/) είναι εξίσου σημαντικά με το UID της υπηρεσίας. Μην συμπεριλαμβάνετε τιμές credentials και private keys σε κοινόχρηστα αποτελέσματα enumeration.

## API provisioning του Cobbler

Η υπηρεσία διαχείρισης του Cobbler εκθέτει ένα XML-RPC API, συνήθως στη θύρα `25151`. Ελέγξτε τον listener και τον ιδιοκτήτη της διεργασίας `cobblerd` πριν αξιολογήσετε τον αντίκτυπό του· ένα API που δέχεται συνδέσεις μόνο από loopback παραμένει προσβάσιμο σε χρήστη του host. Εξετάστε τα modules authentication και authorization στο `/etc/cobbler/modules.conf`, τις ρυθμίσεις της υπηρεσίας στο `/etc/cobbler/settings` ή στο `/etc/cobbler/settings.yaml` και τα δικαιώματα στα `/etc/cobbler/users.conf`, `/etc/cobbler/users.digest` και `/var/lib/cobbler/web.ss`. Τα αρχεία digest και shared-secret περιέχουν στοιχεία credentials, επομένως καταγράψτε αν είναι αναγνώσιμα χωρίς να εμφανίζετε το περιεχόμενό τους από προεπιλογή.

```bash
ps -eo user,pid,args | grep '[c]obblerd'
ss -ltn 2>/dev/null | grep ':25151'
for file in /etc/cobbler/modules.conf /etc/cobbler/settings /etc/cobbler/settings.yaml \
            /etc/cobbler/users.conf /etc/cobbler/users.digest /var/lib/cobbler/web.ss; do
    [ -e "$file" ] && ls -l "$file"
done
```

**CVE-2024-47533** είναι παράκαμψη ελέγχου ταυτότητας XML-RPC στο Cobbler 3.0.0 έως 3.2.2 και 3.3.0 έως 3.3.6. Ένα σφάλμα ανάγνωσης του shared secret επέστρεφε την προβλέψιμη τιμή `-1`, την οποία το API δεχόταν ως κωδικό πρόσβασης. Οι αντίστοιχες διορθώσεις είναι οι εκδόσεις 3.2.3 και 3.3.7. Η έκδοση ενός πακέτου αποτελεί ένδειξη· πριν αναφέρετε έκθεση, επαληθεύστε τον κώδικα που έχει εγκατασταθεί και τυχόν backported διόρθωση.

Μια αυθεντικοποιημένη συνεδρία API μπορεί να αποτελέσει διαδρομή εκτέλεσης με αυξημένα προνόμια όταν το `cobblerd` εκτελείται ως root. Σε ευάλωτες υλοποιήσεις, το `background_import` περνά ελεγχόμενα από τον χρήστη `rsync_flags` σε μια εντολή shell, ενώ η απόδοση ενός προτύπου autoinstall Cheetah που ελέγχεται από τον χρήστη μπορεί να εκτελέσει Python. Ελέγξτε τα δικαιώματα του API και την εγκατεστημένη έκδοση πριν δοκιμάσετε οποιαδήποτε από τις δύο διαδρομές. Περιορίστε την πρόσβαση στο management API, εγκαταστήστε τη διόρθωση για την παράκαμψη ελέγχου ταυτότητας και διασφαλίστε ότι τα αρχεία ρυθμίσεων και διαπιστευτηρίων είναι αναγνώσιμα μόνο από τους διαχειριστές της υπηρεσίας.

## Τοπικοί AWS emulators και αποθηκευμένα διαπιστευτήρια

Ένας χρήστης του host ενδέχεται να μπορεί να προσεγγίσει έναν AWS-compatible emulator που εκτελείται σε container μέσω του δημοσιευμένου endpoint loopback. Πριν αξιολογήσετε την πρόσβαση στο [Secrets Manager](https://docs.localstack.cloud/aws/services/secretsmanager/) ή στο [KMS](https://docs.localstack.cloud/aws/services/kms/), συσχετίστε τον ενεργό listener, το endpoint και τον λογαριασμό που επιλέγει ο client, καθώς και τις εγκατεστημένες ρυθμίσεις εξουσιοδότησης του emulator. Στο LocalStack, [η επιβολή IAM policy είναι ξεχωριστή ρύθμιση](https://docs.localstack.cloud/aws/developer-tools/security-testing/iam-policy-enforcement/)· μην συμπεραίνετε τα πραγματικά δικαιώματα API μόνο από ένα αρχείο διαπιστευτηρίων, ένα IAM policy ή έναν listener. Επιβεβαιώστε τη συμπεριφορά της εγκατεστημένης έκδοσης και των ρυθμίσεων.

Ένα αποθηκευμένο secret είναι χρήσιμο για τοπική κλιμάκωση προνομίων μόνο αν η τρέχουσα ταυτότητα API μπορεί να το ανακτήσει και ένας ξεχωριστός λογαριασμός με υψηλότερα προνόμια αποδέχεται το ανακτημένο διαπιστευτήριο. Ένα κρυπτογραφημένο τοπικό blob απαιτεί επίσης δικαίωμα ανάγνωσης του αρχείου, το αντίστοιχο διαθέσιμο KMS key και algorithm, καθώς και πραγματικό δικαίωμα αποκρυπτογράφησης. Για ένα [asymmetric KMS key](https://docs.aws.amazon.com/cli/latest/reference/kms/decrypt.html), το αίτημα αποκρυπτογράφησης πρέπει να προσδιορίζει τον algorithm που χρησιμοποιήθηκε για την κρυπτογράφηση του blob. Περιορίστε την αυτόματη καταγραφή στοιχείων του host σε τεκμήρια σχετικά με διεργασίες, listeners, διαδρομές ρυθμίσεων και δικαιώματα αρχείων· κατά τη συνήθη απογραφή μην ζητάτε ούτε εμφανίζετε τιμές secret ή αποκρυπτογραφημένο plaintext.
