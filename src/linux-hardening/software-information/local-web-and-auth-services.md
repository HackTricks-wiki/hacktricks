# Τοπικές υπηρεσίες Web και αυθεντικοποίησης

{{#include ../../banners/hacktricks-training.md}}

Ένα Linux shell παρέχει μια εικόνα από την πλευρά του host για τις υπηρεσίες Web και αυθεντικοποίησης: ορίσματα διεργασιών, listeners, αρχεία μονάδων, ρυθμίσεις, logs και διεπαφές που είναι προσβάσιμες μόνο τοπικά. Χρησιμοποιήστε αυτή την εικόνα για να συνδέσετε μια προσβάσιμη υπηρεσία με τον λογαριασμό και τα αρχεία που πράγματι χρησιμοποιεί.

## Χαρτογραφήστε την τοπική στοίβα Web

```bash
ss -lntup
ps -eo user,pid,args | grep -E '[a]pache|[n]ginx|[p]hp-fpm|[j]enkins'
systemctl list-units --type=service --state=running 2>/dev/null
find /etc/apache2 /etc/httpd /etc/nginx -maxdepth 3 -type f 2>/dev/null | head -80
```

Εξετάστε τα ονόματα virtual host, τα document root, τις διαδρομές proxy, τους καταλόγους μεταφόρτωσης, τις ρυθμίσεις εκτέλεσης PHP και τα αρχεία ρυθμίσεων που περιέχουν διαπιστευτήρια. Ένας listener loopback μπορεί να είναι προσβάσιμος μέσω proxy ή SSH tunnel. Για να δοκιμάσετε ένα ονομασμένο virtual host σε τοπικό listener, στείλτε την προβλεπόμενη κεφαλίδα `Host` ή χρησιμοποιήστε το `curl --resolve` με τη σωστή διεύθυνση και θύρα. Η απαρίθμηση virtual host μπορεί επίσης να αποκαλύψει ονόματα που απουσιάζουν από την προεπιλεγμένη απόκριση. Ελέγξτε αν το Apache επιτρέπει παρακάμψεις μέσω `.htaccess` και αν οι διαδρομές μεταφόρτωσης μπορούν να εκτελέσουν PHP, προτού θεωρήσετε ότι ένας εγγράψιμος κατάλογος μεταφόρτωσης επιτρέπει εκτέλεση κώδικα. Ένας αναπτυγμένος JavaScript source map μπορεί να αποκαλύψει διαδρομές πηγαίου κώδικα ή client-side secrets· αντιμετωπίστε τις τιμές που ανακτώνται ως ενδείξεις και επαληθεύστε τα πραγματικά δικαιώματά τους. Για ελέγχους ειδικά για web, δείτε τα [Apache](../../network-services-pentesting/pentesting-web/apache.md) και [Nginx](../../network-services-pentesting/pentesting-web/nginx.md).

Για Apache με [mpm-itk](https://mpm-itk.sesse.net/), ένα ενεργό `AssignUserID` μπορεί να εκτελέσει ένα virtual host ως διαφορετικός χρήστης και ομάδα. Αν ένας λογαριασμός με λιγότερα δικαιώματα μπορεί να γράψει ένα script στο `DocumentRoot` αυτού του host, εξετάστε αν κάποια προσβάσιμη διαδρομή το εκτελεί πράγματι με την εκχωρημένη ταυτότητα. Επιβεβαιώστε ότι το module είναι φορτωμένο, την ενεργή ρύθμιση του virtual host (συμπεριλαμβανομένων των παρακάμψεων ταυτότητας βάσει expression), τα δικαιώματα εγγραφής και αναζήτησης στον κατάλογο, τον script handler και την πρόσβαση στον listener. Μια επισημασμένη οδηγία ή ένας εγγράψιμος κατάλογος από μόνα τους δεν αποδεικνύουν εκτέλεση μεταξύ χρηστών.

Ένας home directory που δημοσιεύεται μέσω web server μπορεί να εκθέσει αντίγραφα ασφαλείας αρχείων SSH identity, ακόμη κι όταν ο ενεργός κατάλογος `.ssh` είναι ιδιωτικός. Για παράδειγμα, η ρύθμιση `homedirs_public` του [Nostromo](https://www.nazgul.ch/dev/nostromo_man.html) επιλέγει έναν υποκατάλογο που εξυπηρετείται από τους home directories των χρηστών. Ένα εύρημα που βασίζεται μόνο στη διαδρομή ενός archive αποτελεί ένδειξη: επαληθεύστε την ενεργή αντιστοίχιση του server, την τοπική δυνατότητα ανάγνωσης ή την εξουσιοδότηση HTTP, τα περιεχόμενα του archive, το passphrase του private key και αν ο αντίστοιχος λογαριασμός αποδέχεται πράγματι το κλειδί. Μην εξάγετε archives ή εμφανίζετε υλικό κλειδιών κατά τη συνήθη απαρίθμηση host.

Ένα αναγνώσιμο αντίγραφο ασφαλείας μιας τοπικής web app με αυξημένα δικαιώματα μπορεί να αποκαλύψει τη λογική authentication και ανάγνωσης αρχείων, ακόμη κι όταν ο ενεργός πηγαίος κώδικας δεν είναι προσβάσιμος. Συγκρίνετε το αντίγραφο ασφαλείας με την αναπτυγμένη υπηρεσία προτού βασιστείτε σε αυτό. Ειδικότερα, αξίζει να εξεταστεί ένα cookie που δημιουργείται κρυπτογραφώντας κείμενο ελεγχόμενο από τον καλούντα και έπειτα ένα secret και μια σημαία role, αν η εφαρμογή χρησιμοποιεί deterministic ECB blocks, επιστρέφει νέα cookies για επιλεγμένο κείμενο και αργότερα διαχωρίζει την αποκρυπτογραφημένη τιμή με delimiter που δεν έχει γίνει escape. Το [NIST εξηγεί την ανεξάρτητη και επαναλαμβανόμενη αντιστοίχιση block του ECB](https://csrc.nist.gov/news/2022/proposal-to-revise-sp-800-38a)· αυτή η ιδιότητα μπορεί να υποστηρίξει σύγκριση με επιλεγμένη είσοδο, αλλά από μόνη της δεν παρέχει υψηλότερο role. Επιβεβαιώστε την ενεργή διαδρομή, τις προϋποθέσεις session, τον ακριβή parser και τη ροή δεδομένων, την ταυτότητα της υπηρεσίας και μια ξεχωριστή προνομιούχα ενέργεια ή διαδρομή ανάγνωσης αρχείων. Η παθητική απογραφή πρέπει να αναφέρει τα metadata των αντιγράφων ασφαλείας και την ιδιοκτησία των listener, χωρίς ανάγνωση των περιεχομένων των archive ή αποστολή authentication probes.

Η ίδια προσέγγιση ελέγχου πηγαίου κώδικα ισχύει για μια προνομιούχα τοπική υπηρεσία **μη-HTTP** loopback, όπως μια custom διεπαφή που βασίζεται σε SSH. Αν ένα προσβάσιμο αντίγραφο ασφαλείας του πηγαίου κώδικα δείχνει μια εντολή που δέχεται διαδρομή αρχείου επιλεγμένη από τον καλούντα, ελέγξτε το authentication gate, τον τρόπο επίλυσης της διαδρομής και αν διασφαλίζεται ότι το αρχείο που προκύπτει παραμένει κάτω από τον προβλεπόμενο κατάλογο πριν ανοιχτεί. Στη Go, το [`filepath.Join`](https://pkg.go.dev/path/filepath#Join) καθαρίζει μια διαδρομή, αλλά δεν επιβάλλει αυτόν τον περιορισμό. Επιβεβαιώστε ότι το αντίγραφο ασφαλείας αντιστοιχεί στο build που εκτελείται, ότι ο listener είναι προσβάσιμος, ότι ο λογαριασμός με λιγότερα δικαιώματα μπορεί να χρησιμοποιήσει την εντολή και ότι η διεργασία μπορεί να διαβάσει τον στόχο· η κατοχή ενός αναγνώσιμου SSH key είναι ξεχωριστό ζήτημα πολιτικής σύνδεσης. Αναφέρετε τις διαδρομές των source archive και την ιδιοκτησία της υπηρεσίας χωρίς να εξάγετε περιεχόμενα ή κλειδιά archive σε αυτοματοποιημένη έξοδο.

Ένα PHP-FPM pool που ακούει σε TCP loopback μπορεί να είναι προσβάσιμο από άλλον τοπικό λογαριασμό, ακόμη κι όταν ο ιστότοπός του απαιτεί authentication. Το [PHP προειδοποιεί ότι ένας client που μπορεί να συνδεθεί στο FastCGI μπορεί να ελέγξει ρυθμίσεις request, συμπεριλαμβανομένου του `auto_prepend_file`](https://www.php.net/manual/en/install.fpm.php). Εξετάστε τις ρυθμίσεις `listen` και `listen.allowed_clients` του pool μαζί με τον ενεργό listener, το worker UID, μια υπάρχουσα διαδρομή script και τυχόν περιορισμούς `security.limit_extensions` ή `php_admin_value`. Τα αρχεία ρυθμίσεων του pool μπορεί να περιέχουν διαπιστευτήρια σε οδηγίες `env[...]`, επομένως η αυτοματοποιημένη απογραφή πρέπει να αναφέρει τις διαδρομές τους και όχι τα περιεχόμενά τους. Ένα αρχείο ρυθμίσεων ή μια θύρα από μόνα τους δεν αποδεικνύουν διαδρομή εκτέλεσης μεταξύ χρηστών· δείτε τον οδηγό [FastCGI](../../network-services-pentesting/9000-pentesting-fastcgi.md) για λεπτομέρειες πρωτοκόλλου.

Για ένα προνομιούχο τοπικό API, εξετάστε τη ροή εξουσιοδότησης καθώς και την εκτέλεση κώδικα. Ένας ρόλος database που μπορεί να αλλάξει ο λογαριασμός με λιγότερα δικαιώματα ενδέχεται να ξεκλειδώσει μια διαδρομή API, αλλά το επόμενο όριο εξαρτάται από την υλοποίηση της διαδρομής. Για παράδειγμα, η συγχώνευση JSON request σε ένα JavaScript object και στη συνέχεια η κλήση του [`child_process.exec`](https://nodejs.org/api/child_process.html) αξίζει να εξεταστεί για [ροή δεδομένων από prototype pollution σε εκτέλεση](../../pentesting-web/deserialization/nodejs-proto-prototype-pollution/prototype-pollution-to-rce.md). Επαληθεύστε την πραγματική βιβλιοθήκη/έκδοση συγχώνευσης, την επικύρωση εισόδου, την προσβάσιμη διαδρομή, την ταυτότητα της διεργασίας και τις επιλογές child process· ένας listener Node που ανήκει στο root ή το όνομα μιας ευάλωτης εξάρτησης αποτελούν απλώς ενδείξεις.

Τα file-backed CMS μπορεί να αποθηκεύουν επαληθευτές κωδικών πρόσβασης διαχειριστών έξω από τα συμβατικά αρχεία ρυθμίσεων `.php`. Παραδείγματα είναι το `data/database.js` ενός ιστότοπου ή το `data/settings/pass.php`. Ελέγξτε την ιδιοκτησία και τη δυνατότητα ανάγνωσης των αρχείων πριν από μη αυτόματο έλεγχο και μην συμπεριλαμβάνετε hashes σε αυτοματοποιημένη κοινόχρηστη έξοδο. Ένας κωδικός πρόσβασης εφαρμογής που μπορεί να ανακτηθεί αποτελεί ξεχωριστό όριο δικαιωμάτων από έναν λογαριασμό Unix: επαληθεύστε τυχόν ισχυρισμό περί επαναχρησιμοποίησης για τον συγκεκριμένο λογαριασμό και την επιτρεπόμενη μέθοδο authentication.

Ο authentication controller μιας εφαρμογής μπορεί επίσης να περιέχει κυριολεκτικό κωδικό πρόσβασης σύνδεσης στον πηγαίο κώδικα αντί σε αρχείο ρυθμίσεων. Αν ένας χρήστης με λιγότερα δικαιώματα μπορεί να διαβάσει τον ενεργό controller, εξετάστε τοπικά τη σύγκριση authentication και μην συμπεριλάβετε καμία τιμή σε κοινόχρηστη έξοδο απαρίθμησης. Επιβεβαιώστε ότι η διαδρομή κώδικα είναι ενεργή, ότι ο κωδικός πρόσβασης είναι έγκυρος για την εφαρμογή και ότι ένας ξεχωριστός λογαριασμός Unix με περισσότερα δικαιώματα αποδέχεται πράγματι τον ίδιο κωδικό, προτού ισχυριστείτε τοπική κλιμάκωση δικαιωμάτων. Ένα όνομα αρχείου controller αποτελεί μόνο ένδειξη προς διερεύνηση.

Το Dolibarr αποθηκεύει τις ρυθμίσεις σύνδεσης στη database, συμπεριλαμβανομένου του `dolibarr_main_db_pass`, στο `htdocs/conf/conf.php` ([αναφορά ρυθμίσεων](https://wiki.dolibarr.org/index.php/Configuration_file)). Ένα αναγνώσιμο αρχείο αποτελεί ένδειξη για διαπιστευτήρια· μόνο μια ξεχωριστά επαληθευμένη επαναχρησιμοποίηση κωδικού λογαριασμού ή κάποιο άλλο δικαίωμα στη database θα το μετέτρεπε σε τοπική κλιμάκωση δικαιωμάτων. Ελέγξτε πρώτα τα δικαιώματα και αποφύγετε την εμφάνιση της τιμής σε αυτοματοποιημένη έξοδο.

Το αρχείο ρυθμίσεων του Linux package του GitLab είναι συνήθως το `/etc/gitlab/gitlab.rb`, αν και οι εγκαταστάσεις ενδέχεται να διατηρούν αναγνώσιμα αντίγραφα και αλλού. Το [GitLab τεκμηριώνει](https://docs.gitlab.com/omnibus/settings/smtp/) ότι αυτό το αρχείο μπορεί να περιέχει το `gitlab_rails['smtp_password']`, παρόλο που οι κρυπτογραφημένες ρυθμίσεις SMTP ενδέχεται να διατηρούν τον κωδικό πρόσβασης εκτός του plaintext αρχείου. Αντιμετωπίστε ένα αναγνώσιμο αρχείο ρυθμίσεων ως ένδειξη για διαπιστευτήρια: επαληθεύστε ότι είναι ενεργό, ότι τα διαπιστευτήρια ισχύουν ακόμη και ότι ένας συγκεκριμένος λογαριασμός με περισσότερα δικαιώματα τα αποδέχεται, προτού ισχυριστείτε επαναχρησιμοποίηση κωδικού πρόσβασης. Ξεχωριστά, το [GitLab εκτελεί το `gitlab.rb` ως κώδικα Ruby με δικαιώματα root κατά το `gitlab-ctl reconfigure`](https://docs.gitlab.com/omnibus/settings/configuration/)· ένα εγγράψιμο ενεργό αρχείο ή ένα συμπεριλαμβανόμενο `from_file` απαιτεί πραγματική δυνατότητα προνομιούχου reconfigure προτού συνιστά εύρημα εκτέλεσης. Η προεπισκόπηση ρυθμίσεων μπορεί να αποκαλύψει τιμές διαπιστευτηρίων, επομένως αντιμετωπίστε την έξοδό της ως ευαίσθητη και κοινοποιήστε μόνο διαδρομές και δικαιώματα.

Μια self-hosted εγκατάσταση Mattermost μπορεί να διατηρεί το `SqlSettings.DataSource` στο `/opt/mattermost/config/config.json`· το [Mattermost τεκμηριώνει](https://docs.mattermost.com/deployment-guide/server/troubleshooting) τόσο αυτή τη συνήθη διαδρομή όσο και εγκαταστάσεις που αποθηκεύουν την ενεργή ρύθμιση σε database. Ένα αναγνώσιμο αρχείο μπορεί να αποκαλύψει διαπιστευτήριο database της εφαρμογής, αλλά δεν αποδεικνύει πρόσβαση στη database ή πρόσβαση root στο Unix. Επαληθεύστε την ενεργή πηγή ρυθμίσεων, τα πραγματικά δικαιώματα του ρόλου database, τυχόν κωδικό πρόσβασης εφαρμογής που ανακτήθηκε ξεχωριστά και αν αυτός ο κωδικός λειτουργεί για συγκεκριμένο λογαριασμό Unix με περισσότερα δικαιώματα. Η μορφή password hash μπορεί να αλλάζει μεταξύ εκδόσεων Mattermost· κατά την απαρίθμηση, καταγράψτε τη διαδρομή των ρυθμίσεων και τα metadata πρόσβασης χωρίς να εμφανίζετε το connection string ή να υποβάλλετε ερωτήματα στη database.

```bash
curl -i -H 'Host: admin.example.local' http://127.0.0.1:8080/
ffuf -w wordlist.txt -u http://127.0.0.1:8080/ -H 'Host: FUZZ.example.local' -fs 1234 # replace 1234 with the default response size
grep -R 'sourceMappingURL' /var/www /opt 2>/dev/null | head
```

Φιλτράρετε τα αποτελέσματα virtual-host σε σχέση με το μέγεθος της προεπιλεγμένης απόκρισης ή με κάποιο άλλο σταθερό σημείο αναφοράς, ώστε να μη φαίνεται έγκυρο κάθε όνομα που μαντεύετε. Ένας source map είναι χρήσιμος μόνο αν έχει πράγματι αναπτυχθεί ή είναι με άλλο τρόπο αναγνώσιμος.

Οι reverse proxy μπορούν να αλλάξουν τις κεφαλίδες client που εμπιστεύεται μια εφαρμογή. Συγκρίνετε απευθείας αιτήματα με αιτήματα μέσω proxy, προτού υποθέσετε ότι κεφαλίδες όπως `X-Forwarded-For`, `X-Forwarded-Host` ή παρόμοιες καθορίζουν την ταυτότητα του αιτούντος. Εξετάστε από κοινού τις ρυθμίσεις του proxy και της εφαρμογής.

Αν η PHP αντιγράφει το `$_SERVER['HTTP_X_FORWARDED_FOR']` σε μια συμβολοσειρά που μεταβιβάζεται στη [`system()`](https://www.php.net/manual/en/function.system.php), ελέγξτε αν η προσβάσιμη διαδρομή αιτήματος επιτρέπει κεφαλίδα που παρέχεται από τον καλούντα και αν οι μεταχαρακτήρες του shell περνούν σε αυτή τη συμβολοσειρά αμετάβλητοι. Μια εντολή όπως `sudo iptables` στην αρχή **δεν** κάνει τις μεταγενέστερες εντολές που χωρίζονται από το shell να εκτελούνται ως root· αυτές εκτελούνται με την ταυτότητα του web worker, εκτός αν υπάρχει ξεχωριστός ισχύων κανόνας sudo που επιτρέπει κλιμάκωση. Επιβεβαιώστε την ταυτότητα του worker, την ακριβή άδεια `sudo -l` και την απαίτηση ταυτοποίησης, καθώς και το όριο ορισμάτων της εντολής, προτού ισχυριστείτε ότι υπάρχει διαδρομή προς root. Επιθεωρήστε τον πηγαίο κώδικα και την πολιτική χωρίς να στείλετε probe injection κατά τη συνήθη απαρίθμηση του host.

## Διαπιστευτήρια σύνδεσης σε access logs

Αν μια εφαρμογή υποβάλλει φόρμα σύνδεσης με `GET`, το όνομα χρήστη και ο κωδικός πρόσβασης μπορεί να γίνουν παράμετροι query στο URI του αιτήματος. Ένα αίτημα `POST` μπορεί επίσης να περιέχει query string· η χρήση του `POST` δεν αποκρύπτει ένα μυστικό που τοποθετήθηκε κατά λάθος στο URI, συμπεριλαμβανομένου ενός κωδικού πρόσβασης που καταχωρίστηκε σε άσχετο πεδίο φόρμας. Η [συνηθισμένη γραμμή αιτήματος του access log του Apache](https://httpd.apache.org/docs/2.4/logs.html) καταγράφει τη μέθοδο και το URI, μαζί με το query string, όταν η διαμορφωμένη μορφή χρησιμοποιεί `%r`. Επομένως, ένας λογαριασμός που επιτρέπεται να διαβάζει αυτά τα logs, για παράδειγμα μέσω της ομάδας `adm` σε ορισμένα συστήματα Linux, μπορεί να εντοπίσει ένα πιθανό διαπιστευτήριο. Ελέγξτε την πραγματική μορφή του log και τα δικαιώματα και, στη συνέχεια, επαληθεύστε ότι η τιμή είναι μυστικό, ότι ο λογαριασμός την αποδέχεται και ότι επιτρέπει μετάβαση ορίου προνομίων. Μην υποθέτετε ότι καταγράφηκε το σώμα του αιτήματος και μην αντιγράφετε πιθανές τιμές σε κοινόχρηστη έξοδο.

Επιθεωρείτε μόνο αναγνώσιμα access logs και μην εμφανίζετε τιμές διαπιστευτηρίων σε κοινόχρηστη έξοδο εντολών. Οι μεγάλες γραμμές αιτημάτων μπορεί επίσης να περιέχουν referrer και user agent, οπότε ένα φίλτρο σύντομων γραμμών μπορεί να αποκρύψει ακριβώς το αίτημα που σας ενδιαφέρει. Οι συνήθεις θέσεις των access logs για Apache, httpd και Nginx είναι `/var/log/apache2/access.log`, `/var/log/httpd/access_log` και `/var/log/nginx/access.log`. Τα περιστραμμένα logs μπορεί να περιέχουν παλαιότερα διαπιστευτήρια. Η [πρόσβαση σε αρχεία log μέσω LFI](../../pentesting-web/file-inclusion/README.md#read-access-logs-to-harvest-get-based-auth-tokens-token-replay) είναι μια σχετική διαδρομή προς τα ίδια δεδομένα.

Τα logs ταυτοποίησης της εφαρμογής μπορεί επίσης να αποκαλύψουν έναν κωδικό πρόσβασης που καταχωρίστηκε κατά λάθος στο πεδίο **ονόματος χρήστη** μιας αποτυχημένης σύνδεσης. Πρώτα εξακριβώστε ότι το log είναι αναγνώσιμο και ότι η μορφή του καταγράφει το υποβληθέν όνομα χρήστη· επιθεωρήστε τοπικά μόνο ένα μικρό σχετικό απόσπασμα και μην αντιγράφετε πιθανά διαπιστευτήρια σε κοινόχρηστη έξοδο. Ένα όνομα χρήστη που μοιάζει με κωδικό πρόσβασης είναι ένδειξη, όχι απόδειξη έγκυρου κωδικού πρόσβασης ή υψηλότερου προνομίου. Επαληθεύστε τον προβλεπόμενο λογαριασμό και τυχόν επαναχρησιμοποίηση κωδικού στη συγκεκριμένη υπηρεσία ή στον λογαριασμό Unix προτού ισχυριστείτε ότι υπάρχει μετάβαση.

Ένας τροποποιήσιμος χειριστής σύνδεσης web χρειάζεται ξεχωριστό έλεγχο, όταν ένας προγραμματισμένος client με άλλη ταυτότητα υποβάλλει διαπιστευτήρια σε αυτό το endpoint. Επιβεβαιώστε δικαίωμα εγγραφής στον **ενεργό** χειριστή, το πραγματικό χρονοδιάγραμμα του client και τη διαδρομή του αιτήματος, ποιανού διαπιστευτήριο στέλνει και αν αυτός ο κωδικός πρόσβασης της εφαρμογής είναι ανεξάρτητα έγκυρος για λογαριασμό λειτουργικού συστήματος με υψηλότερα προνόμια. Μια τροποποιήσιμη σελίδα ή μια επαναλαμβανόμενη διεργασία από μόνη της δεν τεκμηριώνει αυτή τη μετάβαση. Η παθητική απογραφή πρέπει να αναφέρει τα δικαιώματα διαδρομής και τα μεταδεδομένα της εργασίας, χωρίς να τροποποιεί τον χειριστή ή να συλλέγει κωδικούς πρόσβασης.

Τα logs EVE JSON του Suricata μπορούν επίσης να καταγράφουν τις εντολές FTP `USER` και `PASS` μαζί με το `command_data`, όταν είναι ενεργή η καταγραφή συμβάντων FTP. Ελέγξτε πρώτα αν είναι αναγνώσιμα τα `/var/log/suricata/eve*.json*`, συμπεριλαμβανομένων περιστραμμένων ή συμπιεσμένων αρχείων, προτού εξετάσετε τοπικά ένα μικρό σχετικό απόσπασμα. Ένα αναγνώσιμο αρχείο EVE είναι απλώς μια ένδειξη: επιβεβαιώστε ότι καταγράφηκαν συμβάντα FTP, ότι τα δεδομένα περιλαμβάνουν αξιοποιήσιμο διαπιστευτήριο και ότι επιτρέπουν μετάβαση ορίου προνομίων. Αποφύγετε την εμφάνιση του `command_data` σε κοινόχρηστη έξοδο απαρίθμησης. Το Suricata τεκμηριώνει τα [πεδία συμβάντων FTP](https://docs.suricata.io/en/suricata-8.0.2/output/eve/eve-json-format.html) και τις [παραλλαγές περιστροφής και ονοματοδοσίας του EVE](https://docs.suricata.io/en/suricata-7.0.15/output/eve/eve-json-output.html).

## Δημιουργημένες ρυθμίσεις Apache και piped logs

Το [remco](https://github.com/HeavyHorst/remco) μπορεί να παρακολουθεί ένα backend key/value, να αποδίδει ένα template σε αρχείο ρυθμίσεων Apache και να εκτελεί μια εντολή επαναφόρτωσης. Εξετάστε την ταυτότητα της διεργασίας remco που εκτελείται, την πηγή και τον προορισμό του ρυθμισμένου template, τα προθέματα των παρακολουθούμενων keys και αν μια τιμή από το backend εισάγεται απευθείας σε μια οδηγία Apache, όπως το `ServerName`. Ένας τοπικός listener backend από μόνος του δεν αποδεικνύει ότι ο τρέχων χρήστης μπορεί να γράψει σε παρακολουθούμενο key· επαληθεύστε τον έλεγχο ταυτοποίησης και τα δικαιώματα του backend προτού ισχυριστείτε ότι υπάρχει κλιμάκωση.

Μια μη escaped νέα γραμμή σε τροποποιήσιμη τιμή του backend μπορεί να μετατρέψει μία προβλεπόμενη τιμή οδηγίας σε πρόσθετες οδηγίες Apache. Τα [piped logs του Apache](https://httpd.apache.org/docs/2.4/logs.html#piped) είναι ιδιαίτερα ευαίσθητα: τα `CustomLog` ή `ErrorLog` με εντολή `|` εκκινούν ένα helper με την ταυτότητα του γονικού httpd, συχνά ως root· το `|$` ζητά από τον Apache να χρησιμοποιήσει shell. Εξετάστε τις δημιουργημένες ρυθμίσεις και τη διαδρομή επαναφόρτωσής τους χωρίς να αλλάξετε δεδομένα του backend ή να επανεκκινήσετε την υπηρεσία κατά την απαρίθμηση. Κρατήστε ιδιωτική ολόκληρη την εντολή piped, καθώς τα ορίσματά της μπορεί να περιέχουν μυστικά.

## Ταυτοποίηση και ταυτότητες υπηρεσιών

Το αρχείο ελέγχου του Monit είναι συνήθως το `~/.monitrc` ή το `/etc/monitrc`, αλλά η επιλογή `monit -c` μπορεί να ορίσει άλλη διαδρομή. Ένα αναγνώσιμο αρχείο μπορεί να περιέχει εγγραφές `set httpd` και `allow user:password` για τη web διεπαφή του, συχνά στην τοπική θύρα 2812. Ελέγξτε τον ιδιοκτήτη και τα δικαιώματα του αρχείου προτού το εξετάσετε και μην εμφανίζετε τιμές κωδικών πρόσβασης σε κοινόχρηστη έξοδο απαρίθμησης. Τα διαπιστευτήρια web παρέχουν μόνο τον ρόλο Monit που έχει ρυθμιστεί· οι χρήστες μόνο για ανάγνωση δεν μπορούν να εκτελέσουν ενέργειες ελέγχου. Η κλιμάκωση σε ξεχωριστό λογαριασμό Unix απαιτεί επιβεβαιωμένη επαναχρησιμοποίηση κωδικού πρόσβασης ή μια προνομιούχα ενέργεια Monit που μπορεί πράγματι να ενεργοποιήσει ο πιστοποιημένος ρόλος. Δείτε την [τεκμηρίωση του Monit για το αρχείο ελέγχου και την ταυτοποίηση](https://www.mmonit.com/monit/documentation/monit.html).

Για το Webmin, το `/etc/webmin/miniserv.conf` περιέχει τις ρυθμίσεις του server και το `/etc/webmin/webmin.acl` καταγράφει τις μονάδες στις οποίες μπορούν να έχουν πρόσβαση οι χρήστες· το [Webmin τεκμηριώνει τα όρια παραχώρησης πρόσβασης στις μονάδες](https://webmin.com/docs/development/creating-modules/). Ένας κωδικός πρόσβασης Unix ή ένα αναγνώσιμο αρχείο ACL δεν παρέχει από μόνο του συνεδρία Webmin. Επιβεβαιώστε την πραγματική αντιστοίχιση ταυτοποίησης, τον προσβάσιμο listener, τον πιστοποιημένο λογαριασμό, τα ενεργά δικαιώματα της μονάδας Package Updates, τον εγκατεστημένο κώδικα ή την επιδιόρθωση του προμηθευτή και την ταυτότητα της διεργασίας Webmin. Σε επηρεαζόμενες εκδόσεις έως και την 1.910, το [CVE-2019-12840](https://nvd.nist.gov/vuln/detail/CVE-2019-12840) επέτρεπε σε λογαριασμό με δικαίωμα πρόσβασης σε αυτή τη μονάδα να εκτελεί εντολές μέσω του χειριστή ενημερώσεων. Κατά την παθητική απαρίθμηση, αναφέρετε τις διαδρομές ρυθμίσεων και τα δικαιώματα χωρίς να εμφανίζετε διαπιστευτήρια ή να επιχειρείτε ενημέρωση.

```bash
find /etc/pam.d /etc/sssd /etc/postfix -maxdepth 2 -type f -ls 2>/dev/null
systemctl cat sssd postfix jenkins 2>/dev/null
getent passwd
```

- Το [PAM](pam-pluggable-authentication-modules.md) διέπει τον έλεγχο ταυτότητας ανά υπηρεσία· οι εγγράψιμες διαδρομές πολιτικών ή modules μπορούν να αλλάξουν τη συμπεριφορά σύνδεσης.
- Οι ρυθμίσεις LDAP/SSSD μπορούν να αποκαλύψουν endpoints καταλόγου, ταυτότητες bind και κανόνες πρόσβασης. Ένας κωδικός πρόσβασης bind που ανακτήθηκε μπορεί να επιτρέπει ερωτήματα LDAP πέρα από τον τρέχοντα λογαριασμό OS· δοκιμάστε την ακριβή ταυτότητα bind και τα ACL του καταλόγου. Ελέγξτε τα δικαιώματα αρχείων πριν εξετάσετε secrets· τα [Linux Active Directory](../user-information/linux-active-directory.md) και [FreeIPA](freeipa-pentesting.md) καλύπτουν τη χρήση tickets και καταλόγων.
- Τα aliases του Postfix μπορούν να προωθούν τα εισερχόμενα mail σε τοπικές εντολές. Αν ένας χρήστης με χαμηλότερα δικαιώματα μπορεί να αλλάξει το script στο οποίο παραπέμπει το alias, η παράδοση mail μπορεί να εκτελέσει τον κώδικά του με την ταυτότητα παράδοσης. Ελέγξτε τους χάρτες aliases και την ιδιοκτησία των scripts πριν ισχυριστείτε ότι αυτή η διαδρομή είναι εφικτή· δείτε το [SMTP and mail service testing](../../network-services-pentesting/pentesting-smtp/README.md).
- Τα Jenkins και άλλες υπηρεσίες CI μπορεί να εκτελούν jobs με ισχυρό τοπικό λογαριασμό. Ελέγξτε τον χρήστη της υπηρεσίας, τις εγγράψιμες διαδρομές job/workspace και την τοπική διεπαφή διαχείρισης πριν δοκιμάσετε ένα pipeline ή plugin. Ελέγξτε επίσης τα **credentials που είναι διαθέσιμα σε ένα job** και τους λογαριασμούς με τους οποίους μπορούν να πραγματοποιήσουν έλεγχο ταυτότητας: ένα Pipeline που χρησιμοποιεί το [SSH Agent step](https://www.jenkins.io/doc/pipeline/steps/ssh-agent/) μπορεί να αποκτήσει πρόσβαση σε host ως ο χρήστης του SSH credential, ακόμη κι όταν το ίδιο το Jenkins εκτελείται με λογαριασμό Unix χαμηλότερων δικαιωμάτων. Επιβεβαιώστε ότι η τρέχουσα ταυτότητα Jenkins έχει `Job/Create`, `Job/Configure` ή άλλη αποτελεσματική δυνατότητα αλλαγής του Pipeline, ότι το credential είναι διαθέσιμο στο συγκεκριμένο job και ότι ο λογαριασμός SSH-στόχος δέχεται το key, πριν ισχυριστείτε κλιμάκωση δικαιωμάτων στον host. Το εμφανιζόμενο όνομα ή το ID ενός credential δεν αποδεικνύει από μόνο του καμία από αυτές τις προϋποθέσεις. Το Jenkins προειδοποιεί ότι οι δημιουργοί job και, συχνά, οι χρήστες που μπορούν να τα διαμορφώσουν μπορούν να χρησιμοποιούν αυθαίρετα τα credentials που είναι διαθέσιμα στο πεδίο εφαρμογής τους· επομένως, το [credential scope](https://www.jenkins.io/doc/book/security/credentials/) και το [Pipeline trust](https://www.jenkins.io/doc/book/security/securing-org-folders-and-multibranch-pipelines/) είναι εξίσου σημαντικά με το UID της υπηρεσίας. Μην εμφανίζετε τιμές credentials και private keys σε κοινόχρηστα αποτελέσματα απαρίθμησης.

## API προμήθειας του Cobbler

Η υπηρεσία διαχείρισης του Cobbler εκθέτει ένα XML-RPC API, συνήθως στη θύρα `25151`. Ελέγξτε τον listener και τον κάτοχο της διεργασίας `cobblerd` πριν αξιολογήσετε την επίπτωσή του· ακόμη κι ένα API που δέχεται συνδέσεις μόνο μέσω loopback είναι προσβάσιμο από χρήστες του host. Εξετάστε τα modules ελέγχου ταυτότητας και εξουσιοδότησης στο `/etc/cobbler/modules.conf`, τις ρυθμίσεις υπηρεσίας στο `/etc/cobbler/settings` ή στο `/etc/cobbler/settings.yaml` και τα δικαιώματα στα `/etc/cobbler/users.conf`, `/etc/cobbler/users.digest` και `/var/lib/cobbler/web.ss`. Τα αρχεία digest και κοινόχρηστου secret περιέχουν στοιχεία διαπιστευτηρίων· καταγράψτε αν είναι αναγνώσιμα χωρίς να εμφανίζετε το περιεχόμενό τους από προεπιλογή.

```bash
ps -eo user,pid,args | grep '[c]obblerd'
ss -ltn 2>/dev/null | grep ':25151'
for file in /etc/cobbler/modules.conf /etc/cobbler/settings /etc/cobbler/settings.yaml \
            /etc/cobbler/users.conf /etc/cobbler/users.digest /var/lib/cobbler/web.ss; do
    [ -e "$file" ] && ls -l "$file"
done
```

**CVE-2024-47533** είναι παράκαμψη ελέγχου ταυτότητας XML-RPC στο Cobbler 3.0.0 έως 3.2.2 και 3.3.0 έως 3.3.6. Ένα σφάλμα ανάγνωσης shared-secret επέστρεφε την προβλέψιμη τιμή `-1`, την οποία το API δεχόταν ως password. Οι αντίστοιχες διορθώσεις είναι οι 3.2.3 και 3.3.7. Η έκδοση ενός πακέτου αποτελεί ένδειξη· επαληθεύστε τον κώδικα που έχει αναπτυχθεί και τυχόν backported διόρθωση πριν αναφέρετε έκθεση.

Μια authenticated συνεδρία API μπορεί να αποτελέσει διαδρομή εκτέλεσης με προνόμια, όταν το `cobblerd` εκτελείται ως root. Σε ευάλωτες υλοποιήσεις, το `background_import` περνά τα ελεγχόμενα από τον χρήστη `rsync_flags` σε μια εντολή shell, ενώ η απόδοση ενός ελεγχόμενου από τον χρήστη προτύπου Cheetah autoinstall μπορεί να εκτελέσει Python. Ελέγξτε τα δικαιώματα του API και την εγκατεστημένη έκδοση πριν δοκιμάσετε οποιαδήποτε από τις δύο διαδρομές. Περιορίστε την πρόσβαση στο management API, διορθώστε την παράκαμψη ελέγχου ταυτότητας και επιτρέψτε την ανάγνωση των αρχείων ρυθμίσεων και διαπιστευτηρίων μόνο στους διαχειριστές της υπηρεσίας.

## Τοπικοί AWS emulators και αποθηκευμένα διαπιστευτήρια

Ένας χρήστης του host ενδέχεται να έχει πρόσβαση σε έναν AWS-compatible emulator που εκτελείται σε container, μέσω του δημοσιευμένου loopback endpoint του. Συσχετίστε τον ενεργό listener, το endpoint και τον λογαριασμό που επιλέγει ο client, καθώς και τις εγκατεστημένες ρυθμίσεις εξουσιοδότησης του emulator, πριν αξιολογήσετε την πρόσβαση στο [Secrets Manager](https://docs.localstack.cloud/aws/services/secretsmanager/) ή στο [KMS](https://docs.localstack.cloud/aws/services/kms/). Στο LocalStack, [η επιβολή πολιτικών IAM είναι ξεχωριστή ρύθμιση](https://docs.localstack.cloud/aws/developer-tools/security-testing/iam-policy-enforcement/)· μην συμπεραίνετε τα πραγματικά δικαιώματα API μόνο από ένα αρχείο διαπιστευτηρίων, μια πολιτική IAM ή έναν listener. Επιβεβαιώστε τη συμπεριφορά της εγκατεστημένης έκδοσης και των ρυθμίσεων.

Ένα αποθηκευμένο secret είναι χρήσιμο για τοπική κλιμάκωση προνομίων μόνο αν η τρέχουσα ταυτότητα API μπορεί να το ανακτήσει και ένας ξεχωριστός λογαριασμός με περισσότερα προνόμια δέχεται το ανακτημένο διαπιστευτήριο. Ένα κρυπτογραφημένο τοπικό blob απαιτεί επίσης πρόσβαση ανάγνωσης στο αρχείο, το αντίστοιχο χρησιμοποιήσιμο κλειδί KMS και αλγόριθμο, καθώς και αποτελεσματική πρόσβαση αποκρυπτογράφησης. Για ένα [ασύμμετρο κλειδί KMS](https://docs.aws.amazon.com/cli/latest/reference/kms/decrypt.html), το αίτημα αποκρυπτογράφησης πρέπει να καθορίζει τον αλγόριθμο που χρησιμοποιήθηκε για την κρυπτογράφηση του blob. Περιορίστε την αυτόματη απογραφή του host σε ενδείξεις διεργασιών, listener, διαδρομών ρυθμίσεων και δικαιωμάτων αρχείων· μην ζητάτε ούτε εκτυπώνετε τιμές secret ή αποκρυπτογραφημένο απλό κείμενο κατά την τυπική απαρίθμηση.
