# Τοπικές υπηρεσίες web και authentication

{{#include ../../banners/hacktricks-training.md}}

Ένα Linux shell παρέχει εικόνα από την πλευρά του host για τις υπηρεσίες web και authentication: ορίσματα διεργασιών, listeners, αρχεία unit, ρυθμίσεις, logs και διεπαφές που είναι προσβάσιμες μόνο τοπικά. Χρησιμοποιήστε αυτή την εικόνα για να συνδέσετε μια προσβάσιμη υπηρεσία με τον λογαριασμό και τα αρχεία που χρησιμοποιεί στην πράξη.

## Χαρτογραφήστε την τοπική στοίβα web

```bash
ss -lntup
ps -eo user,pid,args | grep -E '[a]pache|[n]ginx|[p]hp-fpm|[j]enkins'
systemctl list-units --type=service --state=running 2>/dev/null
find /etc/apache2 /etc/httpd /etc/nginx -maxdepth 3 -type f 2>/dev/null | head -80
```

Εξετάστε τα ονόματα virtual host, τα document roots, τις διαδρομές proxy, τους καταλόγους upload, τις ρυθμίσεις εκτέλεσης PHP και τα αρχεία διαμόρφωσης που περιέχουν διαπιστευτήρια. Ένας listener στο loopback μπορεί να είναι προσβάσιμος μέσω proxy ή SSH tunnel. Για να δοκιμάσετε ένα συγκεκριμένο virtual host απέναντι σε έναν τοπικό listener, στείλτε την προβλεπόμενη κεφαλίδα `Host` ή χρησιμοποιήστε το `curl --resolve` με τη σωστή διεύθυνση και θύρα. Η απαρίθμηση virtual host μπορεί επίσης να αποκαλύψει ονόματα που απουσιάζουν από την προεπιλεγμένη απόκριση. Ελέγξτε αν το Apache επιτρέπει overrides μέσω `.htaccess` και αν οι διαδρομές upload μπορούν να εκτελέσουν PHP, πριν θεωρήσετε ότι ένας εγγράψιμος κατάλογος upload επιτρέπει εκτέλεση κώδικα. Ένας ανεπτυγμένος JavaScript source map μπορεί να αποκαλύψει διαδρομές πηγαίου κώδικα ή secrets στην πλευρά του client· αντιμετωπίστε τις τιμές που ανακτήθηκαν ως ενδείξεις και επαληθεύστε τα πραγματικά δικαιώματά τους. Για ελέγχους ειδικά για web, δείτε τα [Apache](../../network-services-pentesting/pentesting-web/apache.md) και [Nginx](../../network-services-pentesting/pentesting-web/nginx.md).

Για Apache με [mpm-itk](https://mpm-itk.sesse.net/), ένα ενεργό `AssignUserID` μπορεί να εκτελεί ένα virtual host με διαφορετικό user και group. Αν ένας λογαριασμός με χαμηλότερα δικαιώματα μπορεί να γράψει ένα script στο `DocumentRoot` αυτού του host, εξετάστε αν κάποια προσβάσιμη διαδρομή το εκτελεί πράγματι με την εκχωρημένη ταυτότητα. Επιβεβαιώστε ότι το module είναι φορτωμένο, την ενεργή διαμόρφωση του virtual host (συμπεριλαμβανομένων των overrides ταυτότητας που βασίζονται σε expressions), τα δικαιώματα εγγραφής και αναζήτησης στον κατάλογο, τον script handler και την πρόσβαση στον listener. Μια επισημασμένη οδηγία ή ένας εγγράψιμος κατάλογος από μόνα τους δεν αποδεικνύουν εκτέλεση μεταξύ χρηστών.

Ένας home directory που δημοσιεύεται μέσω web server μπορεί να εκθέσει backup archives αρχείων SSH identity, ακόμη κι όταν ο ενεργός κατάλογος `.ssh` είναι ιδιωτικός. Για παράδειγμα, η ρύθμιση [`homedirs_public` του Nostromo](https://www.nazgul.ch/dev/nostromo_man.html) επιλέγει έναν υποκατάλογο από τους home directories χρηστών για δημοσίευση. Ένα εύρημα archive μόνο βάσει διαδρομής είναι απλώς ένδειξη: επαληθεύστε την ενεργή αντιστοίχιση του server, την τοπική δυνατότητα ανάγνωσης ή την εξουσιοδότηση HTTP, τα περιεχόμενα του archive, το passphrase του private key και αν ο αντίστοιχος λογαριασμός δέχεται πράγματι το key. Μην εξάγετε archives και μην εμφανίζετε υλικό κλειδιών κατά τη συνήθη απαρίθμηση host.

Ένα αναγνώσιμο backup μιας τοπικής web εφαρμογής με υψηλότερα δικαιώματα μπορεί να αποκαλύψει τη λογική authentication και ανάγνωσης αρχείων, ακόμη κι όταν ο ενεργός πηγαίος κώδικας δεν είναι προσβάσιμος. Συγκρίνετε το backup με την ανεπτυγμένη υπηρεσία πριν βασιστείτε σε αυτό. Ειδικότερα, αξίζει να εξεταστεί ένα cookie που δημιουργείται κρυπτογραφώντας κείμενο ελεγχόμενο από τον caller, ακολουθούμενο από ένα secret και μια σημαία ρόλου, αν η εφαρμογή χρησιμοποιεί ντετερμινιστικά blocks ECB, επιστρέφει νέα cookies για επιλεγμένο κείμενο και αργότερα διαχωρίζει την αποκρυπτογραφημένη τιμή με delimiter που δεν γίνεται escape. Το [NIST εξηγεί την ανεξάρτητη, επαναλήψιμη αντιστοίχιση blocks του ECB](https://csrc.nist.gov/news/2022/proposal-to-revise-sp-800-38a)· αυτή η ιδιότητα μπορεί να υποστηρίξει σύγκριση με επιλεγμένη είσοδο, αλλά από μόνη της δεν παρέχει ρόλο με υψηλότερα δικαιώματα. Επιβεβαιώστε την ενεργή διαδρομή, τις προϋποθέσεις session, τον ακριβή parser και τη ροή δεδομένων, την ταυτότητα της υπηρεσίας και μια ξεχωριστή ενέργεια ή διαδρομή ανάγνωσης αρχείων με υψηλότερα δικαιώματα. Η παθητική απογραφή πρέπει να αναφέρει τα metadata των backup και την ιδιοκτησία των listeners, χωρίς να διαβάζει τα περιεχόμενα των archive ή να στέλνει authentication probes.

Η ίδια προσέγγιση ελέγχου πηγαίου κώδικα ισχύει για μια προνομιούχα τοπική υπηρεσία loopback **εκτός HTTP**, όπως ένα custom interface που βασίζεται σε SSH. Αν ένα προσβάσιμο backup πηγαίου κώδικα δείχνει μια εντολή που δέχεται διαδρομή αρχείου επιλεγμένη από τον caller, ελέγξτε τον έλεγχο authentication, τον τρόπο επίλυσης της διαδρομής και αν επαληθεύει ότι το επιλυμένο αρχείο παραμένει κάτω από τον προβλεπόμενο κατάλογο πριν το ανοίξει. Στη Go, η [`filepath.Join`](https://pkg.go.dev/path/filepath#Join) καθαρίζει μια διαδρομή, αλλά δεν επιβάλλει τον περιορισμό εντός αυτού του καταλόγου. Επιβεβαιώστε ότι το backup αντιστοιχεί στο εκτελούμενο build, ότι ο listener είναι προσβάσιμος, ότι ο λογαριασμός με χαμηλότερα δικαιώματα μπορεί να χρησιμοποιήσει την εντολή και ότι η διεργασία μπορεί να διαβάσει τον στόχο· η κατοχή ενός αναγνώσιμου SSH key είναι ξεχωριστό ζήτημα πολιτικής σύνδεσης. Αναφέρετε τις διαδρομές των source archive και την ιδιοκτησία της υπηρεσίας, χωρίς να εξάγετε τα περιεχόμενα των archive ή των keys σε αυτοματοποιημένη έξοδο.

Ένα PHP-FPM pool που ακούει σε TCP loopback μπορεί να είναι προσβάσιμο από άλλον τοπικό λογαριασμό, ακόμη κι όταν ο ιστότοπός του απαιτεί authentication. Το [PHP προειδοποιεί ότι ένας client που μπορεί να συνδεθεί στο FastCGI μπορεί να ελέγχει ρυθμίσεις αιτημάτων, συμπεριλαμβανομένου του `auto_prepend_file`](https://www.php.net/manual/en/install.fpm.php). Εξετάστε τις ρυθμίσεις `listen` και `listen.allowed_clients` του pool μαζί με τον ενεργό listener, το worker UID, μια υπάρχουσα διαδρομή script και τυχόν περιορισμούς `security.limit_extensions` ή `php_admin_value`. Τα αρχεία διαμόρφωσης του pool μπορεί να περιέχουν διαπιστευτήρια σε οδηγίες `env[...]`, επομένως η αυτοματοποιημένη απογραφή πρέπει να αναφέρει τις διαδρομές τους, όχι τα περιεχόμενά τους. Ένα αρχείο διαμόρφωσης ή μια θύρα από μόνα τους δεν αποδεικνύουν διαδρομή εκτέλεσης μεταξύ χρηστών· δείτε τον [οδηγό FastCGI](../../network-services-pentesting/9000-pentesting-fastcgi.md) για λεπτομέρειες του πρωτοκόλλου.

Για ένα προνομιούχο τοπικό API, εξετάστε τόσο την εξουσιοδότηση όσο και την εκτέλεση κώδικα. Ένας ρόλος βάσης δεδομένων που μπορεί να τροποποιήσει ο λογαριασμός με χαμηλότερα δικαιώματα ενδέχεται να ξεκλειδώσει μια διαδρομή API, αλλά το επόμενο όριο εξαρτάται από την υλοποίηση της διαδρομής. Για παράδειγμα, η συγχώνευση JSON αιτήματος σε ένα JavaScript object και στη συνέχεια η κλήση του [`child_process.exec`](https://nodejs.org/api/child_process.html) δικαιολογεί έλεγχο για [ροή δεδομένων από prototype pollution προς εκτέλεση](../../pentesting-web/deserialization/nodejs-proto-prototype-pollution/prototype-pollution-to-rce.md). Επαληθεύστε την πραγματική βιβλιοθήκη/version συγχώνευσης, την επικύρωση εισόδου, την προσβάσιμη διαδρομή, την ταυτότητα της διεργασίας και τις επιλογές της child process· ένας Node listener που ανήκει στον root ή μόνο το όνομα μιας ευάλωτης εξάρτησης αποτελούν απλώς ενδείξεις.

Τα CMS με αποθήκευση σε αρχεία μπορεί να διατηρούν verifiers κωδικών πρόσβασης διαχειριστή έξω από τα συνηθισμένα αρχεία διαμόρφωσης `.php`. Παραδείγματα είναι το `data/database.js` ενός ιστότοπου ή το `data/settings/pass.php`. Ελέγξτε την ιδιοκτησία και τη δυνατότητα ανάγνωσης των αρχείων πριν από μη αυτόματο έλεγχο και μην συμπεριλαμβάνετε hashes σε κοινόχρηστη αυτοματοποιημένη έξοδο. Ένας κωδικός πρόσβασης εφαρμογής που μπορεί να ανακτηθεί αποτελεί διαφορετικό όριο προνομίων από έναν λογαριασμό Unix: επαληθεύστε τυχόν ισχυρισμό περί επαναχρησιμοποίησης στον συγκεκριμένο λογαριασμό και με την επιτρεπόμενη μέθοδο authentication.

Ο authentication controller μιας εφαρμογής μπορεί επίσης να περιέχει κυριολεκτικό κωδικό πρόσβασης σύνδεσης στον πηγαίο κώδικα αντί για αρχείο διαμόρφωσης. Αν ένας χρήστης με χαμηλότερα δικαιώματα μπορεί να διαβάσει τον ανεπτυγμένο controller, εξετάστε τοπικά τη σύγκριση authentication και μην συμπεριλάβετε καμία τιμή σε κοινόχρηστη έξοδο απαρίθμησης. Επιβεβαιώστε ότι η διαδρομή κώδικα είναι ενεργή, ότι ο κωδικός πρόσβασης είναι έγκυρος για την εφαρμογή και ότι ένας ξεχωριστός λογαριασμός Unix με υψηλότερα δικαιώματα δέχεται πράγματι τον ίδιο κωδικό πρόσβασης, πριν ισχυριστείτε τοπική κλιμάκωση δικαιωμάτων. Το όνομα αρχείου ενός controller είναι απλώς ένδειξη για έλεγχο.

Το Dolibarr αποθηκεύει ρυθμίσεις σύνδεσης βάσης δεδομένων, συμπεριλαμβανομένου του `dolibarr_main_db_pass`, στο `htdocs/conf/conf.php` ([αναφορά διαμόρφωσης](https://wiki.dolibarr.org/index.php/Configuration_file)). Ένα αναγνώσιμο αρχείο αποτελεί ένδειξη για διαπιστευτήρια· μόνο η ξεχωριστή, επαληθευμένη επαναχρησιμοποίηση κωδικού πρόσβασης λογαριασμού ή κάποιο άλλο δικαίωμα βάσης δεδομένων θα μπορούσε να οδηγήσει σε τοπική κλιμάκωση δικαιωμάτων. Ελέγξτε πρώτα τα δικαιώματα και αποφύγετε την εμφάνιση της τιμής σε αυτοματοποιημένη έξοδο.

Το αρχείο διαμόρφωσης του Linux package του GitLab είναι συνήθως το `/etc/gitlab/gitlab.rb`, ενώ σε εγκαταστάσεις μπορεί να υπάρχουν αναγνώσιμα αντίγραφά του και αλλού. Το [GitLab τεκμηριώνει](https://docs.gitlab.com/omnibus/settings/smtp/) ότι αυτό το αρχείο μπορεί να περιέχει το `gitlab_rails['smtp_password']`, αν και οι κρυπτογραφημένες ρυθμίσεις SMTP μπορεί να αποθηκεύουν τον κωδικό πρόσβασης έξω από το αρχείο απλού κειμένου. Αντιμετωπίστε ένα αναγνώσιμο αρχείο διαμόρφωσης ως ένδειξη για διαπιστευτήρια: επαληθεύστε ότι είναι ενεργό, ότι το διαπιστευτήριο ισχύει ακόμη και ότι ένας συγκεκριμένος λογαριασμός με υψηλότερα δικαιώματα το δέχεται, πριν ισχυριστείτε επαναχρησιμοποίηση κωδικού πρόσβασης. Ξεχωριστά, το [GitLab εκτελεί το `gitlab.rb` ως κώδικα Ruby υπό τον root κατά το `gitlab-ctl reconfigure`](https://docs.gitlab.com/omnibus/settings/configuration/)· ένα εγγράψιμο ενεργό αρχείο ή ένα αρχείο `from_file` που συμπεριλαμβάνεται χρειάζεται πραγματική διαδρομή προνομιούχου reconfigure προτού συνιστά εύρημα εκτέλεσης. Μια προεπισκόπηση διαμόρφωσης μπορεί να εκθέσει τιμές διαπιστευτηρίων, γι’ αυτό αντιμετωπίστε την έξοδό της ως ευαίσθητη και κοινοποιήστε μόνο τις διαδρομές και τα δικαιώματα.

Μια self-hosted εγκατάσταση Mattermost μπορεί να αποθηκεύει το `SqlSettings.DataSource` στο `/opt/mattermost/config/config.json`· το [Mattermost τεκμηριώνει](https://docs.mattermost.com/deployment-guide/server/troubleshooting) τόσο αυτή τη συνήθη διαδρομή όσο και εγκαταστάσεις που αποθηκεύουν την ενεργή διαμόρφωση σε βάση δεδομένων. Ένα αναγνώσιμο αρχείο μπορεί να εκθέσει διαπιστευτήριο βάσης δεδομένων της εφαρμογής, αλλά δεν αποδεικνύει πρόσβαση στη βάση δεδομένων ή πρόσβαση root στο Unix. Επαληθεύστε την ενεργή πηγή διαμόρφωσης, τα πραγματικά δικαιώματα του ρόλου βάσης δεδομένων, τυχόν κωδικό πρόσβασης εφαρμογής που ανακτήθηκε ξεχωριστά και αν αυτός ο κωδικός λειτουργεί για συγκεκριμένο λογαριασμό Unix με υψηλότερα δικαιώματα. Η μορφή των password hashes μπορεί να αλλάζει μεταξύ εκδόσεων του Mattermost· κατά την απαρίθμηση καταγράψτε τη διαδρομή της διαμόρφωσης και τα metadata πρόσβασης, χωρίς να εμφανίζετε το connection string ή να υποβάλλετε ερωτήματα στη βάση δεδομένων.

```bash
curl -i -H 'Host: admin.example.local' http://127.0.0.1:8080/
ffuf -w wordlist.txt -u http://127.0.0.1:8080/ -H 'Host: FUZZ.example.local' -fs 1234 # replace 1234 with the default response size
grep -R 'sourceMappingURL' /var/www /opt 2>/dev/null | head
```

Φιλτράρετε τα αποτελέσματα των virtual host με βάση το μέγεθος της προεπιλεγμένης απόκρισης ή κάποια άλλη σταθερή τιμή αναφοράς, ώστε να μη φαίνεται έγκυρο κάθε όνομα που δοκιμάστηκε. Ένα source map είναι χρήσιμο μόνο αν έχει όντως αναπτυχθεί ή είναι με άλλον τρόπο αναγνώσιμο.

Οι reverse proxy μπορούν να αλλάξουν τις κεφαλίδες client που εμπιστεύεται μια εφαρμογή. Συγκρίνετε απευθείας αιτήματα με αιτήματα μέσω proxy πριν θεωρήσετε ότι οι κεφαλίδες `X-Forwarded-For`, `X-Forwarded-Host` ή παρόμοιες προσδιορίζουν την ταυτότητα του καλούντος. Εξετάστε από κοινού τις ρυθμίσεις του proxy και της εφαρμογής.

Αν η PHP αντιγράφει το `$_SERVER['HTTP_X_FORWARDED_FOR']` σε ένα string που περνά στη [`system()`](https://www.php.net/manual/en/function.system.php), εξετάστε αν η προσβάσιμη διαδρομή αιτήματος επιτρέπει κεφαλίδα που παρέχεται από τον caller και αν τα shell metacharacters φτάνουν σε αυτό το string χωρίς αλλαγές. Μια εντολή όπως `sudo iptables` στην αρχή **δεν** εκτελεί ως root τις επόμενες εντολές που διαχωρίζονται από το shell· αυτές εκτελούνται με την ταυτότητα του web worker, εκτός αν ένας ξεχωριστός ενεργός κανόνας sudo επιτρέπει privilege escalation. Επιβεβαιώστε την ταυτότητα του worker, την ακριβή παραχώρηση του `sudo -l` και την απαίτηση αυθεντικοποίησης, καθώς και τα όρια των ορισμάτων της εντολής, πριν ισχυριστείτε ότι υπάρχει διαδρομή προς root. Εξετάστε τον κώδικα και την πολιτική χωρίς να στείλετε δοκιμή injection κατά τη συνήθη απαρίθμηση host.

## Διαπιστευτήρια σύνδεσης σε access logs

Αν μια εφαρμογή υποβάλλει φόρμα σύνδεσης με `GET`, το όνομα χρήστη και ο κωδικός πρόσβασης μπορεί να γίνουν query parameters στο URI του αιτήματος. Ένα αίτημα `POST` μπορεί επίσης να περιέχει query string· η χρήση του `POST` δεν αποκρύπτει ένα μυστικό που τοποθετήθηκε κατά λάθος στο URI, συμπεριλαμβανομένου ενός κωδικού πρόσβασης που καταχωρίστηκε σε άσχετο πεδίο φόρμας. Η [συνηθισμένη γραμμή αιτήματος του Apache access log](https://httpd.apache.org/docs/2.4/logs.html) καταγράφει τη μέθοδο και το URI, μαζί με το query string, όταν η διαμορφωμένη μορφή χρησιμοποιεί το `%r`. Έτσι, ένας λογαριασμός που επιτρέπεται να διαβάζει αυτά τα logs, για παράδειγμα μέσω της ομάδας `adm` σε ορισμένα συστήματα Linux, μπορεί να εντοπίσει πιθανό διαπιστευτήριο. Ελέγξτε την πραγματική μορφή log και τα δικαιώματα και, στη συνέχεια, επαληθεύστε ότι η τιμή είναι μυστικό, ότι ο λογαριασμός την αποδέχεται και ότι επιτρέπει τη διέλευση ορίου προνομίων. Μην υποθέτετε ότι καταγράφηκε το σώμα του αιτήματος και μην αντιγράφετε πιθανές τιμές σε κοινόχρηστη έξοδο.

Εξετάζετε μόνο αναγνώσιμα access logs και κρατάτε τις τιμές διαπιστευτηρίων εκτός κοινόχρηστης εξόδου εντολών. Οι μεγάλες γραμμές αιτημάτων μπορεί επίσης να περιέχουν referrer και user agent, οπότε ένα φίλτρο σύντομων γραμμών μπορεί να κρύψει το ίδιο το αίτημα που σας ενδιαφέρει. Οι συνηθισμένες τοποθεσίες των access logs για Apache, httpd και Nginx είναι `/var/log/apache2/access.log`, `/var/log/httpd/access_log` και `/var/log/nginx/access.log`. Τα περιστραμμένα logs μπορεί να περιέχουν παλαιότερα διαπιστευτήρια. Η [πρόσβαση σε αρχεία log μέσω LFI](../../pentesting-web/file-inclusion/README.md#read-access-logs-to-harvest-get-based-auth-tokens-token-replay) είναι μια σχετική διαδρομή προς τα ίδια δεδομένα.

Τα authentication logs της εφαρμογής μπορεί επίσης να εκθέσουν έναν κωδικό πρόσβασης που καταχωρίστηκε κατά λάθος στο πεδίο **username** μιας αποτυχημένης σύνδεσης. Πρώτα επιβεβαιώστε ότι το log είναι αναγνώσιμο και ότι η μορφή του καταγράφει το υποβληθέν όνομα χρήστη· εξετάστε τοπικά μόνο ένα μικρό σχετικό απόσπασμα και μην αντιγράφετε πιθανά διαπιστευτήρια σε κοινόχρηστη έξοδο. Ένα όνομα χρήστη που μοιάζει με κωδικό πρόσβασης είναι απλώς ένα στοιχείο προς διερεύνηση, όχι απόδειξη έγκυρου κωδικού πρόσβασης ή υψηλότερων προνομίων. Επαληθεύστε τον προβλεπόμενο λογαριασμό και τυχόν επαναχρησιμοποίηση διαπιστευτηρίων στη συγκεκριμένη υπηρεσία ή στον Unix λογαριασμό πριν ισχυριστείτε ότι υπάρχει μετάβαση.

Ένας εγγράψιμος handler σύνδεσης ιστού απαιτεί ξεχωριστή διερεύνηση όταν ένας scheduled client με άλλη ταυτότητα υποβάλλει διαπιστευτήρια σε αυτό το endpoint. Επιβεβαιώστε ότι υπάρχει δικαίωμα εγγραφής στον **ενεργό** handler, το πραγματικό πρόγραμμα εκτέλεσης και τη διαδρομή αιτήματος του client, ποιανού διαπιστευτήριο στέλνει και αν αυτός ο κωδικός πρόσβασης της εφαρμογής ισχύει ανεξάρτητα και για λειτουργικό λογαριασμό με υψηλότερα προνόμια. Μια εγγράψιμη σελίδα ή μια επαναλαμβανόμενη διεργασία από μόνη της δεν τεκμηριώνει τέτοια μετάβαση. Η παθητική απογραφή πρέπει να καταγράφει δικαιώματα διαδρομών και μεταδεδομένα εργασιών χωρίς να τροποποιεί τον handler ή να συλλέγει κωδικούς πρόσβασης.

Τα JSON logs EVE του Suricata μπορούν επίσης να καταγράφουν τις εντολές FTP `USER` και `PASS` μαζί με το `command_data`, όταν είναι ενεργή η καταγραφή συμβάντων FTP. Ελέγξτε αν είναι αναγνώσιμα τα `/var/log/suricata/eve*.json*`, συμπεριλαμβανομένων περιστραμμένων ή συμπιεσμένων αρχείων, πριν εξετάσετε τοπικά ένα μικρό σχετικό απόσπασμα. Ένα αναγνώσιμο αρχείο EVE είναι απλώς ένα στοιχείο προς διερεύνηση: επιβεβαιώστε ότι καταγράφηκαν συμβάντα FTP, ότι τα δεδομένα περιλαμβάνουν χρησιμοποιήσιμο διαπιστευτήριο και ότι επιτρέπουν τη διέλευση ορίου προνομίων. Αποφύγετε να εμφανίζετε το `command_data` σε κοινόχρηστη έξοδο απαρίθμησης. Το Suricata τεκμηριώνει τα [πεδία συμβάντων FTP](https://docs.suricata.io/en/suricata-8.0.2/output/eve/eve-json-format.html) και τις [εναλλαγές EVE και τις παραλλαγές ονομάτων αρχείων](https://docs.suricata.io/en/suricata-7.0.15/output/eve/eve-json-output.html).

## Παραγόμενη ρύθμιση Apache και piped logs

Το [remco](https://github.com/HeavyHorst/remco) μπορεί να παρακολουθεί ένα backend key/value, να αποδίδει ένα template σε αρχείο ρυθμίσεων Apache και να εκτελεί μια εντολή reload. Εξετάστε την ταυτότητα της εκτελούμενης διεργασίας remco, την πηγή και τον προορισμό του διαμορφωμένου template, τα prefixes των κλειδιών που παρακολουθούνται και αν μια τιμή του backend εισάγεται απευθείας σε οδηγία Apache, όπως η `ServerName`. Ένας τοπικός listener του backend από μόνος του δεν αποδεικνύει ότι ο τρέχων χρήστης μπορεί να γράψει σε κλειδί που παρακολουθείται· επαληθεύστε την αυθεντικοποίηση και τα δικαιώματα του backend πριν ισχυριστείτε ότι υπάρχει privilege escalation.

Μια μη διαφεύγουσα newline σε εγγράψιμη τιμή backend μπορεί να μετατρέψει την τιμή μιας προβλεπόμενης οδηγίας σε πρόσθετες οδηγίες Apache. Τα [piped logs του Apache](https://httpd.apache.org/docs/2.4/logs.html#piped) είναι ιδιαίτερα ευαίσθητα: το `CustomLog` ή το `ErrorLog` με εντολή `|` ξεκινά ένα βοηθητικό πρόγραμμα με την ταυτότητα του γονικού httpd, συχνά root· το `|$` ζητά από τον Apache να χρησιμοποιήσει shell. Εξετάστε την παραγόμενη ρύθμιση και τη διαδρομή reload χωρίς να αλλάξετε δεδομένα του backend ή να επανεκκινήσετε την υπηρεσία κατά την απογραφή. Κρατήστε ιδιωτική ολόκληρη την piped εντολή, επειδή τα ορίσματά της μπορεί να περιέχουν μυστικά.

## Ταυτότητες αυθεντικοποίησης και υπηρεσιών

Το αρχείο ελέγχου του Monit είναι συνήθως το `~/.monitrc` ή το `/etc/monitrc`, αλλά το `monit -c` μπορεί να επιλέξει διαφορετική διαδρομή. Ένα αναγνώσιμο αρχείο μπορεί να περιέχει εγγραφές `set httpd` και `allow user:password` για το web interface του, συχνά στην τοπική θύρα 2812. Ελέγξτε τον ιδιοκτήτη και τα δικαιώματα του αρχείου πριν το εξετάσετε και κρατήστε τις τιμές κωδικών πρόσβασης εκτός κοινόχρηστης εξόδου απαρίθμησης. Τα web διαπιστευτήρια παρέχουν μόνο τον ρόλο Monit που έχει ρυθμιστεί· οι χρήστες μόνο για ανάγνωση δεν μπορούν να εκτελέσουν ενέργειες ελέγχου. Για privilege escalation μέσω ξεχωριστού Unix λογαριασμού απαιτείται επιβεβαιωμένη επαναχρησιμοποίηση κωδικού πρόσβασης ή προνομιούχα ενέργεια Monit που μπορεί πράγματι να ενεργοποιήσει ο αυθεντικοποιημένος ρόλος. Ανατρέξτε στην [τεκμηρίωση του αρχείου ελέγχου και της αυθεντικοποίησης του Monit](https://www.mmonit.com/monit/documentation/monit.html).

Για το Webmin, το `/etc/webmin/miniserv.conf` προσδιορίζει τις ρυθμίσεις του server και το `/etc/webmin/webmin.acl` καταγράφει σε ποιες ενότητες έχουν πρόσβαση οι χρήστες· το [Webmin τεκμηριώνει τα όρια των δικαιωμάτων ενοτήτων](https://webmin.com/docs/development/creating-modules/). Ένας Unix κωδικός πρόσβασης ή ένα αναγνώσιμο αρχείο ACL δεν παρέχει από μόνο του συνεδρία Webmin. Επιβεβαιώστε την πραγματική αντιστοίχιση αυθεντικοποίησης, τον προσβάσιμο listener, τον αυθεντικοποιημένο λογαριασμό, τα ενεργά δικαιώματα της ενότητας Package Updates, τον εγκατεστημένο κώδικα ή τη διόρθωση του προμηθευτή και την ταυτότητα της διεργασίας Webmin. Σε επηρεαζόμενες εκδόσεις έως και την 1.910, το [CVE-2019-12840](https://nvd.nist.gov/vuln/detail/CVE-2019-12840) επέτρεπε σε λογαριασμό με αυτά τα δικαιώματα ενότητας να εκτελεί εντολές μέσω του update handler. Κατά την παθητική απογραφή, αναφέρετε τις διαδρομές και τα δικαιώματα ρυθμίσεων χωρίς να εμφανίζετε διαπιστευτήρια ή να επιχειρείτε ενημέρωση.

```bash
find /etc/pam.d /etc/sssd /etc/postfix -maxdepth 2 -type f -ls 2>/dev/null
systemctl cat sssd postfix jenkins 2>/dev/null
getent passwd
```

- Το [PAM](pam-pluggable-authentication-modules.md) διέπει τον έλεγχο ταυτότητας ανά υπηρεσία· εγγράψιμες διαδρομές πολιτικών ή modules μπορούν να αλλάξουν τη συμπεριφορά σύνδεσης.
- Οι ρυθμίσεις LDAP/SSSD μπορούν να αποκαλύψουν endpoints καταλόγου, ταυτότητες bind και κανόνες πρόσβασης. Ένας ανακτημένος κωδικός πρόσβασης bind μπορεί να επιτρέψει ερωτήματα LDAP πέρα από τον τρέχοντα λογαριασμό OS· δοκιμάστε την ακριβή ταυτότητα bind και τα ACL του καταλόγου. Ελέγξτε τα δικαιώματα αρχείων πριν εξετάσετε μυστικά· τα [Linux Active Directory](../user-information/linux-active-directory.md) και [FreeIPA](freeipa-pentesting.md) καλύπτουν τη χρήση tickets και καταλόγων.
- Τα aliases του Postfix μπορούν να διοχετεύουν τα εισερχόμενα email σε τοπικές εντολές. Αν ένας χρήστης με λιγότερα προνόμια μπορεί να αλλάξει το αναφερόμενο script, η παράδοση email μπορεί να εκτελέσει τον κώδικά του με την ταυτότητα παράδοσης. Ελέγξτε τους χάρτες aliases και την ιδιοκτησία των scripts πριν ισχυριστείτε ότι αυτή η διαδρομή είναι εφικτή· δείτε τη [δοκιμή SMTP και υπηρεσιών email](../../network-services-pentesting/pentesting-smtp/README.md).
- Τα Jenkins και άλλες υπηρεσίες CI μπορεί να εκτελούν εργασίες με έναν ισχυρό τοπικό λογαριασμό. Εξετάστε τον χρήστη της υπηρεσίας, τις εγγράψιμες διαδρομές εργασιών/workspace και το τοπικό περιβάλλον διαχείρισης πριν δοκιμάσετε ένα pipeline ή plugin. Εξετάστε επίσης τα **διαπιστευτήρια που είναι διαθέσιμα σε μια εργασία** και τον λογαριασμό με τον οποίο μπορούν να πραγματοποιήσουν έλεγχο ταυτότητας: ένα Pipeline που χρησιμοποιεί το [βήμα SSH Agent](https://www.jenkins.io/doc/pipeline/steps/ssh-agent/) μπορεί να αποκτήσει πρόσβαση σε έναν host ως ο χρήστης του SSH credential, ακόμη κι όταν το ίδιο το Jenkins εκτελείται με λογαριασμό Unix με λιγότερα προνόμια. Επιβεβαιώστε ότι η τρέχουσα ταυτότητα Jenkins έχει `Job/Create`, `Job/Configure` ή άλλη αποτελεσματική δυνατότητα να αλλάξει το Pipeline, ότι το credential είναι διαθέσιμο στο συγκεκριμένο job και ότι ο λογαριασμός SSH-στόχος αποδέχεται το κλειδί, πριν ισχυριστείτε κλιμάκωση προνομίων στον host. Το εμφανιζόμενο όνομα ή το ID ενός credential από μόνο του δεν τεκμηριώνει καμία από αυτές τις προϋποθέσεις. Το Jenkins προειδοποιεί ότι όσοι δημιουργούν jobs και, συχνά, όσοι τα ρυθμίζουν μπορούν να χρησιμοποιούν αυθαίρετα τα διαθέσιμα στο scope τους credentials· επομένως, το [scope των credentials](https://www.jenkins.io/doc/book/security/credentials/) και η [εμπιστοσύνη στα Pipeline](https://www.jenkins.io/doc/book/security/securing-org-folders-and-multibranch-pipelines/) έχουν εξίσου σημασία με το UID της υπηρεσίας. Μην συμπεριλαμβάνετε τιμές credentials και ιδιωτικά κλειδιά σε κοινόχρηστα αποτελέσματα απαρίθμησης.

## Εγγραφές αρχείων αποθετηρίου Gogs

Για μια τοπική υπηρεσία Gogs, συσχετίστε τον ιδιοκτήτη της διεργασίας `gogs web` με την έκδοση του εκτελέσιμου αρχείου και το `custom/conf/app.ini`. Η ρύθμιση μπορεί να αποκαλύψει την ταυτότητα της υπηρεσίας, τη ρίζα των αποθετηρίων, τη διεύθυνση ακρόασης και αν είναι απενεργοποιημένη η εγγραφή χρηστών. Ακόμη και ένας listener που ακούει μόνο στο loopback είναι προσβάσιμος από τοπικούς χρήστες. Οι εκδόσεις Gogs έως και την 0.13.3 περιλαμβάνουν ένα ζήτημα εγγραφής αρχείων μέσω symlink στο αυθεντικοποιημένο `PutContents` ([CVE-2025-8110](https://github.com/advisories/GHSA-mq8m-42gh-wq7r)): ένας χρήστης με δικαίωμα εγγραφής στο αποθετήριο μπορεί να κάνει commit ένα symlink και στη συνέχεια να κατευθύνει μέσω αυτού την εγγραφή του API. Η πρόσβαση στο αρχείο που προκύπτει έχει τα προνόμια της διεργασίας Gogs, επομένως μια εγκατάσταση που εκτελείται ως root απαιτεί άμεση προσοχή. Επαληθεύστε ότι έχει εγκατασταθεί η διόρθωση και τις απαιτήσεις ελέγχου ταυτότητας πριν ισχυριστείτε ότι υπάρχει αξιοποιήσιμη διαδρομή· ένα σφάλμα API δεν αποδεικνύει ότι η εγγραφή αρχείου απέτυχε.

## XSS στην περιγραφή αποθετηρίου Gitea και προνομιούχοι θεατές

Το Gitea 1.22.0 επέτρεπε αποθηκευμένο JavaScript σε περιγραφή αποθετηρίου ([CVE-2024-6886](https://github.com/advisories/GHSA-4h4p-553m-46qh))· το πρόβλημα διορθώθηκε στην έκδοση 1.22.1. Ένας χρήστης που μπορεί να επεξεργαστεί μια περιγραφή μπορεί να επηρεάσει μια πιο προνομιούχα συνεδρία browser, εάν ο χρήστης αυτός επισκεφτεί το αποθετήριο και ενεργοποιήσει τον κακόβουλο σύνδεσμο. Αυτή η ταυτότητα browser μπορεί στη συνέχεια να αποκαλύψει ιδιωτικό περιεχόμενο αποθετηρίου ή άλλα δεδομένα της εφαρμογής. Για ξεχωριστή τοπική κλιμάκωση απαιτείται ένα credential ή δικαίωμα προσβάσιμο μέσω αυτού του περιεχομένου, όπως ένας επαναχρησιμοποιημένος κωδικός πρόσβασης διαχειριστή· η ιδιοκτησία της διεργασίας Gitea από μόνη της δεν τεκμηριώνει επίπτωση σε root. Ελέγξτε την εγκατεστημένη έκδοση, την πρόσβαση επεξεργασίας περιγραφών, τη ροή εργασίας των θεατών και την πραγματική αλληλεπίδραση με το browser πριν ισχυριστείτε ότι ισχύει η αλυσίδα επίθεσης.

## API παροχής συστημάτων Cobbler

Η υπηρεσία διαχείρισης του Cobbler εκθέτει ένα API XML-RPC, συνήθως στη θύρα `25151`. Ελέγξτε τον listener και τον ιδιοκτήτη της διεργασίας `cobblerd` πριν αξιολογήσετε τον αντίκτυπο· ακόμη και ένα API που ακούει μόνο στο loopback είναι προσβάσιμο από χρήστη του host. Εξετάστε τα modules ελέγχου ταυτότητας και εξουσιοδότησης στο `/etc/cobbler/modules.conf`, τις ρυθμίσεις υπηρεσίας στο `/etc/cobbler/settings` ή `/etc/cobbler/settings.yaml` και τα δικαιώματα στα `/etc/cobbler/users.conf`, `/etc/cobbler/users.digest` και `/var/lib/cobbler/web.ss`. Τα αρχεία digest και κοινόχρηστου μυστικού περιέχουν διαπιστευτήρια· καταγράψτε αν είναι αναγνώσιμα χωρίς να εμφανίζετε από προεπιλογή το περιεχόμενό τους.

```bash
ps -eo user,pid,args | grep '[c]obblerd'
ss -ltn 2>/dev/null | grep ':25151'
for file in /etc/cobbler/modules.conf /etc/cobbler/settings /etc/cobbler/settings.yaml \
            /etc/cobbler/users.conf /etc/cobbler/users.digest /var/lib/cobbler/web.ss; do
    [ -e "$file" ] && ls -l "$file"
done
```

**CVE-2024-47533** είναι ένα XML-RPC authentication bypass στα Cobbler 3.0.0 έως 3.2.2 και 3.3.0 έως 3.3.6. Ένα σφάλμα ανάγνωσης του shared secret επέστρεφε την προβλέψιμη τιμή `-1`, την οποία το API δεχόταν ως password. Οι αντίστοιχες διορθώσεις είναι οι εκδόσεις 3.2.3 και 3.3.7. Η έκδοση ενός package αποτελεί ένδειξη· επαληθεύστε τον εγκατεστημένο κώδικα και τυχόν backported fix πριν αναφέρετε έκθεση.

Μια authenticated API session μπορεί να παρέχει διαδρομή για privileged execution όταν το `cobblerd` εκτελείται ως root. Σε επηρεαζόμενες υλοποιήσεις, το `background_import` περνά το ελεγχόμενο από τον χρήστη `rsync_flags` σε μια shell command, ενώ η απόδοση ενός Cheetah autoinstall template που ελέγχεται από τον χρήστη μπορεί να εκτελέσει Python. Ελέγξτε τα API permissions και την εγκατεστημένη έκδοση πριν δοκιμάσετε οποιαδήποτε από αυτές τις διαδρομές. Περιορίστε την πρόσβαση στο management API, εφαρμόστε patch για το authentication bypass και επιτρέψτε την ανάγνωση των αρχείων ρυθμίσεων και credentials μόνο στους administrators της υπηρεσίας.

## Ρυθμίσεις Motion και motionEye

Ελέγξτε το `/etc/motioneye/motioneye.conf` για το `conf_path` και, στη συνέχεια, ελέγξτε τα `motion.conf` και έναν μικρό αριθμό αρχείων `camera-*.conf` σε αυτόν τον κατάλογο. Αναφέρετε αν υπάρχει αναγνώσιμο hash `# @admin_password`, χωρίς να το εμφανίσετε. [Παλαιότερες εκδόσεις του motionEye δημιουργούσαν αυτά τα αρχεία με υπερβολικά ευρεία δικαιώματα ανάγνωσης](https://github.com/motioneye-project/motioneye/security/advisories/GHSA-rhgp-6wq6-9j67)· η διόρθωση υπάρχει στην έκδοση 0.44.0. Ελέγξτε μαζί τις ρυθμίσεις Motion `webcontrol_port`, `webcontrol_parms`, `webcontrol_auth_method` και `webcontrol_localhost`: ο advanced έλεγχος (`2` ή `3`) με απενεργοποιημένο authentication μπορεί να εκθέσει ισχυρές λειτουργίες σε τοπικό χρήστη, ακόμη και όταν ο listener είναι loopback. [Το Motion τεκμηριώνει τις τιμές και τις προεπιλογές](https://motion-project.github.io/motion_config.html).

Μια admin session στο motionEye πριν από την έκδοση 0.43.1b5 μπορούσε να μετατρέψει μια ρύθμιση ονόματος αρχείου κάμερας σε command execution, όταν το Motion την επεξεργαζόταν ([CVE-2025-60787](https://github.com/motioneye-project/motioneye/security/advisories/GHSA-j945-qm58-4gjx)). Επιβεβαιώστε την έκδοση που εκτελείται, την ταυτότητα της υπηρεσίας, την αξιοποιήσιμη διαδρομή authentication και αν έχει ρυθμιστεί κάμερα, πριν ισχυριστείτε ότι υπάρχει escalation. Η ρύθμιση από μόνη της δεν αποδεικνύει ότι η υπηρεσία εκτελείται ή ότι διαθέτει προνόμια.

Ένα όνομα υπηρεσίας ή ένα εγκατεστημένο package αποτελεί μόνο ένδειξη. Το όριο προνομίων καθορίζεται από τον συνδυασμό της προσβάσιμης εισόδου, της ταυτότητας της διεργασίας, της δυνατότητας εγγραφής στη ρύθμιση και της εντολής ή του αρχείου που αυτή τελικά ελέγχει.

## Τοπικοί AWS emulators και αποθηκευμένα credentials

Ένας χρήστης του host μπορεί να αποκτήσει πρόσβαση σε έναν AWS-compatible emulator που εκτελείται σε container, μέσω του δημοσιευμένου loopback endpoint του. Συσχετίστε τον ενεργό listener, το endpoint και το account που επιλέγει ο client, καθώς και τις εγκατεστημένες ρυθμίσεις authorization του emulator, πριν αξιολογήσετε την πρόσβαση στο [Secrets Manager](https://docs.localstack.cloud/aws/services/secretsmanager/) ή στο [KMS](https://docs.localstack.cloud/aws/services/kms/). Στο LocalStack, [η επιβολή IAM policy είναι ξεχωριστή ρύθμιση](https://docs.localstack.cloud/aws/developer-tools/security-testing/iam-policy-enforcement/)· μην συμπεραίνετε τα πραγματικά API permissions μόνο από ένα αρχείο credentials, ένα IAM policy ή έναν listener. Επιβεβαιώστε τη συμπεριφορά της εγκατεστημένης έκδοσης και των ρυθμίσεων.

Ένα αποθηκευμένο secret είναι χρήσιμο για τοπικό escalation μόνο αν η τρέχουσα API identity μπορεί να το ανακτήσει και ένας ξεχωριστός λογαριασμός με υψηλότερα προνόμια αποδέχεται το ανακτημένο credential. Ένα κρυπτογραφημένο τοπικό blob απαιτεί επίσης δικαίωμα ανάγνωσης του αρχείου, το αντίστοιχο διαθέσιμο KMS key και τον αλγόριθμο, καθώς και αποτελεσματική άδεια αποκρυπτογράφησης. Για ένα [asymmetric KMS key](https://docs.aws.amazon.com/cli/latest/reference/kms/decrypt.html), το αίτημα decrypt πρέπει να καθορίζει τον αλγόριθμο που χρησιμοποιήθηκε για την κρυπτογράφηση του blob. Περιορίστε την αυτόματη απογραφή του host σε στοιχεία για διεργασίες, listeners, διαδρομές ρυθμίσεων και δικαιώματα αρχείων· μην ζητάτε ή εμφανίζετε τιμές secret ή αποκρυπτογραφημένο plaintext κατά την τακτική απαρίθμηση.
