# Τοπικές υπηρεσίες Web και ελέγχου ταυτότητας

{{#include ../../banners/hacktricks-training.md}}

Ένα Linux shell παρέχει μια εικόνα των υπηρεσιών Web και ελέγχου ταυτότητας από την πλευρά του host: ορίσματα διεργασιών, listeners, αρχεία μονάδων, διαμόρφωση, logs και διεπαφές προσβάσιμες μόνο τοπικά. Χρησιμοποιήστε αυτή την εικόνα για να συνδέσετε μια προσβάσιμη υπηρεσία με τον λογαριασμό και τα αρχεία που χρησιμοποιεί στην πράξη.

## Χαρτογράφηση της τοπικής στοίβας Web

```bash
ss -lntup
ps -eo user,pid,args | grep -E '[a]pache|[n]ginx|[p]hp-fpm|[j]enkins'
systemctl list-units --type=service --state=running 2>/dev/null
find /etc/apache2 /etc/httpd /etc/nginx -maxdepth 3 -type f 2>/dev/null | head -80
```

Επιθεωρήστε τα ονόματα virtual host, τα document root, τις διαδρομές proxy, τους καταλόγους μεταφόρτωσης, τις ρυθμίσεις εκτέλεσης PHP και τα αρχεία ρυθμίσεων που περιέχουν διαπιστευτήρια. Ένας listener loopback μπορεί να είναι προσβάσιμος μέσω proxy ή SSH tunnel. Για να δοκιμάσετε ένα ονομασμένο virtual host σε έναν τοπικό listener, στείλτε την προβλεπόμενη κεφαλίδα `Host` ή χρησιμοποιήστε το `curl --resolve` με τη σωστή διεύθυνση και θύρα. Η απαρίθμηση virtual host μπορεί επίσης να αποκαλύψει ονόματα που απουσιάζουν από την προεπιλεγμένη απόκριση. Ελέγξτε αν το Apache επιτρέπει overrides μέσω `.htaccess` και αν οι διαδρομές μεταφόρτωσης μπορούν να εκτελέσουν PHP, προτού θεωρήσετε ότι ένας εγγράψιμος κατάλογος μεταφόρτωσης επιτρέπει code execution. Ένας αναπτυγμένος JavaScript source map μπορεί να αποκαλύψει διαδρομές πηγαίου κώδικα ή client-side secrets· αντιμετωπίστε τις τιμές που ανακτάτε ως ενδείξεις και επαληθεύστε τα πραγματικά δικαιώματά τους. Για ελέγχους ειδικά για web, δείτε τα [Apache](../../network-services-pentesting/pentesting-web/apache.md) και [Nginx](../../network-services-pentesting/pentesting-web/nginx.md).

Για το Apache με [mpm-itk](https://mpm-itk.sesse.net/), μια ενεργή ρύθμιση `AssignUserID` μπορεί να εκτελεί ένα virtual host με διαφορετικό χρήστη και ομάδα. Αν ένας λογαριασμός με χαμηλότερα δικαιώματα μπορεί να γράψει ένα script στο `DocumentRoot` αυτού του host, εξετάστε αν μια προσβάσιμη διαδρομή το εκτελεί πράγματι με την εκχωρημένη ταυτότητα. Επιβεβαιώστε ότι το module είναι φορτωμένο, την ενεργή ρύθμιση του virtual host (συμπεριλαμβανομένων των overrides ταυτότητας που βασίζονται σε expressions), τα δικαιώματα εγγραφής και αναζήτησης στον κατάλογο, τον script handler και την πρόσβαση στον listener. Μια επισημασμένη οδηγία ή ένας εγγράψιμος κατάλογος από μόνα τους δεν αποδεικνύουν εκτέλεση μεταξύ χρηστών.

Ένας home directory που δημοσιεύεται μέσω web server μπορεί να εκθέσει backup archives αρχείων ταυτότητας SSH, ακόμη κι αν ο ενεργός κατάλογος `.ssh` είναι ιδιωτικός. Για παράδειγμα, η ρύθμιση [`homedirs_public` του Nostromo](https://www.nazgul.ch/dev/nostromo_man.html) επιλέγει έναν υποκατάλογο που σερβίρεται από τους home directories των χρηστών. Η εύρεση ενός archive μόνο μέσω της διαδρομής του είναι απλώς μια ένδειξη: επαληθεύστε την ενεργή αντιστοίχιση του server, την τοπική δυνατότητα ανάγνωσης ή την εξουσιοδότηση HTTP, τα περιεχόμενα του archive, το passphrase του private key και αν ο αντίστοιχος λογαριασμός δέχεται πράγματι το key. Μην εξάγετε archives και μην εμφανίζετε υλικό κλειδιών κατά τη συνήθη απαρίθμηση host.

Ένα αναγνώσιμο backup μιας τοπικής web app με υψηλότερα δικαιώματα μπορεί να αποκαλύψει τη λογική authentication και ανάγνωσης αρχείων, ακόμη κι όταν ο ενεργός πηγαίος κώδικας δεν είναι προσβάσιμος. Συγκρίνετε το backup με την αναπτυγμένη υπηρεσία προτού βασιστείτε σε αυτό. Ειδικότερα, ένα cookie που δημιουργείται κρυπτογραφώντας κείμενο ελεγχόμενο από τον caller και στη συνέχεια ένα secret και ένα role flag χρειάζεται έλεγχο, αν η app χρησιμοποιεί ντετερμινιστικά blocks ECB, επιστρέφει νέα cookies για κείμενο που επιλέγει ο caller και αργότερα διαχωρίζει την αποκρυπτογραφημένη τιμή με delimiter που δεν γίνεται escape. Το [NIST εξηγεί την ανεξάρτητη, επαναλαμβανόμενη αντιστοίχιση blocks του ECB](https://csrc.nist.gov/news/2022/proposal-to-revise-sp-800-38a)· αυτή η ιδιότητα μπορεί να υποστηρίξει σύγκριση με επιλεγμένη είσοδο, αλλά από μόνη της δεν παρέχει υψηλότερο ρόλο. Επιβεβαιώστε την ενεργή διαδρομή, τις προϋποθέσεις session, τον ακριβή parser και τη ροή δεδομένων, την ταυτότητα της υπηρεσίας και μια ξεχωριστή προνομιούχα ενέργεια ή διαδρομή ανάγνωσης αρχείων. Η παθητική απογραφή πρέπει να αναφέρει τα metadata του backup και τον κάτοχο του listener, χωρίς να διαβάζει τα περιεχόμενα του archive ή να στέλνει probes authentication.

Η ίδια προσέγγιση ελέγχου πηγαίου κώδικα ισχύει και για μια προνομιούχα **μη-HTTP** τοπική υπηρεσία, όπως ένα custom interface που βασίζεται σε SSH. Αν ένα προσβάσιμο backup πηγαίου κώδικα δείχνει μια εντολή που δέχεται διαδρομή αρχείου επιλεγμένη από τον caller, ελέγξτε τον έλεγχο authentication, τον τρόπο επίλυσης της διαδρομής και αν διασφαλίζει ότι το επιλυμένο αρχείο παραμένει κάτω από τον προβλεπόμενο κατάλογο πριν το ανοίξει. Στη Go, το [`filepath.Join`](https://pkg.go.dev/path/filepath#Join) καθαρίζει μια διαδρομή, αλλά δεν επιβάλλει περιορισμό εντός του συγκεκριμένου καταλόγου. Επιβεβαιώστε ότι το backup αντιστοιχεί στο build που εκτελείται, ότι ο listener είναι προσβάσιμος, ότι ο λογαριασμός με χαμηλότερα δικαιώματα μπορεί να χρησιμοποιήσει την εντολή και ότι η διεργασία μπορεί να διαβάσει τον στόχο· η κατοχή ενός αναγνώσιμου SSH key είναι ξεχωριστό ζήτημα πολιτικής σύνδεσης. Αναφέρετε τις διαδρομές των source archive και τον κάτοχο της υπηρεσίας, χωρίς να εξάγετε περιεχόμενα archive ή keys σε αυτοματοποιημένη έξοδο.

Ένα pool PHP-FPM που ακούει σε TCP loopback μπορεί να είναι προσβάσιμο από άλλον τοπικό λογαριασμό, ακόμη κι όταν ο ιστότοπός του απαιτεί authentication. Το [PHP προειδοποιεί ότι ένας client που μπορεί να συνδεθεί στο FastCGI μπορεί να ελέγχει ρυθμίσεις request, συμπεριλαμβανομένου του `auto_prepend_file`](https://www.php.net/manual/en/install.fpm.php). Εξετάστε τις ρυθμίσεις `listen` και `listen.allowed_clients` του pool μαζί με τον ενεργό listener, το UID του worker, μια υπάρχουσα διαδρομή script και τυχόν περιορισμούς `security.limit_extensions` ή `php_admin_value`. Τα αρχεία ρυθμίσεων του pool μπορεί να περιέχουν διαπιστευτήρια σε οδηγίες `env[...]`, επομένως η αυτοματοποιημένη απογραφή πρέπει να αναφέρει τις διαδρομές τους και όχι τα περιεχόμενά τους. Ένα αρχείο ρυθμίσεων ή μια θύρα από μόνα τους δεν αποδεικνύουν διαδρομή εκτέλεσης μεταξύ χρηστών· για λεπτομέρειες του πρωτοκόλλου, δείτε τον [οδηγό FastCGI](../../network-services-pentesting/9000-pentesting-fastcgi.md).

Για ένα προνομιούχο τοπικό API, ιχνηλατήστε την εξουσιοδότηση καθώς και την εκτέλεση κώδικα. Ένας ρόλος βάσης δεδομένων που μπορεί να αλλάξει ο λογαριασμός με χαμηλότερα δικαιώματα μπορεί να ξεκλειδώσει μια διαδρομή API, αλλά το επόμενο όριο ασφαλείας εξαρτάται από την υλοποίηση της διαδρομής. Για παράδειγμα, η συγχώνευση JSON request σε ένα αντικείμενο JavaScript και στη συνέχεια η κλήση της [`child_process.exec`](https://nodejs.org/api/child_process.html) δικαιολογεί έλεγχο για [ροή δεδομένων από prototype pollution σε execution](../../pentesting-web/deserialization/nodejs-proto-prototype-pollution/prototype-pollution-to-rce.md). Επαληθεύστε την πραγματική βιβλιοθήκη και έκδοση συγχώνευσης, την επικύρωση εισόδου, την προσβάσιμη διαδρομή, την ταυτότητα της διεργασίας και τις επιλογές της child process· ένας listener Node που ανήκει στον root ή το όνομα μιας ευάλωτης dependency είναι απλώς μια ένδειξη.

Τα CMS που αποθηκεύουν δεδομένα σε αρχεία μπορεί να διατηρούν επαληθευτές κωδικών πρόσβασης διαχειριστή έξω από τα συμβατικά αρχεία ρυθμίσεων `.php`. Παραδείγματα είναι το `data/database.js` ή το `data/settings/pass.php` ενός site. Ελέγξτε την ιδιοκτησία και τη δυνατότητα ανάγνωσης των αρχείων πριν από τον χειροκίνητο έλεγχο και μην συμπεριλαμβάνετε hashes σε κοινόχρηστη αυτοματοποιημένη έξοδο. Ένας ανακτήσιμος κωδικός πρόσβασης εφαρμογής είναι ξεχωριστό όριο δικαιωμάτων από έναν λογαριασμό Unix: επαληθεύστε τυχόν ισχυρισμό περί επαναχρησιμοποίησής του στον συγκεκριμένο λογαριασμό και με την επιτρεπόμενη μέθοδο authentication.

Ο controller authentication μιας εφαρμογής μπορεί επίσης να περιέχει έναν κυριολεκτικό κωδικό σύνδεσης στον πηγαίο κώδικα αντί σε αρχείο ρυθμίσεων. Αν ένας χρήστης με χαμηλότερα δικαιώματα μπορεί να διαβάσει τον αναπτυγμένο controller, εξετάστε τοπικά τη σύγκριση authentication και μην συμπεριλάβετε καμία τιμή σε κοινόχρηστη έξοδο απογραφής. Επιβεβαιώστε ότι η διαδρομή κώδικα είναι ενεργή, ότι ο κωδικός πρόσβασης ισχύει για την εφαρμογή και ότι ένας ξεχωριστός λογαριασμός Unix με υψηλότερα δικαιώματα δέχεται πράγματι τον ίδιο κωδικό, προτού ισχυριστείτε ότι υπάρχει τοπική κλιμάκωση δικαιωμάτων. Ένα όνομα αρχείου controller είναι απλώς μια ένδειξη για έλεγχο.

Το Dolibarr αποθηκεύει ρυθμίσεις σύνδεσης βάσης δεδομένων, συμπεριλαμβανομένου του `dolibarr_main_db_pass`, στο `htdocs/conf/conf.php` ([αναφορά ρυθμίσεων](https://wiki.dolibarr.org/index.php/Configuration_file)). Ένα αναγνώσιμο αρχείο αποτελεί ένδειξη για διαπιστευτήρια· μόνο μια ξεχωριστή, επαληθευμένη επαναχρησιμοποίηση κωδικού πρόσβασης λογαριασμού ή ένα άλλο δικαίωμα βάσης δεδομένων θα μπορούσε να οδηγήσει σε τοπική κλιμάκωση δικαιωμάτων. Ελέγξτε πρώτα τα δικαιώματα και αποφύγετε την εμφάνιση της τιμής σε αυτοματοποιημένη έξοδο.

Το αρχείο ρυθμίσεων του Linux package του GitLab βρίσκεται συνήθως στο `/etc/gitlab/gitlab.rb`, αν και οι εγκαταστάσεις μπορεί να διατηρούν αναγνώσιμα αντίγραφα και αλλού. Το [GitLab τεκμηριώνει](https://docs.gitlab.com/omnibus/settings/smtp/) ότι αυτό το αρχείο μπορεί να περιέχει `gitlab_rails['smtp_password']`, αν και οι κρυπτογραφημένες ρυθμίσεις SMTP μπορεί να διατηρούν τον κωδικό πρόσβασης έξω από το αρχείο απλού κειμένου. Αντιμετωπίστε μια αναγνώσιμη ρύθμιση ως ένδειξη για διαπιστευτήρια: επαληθεύστε ότι είναι ενεργή, ότι το διαπιστευτήριο είναι έγκυρο και ότι ένας συγκεκριμένος λογαριασμός με υψηλότερα δικαιώματα το δέχεται, προτού ισχυριστείτε ότι υπάρχει επαναχρησιμοποίηση κωδικού πρόσβασης. Ξεχωριστά, το [GitLab εκτελεί το `gitlab.rb` ως κώδικα Ruby με δικαιώματα root κατά το `gitlab-ctl reconfigure`](https://docs.gitlab.com/omnibus/settings/configuration/)· ένα εγγράψιμο ενεργό αρχείο ή ένα συμπεριλαμβανόμενο `from_file` απαιτεί πραγματική διαδρομή privileged reconfigure για να αποτελεί εύρημα εκτέλεσης. Μια προεπισκόπηση ρυθμίσεων μπορεί να εκθέσει τιμές διαπιστευτηρίων, επομένως αντιμετωπίστε την έξοδό της ως ευαίσθητη και κοινοποιήστε αντί αυτής τις διαδρομές και τα δικαιώματα.

Μια self-hosted εγκατάσταση Mattermost μπορεί να διατηρεί το `SqlSettings.DataSource` στο `/opt/mattermost/config/config.json`· το [Mattermost τεκμηριώνει](https://docs.mattermost.com/deployment-guide/server/troubleshooting) τόσο αυτή τη συνήθη διαδρομή όσο και εγκαταστάσεις που αποθηκεύουν την ενεργή ρύθμιση σε βάση δεδομένων. Ένα αναγνώσιμο αρχείο μπορεί να εκθέσει ένα διαπιστευτήριο βάσης δεδομένων της εφαρμογής, αλλά δεν αποδεικνύει πρόσβαση στη βάση δεδομένων ή πρόσβαση root στο Unix. Επαληθεύστε την ενεργή πηγή ρυθμίσεων, τα πραγματικά δικαιώματα του ρόλου βάσης δεδομένων, τυχόν κωδικό πρόσβασης εφαρμογής που ανακτήθηκε ξεχωριστά και αν αυτός ο κωδικός λειτουργεί για συγκεκριμένο λογαριασμό Unix με υψηλότερα δικαιώματα. Η μορφή των password hash μπορεί να αλλάζει μεταξύ εκδόσεων Mattermost· κατά την απογραφή, καταγράψτε τη διαδρομή της ρύθμισης και τα metadata πρόσβασης, χωρίς να εμφανίσετε το connection string ή να κάνετε ερωτήματα στη βάση δεδομένων.

```bash
curl -i -H 'Host: admin.example.local' http://127.0.0.1:8080/
ffuf -w wordlist.txt -u http://127.0.0.1:8080/ -H 'Host: FUZZ.example.local' -fs 1234 # replace 1234 with the default response size
grep -R 'sourceMappingURL' /var/www /opt 2>/dev/null | head
```

Φιλτράρετε τα αποτελέσματα virtual-host με βάση το προεπιλεγμένο μέγεθος απόκρισης ή κάποιο άλλο σταθερό baseline, ώστε να μη φαίνεται έγκυρο κάθε όνομα που μαντεύετε. Ένα source map είναι χρήσιμο μόνο αν έχει πράγματι αναπτυχθεί ή είναι με άλλο τρόπο αναγνώσιμο.

Οι reverse proxy μπορούν να αλλάξουν τις κεφαλίδες client που εμπιστεύεται μια εφαρμογή. Συγκρίνετε απευθείας αιτήματα με αιτήματα μέσω proxy προτού υποθέσετε ότι οι κεφαλίδες `X-Forwarded-For`, `X-Forwarded-Host` ή παρόμοιες προσδιορίζουν την ταυτότητα του caller. Εξετάστε από κοινού τη ρύθμιση του proxy και της εφαρμογής.

Αν η PHP αντιγράφει το `$_SERVER['HTTP_X_FORWARDED_FOR']` σε μια συμβολοσειρά που περνά στη [`system()`](https://www.php.net/manual/en/function.system.php), εξετάστε αν η προσβάσιμη διαδρομή αιτήματος επιτρέπει κεφαλίδα που παρέχεται από τον caller και αν οι μεταχαρακτήρες του shell φτάνουν στη συμβολοσειρά χωρίς αλλαγές. Μια εντολή όπως η `sudo iptables` στην αρχή **δεν** κάνει τις επόμενες εντολές που χωρίζονται με shell να εκτελεστούν ως root· αυτές εκτελούνται ως ο web worker, εκτός αν ένας ξεχωριστός ενεργός κανόνας sudo επιτρέπει privilege escalation. Επιβεβαιώστε την ταυτότητα του worker, την ακριβή παραχώρηση από το `sudo -l` και την απαίτηση ελέγχου ταυτότητας, καθώς και το όριο ορισμάτων της εντολής, προτού ισχυριστείτε ότι υπάρχει διαδρομή προς root. Εξετάστε τον πηγαίο κώδικα και την πολιτική χωρίς να στείλετε probe injection κατά τη συνήθη απαρίθμηση του host.

## Privileged loopback APIs μετά από web foothold

Ένα shell του web process μπορεί να καλέσει τοπικές υπηρεσίες HTTP ακόμη κι όταν οι listeners τους είναι δεσμευμένοι στη διεύθυνση `127.0.0.1`. Στην αναφερόμενη ευάλωτη έκδοση του Control Web Panel, το account dashboard εκτελείται ως ο hosting user, αλλά το user API στη διεύθυνση `https://127.0.0.1:2302` εκτελείται ως root. Η διαδρομή POST `/v1/restoredatabase/` παραλείπει τον έλεγχο access-token και περνά το πεδίο `file` στην `shell_exec('mysql ... < ' . $file)`. Επομένως, από ένα foothold ως hosting user, οι διαχωριστές εντολών στο `file` εκτελούνται ως root. Επιβεβαιώστε τόσο τον έλεγχο πρόσβασης της διαδρομής όσο και την πραγματική ταυτότητα του API process· η δέσμευση στη loopback διεύθυνση από μόνη της δεν αποτελεί έλεγχο ταυτότητας. Δείτε το [PHP execution after redirect](../../pentesting-web/login-bypass/#php-execution-after-redirect) για έναν τρόπο απόκτησης αυτού του foothold. Τα αναφερόμενα ελαττώματα διορθώθηκαν πλήρως στην έκδοση CWP 1.29.<sup>[[1]](#references)</sup>

```bash
curl -sk 'https://127.0.0.1:2302/v1/restoredatabase/' \
  --data-urlencode 'file=/dev/null ; id > /tmp/root-proof ; echo'
```

Το ίδιο API έχει επίσης ένα ξεχωριστό ελάττωμα στο authentication gate: η `access_token()` ενσωματώνει το παρεχόμενο token στο `WHERE authorization_code='$access_token' AND client_id='$user'`. Μια γραμμή `UNION` με τις αναμενόμενες στήλες και μελλοντική ημερομηνία λήξης μπορεί να ικανοποιήσει τον έλεγχο του token, ενώ παράλληλα σχολιάζει την αρχική συνθήκη `client-ID`. Έτσι ξεκλειδώνουν προστατευμένες διαδρομές, όπως η `/v1/newpass/`, όπου το ακατέργαστο `user` προσαρτάται σε μια εντολή shell `passwd` που εκτελείται ως root. Το token injection παρακάμπτει το gate· η εκτέλεση εντολών εξακολουθεί να εξαρτάται από αυτό το δεύτερο sink. Δείτε [SQL injection authentication bypass](../../pentesting-web/login-bypass/#sql-injection-authentication-bypass).<sup>[[1]](#references)</sup>

Για το gate έξι στηλών που αποκαλύφθηκε, το injected token μπορεί να παρέχει μελλοντική ημερομηνία λήξης και να καταστείλει το υπόλοιπο predicate· η διάταξη των στηλών αφορά συγκεκριμένα αυτό το build.<sup>[[1]](#references)</sup>

```sql
' UNION SELECT 'a','x','c','d','2099-01-01 00:00:00','f' -- -
```

Μια ξεχωριστή διαδρομή `/v1/user_panel_dashboard/`, χωρίς token, παρεμβάλλει το `user` σε αναζήτηση στον πίνακα `oauth_clients`. Πρόκειται για τυφλή ανάγνωση βάσης δεδομένων μέσω της σύνδεσης της API με δικαιώματα MySQL-root, **όχι** για εκτέλεση εντολών ως root στο λειτουργικό σύστημα: ο MySQL server εκτελείται ως ο χρήστης `mysql` του λειτουργικού συστήματος. Όταν ο πίνακας που αναζητείται είναι κενός, ένα [constant derived-table timing probe](../../pentesting-web/sql-injection/#exploiting-time-based-sqli) αποφεύγει να χαθεί η καθυστέρηση λόγω των απόντων γραμμών.<sup>[[1]](#references)</sup>

## Διαπιστευτήρια σύνδεσης στα access logs

Αν μια εφαρμογή υποβάλει φόρμα σύνδεσης με `GET`, το username και το password μπορούν να γίνουν query parameters στο request URI. Ένα αίτημα `POST` μπορεί επίσης να περιέχει query string· η χρήση του `POST` δεν αποκρύπτει ένα μυστικό που τοποθετήθηκε κατά λάθος στο URI, ακόμη κι αν πρόκειται για password που εισήχθη σε άσχετο πεδίο φόρμας. Η [συνηθισμένη γραμμή αιτήματος στο access log του Apache](https://httpd.apache.org/docs/2.4/logs.html) καταγράφει τη μέθοδο και το URI, συμπεριλαμβανομένου του query string, όταν η διαμορφωμένη μορφή χρησιμοποιεί το `%r`. Επομένως, ένας λογαριασμός που επιτρέπεται να διαβάζει αυτά τα logs, για παράδειγμα μέσω της ομάδας `adm` σε ορισμένα συστήματα Linux, ενδέχεται να αποκαλύψει ένα στοιχείο για διαπιστευτήρια. Ελέγξτε την πραγματική μορφή και τα δικαιώματα του log και, στη συνέχεια, επαληθεύστε ότι η τιμή είναι μυστικό, ότι ο λογαριασμός την αποδέχεται και ότι επιτρέπει μετάβαση σε υψηλότερα δικαιώματα. Μην υποθέτετε ότι καταγράφηκε το request body και μην αντιγράφετε πιθανές τιμές σε κοινόχρηστη έξοδο.

Επιθεωρείτε μόνο access logs στα οποία έχετε δικαίωμα ανάγνωσης και κρατάτε τις τιμές διαπιστευτηρίων εκτός κοινόχρηστης εξόδου εντολών. Οι μεγάλες γραμμές αιτημάτων μπορεί επίσης να περιέχουν referrer και user agent, επομένως ένα φίλτρο για σύντομες γραμμές μπορεί να αποκρύψει ακριβώς το αίτημα που σας ενδιαφέρει. Οι συνήθεις τοποθεσίες των access logs για Apache, httpd και Nginx είναι οι `/var/log/apache2/access.log`, `/var/log/httpd/access_log` και `/var/log/nginx/access.log`. Τα περιστραμμένα logs μπορεί να περιέχουν παλαιότερα διαπιστευτήρια. Η [πρόσβαση σε αρχεία log μέσω LFI](../../pentesting-web/file-inclusion/README.md#read-access-logs-to-harvest-get-based-auth-tokens-token-replay) είναι ένας σχετικός τρόπος πρόσβασης στα ίδια δεδομένα.

Τα logs αυθεντικοποίησης της εφαρμογής μπορεί επίσης να αποκαλύψουν ένα password που καταχωρίστηκε κατά λάθος στο πεδίο **username** μιας αποτυχημένης σύνδεσης. Πρώτα εξακριβώστε ότι το log είναι αναγνώσιμο και ότι η μορφή του καταγράφει το username που υποβλήθηκε· επιθεωρήστε μόνο ένα μικρό, σχετικό τμήμα τοπικά και μην αντιγράφετε πιθανά διαπιστευτήρια σε κοινόχρηστη έξοδο. Ένα username που μοιάζει με password είναι στοιχείο προς διερεύνηση, όχι απόδειξη έγκυρου password ή υψηλότερων δικαιωμάτων. Επαληθεύστε τον λογαριασμό για τον οποίο προορίζεται και τυχόν επαναχρησιμοποίηση του password στη συγκεκριμένη υπηρεσία ή στον λογαριασμό Unix προτού ισχυριστείτε ότι έγινε μετάβαση σε υψηλότερα δικαιώματα.

Ένας τροποποιήσιμος handler σύνδεσης ιστού χρειάζεται ξεχωριστή διερεύνηση όταν ένας προγραμματισμένος client με διαφορετική ταυτότητα υποβάλλει διαπιστευτήρια σε αυτό το endpoint. Επιβεβαιώστε ότι έχετε δικαίωμα εγγραφής στον **ενεργό** handler, το πραγματικό πρόγραμμα και τη διαδρομή αιτήματος του client, ποιανού διαπιστευτήρια αποστέλλει, καθώς και αν το password της εφαρμογής ισχύει ανεξάρτητα για λογαριασμό του λειτουργικού συστήματος με υψηλότερα δικαιώματα. Μια τροποποιήσιμη σελίδα ή μια επαναλαμβανόμενη διεργασία από μόνη της δεν αποδεικνύει ότι έγινε αυτή η μετάβαση. Η παθητική απογραφή θα πρέπει να αναφέρει τα δικαιώματα διαδρομών και τα μεταδεδομένα εργασιών χωρίς να αλλάζει τον handler ή να συλλέγει passwords.

Τα logs EVE JSON του Suricata μπορούν επίσης να καταγράφουν τις εντολές FTP `USER` και `PASS` μαζί με το `command_data`, όταν είναι ενεργή η καταγραφή συμβάντων FTP. Ελέγξτε αν είναι αναγνώσιμα τα `/var/log/suricata/eve*.json*`, συμπεριλαμβανομένων των περιστραμμένων ή συμπιεσμένων αρχείων, πριν εξετάσετε ένα μικρό σχετικό τμήμα τοπικά. Ένα αναγνώσιμο αρχείο EVE είναι μόνο στοιχείο προς διερεύνηση: επιβεβαιώστε ότι καταγράφηκαν συμβάντα FTP, ότι τα δεδομένα περιλαμβάνουν χρησιμοποιήσιμα διαπιστευτήρια και ότι επιτρέπουν μετάβαση σε υψηλότερα δικαιώματα. Αποφύγετε την εκτύπωση του `command_data` σε κοινόχρηστη έξοδο απογραφής. Το Suricata τεκμηριώνει τα [πεδία συμβάντων FTP](https://docs.suricata.io/en/suricata-8.0.2/output/eve/eve-json-format.html) και την [περιστροφή EVE και τις παραλλαγές ονομάτων αρχείων](https://docs.suricata.io/en/suricata-7.0.15/output/eve/eve-json-output.html).

## Δημιουργημένη διαμόρφωση Apache και piped logs

Το [remco](https://github.com/HeavyHorst/remco) μπορεί να παρακολουθεί ένα backend key/value, να αποδίδει ένα template σε αρχείο διαμόρφωσης Apache και να εκτελεί μια εντολή reload. Επιθεωρήστε την ταυτότητα της διεργασίας remco που εκτελείται, την καθορισμένη πηγή και τον προορισμό του template, τα προθέματα των κλειδιών που παρακολουθούνται και το αν μια τιμή backend εισάγεται απευθείας σε οδηγία Apache, όπως η `ServerName`. Η ύπαρξη τοπικού listener του backend από μόνη της δεν αποδεικνύει ότι ο τρέχων χρήστης μπορεί να γράψει σε κλειδί που παρακολουθείται· επαληθεύστε την αυθεντικοποίηση και τα δικαιώματα του backend προτού ισχυριστείτε ότι υπάρχει κλιμάκωση δικαιωμάτων.

Μια μη διαφυγμένη νέα γραμμή σε τροποποιήσιμη τιμή backend μπορεί να μετατρέψει μια προβλεπόμενη τιμή οδηγίας σε πρόσθετες οδηγίες Apache. Τα [piped logs του Apache](https://httpd.apache.org/docs/2.4/logs.html#piped) είναι ιδιαίτερα ευαίσθητα: τα `CustomLog` ή `ErrorLog` με εντολή `|` εκκινούν ένα βοηθητικό πρόγραμμα με την ταυτότητα της γονικής διεργασίας httpd, συχνά ως root· το `|$` ζητά από το Apache να χρησιμοποιήσει shell. Εξετάστε τη δημιουργημένη διαμόρφωση και τη διαδικασία reload χωρίς να αλλάξετε δεδομένα backend ή να επανεκκινήσετε την υπηρεσία κατά την απογραφή. Κρατήστε ιδιωτική ολόκληρη την εντολή piped, επειδή τα ορίσματά της μπορεί να περιέχουν μυστικά.

## Ταυτότητες αυθεντικοποίησης και υπηρεσιών

Το αρχείο ελέγχου του Monit είναι συνήθως το `~/.monitrc` ή το `/etc/monitrc`, αλλά το `monit -c` μπορεί να επιλέξει διαφορετική διαδρομή. Ένα αναγνώσιμο αρχείο μπορεί να περιέχει καταχωρίσεις `set httpd` και `allow user:password` για το web interface, συχνά στην τοπική θύρα 2812. Ελέγξτε τον κάτοχο και τα δικαιώματα του αρχείου προτού το εξετάσετε και κρατήστε τις τιμές password εκτός κοινόχρηστης εξόδου απογραφής. Τα διαπιστευτήρια ιστού παρέχουν μόνο τον ρόλο Monit που έχει διαμορφωθεί· οι χρήστες μόνο για ανάγνωση δεν μπορούν να εκτελέσουν ενέργειες ελέγχου. Για κλιμάκωση μέσω ξεχωριστού λογαριασμού Unix απαιτείται επιβεβαιωμένη επαναχρησιμοποίηση password ή προνομιούχα ενέργεια Monit που μπορεί πράγματι να ενεργοποιήσει ο αυθεντικοποιημένος ρόλος. Δείτε την [τεκμηρίωση του Monit για το αρχείο ελέγχου και την αυθεντικοποίηση](https://www.mmonit.com/monit/documentation/monit.html).

Για το Webmin, το `/etc/webmin/miniserv.conf` καθορίζει τις ρυθμίσεις του server και το `/etc/webmin/webmin.acl` καταγράφει τις μονάδες στις οποίες μπορούν να έχουν πρόσβαση οι χρήστες· το [Webmin τεκμηριώνει τα όρια εκχώρησης μονάδων](https://webmin.com/docs/development/creating-modules/). Ένα password Unix ή ένα αναγνώσιμο αρχείο ACL δεν παρέχει από μόνο του συνεδρία Webmin. Επιβεβαιώστε την πραγματική αντιστοίχιση αυθεντικοποίησης, τον προσβάσιμο listener, τον αυθεντικοποιημένο λογαριασμό, τα ισχύοντα δικαιώματα της μονάδας Package Updates, τον εγκατεστημένο κώδικα ή τη διόρθωση του προμηθευτή και την ταυτότητα της διεργασίας Webmin. Σε ευάλωτες εκδόσεις έως και την 1.910, το [CVE-2019-12840](https://nvd.nist.gov/vuln/detail/CVE-2019-12840) επέτρεπε σε λογαριασμό με δικαίωμα χρήσης αυτής της μονάδας να εκτελεί εντολές μέσω του handler ενημερώσεων. Κατά την παθητική απογραφή, αναφέρετε τις διαδρομές διαμόρφωσης και τα δικαιώματα χωρίς να εμφανίζετε διαπιστευτήρια ή να επιχειρείτε ενημέρωση.

```bash
find /etc/pam.d /etc/sssd /etc/postfix -maxdepth 2 -type f -ls 2>/dev/null
systemctl cat sssd postfix jenkins 2>/dev/null
getent passwd
```

- Το [PAM](pam-pluggable-authentication-modules.md) διέπει τον έλεγχο ταυτότητας ανά υπηρεσία· πολιτικές ή διαδρομές modules με δυνατότητα εγγραφής μπορούν να αλλάξουν τη συμπεριφορά σύνδεσης.
- Οι ρυθμίσεις LDAP/SSSD μπορεί να αποκαλύψουν endpoints καταλόγου, ταυτότητες bind και κανόνες πρόσβασης. Ένας ανακτημένος κωδικός bind μπορεί να επιτρέψει ερωτήματα LDAP πέρα από όσα επιτρέπει ο τρέχων λογαριασμός OS· δοκιμάστε τη συγκεκριμένη ταυτότητα bind και τα ACL του καταλόγου. Ελέγξτε τα δικαιώματα αρχείων πριν εξετάσετε secrets· τα [Linux Active Directory](../user-information/linux-active-directory.md) και [FreeIPA](freeipa-pentesting.md) καλύπτουν τη χρήση tickets και καταλόγων.
- Τα aliases του Postfix μπορούν να διοχετεύσουν τα εισερχόμενα email σε τοπικές εντολές. Αν ένας χρήστης με λιγότερα προνόμια μπορεί να αλλάξει το αναφερόμενο script, η παράδοση email μπορεί να εκτελέσει τον κώδικά του με την ταυτότητα παράδοσης. Ελέγξτε τους χάρτες alias και την ιδιοκτησία των scripts πριν ισχυριστείτε ότι αυτή η διαδρομή είναι εφικτή· δείτε το [SMTP and mail service testing](../../network-services-pentesting/pentesting-smtp/README.md).
- Το Jenkins και άλλες υπηρεσίες CI μπορεί να εκτελούν jobs με έναν ισχυρό τοπικό λογαριασμό. Εξετάστε τον χρήστη της υπηρεσίας, τις διαδρομές job/workspace με δυνατότητα εγγραφής και το τοπικό περιβάλλον διαχείρισης πριν δοκιμάσετε ένα pipeline ή plugin. Εξετάστε επίσης τα **credentials που είναι διαθέσιμα σε ένα job** και τον λογαριασμό με τον οποίο μπορούν να πραγματοποιήσουν έλεγχο ταυτότητας: ένα Pipeline που χρησιμοποιεί το [SSH Agent step](https://www.jenkins.io/doc/pipeline/steps/ssh-agent/) μπορεί να αποκτήσει πρόσβαση σε host ως ο χρήστης του SSH credential, ακόμη κι όταν το ίδιο το Jenkins εκτελείται με λιγότερα προνόμια στον λογαριασμό Unix. Επιβεβαιώστε ότι η τρέχουσα ταυτότητα Jenkins έχει `Job/Create`, `Job/Configure` ή άλλη αποτελεσματική δυνατότητα αλλαγής του Pipeline, ότι το credential βρίσκεται εντός του scope του συγκεκριμένου job και ότι ο λογαριασμός SSH στον στόχο αποδέχεται το κλειδί, πριν ισχυριστείτε κλιμάκωση προνομίων σε host. Το όνομα εμφάνισης ή το ID ενός credential από μόνο του δεν αποδεικνύει καμία από αυτές τις προϋποθέσεις. Το Jenkins προειδοποιεί ότι όσοι δημιουργούν jobs και, συχνά, όσοι τα διαμορφώνουν μπορούν να χρησιμοποιούν αυθαίρετα τα credentials που είναι διαθέσιμα στο scope τους· συνεπώς, το [credential scope](https://www.jenkins.io/doc/book/security/credentials/) και το [Pipeline trust](https://www.jenkins.io/doc/book/security/securing-org-folders-and-multibranch-pipelines/) είναι εξίσου σημαντικά με το UID της υπηρεσίας. Μην συμπεριλαμβάνετε τιμές credentials και ιδιωτικά κλειδιά σε κοινόχρηστα αποτελέσματα enumeration.

## Εγγραφή αρχείων σε repository Gogs

Για μια τοπική υπηρεσία Gogs, συσχετίστε τον κάτοχο της διεργασίας `gogs web` με την έκδοση του εκτελέσιμου αρχείου και το `custom/conf/app.ini`. Η ρύθμιση μπορεί να αποκαλύψει την ταυτότητα της υπηρεσίας, τη ρίζα των repositories, τη διεύθυνση listener και αν είναι απενεργοποιημένη η εγγραφή χρηστών. Η πρόσβαση στο αρχείο που προκύπτει έχει τα προνόμια της διεργασίας Gogs, επομένως μια εγκατάσταση που εκτελείται ως root απαιτεί άμεση προσοχή. Επιβεβαιώστε ότι έχει εγκατασταθεί η διόρθωση και ποιες απαιτήσεις ελέγχου ταυτότητας ισχύουν πριν ισχυριστείτε ότι υπάρχει αξιοποιήσιμη διαδρομή· ένα σφάλμα API δεν αποδεικνύει ότι απέτυχε η εγγραφή στο αρχείο.

## API provisioning του Cobbler

Η υπηρεσία διαχείρισης του Cobbler εκθέτει ένα XML-RPC API, συνήθως στη θύρα `25151`. Ελέγξτε τον listener και τον κάτοχο της διεργασίας `cobblerd` πριν αξιολογήσετε την επίπτωσή του· ακόμη κι ένα API που δέχεται συνδέσεις μόνο από loopback είναι προσβάσιμο από χρήστη του host. Εξετάστε τα modules ελέγχου ταυτότητας και εξουσιοδότησης στο `/etc/cobbler/modules.conf`, τις ρυθμίσεις της υπηρεσίας στο `/etc/cobbler/settings` ή στο `/etc/cobbler/settings.yaml` και τα δικαιώματα στα `/etc/cobbler/users.conf`, `/etc/cobbler/users.digest` και `/var/lib/cobbler/web.ss`. Τα αρχεία digest και shared-secret περιέχουν στοιχεία credentials, επομένως καταγράψτε αν είναι αναγνώσιμα χωρίς να εκτυπώνετε τα περιεχόμενά τους από προεπιλογή.

```bash
ps -eo user,pid,args | grep '[c]obblerd'
ss -ltn 2>/dev/null | grep ':25151'
for file in /etc/cobbler/modules.conf /etc/cobbler/settings /etc/cobbler/settings.yaml \
            /etc/cobbler/users.conf /etc/cobbler/users.digest /var/lib/cobbler/web.ss; do
    [ -e "$file" ] && ls -l "$file"
done
```

**CVE-2024-47533** είναι ένα XML-RPC authentication bypass στο Cobbler 3.0.0 έως 3.2.2 και 3.3.0 έως 3.3.6. Ένα σφάλμα ανάγνωσης του shared secret επέστρεφε την προβλέψιμη τιμή `-1`, την οποία το API αποδεχόταν ως password. Οι αντίστοιχες διορθώσεις περιλαμβάνονται στις εκδόσεις 3.2.3 και 3.3.7. Η έκδοση ενός package αποτελεί ένδειξη· επαληθεύστε τον εγκατεστημένο κώδικα και τυχόν backported fix πριν αναφέρετε ότι το σύστημα είναι ευάλωτο.

Μια authenticated API session μπορεί να αποτελέσει διαδρομή εκτέλεσης με προνόμια, όταν το `cobblerd` εκτελείται ως root. Σε ευάλωτες υλοποιήσεις, το `background_import` περνά τα ελεγχόμενα από τον χρήστη `rsync_flags` σε μια shell command, ενώ η απόδοση ενός ελεγχόμενου από τον χρήστη Cheetah autoinstall template μπορεί να αξιολογήσει Python. Ελέγξτε τα API permissions και την εγκατεστημένη έκδοση πριν δοκιμάσετε οποιαδήποτε από τις δύο διαδρομές. Περιορίστε την πρόσβαση στο management API, εγκαταστήστε το patch για το authentication bypass και επιτρέψτε την ανάγνωση των configuration και credential files μόνο στους διαχειριστές της υπηρεσίας.

[Το Motion τεκμηριώνει τις τιμές και τις προεπιλογές](https://motion-project.github.io/motion_config.html).

Μια admin session στο motionEye πριν από την έκδοση 0.43.1b5 μπορούσε να μετατρέψει μια ρύθμιση ονόματος αρχείου κάμερας σε command execution, όταν το Motion την επεξεργαζόταν ([CVE-2025-60787](https://github.com/motioneye-project/motioneye/security/advisories/GHSA-j945-qm58-4gjx)). Επιβεβαιώστε την έκδοση που εκτελείται, την ταυτότητα της υπηρεσίας, αν υπάρχει διαθέσιμη διαδρομή authentication και αν έχει ρυθμιστεί κάμερα, πριν ισχυριστείτε ότι είναι δυνατή η κλιμάκωση προνομίων. Η διαμόρφωση από μόνη της δεν αποδεικνύει ότι η υπηρεσία εκτελείται ή έχει προνόμια.

Ένα όνομα υπηρεσίας ή ένα εγκατεστημένο package αποτελεί μόνο ένδειξη. Το όριο προνομίων καθορίζεται από τον συνδυασμό της προσβάσιμης εισόδου, της ταυτότητας της διεργασίας, της δυνατότητας εγγραφής στη διαμόρφωση και της εντολής ή του αρχείου που τελικά ελέγχει.

## Τοπικοί AWS emulators και αποθηκευμένα credentials

Ένας χρήστης του host μπορεί να έχει πρόσβαση σε έναν AWS-compatible emulator που εκτελείται σε container, μέσω του δημοσιευμένου loopback endpoint του. Συσχετίστε τον ενεργό listener, το endpoint και τον λογαριασμό που επιλέγει ο client, καθώς και τις εγκατεστημένες ρυθμίσεις authorization του emulator, πριν αξιολογήσετε την πρόσβαση στο [Secrets Manager](https://docs.localstack.cloud/aws/services/secretsmanager/) ή στο [KMS](https://docs.localstack.cloud/aws/services/kms/). Στο LocalStack, [η επιβολή IAM policy είναι ξεχωριστή ρύθμιση](https://docs.localstack.cloud/aws/developer-tools/security-testing/iam-policy-enforcement/)· μην συμπεραίνετε τα πραγματικά API permissions μόνο από ένα credential file, ένα IAM policy ή έναν listener. Επιβεβαιώστε τη συμπεριφορά της εγκατεστημένης έκδοσης και των ρυθμίσεων.

Ένα αποθηκευμένο secret είναι χρήσιμο για τοπική κλιμάκωση προνομίων μόνο αν η τρέχουσα ταυτότητα API μπορεί να το ανακτήσει και ένας ξεχωριστός λογαριασμός με υψηλότερα προνόμια αποδέχεται το ανακτημένο credential. Ένα κρυπτογραφημένο τοπικό blob απαιτεί επίσης δικαίωμα ανάγνωσης του αρχείου, το αντίστοιχο διαθέσιμο KMS key και algorithm, καθώς και αποτελεσματικό δικαίωμα αποκρυπτογράφησης. Για ένα [asymmetric KMS key](https://docs.aws.amazon.com/cli/latest/reference/kms/decrypt.html), το αίτημα decrypt πρέπει να καθορίζει τον algorithm που χρησιμοποιήθηκε για την κρυπτογράφηση του blob. Περιορίστε την αυτόματη απογραφή του host σε στοιχεία για διεργασίες, listeners, διαδρομές ρυθμίσεων και δικαιώματα αρχείων· κατά τη συνήθη απαρίθμηση, μην ζητάτε ούτε εμφανίζετε τιμές secret ή αποκρυπτογραφημένο plaintext.
