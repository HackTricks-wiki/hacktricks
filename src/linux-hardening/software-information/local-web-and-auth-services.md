# Τοπικές υπηρεσίες Web και ελέγχου ταυτότητας

{{#include ../../banners/hacktricks-training.md}}

Ένα Linux shell παρέχει μια εικόνα των υπηρεσιών Web και ελέγχου ταυτότητας από την πλευρά του host: ορίσματα διεργασιών, listeners, αρχεία unit, ρυθμίσεις, logs και διεπαφές που είναι διαθέσιμες μόνο τοπικά. Χρησιμοποιήστε αυτή την εικόνα για να συνδέσετε μια προσβάσιμη υπηρεσία με τον λογαριασμό και τα αρχεία που χρησιμοποιεί πραγματικά.

## Χαρτογράφηση της τοπικής στοίβας Web

```bash
ss -lntup
ps -eo user,pid,args | grep -E '[a]pache|[n]ginx|[p]hp-fpm|[j]enkins'
systemctl list-units --type=service --state=running 2>/dev/null
find /etc/apache2 /etc/httpd /etc/nginx -maxdepth 3 -type f 2>/dev/null | head -80
```

Επιθεωρήστε τα ονόματα virtual host, τα document root, τις διαδρομές proxy, τους καταλόγους upload, τις ρυθμίσεις εκτέλεσης PHP και τα αρχεία config που περιέχουν διαπιστευτήρια. Ένας listener loopback μπορεί να είναι προσβάσιμος μέσω proxy ή SSH tunnel. Για να ελέγξετε ένα ονομασμένο virtual host σε σχέση με έναν τοπικό listener, στείλτε την προβλεπόμενη κεφαλίδα `Host` ή χρησιμοποιήστε το `curl --resolve` με τη σωστή διεύθυνση και θύρα. Η απαρίθμηση virtual host μπορεί επίσης να αποκαλύψει ονόματα που απουσιάζουν από την προεπιλεγμένη απόκριση. Ελέγξτε αν το Apache επιτρέπει παρακάμψεις μέσω `.htaccess` και αν οι διαδρομές upload μπορούν να εκτελούν PHP, πριν θεωρήσετε ότι ένας εγγράψιμος κατάλογος upload επιτρέπει εκτέλεση κώδικα. Ένα ανεπτυγμένο JavaScript source map μπορεί να αποκαλύψει διαδρομές πηγαίου κώδικα ή μυστικά στην πλευρά του client· αντιμετωπίστε τις τιμές που ανακτώνται ως ενδείξεις και επαληθεύστε τα πραγματικά δικαιώματά τους. Για ελέγχους ειδικά για web, δείτε τα [Apache](../../network-services-pentesting/pentesting-web/apache.md) και [Nginx](../../network-services-pentesting/pentesting-web/nginx.md).

Για Apache με [mpm-itk](https://mpm-itk.sesse.net/), ένα ενεργό `AssignUserID` μπορεί να εκτελεί ένα virtual host με διαφορετικό χρήστη και ομάδα. Αν ένας λογαριασμός με χαμηλότερα προνόμια μπορεί να γράψει ένα script στο `DocumentRoot` αυτού του host, ελέγξτε αν μια προσβάσιμη διαδρομή το εκτελεί πράγματι με την εκχωρημένη ταυτότητα. Επιβεβαιώστε ότι το module είναι φορτωμένο, την ενεργή διαμόρφωση του virtual host (συμπεριλαμβανομένων των παρακάμψεων ταυτότητας βάσει εκφράσεων), τα δικαιώματα εγγραφής και αναζήτησης του καταλόγου, τον script handler και την πρόσβαση στον listener. Μια επισημασμένη οδηγία ή ένας εγγράψιμος κατάλογος από μόνα τους δεν αποδεικνύουν εκτέλεση με τα δικαιώματα άλλου χρήστη.

Ένας home directory που δημοσιεύεται μέσω web server μπορεί να εκθέσει αντίγραφα ασφαλείας αρχείων ταυτότητας SSH, ακόμη κι όταν ο ενεργός κατάλογος `.ssh` είναι ιδιωτικός. Για παράδειγμα, η ρύθμιση `homedirs_public` του [Nostromo](https://www.nazgul.ch/dev/nostromo_man.html) επιλέγει έναν υποκατάλογο από τους καταλόγους home των χρηστών για προβολή. Η εύρεση αρχειοθήκης μόνο βάσει διαδρομής είναι απλώς μια ένδειξη: επαληθεύστε την ενεργή αντιστοίχιση του server, την τοπική δυνατότητα ανάγνωσης ή την εξουσιοδότηση HTTP, τα περιεχόμενα της αρχειοθήκης, τη φράση πρόσβασης του ιδιωτικού κλειδιού και αν ο αντίστοιχος λογαριασμός δέχεται πράγματι το κλειδί. Μην εξάγετε αρχειοθήκες και μην εμφανίζετε υλικό κλειδιών κατά τη συνήθη απαρίθμηση host.

Ένα αναγνώσιμο αντίγραφο ασφαλείας μιας τοπικής web εφαρμογής με υψηλότερα προνόμια μπορεί να αποκαλύψει τη λογική αυθεντικοποίησης και ανάγνωσης αρχείων, ακόμη κι όταν ο ενεργός πηγαίος κώδικας δεν είναι προσβάσιμος. Συγκρίνετε το αντίγραφο ασφαλείας με την ανεπτυγμένη υπηρεσία πριν βασιστείτε σε αυτό. Ειδικότερα, αξίζει να εξεταστεί ένα cookie που δημιουργείται κρυπτογραφώντας κείμενο ελεγχόμενο από τον καλούντα, ακολουθούμενο από ένα μυστικό και μια σημαία ρόλου, αν η εφαρμογή χρησιμοποιεί ντετερμινιστικά μπλοκ ECB, επιστρέφει νέα cookies για επιλεγμένο κείμενο και αργότερα διαχωρίζει την αποκρυπτογραφημένη τιμή με βάση έναν μη διαφυγμένο οριοθέτη. Το [NIST εξηγεί την ανεξάρτητη, επαναλήψιμη αντιστοίχιση μπλοκ του ECB](https://csrc.nist.gov/news/2022/proposal-to-revise-sp-800-38a)· αυτή η ιδιότητα μπορεί να υποστηρίξει σύγκριση με επιλεγμένα δεδομένα εισόδου, αλλά από μόνη της δεν παρέχει υψηλότερο ρόλο. Επιβεβαιώστε την ενεργή διαδρομή, τις προϋποθέσεις συνεδρίας, τον ακριβή parser και τη ροή δεδομένων, την ταυτότητα της υπηρεσίας και μια ξεχωριστή προνομιακή ενέργεια ή διαδρομή ανάγνωσης αρχείων. Η παθητική απογραφή πρέπει να αναφέρει τα μεταδεδομένα του αντιγράφου ασφαλείας και τον κάτοχο του listener, χωρίς ανάγνωση των περιεχομένων της αρχειοθήκης ή αποστολή αιτημάτων αυθεντικοποίησης.

Η ίδια προσέγγιση εξέτασης πηγαίου κώδικα ισχύει για μια προνομιακή τοπική υπηρεσία **που δεν χρησιμοποιεί HTTP**, όπως μια προσαρμοσμένη διεπαφή βασισμένη σε SSH. Αν ένα προσβάσιμο αντίγραφο ασφαλείας του πηγαίου κώδικα δείχνει μια εντολή που δέχεται διαδρομή αρχείου επιλεγμένη από τον καλούντα, ελέγξτε την πύλη αυθεντικοποίησής της, τον τρόπο επίλυσης της διαδρομής και αν επιβεβαιώνει ότι το επιλυμένο αρχείο παραμένει κάτω από τον προβλεπόμενο κατάλογο πριν το ανοίξει. Στη Go, η [`filepath.Join`](https://pkg.go.dev/path/filepath#Join) καθαρίζει μια διαδρομή, αλλά δεν επιβάλλει αυτόν τον περιορισμό. Επιβεβαιώστε ότι το αντίγραφο ασφαλείας αντιστοιχεί στο εκτελούμενο build, ότι ο listener είναι προσβάσιμος, ότι ο λογαριασμός με χαμηλότερα προνόμια μπορεί να χρησιμοποιήσει την εντολή και ότι η διεργασία μπορεί να διαβάσει τον στόχο· η κατοχή ενός αναγνώσιμου κλειδιού SSH είναι ξεχωριστό ζήτημα πολιτικής σύνδεσης. Αναφέρετε τις διαδρομές των αρχειοθηκών πηγαίου κώδικα και τον κάτοχο της υπηρεσίας χωρίς να εξάγετε περιεχόμενα αρχειοθηκών ή κλειδιά σε αυτοματοποιημένη έξοδο.

Ένα pool PHP-FPM που ακούει σε TCP loopback μπορεί να είναι προσβάσιμο από άλλον τοπικό λογαριασμό, ακόμη κι όταν ο ιστότοπός του απαιτεί αυθεντικοποίηση. Η [PHP προειδοποιεί ότι ένας client που μπορεί να συνδεθεί στο FastCGI μπορεί να ελέγξει ρυθμίσεις αιτημάτων, συμπεριλαμβανομένου του `auto_prepend_file`](https://www.php.net/manual/en/install.fpm.php). Εξετάστε τις ρυθμίσεις `listen` και `listen.allowed_clients` του pool μαζί με τον ενεργό listener, το UID των worker, μια υπάρχουσα διαδρομή script και τυχόν περιορισμούς `security.limit_extensions` ή `php_admin_value`. Τα αρχεία config των pool μπορεί να περιέχουν διαπιστευτήρια σε οδηγίες `env[...]`, επομένως η αυτοματοποιημένη απογραφή πρέπει να αναφέρει τις διαδρομές τους αντί για τα περιεχόμενά τους. Ένα αρχείο config ή μια θύρα από μόνα τους δεν αποδεικνύουν διαδρομή εκτέλεσης μεταξύ χρηστών· δείτε τον [οδηγό FastCGI](../../network-services-pentesting/9000-pentesting-fastcgi.md) για λεπτομέρειες του πρωτοκόλλου.

Για ένα προνομιακό τοπικό API, ιχνηλατήστε την εξουσιοδότηση καθώς και την εκτέλεση κώδικα. Ένας ρόλος βάσης δεδομένων που μπορεί να τροποποιήσει ο λογαριασμός με χαμηλότερα προνόμια μπορεί να ξεκλειδώσει μια διαδρομή API, αλλά το επόμενο όριο ασφαλείας εξαρτάται από την υλοποίηση της διαδρομής. Για παράδειγμα, η συγχώνευση JSON αιτήματος σε ένα αντικείμενο JavaScript και στη συνέχεια η κλήση της [`child_process.exec`](https://nodejs.org/api/child_process.html) δικαιολογεί έλεγχο για [ροή δεδομένων από prototype pollution σε εκτέλεση](../../pentesting-web/deserialization/nodejs-proto-prototype-pollution/prototype-pollution-to-rce.md). Επαληθεύστε την πραγματική βιβλιοθήκη/έκδοση συγχώνευσης, την επικύρωση εισόδου, την προσβάσιμη διαδρομή, την ταυτότητα της διεργασίας και τις επιλογές της θυγατρικής διεργασίας· ένας listener Node που ανήκει στον root ή το όνομα μιας ευάλωτης εξάρτησης είναι απλώς μια ένδειξη.

Τα CMS που αποθηκεύουν δεδομένα σε αρχεία μπορεί να διατηρούν επαληθευτές κωδικών πρόσβασης διαχειριστών εκτός των συνηθισμένων αρχείων config `.php`. Παραδείγματα είναι το `data/database.js` ενός ιστότοπου ή το `data/settings/pass.php`. Ελέγξτε την ιδιοκτησία και τη δυνατότητα ανάγνωσης των αρχείων πριν από τη μη αυτόματη εξέτασή τους και μην συμπεριλαμβάνετε hashes σε κοινόχρηστη αυτοματοποιημένη έξοδο. Ένας κωδικός πρόσβασης εφαρμογής που μπορεί να ανακτηθεί αποτελεί ξεχωριστό όριο προνομίων από έναν λογαριασμό Unix: επαληθεύστε τυχόν ισχυρισμό περί επαναχρησιμοποίησής του για τον συγκεκριμένο λογαριασμό και την επιτρεπόμενη μέθοδο αυθεντικοποίησης.

Ο controller αυθεντικοποίησης μιας εφαρμογής μπορεί επίσης να περιέχει έναν κυριολεκτικό κωδικό σύνδεσης στον πηγαίο κώδικα αντί σε αρχείο config. Αν ένας χρήστης με χαμηλότερα προνόμια μπορεί να διαβάσει τον ανεπτυγμένο controller, εξετάστε τοπικά τη σύγκριση αυθεντικοποίησης και μην συμπεριλάβετε καμία τιμή σε κοινόχρηστη έξοδο απαρίθμησης. Επιβεβαιώστε ότι η διαδρομή κώδικα είναι ενεργή, ότι ο κωδικός είναι έγκυρος για την εφαρμογή και ότι ένας ξεχωριστός λογαριασμός Unix με υψηλότερα προνόμια δέχεται πράγματι τον ίδιο κωδικό πριν ισχυριστείτε τοπική κλιμάκωση προνομίων. Ένα όνομα αρχείου controller είναι απλώς μια ένδειξη για περαιτέρω έλεγχο.

Το Dolibarr αποθηκεύει ρυθμίσεις σύνδεσης βάσης δεδομένων, συμπεριλαμβανομένου του `dolibarr_main_db_pass`, στο `htdocs/conf/conf.php` ([αναφορά διαμόρφωσης](https://wiki.dolibarr.org/index.php/Configuration_file)). Ένα αναγνώσιμο αρχείο αποτελεί ένδειξη για διαπιστευτήρια· μόνο μια ξεχωριστή, επαληθευμένη επαναχρησιμοποίηση κωδικού πρόσβασης λογαριασμού ή άλλο δικαίωμα βάσης δεδομένων θα μπορούσε να οδηγήσει σε τοπική κλιμάκωση προνομίων. Ελέγξτε πρώτα τα δικαιώματα και αποφύγετε την εμφάνιση της τιμής σε αυτοματοποιημένη έξοδο.

Το αρχείο διαμόρφωσης του πακέτου GitLab για Linux είναι συνήθως το `/etc/gitlab/gitlab.rb`, αν και οι εγκαταστάσεις μπορεί να διατηρούν αναγνώσιμα αντίγραφα και αλλού. Το [GitLab τεκμηριώνει](https://docs.gitlab.com/omnibus/settings/smtp/) ότι αυτό το αρχείο μπορεί να περιέχει το `gitlab_rails['smtp_password']`, αν και οι κρυπτογραφημένες ρυθμίσεις SMTP μπορεί να διατηρούν τον κωδικό πρόσβασης εκτός του αρχείου απλού κειμένου. Αντιμετωπίστε ένα αναγνώσιμο αρχείο διαμόρφωσης ως ένδειξη για διαπιστευτήρια: επαληθεύστε ότι είναι ενεργό, ότι το διαπιστευτήριο είναι τρέχον και ότι ένας συγκεκριμένος λογαριασμός με υψηλότερα προνόμια το δέχεται πριν ισχυριστείτε επαναχρησιμοποίηση κωδικού πρόσβασης. Ξεχωριστά, το [GitLab εκτελεί το `gitlab.rb` ως κώδικα Ruby με δικαιώματα root κατά το `gitlab-ctl reconfigure`](https://docs.gitlab.com/omnibus/settings/configuration/)· ένα εγγράψιμο ενεργό αρχείο ή ένα συμπεριλαμβανόμενο `from_file` απαιτεί πραγματική διαδρομή επαναδιαμόρφωσης με προνόμια πριν αποτελεί εύρημα εκτέλεσης. Μια προεπισκόπηση config μπορεί να αποκαλύψει τιμές διαπιστευτηρίων, επομένως αντιμετωπίστε την έξοδό της ως ευαίσθητη και κοινοποιήστε μόνο διαδρομές και δικαιώματα.

Μια self-hosted εγκατάσταση Mattermost μπορεί να διατηρεί το `SqlSettings.DataSource` στο `/opt/mattermost/config/config.json`· το [Mattermost τεκμηριώνει](https://docs.mattermost.com/deployment-guide/server/troubleshooting) τόσο αυτή τη συνήθη διαδρομή όσο και εγκαταστάσεις που αποθηκεύουν την ενεργή διαμόρφωση σε βάση δεδομένων. Ένα αναγνώσιμο αρχείο μπορεί να αποκαλύψει διαπιστευτήριο βάσης δεδομένων της εφαρμογής, αλλά δεν αποδεικνύει πρόσβαση στη βάση δεδομένων ή πρόσβαση root στο Unix. Επαληθεύστε την ενεργή πηγή διαμόρφωσης, τα πραγματικά δικαιώματα του ρόλου βάσης δεδομένων, τυχόν ξεχωριστά ανακτημένο κωδικό πρόσβασης εφαρμογής και αν αυτός ο κωδικός λειτουργεί για συγκεκριμένο λογαριασμό Unix με υψηλότερα προνόμια. Η μορφή των password hash μπορεί να αλλάζει μεταξύ εκδόσεων Mattermost· κατά την απαρίθμηση, καταγράψτε τη διαδρομή του config και τα μεταδεδομένα πρόσβασης χωρίς να εμφανίζετε τη συμβολοσειρά σύνδεσης ή να υποβάλλετε ερωτήματα στη βάση δεδομένων.

```bash
curl -i -H 'Host: admin.example.local' http://127.0.0.1:8080/
ffuf -w wordlist.txt -u http://127.0.0.1:8080/ -H 'Host: FUZZ.example.local' -fs 1234 # replace 1234 with the default response size
grep -R 'sourceMappingURL' /var/www /opt 2>/dev/null | head
```

Φιλτράρετε τα αποτελέσματα virtual-host με βάση το μέγεθος της προεπιλεγμένης απόκρισης ή κάποιο άλλο σταθερό σημείο αναφοράς, ώστε να μη φαίνεται έγκυρο κάθε όνομα που δοκιμάστηκε. Ένα source map είναι χρήσιμο μόνο αν έχει πράγματι αναπτυχθεί ή είναι προσβάσιμο με άλλο τρόπο.

Τα reverse proxies μπορούν να αλλάξουν τις κεφαλίδες client που εμπιστεύεται μια εφαρμογή. Συγκρίνετε απευθείας και proxied αιτήματα πριν υποθέσετε ότι οι κεφαλίδες `X-Forwarded-For`, `X-Forwarded-Host` ή παρόμοιες καθορίζουν την ταυτότητα του caller. Εξετάστε από κοινού τη διαμόρφωση του proxy και της εφαρμογής.

Αν η PHP αντιγράφει το `$_SERVER['HTTP_X_FORWARDED_FOR']` σε μια συμβολοσειρά που περνά στη [`system()`](https://www.php.net/manual/en/function.system.php), εξετάστε αν η προσβάσιμη διαδρομή αιτήματος επιτρέπει κεφαλίδα που παρέχεται από τον caller και αν οι shell metacharacters φτάνουν σε αυτή τη συμβολοσειρά αναλλοίωτοι. Μια εντολή όπως `sudo iptables` στην αρχή **δεν** κάνει τις επόμενες εντολές που χωρίζονται με shell να εκτελεστούν ως root· αυτές εκτελούνται με τα δικαιώματα του web worker, εκτός αν υπάρχει ξεχωριστός ενεργός κανόνας sudo που επιτρέπει privilege escalation. Επιβεβαιώστε την ταυτότητα του worker, την ακριβή παραχώρηση του `sudo -l` και την απαίτηση αυθεντικοποίησης, καθώς και τα όρια των ορισμάτων της εντολής, πριν ισχυριστείτε ότι υπάρχει διαδρομή προς root. Εξετάστε τον πηγαίο κώδικα και την πολιτική χωρίς να στείλετε δοκιμαστικό injection κατά τη συνήθη απαρίθμηση του host.

## Διαπιστευτήρια σύνδεσης στα access logs

Αν μια εφαρμογή υποβάλλει φόρμα σύνδεσης με `GET`, το username και το password μπορούν να γίνουν query parameters στο URI του αιτήματος. Ένα αίτημα `POST` μπορεί επίσης να περιέχει query string· η χρήση του `POST` δεν αποκρύπτει ένα μυστικό που τοποθετήθηκε κατά λάθος στο URI, συμπεριλαμβανομένου ενός password που καταχωρίστηκε σε άσχετο πεδίο φόρμας. Η [συνηθισμένη γραμμή αιτήματος του access log του Apache](https://httpd.apache.org/docs/2.4/logs.html) καταγράφει τη μέθοδο και το URI, μαζί με το query string, όταν η διαμορφωμένη μορφή χρησιμοποιεί το `%r`. Επομένως, ένας λογαριασμός που μπορεί να διαβάσει αυτά τα logs, για παράδειγμα μέσω της ομάδας `adm` σε ορισμένα συστήματα Linux, ενδέχεται να βρει ένα στοιχείο για διαπιστευτήρια. Ελέγξτε την πραγματική μορφή log και τα δικαιώματα, έπειτα επαληθεύστε ότι η τιμή είναι μυστικό, ότι γίνεται δεκτή από τον λογαριασμό και ότι παρέχει πρόσβαση πέρα από ένα όριο προνομίων. Μην υποθέτετε ότι καταγράφηκε το σώμα του αιτήματος και μην αντιγράφετε πιθανές τιμές σε κοινόχρηστα αποτελέσματα.

Εξετάζετε μόνο προσβάσιμα access logs και μην εμφανίζετε τιμές διαπιστευτηρίων σε κοινόχρηστη έξοδο εντολών. Οι μεγάλες γραμμές αιτημάτων μπορεί επίσης να περιέχουν referrer και user agent, επομένως ένα φίλτρο σύντομων γραμμών μπορεί να αποκρύψει ακριβώς το αίτημα που σας ενδιαφέρει. Οι συνήθεις τοποθεσίες access log για Apache, httpd και Nginx είναι οι `/var/log/apache2/access.log`, `/var/log/httpd/access_log` και `/var/log/nginx/access.log`. Τα rotated logs μπορεί να περιέχουν παλαιότερα διαπιστευτήρια. Η [πρόσβαση σε αρχεία log μέσω LFI](../../pentesting-web/file-inclusion/README.md#read-access-logs-to-harvest-get-based-auth-tokens-token-replay) είναι μια σχετική διαδρομή προς τα ίδια δεδομένα.

Τα logs αυθεντικοποίησης εφαρμογών μπορεί επίσης να αποκαλύψουν κατά λάθος ένα password που καταχωρίστηκε στο πεδίο **username** μιας αποτυχημένης σύνδεσης. Πρώτα βεβαιωθείτε ότι το log είναι αναγνώσιμο και ότι η μορφή του καταγράφει το username που υποβλήθηκε· εξετάστε τοπικά μόνο ένα μικρό σχετικό τμήμα και μην αντιγράφετε πιθανά διαπιστευτήρια σε κοινόχρηστα αποτελέσματα. Ένα username που μοιάζει με password είναι στοιχείο, όχι απόδειξη έγκυρου password ή υψηλότερων προνομίων. Επαληθεύστε τον προβλεπόμενο λογαριασμό και τυχόν επαναχρησιμοποίηση διαπιστευτηρίων στη συγκεκριμένη υπηρεσία ή στον λογαριασμό Unix πριν ισχυριστείτε ότι υπάρχει μετάβαση.

Ένας εγγράψιμος χειριστής σύνδεσης ιστού χρειάζεται ξεχωριστή εξέταση, όταν ένας προγραμματισμένος client με διαφορετική ταυτότητα υποβάλλει διαπιστευτήρια σε αυτό το endpoint. Επιβεβαιώστε ότι υπάρχει δικαίωμα εγγραφής στον **ενεργό** χειριστή, το πραγματικό πρόγραμμα εκτέλεσης του client και τη διαδρομή του αιτήματος, ποιανού τα διαπιστευτήρια στέλνει και αν αυτό το password της εφαρμογής είναι ανεξάρτητα έγκυρο για λογαριασμό λειτουργικού συστήματος με υψηλότερα προνόμια. Μια εγγράψιμη σελίδα ή μια επαναλαμβανόμενη διεργασία από μόνη της δεν αποδεικνύει αυτή τη μετάβαση. Η παθητική απογραφή θα πρέπει να αναφέρει τα δικαιώματα διαδρομών και τα μεταδεδομένα εργασιών χωρίς να αλλάζει τον χειριστή ή να συλλέγει passwords.

Τα logs EVE JSON του Suricata μπορούν επίσης να καταγράφουν τις εντολές FTP `USER` και `PASS` μαζί με το `command_data`, όταν είναι ενεργή η καταγραφή συμβάντων FTP. Ελέγξτε αν είναι αναγνώσιμα τα `/var/log/suricata/eve*.json*`, συμπεριλαμβανομένων rotated ή συμπιεσμένων αρχείων, πριν εξετάσετε τοπικά ένα μικρό σχετικό τμήμα. Ένα αναγνώσιμο αρχείο EVE είναι μόνο ένα στοιχείο: επιβεβαιώστε ότι καταγράφηκαν συμβάντα FTP, ότι τα δεδομένα περιλαμβάνουν αξιοποιήσιμα διαπιστευτήρια και ότι παρέχουν πρόσβαση πέρα από ένα όριο προνομίων. Αποφύγετε να εμφανίζετε το `command_data` σε κοινόχρηστη έξοδο απαρίθμησης. Το Suricata τεκμηριώνει τα [πεδία συμβάντων FTP](https://docs.suricata.io/en/suricata-8.0.2/output/eve/eve-json-format.html) και τις [παραλλαγές περιστροφής και ονοματοδοσίας του EVE](https://docs.suricata.io/en/suricata-7.0.15/output/eve/eve-json-output.html).

## Δημιουργημένη διαμόρφωση Apache και piped logs

Το [remco](https://github.com/HeavyHorst/remco) μπορεί να παρακολουθεί ένα backend key/value, να αποδίδει ένα template σε αρχείο διαμόρφωσης Apache και να εκτελεί εντολή reload. Εξετάστε την ταυτότητα της διεργασίας remco που εκτελείται, την πηγή και τον προορισμό του διαμορφωμένου template, τα watched key prefixes και αν μια τιμή backend εισάγεται απευθείας σε οδηγία Apache, όπως η `ServerName`. Ένας τοπικός listener backend από μόνος του δεν αποδεικνύει ότι ο τρέχων χρήστης μπορεί να γράψει σε watched key· επαληθεύστε την αυθεντικοποίηση και τα δικαιώματα του backend πριν ισχυριστείτε ότι υπάρχει privilege escalation.

Μια μη escaped αλλαγή γραμμής σε εγγράψιμη τιμή backend μπορεί να μετατρέψει μία προβλεπόμενη τιμή οδηγίας σε πρόσθετες οδηγίες Apache. Τα [piped logs του Apache](https://httpd.apache.org/docs/2.4/logs.html#piped) είναι ιδιαίτερα ευαίσθητα: τα `CustomLog` ή `ErrorLog` με εντολή `|` εκκινούν ένα helper με την ταυτότητα του γονικού httpd, συχνά ως root· το `|$` ζητά από το Apache να χρησιμοποιήσει shell. Εξετάστε τη δημιουργημένη διαμόρφωση και τη διαδρομή reload χωρίς να αλλάξετε δεδομένα backend ή να επανεκκινήσετε την υπηρεσία κατά την απαρίθμηση. Διατηρήστε ιδιωτική ολόκληρη την piped εντολή, επειδή τα ορίσματά της μπορεί να περιέχουν μυστικά.

## Ταυτότητες αυθεντικοποίησης και υπηρεσιών

Το αρχείο ελέγχου του Monit είναι συνήθως το `~/.monitrc` ή το `/etc/monitrc`, αλλά το `monit -c` μπορεί να επιλέξει διαφορετική διαδρομή. Ένα αναγνώσιμο αρχείο μπορεί να περιέχει καταχωρίσεις `set httpd` και `allow user:password` για το web interface του, συχνά στην τοπική θύρα 2812. Ελέγξτε τον ιδιοκτήτη και τα δικαιώματα του αρχείου πριν το εξετάσετε και μην εμφανίζετε τιμές password σε κοινόχρηστη έξοδο απαρίθμησης. Τα διαπιστευτήρια web παρέχουν μόνο τον διαμορφωμένο ρόλο Monit· οι χρήστες μόνο για ανάγνωση δεν μπορούν να εκτελέσουν ενέργειες ελέγχου. Η μετάβαση σε ξεχωριστό λογαριασμό Unix απαιτεί επιβεβαιωμένη επαναχρησιμοποίηση password ή προνομιούχα ενέργεια Monit που μπορεί πράγματι να ενεργοποιήσει ο αυθεντικοποιημένος ρόλος. Δείτε την [τεκμηρίωση του αρχείου ελέγχου και της αυθεντικοποίησης του Monit](https://www.mmonit.com/monit/documentation/monit.html).

Για το Webmin, το `/etc/webmin/miniserv.conf` προσδιορίζει τις ρυθμίσεις του server και το `/etc/webmin/webmin.acl` καταγράφει τις μονάδες στις οποίες έχουν πρόσβαση οι χρήστες· το [Webmin τεκμηριώνει τα όρια παραχώρησης μονάδων](https://webmin.com/docs/development/creating-modules/). Ένα Unix password ή ένα αναγνώσιμο αρχείο ACL δεν παρέχει από μόνο του συνεδρία Webmin. Επιβεβαιώστε την πραγματική αντιστοίχιση αυθεντικοποίησης, τον προσβάσιμο listener, τον αυθεντικοποιημένο λογαριασμό, τα ενεργά δικαιώματα της μονάδας Package Updates, τον εγκατεστημένο κώδικα ή τη διόρθωση του vendor και την ταυτότητα της διεργασίας Webmin. Σε επηρεαζόμενες εκδόσεις έως και την 1.910, το [CVE-2019-12840](https://nvd.nist.gov/vuln/detail/CVE-2019-12840) επέτρεπε σε λογαριασμό με αυτά τα δικαιώματα μονάδας να εκτελεί εντολές μέσω του handler ενημερώσεων. Κατά την παθητική απαρίθμηση, αναφέρετε τις διαδρομές και τα δικαιώματα διαμόρφωσης χωρίς να εμφανίζετε διαπιστευτήρια ή να επιχειρείτε ενημέρωση.

```bash
find /etc/pam.d /etc/sssd /etc/postfix -maxdepth 2 -type f -ls 2>/dev/null
systemctl cat sssd postfix jenkins 2>/dev/null
getent passwd
```

- Το [PAM](pam-pluggable-authentication-modules.md) διέπει τον έλεγχο ταυτότητας ανά υπηρεσία· εγγράψιμες πολιτικές ή διαδρομές modules μπορούν να αλλάξουν τη συμπεριφορά σύνδεσης.
- Οι ρυθμίσεις LDAP/SSSD μπορεί να αποκαλύψουν endpoints καταλόγου, bind identities και κανόνες πρόσβασης. Ένας κωδικός πρόσβασης bind που ανακτήθηκε μπορεί να επιτρέπει ερωτήματα LDAP πέρα από τον τρέχοντα λογαριασμό OS· δοκιμάστε την ακριβή bind identity και τα ACL του καταλόγου. Ελέγξτε τα δικαιώματα αρχείων πριν εξετάσετε secrets· τα [Linux Active Directory](../user-information/linux-active-directory.md) και [FreeIPA](freeipa-pentesting.md) καλύπτουν τη χρήση tickets και καταλόγων.
- Τα aliases του Postfix μπορούν να προωθούν εισερχόμενα email σε τοπικές εντολές. Αν ένας χρήστης με χαμηλότερα δικαιώματα μπορεί να αλλάξει το αναφερόμενο script, η παράδοση email μπορεί να εκτελέσει τον κώδικά του με την ταυτότητα παράδοσης. Ελέγξτε τους alias maps και την ιδιοκτησία του script πριν αναφέρετε αυτή τη διαδρομή· δείτε το [SMTP and mail service testing](../../network-services-pentesting/pentesting-smtp/README.md).
- Οι Jenkins και άλλες υπηρεσίες CI μπορεί να εκτελούν jobs με ισχυρό τοπικό λογαριασμό. Εξετάστε τον χρήστη της υπηρεσίας, τις εγγράψιμες διαδρομές job/workspace και το τοπικό περιβάλλον διαχείρισης πριν δοκιμάσετε ένα Pipeline ή plugin. Εξετάστε επίσης τα **credentials που είναι διαθέσιμα σε ένα job** και τον λογαριασμό με τον οποίο μπορούν να κάνουν authentication: ένα Pipeline που χρησιμοποιεί το [SSH Agent step](https://www.jenkins.io/doc/pipeline/steps/ssh-agent/) μπορεί να αποκτήσει πρόσβαση σε έναν host ως ο χρήστης του SSH credential, ακόμη κι όταν το Jenkins εκτελείται με λιγότερο προνομιούχο λογαριασμό Unix. Επιβεβαιώστε ότι η τρέχουσα Jenkins identity έχει `Job/Create`, `Job/Configure` ή άλλη αποτελεσματική δυνατότητα να αλλάξει το Pipeline, ότι το credential είναι εντός του scope για εκείνο το job και ότι ο λογαριασμός SSH του στόχου δέχεται το key, πριν αναφέρετε privilege escalation σε host. Το όνομα εμφάνισης ή το ID ενός credential από μόνο του δεν αποδεικνύει καμία από αυτές τις προϋποθέσεις. Το Jenkins προειδοποιεί ότι οι δημιουργοί job και, συχνά, όσοι ρυθμίζουν job μπορούν να χρησιμοποιήσουν αυθαίρετα τα credentials που είναι διαθέσιμα στο scope τους· επομένως, το [credential scope](https://www.jenkins.io/doc/book/security/credentials/) και το [Pipeline trust](https://www.jenkins.io/doc/book/security/securing-org-folders-and-multibranch-pipelines/) είναι εξίσου σημαντικά με το UID της υπηρεσίας. Μην συμπεριλαμβάνετε τιμές credentials και private keys σε κοινόχρηστα αποτελέσματα enumeration.

## Εγγραφή αρχείων αποθετηρίου Gogs

Για μια τοπική υπηρεσία Gogs, συσχετίστε τον ιδιοκτήτη της διεργασίας `gogs web` με την έκδοση του εκτελέσιμου αρχείου και το `custom/conf/app.ini`. Η ρύθμιση μπορεί να αποκαλύψει την ταυτότητα της υπηρεσίας, τη ρίζα του αποθετηρίου, τη διεύθυνση listener και αν είναι απενεργοποιημένη η εγγραφή χρηστών. Ένας listener που δέχεται συνδέσεις μόνο από loopback παραμένει προσβάσιμος σε τοπικούς χρήστες. Οι εκδόσεις Gogs έως και 0.13.3 έχουν ένα authenticated πρόβλημα εγγραφής αρχείου μέσω symlink στο `PutContents` ([CVE-2025-8110](https://github.com/advisories/GHSA-mq8m-42gh-wq7r)): ένας χρήστης με δικαίωμα εγγραφής στο αποθετήριο μπορεί να κάνει commit ένα symlink και στη συνέχεια να κατευθύνει μέσω αυτού την εγγραφή του API. Η πρόσβαση στο αρχείο που προκύπτει έχει τα δικαιώματα της διεργασίας Gogs, επομένως μια instance που εκτελείται ως root απαιτεί άμεση προσοχή. Επιβεβαιώστε τη διορθωμένη έκδοση που έχει εγκατασταθεί και τις απαιτήσεις authentication πριν αναφέρετε αξιοποιήσιμη διαδρομή· ένα σφάλμα API δεν αποδεικνύει ότι η εγγραφή του αρχείου απέτυχε.

## XSS στην περιγραφή αποθετηρίου Gitea και προνομιούχοι χρήστες που την προβάλλουν

Το Gitea 1.22.0 επέτρεπε αποθηκευμένο JavaScript σε περιγραφή αποθετηρίου ([CVE-2024-6886](https://github.com/advisories/GHSA-4h4p-553m-46qh))· το 1.22.1 το διόρθωσε. Ένας χρήστης που μπορεί να επεξεργαστεί μια περιγραφή μπορεί να επηρεάσει μια συνεδρία browser με περισσότερα δικαιώματα, αν ο χρήστης εκείνης της συνεδρίας προβάλλει το αποθετήριο και ενεργοποιήσει τον κακόβουλο σύνδεσμο. Στη συνέχεια, αυτή η ταυτότητα browser μπορεί να αποκαλύψει περιεχόμενο ιδιωτικού αποθετηρίου ή άλλα δεδομένα της εφαρμογής. Για ξεχωριστό local escalation απαιτείται credential ή permission προσβάσιμο μέσω αυτού του περιεχομένου, όπως ένας επαναχρησιμοποιημένος κωδικός πρόσβασης διαχειριστή· ο ιδιοκτήτης της διεργασίας Gitea από μόνος του δεν τεκμηριώνει επίπτωση σε root. Ελέγξτε την εγκατεστημένη έκδοση, την πρόσβαση επεξεργασίας περιγραφής, τη ροή εργασίας του χρήστη που την προβάλλει και την πραγματική αλληλεπίδραση με το browser πριν αναφέρετε την αλυσίδα.

## API provisioning του Cobbler

Η υπηρεσία διαχείρισης του Cobbler εκθέτει ένα XML-RPC API, συνήθως στη θύρα `25151`. Ελέγξτε τον listener και τον ιδιοκτήτη της διεργασίας `cobblerd` πριν αξιολογήσετε τον αντίκτυπό του· ένα API που δέχεται συνδέσεις μόνο από loopback παραμένει προσβάσιμο από χρήστη του host. Εξετάστε τα modules authentication και authorization στο `/etc/cobbler/modules.conf`, τις ρυθμίσεις υπηρεσίας στο `/etc/cobbler/settings` ή στο `/etc/cobbler/settings.yaml` και τα δικαιώματα στα `/etc/cobbler/users.conf`, `/etc/cobbler/users.digest` και `/var/lib/cobbler/web.ss`. Τα αρχεία digest και shared-secret περιέχουν στοιχεία credentials, επομένως καταγράψτε αν είναι αναγνώσιμα χωρίς να εκτυπώνετε το περιεχόμενό τους από προεπιλογή.

```bash
ps -eo user,pid,args | grep '[c]obblerd'
ss -ltn 2>/dev/null | grep ':25151'
for file in /etc/cobbler/modules.conf /etc/cobbler/settings /etc/cobbler/settings.yaml \
            /etc/cobbler/users.conf /etc/cobbler/users.digest /var/lib/cobbler/web.ss; do
    [ -e "$file" ] && ls -l "$file"
done
```

**CVE-2024-47533** είναι παράκαμψη ελέγχου ταυτότητας XML-RPC στο Cobbler 3.0.0 έως 3.2.2 και 3.3.0 έως 3.3.6. Ένα σφάλμα ανάγνωσης του shared secret επέστρεφε την προβλέψιμη τιμή `-1`, την οποία το API δεχόταν ως password. Οι αντίστοιχες διορθώσεις είναι οι εκδόσεις 3.2.3 και 3.3.7. Η έκδοση ενός πακέτου αποτελεί μόνο ένδειξη· επαληθεύστε τον εγκατεστημένο κώδικα και τυχόν backported διόρθωση πριν αναφέρετε έκθεση.

Μια αυθεντικοποιημένη συνεδρία API μπορεί να προσφέρει προνομιακή διαδρομή εκτέλεσης όταν το `cobblerd` εκτελείται ως root. Σε ευάλωτες υλοποιήσεις, το `background_import` περνά το ελεγχόμενο από τον χρήστη `rsync_flags` σε μια shell command, ενώ η απόδοση ενός ελεγχόμενου από τον χρήστη Cheetah autoinstall template μπορεί να εκτελέσει Python. Ελέγξτε τα δικαιώματα του API και την εγκατεστημένη έκδοση πριν δοκιμάσετε οποιαδήποτε από αυτές τις διαδρομές. Περιορίστε την πρόσβαση στο management API, διορθώστε την παράκαμψη ελέγχου ταυτότητας και επιτρέψτε την ανάγνωση των αρχείων ρυθμίσεων και διαπιστευτηρίων μόνο στους διαχειριστές της υπηρεσίας.

## Ρυθμίσεις Motion και motionEye

Εξετάστε το `/etc/motioneye/motioneye.conf` για το `conf_path` και, στη συνέχεια, ελέγξτε τα `motion.conf` και μερικά αρχεία `camera-*.conf` σε αυτόν τον κατάλογο. Αναφέρετε αν υπάρχει αναγνώσιμο hash `# @admin_password`, χωρίς να το εμφανίσετε. [Παλαιότερες εκδόσεις του motionEye δημιουργούσαν αυτά τα αρχεία με ευρεία δικαιώματα ανάγνωσης](https://github.com/motioneye-project/motioneye/security/advisories/GHSA-rhgp-6wq6-9j67)· η διόρθωση περιλαμβάνεται στην έκδοση 0.44.0. Ελέγξτε μαζί τις ρυθμίσεις Motion `webcontrol_port`, `webcontrol_parms`, `webcontrol_auth_method` και `webcontrol_localhost`: ο προηγμένος έλεγχος (`2` ή `3`) με απενεργοποιημένο έλεγχο ταυτότητας μπορεί να εκθέσει ισχυρές λειτουργίες σε τοπικό χρήστη, ακόμη και σε listener loopback. [Το Motion τεκμηριώνει τις τιμές και τις προεπιλογές](https://motion-project.github.io/motion_config.html).

Μια συνεδρία admin στο motionEye πριν από την έκδοση 0.43.1b5 μπορούσε να μετατρέψει μια ρύθμιση ονόματος αρχείου κάμερας σε εκτέλεση εντολών κατά την επεξεργασία της από το Motion ([CVE-2025-60787](https://github.com/motioneye-project/motioneye/security/advisories/GHSA-j945-qm58-4gjx)). Επιβεβαιώστε την έκδοση που εκτελείται, την ταυτότητα της υπηρεσίας, αν υπάρχει λειτουργική διαδρομή ελέγχου ταυτότητας και αν έχει ρυθμιστεί κάμερα πριν αναφέρετε πιθανή κλιμάκωση προνομίων. Η ρύθμιση από μόνη της δεν αποδεικνύει ότι η υπηρεσία εκτελείται ή έχει προνόμια.

Ένα όνομα υπηρεσίας ή ένα εγκατεστημένο πακέτο αποτελεί μόνο ένδειξη. Το όριο προνομίων καθορίζεται από τον συνδυασμό της προσβάσιμης εισόδου, της ταυτότητας της διεργασίας, των εγγράψιμων ρυθμίσεων και της εντολής ή του αρχείου που τελικά ελέγχει.

## Τοπικοί εξομοιωτές AWS και αποθηκευμένα διαπιστευτήρια

Ένας χρήστης του host μπορεί να έχει πρόσβαση σε έναν συμβατό με AWS εξομοιωτή που εκτελείται σε container μέσω του δημοσιευμένου endpoint loopback. Συσχετίστε τον ενεργό listener, το endpoint και τον λογαριασμό που επιλέγει ο client, καθώς και τις εγκατεστημένες ρυθμίσεις εξουσιοδότησης του εξομοιωτή, πριν αξιολογήσετε την πρόσβαση στο [Secrets Manager](https://docs.localstack.cloud/aws/services/secretsmanager/) ή στο [KMS](https://docs.localstack.cloud/aws/services/kms/). Στο LocalStack, [η επιβολή πολιτικών IAM είναι ξεχωριστή ρύθμιση](https://docs.localstack.cloud/aws/developer-tools/security-testing/iam-policy-enforcement/)· μην συμπεραίνετε τα πραγματικά δικαιώματα API μόνο από ένα αρχείο διαπιστευτηρίων, μια πολιτική IAM ή έναν listener. Επιβεβαιώστε τη συμπεριφορά της εγκατεστημένης έκδοσης και των ρυθμίσεων.

Ένα αποθηκευμένο secret είναι χρήσιμο για τοπική κλιμάκωση προνομίων μόνο αν η τρέχουσα ταυτότητα API μπορεί να το ανακτήσει και ένας ξεχωριστός λογαριασμός με υψηλότερα προνόμια αποδέχεται το διαπιστευτήριο που ανακτήθηκε. Ένα κρυπτογραφημένο τοπικό blob απαιτεί επίσης δικαίωμα ανάγνωσης του αρχείου, το αντίστοιχο λειτουργικό κλειδί KMS και αλγόριθμο, καθώς και πραγματική πρόσβαση αποκρυπτογράφησης. Για ένα [ασύμμετρο κλειδί KMS](https://docs.aws.amazon.com/cli/latest/reference/kms/decrypt.html), το αίτημα αποκρυπτογράφησης πρέπει να καθορίζει τον αλγόριθμο που χρησιμοποιήθηκε για την κρυπτογράφηση του blob. Περιορίστε την αυτόματη απογραφή του host σε στοιχεία για διεργασίες, listeners, διαδρομές ρυθμίσεων και δικαιώματα αρχείων· μην ζητάτε ούτε εμφανίζετε τιμές secret ή αποκρυπτογραφημένο plaintext κατά τη συνήθη απαρίθμηση.
