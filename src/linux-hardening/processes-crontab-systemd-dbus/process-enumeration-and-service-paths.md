# Απαρίθμηση διεργασιών και διαδρομές υπηρεσιών

{{#include ../../banners/hacktricks-training.md}}

Το χρήσιμο ερώτημα είναι ποια προνομιούχα διεργασία καταναλώνει δεδομένα ή κώδικα που μπορεί να επηρεάσει ένας χρήστης με λιγότερα προνόμια. Εξετάστε το δέντρο διεργασιών, το ενεργό περιβάλλον, τα ανοιχτά αρχεία, καθώς και το unit ή το script που εκκίνησε κάθε υποψήφια διεργασία.

## Χαρτογράφηση διεργασιών και ιδιοκτησίας

```bash
ps -eo user,pid,ppid,tty,comm,args --sort=ppid
pstree -alp 2>/dev/null
systemctl list-units --type=service --state=running 2>/dev/null
ss -lntup
```

Μια σχέση γονέα-παιδιού μεταξύ διαφορετικών χρηστών μπορεί να είναι φυσιολογική, αλλά μια απρόσμενη μετάβαση απαιτεί έλεγχο της εντολής του γονέα, των ορισμάτων, του εκτελέσιμου αρχείου, του καταλόγου εργασίας και των αρχείων στα οποία γίνεται αναφορά. Χρησιμοποιήστε τις [πληροφορίες χρηστών και συνεδριών](../user-information/user-and-session-triage.md) για να ερμηνεύσετε τον κάτοχο και το πλαίσιο σύνδεσης.

### Κονσόλες τοπικών εικονικών μηχανών

Εξετάστε τις επιλογές `-spice` μιας διεργασίας QEMU μαζί με τη διεύθυνση στην οποία ακούει. Η [τεκμηρίωση του QEMU](https://www.qemu.org/docs/master/system/qemu-manpage.html) αναφέρει ότι το `disable-ticketing` επιτρέπει σε SPICE clients να συνδέονται χωρίς έλεγχο ταυτότητας. Ένας listener που είναι δεσμευμένος στη loopback μπορεί και πάλι να είναι προσβάσιμος από άλλους τοπικούς χρήστες του host. Επιβεβαιώστε τον ενεργό listener, τις επιλογές ελέγχου ταυτότητας και την τοπική πρόσβαση προτού θεωρήσετε ότι η γραμμή εντολών εκθέτει μια κονσόλα. Ο έλεγχος της κονσόλας επηρεάζει το **guest**· η απόκτηση λογαριασμού guest ή η αλλαγή της κατάστασης εκκίνησής του απαιτεί ξεχωριστές συνθήκες στο guest και δεν παρέχει root στον host εικονικοποίησης. Διαβάστε τα ορίσματα της διεργασίας και τα μεταδεδομένα του socket χωρίς να συνδεθείτε στο guest ή να το επανεκκινήσετε κατά την παθητική απαρίθμηση.

Μια τοπικά προσβάσιμη web διεπαφή μπορεί να εκτελέσει κώδικα με τον λογαριασμό της υπηρεσίας, ακόμη κι όταν το αρχικό shell δεν μπορεί να προσπελάσει τα αρχεία αυτού του λογαριασμού. Για παράδειγμα, το CVE-2023-0297 επηρέαζε τον χειρισμό του `/flash/addcrypted2` από το pyLoad, όταν μη έμπιστο JavaScript έφτανε στο Js2Py με ενεργοποιημένα τα Python imports· η [διόρθωση upstream](https://github.com/pyload/pyload/commit/7d73ba7919e594d783b3411d7ddb87885aea782d) απενεργοποίησε το `pyimport`. Συσχετίστε τον κάτοχο της εκτελούμενης διεργασίας, τη διεύθυνση ακρόασης, την έκθεση του endpoint και την εγκατεστημένη ενημέρωση κώδικα ή το backport του προμηθευτή, προτού θεωρήσετε μια διεργασία pyLoad διαδρομή κλιμάκωσης προνομίων. Το όνομα διεργασίας, μια ανοιχτή θύρα ή η έκδοση του πακέτου από μόνα τους δεν αποδεικνύουν έκθεση· η παθητική απαρίθμηση δεν πρέπει να στέλνει payload εκτέλεσης.

### Προνομιούχα login shells που μοιράζονται ένα terminal

Ένα προνομιούχο διαδραστικό shell που εκτελεί `su --login <user>` χωρίς ανεξάρτητο pseudo-terminal μπορεί να αφήσει το terminal κοινόχρηστο με το login shell του χρήστη με τα λιγότερα προνόμια. Αν το startup file αυτού του χρήστη είναι ελέγξιμο και ο κώδικας σε αυτό μπορεί να χρησιμοποιήσει το `TIOCSTI` για να εισαγάγει είσοδο στο terminal, η είσοδος μπορεί να φτάσει στο προνομιούχο shell όταν αυτό συνεχίσει. Το [εγχειρίδιο του `su` από το util-linux](https://man7.org/linux/man-pages/man1/su.1.html#SECURITY_NOTES) περιγράφει τον κίνδυνο του κοινόχρηστου terminal και συνιστά `su --pty`/`-P` για διαδραστική χρήση· το `su -c` ξεκινά ξεχωριστή συνεδρία χωρίς controlling terminal. Ο κίνδυνος εξαρτάται από το πραγματικό parent shell, τη σχέση των terminal, το startup file-στόχο και την πολιτική του kernel. Ένα όνομα διεργασίας ή το όρισμα `su -l` είναι απλώς αφορμή για έλεγχο.

Εξετάστε το παρατηρούμενο δέντρο διεργασιών και τις στήλες TTY, έπειτα ελέγξτε τον launcher που είναι αναγνώσιμος και την ιδιοκτησία/τα δικαιώματα του startup file. Στο Linux, το `/proc/sys/dev/tty/legacy_tiocsti` μπορεί να βοηθήσει στην ερμηνεία της πολιτικής, αν υπάρχει· η απουσία του δεν αποδεικνύει ότι το σύστημα είναι ασφαλές. Το [εγχειρίδιο του Linux για το `TIOCSTI`](https://man7.org/linux/man-pages/man2/TIOCSTI.2const.html) σημειώνει ότι από το Linux 6.2 και μετά, η λειτουργία μπορεί να απαιτεί `CAP_SYS_ADMIN` όταν αυτό το sysctl είναι false. Μην εκτελείτε το ioctl απλώς για να απαριθμήσετε τον host.

Ένας λογαριασμός βάσης δεδομένων μπορεί μερικές φορές να τροποποιήσει το startup file του χρήστη-στόχου χωρίς άμεση πρόσβαση εγγραφής στο filesystem. Η εντολή `COPY ... TO 'filename'` στην πλευρά του server PostgreSQL γράφει ως ο λογαριασμός OS του server βάσης δεδομένων, αλλά το [PostgreSQL θέτει περιορισμούς](https://www.postgresql.org/docs/current/sql-copy.html) σε αυτή τη μορφή αρχείου, επιτρέποντάς την μόνο σε superusers της βάσης δεδομένων ή σε ρόλους όπως το `pg_write_server_files`. Επιβεβαιώστε τόσο τον ρόλο της βάσης δεδομένων όσο και τα δικαιώματα αρχείων του OS του server· μια συμβολοσειρά σύνδεσης εφαρμογής από μόνη της δεν παρέχει δικαιώματα εγγραφής σε αρχεία. Κατά την αξιολόγηση της αλυσίδας, εξετάστε ξεχωριστά τον προνομιούχο launcher και τις δυνατότητες του λογαριασμού της βάσης δεδομένων.

## Επιθεώρηση τεχνουργημάτων εκτέλεσης

```bash
readlink /proc/<PID>/exe
tr '\0' ' ' </proc/<PID>/cmdline; echo
ls -l /proc/<PID>/fd 2>/dev/null
lsof -p <PID> 2>/dev/null
lsof +L1 2>/dev/null
```

Τα διαγραμμένα εκτελέσιμα αρχεία και τα διαγραμμένα αλλά ανοιχτά αρχεία παραμένουν προσβάσιμα μέσω αναφοράς μέχρι να κλείσει ο τελευταίος descriptor. Μπορούν να διατηρούν αποδεικτικά στοιχεία ή προσβάσιμα μυστικά. Τα περιβάλλοντα και η μνήμη διεργασιών μπορεί να περιέχουν διαπιστευτήρια, αλλά η ανάγνωση μιας άλλης διεργασίας περιορίζεται από τον κάτοχο, τις επιλογές προσάρτησης του `/proc`, την πολιτική Yama ptrace και άλλα μέτρα ασφαλείας. Δείτε τα [file descriptors](../main-system-information/filesystem-links-and-file-descriptors.md) και το [post-exploitation credential hunting](../post-exploitation/README.md) για σχετικές τεχνικές.

Τα αποθηκευμένα ίχνη syscall αποτελούν ένα ακόμη όριο δικαιωμάτων αρχείων. Το [`strace` καταγράφει ορίσματα syscall σε ένα αρχείο εξόδου](https://man7.org/linux/man-pages/man1/strace.1.html), επομένως ένα αναγνώσιμο ίχνος ορισμάτων [`execve`](https://man7.org/linux/man-pages/man2/execve.2.html) μπορεί να αποκαλύψει έναν κωδικό πρόσβασης που μια προνομιούχα εργασία πέρασε στη γραμμή εντολών της. Αρχικά, βεβαιωθείτε ότι ο τρέχων χρήστης μπορεί να διαβάσει το συγκεκριμένο ίχνος και ότι το όρισμα πράγματι περιέχει διαπιστευτήριο· για να αποδειχθεί στη συνέχεια ότι η μετάβαση σε άλλον λογαριασμό Unix είναι εφικτή, χρειάζεται ξεχωριστή επιβεβαίωση ότι το διαπιστευτήριο γίνεται αποδεκτό εκεί. Τα μεταδεδομένα αρχείων αποτελούν χρήσιμο παθητικό στοιχείο χωρίς να χρειάζεται να σαρώσετε κάθε ίχνος ή να εμφανίσετε τα περιεχόμενά του κατά τη συνήθη απαρίθμηση.

## Sockets αυτοματοποίησης γραφείου με προνόμια

Τα LibreOffice και OpenOffice μπορούν να εκθέσουν το UNO API τους μέσω ενός ορίσματος `--accept=socket,host=<host>,port=<port>;urp;`. Μια διεργασία γραφείου που ανήκει στον root και διαθέτει προσβάσιμο endpoint μπορεί να επιτρέψει σε έναν τοπικό χρήστη με λιγότερα προνόμια να καλέσει υπηρεσίες API στο πλαίσιο ασφαλείας αυτής της διεργασίας. Η υπηρεσία `SystemShellExecute` περιλαμβάνει λειτουργία για την εκκίνηση μιας εντολής συστήματος. Η σύνδεση στη διεύθυνση loopback περιορίζει την απομακρυσμένη προσβασιμότητα, αλλά το socket παραμένει προσβάσιμο σε τοπικούς χρήστες, εκτός αν κάποιο άλλο μέτρο ελέγχου εμποδίζει την πρόσβαση.<sup>[[7]](#references)[[8]](#references)</sup>

```bash
ps -eo user,args | grep -E '[s]office|[l]ibreoffice|[o]penoffice'
ss -ltn 2>/dev/null
```

Συσχετίστε τον κάτοχο της διεργασίας, το ακριβές όρισμα `--accept` και την τρέχουσα διεύθυνση και θύρα ακρόασης. Ένας acceptor που έχει ρυθμιστεί αλλά απέτυχε να δεσμεύσει τη διεύθυνση αποτελεί απλώς ένδειξη· μην συνδεθείτε στο API και μην το καλέσετε κατά την παθητική απαρίθμηση. Αποφύγετε να εκκινήσετε μια προνομιούχα διεργασία office μόνο και μόνο για να ελέγξετε αυτήν την περίπτωση.

## System V shared memory που χρησιμοποιείται από προνομιούχες διεργασίες

Ένα βοηθητικό πρόγραμμα που ανήκει στον root μπορεί να δημιουργήσει ένα τμήμα System V shared memory στο οποίο μπορεί να γράψει κάποιος άλλος χρήστης. Αν το βοηθητικό πρόγραμμα εμπιστευτεί αργότερα δεδομένα από αυτό το τμήμα σε μια εντολή shell ή σε άλλη ευαίσθητη λειτουργία, το τμήμα διασχίζει ένα όριο προνομίων, ακόμη κι αν το εκτελέσιμο αρχείο και τα αρχεία του είναι προστατευμένα. Η `shmget()` λαμβάνει τα δικαιώματα πρόσβασης από τα εννέα χαμηλότερα bit των flags της· η λειτουργία `0666` επιτρέπει σε άλλους χρήστες να γράφουν, ενώ το flag `IPC_CREAT` δεν περιορίζει αυτά τα δικαιώματα. Επιθεωρήστε παθητικά τα ενεργά τμήματα με `ipcs -m` και συσχετίστε τον κάτοχό τους, τη λειτουργία και τη διάρκεια ζωής τους με την προνομιούχα διεργασία και τον χειρισμό των εισόδων της. Ένα τμήμα με δικαίωμα εγγραφής από όλους δεν αποδεικνύει από μόνο του την εκτέλεση εντολών.<sup>[[1]](#references)[[2]](#references)</sup>

```bash
ipcs -m
```

Τα segments System V διαφέρουν από τα αρχεία shared memory του POSIX στο `/dev/shm`. Ένα segment που δημιουργείται μόνο για λίγο μπορεί να απουσιάζει από ένα μεμονωμένο στιγμιότυπο του `ipcs`, επομένως η κενή έξοδος δεν αποκλείει την ύπαρξη ενός helper που χρησιμοποιεί shared memory. Εξετάστε τον πηγαίο κώδικα ή τη συμπεριφορά του binary, καθώς και τυχόν κανόνα `sudo` που το εκκινεί· μην εκτελέσετε το privileged helper μόνο και μόνο για να εμφανιστεί ένα segment κατά την απαρίθμηση. Ο [οδηγός για τα IPC namespaces](../containers-namespaces/container-security/protections/namespaces/ipc-namespace.md) εξηγεί πώς τα namespaces επηρεάζουν την ορατότητα.<sup>[[2]](#references)[[3]](#references)</sup>

## Έλεγχοι script του Consul agent

Το Consul μπορεί να εκτελεί ελέγχους υγείας μέσω script με την ταυτότητα λειτουργικού συστήματος του agent του. Αν ένας agent εκτελείται ως root, έχει ενεργοποιημένο το `enable_script_checks` και επιτρέπει σε έναν χρήστη με χαμηλότερα προνόμια να καταχωρίσει μια υπηρεσία με έλεγχο script μέσω του τοπικού HTTP API, ο χρήστης αυτός μπορεί να προκαλέσει την εκτέλεση εντολών ως root. Η σύνδεση του API μόνο στο `127.0.0.1` εξακολουθεί να επιτρέπει στους τοπικούς χρήστες να έχουν πρόσβαση σε αυτό. Η ρύθμιση `enable_local_script_checks` είναι πιο περιορισμένη: αποκλείει τους ελέγχους script που υποβάλλονται μέσω καταχωρίσεων του HTTP API. Όταν είναι ενεργοποιημένα τα ACL του Consul, η καταχώριση υπηρεσίας απαιτεί `service:write`· από μόνη της, μια γραμμή `acl.default_policy=allow` δεν αποδεικνύει ότι ένας ανώνυμος χρήστης μπορεί να κάνει καταχώριση. Εξετάστε από κοινού την ταυτότητα του agent, τις φορτωμένες ρυθμίσεις, τη σύνδεση του API και την εξουσιοδότηση.<sup>[[4]](#references)[[5]](#references)[[6]](#references)</sup>

```bash
ps -eo user,args | grep '[c]onsul agent'
ls -l /etc/consul.d 2>/dev/null
```

Ακολουθήστε τα ορίσματα `-config-dir` και `-config-file` του agent που εκτελείται για να εντοπίσετε τη σχετική διαμόρφωση και εξετάστε μόνο τα ονόματα και τις ρυθμίσεις των πεδίων ελέγχου script και ACL. Τα αρχεία διαμόρφωσης μπορεί επίσης να περιέχουν κλειδιά ή tokens gossip· αποφύγετε να τα επικολλάτε σε κοινόχρηστα logs. Μην καταχωρίζετε μια υπηρεσία ούτε εκτελείτε health check απλώς για να διερευνήσετε αυτή την περίπτωση.

Υπάρχει ξεχωριστή διαδρομή μέσω τοπικού αρχείου όταν ένας χρήστης με χαμηλότερα προνόμια μπορεί να **εγγράψει στον κατάλογο** που ορίζεται από το `-config-dir` ενός agent που εκτελείται ως root και να **αναζητήσει μέσα σε αυτόν**: ένας νέος ορισμός υπηρεσίας `.hcl` ή `.json` μπορεί να φορτωθεί από τον συγκεκριμένο κατάλογο. Η δυνατότητα αναζήτησης μέσα στον κατάλογο και εγγραφής σε αυτόν μπορεί να επιτρέψει την προσθήκη αρχείου ακόμη κι όταν δεν επιτρέπεται η εμφάνιση των περιεχομένων του. Για εκτέλεση εντολών ως root, επιβεβαιώστε ότι ο agent πράγματι φορτώνει τον συγκεκριμένο κατάλογο, ότι η **ενεργή** ρύθμιση ελέγχων script επιτρέπει τοπικούς ορισμούς, ότι ο ορισμός φορτώνεται και ότι ο agent διατηρεί τα προνόμια root. Η [τεκμηρίωση του Consul](https://developer.hashicorp.com/consul/docs/fundamentals/agent#reloadable-configurations) περιγράφει ποιες ρυθμίσεις και ορισμοί health check μπορούν να φορτωθούν ξανά· η ενεργοποίηση των ελέγχων script μπορεί από μόνη της να απαιτεί επανεκκίνηση, οπότε επαληθεύστε τη συμπεριφορά της εγκατεστημένης έκδοσης. Όταν ACL προστατεύουν τον agent, η [`consul reload` απαιτεί `agent:write`](https://developer.hashicorp.com/consul/api-docs/agent#reload-agent)· η άδεια εγγραφής στο KV από μόνη της δεν την παρέχει. Αντιμετωπίστε τα εγγράψιμα μεταδεδομένα καταλόγου ως ένδειξη που αξίζει διερεύνηση, όχι ως απόδειξη ότι επιτρέπεται η επαναφόρτωση, η επανεκκίνηση ή η εκτέλεση εντολών. Επιθεωρήστε διαδρομές, δικαιώματα και πολιτική χωρίς να γράψετε στη διαμόρφωση ή να καλέσετε το API.

## Ακολουθήστε την αλυσίδα εκτέλεσης της υπηρεσίας

```bash
systemctl cat <unit>.service
systemctl show <unit>.service -p User -p Group -p ExecStart -p EnvironmentFiles -p WorkingDirectory
namei -l /path/from/ExecStart
```

Ελέγξτε το unit, τα drop-ins, το `EnvironmentFile=`, τα helper scripts, τις σχετικές εντολές, τους εγγράψιμους καταλόγους και το socket activation. Ένα unit που ανήκει στον root μπορεί να μην είναι ασφαλές αν διαβάζει ένα config ή script εγγράψιμο από χρήστη. Η σελίδα [arbitrary file write](../interesting-files-permissions/write-to-root.md) καλύπτει συνήθεις διαδρομές κατάχρησης υπηρεσιών και unit. Παρακολουθήστε σύντομες εργασίες με το [pspy](https://github.com/DominicBreuker/pspy) ή με audit/process telemetry όταν μια εφάπαξ καταχώριση `ps` δεν τις εντοπίζει.

Για μια προσαρμοσμένη υπηρεσία **xinetd**, συσχετίστε τα `server`, `user` και τα access controls της ενεργοποιημένης ενότητας με τον ενεργό listener και το ακριβές εκτελέσιμο. Η ρύθμιση [`user`](https://manpages.debian.org/testing/xinetd/xinetd.conf.5.en.html) επιλέγει την ταυτότητα της διεργασίας που θα δημιουργηθεί, ενώ ένα bit set-user-ID στο εκτελέσιμο μπορεί να αλλάξει ξεχωριστά την effective identity, εφόσον το [`execve` επιτρέπει αυτή τη μετάβαση](https://man7.org/linux/man-pages/man2/execve.2.html). Ένα προσβάσιμο προνομιούχο binary που δέχεται μη έμπιστη είσοδο αξίζει offline έλεγχο του source ή αποσυναρμολόγησης για σφάλματα ασφάλειας μνήμης, όπως μια μη οριοθετημένη [μετατροπή συμβολοσειράς `scanf`](https://www.gnu.org/software/libc/manual/html_node/String-Input-Conversions.html) σε σταθερό buffer. Η αντιστοίχιση της υπηρεσίας και τα μεταδεδομένα set-user-ID είναι ενδείξεις για περαιτέρω έλεγχο, όχι απόδειξη τέτοιου σφάλματος· μην στέλνετε εισόδους που προκαλούν crash και μην κάνετε debug στην ενεργή προνομιούχο υπηρεσία κατά την παθητική απαρίθμηση.

Για έναν προσαρμοσμένο προνομιούχο listener με αναγνώσιμο source, ελέγξτε κάθε μήκος που ελέγχεται από τον caller και χρησιμοποιείται σε μια λειτουργία αντιγραφής, όπως [`memcpy`](https://man7.org/linux/man-pages/man3/memcpy.3.html). Το να ελέγξετε μόνο ότι ο τρέχων δείκτης εγγραφής βρίσκεται εντός ενός σταθερού buffer δεν αποδεικνύει ότι το **μήκος αντιγραφής** χωράει στον εναπομένοντα χώρο· επαληθεύστε ότι `copy_length <= capacity - index` αφού επιβεβαιώσετε ότι ο δείκτης είναι εντός ορίων, και ελέγξτε το πρόσημο και την υπερχείλιση αριθμητικών πράξεων. Αυτό αποτελεί ένδειξη για περαιτέρω έλεγχο μόνο αν η είσοδος φτάνει στη συγκεκριμένη λειτουργία, ο listener είναι προσβάσιμος από τον χρήστη με τα χαμηλότερα προνόμια και η διεργασία διατηρεί υψηλότερη effective identity. Ελέγξτε offline το source και τα μεταδεδομένα της διεργασίας· μην στέλνετε εισόδους που προκαλούν crash στην ενεργή υπηρεσία κατά την απαρίθμηση.

Σε συστήματα που χρησιμοποιούν **Upstart**, οι ορισμοί system jobs μπορεί να βρίσκονται στο `/etc/init/*.conf`. Ένα αρχείο job εγγράψιμο από τον τρέχοντα χρήστη έχει σημασία όταν ο ενεργός init daemon φορτώνει το συγκεκριμένο job, το stanza `script` ή `exec` εκτελείται με υψηλότερα προνόμια και ο χρήστης μπορεί να το ξεκινήσει μέσω επιτρεπόμενης εντολής `initctl` ή άλλου πραγματικού trigger. Μια παραχώρηση sudo για `initctl` από μόνη της δεν αποδεικνύει ότι κάποιο αρχείο job είναι εγγράψιμο ή ότι θα εκτελεστεί ένα τροποποιημένο job. Ελέγξτε τα δικαιώματα του συγκεκριμένου αρχείου job, την effective ρύθμιση run-as, τον ενεργό daemon και το trigger, χωρίς να επεξεργαστείτε ή να ξεκινήσετε το job κατά την απαρίθμηση. Δείτε τα εγχειρίδια [Upstart job configuration](https://manpages.ubuntu.com/manpages/trusty/man5/init.5.html) και [`initctl`](https://manpages.ubuntu.com/manpages/xenial/man8/initctl.8.html).

Ένα αναγνώσιμο αρχείο κωδικών πρόσβασης autologin, όπως το `/etc/autologin/passwd` σε συστήματα των οποίων το [boot job διαβάζει ακριβώς αυτή τη διαδρομή](https://chromium.googlesource.com/chromiumos/overlays/chromiumos-overlay/+/master/chromeos-base/autologin/files/init/autologin.conf), αποτελεί ένδειξη έκθεσης διαπιστευτηρίων. Επιβεβαιώστε ότι το boot job είναι εγκατεστημένο και χρησιμοποιεί το αρχείο, και έπειτα ελέγξτε ξεχωριστά αν ο κωδικός πρόσβασης ισχύει για κάποιον άλλο τοπικό λογαριασμό ή υπηρεσία. Το όνομα αρχείου από μόνο του δεν αποδεικνύει επαναχρησιμοποίηση κωδικού· καταγράψτε τη διαδρομή και τα μεταδεδομένα πρόσβασης χωρίς να συμπεριλάβετε τον κωδικό πρόσβασης σε κοινόχρηστα αποτελέσματα απαρίθμησης.

Το `ExecStart=` ενός unit ή μια προγραμματισμένη εντολή μπορεί να αποκαλύψει την ακριβή διαδρομή ενός script μέσα σε κατάλογο που δεν μπορεί να εμφανιστεί με listing. Το [δικαίωμα αναζήτησης καταλόγου](https://man7.org/linux/man-pages/man7/path_resolution.7.html) μπορεί και πάλι να επιτρέπει στην τρέχουσα ταυτότητα να διασχίσει αυτή τη γνωστή διαδρομή· επιβεβαιώστε το δικαίωμα αναζήτησης σε κάθε γονικό κατάλογο και το δικαίωμα ανάγνωσης του αρχείου, αντί να υποθέσετε ότι η αποτυχία εμφάνισης του περιεχομένου του καταλόγου το προστατεύει. Ένα αναγνώσιμο script μπορεί να περιέχει διαπιστευτήριο για μεταφορά δεδομένων, αλλά η μετάβαση σε άλλον λογαριασμό απαιτεί το διαπιστευτήριο να εξακολουθεί να ισχύει και να γίνεται ανεξάρτητα δεκτό εκεί. Καταγράψτε τη διαδρομή και τα στοιχεία δικαιωμάτων χωρίς να εμφανίσετε μυστικές τιμές σε κοινόχρηστα logs.

Για ένα προγραμματισμένο CommonJS script Node.js, ελέγξτε τα bare imports όπως `require('package')` ακόμη και όταν το ίδιο το script είναι μόνο για ανάγνωση. [Το Node αναζητά `node_modules` δίπλα στο αρχείο που κάνει το import και έπειτα στους γονικούς του καταλόγους](https://nodejs.org/api/modules.html#loading-from-node_modules-folders), πριν καταφύγει στις ρυθμισμένες global διαδρομές. Ένας χρήστης με χαμηλότερα προνόμια που μπορεί να **γράψει και να αναζητήσει** σε έναν από αυτούς τους γονικούς καταλόγους μπορεί να είναι σε θέση να δημιουργήσει ένα package που θα αντιστοιχιστεί νωρίτερα. Επιβεβαιώστε ότι το συγκεκριμένο import εκτελείται, ότι το επιλεγμένο package δεν είναι built-in module, ότι μπορεί να δημιουργηθεί ή να τροποποιηθεί η σχετική διαδρομή, ότι το module επιλύεται εκεί στο εγκατεστημένο runtime και ότι ένα job με υψηλότερα προνόμια θα το φορτώσει σε μελλοντική εκτέλεση. Τα μεταδεδομένα ενός εγγράψιμου γονικού καταλόγου είναι απλώς αφορμή για έλεγχο· επιθεωρήστε παθητικά το script και τον scheduler, χωρίς να τοποθετήσετε module ή να ενεργοποιήσετε το job.

Ένα ιδιωτικό package index Python αποτελεί ακόμη ένα όριο εμπιστοσύνης όταν ένα αυτοματοποιημένο job εγκαθιστά packages με διαφορετική ταυτότητα OS. Συσχετίστε το συγκεκριμένο job και τον λογαριασμό run-as με το ρυθμισμένο index, τα επιλεγμένα ονόματα packages και το αν ένας χρήστης με χαμηλότερα προνόμια μπορεί να δημοσιεύσει ή να αντικαταστήσει ένα package που θα εγκαταστήσει πράγματι το job. Η δημιουργία ενός source distribution μπορεί να εκτελέσει το build backend του ή το παλαιού τύπου `setup.py` με την ταυτότητα του installer· η εισαγωγή του εγκατεστημένου package είναι διαφορετική διαδρομή εκτέλεσης. Ένας listener του index, ένα αναγνώσιμο hash κωδικού πρόσβασης για upload ή μόνο το όνομα αρχείου ενός package δεν αποδεικνύουν αυτή την αλυσίδα. Ελέγξτε το job, την εξουσιοδότηση του index και την προέλευση του package, χωρίς να ανεβάσετε ή να εγκαταστήσετε κάτι κατά την απαρίθμηση. Δείτε τις οδηγίες [build-system του pip](https://pip.pypa.io/en/stable/reference/build-system/) και [ασφαλών εγκαταστάσεων](https://pip.pypa.io/en/stable/topics/secure-installs/).

Ένας προνομιούχος agent μπορεί να ελέγχει περιοδικά μια ουρά εργασιών που διαχειρίζεται ξεχωριστή web service ή container. Αν μια ταυτότητα χαμηλότερης εμπιστοσύνης μπορεί να γράψει στη βάση δεδομένων εργασιών της υπηρεσίας, εξακριβώστε αν αυτές οι εγγραφές παρέχονται πράγματι στον συγκεκριμένο agent και αν μια command task εκτελείται με την ταυτότητα OS του agent. Επιβεβαιώστε ξεχωριστά την πρόσβαση εγγραφής στη βάση δεδομένων, το target session ή routing key, την ενεργή περιοδική ανάγνωση, την εξουσιοδότηση της εργασίας και τον effective user του agent. Το ότι κάποιος είναι root μέσα σε container δεν συνεπάγεται από μόνο του πρόσβαση ως root στο host· το όριο παραβιάζεται μόνο αν ένας consumer με προνόμια host εκτελέσει δεδομένα εργασίας που ελέγχονται από επιτιθέμενο. Ελέγξτε τα μεταδεδομένα διεργασίας, αρχείου βάσης δεδομένων και υπηρεσίας, χωρίς να τροποποιήσετε την ουρά ή να στείλετε εργασία κατά την απαρίθμηση.

Ένα επαναλαμβανόμενο job μπορεί αντί γι’ αυτό να διαβάζει μια εντολή από μια γραμμή ρυθμίσεων βάσης δεδομένων εφαρμογής. Επιβεβαιώστε ότι ο ρόλος βάσης δεδομένων με τα χαμηλότερα προνόμια μπορεί να τροποποιήσει τη συγκεκριμένη γραμμή, ότι το ενεργό job τη διαβάζει μετά την αλλαγή και ότι η τιμή φτάνει σε shell ή ισοδύναμο command runner με υψηλότερη ταυτότητα OS. Η πρόσβαση εγγραφής στη βάση δεδομένων ή μια τιμή που μοιάζει με εντολή δεν αποδεικνύουν από μόνες τους εκτέλεση· ελέγξτε το job και τα δικαιώματα χωρίς να αλλάξετε τη γραμμή κατά την παθητική απαρίθμηση.

Ένα μήνυμα σε ουρά μπορεί επίσης να περιέχει URL αντί για κώδικα. Αν ένας προνομιούχος consumer ανακτά αυτό το URL και φορτώνει την απάντηση ως Lua ή άλλο εκτελέσιμο plugin, επαληθεύστε το δικαίωμα του publisher στο συγκεκριμένο exchange και routing key, τη σύνδεση με την ουρά από την οποία γίνεται η ανάγνωση, τη διαδρομή ανάκτησης και φόρτωσης του plugin και την effective identity του worker. Το [RabbitMQ δρομολογεί τα δημοσιευμένα μηνύματα μέσω exchanges](https://www.rabbitmq.com/docs/exchanges)· ένας broker listener ή ένα έγκυρο login από μόνο του δεν αποδεικνύει ότι το μήνυμα παραδίδεται σε αυτόν τον worker. Διαπιστευτήρια broker σε cleartext που έχουν καταγραφεί αποτελούν ξεχωριστή ένδειξη, η οποία απαιτεί πραγματική πρόσβαση σε packet capture και αναγνώσιμη κίνηση· δεν αποδεικνύουν δικαίωμα δημοσίευσης. Ένα Lua plugin μπορεί να εκτελέσει shell commands μέσω του [`os.execute`](https://www.lua.org/manual/5.4/manual.html#pdf-os.execute) μόνο αν αυτό το API είναι διαθέσιμο στο runtime του. Ελέγξτε το config και τον κώδικα χωρίς να καταγράψετε κίνηση, να δημοσιεύσετε μηνύματα ή να ανακτήσετε plugin κατά την παθητική απαρίθμηση.

Όταν μια προνομιούχος υπηρεσία Python εκθέτει ένα τοπικό HTTP ή socket endpoint, ένα αναγνώσιμο script μπορεί να αποκαλύψει διαδρομή από την είσοδο προς τον κώδικα, ακόμη κι αν τα δικαιώματα του αρχείου αποκλείουν την τροποποίησή του. Συσχετίστε την ενεργή διεργασία και την ταυτότητα του unit με το συγκεκριμένο script, τον listener, την εξουσιοδότηση της διαδρομής και τα πεδία που ελέγχει ο caller. Έπειτα ακολουθήστε αυτά τα πεδία κατά την ανάλυση και την επικύρωσή τους μέχρι ένα δυναμικό sink `eval()` ή `exec()`. Ειδικότερα, η δημιουργία νέου f-string από κείμενο αιτήματος και η αξιολόγησή του μπορεί να ερμηνεύσει τα πεδία αντικατάστασης που παρέχει ο επιτιθέμενος ως Python expressions ([προειδοποίηση της Python για το `eval`](https://docs.python.org/3/library/functions.html#eval)· [σημασιολογία των f-string](https://docs.python.org/3/reference/lexical_analysis.html#f-strings)). Μια απλή αντιστοιχία `eval` ή η σύνδεση σε loopback δεν αποδεικνύουν ότι ένας μη έμπιστος caller φτάνει στο sink· ελέγξτε την πραγματική ροή δεδομένων και τα access controls χωρίς να στείλετε δοκιμαστικό payload κατά την απαρίθμηση.

Μια πύλη signed-request σε αυτή τη διαδρομή χρειάζεται ξεχωριστό έλεγχο. Αν το αναγνώσιμο source παράγει το signing key από ένα αποδεδειγμένα μικρό ή προβλέψιμο σύνολο πιθανών τιμών και η υπηρεσία εκθέτει ένα έγκυρο υπογεγραμμένο δείγμα, η υπογραφή μπορεί να μην προστατεύει πλέον ένα προνομιούχο sink `eval()`. Επαληθεύστε ακριβώς τον τρόπο παραγωγής του key και τον verifier, την ταυτότητα της ενεργής υπηρεσίας και την πρόσβαση τοπικών callers, καθώς και το αν το υπογεγραμμένο πεδίο φτάνει στο sink· ένα import του Python [`random module`](https://docs.python.org/3/library/random.html) ή μόνο ένα δείγμα υπογραφής δεν αποδεικνύει καμία από αυτές τις συνθήκες. Η Python προειδοποιεί επίσης ότι ο περιορισμός του `__builtins__` [δεν αποτελεί όριο ασφαλείας για μη έμπιστη είσοδο στο `eval()`](https://docs.python.org/3/library/functions.html#eval). Αναλύστε το key offline και μην υποβάλετε πλαστογραφημένα requests κατά την παθητική απαρίθμηση.

Ένας κενός αλλά εγγράψιμος κατάλογος `/etc/systemd/system/<unit>.service.d` έχει σημασία ακόμη κι όταν το αρχείο unit και όλα τα υπάρχοντα drop-ins είναι προστατευμένα: ο χρήστης μπορεί να δημιουργήσει νέο override `.conf`. Ελέγξτε αν ο τρέχων χρήστης έχει δικαιώματα εγγραφής και αναζήτησης στον κατάλογο, αν το unit είναι φορτωμένο και εκτελείται ως root, καθώς και αν θα ακολουθήσει επαναφόρτωση του daemon και επανεκκίνηση. Μια άδεια για reload ή restart, ένας timer ή μια μελλοντική εκκίνηση συστήματος μπορεί να ενεργοποιήσει την αλλαγή· η πρόσβαση εγγραφής στον κατάλογο από μόνη της δεν την εκτελεί αμέσως.

Για υπηρεσίες που εκτελούνται, ακολουθήστε τις κυριολεκτικές διαδρομές `EnvironmentFile=` από την ενότητα `[Service]` του unit, συμπεριλαμβανομένων αρχείων τα ονόματα των οποίων δεν αρχίζουν με `.env`. Αν ένας χρήστης με χαμηλά προνόμια μπορεί να διαβάσει κάποιο από αυτά, καταγράψτε ονόματα κλειδιών που μοιάζουν με διαπιστευτήρια, όπως `API_TOKEN` ή `APP_SECRET_KEY`, χωρίς να εμφανίσετε τις τιμές τους σε κοινόχρηστα logs. Ελέγξτε τα drop-in overrides και τα προαιρετικά πρόθεματα `-` κατά την αξιολόγηση του effective unit. Η δυνατότητα ανάγνωσης αποτελεί ένδειξη έκθεσης διαπιστευτηρίων· η τιμή πρέπει και πάλι να ισχύει για κάποια προνομιούχα ενέργεια ώστε να οδηγήσει σε κλιμάκωση προνομίων.

### Προνομιούχα επεξεργασία μη έμπιστων uploads

Ένας file watcher που εκτελείται ως root μπορεί να παραδίδει αρχεία από έναν εγγράψιμο από χρήστες κατάλογο upload σε έναν parser ή extractor βραχείας διάρκειας. Ακολουθήστε το γονικό script ή service του ενεργού watcher και επιβεβαιώστε τον συγκεκριμένο κατάλογο, ποιος μπορεί να τοποθετεί εκεί αρχεία, την child command και τα ορίσματά της, καθώς και την ταυτότητα με την οποία εκτελείται το child. Ένα στιγμιότυπο διεργασιών μπορεί να εμφανίσει τον watcher αλλά να μην προλάβει τον extractor ανάμεσα σε δύο uploads. Μην τοποθετείτε δοκιμαστικό payload και μην ενεργοποιείτε τον watcher κατά την παθητική απαρίθμηση.

Ένα συγκεκριμένο παράδειγμα είναι η λειτουργία extraction του Binwalk (`-e`) σε δεδομένα PFS που ελέγχονται από επιτιθέμενο. Το [CVE-2022-4510](https://github.com/ReFirmLabs/binwalk/pull/617) επέτρεπε στον PFS extractor να γράφει έξω από τον προβλεπόμενο κατάλογο, ακόμη και σε διαδρομή plugin που το Binwalk μπορούσε αργότερα να φορτώσει. Το upstream περιέλαβε τη διόρθωση στην [2.3.4](https://github.com/ReFirmLabs/binwalk/releases/tag/v2.3.4), αλλά τα backports διανομών μπορεί να διατηρούν παλαιότερη εμφανιζόμενη έκδοση· ελέγξτε την κατάσταση ασφαλείας του εγκατεστημένου package, όπως στον [Debian tracker](https://security-tracker.debian.org/tracker/CVE-2022-4510), προτού κρίνετε αν εφαρμόζεται. Μόνο η εγκατεστημένη έκδοση του Binwalk δεν αποδεικνύει διαδρομή κλιμάκωσης προνομίων: το extraction πρέπει πράγματι να εκτελείται από διεργασία με υψηλότερα προνόμια σε είσοδο που μπορεί να ελέγξει ο χρήστης με τα χαμηλότερα προνόμια.

### Προγραμματισμένα builds με τοπικές εξαρτήσεις

Ένα προγραμματισμένο `cargo run` μεταγλωττίζει ξανά το source με τον χρήστη run-as του job. Ελέγξτε τις τοπικές εξαρτήσεις `{ path = "..." }` του manifest, καθώς και τα δικαιώματα του source και των γονικών καταλόγων κάθε εξάρτησης, όχι μόνο του κύριου crate. Αν ένας χρήστης με χαμηλότερα προνόμια μπορεί να τροποποιήσει μια εξάρτηση που μεταγλωττίζει το Cargo και το προγραμματισμένο job εκτελεί το αποτέλεσμά της, ο μεταγλωττισμένος κώδικας μπορεί να εκτελεστεί ως ο συγκεκριμένος χρήστης run-as. Επιβεβαιώστε την effective εντολή του scheduler, τον working directory, την επίλυση των εξαρτήσεων και το αν θα γίνει rebuild· ένα εγγράψιμο Rust source file αλλού αποτελεί απλώς ένδειξη για περαιτέρω έλεγχο. Για παθητική διαλογή αρκεί να διαβάσετε το manifest και τα μεταδεδομένα των διαδρομών. Δείτε την [τεκμηρίωση του Cargo για path dependencies](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#specifying-path-dependencies).

## Αρχεία framebuffer του Xvfb

Το `Xvfb -fbdir <directory>` χρησιμοποιεί memory-mapped αρχεία με ονόματα `Xvfb_screen<n>` για τις εικονικές οθόνες του. Αν η ενεργή διεργασία Xvfb άλλου χρήστη ορίζει κατάλογο του οποίου τα αρχεία οθόνης είναι αναγνώσιμα από τον τρέχοντα χρήστη, το framebuffer μπορεί να αποκαλύπτει το περιεχόμενο της επιφάνειας εργασίας εκείνου του χρήστη. Επιβεβαιώστε από κοινού τη διεργασία, την ιδιοκτησία των αρχείων και τα δικαιώματα· ένα αναγνώσιμο αρχείο από μόνο του δεν αποδεικνύει ότι υπάρχει χρήσιμο περιεχόμενο στην οθόνη. Ελέγξτε πρώτα τις διαδρομές και τα μεταδεδομένα, χωρίς να αντιγράψετε δεδομένα εικόνας σε κοινόχρηστα αποτελέσματα απαρίθμησης. Το [εγχειρίδιο του Xvfb](https://xorg.freedesktop.org/archive/X11R7.5/doc/man/man1/Xvfb.1.html) περιγράφει τη συμπεριφορά του `-fbdir`.

```bash
pgrep -a -x Xvfb
ls -l /path/from/-fbdir/Xvfb_screen*
```
