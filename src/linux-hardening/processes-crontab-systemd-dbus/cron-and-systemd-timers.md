# Εργασίες Cron και χρονόμετρα Systemd

{{#include ../../banners/hacktricks-training.md}}

Οι προγραμματισμένες εργασίες μπορούν να εκτελούνται με διαφορετική ταυτότητα και περιβάλλον από αυτά του τρέχοντος κελύφους. Καταγράψτε τα cron, `at`, anacron και systemd timers και, στη συνέχεια, ακολουθήστε κάθε προγραμματισμένη εντολή μέσα από τα scripts, τις εισαγωγές, τον κατάλογο εργασίας και τις εγγράψιμες εισόδους της.

## Καταγραφή προγραμματισμένων εργασιών

```bash
crontab -l 2>/dev/null
ls -la /etc/crontab /etc/cron.* /var/spool/cron* 2>/dev/null
atq 2>/dev/null
systemctl list-timers --all 2>/dev/null
```

Τα system crontabs συνήθως περιλαμβάνουν πεδίο χρήστη· το crontab ενός χρήστη δεν περιλαμβάνει. Ελέγξτε το ενεργό PATH και το περιβάλλον του πραγματικού scheduler. Η εντολή `run-parts --test /etc/cron.daily` εμφανίζει ποια ονόματα αρχείων θα επιλεγούν σε αυτόν τον host. Οι χαρακτήρες ελέγχου μπορούν να αποκρύψουν μια εγγραφή σε απλή προβολή, γι’ αυτό χρησιμοποιήστε `cat -A` ή `sed -n l` όταν ένα πρόγραμμα μοιάζει ύποπτο.

## Ανιχνεύστε την επίλυση διαδρομών και εντολών με προνόμια

```bash
systemctl cat <name>.timer <name>.service
systemctl show <name>.service -p User -p ExecStart -p EnvironmentFiles -p WorkingDirectory
namei -l /path/to/scheduled/script
```

Ελέγξτε αλυσίδες script με δυνατότητα εγγραφής, διαδρομές `EnvironmentFile=`, drop-ins, symlinks, σχετικές εντολές, επέκταση wildcard και binaries που αντιγράφονται ή εκτελούνται από προνομιούχο task. Ένα timer μπορεί να ενεργοποιεί service με διαφορετικό όνομα μέσω της ρύθμισης `Unit=`. Οι σελίδες [PATH](../linux-basics/linux-environment-variables.md#path), [wildcard](../interesting-files-permissions/wildcards-spare-tricks.md) και [file-link](../main-system-information/filesystem-links-and-file-descriptors.md) εξηγούν τους βασικούς μηχανισμούς.

Για ένα προγραμματισμένο script `chkrootkit` που εκτελείται ως root, ελέγξτε τον εγκατεστημένο πηγαίο κώδικα για το παλιό [σφάλμα quoting στο slapper-loop (CVE-2014-0476)](https://bugzilla.redhat.com/show_bug.cgi?id=CVE-2014-0476): μια εντολή `file_port=$file_port $i` χωρίς quotes, μετά από έλεγχο μιας προσωρινής διαδρομής `SLAPPER_FILES`, μπορεί να εκτελέσει αυτό το αρχείο. Επαληθεύστε το πραγματικό script ή το patch του προμηθευτή, τον προγραμματισμό ως root, τη δυνατότητα εγγραφής από χρήστη χαμηλότερων προνομίων στην ακριβή προσωρινή διαδρομή, αν το αρχείο είναι εκτελέσιμο και την πολιτική του mount. Μια συμβολοσειρά έκδοσης ή η απλή παρουσία του `chkrootkit` δεν αποδεικνύει ότι υπάρχει αυτή η διαδρομή· μην δημιουργείτε ούτε εκτελείτε προσωρινό αρχείο κατά την παθητική επισκόπηση.

Αν ένα root service που εκτελείται από timer κάνει `systemctl restart <other>.service`, ακολουθήστε ένα ακόμη hop μονάδας: η μονάδα που επανεκκινείται μπορεί να καλέσει shell με script στο οποίο μπορεί να γράψει χρήστης χαμηλότερων προνομίων. Επιβεβαιώστε τα ενεργά `User=`, `DynamicUser=`, `RootDirectory=`/`RootImage=`, τα ακριβή ορίσματα `ExecStart=` και τα δικαιώματα του script και της γονικής διαδρομής του. Ένα script με δυνατότητα εγγραφής είναι απλώς υποψήφιο εύρημα, μέχρι να επιβεβαιωθεί ότι το timer και το service που επανεκκινείται είναι ενεργά σε αυτό το περιβάλλον εκτέλεσης· ελέγξτε τις ιδιότητες των μονάδων χωρίς να επανεκκινήσετε κανένα από τα δύο service.

Αν ένα job με υψηλότερα προνόμια ανακτά script βάσει hostname και περνά την απόκριση σε shell, ελέγξτε ποιος ελέγχει την επίλυση του hostname, καθώς και το απομακρυσμένο script. Ένα αρχείο `/etc/hosts` με δυνατότητα εγγραφής, ακόμη κι αν η πρόσβαση δίνεται μέσω group ή ACL, μπορεί να ανακατευθύνει ένα όνομα που το job επιλύει τοπικά· μια απόκριση `curl` γίνεται διαδρομή εκτέλεσης μεταξύ χρηστών μόνο αν η πραγματική προγραμματισμένη εντολή εκτελεί αυτή την απόκριση και το job χρησιμοποιεί την επηρεαζόμενη διαδρομή επίλυσης. Επαληθεύστε την ταυτότητα εκτέλεσης του job, το ακριβές URL και το shell pipeline, την ενεργή συμπεριφορά proxy/DNS και τα δικαιώματα του αρχείου και του γονικού καταλόγου. Ένα αρχείο hosts με δυνατότητα εγγραφής είναι λόγος για έλεγχο, όχι απόδειξη ότι υπάρχει προνομιούχος καταναλωτής του. Ελέγξτε το πρόγραμμα και τα metadata χωρίς να αλλάξετε την αντιστοίχιση ή να ανακτήσετε το script κατά την καταγραφή.

Μια προνομιούχα προγραμματισμένη λήψη με `wget` αποτελεί ξεχωριστό όριο εγγραφής αρχείων, ακόμη κι αν το περιεχόμενο που κατεβαίνει δεν εκτελείται απευθείας. Η [GNU Wget 1.18 άλλαξε την προεπιλεγμένη διαχείριση ονόματος αρχείου κατά την ανακατεύθυνση HTTP σε FTP για τη διόρθωση του CVE-2016-4971](https://lists.gnu.org/archive/html/info-gnu/2016-06/msg00004.html)· παλαιότερα επηρεαζόμενα builds μπορούσαν να χρησιμοποιήσουν το όνομα αρχείου της ανακατεύθυνσης FTP, ενώ το `--trust-server-names` ζητά ρητά αυτή τη συμπεριφορά. Αν κάποιο μέρος χαμηλότερης εμπιστοσύνης ελέγχει την HTTP απόκριση και τον FTP πόρο, ελέγξτε αν το job ακολουθεί αυτή την ανακατεύθυνση, το πραγματικό build του Wget ή το backport του προμηθευτή, τις επιλογές εξόδου, την ταυτότητα εκτέλεσης, τον working directory και αν το όνομα αρχείου προορισμού μπορεί να γίνει αρχείο εκκίνησης. Το [Wget φορτώνει το `WGETRC` ή το `$HOME/.wgetrc`](https://www.gnu.org/software/wget/manual/html_node/Wgetrc-Location.html) και [οι ρυθμίσεις του μπορούν να επιλέξουν πηγή POST ή διαδρομή εξόδου](https://www.gnu.org/software/wget/manual/html_node/Wgetrc-Commands.html)· μια μεταγενέστερη προνομιούχα λήψη είναι ξεχωριστή προϋπόθεση για οποιαδήποτε επακόλουθη αποκάλυψη ή εγγραφή. Η πρόσβαση σε χαμηλή θύρα μέσω `authbind` έχει σημασία μόνο αν ο καλών μπορεί πράγματι να εξυπηρετήσει το URL που ζητά το job. Ελέγξτε παθητικά τις ρυθμίσεις και τα logs, χωρίς να εξυπηρετήσετε ανακατεύθυνση ή να εκτελέσετε το job. Η [πρόσβαση σε raw block device μέσω του group `disk`](../user-information/interesting-groups-linux-pe/README.md#disk-group) είναι ανεξάρτητη από αυτή τη διαδρομή λήψης μέσω δικτύου.

Ακολουθήστε και τα αρχεία δεδομένων, όχι μόνο τα script. Ένα προγραμματισμένο εργαλείο προσομοίωσης ή orchestration μπορεί να διαβάζει αρχείο YAML που ορίζει διεργασίες προς εκκίνηση· αν χρήστης χαμηλότερων προνομίων μπορεί να επεξεργαστεί αυτό το αρχείο και το job το εκτελεί με άλλο λογαριασμό, τα δεδομένα μπορούν να μετατραπούν σε εντολές με την ταυτότητα του job. Επαληθεύστε την ακριβή προγραμματισμένη εντολή, τον ενεργό χρήστη, τη διαδρομή του αρχείου, τη σημασιολογία του parser και τα δικαιώματα εγγραφής, συμπεριλαμβανομένων των γονικών καταλόγων, πριν θεωρήσετε ένα YAML με δυνατότητα εγγραφής διαδρομή εκτέλεσης. Για παθητική διαλογή αρκεί να διαβάσετε το πρόγραμμα και τα metadata του αρχείου· μην εκτελέσετε το job ή τροποποιήσετε την είσοδό του κατά την καταγραφή.

Οι ρυθμίσεις SSH client αποτελούν επίσης εκτελέσιμη είσοδο, όταν job με υψηλότερα προνόμια εκτελεί `ssh -F` με αρχείο που μπορεί να αντικαταστήσει χρήστης χαμηλότερων προνομίων. Το OpenSSH [`ProxyCommand`](https://man.openbsd.org/ssh_config#ProxyCommand) εκτελεί τοπική εντολή μέσω του shell του client, ενώ τα `Host`/`Match` και οι προηγούμενες επιλογές καθορίζουν αν εφαρμόζεται αυτή η οδηγία. Συσχετίστε την ακριβή προγραμματισμένη κλήση SSH, την ταυτότητα εκτέλεσης, την επιλεγμένη διαδρομή config, τα δικαιώματα εγγραφής του καταλόγου και του αρχείου και την ενεργή σειρά επιλογών, πριν το χαρακτηρίσετε διαδρομή εκτέλεσης μεταξύ χρηστών. Ελέγξτε αυτές τις εγγραφές χωρίς να εκτελέσετε το job ή να φορτώσετε την μη έμπιστη ρύθμιση ως προνομιούχος λογαριασμός.

Ένα προγραμματισμένο `scp` και στη συνέχεια `ssh` για εκτέλεση του αντιγραμμένου script απαιτεί δεύτερο έλεγχο ορίου εμπιστοσύνης, όταν χρήστης χαμηλότερων προνομίων ελέγχει την υπηρεσία SSH προορισμού. Αν η υπηρεσία μπορεί να προωθήσει τη σύνδεση σε άλλο host, ο προνομιούχος client μπορεί να πιστοποιηθεί σε ακούσιο endpoint· το [`StrictHostKeyChecking no`](https://man.openbsd.org/ssh_config#StrictHostKeyChecking) αποδυναμώνει την προστασία από αλλαγή host key, με την επιφύλαξη των υπόλοιπων περιορισμών του OpenSSH και των ενεργών επιλογών ανά host. Διαπιστώστε την ταυτότητα εκτέλεσης του job, τον πραγματικό προορισμό και τη μέθοδο πιστοποίησης, την ενεργή ταυτότητα της απομακρυσμένης εντολής και αν η ίδια διαδρομή προορισμού είναι εγγράψιμη ή υπάρχει ήδη στον ανακατευθυνόμενο host. Η εκτέλεση παλαιότερου ή ελεγχόμενου από επιτιθέμενο αρχείου απαιτεί επιπλέον η αντιγραφή να αποτύχει ή να μην εντοπίσει αυτή τη διαδρομή **και** το wrapper να συνεχίσει στην εντολή SSH· τα [`errexit` του Bash](https://www.gnu.org/software/bash/manual/html_node/The-Set-Builtin.html) και ο ρητός χειρισμός της κατάστασης εξόδου επηρεάζουν αυτή τη ροή. Μια αδύναμη ρύθμιση host key, μια ορατή διεργασία `sshpass` ή ένας προσωρινός κατάλογος με δυνατότητα εγγραφής δεν αρκούν από μόνα τους για να αποδειχθεί αυτή η αλυσίδα. Ελέγξτε το πρόγραμμα, το script, τις ρυθμίσεις SSH και τα metadata των αρχείων χωρίς να ανακατευθύνετε την υπηρεσία ή να ενεργοποιήσετε το job κατά την καταγραφή.

Ένας προνομιούχος application scheduler μπορεί να αντλεί τα jobs του από γραμμές βάσης δεδομένων αντί από αρχεία με δυνατότητα εγγραφής. Για παράδειγμα, μια εγγραφή root cron που καλεί το Laravel [`php artisan schedule:run`](https://laravel.com/docs/9.x/scheduling#running-the-scheduler) μπορεί να φτάσει σε κώδικα εφαρμογής που διαβάζει γραμμές εργασιών. Αν λογαριασμός χαμηλότερων προνομίων μπορεί να γράψει γραμμή με τοπική διαδρομή και το προγραμματισμένο callback καλεί την PHP [`file_get_contents`](https://www.php.net/manual/en/function.file-get-contents.php) ως root και στέλνει το περιεχόμενο που επέστρεψε σε webhook που επιλέγεται από τη γραμμή, τότε υπάρχει προνομιούχα διαδρομή αποκάλυψης αρχείων. Επαληθεύστε την ταυτότητα του cron, το πραγματικό callback του scheduler και τη ροή δεδομένων από τη γραμμή προς τη διαδρομή, τα δικαιώματα εγγραφής στη βάση δεδομένων, την επικύρωση μετά την ανάγνωση της γραμμής και τον εξερχόμενο προορισμό. Ένα αρχείο `.env` της εφαρμογής που είναι αναγνώσιμο αποτελεί μόνο ένδειξη για διαπιστευτήρια· η επικύρωση web φόρμας ή ένας κωδικός βάσης δεδομένων από μόνα τους δεν αποδεικνύουν έλεγχο της γραμμής ή αποκάλυψη. Ελέγξτε παθητικά το πρόγραμμα, τον κώδικα και τα δικαιώματα του αρχείου διαπιστευτηρίων, χωρίς να κάνετε ερωτήματα στη βάση δεδομένων ή να προγραμματίσετε εργασία κατά την καταγραφή.

Τα event-driven jobs `incron` απαιτούν ανάλογο έλεγχο: οι [εγγραφές incrontab](https://manpages.debian.org/testing/incron/incrontab.5.en.html) αντιστοιχίζουν μια διαδρομή που παρακολουθείται και ένα συμβάν με μια εντολή που εκτελείται με την ταυτότητα του ιδιοκτήτη του πίνακα. Χρήστης χαμηλότερων προνομίων μπορεί να επηρεάσει έμμεσα ένα αρχείο που παρακολουθείται, όταν μια εφαρμογή ακολουθεί link από εγγράψιμο κατάλογο και γράφει κείμενο ελεγχόμενο από επιτιθέμενο στον στόχο που παρακολουθείται. Επαληθεύστε τον πραγματικό ιδιοκτήτη του πίνακα, το συμβάν, τον στόχο και τα δικαιώματα των προγονικών καταλόγων, τη συμπεριφορά της εφαρμογής ως προς την ακολούθηση link και τον τρόπο με τον οποίο το κείμενο γίνεται ορίσματα εντολής. Ειδικότερα, το [GNU Mailutils `mail` δέχεται `--exec`](https://mailutils.org/manual/html_node/Invoking-Mail.html) και η [εντολή διαφυγής στο shell](https://mailutils.org/manual/html_node/Shell-Escapes.html) μπορεί να εκτελέσει πρόγραμμα· μη έμπιστο πεδίο που περνά ως ξεχωριστή επιλογή σε αυτή την υλοποίηση μπορεί να οδηγήσει σε εκτέλεση εντολής. Άλλες υλοποιήσεις `mail` ή ένα quoted, σταθερό όριο ορισμάτων μπορεί να συμπεριφέρονται διαφορετικά. Ελέγξτε το πρόγραμμα, τον κώδικα της εφαρμογής και τα metadata των αρχείων, χωρίς να τροποποιήσετε το αρχείο που παρακολουθείται ή να ενεργοποιήσετε το job κατά την καταγραφή.

Ένα log που παρακολουθείται μπορεί επίσης να διασχίσει όριο χρηστών μέσω helper script. Αν λογαριασμός χαμηλότερων προνομίων μπορεί να γράψει στο log και ο ιδιοκτήτης του `incron` διαβάζει ένα πεδίο από αυτό και το ενσωματώνει σε νέα συμβολοσειρά εντολής [`sh -c`](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/sh.html), το shell αναλύει ξανά αυτό το πεδίο με την ταυτότητα του ιδιοκτήτη. Ελέγξτε το ακριβές συμβάν που παρακολουθείται, τα δικαιώματα του log και των γονικών καταλόγων, τη διαδρομή του helper, τον μετασχηματισμό του πεδίου του log και αν εκτελείται τελικά η παραγόμενη εντολή. Η ύπαρξη log με δυνατότητα εγγραφής και μιας εγγραφής `incron` δεν αποδεικνύει από μόνη της τη ροή δεδομένων· μην γράψετε γραμμή ενεργοποίησης ή εκτελέσετε το helper κατά την παθητική καταγραφή.

Jobs ανανέωσης πιστοποιητικών μπορούν να διασχίσουν το ίδιο όριο. Ένα προνομιούχο helper μπορεί να διαβάσει subject X.509 από πιστοποιητικό σε κατάλογο εγγράψιμο από χρήστη χαμηλότερων προνομίων και να ενσωματώσει το common name σε νέα συμβολοσειρά εντολής `bash -c`. Η [OpenSSL μπορεί να εμφανίσει το subject ενός πιστοποιητικού και να ελέγξει τη λήξη του](https://docs.openssl.org/3.3/man1/openssl-x509/)· [το Bash αναλύει τη συμβολοσειρά `-c` ως είσοδο shell](https://www.gnu.org/software/bash/manual/html_node/Invoking-Bash.html), επομένως το quoting της μεταβλητής στο εξωτερικό script δεν προστατεύει από τη δεύτερη ανάλυση. Επιβεβαιώστε την προγραμματισμένη ταυτότητα, την ακριβή διαδρομή εισόδου και τα δικαιώματα εγγραφής, τον κλάδο ανανέωσης και τη ροή δεδομένων προς το `bash -c`, πριν το χαρακτηρίσετε command injection. Ελέγξτε παθητικά το script και τα metadata του πιστοποιητικού· μην ενεργοποιήσετε την ανανέωση κατά την καταγραφή.

Η ίδια δεύτερη ανάλυση μπορεί να συμβεί όταν προνομιούχο προγραμματισμένο job εξάγει όνομα από archive ή package χρήστη χαμηλότερων προνομίων και το περνά στο `xargs -I` για ενσωμάτωση σε συμβολοσειρά εντολής `sh -c`. Το [GNU `xargs -I` αντικαθιστά το placeholder στα αρχικά ορίσματα](https://www.gnu.org/software/findutils/manual/html_node/find_html/xargs-options.html) και το [`sh -c` ερμηνεύει τη συμβολοσειρά εντολής](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/sh.html). Ακόμη κι αν το εξωτερικό script κάνει quote το εξαγμένο όνομα, αυτό δεν καθιστά ασφαλές ένα μεταγενέστερο πρόγραμμα shell στο οποίο έγινε αντικατάσταση. Επαληθεύστε την ταυτότητα εκτέλεσης του job, την ακριβή διαδρομή αποδεκτής εισόδου και τα δικαιώματα εγγραφής, την επικύρωση archive και τις συνθήκες του κλάδου, καθώς και τη ροή από το όνομα προς το shell. Ένας κατάλογος upload με δυνατότητα εγγραφής ή μια κλήση `xargs` αποτελούν απλώς ένδειξη· ελέγξτε το πρόγραμμα, το script και τα metadata της διαδρομής χωρίς να υποβάλετε package ή να εκτελέσετε το job κατά την καταγραφή.

Ένας προγραμματισμένος importer γραμματοσειρών ή εικόνων μπορεί επίσης να εμπιστεύεται ονόματα *μέσα* σε archive που παρέχεται από τον καλούντα, ακόμη κι αν το εξωτερικό όνομα του upload είναι περιορισμένο. Το FontForge διόρθωσε command injection μέσω ονόματος μέλους archive στην [upstream αλλαγή για τα CVE-2024-25081 και CVE-2024-25082](https://github.com/fontforge/fontforge/pull/5367). Επιβεβαιώστε ότι job με υψηλότερα προνόμια ανοίγει πράγματι archive από διαδρομή εγγράψιμη από χρήστη χαμηλότερων προνομίων, την ταυτότητα εκτέλεσής του, το ακριβές build του FontForge ή το backport του προμηθευτή και τη διαδρομή κώδικα διαχείρισης archive. Μια συμβολοσειρά έκδοσης ή ένα επιτρεπόμενο επίθημα upload δεν αποδεικνύει από μόνη της εκτέλεση. Ελέγξτε το πρόγραμμα, τα δικαιώματα διαδρομών και τα metadata του build, χωρίς να εισαγάγετε μη έμπιστο archive κατά την καταγραφή.

Οι προγραμματισμένοι network scanners μπορούν να διασχίσουν διαφορετικό όριο, όταν ένα custom script αντιμετωπίζει το subject απομακρυσμένου TLS πιστοποιητικού ως τοπικό όνομα αρχείου. Το [Nmap NSE εκτελεί τα επιλεγμένα script χωρίς sandbox](https://nmap.org/book/nse-usage.html), επομένως ελέγξτε το πραγματικό script και αν ενώνει μη έμπιστο πεδίο subject με κατάλογο δεδομένων χωρίς ελέγχους περιορισμού της διαδρομής. Η αποκάλυψη αρχείου απαιτεί στόχο που θα σαρώσει ο scheduler, διαδρομή που επιλύεται σε αρχείο αναγνώσιμο από την ταυτότητα εκτέλεσης του scanner και αναφορά ή log που παραδίδεται σε αναγνώστη χαμηλότερων προνομίων. Ένα πεδίο πιστοποιητικού ή η εγκατάσταση scanner από μόνα τους δεν αποδεικνύουν αυτή την αλυσίδα· ελέγξτε το πρόγραμμα, το script, την επίλυση διαδρομής και τον προορισμό της αναφοράς, χωρίς να σαρώσετε νέο στόχο κατά την παθητική καταγραφή.

Μια προνομιούχα εντολή cron που περνά shell glob όπως `/path/to/tasks/*.yml` σε runner Ansible απαιτεί έλεγχο δικαιωμάτων καταλόγου, ακόμη κι αν όλα τα υπάρχοντα playbook είναι μόνο για ανάγνωση. Χρήστης με δικαιώματα εγγραφής και αναζήτησης στον κατάλογο του glob μπορεί να δημιουργήσει άλλο playbook που ταιριάζει. Τα [playbook Ansible ορίζουν εργασίες που εκτελεί ο runner](https://docs.ansible.com/projects/ansible/latest/cli/ansible-playbook.html), αλλά ένα custom wrapper μπορεί να φιλτράρει διαδρομές ή να χρησιμοποιεί διαφορετική ταυτότητα: επαληθεύστε τη συμπεριφορά του, τον πραγματικό χρήστη cron, την επέκταση shell, τα ACL, το sticky bit και την πολιτική mount, πριν θεωρήσετε τον κατάλογο διαδρομή εκτέλεσης. Ελέγξτε στατικά τα metadata και το wrapper· μην εκτελέσετε το προγραμματισμένο job κατά την καταγραφή.

Ένα προνομιούχο cron wrapper μπορεί να περάσει ονόματα αρχείων από κατάλογο upload σε helper Perl αφού επεκτείνει ένα glob. Ο [`<>` diamond operator της Perl χρησιμοποιεί `open` δύο ορισμάτων](https://perldoc.perl.org/perlop#The-Null-Filehandle), επομένως ένα όνομα αρχείου που ταιριάζει και ερμηνεύεται ως εντολή pipe μπορεί να εκτελεστεί με την ταυτότητα του helper· το [`<<>>` αντιμετωπίζει τα ορίσματα ως κυριολεκτικά ονόματα αρχείων](https://perldoc.perl.org/perlop#The-Null-Filehandle). Επιβεβαιώστε την ταυτότητα του scheduler, τον working directory και το glob του wrapper, τον πραγματικό χειρισμό του `@ARGV` από το helper, τους περιορισμούς ονομάτων αρχείων και αν χρήστης χαμηλότερων προνομίων μπορεί να τοποθετήσει όνομα που ταιριάζει μέσω δικαιωμάτων filesystem ή πιστοποιημένης υπηρεσίας upload. Μια γραμμή cron, ένα script Perl ή ένας κατάλογος FTP με δυνατότητα εγγραφής από μόνα τους δεν αποδεικνύουν την πλήρη αλυσίδα. Ελέγξτε τον πηγαίο κώδικα και τα metadata χωρίς να υποβάλετε ειδικά διαμορφωμένο όνομα αρχείου ή να εκτελέσετε το job κατά την καταγραφή.

Ένα read-only cron script εξακολουθεί να μπορεί να αντικατασταθεί, αν ο προγραμματισμένος λογαριασμός το εκτελεί με βάση τη διαδρομή του και χρήστης χαμηλότερων προνομίων μπορεί να γράψει και να διασχίσει τον γονικό κατάλογό του, ο οποίος δεν έχει sticky bit. Ελέγξτε την ταυτότητα εκτέλεσης του προγράμματος, κάθε συνιστώσα της διαδρομής, το sticky bit του καταλόγου, τα ACL και την πολιτική mount· ελέγξτε τα metadata χωρίς να μετακινήσετε το αρχείο ή να εκτελέσετε το job.

Ένα προνομιούχο PHP cron wrapper μπορεί να φτάσει σε helper που δεν υπάρχει ακόμη. Αν καλεί την PHP [`exec()`](https://www.php.net/manual/en/function.exec.php) με σταθερή απόλυτη διαδρομή helper, χρήστης χαμηλότερων προνομίων που μπορεί να δημιουργήσει αυτό το όνομα στον γονικό κατάλογο μπορεί να ελέγχει τι θα εκτελέσει μια μεταγενέστερη εκτέλεση. Επιβεβαιώστε ότι η εγγραφή cron εκτελεί πράγματι το wrapper με την υψηλότερη ταυτότητα, την ακριβή συμβολοσειρά εντολής και την πολιτική εκτέλεσης της PHP, τα δικαιώματα εγγραφής και αναζήτησης στον κατάλογο του helper, τη συμπεριφορά symlink και sticky bit, καθώς και αν η διαδρομή του helper απουσιάζει ακόμη. Ένας κατάλογος με δυνατότητα εγγραφής ή ένας helper που λείπει αποτελούν απλώς ένδειξη· ελέγξτε το πρόγραμμα, τον πηγαίο κώδικα και τα metadata της διαδρομής, χωρίς να δημιουργήσετε τον helper ή να ενεργοποιήσετε το job.

Ένα προγραμματισμένο job μπορεί επίσης να εντοπίζει input script με `find` και να περνά το καθένα σε interpreter. Για παράδειγμα, η συνάρτηση [`system()` του gnuplot επικαλείται shell](https://gnuplot.sourceforge.net/docs_6.0/gnuplot.pdf), επομένως προνομιούχο job που εκτελεί `gnuplot` σε κάθε αρχείο `*.plt` σε κατάλογο εγγράψιμο από χρήστη χαμηλότερων προνομίων μπορεί να εκτελέσει εντολές με την ταυτότητα του job. Τα [δικαιώματα ανάγνωσης καταλόγου ελέγχουν την εμφάνιση της λίστας, ενώ η εγγραφή και η αναζήτηση (`x`) ελέγχουν τη δημιουργία και την πρόσβαση σε γνωστά ονόματα](https://www.gnu.org/software/coreutils/manual/html_node/Mode-Structure.html)· ελέγξτε την πρόσβαση εγγραφής και αναζήτησης ακόμη κι όταν η `ls` δεν μπορεί να εμφανίσει τα περιεχόμενα του καταλόγου. Συσχετίστε την ακριβή ταυτότητα και εντολή του scheduler, τη συμπεριφορά του interpreter, το επιλεγμένο μοτίβο αρχείων και τα δικαιώματα του καταλόγου· ένας κατάλογος με δυνατότητα εγγραφής ή ένας εγκατεστημένος interpreter από μόνα τους δεν αποδεικνύουν κλιμάκωση. Ιδιωτικά προγράμματα και βραχύβια jobs μπορεί να απαιτούν εξουσιοδοτημένη παρατήρηση συμβάντων, επειδή ένα στιγμιότυπο διεργασιών μπορεί να τα χάσει.

Για προνομιούχο PHP job, ελέγξτε τις κυριολεκτικές δηλώσεις `include`/`require` ως μέρος της αλυσίδας εκτελέσιμων script. Η [PHP αξιολογεί τα αρχεία που περιλαμβάνονται](https://www.php.net/manual/en/function.include.php), επομένως ένα `.php` αρχείο εγγράψιμο από group μπορεί να εκτελέσει κώδικα με την ταυτότητα του job, ακόμη κι όταν το κύριο script είναι μόνο για ανάγνωση. Επαληθεύστε την προγραμματισμένη ταυτότητα, την ενεργή επίλυση της διαδρομής include, τα δικαιώματα αρχείου και καταλόγου και αν το job εκτελείται πραγματικά· ένα δείγμα γραμμής cron σε σχόλιο αποτελεί μόνο ένδειξη. Ο ίδιος έλεγχος ισχύει για root-owned [ενσωματωμένο server PHP](https://www.php.net/commandline.webserver) που ξεκινά με `-S` και `-t <document-root>`: ένας listener σε loopback μπορεί και πάλι να εκτελεί PHP εφαρμογής για τοπικά αιτήματα. Ελέγξτε τη διεργασία και τον πηγαίο κώδικα χωρίς να ενεργοποιήσετε κανένα trigger κατά την καταγραφή.

Ένα προνομιούχο PHP job μπορεί επίσης να διασχίσει το όριο μέσω **αρχείου δεδομένων**: αν χρήστης χαμηλότερων προνομίων μπορεί να αλλάξει το ακριβές αρχείο που περνά στη [`unserialize()`](https://www.php.net/manual/en/function.unserialize.php), η PHP μπορεί να καλέσει τη μέθοδο `__wakeup()` ή `__unserialize()` μιας φορτωμένης κλάσης κατά την επαναφορά ενός object. Εξετάστε την ενεργή ταυτότητα του job, τα δικαιώματα του αρχείου και των προγονικών καταλόγων, τις φορτωμένες κλάσεις και τις πραγματικές παρενέργειες των μεθόδων, όπως εγγραφή αρχείου που επιλέγεται μέσω property. Ένα log με δυνατότητα εγγραφής ή μια κλήση `unserialize()` από μόνα τους δεν αποδεικνύουν αξιοποιήσιμη διαδρομή. Ελέγξτε τον πηγαίο κώδικα και τα metadata χωρίς να γράψετε serialized είσοδο ή να εκτελέσετε το job κατά την καταγραφή.

Μια root cron εργασία μπορεί να καλεί **CLI page runner** εφαρμογής PHP αντί για τον web server. Ακολουθήστε το document root και το URI που επιλέγει ο runner μέχρι το πραγματικό PHP entrypoint· αν ο λογαριασμός της web υπηρεσίας μπορεί να γράψει σε αυτό το entrypoint, το προγραμματισμένο CLI αίτημα μπορεί να εκτελέσει τον τροποποιημένο κώδικά του ως root, ακόμη κι αν ο runner και το cron wrapper είναι μόνο για ανάγνωση. Επιβεβαιώστε την ταυτότητα του scheduler, την ακριβή επίλυση URI προς αρχείο, τα ενεργά δικαιώματα αρχείου και προγονικών καταλόγων και αν έλεγχος ακεραιότητας προστατεύει το ίδιο το entrypoint. Ελέγξτε τον πηγαίο κώδικα και τα metadata χωρίς να καλέσετε τον runner ή να αλλάξετε τη σελίδα κατά την καταγραφή.

Μια διεργασία `ipython` που ξεκινά από προγραμματισμένο job ή άλλον χρήστη από κοινόχρηστο working directory απαιτεί έλεγχο αρχείων εκκίνησης. Οι [σημειώσεις έκδοσης ασφαλείας του IPython](https://ipython.readthedocs.io/en/8.25.0/whatsnew/version8.html#ipython-8-0-1-cve-2022-21699) εξηγούν ότι τα επηρεαζόμενα builds αναζητούσαν profiles και ρυθμίσεις στον τρέχοντα κατάλογο, συμπεριλαμβανομένου κώδικα στο `profile_default/startup`, πριν από τη διόρθωση του CVE-2022-21699. Συσχετίστε το πραγματικά εγκατεστημένο build ή το patch του προμηθευτή, τον working directory της εντολής, την ταυτότητα της διεργασίας με τα υψηλότερα προνόμια και τη δυνατότητα του χρήστη χαμηλότερων προνομίων να γράψει και να αναζητήσει την ακριβή διαδρομή εκκίνησης. Η εγκατάσταση `ipython`, ένας κατάλογος με δυνατότητα εγγραφής ή μια συμβολοσειρά έκδοσης από μόνα τους δεν αποδεικνύουν ότι άλλη ταυτότητα θα φορτώσει αρχείο από εκεί. Ελέγξτε το πρόγραμμα και τα metadata της διαδρομής χωρίς να εκκινήσετε τον interpreter με τα υψηλότερα προνόμια.

Για προνομιούχο PHP server που καλεί συναρτήσεις από custom native extension, εντοπίστε το PHP SAPI της υπηρεσίας και το ενεργό `php.ini` καθώς και τα αρχεία `.ini` που σαρώνονται, πριν εξετάσετε το extension. Η [PHP φορτώνει τις ρυθμισμένες βιβλιοθήκες `extension` κατά την εκκίνηση](https://www.php.net/manual/en/ini.core.php) και τα [CLI και web SAPI μπορούν να χρησιμοποιούν διαφορετικά αρχεία ρυθμίσεων](https://www.php.net/manual/en/configuration.file.php). Έτσι, μια προσβάσιμη φόρμα σύνδεσης ή ένας τοπικός listener μπορεί να περάσει συμβολοσειρές ελεγχόμενες από χρήστη σε μεταγλωττισμένο κώδικα που εκτελείται με την ταυτότητα της υπηρεσίας. Καταγράψτε το `User=` της μονάδας, το `ExecStart=`, τον working directory, την πραγματική διαδρομή του extension και τα ορίσματα που ελέγχει ο καλών· η απλή παρουσία ενός `.so` ή ενός socket σε loopback δεν αποδεικνύει σφάλμα memory corruption. Αναλύστε ξεχωριστά κάθε custom parser, αντί να στείλετε probes κατά την παθητική καταγραφή.

Όταν προνομιούχο wrapper υπολογίζει hash ενός script μέσω της διαδρομής του και αργότερα ανοίγει ξανά αυτή τη διαδρομή για να το εκτελέσει, το digest πιστοποιεί μόνο το object που διαβάστηκε στο πρώτο άνοιγμα. Αν χρήστης χαμηλότερων προνομίων μπορεί να αντικαταστήσει την εγγραφή καταλόγου του script μεταξύ αυτών των δύο ανοιγμάτων, η μεταγενέστερη εκτέλεση μπορεί να επιλύσει διαφορετικό object, ακόμη κι αν το αρχικό αρχείο script ανήκει στο root. Ένα FIFO μπορεί να παρατείνει τη φάση ελέγχου, αλλά η διαδρομή εξαρτάται από δικαιώματα αντικαταστάσιμου γονικού καταλόγου, από το αν γίνονται πράγματι ξεχωριστά ανοίγματα, την ταυτότητα του scheduler, τους κανόνες sticky bit και mount, καθώς και τον χρονισμό. Ελέγξτε το wrapper και την έξοδο `namei -l` ως παθητικές ενδείξεις· επιτυχής έλεγχος checksum δεν αποδεικνύει από μόνος του ότι προστατεύεται η μεταγενέστερη επίλυση της διαδρομής.

Ένα προνομιούχο backup job μπορεί επίσης να **αποκαλύψει** δεδομένα χωρίς να εκτελέσει εντολές που παρέχει ο επιτιθέμενος. Εξετάστε αν χρήστης χαμηλότερων προνομίων μπορεί να δημιουργήσει control file που διαβάζει το job, αν στη συνέχεια το job ανοίγει προστατευμένη πηγή όπως το `/etc/shadow` και αν ένα URL που επιλέγει ο επιτιθέμενος ή κάποιο αναγνώσιμο output λαμβάνει το αποτέλεσμα. Επαληθεύστε και τα τρία μέρη πριν το χαρακτηρίσετε διαδρομή αποκάλυψης. Μια σταθερή shell εντολή στο ίδιο script δεν καθιστά από μόνη της αυτό το control file είσοδο shell injection. Ελέγξτε το script και τα δικαιώματα αρχείων χωρίς να εκτελέσετε το job ή να τοποθετήσετε control file κατά την καταγραφή.

Αν προνομιούχο προγραμματισμένο job εκτελεί `curl -K FILE` ή `curl --config FILE`, το [curl αντιμετωπίζει τις επιλογές σε αυτό το αρχείο ως ορίσματα γραμμής εντολών](https://curl.se/docs/manpage.html). Χρήστης χαμηλότερων προνομίων που ελέγχει το ακριβές αρχείο όταν το διαβάζει το curl μπορεί να επηρεάσει το URL που ζητείται, την είσοδο τοπικού αρχείου ή τη διαδρομή εξόδου. Επιβεβαιώστε την ενεργή ταυτότητα του job, τα δικαιώματα εγγραφής στο αρχείο και στους προγονικούς καταλόγους, τον χρονισμό οποιουδήποτε άλλου job που αντικαθιστά το αρχείο και τον τρόπο με τον οποίο οι επιλογές config αλληλεπιδρούν με τις σταθερές επιλογές γραμμής εντολών, πριν ισχυριστείτε ότι υπάρχει προστατευμένη ανάγνωση ή εγγραφή. Μια διαδρομή config με δυνατότητα εγγραφής ή μια ορατή σημαία `-K` από μόνα τους δεν αποδεικνύουν ότι ενεργοποιούνται οι επιλεγμένες επιλογές· ελέγξτε το πρόγραμμα και τα metadata χωρίς να εκτελέσετε το job ή να ανακτήσετε URL κατά την παθητική καταγραφή.

Αν μια εγγραφή cron καλεί helper script, ελέγξτε επίσης τον working directory του helper και την εντολή archive. Ένα wildcard χωρίς quotes πάνω σε κατάλογο εγγράψιμο από άλλο χρήστη μπορεί να μετατρέψει ονόματα αρχείων σε επιλογές archiver· οι ενέργειες checkpoint του GNU tar είναι ένα παράδειγμα. Επιβεβαιώστε την ταυτότητα εκτέλεσης του job, τον κατάλογο εισόδου με δυνατότητα εγγραφής, τον ακριβή archiver και τις επιλογές του, καθώς και αν το `--` τερματίζει την ανάλυση επιλογών, πριν ισχυριστείτε ότι υπάρχει διαδρομή εντολών μεταξύ χρηστών. Δείτε τη [συμπεριφορά wildcard και tar](../interesting-files-permissions/wildcards-spare-tricks.md).

Μια ξεχωριστή αποκάλυψη μέσω αρχείου backup μπορεί να προκύψει όταν προνομιούχο helper εκτελεί `cd INPUT_DIR; tar ... *` χωρίς να ελέγξει αν πέτυχε το `cd`. Αν χρήστης χαμηλότερων προνομίων μπορεί να αφαιρέσει ή να αντικαταστήσει το `INPUT_DIR`, ένα αποτυχημένο `cd` μπορεί να αφήσει το shell στον προηγούμενο κατάλογο, από τον οποίο μπορεί να διαβάσει η επόμενη εντολή archive. Επαληθεύστε τον αρχικό working directory του job, μια πραγματική διαδρομή αποτυχίας `cd`, αν το script τερματίζει ή χρησιμοποιεί `&&`, τις ακριβείς επιλογές του archiver και αν ο χρήστης χαμηλότερων προνομίων μπορεί να διαβάσει το archive εξόδου. Ένας κατάλογος εισόδου με δυνατότητα εγγραφής ή ένα αναγνώσιμο archive από μόνα τους αποτελούν μόνο ένδειξη· ελέγξτε το helper και τα δικαιώματα διαδρομών χωρίς να αλλάξετε το ενεργό job.

Ένα προγραμματισμένο εκτελέσιμο μπορεί να κρύβει shell script αντί να καταργεί το όριο εμπιστοσύνης: το [SHc](https://github.com/neurobin/shc) περικλείει κρυπτογραφημένο κείμενο script σε native binary και το εκτελεί μέσω shell κατά την εκτέλεση. Ένα επίθημα `.sh.x` ή ένα αδιαφανές ELF αποτελεί μόνο ένδειξη για έλεγχο. Για να αξιολογήσετε injection επιλογών μέσω ονόματος αρχείου, διαπιστώστε την ταυτότητα του προνομιούχου scheduler, τον πραγματικό working directory και την εντολή του helper, αν χρήστης χαμηλότερων προνομίων μπορεί να δημιουργήσει ονόματα που ταιριάζουν εκεί και αν ένα glob χωρίς quotes φτάνει σε εντολή όπως το `rsync` χωρίς όριο επιλογών. Η [επιλογή remote-shell του `rsync`](../interesting-files-permissions/wildcards-spare-tricks.md#rsync) έχει σημασία μόνο αν χρησιμοποιείται αυτή η ακριβής διαδρομή εντολής. Περιορισμένη ορατότητα `/proc` ή αποτυχημένη στατική αποκρυπτογράφηση αφήνουν την εντολή άγνωστη· μην εκτελέσετε το προνομιούχο helper απλώς για να το ταξινομήσετε.

Το κείμενο της γραμμής εντολών μιας διεργασίας αποτελεί άλλη μια μη έμπιστη είσοδο για προνομιούχο helper. Χρήστης χαμηλότερων προνομίων μπορεί να επιλέξει τίτλο διεργασίας ή `argv[0]` που ταιριάζει στο `pgrep -f`· ένα όνομα που ταιριάζει δεν πιστοποιεί το εκτελέσιμο ή τον ιδιοκτήτη του. Αν script που εκτελείται ως root καταγράψει αυτό το κείμενο, ξαναγράψει μέρος του σε `apache2ctl`/`httpd` και εκτελέσει το αποτέλεσμα χωρίς σταθερό πίνακα ορισμάτων, οι επιλογές που επιλέγει ο επιτιθέμενος μπορούν να ορίσουν διαφορετικό κατάλογο ρυθμίσεων ή error log. Η ανάλυση ρυθμίσεων Apache μπορεί να φορτώσει modules ή να φτάσει σε ρυθμισμένα helper, επομένως μην επικυρώσετε μη έμπιστη ρύθμιση ως root κατά την καταγραφή. Ελέγξτε τον ιδιοκτήτη του scheduler, το ακριβές helper, την ταυτότητα της διεργασίας και τη ροή δεδομένων προς τα ορίσματα· πρόκειται για injection επιλογών/ρυθμίσεων, εκτός αν αποδειχθεί ξεχωριστά εκτέλεση shell metacharacter.

Ένας parser που εκτελείται ως root και περνά μη έμπιστο κείμενο σε αριθμητικές εκφράσεις Bash μπορεί να εκτελέσει substitutions μέσα σε αυτό το κείμενο. Ο [οδηγός κλιμάκωσης προνομίων](../linux-basics/linux-privilege-escalation/README.md#bash-arithmetic-expansion-injection-in-cron-log-parsers) περιλαμβάνει ολοκληρωμένο παράδειγμα. Επιβεβαιώστε την πηγή εισόδου και την εντολή ανάλυσης, πριν θεωρήσετε εκμεταλλεύσιμη κάθε αριθμητική έκφραση.

Για προνομιούχο job που αναλύει log εφαρμογής, ακολουθήστε τα μη έμπιστα πεδία πέρα από την πρώτη ανάλυση. Χρήστης χαμηλότερων προνομίων μπορεί να έχει δυνατότητα εγγραφής στο log μέσω της τρέχουσας ομάδας διεργασίας του ή να επηρεάζει καταγεγραμμένα πεδία αιτήματος· μια εγγραφή μπορεί στη συνέχεια να επιλέξει εικόνα, τα metadata της οποίας γίνονται δεύτερη διαδρομή για άνοιγμα XML. Ελέγξτε την ενεργή ταυτότητα του job, την πραγματική πρόσβαση εγγραφής στο log, τον χειρισμό οριοθετών, τον κανονικοποιημένο περιορισμό της διαδρομής και αν το επιλεγμένο XML ελέγχεται από τον επιτιθέμενο. Η επέκταση external entity μπορεί να μετατρέψει αυτή τη δεύτερη ανάγνωση σε προνομιούχα αποκάλυψη αρχείου, αν το αποτέλεσμα της επέκτασης φτάσει σε output αναγνώσιμο από χρήστη χαμηλότερων προνομίων. Ο [οδηγός ασφάλειας επεξεργασίας XML της Java](https://docs.oracle.com/en/java/javase/17/security/java-api-xml-processing-jaxp-security-guide.html) περιγράφει ελέγχους για πρόσβαση σε εξωτερικά DTD/entity· ελέγξτε τον εγκατεστημένο parser και τις ενεργές ρυθμίσεις του. Ένα log ή αρχείο XML με δυνατότητα εγγραφής από μόνο του αποτελεί απλώς ένδειξη. Ελέγξτε τον κώδικα και τα metadata χωρίς να δώσετε είσοδο στον προγραμματισμένο parser κατά την καταγραφή.

Ελέγξτε επίσης προνομιούχα jobs που δημιουργούν αρχεία από Git repository άλλου χρήστη. Ένα script μπορεί να χρησιμοποιεί `git ls-tree` και `git cat-file` αντί για `git checkout`, αλλά και πάλι να εμπιστεύεται διαδρομές tree ελεγχόμενες από επιτιθέμενο όταν τις ενώνει με έναν κατάλογο staging. Απόλυτες διαδρομές και συνιστώσες `..` μπορούν να διαφύγουν από αυτόν τον κατάλογο, εκτός αν ο προορισμός κανονικοποιείται και ελέγχεται ότι παραμένει εντός του καταλόγου πριν από την εγγραφή. Το `git -c safe.directory=*` επιτρέπει πρόσβαση σε repository διαφορετικής ιδιοκτησίας· από μόνο του δεν δημιουργεί συνθήκη αυθαίρετης εγγραφής.

Ένα root-run backup βάσης δεδομένων μπορεί να δημιουργήσει άλλο ένα όριο ιδιοκτησίας. Το PostgreSQL [`pg_basebackup`](https://www.postgresql.org/docs/14/app-pgbasebackup.html) αντιγράφει πρόσθετα κανονικά αρχεία που τοποθετούνται στον κατάλογο δεδομένων της πηγής και η προεπιλεγμένη plain μορφή του γράφει τα αρχεία στο `-D` ως δέντρο καταλόγων. Αν λογαριασμός χαμηλότερων προνομίων μπορεί να δημιουργήσει ή να τροποποιήσει αυτά τα αρχεία πηγής, ελέγξτε την ιδιοκτησία και τα δικαιώματα του προορισμού που προκύπτει, αν η διαδρομή του είναι προσβάσιμη και εκτελέσιμη και αν το mount έχει `nosuid`. Ένα αντίγραφο που ανήκει στο root και διατηρεί δικαιώματα set-ID μπορεί να είναι επικίνδυνο· backup μόνο σε tar, αφαίρεση δικαιωμάτων ή μη προσβάσιμος προορισμός δεν αποδεικνύουν την ίδια διαδρομή. Ακολουθήστε το προγραμματισμένο wrapper και τον ενεργό χρήστη πριν θεωρήσετε την εντολή backup εύρημα.

## Παρατήρηση βραχύβιων εργασιών

Ένα μόνο στιγμιότυπο διεργασιών μπορεί να χάσει job που εκτελείται για χιλιοστά του δευτερολέπτου. Συγκρίνετε τις δηλώσεις timer/cron με τα logs και, όταν υπάρχει εξουσιοδότηση, με παρακολούθηση συμβάντων διεργασιών, όπως `pspy` ή audit. Συσχετίστε τον προγραμματισμένο ιδιοκτήτη, την ακριβή γραμμή εντολής και τα αρχεία που διαβάζει ή γράφει η εργασία. Ένα web UI scheduler σε loopback είναι ξεχωριστή διεπαφή· δείτε το [παράδειγμα Crontab UI](../linux-basics/linux-privilege-escalation/README.md#crontab-ui-alseambusher-running-as-root--web-based-scheduler-privesc).
