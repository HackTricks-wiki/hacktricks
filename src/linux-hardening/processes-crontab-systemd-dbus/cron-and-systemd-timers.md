# Kazi za Cron na Systemd Timers

{{#include ../../banners/hacktricks-training.md}}

Kazi zilizoratibiwa zinaweza kutekelezwa kwa utambulisho na mazingira tofauti na ya shell ya sasa. Orodhesha cron, `at`, anacron na systemd timers, kisha fuatilia kila amri iliyoratibiwa kupitia scripts zake, imports, working directory na inputs zinazoweza kuandikwa.

## Orodhesha ratiba

```bash
crontab -l 2>/dev/null
ls -la /etc/crontab /etc/cron.* /var/spool/cron* 2>/dev/null
atq 2>/dev/null
systemctl list-timers --all 2>/dev/null
```

System crontab kwa kawaida huwa na sehemu ya mtumiaji; crontab ya mtumiaji haina. Kagua PATH na mazingira halisi ya scheduler. `run-parts --test /etc/cron.daily` huonyesha majina ya faili ambayo yangechaguliwa kwenye host hiyo. Herufi za udhibiti zinaweza kuficha ingizo lisitambulike kwa urahisi unapotazama matokeo, kwa hivyo tumia `cat -A` au `sed -n l` ratiba inapoonekana kuwa ya kutiliwa shaka.

## Fuatilia utatuzi wa faili na amri zenye upendeleo wa juu

```bash
systemctl cat <name>.timer <name>.service
systemctl show <name>.service -p User -p ExecStart -p EnvironmentFiles -p WorkingDirectory
namei -l /path/to/scheduled/script
```

Kagua minyororo ya script zinazoweza kuandikwa, njia za `EnvironmentFile=`, drop-in, symlink, amri za relative, upanuzi wa wildcard, na binary zinazonakiliwa au kutekelezwa na kazi yenye privileges. Timer inaweza kuwasha service yenye jina tofauti kupitia setting yake ya `Unit=`. Kurasa za [PATH](../linux-basics/linux-environment-variables.md#path), [wildcard](../interesting-files-permissions/wildcards-spare-tricks.md), na [file-link](../main-system-information/filesystem-links-and-file-descriptors.md) zinaeleza primitives kuu.

Kwa script ya `chkrootkit` inayopangwa kuendeshwa kama root, kagua source iliyosakinishwa ili kutafuta kasoro ya zamani ya quoting ya [slapper-loop (CVE-2014-0476)](https://bugzilla.redhat.com/show_bug.cgi?id=CVE-2014-0476): `file_port=$file_port $i` isiyo na quotes baada ya ukaguzi wa temporary path ya `SLAPPER_FILES` inaweza kutekeleza faili hiyo. Hakiki script halisi au patch ya vendor, upangaji wa root, ruhusa ya mtumiaji wa kiwango cha chini kuandika kwenye temporary path hiyo mahususi, hali yake ya executable, na sera ya mount. String ya version au kuwepo tu kwa `chkrootkit` hakuthibitishi path hiyo; usiunde wala kuendesha temporary file wakati wa ukaguzi wa bila mabadiliko.

Fuatilia hop moja zaidi ya unit wakati service ya root iliyoanzishwa na timer inaendesha `systemctl restart <other>.service`: unit iliyoanzishwa upya inaweza kuita shell yenye script inayoweza kuandikwa na mtumiaji wa privileges za chini. Thibitisha `User=`, `DynamicUser=`, `RootDirectory=`/`RootImage=`, argument halisi za `ExecStart=`, na ruhusa kwenye script na parent path yake. Script inayoweza kuandikwa ni candidate tu hadi timer na service iliyoanzishwa upya ziwe active katika execution context hiyo; kagua properties za unit bila kuanzisha upya service yoyote.

Ikiwa kazi yenye privileges za juu inapakua script kwa kutumia hostname na kuipitisha kwa shell, kagua pia nani anadhibiti resolution ya hostname hiyo pamoja na script ya remote. Faili ya `/etc/hosts` inayoweza kuandikwa, ikiwemo ruhusa kupitia group au ACL, inaweza kuelekeza upya jina ambalo kazi inaresolve locally; jibu la `curl` huwa execution path ya kuvuka akaunti tu pale amri halisi iliyopangwa inapoendesha jibu hilo na kazi inapotumia resolver path iliyoathiriwa. Hakiki identity inayotekeleza kazi, URL halisi na shell pipeline, tabia ya proxy/DNS inayotumika, na ruhusa za faili na parent directory. Faili ya hosts inayoweza kuandikwa pekee ni kidokezo cha ukaguzi, si uthibitisho kuwa kuna consumer yenye privileges. Kagua schedule na metadata bila kubadilisha mapping au kupakua script wakati wa enumeration.

Upakuaji uliopangwa wa `wget` wenye privileges ni mpaka tofauti wa kuandika faili, hata kama maudhui yaliyopakuliwa hayatekelezwi moja kwa moja. [GNU Wget 1.18 ilibadilisha tabia ya default ya kushughulikia jina la faili wakati wa redirect ya HTTP kwenda FTP ili kurekebisha CVE-2016-4971](https://lists.gnu.org/archive/html/info-gnu/2016-06/msg00004.html); build za zamani zilizoathirika zingeweza kutumia jina la faili la redirect ya FTP, huku `--trust-server-names` ikiomba tabia hiyo waziwazi. Ikiwa mtu asiyeaminika sana anadhibiti jibu la HTTP na rasilimali ya FTP, kagua kama kazi inafuata redirect hiyo, build halisi ya Wget au backport ya vendor, options za output, identity inayotekeleza kazi, working directory, na kama jina la faili lengwa linaweza kuwa startup file. [Wget hupakia `WGETRC` au `$HOME/.wgetrc`](https://www.gnu.org/software/wget/manual/html_node/Wgetrc-Location.html), na [settings zake zinaweza kuchagua chanzo cha POST au njia ya output](https://www.gnu.org/software/wget/manual/html_node/Wgetrc-Commands.html); upakuaji wa baadaye wenye privileges ni sharti tofauti kwa disclosure au write yoyote inayoweza kutokea. Ufikiaji wa port ya chini kupitia `authbind` ni muhimu tu ikiwa caller anaweza kweli kutoa URL ambayo kazi inaomba. Kagua configuration na logs bila kutoa redirect au kuendesha kazi. [Ufikiaji wa raw block-device kupitia group ya `disk`](../user-information/interesting-groups-linux-pe/README.md#disk-group) hauhusiani na njia hii ya upakuaji wa mtandao.

Fuatilia data files pamoja na scripts. Zana ya simulation au orchestration iliyopangwa inaweza kusoma faili ya YAML inayofafanua processes za kuanzisha; ikiwa mtumiaji wa privileges za chini anaweza kuhariri faili hiyo na kazi ikaitekeleza chini ya akaunti nyingine, data hiyo inaweza kuwa amri chini ya identity ya kazi. Hakiki amri halisi iliyopangwa, mtumiaji anayetumika, njia ya faili, semantics za parser, na ruhusa za kuandika (ikiwemo parent directories) kabla ya kuchukulia YAML inayoweza kuandikwa kuwa execution path. Kusoma schedule na metadata ya faili kunatosha kwa triage ya bila mabadiliko; usiendeshe kazi wala kubadilisha input yake wakati wa enumeration.

Configuration ya SSH client pia ni input inayoweza kutekelezwa wakati kazi yenye privileges za juu inaendesha `ssh -F` dhidi ya faili ambayo mtumiaji wa privileges za chini anaweza kubadilisha. OpenSSH [`ProxyCommand`](https://man.openbsd.org/ssh_config#ProxyCommand) huendesha amri ya ndani kupitia shell ya client, huku `Host`/`Match` na options za awali zikiamua kama directive hiyo itatumika. Linganisha SSH invocation halisi iliyopangwa, identity inayotekeleza kazi, njia ya config iliyochaguliwa, ruhusa za kuandika kwenye directory na faili, na mpangilio wa options unaotumika kabla ya kuiita execution path ya kuvuka akaunti. Kagua rekodi hizi bila kuendesha kazi au kupakia config isiyoaminika kama akaunti yenye privileges.

`scp` iliyopangwa ikifuatiwa na `ssh` ya kuendesha script iliyonakiliwa inahitaji ukaguzi wa pili wa mpaka wa uaminifu ikiwa mtumiaji wa privileges za chini anadhibiti SSH service lengwa. Ikiwa service hiyo inaweza ku-forward connection kwenda host nyingine, client yenye privileges inaweza kujithibitisha kwa endpoint isiyokusudiwa; [`StrictHostKeyChecking no`](https://man.openbsd.org/ssh_config#StrictHostKeyChecking) hudhoofisha ulinzi dhidi ya host key iliyobadilika, kwa kuzingatia vizuizi vilivyosalia vya OpenSSH na options zinazotumika kwa host husika. Tambua identity inayotekeleza kazi, destination na authentication method halisi, identity inayotumika kwa amri ya remote, na kama path hiyo hiyo ya destination inaweza kuandikwa au tayari ipo kwenye host iliyoelekezwa upya. Ili faili ya zamani au inayodhibitiwa na mshambuliaji itekelezwe, copy lazima ishindwe au ikose path hiyo **na** wrapper iendelee hadi amri yake ya SSH; [Bash `errexit`](https://www.gnu.org/software/bash/manual/html_node/The-Set-Builtin.html) na ushughulikiaji wa status ulio wazi huathiri mtiririko huo. Setting dhaifu ya host-key, process ya `sshpass` inayoonekana, au temporary directory inayoweza kuandikwa pekee haithibitishi mnyororo huu. Kagua schedule, script, SSH configuration, na metadata ya faili bila kuelekeza upya service au kuanzisha kazi wakati wa enumeration.

Scheduler ya application yenye privileges inaweza kupata kazi zake kutoka kwenye rows za database badala ya faili zinazoweza kuandikwa. Kwa mfano, cron entry ya root inayoita Laravel [`php artisan schedule:run`](https://laravel.com/docs/9.x/scheduling#running-the-scheduler) inaweza kufikia application code inayosoma task rows. Ikiwa akaunti yenye privileges za chini inaweza kuandika row yenye pathname ya ndani na scheduled callback ikaita PHP [`file_get_contents`](https://www.php.net/manual/en/function.file-get-contents.php) kama root na kutuma body iliyorejeshwa kwenye webhook iliyochaguliwa na row hiyo, huo ni privileged file-disclosure path. Hakiki identity ya cron, callback halisi ya scheduler na mtiririko wa data kutoka row hadi path, ruhusa ya kuandika database, validation inayofanywa baada ya row kusomwa, na destination ya outbound. Application `.env` inayosomeka ni kidokezo tu cha credential; validation ya web form au database password pekee havithibitishi udhibiti wa row au disclosure. Kagua schedule, code, na ruhusa za credential-file bila mabadiliko, bila kuuliza database au kupanga task wakati wa enumeration.

Kazi za event-driven `incron` zinahitaji ukaguzi huohuo: [incrontab entries](https://manpages.debian.org/testing/incron/incrontab.5.en.html) huhusisha path inayofuatiliwa na event na amri inayoendeshwa chini ya identity ya mmiliki wa table. Mtumiaji wa privileges za chini anaweza kuathiri faili inayofuatiliwa kwa njia isiyo ya moja kwa moja ikiwa application itafuata link kutoka directory inayoweza kuandikwa na kuandika maandishi yanayodhibitiwa na mshambuliaji kwenye target inayofuatiliwa. Hakiki mmiliki halisi wa table, event, target na ruhusa za ancestor, tabia ya application ya kufuata link, na jinsi maandishi hayo yanavyogeuka kuwa command arguments. Hasa, [GNU Mailutils `mail` inakubali `--exec`](https://mailutils.org/manual/html_node/Invoking-Mail.html), na [amri yake ya shell-escape](https://mailutils.org/manual/html_node/Shell-Escapes.html) inaweza kuendesha program; field isiyoaminika inayopitishwa kama option tofauti kwa implementation hiyo inaweza kuvuka hadi command execution. Implementations nyingine za `mail` au mpaka wa argument uliowekwa quotes na usiobadilika zinaweza kufanya kazi tofauti. Kagua schedule, application code, na metadata ya faili bila kubadilisha faili inayofuatiliwa au kuanzisha kazi wakati wa enumeration.

Log inayofuatiliwa pia inaweza kuvuka mpaka wa akaunti kupitia helper script. Ikiwa akaunti yenye privileges za chini inaweza kuandika log na mmiliki wa `incron` akasoma field kutoka humo na kuiweka kwenye string mpya ya amri ya [`sh -c`](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/sh.html), shell huchanganua field hiyo tena chini ya identity ya mmiliki. Kagua event halisi inayofuatiliwa, log na ruhusa za parent, njia ya helper, jinsi field ya log inavyobadilishwa, na kama amri inayotokana nayo inafikiwa. Kuona log inayoweza kuandikwa na entry ya `incron` pekee hakuthibitishi mtiririko wa data; usiandike trigger line wala kuendesha helper wakati wa enumeration ya bila mabadiliko.

Kazi za kufanya upya vyeti zinaweza kuvuka mpaka huohuo. Helper yenye privileges inaweza kusoma X.509 subject kutoka kwenye certificate iliyo kwenye directory inayoweza kuandikwa na mtumiaji wa privileges za chini na kuingiza common name yake kwenye string mpya ya amri ya `bash -c`. [OpenSSL inaweza kuonyesha subject ya certificate na kuangalia kama muda wake umeisha](https://docs.openssl.org/3.3/man1/openssl-x509/); [Bash huchanganua string ya `-c` kama shell input](https://www.gnu.org/software/bash/manual/html_node/Invoking-Bash.html), kwa hiyo kuweka variable kwenye quotes kwenye script ya nje hakulindi uchanganuzi wa pili. Thibitisha identity iliyopangwa, njia halisi ya input na ruhusa za kuandika, branch ya kufanya upya, na mtiririko wa data hadi `bash -c` kabla ya kuiita command injection. Kagua script na metadata ya certificate bila kuanzisha upya mchakato wa renewal wakati wa enumeration.

Uchanganuzi huohuo wa pili unaweza kutokea kazi iliyopangwa yenye privileges inapotoa jina kutoka kwenye archive au package ya mtumiaji wa privileges za chini na kulipitisha kwa `xargs -I` ili liingizwe kwenye string ya amri ya `sh -c`. [GNU `xargs -I` hubadilisha placeholder kwenye arguments za awali](https://www.gnu.org/software/findutils/manual/html_node/find_html/xargs-options.html), na [`sh -c` hutafsiri command string yake](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/sh.html). Hata kama script ya nje inaweka jina lililotolewa kwenye quotes, hilo halifanyi shell program itakayobadilishwa baadaye kuwa salama. Hakiki identity inayotekeleza kazi, njia halisi ya input inayokubaliwa na ruhusa za kuandika, validation ya archive na masharti ya branch, na mtiririko wa jina hadi shell. Directory ya upload inayoweza kuandikwa au invocation ya `xargs` pekee ni kidokezo tu; kagua schedule, script, na metadata ya path bila kuwasilisha package au kuendesha kazi wakati wa enumeration.

Kazi iliyopangwa ya kuingiza fonti au picha inaweza pia kuamini majina *ndani* ya archive iliyotolewa na caller hata wakati filename ya nje ya upload imewekewa vikwazo. FontForge ilirekebisha command injection ya majina ya archive members katika [mabadiliko ya upstream ya CVE-2024-25081 na CVE-2024-25082](https://github.com/fontforge/fontforge/pull/5367). Thibitisha kuwa kazi yenye privileges za juu kweli inafungua archive kutoka path inayoweza kuandikwa na mtumiaji wa privileges za chini, identity inayotekeleza kazi, build halisi ya FontForge au backport ya vendor, na code path ya kushughulikia archive. String ya version au suffix ya upload inayoruhusiwa pekee si uthibitisho wa execution. Kagua schedule, ruhusa za path, na metadata ya build bila kuingiza archive isiyoaminika wakati wa enumeration.

Network scanner zilizopangwa zinaweza kuvuka mpaka tofauti wakati script maalum inachukulia subject ya remote TLS certificate kama filename ya ndani. [Nmap NSE huendesha scripts zilizochaguliwa bila sandbox](https://nmap.org/book/nse-usage.html), kwa hiyo kagua script halisi na kama inaunganisha field ya subject isiyoaminika kwenye data directory bila ukaguzi wa containment. File disclosure inahitaji target ambayo scheduler itaskana, path inayopatikana kama faili inayosomeka na identity inayotekeleza scanner, na report au log inayowasilishwa kwa msomaji wa privileges za chini. Field ya certificate au scanner iliyosakinishwa pekee havithibitishi mnyororo huo; kagua schedule, script, path resolution, na report destination bila kuscan target mpya wakati wa enumeration ya bila mabadiliko.

Amri ya cron yenye privileges inayopitisha shell glob kama `/path/to/tasks/*.yml` kwa Ansible runner inahitaji ukaguzi wa ruhusa za directory, hata kama kila playbook iliyopo ni read-only. Mtumiaji mwenye ruhusa za kuandika na search kwenye directory inayotumiwa na glob anaweza kuunda playbook nyingine inayolingana. [Ansible playbooks hufafanua tasks ambazo runner huendesha](https://docs.ansible.com/projects/ansible/latest/cli/ansible-playbook.html), lakini custom wrapper inaweza kuchuja paths au kutumia identity tofauti: hakiki tabia yake, mtumiaji halisi wa cron, upanuzi wa shell, ACLs, sticky bit, na sera ya mount kabla ya kuchukulia directory hiyo kuwa execution path. Kagua metadata na wrapper kwa uchanganuzi wa static; usiendeshe kazi iliyopangwa wakati wa enumeration.

Cron wrapper yenye privileges inaweza kupitisha filenames kutoka directory ya upload kwa Perl helper baada ya kupanua glob. Perl [`<>` diamond operator hutumia two-argument `open`](https://perldoc.perl.org/perlop#The-Null-Filehandle), kwa hiyo filename inayolingana ikitafsiriwa kama amri ya pipe inaweza kutekelezwa chini ya identity ya helper; [`<<>>` huchukulia arguments kama filenames halisi](https://perldoc.perl.org/perlop#The-Null-Filehandle). Thibitisha identity ya scheduler, working directory na glob ya wrapper, jinsi helper inavyoshughulikia `@ARGV` hasa, vizuizi vya filename, na kama identity yenye privileges za chini inaweza kuweka jina linalolingana kupitia ruhusa za filesystem au huduma ya upload inayohitaji authentication. Cron line, Perl script, au FTP directory inayoweza kuandikwa pekee havithibitishi mnyororo kamili. Kagua source na metadata bila kuwasilisha filename iliyoundwa kwa makusudi au kuendesha kazi wakati wa enumeration.

Script ya cron iliyo read-only bado inaweza kubadilishwa ikiwa akaunti iliyopangwa huiendesha kwa pathname na mtumiaji wa privileges za chini anaweza kuandika na kupita kwenye parent directory yake isiyo na sticky bit. Kagua identity inayotekeleza schedule, kila sehemu ya path, sticky bit ya directory, ACLs na sera ya mount; kagua metadata bila kuhamisha faili au kuendesha kazi.

PHP cron wrapper yenye privileges inaweza kufikia helper ambayo bado haipo. Ikiwa inaita PHP [`exec()`](https://www.php.net/manual/en/function.exec.php) kwa njia kamili isiyobadilika ya helper, mtumiaji wa privileges za chini anayeweza kuunda jina hilo kwenye parent directory yake anaweza kudhibiti kitakachoendeshwa baadaye. Thibitisha kuwa cron entry inaendesha wrapper chini ya identity ya juu, command string halisi na sera ya PHP ya execution, ruhusa za kuandika na search kwenye helper directory, tabia ya symlink na sticky bit, na kama helper path bado haipo. Directory inayoweza kuandikwa au helper inayokosekana pekee ni kidokezo tu; kagua schedule, source, na metadata ya path bila kuunda helper au kuanzisha kazi.

Kazi iliyopangwa inaweza pia kugundua input scripts kwa `find` na kupitisha kila moja kwa interpreter. Kwa mfano, [function ya `system()` ya gnuplot huita shell](https://gnuplot.sourceforge.net/docs_6.0/gnuplot.pdf), kwa hiyo kazi yenye privileges inayoendesha `gnuplot` kwa kila faili ya `*.plt` kwenye directory inayoweza kuandikwa na mtumiaji wa privileges za chini inaweza kutekeleza amri chini ya identity ya kazi. [Ruhusa ya directory ya kusoma hudhibiti uorodheshaji, huku write na search (`x`) zikidhibiti kuunda na kufikia majina yanayojulikana](https://www.gnu.org/software/coreutils/manual/html_node/Mode-Structure.html); kagua ruhusa za write na search hata kama `ls` haiwezi kuorodhesha directory. Linganisha identity na amri halisi ya scheduler, tabia ya interpreter, pattern ya faili iliyochaguliwa, na ruhusa za directory; directory inayoweza kuandikwa au interpreter iliyosakinishwa pekee havithibitishi privilege escalation. Schedules za private na kazi za muda mfupi zinaweza kuhitaji uangalizi wa matukio ulioidhinishwa kwa sababu snapshot moja ya process inaweza kuzikosa.

Kwa kazi ya PHP yenye privileges, kagua taarifa halisi za `include`/`require` kama sehemu ya mnyororo wa script inayotekelezwa. [PHP hutathmini faili zilizojumuishwa](https://www.php.net/manual/en/function.include.php), kwa hiyo faili ya `.php` inayoweza kuandikwa na group inaweza kuendesha code chini ya identity ya kazi hata kama script kuu ni read-only. Hakiki identity iliyopangwa, resolution ya include-path inayotumika, ruhusa za faili na directory, na kama kazi inaendeshwa kweli; mfano wa cron line kwenye comment ni kidokezo tu. Ukaguzi huohuo unatumika kwa [PHP built-in server](https://www.php.net/commandline.webserver) inayomilikiwa na root na kuanzishwa kwa `-S` na `-t <document-root>`: listener ya loopback bado inaweza kutekeleza application PHP kwa maombi ya ndani. Kagua process na source bila kuanzisha trigger yoyote wakati wa enumeration.

Kazi ya PHP yenye privileges inaweza pia kuvuka mpaka kupitia **data file**: ikiwa mtumiaji wa privileges za chini anaweza kubadilisha faili halisi inayopitishwa kwa [`unserialize()`](https://www.php.net/manual/en/function.unserialize.php), PHP inaweza kuita method ya `__wakeup()` au `__unserialize()` ya class iliyopakiwa wakati wa kurejesha object. Kagua identity halisi ya kazi, ruhusa za faili na ancestor, classes zilizopakiwa, na madhara halisi ya method, kama vile kuandika faili iliyochaguliwa na property. Log inayoweza kuandikwa au mwito wa `unserialize()` pekee havithibitishi path inayoweza kutumiwa. Kagua source na metadata bila kuandika serialized input au kuendesha kazi wakati wa enumeration.

Kazi ya cron ya root inaweza kuita **CLI page runner** ya application ya PHP badala ya web server. Fuatilia document root na URI iliyochaguliwa na runner hadi PHP entrypoint halisi; ikiwa akaunti ya web-service inaweza kuandika entrypoint hiyo, CLI request iliyopangwa inaweza kuendesha code iliyobadilishwa kama root hata wakati runner na cron wrapper ni read-only. Thibitisha identity ya scheduler, URI-to-file resolution halisi, ruhusa zinazotumika za faili na ancestor, na kama integrity check inalinda entrypoint yenyewe. Kagua source na metadata bila kuita runner au kubadilisha ukurasa wakati wa enumeration.

Mchakato wa `ipython` ulioanzishwa na kazi iliyopangwa au mtumiaji mwingine kutoka shared working directory unahitaji ukaguzi wa startup-file. [Maelezo ya usalama ya IPython](https://ipython.readthedocs.io/en/8.25.0/whatsnew/version8.html#ipython-8-0-1-cve-2022-21699) yanaeleza kuwa build zilizoathirika zilitafuta profiles na configuration kwenye current directory, ikiwemo code ya `profile_default/startup`, kabla ya kurekebishwa kwa CVE-2022-21699. Linganisha build halisi iliyosakinishwa au patch ya vendor, working directory ya amri, identity ya process yenye privileges za juu, na uwezo wa mtumiaji wa privileges za chini kuandika na kutafuta startup path halisi. `ipython` iliyosakinishwa, directory inayoweza kuandikwa, au string ya version pekee havithibitishi kuwa identity nyingine itapakia faili humo. Kagua schedule na metadata ya path bila kuzindua interpreter yenye privileges za juu.

Kwa PHP server yenye privileges inayotumia functions kutoka custom native extension, fuatilia PHP SAPI ya service na `php.ini` pamoja na faili za `.ini` zilizochanganuliwa kabla ya kukagua extension. [PHP hupakia library za `extension` zilizosanidiwa wakati wa startup](https://www.php.net/manual/en/ini.core.php), na [CLI na web SAPI zinaweza kutumia configuration file tofauti](https://www.php.net/manual/en/configuration.file.php). Kwa hiyo, login form inayofikika au listener ya ndani inaweza kupitisha string zinazodhibitiwa na mtumiaji kwenye compiled code inayoendeshwa kwa identity ya service. Rekodi `User=`, `ExecStart=`, working directory, njia halisi ya extension, na arguments zinazodhibitiwa na caller; kuwepo tu kwa `.so` au loopback socket hakuthibitishi memory-corruption flaw. Changanua parser yoyote maalum kando badala ya kutuma probes wakati wa enumeration ya bila mabadiliko.

Wakati wrapper yenye privileges inahesabu hash ya script kwa pathname na baadaye inafungua tena pathname hiyo ili kuitekeleza, digest huthibitisha tu object iliyosomwa wakati wa open ya kwanza. Ikiwa mtumiaji wa privileges za chini anaweza kubadilisha directory entry ya script kati ya open hizo mbili, execution ya baadaye inaweza kupata object tofauti hata kama faili ya awali ya script inamilikiwa na root. FIFO inaweza kurefusha awamu ya ukaguzi, lakini path hiyo inategemea ruhusa za parent-directory zinazoweza kubadilishwa, opens tofauti halisi, identity ya scheduler, sheria za sticky bit na mount, na timing. Kagua wrapper na matokeo ya `namei -l` kama kidokezo cha bila mabadiliko; checksum iliyofaulu peke yake haithibitishi kuwa pathname ya baadaye inalindwa.

Kazi ya backup yenye privileges inaweza pia **kufichua** data bila kutekeleza amri zilizotolewa na mshambuliaji. Fuatilia kama mtumiaji wa privileges za chini anaweza kuunda control file ambayo kazi inasoma, kama kazi kisha inafungua chanzo kilicholindwa kama `/etc/shadow`, na kama URL iliyochaguliwa na mshambuliaji au output inayosomeka inapokea matokeo. Hakiki sehemu zote tatu kabla ya kuiita disclosure path. Amri ya shell isiyobadilika kwenye script hiyohiyo haifanyi control file hiyo kuwa input ya shell-injection yenyewe. Kagua script na ruhusa za faili bila kuendesha kazi au kuweka control file wakati wa enumeration.

Ikiwa kazi iliyopangwa yenye privileges inaendesha `curl -K FILE` au `curl --config FILE`, [curl huchukulia options katika faili hiyo kama command-line arguments](https://curl.se/docs/manpage.html). Mtumiaji wa privileges za chini anayesimamia faili halisi wakati curl inaisoma anaweza kuathiri URL inayoombwa, local-file input, au output path. Thibitisha identity halisi ya kazi, ruhusa za kuandika kwenye faili na ancestor, timing ya kazi nyingine yoyote inayobadilisha faili hiyo, na jinsi config options zinavyoingiliana na command-line options zisizobadilika kabla ya kudai kuwa kuna protected read au write. Config path inayoweza kuandikwa au flag ya `-K` inayoonekana pekee havithibitishi kuwa options zilizochaguliwa zitaanza kutumika; kagua schedule na metadata bila kuendesha kazi au kuomba URL wakati wa enumeration.

Ikiwa cron entry inaita helper script, kagua working directory ya helper na amri yake ya archive pia. Wildcard isiyo na quotes juu ya directory inayoweza kuandikwa na mtumiaji mwingine inaweza kubadilisha filenames kuwa archiver options; checkpoint actions za GNU tar ni mfano mmoja. Thibitisha identity iliyopangwa kutekeleza kazi, input directory inayoweza kuandikwa, archiver na options halisi, na kama `--` inamaliza uchanganuzi wa options kabla ya kudai kuwa kuna command path ya kuvuka akaunti. Tazama [tabia ya wildcard na tar](../interesting-files-permissions/wildcards-spare-tricks.md).

Disclosure tofauti ya backup-file inaweza kutokea helper yenye privileges inapoendesha `cd INPUT_DIR; tar ... *` bila kuangalia kama `cd` ilifaulu. Ikiwa mtumiaji wa privileges za chini anaweza kuondoa au kubadilisha `INPUT_DIR`, `cd` ikishindwa shell inaweza kubaki kwenye directory yake ya awali, ambayo amri ya archive inayofuata inaweza kusoma. Hakiki working directory ya mwanzo ya kazi, njia halisi ya `cd` kushindwa, kama script inatoka au inatumia `&&`, options halisi za archiver, na kama archive ya output inasomeka kwa mtumiaji wa privileges za chini. Input directory inayoweza kuandikwa au archive inayosomeka pekee ni kidokezo tu; kagua helper na ruhusa za path bila kubadilisha kazi inayoendelea.

Executable iliyopangwa inaweza kuficha shell script badala ya kuondoa mpaka wake wa uaminifu: [SHc](https://github.com/neurobin/shc) hufunga maandishi ya script yaliyosimbwa ndani ya native binary na kuyatekeleza kupitia shell wakati wa runtime. Suffix ya `.sh.x` au ELF isiyoeleweka ni kidokezo cha ukaguzi tu. Kutathmini filename option injection, thibitisha identity ya scheduler yenye privileges, working directory na amri halisi ya helper, uwezo wa mtumiaji wa privileges za chini kuunda majina yanayolingana humo, na kama glob isiyo na quotes inafikia amri kama `rsync` bila mpaka wa options. [`rsync` remote-shell option](../interesting-files-permissions/wildcards-spare-tricks.md#rsync) ni muhimu tu ikiwa command path hiyo mahususi inatumika. Uonekano mdogo wa `/proc` au kushindwa kwa static decryption kunaacha amri ikiwa haijulikani; usiendeshe helper yenye privileges kwa lengo tu la kuitambua.

Maandishi ya command line ya process ni input nyingine isiyoaminika kwa helper yenye privileges. Mtumiaji wa privileges za chini anaweza kuchagua process title au `argv[0]` inayolingana na `pgrep -f`; jina linalolingana halithibitishi executable au mmiliki wake. Ikiwa script inayoendeshwa kama root inakamata maandishi hayo, inabadilisha sehemu yake kuwa `apache2ctl`/`httpd`, na kutekeleza matokeo bila fixed argument array, options zilizochaguliwa na mshambuliaji zinaweza kuchagua configuration directory au error log tofauti. Uchanganuzi wa Apache configuration unaweza kupakia modules au kufikia helpers zilizosanidiwa, kwa hiyo usithibitishe configuration isiyoaminika kama root wakati wa enumeration. Kagua mmiliki wa scheduler, helper halisi, identity ya process, na mtiririko wa data hadi argument; hii ni option/configuration injection isipokuwa utekelezaji wa shell metacharacter uonyeshwe tofauti.

Parser inayoendeshwa kama root na kulisha maandishi yasiyoaminika kwenye Bash arithmetic inaweza kutekeleza substitutions katika maandishi hayo. [Mwongozo wa privilege escalation](../linux-basics/linux-privilege-escalation/README.md#bash-arithmetic-expansion-injection-in-cron-log-parsers) una mfano uliofafanuliwa. Thibitisha chanzo cha input na amri ya parsing kabla ya kuchukulia kila arithmetic expression kuwa inaweza kutumiwa.

Kwa kazi yenye privileges inayoparse application log, fuatilia fields zisizoaminika baada ya parse ya kwanza. Akaunti yenye privileges za chini inaweza kuweza kuandika log kupitia process group yake ya sasa au kuathiri request fields zinazorekodiwa; rekodi inaweza kuchagua picha, ambayo metadata yake inakuwa pathname ya pili inayotumika kufungua XML. Kagua identity halisi ya kazi, uwezo halisi wa kuandika log, ushughulikiaji wa delimiter, containment ya canonical path, na kama XML iliyochaguliwa inadhibitiwa na mshambuliaji. Upanuzi wa external entity unaweza kusababisha ufichuzi wa faili zenye privileges ikiwa matokeo yaliyopanuliwa yanafika kwenye output inayosomeka na mtumiaji wa privileges za chini. [Mwongozo wa usalama wa uchakataji wa Java XML](https://docs.oracle.com/en/java/javase/17/security/java-api-xml-processing-jaxp-security-guide.html) unaeleza controls za ufikiaji wa external DTD/entity; kagua parser iliyosakinishwa na settings zake zinazotumika. Log inayoweza kuandikwa au faili ya XML pekee ni kidokezo tu. Kagua code na metadata bila kuingiza data kwenye parser iliyopangwa wakati wa enumeration.

Kagua pia kazi zenye privileges zinazounda faili kutoka kwenye Git repository ya mtumiaji mwingine. Script inaweza kutumia `git ls-tree` na `git cat-file` badala ya `git checkout`, lakini bado ikaamini tree paths zinazodhibitiwa na mshambuliaji inapozijumuisha kwenye staging directory. Absolute paths na vipengele vya `..` vinaweza kutoka nje ya directory hiyo isipokuwa destination iwe normalized na kukaguliwa kwa containment kabla ya kuandika. `git -c safe.directory=*` huruhusu ufikiaji wa repositories zenye umiliki tofauti; yenyewe haisababishi hali ya arbitrary-write.

Backup ya database inayoendeshwa kama root inaweza kuunda mpaka mwingine wa ownership. PostgreSQL [`pg_basebackup`](https://www.postgresql.org/docs/14/app-pgbasebackup.html) hunakili regular files za ziada zilizowekwa kwenye source data directory, na default plain format huandika faili kwenye `-D` kama directory tree. Ikiwa akaunti yenye privileges za chini inaweza kuunda au kubadilisha source files hizo, kagua umiliki na mode ya destination inayotokana, kama path yake inaweza kupitiwa na kutekelezwa, na kama mount ina `nosuid`. Copy inayomilikiwa na root na kuhifadhi ruhusa za set-ID inaweza kuwa hatari; backup ya tar pekee, ruhusa zilizovuliwa, au destination isiyofikika haithibitishi path hiyo hiyo. Fuatilia wrapper iliyopangwa na mtumiaji halisi kabla ya kuchukulia amri ya backup kuwa finding.

## Observe short-lived work

Snapshot moja ya process inaweza kukosa kazi inayochukua milliseconds pekee. Linganisha matamko ya timer/cron na logs na, ukiwa na idhini, ufuatiliaji wa process-event kama `pspy` au audit. Linganisha mmiliki aliyepangwa, command line halisi, na faili ambazo kazi inasoma au kuandika. Web UI ya scheduler inayosikiliza loopback ni interface tofauti; tazama [mfano wa Crontab UI](../linux-basics/linux-privilege-escalation/README.md#crontab-ui-alseambusher-running-as-root--web-based-scheduler-privesc).
