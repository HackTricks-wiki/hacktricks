# Cron Jobs και Systemd Timers

{{#include ../../banners/hacktricks-training.md}}

Οι προγραμματισμένες εργασίες μπορεί να εκτελούνται με διαφορετική ταυτότητα και περιβάλλον από αυτά του τρέχοντος shell. Καταγράψτε τα cron, `at`, anacron και systemd timers και, στη συνέχεια, ακολουθήστε κάθε προγραμματισμένη εντολή στα scripts, τις εισαγωγές, τον κατάλογο εργασίας και τις εγγράψιμες εισόδους της.

## Καταγραφή προγραμματισμένων εργασιών

```bash
crontab -l 2>/dev/null
ls -la /etc/crontab /etc/cron.* /var/spool/cron* 2>/dev/null
atq 2>/dev/null
systemctl list-timers --all 2>/dev/null
```

Τα crontab του συστήματος συνήθως περιλαμβάνουν πεδίο χρήστη· το crontab ενός χρήστη δεν περιλαμβάνει. Ελέγξτε το ενεργό PATH και το περιβάλλον του πραγματικού scheduler. Η εντολή `run-parts --test /etc/cron.daily` εμφανίζει ποια ονόματα αρχείων θα επιλεγούν σε αυτό το host. Οι χαρακτήρες ελέγχου μπορούν να κρύψουν μια εγγραφή σε μια πρόχειρη προβολή, γι’ αυτό χρησιμοποιήστε `cat -A` ή `sed -n l` όταν ένα πρόγραμμα φαίνεται ύποπτο.

## Ανίχνευση επίλυσης προνομιακών αρχείων και εντολών

```bash
systemctl cat <name>.timer <name>.service
systemctl show <name>.service -p User -p ExecStart -p EnvironmentFiles -p WorkingDirectory
namei -l /path/to/scheduled/script
```

Ελέγξτε αλυσίδες scripts με δυνατότητα εγγραφής, διαδρομές `EnvironmentFile=`, drop-ins, symlinks, σχετικές εντολές, επέκταση wildcard και binaries που αντιγράφονται ή εκτελούνται από προνομιούχο task. Ένα timer μπορεί να ενεργοποιήσει service με διαφορετικό όνομα μέσω της ρύθμισης `Unit=`. Οι σελίδες [PATH](../linux-basics/linux-environment-variables.md#path), [wildcard](../interesting-files-permissions/wildcards-spare-tricks.md) και [file-link](../main-system-information/filesystem-links-and-file-descriptors.md) εξηγούν τους βασικούς μηχανισμούς.

Για ένα προγραμματισμένο script `chkrootkit` που εκτελείται ως root, εξετάστε τον εγκατεστημένο πηγαίο κώδικα για το παλιό [σφάλμα quoting στο slapper-loop (CVE-2014-0476)](https://bugzilla.redhat.com/show_bug.cgi?id=CVE-2014-0476): ένα unquoted `file_port=$file_port $i`, μετά από έλεγχο μιας προσωρινής διαδρομής `SLAPPER_FILES`, μπορεί να εκτελέσει αυτό το αρχείο. Επαληθεύστε το πραγματικό script ή το patch του προμηθευτή, τον προγραμματισμό ως root, τη δυνατότητα εγγραφής του ακριβούς προσωρινού path από χαμηλότερο χρήστη, το αν είναι εκτελέσιμο και την πολιτική mount. Μια συμβολοσειρά έκδοσης ή η απλή παρουσία του `chkrootkit` δεν αποδεικνύει ότι υπάρχει αυτή η διαδρομή· μην δημιουργείτε ή εκτελείτε προσωρινό αρχείο κατά την παθητική εξέταση.

Αν ένα root service που ξεκινά από timer εκτελεί `systemctl restart <other>.service`, ακολουθήστε ένα ακόμη άλμα unit: το unit που επανεκκινείται μπορεί να καλέσει shell με script στο οποίο μπορεί να γράψει χρήστης χαμηλότερων προνομίων. Επιβεβαιώστε τα ενεργά `User=`, `DynamicUser=`, `RootDirectory=`/`RootImage=`, τα ακριβή ορίσματα `ExecStart=` και τα δικαιώματα του script και της γονικής διαδρομής του. Ένα script με δυνατότητα εγγραφής είναι απλώς υποψήφια περίπτωση μέχρι να επιβεβαιωθεί ότι το timer και το service που επανεκκινείται είναι ενεργά σε αυτό το περιβάλλον εκτέλεσης· εξετάστε τις ιδιότητες των unit χωρίς να επανεκκινήσετε κανένα από τα δύο service.

Αν ένα job υψηλότερων προνομίων λαμβάνει script μέσω hostname και περνά την απόκριση σε shell, ελέγξτε ποιος ελέγχει την επίλυση αυτού του hostname, καθώς και το απομακρυσμένο script. Ένα αρχείο `/etc/hosts` με δυνατότητα εγγραφής, συμπεριλαμβανομένης πρόσβασης μέσω group ή ACL, μπορεί να ανακατευθύνει ένα όνομα που το job επιλύει τοπικά· μια απόκριση `curl` γίνεται διαδρομή εκτέλεσης μεταξύ χρηστών μόνο όταν η πραγματική προγραμματισμένη εντολή εκτελεί αυτή την απόκριση και το job χρησιμοποιεί την επηρεαζόμενη διαδρομή επίλυσης. Επαληθεύστε την ταυτότητα χρήστη εκτέλεσης του job, το ακριβές URL και το shell pipeline, την ενεργή συμπεριφορά proxy/DNS και τα δικαιώματα αρχείου και γονικού καταλόγου. Ένα αρχείο hosts με δυνατότητα εγγραφής από μόνο του είναι αφορμή για έλεγχο, όχι απόδειξη ότι υπάρχει προνομιούχος καταναλωτής. Εξετάστε το schedule και τα metadata χωρίς να αλλάξετε την αντιστοίχιση ή να λάβετε το script κατά την απογραφή.

Μια προνομιούχα προγραμματισμένη λήψη `wget` αποτελεί ξεχωριστό όριο εγγραφής αρχείου, ακόμη κι αν το περιεχόμενο που λαμβάνεται δεν εκτελείται απευθείας. Το [GNU Wget 1.18 άλλαξε τον προεπιλεγμένο χειρισμό ονόματος αρχείου σε ανακατεύθυνση HTTP-to-FTP για να διορθώσει το CVE-2016-4971](https://lists.gnu.org/archive/html/info-gnu/2016-06/msg00004.html)· οι παλαιότερες επηρεαζόμενες εκδόσεις μπορούσαν να χρησιμοποιήσουν το όνομα αρχείου της ανακατεύθυνσης FTP, ενώ το `--trust-server-names` ζητά ρητά αυτή τη συμπεριφορά. Αν ένα μέρος χαμηλότερης εμπιστοσύνης ελέγχει την απόκριση HTTP και τον πόρο FTP, εξετάστε αν το job ακολουθεί αυτή την ανακατεύθυνση, την πραγματική έκδοση Wget ή το backport του προμηθευτή, τις επιλογές εξόδου, την ταυτότητα χρήστη εκτέλεσης, τον κατάλογο εργασίας και το αν το όνομα προορισμού μπορεί να καταλήξει σε αρχείο εκκίνησης. Το [Wget φορτώνει το `WGETRC` ή το `$HOME/.wgetrc`](https://www.gnu.org/software/wget/manual/html_node/Wgetrc-Location.html), ενώ οι [ρυθμίσεις του μπορούν να επιλέξουν πηγή POST ή διαδρομή εξόδου](https://www.gnu.org/software/wget/manual/html_node/Wgetrc-Commands.html)· για οποιαδήποτε επακόλουθη αποκάλυψη ή εγγραφή απαιτείται ξεχωριστά μια μεταγενέστερη προνομιούχα λήψη. Η πρόσβαση σε χαμηλή θύρα μέσω `authbind` έχει σημασία μόνο αν ο καλών μπορεί πράγματι να εξυπηρετήσει το URL που ζητά το job. Εξετάστε παθητικά τις ρυθμίσεις και τα logs, χωρίς να εξυπηρετήσετε ανακατεύθυνση ή να εκτελέσετε το job. Η [ακατέργαστη πρόσβαση σε block device μέσω του group `disk`](../user-information/interesting-groups-linux-pe/README.md#disk-group) είναι ανεξάρτητη από αυτή τη διαδρομή λήψης μέσω δικτύου.

Ακολουθήστε και τα data files, όχι μόνο τα scripts. Ένα προγραμματισμένο εργαλείο προσομοίωσης ή ενορχήστρωσης μπορεί να διαβάζει αρχείο YAML που ορίζει διεργασίες προς εκκίνηση· αν χρήστης χαμηλότερων προνομίων μπορεί να επεξεργαστεί αυτό το αρχείο και το job το εκτελεί με άλλο account, τα δεδομένα μπορούν να μετατραπούν σε εντολές που εκτελούνται με την ταυτότητα του job. Επαληθεύστε την ακριβή προγραμματισμένη εντολή, τον ενεργό χρήστη, τη διαδρομή του αρχείου, τη σημασιολογία του parser και τα δικαιώματα εγγραφής (συμπεριλαμβανομένων των γονικών καταλόγων), πριν θεωρήσετε ένα YAML με δυνατότητα εγγραφής ως διαδρομή εκτέλεσης. Για παθητική αρχική διαλογή αρκούν η ανάγνωση του schedule και των metadata του αρχείου· μην εκτελείτε το job ή τροποποιείτε την είσοδό του κατά την απογραφή.

Οι ρυθμίσεις SSH client είναι επίσης εκτελέσιμη είσοδος όταν ένα job υψηλότερων προνομίων εκτελεί `ssh -F` με αρχείο που μπορεί να αντικαταστήσει χρήστης χαμηλότερων προνομίων. Το OpenSSH [`ProxyCommand`](https://man.openbsd.org/ssh_config#ProxyCommand) εκτελεί τοπική εντολή μέσω του shell του client, ενώ τα `Host`/`Match` και οι προηγούμενες επιλογές καθορίζουν αν εφαρμόζεται αυτή η οδηγία. Συσχετίστε την ακριβή προγραμματισμένη κλήση SSH, την ταυτότητα χρήστη εκτέλεσης, την επιλεγμένη διαδρομή ρυθμίσεων, τα δικαιώματα εγγραφής καταλόγου και αρχείου και την ενεργή σειρά επιλογών, πριν χαρακτηρίσετε την περίπτωση διαδρομή εκτέλεσης μεταξύ χρηστών. Εξετάστε αυτά τα στοιχεία χωρίς να εκτελέσετε το job ή να φορτώσετε τις μη έμπιστες ρυθμίσεις ως προνομιούχος λογαριασμός.

Ένα προγραμματισμένο `scp` και κατόπιν `ssh` για εκτέλεση του αντιγραμμένου script απαιτεί δεύτερο έλεγχο ορίου εμπιστοσύνης, όταν χρήστης χαμηλότερων προνομίων ελέγχει την υπηρεσία SSH προορισμού. Αν η υπηρεσία μπορεί να προωθήσει τη σύνδεση σε άλλον host, ο προνομιούχος client μπορεί να πιστοποιηθεί σε μη προβλεπόμενο endpoint· το [`StrictHostKeyChecking no`](https://man.openbsd.org/ssh_config#StrictHostKeyChecking) αποδυναμώνει την προστασία από αλλαγή host key, με την επιφύλαξη των υπόλοιπων περιορισμών του OpenSSH και των ενεργών επιλογών ανά host. Προσδιορίστε την ταυτότητα χρήστη εκτέλεσης του job, τον πραγματικό προορισμό και τη μέθοδο πιστοποίησης, την ενεργή ταυτότητα της απομακρυσμένης εντολής και το αν η ίδια διαδρομή προορισμού είναι εγγράψιμη ή υπάρχει ήδη στον ανακατευθυνόμενο host. Για να εκτελεστεί παλιό ή ελεγχόμενο από επιτιθέμενο αρχείο, πρέπει επιπλέον η αντιγραφή να αποτύχει ή να μην εντοπίσει αυτή τη διαδρομή **και** το wrapper να συνεχίσει στην εντολή SSH· τα [`errexit`](https://www.gnu.org/software/bash/manual/html_node/The-Set-Builtin.html) του Bash και ο ρητός χειρισμός status επηρεάζουν αυτή τη ροή. Μια αδύναμη ρύθμιση host key, μια ορατή διεργασία `sshpass` ή ένας προσωρινός κατάλογος με δυνατότητα εγγραφής δεν αποδεικνύουν από μόνα τους αυτή την αλυσίδα. Εξετάστε το schedule, το script, τις ρυθμίσεις SSH και τα metadata αρχείων, χωρίς να ανακατευθύνετε την υπηρεσία ή να ενεργοποιήσετε το job κατά την απογραφή.

Ένας προνομιούχος application scheduler μπορεί να αντλεί τα jobs του από εγγραφές βάσης δεδομένων, αντί από αρχεία με δυνατότητα εγγραφής. Για παράδειγμα, μια εγγραφή root cron που εκτελεί το Laravel [`php artisan schedule:run`](https://laravel.com/docs/9.x/scheduling#running-the-scheduler) μπορεί να φτάσει σε κώδικα εφαρμογής που διαβάζει εγγραφές tasks. Αν ένας λογαριασμός χαμηλότερων προνομίων μπορεί να γράψει εγγραφή που περιέχει τοπικό pathname και το προγραμματισμένο callback καλεί την PHP [`file_get_contents`](https://www.php.net/manual/en/function.file-get-contents.php) ως root και στέλνει το σώμα που επέστρεψε σε webhook που επιλέγεται από την εγγραφή, πρόκειται για διαδρομή αποκάλυψης προνομιούχου αρχείου. Επαληθεύστε την ταυτότητα του cron, το πραγματικό scheduler callback και τη ροή δεδομένων από την εγγραφή προς το path, την εξουσιοδότηση εγγραφής στη βάση δεδομένων, την επικύρωση μετά την ανάγνωση της εγγραφής και τον προορισμό εξερχόμενης κίνησης. Ένα αναγνώσιμο application `.env` είναι μόνο ένδειξη για διαπιστευτήρια· η επικύρωση σε web form ή ένας κωδικός βάσης δεδομένων από μόνα τους δεν αποδεικνύουν δυνατότητα ελέγχου εγγραφών ή αποκάλυψη. Εξετάστε παθητικά το schedule, τον κώδικα και τα δικαιώματα του αρχείου διαπιστευτηρίων, χωρίς να κάνετε query στη βάση δεδομένων ή να προγραμματίσετε task κατά την απογραφή.

Τα event-driven jobs `incron` απαιτούν αντίστοιχο έλεγχο: οι [εγγραφές incrontab](https://manpages.debian.org/testing/incron/incrontab.5.en.html) συσχετίζουν ένα path και event που παρακολουθούνται με εντολή η οποία εκτελείται με την ταυτότητα του κατόχου του table. Ένας χρήστης χαμηλότερων προνομίων μπορεί να επηρεάσει έμμεσα ένα παρακολουθούμενο αρχείο, όταν μια εφαρμογή ακολουθεί link από κατάλογο με δυνατότητα εγγραφής και γράφει κείμενο ελεγχόμενο από επιτιθέμενο στο παρακολουθούμενο target. Επαληθεύστε τον πραγματικό κάτοχο του table, το event, τα δικαιώματα του target και των γονικών καταλόγων, τη συμπεριφορά της εφαρμογής ως προς την ακολούθηση links και τον τρόπο με τον οποίο το κείμενο μετατρέπεται σε ορίσματα εντολής. Ειδικότερα, το [GNU Mailutils `mail` δέχεται `--exec`](https://mailutils.org/manual/html_node/Invoking-Mail.html), ενώ η [εντολή shell-escape](https://mailutils.org/manual/html_node/Shell-Escapes.html) μπορεί να εκτελέσει πρόγραμμα· ένα μη έμπιστο πεδίο που περνά ως ξεχωριστή επιλογή σε αυτή την υλοποίηση μπορεί να οδηγήσει σε εκτέλεση εντολών. Άλλες υλοποιήσεις `mail` ή ένα quoted, σταθερό όριο ορισμάτων μπορεί να συμπεριφέρονται διαφορετικά. Εξετάστε το schedule, τον κώδικα της εφαρμογής και τα metadata του αρχείου, χωρίς να τροποποιήσετε το παρακολουθούμενο αρχείο ή να ενεργοποιήσετε το job κατά την απογραφή.

Ένα παρακολουθούμενο log μπορεί επίσης να περάσει όριο χρηστών μέσω helper script. Αν ένας χρήστης χαμηλότερων προνομίων μπορεί να γράψει στο log και ο κάτοχος του `incron` διαβάζει ένα πεδίο του σε νέο string εντολής [`sh -c`](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/sh.html), το shell αναλύει ξανά αυτό το πεδίο με την ταυτότητα του κατόχου. Ελέγξτε το ακριβές παρακολουθούμενο event, τα δικαιώματα του log και των γονικών καταλόγων, τη διαδρομή του helper, τον μετασχηματισμό του πεδίου του log και το αν εκτελείται τελικά η παραγόμενη εντολή. Η παρατήρηση ενός log με δυνατότητα εγγραφής και μιας εγγραφής `incron` από μόνη της δεν αποδεικνύει τη ροή δεδομένων· μην γράφετε γραμμή ενεργοποίησης ή εκτελείτε τον helper κατά την παθητική απογραφή.

Τα jobs ανανέωσης πιστοποιητικών μπορούν να περάσουν το ίδιο όριο. Ένα προνομιούχο helper μπορεί να διαβάζει subject X.509 από πιστοποιητικό σε κατάλογο με δυνατότητα εγγραφής από χρήστη χαμηλότερων προνομίων και να εισάγει το common name του σε νέο string εντολής `bash -c`. Το [OpenSSL μπορεί να εμφανίσει το subject ενός πιστοποιητικού και να ελέγξει τη λήξη του](https://docs.openssl.org/3.3/man1/openssl-x509/)· το [Bash αναλύει το string `-c` ως είσοδο shell](https://www.gnu.org/software/bash/manual/html_node/Invoking-Bash.html), επομένως το quoting της μεταβλητής στο εξωτερικό script δεν προστατεύει από τη δεύτερη ανάλυση. Επιβεβαιώστε την προγραμματισμένη ταυτότητα, το ακριβές path εισόδου και τα δικαιώματα εγγραφής, τον κλάδο ανανέωσης και τη ροή δεδομένων προς το `bash -c`, πριν χαρακτηρίσετε την περίπτωση ως command injection. Εξετάστε παθητικά το script και τα metadata του πιστοποιητικού· μην ενεργοποιείτε την ανανέωση κατά την απογραφή.

Η ίδια δεύτερη ανάλυση μπορεί να συμβεί όταν ένα προνομιούχο προγραμματισμένο job εξάγει όνομα από archive ή package χρήστη χαμηλότερων προνομίων και το περνά στο `xargs -I` για εισαγωγή σε string εντολής `sh -c`. Το [GNU `xargs -I` αντικαθιστά το placeholder στα αρχικά ορίσματα](https://www.gnu.org/software/findutils/manual/html_node/find_html/xargs-options.html), ενώ το [`sh -c` ερμηνεύει το string εντολής](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/sh.html). Ακόμη κι αν το εξωτερικό script κάνει quote το εξαγόμενο όνομα, αυτό δεν καθιστά ασφαλές ένα μεταγενέστερα αντικατεστημένο shell program. Επαληθεύστε την ταυτότητα χρήστη εκτέλεσης του job, το ακριβές αποδεκτό path εισόδου και τα δικαιώματα εγγραφής, την επικύρωση του archive και τις συνθήκες κλάδου, καθώς και τη ροή δεδομένων από το όνομα στο shell. Ένας κατάλογος uploads με δυνατότητα εγγραφής ή μια κλήση `xargs` από μόνη της είναι απλώς ένδειξη· εξετάστε το schedule, το script και τα metadata path, χωρίς να υποβάλετε package ή να εκτελέσετε το job κατά την απογραφή.

Ένας προγραμματισμένος importer γραμματοσειρών ή εικόνων μπορεί επίσης να εμπιστεύεται ονόματα *μέσα* σε archive που παρέχει ο καλών, ακόμη κι όταν περιορίζεται το εξωτερικό όνομα του upload. Το FontForge διόρθωσε command injection μέσω ονόματος μέλους archive στην [αλλαγή upstream για τα CVE-2024-25081 και CVE-2024-25082](https://github.com/fontforge/fontforge/pull/5367). Επιβεβαιώστε ότι ένα job υψηλότερων προνομίων ανοίγει πράγματι archive από path με δυνατότητα εγγραφής από χρήστη χαμηλότερων προνομίων, την ταυτότητα χρήστη εκτέλεσης, το ακριβές build του FontForge ή το backport του προμηθευτή και τη διαδρομή κώδικα χειρισμού archive. Μια συμβολοσειρά έκδοσης ή ένα επιτρεπόμενο suffix upload από μόνα τους δεν αποδεικνύουν εκτέλεση. Εξετάστε το schedule, τα δικαιώματα path και τα metadata του build, χωρίς να εισαγάγετε μη έμπιστο archive κατά την απογραφή.

Οι προγραμματισμένοι network scanners μπορούν να περάσουν διαφορετικό όριο όταν ένα custom script μεταχειρίζεται το subject απομακρυσμένου TLS certificate ως τοπικό όνομα αρχείου. Το [Nmap NSE εκτελεί τα επιλεγμένα scripts χωρίς sandbox](https://nmap.org/book/nse-usage.html), επομένως εξετάστε το πραγματικό script και το αν συνενώνει μη έμπιστο πεδίο subject με κατάλογο δεδομένων χωρίς ελέγχους περιορισμού διαδρομής. Η αποκάλυψη αρχείου απαιτεί target που θα σαρώσει ο scheduler, path που επιλύεται σε αρχείο αναγνώσιμο από την ταυτότητα χρήστη του scanner και report ή log που παραδίδεται σε χρήστη χαμηλότερων προνομίων. Ένα πεδίο πιστοποιητικού ή ένας εγκατεστημένος scanner από μόνος του δεν αποδεικνύει αυτή την αλυσίδα· εξετάστε το schedule, το script, την επίλυση path και τον προορισμό report, χωρίς να σαρώσετε νέο target κατά την παθητική απογραφή.

Μια προνομιούχα εντολή cron που περνά shell glob, όπως `/path/to/tasks/*.yml`, σε Ansible runner χρειάζεται έλεγχο δικαιωμάτων καταλόγου, ακόμη κι όταν όλα τα υπάρχοντα playbooks είναι μόνο για ανάγνωση. Χρήστης με δικαιώματα εγγραφής και αναζήτησης στον κατάλογο του glob μπορεί να δημιουργήσει άλλο playbook που ταιριάζει. Τα [Ansible playbooks ορίζουν tasks που εκτελεί ο runner](https://docs.ansible.com/projects/ansible/latest/cli/ansible-playbook.html), αλλά ένα custom wrapper μπορεί να φιλτράρει paths ή να χρησιμοποιεί διαφορετική ταυτότητα: επαληθεύστε τη συμπεριφορά του, τον πραγματικό χρήστη cron, την επέκταση shell, τα ACL, το sticky bit και την πολιτική mount, πριν θεωρήσετε τον κατάλογο διαδρομή εκτέλεσης. Εξετάστε στατικά τα metadata και το wrapper· μην εκτελέσετε το προγραμματισμένο job κατά την απογραφή.

Ένα προνομιούχο cron wrapper μπορεί να περνά ονόματα αρχείων από κατάλογο upload σε Perl helper, αφού επεκτείνει ένα glob. Ο τελεστής Perl [`<>` diamond χρησιμοποιεί two-argument `open`](https://perldoc.perl.org/perlop#The-Null-Filehandle), επομένως ένα όνομα αρχείου που ταιριάζει και ερμηνεύεται ως pipe command μπορεί να εκτελεστεί με την ταυτότητα του helper· το [`<<>>` αντιμετωπίζει τα ορίσματα ως κυριολεκτικά ονόματα αρχείων](https://perldoc.perl.org/perlop#The-Null-Filehandle). Επιβεβαιώστε την ταυτότητα του scheduler, τον κατάλογο εργασίας και το glob του wrapper, τον πραγματικό χειρισμό `@ARGV` από τον helper, τους περιορισμούς ονομάτων αρχείων και το αν μια ταυτότητα χαμηλότερων προνομίων μπορεί να τοποθετήσει όνομα που ταιριάζει μέσω δικαιωμάτων filesystem ή εξουσιοδοτημένης υπηρεσίας upload. Μια γραμμή cron, ένα Perl script ή ένας κατάλογος FTP με δυνατότητα εγγραφής από μόνα τους δεν αποδεικνύουν την πλήρη αλυσίδα. Εξετάστε τον κώδικα και τα metadata, χωρίς να υποβάλετε κατασκευασμένο όνομα αρχείου ή να εκτελέσετε το job κατά την απογραφή.

Ένα read-only cron script εξακολουθεί να μπορεί να αντικατασταθεί, αν ο προγραμματισμένος λογαριασμός το εκτελεί μέσω pathname και ο χρήστης χαμηλότερων προνομίων μπορεί να γράψει και να διασχίσει τον μη-sticky γονικό κατάλογό του. Ελέγξτε την ταυτότητα χρήστη εκτέλεσης του schedule, κάθε συστατικό του path, το sticky bit του καταλόγου, τα ACL και την πολιτική mount· εξετάστε τα metadata χωρίς να μετακινήσετε το αρχείο ή να εκτελέσετε το job.

Ένα προνομιούχο PHP cron wrapper μπορεί να φτάσει σε helper που δεν υπάρχει ακόμη. Αν καλεί την PHP [`exec()`](https://www.php.net/manual/en/function.exec.php) με σταθερό απόλυτο path helper, χρήστης χαμηλότερων προνομίων που μπορεί να δημιουργήσει αυτό το όνομα στον γονικό κατάλογο μπορεί να ελέγξει τι θα εκτελεστεί σε επόμενη εκτέλεση. Επιβεβαιώστε ότι η εγγραφή cron εκτελεί πράγματι το wrapper με την υψηλότερη ταυτότητα, το ακριβές string εντολής και την πολιτική εκτέλεσης της PHP, τα δικαιώματα εγγραφής και αναζήτησης στον κατάλογο του helper, τη συμπεριφορά symlink και sticky bit και το αν το path του helper εξακολουθεί να είναι ανύπαρκτο. Ένας κατάλογος με δυνατότητα εγγραφής ή ένας helper που λείπει από μόνος του είναι απλώς ένδειξη· εξετάστε το schedule, τον πηγαίο κώδικα και τα metadata του path χωρίς να δημιουργήσετε τον helper ή να ενεργοποιήσετε το job.

Ένα προγραμματισμένο job μπορεί επίσης να εντοπίζει scripts εισόδου με `find` και να περνά το καθένα σε interpreter. Για παράδειγμα, η συνάρτηση [`system()` του gnuplot καλεί shell](https://gnuplot.sourceforge.net/docs_6.0/gnuplot.pdf), επομένως ένα προνομιούχο job που εκτελεί `gnuplot` σε κάθε αρχείο `*.plt` σε κατάλογο με δυνατότητα εγγραφής από χρήστη χαμηλότερων προνομίων μπορεί να εκτελέσει εντολές με την ταυτότητα του job. Το [δικαίωμα ανάγνωσης καταλόγου ελέγχει την εμφάνιση των περιεχομένων, ενώ τα δικαιώματα εγγραφής και αναζήτησης (`x`) ελέγχουν τη δημιουργία και πρόσβαση σε γνωστά ονόματα](https://www.gnu.org/software/coreutils/manual/html_node/Mode-Structure.html)· ελέγξτε την πρόσβαση εγγραφής και αναζήτησης ακόμη κι όταν το `ls` δεν μπορεί να εμφανίσει τον κατάλογο. Συσχετίστε την ακριβή ταυτότητα και εντολή του scheduler, τη συμπεριφορά του interpreter, το επιλεγμένο pattern αρχείων και τα δικαιώματα καταλόγου· ένας κατάλογος με δυνατότητα εγγραφής ή ένας εγκατεστημένος interpreter από μόνος του δεν αποδεικνύει κλιμάκωση. Ιδιωτικά schedules και jobs μικρής διάρκειας μπορεί να απαιτούν εξουσιοδοτημένη παρατήρηση συμβάντων, επειδή ένα στιγμιότυπο διεργασιών ενδέχεται να μην τα καταγράψει.

Για ένα προνομιούχο PHP job, εξετάστε τις κυριολεκτικές δηλώσεις `include`/`require` ως μέρος της αλυσίδας εκτελέσιμων scripts. Η [PHP αξιολογεί τα αρχεία που περιλαμβάνονται](https://www.php.net/manual/en/function.include.php), επομένως ένα `.php` με δυνατότητα εγγραφής από group μπορεί να εκτελέσει κώδικα με την ταυτότητα του job, ακόμη κι όταν το κύριο script είναι read-only. Επαληθεύστε την προγραμματισμένη ταυτότητα, την ενεργή επίλυση του include path, τα δικαιώματα αρχείων και καταλόγων και το αν το job εκτελείται πράγματι· ένα δείγμα γραμμής cron σε σχόλιο είναι μόνο ένδειξη. Ο ίδιος έλεγχος ισχύει για έναν root-owned [ενσωματωμένο server PHP](https://www.php.net/commandline.webserver) που ξεκινά με `-S` και `-t <document-root>`: ακόμη και ένας listener loopback μπορεί να εκτελεί PHP της εφαρμογής για τοπικά requests. Εξετάστε τη διεργασία και τον πηγαίο κώδικα χωρίς να ενεργοποιήσετε κανένα trigger κατά την απογραφή.

Ένα προνομιούχο PHP job μπορεί επίσης να περάσει το όριο μέσω **data file**: αν χρήστης χαμηλότερων προνομίων μπορεί να αλλάξει το ακριβές αρχείο που δίνεται στην [`unserialize()`](https://www.php.net/manual/en/function.unserialize.php), η PHP μπορεί να καλέσει τη μέθοδο `__wakeup()` ή `__unserialize()` μιας φορτωμένης κλάσης κατά την επαναφορά αντικειμένου. Εξετάστε την ενεργή ταυτότητα του job, τα δικαιώματα του αρχείου και των γονικών καταλόγων, τις φορτωμένες κλάσεις και τις πραγματικές παρενέργειες των μεθόδων, όπως εγγραφή αρχείου που επιλέγεται από property. Ένα log με δυνατότητα εγγραφής ή μια κλήση `unserialize()` από μόνη της δεν αποδεικνύει αξιοποιήσιμη διαδρομή. Εξετάστε τον κώδικα και τα metadata χωρίς να γράψετε serialized είσοδο ή να εκτελέσετε το job κατά την απογραφή.

Μια root cron εργασία μπορεί να καλεί **CLI page runner** μιας PHP εφαρμογής αντί για τον web server. Ακολουθήστε το επιλεγμένο document root και URI του runner μέχρι το πραγματικό PHP entrypoint· αν ο λογαριασμός της υπηρεσίας web μπορεί να γράψει σε αυτό το entrypoint, το προγραμματισμένο CLI request μπορεί να εκτελέσει τον τροποποιημένο κώδικα ως root, ακόμη κι όταν ο runner και το cron wrapper είναι read-only. Επιβεβαιώστε την ταυτότητα του scheduler, την ακριβή επίλυση URI προς αρχείο, τα ενεργά δικαιώματα αρχείου και γονικών καταλόγων και το αν έλεγχος ακεραιότητας προστατεύει το ίδιο το entrypoint. Εξετάστε τον κώδικα και τα metadata χωρίς να καλέσετε τον runner ή να αλλάξετε τη σελίδα κατά την απογραφή.

Μια διεργασία `ipython` που ξεκινά από προγραμματισμένο job ή άλλον χρήστη σε κοινόχρηστο κατάλογο εργασίας χρειάζεται έλεγχο αρχείων εκκίνησης. Οι [σημειώσεις έκδοσης ασφαλείας του IPython](https://ipython.readthedocs.io/en/8.25.0/whatsnew/version8.html#ipython-8-0-1-cve-2022-21699) εξηγούν ότι οι επηρεαζόμενες εκδόσεις αναζητούσαν profiles και ρυθμίσεις στον τρέχοντα κατάλογο, συμπεριλαμβανομένου κώδικα στο `profile_default/startup`, πριν από τη διόρθωση του CVE-2022-21699. Συσχετίστε την πραγματικά εγκατεστημένη έκδοση ή το patch του προμηθευτή, τον κατάλογο εργασίας της εντολής, την ταυτότητα της διεργασίας υψηλότερων προνομίων και τη δυνατότητα χρήστη χαμηλότερων προνομίων να γράψει και να αναζητήσει το ακριβές path εκκίνησης. Ένα εγκατεστημένο `ipython`, ένας κατάλογος με δυνατότητα εγγραφής ή μια συμβολοσειρά έκδοσης από μόνα τους δεν αποδεικνύουν ότι άλλη ταυτότητα θα φορτώσει αρχείο από εκεί. Εξετάστε το schedule και τα metadata του path χωρίς να εκκινήσετε τον interpreter με υψηλότερα προνόμια.

Για έναν προνομιούχο PHP server που καλεί συναρτήσεις από custom native extension, εντοπίστε το PHP SAPI της υπηρεσίας και το ενεργό `php.ini` μαζί με τα σαρωμένα αρχεία `.ini`, πριν εξετάσετε το extension. Η [PHP φορτώνει τις ρυθμισμένες βιβλιοθήκες `extension` κατά την εκκίνηση](https://www.php.net/manual/en/ini.core.php), ενώ τα [CLI και web SAPI μπορούν να χρησιμοποιούν διαφορετικά αρχεία ρυθμίσεων](https://www.php.net/manual/en/configuration.file.php). Έτσι, μια προσβάσιμη φόρμα login ή ένας τοπικός listener μπορεί να περνά strings ελεγχόμενα από χρήστη σε compiled code που εκτελείται με την ταυτότητα της υπηρεσίας. Καταγράψτε το `User=`, το `ExecStart=`, τον κατάλογο εργασίας, το πραγματικό path του extension και τα ορίσματα που ελέγχει ο καλών· η απλή παρουσία ενός `.so` ή ενός socket loopback δεν αποδεικνύει memory-corruption flaw. Αναλύστε ξεχωριστά οποιονδήποτε custom parser, αντί να στέλνετε probes κατά την παθητική απογραφή.

Όταν ένα προνομιούχο wrapper υπολογίζει hash ενός script μέσω pathname και αργότερα ανοίγει ξανά το ίδιο pathname για να το εκτελέσει, το digest πιστοποιεί μόνο το αντικείμενο που διαβάστηκε στο πρώτο άνοιγμα. Αν χρήστης χαμηλότερων προνομίων μπορεί να αντικαταστήσει την εγγραφή καταλόγου του script ανάμεσα στα δύο ανοίγματα, η μεταγενέστερη εκτέλεση μπορεί να επιλύσει διαφορετικό αντικείμενο, ακόμη κι όταν το αρχικό αρχείο script ανήκει στον root. Ένα FIFO μπορεί να παρατείνει τη φάση ελέγχου, αλλά η διαδρομή εξαρτάται από δικαιώματα γονικού καταλόγου που επιτρέπουν αντικατάσταση, από το αν γίνονται πράγματι ξεχωριστά ανοίγματα, την ταυτότητα του scheduler, τους κανόνες sticky-bit και mount και τον χρονισμό. Εξετάστε το wrapper και την έξοδο `namei -l` ως παθητική ένδειξη· ένας επιτυχής έλεγχος checksum δεν αποδεικνύει από μόνος του ότι προστατεύεται το μεταγενέστερο pathname.

Ένα προνομιούχο backup job μπορεί επίσης να **αποκαλύψει** δεδομένα χωρίς να εκτελέσει εντολές που παρέχει ο επιτιθέμενος. Εντοπίστε αν χρήστης χαμηλότερων προνομίων μπορεί να δημιουργήσει control file που διαβάζει το job, αν το job ανοίγει στη συνέχεια προστατευμένη πηγή όπως το `/etc/shadow` και αν URL που επιλέγει ο επιτιθέμενος ή αναγνώσιμη έξοδος λαμβάνει το αποτέλεσμα. Επαληθεύστε και τα τρία μέρη πριν το χαρακτηρίσετε διαδρομή αποκάλυψης. Μια σταθερή εντολή shell στο ίδιο script δεν καθιστά από μόνη της αυτό το control file είσοδο shell injection. Εξετάστε το script και τα δικαιώματα αρχείων χωρίς να εκτελέσετε το job ή να τοποθετήσετε control file κατά την απογραφή.

Αν ένα προνομιούχο προγραμματισμένο job εκτελεί `curl -K FILE` ή `curl --config FILE`, το [curl αντιμετωπίζει τις επιλογές αυτού του αρχείου ως ορίσματα γραμμής εντολών](https://curl.se/docs/manpage.html). Χρήστης χαμηλότερων προνομίων που ελέγχει το ακριβές αρχείο όταν το διαβάζει το curl μπορεί να επηρεάσει το ζητούμενο URL, την είσοδο τοπικού αρχείου ή τη διαδρομή εξόδου. Επιβεβαιώστε την ενεργή ταυτότητα του job, τα δικαιώματα εγγραφής στο αρχείο και στους γονικούς καταλόγους, τον χρονισμό οποιουδήποτε άλλου job που αντικαθιστά το αρχείο και τον τρόπο αλληλεπίδρασης των επιλογών ρυθμίσεων με τις σταθερές επιλογές γραμμής εντολών, πριν ισχυριστείτε ότι υπάρχει προστατευμένη ανάγνωση ή εγγραφή. Ένα path ρυθμίσεων με δυνατότητα εγγραφής ή μια ορατή σημαία `-K` από μόνα τους δεν αποδεικνύουν ότι θα εφαρμοστούν οι επιλεγμένες επιλογές· εξετάστε το schedule και τα metadata χωρίς να εκτελέσετε το job ή να λάβετε URL κατά την παθητική απογραφή.

Αν μια εγγραφή cron καλεί helper script, εξετάστε επίσης τον κατάλογο εργασίας του helper και την εντολή archive. Ένα unquoted wildcard σε κατάλογο με δυνατότητα εγγραφής από άλλον χρήστη μπορεί να μετατρέψει ονόματα αρχείων σε επιλογές archiver· οι ενέργειες checkpoint του GNU tar είναι ένα παράδειγμα. Επιβεβαιώστε την ταυτότητα χρήστη εκτέλεσης του schedule, τον κατάλογο εισόδου με δυνατότητα εγγραφής, το ακριβές archiver και τις επιλογές του, καθώς και το αν το `--` τερματίζει την ανάλυση επιλογών, πριν ισχυριστείτε ότι υπάρχει διαδρομή εντολών μεταξύ χρηστών. Δείτε τη σελίδα [συμπεριφοράς wildcard και tar](../interesting-files-permissions/wildcards-spare-tricks.md).

Μια ξεχωριστή αποκάλυψη από backup file μπορεί να προκύψει όταν προνομιούχος helper εκτελεί `cd INPUT_DIR; tar ... *` χωρίς να ελέγχει αν πέτυχε το `cd`. Αν χρήστης χαμηλότερων προνομίων μπορεί να αφαιρέσει ή να αντικαταστήσει το `INPUT_DIR`, ένα αποτυχημένο `cd` μπορεί να αφήσει το shell στον προηγούμενο κατάλογο, τον οποίο ενδέχεται να διαβάσει στη συνέχεια η εντολή archive. Επαληθεύστε τον αρχικό κατάλογο εργασίας του job, μια πραγματική περίπτωση αποτυχίας `cd`, το αν το script τερματίζει ή χρησιμοποιεί `&&`, τις ακριβείς επιλογές archiver και το αν ο χαμηλότερος χρήστης μπορεί να διαβάσει το αρχείο archive εξόδου. Ένας κατάλογος εισόδου με δυνατότητα εγγραφής ή ένα αναγνώσιμο archive από μόνο του είναι απλώς ένδειξη· εξετάστε τον helper και τα δικαιώματα path χωρίς να τροποποιήσετε το ενεργό job.

Ένα προγραμματισμένο εκτελέσιμο μπορεί να αποκρύπτει shell script αντί να παρακάμπτει το όριο εμπιστοσύνης: το [SHc](https://github.com/neurobin/shc) τυλίγει κρυπτογραφημένο κείμενο script σε native binary και το εκτελεί μέσω shell κατά την εκτέλεση. Ένα suffix `.sh.x` ή ένα αδιαφανές ELF είναι απλώς ένδειξη προς εξέταση. Για να εκτιμήσετε option injection μέσω ονόματος αρχείου, εξακριβώστε την ταυτότητα του προνομιούχου scheduler, τον πραγματικό κατάλογο εργασίας και την εντολή του helper, τη δυνατότητα χρήστη χαμηλότερων προνομίων να δημιουργήσει ονόματα που ταιριάζουν εκεί και το αν ένα unquoted glob φτάνει σε εντολή όπως το `rsync` χωρίς όριο επιλογών. Η επιλογή [`rsync` remote-shell](../interesting-files-permissions/wildcards-spare-tricks.md#rsync) έχει σημασία μόνο αν χρησιμοποιείται αυτή η ακριβής διαδρομή εντολής. Η περιορισμένη ορατότητα του `/proc` ή αποτυχημένη στατική αποκρυπτογράφηση αφήνει άγνωστη την εντολή· μην εκτελείτε τον προνομιούχο helper απλώς για να τον ταξινομήσετε.

Το κείμενο της γραμμής εντολών διεργασίας είναι μια ακόμη μη έμπιστη είσοδος για προνομιούχο helper. Χρήστης χαμηλότερων προνομίων μπορεί να επιλέξει τίτλο διεργασίας ή `argv[0]` που ταιριάζει με `pgrep -f`· ένα όνομα που ταιριάζει δεν πιστοποιεί το εκτελέσιμο ή τον κάτοχό του. Αν script που εκτελείται ως root συλλέγει αυτό το κείμενο, ξαναγράφει μέρος του σε `apache2ctl`/`httpd` και εκτελεί το αποτέλεσμα χωρίς σταθερό array ορισμάτων, επιλογές που επιλέγει ο επιτιθέμενος μπορεί να επιλέξουν διαφορετικό κατάλογο ρυθμίσεων ή error log. Η ανάλυση ρυθμίσεων Apache μπορεί να φορτώσει modules ή να φτάσει σε ρυθμισμένους helpers, επομένως μην επικυρώνετε μη έμπιστες ρυθμίσεις ως root κατά την απογραφή. Εξετάστε τον κάτοχο του scheduler, τον ακριβή helper, την ταυτότητα της διεργασίας και τη ροή δεδομένων προς τα ορίσματα· πρόκειται για option/configuration injection, εκτός αν αποδειχθεί ξεχωριστά εκτέλεση shell metacharacters.

Ένας parser που εκτελείται ως root και περνά μη έμπιστο κείμενο σε αριθμητική Bash μπορεί να εκτελέσει substitutions μέσα σε αυτό το κείμενο. Ο [οδηγός privilege escalation](../linux-basics/linux-privilege-escalation/README.md#bash-arithmetic-expansion-injection-in-cron-log-parsers) δίνει αναλυτικό παράδειγμα. Επιβεβαιώστε την πηγή εισόδου και την εντολή parsing πριν θεωρήσετε εκμεταλλεύσιμη κάθε αριθμητική έκφραση.

Για ένα προνομιούχο job που αναλύει log εφαρμογής, ακολουθήστε τα μη έμπιστα πεδία πέρα από την πρώτη ανάλυση. Ένας χρήστης χαμηλότερων προνομίων μπορεί να έχει τη δυνατότητα εγγραφής στο log μέσω του τρέχοντος process group του ή να επηρεάζει πεδία καταγεγραμμένων requests· μια εγγραφή μπορεί στη συνέχεια να επιλέξει εικόνα, τα metadata της οποίας γίνονται δεύτερο pathname για άνοιγμα XML. Ελέγξτε την ενεργή ταυτότητα του job, την πραγματική πρόσβαση εγγραφής στο log, τον χειρισμό delimiter, τον περιορισμό canonical path και το αν το επιλεγμένο XML ελέγχεται από τον επιτιθέμενο. Η επέκταση external entity μπορεί να μετατρέψει αυτή τη δεύτερη ανάγνωση σε αποκάλυψη προνομιούχου αρχείου, αν το αποτέλεσμα της επέκτασης φτάσει σε έξοδο αναγνώσιμη από χρήστη χαμηλότερων προνομίων. Ο [οδηγός ασφαλείας επεξεργασίας Java XML](https://docs.oracle.com/en/java/javase/17/security/java-api-xml-processing-jaxp-security-guide.html) περιγράφει ελέγχους για πρόσβαση σε external DTD/entity· εξετάστε τον εγκατεστημένο parser και τις ενεργές ρυθμίσεις του. Ένα log ή XML αρχείο με δυνατότητα εγγραφής από μόνο του είναι απλώς ένδειξη. Εξετάστε τον κώδικα και τα metadata χωρίς να τροφοδοτήσετε τον προγραμματισμένο parser κατά την απογραφή.

Εξετάστε επίσης προνομιούχα jobs που δημιουργούν αρχεία από Git repository άλλου χρήστη. Ένα script μπορεί να χρησιμοποιεί `git ls-tree` και `git cat-file` αντί για `git checkout`, αλλά και πάλι να εμπιστεύεται διαδρομές tree που ελέγχονται από επιτιθέμενο όταν τις συνενώνει με staging directory. Απόλυτες διαδρομές και στοιχεία `..` μπορούν να διαφύγουν από αυτόν τον κατάλογο, εκτός αν ο προορισμός κανονικοποιηθεί και ελεγχθεί ότι παραμένει εντός του πριν από την εγγραφή. Το `git -c safe.directory=*` επιτρέπει πρόσβαση σε repositories με διαφορετικό ιδιοκτήτη· από μόνο του δεν δημιουργεί συνθήκη arbitrary-write.

Ένα database backup που εκτελείται ως root μπορεί να δημιουργήσει άλλο όριο ιδιοκτησίας. Το PostgreSQL [`pg_basebackup`](https://www.postgresql.org/docs/14/app-pgbasebackup.html) αντιγράφει επιπλέον regular files που τοποθετούνται στον source data directory, ενώ η προεπιλεγμένη plain format του γράφει αρχεία στο `-D` ως δέντρο καταλόγων. Αν λογαριασμός χαμηλότερων προνομίων μπορεί να δημιουργήσει ή να τροποποιήσει αυτά τα source files, εξετάστε την ιδιοκτησία και τα mode του προορισμού, το αν το path είναι προσβάσιμο και εκτελέσιμο και το αν το mount έχει `nosuid`. Ένα αντίγραφο με ιδιοκτήτη root και διατηρημένα set-ID permissions μπορεί να είναι επικίνδυνο· ένα backup μόνο tar, αφαιρεμένα permissions ή μη προσβάσιμος προορισμός δεν θεμελιώνουν την ίδια διαδρομή. Ακολουθήστε το προγραμματισμένο wrapper και τον ενεργό χρήστη πριν θεωρήσετε την εντολή backup εύρημα.

## Observe short-lived work

Ένα στιγμιότυπο διεργασιών μπορεί να παραλείψει job που εκτελείται για χιλιοστά του δευτερολέπτου. Συγκρίνετε τις δηλώσεις timer/cron με τα logs και, όταν υπάρχει εξουσιοδότηση, με παρακολούθηση συμβάντων διεργασιών όπως `pspy` ή audit. Συσχετίστε τον προγραμματισμένο κάτοχο, την ακριβή γραμμή εντολής και τα αρχεία που διαβάζει ή γράφει το task. Ένα loopback web UI scheduler είναι ξεχωριστή διεπαφή· δείτε το [παράδειγμα Crontab UI](../linux-basics/linux-privilege-escalation/README.md#crontab-ui-alseambusher-running-as-root--web-based-scheduler-privesc).
