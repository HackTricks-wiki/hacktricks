# Cron Jobs και Systemd Timers

{{#include ../../banners/hacktricks-training.md}}

Οι προγραμματισμένες εργασίες μπορούν να εκτελούνται με διαφορετική ταυτότητα και περιβάλλον από το τρέχον shell. Καταγράψτε τα cron, `at`, anacron και systemd timers και, στη συνέχεια, εντοπίστε για κάθε προγραμματισμένη εντολή τα scripts, τα imports, τον κατάλογο εργασίας και τις εγγράψιμες εισόδους της.

## Καταγραφή προγραμματισμένων εργασιών

```bash
crontab -l 2>/dev/null
ls -la /etc/crontab /etc/cron.* /var/spool/cron* 2>/dev/null
atq 2>/dev/null
systemctl list-timers --all 2>/dev/null
```

Τα system crontab συνήθως περιλαμβάνουν πεδίο χρήστη· το crontab ενός χρήστη όχι. Ελέγξτε το ενεργό PATH και το περιβάλλον του πραγματικού scheduler. Η εντολή `run-parts --test /etc/cron.daily` δείχνει ποια ονόματα αρχείων θα επιλέγονταν σε αυτό το σύστημα. Οι χαρακτήρες ελέγχου μπορούν να κρύψουν μια εγγραφή σε πρόχειρη έξοδο, γι’ αυτό χρησιμοποιήστε `cat -A` ή `sed -n l` όταν ένα χρονοδιάγραμμα φαίνεται ύποπτο.

## Ανιχνεύστε την επίλυση προνομιακών αρχείων και εντολών

```bash
systemctl cat <name>.timer <name>.service
systemctl show <name>.service -p User -p ExecStart -p EnvironmentFiles -p WorkingDirectory
namei -l /path/to/scheduled/script
```

Ελέγξτε αλυσίδες script με δυνατότητα εγγραφής, διαδρομές `EnvironmentFile=`, drop-ins, symlinks, σχετικές εντολές, επέκταση wildcard και binaries που αντιγράφονται ή εκτελούνται από privileged task. Ένα timer μπορεί να ενεργοποιεί service με διαφορετικό όνομα μέσω της ρύθμισης `Unit=`. Οι σελίδες [PATH](../linux-basics/linux-environment-variables.md#path), [wildcard](../interesting-files-permissions/wildcards-spare-tricks.md) και [file-link](../main-system-information/filesystem-links-and-file-descriptors.md) εξηγούν τα βασικά primitives.

Για ένα προγραμματισμένο script `chkrootkit` που εκτελείται ως root, ελέγξτε τον εγκατεστημένο κώδικα για το παλιό [σφάλμα παράθεσης slapper-loop (CVE-2014-0476)](https://bugzilla.redhat.com/show_bug.cgi?id=CVE-2014-0476): μια μη παραθεμένη εντολή `file_port=$file_port $i` μετά από έλεγχο προσωρινού path `SLAPPER_FILES` μπορεί να εκτελέσει αυτό το αρχείο. Επαληθεύστε το πραγματικό script ή το vendor patch, τον προγραμματισμό ως root, την πρόσβαση εγγραφής χαμηλότερου χρήστη στο ακριβές προσωρινό path, την εκτελέσιμη κατάστασή του και την πολιτική mount. Ένα version string ή μόνο η παρουσία του `chkrootkit` δεν αποδεικνύει ότι υπάρχει αυτό το path· μην δημιουργείτε και μην εκτελείτε προσωρινό αρχείο κατά τον παθητικό έλεγχο.

Ακολουθήστε ακόμη ένα unit hop όταν το root service ενός timer εκτελεί `systemctl restart <other>.service`: το unit που επανεκκινείται μπορεί να καλέσει shell με script στο οποίο μπορεί να γράψει χρήστης χαμηλότερων προνομίων. Επιβεβαιώστε τα ενεργά `User=`, `DynamicUser=`, `RootDirectory=`/`RootImage=`, τα ακριβή ορίσματα `ExecStart=` και τα δικαιώματα του script και του parent path. Ένα script με δυνατότητα εγγραφής είναι απλώς υποψήφιο μέχρι να επιβεβαιωθεί ότι το timer και το service που επανεκκινείται είναι ενεργά στο συγκεκριμένο πλαίσιο εκτέλεσης· ελέγξτε τις ιδιότητες των unit χωρίς να επανεκκινήσετε κανένα από τα δύο service.

Αν ένα job με υψηλότερα προνόμια ανακτά script με hostname και περνά την απόκριση σε shell, ελέγξτε ποιος ελέγχει την επίλυση αυτού του hostname, καθώς και το remote script. Ένα αρχείο `/etc/hosts` με δυνατότητα εγγραφής, συμπεριλαμβανομένης πρόσβασης μέσω group ή ACL, μπορεί να ανακατευθύνει όνομα που το job επιλύει τοπικά· μια απόκριση `curl` γίνεται path εκτέλεσης μεταξύ χρηστών μόνο αν η πραγματική προγραμματισμένη εντολή εκτελεί αυτή την απόκριση και το job χρησιμοποιεί την επηρεαζόμενη διαδρομή resolver. Επαληθεύστε την ταυτότητα εκτέλεσης του job, το ακριβές URL και shell pipeline, την πραγματική συμπεριφορά proxy/DNS και τα δικαιώματα αρχείου και parent directory. Ένα αρχείο hosts με δυνατότητα εγγραφής από μόνο του είναι ένδειξη για έλεγχο, όχι απόδειξη ότι υπάρχει privileged consumer. Ελέγξτε τον προγραμματισμό και τα metadata χωρίς να αλλάξετε την αντιστοίχιση ή να ανακτήσετε το script κατά την enumeration.

Μια προγραμματισμένη ανάκτηση `wget` με προνόμια αποτελεί ξεχωριστό όριο εγγραφής αρχείου, ακόμη κι αν το σώμα που κατεβαίνει δεν εκτελείται απευθείας. Το [GNU Wget 1.18 άλλαξε τον προεπιλεγμένο χειρισμό ονόματος αρχείου για HTTP-to-FTP redirect, διορθώνοντας το CVE-2016-4971](https://lists.gnu.org/archive/html/info-gnu/2016-06/msg00004.html)· παλαιότερα ευάλωτα builds μπορούσαν να χρησιμοποιήσουν το όνομα αρχείου του redirect FTP, ενώ το `--trust-server-names` ζητά ρητά αυτή τη συμπεριφορά. Αν ένα άτομο χαμηλότερης εμπιστοσύνης ελέγχει την HTTP απόκριση και τον FTP πόρο, ελέγξτε αν το job ακολουθεί αυτό το redirect, το πραγματικό build του Wget ή το vendor backport, τις επιλογές εξόδου, την ταυτότητα εκτέλεσης, τον working directory και αν το όνομα αρχείου προορισμού μπορεί να γίνει αρχείο εκκίνησης. Το [Wget φορτώνει `WGETRC` ή `$HOME/.wgetrc`](https://www.gnu.org/software/wget/manual/html_node/Wgetrc-Location.html), ενώ [οι ρυθμίσεις του μπορούν να επιλέξουν πηγή POST ή διαδρομή εξόδου](https://www.gnu.org/software/wget/manual/html_node/Wgetrc-Commands.html)· μια μεταγενέστερη privileged ανάκτηση αποτελεί ξεχωριστή προϋπόθεση για τυχόν αποκάλυψη ή εγγραφή. Η πρόσβαση σε χαμηλή θύρα μέσω `authbind` έχει σημασία μόνο αν ο καλών μπορεί πράγματι να εξυπηρετήσει το URL που ζητά το job. Ελέγξτε παθητικά τη ρύθμιση και τα logs, χωρίς να εξυπηρετήσετε redirect ή να εκτελέσετε το job. Η [πρόσβαση raw block-device μέσω του group `disk`](../user-information/interesting-groups-linux-pe/README.md#disk-group) είναι ανεξάρτητη από αυτή τη διαδρομή network-fetch.

Ακολουθήστε και τα data files, όχι μόνο τα scripts. Ένα προγραμματισμένο εργαλείο προσομοίωσης ή orchestration μπορεί να διαβάζει YAML που ορίζει διεργασίες προς εκκίνηση· αν χρήστης χαμηλότερων προνομίων μπορεί να τροποποιήσει αυτό το αρχείο και το job το εκτελεί με άλλο account, τα δεδομένα μπορούν να μετατραπούν σε εντολές με την ταυτότητα του job. Επαληθεύστε την ακριβή προγραμματισμένη εντολή, τον ενεργό χρήστη, το file path, τη σημασιολογία του parser και την πρόσβαση εγγραφής (και στους parent directories), προτού θεωρήσετε ένα YAML με δυνατότητα εγγραφής path εκτέλεσης. Για παθητική αρχική αξιολόγηση αρκεί η ανάγνωση του προγραμματισμού και των metadata του αρχείου· μην εκτελέσετε το job και μην τροποποιήσετε την είσοδό του κατά την enumeration.

Η ρύθμιση SSH client αποτελεί επίσης εκτελέσιμη είσοδο όταν job με υψηλότερα προνόμια εκτελεί `ssh -F` με αρχείο που μπορεί να αντικαταστήσει χρήστης χαμηλότερων προνομίων. Το [`ProxyCommand` του OpenSSH](https://man.openbsd.org/ssh_config#ProxyCommand) εκτελεί τοπική εντολή μέσω του shell του client, ενώ τα `Host`/`Match` και οι προηγούμενες επιλογές καθορίζουν αν ισχύει αυτή η οδηγία. Συσχετίστε την ακριβή προγραμματισμένη κλήση SSH, την ταυτότητα εκτέλεσης, το επιλεγμένο config path, τα δικαιώματα εγγραφής του directory και του αρχείου, καθώς και την πραγματική σειρά εφαρμογής των επιλογών, προτού το χαρακτηρίσετε path εκτέλεσης μεταξύ χρηστών. Ελέγξτε αυτά τα στοιχεία χωρίς να εκτελέσετε το job ή να φορτώσετε τη μη έμπιστη ρύθμιση ως privileged account.

Ένα προγραμματισμένο `scp` και στη συνέχεια `ssh` για εκτέλεση του αντιγραμμένου script χρειάζεται δεύτερο έλεγχο ορίου εμπιστοσύνης όταν χρήστης χαμηλότερων προνομίων ελέγχει την υπηρεσία SSH προορισμού. Αν η υπηρεσία μπορεί να προωθήσει τη σύνδεση σε άλλο host, ο privileged client ενδέχεται να αυθεντικοποιηθεί σε ακούσιο endpoint· το [`StrictHostKeyChecking no`](https://man.openbsd.org/ssh_config#StrictHostKeyChecking) αποδυναμώνει την προστασία από αλλαγή host key, με την επιφύλαξη των υπόλοιπων περιορισμών του OpenSSH και των ενεργών επιλογών ανά host. Εξακριβώστε την ταυτότητα εκτέλεσης του job, τον πραγματικό προορισμό και τη μέθοδο αυθεντικοποίησης, την πραγματική ταυτότητα εκτέλεσης της remote command και αν το ίδιο destination path είναι εγγράψιμο ή υπάρχει ήδη στον host στον οποίο γίνεται η ανακατεύθυνση. Η εκτέλεση παλιότερου ή attacker-controlled αρχείου απαιτεί επιπλέον να αποτύχει ή να παραλείψει αυτό το path η αντιγραφή **και** να συνεχίσει το wrapper στην εντολή SSH· τα [Bash `errexit`](https://www.gnu.org/software/bash/manual/html_node/The-Set-Builtin.html) και ο ρητός χειρισμός status επηρεάζουν αυτή τη ροή. Μια αδύναμη ρύθμιση host-key, μια ορατή διεργασία `sshpass` ή ένας προσωρινός κατάλογος με δυνατότητα εγγραφής δεν αποδεικνύουν από μόνα τους αυτή την αλυσίδα. Ελέγξτε τον προγραμματισμό, το script, τη ρύθμιση SSH και τα metadata των αρχείων, χωρίς να ανακατευθύνετε την υπηρεσία ή να ενεργοποιήσετε το job κατά την enumeration.

Ένας privileged application scheduler μπορεί να παίρνει τα jobs του από γραμμές βάσης δεδομένων αντί για εγγράψιμα αρχεία. Για παράδειγμα, μια εγγραφή root cron που καλεί το Laravel [`php artisan schedule:run`](https://laravel.com/docs/9.x/scheduling#running-the-scheduler) μπορεί να φτάσει σε κώδικα εφαρμογής που διαβάζει γραμμές εργασιών. Αν account χαμηλότερων προνομίων μπορεί να γράψει γραμμή με τοπικό pathname και το προγραμματισμένο callback καλεί την PHP [`file_get_contents`](https://www.php.net/manual/en/function.file-get-contents.php) ως root και στέλνει το σώμα που επιστρέφεται σε webhook που επιλέγεται από τη γραμμή, τότε υπάρχει path αποκάλυψης αρχείων με προνόμια. Επαληθεύστε την ταυτότητα του cron, το πραγματικό scheduler callback και τη ροή δεδομένων από τη γραμμή στο path, τα δικαιώματα εγγραφής στη βάση, την επικύρωση μετά την ανάγνωση της γραμμής και τον προορισμό outbound. Ένα αναγνώσιμο `.env` της εφαρμογής είναι μόνο ένδειξη για credentials· η επικύρωση web form ή ένας κωδικός βάσης δεδομένων από μόνη της δεν αποδεικνύει έλεγχο της γραμμής ή αποκάλυψη. Ελέγξτε παθητικά τον προγραμματισμό, τον κώδικα και τα δικαιώματα του αρχείου credentials, χωρίς να κάνετε query στη βάση ή να προγραμματίσετε task κατά την enumeration.

Τα event-driven jobs `incron` απαιτούν τον ίδιο έλεγχο: οι [εγγραφές incrontab](https://manpages.debian.org/testing/incron/incrontab.5.en.html) αντιστοιχίζουν ένα watched path και event σε εντολή που εκτελείται με την ταυτότητα του κατόχου του πίνακα. Χρήστης χαμηλότερων προνομίων μπορεί να επηρεάσει έμμεσα ένα watched file όταν εφαρμογή ακολουθεί link από εγγράψιμο directory και γράφει κείμενο ελεγχόμενο από attacker στο watched target. Επαληθεύστε τον πραγματικό κάτοχο του πίνακα, το event, τα δικαιώματα του target και των ancestor directories, τη συμπεριφορά της εφαρμογής ως προς την ακολούθηση link και τον τρόπο με τον οποίο το κείμενο γίνεται ορίσματα εντολής. Ειδικότερα, το [GNU Mailutils `mail` δέχεται `--exec`](https://mailutils.org/manual/html_node/Invoking-Mail.html), και η [εντολή shell-escape](https://mailutils.org/manual/html_node/Shell-Escapes.html) μπορεί να εκτελέσει πρόγραμμα· ένα μη έμπιστο πεδίο που περνά ως ξεχωριστή επιλογή σε αυτή την υλοποίηση μπορεί να οδηγήσει σε εκτέλεση εντολών. Άλλες υλοποιήσεις `mail` ή ένα παρατιθέμενο, σταθερό όριο ορισμάτων μπορεί να συμπεριφέρονται διαφορετικά. Ελέγξτε τον προγραμματισμό, τον κώδικα της εφαρμογής και τα metadata του αρχείου, χωρίς να τροποποιήσετε το watched file ή να ενεργοποιήσετε το job κατά την enumeration.

Ένα watched log μπορεί επίσης να διασχίσει όριο χρηστών μέσω helper script. Αν account χαμηλότερων προνομίων μπορεί να γράψει στο log και ο κάτοχος του `incron` διαβάζει ένα πεδίο από αυτό και το εισάγει σε νέα συμβολοσειρά εντολής [`sh -c`](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/sh.html), το shell αναλύει ξανά αυτό το πεδίο με την ταυτότητα του κατόχου. Ελέγξτε το ακριβές watched event, τα δικαιώματα του log και των parent directories, το path του helper, τον μετασχηματισμό του πεδίου log και αν φτάνει στην τελική εντολή. Το ότι υπάρχει log με δυνατότητα εγγραφής και εγγραφή `incron` από μόνο του δεν αποδεικνύει τη ροή δεδομένων· μην γράψετε γραμμή-trigger και μην εκτελέσετε το helper κατά την παθητική enumeration.

Jobs ανανέωσης πιστοποιητικών μπορούν να διασχίσουν το ίδιο όριο. Ένα privileged helper μπορεί να διαβάζει subject X.509 από πιστοποιητικό σε εγγράψιμο directory χρήστη χαμηλότερων προνομίων και να εισάγει το common name του σε νέα συμβολοσειρά εντολής `bash -c`. Το [OpenSSL μπορεί να εμφανίσει το subject πιστοποιητικού και να ελέγξει τη λήξη του](https://docs.openssl.org/3.3/man1/openssl-x509/)· το [Bash αναλύει τη συμβολοσειρά `-c` ως είσοδο shell](https://www.gnu.org/software/bash/manual/html_node/Invoking-Bash.html), επομένως η παράθεση της μεταβλητής στο εξωτερικό script δεν προστατεύει από τη δεύτερη ανάλυση. Επιβεβαιώστε την ταυτότητα εκτέλεσης του job, το ακριβές input path και τα δικαιώματα εγγραφής, τον κλάδο ανανέωσης και τη ροή δεδομένων προς το `bash -c`, προτού το χαρακτηρίσετε command injection. Ελέγξτε παθητικά το script και τα metadata πιστοποιητικού· μην ενεργοποιήσετε ανανέωση κατά την enumeration.

Η ίδια δεύτερη ανάλυση μπορεί να συμβεί όταν προγραμματισμένο job με προνόμια εξάγει όνομα από archive ή package χρήστη χαμηλότερων προνομίων και το περνά στο `xargs -I` για εισαγωγή σε συμβολοσειρά εντολής `sh -c`. Το [GNU `xargs -I` αντικαθιστά το placeholder στα αρχικά ορίσματα](https://www.gnu.org/software/findutils/manual/html_node/find_html/xargs-options.html), ενώ το [`sh -c` ερμηνεύει τη συμβολοσειρά εντολής](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/sh.html). Ακόμη κι αν το εξωτερικό script παραθέτει το εξαγόμενο όνομα, αυτό δεν καθιστά ασφαλές ένα shell program που αντικαθίσταται αργότερα. Επαληθεύστε την ταυτότητα εκτέλεσης του job, το ακριβές αποδεκτό input path και τα δικαιώματα εγγραφής, την επικύρωση archive και τις συνθήκες του κλάδου, καθώς και τη ροή δεδομένων από το όνομα στο shell. Ένας κατάλογος upload με δυνατότητα εγγραφής ή μια κλήση `xargs` από μόνα τους είναι μόνο ένδειξη· ελέγξτε τον προγραμματισμό, το script και τα metadata του path χωρίς να υποβάλετε package ή να εκτελέσετε το job κατά την enumeration.

Ένας προγραμματισμένος importer γραμματοσειρών ή εικόνων μπορεί επίσης να εμπιστεύεται ονόματα *μέσα* σε archive που παρέχεται από caller, ακόμη κι όταν το εξωτερικό όνομα upload είναι περιορισμένο. Το FontForge διόρθωσε command injection μέσω ονομάτων μελών archive στην [upstream αλλαγή για τα CVE-2024-25081 και CVE-2024-25082](https://github.com/fontforge/fontforge/pull/5367). Επιβεβαιώστε ότι job με υψηλότερα προνόμια ανοίγει πράγματι archive από εγγράψιμο path χρήστη χαμηλότερων προνομίων, την ταυτότητα εκτέλεσής του, το ακριβές build FontForge ή vendor backport και τη διαδρομή χειρισμού archive. Ένα version string ή ένα επιτρεπόμενο suffix upload από μόνο του δεν αποδεικνύει εκτέλεση. Ελέγξτε τον προγραμματισμό, τα δικαιώματα του path και τα metadata του build, χωρίς να εισαγάγετε μη έμπιστο archive κατά την enumeration.

Προγραμματισμένοι network scanners μπορούν να διασχίσουν διαφορετικό όριο όταν custom script μεταχειρίζεται subject remote TLS certificate ως τοπικό filename. Το [Nmap NSE εκτελεί επιλεγμένα scripts χωρίς sandbox](https://nmap.org/book/nse-usage.html), οπότε ελέγξτε το πραγματικό script και αν ενώνει μη έμπιστο πεδίο subject με data directory χωρίς ελέγχους containment. Η αποκάλυψη αρχείου απαιτεί στόχο που θα σαρώσει ο scheduler, path που επιλύεται σε αρχείο αναγνώσιμο από την ταυτότητα εκτέλεσης του scanner και report ή log που παραδίδεται σε αναγνώστη χαμηλότερων προνομίων. Ένα πεδίο certificate ή μόνο ένας εγκατεστημένος scanner δεν αποδεικνύει αυτή την αλυσίδα· ελέγξτε τον προγραμματισμό, το script, την επίλυση path και τον προορισμό report, χωρίς να σαρώσετε νέο στόχο κατά την παθητική enumeration.

Μια privileged εντολή cron που περνά shell glob όπως `/path/to/tasks/*.yml` σε Ansible runner χρήζει ελέγχου δικαιωμάτων directory, ακόμη κι αν όλα τα υπάρχοντα playbook είναι μόνο για ανάγνωση. Χρήστης με δικαιώματα εγγραφής και search στο directory που καλύπτει το glob μπορεί να δημιουργήσει άλλο playbook που ταιριάζει. Τα [Ansible playbooks ορίζουν tasks που εκτελεί ο runner](https://docs.ansible.com/projects/ansible/latest/cli/ansible-playbook.html), αλλά ένα custom wrapper μπορεί να φιλτράρει paths ή να χρησιμοποιεί διαφορετική ταυτότητα: επαληθεύστε τη συμπεριφορά του, τον πραγματικό χρήστη cron, την επέκταση shell, τα ACL, το sticky bit και την πολιτική mount, προτού θεωρήσετε το directory path εκτέλεσης. Ελέγξτε στατικά τα metadata και το wrapper· μην εκτελέσετε το προγραμματισμένο job κατά την enumeration.

Ένα privileged cron wrapper μπορεί να περάσει filenames από directory upload σε Perl helper, αφού πρώτα επεκτείνει ένα glob. Ο τελεστής Perl [`<>` diamond χρησιμοποιεί open δύο ορισμάτων](https://perldoc.perl.org/perlop#The-Null-Filehandle), επομένως ένα matching filename που ερμηνεύεται ως pipe command μπορεί να εκτελεστεί με την ταυτότητα του helper· το [`<<>>` αντιμετωπίζει τα ορίσματα ως κυριολεκτικά filenames](https://perldoc.perl.org/perlop#The-Null-Filehandle). Επιβεβαιώστε την ταυτότητα του scheduler, τον working directory και το glob του wrapper, τον πραγματικό χειρισμό `@ARGV` από το helper, τους περιορισμούς ονομάτων αρχείων και αν τα δικαιώματα filesystem ή μια υπηρεσία authenticated upload επιτρέπουν σε ταυτότητα χαμηλότερων προνομίων να τοποθετήσει matching όνομα. Μια γραμμή cron, ένα Perl script ή ένας εγγράψιμος FTP directory από μόνα τους δεν αποδεικνύουν ολόκληρη την αλυσίδα. Ελέγξτε τον κώδικα και τα metadata χωρίς να υποβάλετε crafted filename ή να εκτελέσετε το job κατά την enumeration.

Ένα read-only cron script μπορεί παρ’ όλα αυτά να αντικατασταθεί, αν ο προγραμματισμένος λογαριασμός το εκτελεί μέσω pathname και χρήστης χαμηλότερων προνομίων μπορεί να γράψει και να διασχίσει το μη-sticky parent directory του. Ελέγξτε την ταυτότητα εκτέλεσης του προγραμματισμού, κάθε συνιστώσα του path, το sticky bit του directory, τα ACL και την πολιτική mount· ελέγξτε τα metadata χωρίς να μετακινήσετε το αρχείο ή να εκτελέσετε το job.

Ένα privileged PHP cron wrapper μπορεί να φτάσει σε helper που δεν υπάρχει ακόμη. Αν καλεί PHP [`exec()`](https://www.php.net/manual/en/function.exec.php) με σταθερό απόλυτο path helper, χρήστης χαμηλότερων προνομίων που μπορεί να δημιουργήσει αυτό το όνομα στο parent directory μπορεί να ελέγξει τι θα εκτελέσει μια μεταγενέστερη εκτέλεση. Επιβεβαιώστε ότι η εγγραφή cron εκτελεί πράγματι το wrapper με την ταυτότητα υψηλότερων προνομίων, την ακριβή συμβολοσειρά εντολής και την πολιτική εκτέλεσης PHP, τα δικαιώματα εγγραφής και search στο directory του helper, τη συμπεριφορά symlink και sticky bit, καθώς και αν το path του helper απουσιάζει ακόμη. Ένα directory με δυνατότητα εγγραφής ή ένας helper που λείπει από μόνο του είναι μόνο ένδειξη· ελέγξτε τον προγραμματισμό, τον κώδικα και τα metadata του path, χωρίς να δημιουργήσετε τον helper ή να ενεργοποιήσετε το job.

Ένα προγραμματισμένο job μπορεί επίσης να εντοπίζει input scripts με `find` και να περνά καθένα σε interpreter. Για παράδειγμα, η συνάρτηση [`system()` του gnuplot καλεί shell](https://gnuplot.sourceforge.net/docs_6.0/gnuplot.pdf), επομένως privileged job που εκτελεί `gnuplot` σε κάθε αρχείο `*.plt` σε εγγράψιμο directory χρήστη χαμηλότερων προνομίων μπορεί να εκτελέσει εντολές με την ταυτότητα του job. Το [δικαίωμα ανάγνωσης directory ελέγχει την απαρίθμηση, ενώ η εγγραφή και το search (`x`) ελέγχουν τη δημιουργία και πρόσβαση σε γνωστά ονόματα](https://www.gnu.org/software/coreutils/manual/html_node/Mode-Structure.html)· ελέγξτε τα δικαιώματα εγγραφής και search ακόμη κι όταν το `ls` δεν μπορεί να απαριθμήσει το directory. Συσχετίστε την ακριβή ταυτότητα και εντολή του scheduler, τη συμπεριφορά του interpreter, το επιλεγμένο file pattern και τα δικαιώματα του directory· ένα directory με δυνατότητα εγγραφής ή μόνο ένας εγκατεστημένος interpreter δεν αποδεικνύει escalation. Ιδιωτικά schedules και σύντομα jobs μπορεί να απαιτούν εξουσιοδοτημένη παρατήρηση συμβάντων, καθώς ένα στιγμιότυπο διεργασιών μπορεί να τα χάσει.

Για privileged PHP job, ελέγξτε τις κυριολεκτικές εντολές `include`/`require` ως μέρος της αλυσίδας εκτελέσιμων script. Η [PHP αξιολογεί τα included αρχεία](https://www.php.net/manual/en/function.include.php), επομένως group-writable included `.php` αρχείο μπορεί να εκτελέσει κώδικα με την ταυτότητα του job, ακόμη κι όταν το κύριο script είναι read-only. Επαληθεύστε την ταυτότητα εκτέλεσης, την πραγματική επίλυση include-path, τα δικαιώματα αρχείων και directories και αν το job εκτελείται όντως· ένα ενδεικτικό cron line σε σχόλιο είναι μόνο στοιχείο. Ο ίδιος έλεγχος ισχύει για root-owned [PHP built-in server](https://www.php.net/commandline.webserver) που ξεκινά με `-S` και `-t <document-root>`: ένας listener στο loopback μπορεί και πάλι να εκτελεί PHP εφαρμογής για τοπικά requests. Ελέγξτε τη διεργασία και τον κώδικα χωρίς να ενεργοποιήσετε κανένα από τα δύο triggers κατά την enumeration.

Ένα privileged PHP job μπορεί επίσης να διασχίσει το όριο μέσω **data file**: αν χρήστης χαμηλότερων προνομίων μπορεί να αλλάξει το ακριβές αρχείο που περνά στην [`unserialize()`](https://www.php.net/manual/en/function.unserialize.php), η PHP ενδέχεται να καλέσει τη μέθοδο `__wakeup()` ή `__unserialize()` μιας φορτωμένης κλάσης κατά την επαναφορά αντικειμένου. Ελέγξτε την πραγματική ταυτότητα του job, τα δικαιώματα του αρχείου και των ancestor directories, τις φορτωμένες κλάσεις και τις πραγματικές παρενέργειες των μεθόδων, όπως εγγραφή αρχείου που επιλέγεται μέσω property. Ένα log με δυνατότητα εγγραφής ή μια κλήση `unserialize()` από μόνα τους δεν αποδεικνύουν αξιοποιήσιμο path. Ελέγξτε κώδικα και metadata χωρίς να γράψετε serialized input ή να εκτελέσετε το job κατά την enumeration.

Μια root cron εργασία μπορεί να καλεί **CLI page runner** εφαρμογής PHP αντί για τον web server. Ακολουθήστε το document root και το URI που επιλέγει ο runner έως το πραγματικό PHP entrypoint· αν ο λογαριασμός υπηρεσίας web μπορεί να γράψει στο entrypoint, το προγραμματισμένο CLI request μπορεί να εκτελέσει τον τροποποιημένο κώδικα ως root ακόμη κι αν ο runner και το cron wrapper είναι read-only. Επιβεβαιώστε την ταυτότητα του scheduler, την ακριβή επίλυση URI-to-file, τα πραγματικά δικαιώματα αρχείου και ancestor directories, καθώς και αν το entrypoint προστατεύεται από έλεγχο ακεραιότητας. Ελέγξτε κώδικα και metadata χωρίς να καλέσετε τον runner ή να αλλάξετε τη σελίδα κατά την enumeration.

Μια διεργασία `ipython` που ξεκινά από προγραμματισμένο job ή άλλον χρήστη από shared working directory χρήζει ελέγχου startup files. Οι [σημειώσεις έκδοσης ασφαλείας του IPython](https://ipython.readthedocs.io/en/8.25.0/whatsnew/version8.html#ipython-8-0-1-cve-2022-21699) εξηγούν ότι τα επηρεαζόμενα builds αναζητούσαν profiles και configuration στον current directory, συμπεριλαμβανομένου κώδικα `profile_default/startup`, πριν από τη διόρθωση του CVE-2022-21699. Συσχετίστε το πραγματικό εγκατεστημένο build ή vendor patch, τον working directory της εντολής, την ταυτότητα της διεργασίας με υψηλότερα προνόμια και τη δυνατότητα χρήστη χαμηλότερων προνομίων να γράψει και να κάνει search στο ακριβές startup path. Η εγκατάσταση `ipython`, ένα directory με δυνατότητα εγγραφής ή ένα version string από μόνο του δεν αποδεικνύει ότι άλλη ταυτότητα θα φορτώσει αρχείο εκεί. Ελέγξτε τον προγραμματισμό και τα metadata του path χωρίς να εκκινήσετε τον interpreter με υψηλότερα προνόμια.

Για privileged PHP server που καλεί συναρτήσεις από custom native extension, εντοπίστε το PHP SAPI της υπηρεσίας και τα ενεργά `php.ini` και σαρωμένα `.ini` αρχεία πριν ελέγξετε το extension. Η [PHP φορτώνει κατά την εκκίνηση τις ρυθμισμένες βιβλιοθήκες `extension`](https://www.php.net/manual/en/ini.core.php), ενώ [τα CLI και web SAPI μπορεί να χρησιμοποιούν διαφορετικά αρχεία ρύθμισης](https://www.php.net/manual/en/configuration.file.php). Επομένως, μια προσβάσιμη φόρμα login ή ένας τοπικός listener μπορεί να περάσει strings ελεγχόμενα από χρήστη σε compiled code που εκτελείται με την ταυτότητα της υπηρεσίας. Καταγράψτε το `User=`, το `ExecStart=`, τον working directory του unit, το πραγματικό path του extension και τα ορίσματα που ελέγχει ο caller· η απλή παρουσία ενός `.so` ή ενός socket loopback δεν αποδεικνύει memory-corruption flaw. Αναλύστε χωριστά κάθε custom parser αντί να στέλνετε probes κατά την παθητική enumeration.

Όταν ένα privileged wrapper κάνει hash σε script μέσω pathname και αργότερα ανοίγει ξανά το ίδιο pathname για να το εκτελέσει, το digest επαληθεύει μόνο το αντικείμενο που διαβάστηκε στο πρώτο άνοιγμα. Αν χρήστης χαμηλότερων προνομίων μπορεί να αντικαταστήσει την καταχώριση του script στον κατάλογο ανάμεσα στα δύο ανοίγματα, η μεταγενέστερη εκτέλεση μπορεί να επιλύσει διαφορετικό αντικείμενο, ακόμη κι όταν το αρχικό αρχείο script ανήκει στον root. Ένα FIFO μπορεί να παρατείνει τη φάση ελέγχου, αλλά το path εξαρτάται από δικαιώματα replaceable parent directory, πραγματικά ξεχωριστά ανοίγματα, την ταυτότητα του scheduler, τους κανόνες sticky bit και mount και τον χρονισμό. Ελέγξτε το wrapper και την έξοδο `namei -l` ως παθητική ένδειξη· επιτυχής έλεγχος checksum από μόνος του δεν αποδεικνύει ότι προστατεύεται το pathname που χρησιμοποιείται αργότερα.

Ένα privileged backup job μπορεί επίσης να **αποκαλύψει** δεδομένα χωρίς να εκτελεί εντολές που παρέχει attacker. Εξετάστε αν χρήστης χαμηλότερων προνομίων μπορεί να δημιουργήσει control file που διαβάζει το job, αν το job στη συνέχεια ανοίγει προστατευμένη πηγή όπως το `/etc/shadow` και αν URL που επιλέγει attacker ή αναγνώσιμη έξοδος λαμβάνει το αποτέλεσμα. Επαληθεύστε και τα τρία μέρη προτού το χαρακτηρίσετε path αποκάλυψης. Μια σταθερή shell command στο ίδιο script δεν καθιστά από μόνη της το control file είσοδο shell injection. Ελέγξτε το script και τα δικαιώματα αρχείων χωρίς να εκτελέσετε το job ή να τοποθετήσετε control file κατά την enumeration.

Αν προγραμματισμένο job με προνόμια εκτελεί `curl -K FILE` ή `curl --config FILE`, το [curl αντιμετωπίζει τις επιλογές του αρχείου ως ορίσματα γραμμής εντολών](https://curl.se/docs/manpage.html). Χρήστης χαμηλότερων προνομίων που ελέγχει το ακριβές αρχείο τη στιγμή που το διαβάζει το curl μπορεί να επηρεάσει το ζητούμενο URL, την τοπική είσοδο αρχείου ή το path εξόδου. Επιβεβαιώστε την πραγματική ταυτότητα του job, τα δικαιώματα εγγραφής του αρχείου και των ancestor directories, τον χρονισμό οποιουδήποτε άλλου job αντικαθιστά το αρχείο και τον τρόπο αλληλεπίδρασης των επιλογών config με τις σταθερές επιλογές γραμμής εντολών, προτού ισχυριστείτε ότι υπάρχει προστατευμένη ανάγνωση ή εγγραφή. Ένα config path με δυνατότητα εγγραφής ή μια ορατή σημαία `-K` από μόνα τους δεν αποδεικνύουν ότι εφαρμόζονται οι επιλεγμένες επιλογές· ελέγξτε τον προγραμματισμό και τα metadata χωρίς να εκτελέσετε το job ή να ανακτήσετε URL κατά την παθητική enumeration.

Αν μια εγγραφή cron καλεί helper script, ελέγξτε επίσης τον working directory και την εντολή archive του helper. Ένα μη παρατιθέμενο wildcard πάνω σε directory εγγράψιμο από άλλον χρήστη μπορεί να μετατρέψει filenames σε επιλογές archiver· οι ενέργειες checkpoint του GNU tar είναι ένα παράδειγμα. Επιβεβαιώστε την ταυτότητα εκτέλεσης του job, το input directory με δυνατότητα εγγραφής, τον ακριβή archiver και τις επιλογές, καθώς και αν το `--` τερματίζει την ανάλυση επιλογών, προτού ισχυριστείτε ότι υπάρχει path εντολών μεταξύ χρηστών. Δείτε τη [συμπεριφορά wildcard και tar](../interesting-files-permissions/wildcards-spare-tricks.md).

Μια ξεχωριστή αποκάλυψη backup file μπορεί να προκύψει όταν privileged helper εκτελεί `cd INPUT_DIR; tar ... *` χωρίς να ελέγχει αν πέτυχε το `cd`. Αν χρήστης χαμηλότερων προνομίων μπορεί να αφαιρέσει ή να αντικαταστήσει το `INPUT_DIR`, ένα αποτυχημένο `cd` μπορεί να αφήσει το shell στον προηγούμενο κατάλογο, από τον οποίο ενδέχεται να διαβάσει η επόμενη εντολή archive. Επαληθεύστε τον αρχικό working directory του job, μια πραγματική διαδρομή αποτυχίας `cd`, αν το script τερματίζεται ή χρησιμοποιεί `&&`, τις ακριβείς επιλογές archiver και αν ο χρήστης χαμηλότερων προνομίων μπορεί να διαβάσει το output archive. Ένα input directory με δυνατότητα εγγραφής ή ένα αναγνώσιμο archive από μόνο του είναι απλώς ένδειξη· ελέγξτε το helper και τα δικαιώματα του path χωρίς να αλλάξετε το ενεργό job.

Ένα προγραμματισμένο executable μπορεί να κρύβει shell script αντί να αφαιρεί το όριο εμπιστοσύνης: το [SHc](https://github.com/neurobin/shc) ενσωματώνει κρυπτογραφημένο κείμενο script σε native binary και το εκτελεί μέσω shell κατά τον runtime. Το suffix `.sh.x` ή ένα αδιαφανές ELF είναι μόνο ένδειξη για έλεγχο. Για να αξιολογήσετε filename option injection, επιβεβαιώστε την ταυτότητα του privileged scheduler, τον πραγματικό working directory και την εντολή του helper, τη δυνατότητα χρήστη χαμηλότερων προνομίων να δημιουργήσει εκεί matching names και αν μη παρατιθέμενο glob φτάνει σε εντολή όπως `rsync` χωρίς όριο επιλογών. Η [επιλογή remote-shell του `rsync`](../interesting-files-permissions/wildcards-spare-tricks.md#rsync) έχει σημασία μόνο αν χρησιμοποιείται αυτή ακριβώς η διαδρομή εντολής. Περιορισμένη ορατότητα `/proc` ή αποτυχημένη στατική αποκρυπτογράφηση αφήνουν την εντολή άγνωστη· μην εκτελέσετε το privileged helper απλώς για να το ταξινομήσετε.

Το κείμενο γραμμής εντολών διεργασίας είναι άλλη μία μη έμπιστη είσοδος για privileged helper. Χρήστης χαμηλότερων προνομίων μπορεί να επιλέξει τίτλο διεργασίας ή `argv[0]` που ταιριάζει με `pgrep -f`· ένα matching όνομα δεν πιστοποιεί το executable ή τον κάτοχό του. Αν script που εκτελείται ως root καταγράφει αυτό το κείμενο, ξαναγράφει μέρος του ως `apache2ctl`/`httpd` και εκτελεί το αποτέλεσμα χωρίς σταθερό πίνακα ορισμάτων, επιλογές που επιλέγει attacker μπορεί να ορίσουν διαφορετικό configuration directory ή error log. Η ανάλυση Apache configuration μπορεί να φορτώσει modules ή να φτάσει σε ρυθμισμένους helpers, επομένως μην επικυρώνετε μη έμπιστο configuration ως root κατά την enumeration. Ελέγξτε τον ιδιοκτήτη του scheduler, τον ακριβή helper, την ταυτότητα διεργασίας και τη ροή δεδομένων προς τα ορίσματα· πρόκειται για option/configuration injection, εκτός αν αποδειχθεί χωριστά εκτέλεση shell metacharacter.

Ένας root-run parser που τροφοδοτεί μη έμπιστο κείμενο σε αριθμητική Bash μπορεί να εκτελέσει substitutions μέσα σε αυτό το κείμενο. Ο [οδηγός privilege escalation](../linux-basics/linux-privilege-escalation/README.md#bash-arithmetic-expansion-injection-in-cron-log-parsers) περιέχει αναλυμένο παράδειγμα. Επιβεβαιώστε την πηγή εισόδου και την εντολή parsing προτού θεωρήσετε ότι κάθε αριθμητική έκφραση είναι exploitable.

Για privileged job που αναλύει log εφαρμογής, ακολουθήστε τα μη έμπιστα πεδία πέρα από την πρώτη ανάλυση. Account χαμηλότερων προνομίων μπορεί να γράφει στο log μέσω της τρέχουσας process group του ή να επηρεάζει πεδία logged request· μια εγγραφή μπορεί στη συνέχεια να επιλέξει εικόνα, της οποίας τα metadata γίνονται δεύτερο pathname για άνοιγμα XML. Ελέγξτε την πραγματική ταυτότητα του job, την πραγματική πρόσβαση εγγραφής στο log, τον χειρισμό delimiter, τον περιορισμό σε canonical path και αν το επιλεγμένο XML ελέγχεται από attacker. Η επέκταση external entity μπορεί να μετατρέψει αυτή τη δεύτερη ανάγνωση σε αποκάλυψη αρχείων με προνόμια, αν το αποτέλεσμα της επέκτασης φτάσει σε έξοδο αναγνώσιμη από χρήστη χαμηλότερων προνομίων. Ο [οδηγός ασφάλειας επεξεργασίας Java XML](https://docs.oracle.com/en/java/javase/17/security/java-api-xml-processing-jaxp-security-guide.html) τεκμηριώνει ελέγχους για πρόσβαση σε external DTD/entity· ελέγξτε τον εγκατεστημένο parser και τις ενεργές ρυθμίσεις του. Ένα log ή XML αρχείο με δυνατότητα εγγραφής από μόνο του είναι απλώς ένδειξη. Ελέγξτε κώδικα και metadata χωρίς να τροφοδοτήσετε τον προγραμματισμένο parser κατά την enumeration.

Ελέγξτε επίσης privileged jobs που δημιουργούν αρχεία από Git repository άλλου χρήστη. Ένα script μπορεί να χρησιμοποιεί `git ls-tree` και `git cat-file` αντί για `git checkout`, αλλά και πάλι να εμπιστεύεται paths του tree που ελέγχει attacker, όταν τα ενώνει με staging directory. Απόλυτα paths και στοιχεία `..` μπορούν να διαφύγουν από αυτόν τον κατάλογο, εκτός αν ο προορισμός κανονικοποιείται και ελέγχεται ως προς containment πριν από την εγγραφή. Το `git -c safe.directory=*` επιτρέπει πρόσβαση σε repositories διαφορετικής ιδιοκτησίας· από μόνο του δεν δημιουργεί συνθήκη αυθαίρετης εγγραφής.

Ένα root-run database backup μπορεί να δημιουργήσει άλλο όριο ιδιοκτησίας. Το PostgreSQL [`pg_basebackup`](https://www.postgresql.org/docs/14/app-pgbasebackup.html) αντιγράφει πρόσθετα κανονικά αρχεία που τοποθετούνται στον κατάλογο δεδομένων της πηγής, ενώ η προεπιλεγμένη plain μορφή του γράφει αρχεία στο `-D` ως δέντρο directory. Αν account χαμηλότερων προνομίων μπορεί να δημιουργήσει ή να τροποποιήσει αυτά τα αρχεία πηγής, ελέγξτε την ιδιοκτησία και τα δικαιώματα του αποτελέσματος, αν το path είναι προσβάσιμο και εκτελέσιμο και αν το mount έχει `nosuid`. Αντίγραφο ιδιοκτησίας root με διατηρημένα set-ID permissions μπορεί να είναι επικίνδυνο· backup μόνο σε tar, αφαίρεση δικαιωμάτων ή μη προσβάσιμος προορισμός δεν τεκμηριώνουν το ίδιο path. Ακολουθήστε το προγραμματισμένο wrapper και τον ενεργό χρήστη πριν θεωρήσετε την εντολή backup εύρημα.

## Παρατηρήστε εργασίες σύντομης διάρκειας

Ένα στιγμιότυπο διεργασιών μπορεί να χάσει job που εκτελείται για χιλιοστά του δευτερολέπτου. Συγκρίνετε τις δηλώσεις timer/cron με τα logs και, όταν είναι εξουσιοδοτημένο, παρακολούθηση συμβάντων διεργασιών όπως `pspy` ή audit. Συσχετίστε τον προγραμματισμένο κάτοχο, την ακριβή γραμμή εντολών και τα αρχεία που διαβάζει ή γράφει το task. Ένα loopback scheduler web UI είναι ξεχωριστή διεπαφή· δείτε το [παράδειγμα Crontab UI](../linux-basics/linux-privilege-escalation/README.md#crontab-ui-alseambusher-running-as-root--web-based-scheduler-privesc).
