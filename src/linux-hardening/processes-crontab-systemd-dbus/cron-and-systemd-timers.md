# Εργασίες Cron και χρονόμετρα systemd

{{#include ../../banners/hacktricks-training.md}}

Οι προγραμματισμένες εργασίες μπορούν να εκτελούνται με διαφορετική ταυτότητα και περιβάλλον από το τρέχον shell. Καταγράψτε τα cron, `at`, anacron και τα χρονόμετρα systemd και, στη συνέχεια, ακολουθήστε κάθε προγραμματισμένη εντολή μέσα από τα scripts, τα imports, τον κατάλογο εργασίας και τις εγγράψιμες εισόδους της.

## Καταγραφή προγραμματισμών

```bash
crontab -l 2>/dev/null
ls -la /etc/crontab /etc/cron.* /var/spool/cron* 2>/dev/null
atq 2>/dev/null
systemctl list-timers --all 2>/dev/null
```

Τα system crontabs συνήθως περιλαμβάνουν πεδίο χρήστη· το crontab ενός χρήστη δεν το περιλαμβάνει. Εξετάστε το ενεργό PATH και το περιβάλλον του πραγματικού scheduler. Η εντολή `run-parts --test /etc/cron.daily` δείχνει ποια ονόματα αρχείων θα επιλεγούν σε αυτό το host. Οι control characters μπορούν να αποκρύψουν μια εγγραφή σε μια πρόχειρη προβολή, οπότε χρησιμοποιήστε `cat -A` ή `sed -n l` όταν ένα πρόγραμμα φαίνεται ύποπτο.

## Ανιχνεύστε την επίλυση διαδρομών αρχείων και εντολών με προνόμια

```bash
systemctl cat <name>.timer <name>.service
systemctl show <name>.service -p User -p ExecStart -p EnvironmentFiles -p WorkingDirectory
namei -l /path/to/scheduled/script
```

Εξετάστε αλυσίδες script με δυνατότητα εγγραφής, διαδρομές `EnvironmentFile=`, drop-ins, symlinks, σχετικές εντολές, επέκταση wildcard και binaries που αντιγράφονται ή εκτελούνται από privileged task. Ένα timer μπορεί να ενεργοποιήσει service με διαφορετικό όνομα μέσω της ρύθμισης `Unit=`. Οι σελίδες [PATH](../linux-basics/linux-environment-variables.md#path), [wildcard](../interesting-files-permissions/wildcards-spare-tricks.md) και [file-link](../main-system-information/filesystem-links-and-file-descriptors.md) εξηγούν τα βασικά primitives.

Για script `chkrootkit` που εκτελείται ως root μέσω scheduler, εξετάστε τον εγκατεστημένο κώδικα για το παλιό [slapper-loop quoting defect (CVE-2014-0476)](https://bugzilla.redhat.com/show_bug.cgi?id=CVE-2014-0476): μια μη περικλεισμένη σε εισαγωγικά εντολή `file_port=$file_port $i` μετά τον έλεγχο μιας προσωρινής διαδρομής `SLAPPER_FILES` μπορεί να εκτελέσει το αρχείο. Επαληθεύστε το πραγματικό script ή το vendor patch, τον προγραμματισμό ως root, την πρόσβαση εγγραφής χρήστη χαμηλότερων δικαιωμάτων στην ακριβή προσωρινή διαδρομή, την εκτελεσιμότητά της και την πολιτική mount. Μια συμβολοσειρά έκδοσης ή μόνο η παρουσία του `chkrootkit` δεν επιβεβαιώνει τη διαδρομή. Μην δημιουργείτε ή εκτελείτε προσωρινό αρχείο κατά την παθητική εξέταση.

Εξετάστε ένα ακόμη hop μονάδας όταν το root service ενός timer εκτελεί `systemctl restart <other>.service`: η μονάδα που επανεκκινείται μπορεί να καλέσει shell με script στο οποίο μπορεί να γράψει χρήστης χαμηλότερων δικαιωμάτων. Επιβεβαιώστε τα ενεργά `User=`, `DynamicUser=`, `RootDirectory=`/`RootImage=`, τα ακριβή ορίσματα `ExecStart=` και τα δικαιώματα του script και της γονικής διαδρομής του. Ένα script με δυνατότητα εγγραφής είναι μόνο υποψήφιο εύρημα, μέχρι να επιβεβαιωθεί ότι ο timer και η μονάδα που επανεκκινείται είναι ενεργοί σε αυτό το πλαίσιο εκτέλεσης. Εξετάστε τις ιδιότητες των μονάδων χωρίς να επανεκκινήσετε καμία από τις δύο υπηρεσίες.

Αν ένα job με υψηλότερα δικαιώματα κατεβάζει script μέσω hostname και περνά την απόκριση σε shell, ελέγξτε ποιος ελέγχει την επίλυση του hostname, καθώς και το απομακρυσμένο script. Ένα αρχείο `/etc/hosts` με δυνατότητα εγγραφής, ακόμη και μέσω δικαιωμάτων ομάδας ή ACL, μπορεί να ανακατευθύνει ένα όνομα που επιλύει τοπικά το job. Μια απόκριση `curl` γίνεται διαδρομή εκτέλεσης μεταξύ χρηστών μόνο αν η πραγματική προγραμματισμένη εντολή εκτελεί αυτή την απόκριση και το job χρησιμοποιεί τη διαδρομή resolver που επηρεάζεται. Επαληθεύστε την ταυτότητα εκτέλεσης του job, το ακριβές URL και το shell pipeline, την ενεργή συμπεριφορά proxy/DNS, καθώς και τα δικαιώματα αρχείου και γονικού καταλόγου. Ένα αρχείο hosts με δυνατότητα εγγραφής από μόνο του είναι ένδειξη για περαιτέρω εξέταση, όχι απόδειξη ύπαρξης privileged consumer. Εξετάστε το schedule και τα metadata χωρίς να αλλάξετε την αντιστοίχιση ή να κατεβάσετε το script κατά την καταγραφή.

Ένα προγραμματισμένο `wget` με privileged δικαιώματα αποτελεί ξεχωριστό όριο εγγραφής σε αρχείο, ακόμη και αν το περιεχόμενο που κατεβαίνει δεν εκτελείται απευθείας. [Το GNU Wget 1.18 άλλαξε τον προεπιλεγμένο χειρισμό ονόματος αρχείου σε HTTP-to-FTP redirect για να διορθώσει το CVE-2016-4971](https://lists.gnu.org/archive/html/info-gnu/2016-06/msg00004.html): παλαιότερα επηρεαζόμενα builds μπορούσαν να χρησιμοποιήσουν το όνομα αρχείου του redirect FTP, ενώ το `--trust-server-names` ζητά ρητά αυτή τη συμπεριφορά. Αν μέρος χαμηλότερης εμπιστοσύνης ελέγχει την HTTP απόκριση και τον FTP πόρο, εξετάστε αν το job ακολουθεί το redirect, το πραγματικό build του Wget ή το vendor backport, τις επιλογές εξόδου, την ταυτότητα εκτέλεσης, τον τρέχοντα κατάλογο εργασίας και το αν το όνομα προορισμού μπορεί να γίνει startup file. [Το Wget φορτώνει το `WGETRC` ή το `$HOME/.wgetrc`](https://www.gnu.org/software/wget/manual/html_node/Wgetrc-Location.html), ενώ [οι ρυθμίσεις του μπορούν να ορίσουν πηγή POST ή διαδρομή εξόδου](https://www.gnu.org/software/wget/manual/html_node/Wgetrc-Commands.html). Ένα μεταγενέστερο privileged fetch αποτελεί ξεχωριστή προϋπόθεση για οποιαδήποτε επακόλουθη αποκάλυψη ή εγγραφή. Πρόσβαση σε χαμηλή θύρα μέσω `authbind` έχει σημασία μόνο αν ο καλών μπορεί πράγματι να εξυπηρετήσει το URL που ζητά το job. Εξετάστε παθητικά τις ρυθμίσεις και τα logs, χωρίς να εξυπηρετήσετε redirect ή να εκτελέσετε το job. Η [πρόσβαση σε raw block device μέσω της ομάδας `disk`](../user-information/interesting-groups-linux-pe/README.md#disk-group) είναι ανεξάρτητη από αυτή τη διαδρομή λήψης μέσω δικτύου.

Εξετάστε τα αρχεία δεδομένων, όχι μόνο τα scripts. Ένα προγραμματισμένο εργαλείο προσομοίωσης ή orchestration μπορεί να διαβάζει αρχείο YAML που ορίζει διεργασίες προς εκκίνηση. Αν χρήστης χαμηλότερων δικαιωμάτων μπορεί να επεξεργαστεί αυτό το αρχείο και το job το εκτελεί υπό άλλον λογαριασμό, τα δεδομένα μπορούν να γίνουν εντολές υπό την ταυτότητα του job. Επαληθεύστε την ακριβή προγραμματισμένη εντολή, τον ενεργό χρήστη, τη διαδρομή του αρχείου, τη σημασιολογία του parser και την πρόσβαση εγγραφής, συμπεριλαμβανομένων των γονικών καταλόγων, προτού θεωρήσετε ένα YAML με δυνατότητα εγγραφής διαδρομή εκτέλεσης. Για παθητική διαλογή αρκεί η ανάγνωση του schedule και των metadata του αρχείου. Μην εκτελέσετε το job ή τροποποιήσετε την είσοδό του κατά την καταγραφή.

Η διαμόρφωση SSH client αποτελεί επίσης εκτελέσιμη είσοδο όταν ένα job με υψηλότερα δικαιώματα εκτελεί `ssh -F` χρησιμοποιώντας αρχείο που μπορεί να αντικαταστήσει χρήστης χαμηλότερων δικαιωμάτων. Το OpenSSH [`ProxyCommand`](https://man.openbsd.org/ssh_config#ProxyCommand) εκτελεί τοπική εντολή μέσω του shell του client, ενώ τα `Host`/`Match` και οι προηγούμενες επιλογές καθορίζουν αν ισχύει αυτή η οδηγία. Συσχετίστε την ακριβή προγραμματισμένη κλήση SSH, την ταυτότητα εκτέλεσης, την επιλεγμένη διαδρομή ρυθμίσεων, τα δικαιώματα εγγραφής σε κατάλογο και αρχείο, καθώς και τη σειρά των ενεργών επιλογών, προτού το χαρακτηρίσετε διαδρομή εκτέλεσης μεταξύ χρηστών. Εξετάστε αυτά τα στοιχεία χωρίς να εκτελέσετε το job ή να φορτώσετε τη μη έμπιστη διαμόρφωση ως privileged account.

Ένα προγραμματισμένο `scp` και στη συνέχεια `ssh` για εκτέλεση του αντιγραμμένου script απαιτεί δεύτερο έλεγχο ορίου εμπιστοσύνης, όταν χρήστης χαμηλότερων δικαιωμάτων ελέγχει την υπηρεσία SSH προορισμού. Αν η υπηρεσία μπορεί να προωθήσει τη σύνδεση σε άλλον host, ο privileged client ενδέχεται να πιστοποιηθεί σε μη αναμενόμενο endpoint. Το [`StrictHostKeyChecking no`](https://man.openbsd.org/ssh_config#StrictHostKeyChecking) αποδυναμώνει την προστασία έναντι αλλαγής host key, υπό τους υπόλοιπους περιορισμούς του OpenSSH και τις ενεργές επιλογές ανά host. Προσδιορίστε την ταυτότητα εκτέλεσης του job, τον πραγματικό προορισμό και τη μέθοδο πιστοποίησης, την ενεργό ταυτότητα της απομακρυσμένης εντολής και το αν η ίδια διαδρομή προορισμού είναι εγγράψιμη ή υπάρχει ήδη στον ανακατευθυνόμενο host. Η εκτέλεση παλιού ή ελεγχόμενου από επιτιθέμενο αρχείου απαιτεί επιπλέον η αντιγραφή να αποτύχει ή να μην εντοπίσει τη διαδρομή **και** το wrapper να συνεχίσει στην εντολή SSH. Τα [Bash `errexit`](https://www.gnu.org/software/bash/manual/html_node/The-Set-Builtin.html) και ο ρητός χειρισμός status επηρεάζουν αυτή τη ροή. Μια αδύναμη ρύθμιση host key, μια ορατή διεργασία `sshpass` ή ένας προσωρινός κατάλογος με δυνατότητα εγγραφής δεν αποδεικνύουν από μόνα τους αυτή την αλυσίδα. Εξετάστε το schedule, το script, τη διαμόρφωση SSH και τα metadata αρχείων χωρίς ανακατεύθυνση της υπηρεσίας ή ενεργοποίηση του job κατά την καταγραφή.

Ένας privileged scheduler εφαρμογής μπορεί να παίρνει τα jobs του από εγγραφές βάσης δεδομένων αντί για αρχεία με δυνατότητα εγγραφής. Για παράδειγμα, μια εγγραφή root cron που εκτελεί Laravel [`php artisan schedule:run`](https://laravel.com/docs/9.x/scheduling#running-the-scheduler) μπορεί να φτάσει σε κώδικα εφαρμογής που διαβάζει εγγραφές εργασιών. Αν λογαριασμός χαμηλότερων δικαιωμάτων μπορεί να γράψει εγγραφή που περιέχει τοπική διαδρομή και το προγραμματισμένο callback καλεί την PHP [`file_get_contents`](https://www.php.net/manual/en/function.file-get-contents.php) ως root και στέλνει το σώμα που επιστρέφεται σε webhook που επιλέγει η εγγραφή, τότε πρόκειται για διαδρομή αποκάλυψης αρχείου με privileged δικαιώματα. Επαληθεύστε την ταυτότητα του cron, το πραγματικό scheduler callback και τη ροή δεδομένων από την εγγραφή στη διαδρομή, τα δικαιώματα εγγραφής στη βάση δεδομένων, την επικύρωση μετά την ανάγνωση της εγγραφής και τον προορισμό εξερχόμενης κίνησης. Ένα αναγνώσιμο `.env` εφαρμογής είναι μόνο ένδειξη για credentials. Η επικύρωση φόρμας web ή μόνο ένας κωδικός πρόσβασης βάσης δεδομένων δεν αποδεικνύουν έλεγχο εγγραφών ή αποκάλυψη. Εξετάστε παθητικά το schedule, τον κώδικα και τα δικαιώματα του αρχείου credentials, χωρίς να υποβάλετε ερώτημα στη βάση ή να προγραμματίσετε εργασία κατά την καταγραφή.

Τα event-driven jobs `incron` χρειάζονται τον ίδιο έλεγχο: οι [εγγραφές incrontab](https://manpages.debian.org/testing/incron/incrontab.5.en.html) συνδέουν μια παρακολουθούμενη διαδρομή και ένα συμβάν με εντολή που εκτελείται υπό την ταυτότητα του ιδιοκτήτη του πίνακα. Χρήστης χαμηλότερων δικαιωμάτων μπορεί να επηρεάσει έμμεσα ένα παρακολουθούμενο αρχείο, όταν μια εφαρμογή ακολουθεί σύνδεσμο από εγγράψιμο κατάλογο και γράφει στοχοθετημένο κείμενο στο παρακολουθούμενο αρχείο. Επαληθεύστε τον πραγματικό ιδιοκτήτη του πίνακα, το συμβάν, τα δικαιώματα του στόχου και των γονικών καταλόγων, τη συμπεριφορά της εφαρμογής ως προς την ακολούθηση συνδέσμων και τον τρόπο με τον οποίο το κείμενο γίνεται ορίσματα εντολής. Συγκεκριμένα, το [GNU Mailutils `mail` δέχεται `--exec`](https://mailutils.org/manual/html_node/Invoking-Mail.html), ενώ η [εντολή shell-escape](https://mailutils.org/manual/html_node/Shell-Escapes.html) μπορεί να εκτελέσει πρόγραμμα. Μη έμπιστο πεδίο που περνά ως ξεχωριστή επιλογή σε αυτή την υλοποίηση μπορεί να οδηγήσει σε εκτέλεση εντολών. Άλλες υλοποιήσεις `mail` ή ένα παρατεθειμένο, σταθερό όριο ορισμάτων μπορεί να συμπεριφέρονται διαφορετικά. Εξετάστε το schedule, τον κώδικα της εφαρμογής και τα metadata αρχείων χωρίς να τροποποιήσετε το παρακολουθούμενο αρχείο ή να ενεργοποιήσετε το job κατά την καταγραφή.

Ένα παρακολουθούμενο log μπορεί επίσης να διασχίσει όριο χρηστών μέσω βοηθητικού script. Αν λογαριασμός χαμηλότερων δικαιωμάτων μπορεί να γράψει στο log και ο ιδιοκτήτης του `incron` διαβάζει ένα πεδίο από αυτό και το εισάγει σε νέα συμβολοσειρά εντολής [`sh -c`](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/sh.html), το shell αναλύει ξανά αυτό το πεδίο υπό την ταυτότητα του ιδιοκτήτη. Ελέγξτε το ακριβές παρακολουθούμενο συμβάν, τα δικαιώματα του log και των γονικών καταλόγων, τη διαδρομή του helper, τον μετασχηματισμό του πεδίου log και το αν εκτελείται τελικά η παραγόμενη εντολή. Η διαπίστωση ότι ένα log είναι εγγράψιμο και υπάρχει εγγραφή `incron` δεν αποδεικνύει από μόνη της τη ροή δεδομένων. Μην γράψετε γραμμή ενεργοποίησης ή εκτελέσετε το helper κατά την παθητική καταγραφή.

Τα jobs ανανέωσης πιστοποιητικών μπορούν να διασχίσουν το ίδιο όριο. Ένα privileged helper μπορεί να διαβάζει subject X.509 από πιστοποιητικό σε κατάλογο όπου μπορεί να γράψει χρήστης χαμηλότερων δικαιωμάτων και να εισάγει το common name σε νέα συμβολοσειρά εντολής `bash -c`. [Το OpenSSL μπορεί να εμφανίσει το subject πιστοποιητικού και να ελέγξει τη λήξη του](https://docs.openssl.org/3.3/man1/openssl-x509/). [Το Bash αναλύει τη συμβολοσειρά `-c` ως είσοδο shell](https://www.gnu.org/software/bash/manual/html_node/Invoking-Bash.html), επομένως το να περικλείεται η μεταβλητή σε εισαγωγικά στο εξωτερικό script δεν προστατεύει τη δεύτερη ανάλυση. Επιβεβαιώστε την προγραμματισμένη ταυτότητα, την ακριβή διαδρομή εισόδου και τα δικαιώματα εγγραφής, τον κλάδο ανανέωσης και τη ροή δεδομένων προς το `bash -c`, προτού το χαρακτηρίσετε command injection. Εξετάστε παθητικά το script και τα metadata του πιστοποιητικού. Μην ενεργοποιήσετε ανανέωση κατά την καταγραφή.

Η ίδια δεύτερη ανάλυση μπορεί να συμβεί όταν ένα privileged scheduled job εξάγει όνομα από archive ή package χρήστη χαμηλότερων δικαιωμάτων και το περνά στο `xargs -I` για εισαγωγή σε συμβολοσειρά εντολής `sh -c`. Το [GNU `xargs -I` αντικαθιστά το placeholder στα αρχικά ορίσματα](https://www.gnu.org/software/findutils/manual/html_node/find_html/xargs-options.html), ενώ το [`sh -c` ερμηνεύει τη συμβολοσειρά εντολής](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/sh.html). Ακόμη κι αν το εξωτερικό script περικλείει σε εισαγωγικά το εξαγόμενο όνομα, αυτό δεν καθιστά ασφαλές ένα μεταγενέστερο υποκατεστημένο shell program. Επαληθεύστε την ταυτότητα εκτέλεσης του job, την ακριβή διαδρομή αποδεκτής εισόδου και τα δικαιώματα εγγραφής, την επικύρωση archive και τις συνθήκες του κλάδου, καθώς και τη ροή από το όνομα στο shell. Ένας κατάλογος upload με δυνατότητα εγγραφής ή μια κλήση `xargs` από μόνα τους είναι μόνο ενδείξεις. Εξετάστε το schedule, το script και τα metadata διαδρομών χωρίς να υποβάλετε package ή να εκτελέσετε το job κατά την καταγραφή.

Ένα προγραμματισμένο πρόγραμμα εισαγωγής γραμματοσειρών ή εικόνων μπορεί επίσης να εμπιστευτεί ονόματα *μέσα* σε archive που παρέχει ο καλών, ακόμη κι αν το εξωτερικό όνομα του upload είναι περιορισμένο. Το FontForge διόρθωσε command injection μέσω ονομάτων μελών archive στην [upstream αλλαγή για τα CVE-2024-25081 και CVE-2024-25082](https://github.com/fontforge/fontforge/pull/5367). Επιβεβαιώστε ότι job με υψηλότερα δικαιώματα ανοίγει πράγματι archive από διαδρομή όπου μπορεί να γράψει χρήστης χαμηλότερων δικαιωμάτων, την ταυτότητα εκτέλεσής του, το ακριβές build του FontForge ή το vendor backport και τη διαδρομή κώδικα χειρισμού archive. Μια συμβολοσειρά έκδοσης ή μόνο ένα επιτρεπόμενο επίθημα upload δεν αποδεικνύει εκτέλεση. Εξετάστε το schedule, τα δικαιώματα διαδρομής και τα metadata build χωρίς να εισαγάγετε μη έμπιστο archive κατά την καταγραφή.

Τα προγραμματισμένα network scanners μπορούν να διασχίσουν διαφορετικό όριο όταν custom script αντιμετωπίζει το subject απομακρυσμένου TLS certificate ως τοπικό όνομα αρχείου. Το [Nmap NSE εκτελεί τα επιλεγμένα scripts χωρίς sandbox](https://nmap.org/book/nse-usage.html), επομένως εξετάστε το πραγματικό script και αν συνενώνει μη έμπιστο πεδίο subject με κατάλογο δεδομένων χωρίς ελέγχους περιορισμού διαδρομής. Η αποκάλυψη αρχείου απαιτεί στόχο που θα σαρώσει ο scheduler, διαδρομή που αντιστοιχεί σε αρχείο αναγνώσιμο από την ταυτότητα εκτέλεσης του scanner και αναφορά ή log που παραδίδεται σε χρήστη χαμηλότερων δικαιωμάτων. Ένα πεδίο πιστοποιητικού ή μόνο ένας εγκατεστημένος scanner δεν αποδεικνύει αυτή την αλυσίδα. Εξετάστε το schedule, το script, την επίλυση διαδρομής και τον προορισμό της αναφοράς, χωρίς να σαρώσετε νέο στόχο κατά την παθητική καταγραφή.

Μια privileged εντολή cron που περνά shell glob όπως `/path/to/tasks/*.yml` σε Ansible runner χρειάζεται έλεγχο δικαιωμάτων καταλόγου, ακόμη κι αν όλα τα υπάρχοντα playbook είναι μόνο για ανάγνωση. Χρήστης με δικαιώματα εγγραφής και αναζήτησης στον κατάλογο του glob μπορεί να δημιουργήσει άλλο playbook που ταιριάζει. Τα [Ansible playbook ορίζουν εργασίες που εκτελεί ο runner](https://docs.ansible.com/projects/ansible/latest/cli/ansible-playbook.html), αλλά ένα custom wrapper μπορεί να φιλτράρει διαδρομές ή να χρησιμοποιεί διαφορετική ταυτότητα: επαληθεύστε τη συμπεριφορά του, τον πραγματικό χρήστη cron, την επέκταση shell, τα ACL, το sticky bit και την πολιτική mount προτού θεωρήσετε τον κατάλογο διαδρομή εκτέλεσης. Εξετάστε στατικά τα metadata και το wrapper. Μην εκτελέσετε το προγραμματισμένο job κατά την καταγραφή.

Ένα privileged cron wrapper μπορεί να περάσει ονόματα αρχείων από κατάλογο upload σε Perl helper μετά την επέκταση glob. Ο Perl [`<>` diamond operator χρησιμοποιεί two-argument `open`](https://perldoc.perl.org/perlop#The-Null-Filehandle), επομένως όνομα αρχείου που ταιριάζει και ερμηνεύεται ως pipe command μπορεί να εκτελεστεί υπό την ταυτότητα του helper. Το [`<<>>` αντιμετωπίζει τα ορίσματα ως κυριολεκτικά ονόματα αρχείων](https://perldoc.perl.org/perlop#The-Null-Filehandle). Επιβεβαιώστε την ταυτότητα του scheduler, τον τρέχοντα κατάλογο εργασίας και το glob του wrapper, τον πραγματικό χειρισμό `@ARGV` από το helper, τους περιορισμούς ονομάτων αρχείων και το αν χρήστης χαμηλότερων δικαιωμάτων μπορεί να τοποθετήσει κατάλληλο όνομα μέσω δικαιωμάτων filesystem ή αυθεντικοποιημένης υπηρεσίας upload. Μια γραμμή cron, ένα Perl script ή ένας εγγράψιμος κατάλογος FTP από μόνα τους δεν αποδεικνύουν ολόκληρη την αλυσίδα. Εξετάστε τον κώδικα και τα metadata χωρίς να υποβάλετε κατασκευασμένο όνομα αρχείου ή να εκτελέσετε το job κατά την καταγραφή.

Ένα read-only cron script μπορεί και πάλι να αντικατασταθεί, αν ο προγραμματισμένος λογαριασμός το εκτελεί μέσω pathname και χρήστης χαμηλότερων δικαιωμάτων μπορεί να γράψει και να διασχίσει τον μη-sticky γονικό κατάλογό του. Ελέγξτε την ταυτότητα εκτέλεσης του schedule, κάθε στοιχείο διαδρομής, το sticky bit του καταλόγου, τα ACL και την πολιτική mount. Εξετάστε τα metadata χωρίς να μετακινήσετε το αρχείο ή να εκτελέσετε το job.

Ένα privileged PHP cron wrapper μπορεί να φτάσει σε helper που δεν υπάρχει ακόμη. Αν καλεί την PHP [`exec()`](https://www.php.net/manual/en/function.exec.php) με σταθερή απόλυτη διαδρομή helper, χρήστης χαμηλότερων δικαιωμάτων που μπορεί να δημιουργήσει αυτό το όνομα στον γονικό κατάλογο μπορεί να ελέγξει τι θα εκτελέσει μελλοντική εκτέλεση. Επιβεβαιώστε ότι η εγγραφή cron εκτελεί πράγματι το wrapper με την υψηλότερη ταυτότητα, την ακριβή συμβολοσειρά εντολής και την πολιτική εκτέλεσης της PHP, τα δικαιώματα εγγραφής και αναζήτησης στον κατάλογο του helper, τη συμπεριφορά symlink και sticky bit, καθώς και αν η διαδρομή του helper απουσιάζει ακόμη. Ένας εγγράψιμος κατάλογος ή ένας helper που λείπει είναι μόνο ένδειξη. Εξετάστε το schedule, τον κώδικα και τα metadata διαδρομής χωρίς να δημιουργήσετε τον helper ή να ενεργοποιήσετε το job.

Ένα προγραμματισμένο job μπορεί επίσης να εντοπίζει input scripts με `find` και να περνά το καθένα σε interpreter. Για παράδειγμα, η συνάρτηση [`system()` του gnuplot καλεί shell](https://gnuplot.sourceforge.net/docs_6.0/gnuplot.pdf), επομένως privileged job που εκτελεί `gnuplot` σε κάθε αρχείο `*.plt` σε κατάλογο όπου μπορεί να γράψει χρήστης χαμηλότερων δικαιωμάτων μπορεί να εκτελέσει εντολές με την ταυτότητα του job. Το [δικαίωμα ανάγνωσης καταλόγου ελέγχει την καταχώριση, ενώ η εγγραφή και η αναζήτηση (`x`) ελέγχουν τη δημιουργία και πρόσβαση σε γνωστά ονόματα](https://www.gnu.org/software/coreutils/manual/html_node/Mode-Structure.html). Ελέγξτε τα δικαιώματα εγγραφής και αναζήτησης ακόμη κι όταν το `ls` δεν μπορεί να εμφανίσει τα περιεχόμενα του καταλόγου. Συσχετίστε την ακριβή ταυτότητα και εντολή του scheduler, τη συμπεριφορά του interpreter, το επιλεγμένο μοτίβο αρχείων και τα δικαιώματα καταλόγου. Ένας εγγράψιμος κατάλογος ή ένας εγκατεστημένος interpreter από μόνα τους δεν αποδεικνύουν κλιμάκωση δικαιωμάτων. Ιδιωτικά schedules και σύντομης διάρκειας jobs μπορεί να απαιτούν εξουσιοδοτημένη παρατήρηση συμβάντων, καθώς ένα στιγμιότυπο διεργασιών μπορεί να τα χάσει.

Για privileged PHP job, εξετάστε τις κυριολεκτικές εντολές `include`/`require` ως μέρος της αλυσίδας εκτελέσιμων scripts. Η [PHP αξιολογεί τα αρχεία που περιλαμβάνονται](https://www.php.net/manual/en/function.include.php), επομένως ένα `.php` αρχείο εγγράψιμο από ομάδα μπορεί να εκτελέσει κώδικα με την ταυτότητα του job, ακόμη κι αν το κύριο script είναι read-only. Επαληθεύστε την προγραμματισμένη ταυτότητα, την ενεργή επίλυση include-path, τα δικαιώματα αρχείων και καταλόγων, καθώς και το αν εκτελείται πράγματι το job. Ένα δείγμα γραμμής cron σε σχόλιο είναι απλώς ένδειξη. Ο ίδιος έλεγχος ισχύει για root-owned [PHP built-in server](https://www.php.net/commandline.webserver) που ξεκινά με `-S` και `-t <document-root>`: ένας listener σε loopback μπορεί και πάλι να εκτελεί PHP εφαρμογής για τοπικά αιτήματα. Εξετάστε τη διεργασία και τον κώδικα χωρίς να ενεργοποιήσετε κανένα από τα δύο κατά την καταγραφή.

Ένα privileged PHP job μπορεί επίσης να διασχίσει το όριο μέσω **αρχείου δεδομένων**: αν χρήστης χαμηλότερων δικαιωμάτων μπορεί να αλλάξει το ακριβές αρχείο που περνά στην [`unserialize()`](https://www.php.net/manual/en/function.unserialize.php), η PHP μπορεί να καλέσει τη μέθοδο `__wakeup()` ή `__unserialize()` μιας φορτωμένης κλάσης κατά την επαναφορά αντικειμένου. Εξετάστε την ενεργή ταυτότητα του job, τα δικαιώματα αρχείου και γονικών καταλόγων, τις φορτωμένες κλάσεις και τις πραγματικές παρενέργειες των μεθόδων, όπως εγγραφή αρχείου που επιλέγεται από property. Ένα εγγράψιμο log ή μια κλήση `unserialize()` από μόνα τους δεν αποδεικνύουν αξιοποιήσιμη διαδρομή. Εξετάστε τον κώδικα και τα metadata χωρίς να γράψετε serialized input ή να εκτελέσετε το job κατά την καταγραφή.

Μια root cron εργασία μπορεί να καλεί **CLI page runner** εφαρμογής PHP αντί για τον web server. Ακολουθήστε το επιλεγμένο document root και URI του runner μέχρι το πραγματικό PHP entrypoint. Αν ο λογαριασμός της web υπηρεσίας μπορεί να γράψει σε αυτό το entrypoint, το προγραμματισμένο CLI request μπορεί να εκτελέσει τον τροποποιημένο κώδικά του ως root, ακόμη κι αν ο runner και το cron wrapper είναι read-only. Επιβεβαιώστε την ταυτότητα του scheduler, την ακριβή αντιστοίχιση URI σε αρχείο, τα ενεργά δικαιώματα αρχείου και γονικών καταλόγων, καθώς και αν έλεγχος ακεραιότητας προστατεύει το ίδιο το entrypoint. Εξετάστε τον κώδικα και τα metadata χωρίς να καλέσετε τον runner ή να αλλάξετε τη σελίδα κατά την καταγραφή.

Μια διεργασία `ipython` που ξεκινά από προγραμματισμένο job ή άλλον χρήστη σε κοινόχρηστο κατάλογο εργασίας χρειάζεται έλεγχο startup files. Οι [σημειώσεις έκδοσης ασφαλείας του IPython](https://ipython.readthedocs.io/en/8.25.0/whatsnew/version8.html#ipython-8-0-1-cve-2022-21699) εξηγούν ότι επηρεαζόμενα builds αναζητούσαν profiles και configuration στον τρέχοντα κατάλογο, συμπεριλαμβανομένου κώδικα στο `profile_default/startup`, πριν από τη διόρθωση του CVE-2022-21699. Συσχετίστε το πραγματικά εγκατεστημένο build ή vendor patch, τον κατάλογο εργασίας της εντολής, την ταυτότητα της διεργασίας με υψηλότερα δικαιώματα και τη δυνατότητα χρήστη χαμηλότερων δικαιωμάτων να γράψει και να αναζητήσει την ακριβή διαδρομή startup. Ένα εγκατεστημένο `ipython`, ένας εγγράψιμος κατάλογος ή μόνο μια συμβολοσειρά έκδοσης δεν αποδεικνύουν ότι άλλη ταυτότητα θα φορτώσει αρχείο από εκεί. Εξετάστε το schedule και τα metadata διαδρομών χωρίς να εκκινήσετε τον interpreter με υψηλότερα δικαιώματα.

Για privileged PHP server που καλεί συναρτήσεις custom native extension, προσδιορίστε το PHP SAPI της υπηρεσίας και το ενεργό `php.ini` μαζί με τα σαρωμένα αρχεία `.ini` πριν εξετάσετε την extension. Η [PHP φορτώνει τις ρυθμισμένες βιβλιοθήκες `extension` κατά την εκκίνηση](https://www.php.net/manual/en/ini.core.php), ενώ [τα CLI και web SAPI μπορεί να χρησιμοποιούν διαφορετικά αρχεία ρυθμίσεων](https://www.php.net/manual/en/configuration.file.php). Επομένως, μια προσβάσιμη φόρμα login ή ένας τοπικός listener μπορεί να περάσει strings ελεγχόμενα από χρήστη σε compiled code που εκτελείται με την ταυτότητα της υπηρεσίας. Καταγράψτε το `User=`, το `ExecStart=`, τον τρέχοντα κατάλογο εργασίας της μονάδας, την πραγματική διαδρομή extension και τα ορίσματα που ελέγχει ο καλών. Η απλή παρουσία ενός `.so` ή ενός socket loopback δεν αποδεικνύει flaw αλλοίωσης μνήμης. Αναλύστε ξεχωριστά κάθε custom parser, αντί να στέλνετε probes κατά την παθητική καταγραφή.

Όταν ένα privileged wrapper υπολογίζει hash script μέσω pathname και αργότερα ανοίγει ξανά αυτό το pathname για να το εκτελέσει, το digest πιστοποιεί μόνο το αντικείμενο που διαβάστηκε στο πρώτο άνοιγμα. Αν χρήστης χαμηλότερων δικαιωμάτων μπορεί να αντικαταστήσει την εγγραφή καταλόγου του script ανάμεσα στα δύο ανοίγματα, η μεταγενέστερη εκτέλεση μπορεί να επιλύσει διαφορετικό αντικείμενο, ακόμη κι αν το αρχικό αρχείο script είναι root-owned. Ένα FIFO μπορεί να επιμηκύνει τη φάση ελέγχου, αλλά η διαδρομή εξαρτάται από αντικαταστάσιμα δικαιώματα γονικού καταλόγου, από ξεχωριστά πραγματικά ανοίγματα, την ταυτότητα του scheduler, τους κανόνες sticky bit και mount, καθώς και τον χρονισμό. Εξετάστε το wrapper και την έξοδο `namei -l` ως παθητική ένδειξη. Ένας επιτυχής έλεγχος checksum δεν αποδεικνύει ότι προστατεύεται το pathname κατά τη μεταγενέστερη εκτέλεση.

Ένα privileged backup job μπορεί επίσης να **αποκαλύψει** δεδομένα χωρίς να εκτελέσει εντολές που παρέχει επιτιθέμενος. Εξετάστε αν χρήστης χαμηλότερων δικαιωμάτων μπορεί να δημιουργήσει control file που διαβάζει το job, αν το job ανοίγει στη συνέχεια προστατευμένη πηγή όπως το `/etc/shadow` και αν URL που επιλέγει επιτιθέμενος ή αναγνώσιμη έξοδος λαμβάνει το αποτέλεσμα. Επαληθεύστε και τα τρία μέρη προτού το χαρακτηρίσετε διαδρομή αποκάλυψης. Μια σταθερή shell command στο ίδιο script δεν καθιστά από μόνη της αυτό το control file είσοδο shell injection. Εξετάστε το script και τα δικαιώματα αρχείων χωρίς να εκτελέσετε το job ή να τοποθετήσετε control file κατά την καταγραφή.

Αν privileged scheduled job εκτελεί `curl -K FILE` ή `curl --config FILE`, [το curl αντιμετωπίζει τις επιλογές σε αυτό το αρχείο ως ορίσματα γραμμής εντολών](https://curl.se/docs/manpage.html). Χρήστης χαμηλότερων δικαιωμάτων που ελέγχει το ακριβές αρχείο όταν το διαβάζει το curl μπορεί να επηρεάσει το URL που ζητείται, την είσοδο τοπικού αρχείου ή τη διαδρομή εξόδου. Επιβεβαιώστε την ενεργή ταυτότητα του job, τα δικαιώματα εγγραφής στο αρχείο και στους γονικούς καταλόγους, τον χρονισμό οποιουδήποτε άλλου job που αντικαθιστά το αρχείο, καθώς και τον τρόπο με τον οποίο οι επιλογές config αλληλεπιδρούν με τις σταθερές επιλογές γραμμής εντολών, προτού ισχυριστείτε ότι υπάρχει προστατευμένη ανάγνωση ή εγγραφή. Μια διαδρομή config με δυνατότητα εγγραφής ή μια ορατή σημαία `-K` από μόνα τους δεν αποδεικνύουν ότι οι επιλεγμένες επιλογές εφαρμόζονται. Εξετάστε το schedule και τα metadata χωρίς να εκτελέσετε το job ή να κατεβάσετε URL κατά την παθητική καταγραφή.

Αν εγγραφή cron καλεί helper script, εξετάστε επίσης τον κατάλογο εργασίας του helper και την εντολή archive. Ένα μη περικλεισμένο σε εισαγωγικά wildcard σε κατάλογο όπου μπορεί να γράψει άλλος χρήστης μπορεί να μετατρέψει ονόματα αρχείων σε επιλογές archiver. Οι checkpoint actions του GNU tar είναι ένα παράδειγμα. Επιβεβαιώστε την ταυτότητα εκτέλεσης του scheduler, τον εγγράψιμο κατάλογο εισόδου, το ακριβές archiver και τις επιλογές, καθώς και αν το `--` τερματίζει την ανάλυση επιλογών, προτού ισχυριστείτε ότι υπάρχει διαδρομή εντολών μεταξύ χρηστών. Δείτε τη [συμπεριφορά wildcard και tar](../interesting-files-permissions/wildcards-spare-tricks.md).

Μια ξεχωριστή αποκάλυψη αρχείων backup μπορεί να προκύψει όταν privileged helper εκτελεί `cd INPUT_DIR; tar ... *` χωρίς να ελέγχει αν πέτυχε το `cd`. Αν χρήστης χαμηλότερων δικαιωμάτων μπορεί να αφαιρέσει ή να αντικαταστήσει το `INPUT_DIR`, αποτυχία του `cd` μπορεί να αφήσει το shell στον προηγούμενο κατάλογο, από τον οποίο μπορεί να διαβάσει η μεταγενέστερη εντολή archive. Επαληθεύστε τον αρχικό κατάλογο εργασίας του job, μια πραγματική διαδρομή αποτυχημένου `cd`, αν το script τερματίζει ή χρησιμοποιεί `&&`, τις ακριβείς επιλογές archiver και αν ο χρήστης χαμηλότερων δικαιωμάτων μπορεί να διαβάσει το αρχείο εξόδου. Ένας εγγράψιμος κατάλογος εισόδου ή ένα αναγνώσιμο archive από μόνα τους είναι μόνο ένδειξη. Εξετάστε το helper και τα δικαιώματα διαδρομής χωρίς να αλλάξετε το ενεργό job.

Ένα προγραμματισμένο εκτελέσιμο μπορεί να κρύβει shell script, χωρίς να αφαιρεί το όριο εμπιστοσύνης του: το [SHc](https://github.com/neurobin/shc) περιτυλίγει κρυπτογραφημένο κείμενο script σε native binary και το εκτελεί μέσω shell κατά την εκτέλεση. Επίθημα `.sh.x` ή αδιαφανές ELF είναι απλώς ένδειξη για εξέταση. Για την αξιολόγηση filename option injection, επιβεβαιώστε την ταυτότητα του privileged scheduler, τον πραγματικό κατάλογο εργασίας και την εντολή του helper, τη δυνατότητα χρήστη χαμηλότερων δικαιωμάτων να δημιουργεί ονόματα που ταιριάζουν εκεί και το αν μη περικλεισμένο glob φτάνει σε εντολή όπως το `rsync` χωρίς όριο επιλογών. Η [επιλογή remote-shell του `rsync`](../interesting-files-permissions/wildcards-spare-tricks.md#rsync) έχει σημασία μόνο αν χρησιμοποιείται αυτή η ακριβής διαδρομή εντολής. Περιορισμένη ορατότητα `/proc` ή αποτυχία στατικής αποκρυπτογράφησης αφήνουν άγνωστη την εντολή. Μην εκτελέσετε το privileged helper απλώς για να το ταξινομήσετε.

Το κείμενο γραμμής εντολών διεργασίας είναι άλλη μία μη έμπιστη είσοδος για privileged helper. Χρήστης χαμηλότερων δικαιωμάτων μπορεί να επιλέξει process title ή `argv[0]` που ταιριάζει στο `pgrep -f`. Ένα όνομα που ταιριάζει δεν πιστοποιεί το εκτελέσιμο ή τον ιδιοκτήτη του. Αν root-run script καταγράφει αυτό το κείμενο, ξαναγράφει μέρος του σε `apache2ctl`/`httpd` και εκτελεί το αποτέλεσμα χωρίς σταθερό πίνακα ορισμάτων, επιλογές που επιλέγει ο επιτιθέμενος μπορεί να ορίσουν διαφορετικό κατάλογο ρυθμίσεων ή error log. Η ανάλυση ρυθμίσεων Apache μπορεί να φορτώσει modules ή να φτάσει σε ρυθμισμένα helpers, επομένως μην επικυρώνετε μη έμπιστη ρύθμιση ως root κατά την καταγραφή. Εξετάστε τον ιδιοκτήτη του scheduler, τον ακριβή helper, την ταυτότητα της διεργασίας και τη ροή δεδομένων προς τα ορίσματα. Πρόκειται για injection επιλογών/ρυθμίσεων, εκτός αν αποδειχθεί ξεχωριστά εκτέλεση shell metacharacters.

Ένας root-run parser που περνά μη έμπιστο κείμενο σε Bash arithmetic μπορεί να εκτελέσει substitutions μέσα σε αυτό το κείμενο. Ο [οδηγός κλιμάκωσης δικαιωμάτων](../linux-basics/linux-privilege-escalation/README.md#bash-arithmetic-expansion-injection-in-cron-log-parsers) περιλαμβάνει ολοκληρωμένο παράδειγμα. Επιβεβαιώστε την πηγή εισόδου και την εντολή parsing προτού θεωρήσετε εκμεταλλεύσιμη κάθε αριθμητική έκφραση.

Για privileged job που αναλύει log εφαρμογής, ακολουθήστε τα μη έμπιστα πεδία και πέρα από την πρώτη ανάλυση. Λογαριασμός χαμηλότερων δικαιωμάτων μπορεί να έχει δυνατότητα εγγραφής στο log μέσω της τρέχουσας ομάδας διεργασίας του ή να επηρεάζει καταγεγραμμένα πεδία αιτημάτων. Μια εγγραφή μπορεί στη συνέχεια να επιλέξει εικόνα, τα metadata της οποίας γίνονται δεύτερο pathname για άνοιγμα XML. Ελέγξτε την ενεργή ταυτότητα του job, την πραγματική πρόσβαση εγγραφής στο log, τον χειρισμό οριοθετών, τον κανονικοποιημένο περιορισμό διαδρομής και το αν το επιλεγμένο XML ελέγχεται από τον επιτιθέμενο. Η επέκταση external entities μπορεί να μετατρέψει αυτή τη δεύτερη ανάγνωση σε αποκάλυψη privileged αρχείων, αν το αποτέλεσμα της επέκτασης φτάσει σε έξοδο αναγνώσιμη από χρήστη χαμηλότερων δικαιωμάτων. Ο [οδηγός ασφάλειας επεξεργασίας XML της Java](https://docs.oracle.com/en/java/javase/17/security/java-api-xml-processing-jaxp-security-guide.html) τεκμηριώνει ελέγχους για πρόσβαση σε external DTD/entity. Εξετάστε τον εγκατεστημένο parser και τις ενεργές ρυθμίσεις του. Ένα εγγράψιμο log ή XML αρχείο από μόνο του είναι απλώς ένδειξη. Εξετάστε τον κώδικα και τα metadata χωρίς να τροφοδοτήσετε τον προγραμματισμένο parser κατά την καταγραφή.

Εξετάστε επίσης privileged jobs που δημιουργούν αρχεία από το Git repository άλλου χρήστη. Ένα script μπορεί να χρησιμοποιεί `git ls-tree` και `git cat-file` αντί για `git checkout`, αλλά να εμπιστεύεται και πάλι διαδρομές tree ελεγχόμενες από επιτιθέμενο όταν τις συνενώνει με staging directory. Απόλυτες διαδρομές και στοιχεία `..` μπορούν να διαφύγουν από αυτόν τον κατάλογο, εκτός αν ο προορισμός κανονικοποιηθεί και ελεγχθεί ότι παραμένει εντός των ορίων πριν από την εγγραφή. Το `git -c safe.directory=*` επιτρέπει πρόσβαση σε repositories διαφορετικής ιδιοκτησίας. Δεν δημιουργεί από μόνο του συνθήκη αυθαίρετης εγγραφής.

Ένα root-run database backup μπορεί να δημιουργήσει άλλο όριο ιδιοκτησίας. Το PostgreSQL [`pg_basebackup`](https://www.postgresql.org/docs/14/app-pgbasebackup.html) αντιγράφει επιπλέον κανονικά αρχεία που τοποθετούνται στον κατάλογο δεδομένων της πηγής, ενώ η προεπιλεγμένη plain μορφή γράφει αρχεία στο `-D` ως δέντρο καταλόγων. Αν λογαριασμός χαμηλότερων δικαιωμάτων μπορεί να δημιουργήσει ή να τροποποιήσει αυτά τα αρχεία πηγής, εξετάστε την ιδιοκτησία και τα δικαιώματα του προορισμού που προκύπτει, αν η διαδρομή του είναι προσπελάσιμη και εκτελέσιμη, καθώς και αν το mount έχει `nosuid`. Αντίγραφο με ιδιοκτήτη root και διατηρημένα set-ID δικαιώματα μπορεί να είναι επικίνδυνο. Backup μόνο σε tar, αφαίρεση δικαιωμάτων ή μη προσβάσιμος προορισμός δεν τεκμηριώνουν την ίδια διαδρομή. Εξετάστε το προγραμματισμένο wrapper και τον ενεργό χρήστη προτού θεωρήσετε την εντολή backup εύρημα.

## Παρατήρηση εργασιών σύντομης διάρκειας

Ένα μοναδικό στιγμιότυπο διεργασιών μπορεί να χάσει job που εκτελείται για χιλιοστά του δευτερολέπτου. Συγκρίνετε τις δηλώσεις timer/cron με τα logs και, όταν υπάρχει εξουσιοδότηση, χρησιμοποιήστε παρακολούθηση συμβάντων διεργασιών όπως `pspy` ή audit. Συσχετίστε τον προγραμματισμένο ιδιοκτήτη, την ακριβή γραμμή εντολής και τα αρχεία που διαβάζει ή γράφει η εργασία. Το loopback web UI scheduler είναι ξεχωριστή διεπαφή. Δείτε το [παράδειγμα Crontab UI](../linux-basics/linux-privilege-escalation/README.md#crontab-ui-alseambusher-running-as-root--web-based-scheduler-privesc).
