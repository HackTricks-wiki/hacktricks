# Εκκίνηση shell, aliases και ιστορικό

{{#include ../../banners/hacktricks-training.md}}

Μια εντολή shell μπορεί να συμπεριφέρεται διαφορετικά από το εκτελέσιμο αρχείο με το ίδιο όνομα, αν ένα alias, μια συνάρτηση, ένα αρχείο εκκίνησης ή μια μεταβλητή περιβάλλοντος αλλάζει τον τρόπο εκτέλεσής της. Ελέγξτε τα παραπάνω πριν εμπιστευτείτε το αποτέλεσμα μιας εντολής ή υποθέσετε ότι ένα script χρησιμοποιεί το ίδιο PATH με μια διαδραστική συνεδρία.

## Επιθεώρηση του τρέχοντος shell

```bash
printf '%s\n' "$SHELL" "$PATH"
type -a ls sudo curl 2>/dev/null
alias
command -V python3
history | tail -50
```

Τα `type` και `command -V` αποκαλύπτουν αν ένα όνομα αντιστοιχεί σε alias, function, builtin ή αρχείο. Τα `command -v` και `which` ενδέχεται να μη δίνουν την ίδια εικόνα για aliases και functions. Το ιστορικό του shell μπορεί να εκθέσει εντολές ή διαπιστευτήρια, αλλά μπορεί να είναι ελλιπές, απενεργοποιημένο ή να παραμένει στη μνήμη μέχρι να τερματιστεί η συνεδρία.

## Ελέγξτε τα αρχεία εκκίνησης και ιστορικού

```bash
ls -la ~/.bashrc ~/.bash_profile ~/.profile ~/.zshrc ~/.zprofile ~/.bash_history ~/.zsh_history 2>/dev/null
ls -ld /etc/profile /etc/profile.d /etc/bash.bashrc 2>/dev/null
printenv HISTFILE HISTSIZE HISTCONTROL BASH_ENV ENV 2>/dev/null
```

Ένα αρχείο εκκίνησης που μπορεί να τροποποιήσει ένας χρήστης μπορεί να εκτελέσει εντολές κατά την επόμενη εκκίνηση του shell. Ένα καθολικό αρχείο εκκίνησης ή το αρχείο εκκίνησης ενός προνομιούχου χρήστη είναι πιο ευαίσθητο, αν ένας λογαριασμός με χαμηλότερα προνόμια μπορεί να το τροποποιήσει. Το μη διαδραστικό Bash μπορεί επίσης να διαβάσει το αρχείο που ορίζεται από το `BASH_ENV`· η σελίδα [μεταβλητές περιβάλλοντος](linux-environment-variables.md#bash_env--env) εξηγεί αυτή τη συμπεριφορά και άλλα hooks διερμηνευτών. Επαληθεύστε ποια αρχεία διαβάζει το πραγματικό shell για συνεδρίες σύνδεσης, διαδραστικές και μη διαδραστικές, προτού ισχυριστείτε ότι υπάρχει διαδρομή persistence.

Ελέγξτε επίσης τα αρχεία που γίνονται source από ένα καθολικό αρχείο εκκίνησης. Για παράδειγμα, ένα κυριολεκτικό `source /opt/app/venv/bin/activate` στο `/etc/bash.bashrc` εκτελεί το αρχείο ενεργοποίησης ως κώδικα shell, όταν το shell πράγματι διαβάζει αυτό το αρχείο εκκίνησης. Ελέγξτε το αρχείο ενεργοποίησης, τα δικαιώματα συμβολικών συνδέσμων και γονικών καταλόγων, καθώς και τα ACL· ένας χρήστης με χαμηλότερα προνόμια μπορεί να επηρεάσει ένα προνομιούχο shell μόνο αν αυτό το shell ή μια προνομιούχα εργασία κάνει αργότερα source το αρχείο. Αν η πρόσβαση εγγραφής εξαρτάται από το `sudoedit`, επαληθεύστε πρώτα τον ακριβή κανόνα sudoers και το εγκατεστημένο πακέτο sudo με τις τροποποιήσεις του προμηθευτή· από μόνο του, ένα upstream version string δεν τεκμηριώνει έκθεση σε [sudoedit argument-injection](../main-system-information/linux-privilege-escalation-checklist.md#sudo-and-suid-commands).

Ελέγξτε το ιστορικό, τα dotfiles και τα αντίγραφα ασφαλείας για μυστικά, όπως περιγράφεται στη σελίδα [χρήστες και συνεδρίες](../user-information/user-and-session-triage.md). Αν ένα προνομιούχο script εντοπίζει εντολές βάσει ονόματος, συνδυάστε αυτόν τον έλεγχο με τις [οδηγίες για PATH hijacking](linux-environment-variables.md#path).
