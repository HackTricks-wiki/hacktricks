# Εκκίνηση του shell, aliases και ιστορικό

{{#include ../../banners/hacktricks-training.md}}

Μια εντολή shell μπορεί να συμπεριφέρεται διαφορετικά από το εκτελέσιμο αρχείο με το ίδιο όνομα, αν ένα alias, μια συνάρτηση, ένα αρχείο εκκίνησης ή μια μεταβλητή περιβάλλοντος αλλάζει τον τρόπο εκτέλεσής της. Ελέγξτε τα παραπάνω πριν εμπιστευτείτε την έξοδο μιας εντολής ή υποθέσετε ότι ένα script χρησιμοποιεί το ίδιο PATH με μια διαδραστική συνεδρία.

## Επιθεώρηση του τρέχοντος shell

```bash
printf '%s\n' "$SHELL" "$PATH"
type -a ls sudo curl 2>/dev/null
alias
command -V python3
history | tail -50
```

Το `type` και το `command -V` αποκαλύπτουν αν ένα όνομα αντιστοιχεί σε alias, function, builtin ή αρχείο. Τα `command -v` και `which` μπορεί να μην εμφανίζουν το ίδιο αποτέλεσμα για aliases και functions. Το ιστορικό του shell μπορεί να αποκαλύψει εντολές ή διαπιστευτήρια, αλλά μπορεί να είναι ελλιπές, απενεργοποιημένο ή να παραμένει στη μνήμη μέχρι να τερματιστεί η συνεδρία.

## Εξέταση αρχείων εκκίνησης και ιστορικού

```bash
ls -la ~/.bashrc ~/.bash_profile ~/.profile ~/.zshrc ~/.zprofile ~/.bash_history ~/.zsh_history 2>/dev/null
ls -ld /etc/profile /etc/profile.d /etc/bash.bashrc 2>/dev/null
printenv HISTFILE HISTSIZE HISTCONTROL BASH_ENV ENV 2>/dev/null
```

Ένα αρχείο εκκίνησης εγγράψιμο από τον χρήστη μπορεί να εκτελέσει εντολές κατά την επόμενη εκκίνηση ενός shell. Ένα αρχείο εκκίνησης σε όλο το σύστημα ή ένα αρχείο εκκίνησης προνομιούχου χρήστη είναι πιο ευαίσθητο, αν μπορεί να το τροποποιήσει ένας λογαριασμός με χαμηλότερα προνόμια. Το μη διαδραστικό Bash μπορεί επίσης να διαβάσει το αρχείο που ορίζεται από το `BASH_ENV`· η σελίδα [environment variables](linux-environment-variables.md#bash_env--env) εξηγεί αυτή τη συμπεριφορά και άλλα hooks διερμηνέων. Επαληθεύστε ποια αρχεία διαβάζει το πραγματικό shell για συνεδρίες σύνδεσης, διαδραστικές και μη διαδραστικές, πριν ισχυριστείτε ότι υπάρχει διαδρομή persistence.

Επιθεωρήστε επίσης τα αρχεία που φορτώνονται από ένα καθολικό αρχείο εκκίνησης. Για παράδειγμα, ένα κυριολεκτικό `source /opt/app/venv/bin/activate` στο `/etc/bash.bashrc` εκτελεί το αρχείο ενεργοποίησης ως κώδικα shell, όταν ένα shell διαβάσει πράγματι αυτό το αρχείο εκκίνησης. Εξετάστε το αρχείο ενεργοποίησης, τα δικαιώματα του συμβολικού συνδέσμου και των γονικών καταλόγων, καθώς και τα ACL· ένας χρήστης με χαμηλότερα προνόμια μπορεί να επηρεάσει ένα προνομιούχο shell μόνο αν το shell ή μια προνομιούχα εργασία φορτώσει αργότερα αυτό το αρχείο. Αν η πρόσβαση εγγραφής εξαρτάται από το `sudoedit`, επαληθεύστε πρώτα τον ακριβή κανόνα sudoers και το εγκατεστημένο πακέτο sudo με τις τροποποιήσεις του προμηθευτή· μια συμβολοσειρά έκδοσης upstream από μόνη της δεν αποδεικνύει έκθεση σε [sudoedit argument-injection](../main-system-information/linux-privilege-escalation-checklist.md#sudo-and-suid-commands).

Ελέγξτε το ιστορικό, τα dotfiles και τα αντίγραφα ασφαλείας για μυστικά, όπως περιγράφεται στην ενότητα [users and sessions](../user-information/user-and-session-triage.md). Αν ένα προνομιούχο script επιλύει εντολές με βάση το όνομά τους, συνδυάστε αυτόν τον έλεγχο με τις [οδηγίες για PATH hijacking](linux-environment-variables.md#path).

## Ανακατεύθυνση εκκίνησης του Zsh και μεταγλωττισμένα αρχεία

Με τις προεπιλεγμένες ρυθμίσεις `RCS`, το zsh διαβάζει το `$ZDOTDIR/.zshenv` πριν από τις συνήθεις κλήσεις, συμπεριλαμβανομένων των `zsh -c` και των scripts· αν το `ZDOTDIR` δεν έχει οριστεί, χρησιμοποιεί το `$HOME`. Όταν ένας runner εντολών δέχεται έναν χάρτη περιβάλλοντος, ελέγξτε αν προωθεί κάποια από αυτές τις μεταβλητές σε μια προνομιούχα διεργασία zsh. Ένα εγγράψιμο `.zshenv` μπορεί τότε να εκτελεστεί **πριν** από το σώμα της εντολής που ελέγχει ή επιτρέπει ο runner. Αυτό απαιτεί η προνομιούχα διεργασία να κληρονομήσει τον ανακατευθυνόμενο κατάλογο· το `zsh -f` παρακάμπτει τα αρχεία εκκίνησης χρήστη, αλλά όχι το καθολικό `zshenv` (συχνά `/etc/zshenv`, αλλά οι διαδρομές διαφέρουν ανά διανομή). Η [σελίδα zsh injection του macOS](../../macos-hardening/macos-security-and-privilege-escalation/macos-proces-abuse/macos-bash-applications-injection.md#zsh-zdotdir) περιλαμβάνει ένα ελάχιστο παράδειγμα `ZDOTDIR`.<sup>[[1]](#references)[[2]](#references)</sup>

Ένα νεότερο και έγκυρο `.zshenv.zwc` ή `.zshrc.zwc` εκτελείται αντί για το αντίστοιχο αρχείο εκκίνησης απλού κειμένου. Αν μπορείτε να γράψετε στον κατάλογο εκκίνησης, η μεταγλώττιση ενός τροποποιημένου αρχείου και κατόπιν η επαναφορά ενός ακίνδυνου κειμένου μπορεί να αφήσει εκτελέσιμο κώδικα στο μεταγλωττισμένο αντίγραφο. Αυτό είναι απόκρυψη, όχι κρυπτογράφηση. Η δοκιμή που ακολουθεί, η οποία εκτελείται σε προσωρινό περιβάλλον, δείχνει γιατί δεν αρκεί η επιθεώρηση μόνο του αρχείου κειμένου· δεν επηρεάζει πραγματικό προσωπικό κατάλογο.<sup>[[1]](#references)[[3]](#references)[[4]](#references)</sup>

```bash
lab=$(mktemp -d)
printf '%s\n' 'print -r -- compiled > "$ZDOTDIR/result"' > "$lab/.zshenv"
zsh -f -c 'zcompile -R "$1"' _ "$lab/.zshenv"
printf '%s\n' 'print -r -- plaintext > "$ZDOTDIR/result"' > "$lab/.zshenv"
touch -d '2 minutes ago' "$lab/.zshenv"  # ensure the .zwc is newer
ZDOTDIR="$lab" zsh -c :
cat "$lab/result"  # compiled
zsh -f -c 'zcompile -t "$1"' _ "$lab/.zshenv.zwc"
```

Για έναν πραγματικό στόχο, εντοπίστε τις ενεργές τιμές των `ZDOTDIR`/`HOME`, ελέγξτε τόσο τα αρχεία κειμένου όσο και τα αρχεία `.zwc`, καθώς και τις χρονικές σημάνσεις, την ιδιοκτησία και τους εγγράψιμους γονικούς καταλόγους. Για να υπερισχύσει ένα αρχείο `.zwc`, πρέπει να αντιστοιχεί στο αρχείο πηγαίου κώδικα και να είναι νεότερο.<sup>[[1]](#references)[[3]](#references)</sup>
