# Запуск оболонки, псевдоніми та історія

{{#include ../../banners/hacktricks-training.md}}

Команда оболонки може поводитися інакше, ніж виконуваний файл із такою самою назвою, якщо псевдонім, функція, файл запуску або змінна середовища змінює спосіб її виконання. Перевірте їх, перш ніж довіряти виводу команди або припускати, що скрипт використовує той самий PATH, що й інтерактивний сеанс.

## Перевірка поточної оболонки

```bash
printf '%s\n' "$SHELL" "$PATH"
type -a ls sudo curl 2>/dev/null
alias
command -V python3
history | tail -50
```

`type` і `command -V` показують, чи відповідає ім’я alias, функції, builtin-команді або файлу. `command -v` і `which` можуть показувати різні результати для alias і функцій. Історія shell може розкрити команди або облікові дані, але вона може бути неповною, вимкненою або зберігатися в пам’яті до завершення сеансу.

## Перевірка файлів запуску та історії

```bash
ls -la ~/.bashrc ~/.bash_profile ~/.profile ~/.zshrc ~/.zprofile ~/.bash_history ~/.zsh_history 2>/dev/null
ls -ld /etc/profile /etc/profile.d /etc/bash.bashrc 2>/dev/null
printenv HISTFILE HISTSIZE HISTCONTROL BASH_ENV ENV 2>/dev/null
```

Файл запуску, доступний для запису користувачу, може виконувати команди під час наступного запуску shell. Загальносистемний файл запуску або файл запуску привілейованого користувача є чутливішим, якщо його може змінювати обліковий запис із нижчими привілеями. Неінтерактивний Bash також може читати файл, указаний у `BASH_ENV`; на сторінці [змінні середовища](linux-environment-variables.md#bash_env--env) описано цю поведінку та інші хуки інтерпретатора. Перш ніж стверджувати, що це шлях закріплення, перевірте, які саме файли читає фактичний shell під час входу в систему, в інтерактивних і неінтерактивних сеансах.

Також перевірте файли, які підключає загальний файл запуску. Наприклад, рядок `source /opt/app/venv/bin/activate` у `/etc/bash.bashrc` виконує файл активації як shell-код, коли shell справді читає цей файл запуску. Перевірте файл активації, права на символьне посилання та батьківські каталоги, а також ACL; користувач із нижчими привілеями може вплинути на привілейований shell лише тоді, коли цей shell або привілейоване завдання згодом підключає цей файл. Якщо доступ на запис залежить від `sudoedit`, спершу перевірте точне правило sudoers і встановлений пакет sudo із виправленнями постачальника; самого рядка версії upstream недостатньо, щоб підтвердити [вразливість sudoedit до ін'єкції аргументів](../main-system-information/linux-privilege-escalation-checklist.md#sudo-and-suid-commands).

Перевірте історію команд, dotfiles і резервні копії на наявність секретів, як описано в розділі [користувачі та сеанси](../user-information/user-and-session-triage.md). Якщо привілейований скрипт шукає команди за назвою, доповніть цю перевірку [рекомендаціями щодо перехоплення PATH](linux-environment-variables.md#path).
