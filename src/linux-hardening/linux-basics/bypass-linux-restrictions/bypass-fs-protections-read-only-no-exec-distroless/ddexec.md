# DDexec / EverythingExec

{{#include ../../../../banners/hacktricks-training.md}}

## Πλαίσιο

Το Linux εκτελεί συνήθως προγράμματα από εκτελέσιμα αρχεία που είναι αποθηκευμένα στον δίσκο ή στη μνήμη. Μπορεί να αναγνωρίσει ένα εκτελέσιμο μέσω της διαδρομής του ή ενός file descriptor, επομένως δεν απαιτείται πάντα μια συνηθισμένη διαδρομή συστήματος αρχείων.<sup>[[2]](#references)</sup>

Το DDexec / EverythingExec χρησιμοποιεί τη μνήμη μιας **ήδη εκτελούμενης διεργασίας**. Η σελίδα [Linux Fileless Execution](../../../post-exploitation/linux-fileless-execution.md) καλύπτει την εκτέλεση μέσω ανώνυμων αρχείων και τις σχετικές μεθόδους ανίχνευσης και συλλογής εγκληματολογικών στοιχείων. Η [επισκόπηση Memory Bypasses](index.html#memory-bypasses) περιλαμβάνει επίσης συνδέσμους προς τα MemExec και Memdlopen.<sup>[[1]](#references)</sup>

Αυτή η τεχνική σάς επιτρέπει να **παρακάμπτετε συνήθεις τεχνικές προστασίας, όπως read-only, noexec, λευκές λίστες ονομάτων αρχείων και λευκές λίστες hash**.<sup>[[1]](#references)</sup>

## Εξαρτήσεις

Για να λειτουργήσει, το τελικό script εξαρτάται από τα παρακάτω εργαλεία, τα οποία πρέπει να είναι προσβάσιμα στο σύστημα που επιτίθεστε (από προεπιλογή, θα τα βρείτε παντού):

```
dd
bash | zsh | ash (busybox)
head
tail
cut
grep
od
readlink
wc
tr
base64
```

## Η τεχνική

Αν μπορείτε να τροποποιήσετε αυθαίρετα τη μνήμη μιας διεργασίας, μπορείτε να την καταλάβετε. Αυτό μπορεί να χρησιμοποιηθεί για να καταλάβετε μια ήδη υπάρχουσα διεργασία και να την αντικαταστήσετε με ένα άλλο πρόγραμμα. Μπορούμε να το πετύχουμε είτε χρησιμοποιώντας το syscall `ptrace()` (κάτι που απαιτεί να μπορείτε να εκτελέσετε syscalls ή να είναι διαθέσιμο το gdb στο σύστημα) είτε, πιο ενδιαφέροντα, γράφοντας στο `/proc/$pid/mem`.<sup>[[1]](#references)</sup>

Το αρχείο `/proc/$pid/mem` είναι μια αντιστοίχιση ένα προς ένα ολόκληρου του χώρου διευθύνσεων μιας διεργασίας (_π.χ._ από `0x0000000000000000` έως `0x7ffffffffffff000` στο x86-64). Αυτό σημαίνει ότι η ανάγνωση ή η εγγραφή σε αυτό το αρχείο στη μετατόπιση `x` είναι το ίδιο με την ανάγνωση ή την τροποποίηση των περιεχομένων στην εικονική διεύθυνση `x`.

Τώρα, υπάρχουν τέσσερα βασικά προβλήματα που πρέπει να αντιμετωπίσουμε:

- Γενικά, μόνο ο root και ο κάτοχος του αρχείου που είναι το πρόγραμμα μπορούν να το τροποποιήσουν.
- ASLR.
- Αν προσπαθήσουμε να διαβάσουμε ή να γράψουμε σε μια διεύθυνση που δεν είναι αντιστοιχισμένη στον χώρο διευθύνσεων του προγράμματος, θα λάβουμε σφάλμα I/O.

Αυτά τα προβλήματα έχουν λύσεις που, αν και δεν είναι τέλειες, είναι καλές:

- Οι περισσότεροι interpreters κελύφους επιτρέπουν τη δημιουργία file descriptors, οι οποίοι στη συνέχεια κληρονομούνται από τις θυγατρικές διεργασίες. Μπορούμε να δημιουργήσουμε ένα fd που δείχνει στο αρχείο `mem` του shell με δικαιώματα εγγραφής... έτσι, οι θυγατρικές διεργασίες που χρησιμοποιούν αυτό το fd θα μπορούν να τροποποιούν τη μνήμη του shell.
- Το ASLR δεν αποτελεί καν πρόβλημα· μπορούμε να ελέγξουμε το αρχείο `maps` του shell ή οποιοδήποτε άλλο αρχείο από το procfs, ώστε να αποκτήσουμε πληροφορίες για τον χώρο διευθύνσεων της διεργασίας.
- Επομένως, πρέπει να κάνουμε `lseek()` στο αρχείο. Αυτό δεν μπορεί να γίνει από το shell, εκτός αν χρησιμοποιήσουμε το διαβόητο `dd`.

### Αναλυτικότερα

Τα βήματα είναι σχετικά εύκολα και δεν απαιτούν εξειδικευμένες γνώσεις για να γίνουν κατανοητά:<sup>[[1]](#references)</sup>

- Αναλύστε το binary που θέλουμε να εκτελέσουμε και τον loader, για να διαπιστώσετε ποιες αντιστοιχίσεις χρειάζονται. Έπειτα δημιουργήστε ένα "shell"code που θα εκτελεί, σε γενικές γραμμές, τα ίδια βήματα με αυτά που εκτελεί ο kernel σε κάθε κλήση `execve()`:
  - Δημιουργήστε τις εν λόγω αντιστοιχίσεις.
  - Διαβάστε τα binaries μέσα σε αυτές.
  - Ορίστε τα δικαιώματα.
  - Τέλος, αρχικοποιήστε τη στοίβα με τα ορίσματα του προγράμματος και τοποθετήστε το auxiliary vector (που χρειάζεται ο loader).
  - Μεταβείτε στον loader και αφήστε τον να κάνει τα υπόλοιπα (να φορτώσει τις βιβλιοθήκες που χρειάζεται το πρόγραμμα).
- Αποκτήστε από το αρχείο `syscall` τη διεύθυνση στην οποία θα επιστρέψει η διεργασία μετά το syscall που εκτελεί.
- Αντικαταστήστε εκείνο το σημείο, το οποίο θα είναι εκτελέσιμο, με το shellcode μας (μέσω του `mem` μπορούμε να τροποποιήσουμε σελίδες χωρίς δικαιώματα εγγραφής).
- Περάστε το πρόγραμμα που θέλουμε να εκτελέσουμε στο stdin της διεργασίας (θα γίνει `read()` από το εν λόγω "shell"code).
- Σε αυτό το σημείο, ο loader θα φορτώσει τις απαραίτητες βιβλιοθήκες για το πρόγραμμά μας και θα μεταβεί σε αυτό.

**Δείτε το εργαλείο στο** [**https://github.com/arget13/DDexec**](https://github.com/arget13/DDexec).<sup>[[1]](#references)</sup>

## EverythingExec

Υπάρχουν αρκετές εναλλακτικές του `dd`, μία από τις οποίες, το `tail`, είναι αυτήν τη στιγμή το προεπιλεγμένο πρόγραμμα που χρησιμοποιείται για να κάνει `lseek()` στο αρχείο `mem` (αυτή ήταν η μόνη χρήση του `dd`). Οι εν λόγω εναλλακτικές είναι:<sup>[[1]](#references)</sup>

```bash
tail
hexdump
cmp
xxd
```

Ορίζοντας τη μεταβλητή `SEEKER`, μπορείτε να αλλάξετε τον seeker που χρησιμοποιείται, _π.χ._:

```bash
SEEKER=cmp bash ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)
```

Αν βρείτε κάποιον άλλο έγκυρο seeker που δεν έχει υλοποιηθεί στο script, μπορείτε και πάλι να τον χρησιμοποιήσετε ορίζοντας τη μεταβλητή `SEEKER_ARGS`:

```bash
SEEKER=xxd SEEKER_ARGS='-s $offset' zsh ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)
```

Μπλοκάρετέ το, EDRs.
