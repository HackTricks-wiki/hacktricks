# DDexec / EverythingExec

## Context

Στο Linux, για να εκτελεστεί ένα πρόγραμμα, πρέπει να υπάρχει ως αρχείο και να είναι προσβάσιμο με κάποιον τρόπο μέσω της ιεραρχίας του file system (έτσι λειτουργεί το `execve()`). Αυτό το αρχείο μπορεί να βρίσκεται στον δίσκο ή στη RAM (tmpfs, memfd), αλλά χρειάζεσαι ένα filepath. Αυτό έχει κάνει πολύ εύκολο τον έλεγχο του τι εκτελείται σε ένα Linux σύστημα, καθώς και τον εντοπισμό threats και των tools του attacker ή την πλήρη αποτροπή της προσπάθειάς τους να εκτελέσουν οτιδήποτε δικό τους (_π.χ._ απαγορεύοντας σε unprivileged users να τοποθετούν executable files οπουδήποτε).

Όμως, αυτή η technique έρχεται για να αλλάξει όλα αυτά. Αν δεν μπορείς να εκκινήσεις το process που θέλεις... **τότε κάνεις hijack ένα που υπάρχει ήδη**.

Αυτή η technique σου επιτρέπει να **κάνεις bypass common protection techniques, όπως read-only, noexec, file-name whitelisting και hash whitelisting**.<sup>[[1]](#references)</sup>

## Dependencies

Το τελικό script εξαρτάται από τα παρακάτω tools για να λειτουργήσει· πρέπει να είναι προσβάσιμα στο σύστημα που επιτίθεσαι (από προεπιλογή, θα βρεις όλα αυτά παντού):
```

```
## Η τεχνική

Αν μπορείτε να τροποποιήσετε αυθαίρετα τη μνήμη μιας διεργασίας, τότε μπορείτε να την αναλάβετε. Αυτό μπορεί να χρησιμοποιηθεί για την παραβίαση μιας ήδη υπάρχουσας διεργασίας και την αντικατάστασή της με ένα άλλο πρόγραμμα. Αυτό μπορεί να επιτευχθεί είτε χρησιμοποιώντας το syscall `ptrace()` (το οποίο απαιτεί να έχετε τη δυνατότητα εκτέλεσης syscalls ή να υπάρχει διαθέσιμο το gdb στο σύστημα) είτε, πιο ενδιαφέροντα, γράφοντας στο `/proc/$pid/mem`.<sup>[[1]](#references)</sup>

Το αρχείο `/proc/$pid/mem` είναι μια αντιστοίχιση ένα προς ένα ολόκληρου του address space μιας διεργασίας (_π.χ._ από `0x0000000000000000` έως `0x7ffffffffffff000` σε x86-64). Αυτό σημαίνει ότι η ανάγνωση ή η εγγραφή σε αυτό το αρχείο, σε offset `x`, ισοδυναμεί με την ανάγνωση ή την τροποποίηση των περιεχομένων στην virtual address `x`.

Τώρα, έχουμε τέσσερα βασικά προβλήματα να αντιμετωπίσουμε:

- Γενικά, μόνο ο root και ο owner του αρχείου μπορούν να το τροποποιήσουν.
- ASLR.
- Αν προσπαθήσουμε να διαβάσουμε ή να γράψουμε σε μια address που δεν είναι mapped στο address space του προγράμματος, θα λάβουμε σφάλμα I/O.

Αυτά τα προβλήματα έχουν λύσεις οι οποίες, αν και δεν είναι τέλειες, είναι ικανοποιητικές:

- Οι περισσότεροι shell interpreters επιτρέπουν τη δημιουργία file descriptors που στη συνέχεια κληρονομούνται από child processes. Μπορούμε να δημιουργήσουμε ένα fd που δείχνει στο αρχείο `mem` του shell, με write permissions... έτσι τα child processes που χρησιμοποιούν αυτό το fd θα μπορούν να τροποποιούν τη μνήμη του shell.
- Το ASLR δεν αποτελεί καν πρόβλημα· μπορούμε να ελέγξουμε το αρχείο `maps` του shell ή οποιοδήποτε άλλο αρχείο από το procfs, ώστε να αποκτήσουμε πληροφορίες για το address space της διεργασίας.
- Επομένως, πρέπει να κάνουμε `lseek()` πάνω στο αρχείο. Από το shell αυτό δεν μπορεί να γίνει, εκτός αν χρησιμοποιήσουμε το διαβόητο `dd`.

### Πιο αναλυτικά

Τα βήματα είναι σχετικά εύκολα και δεν απαιτούν κάποιου είδους εξειδίκευση για να γίνουν κατανοητά:<sup>[[1]](#references)</sup>

- Κάντε parse το binary που θέλουμε να εκτελέσουμε και τον loader, ώστε να εντοπίσουμε ποια mappings χρειάζονται. Στη συνέχεια, δημιουργήστε ένα "shell"code που θα εκτελεί, σε γενικές γραμμές, τα ίδια βήματα με αυτά που εκτελεί ο kernel σε κάθε κλήση του `execve()`:
- Δημιουργήστε τα συγκεκριμένα mappings.
- Διαβάστε τα binaries μέσα σε αυτά.
- Ρυθμίστε τα permissions.
- Τέλος, αρχικοποιήστε το stack με τα arguments του προγράμματος και τοποθετήστε το auxiliary vector (που απαιτείται από τον loader).
- Κάντε jump στον loader και αφήστε τον να ολοκληρώσει τα υπόλοιπα (να φορτώσει τις libraries που χρειάζεται το πρόγραμμα).
- Αποκτήστε από το αρχείο `syscall` τη διεύθυνση στην οποία θα επιστρέψει η διεργασία μετά το syscall που εκτελεί.
- Κάντε overwrite εκείνο το σημείο, το οποίο θα είναι executable, με το shellcode μας (μέσω του `mem` μπορούμε να τροποποιήσουμε unwritable pages).
- Περάστε το πρόγραμμα που θέλουμε να εκτελέσουμε στο stdin της διεργασίας (θα γίνει `read()` από το συγκεκριμένο "shell"code).
- Σε αυτό το σημείο, εναπόκειται στον loader να φορτώσει τις απαραίτητες libraries για το πρόγραμμά μας και να κάνει jump σε αυτό.

**Δείτε το tool στο** [**https://github.com/arget13/DDexec**](https://github.com/arget13/DDexec).<sup>[[1]](#references)</sup>

## EverythingExec

Υπάρχουν αρκετές εναλλακτικές του `dd`, μία από τις οποίες, το `tail`, είναι επί του παρόντος το default πρόγραμμα που χρησιμοποιείται για να κάνει `lseek()` μέσα στο αρχείο `mem` (κάτι που αποτελούσε τον μοναδικό λόγο χρήσης του `dd`). Αυτές οι εναλλακτικές είναι:<sup>[[1]](#references)</sup>
```bash
tail
hexdump
cmp
xxd
```
Ορίζοντας τη μεταβλητή `SEEKER`, μπορείτε να αλλάξετε το seeker που χρησιμοποιείται, _π.χ._:
```bash
SEEKER=cmp bash ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)
```
Αν βρείτε άλλο έγκυρο seeker που δεν έχει υλοποιηθεί στο script, μπορείτε να το χρησιμοποιήσετε ορίζοντας τη μεταβλητή `SEEKER_ARGS`:
```bash
SEEKER=xxd SEEKER_ARGS='-s $offset' zsh ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)
```
Μπλοκάρετέ το, EDRs.
