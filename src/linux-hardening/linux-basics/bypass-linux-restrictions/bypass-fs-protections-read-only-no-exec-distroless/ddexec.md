# DDexec / EverythingExec

{{#include ../../../../banners/hacktricks-training.md}}

## Контекст

У Linux, щоб запустити програму, вона має існувати як файл і бути певним чином доступною через ієрархію файлової системи (саме так працює `execve()`). Цей файл може зберігатися на диску або в RAM (tmpfs, memfd), але вам потрібен filepath. Це дуже спрощує контроль того, що запускається в Linux-системі, полегшує виявлення загроз та інструментів атакувальника або взагалі запобігає спробам їх виконання (_наприклад_, заборона непривілейованим користувачам розміщувати виконувані файли будь-де).

Але ця техніка покликана все це змінити. Якщо ви не можете запустити потрібний процес... **тоді ви захоплюєте вже наявний**.

Ця техніка дає змогу **обійти поширені захисні механізми, такі як read-only, noexec, file-name whitelisting і hash whitelisting**.<sup>[[1]](#references)</sup>

## Залежності

Фінальний скрипт залежить від наведених нижче інструментів для роботи; вони мають бути доступні в системі, яку ви атакуєте (за замовчуванням ви знайдете їх усі практично всюди):
```
dd
bash | zsh | ash (busybox)
head
tail
cut
grep
od
readlink
wc
tr
base64
```
## Техніка

Якщо ви можете довільно змінювати пам'ять процесу, то можете взяти його під контроль. Це можна використати для викрадення вже наявного процесу та його заміни іншою програмою. Цього можна досягти або за допомогою syscall `ptrace()` (для цього потрібно мати можливість виконувати syscall або мати `gdb` у системі), або, що цікавіше, записуючи дані до `/proc/$pid/mem`.<sup>[[1]](#references)</sup>

Файл `/proc/$pid/mem` є однозначним відображенням усього адресного простору процесу (_напр._ від `0x0000000000000000` до `0x7ffffffffffff000` в x86-64). Це означає, що читання з цього файлу або запис до нього за зміщенням `x` еквівалентні читанню або зміні вмісту за віртуальною адресою `x`.

Тепер нам потрібно розв'язати чотири основні проблеми:

- Загалом лише root і власник програми можуть змінювати цей файл.
- ASLR.
- Якщо спробувати читати або записувати за адресою, не відображеною в адресному просторі програми, ми отримаємо помилку введення-виведення.

Ці проблеми мають рішення, які, хоча й не є ідеальними, добре працюють:

- Більшість shell-інтерпретаторів дозволяють створювати файлові дескриптори, які потім успадковуються дочірніми процесами. Ми можемо створити fd, що вказує на файл `mem` shell із дозволами на запис... тоді дочірні процеси, які використовують цей fd, зможуть змінювати пам'ять shell.
- ASLR взагалі не є проблемою: ми можемо перевірити файл `maps` shell або будь-який інший файл у procfs, щоб отримати інформацію про адресний простір процесу.
- Отже, нам потрібно виконати `lseek()` у файлі. З shell це неможливо зробити без використання сумнозвісної `dd`.

### Детальніше

Кроки відносно прості, і для їх розуміння не потрібні спеціальні знання:<sup>[[1]](#references)</sup>

- Проаналізувати binary, яку ми хочемо запустити, і loader, щоб визначити, які mappings їм потрібні. Потім створити shellcode, який, загалом, виконуватиме ті самі кроки, що й kernel під час кожного виклику `execve()`:
- Створити зазначені mappings.
- Прочитати binary у них.
- Налаштувати permissions.
- Нарешті, ініціалізувати stack аргументами для програми та розмістити auxiliary vector (потрібний loader).
- Перейти до loader і дозволити йому виконати решту (завантажити libraries, потрібні програмі).
- Отримати з файлу `syscall` адресу, на яку процес повернеться після syscall, що виконується.
- Перезаписати це місце, яке буде executable, нашим shellcode (через `mem` можна змінювати unwritable pages).
- Передати програму, яку ми хочемо запустити, у stdin процесу (цей "shell"code виконає `read()`).
- На цьому етапі loader має завантажити необхідні libraries для нашої програми та перейти до неї.

**Перегляньте tool у** [**https://github.com/arget13/DDexec**](https://github.com/arget13/DDexec).<sup>[[1]](#references)</sup>

## EverythingExec

Існує кілька альтернатив `dd`, одна з яких, `tail`, наразі є програмою за замовчуванням для виконання `lseek()` у файлі `mem` (саме для цього використовувалася `dd`). Ці альтернативи такі:<sup>[[1]](#references)</sup>
```bash
tail
hexdump
cmp
xxd
```
Встановивши змінну `SEEKER`, ви можете змінити використовуваний seeker, _наприклад_:
```bash
SEEKER=cmp bash ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)
```
Якщо ви знайдете інший дійсний seeker, не реалізований у скрипті, ви все одно можете використовувати його, задавши змінну `SEEKER_ARGS`:
```bash
SEEKER=xxd SEEKER_ARGS='-s $offset' zsh ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)
```
Заблокуйте це, EDR-системи.
