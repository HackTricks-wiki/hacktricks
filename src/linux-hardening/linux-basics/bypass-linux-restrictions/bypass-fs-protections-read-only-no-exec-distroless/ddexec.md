# DDexec / EverythingExec

{{#include ../../../../banners/hacktricks-training.md}}

## Πλαίσιο

Στο Linux, για να εκτελεστεί ένα πρόγραμμα, πρέπει να υπάρχει ως αρχείο και να είναι με κάποιον τρόπο προσβάσιμο μέσω της ιεραρχίας του file system (έτσι ακριβώς λειτουργεί το `execve()`). Αυτό το αρχείο μπορεί να βρίσκεται στον δίσκο ή στη RAM (tmpfs, memfd), αλλά χρειάζεσαι ένα filepath. Αυτό έχει κάνει πολύ εύκολο τον έλεγχο του τι εκτελείται σε ένα Linux system, διευκολύνει τον εντοπισμό threats και εργαλείων του attacker ή την πλήρη αποτροπή της προσπάθειάς τους να εκτελέσουν οτιδήποτε δικό τους (_π.χ._ να μην επιτρέπεται σε unprivileged users να τοποθετούν executable files οπουδήποτε).

Όμως αυτή η τεχνική έρχεται για να αλλάξει όλα αυτά. Αν δεν μπορείς να ξεκινήσεις το process που θέλεις... **τότε κάνεις hijack ένα που υπάρχει ήδη**.

Αυτή η τεχνική επιτρέπει να **παρακάμψεις common protection techniques όπως read-only, noexec, file-name whitelisting, hash whitelisting...**<sup>[[1]](#references)</sup>

## Εξαρτήσεις

Το τελικό script εξαρτάται από τα παρακάτω tools για να λειτουργήσει· πρέπει να είναι προσβάσιμα στο system που επιτίθεσαι (από προεπιλογή θα βρεις όλα αυτά παντού):

## Η τεχνική

Αν μπορείτε να τροποποιήσετε αυθαίρετα τη μνήμη μιας διεργασίας, τότε μπορείτε να την αναλάβετε. Αυτό μπορεί να χρησιμοποιηθεί για την παρεμβολή σε μια ήδη υπάρχουσα διεργασία και την αντικατάστασή της με ένα άλλο πρόγραμμα. Αυτό μπορεί να επιτευχθεί είτε μέσω του syscall `ptrace()` (το οποίο απαιτεί να έχετε τη δυνατότητα εκτέλεσης syscalls ή να υπάρχει διαθέσιμο το gdb στο σύστημα) είτε, πιο ενδιαφέρον, με εγγραφή στο `/proc/$pid/mem`.<sup>[[1]](#references)</sup>

Το αρχείο `/proc/$pid/mem` είναι μια αντιστοίχιση ένα-προς-ένα ολόκληρου του address space μιας διεργασίας (_π.χ._ από `0x0000000000000000` έως `0x7ffffffffffff000` σε x86-64). Αυτό σημαίνει ότι η ανάγνωση από ή η εγγραφή σε αυτό το αρχείο στη θέση `x` είναι ίδια με την ανάγνωση ή την τροποποίηση των περιεχομένων στην virtual address `x`.

Τώρα, έχουμε τέσσερα βασικά προβλήματα να αντιμετωπίσουμε:

- Γενικά, μόνο ο root και ο program owner του αρχείου μπορούν να το τροποποιήσουν.
- ASLR.
- Αν προσπαθήσουμε να διαβάσουμε ή να γράψουμε σε μια address που δεν είναι mapped στο address space του προγράμματος, θα λάβουμε ένα I/O error.

Αυτά τα προβλήματα έχουν λύσεις οι οποίες, αν και δεν είναι τέλειες, είναι ικανοποιητικές:

- Οι περισσότεροι shell interpreters επιτρέπουν τη δημιουργία file descriptors, οι οποίοι στη συνέχεια κληρονομούνται από child processes. Μπορούμε να δημιουργήσουμε ένα fd που δείχνει στο `mem` file του shell με write permissions... έτσι, τα child processes που χρησιμοποιούν αυτό το fd θα μπορούν να τροποποιήσουν τη μνήμη του shell.
- Το ASLR δεν αποτελεί καν πρόβλημα· μπορούμε να ελέγξουμε το `maps` file του shell ή οποιοδήποτε άλλο από το procfs, ώστε να αποκτήσουμε πληροφορίες για το address space της διεργασίας.
- Επομένως, πρέπει να εκτελέσουμε `lseek()` πάνω στο αρχείο. Από το shell αυτό δεν μπορεί να γίνει, εκτός αν χρησιμοποιήσουμε το διαβόητο `dd`.

### Αναλυτικότερα

Τα βήματα είναι σχετικά απλά και δεν απαιτούν κανενός είδους εξειδίκευση για να τα κατανοήσετε:<sup>[[1]](#references)</sup>

- Κάντε parse το binary που θέλουμε να εκτελέσουμε και το loader, ώστε να διαπιστώσουμε ποια mappings χρειάζονται. Στη συνέχεια, δημιουργήστε έναν "shell"code που θα εκτελεί, σε γενικές γραμμές, τα ίδια βήματα με αυτά που εκτελεί ο kernel σε κάθε κλήση στο `execve()`:
- Δημιουργήστε τα εν λόγω mappings.
- Διαβάστε τα binaries μέσα σε αυτά.
- Ορίστε τα permissions.
- Τέλος, αρχικοποιήστε το stack με τα arguments του προγράμματος και τοποθετήστε το auxiliary vector (το οποίο απαιτείται από τον loader).
- Κάντε jump στον loader και αφήστε τον να κάνει τα υπόλοιπα (να φορτώσει τις libraries που απαιτούνται από το πρόγραμμα).
- Αποκτήστε από το `syscall` file τη διεύθυνση στην οποία θα επιστρέψει η διεργασία μετά το syscall που εκτελεί.
- Αντικαταστήστε εκείνο το σημείο, το οποίο θα είναι executable, με το shellcode μας (μέσω του `mem` μπορούμε να τροποποιήσουμε unwritable pages).
- Περάστε το πρόγραμμα που θέλουμε να εκτελέσουμε στο stdin της διεργασίας (θα γίνει `read()` από το εν λόγω "shell"code).
- Σε αυτό το σημείο, είναι ευθύνη του loader να φορτώσει τις απαραίτητες libraries για το πρόγραμμά μας και να κάνει jump σε αυτό.

**Δείτε το tool στο** [**https://github.com/arget13/DDexec**](https://github.com/arget13/DDexec)<sup>[[1]](#references)</sup>

## EverythingExec

Υπάρχουν αρκετές εναλλακτικές του `dd`, μία από τις οποίες, το `tail`, είναι σήμερα το default πρόγραμμα που χρησιμοποιείται για την εκτέλεση `lseek()` μέσα στο `mem` file (που ήταν ο μοναδικός λόγος για τη χρήση του `dd`). Οι εν λόγω εναλλακτικές είναι:<sup>[[1]](#references)</sup>
```bash
tail
hexdump
cmp
xxd
```
Ορίζοντας τη μεταβλητή `SEEKER`, μπορείτε να αλλάξετε το seeker που χρησιμοποιείται, _π.χ._:
```bash
SEEKER=cmp bash ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)
```
Αν βρείτε κάποιον άλλο έγκυρο seeker που δεν έχει υλοποιηθεί στο script, μπορείτε να τον χρησιμοποιήσετε ορίζοντας τη μεταβλητή `SEEKER_ARGS`:
```bash
SEEKER=xxd SEEKER_ARGS='-s $offset' zsh ddexec.sh ls -l <<< $(base64 -w0 /bin/ls)
```
Μπλοκάρετέ το, EDRs.
