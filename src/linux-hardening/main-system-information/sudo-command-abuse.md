## Interpreteri dozvoljeni preko sudo

Ako `sudo -l` dozvoljava korisniku da pokrene interpreter kao root, tretirajte to kao direktno izvršavanje koda. Interpreteri su namenjeni izvršavanju proizvoljnog koda, pa je pravilo koje dozvoljava `python3`, `perl`, `ruby`, `lua`, `node` ili slične binarne datoteke obično ekvivalentno izvršavanju root komandi, osim ako argumenti nisu strogo ograničeni i provereni.<sup>[[1]](#references)[[2]](#references)[[3]](#references)[[4]](#references)[[5]](#references)[[7]](#references)[[9]](#references)[[11]](#references)</sup>

Uobičajeni postupak provere: prvo izlistajte privilegije korisnika, a zatim izvršite Python naredbu pomoću opcije `-c` interpretera.<sup>[[1]](#references)[[3]](#references)[[4]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/python3 -c 'import os; os.system("id")'
sudo /usr/bin/python3 -c 'import os; os.system("/bin/sh")'
```

Drugi primeri interpretera prikazani su u nastavku; navedeni interpreteri dokumentuju izvršavanje inline koda ili API-je za podređene procese.<sup>[[5]](#references)[[6]](#references)[[7]](#references)[[8]](#references)[[9]](#references)[[10]](#references)[[11]](#references)</sup>

```bash
sudo /usr/bin/perl -e 'exec "/bin/sh";'
sudo /usr/bin/ruby -e 'exec "/bin/sh"'
sudo /usr/bin/node -e 'require("child_process").spawn("/bin/sh", {stdio: [0,1,2]})'
```

Tačna putanja je važna. Ako sudo pravilo dozvoljava `/usr/bin/python3`, tokom validacije koristite baš tu putanju.<sup>[[2]](#references)</sup>

sudo izvršni fajl sa glob obrascem, kao što je `/usr/bin/python*`, može da dozvoli i Python 2 za skriptu napisanu za Python 3. Ako skripta stigne do `input()` sa tekstom koji kontroliše pozivalac, [Python 2 evaluira taj tekst kao izraz](https://docs.python.org/2/library/functions.html#input); eksplicitno pozivanje interpretera ima prednost nad shebang-om skripte. Proverite instalirane izvršne fajlove koji odgovaraju obrascu, efektivni RunAs i pravila za argumente, zabrane i dostupni ulaz pre nego što ovo tretirate kao putanju za izvršavanje.

Fiksna putanja skripte u sudo pravilu koje može da se izvršava kao root ne ograničava šta skripta izvršava. Za Bash omotač koji može da se čita proverite da li njegova prva izvršna komanda koristi nequoted pozicioni parametar kao što je `$1` kao **reč komande**, dok sudo dozvoljava argumente koje bira pozivalac. Potvrdite efektivni RunAs identitet, pravila za lozinku i argumente, kasnije zabrane i stvarnu granu skripte; `NOEXEC`, fiksna bezbedna lista argumenata ili omotač koji proverava komandu mogu da promene ishod. Tokom enumeracije statički pregledajte kratku skriptu, umesto da je pozivate probnom komandom.

Neograničeno sudo pravilo za `dotnet` koje može da se izvršava kao root takođe zaslužuje proveru interpretera. Ako je instaliran .NET SDK, [`dotnet fsi` izvršava F# kôd interaktivno ili iz skripte](https://learn.microsoft.com/en-us/dotnet/fsharp/tools/fsharp-interactive/), a [`dotnet run` izvršava projekat iz izvornog kôda](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-run). Najpre potvrdite efektivni RunAs идентитет и tačna pravila za argumente: pravilo ograničeno na određenu bezbednu podkomandu ili pouzdanu aplikaciju predstavlja drugačiju dozvolu, a instalacija koja sadrži samo runtime možda nema SDK komande. Sam naziv izvršnog fajla nagoveštava šta treba proveriti, ali nije dokaz mogućnosti izvršavanja kôda.

```bash
sudo /usr/bin/python3 -c 'import os; os.setuid(0); os.setgid(0); os.system("/bin/sh")'
```

## Uređivači dozvoljeni preko sudo

Ako `sudo -l` dozvoljava korisniku da pokrene interaktivni uređivač kao root, tretirajte to kao površinu za izvršavanje komandi, a ne kao bezazlenu dozvolu za uređivanje datoteka. Uređivači često mogu da izvršavaju shell komande, čitaju proizvoljne datoteke, upisuju proizvoljne datoteke ili pozivaju spoljne pomoćne programe iz samog uređivača.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

Uobičajeni postupak provere: navedite korisnikove privilegije, pa zatim pokrenite svaki dozvoljeni uređivač ili pager preko sudo.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/nano /etc/hosts
sudo /usr/bin/vim /etc/hosts
sudo /usr/bin/less /etc/hosts
```

### Izvršavanje komandi pomoću Nano-a

Kada je `nano` dozvoljen preko sudo-a, izvršavanje komandi može biti dostupno iz interfejsa uređivača.<sup>[[12]](#references)</sup>

```text
Ctrl+R
Ctrl+X
```

Zatim unesite komandu kao što je `id` ili `/bin/sh` u komandni prompt programa nano.<sup>[[12]](#references)</sup>

```bash
id
/bin/sh
```

Ako interaktivna ljuska nema upotrebljive terminalske tokove, ovaj oblik preusmeravanja mapira njen standardni izlaz i standardnu grešku na deskriptor 0.<sup>[[15]](#references)</sup>

```bash
reset; /bin/sh 1>&0 2>&0
```

Tačan niz tastera može da se razlikuje u zavisnosti od verzije nano-a i opcija za kompajliranje, ali bezbednosni problem je isti: uređivač se pokreće kao root i može da izvršava spoljne komande.<sup>[[1]](#references)[[12]](#references)</sup>

### Drugi uobičajeni načini izlaska iz uređivača

Uređivači nalik Vim-u obično omogućavaju izvršavanje komandi pomoću `:!`.<sup>[[13]](#references)</sup>

```text
:!/bin/sh
```

Programi za prikaz stranica kao što je `less` mogu takođe da omoguće izvršavanje shell komandi.<sup>[[14]](#references)</sup>

sudo pravilo koje dozvoljava pokretanje `apport-cli` kao root zaslužuje istu proveru pagera. Pogođene verzije Apporta mogle su da otvore izveštaj o padu u `less` uz veličinu terminala koju napadač može da podesi; pager je tada mogao da omogući root shell ako su bili ispunjeni posebni uslovi za sudo i pager. Proverite efektivno sudo pravilo, konfiguraciju pagera i ispravku paketa za konkretnu distribuciju pre nego što samo na osnovu verzije zaključite da je sistem ranjiv. Tokom pasivnog prikupljanja podataka pročitajte metapodatke paketa i politike bez izazivanja pada ili otvaranja privilegovanog izveštaja. [Ubuntu-ov CVE zapis](https://ubuntu.com/security/CVE-2023-1326) navodi verzije paketa sa ispravkama za pojedina izdanja, uključujući i ispravke koje su naknadno prenete.

```text
!/bin/sh
```

## Ostale opasnosti u sudo i doas pravilima

Počnite sa `sudo -l`, `sudo -V` i svim primenljivim `doas` pravilima. Posmatrajte zajedno dozvoljenu komandu, korisnika u čije ime se izvršava, argumente, okruženje i podrazumevane postavke. Dozvola za izvršavanje komande u ime servisnog naloga koji nije root i dalje može otkriti njegove datoteke ili omogućiti put do root privilegija.

Python skripta kojoj je `sudo` dozvolio izvršavanje može i dalje da pokrene shell komandu u ime svog RunAs identiteta ako se interaktivni unos koji kontroliše pozivalac nadovezuje u [`os.system()`](https://docs.python.org/3/library/os.html#os.system). Lista zabranjenih shell interpunkcijskih znakova nije dovoljna da bi se potvrdila bezbednost: [shell prepoznaje i zamenu komande `$(...)`](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html). Proverite da li dozvoljeni argumenti stižu do grane koja obrađuje unos, da li se unos bezbedne validacije prosleđuje shell komandi i da li efektivna sudo politika dozvoljava nameravanog RunAs korisnika. Putanja skripte ili poziv funkcije `os.system()` sami po sebi samo ukazuju šta treba proveriti; pregledajte izvorni kod bez pokretanja skripte sa privilegijama.

Efektivno root sudo ovlašćenje za `chattr` može da ukloni nepromenljiv atribut (`i`) sa datoteke, ali time samo po sebi ne даје право на њено записивање нити нови идентитет. У [приручнику за `chattr`](https://man7.org/linux/man-pages/man1/chattr.1.html) piše da atribut sprečava izmene i da ga mogu promeniti samo root ili proces sa `CAP_LINUX_IMMUTABLE`. Proverite tačna sudo pravila za argumente i podršku sistema datoteka, a zatim odvojeno utvrdite da li pozivalac može da piše u datoteku nakon uklanjanja atributa i da li je koristi proces višeg identiteta. Zamena login shell-a, na primer, zahteva i da ciljni nalog prihvata njegove kredencijale i da se zaista prijavite kroz taj shell. Tokom enumeracije pregledajte pravila, atribute datoteka i dozvole, ali ih nemojte menjati.

Ako sudo traži i lozinku i jednokratni kôd, posmatrajte te preduslove odvojeno od dozvole za komandu. Čitljiva datoteka `.google_authenticator` sadrži osetljiv seed, dok je stari hash lozinke aplikacije ili baze podataka samo mogući kandidat za trenutnu lozinku naloga; nijedno od toga ne dokazuje da efektivna PAM konfiguracija prihvata drugi faktor. Nakon dobijanja ovlašćenja, proverite tačan RunAs identitet i argumente: neograničena root dozvola za RubyGems `gem` može izložiti njegovu editor komandu ([GTFOBins](https://gtfobins.github.io/gtfobins/gem/)), ali ograničena dozvola ili neuspešna autentifikacija to ne omogućavaju. Pasivna enumeracija treba da zabeleži putanje i pravila bez ispisivanja seed-a, vraćanja lozinke, generisanja kôda ili pokretanja privilegovane komande.

Neograničeno sudo ovlašćenje za `knife` iz Chef-a koje može da se izvršava kao root zahteva pregled na nivou interpretera: [Chef navodi da `knife exec -E` lokalno evaluira Ruby string](https://docs.chef.io/workstation/26/tools/knife/knife_exec/). Proverite da li efektivno sudo pravilo dozvoljava potkomandu `exec` i argument `-E` koji zadaje pozivalac, željeni RunAs identitet i eventualne zabrane komandi ili fiksne argumente. Instalirani binarni fajl ili pravilo ograničeno na druge potkomande samo su povod za proveru. Pasivna enumeracija treba da zabeleži pravilo bez pokretanja `knife`.

Tačno sudo ovlašćenje za interaktivni `msfconsole` koje može da se izvršava kao root takođe je osetljivo: [GTFOBins opisuje njegovu `irb` konzolu](https://gtfobins.org/gtfobins/msfconsole/), koja može da nasledi sudo identitet. Proverite efektivnog RunAs korisnika, dozvoljenu listu argumenata, zabrane komandi, `NOEXEC` ili druga ograničenja, ponašanje instalirane konzole i mogućnost da pozivalac prosledi interaktivni unos. Isticanje putanje samo ukazuje šta treba proveriti; pasivna enumeracija ne treba da pokreće konzolu.

Na FreeBSD-u, čak i sudo pravilo ograničeno na `pkg update` i `pkg install *` kao root zahteva proveru poverenja u repozitorijum. Proverite da li pozivalac može da piše u `/etc/hosts` i da li efektivna, omogućena konfiguracija repozitorijuma koristi HTTP hostname uz `signature_type: none`. U [priručniku za `pkg.conf` na FreeBSD-u](https://man.freebsd.org/cgi/man.cgi?query=pkg.conf&sektion=5) piše da `none` isključuje proveru potpisa; samo korišćenje `pkg+http` to ne dokazuje. [Paket može da sadrži instalacione skripte](https://docs.freebsd.org/en/books/porters-handbook/pkg-files/), pa korisnik koji zaista kontroliše krajnju tačku repozitorijuma i može da izabere paket može da pređe granicu privilegija. Pre takvog zaključka proverite zamene repozitorijuma, SRV/mirror razrešavanje, efektivne sudo argumente, izbor paketa i izvršavanje skripti. Pregledajte pravila i male lokalne konfiguracione datoteke, ali tokom enumeracije nemojte preusmeravati nazive niti pokretati `pkg`.

Sudo pravilo koje može da se izvršava kao root i dozvoljava `apt-get update` i `apt-get upgrade` takođe zahteva proveru poverenja u repozitorijume ako sudo čuva `http_proxy` koji kontroliše pozivalac. Proverite da li efektivna APT proxy konfiguracija zaista koristi tu promenljivu i na koje omogućene zahteve ka repozitorijumima može da utiče; sam proxy ne može da zameni pakete iz arhive autentifikovane pouzdanim ključem za potpisivanje. [Priručnik za APT HTTP transport](https://manpages.debian.org/experimental/apt/apt-transport-http.1.en.html) opisuje prvenstvo proxy podešavanja, a [apt-secure](https://manpages.debian.org/experimental/apt/apt-secure.8.en.html) opisuje proveru potpisa, zamene za nebezbedne repozitorijume i potvrdu za neautentifikovane pakete. Proverite tačnog sudo RunAs korisnika i argumente, politiku autentifikacije repozitorijuma, eventualnu potrebnu interaktivnu potvrdu i da li izabrana nadogradnja pokreće skripte paketa kao root. Pasivno pregledajte pravila i lokalnu konfiguraciju; tokom enumeracije nemojte preusmeravati paketni saobraćaj niti pokretati nadogradnju.

Root sudo pravilo za `snap install` može da pređe granicu između paketa i koda ako argumenti dopuštaju pozivaocu da izabere lokalni snap i permissive režim instalacije. [Snap dokumentuje](https://snapcraft.io/docs/explanation/snap-development/install-modes/) da `--dangerous` preskače provere assertion-a za lokalni snap, a `--devmode` popušta ograničenja; [install hook može da se pokrene pri prvobitnoj instalaciji](https://snapcraft.io/docs/reference/development/supported-snap-hooks/). Proverite tačnu sudo politiku za argumente i RunAs identitet, ko kontroliše snap datoteku, da li instalirani snapd prihvata te režime i efektivni identitet i ograničenja hook-a pre nego što tvrdite da je moguć pristup zaštićenim datotekama hosta. Binarni fajl `snap` ili pravilo koje izgleda kao da sadrži džoker sami po sebi ne dokazuju ovaj lanac. Pasivna enumeracija ne treba da instalira paket niti izvršava njegov hook.

Za tačno sudo ovlašćenje za prilagođeni binarni fajl koji čita kredencijale u ime naloga koji nije root, najpre pregledajte dozvole binarnog fajla i sam fajl bez pokretanja. Ugrađena provera lozinke može da bude vidljiva samo kao široki znakovi; [GNU `strings` dokumentuje izdvajanje 16-bitnog little-endian teksta](https://sourceware.org/binutils/docs/binutils/strings.html). Vidljiv string ne dokazuje da je to prihvaćena lozinka niti da grana uspeha otkriva važeći kredencijal. Zasebno proverite ponašanje binarnog fajla, pristup ciljnog naloga zaštićenim podacima, validnost kredencijala i eventualni kasniji prelaz na drugi nalog ili grupu. Ako taj nalog pripada grupi `docker`, proverite pristup socket-u i da li daemon koristi rootful ili rootless identitet pre zaključka da je moguć pristup root-u hosta; [Docker dokumentuje implikacije te grupe na nivou root-a](https://docs.docker.com/engine/install/linux-postinstall/). Rutinska enumeracija treba da zabeleži sudo pravilo i članstvo u grupi bez pokretanja binarnog fajla ili ispisivanja njegovih stringova.

Sudo pravilo sa džokerom za skripte održavanja aplikacije treba da se proveri i van same putanje skripte. Proverite da li dozvoljena skripta prihvata neograničene argumente ili čita podešavanja koja može da menja nalog aplikacije sa nižim privilegijama, pa pratite te vrednosti do shell komandi ili okruženja potprocesa. Na primer, ZoneMinder-ov [`zmupdate.pl` sastavlja komandu `mysqldump` i izvršava je preko `qx`](https://github.com/ZoneMinder/ZoneMinder/blob/master/scripts/zmupdate.pl.in), dok [`zmdc.pl` kopira podešavanje `ZM_LD_PRELOAD` u `LD_PRELOAD`](https://github.com/ZoneMinder/ZoneMinder/blob/master/scripts/zmdc.pl.in) pre pokretanja daemon-a. Sudo pravilo koje dozvoljava bilo koju od tih skripti kao root može da pređe granicu poverenja ako se odgovarajući ulaz može kontrolisati i stiže do tog koda u instaliranoj verziji. Pregledajte efektivno sudo pravilo, dozvole za konfiguraciju aplikacije i izvorni kod skripte; džoker ili podešavanje sami po sebi samo ukazuju šta treba proveriti, a ne dokazuju izvršavanje.

- `SETENV`, `env_keep`, `secure_path` i `LD_PRELOAD` mogu da pretvore inače usku komandu u preuzimanje kontrole nad importom, bibliotekom ili PATH-om. Pogledajte [vodič za promenljive okruženja](../linux-basics/linux-environment-variables.md) i [zloupotrebu SUID/linker-a](../interesting-files-permissions/suid-shared-library-and-linker-abuse.md).

Tačno root sudo ovlašćenje sa `SETENV` za shell wrapper zahteva i proveru jednog koraka unapred ako wrapper pokreće fiksnu Python skriptu sa doslovnim importom. `secure_path` ograničava pronalaženje shell komandi, ali ne i Python-ovu [pretragu modula preko `PYTHONPATH`](https://docs.python.org/3/using/cmdline.html#envvar-PYTHONPATH); [`-E` i `-I`](https://docs.python.org/3/using/cmdline.html#cmdoption-E) navode Python da ignoriše tu promenljivu okruženja. Pre nego što ovo smatrate izvršavanjem koda, proverite efektivne sudo oznake i zabrane, granu wrapper-a, opcije interpretera, razrešavanje importa i direktorijum za pretragu u koji pozivalac može da piše. Kratke skripte pregledajte statički; nemojte pokretati privilegovani wrapper.

Tačno root sudo ovlašćenje za `neofetch ""` i dalje može da učita shell konfiguraciju ako odgovarajuće sudo podrazumevane postavke čuvaju `XDG_CONFIG_HOME` koji kontroliše pozivalac. [Neofetch-ov učitavač konfiguracije](https://github.com/dylanaraps/neofetch/blob/master/neofetch) učitava `neofetch/config.conf` ili `neofetch/config` iz tog direktorijuma; prazan spisak argumenata ne sprečava tu pretragu. Proverite instalirani učitavač, efektivna RunAs i argument pravila, eventualne zabrane komandi, da li sudo zaista čuva izabranu promenljivu za ovu komandu i da li pozivalac kontroliše čitljivu putanju do konfiguracije. Sačuvana promenljiva ili instalirani Neofetch sami po sebi samo ukazuju šta treba proveriti. Pregledajte pravila i metapodatke datoteka bez pokretanja privilegovane komande ili ispisivanja sadržaja konfiguracije; pogledajte [sudoers obradu okruženja](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf).

Neograničeno root sudo ovlašćenje za `facter` zahteva posebnu proveru prilagođenih fact-ova. [Puppet dokumentuje](https://help.puppet.com/core/current/Content/PuppetCore/loading_custom_facts.htm) da `--custom-dir` učitava Ruby fact datoteke iz izabranog direktorijuma. Proverite da li tačno sudo pravilo dozvoljava tu opciju, da li je podržava instalirani Facter i da li pozivalac kontroliše direktorijum. Fiksni argumenti, izričita zabrana komande ili onemogućeni prilagođeni fact-ovi mogu da promene ishod. Pasivna enumeracija treba da zabeleži kandidat za proveru u pravilima bez pokretanja Facter-a ili čitanja sadržaja fact-ova.

Za tačno root sudo ovlašćenje za skriptu sa `SETENV`, proverite gole nazive komandi kao što je `find` i efektivni `PATH` nakon primene sudo politike i inicijalizacije skripte. Bash datoteka koja se učitava može i da pokrene `enable -n [`: [Bash zatim pretražuje `PATH`](https://www.gnu.org/software/bash/manual/html_node/Bash-Builtins.html) za spoljašnju komandu `[`, kada je skripta kasnije pozove. Proverite primenljiva [sudoers pravila za okruženje i `secure_path`](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf), eventualne stavke `NOSETENV`/`NOEXEC` ili zabrane, tok skripte i učitanih datoteka i izvršni direktorijum za pretragu koji kontroliše pozivalac. Čitljiva skripta koja sadrži golu komandu samo ukazuje šta treba proveriti; ne dokazuje privilegovano izvršavanje. Pregledajte je bez pokretanja sudo pravila.
- Privilegovana skripta koja preuzima fiksni URL pomoću `curl` i dalje može da prihvati odgovor koji izabere pozivalac ako odgovarajuće sudo pravilo čuva `http_proxy`, a zahtev se šalje preko tog proxy-ja. Ako skripta zatim prosledi odgovor XML parseru koji razrešava spoljne entitete, zlonamerni odgovor može da otkrije datoteke čitljive privilegovanom procesu. Proverite tačnu sudo politiku za okruženje, izuzetke `no_proxy`, traženi URL, konfiguraciju parsera i odredište izlaza; sama proxy promenljiva ili XML parser nisu ranjivost. U [dokumentaciji za curl proxy okruženja](https://everything.curl.dev/usingcurl/proxies/env.html) opisan je način rada ovih promenljivih. Tokom pasivne enumeracije nemojte slati mrežne zahteve niti parsirati zlonamerni XML.
- Root sudo skripta koja pravi PostScript datoteku od podataka na koje utiče pozivalac, a zatim pokreće `ps2pdf -dNOSAFER`, zahteva posebnu proveru toka ulaza. Ghostscript navodi da ova zastavica isključuje SAFER do poziva `.setsafe`, čime omogućava PostScript operacije nad datotekama u okviru OS dozvola procesa. SQL upit sastavljen od argumenta pozivaoca može da prosledi redove koje kontroliše napadač PostScript šablonu, ali sam upit ili poziv `ps2pdf` ne dokazuje da podaci stižu do izvršive PostScript sintakse. Proverite efektivno sudo pravilo, tačan put od ulaza do šablona, eventualno escapovanje, ponašanje instaliranog Ghostscript-a i da li se SAFER ponovo uključuje pre interpretacije dokumenta. Tokom pasivne enumeracije nemojte pokretati privilegovanu konverziju. Pogledajte [Ghostscript dokumentaciju za `-dNOSAFER`](https://ghostscript.readthedocs.io/en/master/Use.html).
- Za sudo pravilo koje pokreće shell skriptu uporedite sačuvane promenljive sa samom skriptom. Konstrukcija poput `if $CHECK_CONTENT; then` pokreće proširenu vrednost kao komandu, pa čuvanje `CHECK_CONTENT` može da omogući izvršavanje komandi čak i kada su putanja skripte i argumenti fiksni. Za konkretno pravilo treba proveriti da li je grana dostupna i da li se okruženje zaista čuva.<sup>[[2]](#references)[[22]](#references)</sup>
- Python skripta kojoj sudo dozvoljava izvršavanje može da uveze kôd iz direktorijuma ili keširane `.pyc` datoteke u koju može da se piše. Slučaj sa kešom opisan je u [vodiču za eskalaciju privilegija](../linux-basics/linux-privilege-escalation/README.md).
- Fiksna Python skripta kojoj sudo dozvoljava izvršavanje može da izloži i interaktivni debugger. Pozivi kao što su `pdb.set_trace()` ili `pdb.post_mortem()` omogućavaju izvršavanje Python naredbi u kontekstu procesa koji se debaguje kada pozivalac može da stigne do tačke prekida ili rukovaoca izuzecima **i kontroliše ulazni tok debugger-a**. Proverite tačno sudo RunAs pravilo, autentifikaciju i uslove grane, mogućnost dolaska do izuzetka, vlasništvo nad terminalom/ulazom i da li se debugger izvršava u istom privilegovanom procesu. Zahtev preko socketa koji izazove izuzetak sam po sebi ne omogućava pristup debugger-u povezanom sa drugim terminalom. [Python dokumentuje evaluaciju naredbi u debugger-u i post-mortem režim](https://docs.python.org/3/library/pdb.html); pregledajte skriptu statički umesto da tokom enumeracije aktivirate privilegovani rukovalac.
- Fiksna Python skripta kojoj sudo dozvoljava izvršavanje može i da pročita polje profila iz baze podataka ili Unix socketa i nadoveže ga na string koji kasnije postaje **format string** za `str.format()`. [Polja zamene mogu da referišu atribute i ključeve mapiranja](https://docs.python.org/3/library/string.html#format-string-syntax), pa polje koje kontroliše napadač može da pregleda objekte prosleđene funkciji `format()` i otkrije podatke do kojih oni mogu da dođu, ako se rezultat ispiše ili sačuva na mestu čitljivom pozivaocu. Proverite efektivni sudo RunAs identitet, pravo upisa u konkretan zapis, tok podataka do format string-a, prosleđene objekte i vidljivost izlaza. Ovo ne omogućava automatski izvršavanje koda; pouzdan doslovni format string sa vrednostima koje kontroliše napadač predstavlja drugačiji slučaj. Otkriveni secret omogućava prelazak na OS nalog samo ako taj nalog prihvata taj kredencijal. Pregledajte skriptu i dozvole socketa bez pokretanja privilegovane operacije.
- Root Python wrapper može da prosledi URL koji izabere pozivalac funkciji `Repo.clone_from` iz GitPython-a. Ako wrapper uz to omogući Git-ov `protocol.ext.allow=always`, udaljeni `ext::` može da pokrene spoljašnji pomoćni program. Proverite tačne sudo argumente, izvor URL-a, verziju GitPython paketa i stanje vendor zakrpa, kao i da li wrapper izričito omogućava nebezbedne protokole. GitPython je dodao [podrazumevanu zaštitu od nebezbednih protokola](https://github.com/gitpython-developers/GitPython/commit/2625ed9) u verziji 3.1.30; verzija izvršnog fajla `git` je odvojena činjenica. Pasivni pregled treba da obuhvati samo pravilo i ograničeni deo izvornog koda, bez pokretanja kloniranja.
- Sudo ovlašćenje za korišćenje CLI alata za kloniranje repozitorijuma u ime drugog korisnika može da otkrije zaseban put za ubacivanje shell string-a. Pratite da li argument repozitorijuma koji bira pozivalac stiže do Node.js [`child_process.exec`](https://nodejs.org/api/child_process.html#child_processexeccommand-options-callback) ili drugog sastavljača shell komandi bez bezbednog razdvajanja argumenata; Node-ov `exec` prosleđuje komandni string shell-u. Proverite tačnog RunAs korisnika, dozvoljene potkomande i argumente, instalirani kod wrapper-a i validaciju ulaza. Sam naziv alata za repozitorijum ili neograničeno sudo pravilo ne dokazuju ubacivanje komandi. Pregledajte wrapper bez pokretanja privilegovanog kloniranja tokom enumeracije.
- Prilagođeni wrapper u vlasništvu root-a može da deluje bezbedno zato što njegovi binarni fajlovi i skripte ne mogu da se menjaju, ali odluka da pokrene privilegovanu radnju može da zavisi od zastavice, lokalne API vrednosti ili stanja servisa koje neprivilegovani korisnik može da promeni. Pratite svaki uslov do njegovog ulaza i provera ovlašćenja. Tokom enumeracije pregledajte konfiguraciju i dozvole bez menjanja operativnog stanja; poziv `systemd-run` unutar wrapper-a bitan je samo ako može da se utiče na uslov.
- Klijent za rezervne kopije kome sudo dozvoljava izvršavanje kao root može da prihvati konfiguracionu datoteku koju izabere pozivalac (na primer, `npbackup-cli -c`). Proverite tačnog RunAs korisnika i dozvoljene argumente, pa zatim da li pozivalac kontroliše putanju konfiguracije, izvorne putanje rezervne kopije i opcije za repozitorijum ili čitanje/obnavljanje. Šifrovani secret repozitorijuma u čitljivoj konfiguraciji klijent i dalje može da koristi, ali samo pravilo ne dokazuje pristup repozitorijumu niti otkrivanje root datoteka. Proverite ovlašćenje bez pokretanja rezervne kopije ili ispisivanja njenog sadržaja.
- [Restic](https://github.com/restic/restic/blob/master/doc/030_preparing_a_new_repo.rst) podržava `--password-command`, koji poziva program radi pribavljanja lozinke repozitorijuma. Ako sudo pravilo dozvoljava korisniku sa nižim privilegijama da pokrene restic kao root sa proizvoljno izabranom password komandom i potkomandom kojoj je potrebna lozinka, taj pomoćni program može da se izvrši kao root. Pregledajte tačne sudo argumente i izuzetke; nemojte pokretati pomoćni program ili komandu za rezervnu kopiju samo da biste proverili uslov tokom enumeracije.
- Privilegovano ovlašćenje za `restic backup` može i da pređe granicu pristupa datotekama ako sudo šablon argumenata dozvoljava pozivaocu da izabere i izvor i repozitorijum koji kasnije može da pročita i dešifruje. [Džokeri u sudoers argumentima mogu da odgovaraju razmacima i kosim crtama](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf), zato pregledajte završne džokere umesto da pretpostavite da fiksni prefiks repozitorijuma ograničava izvor. [Restic može da čuva rezervne kopije u lokalnim i udaljenim repozitorijumima](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html), ali lokalni repozitorijum može da sadrži novozapisane root-only objekte; pre nego što ovo smatrate otkrivanjem podataka, proverite efektivnu sudo politiku, pristup backend-u, lozinku repozitorijuma i dozvole dobijenih objekata. Rezervni SSH ključ omogućava pristup samo ako ga odredišni nalog prihvata. Tokom pasivnog pregleda nemojte pokretati rezervnu kopiju radi testiranja.
- Neograničena prilagođena komanda za održavanje ili rezervne kopije može da prihvati putanju izlaza ili da sadrži sopstveni planer poslova. Za putanju upisa u datoteku proverite tačno sudo pravilo i RunAs korisnika, a zatim da li pozivalac kontroliše i podatke i odredište. Za putanju preko planiranog zadatka proverite identitet koji ga izvršava, ulaz komande i sve dodatne provere lozinke ili ovlašćenja. Sam naziv komande ili `NOPASSWD` ne dokazuju nijednu od tih putanja. Pogledajte [upis u datoteke u vlasništvu root-a](../interesting-files-permissions/write-to-root.md) i [cron i systemd tajmere](../processes-crontab-systemd-dbus/cron-and-systemd-timers.md).
- Fiksna sudo komanda i dalje može da učita predvidivu konfiguracionu datoteku iz direktorijuma sa zajedničkim upisom. Utvrdite da li pozivalac može da zameni tu datoteku i da li njena polja source i destination kontrolišu privilegovano preuzimanje ili kopiranje. URL do lokalne datoteke može da otkrije podatke čitljive samo RunAs nalogu pod sudo-om; izvor koji kontroliše pozivalac, uparen sa zaštićenim odredištem, može da omogući upis. Proverite obradu URL-ova u instaliranom programu, provere putanje odredišta, efektivno sudo pravilo i dostupnost izlaza. Sama upisiva konfiguraciona putanja u `/tmp` samo je povod za proveru; pregledajte binarni fajl i metapodatke datoteka bez pokretanja privilegovanog prenosa.
- Sudo pravilo za `git apply` može da omogući RunAs nalogu da upisuje datoteke koje izabere patch pod kontrolom pozivaoca. [CVE-2023-23946](https://github.com/git/git/security/advisories/GHSA-r87m-v37r-cwfh) omogućavao je da posebno napravljen patch stvori simboličku vezu, a zatim upisuje izvan radnog stabla, čak i kada komanda nije prihvatala `--unsafe-paths`. Proverite efektivno sudo pravilo argumenata, izvor patch-a, pristup radnom direktorijumu RunAs naloga i zakrpu za instalirani Git ili vendor backport. Neograničeno pravilo koje dozvoljava `--unsafe-paths` predstavlja zaseban rizik eksplicitne opcije; ni Git verzija ni dozvola za `git apply` sami po sebi ne dokazuju da se zaštićena datoteka može promeniti. Tokom pasivne enumeracije nemojte primenjivati nepouzdan patch.
- Root sudo pravilo za `clamscan --debug` može da pređe granicu čitanja ako korisnik sa nižim privilegijama može da prosledi DMG sliku, a instalirani parser je pogođen problemom [CVE-2023-20052](https://blog.clamav.net/2023/02/clamav-01038-01052-and-101-patch.html), koji je mogao da otkrije sadržaj datoteka kroz debug izlaz. Proverite tačne dozvoljene argumente i putanju skeniranja, kontrolu ulaza, efektivni RunAs nalog, zakrpu/backport za engine i da li pozivalac može da vidi izlaz. Ako šire pravilo dozvoljava `--file-list`/`-f`, zasebno proverite ponašanje te liste; pravilo fiksirano na `--debug <scan-path>` to ne dozvoljava. Tokom enumeracije pregledajte pravila i metapodatke paketa bez skeniranja posebno napravljene datoteke ili ispisivanja zaštićenog izlaza.
- Root sudo pravilo koje otvara šifrovanu sliku diska koju je izabrao pozivalac i drugo pravilo koje montira dobijeni mapper mogu da unesu datoteke koje kontroliše pozivalac u mount namespace hosta. Potvrdite efektivna pravila i argumente za oba, kontrolu nad slikom i imenom mapper-a, stvarnu tačku montiranja i vlasnika i režim dozvola dobijenih datoteka. Prelaz na set-user-ID dodatno zahteva dostupnu izvršnu datoteku, opcije montiranja koje ga omogućavaju (`nosuid` ga blokira) i primenljivu procesnu ili MAC politiku; samo otvaranje ili montiranje slike predstavlja tek povod za proveru. Zaseban put preko postojeće rezervne kopije zahteva njen stvarni ključ i koristan čitljiv secret u njoj. Pregledajte pravila i putanje bez otvaranja ili montiranja slike tokom pasivne enumeracije. Pogledajte [priručnik za cryptsetup](https://gitlab.com/cryptsetup/cryptsetup/-/blob/main/man/cryptsetup.8.adoc) i [opcije za mount](https://man7.org/linux/man-pages/man8/mount.8.html).
- Root sudo pravilo za shell ili Python skriptu zahteva proveru radnog direktorijuma ako skripta poziva `./helper` a prethodno ne pređe u fiksni direktorijum. Python lista kao što je `['./helper']` prosleđena funkciji `subprocess.run` može da ima isto ponašanje u pogledu radnog direktorijuma koji bira pozivalac. Pozivalac možda može da izabere direktorijum u koji može da piše i da u njemu napravi izvršni fajl sa tim relativnim imenom; apsolutna putanja negde drugde u skripti ne štiti ovaj poziv. Pre nego što ovo smatrate izvršavanjem koda, proverite efektivno pravilo, `runchdir` ili drugu politiku za promenu direktorijuma, tok skripte i dostupnost grane, direktorijum u koji može da se piše i koji je izvršan, kao i ograničenja mount-a/`NOEXEC`. Ako skripta nije čitljiva, ponašanje ostaje nepoznato dok se izvor ne pregleda ovlašćenim putem. Skripte pregledajte statički umesto pokretanja pomoćnog programa. U [priručniku za sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) opisana je politika radnog direktorijuma.
- Fiksni root Python validator i dalje može da evaluira datoteku sa podacima koju izabere pozivalac. U [Python dokumentaciji za `eval()` upozorava se da ne treba koristiti nepoverljiv unos](https://docs.python.org/3/library/functions.html#eval): provera sufiksa ulaza, aritmetički prefiks ili grana za validaciju nisu sandbox ako preostali izraz stiže do `eval`. Pre nego što ovo nazovete putanjom za izvršavanje, proverite efektivno sudo pravilo, da li pozivalac može da izabere i kontroliše konkretnu datoteku, uslove grana parsera i sastavljanje izraza, kao i identitet privilegovanog procesa. Pojava `eval` u čitljivoj skripti samo je povod za proveru; tokom enumeracije pregledajte izvorni kôd i dozvole datoteka bez pokretanja validatora ili slanja test izraza.
- Root Ruby wrapper pod sudo-om koji čita relativni naziv YAML datoteke, kao što je `YAML.load(File.read("dependencies.yml"))`, može da učita podatke iz radnog direktorijuma pozivaoca ako wrapper ili sudo politika ne fiksiraju taj direktorijum. Proverite tačne dozvoljene argumente, dozvole direktorijuma i datoteke, kao i ponašanje instaliranog Psych-a: starije implementacije `YAML.load` mogle su da deserijalizuju proizvoljne Ruby objekte, dok novija izdanja podrazumevano ograničavaju klase. Samo statički poziv ukazuje šta treba proveriti; potvrdite da datoteka zaista dolazi iz direktorijuma u koji pozivalac može da piše i da instalirani učitavač prihvata opasne klase. Za nepoverljiv unos prednost dajte `safe_load`-u sa izričitim, minimalnim spiskom dozvoljenih klasa. Pogledajte [Ruby 3.0 Psych dokumentaciju](https://docs.ruby-lang.org/en/3.0/Psych.html) i [Ruby 3.1 Psych dokumentaciju](https://ruby-doc.org/core-3.1.2/Psych.html).

- Tačno root sudo ovlašćenje za `sudo go run /absolute/file.go` zahteva proveru radnog direktorijuma kada Go izvorni kod čita relativnu WASM datoteku i možda pokreće relativnu shell skriptu nakon provere rezultata. Proverite efektivni RunAs identitet, argumente komande i zabrane, trenutni direktorijum u koji pozivalac može da piše, tok podataka od WASM-a do grane i da li ta grana poziva pomoćni program. Fiksni sudo `runchdir`, `os.Chdir` ili [`exec.Cmd.Dir`](https://pkg.go.dev/os/exec) mogu da promene mesto pretrage. Istovremena pojava tih elemenata u statičkom kodu samo je kandidat za proveru; pregledajte izvorni kod bez pokretanja Go-a, WASM-a ili pomoćnog programa.
- `sudoedit` i džokeri argumenata zahtevaju precizne provere verzije i pravila; [kontrolna lista](linux-privilege-escalation-checklist.md) obuhvata problem uređivanja datoteka preko sudoedit-a. Za cross-user `sudoedit` ovlašćenje nad putanjom sa džokerom, proverite efektivno podešavanje `sudoedit_follow` ili `FOLLOW`, `sudoedit_checkdir`, razrešenu ciljnu putanju i ko može da zameni svaku stavku roditeljske putanje. Prvo može da omogući praćenje simboličke veze, dok isključivanje drugog uklanja provere direktorijuma u koji može da se piše; nijedno podešavanje samo po sebi ne potvrđuje upis u datoteku drugog korisnika. Pre takvog zaključka potvrdite instaliranu sudo politiku i tačno poklapanje argumenata. Pogledajte [definicije opcija za sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf).
- U sudoers pravilu za komandu, džoker argumenta može da odgovara i razmacima i znakovima putanje. Pravilo za komandu sa mogućnošću čitanja i argumentom kao što je `/restricted/*` zato može da dozvoli dodatni argument datoteke nakon prefiksa koji se podudara. Proverite tačnog run-as korisnika, putanju komande, šablon argumenata i kasnije zabrane; dokazano čitanje datoteke ne znači i izvršavanje komandi. U [priručniku za sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) razlikuju se džokeri argumenata i džokeri putanje komande.
- Šablon džokera argumenta koji liči na putanju takođe može da odgovara `../`. Na primer, root sudo pravilo `node /opt/scripts/*.js` može da dozvoli JavaScript datoteku izvan `/opt/scripts` koju kontroliše pozivalac, ako prosleđeno ime putanje i dalje počinje sa `/opt/scripts/`, a razrešava se kroz segmente roditeljskih direktorijuma. Ovo je džoker za **argument**; za džoker putanje izvršnog fajla Node-a važe drugačija pravila za kosu crtu. Pre zaključka da je moguće izvršavanje koda proverite efektivno pravilo, kasnije zabrane, razrešavanje putanje, kontrolu nad ciljnom datotekom i sva sudoers ograničenja preko regularnih izraza ili digest-a. Pogledajte [pravila džokera u sudoers-u](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) i [Node dokumentaciju za komandnu liniju](https://nodejs.org/api/cli.html).
- Programi za arhiviranje i drugi pomoćni programi mogu da imaju hook-ove za izvršavanje. Proverite tačne dozvoljene argumente u [GTFOBins](https://gtfobins.github.io/) umesto da pretpostavite da samo shell-ovi ili interpreteri izvršavaju komande.
- Neograničeno root sudo ovlašćenje za `qpdf` može da otkrije privilegovanu datoteku kroz PDF priloge: qpdf 10.2 i novije verzije podržavaju `--empty` i `--add-attachment file ... --` uz izlazni PDF. Ako privilegovani proces može da pročita izabrani izvor i upiše PDF na putanju dostupnu pozivaocu, taj izlaz može da prenese bajtove izvora. Pre zaključka da je otkrivanje datoteke moguće, proverite efektivne sudo argumente i izuzetke, qpdf verziju, pristup izvoru i putanju izlaza. Čitanje root SSH ključa korisno je za prijavu samo ako je ključ važeći i ako je root SSH autentifikacija dozvoljena. Pogledajte [qpdf opcije za priloge](https://qpdf.readthedocs.io/en/stable/cli.html#embedded-files-attachments).
- Ponovno korišćenje sudo vremenske oznake zavisi od politike keša, korisnika vlasnika, terminala/sesije i dozvola. Provere su opisane u [vodiču za eskalaciju privilegija](../linux-basics/linux-privilege-escalation/README.md#reusing-sudo-tokens).
- `doas` ima sopstvena pravila i konfiguraciju. Proverite dozvoljene komande i putanje konfiguracije u koje može da se piše, kao što je opisano u [odeljku o doas-u](../linux-basics/linux-privilege-escalation/README.md#doas).

### Alati za izgradnju i pakete pokrenuti preko sudo-a

Neograničeno sudo ovlašćenje za Foundry-jev `forge` može biti značajno čak i kada je RunAs identitet drugi korisnik koji nije root. Opcije kompajlera kao što je `--use` mogu da izaberu lokalni izvršni fajl, a `forge flatten -o` bira izlaznu datoteku. Pre nego što ovo smatrate iskoristivim, proverite instaliranu verziju Forge-a, tačne sudo argumente, dostupnost projekta i putanja kompajlera, dozvole izlaza i efektivno okruženje. Relativni pomoćni izvršni fajl pronađen preko `PATH`-a predstavlja putanju koja zavisi od verzije i okruženja, a ne osobinu koju treba pretpostaviti za svaku Forge izgradnju.<sup>[[23]](#references)[[24]](#references)</sup>

Neograničeno root sudo ovlašćenje za `pacman` omogućava više od upita za pakete: `-U` prihvata lokalni paket, paketi mogu da sadrže instalacione skripte, a `--hookdir` bira drugi direktorijum za hook-ove. Pre testiranja pregledajte efektivno sudo pravilo, ograničenja argumenata i izuzetke; pasivna enumeracija ne zahteva instalaciju paketa niti pokretanje hook-a.<sup>[[25]](#references)[[26]](#references)</sup>

Fiksni sudo shell wrapper može i da instalira imenovanu npm zavisnost, a zatim pokrene Node aplikaciju. Pregledajte njegovo tačno RunAs pravilo, da li je paket već instaliran, efektivne vrednosti `HOME` i npm `userconfig`, konfiguraciju projekta ili izmene komandne linije i da li korisnik sa nižim privilegijama kontroliše registry ili paket koji se vraća za to ime. [npm dokumentuje pretragu `.npmrc` datoteka po korisniku i projektu](https://docs.npmjs.com/cli/v6/configuring-npm/npmrc/); ponašanje sudo-a u vezi sa `HOME` zavisi od instalirane politike i distribucije, pa npm proces sa privilegijama može, ali ne mora, da pročita upisivu `.npmrc` datoteku korisnika. Ako novoinstalirani paket uveze privilegovana aplikacija, njegov kod modula može da se izvrši u identitetu te aplikacije. Skripte koje se pokreću tokom instalacije predstavljaju zasebnu putanju koja zavisi od verzije i konfiguracije; [npm dokumentuje njihov životni ciklus i obradu korisnika](https://docs.npmjs.com/cli/v6/using-npm/scripts/). Sama `.npmrc` putanja ili red `npm install` samo su povod za proveru. Tokom pasivne enumeracije pregledajte pravilo, kratak wrapper, konfiguracione putanje i poreklo paketa bez instaliranja paketa ili pokretanja aplikacije.

Root sudo ovlašćenje za `pip` ili `pip3 download` takođe ukazuje na potrebu za proverom izgradnje paketa ako argumenti dozvoljavaju pozivaocu da izabere nepouzdan source distribution, čak i ako šablon URL-a ograničava izvor na lokalni servis, a sufiks na `.tar.gz`. `pip download` prihvata URL-ove arhiva i razrešava metapodatke paketa; priprema sdist-a može da pokrene njegov build backend ili nasleđeni `setup.py` kod pre nego što se arhiva samo sačuva. Proverite tačno sudo RunAs i pravilo argumenata, da li pozivalac može da objavi ili zameni izabranu arhivu i da li ta verzija pip-a zaista priprema njene metapodatke. Fiksna pouzdana arhiva ili wheel ne dokazuju da je ova putanja moguća. Tokom pasivne enumeracije nemojte preuzimati niti izgrađivati nepouzdan paket. Pogledajte pip [komandu za preuzimanje](https://pip.pypa.io/en/stable/cli/pip_download/), [interfejs build-system-a](https://pip.pypa.io/en/stable/reference/build-system/) i [uputstvo za bezbednu instalaciju](https://pip.pypa.io/en/stable/topics/secure-installs/).

Sudo pravilo koje dozvoljava `pip install` sa putanjom lokalnog projekta koju bira pozivalac predstavlja neposredniji prelaz granice izgradnje. [pip prihvata direktorijume lokalnih projekata](https://pip.pypa.io/en/stable/topics/local-project-installs/) i poziva njihov build system; [build backend pokreće hook-ove za izgradnju koje kontroliše projekat](https://pip.pypa.io/en/stable/reference/build-system/). Pre nego što ovo smatrate privilegovanim izvršavanjem koda, proverite efektivni RunAs identitet, tačna ograničenja argumenata i zabrane, kontrolu nad izabranim projektom i ponašanje instaliranog pip/backend-a. Fiksni pouzdani projekat ili pravilo koje isključuje putanje po izboru pozivaoca ne dokazuju ovu putanju. Tokom pasivne enumeracije pregledajte pravilo i metapodatke projekta bez instaliranja paketa.

Neograničeno root sudo ovlašćenje za `easy_install` predstavlja sličan pokazatelj zastarele izgradnje paketa. [Setuptools dokumentuje](https://setuptools.pypa.io/en/stable/deprecated/easy_install.html) da Easy Install prihvata lokalni direktorijum projekta i izgrađuje source distribution-e; projekat koji kontroliše pozivalac može da izvrši svoj `setup.py` tokom izgradnje u sudo identitetu. Proverite efektivni RunAs nalog, tačnu komandu i ograničenja argumenata (uključujući kasnije zabrane), kontrolu nad izabranim projektom i ponašanje instaliranog alata. Fiksni pouzdani projekat ili pravilo koje ne dozvoljava izvor po izboru pozivaoca ne dokazuju ovu putanju. Tokom enumeracije pregledajte pravilo i metapodatke projekta bez instaliranja paketa.

Python wrapper kojem sudo dozvoljava izvršavanje, a koji koristi `setuptools.package_index.PackageIndex.download` sa URL-om po izboru pozivaoca, predstavlja drugačiji slučaj za proveru od `pip download`: [Setuptools GHSA-5rjg-fvgr-3xxf](https://github.com/pypa/setuptools/security/advisories/GHSA-5rjg-fvgr-3xxf) opisuje slučaj u kojem je ime datoteke izvedeno iz URL-a u pogođenim izdanjima pre 78.1.1 izlazilo iz predviđenog direktorijuma za preuzimanje i upisivalo se uz dozvole procesa. Proverite efektivni sudo RunAs i pravilo argumenata, da li wrapper prosleđuje URL pozivaoca upravo ovom API-ju, instaliranu verziju ili vendor backport i gde se dobijena putanja razrešava. Sam broj verzije ili upisivi direktorijum za preuzimanja ne dokazuju proizvoljan upis. Tokom enumeracije pregledajte kratak wrapper i metapodatke paketa bez preuzimanja URL-a ili upisivanja datoteke.

Wrapper za izgradnju kojem sudo dozvoljava izvršavanje, a koji prosleđuje `.spec` datoteku koju je izabrao pozivalac PyInstaller-u, zahteva sličnu proveru granice poverenja. PyInstaller spec je izvršivi Python koji se evaluira tokom **izgradnje**, a njegovi `datas` unosi mogu da spakuju datoteke čitljive identitetu koji vrši izgradnju u artefakt. Proverite tačnog RunAs korisnika, sudo pravilo za argumente i zabrane, obradu putanja i grana u wrapper-u, kontrolu nad izabranom spec datotekom i pristup dobijenom artefaktu. Sama dozvola za unos `.py` datoteke ili instalirani PyInstaller ne dokazuju kontrolu nad spec datotekom niti privilegovano izvršavanje. Pasivni pregled treba da obuhvati samo ograničeni deo wrapper datoteke i metapodatke; nemojte pokretati izgradnju. Pogledajte [PyInstaller dokumentaciju za spec datoteke](https://pyinstaller.org/en/stable/spec-files.html).

Proverite instaliranu verziju, tačnu sudo politiku za run-as korisnika i argumente, kao i vlasništvo nad putanjama preset-a i modula, bez učitavanja modula tokom enumeracije.

### Privilegovani wrapper-i za rezervne kopije koji prepravljaju task datoteku pozivaoca

Shell wrapper koji se pokreće kao root može da prihvati task datoteku koju je izabrao pozivalac, ukloni `../` iz izvornih putanja, proveri da li svaki rezultat počinje dozvoljenim direktorijumom, prepravi task datoteku, a zatim prosledi njenu *putanju* programu za pravljenje rezervne kopije. Proverite transformisanu putanju nakon potpune kanonske rezolucije: jedan prolaz zamene string-a može da otkrije novi niz za prolazak kroz direktorijume koji prođe leksičku proveru prefiksa. Proverite i da li program za rezervne kopije čita transformisane podatke iz memorije ili ponovo otvara datoteku. Ako je ponovo otvara, neuspešno prepravljanje može da ostavi originalni unos neizmenjen.

Na Linux-u `fs.protected_regular` može da zabrani upis sa `O_CREAT` u običnu datoteku drugog korisnika u direktorijumu sa sticky bit-om u koji svako može da piše. Ta zabrana je zaštitna, ali shell wrapper koji ignoriše grešku upisa može i dalje da nastavi sa originalnom task datotekom. Potvrdite podešavanje, vlasnika datoteke i direktorijuma, kao i da li se wrapper zaustavlja nakon greške. Putanja je kandidat za otkrivanje datoteka samo ako efektivno sudo pravilo dozvoljava wrapper-u da se izvršava u ime privilegovanog korisnika, pozivalac kontroliše ulazni task i čitljivo odredište rezervne kopije, a alat za rezervne kopije zaista uključuje zaštićene izvore. Tokom enumeracije pregledajte ove uslove bez pokretanja rezervne kopije.

### Džokeri argumenata u privilegovanim packet alatima

U sudo pravilu za `tcpdump`, `*` u **šablonu argumenta** može da odgovara razmacima i kosim crtama, pa ograničenje koje liči na putanju i dalje može da dozvoli dodatni tekst sa opcijom. Ovo se razlikuje od džokera u putanji izvršnog fajla komande; pregledajte celo RunAs pravilo i sve kasnije zabrane. Ako je moguće ubaciti opcije, dozvoljeno pozivanje i semantika opcija instaliranog [`tcpdump`-a](https://github.com/the-tcpdump-group/tcpdump/blob/master/tcpdump.1.in) određuju da li `-F`, `-V`, `-r`, `-w` ili `-Z` omogućava koristan primitiv za čitanje/upis. `-V` čita listu imena datoteka sa snimcima, a ne proizvoljno ispisuje sadržaj bilo koje datoteke. AppArmor ili druga MAC politika može da blokira pristup datotekama čak i kada sudo dozvoljava komandu; sama datoteka profila na disku ne dokazuje da je profil učitan ili da se primenjuje. Pre zaključka pasivno pregledajte ovlašćenja i politiku. U [priručniku za sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) opisana je razlika između džokera.

Root sudo pravilo u kom je naveden samo izvršni fajl `tcpdump`, bez ograničenja argumenata, takođe treba proveriti. U [priručniku za tcpdump](https://github.com/the-tcpdump-group/tcpdump/blob/master/tcpdump.1.in) piše da je `-z` komanda koja se izvršava nakon rotacije kada `-C` ili `-G` rotira sačuvan snimak; `-Z` ili podrazumevana vrednost izabrana pri kompajliranju mogu da uklone privilegije pre njenog pokretanja. Pre nego što ovo smatrate putanjom eskalacije, proverite efektivno sudo pravilo, instaliranu izgradnju, ponašanje pri uklanjanju privilegija i da li rotacija može da se dogodi. Istaknuto pravilo je kandidat za proveru, a ne dokaz izvršavanja komandi kao root.

### Nmap wrapper-i pokrenuti preko sudo-a

Blokiranje poznatog zapisa `--script` ne mora da blokira učitavanje NSE koda: Nmap-ov [`--datadir`](https://nmap.org/book/man-misc-options.html) bira datoteke sa podacima, a NSE [učitava `nse_main.lua`](https://nmap.org/book/nse-implementation.html) iz izabranog direktorijuma sa podacima kada je skriptovanje omogućeno. Neke instalirane izgradnje prihvataju i alternativne zapise dugih opcija, zato uporedite ograničenja sa stvarnim parserom tog binarnog fajla. [`--excludefile`](https://nmap.org/book/host-discovery-controls.html) predstavlja zasebnu površinu za čitanje datoteka; greške parsera mogu da otkriju tekst. Tokom enumeracije proverite efektivno sudo pravilo, logiku wrapper-a, Nmap verziju, kontrolu nad direktorijumom i MAC politiku bez pokretanja skeniranja.

### Rsync kopiranje arhiva pokrenuto preko sudo-a

Za `sudo rsync -a ... /writable/source/* /fixed/destination/`, `*` u **sudoers šablonu argumenata** može da odgovara razmacima i dozvoli dodatnu opciju između izvora i odredišta. Ovo se razlikuje od shell proširivanja imena datoteka. Ako pozivalac može da popuni izvor, a privilegovani rsync proces može da piše u odredište, [`--chown`](https://download.samba.org/pub/rsync/rsync.1) može da zatraži privilegovanu promenu vlasništva dok režim arhive čuva bitove dozvola, čime potencijalno nastaje SetUID datoteka u vlasništvu privilegovanog naloga. Proverite tačnu [semantiku sudoers džokera](https://man7.org/linux/man-pages/man5/sudoers.5.html), rsync verziju, kasnije zabrane, `nosuid` sistema datoteka i MAC politiku. Poklapanje sa pravilom je kandidat za proveru, a ne dokaz uspešne eskalacije privilegija.

### Privilegovani direktorijum za Below logove

### Parsiranje izraza iz sačuvanog ulaza pokrenuto preko sudo-a

Fiksna Python skripta pokrenuta kao root preko sudo-a i dalje može da evaluira tekst koji korisnik sa nižim privilegijama može da sačuva u bazi podataka aplikacije. Poziv aplikacije sa izričitim `safe=False` zahteva zasebnu proveru čak i kada je taj pozivalac iz komandne linije zakrpljen. Proverite efektivno sudo pravilo, ko može da menja konkretan red ulaza, da li filtriranje ili bodovanje omogućava da taj red stigne do poziva i ponašanje instalirane funkcije. TensorFlow verzija, sudo ovlašćenje ili fiksna datoteka modela sami po sebi ne dokazuju ovaj lanac. Pasivno pregledajte skriptu i tok podataka; tokom enumeracije nemojte pokretati privilegovanu pomoćnu skriptu niti slati test izraze.

### needrestart konfiguracija dozvoljena preko sudo-a

`needrestart -c` učitava Perl konfiguracionu datoteku koju bira pozivalac i evaluira njen sadržaj. Ako `sudo -l` dozvoljava `needrestart` kao root sa argumentima koji omogućavaju `-c`, a pozivalac može da izabere čitljivu konfiguracionu datoteku na upisivoj lokaciji, ta dozvola može da omogući izvršavanje koda kao root. Proverite tačno sudo pravilo za run-as korisnika i argumente; pravilo koje dozvoljava samo fiksnu listu argumenata može da blokira ovu putanju. Ovo je odvojeno od ranjivosti needrestart-a pri skeniranju interpretera: ažuriranje paketa ili isključivanje `interpscan` ne čini bezbednim neograničeno root ovlašćenje za `-c`.<sup>[[2]](#references)[[18]](#references)[[19]](#references)</sup>

### Python import-i preko sudo-a u ime drugog naloga

Fiksna Python ulazna tačka i dalje može da uveze modul koji pozivalac može da menja ili zameni, čak i kada sudo pokreće skriptu u ime **ne-root** servisnog korisnika. Za doslovni `from utils import status`, pregledajte lokalne `utils/__init__.py` i `utils/status.py`, kao i dozvole direktorijuma paketa. Pre nego što upisivu datoteku smatrate putanjom za izvršavanje, potvrdite putanju za import u skripti, tačne sudo argumente i da li odgovarajuća radnja stiže do tog importa. Tokom enumeracije pregledajte datoteke i dozvole bez uvoza modula ili pokretanja skripte.<sup>[[2]](#references)[[3]](#references)</sup>

Tačno sudo pravilo za `python3 /absolute/script.py` zahteva samo da skripta bude čitljiva; ne mora da bude izvršna niti da ima shebang. Pregledajte i **module koji nedostaju**: ako skripta uvozi modul čije ime datoteke može da se napravi u direktorijumu skripte u koji pozivalac može da piše, Python može da učita tu datoteku u RunAs identitetu. Proverite efektivno sudo pravilo, stvarnu [putanju za pretragu modula](https://docs.python.org/3/library/sys_path_init.html) u interpreteru, da li je modul ugrađen ili zamrznut i da li se import zaista izvršava. Direktno sudo pravilo za skriptu ima drugačije zahteve za execute bit i shebang. Poseban wrapper koji dodaje tokene koje prosleđuje pozivalac nakon `sudo -u account` takođe zahteva proveru toka argumenata: dodatni `-u` u tim tokenima bitan je samo ako sudo politika dozvoljava dobijeni identitet. Sami statički string-ovi ne dokazuju nijednu putanju.

### Apache pokrenut preko sudo-a sa konfiguracijom koju kontroliše pozivalac

Ako sudo pravilo dozvoljava privilegovani `apachectl`, `apache2ctl` ili `httpd` sa konfiguracionom datotekom `-f` koju kontroliše pozivalac, pregledajte dozvole te datoteke i njenog roditeljskog direktorijuma. Apache direktiva [`LoadModule`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadmodule) prima ime modula, a zatim **ime datoteke modula**; [`LoadFile`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadfile) takođe učitava datoteku. [`Include` i `IncludeOptional`](https://httpd.apache.org/docs/2.4/mod/core.html#include) mogu da prošire konfiguraciju ili otkriju sadržaj datoteka preko grešaka. Prilagođeni wrapper može da validira ove putanje, ukloni privilegije ili ograniči argumente, pa sama upisiva konfiguracija predstavlja samo kandidata za proveru, a ne dokaz izvršavanja koda. Pre zaključka proverite kanonsko razrešavanje putanja, simboličke veze i parsiranje direktiva.

### nginx pokrenut preko sudo-a sa konfiguracijom koju kontroliše pozivalac

Neograničeno root sudo ovlašćenje za `nginx` može da dozvoli [`-c` da izabere drugu konfiguraciju](https://nginx.org/en/docs/switches.html). Pregledajte tačne sudo argumente i izuzetke, da li pozivalac može da navede konfiguraciju i da li dobijeni master ili worker procesi zadržavaju pristup zaštićenim putanjama. Izabrani `root` uz `autoindex` može da izloži datoteke preko novog listener-a; [`dav_methods PUT`](https://nginx.org/en/docs/http/ngx_http_dav_module.html) može da omogući privilegovani upis datoteke, ali DAV modul se podrazumevano ne ugrađuje i treba proveriti njegovo prisustvo, dostupnost listener-a, dozvole datoteka i ponašanje privremenih datoteka. Direktiva [`error_log`](https://nginx.org/en/docs/ngx_core_module.html#error_log) takođe može da cilja izabranu datoteku; upisivanje logova u osetljivu konfiguracionu datoteku, kao što je `/etc/ld.so.preload`, postaje putanja eskalacije tek ako privilegovani proces zaista može da piše u nju i ako se može kontrolisati zapis u logu. Isticanje izvršnog fajla u `sudo -l` samo ukazuje šta treba proveriti, a ne dokazuje da bilo koja od ovih putanja funkcioniše. Tokom pasivne enumeracije nemojte pokretati niti ponovo konfigurisati nginx.

### Poređenje obrazaca u privilegovanim Bash prompt-ovima

Kada Bash skripta dozvoljena preko sudo-a pročita vrednost od pozivaoca i proveri je pomoću `[[ "$expected" == $entered ]]`, Bash tumači neizrazovanu desnu stranu kao obrazac. Zbog toga džoker može da zadovolji poređenje bez poznavanja očekivane vrednosti. Stavljanje operanda u navodnike (`[[ "$expected" == "$entered" ]]`) pretvara poređenje u doslovno poređenje string-ova. Proverite tačno sudo pravilo, da li je prompt dostupan i šta skripta radi nakon poređenja; sama sintaksa ne dokazuje iskoristivu putanju. Tokom enumeracije izbegavajte ispisivanje očekivane vrednosti. Pogledajte [referencu za Bash uslovne konstrukcije](https://www.gnu.org/software/bash/manual/html_node/Conditional-Constructs.html).

### Pomoćni programi pokrenuti preko sudo-a koji preuzimaju i izvršavaju datoteku

Neograničeno root sudo ovlašćenje za prilagođeni pomoćni program zahteva proveru toka podataka ako prihvata URL koji bira pozivalac, upisuje odgovor na disk, a zatim pokreće tu datoteku pomoću interpretera ili shell-a. [Sudoers dozvoljava proizvoljne argumente kada uz stavku komande nije navedena lista argumenata](https://man7.org/linux/man-pages/man5/sudoers.5.html); fiksna putanja izvršnog fajla ne ograničava izbor koji omogućavaju njegovi argumenti. Proverite stvarnu validaciju URL-a, putanju izlaza, granu uspeha i kasnije izvršavanje u instaliranom pomoćnom programu. Sam import libcurl-a ili vidljiv string ne dokazuju ovaj lanac.

Čak i fiksni osnovni naziv izlazne datoteke može da se zameni između upisa i izvršavanja ako pomoćni program koristi **relativnu putanju u radnom direktorijumu koji kontroliše pozivalac**. Preimenovanje ili zamena datoteke u vlasništvu root-a zavisi od dozvola za upis i prolazak kroz direktorijum i eventualnih ograničenja sticky bit-a, a ne samo od režima datoteke; pogledajte [`rename(2)`](https://man7.org/linux/man-pages/man2/rename.2.html). Proverite da li pomoćni program kasnije ponovo otvara putanju ili koristi već otvoren deskriptor i da li prelazi u pouzdan direktorijum pre upisa. Pasivno pregledajte sudo politiku, pomoćni program i metapodatke direktorijuma; tokom enumeracije nemojte pokretati privilegovano preuzimanje niti pokušavati race.

Root sudo pomoćni program za preuzimanje može da omogući i ubacivanje **argumenata** ako sastavlja Bash komandni string kao što je `curl <caller input> -o <fixed output>`. Filter koji odbacuje razmake i dalje ostavlja [Bash proširivanje vitičastih zagrada](https://www.gnu.org/software/bash/manual/html_node/Brace-Expansion.html): elementi razdvojeni zarezima bez navodnika mogu da postanu zasebni curl argumenti. Ako ulaz stiže do curl-a pre fiksnog `-o`, opcija izlaza koju prosledi pozivalac može da izabere odredište za prvi URL u identitetu pomoćnog programa; [curl povezuje opcije izlaza sa URL-ovima po redosledu](https://curl.se/docs/manpage.html#-o). Proverite tačan shell, stavljanje u navodnike, validaciju ulaza, efektivno sudo pravilo, redosled curl argumenata i podržane URL šeme, kao i da li pozivalac kontroliše preuzete bajtove ili može da pročita rezultat. Izvršni fajl upakovan pomoću PyInstaller-a može da sadrži Python logiku aplikacije, ali sama oznaka pakovanja ili string `curl` ne dokazuju ovaj tok podataka. Kada je ovlašćeno, pregledajte ograničenu lokalnu kopiju; rutinska enumeracija ne treba da pokreće pomoćni program niti preuzima podatke iz izvora koji je izabrao napadač.

Root sudo shell skripta koja poziva [`mktemp -u` / `--dry-run`](https://www.gnu.org/software/coreutils/manual/html_node/mktemp-invocation.html) bira samo nekorišćeno ime; ona **ne pravi datoteku**. Ako skripta kasnije napravi datoteku pod tim imenom u direktorijumu na koji drugi korisnik može da utiče, ponovo je otvori i doda njen sadržaj u zaštićeno odredište poput root-ovog `authorized_keys`, proverite da li postoji race sa privremenom datotekom. Potvrdite tačno sudo pravilo, vlasništvo nad direktorijumom i datotekom, redosled pravljenja i ponovnog otvaranja, zaštite kernela i da li privilegovani upis zaista koristi bajtove koje kontroliše napadač. Sam string `mktemp -u` ili upisivi `/tmp` ne dokazuju postojanje race-a. Tokom enumeracije pregledajte skriptu i metapodatke putanje bez njenog pokretanja ili utrkivanja u zameni privremene datoteke.

## Napomene za odbranu

- Izbegavajte da preko sudo-a dozvoljavate interpretere ili interaktivne editore.<sup>[[1]](#references)</sup>
- Prednost dajte fiksnim wrapper-ima u vlasništvu root-a koji izvršavaju jednu usku administrativnu radnju.<sup>[[1]](#references)[[2]](#references)</sup>
- Ako je interpreter neophodan, ograničite tačnu putanju skripte i sprečite argumente, importe u koje korisnik može da piše, `PYTHONPATH` i nebezbedno čuvanje okruženja koje kontroliše korisnik.<sup>[[2]](#references)[[3]](#references)[[4]](#references)</sup>
- Ako je potrebno uređivanje datoteka, ograničite tačnu putanju datoteke i razmotrite `sudoedit` uz zakrpljene sudo verzije i strogu obradu okruženja.<sup>[[1]](#references)[[2]](#references)</sup>
- Pregledajte `SETENV`, `env_keep`, upisive radne direktorijume, upisive putanje modula/importa, `NOEXEC`, `use_pty` i logovanje, ali nemojte smatrati da oni sami predstavljaju potpun sandbox.<sup>[[1]](#references)[[2]](#references)[[3]](#references)</sup>
