## Interpreters που επιτρέπονται μέσω sudo

Αν το `sudo -l` επιτρέπει σε έναν χρήστη να εκτελέσει έναν interpreter ως root, αντιμετωπίστε το ως άμεση εκτέλεση κώδικα. Οι interpreters έχουν σχεδιαστεί για να εκτελούν αυθαίρετο κώδικα, επομένως ένας κανόνας που επιτρέπει τα `python3`, `perl`, `ruby`, `lua`, `node` ή παρόμοια binaries είναι συνήθως ισοδύναμος με εκτέλεση εντολών ως root, εκτός αν τα ορίσματα είναι αυστηρά περιορισμένα και επικυρωμένα.<sup>[[1]](#references)[[2]](#references)[[3]](#references)[[4]](#references)[[5]](#references)[[7]](#references)[[9]](#references)[[11]](#references)</sup>

Συνήθης διαδικασία ελέγχου: πρώτα καταγράψτε τα δικαιώματα του χρήστη και, στη συνέχεια, εκτελέστε μια εντολή Python με την επιλογή `-c` του interpreter.<sup>[[1]](#references)[[3]](#references)[[4]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/python3 -c 'import os; os.system("id")'
sudo /usr/bin/python3 -c 'import os; os.system("/bin/sh")'
```

Παρακάτω παρουσιάζονται άλλα παραδείγματα διερμηνευτών· οι αναφερόμενοι διερμηνευτές τεκμηριώνουν την εκτέλεση inline κώδικα ή API θυγατρικών διεργασιών.<sup>[[5]](#references)[[6]](#references)[[7]](#references)[[8]](#references)[[9]](#references)[[10]](#references)[[11]](#references)</sup>

```bash
sudo /usr/bin/perl -e 'exec "/bin/sh";'
sudo /usr/bin/ruby -e 'exec "/bin/sh"'
sudo /usr/bin/node -e 'require("child_process").spawn("/bin/sh", {stdio: [0,1,2]})'
```

Η ακριβής διαδρομή έχει σημασία. Αν ο κανόνας sudo επιτρέπει το `/usr/bin/python3`, χρησιμοποιήστε αυτήν ακριβώς τη διαδρομή κατά την επαλήθευση.<sup>[[2]](#references)</sup>

Ένα glob εκτελέσιμου στο sudo, όπως το `/usr/bin/python*`, μπορεί επίσης να επιτρέπει το Python 2 για ένα script γραμμένο για Python 3. Αν το script φτάσει στο `input()` με κείμενο που ελέγχει ο καλών, το [Python 2 αξιολογεί αυτό το κείμενο ως έκφραση](https://docs.python.org/2/library/functions.html#input)· η ρητή κλήση του interpreter παρακάμπτει το shebang του script. Επαληθεύστε τα εγκατεστημένα δυαδικά αρχεία που ταιριάζουν, την αποτελεσματική ταυτότητα RunAs και την πολιτική ορισμάτων, τις αρνήσεις και το αν είναι προσβάσιμη η είσοδος, πριν θεωρήσετε ότι πρόκειται για διαδρομή εκτέλεσης.

Μια σταθερή διαδρομή script σε έναν κανόνα sudo που μπορεί να εκτελεστεί ως root δεν περιορίζει όσα εκτελεί το script. Για ένα αναγνώσιμο Bash wrapper, ελέγξτε αν η πρώτη εκτελέσιμη εντολή χρησιμοποιεί μια μη περικλεισμένη σε εισαγωγικά παράμετρο θέσης, όπως το `$1`, ως **λέξη εντολής**, ενώ το sudo επιτρέπει ορίσματα που επιλέγει ο καλών. Επιβεβαιώστε την αποτελεσματική ταυτότητα RunAs, την πολιτική κωδικού πρόσβασης και ορισμάτων, τις μεταγενέστερες αρνήσεις και τον κλάδο του script που εκτελείται στην πράξη· το `NOEXEC`, μια σταθερή ασφαλής λίστα ορισμάτων ή ένα wrapper που επικυρώνει την εντολή μπορούν να αλλάξουν το αποτέλεσμα. Κατά την απαρίθμηση, επιθεωρήστε στατικά το σύντομο script αντί να το καλέσετε με μια δοκιμαστική εντολή.

Ένας απεριόριστος κανόνας sudo για το `dotnet` που επιτρέπει εκτέλεση ως root αξίζει επίσης έλεγχο ως προς τον interpreter. Αν είναι εγκατεστημένο το .NET SDK, το [`dotnet fsi` εκτελεί κώδικα F# διαδραστικά ή από script](https://learn.microsoft.com/en-us/dotnet/fsharp/tools/fsharp-interactive/), ενώ το [`dotnet run` εκτελεί ένα project από τον πηγαίο κώδικα](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-run). Επιβεβαιώστε πρώτα την αποτελεσματική ταυτότητα RunAs και την ακριβή πολιτική ορισμάτων: ένας κανόνας που περιορίζεται σε συγκεκριμένη ασφαλή υποεντολή ή έμπιστη εφαρμογή αποτελεί διαφορετική παραχώρηση, ενώ μια εγκατάσταση μόνο για runtime μπορεί να μην περιλαμβάνει εντολές SDK. Το όνομα του εκτελέσιμου είναι αφορμή για έλεγχο, όχι απόδειξη εκτέλεσης κώδικα.

```bash
sudo /usr/bin/python3 -c 'import os; os.setuid(0); os.setgid(0); os.system("/bin/sh")'
```

## Editors που επιτρέπονται μέσω sudo

Αν το `sudo -l` επιτρέπει σε έναν χρήστη να εκτελέσει έναν διαδραστικό editor ως root, αντιμετωπίστε το ως επιφάνεια εκτέλεσης εντολών και όχι ως ακίνδυνη άδεια επεξεργασίας αρχείων. Οι editors συχνά μπορούν να εκτελέσουν shell commands, να διαβάσουν αυθαίρετα αρχεία, να γράψουν αυθαίρετα αρχεία ή να καλέσουν εξωτερικά βοηθητικά προγράμματα μέσα από τον editor.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

Συνήθης διαδικασία ελέγχου: καταγράψτε τα δικαιώματα του χρήστη και, στη συνέχεια, εκτελέστε κάθε επιτρεπόμενο editor ή pager μέσω sudo.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/nano /etc/hosts
sudo /usr/bin/vim /etc/hosts
sudo /usr/bin/less /etc/hosts
```

### Εκτέλεση εντολών από το Nano

Όταν επιτρέπεται η χρήση του `nano` μέσω sudo, μπορεί να είναι δυνατή η εκτέλεση εντολών από το περιβάλλον του editor.<sup>[[12]](#references)</sup>

```text
Ctrl+R
Ctrl+X
```

Στη συνέχεια, δώστε μια εντολή όπως `id` ή `/bin/sh` στη γραμμή εντολών του nano.<sup>[[12]](#references)</sup>

```bash
id
/bin/sh
```

Αν ένα διαδραστικό κέλυφος δεν διαθέτει χρησιμοποιήσιμες ροές τερματικού, αυτή η μορφή ανακατεύθυνσης αντιστοιχίζει την τυπική έξοδο και το σφάλμα του στον περιγραφέα 0.<sup>[[15]](#references)</sup>

```bash
reset; /bin/sh 1>&0 2>&0
```

Η ακριβής ακολουθία πλήκτρων μπορεί να διαφέρει ανάλογα με την έκδοση του nano και τις επιλογές κατά τη μεταγλώττιση, αλλά το ζήτημα ασφάλειας παραμένει το ίδιο: ο editor εκτελείται ως root και μπορεί να εκτελεί εξωτερικές εντολές.<sup>[[1]](#references)[[12]](#references)</sup>

### Άλλες συνηθισμένες δυνατότητες διαφυγής από editor

Οι editors τύπου Vim συνήθως επιτρέπουν την εκτέλεση εντολών μέσω του `:!`.<sup>[[13]](#references)</sup>

```text
:!/bin/sh
```

Οι pagers όπως το `less` μπορούν επίσης να επιτρέψουν την εκτέλεση shell.<sup>[[14]](#references)</sup>

Ένας κανόνας sudo που επιτρέπει την εκτέλεση του `apport-cli` ως root χρειάζεται τον ίδιο έλεγχο για pager. Οι επηρεαζόμενες εκδόσεις του Apport μπορούσαν να ανοίξουν μια αναφορά σφάλματος στο `less` με μέγεθος τερματικού που μπορούσε να ορίσει ο επιτιθέμενος· υπό τις κατάλληλες συνθήκες για το sudo και το pager, το pager μπορούσε έπειτα να παρέχει root shell. Ελέγξτε τον ενεργό κανόνα sudo, τη διαμόρφωση του pager και τη διόρθωση του πακέτου της διανομής προτού θεωρήσετε ευάλωτη την έκδοση και μόνο. Κατά την παθητική απαρίθμηση, διαβάστε τα μεταδεδομένα του πακέτου και της πολιτικής χωρίς να προκαλέσετε σφάλμα ή να ανοίξετε την προνομιούχα αναφορά. Η [καταχώριση CVE του Ubuntu](https://ubuntu.com/security/CVE-2023-1326) παραθέτει τις διορθωμένες εκδόσεις πακέτων ανά έκδοση, συμπεριλαμβανομένων των διορθώσεων που έχουν μεταφερθεί προς τα πίσω.

```text
!/bin/sh
```

## Άλλοι κίνδυνοι από κανόνες sudo και doas

Ξεκινήστε με `sudo -l`, `sudo -V` και κάθε σχετική πολιτική `doas`. Διαβάστε μαζί την επιτρεπόμενη εντολή, τον χρήστη RunAs, τα ορίσματα, το περιβάλλον και τις προεπιλογές. Η άδεια εκτέλεσης ως μη-root λογαριασμός υπηρεσίας μπορεί και πάλι να εκθέσει τα αρχεία αυτού του λογαριασμού ή να παρέχει διαδρομή προς root.

Ένα σταθερό Python script που επιτρέπεται από το sudo μπορεί και πάλι να εκτελέσει shell command με την ταυτότητα RunAs του, αν συνενώνει διαδραστική είσοδο ελεγχόμενη από τον καλούντα στο [`os.system()`](https://docs.python.org/3/library/os.html#os.system). Μια denylist σημείων στίξης του shell δεν αρκεί για να αποδείξει ότι η χρήση είναι ασφαλής: το [shell αναγνωρίζει επίσης την υποκατάσταση εντολών `$(...)`](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html). Επιβεβαιώστε ότι τα επιτρεπόμενα ορίσματα φτάνουν στον κλάδο εισόδου, ότι η είσοδος φτάνει στην εντολή shell χωρίς ασφαλή επικύρωση και ότι η ενεργή πολιτική sudo επιτρέπει τον προβλεπόμενο χρήστη RunAs. Η διαδρομή του script ή μια κλήση στο `os.system()` από μόνη της αποτελεί μόνο ένδειξη για έλεγχο· εξετάστε τον πηγαίο κώδικα χωρίς να εκτελέσετε το προνομιούχο script.

Μια ενεργή χορήγηση sudo ως root για το `chattr` μπορεί να αφαιρέσει το χαρακτηριστικό αμεταβλητότητας (`i`) ενός αρχείου, αλλά αυτό από μόνο του δεν παρέχει δικαίωμα εγγραφής ή νέα ταυτότητα. Το [εγχειρίδιο του `chattr`](https://man7.org/linux/man-pages/man1/chattr.1.html) αναφέρει ότι το χαρακτηριστικό εμποδίζει τις τροποποιήσεις και ότι μόνο ο root ή μια διεργασία με `CAP_LINUX_IMMUTABLE` μπορεί να το αλλάξει. Ελέγξτε την ακριβή πολιτική ορισμάτων sudo και την υποστήριξη του συστήματος αρχείων. Έπειτα, επαληθεύστε ξεχωριστά ότι ο καλών μπορεί να γράψει στο αρχείο μετά την εκκαθάριση του χαρακτηριστικού και ότι κάποιος καταναλωτής με υψηλότερη ταυτότητα το χρησιμοποιεί. Για παράδειγμα, η αντικατάσταση ενός login shell απαιτεί επίσης τα διαπιστευτήρια που δέχεται ο λογαριασμός-στόχος και πραγματική σύνδεση μέσω αυτού του shell. Κατά την απαρίθμηση, εξετάστε την πολιτική, τα χαρακτηριστικά αρχείων και τα δικαιώματα χωρίς να τα αλλάξετε.

Αν το sudo ζητά κωδικό πρόσβασης και κωδικό μιας χρήσης, αντιμετωπίστε αυτές τις προϋποθέσεις ξεχωριστά από τη χορήγηση της εντολής. Ένα αναγνώσιμο αρχείο `.google_authenticator` περιέχει ευαίσθητο υλικό seed, ενώ ένα παλιό hash κωδικού εφαρμογής ή βάσης δεδομένων είναι μόνο πιθανός κωδικός του τρέχοντος λογαριασμού· κανένα από τα δύο δεν αποδεικνύει ότι ο άλλος παράγοντας γίνεται δεκτός από την ενεργή διαμόρφωση PAM. Αφού λάβετε εξουσιοδότηση, εξετάστε τον ακριβή χρήστη RunAs και τα ορίσματα: μια απεριόριστη χορήγηση root για το `gem` του RubyGems μπορεί να εκθέσει την εντολή editor του ([GTFOBins](https://gtfobins.github.io/gtfobins/gem/)), αλλά μια περιορισμένη χορήγηση ή αποτυχημένη αυθεντικοποίηση δεν το επιτρέπει. Η παθητική απαρίθμηση πρέπει να αναφέρει διαδρομές και πολιτική, χωρίς να εμφανίζει το seed, να ανακτά κωδικό, να δημιουργεί κωδικό μιας χρήσης ή να εκτελεί την προνομιούχο εντολή.

Μια απεριόριστη χορήγηση sudo με δυνατότητα εκτέλεσης ως root για το `knife` του Chef απαιτεί έλεγχο στο επίπεδο interpreter: [η Chef τεκμηριώνει ότι το `knife exec -E` αξιολογεί τοπικά μια συμβολοσειρά Ruby](https://docs.chef.io/workstation/26/tools/knife/knife_exec/). Επιβεβαιώστε ότι ο ενεργός κανόνας sudo επιτρέπει την υποεντολή `exec` και το όρισμα `-E` που παρέχει ο καλών, την προβλεπόμενη ταυτότητα RunAs και τυχόν αντίστοιχες αρνήσεις εντολών ή σταθερά ορίσματα. Το εγκατεστημένο εκτελέσιμο ή ένας κανόνας περιορισμένος σε άλλες υποεντολές αποτελούν μόνο ένδειξη. Η παθητική απαρίθμηση πρέπει να αναφέρει τον κανόνα χωρίς να εκτελεί το `knife`.

Μια ακριβής χορήγηση sudo με δυνατότητα εκτέλεσης ως root για διαδραστικό `msfconsole` είναι εξίσου ευαίσθητη: το [GTFOBins τεκμηριώνει την κονσόλα `irb`](https://gtfobins.org/gtfobins/msfconsole/), η οποία μπορεί να κληρονομήσει την ταυτότητα sudo. Επιβεβαιώστε τον ενεργό χρήστη RunAs, τη λίστα επιτρεπόμενων ορισμάτων, τις αρνήσεις εντολών, το `NOEXEC` ή άλλους περιορισμούς, τη συμπεριφορά της εγκατεστημένης κονσόλας και αν ο καλών μπορεί να παρέχει διαδραστική είσοδο. Μια επισήμανση διαδρομής από μόνη της αποτελεί μόνο ένδειξη για έλεγχο· η παθητική απαρίθμηση δεν πρέπει να εκκινεί την κονσόλα.

Στο FreeBSD, ακόμη κι ένας κανόνας sudo περιορισμένος σε `pkg update` και `pkg install *` ως root απαιτεί έλεγχο εμπιστοσύνης των αποθετηρίων. Ελέγξτε αν ο καλών μπορεί να γράψει στο `/etc/hosts` και αν η *ενεργή* διαμόρφωση ενεργοποιημένου αποθετηρίου χρησιμοποιεί hostname HTTP με `signature_type: none`. Το [εγχειρίδιο `pkg.conf` του FreeBSD](https://man.freebsd.org/cgi/man.cgi?query=pkg.conf&sektion=5) αναφέρει ότι το `none` απενεργοποιεί τους ελέγχους υπογραφών· το `pkg+http` από μόνο του δεν το αποδεικνύει. Ένα πακέτο μπορεί να περιέχει scripts εγκατάστασης ([FreeBSD Porter's Handbook](https://docs.freebsd.org/en/books/porters-handbook/pkg-files/)), οπότε ένας καλών που ελέγχει πραγματικά το endpoint του αποθετηρίου και μπορεί να επιλέξει πακέτο ενδέχεται να περάσει το όριο εμπιστοσύνης προς root. Επαληθεύστε τις παρακάμψεις αποθετηρίων, την επίλυση SRV/mirror, τα ενεργά ορίσματα sudo, την επιλογή πακέτου και την εκτέλεση script πριν καταλήξετε σε αυτό το συμπέρασμα. Εξετάστε την πολιτική και μικρά τοπικά αρχεία διαμόρφωσης χωρίς να ανακατευθύνετε ονόματα ή να εκτελέσετε `pkg` κατά την απαρίθμηση.

Μια χορήγηση sudo με δυνατότητα εκτέλεσης ως root για `apt-get update` και `apt-get upgrade` απαιτεί επίσης έλεγχο εμπιστοσύνης αποθετηρίων όταν το sudo διατηρεί `http_proxy` που ελέγχει ο καλών. Ελέγξτε αν η ενεργή διαμόρφωση APT χρησιμοποιεί πράγματι αυτή τη μεταβλητή και ποια αιτήματα προς ενεργοποιημένα αποθετήρια μπορεί να επηρεάσει· ένας proxy από μόνος του δεν μπορεί να αντικαταστήσει πακέτα από αρχείο που έχει αυθεντικοποιηθεί με έμπιστο κλειδί υπογραφής. Το [εγχειρίδιο μεταφοράς HTTP του APT](https://manpages.debian.org/experimental/apt/apt-transport-http.1.en.html) τεκμηριώνει την προτεραιότητα των proxy, ενώ το [apt-secure](https://manpages.debian.org/experimental/apt/apt-secure.8.en.html) τεκμηριώνει τους ελέγχους υπογραφών, τις παρακάμψεις μη ασφαλών αποθετηρίων και την επιβεβαίωση για μη αυθεντικοποιημένα πακέτα. Επιβεβαιώστε τον ακριβή χρήστη RunAs και τα ορίσματα sudo, την πολιτική αυθεντικοποίησης αποθετηρίων, τυχόν απαιτούμενη διαδραστική αποδοχή και αν η επιλεγμένη αναβάθμιση εκτελεί scripts πακέτων ως root. Εξετάστε παθητικά την πολιτική και την τοπική διαμόρφωση· μην ανακατευθύνετε την κίνηση πακέτων ή εκτελέσετε αναβάθμιση κατά την απαρίθμηση.

Ένας κανόνας sudo με δυνατότητα εκτέλεσης ως root για `snap install` μπορεί να δημιουργήσει όριο από πακέτο σε κώδικα, αν τα ορίσματά του επιτρέπουν στον καλούντα να επιλέξει τοπικό snap και επιτρεπτικό τρόπο εγκατάστασης. Το [Snap τεκμηριώνει](https://snapcraft.io/docs/explanation/snap-development/install-modes/) ότι το `--dangerous` παρακάμπτει τους ελέγχους assertion για τοπικά snap και ότι το `--devmode` χαλαρώνει τον περιορισμό· [ένα install hook μπορεί να εκτελεστεί κατά την αρχική εγκατάσταση](https://snapcraft.io/docs/reference/development/supported-snap-hooks/). Ελέγξτε την ακριβή πολιτική ορισμάτων/RunAs του sudo, ποιος ελέγχει το αρχείο snap, αν το εγκατεστημένο snapd δέχεται αυτούς τους τρόπους και την ταυτότητα και τον περιορισμό του hook προτού ισχυριστείτε πρόσβαση σε προστατευμένα αρχεία του host. Ένα εκτελέσιμο `snap` ή ένας κανόνας που μοιάζει να περιέχει wildcard δεν αποδεικνύει από μόνο του αυτή την αλυσίδα. Η παθητική απαρίθμηση δεν πρέπει να εγκαθιστά πακέτο ή να εκτελεί το hook του.

Για μια ακριβή χορήγηση sudo σε προσαρμοσμένο δυαδικό που διαβάζει διαπιστευτήρια ως **μη-root** λογαριασμός, εξετάστε πρώτα το δυαδικό και τα δικαιώματα του αρχείου χωρίς να το εκτελέσετε. Μια ενσωματωμένη πύλη κωδικού μπορεί να εμφανίζεται μόνο ως χαρακτήρες μεγάλου πλάτους· το [GNU `strings` τεκμηριώνει εξαγωγή 16-bit little-endian](https://sourceware.org/binutils/docs/binutils/strings.html). Μια ορατή συμβολοσειρά δεν αποδεικνύει ότι είναι ο αποδεκτός κωδικός ή ότι ο κλάδος επιτυχίας εκθέτει τρέχον διαπιστευτήριο. Επιβεβαιώστε ξεχωριστά τη συμπεριφορά του δυαδικού, την πρόσβαση του λογαριασμού-στόχου στα προστατευμένα δεδομένα, την εγκυρότητα των διαπιστευτηρίων και κάθε επόμενη μετάβαση λογαριασμού ή ομάδας. Αν ο λογαριασμός ανήκει στην ομάδα `docker`, επαληθεύστε την πρόσβαση στο socket και την ταυτότητα του daemon, rootful ή rootless, πριν συμπεράνετε πρόσβαση σε root του host· το [Docker τεκμηριώνει τις συνέπειες της ομάδας του σε επίπεδο root](https://docs.docker.com/engine/install/linux-postinstall/). Η συνήθης απαρίθμηση πρέπει να αναφέρει τον κανόνα sudo και τη συμμετοχή στην ομάδα χωρίς να εκτελεί το δυαδικό ή να εξάγει τις συμβολοσειρές του.

Ένας κανόνας sudo με wildcard για scripts συντήρησης εφαρμογής απαιτεί έλεγχο πέρα από τη διαδρομή του script. Ελέγξτε αν το επιτρεπόμενο script δέχεται απεριόριστα ορίσματα ή διαβάζει ρυθμίσεις που μπορούν να τροποποιηθούν μέσω λογαριασμού εφαρμογής χαμηλότερων δικαιωμάτων και, στη συνέχεια, ανιχνεύστε αυτές τις τιμές μέχρι τις εντολές shell ή το περιβάλλον υποδιεργασίας. Για παράδειγμα, το [`zmupdate.pl` του ZoneMinder συνθέτει εντολή `mysqldump` και την εκτελεί μέσω `qx`](https://github.com/ZoneMinder/ZoneMinder/blob/master/scripts/zmupdate.pl.in), ενώ το [`zmdc.pl` αντιγράφει τη ρύθμιση `ZM_LD_PRELOAD` στο `LD_PRELOAD`](https://github.com/ZoneMinder/ZoneMinder/blob/master/scripts/zmdc.pl.in) πριν εκκινήσει daemons. Μια διαδρομή διαμόρφωσης εγγράψιμη στο `/tmp` από μόνη της αποτελεί μόνο ένδειξη για έλεγχο· εξετάστε το δυαδικό και τα μεταδεδομένα αρχείων χωρίς να εκτελέσετε την προνομιούχο μεταφορά.
- Ένας κανόνας sudo για `git apply` μπορεί να επιτρέψει στον λογαριασμό RunAs να γράψει αρχεία που επιλέγει patch ελεγχόμενο από τον καλούντα. Το [CVE-2023-23946](https://github.com/git/git/security/advisories/GHSA-r87m-v37r-cwfh) επέτρεπε σε ειδικά διαμορφωμένο patch να δημιουργήσει symlink και στη συνέχεια να γράψει εκτός του working tree, ακόμη κι όταν η εντολή δεν δεχόταν `--unsafe-paths`. Ελέγξτε τον ενεργό κανόνα ορισμάτων sudo, την πηγή του patch, την πρόσβαση του λογαριασμού RunAs στον κατάλογο εργασίας και τη διόρθωση του εγκατεστημένου Git ή vendor backport. Ένας απεριόριστος κανόνας που δέχεται `--unsafe-paths` αποτελεί ξεχωριστό, ρητό κίνδυνο επιλογής· ούτε η έκδοση Git ούτε η άδεια `git apply` από μόνες τους αποδεικνύουν ότι μπορεί να τροποποιηθεί προστατευμένο αρχείο. Μην εφαρμόζετε μη έμπιστο patch κατά την παθητική απαρίθμηση.
- Ένας κανόνας `clamscan --debug` με δυνατότητα εκτέλεσης ως root μπορεί να περάσει όριο ανάγνωσης, αν χρήστης χαμηλότερων δικαιωμάτων μπορεί να δώσει εικόνα DMG και ο εγκατεστημένος parser επηρεάζεται από το [CVE-2023-20052](https://blog.clamav.net/2023/02/clamav-01038-01052-and-101-patch.html), το οποίο μπορούσε να αποκαλύψει περιεχόμενα αρχείων μέσω εξόδου debug. Επιβεβαιώστε τα ακριβή επιτρεπόμενα ορίσματα και τη διαδρομή σάρωσης, τον έλεγχο της εισόδου, τον ενεργό λογαριασμό RunAs, τη διόρθωση/backport του engine και αν η έξοδος είναι ορατή στον καλούντα. Αν ευρύτερος κανόνας επιτρέπει `--file-list`/`-f`, εξετάστε ξεχωριστά τη συμπεριφορά της λίστας αρχείων· μια πολιτική σταθερή σε `--debug <scan-path>` δεν το επιτρέπει. Εξετάστε την πολιτική και τα μεταδεδομένα πακέτου χωρίς να σαρώσετε ειδικά διαμορφωμένο αρχείο ή να εμφανίσετε προστατευμένη έξοδο κατά την απαρίθμηση.
- Ένας κανόνας sudo με δυνατότητα εκτέλεσης ως root που ανοίγει εικόνα κρυπτογραφημένου δίσκου επιλεγμένη από τον καλούντα, μαζί με δεύτερο κανόνα που προσαρτά το mapper που προκύπτει, μπορεί να εισαγάγει αρχεία ελεγχόμενα από τον καλούντα στο mount namespace του host. Επιβεβαιώστε και τους δύο ενεργούς κανόνες και τα ορίσματά τους, τον έλεγχο της εικόνας και του ονόματος mapper, το πραγματικό σημείο προσάρτησης και τον ιδιοκτήτη και τα δικαιώματα των αρχείων που προκύπτουν. Μια μετάβαση set-user-ID απαιτεί επιπλέον προσβάσιμο εκτελέσιμο, επιλογές mount που το επιτρέπουν (`nosuid` το εμποδίζει) και εφαρμοστέα πολιτική διεργασίας ή MAC· το άνοιγμα ή η προσάρτηση εικόνας από μόνη της αποτελεί μόνο ένδειξη. Μια ξεχωριστή διαδρομή μέσω υπάρχοντος backup απαιτεί το πραγματικό κλειδί και χρήσιμο αναγνώσιμο μυστικό μέσα σε αυτό. Εξετάστε την πολιτική και τις διαδρομές χωρίς να ανοίξετε ή να προσαρτήσετε εικόνα κατά την παθητική απαρίθμηση. Δείτε το [εγχειρίδιο cryptsetup](https://gitlab.com/cryptsetup/cryptsetup/-/blob/main/man/cryptsetup.8.adoc) και τις [επιλογές mount](https://man7.org/linux/man-pages/man8/mount.8.html).
- Ένας κανόνας sudo με δυνατότητα εκτέλεσης ως root για shell ή Python script απαιτεί έλεγχο του working directory, αν το script εκτελεί `./helper` χωρίς προηγουμένως να μεταβεί σε σταθερό κατάλογο. Μια Python λίστα όπως `['./helper']` που περνά στο `subprocess.run` μπορεί να έχει την ίδια συμπεριφορά επιλογής καταλόγου εργασίας από τον καλούντα. Ο καλών ενδέχεται να επιλέξει εγγράψιμο κατάλογο και να τοποθετήσει εκεί εκτελέσιμο με αυτό το σχετικό όνομα· μια απόλυτη διαδρομή αλλού στο script δεν προστατεύει αυτή την κλήση. Επιβεβαιώστε τον ενεργό κανόνα, το `runchdir` ή άλλη πολιτική αλλαγής καταλόγου, τη ροή και την προσπελασιμότητα του κλάδου του script, τον εγγράψιμο και εκτελέσιμο κατάλογο, καθώς και τους περιορισμούς mount/`NOEXEC` πριν το θεωρήσετε εκτέλεση κώδικα. Αν το script δεν είναι αναγνώσιμο, η συμπεριφορά παραμένει άγνωστη μέχρι να εξεταστεί ο πηγαίος κώδικας μέσω εξουσιοδοτημένης διαδρομής. Εξετάστε τα scripts στατικά αντί να εκτελέσετε το helper. Το [εγχειρίδιο sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) τεκμηριώνει την πολιτική working directory.
- Ένας σταθερός validator Python με δυνατότητα εκτέλεσης ως root μπορεί και πάλι να αξιολογήσει αρχείο δεδομένων που επιλέγει ο καλών. Η [τεκμηρίωση της Python για το `eval()` προειδοποιεί κατά της μη έμπιστης εισόδου](https://docs.python.org/3/library/functions.html#eval): έλεγχος επιθέματος εισόδου, αριθμητικό πρόθεμα ή κλάδος επικύρωσης δεν αποτελούν sandbox, αν η υπόλοιπη έκφραση φτάνει στο `eval`. Επιβεβαιώστε τον ενεργό κανόνα sudo, αν ο καλών μπορεί να επιλέξει και να ελέγξει το συγκεκριμένο αρχείο, τις συνθήκες κλάδων του parser και τη σύνθεση της έκφρασης, καθώς και την ταυτότητα της προνομιούχας διεργασίας πριν το χαρακτηρίσετε διαδρομή εκτέλεσης. Η παρουσία του `eval` σε αναγνώσιμο script από μόνη της αποτελεί μόνο αφορμή για έλεγχο· εξετάστε τον πηγαίο κώδικα και τα δικαιώματα αρχείων χωρίς να εκτελέσετε τον validator ή να υποβάλετε δοκιμαστική έκφραση κατά την απαρίθμηση.
- Ένα Ruby wrapper sudo με δυνατότητα εκτέλεσης ως root που διαβάζει σχετικό όνομα αρχείου YAML, όπως `YAML.load(File.read("dependencies.yml"))`, μπορεί να λάβει είσοδο από τον working directory του καλούντος, εκτός αν το wrapper ή η πολιτική sudo ορίζει αυτόν τον κατάλογο. Ελέγξτε τα ακριβή επιτρεπόμενα ορίσματα, τα δικαιώματα καταλόγου και αρχείου και τη συμπεριφορά του εγκατεστημένου Psych: παλαιότερες υλοποιήσεις του `YAML.load` μπορούσαν να αποσειριοποιούν αυθαίρετα αντικείμενα Ruby, ενώ νεότερες εκδόσεις περιορίζουν τις κλάσεις από προεπιλογή. Ένα στατικό σημείο κλήσης αποτελεί μόνο ένδειξη για έλεγχο· επιβεβαιώστε ότι το αρχείο βρίσκεται πράγματι σε κατάλογο εγγράψιμο από τον καλούντα και ότι ο εγκατεστημένος loader δέχεται επικίνδυνες κλάσεις. Για μη έμπιστη είσοδο προτιμήστε το `safe_load` με ρητή, ελάχιστη allowlist κλάσεων. Δείτε την [τεκμηρίωση Psych του Ruby 3.0](https://docs.ruby-lang.org/en/3.0/Psych.html) και την [τεκμηρίωση Psych του Ruby 3.1](https://ruby-doc.org/core-3.1.2/Psych.html).

- Μια ακριβής χορήγηση `sudo go run /absolute/file.go` με δυνατότητα εκτέλεσης ως root απαιτεί έλεγχο working directory, όταν ο πηγαίος κώδικας Go διαβάζει σχετικό αρχείο WASM και ενδέχεται να εκτελέσει σχετικό shell script αφού εξετάσει το αποτέλεσμά του. Επιβεβαιώστε τον ενεργό χρήστη RunAs, τα ορίσματα και τις αρνήσεις εντολών, την ύπαρξη τρέχοντος καταλόγου εγγράψιμου από τον καλούντα, τη ροή δεδομένων WASM προς τον κλάδο και αν αυτός ο κλάδος καλεί το helper. Το σταθερό sudo `runchdir`, το `os.Chdir` ή το [`exec.Cmd.Dir`](https://pkg.go.dev/os/exec) μπορούν να αλλάξουν τη θέση αναζήτησης. Η στατική συνύπαρξη αποτελεί μόνο υποψήφια ένδειξη· εξετάστε τον πηγαίο κώδικα χωρίς να εκτελέσετε Go, WASM ή το helper.
- Τα `sudoedit` και τα wildcards ορισμάτων απαιτούν ελέγχους ακριβούς έκδοσης και κανόνα· η [λίστα ελέγχου](linux-privilege-escalation-checklist.md) περιλαμβάνει το ζήτημα επεξεργασίας αρχείων sudoedit. Για χορήγηση `sudoedit` μεταξύ χρηστών σε διαδρομή με wildcard, εξετάστε την ενεργή ρύθμιση `sudoedit_follow` ή `FOLLOW`, το `sudoedit_checkdir`, τον επιλυμένο στόχο και ποιος μπορεί να αντικαταστήσει κάθε γονική εγγραφή. Η πρώτη μπορεί να επιτρέψει ακολούθηση symlink, ενώ η απενεργοποίηση της δεύτερης αφαιρεί τους ελέγχους εγγράψιμων καταλόγων· καμία ρύθμιση από μόνη της δεν αποδεικνύει εγγραφή σε αρχείο άλλου χρήστη. Επιβεβαιώστε την εγκατεστημένη πολιτική sudo και τα ακριβή ορίσματα που αντιστοιχούν πριν καταλήξετε σε συμπέρασμα. Δείτε τους [ορισμούς επιλογών sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf).
- Σε κανόνα εντολής sudoers, ένα wildcard ορισμάτων μπορεί να αντιστοιχίσει whitespace και χαρακτήρες διαδρομής. Ένας κανόνας για εντολή με δυνατότητα ανάγνωσης και όρισμα όπως `/restricted/*` μπορεί επομένως να επιτρέπει επιπλέον όρισμα αρχείου μετά από συμβατό πρόθεμα. Εξετάστε τον ακριβή χρήστη run-as, τη διαδρομή εντολής, το μοτίβο ορισμάτων και τυχόν μεταγενέστερες αρνήσεις· η αποδεδειγμένη ανάγνωση αρχείου δεν συνεπάγεται εκτέλεση εντολών. Το [εγχειρίδιο sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) διακρίνει τα globs ορισμάτων από τα globs διαδρομής εντολής.
- Ένα glob ορισμάτων που μοιάζει με διαδρομή μπορεί επίσης να αντιστοιχίσει `../`. Για παράδειγμα, ένας κανόνας `node /opt/scripts/*.js` με δυνατότητα εκτέλεσης ως root μπορεί να επιτρέψει αρχείο JavaScript ελεγχόμενο από τον καλούντα, εκτός του `/opt/scripts`, αν το παρεχόμενο όνομα διαδρομής εξακολουθεί να αρχίζει με `/opt/scripts/` και επιλύεται μέσω τμημάτων γονικών καταλόγων. Αυτό είναι glob **ορίσματος**· το glob της διαδρομής εντολής για το εκτελέσιμο Node έχει διαφορετικούς κανόνες αντιστοίχισης κάθετων. Ελέγξτε τον ενεργό κανόνα, μεταγενέστερες αρνήσεις, την επίλυση ονόματος διαδρομής, τον έλεγχο του αρχείου-στόχου και τυχόν περιορισμούς κανονικών εκφράσεων ή digest του sudoers πριν καταλήξετε σε εκτέλεση κώδικα. Δείτε τους [κανόνες wildcard του sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) και την [τεκμηρίωση γραμμής εντολών του Node](https://nodejs.org/api/cli.html).
- Τα προγράμματα αρχειοθέτησης και άλλα βοηθητικά προγράμματα μπορεί να έχουν hooks εκτέλεσης. Ελέγξτε τα ακριβή επιτρεπόμενα ορίσματα στο [GTFOBins](https://gtfobins.github.io/) αντί να υποθέτετε ότι μόνο shells ή interpreters εκτελούν εντολές.
- Ένας απεριόριστος κανόνας `qpdf` με δυνατότητα εκτέλεσης ως root μπορεί να εκθέσει προνομιούχο αρχείο μέσω συνημμένων PDF: το qpdf 10.2 και νεότερες εκδόσεις υποστηρίζουν `--empty` και `--add-attachment file ... --` με PDF εξόδου. Αν η προνομιούχα διεργασία μπορεί να διαβάσει την επιλεγμένη πηγή και να γράψει το PDF σε διαδρομή προσβάσιμη από τον καλούντα, αυτή η έξοδος μπορεί να μεταφέρει τα bytes της πηγής. Εξετάστε τα ενεργά ορίσματα και τις εξαιρέσεις sudo, την έκδοση qpdf, την πρόσβαση στην πηγή και τη διαδρομή εξόδου προτού συμπεράνετε ότι είναι δυνατή η αποκάλυψη αρχείου. Η ανάγνωση root SSH key είναι χρήσιμη για σύνδεση μόνο όταν το κλειδί είναι έγκυρο και επιτρέπεται αυθεντικοποίηση SSH ως root. Δείτε τις [επιλογές συνημμένων του qpdf](https://qpdf.readthedocs.io/en/stable/cli.html#embedded-files-attachments).
- Η επαναχρησιμοποίηση timestamp sudo εξαρτάται από την πολιτική cache, τον χρήστη-ιδιοκτήτη, το terminal/session και τα δικαιώματα. Ο [οδηγός κλιμάκωσης προνομίων](../linux-basics/linux-privilege-escalation/README.md#reusing-sudo-tokens) καλύπτει τους σχετικούς ελέγχους.
- Το `doas` έχει δικούς του κανόνες και διαμόρφωση. Ελέγξτε τις επιτρεπόμενες εντολές και τις διαδρομές διαμόρφωσης που είναι εγγράψιμες, όπως περιγράφεται στην [ενότητα doas](../linux-basics/linux-privilege-escalation/README.md#doas).

### Εργαλεία build και πακέτων που εκτελούνται μέσω sudo

Μια απεριόριστη χορήγηση sudo για το `forge` του Foundry μπορεί να έχει σημασία ακόμη κι όταν η ταυτότητα RunAs είναι άλλος μη-root χρήστης. Επιλογές compiler όπως το `--use` μπορούν να επιλέξουν τοπικό εκτελέσιμο, ενώ το `forge flatten -o` επιλέγει αρχείο εξόδου. Ελέγξτε την εγκατεστημένη έκδοση Forge, τα ακριβή ορίσματα sudo, την προσβασιμότητα του project και των διαδρομών compiler, τα δικαιώματα εξόδου και το ενεργό περιβάλλον προτού θεωρήσετε εκμεταλλεύσιμη τη χορήγηση. Ένα σχετικό εκτελέσιμο helper που εντοπίζεται μέσω `PATH` είναι διαδρομή που εξαρτάται από την έκδοση και το περιβάλλον, όχι ιδιότητα που πρέπει να θεωρείται δεδομένη για κάθε build Forge.<sup>[[23]](#references)[[24]](#references)</sup>

Μια απεριόριστη χορήγηση `pacman` με δυνατότητα εκτέλεσης ως root επιτρέπει περισσότερα από ερωτήματα πακέτων: το `-U` δέχεται τοπικό πακέτο, τα πακέτα μπορεί να περιέχουν scripts εγκατάστασης και το `--hookdir` επιλέγει διαφορετικό κατάλογο hooks. Εξετάστε τον ενεργό κανόνα sudo, τους περιορισμούς ορισμάτων και τις εξαιρέσεις πριν από οποιαδήποτε δοκιμή· η παθητική απαρίθμηση δεν απαιτεί εγκατάσταση πακέτου ή εκτέλεση hook.<sup>[[25]](#references)[[26]](#references)</sup>

Ένα σταθερό shell wrapper sudo μπορεί επίσης να εγκαθιστά ονομασμένη εξάρτηση npm και στη συνέχεια να εκκινεί εφαρμογή Node. Εξετάστε τον ακριβή κανόνα RunAs, αν το πακέτο είναι ήδη εγκατεστημένο, το ενεργό `HOME` και το `userconfig` του npm, τη διαμόρφωση του project ή τις παρακάμψεις γραμμής εντολών και αν χρήστης χαμηλότερων δικαιωμάτων ελέγχει το registry ή το πακέτο που επιστρέφεται για αυτό το όνομα. Το [npm τεκμηριώνει την αναζήτηση `.npmrc` ανά χρήστη και project](https://docs.npmjs.com/cli/v6/configuring-npm/npmrc/)· η συμπεριφορά του `HOME` στο sudo εξαρτάται από την εγκατεστημένη πολιτική και τη διανομή, επομένως ένα `.npmrc` εγγράψιμο από χρήστη μπορεί ή όχι να διαβαστεί από την προνομιούχα διεργασία npm. Αν το νέο πακέτο εισάγεται από την προνομιούχα εφαρμογή, ο κώδικας module του μπορεί να εκτελεστεί με την ταυτότητα αυτής της εφαρμογής. Τα scripts κατά την εγκατάσταση αποτελούν ξεχωριστή διαδρομή που εξαρτάται από την έκδοση και τη διαμόρφωση· το [npm τεκμηριώνει τον κύκλο ζωής και τον χειρισμό χρήστη τους](https://docs.npmjs.com/cli/v6/using-npm/scripts/). Μια διαδρομή `.npmrc` ή μια γραμμή `npm install` από μόνη της αποτελεί μόνο ένδειξη για έλεγχο. Εξετάστε τον κανόνα, το σύντομο wrapper, τις διαδρομές διαμόρφωσης και την προέλευση του πακέτου χωρίς να εγκαταστήσετε πακέτο ή να εκκινήσετε την εφαρμογή κατά την παθητική απαρίθμηση.

Μια χορήγηση `pip` ή `pip3 download` με δυνατότητα εκτέλεσης ως root αποτελεί επίσης αφορμή για έλεγχο build πακέτου, όταν τα ορίσματα επιτρέπουν στον καλούντα να επιλέξει μη έμπιστη διανομή πηγαίου κώδικα, ακόμη κι αν το μοτίβο URL την περιορίζει σε τοπική υπηρεσία και επίθεμα `.tar.gz`. Το `pip download` δέχεται URL αρχείων και επιλύει μεταδεδομένα πακέτων· η προετοιμασία ενός sdist μπορεί να καλέσει το build backend του ή παλιό κώδικα `setup.py` πριν απλώς αποθηκευτεί το αρχείο. Επιβεβαιώστε τον ακριβή χρήστη sudo RunAs και τον κανόνα ορισμάτων, αν ο καλών μπορεί να δημοσιεύσει ή να αντικαταστήσει το επιλεγμένο αρχείο και αν αυτή η έκδοση pip πράγματι προετοιμάζει τα μεταδεδομένα του. Ένα σταθερό, έμπιστο archive ή wheel δεν αποδεικνύει αυτή τη διαδρομή. Μην ανακτήσετε ή δημιουργήσετε build μη έμπιστου πακέτου κατά την παθητική απαρίθμηση. Δείτε την [εντολή download του pip](https://pip.pypa.io/en/stable/cli/pip_download/), τη [διεπαφή build-system](https://pip.pypa.io/en/stable/reference/build-system/) και τις [οδηγίες ασφαλούς εγκατάστασης](https://pip.pypa.io/en/stable/topics/secure-installs/).

Ένας κανόνας sudo που επιτρέπει `pip install` με διαδρομή τοπικού project επιλεγμένη από τον καλούντα δημιουργεί πιο άμεσο όριο build. Το [pip δέχεται τοπικούς καταλόγους project](https://pip.pypa.io/en/stable/topics/local-project-installs/) και καλεί το build system τους· το [build backend εκτελεί build hooks που ελέγχονται από το project](https://pip.pypa.io/en/stable/reference/build-system/). Επιβεβαιώστε την ενεργή ταυτότητα RunAs, τους ακριβείς περιορισμούς και τις αρνήσεις ορισμάτων, τον έλεγχο του επιλεγμένου project και τη συμπεριφορά του εγκατεστημένου pip/backend προτού θεωρήσετε τον κανόνα προνομιούχα εκτέλεση κώδικα. Ένα σταθερό έμπιστο project ή κανόνας που αποκλείει διαδρομές επιλεγμένες από τον καλούντα δεν αποδεικνύει αυτή τη διαδρομή. Εξετάστε τον κανόνα και τα μεταδεδομένα του project χωρίς να εγκαταστήσετε πακέτο κατά την παθητική απαρίθμηση.

Μια απεριόριστη χορήγηση `easy_install` με δυνατότητα εκτέλεσης ως root αποτελεί παρόμοια ένδειξη παλαιού μηχανισμού build πακέτων. Το [Setuptools τεκμηριώνει](https://setuptools.pypa.io/en/stable/deprecated/easy_install.html) ότι το Easy Install δέχεται τοπικό κατάλογο project και δημιουργεί builds διανομών πηγαίου κώδικα· ένα project ελεγχόμενο από τον καλούντα μπορεί να εκτελέσει το `setup.py` κατά τη δημιουργία build με την ταυτότητα sudo. ### Scripts επαναφοράς archive Python που εκτελούνται ως root

Ένας αυστηρά περιορισμένος κανόνας sudo για Python script επαναφοράς εξακολουθεί να απαιτεί έλεγχο της εισόδου archive. Αν ο καλών μπορεί να επιλέξει ή να αντικαταστήσει το archive και το script το αποσυμπιέζει ως root με `tarfile.extractall(filter="data")`, ελέγξτε τις ενημερώσεις ασφαλείας του interpreter πριν εμπιστευτείτε το φίλτρο. Το CPython διόρθωσε διάφορες παρακάμψεις φίλτρων μέσω symlink και hard link, μεταξύ των οποίων το CVE-2025-4517, στις εκδόσεις 3.9.23, 3.10.18, 3.11.13, 3.12.11 και 3.13.4. Τα backport διανομών μπορούν να διορθώσουν παλαιότερη έκδοση, επομένως η εμφανιζόμενη έκδοση interpreter από μόνη της δεν αποδεικνύει ευπάθεια.<sup>[[16]](#references)[[17]](#references)</sup>

Για παθητικό έλεγχο, διαβάστε την ακριβή εντολή sudo και το script, ανιχνεύστε ποιο όρισμα επιλέγει το archive και ελέγξτε αν ο τρέχων χρήστης μπορεί να γράψει στο archive ή στον κατάλογο που το περιέχει. Επιβεβαιώστε ξεχωριστά το vendor patch που είναι εγκατεστημένο και τον προορισμό εξαγωγής· το `filter="data"` δεν καθιστά ασφαλές κάθε μη έμπιστο archive.<sup>[[16]](#references)[[17]](#references)</sup>

### Loaders μοντέλων machine learning που εκτελούνται μέσω sudo

Ένας κανόνας sudo που επιτρέπει αρχείο `.pt`, `.pth` ή `.ckpt` επιλεγμένο από τον καλούντα απαιτεί έλεγχο, όταν ένα προνομιούχο script περνά αυτό το αρχείο στο [`torch.load`](https://docs.pytorch.org/docs/stable/generated/torch.load.html), στο `pickle.load` ή σε άλλο loader βασισμένο σε pickle. Ελέγξτε τον ενεργό κανόνα RunAs, αν ο καλών μπορεί να δημιουργήσει ή να αντικαταστήσει το επιλεγμένο μοντέλο και την πραγματική ροή ορίσματος μέσω οποιουδήποτε shell wrapper προς το Python helper. Η επέκταση `.pth` ονομάζει επίσης άσχετα αρχεία διαμόρφωσης Python site, επομένως η επέκταση από μόνη της δεν αποτελεί ένδειξη φόρτωσης μοντέλου. Μια σάρωση archive ή στατικό scan pickle δεν αποδεικνύει ότι η μεταγενέστερη φόρτωση είναι ασφαλής· εξετάστε τη [συμπεριφορά `weights_only` που εξαρτάται από την έκδοση](https://docs.pytorch.org/docs/stable/notes/serialization.html) και τυχόν allowlisting. Δείτε τις [σημειώσεις ML pickle και Fickling](../../generic-methodologies-and-resources/python/keras-model-deserialization-rce-and-gadget-hunting.md). Η παθητική απαρίθμηση δεν πρέπει ποτέ να φορτώνει ή να αποσυμπιέζει το μοντέλο.

### Ανάλυση εκφράσεων από αποθηκευμένη είσοδο μέσω sudo

Ένα σταθερό Python script που εκτελείται ως root μέσω sudo μπορεί και πάλι να αξιολογήσει κείμενο που χρήστης χαμηλότερων δικαιωμάτων αποθηκεύει σε βάση δεδομένων εφαρμογής. Στο TensorFlow, κλήση `preprocess_input_exprs_arg_string(value, safe=False)` επιλέγει διαδρομή `eval`· η [συμβουλευτική ανακοίνωση του TensorFlow](https://github.com/tensorflow/tensorflow/security/advisories/GHSA-75c9-jrh4-79mc) περιγράφει τον μη ασφαλή parser και διόρθωση στον caller της γραμμής εντολών. Μια ρητή κλήση `safe=False` από εφαρμογή απαιτεί ξεχωριστό έλεγχο ακόμη κι όταν έχει διορθωθεί ο caller της γραμμής εντολών. Ελέγξτε τον ενεργό κανόνα sudo, ποιος μπορεί να τροποποιήσει τη συγκεκριμένη εγγραφή εισόδου, αν το φιλτράρισμα ή η βαθμολόγηση επιτρέπει στην εγγραφή να φτάσει στην κλήση και τη συμπεριφορά της εγκατεστημένης συνάρτησης. Μια έκδοση TensorFlow, μια χορήγηση sudo ή ένα hardcoded αρχείο μοντέλου από μόνα τους δεν αποδεικνύουν την αλυσίδα. Εξετάστε παθητικά το script και τη ροή δεδομένων· μην εκτελέσετε το προνομιούχο helper ή υποβάλετε δοκιμαστικές εκφράσεις κατά την απαρίθμηση.

### Διαμόρφωση needrestart που επιτρέπεται μέσω sudo

Το `needrestart -c` φορτώνει αρχείο διαμόρφωσης Perl επιλεγμένο από τον καλούντα και αξιολογεί τα περιεχόμενά του. Αν το `sudo -l` επιτρέπει το `needrestart` ως root με ορίσματα που επιτρέπουν το `-c`, και ο καλών μπορεί να επιλέξει αναγνώσιμο αρχείο διαμόρφωσης σε εγγράψιμη τοποθεσία, αυτή η άδεια μπορεί να οδηγήσει σε εκτέλεση κώδικα ως root. Ελέγξτε τον ακριβή χρήστη sudo run-as και τον κανόνα ορισμάτων· ένας κανόνας που επιτρέπει μόνο σταθερή λίστα ορισμάτων μπορεί να εμποδίσει αυτή τη διαδρομή. Αυτό είναι ξεχωριστό από τις ευπάθειες σάρωσης interpreter του needrestart: η ενημέρωση του πακέτου ή η απενεργοποίηση του `interpscan` δεν καθιστά ασφαλή μια απεριόριστη χορήγηση root `-c`.<sup>[[2]](#references)[[18]](#references)[[19]](#references)</sup>

### Imports Python μέσω sudo ως άλλος λογαριασμός

Ένα σταθερό Python entry point μπορεί και πάλι να κάνει import module που ο καλών μπορεί να επεξεργαστεί ή να αντικαταστήσει, ακόμη κι όταν το sudo εκτελεί το script ως **μη-root** χρήστη υπηρεσίας. Για κυριολεκτικό `from utils import status`, εξετάστε τα τοπικά `utils/__init__.py` και `utils/status.py`, καθώς και τα δικαιώματα του καταλόγου πακέτου. Επιβεβαιώστε τη διαδρομή import του script, τα ακριβή επιτρεπόμενα ορίσματα sudo και αν η σχετική λειτουργία φτάνει σε αυτό το import πριν θεωρήσετε το εγγράψιμο αρχείο διαδρομή εκτέλεσης. Εξετάστε αρχεία και δικαιώματα χωρίς να κάνετε import ή να εκτελέσετε το script κατά την απαρίθμηση.<sup>[[2]](#references)[[3]](#references)</sup>

Ένας ακριβής κανόνας sudo για `python3 /absolute/script.py` απαιτεί μόνο αναγνώσιμο script· το αρχείο δεν χρειάζεται να είναι εκτελέσιμο ή να έχει shebang. Εξετάστε και **τοπικά modules που λείπουν**: αν το script κάνει import module του οποίου το όνομα αρχείου μπορεί να δημιουργηθεί σε κατάλογο script εγγράψιμο από τον καλούντα, η Python μπορεί να φορτώσει αυτό το αρχείο με την ταυτότητα RunAs. Επιβεβαιώστε τον ενεργό κανόνα sudo, την πραγματική [διαδρομή αναζήτησης modules](https://docs.python.org/3/library/sys_path_init.html) του interpreter, αν το module είναι ενσωματωμένο ή frozen και αν εκτελείται το import. Ένας άμεσος κανόνας sudo για το script έχει διαφορετικές απαιτήσεις execute bit και shebang. Ένας ξεχωριστός wrapper που προσθέτει tokens από τον καλούντα μετά το `sudo -u account` απαιτεί επίσης έλεγχο ροής ορισμάτων: ένα ακόμη `-u` σε αυτά τα tokens έχει σημασία μόνο αν η πολιτική sudo της εντολής επιτρέπει την ταυτότητα που προκύπτει. Στατικές συμβολοσειρές από μόνες τους δεν αποδεικνύουν καμία από τις δύο διαδρομές.

### Apache μέσω sudo με διαμόρφωση ελεγχόμενη από τον καλούντα

Αν ένας κανόνας sudo επιτρέπει προνομιούχο `apachectl`, `apache2ctl` ή `httpd` με αρχείο διαμόρφωσης `-f` ελεγχόμενο από τον καλούντα, εξετάστε τα δικαιώματα αυτού του αρχείου και του γονικού καταλόγου. Η οδηγία [`LoadModule`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadmodule) του Apache δέχεται όνομα module και στη συνέχεια το **όνομα αρχείου module**· το [`LoadFile`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadfile) επίσης φορτώνει αρχείο. Τα [`Include` και `IncludeOptional`](https://httpd.apache.org/docs/2.4/mod/core.html#include) μπορούν να επεκτείνουν τη διαμόρφωση ή να αποκαλύψουν περιεχόμενα αρχείων μέσω σφαλμάτων. Ένα προσαρμοσμένο wrapper μπορεί να επικυρώνει αυτές τις διαδρομές, να υποβαθμίζει προνόμια ή να περιορίζει ορίσματα, επομένως μια εγγράψιμη διαμόρφωση αποτελεί υποψήφια περίπτωση ελέγχου και όχι απόδειξη εκτέλεσης κώδικα. Ελέγξτε την κανονικοποίηση διαδρομών, τα symlink και την ανάλυση οδηγιών πριν καταλήξετε σε συμπέρασμα.

### nginx μέσω sudo με διαμόρφωση ελεγχόμενη από τον καλούντα

Ένας απεριόριστος κανόνας `nginx` με δυνατότητα εκτέλεσης ως root μπορεί να επιτρέπει στο [`-c` να επιλέγει διαφορετική διαμόρφωση](https://nginx.org/en/docs/switches.html). Εξετάστε τα ακριβή ορίσματα και τις εξαιρέσεις sudo, αν ο καλών μπορεί να παρέχει τη διαμόρφωση και αν ο master ή οι workers που προκύπτουν διατηρούν πρόσβαση σε προστατευμένες διαδρομές. Ένα επιλεγμένο `root` μαζί με `autoindex` μπορεί να εκθέσει αρχεία μέσω νέου listener· το [`dav_methods PUT`](https://nginx.org/en/docs/http/ngx_http_dav_module.html) μπορεί να παρέχει προνομιούχο διαδρομή εγγραφής αρχείου, αλλά το module DAV δεν ενσωματώνεται από προεπιλογή και πρέπει να ελεγχθούν η παρουσία του, η προσβασιμότητα του listener, τα δικαιώματα αρχείων και η συμπεριφορά προσωρινών αρχείων. Η οδηγία [`error_log`](https://nginx.org/en/docs/ngx_core_module.html#error_log) μπορεί επίσης να στοχεύει επιλεγμένο αρχείο· η εγγραφή logs σε ευαίσθητο αρχείο διαμόρφωσης, όπως το `/etc/ld.so.preload`, απαιτεί ενεργό προνομιούχο writer και ελεγχόμενη εγγραφή log προτού αποτελέσει διαδρομή κλιμάκωσης. Η επισήμανση του εκτελέσιμου στο `sudo -l` αποτελεί αφορμή για έλεγχο, όχι απόδειξη ότι λειτουργεί κάποια από αυτές τις διαδρομές. Η παθητική απαρίθμηση δεν πρέπει να εκκινεί ή να επαναδιαμορφώνει το nginx.

### Σύγκριση μοτίβων σε προνομιούχα Bash prompts

Όταν ένα Bash script που επιτρέπεται από το sudo διαβάζει τιμή από τον καλούντα και την ελέγχει με `[[ "$expected" == $entered ]]`, το Bash ερμηνεύει το μη quoted δεξιό όρισμα ως pattern. Έτσι, ένα wildcard μπορεί να πετύχει τη σύγκριση χωρίς γνώση της αναμενόμενης τιμής. Με το quoting του ορίσματος (`[[ "$expected" == "$entered" ]]`), η σύγκριση γίνεται κυριολεκτικά ως συμβολοσειρά. Εξετάστε τον ακριβή κανόνα sudo, αν είναι προσβάσιμο το prompt και τι κάνει το script μετά τη σύγκριση· η σύνταξη από μόνη της δεν αποδεικνύει εκμεταλλεύσιμη διαδρομή. Αποφύγετε να εμφανίσετε την αναμενόμενη τιμή κατά την απαρίθμηση. Δείτε την [αναφορά κατασκευών conditional του Bash](https://www.gnu.org/software/bash/manual/html_node/Conditional-Constructs.html).

### Helpers που κατεβάζουν και εκτελούν αρχείο μέσω sudo

Μια απεριόριστη χορήγηση sudo με δυνατότητα εκτέλεσης ως root σε προσαρμοσμένο helper απαιτεί έλεγχο ροής δεδομένων, αν δέχεται URL επιλεγμένο από τον καλούντα, γράφει την απόκριση στον δίσκο και αργότερα εκτελεί αυτό το αρχείο μέσω interpreter ή shell. Το [sudoers επιτρέπει αυθαίρετα ορίσματα όταν η εγγραφή εντολής δεν αναφέρει κανένα](https://man7.org/linux/man-pages/man5/sudoers.5.html)· μια σταθερή διαδρομή εκτελέσιμου δεν περιορίζει όσα μπορούν να επιλέξουν τα ορίσματά του. Επιβεβαιώστε την πραγματική επικύρωση URL, τη διαδρομή εξόδου, τον κλάδο επιτυχίας και τη μεταγενέστερη εκτέλεση στο εγκατεστημένο helper. Ένα matching libcurl import ή μια εκτυπώσιμη συμβολοσειρά από μόνα τους δεν αποδεικνύουν αυτή την αλυσίδα.

Ακόμη και σταθερό βασικό όνομα εξόδου μπορεί να αντικατασταθεί ανάμεσα στην εγγραφή και την εκτέλεση, όταν το helper χρησιμοποιεί **σχετική διαδρομή σε working directory ελεγχόμενο από τον καλούντα**. Η μετονομασία ή αντικατάσταση αρχείου ιδιοκτησίας root διέπεται από δικαίωμα εγγραφής και αναζήτησης καταλόγου και από τυχόν περιορισμούς sticky bit, όχι μόνο από τα δικαιώματα του αρχείου· δείτε την [`rename(2)`](https://man7.org/linux/man-pages/man2/rename.2.html). Ελέγξτε αν το helper ανοίγει ξανά τη διαδρομή αργότερα ή χρησιμοποιεί ήδη ανοιχτό descriptor και αν μεταβαίνει σε έμπιστο κατάλογο πριν γράψει. Εξετάστε παθητικά την πολιτική sudo, το helper και τα μεταδεδομένα καταλόγου· μην εκτελέσετε την προνομιούχο λήψη ή race κατά την απαρίθμηση.

Ένα helper λήψης μέσω sudo ως root μπορεί επίσης να εκθέσει injection **ορίσματος**, όταν συνθέτει συμβολοσειρά εντολής Bash όπως `curl <caller input> -o <fixed output>`. Ένα φίλτρο που απορρίπτει whitespace εξακολουθεί να αφήνει το [brace expansion του Bash](https://www.gnu.org/software/bash/manual/html_node/Brace-Expansion.html): μη quoted στοιχεία χωρισμένα με κόμμα μπορούν να μετατραπούν σε ξεχωριστά ορίσματα curl. Αν η είσοδος φτάνει στο curl πριν από το σταθερό `-o`, μια επιλογή εξόδου που παρέχει ο καλών μπορεί να επιλέξει τον προορισμό της πρώτης URL με την ταυτότητα του helper· το [curl αντιστοιχίζει τις επιλογές εξόδου στα URL με τη σειρά](https://curl.se/docs/manpage.html#-o). Επιβεβαιώστε το ακριβές shell, το quoting, την επικύρωση εισόδου, τον ενεργό κανόνα sudo, τη σειρά ορισμάτων curl και τα υποστηριζόμενα σχήματα URL, καθώς και αν ο καλών ελέγχει τα bytes που ανακτώνται ή μπορεί να διαβάσει το αποτέλεσμα. Ένα εκτελέσιμο πακεταρισμένο με PyInstaller μπορεί να περιέχει λογική εφαρμογής Python, αλλά η ένδειξη πακεταρίσματος ή μια συμβολοσειρά `curl` από μόνη της δεν αποδεικνύει αυτή τη ροή δεδομένων. Εξετάστε εξουσιοδοτημένο, περιορισμένο αντίγραφο εκτός σύνδεσης· η συνήθης απαρίθμηση δεν πρέπει να εκτελεί το helper ή να ανακτά δεδομένα επιλεγμένα από επιτιθέμενο.

Ένα shell script sudo ως root που καλεί [`mktemp -u` / `--dry-run`](https://www.gnu.org/software/coreutils/manual/html_node/mktemp-invocation.html) επιλέγει μόνο ένα αχρησιμοποίητο όνομα· **δεν** δημιουργεί το αρχείο. Αν το script δημιουργεί αργότερα αυτό το όνομα σε κατάλογο που μπορεί να επηρεάσει άλλος χρήστης, το ανοίγει ξανά και προσθέτει τα περιεχόμενά του σε προστατευμένο προορισμό, όπως το `authorized_keys` του root, εξετάστε πιθανό race προσωρινού αρχείου. Επιβεβαιώστε τον ακριβή κανόνα sudo, την ιδιοκτησία καταλόγου και αρχείου, τη σειρά δημιουργίας και επανανοίγματος, τις προστασίες του kernel και αν η προνομιούχα εγγραφή χρησιμοποιεί πράγματι bytes ελεγχόμενα από τον επιτιθέμενο. Μια συμβολοσειρά `mktemp -u` ή ένα εγγράψιμο `/tmp` από μόνο του δεν αποδεικνύει το race. Εξετάστε το script και τα μεταδεδομένα διαδρομών χωρίς να το εκτελέσετε ή να προκαλέσετε race στο προσωρινό αρχείο κατά την απαρίθμηση.

## Αμυντικές σημειώσεις

- Αποφύγετε να χορηγείτε interpreters ή διαδραστικούς editors μέσω sudo.<sup>[[1]](#references)</sup>
- Προτιμήστε σταθερά wrappers ιδιοκτησίας root που εκτελούν μία περιορισμένη διοικητική ενέργεια.<sup>[[1]](#references)[[2]](#references)</sup>
- Αν είναι αναπόφευκτος ένας interpreter, περιορίστε την ακριβή διαδρομή του script και αποτρέψτε ορίσματα ελεγχόμενα από χρήστη, εγγράψιμα imports, το `PYTHONPATH` και μη ασφαλή διατήρηση περιβάλλοντος.<sup>[[2]](#references)[[3]](#references)[[4]](#references)</sup>
- Αν απαιτείται επεξεργασία αρχείων, περιορίστε την ακριβή διαδρομή αρχείου και εξετάστε το `sudoedit` με διορθωμένες εκδόσεις sudo και αυστηρό χειρισμό περιβάλλοντος.<sup>[[1]](#references)[[2]](#references)</sup>
- Εξετάστε τα `SETENV`, `env_keep`, τους εγγράψιμους working directories, τις εγγράψιμες διαδρομές module/import, το `NOEXEC`, το `use_pty` και το logging, αλλά μην τα θεωρείτε ολοκληρωμένο sandbox.<sup>[[1]](#references)[[2]](#references)[[3]](#references)</sup>
