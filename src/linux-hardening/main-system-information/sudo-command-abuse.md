## Interpreteri dozvoljeni preko sudo-a

Ako `sudo -l` dozvoljava korisniku da pokrene interpreter kao root, tretirajte to kao direktno izvršavanje koda. Interpreteri su namenjeni izvršavanju proizvoljnog koda, pa je pravilo koje dozvoljava `python3`, `perl`, `ruby`, `lua`, `node` ili slične binarne fajlove obično ekvivalentno izvršavanju komandi kao root, osim ako su argumenti strogo ograničeni i provereni.<sup>[[1]](#references)[[2]](#references)[[3]](#references)[[4]](#references)[[5]](#references)[[7]](#references)[[9]](#references)[[11]](#references)</sup>

Uobičajeni postupak provere: prvo navedite korisnikove privilegije, a zatim izvršite Python izraz pomoću opcije `-c` interpretera.<sup>[[1]](#references)[[3]](#references)[[4]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/python3 -c 'import os; os.system("id")'
sudo /usr/bin/python3 -c 'import os; os.system("/bin/sh")'
```

Drugi primeri interpretera prikazani su u nastavku; navedeni interpreteri dokumentuju izvršavanje inline koda ili API-je za child procese.<sup>[[5]](#references)[[6]](#references)[[7]](#references)[[8]](#references)[[9]](#references)[[10]](#references)[[11]](#references)</sup>

```bash
sudo /usr/bin/perl -e 'exec "/bin/sh";'
sudo /usr/bin/ruby -e 'exec "/bin/sh"'
sudo /usr/bin/node -e 'require("child_process").spawn("/bin/sh", {stdio: [0,1,2]})'
```

Tačna putanja je važna. Ako sudo pravilo dozvoljava `/usr/bin/python3`, tokom provere koristite baš tu putanju.<sup>[[2]](#references)</sup>

Glob za sudo izvršnu datoteku kao što je `/usr/bin/python*` može da dozvoli i Python 2 za skriptu napisanu za Python 3. Ako skripta dođe do `input()` sa tekstom koji kontroliše pozivalac, [Python 2 taj tekst evaluira kao izraz](https://docs.python.org/2/library/functions.html#input); eksplicitno pozivanje interpretera ima prednost nad shebang linijom skripte. Pre nego što ovo smatrate putanjom do izvršavanja koda, proverite instalirane binarne datoteke koje odgovaraju globu, efektivni RunAs i pravila za argumente, zabrane i dostupnost ulaza koji se može kontrolisati.

Fiksna putanja skripte u sudo pravilu koje omogućava izvršavanje kao root ne ograničava šta skripta izvršava. Ako je u pitanju čitljiv Bash omotač, proverite da li njegova prva izvršna komanda koristi necitiran pozicioni parametar, kao što je `$1`, kao **reč komande**, dok sudo dozvoljava argumente koje bira pozivalac. Potvrdite efektivni RunAs identitet, pravila za lozinku i argumente, kasnije zabrane i stvarnu granu skripte; `NOEXEC`, fiksna bezbedna lista argumenata ili omotač koji proverava komandu mogu da promene rezultat. Tokom enumeracije statički pregledajte kratku skriptu umesto da je pozivate probnom komandom.

I sudo pravilo bez ograničenja koje omogućava izvršavanje `dotnet` kao root zaslužuje proveru interpretera. Ako je instaliran .NET SDK, [`dotnet fsi` pokreće F# kod interaktivno ili iz skripte](https://learn.microsoft.com/en-us/dotnet/fsharp/tools/fsharp-interactive/), a [`dotnet run` izvršava projekat iz izvornog koda](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-run). Najpre potvrdite efektivni RunAs identitet i tačna pravila za argumente: pravilo ograničeno na određenu bezbednu podkomandu ili pouzdanu aplikaciju predstavlja drugačije ovlašćenje, a instalacija koja sadrži samo runtime možda nema SDK komande. Sam naziv izvršne datoteke je povod za proveru, a ne dokaz da je moguće izvršavanje koda.

```bash
sudo /usr/bin/python3 -c 'import os; os.setuid(0); os.setgid(0); os.system("/bin/sh")'
```

## `tee` dozvoljen preko sudo: proizvoljan upis u fajl sa privilegijama

GNU `tee` kopira standardni ulaz u svaku putanju navedenu kao operand fajla. Zato sudo pravilo koje dozvoljava pokretanje komande `/usr/bin/tee` kao root, uz argumente pod kontrolom pozivaoca, omogućava proizvoljno kreiranje ili prepisivanje fajlova kao root. Dodavanjem opcije `-a`, primitiv omogućava dodavanje sadržaja. Oznaka `PASSWD:` odnosi se na sudo autentifikaciju; sama po sebi ne ograničava odredište niti bajtove pročitane sa standardnog ulaza.<sup>[[2]](#references)[[27]](#references)[[28]](#references)</sup>

Najpre proverite tačno pravilo. Na sistemu za testiranje za koji imate ovlašćenje, proverite ovaj primitiv samo koristeći odredište za jednokratnu upotrebu koje je bezbedno kreirati. Završni deo `>/dev/null` samo sprečava da se `tee`-ova kopija ispiše na standardni izlaz.<sup>[[28]](#references)</sup>

```bash
sudo -l
printf '%s\n' 'controlled-write' | sudo /usr/bin/tee /root/tee-proof >/dev/null
printf '%s\n' 'appended-line' | sudo /usr/bin/tee -a /root/tee-proof >/dev/null
```

Postavljanje `sudo` ispred producer-a ne podiže privilegije kasnijeg shell preusmeravanja, jer odredište otvara shell pozivaoca. Privilegovani proces mora da bude proces koji upisuje, kao u gornjem pipeline-u.<sup>[[1]](#references)[[15]](#references)</sup>

Nakon potvrde upisa, izaberite odgovarajući cilj za root code execution iz odeljka [Arbitrary File Write to Root](../interesting-files-permissions/write-to-root.md). U jednom zabeleženom lancu, root `tee` je kreirao kratkotrajnu datoteku u direktorijumu `/etc/cron.d/`, pokrenuo backdoor preko skripte pod kontrolom korisnika i obrisao cron datoteku nakon izvršavanja. Uklanjanje cron datoteke sprečilo je da ona postane dugoročni persistence unos, mada su sistemski logovi i dalje sačuvali dokaze o aktivnosti.<sup>[[27]](#references)</sup>

## Uređivači dozvoljeni kroz sudo

Ako `sudo -l` dozvoljava korisniku da pokrene interaktivni uređivač kao root, tretirajte to kao površinu za izvršavanje komandi, a ne kao bezazlenu dozvolu za uređivanje datoteka. Uređivači često mogu da izvršavaju shell komande, čitaju proizvoljne datoteke, upisuju proizvoljne datoteke ili pozivaju spoljne pomoćne programe iz samog uređivača.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

Uobičajeni tok provere: izlistajte korisnikove privilegije, a zatim pokrenite svaki dozvoljeni uređivač ili pager kroz sudo.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/nano /etc/hosts
sudo /usr/bin/vim /etc/hosts
sudo /usr/bin/less /etc/hosts
```

### Izvršavanje komandi pomoću nano

Kada je `nano` dozvoljen preko `sudo`, izvršavanje komandi može biti dostupno iz interfejsa uređivača.<sup>[[12]](#references)</sup>

```text
Ctrl+R
Ctrl+X
```

Zatim unesite komandu kao što je `id` ili `/bin/sh` u komandni prompt programa nano.<sup>[[12]](#references)</sup>

```bash
id
/bin/sh
```

Ako interaktivni shell nema upotrebljive terminalske tokove, ovaj oblik preusmeravanja mapira njegov standardni izlaz i grešku na deskriptor 0.<sup>[[15]](#references)</sup>

```bash
reset; /bin/sh 1>&0 2>&0
```

Tačan niz tastera može da se razlikuje u zavisnosti od verzije nano-a i opcija pri kompajliranju, ali bezbednosni problem je isti: uređivač radi kao root i može da pokreće spoljne komande.<sup>[[1]](#references)[[12]](#references)</sup>

### Drugi česti načini izlaska iz uređivača

Uređivači u Vim stilu obično omogućavaju izvršavanje komandi pomoću `:!`.<sup>[[13]](#references)</sup>

```text
:!/bin/sh
```

Pageri kao što je `less` takođe mogu da omoguće izvršavanje shell komandi.<sup>[[14]](#references)</sup>

Sudo pravilo koje dozvoljava pokretanje `apport-cli` kao root zahteva istu proveru pagera. Pogođene verzije Apport-a mogle su da otvore izveštaj o padu sistema u programu `less` uz veličinu terminala koju napadač može da podesi; pager je zatim mogao da omogući root shell ako su bili ispunjeni posebni uslovi za sudo i pager. Pre nego što verziju proglasite ranjivom, proverite efektivno sudo pravilo, konfiguraciju pagera i ispravku u paketu distribucije. Tokom pasivnog prikupljanja podataka pročitajte metapodatke paketa i pravila bez izazivanja pada sistema ili otvaranja privilegovanog izveštaja. [Ubuntu-ov CVE zapis](https://ubuntu.com/security/CVE-2023-1326) navodi verzije paketa sa ispravkama za pojedina izdanja, uključujući i backportovane ispravke.

```text
!/bin/sh
```

## Ostale opasnosti u pravilima sudo i doas

Počnite sa `sudo -l`, `sudo -V` i svim primenljivim pravilima za `doas`. Razmatrajte zajedno dozvoljenu komandu, korisnika u čije ime se izvršava, argumente, okruženje i podrazumevane postavke. Dozvola za izvršavanje komandi kao ne-root servisni nalog i dalje može da otkrije fajlove tog naloga ili put do root pristupa.

Fiksna Python skripta dozvoljena preko sudo i dalje može da pokrene shell komandu pod svojim RunAs identitetom ako se interaktivni unos koji kontroliše pozivalac nadovezuje u [`os.system()`](https://docs.python.org/3/library/os.html#os.system). Lista zabranjenih shell interpunkcijskih znakova nije dovoljna da bi se utvrdila bezbednost: [shell prepoznaje i zamenu komande `$(...)`](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html). Potvrdite da dozvoljeni argumenti stižu do grane koja obrađuje unos, da unos stiže do shell komande bez bezbedne validacije i da efektivna sudo politika dozvoljava željenog RunAs korisnika. Putanja skripte ili poziv `os.system()` samo su smernica za pregled; pregledajte izvorni kod bez pokretanja privilegovane skripte.

Efektivno sudo pravilo za root koje dozvoljava `chattr` može da ukloni nepromenljivi (`i`) atribut fajla, ali to samo po sebi ne daje pravo upisa niti novi identitet. [Uputstvo za `chattr`](https://man7.org/linux/man-pages/man1/chattr.1.html) navodi da atribut sprečava izmene i da ga mogu promeniti samo root ili proces sa `CAP_LINUX_IMMUTABLE`. Proverite tačnu sudo politiku argumenata i podršku fajl-sistema, a zatim zasebno utvrdite da li pozivalac može da upisuje u fajl nakon uklanjanja atributa i da li ga koristi proces sa višim identitetom. Zamena login shell-a, na primer, zahteva i akreditacije koje ciljni nalog prihvata, kao i stvarnu prijavu preko tog shell-a. Tokom enumeracije pregledajte politiku, atribute fajla i dozvole, ali ih nemojte menjati.

Ako sudo traži i lozinku i jednokratni kod, posmatrajte te preduslove odvojeno od dozvole za komandu. Čitljiv fajl `.google_authenticator` sadrži osetljiv seed, dok je stari hash lozinke aplikacije ili baze podataka samo mogući kandidat za lozinku aktuelnog naloga; nijedno ne dokazuje da efektivna PAM konfiguracija prihvata drugi faktor. Nakon dobijanja ovlašćenja pregledajte tačan RunAs i argumente: neograničena root dozvola za RubyGems `gem` može da otkrije njegovu editor komandu ([GTFOBins](https://gtfobins.github.io/gtfobins/gem/)), ali ograničeno pravilo ili neuspešna autentikacija to ne omogućavaju. Pasivna enumeracija treba da navede putanje i politiku, bez prikazivanja seed-a, otkrivanja lozinke, generisanja koda ili pokretanja privilegovane komande.

Neograničena sudo dozvola za Chef-ov `knife` koja može da se izvršava kao root zahteva pregled na nivou interpretera: [Chef navodi da `knife exec -E` lokalno evaluira Ruby string](https://docs.chef.io/workstation/26/tools/knife/knife_exec/). Proverite da li efektivno sudo pravilo dozvoljava podkomandu `exec` i argument `-E` koji obezbeđuje pozivalac, željeni RunAs identitet i sva podudarna odbijanja komandi ili fiksni argumenti. Instalirana binarna datoteka ili pravilo ograničeno na druge podkomande samo su smernice za pregled. Pasivna enumeracija treba da navede pravilo bez pokretanja `knife`.

Tačna sudo dozvola za interaktivni `msfconsole` koja omogućava root pristup jednako je osetljiva: [GTFOBins dokumentuje njegovu `irb` konzolu](https://gtfobins.org/gtfobins/msfconsole/), koja može da nasledi sudo identitet. Potvrdite efektivnog RunAs korisnika, dozvoljenu listu argumenata, odbijanja komandi, ograničenja `NOEXEC` ili druga ograničenja, ponašanje instalirane konzole i mogućnost da pozivalac unosi interaktivne podatke. Istaknuta putanja sama po sebi samo ukazuje na mesto za pregled; tokom pasivne enumeracije nemojte pokretati konzolu.

Na FreeBSD-u i sudo pravilo ograničeno na root komande `pkg update` i `pkg install *` zahteva proveru poverenja u repozitorijum. Proverite da li pozivalac može da upisuje u `/etc/hosts` i da li efektivna konfiguracija omogućenih repozitorijuma koristi HTTP hostname sa `signature_type: none`. [Uputstvo za FreeBSD `pkg.conf`](https://man.freebsd.org/cgi/man.cgi?query=pkg.conf&sektion=5) navodi da `none` isključuje proveru potpisa; samo `pkg+http` ne dokazuje ništa više. [Paket može da sadrži instalacione skripte](https://docs.freebsd.org/en/books/porters-handbook/pkg-files/), pa pozivalac koji zaista kontroliše krajnju tačku repozitorijuma i može da izabere paket može da pređe granicu root pristupa. Pre tog zaključka proverite zamene repozitorijuma, SRV/mirror razrešavanje, efektivne sudo argumente, izbor paketa i izvršavanje skripti. Pregledajte politiku i male lokalne konfiguracione fajlove bez preusmeravanja imena ili pokretanja `pkg` tokom enumeracije.

Sudo pravilo koje omogućava root izvršavanje `apt-get update` i `apt-get upgrade` takođe zahteva proveru poverenja u repozitorijum kada sudo čuva `http_proxy` koji kontroliše pozivalac. Proverite da li efektivna APT proxy konfiguracija zaista koristi tu promenljivu i na koje omogućene zahteve ka repozitorijumima može da utiče; proxy sam po sebi ne može da zameni pakete iz arhive autentifikovane pouzdanim ključem za potpisivanje. [Uputstvo za APT HTTP transport](https://manpages.debian.org/experimental/apt/apt-transport-http.1.en.html) dokumentuje prioritet proxy-ja, a [apt-secure](https://manpages.debian.org/experimental/apt/apt-secure.8.en.html) dokumentuje provere potpisa, zamene za nebezbedne repozitorijume i potvrdu za neautentifikovane pakete. Potvrdite tačne sudo RunAs i argumente, politiku autentifikacije repozitorijuma, eventualnu obaveznu interaktivnu potvrdu i da li izabrana nadogradnja pokreće skripte paketa kao root. Pasivno pregledajte politiku i lokalnu konfiguraciju; tokom enumeracije nemojte preusmeravati saobraćaj paketa niti pokretati nadogradnju.

Sudo pravilo za root koje dozvoljava `snap install` može da pređe granicu između paketa i koda ako argumenti omogućavaju pozivaocu da izabere lokalni snap i permissive režim instalacije. [Snap dokumentuje](https://snapcraft.io/docs/explanation/snap-development/install-modes/) da `--dangerous` preskače proveru assertion-a lokalnog snap-a, a `--devmode` ublažava ograničenja; [install hook može da se pokrene pri početnoj instalaciji](https://snapcraft.io/docs/reference/development/supported-snap-hooks/). Pre tvrdnje o pristupu zaštićenim fajlovima hosta proverite tačnu sudo politiku argumenata/RunAs, ko kontroliše snap fajl, da li instalirani snapd prihvata te režime, kao i identitet i ograničenja hook-a. Sama `snap` binarna datoteka ili pravilo koje izgleda kao da sadrži džoker ne dokazuju ovaj lanac. Pasivna enumeracija ne treba da instalira paket niti izvrši njegov hook.

Za tačnu sudo dozvolu za binarnu datoteku koja čita akreditive i pripada **ne-root** nalogu, prvo pregledajte dozvoljenu binarnu datoteku i njene dozvole, ali je nemojte pokretati. Ugrađena provera lozinke može biti vidljiva samo kao široki karakteri; [GNU `strings` dokumentuje izdvajanje 16-bitnih little-endian nizova](https://sourceware.org/binutils/docs/binutils/strings.html). Vidljiv string ne dokazuje da je to prihvaćena lozinka niti da uspešna grana otkriva aktuelne akreditive. Zasebno potvrdite ponašanje binarne datoteke, pristup ciljnog naloga zaštićenim podacima, validnost akreditiva i svaki kasniji prelazak na drugi nalog ili grupu. Ako taj nalog pripada grupi `docker`, proverite pristup socket-u i da li je identitet daemon-a rootful ili rootless pre zaključka o pristupu host root-u; [Docker dokumentuje posledice te grupe na nivou root-a](https://docs.docker.com/engine/install/linux-postinstall/). Rutinska enumeracija treba da navede sudo pravilo i članstvo u grupi, bez izvršavanja binarne datoteke ili izlistavanja njenih stringova.

Pravilo sa džokerom za sudo koje obuhvata skripte za održavanje aplikacije zahteva pregled koji ide dalje od putanje skripte. Proverite da li dozvoljena skripta prihvata neograničene argumente ili čita podešavanja koja korisnik sa nižim privilegijama, kao nalog aplikacije, može da menja; zatim pratite te vrednosti do shell komandi ili okruženja podprocesa. Na primer, ZoneMinder-ov [`zmupdate.pl` sastavlja komandu `mysqldump` i izvršava je putem `qx`](https://github.com/ZoneMinder/ZoneMinder/blob/master/scripts/zmupdate.pl.in), dok [`zmdc.pl` kopira podešavanje `ZM_LD_PRELOAD` u `LD_PRELOAD`](https://github.com/ZoneMinder/ZoneMinder/blob/master/scripts/zmdc.pl.in) pre pokretanja daemon-a. Sudo pravilo koje dozvoljava izvršavanje bilo koje od tih skripti kao root može da pređe granicu poverenja ako se odgovarajući ulaz može kontrolisati i stiže do tog koda u instaliranoj verziji. Pregledajte efektivno sudo pravilo, dozvole za konfiguraciju aplikacije i izvorni kod skripte; džoker ili podešavanje sami po sebi samo su smernice za pregled, ne dokaz izvršavanja.

- `SETENV`, `env_keep`, `secure_path` i `LD_PRELOAD` mogu usku komandu da pretvore u preuzimanje import-a, biblioteke ili `PATH`-a. Pogledajte [vodič za promenljive okruženja](../linux-basics/linux-environment-variables.md) i [zloupotrebu SUID/linker-a](../interesting-files-permissions/suid-shared-library-and-linker-abuse.md).

Tačna sudo dozvola za root sa `SETENV` koja pokreće shell wrapper takođe zahteva proveru jednog koraka ako wrapper pokreće fiksnu Python skriptu sa doslovnim import-om. `secure_path` ograničava pronalaženje shell komandi, a ne Python-ovu [pretragu modula preko `PYTHONPATH`](https://docs.python.org/3/using/cmdline.html#envvar-PYTHONPATH); [`-E` i `-I`](https://docs.python.org/3/using/cmdline.html#cmdoption-E) nalažu Python-u da ignoriše tu promenljivu okruženja. Pre nego što ovo smatrate izvršavanjem koda, proverite efektivne sudo oznake i odbijanja, granu wrapper-a, opcije interpretera, razrešavanje import-a i direktorijum putanje pretrage u koji pozivalac može da upisuje. Kratke skripte pregledajte statički; nemojte pokretati privilegovani wrapper.

Tačna sudo dozvola za root komandu `neofetch ""` i dalje može da učita shell konfiguraciju ako odgovarajuća sudo podrazumevana podešavanja čuvaju `XDG_CONFIG_HOME` koji kontroliše pozivalac. [Neofetch-ov učitavač konfiguracije](https://github.com/dylanaraps/neofetch/blob/master/neofetch) učitava `neofetch/config.conf` ili `neofetch/config` ispod tog direktorijuma; prazna lista argumenata ne sprečava to traženje. Potvrdite instalirani učitavač, efektivni RunAs i politiku argumenata, eventualna odbijanja komandi, da li sudo zaista čuva izabranu promenljivu za ovu komandu i da li pozivalac kontroliše čitljivu putanju konfiguracije. Sačuvana promenljiva ili instalirani Neofetch samo su smernice za pregled. Pregledajte politiku i metapodatke fajlova bez pokretanja privilegovane komande ili prikazivanja sadržaja konfiguracije; pogledajte [obradu okruženja u sudoers-u](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf).

Neograničeno sudo pravilo za `facter` koje omogućava root pristup zahteva zaseban pregled custom fact-ova. [Puppet dokumentuje](https://help.puppet.com/core/current/Content/PuppetCore/loading_custom_facts.htm) da `--custom-dir` učitava Ruby fact fajlove iz izabranog direktorijuma. Proverite da li tačno sudo pravilo dozvoljava tu opciju, da li je instalirani Facter prihvata i da li pozivalac kontroliše direktorijum. Pravilo sa fiksnim argumentima, izričito odbijanje komande ili isključeni custom fact-ovi mogu promeniti ishod. Pasivna enumeracija treba da prikaže kandidata iz politike, bez pokretanja Facter-a ili čitanja sadržaja fact-ova.

Za tačnu sudo dozvolu za root nad skriptom sa `SETENV`, pregledajte neimenovane komande kao što je `find` i efektivni `PATH` nakon primene sudo politike i inicijalizacije skripte. Izvorni Bash fajl takođe može da izvrši `enable -n [`: [Bash zatim traži eksterni `[` u `PATH`-u](https://www.gnu.org/software/bash/manual/html_node/Bash-Builtins.html) kada skripta kasnije koristi tu komandu. Proverite primenljiva [sudoers pravila za okruženje i `secure_path`](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf), eventualne unose `NOSETENV`/`NOEXEC` ili odbijanja, tok skripte i učitanih fajlova i izvršivi direktorijum putanje pretrage kojim upravlja pozivalac. Čitljiva skripta koja sadrži neimenovanu komandu samo je smernica za pregled, ne dokaz privilegovanog izvršavanja; pregledajte je bez pokretanja sudo pravila.
- Privilegovana skripta koja preuzima fiksni URL pomoću `curl` i dalje može da prihvati odgovor koji izabere pozivalac ako odgovarajuće sudo pravilo čuva `http_proxy`, a zahtev se šalje preko tog proxy-ja. Ako skripta zatim prosleđuje odgovor XML parser-u koji razrešava spoljne entitete, zlonameran odgovor može da otkrije fajlove koje privilegovani proces može da čita. Proverite tačnu sudo politiku okruženja, izuzetke `no_proxy`, traženi URL, konfiguraciju parser-a i odredište izlaza; sama proxy promenljiva ili XML parser nisu ranjivost. [Dokumentacija za curl proxy okruženje](https://everything.curl.dev/usingcurl/proxies/env.html) opisuje ponašanje promenljivih. Tokom pasivne enumeracije nemojte slati mrežne zahteve niti parsirati zlonamerni XML.
- Sudo skripta koja omogućava root pristup i gradi PostScript fajl iz podataka na koje utiče pozivalac, pa zatim pokreće `ps2pdf -dNOSAFER`, zahteva zaseban pregled toka ulaza. Ghostscript navodi da ova zastavica isključuje SAFER do poziva `.setsafe`, čime se omogućavaju operacije nad fajlovima unutar OS dozvola procesa. SQL upit sastavljen od argumenta pozivaoca može proslediti redove pod kontrolom napadača u PostScript šablon, ali sam string upita ili poziv `ps2pdf` ne dokazuje da podaci stižu do izvršive PostScript sintakse. Potvrdite efektivno sudo pravilo, tačan tok od ulaza do šablona, eventualno escaping ponašanje, instalirano Ghostscript ponašanje i da li se SAFER ponovo uključuje pre interpretacije dokumenta. Tokom pasivne enumeracije nemojte pokretati privilegovanu konverziju. Pogledajte [Ghostscript dokumentaciju za `-dNOSAFER`](https://ghostscript.readthedocs.io/en/master/Use.html).
- Za sudo pravilo koje pokreće shell skriptu uporedite sačuvane promenljive sa samom skriptom. Konstrukcija poput `if $CHECK_CONTENT; then` pokreće proširenu vrednost kao komandu, pa čuvanje `CHECK_CONTENT` može da omogući izvršavanje komande čak i kada su putanja skripte i argumenti fiksni. Za konkretno pravilo treba proveriti da li je grana dostupna i da li se okruženje zaista čuva.<sup>[[2]](#references)[[22]](#references)</sup>
- Skripta dozvoljena preko sudo i napisana na Python-u može da uveze kod iz direktorijuma u koji se može upisivati ili iz keširanog `.pyc` fajla. [Vodič za eskalaciju privilegija](../linux-basics/linux-privilege-escalation/README.md) opisuje slučaj sa kešom.
- Fiksna Python skripta dozvoljena preko sudo za izvršavanje kao root i dalje može da izloži interaktivni debugger. Pozivi poput `pdb.set_trace()` ili `pdb.post_mortem()` omogućavaju Python naredbe u kontekstu procesa koji se debaguje kada pozivalac može da dođe do breakpoint-a ili exception handler-a **i kontroliše ulazni tok debugger-a**. Proverite tačno sudo RunAs pravilo, uslove autentifikacije i grane, dostupnost izuzetka, vlasništvo nad terminalom/ulazom i da li debugger radi u istom privilegovanom procesu. Zahtev ka socket-u koji izazove izuzetak sam po sebi ne daje pristup debugger-u priključenom na drugi terminal. [Python dokumentuje evaluaciju naredbi u debugger-u i post-mortem režim](https://docs.python.org/3/library/pdb.html); skriptu pregledajte statički umesto da tokom enumeracije aktivirate privilegovani handler.
- Fiksna Python skripta dozvoljena preko sudo može takođe da pročita profilno polje iz baze podataka ili Unix socket-a i nadoveže ga na string koji kasnije postaje **format string** za `str.format()`. [Zamenljiva polja mogu da prate atribute i ključeve mapiranja](https://docs.python.org/3/library/string.html#format-string-syntax), pa polje koje kontroliše napadač može da pregleda objekte prosleđene funkciji `format()` i otkrije podatke koji su tim objektima dostupni, ako se rezultat ispiše ili sačuva na mestu koje pozivalac može da čita. Proverite efektivni sudo RunAs identitet, pravo upisa u konkretan zapis, tok podataka do format string-a, prosleđene objekte i vidljivost izlaza. Ovo ne podrazumeva automatsko izvršavanje koda; doslovni pouzdani format string sa vrednostima koje kontroliše napadač je drugačiji slučaj. Otkrivena tajna omogućava prelazak na OS nalog samo ako taj nalog prihvata tu tajnu. Pregledajte skriptu i dozvole socket-a bez pokretanja privilegovane operacije.
- Python wrapper koji može da se izvršava kao root može da prosledi URL koji je izabrao pozivalac funkciji `Repo.clone_from` iz GitPython-a. Ako wrapper takođe omogući Git-ov `protocol.ext.allow=always`, `ext::` remote može da pokrene eksterni helper. Proverite tačne sudo argumente, poreklo URL-a, verziju GitPython paketa i status dobavljačeve zakrpe, kao i da li wrapper izričito dozvoljava nebezbedne protokole. GitPython je dodao [podrazumevanu zaštitu od nebezbednih protokola](https://github.com/gitpython-developers/GitPython/commit/2625ed9) u verziji 3.1.30; verzija izvršne datoteke `git` je zaseban podatak. Pasivni pregled treba da obuhvati samo pravilo i ograničen deo izvornog koda, bez pokretanja kloniranja.
- Sudo dozvola za prelazak na drugi korisnički nalog pri korišćenju CLI alata za kloniranje repozitorijuma može da izloži zaseban put za injekciju shell string-a. Proverite da li argument repozitorijuma koji bira pozivalac stiže do Node.js [`child_process.exec`](https://nodejs.org/api/child_process.html#child_processexeccommand-options-callback) ili drugog mehanizma za sastavljanje shell komandi bez bezbednog razdvajanja argumenata; Node-ov `exec` prosleđuje string komande shell-u. Potvrdite tačnog RunAs korisnika, dozvoljene podkomande i argumente, instalirani kod wrapper-a i validaciju ulaza. Ime alata za repozitorijume ili neograničeno sudo pravilo sami po sebi ne dokazuju injekciju komande. Pregledajte wrapper bez pokretanja privilegovanog kloniranja tokom enumeracije.
- Custom wrapper u vlasništvu root-a može izgledati bezbedno zato što njegove binarne datoteke i skripte nisu podložne upisu, ali odluka da se pokrene privilegovana radnja može zavisiti od zastavice, lokalne API vrednosti ili stanja servisa koje neprivilegovani korisnik može da promeni. Pratite svaki uslov do njegovog ulaza i provera autorizacije. Tokom enumeracije pregledajte konfiguraciju i dozvole bez promene operativnog stanja; poziv `systemd-run` unutar wrapper-a važan je samo ako se na uslov može uticati.
- Klijent za backup dozvoljen preko sudo kao root može da prihvati konfiguracioni fajl koji bira pozivalac (na primer `npbackup-cli -c`). Proverite tačnog korisnika u čije ime se izvršava i dozvoljene argumente, a zatim da li pozivalac kontroliše putanju konfiguracije, izvorne putanje za backup i opcije repozitorijuma ili čitanja/obnavljanja. Tajna za šifrovan repozitorijum u čitljivoj konfiguraciji možda može da se koristi preko klijenta, ali samo pravilo ne dokazuje pristup repozitorijumu niti otkrivanje root fajlova. Potvrdite autorizaciju bez pokretanja backup-a ili izlistavanja njegovog sadržaja.
- [Restic](https://github.com/restic/restic/blob/master/doc/030_preparing_a_new_repo.rst) podržava `--password-command`, koji poziva program za pribavljanje lozinke repozitorijuma. Ako sudo pravilo dozvoljava korisniku sa nižim privilegijama da pokrene restic kao root sa komandnom linijom za lozinku koju sam izabere i podkomandom kojoj je potrebna lozinka, taj helper može da se pokrene kao root. Pregledajte tačne sudo argumente i izuzetke; nemojte pokretati helper niti backup komandu samo radi enumeracije uslova.
- Privilegovana dozvola za `restic backup` može takođe da pređe granicu čitanja fajlova ako sudo obrazac argumenata dopušta pozivaocu da izabere i izvor i repozitorijum koji kasnije može da čita i dešifruje. [Džokeri u argumentima sudoers-a mogu da se podudare sa razmacima i kosim crtama](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf), pa pregledajte završne džokere umesto da pretpostavljate da fiksni prefiks repozitorijuma ograničava izvor. [Restic može da čuva backup u lokalnim i udaljenim repozitorijumima](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html), ali lokalni repozitorijum može sadržati tek upisane objekte dostupne samo root-u; pre zaključka da je došlo do otkrivanja podataka potvrdite efektivnu sudo politiku, pristup backend-u, lozinku repozitorijuma i dozvole nastalih objekata. Backup SSH ključa omogućava pristup samo ako ga ciljni nalog prihvata. Tokom pasivnog pregleda nemojte pokretati backup radi provere.
- Neograničena custom komanda za održavanje ili backup može da prihvati putanju izlaza ili da ima sopstveni raspoređivač poslova. Za put upisa u fajl proverite tačno sudo pravilo i korisnika u čije ime se komanda izvršava, a zatim da li pozivalac kontroliše i podatke i odredište. Za put pokretanja zakazane komande proverite identitet pod kojim se izvršava, ulaz komande i sve dodatne provere lozinke ili autorizacije. Samo ime komande ili `NOPASSWD` ne dokazuju nijedan put. Pogledajte [upis u fajlove u vlasništvu root-a](../interesting-files-permissions/write-to-root.md) i [cron i systemd tajmere](../processes-crontab-systemd-dbus/cron-and-systemd-timers.md).
- Fiksna sudo komanda i dalje može da učita predvidljiv konfiguracioni fajl iz deljenog direktorijuma u koji se može upisivati. Proverite da li pozivalac može da zameni taj fajl i da li njegova polja za izvor i odredište kontrolišu privilegovano preuzimanje ili kopiranje. URL lokalnog fajla može da otkrije podatke koje može da čita samo sudo RunAs nalog; izvor pod kontrolom pozivaoca uparen sa zaštićenim odredištem može da omogući upis. Potvrdite obradu URL-a u instaliranom programu, provere putanje odredišta, efektivno sudo pravilo i dostupnost izlaza. Putanja konfiguracije koja se može upisivati u `/tmp` sama po sebi samo je smernica za pregled, pa pregledajte binarnu datoteku i metapodatke fajla bez pokretanja privilegovanog prenosa.
- Sudo pravilo za `git apply` može da omogući korisniku u čije ime se komanda izvršava da upisuje fajlove koje bira zakrpa pod kontrolom pozivaoca. [CVE-2023-23946](https://github.com/git/git/security/advisories/GHSA-r87m-v37r-cwfh) je omogućavao da kreirana simbolička veza usmeri upis izvan radnog stabla, čak i kada komanda nije prihvatala `--unsafe-paths`. Proverite efektivno sudo pravilo argumenata, izvor zakrpe, pristup radnom direktorijumu za RunAs nalog i instaliranu ispravku za Git ili zakrpu dobavljača. Neograničeno pravilo koje dopušta `--unsafe-paths` predstavlja zaseban rizik zbog izričite opcije; ni verzija Git-a ni dozvola za `git apply` same po sebi ne dokazuju da zaštićeni fajl može da se promeni. Tokom pasivne enumeracije nemojte primenjivati nepouzdanu zakrpu.
- Pravilo za `clamscan --debug` koje omogućava root pristup može da pređe granicu čitanja ako korisnik sa nižim privilegijama može da obezbedi DMG sliku, a instalirani parser je pogođen ranjivošću [CVE-2023-20052](https://blog.clamav.net/2023/02/clamav-01038-01052-and-101-patch.html), koja je mogla da otkrije sadržaj fajlova kroz debug izlaz. Potvrdite tačne dozvoljene argumente i putanju skeniranja, kontrolu nad ulazom, efektivni RunAs nalog, zakrpu za engine ili zakrpu dobavljača i vidljivost izlaza pozivaocu. Ako šire pravilo dozvoljava `--file-list`/`-f`, zasebno pregledajte ponašanje te liste fajlova; politika fiksirana na `--debug <scan-path>` ne dozvoljava tu opciju. Tokom enumeracije pregledajte politiku i metapodatke paketa bez skeniranja napravljene datoteke ili prikazivanja zaštićenog izlaza.
- Sudo pravilo koje omogućava root pristup i otvara sliku šifrovanog diska koju je izabrao pozivalac, uz drugo pravilo koje montira dobijeni mapper, može da uveze fajlove pod kontrolom pozivaoca u mount namespace hosta. Potvrdite oba efektivna pravila i argumente, kontrolu nad slikom i imenom mapper-a, stvarno odredište montiranja i vlasnika i režim dozvola nastalih fajlova. Prelazak preko set-user-ID zahteva i dostupan izvršni fajl, opcije montiranja koje ga poštuju (`nosuid` to sprečava) i primenljivu procesnu ili MAC politiku; samo otvaranje ili montiranje slike ukazuje na mogućnost za pregled, ali je ne dokazuje. Zaseban put preko postojećeg backup-a zahteva stvarni ključ i korisnu čitljivu tajnu unutar njega. Tokom pasivne enumeracije pregledajte politiku i putanje bez otvaranja ili montiranja slike. Pogledajte [uputstvo za cryptsetup](https://gitlab.com/cryptsetup/cryptsetup/-/blob/main/man/cryptsetup.8.adoc) i [opcije za mount](https://man7.org/linux/man-pages/man8/mount.8.html).
- Sudo pravilo za shell ili Python skriptu koja omogućava root pristup zahteva pregled radnog direktorijuma ako skripta poziva `./helper` bez prethodnog prelaska u fiksni direktorijum. Python lista poput `['./helper']` prosleđena funkciji `subprocess.run` može da zavisi od radnog direktorijuma koji bira pozivalac na isti način. Pozivalac možda može da izabere direktorijum u koji može da upisuje i postavi u njega izvršni fajl sa tim relativnim imenom; apsolutna putanja na drugom mestu u skripti ne štiti ovaj poziv. Pre nego što ovo smatrate izvršavanjem koda, potvrdite efektivno pravilo, `runchdir` ili drugu politiku promene direktorijuma, tok skripte i dostupnost grane, direktorijum u koji se može upisivati i izvršavati, kao i ograničenja montiranja/`NOEXEC`. Ako skripta nije čitljiva, ponašanje je nepoznato dok se njen izvor ne pregleda preko ovlašćenog kanala. Skripte pregledajte statički umesto pokretanja helper-a. [Uputstvo za sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) dokumentuje politiku radnog direktorijuma.
- Fiksni Python validator koji omogućava root pristup i dalje može da evaluira fajl sa podacima koji je izabrao pozivalac. [Python dokumentacija za `eval()` upozorava da se ne koristi sa nepouzdanim ulazom](https://docs.python.org/3/library/functions.html#eval): provera sufiksa ulaza, aritmetički prefiks ili grana validacije nisu sandbox ako preostali izraz stiže do `eval`. Pre nego što ovo nazovete putanjom izvršavanja, potvrdite efektivno sudo pravilo, da li pozivalac može da izabere i kontroliše konkretan fajl, uslove grana parser-a i sastavljanje izraza, kao i identitet privilegovanog procesa. Sama pojava `eval` u čitljivoj skripti samo je smernica za pregled; pregledajte izvorni kod i dozvole fajla bez pokretanja validatora ili slanja testnog izraza tokom enumeracije.
- Ruby wrapper pokrenut kao root preko sudo koji čita relativno ime YAML fajla, kao što je `YAML.load(File.read("dependencies.yml"))`, može da uzme ulaz iz radnog direktorijuma pozivaoca, osim ako wrapper ili sudo politika ne fiksiraju taj direktorijum. Proverite tačne dozvoljene argumente, dozvole direktorijuma i fajla, kao i instalirano ponašanje Psych-a: starije implementacije `YAML.load` mogle su da deserijalizuju proizvoljne Ruby objekte, dok novija izdanja podrazumevano ograničavaju klase. Statičko mesto poziva samo je smernica za pregled; potvrdite da fajl zaista dolazi iz direktorijuma u koji pozivalac može da upisuje i da instalirani učitavač prihvata opasne klase. Za nepouzdan ulaz prednost dajte `safe_load` sa izričitom minimalnom listom dozvoljenih klasa. Pogledajte [Ruby 3.0 Psych dokumentaciju](https://docs.ruby-lang.org/en/3.0/Psych.html) i [Ruby 3.1 Psych dokumentaciju](https://ruby-doc.org/core-3.1.2/Psych.html).

- Tačna `sudo go run /absolute/file.go` dozvola koja omogućava root pristup zahteva pregled radnog direktorijuma kada Go izvorni kod čita relativni WASM fajl i može da pokrene relativnu shell skriptu nakon provere rezultata. Potvrdite efektivnog RunAs korisnika, argumente komande i odbijanja, trenutni direktorijum u koji pozivalac može da upisuje, tok podataka iz WASM-a do grane i da li ta grana poziva helper. Fiksni `sudo runchdir`, `os.Chdir` ili [`exec.Cmd.Dir`](https://pkg.go.dev/os/exec) mogu da promene lokaciju pretrage. Statičko istovremeno pojavljivanje ovih elemenata samo ukazuje na kandidata; pregledajte izvorni kod bez pokretanja Go-a, WASM-a ili helper-a.
- `sudoedit` i džokeri u argumentima zahtevaju preciznu proveru verzije i pravila; [kontrolna lista](linux-privilege-escalation-checklist.md) obuhvata problem izmene fajla preko sudoedit. Za sudoedit dozvolu između korisnika koja se odnosi na putanju sa džokerom pregledajte efektivno podešavanje `sudoedit_follow` ili `FOLLOW`, `sudoedit_checkdir`, razrešenu ciljnu putanju i ko može da zameni svaki unos u nadređenim direktorijumima. Prvo može da omogući praćenje simboličke veze, dok isključivanje drugog uklanja provere direktorijuma u koje može da se upisuje; nijedno podešavanje samo po sebi ne dokazuje upis u fajl drugog korisnika. Pre zaključka potvrdite instaliranu sudo politiku i tačne argumente koji joj odgovaraju. Pogledajte [definicije opcija sudoers-a](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf).
- U pravilu sudoers komande džoker u argumentu može da odgovara razmacima, kao i znakovima putanje. Pravilo za komandu koja može da čita, sa argumentom kao što je `/restricted/*`, može zato da dozvoli dodatni argument za fajl nakon prefiksa koji se podudario. Pregledajte tačnog korisnika u čije ime se komanda izvršava, putanju komande, obrazac argumenata i kasnija odbijanja; demonstrirano čitanje fajla ne podrazumeva izvršavanje komande. [Uputstvo za sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) razlikuje džokere u argumentima od džokera u putanji komande.
- Obrazac argumenata koji izgleda kao putanja može da odgovara i `../`. Na primer, pravilo za root komandu `node /opt/scripts/*.js` može da dozvoli JavaScript fajl koji kontroliše pozivalac, a nalazi se izvan `/opt/scripts`, ako prosleđena putanja i dalje počinje sa `/opt/scripts/` i razrešava se preko segmenata roditeljskih direktorijuma. Ovo je džoker za **argumente**; džoker u putanji komande za Node izvršnu datoteku ima drugačija pravila za poklapanje kosih crta. Pre zaključka o izvršavanju koda proverite efektivno pravilo, kasnija odbijanja, razrešavanje putanje, kontrolu nad ciljnim fajlom i sva sudoers ograničenja regularnim izrazom ili digest-om. Pogledajte [pravila džokera u sudoers-u](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) i [Node dokumentaciju komandne linije](https://nodejs.org/api/cli.html).
- Arhiveri i drugi pomoćni programi mogu da imaju hook-ove za izvršavanje. Uporedite tačne dozvoljene argumente sa [GTFOBins](https://gtfobins.github.io/) umesto da pretpostavljate da samo shell-ovi ili interpreter-i izvršavaju komande.
- Neograničeno sudo pravilo za root komandu `qpdf` može da otkrije privilegovani fajl kroz PDF priloge: qpdf 10.2 i novije verzije podržavaju `--empty` i `--add-attachment file ... --` uz izlazni PDF. Ako privilegovani proces može da čita izabrani izvor i upiše PDF na putanju dostupnu pozivaocu, taj izlaz može da sadrži bajtove izvornog fajla. Pre zaključka da je otkrivanje fajla moguće, pregledajte efektivne sudo argumente i izuzetke, verziju qpdf-a, pristup izvoru i putanju izlaza. Čitanje root SSH ključa korisno je za prijavu samo ako je ključ važeći i ako je SSH autentifikacija za root dozvoljena. Pogledajte [opcije za priloge u qpdf-u](https://qpdf.readthedocs.io/en/stable/cli.html#embedded-files-attachments).
- Ponovna upotreba sudo timestamp-a zavisi od politike keša, korisnika-vlasnika, terminala/sesije i dozvola. [Vodič za eskalaciju privilegija](../linux-basics/linux-privilege-escalation/README.md#reusing-sudo-tokens) objašnjava provere.
- `doas` ima sopstvena pravila i konfiguraciju. Proverite dozvoljene komande i putanje konfiguracije u koje može da se upisuje, kao što je opisano u [odeljku o doas](../linux-basics/linux-privilege-escalation/README.md#doas).

### Alati za izgradnju i pakete pokrenuti preko sudo

Neograničena sudo dozvola za Foundry-jev `forge` može biti značajna čak i kada je RunAs identitet drugi ne-root korisnik. Opcije kompajlera kao što je `--use` mogu da izaberu lokalnu izvršnu datoteku, a `forge flatten -o` određuje izlazni fajl. Pre nego što dozvolu smatrate iskoristivom, proverite instaliranu Forge verziju, tačne sudo argumente, dostupne putanje projekta i kompajlera, dozvole izlaza i efektivno okruženje. Relativna pomoćna izvršna datoteka pronađena preko `PATH`-a zavisi od verzije i okruženja; nemojte pretpostavljati da je to svojstvo svake Forge izgradnje.<sup>[[23]](#references)[[24]](#references)</sup>

Neograničena `pacman` dozvola koja omogućava root pristup uključuje više od upita o paketima: `-U` prihvata lokalni paket, paketi mogu da sadrže instalacione skripte, a `--hookdir` bira drugi direktorijum hook-ova. Pre testiranja pregledajte efektivno sudo pravilo, ograničenja argumenata i izuzetke; pasivnoj enumeraciji nije potrebno instaliranje paketa niti pokretanje hook-a.<sup>[[25]](#references)[[26]](#references)</sup>

Fiksni sudo shell wrapper može takođe da instalira imenovanu npm zavisnost, a zatim pokrene Node aplikaciju. Pregledajte tačno RunAs pravilo, da li je paket već instaliran, efektivni `HOME` i npm `userconfig`, konfiguraciju projekta ili zamene iz komandne linije, kao i da li korisnik sa nižim privilegijama kontroliše registry ili paket vraćen za to ime. [npm dokumentuje traženje korisničkog i projektnog `.npmrc` fajla](https://docs.npmjs.com/cli/v6/configuring-npm/npmrc/); ponašanje sudo-a za `HOME` zavisi od instalirane politike i distribucije, pa privilegovani npm proces može, ali ne mora, da čita `.npmrc` korisnika u koji može da se upisuje. Ako privilegovana aplikacija uveze novoinstalirani paket, njegov kod modula može da se izvrši pod identitetom te aplikacije. Skripte tokom instalacije predstavljaju zaseban put koji zavisi od verzije i konfiguracije; [npm dokumentuje njihov životni ciklus i obradu korisnika](https://docs.npmjs.com/cli/v6/using-npm/scripts/). Putanja `.npmrc` fajla ili red `npm install` samo su smernice za pregled. Tokom pasivne enumeracije pregledajte pravilo, kratak wrapper, putanje konfiguracije i poreklo paketa bez instaliranja paketa ili pokretanja aplikacije.

Dozvola za root komandu `pip` ili `pip3 download` takođe ukazuje na potrebu za pregledom izgradnje paketa kada argumenti omogućavaju pozivaocu da izabere nepouzdanu izvornu distribuciju, čak i ako obrazac URL-a ograničava izbor na lokalni servis i sufiks `.tar.gz`. `pip download` prihvata URL-ove arhiva i razrešava metapodatke paketa; priprema sdist paketa može da pozove njegov build backend ili nasleđeni `setup.py` kod pre samog čuvanja arhive. Potvrdite tačan sudo RunAs i pravilo argumenata, da li pozivalac može da objavi ili zameni izabranu arhivu i da li ta verzija pip-a zaista priprema metapodatke. Fiksna pouzdana arhiva ili wheel ne dokazuju da postoji ovaj put. Tokom pasivne enumeracije nemojte preuzimati niti graditi nepouzdan paket. Pogledajte pip [komandu za preuzimanje](https://pip.pypa.io/en/stable/cli/pip_download/), [interfejs build-system-a](https://pip.pypa.io/en/stable/reference/build-system/) i [smernice za bezbednu instalaciju](https://pip.pypa.io/en/stable/topics/secure-installs/).

Sudo pravilo koje dozvoljava `pip install` sa putanjom lokalnog projekta koju bira pozivalac predstavlja neposredniji prelazak granice izgradnje. [pip prihvata direktorijume lokalnih projekata](https://pip.pypa.io/en/stable/topics/local-project-installs/) i poziva njihov build system; [build backend izvršava build hook-ove koje kontroliše projekat](https://pip.pypa.io/en/stable/reference/build-system/). Pre nego što pravilo smatrate privilegovanim izvršavanjem koda, potvrdite efektivni RunAs identitet, tačna ograničenja argumenata i odbijanja, kontrolu nad izabranim projektom, kao i ponašanje instaliranog pip-a/backend-a. Fiksni pouzdani projekat ili pravilo koje isključuje putanje koje bira pozivalac ne dokazuje ovaj put. Tokom pasivne enumeracije pregledajte pravilo i metapodatke projekta bez instaliranja paketa.

Neograničena `easy_install` dozvola koja omogućava root pristup predstavlja sličan, nasleđeni pokazatelj da treba pregledati izgradnju paketa. [Setuptools dokumentuje](https://setuptools.pypa.io/en/stable/deprecated/easy_install.html) da Easy Install prihvata direktorijum lokalnog projekta i gradi izvorne distribucije; projekat pod kontrolom pozivaoca može da izvrši svoj `setup.py` tokom te izgradnje pod sudo identitetom. Potvrdite efektivni RunAs nalog, tačnu komandu i ograničenja argumenata (uključujući kasnija odbijanja), kontrolu nad izabranim projektom i ponašanje instaliranog alata. Fiksni pouzdani projekat ili politika koja ne dozvoljava izvor koji bira pozivalac ne dokazuje ovaj put. Tokom enumeracije pregledajte pravilo i metapodatke projekta bez instaliranja paketa.

Python wrapper dozvoljen preko sudo koji koristi `setuptools.package_index.PackageIndex.download` sa URL-om koji bira pozivalac razlikuje se od slučaja `pip download`: [Setuptools GHSA-5rjg-fvgr-3xxf](https://github.com/pypa/setuptools/security/advisories/GHSA-5rjg-fvgr-3xxf) opisuje kako je u pogođenim izdanjima, pre verzije 78.1.1, ime izvedeno iz URL-a moglo da izađe iz predviđenog direktorijuma za preuzimanja i da se upiše uz dozvole procesa. Potvrdite efektivni sudo RunAs i pravilo argumenata, da li wrapper prosleđuje URL koji je izabrao pozivalac baš tom API-ju, instaliranu verziju build-a ili zakrpu dobavljača i gde se razrešava nastala putanja. Sam string verzije ili direktorijum za preuzimanja u koji može da se upiše ne dokazuju proizvoljan upis. Pregledajte kratak wrapper i metapodatke paketa bez preuzimanja URL-a ili upisivanja fajla tokom enumeracije.

Wrapper za izgradnju dozvoljen preko sudo koji prosleđuje PyInstaller-u `.spec` fajl koji je izabrao pozivalac zahteva istu proveru granice poverenja. PyInstaller spec je izvršivi Python koji se evaluira tokom **izgradnje**, a njegovi unosi `datas` mogu da uključe u artefakt fajlove koje build identitet može da čita. Potvrdite tačnog RunAs korisnika, sudo pravilo za argumente i odbijanja, obradu putanje i grana u wrapper-u, kontrolu nad izabranim spec fajlom i pristup nastalom artefaktu. Samo dozvola za `.py` ulaz ili prisustvo PyInstaller-a ne dokazuju kontrolu nad spec fajlom ili privilegovano izvršavanje. Pasivni pregled treba da obuhvati samo ograničen deo wrapper fajla i metapodatke; nemojte pokretati izgradnju. Pogledajte [PyInstaller dokumentaciju za spec fajlove](https://pyinstaller.org/en/stable/spec-files.html).

### Privilegovani backup wrapper-i koji menjaju fajl zadataka koji je izabrao pozivalac

Shell wrapper pokrenut kao root može da prihvati fajl zadataka koji izabere pozivalac, ukloni `../` iz izvornih putanja, proveri da svaki rezultat počinje dozvoljenim direktorijumom, izmeni fajl zadataka, pa zatim prosledi njegovu *putanju* programu za backup. Proverite transformisanu putanju nakon potpunog kanonskog razrešavanja: jedna zamena stringa može da otkrije novi niz za prolazak uz putanju koji leksička provera prefiksa prihvata. Proverite i da li program za backup čita transformisane podatke iz memorije ili ponovo otvara fajl. Ako ga ponovo otvara, neuspešna izmena može da ostavi originalni ulazni fajl na mestu.

Na Linux-u `fs.protected_regular` može da zabrani `O_CREAT` upis u običan fajl drugog korisnika u sticky direktorijumu sa dozvolom za sve korisnike. Ta zabrana je zaštitna, ali shell wrapper koji ignoriše grešku upisa i dalje može da nastavi sa originalnim fajlom zadataka. Potvrdite podešavanje, vlasnika fajla i direktorijuma, kao i to da li wrapper prekida rad pri grešci. Putanja je kandidat za otkrivanje fajla samo ako efektivno sudo pravilo dozvoljava wrapper-u da se pokrene kao privilegovani korisnik, pozivalac kontroliše ulaz zadataka i odredište backup-a koje može da čita, a uslužni program za backup zaista uključuje zaštićene izvore. Tokom enumeracije proverite ove uslove bez pokretanja backup-a.

### Džokeri u argumentima privilegovanih packet alata

U sudo pravilu za `tcpdump`, `*` u **obrascu argumenata** može da odgovara razmacima i kosim crtama, pa ograničenje koje izgleda kao putanja i dalje može da dozvoli dodatni tekst opcije. To se razlikuje od džokera u putanji izvršne datoteke komande; pregledajte celo RunAs pravilo i eventualna kasnija odbijanja. Ako je moguće ubaciti opcije, dozvoljeno pokretanje i semantika opcija instaliranog [`tcpdump`-a](https://github.com/the-tcpdump-group/tcpdump/blob/master/tcpdump.1.in) određuju da li `-F`, `-V`, `-r`, `-w` ili `-Z` omogućava korisnu primitivu za čitanje/upis. `-V` čita listu imena capture fajlova, a ne proizvoljan dump opšte namene. AppArmor ili druga MAC politika može da blokira pristup fajlovima čak i kada sudo dozvoljava komandu; fajl profila na disku ne dokazuje da je profil učitan i da sprovodi ograničenja. Pre zaključka pasivno pregledajte autorizaciju i politiku. [Uputstvo za sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) opisuje razliku između džokera.

Sudo pravilo koje omogućava root pristup i navodi samo izvršnu datoteku `tcpdump`, bez ograničenja argumenata, takođe zaslužuje pregled. [Uputstvo za tcpdump](https://github.com/the-tcpdump-group/tcpdump/blob/master/tcpdump.1.in) dokumentuje `-z` kao komandu koja se pokreće posle rotacije kada `-C` ili `-G` rotira sačuvani capture; `-Z` ili podrazumevana vrednost postavljena tokom kompajliranja mogu da uklone privilegije pre pokretanja te komande. Pre nego što ovo smatrate putem za eskalaciju, proverite efektivno sudo pravilo, instaliranu izgradnju, ponašanje pri uklanjanju privilegija i mogućnost rotacije. Istaknuto pravilo je kandidat za proveru, ne dokaz root izvršavanja komande.

### Nmap wrapper-i pokrenuti preko sudo

Kada je putanja `nmap` dozvoljena preko sudo-a zapravo shell wrapper, pregledajte tačnu dozvoljenu putanju i svaku opciju koju prosleđuje. Blokiranje poznatog zapisa `--script` ne blokira nužno učitavanje NSE koda: Nmap-ov [`--datadir`](https://nmap.org/book/man-misc-options.html) bira fajlove sa podacima, a NSE [učitava `nse_main.lua`](https://nmap.org/book/nse-implementation.html) iz izabranog direktorijuma podataka kada je scripting omogućen. Neke instalirane izgradnje prihvataju i alternativne zapise dugih opcija, pa uporedite ograničenja sa stvarnim parser-om te binarne datoteke. [`--excludefile`](https://nmap.org/book/man-target-specification.html) je zasebna površina za čitanje fajlova; greške parser-a mogu da otkriju tekst. Proverite efektivno sudo pravilo, logiku wrapper-a, Nmap verziju, kontrolu nad direktorijumom i MAC politiku bez pokretanja skeniranja tokom enumeracije.

### Mercurial pull hook-ovi pokrenuti preko sudo

Fiksni izvor u `sudo hg pull /fixed/source` i dalje ostavlja **ciljni** repozitorijum da ga bira trenutni radni direktorijum, osim ako komanda ne fiksira repozitorijum pomoću `-R`. ### Git pull hook-ovi pokrenuti preko sudo

Za tačnu root sudo dozvolu za `sudo git pull` proverite i **ciljni** repozitorijum izabran radnim direktorijumom. Repozitorijum u vlasništvu pozivaoca može da ima izvršivi hook `post-merge`, koji se pokreće sa Git identitetom kada `pull` zaista izvrši uspešno spajanje; [Git dokumentuje ovaj hook](https://git-scm.com/docs/githooks) i [ponašanje `pull` komande pri spajanju naspram rebase-a](https://git-scm.com/docs/git-pull). Proverite efektivno sudo pravilo i CWD, aktivnu putanju hook-a i njegove dozvole, kao i da li je moguće spajanje sa novim commit-ovima. Neuspešan `pull`, operacija bez izmena ili `pull` koji koristi samo rebase ne dokazuje ovaj put kroz hook. Pregledajte politiku i metapodatke repozitorijuma bez pokretanja privilegovanog `pull`-a.

### Rsync arhivske kopije pokrenute preko sudo

Za `sudo rsync -a ... /writable/source/* /fixed/destination/`, `*` u **obrascu argumenata sudoers-a** može da odgovara razmacima i da dozvoli dodatnu opciju između izvora i odredišta. Ovo se razlikuje od shell proširivanja imena fajlova. Ako pozivalac može da popunjava izvor, a privilegovani rsync proces može da upisuje u odredište, [`--chown`](https://download.samba.org/pub/rsync/rsync.1) može da zatraži privilegovano vlasništvo, dok arhivski režim čuva bitove dozvola, čime se potencijalno stvara fajl u vlasništvu korisnika sa SetUID atributom. Proverite tačnu [semantiku džokera u sudoers-u](https://man7.org/linux/man-pages/man5/sudoers.5.html), rsync verziju, kasnija odbijanja, opciju `nosuid` na fajl-sistemu i MAC politiku. Pravilo koje se podudara kandidat je za pregled, a ne dokaz uspešne eskalacije privilegija.

### Izvoz pravila packet filter-a pokrenut preko sudo

Neograničena sudo dozvola za root nad komandama `iptables` i `iptables-save` (ili odgovarajućim parom `ip6tables`) zahteva pregled upisa u fajl. `comment` match prihvata tekst pravila koji bira pozivalac, dok `iptables-save -f` upisuje serijalizovani skup pravila na izabranu putanju.<sup>[[20]](#references)[[21]](#references)</sup> Koristan payload zavisi od toga kako instalirani backend serijalizuje komentare i da li odredišni fajl prihvata i druge redove u izvezenom sadržaju; sam `iptables-save` ne omogućava proizvoljan sadržaj po izboru korisnika. Tokom enumeracije pregledajte dozvolu bez menjanja firewall pravila ili upisivanja fajla.

### Privilegovani direktorijum za logove Below-a

[CVE-2025-27591](https://github.com/facebookincubator/below/security/advisories/GHSA-9mc5-7qhg-fp3w) pogađao je izdanja Below-a pre verzije 0.9.0, koja su kreirala direktorijum `/var/log/below` sa dozvolom upisa za sve korisnike. Ako servis ili dozvoljena sudo komanda pokreće pogođenu izgradnju kao root, korisnik koji može da upisuje u direktorijum logova i da prolazi kroz njega, a koji nema sticky bit, možda može da zameni unos loga simboličkom vezom pre nego što privilegovani proces otvori fajl. Pregledajte status zakrpe instaliranog paketa, tačan put privilegovanog izvršavanja, efektivan pristup direktorijumu, sticky bit i ACL-ove, kao i metapodatke za `/var/log/below/error_root.log`. Putanja sa dozvolom upisa za sve ili sudo pravilo sami po sebi ne dokazuju ceo lanac. Sticky direktorijum ili zakrpa dobavljača menjaju procenu. Pasivna enumeracija treba da pregleda samo metapodatke; nema potrebe da pravi vezu ili pokreće privilegovani program.

### Prikupljanje privilegovanog paketa za podršku iz ulaza u koje može da se upisuje

Skripta profila za podršku dozvoljena preko `sudo` može da čita fiksne putanje logova kao root i kopira njihov sadržaj u arhivu profila. Pregledajte samu skriptu da biste utvrdili čitanje fajlova, a zatim proverite da li pozivalac može da zameni izvornu putanju ili neki unos u nadređenom direktorijumu simboličkom vezom. Ako privilegovano čitanje prati tu vezu, a nastala arhiva je čitljiva pozivaocu, zaštićeni fajl može da bude otkriven. Svi elementi moraju biti prisutni: sudo dozvola, izvorna putanja u koju može da se upisuje, privilegovano čitanje i izlaz koji može da se čita; sam log ili ime profila u koji može da se upisuje nisu dovoljni. ### Python skripte za obnavljanje arhiva pokrenute kao root

Čak i usko ograničeno sudo pravilo za Python skriptu za obnavljanje zahteva pregled ulazne arhive. Ako pozivalac može da izabere ili zameni arhivu, a skripta je raspakuje kao root pomoću `tarfile.extractall(filter="data")`, proverite bezbednosne ispravke interpretera pre nego što se oslonite na taj filter. CPython je ispravio nekoliko zaobilaženja filtera za simboličke i hard link-ove, uključujući CVE-2025-4517, u verzijama 3.9.23, 3.10.18, 3.11.13, 3.12.11 i 3.13.4. Zakrpe dobavljača mogu da isprave stariju verziju, pa prikazana verzija interpretera sama po sebi ne dokazuje izloženost.<sup>[[16]](#references)[[17]](#references)</sup>

Za pasivan pregled pročitajte tačnu sudo komandu i skriptu, utvrdite koji argument bira arhivu i proverite da li aktuelni korisnik može da upisuje u arhivu ili direktorijum koji je sadrži. Zasebno potvrdite instaliranu zakrpu dobavljača i odredište raspakivanja; `filter="data"` ne čini svaku nepouzdanu arhivu bezbednom.<sup>[[16]](#references)[[17]](#references)</sup>

### Učitavači modela mašinskog učenja pokrenuti preko sudo

Sudo pravilo koje dozvoljava fajl `.pt`, `.pth` ili `.ckpt` koji bira pozivalac zahteva pregled ako privilegovana skripta prosleđuje fajl funkciji [`torch.load`](https://docs.pytorch.org/docs/stable/generated/torch.load.html), `pickle.load` ili drugom učitavaču zasnovanom na pickle-u. Proverite efektivno RunAs pravilo, da li pozivalac može da kreira ili zameni izabrani model i stvarni tok argumenta kroz shell wrapper do Python pomoćne skripte. Ekstenzija `.pth` takođe označava nepovezane Python site konfiguracione fajlove, pa sama ekstenzija nije dokaz učitavanja modela. Skeniranje arhive ili statičko skeniranje pickle-a ne dokazuje da je kasnije učitavanje bezbedno; pregledajte [ponašanje `weights_only`, koje zavisi od verzije](https://docs.pytorch.org/docs/stable/notes/serialization.html), i eventualnu listu dozvoljenih klasa. Pogledajte [napomene o ML pickle-u i Fickling-u](../../generic-methodologies-and-resources/python/keras-model-deserialization-rce-and-gadget-hunting.md). Pasivna enumeracija nikada ne treba da učitava ili raspakuje model.

### Parsiranje izraza iz sačuvanog ulaza pokrenuto preko sudo

Fiksna Python skripta pokrenuta kao root preko sudo-a i dalje može da evaluira tekst koji korisnik sa nižim privilegijama može da sačuva u bazi podataka aplikacije. U TensorFlow-u poziv `preprocess_input_exprs_arg_string(value, safe=False)` bira putanju sa `eval`; [TensorFlow savetodavno obaveštenje](https://github.com/tensorflow/tensorflow/security/advisories/GHSA-75c9-jrh4-79mc) opisuje nebezbedni parser i ispravku njegovog pozivaoca iz komandne linije. Izričiti poziv aplikacije sa `safe=False` zahteva zaseban pregled čak i kada je taj pozivalac iz komandne linije zakrpljen. Proverite efektivno sudo pravilo, ko može da menja konkretan ulazni red, da li filtriranje ili bodovanje omogućavaju tom redu da stigne do poziva i ponašanje instalirane funkcije. TensorFlow verzija, sudo dozvola ili hardkodovani fajl modela sami po sebi ne dokazuju lanac. Pasivno pregledajte skriptu i tok podataka; tokom enumeracije nemojte pokretati privilegovani helper niti slati testne izraze.

### Needrestart konfiguracija dozvoljena preko sudo

`needrestart -c` učitava Perl konfiguracioni fajl koji bira pozivalac i evaluira njegov sadržaj. Ako `sudo -l` dozvoljava `needrestart` kao root sa argumentima koji omogućavaju `-c`, a pozivalac može da izabere čitljiv konfiguracioni fajl na lokaciji u koju može da upisuje, ta dozvola može da dovede do izvršavanja koda kao root. Proverite tačno sudo RunAs pravilo i pravilo argumenata; pravilo koje dozvoljava samo fiksnu listu argumenata može da blokira ovaj put. Ovo je odvojeno od ranjivosti needrestart-a pri skeniranju interpretera: ažuriranje paketa ili isključivanje `interpscan` ne čini neograničenu root dozvolu za `-c` bezbednom.<sup>[[2]](#references)[[18]](#references)[[19]](#references)</sup>

### Python import-i pokrenuti preko sudo pod drugim nalogom

Fiksna Python ulazna tačka i dalje može da uveze modul koji pozivalac može da menja ili zameni, čak i kada sudo pokreće skriptu kao **ne-root** servisni korisnik. Za doslovno `from utils import status` pregledajte lokalne `utils/__init__.py` i `utils/status.py`, kao i dozvole direktorijuma paketa. Pre nego što fajl koji može da se menja smatrate putem izvršavanja, potvrdite putanju import-a skripte, tačne dozvoljene sudo argumente i da li se odgovarajuća radnja izvršava pre tog import-a. Tokom enumeracije pregledajte fajlove i dozvole bez importovanja ili pokretanja skripte.<sup>[[2]](#references)[[3]](#references)</sup>

Tačnom sudo pravilu za `python3 /absolute/script.py` potreban je samo čitljiv skript fajl; fajl ne mora biti izvršiv niti imati shebang. Pregledajte i **nedostajuće** lokalne module: ako skripta uvozi modul čije ime fajla može da se kreira u direktorijumu skripte u koji pozivalac može da upisuje, Python može da učita taj fajl pod RunAs identitetom. Potvrdite efektivno sudo pravilo, stvarnu [putanju pretrage modula](https://docs.python.org/3/library/sys_path_init.html) interpretera, da li je modul ugrađen ili zamrznut i da li se import zaista dešava. Direktno sudo pravilo za skriptu ima drugačije zahteve za execute bit i shebang. Zaseban wrapper koji dodaje tokene koje obezbeđuje pozivalac nakon `sudo -u account` takođe zahteva pregled toka argumenata: dodatni `-u` u tim tokenima važan je samo ako pozvana sudo politika dozvoljava dobijeni identitet. Statički stringovi sami po sebi ne dokazuju nijedan od ova dva puta.

### Apache pokrenut preko sudo sa konfiguracijom koju kontroliše pozivalac

Ako sudo pravilo dozvoljava privilegovani poziv `apachectl`, `apache2ctl` ili `httpd` sa konfiguracionim fajlom `-f` koji kontroliše pozivalac, pregledajte taj fajl i dozvole njegovog nadređenog direktorijuma. Apache-ova direktiva [`LoadModule`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadmodule) prima ime modula praćeno **imenom fajla modula**; [`LoadFile`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadfile) takođe učitava fajl. [`Include` i `IncludeOptional`](https://httpd.apache.org/docs/2.4/mod/core.html#include) mogu da prošire konfiguraciju ili otkriju sadržaj fajla kroz greške. Custom wrapper može da validira te putanje, ukloni privilegije ili ograniči argumente, pa konfiguracija u koju može da se upisuje samo je kandidat za pregled, ne dokaz izvršavanja koda. Pre zaključka proverite kanonsko razrešavanje putanja, simboličke veze i parsiranje direktiva.

### nginx pokrenut preko sudo sa konfiguracijom koju kontroliše pozivalac

Neograničeno nginx pravilo koje omogućava root pristup može da dozvoli [`-c` za izbor druge konfiguracije](https://nginx.org/en/docs/switches.html). Pregledajte tačne sudo argumente i izuzetke, da li pozivalac može da obezbedi konfiguraciju i da li rezultujući master ili worker procesi zadržavaju pristup zaštićenim putanjama. Izabrani `root` uz `autoindex` može da otkrije fajlove preko novog listener-a; [`dav_methods PUT`](https://nginx.org/en/docs/http/ngx_http_dav_module.html) može da omogući privilegovani upis u fajl, ali DAV modul nije uključen po podrazumevanim podešavanjima i treba proveriti njegovo prisustvo, dostupnost listener-a, dozvole fajlova i ponašanje privremenih fajlova. Direktiva [`error_log`](https://nginx.org/en/docs/ngx_core_module.html#error_log) takođe može da cilja izabrani fajl; upisivanje logova u osetljiv konfiguracioni fajl, kao što je `/etc/ld.so.preload`, postaje put za eskalaciju tek kada postoji efektivan privilegovani upisivač i zapis loga koji se može kontrolisati. Istaknuta izvršna datoteka u `sudo -l` samo je smernica za pregled, a ne dokaz da bilo koji od ovih puteva radi. Tokom pasivne enumeracije nemojte pokretati niti rekonfigurisati nginx.

### Poređenje obrasca u privilegovanim Bash prompt-ovima

Kada sudo skripta napisana na Bash-u čita vrednost od pozivaoca i proverava je pomoću `[[ "$expected" == $entered ]]`, Bash tumači nequoted desni operand kao obrazac. Džoker zato može da zadovolji poređenje bez poznavanja očekivane vrednosti. Stavljanje operanda u navodnike (`[[ "$expected" == "$entered" ]]`) pretvara ga u doslovno poređenje stringova. Pregledajte tačno sudo pravilo, da li je prompt dostupan i šta skripta radi nakon poređenja; sama sintaksa ne dokazuje iskoristiv put. Tokom enumeracije nemojte prikazivati očekivanu vrednost. Pogledajte [Bash referencu za uslovne konstrukcije](https://www.gnu.org/software/bash/manual/html_node/Conditional-Constructs.html).

### Helper-i pokrenuti preko sudo koji preuzimaju i izvršavaju fajl

Neograničena sudo dozvola za custom helper koji omogućava root pristup zahteva pregled toka podataka ako prihvata URL koji bira pozivalac, upisuje odgovor na disk, a zatim taj fajl pokreće kroz interpreter ili shell. [Sudoers dozvoljava proizvoljne argumente kada unos komande ne navodi nijedan](https://man7.org/linux/man-pages/man5/sudoers.5.html); fiksna putanja izvršne datoteke ne ograničava šta njeni argumenti mogu da izaberu. Potvrdite stvarnu validaciju URL-a, putanju izlaza, granu uspeha i kasnije izvršavanje u instaliranom helper-u. Odgovarajući libcurl import ili štampiv string sami po sebi ne dokazuju ovaj lanac.

Čak i fiksno ime izlaznog fajla može biti zamenjeno između upisa i izvršavanja kada helper koristi **relativnu putanju u radnom direktorijumu koji kontroliše pozivalac**. Preimenovanje ili zamena fajla u vlasništvu root-a zavisi od prava upisa i pretrage direktorijuma i svih ograničenja sticky bit-a, a ne samo od dozvola fajla; pogledajte [`rename(2)`](https://man7.org/linux/man-pages/man2/rename.2.html). Proverite da li helper kasnije ponovo otvara putanju ili koristi već otvoreni deskriptor i da li prelazi u pouzdani direktorijum pre upisa. Pasivno pregledajte sudo politiku, helper i metapodatke direktorijuma; tokom enumeracije nemojte pokretati privilegovano preuzimanje niti trku.

Helper za preuzimanje pokrenut preko sudo kao root može takođe da omogući injekciju **argumenata** kada sastavlja Bash komandni string kao što je `curl <caller input> -o <fixed output>`. Filter koji odbacuje razmake i dalje ostavlja [Bash proširivanje vitičastih zagrada](https://www.gnu.org/software/bash/manual/html_node/Brace-Expansion.html): nequoted elementi razdvojeni zarezima mogu da postanu zasebni curl argumenti. Ako ulaz stiže do curl-a pre fiksnog `-o`, pozivalac može da prosledi opciju za izlaz i izabere odredište za prvi URL pod identitetom helper-a; [curl vezuje opcije izlaza za URL-ove po redosledu](https://curl.se/docs/manpage.html#-o). Potvrdite tačan shell, citiranje, validaciju ulaza, efektivno sudo pravilo, redosled curl argumenata i podržane URL šeme, kao i da li pozivalac kontroliše preuzete bajtove ili može da čita rezultat. Izvršna datoteka zapakovana PyInstaller-om može da sadrži Python aplikacionu logiku, ali oznaka pakovanja ili string `curl` sami po sebi ne dokazuju ovaj tok podataka. Ako je odobreno, pregledajte ograničenu offline kopiju; rutinska enumeracija ne treba da pokreće helper niti preuzima podatke koje je izabrao napadač.

Root shell skripta pokrenuta preko sudo koja poziva [`mktemp -u` / `--dry-run`](https://www.gnu.org/software/coreutils/manual/html_node/mktemp-invocation.html) samo bira slobodno ime; ona **ne kreira** fajl. Ako skripta kasnije kreira fajl pod tim imenom u direktorijumu na koji drugi korisnik može da utiče, zatim ga ponovo otvara i dodaje njegov sadržaj u zaštićeno odredište kao što je root-ov `authorized_keys`, pregledajte mogućnost trke oko privremenog fajla. Potvrdite tačno sudo pravilo, vlasništvo nad direktorijumom i fajlom, redosled kreiranja i ponovnog otvaranja, zaštite kernela i da li privilegovani upis zaista koristi bajtove koje kontroliše napadač. String `mktemp -u` ili `/tmp` u koji može da se upisuje sami po sebi ne dokazuju trku. Pregledajte skriptu i metapodatke putanje bez njenog pokretanja ili trke oko privremenog fajla tokom enumeracije.

## Napomene o odbrani

- Izbegavajte da preko sudo dozvoljavate interpretere ili interaktivne editore.<sup>[[1]](#references)</sup>
- Nemojte davati neograničene operande generičkim programima za upis u fajlove kao što je `tee`. Koristite wrapper u vlasništvu root-a koji bira fiksno odredište i odbacuje putanje koje kontroliše pozivalac.<sup>[[2]](#references)</sup>
- Prednost dajte fiksnim wrapper-ima u vlasništvu root-a koji izvršavaju jednu usku administrativnu radnju.<sup>[[1]](#references)[[2]](#references)</sup>
- Ako je interpreter neophodan, ograničite tačnu putanju skripte i sprečite argumente pod kontrolom korisnika, importe u direktorijume u koje može da se upisuje, `PYTHONPATH` i nebezbedno čuvanje okruženja.<sup>[[2]](#references)[[3]](#references)[[4]](#references)</sup>
- Ako je potrebna izmena fajla, ograničite tačnu putanju fajla i razmotrite `sudoedit` uz zakrpljene sudo verzije i strogu obradu okruženja.<sup>[[1]](#references)[[2]](#references)</sup>
- Pregledajte `SETENV`, `env_keep`, radne direktorijume u koje može da se upisuje, putanje modula/import-a u koje može da se upisuje, `NOEXEC`, `use_pty` i logovanje, ali ih nemojte smatrati potpunim sandbox-om.<sup>[[1]](#references)[[2]](#references)[[3]](#references)</sup>
