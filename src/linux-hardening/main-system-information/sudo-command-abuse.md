## Interpreters zinazoruhusiwa na Sudo

Ikiwa `sudo -l` inamruhusu mtumiaji kuendesha interpreter kama root, ichukulie kuwa ni utekelezaji wa msimbo moja kwa moja. Interpreters zimeundwa kutekeleza msimbo wowote, kwa hivyo sheria inayoruhusu `python3`, `perl`, `ruby`, `lua`, `node` au binary zinazofanana kwa kawaida ni sawa na kuruhusu utekelezaji wa amri kama root, isipokuwa hoja zimewekewa vizuizi na kuthibitishwa kwa makini.<sup>[[1]](#references)[[2]](#references)[[3]](#references)[[4]](#references)[[5]](#references)[[7]](#references)[[9]](#references)[[11]](#references)</sup>

Utaratibu wa kawaida wa ukaguzi: kwanza orodhesha ruhusa za mtumiaji, kisha tekeleza kauli ya Python kwa kutumia chaguo la `-c` la interpreter.<sup>[[1]](#references)[[3]](#references)[[4]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/python3 -c 'import os; os.system("id")'
sudo /usr/bin/python3 -c 'import os; os.system("/bin/sh")'
```

Mifano mingine ya interpreter imeonyeshwa hapa chini; interpreter zilizoorodheshwa zinaandika kuhusu utekelezaji wa inline-code au API za child-process.<sup>[[5]](#references)[[6]](#references)[[7]](#references)[[8]](#references)[[9]](#references)[[10]](#references)[[11]](#references)</sup>

```bash
sudo /usr/bin/perl -e 'exec "/bin/sh";'
sudo /usr/bin/ruby -e 'exec "/bin/sh"'
sudo /usr/bin/node -e 'require("child_process").spawn("/bin/sh", {stdio: [0,1,2]})'
```

Njia kamili ni muhimu. Ikiwa sheria ya sudo inaruhusu `/usr/bin/python3`, tumia njia hiyo kamili wakati wa uthibitishaji.<sup>[[2]](#references)</sup>

Glob ya executable ya sudo kama `/usr/bin/python*` inaweza pia kuruhusu Python 2 kwa script iliyoandikwa kwa Python 3. Ikiwa script inafikia `input()` ikiwa na maandishi yanayodhibitiwa na mtumiaji, [Python 2 hutathmini maandishi hayo kama expression](https://docs.python.org/2/library/functions.html#input); kuita interpreter moja kwa moja hubatilisha shebang ya script. Thibitisha binaries zinazolingana zilizosakinishwa, RunAs inayotumika na sera ya arguments, makataa, na input inayoweza kufikiwa kabla ya kuichukulia kama njia ya kutekeleza code.

Njia isiyobadilika ya script katika sheria ya sudo yenye uwezo wa root haizuii kile ambacho script hutekeleza. Kwa wrapper ya Bash inayosomeka, angalia kama command yake ya kwanza inayotekelezeka hutumia positional parameter isiyonukuliwa kama `$1` kama **command word**, huku sudo ikiruhusu arguments zinazochaguliwa na mtumiaji. Thibitisha utambulisho wa RunAs unaotumika, sera ya password na arguments, makataa yanayofuata, na tawi halisi la script; `NOEXEC`, orodha isiyobadilika ya arguments salama, au wrapper inayothibitisha command yake inaweza kubadilisha matokeo. Kagua script fupi kwa njia tuli wakati wa upelelezi badala ya kuiita kwa command ya majaribio.

Sheria ya sudo isiyo na vizuizi na yenye uwezo wa root kwa `dotnet` pia inastahili kukaguliwa kama interpreter. Ikiwa .NET SDK imesakinishwa, [`dotnet fsi` huendesha code ya F# kwa njia shirikishi au kutoka kwenye script](https://learn.microsoft.com/en-us/dotnet/fsharp/tools/fsharp-interactive/), na [`dotnet run` hutekeleza project kutoka kwenye source](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-run). Thibitisha kwanza utambulisho wa RunAs unaotumika na sera kamili ya arguments: sheria iliyowekwa kwenye subcommand fulani salama au application inayoaminika ni ruhusa tofauti, na usakinishaji wa runtime pekee huenda usiwe na commands za SDK. Jina la executable pekee ni kidokezo cha kukagua, si uthibitisho wa utekelezaji wa code.

```bash
sudo /usr/bin/python3 -c 'import os; os.setuid(0); os.setgid(0); os.system("/bin/sh")'
```

## Uandishi holela wa faili kwa mapendeleo ya juu kupitia `tee` iliyoruhusiwa na sudo

GNU `tee` hunakili ingizo sanifu kwenye kila njia iliyotolewa kama operand ya faili. Kwa hivyo, sheria ya sudo inayoruhusu kuendesha `/usr/bin/tee` kama root kwa hoja zinazodhibitiwa na mtumiaji huiwezesha primitive ya kuunda faili lolote kama root au kubatilisha faili zilizopo. Kuongeza `-a` hubadilisha primitive hiyo kuwa ya kuongeza maudhui kwenye faili. Lebo ya `PASSWD:` inahusu uthibitishaji wa sudo; yenyewe haizuii lengwa wala baiti zinazosomwa kutoka ingizo sanifu.<sup>[[2]](#references)[[27]](#references)[[28]](#references)</sup>

Kwanza kagua sheria husika. Kwenye mfumo wa majaribio ulioidhinishwa, thibitisha primitive hiyo kwa kutumia tu lengwa la muda ambalo ni salama kuunda. `>/dev/null` iliyo mwisho huzuia tu nakala ya `tee` kwenda kwenye matokeo sanifu.<sup>[[28]](#references)</sup>

```bash
sudo -l
printf '%s\n' 'controlled-write' | sudo /usr/bin/tee /root/tee-proof >/dev/null
printf '%s\n' 'appended-line' | sudo /usr/bin/tee -a /root/tee-proof >/dev/null
```

Kuweka `sudo` kabla ya producer hakupandishi ruhusa za shell redirection inayofuata, kwa sababu shell ya caller hufungua destination. Mchakato wenye ruhusa za juu lazima uwe ndiye anayeandika, kama ilivyo kwenye pipeline iliyo hapo juu.<sup>[[1]](#references)[[15]](#references)</sup>

Baada ya kuthibitisha kuwa uandishi unafanya kazi, chagua sink inayofaa ya root-code-execution kutoka [Arbitrary File Write to Root](../interesting-files-permissions/write-to-root.md). Mlolongo mmoja ulioonekana ulitumia root `tee` kuunda faili la muda mfupi chini ya `/etc/cron.d/`, kuzindua backdoor kupitia script inayodhibitiwa na mtumiaji, kisha kufuta faili la cron baada ya kutekelezwa. Kuondoa faili la cron kulizuia lisiwe ingizo la persistence la muda mrefu, ingawa system logs zilihifadhi ushahidi wa shughuli hiyo.<sup>[[27]](#references)</sup>

## Vihariri vinavyoruhusiwa na Sudo

Ikiwa `sudo -l` inamruhusu mtumiaji kutumia kihariri shirikishi kama root, kichukulie kama sehemu inayoweza kutekeleza amri, si ruhusa isiyo na madhara ya kuhariri faili. Vihariri mara nyingi vinaweza kutekeleza shell commands, kusoma faili zozote, kuandika faili zozote, au kuitisha external helpers kutoka ndani ya kihariri.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

Mtiririko wa kawaida wa ukaguzi: orodhesha ruhusa za mtumiaji, kisha endesha kila kihariri au pager kinachoruhusiwa kupitia sudo.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/nano /etc/hosts
sudo /usr/bin/vim /etc/hosts
sudo /usr/bin/less /etc/hosts
```

### Utekelezaji wa amri kupitia nano

Wakati `nano` inaruhusiwa kupitia sudo, huenda ukaweza kutekeleza amri kupitia kiolesura cha kihariri.<sup>[[12]](#references)</sup>

```text
Ctrl+R
Ctrl+X
```

Kisha weka amri kama `id` au `/bin/sh` kwenye kidokezo cha amri cha nano.<sup>[[12]](#references)</sup>

```bash
id
/bin/sh
```

Ikiwa shell ya mwingiliano haina streams za terminal zinazoweza kutumika, aina hii ya uelekezaji upya hupeleka matokeo yake ya kawaida na makosa kwenye descriptor 0.<sup>[[15]](#references)</sup>

```bash
reset; /bin/sh 1>&0 2>&0
```

Mfuatano halisi wa vitufe unaweza kutofautiana kulingana na toleo la nano na chaguo za build, lakini tatizo la usalama ni lilelile: editor inaendeshwa kama root na inaweza kutekeleza amri za nje.<sup>[[1]](#references)[[12]](#references)</sup>

### Njia nyingine za kawaida za kutoka kwenye editor

Editor za mtindo wa Vim kwa kawaida huruhusu kutekeleza amri kupitia `:!`.<sup>[[13]](#references)</sup>

```text
:!/bin/sh
```

Pager kama `less` pia zinaweza kufichua utekekelezaji wa shell.<sup>[[14]](#references)</sup>

Sheria ya sudo inayoruhusu `apport-cli` kuendeshwa kama root inastahili kukaguliwa pager vivyo hivyo. Matoleo ya Apport yaliyoathiriwa yangeweza kufungua ripoti ya hitilafu kwenye `less` kwa kutumia ukubwa wa terminal unaoweza kurekebishwa na mshambuliaji; pager ingeweza kutoa root shell ikiwa masharti maalum ya sudo na pager yangetimizwa. Kagua sheria ya sudo inayotumika, usanidi wa pager na marekebisho ya kifurushi cha usambazaji kabla ya kuhitimisha kuwa toleo pekee ndilo linaathirika. Soma metadata ya kifurushi na sera bila kusababisha hitilafu au kufungua ripoti yenye ruhusa za juu wakati wa ukaguzi usioingilia mfumo. [Rekodi ya CVE ya Ubuntu](https://ubuntu.com/security/CVE-2023-1326) inaorodhesha matoleo ya kifurushi yaliyorekebishwa kwa kila toleo la mfumo, yakiwemo marekebisho yaliyorejeshwa kwenye matoleo ya zamani.

```text
!/bin/sh
```

## Hatari nyingine za kanuni za sudo na doas

Anza na `sudo -l`, `sudo -V`, na sera yoyote ya `doas` inayotumika. Soma pamoja amri zinazoruhusiwa, mtumiaji wa RunAs, hoja, mazingira na chaguomsingi. Ruhusa ya kuendesha amri kama akaunti ya huduma isiyo ya root bado inaweza kufichua faili za akaunti hiyo au njia ya kufikia root.

Script maalum ya Python iliyoruhusiwa na sudo bado inaweza kuendesha amri ya shell chini ya utambulisho wake wa RunAs ikiwa ingizo shirikishi linalodhibitiwa na mpigaji simu litaunganishwa kwenye [`os.system()`](https://docs.python.org/3/library/os.html#os.system). Orodha ya kukataza alama za uakifishaji za shell haitoshi kuthibitisha usalama: [shell pia hutambua ubadilishaji wa amri wa `$(...)`](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html). Thibitisha kuwa hoja zinazoruhusiwa zinafika kwenye tawi la ingizo, kuwa ingizo linafika kwenye amri ya shell bila uthibitishaji salama, na kuwa sera ya sudo inayotumika inaruhusu mtumiaji wa RunAs anayelengwa. Njia ya script au mwito wa `os.system()` pekee ni kidokezo cha ukaguzi; kagua chanzo bila kuendesha script yenye marupurupu.

Ruhusa inayotumika ya sudo ya root kwa `chattr` inaweza kuondoa sifa ya faili ya immutable (`i`), lakini hilo pekee halitoi ruhusa ya kuandika au utambulisho mpya. [Mwongozo wa `chattr`](https://man7.org/linux/man-pages/man1/chattr.1.html) unasema kuwa sifa hiyo huzuia marekebisho na ni root pekee au mchakato wenye `CAP_LINUX_IMMUTABLE` unaoweza kuibadilisha. Kagua sera halisi ya hoja za sudo na usaidizi wa mfumo wa faili, kisha uthibitishe kivyake kuwa mpigaji simu anaweza kuandika faili baada ya sifa kuondolewa na kuwa mtumiaji wa utambulisho wa juu anaitumia. Kwa mfano, kubadilisha login shell pia kunahitaji vitambulisho vinavyokubaliwa na akaunti lengwa na kuingia halisi kupitia shell hiyo. Kagua sera, sifa za faili na ruhusa bila kuzibadilisha wakati wa ukusanyaji wa taarifa.

Ikiwa sudo inaomba nenosiri na msimbo wa matumizi moja, zichukulie sharti hizo tofauti na ruhusa ya amri. Faili ya `.google_authenticator` inayoweza kusomwa ina nyenzo nyeti ya seed, ilhali hash ya zamani ya nenosiri la programu au hifadhidata ni mgombea tu wa nenosiri la sasa la akaunti; hakuna kati ya hizo inayothibitisha kuwa kipengele kingine kinakubaliwa na usanidi wa PAM unaotumika. Baada ya kupata idhini, kagua RunAs na hoja husika: ruhusa isiyo na vizuizi ya root kwa RubyGems `gem` inaweza kufichua amri yake ya editor ([GTFOBins](https://gtfobins.github.io/gtfobins/gem/)), lakini ruhusa yenye vizuizi au uthibitishaji ulioshindwa haiwezi. Ukusanyaji wa taarifa usiotekeleza amri unapaswa kuripoti njia na sera bila kuchapisha seed, kurejesha nenosiri, kutengeneza msimbo au kuendesha amri yenye marupurupu.

Ruhusa isiyo na vizuizi ya sudo inayoweza kuwa root kwa `knife` ya Chef inahitaji ukaguzi wa kiwango cha interpreter: [Chef inaeleza kuwa `knife exec -E` hutathmini mfuatano wa Ruby ndani ya mfumo](https://docs.chef.io/workstation/26/tools/knife/knife_exec/). Thibitisha kuwa kanuni ya sudo inayotumika inaruhusu subcommand ya `exec` na hoja ya `-E` inayotolewa na mpigaji simu, utambulisho wa RunAs unaolengwa, na makatazo yoyote ya amri au hoja zisizobadilika zinazolingana. Binary iliyosakinishwa au kanuni inayozuia subcommands nyingine ni kidokezo tu. Ukusanyaji wa taarifa usiotekeleza amri unapaswa kuripoti kanuni hiyo bila kuendesha `knife`.

Ruhusa kamili ya sudo inayoweza kuwa root kwa `msfconsole` shirikishi ni nyeti vivyo hivyo: [GTFOBins inaeleza console yake ya `irb`](https://gtfobins.org/gtfobins/msfconsole/), ambayo inaweza kurithi utambulisho wa sudo. Thibitisha mtumiaji wa RunAs anayetumika, orodha ya hoja zinazoruhusiwa, makatazo ya amri, `NOEXEC` au vizuizi vingine, tabia ya console iliyosakinishwa, na kama mpigaji simu anaweza kutoa ingizo shirikishi. Kuangaziwa kwa njia pekee ni kidokezo cha ukaguzi; ukusanyaji wa taarifa usiotekeleza amri haupaswi kuwasha console.

Kwenye FreeBSD, hata kanuni ya sudo iliyozuiwa kwa `pkg update` ya root na `pkg install *` inahitaji ukaguzi wa uaminifu wa hazina. Kagua kama mpigaji simu anaweza kuandika `/etc/hosts` na kama usanidi wa hazina unaowezeshwa na kutumika kweli unatumia hostname ya HTTP yenye `signature_type: none`. [Mwongozo wa `pkg.conf` wa FreeBSD](https://man.freebsd.org/cgi/man.cgi?query=pkg.conf&sektion=5) unasema kuwa `none` huzima ukaguzi wa sahihi; `pkg+http` pekee hauthibitishi hilo. Kifurushi kinaweza kuwa na script za usakinishaji ([FreeBSD Porter's Handbook](https://docs.freebsd.org/en/books/porters-handbook/pkg-files/)), kwa hiyo mpigaji simu anayedhibiti endpoint ya hazina na anayeweza kuchagua kifurushi anaweza kuvuka mpaka wa root. Thibitisha mipitisho ya hazina, uelekezaji wa SRV/mirror, hoja halisi za sudo, uteuzi wa kifurushi na utekelezaji wa script kabla ya kufikia hitimisho hilo. Kagua sera na faili ndogo za usanidi wa ndani bila kuelekeza majina upya au kuendesha `pkg` wakati wa ukusanyaji wa taarifa.

Ruhusa ya sudo inayoweza kuwa root kwa `apt-get update` na `apt-get upgrade` pia inahitaji ukaguzi wa uaminifu wa hazina wakati sudo inahifadhi `http_proxy` inayodhibitiwa na mpigaji simu. Kagua kama usanidi wa APT unaotumika kweli unatumia kigezo hicho na maombi ya hazina yaliyowezeshwa ambayo kinaweza kuathiri; proxy pekee haiwezi kubadilisha vifurushi kutoka kwenye archive iliyothibitishwa kwa ufunguo wa sahihi unaoaminika. [Mwongozo wa usafirishaji wa HTTP wa APT](https://manpages.debian.org/experimental/apt/apt-transport-http.1.en.html) unaeleza kipaumbele cha proxy, na [apt-secure](https://manpages.debian.org/experimental/apt/apt-secure.8.en.html) unaeleza ukaguzi wa sahihi, vizuizi vya hazina zisizo salama, na uthibitishaji wa vifurushi visivyothibitishwa. Thibitisha RunAs na hoja halisi za sudo, sera ya uthibitishaji wa hazina, kukubali kwa mwingiliano kunakohitajika, na kama uboreshaji uliochaguliwa unaendesha script za kifurushi kama root. Kagua sera na usanidi wa ndani bila kutekeleza amri; usielekeze upya trafiki ya vifurushi au kuendesha uboreshaji wakati wa ukusanyaji wa taarifa.

Kanuni ya sudo inayoweza kuwa root kwa `snap install` inaweza kuwa mpaka kati ya kifurushi na msimbo ikiwa hoja zake zinamruhusu mpigaji simu kuchagua snap ya ndani na hali ya usakinishaji isiyo na vizuizi. [Snap inaeleza](https://snapcraft.io/docs/explanation/snap-development/install-modes/) kuwa `--dangerous` huruka ukaguzi wa uthibitisho wa snap ya ndani na `--devmode` hurahisisha vizuizi; [hook ya usakinishaji inaweza kuendeshwa wakati wa usakinishaji wa kwanza](https://snapcraft.io/docs/reference/development/supported-snap-hooks/). Kagua sera halisi ya hoja/RunAs ya sudo, nani anayedhibiti faili ya snap, kama snapd iliyosakinishwa inakubali hali hizi, na utambulisho na vizuizi halisi vya hook kabla ya kudai ufikiaji wa faili za host zilizolindwa. Binary ya `snap` au kanuni inayoonekana kuwa na wildcard pekee haithibitishi mlolongo huu. Ukusanyaji wa taarifa usiotekeleza amri haupaswi kusakinisha kifurushi au kuendesha hook yake.

Kwa ruhusa kamili ya sudo kwa binary maalum ya kusoma vitambulisho ya akaunti **isiyo root**, kagua kwanza binary iliyopewa ruhusa na ruhusa zake za faili bila kuiendesha. Kizuizi cha nenosiri kilichopachikwa kinaweza kuonekana tu kama herufi pana; [GNU `strings` inaeleza uchimbaji wa 16-bit little-endian](https://sourceware.org/binutils/docs/binutils/strings.html). Mfuatano unaoonekana si uthibitisho kuwa hilo ndilo nenosiri linalokubaliwa au kuwa tawi la mafanikio linafichua kitambulisho cha sasa. Thibitisha tabia ya binary, ufikiaji wa akaunti lengwa kwa data iliyolindwa, uhalali wa kitambulisho, na mabadiliko yoyote ya baadaye ya akaunti au kundi kivyake. Ikiwa akaunti hiyo ni mwanachama wa `docker`, thibitisha ufikiaji wa socket na kama daemon inatumia utambulisho wa rootful au rootless kabla ya kudhani kuwa ufikiaji wa root wa host unawezekana; [Docker inaeleza athari za kiwango cha root za kundi lake](https://docs.docker.com/engine/install/linux-postinstall/). Ukusanyaji wa kawaida wa taarifa unapaswa kuripoti kanuni ya sudo na uanachama wa kundi bila kuendesha binary au kutoa mfuatano wake.

Kanuni ya sudo yenye wildcard kwa script za matengenezo za programu inahitaji ukaguzi zaidi ya njia ya script. Kagua kama script inayoruhusiwa inakubali hoja zisizo na vizuizi au inasoma mipangilio inayoweza kuandikwa kupitia akaunti ya programu yenye marupurupu ya chini, kisha fuatilia thamani hizo hadi kwenye amri za shell au mazingira ya subprocess. Kwa mfano, ZoneMinder [`zmupdate.pl` hutengeneza amri ya `mysqldump` na kuiendesha kupitia `qx`](https://github.com/ZoneMinder/ZoneMinder/blob/master/scripts/zmupdate.pl.in), ilhali [`zmdc.pl` hunakili mpangilio wa `ZM_LD_PRELOAD` hadi `LD_PRELOAD`](https://github.com/ZoneMinder/ZoneMinder/blob/master/scripts/zmdc.pl.in) kabla ya kuanzisha daemon. Kanuni ya sudo inayoruhusu mojawapo ya script hizo kama root inaweza kuvuka mpaka wa uaminifu ikiwa ingizo husika linadhibitika na kufika kwenye msimbo huo katika toleo lililosakinishwa. Kagua kanuni halisi ya sudo, ruhusa za usanidi wa programu na chanzo cha script; wildcard au mpangilio pekee ni kidokezo cha ukaguzi, si uthibitisho wa utekelezaji.

- `SETENV`, `env_keep`, `secure_path`, na `LD_PRELOAD` zinaweza kugeuza amri yenye vizuizi vinginevyo kuwa utekaji wa import, library au PATH. Tazama [mwongozo wa vigezo vya mazingira](../linux-basics/linux-environment-variables.md) na [unyonyaji wa SUID/linker](../interesting-files-permissions/suid-shared-library-and-linker-abuse.md).

Ruhusa kamili ya `SETENV` inayoweza kuwa root kwa wrapper ya shell pia inahitaji ukaguzi wa hatua moja ikiwa wrapper inaanzisha script maalum ya Python yenye import halisi. `secure_path` hudhibiti utafutaji wa amri wa shell, si utafutaji wa moduli wa Python wa [`PYTHONPATH`](https://docs.python.org/3/using/cmdline.html#envvar-PYTHONPATH); [`-E` na `-I`](https://docs.python.org/3/using/cmdline.html#cmdoption-E) hufanya Python ipuuze kigezo hicho cha mazingira. Thibitisha tag na makatazo ya sudo yanayotumika, tawi la wrapper, chaguo za interpreter, utatuzi wa import, na saraka ya utafutaji inayoweza kuandikwa na mpigaji simu kabla ya kuichukulia kama utekelezaji wa msimbo. Kagua script fupi bila kuziendesha; usiendeshe wrapper yenye marupurupu.

Ruhusa kamili ya `neofetch ""` inayoweza kuwa root bado inaweza kupakia usanidi wa shell ikiwa chaguomsingi za sudo zinazotumika zinahifadhi `XDG_CONFIG_HOME` inayodhibitiwa na mpigaji simu. [Kipakiaji cha usanidi cha Neofetch](https://github.com/dylanaraps/neofetch/blob/master/neofetch) hupakia `neofetch/config.conf` au `neofetch/config` chini ya saraka hiyo; orodha tupu ya hoja haizuii utafutaji huu. Thibitisha kipakiaji kilichosakinishwa, sera halisi ya RunAs na hoja, makatazo yoyote ya amri, kama sudo kweli huhifadhi kigezo kilichochaguliwa kwa amri hii, na kama mpigaji simu anadhibiti njia ya usanidi inayoweza kusomwa. Kigezo kilichohifadhiwa au Neofetch iliyosakinishwa pekee ni kidokezo cha ukaguzi. Kagua sera na metadata ya faili bila kuendesha amri yenye marupurupu au kuchapisha yaliyomo kwenye usanidi; tazama [ushughulikiaji wa mazingira wa sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf).

Kanuni ya sudo isiyo na vizuizi inayoweza kuwa root kwa `facter` inahitaji ukaguzi tofauti wa custom-fact. [Puppet inaeleza](https://help.puppet.com/core/current/Content/PuppetCore/loading_custom_facts.htm) kuwa `--custom-dir` hupakia faili za fact za Ruby kutoka kwenye saraka iliyochaguliwa. Kagua kama kanuni halisi ya sudo inaruhusu chaguo hilo, kama Facter iliyosakinishwa inalikubali, na kama mpigaji simu anadhibiti saraka hiyo. Ruhusa yenye hoja zisizobadilika, katazo la wazi la amri au custom facts zilizozimwa zinaweza kubadilisha matokeo. Ukusanyaji wa taarifa usiotekeleza amri unapaswa kuripoti mgombea wa sera bila kuendesha Facter au kusoma yaliyomo kwenye fact.

Kwa ruhusa kamili ya script ya sudo inayoweza kuwa root yenye `SETENV`, kagua majina ya amri tupu kama `find` na `PATH` inayotumika baada ya sera ya sudo na uanzishaji wa script. Faili ya Bash iliyopakiwa pia inaweza kuendesha `enable -n [`: [Bash kisha hutafuta `[` ya nje kwenye `PATH`](https://www.gnu.org/software/bash/manual/html_node/Bash-Builtins.html) pale script inapotumia amri hiyo baadaye. Thibitisha [kanuni za mazingira za sudoers na `secure_path`](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) zinazotumika, ingizo lolote la `NOSETENV`/`NOEXEC` au katazo, mtiririko wa script na faili iliyopakiwa, na saraka ya utafutaji inayoweza kutekelezwa na kudhibitiwa na mpigaji simu. Script inayosomeka yenye amri tupu ni kidokezo cha ukaguzi, si uthibitisho wa utekelezaji wenye marupurupu; ikague bila kuendesha kanuni ya sudo.

Ikiwa script kisha inapeleka jibu kwa kichanganuzi cha XML kinachotatua external entities, jibu hasidi linaweza kufichua faili zinazoweza kusomwa na mchakato wenye marupurupu. Kagua sera halisi ya mazingira ya sudo, vizuizi vya `no_proxy`, URL inayoombwa, usanidi wa kichanganuzi na mahali matokeo yanapoandikwa; kigezo cha proxy au kichanganuzi cha XML pekee si udhaifu. Usitume maombi ya mtandao au kuchanganua XML hasidi wakati wa ukusanyaji wa taarifa usiotekeleza amri.

Ghostscript inaeleza kuwa flag hii huzima SAFER hadi `.setsafe`, na kuruhusu shughuli za faili za PostScript ndani ya ruhusa za mfumo wa uendeshaji za mchakato huo. Hoja ya mpigaji simu inaweza kutengeneza query ya SQL ambayo matokeo yake yanayodhibitiwa na mshambuliaji yanaingizwa kwenye kiolezo cha PostScript, lakini mfuatano wa query au mwito wa `ps2pdf` pekee hauthibitishi kuwa data inafika kwenye sintaksia ya PostScript inayotekelezeka. Thibitisha kanuni halisi ya sudo, njia halisi ya ingizo hadi kwenye kiolezo, escaping yoyote, tabia ya Ghostscript iliyosakinishwa, na kama SAFER inawashwa tena kabla ya hati kutafsiriwa. Usifanye ubadilishaji wenye marupurupu wakati wa ukusanyaji wa taarifa usiotekeleza amri. Tazama [nyaraka za `-dNOSAFER` za Ghostscript](https://ghostscript.readthedocs.io/en/master/Use.html).

Muundo kama `if $CHECK_CONTENT; then` huendesha thamani iliyopanuliwa kama amri, kwa hiyo kuhifadhi `CHECK_CONTENT` kunaweza kuruhusu utekelezaji wa amri hata kama njia ya script na hoja zake hazibadiliki. Siri iliyofichuliwa hugeuka kuwa mabadiliko ya akaunti ya mfumo wa uendeshaji tu ikiwa akaunti hiyo inaikubali. Kagua script na ruhusa za socket bila kuendesha operesheni yenye marupurupu.

Thibitisha ushughulikiaji wa URL wa programu iliyosakinishwa, ukaguzi wa njia lengwa, kanuni halisi ya sudo na ufikiaji wa matokeo. Njia ya usanidi inayoweza kuandikwa ndani ya `/tmp` pekee ni kidokezo cha ukaguzi; kagua binary na metadata ya faili bila kuanzisha uhamishaji wenye marupurupu.

### Zana za build na vifurushi zinazoendeshwa kupitia sudo

Ruhusa isiyo na vizuizi ya sudo kwa `forge` ya Foundry inaweza kuwa muhimu hata utambulisho wa RunAs unapokuwa mtumiaji mwingine asiye root. Chaguo za compiler kama `--use` zinaweza kuchagua executable ya ndani, na `forge flatten -o` huchagua faili ya matokeo. Kagua toleo la Forge lililosakinishwa, hoja halisi za sudo, njia za mradi na compiler zinazofikiwa, ruhusa za matokeo, na mazingira halisi kabla ya kuichukulia ruhusa hiyo kama inayoweza kutumiwa vibaya. Executable ya helper ya relative path inayopatikana kupitia `PATH` ni njia inayotegemea toleo na mazingira, si tabia inayopaswa kudhaniwa kwa kila build ya Forge.<sup>[[23]](#references)[[24]](#references)</sup>

Ruhusa isiyo na vizuizi ya `pacman` inayoweza kuwa root inaruhusu zaidi ya kuuliza taarifa za vifurushi: `-U` hukubali kifurushi cha ndani, vifurushi vinaweza kuwa na script za usakinishaji, na `--hookdir` huchagua saraka nyingine ya hook. Kagua kanuni halisi ya sudo, vizuizi vya hoja na makatazo kabla ya kujaribu; ukusanyaji wa taarifa usiotekeleza amri hauhitaji kusakinisha kifurushi au kuendesha hook.<sup>[[25]](#references)[[26]](#references)</sup>

Wrapper isiyobadilika ya shell ya sudo inaweza pia kusakinisha dependency ya npm yenye jina maalum kisha kuanzisha programu ya Node. Kagua kanuni yake halisi ya RunAs, kama kifurushi tayari kimesakinishwa, `HOME` na `userconfig` halisi za npm, usanidi wa mradi au mipitisho ya command line, na kama mtumiaji mwenye marupurupu ya chini anadhibiti registry au kifurushi kinachorejeshwa kwa jina hilo. [npm inaeleza utafutaji wa `.npmrc` kwa kila mtumiaji na mradi](https://docs.npmjs.com/cli/v6/configuring-npm/npmrc/); tabia ya `HOME` ya sudo hutegemea sera na usambazaji uliosakinishwa, kwa hiyo `.npmrc` ya mtumiaji inayoweza kuandikwa inaweza kusomwa au kutosomwa na mchakato wa npm wenye marupurupu. Ikiwa kifurushi kipya kilichosakinishwa kina-importiwa na programu yenye marupurupu, msimbo wa moduli yake unaweza kuendeshwa chini ya utambulisho wa programu hiyo. Script za wakati wa usakinishaji ni njia tofauti inayotegemea toleo na usanidi; [npm inaeleza lifecycle yake na ushughulikiaji wa mtumiaji](https://docs.npmjs.com/cli/v6/using-npm/scripts/). Njia ya `.npmrc` au mstari wa `npm install` pekee ni kidokezo cha ukaguzi. Kagua kanuni, wrapper fupi, njia za usanidi na asili ya kifurushi bila kusakinisha kifurushi au kuanzisha programu wakati wa ukusanyaji wa taarifa usiotekeleza amri.

Ruhusa ya sudo ya `pip` au `pip3 download` inayoweza kuwa root pia ni kidokezo cha kukagua build ya kifurushi wakati hoja zake zinamruhusu mpigaji simu kuchagua source distribution isiyoaminika, hata ikiwa muundo wa URL unaizuia kwenye huduma ya ndani na kiambishi tamati cha `.tar.gz`. `pip download` hukubali URL za archive na kutatua metadata ya kifurushi; kuandaa sdist kunaweza kuita backend yake ya build au msimbo wa zamani wa `setup.py` kabla tu ya archive kuhifadhiwa. Thibitisha RunAs halisi ya sudo na kanuni ya hoja, kama mpigaji simu anaweza kuchapisha au kubadilisha archive iliyochaguliwa, na kama toleo hilo la pip kweli huandaa metadata yake. Archive au wheel ya kuaminika isiyobadilika haithibitishi njia hii. Usichukue au kujenga kifurushi kisichoaminika wakati wa ukusanyaji wa taarifa usiotekeleza amri. Tazama amri ya pip ya [download](https://pip.pypa.io/en/stable/cli/pip_download/), [kiolesura cha build-system](https://pip.pypa.io/en/stable/reference/build-system/), na [mwongozo wa usakinishaji salama](https://pip.pypa.io/en/stable/topics/secure-installs/).

Kanuni ya sudo inayoruhusu `pip install` pamoja na njia ya mradi wa ndani iliyochaguliwa na mpigaji simu ina mpaka wa build ulio wa moja kwa moja zaidi. [pip hukubali saraka za mradi za ndani](https://pip.pypa.io/en/stable/topics/local-project-installs/) na kuita build system zake; [backend ya build huendesha build hooks zinazodhibitiwa na mradi](https://pip.pypa.io/en/stable/reference/build-system/). Thibitisha utambulisho halisi wa RunAs, vizuizi vya hoja na makatazo, udhibiti wa mradi uliochaguliwa, na tabia ya pip/backend iliyosakinishwa kabla ya kuichukulia kanuni hiyo kama utekelezaji wa msimbo wenye marupurupu. Mradi maalum unaoaminika au kanuni isiyoruhusu njia zilizochaguliwa na mpigaji simu haithibitishi njia hii. Kagua kanuni na metadata ya mradi bila kusakinisha kifurushi wakati wa ukusanyaji wa taarifa usiotekeleza amri.

Ruhusa isiyo na vizuizi ya `easy_install` inayoweza kuwa root ni kidokezo kinachohusiana na legacy package-build. [Setuptools inaeleza](https://setuptools.pypa.io/en/stable/deprecated/easy_install.html) kuwa Easy Install hukubali saraka ya mradi wa ndani na kujenga source distribution; mradi unaodhibitiwa na mpigaji simu unaweza kuendesha `setup.py` yake wakati wa build chini ya utambulisho wa sudo. Thibitisha akaunti halisi ya RunAs, amri na vizuizi vya hoja (pamoja na makatazo yanayofuata), udhibiti wa mradi uliochaguliwa, na tabia ya zana iliyosakinishwa. Mradi maalum unaoaminika au sera isiyoruhusu chanzo kilichochaguliwa na mpigaji simu haithibitishi njia hii. Kagua kanuni na metadata ya mradi bila kusakinisha kifurushi wakati wa ukusanyaji wa taarifa.

Wrapper ya Python iliyoruhusiwa na sudo inayotumia `setuptools.package_index.PackageIndex.download` pamoja na URL iliyochaguliwa na mpigaji simu ni hali tofauti ya ukaguzi na `pip download`: [Setuptools GHSA-5rjg-fvgr-3xxf](https://github.com/pypa/setuptools/security/advisories/GHSA-5rjg-fvgr-3xxf) inaeleza jina la faili linalotokana na URL kukwepa saraka ya upakuaji iliyokusudiwa na kuandika kwa ruhusa za mchakato katika matoleo yaliyoathirika kabla ya 78.1.1. Thibitisha RunAs na kanuni ya hoja halisi za sudo, kuwa wrapper hupitisha URL ya mpigaji simu kwa API hii hasa, build iliyosakinishwa au backport ya muuzaji, na mahali njia inayotokana inapoelekezwa. Mfuatano wa toleo au saraka ya upakuaji inayoweza kuandikwa pekee hauthibitishi uandishi wa kiholela. Kagua wrapper fupi na metadata ya kifurushi bila kuchukua URL au kuandika faili wakati wa ukusanyaji wa taarifa.

Wrapper ya build inayoruhusiwa na sudo inayopitisha faili ya `.spec` iliyochaguliwa na mpigaji simu kwa PyInstaller inahitaji ukaguzi huohuo wa mpaka wa uaminifu. PyInstaller spec ni Python inayotekelezeka inayotathminiwa wakati wa **build**, na ingizo zake za `datas` zinaweza kufunga kwenye artifact faili zinazoweza kusomwa na utambulisho wa build. Thibitisha mtumiaji halisi wa RunAs, kanuni za hoja na makatazo za sudo, ushughulikiaji wa njia na matawi wa wrapper, udhibiti wa faili ya spec iliyochaguliwa, na ufikiaji wa artifact inayotokana. Kuruhusu ingizo la `.py` au kupata PyInstaller ikiwa imesakinishwa pekee hakuthibitishi udhibiti wa spec file au utekelezaji wenye marupurupu. Ukaguzi usiotekeleza amri unapaswa kusoma wrapper yenye mipaka na metadata tu; usiendeshe build. Tazama [nyaraka za spec file za PyInstaller](https://pyinstaller.org/en/stable/spec-files.html).

### Wrapper za backup zenye marupurupu zinazobadilisha faili ya kazi ya mpigaji simu

Wrapper ya shell inayoendeshwa kama root inaweza kukubali faili ya kazi iliyochaguliwa na mpigaji simu, kuondoa `../` kutoka njia za chanzo, kuthibitisha kuwa kila matokeo yanaanza na saraka inayoruhusiwa, kubadilisha faili ya kazi, kisha kupitisha *njia yake* kwa programu ya backup. Kagua njia iliyobadilishwa baada ya utatuzi kamili wa canonical: ubadilishaji mmoja wa mfuatano unaweza kufichua mfuatano mpya wa traversal ambao ukaguzi wa kiambishi awali cha kileksika unakubali. Pia kagua kama programu ya backup husoma data iliyobadilishwa iliyo kwenye kumbukumbu au hufungua faili tena. Ikiwa inafungua faili tena, kushindwa kwa marekebisho kunaweza kuacha ingizo la awali kama lilivyokuwa.

Kwenye Linux, `fs.protected_regular` inaweza kukataa uandishi wa `O_CREAT` kwenye faili ya kawaida inayomilikiwa na mtumiaji mwingine ndani ya saraka ya sticky inayoweza kuandikwa na wote. Kukataa huko ni kinga, lakini wrapper ya shell inayopuuza hitilafu ya uandishi bado inaweza kuendelea na faili ya kazi ya awali. Thibitisha mpangilio, mmiliki wa faili na saraka, na kama wrapper husimama hitilafu inapotokea. Njia hii ni mgombea wa ufichuaji wa faili tu ikiwa kanuni halisi ya sudo inaruhusu wrapper kuendeshwa kama mtumiaji mwenye marupurupu, mpigaji simu anadhibiti ingizo la kazi na lengwa la backup linaloweza kusomwa, na zana ya backup kwa kweli inajumuisha vyanzo vilivyolindwa. Kagua masharti haya bila kuendesha backup wakati wa ukusanyaji wa taarifa.

### Wildcards za hoja kwenye zana za pakiti zenye marupurupu

Katika kanuni ya sudo ya `tcpdump`, `*` kwenye **muundo wa hoja** inaweza kulingana na nafasi tupu na slash, kwa hiyo kizuizi kinachoonekana kama njia bado kinaweza kuruhusu maandishi ya chaguo ya ziada. Hili ni tofauti na wildcard kwenye njia ya executable ya amri; kagua kanuni kamili ya RunAs na makatazo yoyote yanayofuata. Ikiwa chaguo zinaweza kudungwa, mwito unaoruhusiwa na semantiki za chaguo za [`tcpdump`](https://github.com/the-tcpdump-group/tcpdump/blob/master/tcpdump.1.in) iliyosakinishwa huamua kama `-F`, `-V`, `-r`, `-w` au `-Z` hutoa primitive ya kusoma/kuandika yenye manufaa. `-V` husoma orodha ya majina ya faili za capture, si utoaji wa jumla wa faili yoyote. AppArmor au sera nyingine ya MAC inaweza kuzuia ufikiaji wa faili hata sudo ikiruhusu amri; faili ya profile kwenye diski haithibitishi kuwa imepakiwa au inatekelezwa. Kagua uidhinishaji na sera bila kutekeleza amri kabla ya kufikia hitimisho. [Mwongozo wa sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) unaeleza tofauti ya wildcard.

Kanuni ya sudo inayoweza kuwa root inayoorodhesha executable ya `tcpdump` pekee bila kizuizi cha hoja pia inahitaji ukaguzi. [Mwongozo wa tcpdump](https://github.com/the-tcpdump-group/tcpdump/blob/master/tcpdump.1.in) unaeleza `-z` kama amri ya baada ya rotation wakati `-C` au `-G` inapozungusha capture iliyohifadhiwa; `-Z` au chaguomsingi la wakati wa compile huenda likaondoa marupurupu kabla amri hiyo haijaendeshwa. Thibitisha kanuni halisi ya sudo, build iliyosakinishwa, tabia ya kuondoa marupurupu, na kama rotation inaweza kutokea kabla ya kuchukulia kanuni hiyo kama njia ya privilege escalation. Kanuni iliyoangaziwa ni mgombea, si uthibitisho wa utekelezaji wa amri kama root.

### Wrapper za Nmap zinazoendeshwa kupitia sudo

### Script za kurejesha archive za Python zinazoendeshwa kama root

Thibitisha marekebisho ya muuzaji yaliyosakinishwa na lengwa la ufunguaji kivyake; `filter="data"` haifanyi kila archive isiyoaminika kuwa salama.<sup>[[16]](#references)[[17]](#references)</sup>

### Vipakiaji vya modeli za machine-learning vinavyoendeshwa kupitia sudo

Kanuni ya sudo inayoruhusu faili ya `.pt`, `.pth` au `.ckpt` iliyochaguliwa na mpigaji simu inahitaji ukaguzi ikiwa script yenye marupurupu inapita faili hiyo kwa [`torch.load`](https://docs.pytorch.org/docs/stable/generated/torch.load.html), `pickle.load` au loader nyingine inayotegemea pickle. Kagua kanuni halisi ya RunAs, kama mpigaji simu anaweza kuunda au kubadilisha modeli iliyochaguliwa, na mtiririko halisi wa hoja kupitia wrapper yoyote ya shell hadi kwa helper ya Python. Kiambishi tamati cha `.pth` pia hutaja faili za usanidi wa Python site zisizohusiana, kwa hiyo kiambishi tamati pekee si ushahidi wa kupakia modeli. Kuchanganua archive au pickle kwa njia tuli hakuthibitishi kuwa upakiaji wa baadaye ni salama; kagua tabia ya [`weights_only` inayotegemea toleo](https://docs.pytorch.org/docs/stable/notes/serialization.html) ya loader na allowlisting yoyote. Tazama [maelezo ya ML pickle na Fickling](../../AI/keras-model-deserialization-rce-and-gadget-hunting.md#ml-pickle-import-allowlisting-for-aiml-models-fickling). Ukusanyaji wa taarifa usiotekeleza amri haupaswi kamwe kupakia au kufungua modeli.

### Kuchanganua usemi wa ingizo lililohifadhiwa kupitia sudo

Script maalum ya Python inayoendeshwa kama root kupitia sudo bado inaweza kutathmini maandishi ambayo mtumiaji mwenye marupurupu ya chini anaweza kuhifadhi kwenye hifadhidata ya programu. Katika TensorFlow, mwito wa `preprocess_input_exprs_arg_string(value, safe=False)` huchagua njia ya `eval`; [ushauri wa TensorFlow](https://github.com/tensorflow/tensorflow/security/advisories/GHSA-75c9-jrh4-79mc) unaeleza parser isiyo salama na marekebisho kwa mwitaji wake wa command-line. Mwito wa wazi wa `safe=False` wa programu unahitaji ukaguzi tofauti hata kama mwitaji huyo wa command-line umerekebishwa. Kagua kanuni halisi ya sudo, nani anayeweza kubadilisha rekodi husika ya ingizo, kama uchujaji au scoring huruhusu rekodi hiyo kufikia mwito, na tabia ya function iliyosakinishwa. Toleo la TensorFlow, ruhusa ya sudo au faili ya modeli iliyowekwa kwenye msimbo pekee havithibitishi mlolongo. Kagua script na mtiririko wa data bila kutekeleza amri; usiendeshe helper yenye marupurupu au kuwasilisha usemi wa majaribio wakati wa ukusanyaji wa taarifa.

### Usanidi wa needrestart unaoruhusiwa na sudo

`needrestart -c` hupakia faili ya usanidi ya Perl iliyochaguliwa na mpigaji simu na kutathmini yaliyomo. Ikiwa `sudo -l` inaruhusu `needrestart` kama root kwa hoja zinazoruhusu `-c`, na mpigaji simu anaweza kuchagua faili ya usanidi inayosomeka katika eneo linaloweza kuandikwa, ruhusa hiyo inaweza kusababisha utekelezaji wa msimbo wa root. Kagua kanuni halisi ya run-as na hoja za sudo; kanuni inayoruhusu orodha isiyobadilika tu ya hoja inaweza kuzuia njia hii. Hili ni tofauti na udhaifu wa needrestart wa kuchanganua interpreter: kusasisha kifurushi au kuzima `interpscan` hakufanyi ruhusa isiyo na vizuizi ya root `-c` kuwa salama.<sup>[[2]](#references)[[18]](#references)[[19]](#references)</sup>

### Python imports zinazoendeshwa kupitia sudo chini ya akaunti nyingine

Entry point isiyobadilika ya Python bado inaweza ku-import moduli ambayo mpigaji simu anaweza kuhariri au kubadilisha, hata sudo inapoendesha script kama mtumiaji wa huduma **asiye root**. Kwa `from utils import status` halisi, kagua `utils/__init__.py` na `utils/status.py` za eneo hilo pamoja na ruhusa za saraka ya kifurushi. Thibitisha njia ya import ya script, hoja halisi za sudo zinazoruhusiwa, na kama kitendo husika kinafika kwenye import hiyo kabla ya kuchukulia faili inayoweza kuandikwa kama njia ya utekelezaji. Kagua faili na ruhusa bila ku-import au kuendesha script wakati wa ukusanyaji wa taarifa.<sup>[[2]](#references)[[3]](#references)</sup>

Kanuni halisi ya sudo ya `python3 /absolute/script.py` inahitaji script isomeke tu; si lazima faili iwe executable au iwe na shebang. Kagua pia moduli za ndani **zinazokosekana**: ikiwa script ina-import moduli ambayo jina la faili lake linaweza kuundwa katika saraka ya script inayoweza kuandikwa na mpigaji simu, Python inaweza kupakia faili hiyo chini ya utambulisho wa RunAs. Thibitisha kanuni halisi ya sudo, [njia halisi ya utafutaji wa moduli](https://docs.python.org/3/library/sys_path_init.html) ya interpreter, kama moduli imejengwa ndani au imegandishwa, na kama import hiyo inafikiwa. Kanuni ya sudo ya moja kwa moja kwa script ina masharti tofauti ya execute bit na shebang. Wrapper tofauti inayoongeza tokeni zilizotolewa na mpigaji simu baada ya `sudo -u account` pia inahitaji ukaguzi wa mtiririko wa hoja: `-u` nyingine ndani ya tokeni hizo ni muhimu tu ikiwa sera ya sudo inayotumika inaruhusu utambulisho unaotokana. Mfuatano tuli pekee hauthibitishi njia yoyote kati ya hizo.

### Apache inayoendeshwa kupitia sudo yenye usanidi unaodhibitiwa na mpigaji simu

Ikiwa kanuni ya sudo inaruhusu mwito wenye marupurupu wa `apachectl`, `apache2ctl` au `httpd` wenye faili ya usanidi ya `-f` inayodhibitiwa na mpigaji simu, kagua faili hiyo na ruhusa za saraka yake ya mzazi. Maelekezo ya Apache ya [`LoadModule`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadmodule) huchukua jina la moduli likifuatiwa na **jina la faili la moduli**; [`LoadFile`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadfile) pia hupakia faili. [`Include` na `IncludeOptional`](https://httpd.apache.org/docs/2.4/mod/core.html#include) zinaweza kupanua usanidi au kufichua yaliyomo kwenye faili kupitia hitilafu. Wrapper maalum inaweza kuthibitisha njia hizi, kuondoa marupurupu au kuzuia hoja, kwa hiyo usanidi unaoweza kuandikwa ni mgombea wa ukaguzi badala ya uthibitisho wa utekelezaji wa msimbo. Kagua usanifishaji wa njia, symlink na uchanganuzi wa maelekezo kabla ya kufikia hitimisho.

### nginx inayoendeshwa kupitia sudo yenye usanidi unaodhibitiwa na mpigaji simu

Kanuni ya `nginx` isiyo na vizuizi inayoweza kuwa root inaweza kuruhusu [`-c` kuchagua usanidi mwingine](https://nginx.org/en/docs/switches.html). Kagua hoja na makatazo halisi ya sudo, kama mpigaji simu anaweza kutoa usanidi, na kama master au workers zinazotokana huhifadhi ufikiaji wa njia zilizolindwa. `root` iliyochaguliwa pamoja na `autoindex` inaweza kufichua faili kupitia listener mpya; [`dav_methods PUT`](https://nginx.org/en/docs/http/ngx_http_dav_module.html) inaweza kutoa njia ya uandishi wa faili yenye marupurupu, lakini moduli ya DAV haijengwi kwa chaguomsingi na uwepo wake, ufikikaji wa listener, ruhusa za faili na tabia ya faili za muda lazima vikaguliwe. Maelekezo ya [`error_log`](https://nginx.org/en/docs/ngx_core_module.html#error_log) yanaweza pia kulenga faili iliyochaguliwa; kuandika log kwenye faili nyeti ya usanidi, kama `/etc/ld.so.preload`, kunahitaji mwandishi mwenye marupurupu halisi na rekodi ya log inayodhibitika kabla haijawa njia ya privilege escalation. Kuangaziwa kwa executable katika `sudo -l` ni kidokezo cha ukaguzi, si uthibitisho kuwa njia yoyote kati ya hizi inafanya kazi. Ukusanyaji wa taarifa usiotekeleza amri haupaswi kuanzisha au kusanidi upya nginx.

### Ulinganishaji wa pattern katika prompts zenye marupurupu za Bash

Script ya Bash iliyoruhusiwa na sudo inaposoma thamani kutoka kwa mpigaji simu na kuikagua kwa `[[ "$expected" == $entered ]]`, Bash hutafsiri operand ya kulia isiyonukuliwa kama pattern. Kwa hiyo wildcard inaweza kutimiza ulinganisho bila kujua thamani inayotarajiwa. Kuweka operand kwenye nukuu (`[[ "$expected" == "$entered" ]]`) hufanya ulinganisho wa mfuatano halisi. Kagua kanuni halisi ya sudo, kama prompt inaweza kufikiwa na kitendo ambacho script hufanya baada ya ulinganisho; sintaksia pekee haithibitishi njia inayoweza kunyonywa. Epuka kuchapisha thamani inayotarajiwa wakati wa ukusanyaji wa taarifa. Tazama [marejeo ya miundo ya masharti ya Bash](https://www.gnu.org/software/bash/manual/html_node/Conditional-Constructs.html).

### Helper zinazoendeshwa kupitia sudo zinazopakua na kuendesha faili

Ruhusa isiyo na vizuizi ya sudo inayoweza kuwa root kwa helper maalum inahitaji ukaguzi wa mtiririko wa data ikiwa inakubali URL iliyochaguliwa na mpigaji simu, inaandika jibu kwenye diski, kisha baadaye inaita faili hiyo kwa interpreter au shell. [Sudoers huruhusu hoja zozote amri inapoorodheshwa bila hoja](https://man7.org/linux/man-pages/man5/sudoers.5.html); njia ya executable isiyobadilika haizuii kile ambacho hoja zake zinaweza kuchagua. Thibitisha uthibitishaji halisi wa URL, njia ya matokeo, tawi la mafanikio, na utekelezaji unaofuata katika helper iliyosakinishwa. Import ya libcurl inayolingana au mfuatano unaochapishika pekee hauthibitishi mlolongo huu.

Hata jina lisilobadilika la faili ya matokeo linaweza kubadilishwa kati ya uandishi na utekelezaji helper inapotumia **relative path katika working directory inayodhibitiwa na mpigaji simu**. Kubadilisha jina au kuweka faili nyingine badala ya faili linalomilikiwa na root hutegemea ufikiaji wa kuandika/kutafuta wa saraka na vizuizi vyovyote vya sticky bit, si mode ya faili pekee; tazama [`rename(2)`](https://man7.org/linux/man-pages/man2/rename.2.html). Kagua kama helper baadaye hufungua njia tena au kutumia descriptor iliyokuwa tayari imefunguliwa, na kama inahamia kwenye saraka inayoaminika kabla ya kuandika. Kagua sera ya sudo, helper na metadata ya saraka bila kutekeleza amri; usiendeshe upakuaji wenye marupurupu au race wakati wa ukusanyaji wa taarifa.

Helper ya upakuaji ya root-sudo pia inaweza kufichua udungaji wa **hoja** inapojenga mfuatano wa amri ya Bash kama `curl <caller input> -o <fixed output>`. Kichujio kinachokataa nafasi tupu bado huacha [upanuzaji wa mabano wa Bash](https://www.gnu.org/software/bash/manual/html_node/Brace-Expansion.html): vipengele vilivyotenganishwa kwa koma visivyonukuliwa vinaweza kuwa hoja tofauti za curl. Ikiwa ingizo linafika curl kabla ya `-o` isiyobadilika, chaguo la matokeo linalotolewa na mpigaji simu linaweza kuchagua lengwa la URL ya kwanza chini ya utambulisho wa helper; [curl huhusisha chaguo za matokeo na URL kwa mpangilio](https://curl.se/docs/manpage.html#-o). Thibitisha shell halisi, uwekaji wa nukuu, uthibitishaji wa ingizo, kanuni halisi ya sudo, mpangilio wa hoja za curl na scheme za URL zinazoungwa mkono, na kama mpigaji simu anadhibiti byte zinazochukuliwa au anaweza kusoma matokeo. Executable iliyofungashwa kwa PyInstaller inaweza kuwa na mantiki ya programu ya Python, lakini alama ya ufungashaji au mfuatano wa `curl` pekee hauthibitishi mtiririko huu wa data. Kagua nakala ya nje ya mtandao yenye mipaka ikiwa umeidhinishwa; ukusanyaji wa kawaida wa taarifa haupaswi kuendesha helper au kuchukua data iliyochaguliwa na mshambuliaji.

Script ya shell ya root-sudo inayoita [`mktemp -u` / `--dry-run`](https://www.gnu.org/software/coreutils/manual/html_node/mktemp-invocation.html) huchagua jina lisilotumika tu; **haiundi faili**. Ikiwa script baadaye inaunda jina hilo katika saraka ambayo mtumiaji mwingine anaweza kuathiri, kisha inalifungua tena na kuambatanisha yaliyomo kwenye lengwa lililolindwa kama `authorized_keys` ya root, kagua uwezekano wa race ya faili ya muda. Thibitisha kanuni halisi ya sudo, umiliki wa saraka na faili, mfuatano wa uundaji na ufunguaji tena, kinga za kernel, na kama uandishi wenye marupurupu kwa kweli hutumia byte zinazodhibitiwa na mshambuliaji. Mfuatano wa `mktemp -u` au `/tmp` inayoweza kuandikwa pekee hauthibitishi race. Kagua script na metadata ya njia bila kuiendesha au kufanya race ya faili yake ya muda wakati wa ukusanyaji wa taarifa.

- Epuka kutoa ruhusa ya interpreters au editors shirikishi kupitia sudo.<sup>[[1]](#references)</sup>

- Pendelea wrapper zisizobadilika zinazomilikiwa na root na zinazotekeleza kitendo kimoja chembamba cha usimamizi.<sup>[[1]](#references)[[2]](#references)</sup>
- Ikiwa interpreter haiwezi kuepukwa, zuia njia halisi ya script na uzuie hoja zinazodhibitiwa na mtumiaji, imports zinazoweza kuandikwa, `PYTHONPATH` na uhifadhi usio salama wa mazingira.<sup>[[2]](#references)[[3]](#references)[[4]](#references)</sup>
- Ikiwa kuhariri faili kunahitajika, zuia njia halisi ya faili na uzingatie `sudoedit` pamoja na matoleo ya sudo yaliyorekebishwa na ushughulikiaji mkali wa mazingira.<sup>[[1]](#references)[[2]](#references)</sup>
- Kagua `SETENV`, `env_keep`, working directories zinazoweza kuandikwa, njia za moduli/import zinazoweza kuandikwa, `NOEXEC`, `use_pty` na logging, lakini usizichukulie kama sandbox kamili.<sup>[[1]](#references)[[2]](#references)[[3]](#references)</sup>
