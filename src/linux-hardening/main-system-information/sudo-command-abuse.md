## Διερμηνευτές που επιτρέπονται μέσω Sudo

Αν το `sudo -l` επιτρέπει σε έναν χρήστη να εκτελέσει έναν διερμηνευτή ως root, αντιμετωπίστε το ως άμεση εκτέλεση code. Οι διερμηνευτές έχουν σχεδιαστεί για να εκτελούν αυθαίρετο code, επομένως ένας κανόνας που επιτρέπει τα `python3`, `perl`, `ruby`, `lua`, `node` ή παρόμοια binaries είναι συνήθως ισοδύναμος με εκτέλεση εντολών ως root, εκτός αν τα ορίσματα είναι αυστηρά περιορισμένα και επικυρωμένα.<sup>[[1]](#references)[[2]](#references)[[3]](#references)[[4]](#references)[[5]](#references)[[7]](#references)[[9]](#references)[[11]](#references)</sup>

Συνηθισμένη διαδικασία ελέγχου: πρώτα καταγράψτε τα δικαιώματα του χρήστη και, στη συνέχεια, εκτελέστε μια δήλωση Python με την επιλογή `-c` του διερμηνευτή.<sup>[[1]](#references)[[3]](#references)[[4]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/python3 -c 'import os; os.system("id")'
sudo /usr/bin/python3 -c 'import os; os.system("/bin/sh")'
```

Παρακάτω παρουσιάζονται και άλλα παραδείγματα διερμηνευτών· οι αναφερόμενοι διερμηνευτές τεκμηριώνουν την εκτέλεση inline κώδικα ή API για θυγατρικές διεργασίες.<sup>[[5]](#references)[[6]](#references)[[7]](#references)[[8]](#references)[[9]](#references)[[10]](#references)[[11]](#references)</sup>

```bash
sudo /usr/bin/perl -e 'exec "/bin/sh";'
sudo /usr/bin/ruby -e 'exec "/bin/sh"'
sudo /usr/bin/node -e 'require("child_process").spawn("/bin/sh", {stdio: [0,1,2]})'
```

Η ακριβής διαδρομή έχει σημασία. Αν ο κανόνας sudo επιτρέπει το `/usr/bin/python3`, χρησιμοποιήστε αυτήν ακριβώς τη διαδρομή κατά την επικύρωση.<sup>[[2]](#references)</sup>

Ένα glob εκτελέσιμου sudo, όπως το `/usr/bin/python*`, μπορεί επίσης να επιτρέπει την Python 2 για ένα script γραμμένο για Python 3. Αν το script φτάνει σε `input()` με κείμενο που ελέγχει ο καλών, [η Python 2 αξιολογεί αυτό το κείμενο ως έκφραση](https://docs.python.org/2/library/functions.html#input)· η ρητή κλήση του interpreter παρακάμπτει το shebang του script. Επαληθεύστε τα εγκατεστημένα δυαδικά αρχεία που ταιριάζουν, την αποτελεσματική ταυτότητα RunAs και την πολιτική ορισμάτων, τις αρνήσεις και το αν είναι προσβάσιμο το σημείο εισόδου, πριν θεωρήσετε ότι αυτή είναι διαδρομή εκτέλεσης.

Μια σταθερή διαδρομή script σε κανόνα sudo με δυνατότητα root δεν περιορίζει τι εκτελεί το script. Για ένα αναγνώσιμο Bash wrapper, ελέγξτε αν η πρώτη εκτελέσιμη εντολή χρησιμοποιεί μια μη περικλεισμένη σε εισαγωγικά positional παράμετρο, όπως το `$1`, ως **λέξη εντολής**, ενώ το sudo επιτρέπει ορίσματα που επιλέγει ο καλών. Επιβεβαιώστε την αποτελεσματική ταυτότητα RunAs, την πολιτική κωδικού πρόσβασης και ορισμάτων, τις μεταγενέστερες αρνήσεις και τον κλάδο του script που πράγματι εκτελείται· το `NOEXEC`, μια σταθερή λίστα ασφαλών ορισμάτων ή ένα wrapper που επικυρώνει την εντολή μπορεί να αλλάξουν το αποτέλεσμα. Επιθεωρήστε στατικά το σύντομο script κατά την απαρίθμηση αντί να το καλέσετε με μια δοκιμαστική εντολή.

Ένας απεριόριστος κανόνας sudo για το `dotnet` με δυνατότητα root αξίζει επίσης έλεγχο ως interpreter. Αν είναι εγκατεστημένο το .NET SDK, το [`dotnet fsi` εκτελεί κώδικα F# διαδραστικά ή από script](https://learn.microsoft.com/en-us/dotnet/fsharp/tools/fsharp-interactive/), ενώ το [`dotnet run` εκτελεί ένα project από τον πηγαίο κώδικα](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-run). Επιβεβαιώστε πρώτα την αποτελεσματική ταυτότητα RunAs και την ακριβή πολιτική ορισμάτων: ένας κανόνας που περιορίζεται σε συγκεκριμένη ασφαλή υποεντολή ή έμπιστη εφαρμογή αποτελεί διαφορετική παραχώρηση, ενώ μια εγκατάσταση μόνο για runtime ενδέχεται να μην περιλαμβάνει εντολές SDK. Το όνομα του εκτελέσιμου είναι λόγος για έλεγχο, όχι απόδειξη εκτέλεσης κώδικα.

```bash
sudo /usr/bin/python3 -c 'import os; os.setuid(0); os.setgid(0); os.system("/bin/sh")'
```

## `tee` που επιτρέπεται από το sudo: αυθαίρετη εγγραφή αρχείων με προνόμια

Το GNU `tee` αντιγράφει την τυπική είσοδο σε κάθε διαδρομή που παρέχεται ως τελεστέος αρχείου. Επομένως, ένας κανόνας sudo που επιτρέπει την εκτέλεση του `/usr/bin/tee` ως root με ορίσματα που ελέγχει ο καλών παρέχει τη δυνατότητα αυθαίρετης δημιουργίας ή αντικατάστασης αρχείων ως root. Η προσθήκη του `-a` αλλάζει τη δυνατότητα σε προσθήκη στο τέλος του αρχείου. Η ετικέτα `PASSWD:` αφορά τον έλεγχο ταυτότητας του sudo· από μόνη της, δεν περιορίζει τον προορισμό ή τα bytes που διαβάζονται από την τυπική είσοδο.<sup>[[2]](#references)[[27]](#references)[[28]](#references)</sup>

Αρχικά, ελέγξτε τον ακριβή κανόνα. Σε εξουσιοδοτημένο δοκιμαστικό σύστημα, επικυρώστε τη δυνατότητα μόνο με έναν προσωρινό προορισμό που είναι ασφαλές να δημιουργηθεί. Το τελικό `>/dev/null` καταστέλλει μόνο το αντίγραφο του `tee` προς την τυπική έξοδο.<sup>[[28]](#references)</sup>

```bash
sudo -l
printf '%s\n' 'controlled-write' | sudo /usr/bin/tee /root/tee-proof >/dev/null
printf '%s\n' 'appended-line' | sudo /usr/bin/tee -a /root/tee-proof >/dev/null
```

Το να βάλεις το `sudo` πριν από τον παραγωγό δεν δίνει αυξημένα δικαιώματα σε μια μεταγενέστερη ανακατεύθυνση κελύφους, επειδή το κέλυφος του καλούντος ανοίγει τον προορισμό. Η διεργασία με αυξημένα δικαιώματα πρέπει να είναι αυτή που γράφει, όπως στο παραπάνω pipeline.<sup>[[1]](#references)[[15]](#references)</sup>

Αφού επιβεβαιώσεις ότι η εγγραφή λειτουργεί, επίλεξε έναν κατάλληλο στόχο για εκτέλεση κώδικα ως root από το [Arbitrary File Write to Root](../interesting-files-permissions/write-to-root.md). Μια αλυσίδα που παρατηρήθηκε χρησιμοποίησε `tee` ως root για να δημιουργήσει ένα βραχύβιο αρχείο στο `/etc/cron.d/`, να εκκινήσει ένα backdoor μέσω ενός script ελεγχόμενου από τον χρήστη και να διαγράψει το αρχείο cron μετά την εκτέλεση. Η διαγραφή του αρχείου cron απέτρεψε τη δημιουργία μιας μακροχρόνιας εγγραφής persistence, αν και τα system logs διατήρησαν ακόμη στοιχεία της δραστηριότητας.<sup>[[27]](#references)</sup>

## Επεξεργαστές που επιτρέπονται μέσω sudo

Αν το `sudo -l` επιτρέπει σε έναν χρήστη να εκτελεί έναν διαδραστικό editor ως root, αντιμετώπισέ το ως επιφάνεια εκτέλεσης εντολών και όχι ως ακίνδυνη άδεια επεξεργασίας αρχείων. Οι editors συχνά μπορούν να εκτελούν εντολές κελύφους, να διαβάζουν αυθαίρετα αρχεία, να γράφουν αυθαίρετα αρχεία ή να καλούν εξωτερικά βοηθητικά εργαλεία από μέσα από τον editor.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

Συνήθης διαδικασία ελέγχου: εμφάνισε τα δικαιώματα του χρήστη και, στη συνέχεια, εκτέλεσε κάθε επιτρεπόμενο editor ή pager μέσω sudo.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/nano /etc/hosts
sudo /usr/bin/vim /etc/hosts
sudo /usr/bin/less /etc/hosts
```

### Εκτέλεση εντολών με το nano

Όταν επιτρέπεται το nano μέσω sudo, ενδέχεται να είναι δυνατή η εκτέλεση εντολών από τη διεπαφή του editor.<sup>[[12]](#references)</sup>

```text
Ctrl+R
Ctrl+X
```

Στη συνέχεια, δώστε μια εντολή όπως `id` ή `/bin/sh` στη γραμμή εντολών του nano.<sup>[[12]](#references)</sup>

```bash
id
/bin/sh
```

Αν ένα διαδραστικό shell δεν διαθέτει χρησιμοποιήσιμες ροές τερματικού, αυτή η μορφή ανακατεύθυνσης αντιστοιχίζει την τυπική έξοδο και το σφάλμα του στον περιγραφέα 0.<sup>[[15]](#references)</sup>

```bash
reset; /bin/sh 1>&0 2>&0
```

Η ακριβής ακολουθία πλήκτρων μπορεί να διαφέρει ανάλογα με την έκδοση του nano και τις επιλογές κατά τη δημιουργία του build, αλλά το ζήτημα ασφάλειας παραμένει το ίδιο: ο editor εκτελείται ως root και μπορεί να εκτελέσει εξωτερικές εντολές.<sup>[[1]](#references)[[12]](#references)</sup>

### Άλλοι συνηθισμένοι τρόποι διαφυγής από editor

Οι editor τύπου Vim συνήθως παρέχουν δυνατότητα εκτέλεσης εντολών μέσω του `:!`.<sup>[[13]](#references)</sup>

```text
:!/bin/sh
```

Οι pagers όπως το `less` μπορούν επίσης να εκθέσουν δυνατότητα εκτέλεσης shell.<sup>[[14]](#references)</sup>

Ένας κανόνας sudo που επιτρέπει την εκτέλεση του `apport-cli` ως root αξίζει τον ίδιο έλεγχο για pager. Σε επηρεαζόμενες εκδόσεις του Apport, μπορούσε να ανοίξει μια αναφορά crash στο `less` με μέγεθος τερματικού που μπορούσε να ορίσει ο attacker· υπό τις κατάλληλες ειδικές συνθήκες για το sudo και το pager, το pager μπορούσε τότε να δώσει πρόσβαση σε root shell. Ελέγξτε τον ενεργό κανόνα sudo, τις ρυθμίσεις του pager και τη διόρθωση στο πακέτο της διανομής πριν θεωρήσετε ότι η έκδοση και μόνο είναι ευάλωτη. Κατά την παθητική απαρίθμηση, διαβάστε τα μεταδεδομένα του πακέτου και της πολιτικής χωρίς να προκαλέσετε crash ή να ανοίξετε την προνομιούχα αναφορά. Το [αρχείο CVE του Ubuntu](https://ubuntu.com/security/CVE-2023-1326) παραθέτει τις διορθωμένες εκδόσεις πακέτων ανά έκδοση, συμπεριλαμβανομένων των backported διορθώσεων.

```text
!/bin/sh
```

## Άλλοι κίνδυνοι από κανόνες sudo και doas

Ξεκινήστε με `sudo -l`, `sudo -V` και τυχόν σχετική πολιτική `doas`. Εξετάστε μαζί την επιτρεπόμενη εντολή, τον χρήστη RunAs, τα ορίσματα, το περιβάλλον και τις προεπιλογές. Η άδεια εκτέλεσης ως μη-root λογαριασμός υπηρεσίας μπορεί και πάλι να εκθέσει τα αρχεία αυτού του λογαριασμού ή να προσφέρει διαδρομή προς root.

Ένα σταθερό Python script που επιτρέπεται από το sudo μπορεί και πάλι να εκτελέσει εντολή κελύφους με την ταυτότητα RunAs του, αν συνενώνει διαδραστική είσοδο ελεγχόμενη από τον καλούντα στο [`os.system()`](https://docs.python.org/3/library/os.html#os.system). Μια denylist σημείων στίξης κελύφους δεν αρκεί για να αποδειχθεί η ασφάλεια: το [κέλυφος αναγνωρίζει επίσης την υποκατάσταση εντολών `$(...)`](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html). Επιβεβαιώστε ότι τα επιτρεπόμενα ορίσματα φτάνουν στον κλάδο εισόδου, ότι η είσοδος καταλήγει στην εντολή κελύφους χωρίς ασφαλή επικύρωση και ότι η ενεργή πολιτική sudo επιτρέπει τον επιθυμητό χρήστη RunAs. Η διαδρομή του script ή μια κλήση στο `os.system()` από μόνη της είναι απλώς ένδειξη προς διερεύνηση· εξετάστε τον πηγαίο κώδικα χωρίς να εκτελέσετε το προνομιούχο script.

Μια ενεργή παραχώρηση sudo για root στο `chattr` μπορεί να αφαιρέσει το αμετάβλητο (`i`) γνώρισμα αρχείου, αλλά αυτό από μόνο του δεν παρέχει δικαίωμα εγγραφής ή νέα ταυτότητα. Το [εγχειρίδιο του `chattr`](https://man7.org/linux/man-pages/man1/chattr.1.html) αναφέρει ότι το γνώρισμα εμποδίζει τις τροποποιήσεις και ότι μόνο ο root ή μια διεργασία με `CAP_LINUX_IMMUTABLE` μπορεί να το αλλάξει. Ελέγξτε την ακριβή πολιτική ορισμάτων sudo και την υποστήριξη του συστήματος αρχείων· έπειτα επαληθεύστε χωριστά ότι ο καλών μπορεί να γράψει στο αρχείο μετά την εκκαθάριση του γνωρίσματος και ότι κάποιος καταναλωτής με υψηλότερη ταυτότητα το χρησιμοποιεί. Για παράδειγμα, η αντικατάσταση ενός κελύφους σύνδεσης απαιτεί επίσης τα αποδεκτά διαπιστευτήρια του λογαριασμού-στόχου και πραγματική σύνδεση μέσω αυτού του κελύφους. Εξετάστε την πολιτική, τα γνωρίσματα αρχείων και τα δικαιώματα χωρίς να τα αλλάξετε κατά την απαρίθμηση.

Αν το sudo ζητά τόσο κωδικό πρόσβασης όσο και κωδικό μίας χρήσης, κρατήστε αυτές τις προϋποθέσεις ξεχωριστές από την παραχώρηση της εντολής. Ένα αναγνώσιμο αρχείο `.google_authenticator` περιέχει ευαίσθητο υλικό seed, ενώ ένα παλιό hash κωδικού πρόσβασης εφαρμογής ή βάσης δεδομένων είναι μόνο υποψήφιος κωδικός πρόσβασης του τρέχοντος λογαριασμού· κανένα από τα δύο δεν αποδεικνύει ότι ο άλλος παράγοντας γίνεται αποδεκτός από την ενεργή διαμόρφωση PAM. Μόλις λάβετε εξουσιοδότηση, εξετάστε τα ακριβή RunAs και ορίσματα: μια απεριόριστη παραχώρηση root για το `gem` του RubyGems μπορεί να εκθέσει την εντολή επεξεργαστή του ([GTFOBins](https://gtfobins.github.io/gtfobins/gem/)), αλλά μια περιορισμένη παραχώρηση ή αποτυχημένη αυθεντικοποίηση δεν το επιτρέπει. Η παθητική απαρίθμηση πρέπει να αναφέρει διαδρομές και πολιτική χωρίς να εμφανίζει το seed, να ανακτά κωδικό πρόσβασης, να παράγει κωδικό ή να εκτελεί την προνομιούχο εντολή.

Μια απεριόριστη παραχώρηση sudo για το `knife` του Chef με δυνατότητα root απαιτεί εξέταση σε επίπεδο διερμηνευτή: [το Chef τεκμηριώνει ότι το `knife exec -E` αξιολογεί τοπικά μια συμβολοσειρά Ruby](https://docs.chef.io/workstation/26/tools/knife/knife_exec/). Επαληθεύστε ότι ο ενεργός κανόνας sudo επιτρέπει την υποεντολή `exec` και το όρισμα `-E` που παρέχει ο καλών, την επιθυμητή ταυτότητα RunAs και τυχόν αντίστοιχες απαγορεύσεις εντολών ή σταθερά ορίσματα. Το εγκατεστημένο δυαδικό αρχείο ή ένας κανόνας περιορισμένος σε άλλες υποεντολές είναι απλώς ένδειξη. Η παθητική απαρίθμηση πρέπει να αναφέρει τον κανόνα χωρίς να εκτελεί το `knife`.

Μια ακριβής παραχώρηση sudo για διαδραστικό `msfconsole` με δυνατότητα root είναι εξίσου ευαίσθητη: το [GTFOBins τεκμηριώνει την κονσόλα `irb`](https://gtfobins.org/gtfobins/msfconsole/), η οποία μπορεί να κληρονομήσει την ταυτότητα sudo. Επιβεβαιώστε τον ενεργό χρήστη RunAs, την επιτρεπόμενη λίστα ορισμάτων, τις απαγορεύσεις εντολών, το `NOEXEC` ή άλλους περιορισμούς, τη συμπεριφορά της εγκατεστημένης κονσόλας και αν ο καλών μπορεί να δώσει διαδραστική είσοδο. Μια απλή επισήμανση διαδρομής είναι μόνο ένδειξη προς διερεύνηση· η παθητική απαρίθμηση δεν πρέπει να εκκινήσει την κονσόλα.

Στο FreeBSD, ακόμη και ένας κανόνας sudo περιορισμένος στα `pkg update` και `pkg install *` ως root απαιτεί έλεγχο εμπιστοσύνης των αποθετηρίων. Ελέγξτε αν ο καλών μπορεί να γράψει στο `/etc/hosts` και αν η *ενεργή* διαμόρφωση αποθετηρίων χρησιμοποιεί HTTP hostname με `signature_type: none`. Το [εγχειρίδιο `pkg.conf` του FreeBSD](https://man.freebsd.org/cgi/man.cgi?query=pkg.conf&sektion=5) αναφέρει ότι το `none` απενεργοποιεί τους ελέγχους υπογραφής· το `pkg+http` από μόνο του δεν αρκεί για να συναχθεί αυτό. Ένα πακέτο μπορεί να περιέχει scripts εγκατάστασης ([Εγχειρίδιο FreeBSD Porter's](https://docs.freebsd.org/en/books/porters-handbook/pkg-files/)), επομένως ένας καλών που ελέγχει πραγματικά το endpoint του αποθετηρίου και μπορεί να επιλέξει πακέτο ενδέχεται να διασχίσει το όριο root. Επαληθεύστε τις παρακάμψεις αποθετηρίων, την επίλυση SRV/mirror, τα ενεργά ορίσματα sudo, την επιλογή πακέτου και την εκτέλεση script πριν καταλήξετε σε αυτό το συμπέρασμα. Εξετάστε την πολιτική και μικρά τοπικά αρχεία διαμόρφωσης χωρίς ανακατεύθυνση ονομάτων ή εκτέλεση του `pkg` κατά την απαρίθμηση.

Μια παραχώρηση sudo με δυνατότητα root για τα `apt-get update` και `apt-get upgrade` απαιτεί επίσης έλεγχο εμπιστοσύνης αποθετηρίων όταν το sudo διατηρεί `http_proxy` ελεγχόμενο από τον καλούντα. Ελέγξτε αν η ενεργή διαμόρφωση APT χρησιμοποιεί πράγματι αυτή τη μεταβλητή proxy και ποια αιτήματα ενεργοποιημένων αποθετηρίων μπορεί να επηρεάσει· ένας proxy από μόνος του δεν μπορεί να αντικαταστήσει πακέτα από αρχείο που αυθεντικοποιείται με έμπιστο κλειδί υπογραφής. Το [εγχειρίδιο HTTP transport του APT](https://manpages.debian.org/experimental/apt/apt-transport-http.1.en.html) τεκμηριώνει την προτεραιότητα των proxy, ενώ το [apt-secure](https://manpages.debian.org/experimental/apt/apt-secure.8.en.html) τεκμηριώνει τους ελέγχους υπογραφών, τις παρακάμψεις μη ασφαλών αποθετηρίων και την επιβεβαίωση για μη αυθεντικοποιημένα πακέτα. Επιβεβαιώστε τα ακριβή RunAs και ορίσματα sudo, την πολιτική αυθεντικοποίησης αποθετηρίων, τυχόν απαιτούμενη διαδραστική αποδοχή και αν η επιλεγμένη αναβάθμιση εκτελεί scripts πακέτων ως root. Εξετάστε παθητικά την πολιτική και την τοπική διαμόρφωση· μην ανακατευθύνετε την κίνηση πακέτων και μην εκτελείτε αναβάθμιση κατά την απαρίθμηση.

Ένας κανόνας sudo με δυνατότητα root για το `snap install` μπορεί να δημιουργήσει όριο πακέτου-προς-κώδικα αν τα ορίσματα επιτρέπουν στον καλούντα να επιλέξει τοπικό snap και επιτρεπτό τρόπο εγκατάστασης. Το [Snap τεκμηριώνει](https://snapcraft.io/docs/explanation/snap-development/install-modes/) ότι το `--dangerous` παρακάμπτει τους ελέγχους assertion των τοπικών snap και ότι το `--devmode` χαλαρώνει την απομόνωση· [ένα install hook μπορεί να εκτελεστεί κατά την αρχική εγκατάσταση](https://snapcraft.io/docs/reference/development/supported-snap-hooks/). - Μια προνομιούχος παραχώρηση `restic backup` μπορεί επίσης να διασχίσει όριο ανάγνωσης αρχείων, αν το πρότυπο ορισμάτων sudo επιτρέπει στον καλούντα να επιλέξει τόσο την πηγή όσο και ένα repository που μπορεί αργότερα να διαβάσει και να αποκρυπτογραφήσει. Το [Restic μπορεί να κάνει backup σε τοπικά και απομακρυσμένα repositories](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html), αλλά ένα τοπικό repository μπορεί να περιέχει αντικείμενα root-only που μόλις γράφτηκαν· επιβεβαιώστε την ενεργή πολιτική sudo, την πρόσβαση στο backend, τον κωδικό πρόσβασης repository και τα δικαιώματα των αντικειμένων που προκύπτουν πριν το θεωρήσετε αποκάλυψη. Ένα κλειδί SSH από backup παρέχει πρόσβαση μόνο αν ο λογαριασμός προορισμού το αποδέχεται. Μην εκτελέσετε backup για να το δοκιμάσετε κατά την παθητική εξέταση.
- Μια απεριόριστη προσαρμοσμένη εντολή συντήρησης ή backup μπορεί να δέχεται διαδρομή εξόδου ή να προσφέρει δικό της προγραμματιστή εργασιών. Για διαδρομή εγγραφής αρχείου, επαληθεύστε τον ακριβή κανόνα sudo και τον χρήστη RunAs, έπειτα αν ο καλών ελέγχει τόσο τα δεδομένα όσο και τον προορισμό. Για διαδρομή προγραμματισμένης εντολής, επαληθεύστε την ταυτότητα εκτέλεσης του προγραμματιστή, την είσοδο εντολής και τυχόν πρόσθετη πύλη κωδικού πρόσβασης ή εξουσιοδότησης. Το όνομα εντολής ή το `NOPASSWD` από μόνο του δεν αποδεικνύει καμία από τις δύο διαδρομές. Δείτε την [εγγραφή σε αρχεία που ανήκουν στον root](../interesting-files-permissions/write-to-root.md) και τους [χρονοδιακόπτες cron και systemd](../processes-crontab-systemd-dbus/cron-and-systemd-timers.md).
- Μια σταθερή εντολή sudo μπορεί και πάλι να φορτώνει προβλέψιμο αρχείο διαμόρφωσης από κοινόχρηστο εγγράψιμο κατάλογο. Εξετάστε αν ο καλών μπορεί να αντικαταστήσει αυτό το αρχείο και αν τα πεδία πηγής και προορισμού ελέγχουν προνομιούχα ανάκτηση ή αντιγραφή. Ένα URL τοπικού αρχείου μπορεί να εκθέσει δεδομένα αναγνώσιμα μόνο από τον χρήστη RunAs του sudo· μια πηγή ελεγχόμενη από τον καλούντα σε συνδυασμό με προστατευμένο προορισμό μπορεί να δημιουργήσει διαδρομή εγγραφής. Επιβεβαιώστε τον χειρισμό URL από το εγκατεστημένο πρόγραμμα, τους ελέγχους διαδρομής προορισμού, τον ενεργό κανόνα sudo και την προσβασιμότητα της εξόδου. Μια εγγράψιμη διαδρομή διαμόρφωσης στο `/tmp` από μόνη της είναι ένδειξη προς διερεύνηση· εξετάστε το δυαδικό αρχείο και τα μεταδεδομένα αρχείων χωρίς να εκτελέσετε την προνομιούχο μεταφορά.
- Ένας κανόνας sudo για `git apply` μπορεί να κάνει τον λογαριασμό RunAs να γράψει αρχεία που επιλέγονται από patch ελεγχόμενο από τον καλούντα. Το [CVE-2023-23946](https://github.com/git/git/security/advisories/GHSA-r87m-v37r-cwfh) επέτρεπε σε κατασκευασμένο patch να δημιουργήσει symlink και έπειτα να γράψει έξω από το working tree, ακόμη κι όταν η εντολή δεν δεχόταν `--unsafe-paths`. Ελέγξτε τον ενεργό κανόνα ορισμάτων sudo, την πηγή του patch, την πρόσβαση του λογαριασμού RunAs στον τρέχοντα κατάλογο και τη διόρθωση της εγκατεστημένης έκδοσης Git ή backport του προμηθευτή. Ένας απεριόριστος κανόνας που επιτρέπει `--unsafe-paths` αποτελεί ξεχωριστό κίνδυνο ρητής επιλογής· ούτε η έκδοση Git ούτε η άδεια `git apply` από μόνες τους αποδεικνύουν ότι μπορεί να τροποποιηθεί προστατευμένο αρχείο. Μην εφαρμόζετε μη έμπιστο patch κατά την παθητική απαρίθμηση.
- Ένας κανόνας `clamscan --debug` με δυνατότητα root μπορεί να διασχίσει όριο ανάγνωσης, αν χρήστης χαμηλότερων προνομίων μπορεί να παράσχει εικόνα DMG και ο εγκατεστημένος parser επηρεάζεται από το [CVE-2023-20052](https://blog.clamav.net/2023/02/clamav-01038-01052-and-101-patch.html), το οποίο μπορούσε να αποκαλύψει περιεχόμενα αρχείων μέσω εξόδου debug. Επιβεβαιώστε τα ακριβή επιτρεπόμενα ορίσματα και τη διαδρομή σάρωσης, τον έλεγχο της εισόδου, τον ενεργό λογαριασμό RunAs, τη διόρθωση/backport του engine και αν ο καλών βλέπει την έξοδο. Αν ευρύτερος κανόνας επιτρέπει `--file-list`/`-f`, εξετάστε χωριστά τη συμπεριφορά αυτής της λίστας αρχείων· μια πολιτική σταθερή σε `--debug <scan-path>` δεν το επιτρέπει. Εξετάστε την πολιτική και τα μεταδεδομένα πακέτου χωρίς να σαρώσετε κατασκευασμένο αρχείο ή να εμφανίσετε προστατευμένη έξοδο κατά την απαρίθμηση.
- Ένας κανόνας sudo με δυνατότητα root που ανοίγει κρυπτογραφημένη εικόνα δίσκου επιλεγμένη από τον καλούντα και δεύτερος κανόνας που προσαρτά τον mapper που προκύπτει μπορεί να εισαγάγει αρχεία ελεγχόμενα από τον καλούντα στον χώρο ονομάτων mount του host. Επιβεβαιώστε και τους δύο ενεργούς κανόνες και τα ορίσματά τους, τον έλεγχο της εικόνας και του ονόματος mapper, τον πραγματικό στόχο mount και τον ιδιοκτήτη και τρόπο δικαιωμάτων των αρχείων που προκύπτουν. Η μετάβαση set-user-ID απαιτεί επιπλέον προσβάσιμο εκτελέσιμο, επιλογές mount που το επιτρέπουν (`nosuid` το εμποδίζει) και κατάλληλη πολιτική διεργασίας ή MAC· το άνοιγμα ή mount μιας εικόνας από μόνο του είναι απλώς ένδειξη προς διερεύνηση. Ξεχωριστή διαδρομή μέσω υπάρχοντος backup απαιτεί το πραγματικό κλειδί του και χρήσιμο αναγνώσιμο μυστικό μέσα σε αυτό. Εξετάστε την πολιτική και τις διαδρομές χωρίς να ανοίξετε ή να προσαρτήσετε εικόνα κατά την παθητική απαρίθμηση. Δείτε το [εγχειρίδιο cryptsetup](https://gitlab.com/cryptsetup/cryptsetup/-/blob/main/man/cryptsetup.8.adoc) και τις [επιλογές mount](https://man7.org/linux/man-pages/man8/mount.8.html).
- Ένας κανόνας sudo για shell ή Python script με δυνατότητα root απαιτεί εξέταση του working directory, αν το script καλεί `./helper` χωρίς πρώτα να μεταβεί σε σταθερό κατάλογο. Μια λίστα Python όπως `['./helper']` που περνά στο `subprocess.run` μπορεί να έχει την ίδια συμπεριφορά, επιλέγοντας τον τρέχοντα κατάλογο από τον καλούντα. Ο καλών ενδέχεται να επιλέξει εγγράψιμο κατάλογο και να τοποθετήσει εκεί εκτελέσιμο με αυτό το σχετικό όνομα· μια απόλυτη διαδρομή αλλού στο script δεν προστατεύει αυτή την κλήση. Επιβεβαιώστε τον ενεργό κανόνα, το `runchdir` ή άλλη πολιτική αλλαγής καταλόγου, τη ροή και την προσβασιμότητα του κλάδου του script, εγγράψιμο και εκτελέσιμο κατάλογο, καθώς και περιορισμούς mount/`NOEXEC` πριν το θεωρήσετε εκτέλεση κώδικα. Αν το script δεν είναι αναγνώσιμο, η συμπεριφορά παραμένει άγνωστη μέχρι να εξεταστεί ο πηγαίος κώδικας μέσω εξουσιοδοτημένης διαδρομής. Εξετάστε στατικά τα scripts αντί να εκτελέσετε τον helper. Το [εγχειρίδιο sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) τεκμηριώνει την πολιτική working directory.
- Ένας σταθερός validator Python με δυνατότητα root μπορεί και πάλι να αξιολογήσει αρχείο δεδομένων επιλεγμένο από τον καλούντα. Η [τεκμηρίωση της Python για το `eval()` προειδοποιεί κατά της μη έμπιστης εισόδου](https://docs.python.org/3/library/functions.html#eval): έλεγχος κατάληξης εισόδου, αριθμητικό πρόθεμα ή κλάδος επικύρωσης δεν είναι sandbox αν η υπόλοιπη έκφραση φτάνει στο `eval`. Επιβεβαιώστε τον ενεργό κανόνα sudo, αν ο καλών μπορεί να επιλέξει και να ελέγξει το ακριβές αρχείο, τις συνθήκες κλάδου του parser και τη σύνθεση της έκφρασης, καθώς και την ταυτότητα της προνομιούχου διεργασίας πριν το θεωρήσετε διαδρομή εκτέλεσης. Η παρουσία του `eval` σε αναγνώσιμο script από μόνη της είναι απλώς αφορμή για έλεγχο· εξετάστε τον πηγαίο κώδικα και τα δικαιώματα αρχείων χωρίς να εκτελέσετε τον validator ή να υποβάλετε δοκιμαστική έκφραση κατά την απαρίθμηση.
- Ένας Ruby wrapper με δυνατότητα root που διαβάζει σχετικό όνομα YAML, όπως `YAML.load(File.read("dependencies.yml"))`, μπορεί να διαβάσει είσοδο από τον τρέχοντα κατάλογο του καλούντος, εκτός αν ο wrapper ή η πολιτική sudo ορίζει αυτόν τον κατάλογο. Ελέγξτε τα ακριβή επιτρεπόμενα ορίσματα, τα δικαιώματα καταλόγου και αρχείου, καθώς και τη συμπεριφορά της εγκατεστημένης έκδοσης Psych: παλαιότερες υλοποιήσεις του `YAML.load` μπορούσαν να αποσειριοποιούν αυθαίρετα αντικείμενα Ruby, ενώ νεότερες εκδόσεις περιορίζουν τις κλάσεις από προεπιλογή. Μια στατική θέση κλήσης είναι απλώς ένδειξη προς διερεύνηση· επιβεβαιώστε ότι το αρχείο προέρχεται πράγματι από κατάλογο εγγράψιμο από τον καλούντα και ότι ο εγκατεστημένος loader δέχεται επικίνδυνες κλάσεις. Προτιμήστε `safe_load` με ρητή, ελάχιστη allowlist κλάσεων για μη έμπιστη είσοδο. Δείτε την [τεκμηρίωση Ruby 3.0 Psych](https://docs.ruby-lang.org/en/3.0/Psych.html) και την [τεκμηρίωση Ruby 3.1 Psych](https://ruby-doc.org/core-3.1.2/Psych.html).

- Μια ακριβής παραχώρηση `sudo go run /absolute/file.go` με δυνατότητα root απαιτεί έλεγχο working directory όταν ο πηγαίος κώδικας Go διαβάζει σχετικό αρχείο WASM και ενδέχεται να εκτελέσει σχετικό shell script αφού εξετάσει το αποτέλεσμά του. Επιβεβαιώστε τον ενεργό RunAs, τα ορίσματα και τις απαγορεύσεις εντολών, έναν τρέχοντα κατάλογο εγγράψιμο από τον καλούντα, τη ροή δεδομένων WASM προς τον κλάδο και αν ο κλάδος καλεί τον helper. Ένα σταθερό sudo `runchdir`, `os.Chdir` ή [`exec.Cmd.Dir`](https://pkg.go.dev/os/exec) μπορεί να αλλάξει τη θέση αναζήτησης. Η στατική συνύπαρξη στοιχείων είναι απλώς υποψήφια ένδειξη· εξετάστε τον πηγαίο κώδικα χωρίς να εκτελέσετε Go, WASM ή τον helper.
- Το `sudoedit` και τα wildcard ορισμάτων απαιτούν ελέγχους ακριβούς έκδοσης και κανόνα· η [λίστα ελέγχου](linux-privilege-escalation-checklist.md) περιλαμβάνει το ζήτημα επεξεργασίας αρχείων μέσω sudoedit. Για διασταυρούμενη παραχώρηση `sudoedit` σε wildcard διαδρομή, εξετάστε την ενεργή ρύθμιση `sudoedit_follow` ή `FOLLOW`, το `sudoedit_checkdir`, τον επιλυμένο στόχο και ποιος μπορεί να αντικαταστήσει κάθε γονική καταχώριση. Η πρώτη μπορεί να επιτρέψει την ακολούθηση symlink, ενώ η απενεργοποίηση της δεύτερης αφαιρεί ελέγχους εγγράψιμων καταλόγων· καμία ρύθμιση από μόνη της δεν αποδεικνύει εγγραφή σε αρχείο άλλου χρήστη. Επιβεβαιώστε την εγκατεστημένη πολιτική sudo και τα ακριβή ορίσματα που αντιστοιχίζονται πριν καταλήξετε σε συμπέρασμα. Δείτε τους [ορισμούς επιλογών sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf).
- Σε κανόνα εντολής sudoers, ένα wildcard ορισμάτων μπορεί να αντιστοιχίσει κενά καθώς και χαρακτήρες διαδρομής. Ένας κανόνας για εντολή με δυνατότητα ανάγνωσης και όρισμα όπως `/restricted/*` μπορεί επομένως να επιτρέπει επιπλέον όρισμα αρχείου μετά από αντίστοιχο πρόθεμα. Εξετάστε τον ακριβή χρήστη RunAs, τη διαδρομή εντολής, το πρότυπο ορισμάτων και μεταγενέστερες απαγορεύσεις· η αποδεδειγμένη ανάγνωση αρχείου δεν συνεπάγεται εκτέλεση εντολών. Το [εγχειρίδιο sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) διακρίνει τα glob ορισμάτων από τα glob διαδρομών εντολών.
- Ένα glob ορίσματος που μοιάζει με διαδρομή μπορεί επίσης να αντιστοιχίσει `../`. Για παράδειγμα, ένας κανόνας `node /opt/scripts/*.js` με δυνατότητα root μπορεί να επιτρέψει αρχείο JavaScript ελεγχόμενο από τον καλούντα έξω από το `/opt/scripts`, αν το παρεχόμενο όνομα διαδρομής εξακολουθεί να αρχίζει με `/opt/scripts/` και επιλύεται μέσω τμημάτων γονικού καταλόγου. Πρόκειται για glob **ορίσματος**· το glob της διαδρομής εκτελέσιμου για το Node έχει διαφορετικούς κανόνες αντιστοίχισης καθέτων. Ελέγξτε τον ενεργό κανόνα, τις μεταγενέστερες απαγορεύσεις, την επίλυση ονόματος διαδρομής, τον έλεγχο του αρχείου-στόχου και τυχόν περιορισμούς regular expression ή digest του sudoers πριν καταλήξετε σε εκτέλεση κώδικα. Δείτε τους [κανόνες wildcard του sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) και την [τεκμηρίωση γραμμής εντολών του Node](https://nodejs.org/api/cli.html).
- Τα προγράμματα αρχειοθέτησης και άλλα βοηθητικά προγράμματα μπορεί να έχουν hooks εκτέλεσης. Ελέγξτε τα ακριβή επιτρεπόμενα ορίσματα στο [GTFOBins](https://gtfobins.github.io/) αντί να υποθέτετε ότι μόνο κελύφη ή διερμηνευτές εκτελούν εντολές.
- Ένας απεριόριστος κανόνας `qpdf` με δυνατότητα root μπορεί να εκθέσει προνομιούχο αρχείο μέσω συνημμένων PDF: οι εκδόσεις qpdf 10.2 και μεταγενέστερες υποστηρίζουν `--empty` και `--add-attachment file ... --` με PDF εξόδου. Αν η προνομιούχος διεργασία μπορεί να διαβάσει την επιλεγμένη πηγή και να γράψει το PDF σε διαδρομή προσβάσιμη από τον καλούντα, η έξοδος μπορεί να μεταφέρει τα bytes της πηγής. Εξετάστε τα ενεργά ορίσματα και τις εξαιρέσεις sudo, την έκδοση qpdf, την πρόσβαση στην πηγή και τη διαδρομή εξόδου πριν συμπεράνετε ότι είναι δυνατή η αποκάλυψη αρχείου. Η ανάγνωση κλειδιού SSH του root είναι χρήσιμη για σύνδεση μόνο όταν το κλειδί είναι έγκυρο και επιτρέπεται αυθεντικοποίηση root μέσω SSH. Δείτε τις [επιλογές συνημμένων qpdf](https://qpdf.readthedocs.io/en/stable/cli.html#embedded-files-attachments).
- Η επαναχρησιμοποίηση timestamp sudo εξαρτάται από την πολιτική cache, τον ιδιοκτήτη, το terminal/session και τα δικαιώματα. Ο [οδηγός κλιμάκωσης προνομίων](../linux-basics/linux-privilege-escalation/README.md#reusing-sudo-tokens) καλύπτει τους ελέγχους.
- Το `doas` έχει δικούς του κανόνες και διαμόρφωση. Ελέγξτε τις επιτρεπόμενες εντολές και τις εγγράψιμες διαδρομές διαμόρφωσης, όπως περιγράφεται στην [ενότητα doas](../linux-basics/linux-privilege-escalation/README.md#doas).

### Εργαλεία build και πακέτων που εκτελούνται μέσω sudo

Μια απεριόριστη παραχώρηση sudo για το `forge` του Foundry μπορεί να έχει σημασία ακόμη κι όταν η ταυτότητα RunAs είναι άλλος μη-root χρήστης. Επιλογές compiler όπως το `--use` μπορούν να επιλέξουν τοπικό εκτελέσιμο, ενώ το `forge flatten -o` επιλέγει αρχείο εξόδου. Ελέγξτε την εγκατεστημένη έκδοση Forge, τα ακριβή ορίσματα sudo, τα προσβάσιμα paths έργου και compiler, τα δικαιώματα εξόδου και το ενεργό περιβάλλον πριν θεωρήσετε την παραχώρηση εκμεταλλεύσιμη. Ένας σχετικός helper που εντοπίζεται μέσω `PATH` εξαρτάται από την έκδοση και το περιβάλλον· δεν πρέπει να θεωρείται δεδομένος σε κάθε build Forge.<sup>[[23]](#references)[[24]](#references)</sup>

Μια απεριόριστη παραχώρηση `pacman` με δυνατότητα root επιτρέπει περισσότερα από ερωτήματα πακέτων: το `-U` δέχεται τοπικό πακέτο, τα πακέτα μπορεί να περιέχουν scripts εγκατάστασης και το `--hookdir` επιλέγει άλλον κατάλογο hooks. Εξετάστε τον ενεργό κανόνα sudo, τους περιορισμούς και τις εξαιρέσεις ορισμάτων πριν από οποιαδήποτε δοκιμή· η παθητική απαρίθμηση δεν χρειάζεται εγκατάσταση πακέτου ή εκτέλεση hook.<sup>[[25]](#references)[[26]](#references)</sup>

Ένας σταθερός wrapper κελύφους μέσω sudo μπορεί επίσης να εγκαθιστά εξάρτηση npm με συγκεκριμένο όνομα και έπειτα να εκκινεί εφαρμογή Node. Εξετάστε τον ακριβή κανόνα RunAs, αν το πακέτο είναι ήδη εγκατεστημένο, τα ενεργά `HOME` και `userconfig` του npm, τη διαμόρφωση έργου ή τις παρακάμψεις γραμμής εντολών και αν χρήστης χαμηλότερων προνομίων ελέγχει το registry ή το πακέτο που επιστρέφεται για αυτό το όνομα. Το [npm τεκμηριώνει την αναζήτηση `.npmrc` ανά χρήστη και έργο](https://docs.npmjs.com/cli/v6/configuring-npm/npmrc/)· η συμπεριφορά του `HOME` στο sudo εξαρτάται από την εγκατεστημένη πολιτική και τη διανομή, επομένως ένα εγγράψιμο `.npmrc` χρήστη μπορεί να διαβαστεί ή να μη διαβαστεί από την προνομιούχο διεργασία npm. Αν η πρόσφατα εγκατεστημένη εξάρτηση εισαχθεί από την προνομιούχο εφαρμογή, ο κώδικας του module μπορεί να εκτελεστεί με την ταυτότητα αυτής της εφαρμογής. Τα scripts χρόνου εγκατάστασης είναι ξεχωριστή διαδρομή που εξαρτάται από την έκδοση και τη διαμόρφωση· το [npm τεκμηριώνει τον κύκλο ζωής και τον χειρισμό χρηστών](https://docs.npmjs.com/cli/v6/using-npm/scripts/). Μια διαδρομή `.npmrc` ή μια γραμμή `npm install` από μόνη της είναι απλώς ένδειξη προς διερεύνηση. Εξετάστε τον κανόνα, τον σύντομο wrapper, τις διαδρομές διαμόρφωσης και την προέλευση του πακέτου χωρίς να εγκαταστήσετε ή να εκκινήσετε την εφαρμογή κατά την παθητική απαρίθμηση.

Μια παραχώρηση `pip` ή `pip3 download` με δυνατότητα root είναι επίσης ένδειξη προς έλεγχο build πακέτου όταν τα ορίσματα επιτρέπουν στον καλούντα να επιλέξει μη έμπιστη διανομή πηγαίου κώδικα, ακόμη κι αν το πρότυπο URL περιορίζεται σε τοπική υπηρεσία και κατάληξη `.tar.gz`. Το `pip download` δέχεται URL αρχείων και επιλύει metadata πακέτων· η προετοιμασία μιας sdist μπορεί να καλέσει το build backend ή παλαιότερο κώδικα `setup.py` πριν απλώς αποθηκευτεί το αρχείο. Επιβεβαιώστε τον ακριβή χρήστη RunAs και τον κανόνα ορισμάτων sudo, αν ο καλών μπορεί να δημοσιεύσει ή να αντικαταστήσει το επιλεγμένο αρχείο και αν αυτή η έκδοση pip πράγματι προετοιμάζει τα metadata του. Ένα σταθερό έμπιστο archive ή wheel δεν αποδεικνύει αυτή τη διαδρομή. Μην ανακτάτε ή κάνετε build μη έμπιστο πακέτο κατά την παθητική απαρίθμηση. Δείτε την [εντολή download του pip](https://pip.pypa.io/en/stable/cli/pip_download/), τη [διεπαφή build-system](https://pip.pypa.io/en/stable/reference/build-system/) και τις [οδηγίες ασφαλούς εγκατάστασης](https://pip.pypa.io/en/stable/topics/secure-installs/).

Ένας κανόνας sudo που επιτρέπει `pip install` με διαδρομή τοπικού έργου επιλεγμένη από τον καλούντα δημιουργεί πιο άμεσο όριο build. Το [pip δέχεται τοπικούς καταλόγους έργου](https://pip.pypa.io/en/stable/topics/local-project-installs/) και καλεί το build system τους· το [build backend εκτελεί hooks build που ελέγχονται από το έργο](https://pip.pypa.io/en/stable/reference/build-system/). Επιβεβαιώστε την ενεργή ταυτότητα RunAs, τους ακριβείς περιορισμούς και απαγορεύσεις ορισμάτων, τον έλεγχο του επιλεγμένου έργου και τη συμπεριφορά του εγκατεστημένου pip/backend πριν θεωρήσετε τον κανόνα προνομιούχο εκτέλεση κώδικα. Ένα σταθερό έμπιστο έργο ή κανόνας που αποκλείει διαδρομές επιλεγμένες από τον καλούντα δεν τεκμηριώνει αυτή τη διαδρομή. Εξετάστε τον κανόνα και τα metadata του έργου χωρίς να εγκαταστήσετε πακέτο κατά την παθητική απαρίθμηση.

Μια απεριόριστη παραχώρηση `easy_install` με δυνατότητα root είναι παρόμοια ένδειξη για παλαιότερη διαδικασία build πακέτων. Το [Setuptools τεκμηριώνει](https://setuptools.pypa.io/en/stable/deprecated/easy_install.html) ότι το Easy Install δέχεται τοπικό κατάλογο έργου και κάνει build διανομών πηγαίου κώδικα· ένα έργο ελεγχόμενο από τον καλούντα μπορεί να εκτελέσει το `setup.py` κατά το build με την ταυτότητα sudo. Επιβεβαιώστε τον ενεργό λογαριασμό RunAs, την ακριβή εντολή και τους περιορισμούς ορισμάτων (μαζί με μεταγενέστερες απαγορεύσεις), τον έλεγχο του επιλεγμένου έργου και τη συμπεριφορά του εγκατεστημένου εργαλείου. Ένα σταθερό έμπιστο έργο ή πολιτική που δεν επιτρέπει επιλογή πηγής από τον καλούντα δεν τεκμηριώνει αυτή τη διαδρομή. Εξετάστε τον κανόνα και τα metadata του έργου χωρίς να εγκαταστήσετε πακέτο κατά την απαρίθμηση.

Ένας Python wrapper που επιτρέπεται από το sudo και χρησιμοποιεί `setuptools.package_index.PackageIndex.download` με URL επιλεγμένο από τον καλούντα είναι διαφορετική περίπτωση ελέγχου από το `pip download`: το [setuptools GHSA-5rjg-fvgr-3xxf](https://github.com/pypa/setuptools/security/advisories/GHSA-5rjg-fvgr-3xxf) περιγράφει filename που προκύπτει από URL και διαφεύγει από τον προβλεπόμενο κατάλογο λήψης, γράφοντας με τα δικαιώματα της διεργασίας σε επηρεαζόμενες εκδόσεις πριν την 78.1.1. Επιβεβαιώστε τον ενεργό χρήστη RunAs και τον κανόνα ορισμάτων sudo, ότι ο wrapper περνά το URL του καλούντος σε αυτό το ακριβές API, το build ή backport του προμηθευτή που είναι εγκατεστημένο και πού επιλύεται η διαδρομή που προκύπτει. Μια συμβολοσειρά έκδοσης ή ένας εγγράψιμος κατάλογος λήψης από μόνα τους δεν αποδεικνύουν αυθαίρετη εγγραφή. Εξετάστε τον σύντομο wrapper και τα metadata πακέτου χωρίς να ανακτήσετε το URL ή να γράψετε αρχείο κατά την απαρίθμηση.

Ένας wrapper build που επιτρέπεται μέσω sudo και περνά αρχείο `.spec` επιλεγμένο από τον καλούντα στο PyInstaller απαιτεί αντίστοιχο έλεγχο ορίου εμπιστοσύνης. Ένα spec PyInstaller είναι εκτελέσιμη Python που αξιολογείται κατά το **build**, και οι καταχωρίσεις `datas` του μπορούν να ενσωματώσουν σε artifact αρχεία αναγνώσιμα από την ταυτότητα build. Επιβεβαιώστε τον ακριβή χρήστη RunAs, τους κανόνες ορισμάτων και απαγορεύσεων sudo, τον χειρισμό διαδρομών και κλάδων του wrapper, τον έλεγχο του επιλεγμένου spec από τον καλούντα και την πρόσβαση στο artifact που προκύπτει. Η απλή άδεια εισόδου `.py` ή η εγκατάσταση του PyInstaller δεν αποδεικνύει έλεγχο αρχείου spec ή προνομιούχα εκτέλεση. Η παθητική εξέταση πρέπει να διαβάζει μόνο περιορισμένο αρχείο wrapper και metadata· δεν πρέπει να εκτελεί build. Δείτε την [τεκμηρίωση αρχείων spec του PyInstaller](https://pyinstaller.org/en/stable/spec-files.html).

### Προνομιούχα wrappers backup που ξαναγράφουν αρχείο εργασιών του καλούντος

Ένας wrapper κελύφους που εκτελείται ως root μπορεί να δέχεται αρχείο εργασιών επιλεγμένο από τον καλούντα, να αφαιρεί το `../` από διαδρομές πηγών, να ελέγχει ότι κάθε αποτέλεσμα αρχίζει με επιτρεπόμενο κατάλογο, να ξαναγράφει το αρχείο εργασιών και έπειτα να περνά τη *διαδρομή* του σε πρόγραμμα backup. Εξετάστε τη μετασχηματισμένη διαδρομή μετά από πλήρη κανονική επίλυση: ένα μόνο πέρασμα αντικατάστασης συμβολοσειρών μπορεί να αποκαλύψει νέα ακολουθία traversal που γίνεται δεκτή από λεξικό έλεγχο προθέματος. Ελέγξτε επίσης αν το πρόγραμμα backup διαβάζει τα μετασχηματισμένα δεδομένα από τη μνήμη ή ανοίγει ξανά το αρχείο. Αν το ανοίγει ξανά, μια αποτυχημένη επανεγγραφή μπορεί να αφήσει στη θέση του το αρχικό αρχείο εισόδου.

Στο Linux, το `fs.protected_regular` μπορεί να αρνηθεί εγγραφή `O_CREAT` σε κανονικό αρχείο άλλου χρήστη μέσα σε sticky κατάλογο εγγράψιμο από όλους. Η άρνηση είναι προστατευτική, αλλά ένας wrapper κελύφους που αγνοεί το σφάλμα εγγραφής μπορεί να συνεχίσει με το αρχικό αρχείο εργασιών. Επιβεβαιώστε τη ρύθμιση, τον ιδιοκτήτη του αρχείου και του καταλόγου και αν ο wrapper διακόπτεται σε αποτυχία. Η διαδρομή αποτελεί υποψήφια αποκάλυψης αρχείου μόνο όταν ο ενεργός κανόνας sudo επιτρέπει τον wrapper ως προνομιούχο χρήστη, ο καλών ελέγχει την είσοδο εργασιών και προορισμό backup που μπορεί να διαβάσει, και το εργαλείο backup περιλαμβάνει πράγματι προστατευμένες πηγές. Εξετάστε αυτές τις συνθήκες χωρίς να εκτελέσετε backup κατά την απαρίθμηση.

### Wildcards ορισμάτων σε προνομιούχα εργαλεία πακέτων

Σε κανόνα sudo για `tcpdump`, το `*` στο **πρότυπο ορισμάτων** μπορεί να αντιστοιχίσει κενά και καθέτους, επομένως ένας περιορισμός που μοιάζει με διαδρομή μπορεί και πάλι να επιτρέπει πρόσθετο κείμενο επιλογών. Αυτό διαφέρει από wildcard στη διαδρομή του εκτελέσιμου της εντολής· εξετάστε ολόκληρο τον κανόνα RunAs και τυχόν μεταγενέστερες απαγορεύσεις. Αν μπορούν να εισαχθούν επιλογές, η επιτρεπόμενη κλήση και η σημασιολογία των επιλογών του εγκατεστημένου [`tcpdump`](https://github.com/the-tcpdump-group/tcpdump/blob/master/tcpdump.1.in) καθορίζουν αν τα `-F`, `-V`, `-r`, `-w` ή `-Z` παρέχουν χρήσιμο primitive ανάγνωσης/εγγραφής. Το `-V` διαβάζει λίστα ονομάτων αρχείων capture, όχι γενικού σκοπού dump αυθαίρετου αρχείου. Το AppArmor ή άλλη πολιτική MAC μπορεί να εμποδίσει την πρόσβαση σε αρχεία ακόμη κι όταν το sudo επιτρέπει την εντολή· ένα αρχείο profile στον δίσκο δεν αποδεικνύει ότι είναι φορτωμένο ή εφαρμόζεται. Εξετάστε παθητικά την εξουσιοδότηση και την πολιτική πριν καταλήξετε. Το [εγχειρίδιο sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) περιγράφει τη διαφορά των wildcard.

Ένας κανόνας sudo με δυνατότητα root που αναφέρει μόνο το εκτελέσιμο `tcpdump`, χωρίς περιορισμό ορισμάτων, απαιτεί επίσης έλεγχο. Το [εγχειρίδιο tcpdump](https://github.com/the-tcpdump-group/tcpdump/blob/master/tcpdump.1.in) τεκμηριώνει το `-z` ως εντολή μετά την εναλλαγή capture, όταν τα `-C` ή `-G` εναλλάσσουν αποθηκευμένο capture· το `-Z` ή προεπιλογή κατά τη μεταγλώττιση μπορεί να αφαιρέσει προνόμια πριν εκτελεστεί αυτή η εντολή. Επαληθεύστε τον ενεργό κανόνα sudo, την εγκατεστημένη έκδοση, τη συμπεριφορά υποβιβασμού προνομίων και αν μπορεί να συμβεί εναλλαγή πριν θεωρήσετε τον κανόνα διαδρομή κλιμάκωσης. Ένας επισημασμένος κανόνας είναι υποψήφια περίπτωση, όχι απόδειξη εκτέλεσης εντολών ως root.

### Προνομιούχος κατάλογος καταγραφής Below

Το [CVE-2025-27591](https://github.com/facebookincubator/below/security/advisories/GHSA-9mc5-7qhg-fp3w) επηρέαζε εκδόσεις Below πριν από την 0.9.0, οι οποίες δημιουργούσαν κατάλογο `/var/log/below` εγγράψιμο από όλους. Αν μια υπηρεσία ή επιτρεπόμενη εντολή sudo εκτελεί επηρεαζόμενη έκδοση ως root, χρήστης που μπορεί να γράψει και να διασχίσει κατάλογο καταγραφής χωρίς sticky bit ενδέχεται να αντικαταστήσει καταχώριση log με symlink πριν την ανοίξει η προνομιούχος διεργασία. Εξετάστε την κατάσταση διόρθωσης του εγκατεστημένου πακέτου, την ακριβή προνομιούχα διαδρομή εκτέλεσης, την ενεργή πρόσβαση στον κατάλογο, το sticky bit και τα ACL, καθώς και τα metadata του `/var/log/below/error_root.log`. Μια διαδρομή εγγράψιμη από όλους ή ένας κανόνας sudo από μόνος του δεν τεκμηριώνει ολόκληρη την αλυσίδα. Sticky directory ή backport προμηθευτή αλλάζει την εκτίμηση. Η παθητική απαρίθμηση πρέπει να εξετάζει μόνο metadata· δεν χρειάζεται να δημιουργήσει σύνδεσμο ή να εκτελέσει το προνομιούχο πρόγραμμα.

### Προνομιούχα συλλογή support bundle από εγγράψιμες εισόδους

Ένα script προφίλ υποστήριξης που επιτρέπεται από το `sudo` μπορεί να διαβάζει σταθερές διαδρομές logs ως root και να αντιγράφει το περιεχόμενό τους σε archive προφίλ. Εξετάστε το πραγματικό script για αναγνώσεις αρχείων και έπειτα ελέγξτε αν ο καλών μπορεί να αντικαταστήσει διαδρομή πηγής ή οποιαδήποτε γονική καταχώριση καταλόγου με symlink. Αν η προνομιούχος ανάγνωση ακολουθεί αυτόν τον σύνδεσμο και το archive που προκύπτει είναι αναγνώσιμο από τον καλούντα, μπορεί να αποκαλυφθεί προστατευμένο αρχείο. Πρέπει να υπάρχουν όλα: παραχώρηση sudo, εγγράψιμη διαδρομή πηγής, προνομιούχος ανάγνωση και αναγνώσιμη έξοδος· ένα εγγράψιμο log ή όνομα προφίλ από μόνο του δεν αρκεί. Εξετάστε τα ενεργά δικαιώματα και metadata συνδέσμων χωρίς να αντικαταστήσετε αρχεία ή να δημιουργήσετε προφίλ κατά την απαρίθμηση. Οι [οδηγίες υποστήριξης Nagios XI](https://support.nagios.com/forum/viewtopic.php?t=62758) τεκμηριώνουν το script προφίλ που εκτελείται ως root και το archive εξόδου, δείχνοντας γιατί αυτά τα bundles χρειάζονται περιορισμένες εισόδους και πρόσβαση εξόδου.

### Scripts επαναφοράς archive Python που εκτελούνται ως root

Ένας στενά περιορισμένος κανόνας sudo για script επαναφοράς Python απαιτεί και πάλι εξέταση της εισόδου archive. Αν ο καλών μπορεί να επιλέξει ή να αντικαταστήσει το archive και το script το εξάγει ως root με `tarfile.extractall(filter="data")`, ελέγξτε τις ενημερώσεις ασφαλείας του διερμηνευτή πριν εμπιστευτείτε το φίλτρο. Το CPython διόρθωσε αρκετές παρακάμψεις φίλτρων symlink και hard-link, μεταξύ των οποίων το CVE-2025-4517, στις εκδόσεις 3.9.23, 3.10.18, 3.11.13, 3.12.11 και 3.13.4. Backport διανομής μπορεί να διορθώσει προγενέστερη έκδοση, επομένως η εμφανιζόμενη έκδοση διερμηνευτή από μόνη της δεν αποδεικνύει έκθεση.<sup>[[16]](#references)[[17]](#references)</sup>

Για παθητική εξέταση, διαβάστε την ακριβή εντολή sudo και το script, ακολουθήστε ποιο όρισμα επιλέγει το archive και ελέγξτε αν ο τρέχων χρήστης μπορεί να γράψει στο archive ή στον περιέχοντα κατάλογο. Επιβεβαιώστε χωριστά τη διόρθωση του προμηθευτή και τον προορισμό εξαγωγής· το `filter="data"` δεν καθιστά ασφαλές κάθε μη έμπιστο archive.<sup>[[16]](#references)[[17]](#references)</sup>

### Loaders μοντέλων μηχανικής μάθησης μέσω sudo

Ένας κανόνας sudo που επιτρέπει αρχείο `.pt`, `.pth` ή `.ckpt` επιλεγμένο από τον καλούντα απαιτεί εξέταση όταν προνομιούχο script περνά αυτό το αρχείο στο [`torch.load`](https://docs.pytorch.org/docs/stable/generated/torch.load.html), στο `pickle.load` ή σε άλλον loader βασισμένο σε pickle. Ελέγξτε τον ενεργό κανόνα RunAs, αν ο καλών μπορεί να δημιουργήσει ή να αντικαταστήσει το επιλεγμένο μοντέλο και την πραγματική ροή ορίσματος μέσω οποιουδήποτε wrapper κελύφους προς τον Python helper. Η κατάληξη `.pth` ονομάζει επίσης άσχετα αρχεία διαμόρφωσης Python site, επομένως η κατάληξη από μόνη της δεν αποδεικνύει φόρτωση μοντέλου. Η σάρωση archive ή στατική σάρωση pickle δεν αποδεικνύει ότι η μεταγενέστερη φόρτωση είναι ασφαλής· εξετάστε τη [συμπεριφορά `weights_only` που εξαρτάται από την έκδοση](https://docs.pytorch.org/docs/stable/notes/serialization.html) και τυχόν allowlisting. Δείτε τις [σημειώσεις ML pickle και Fickling](../../AI/keras-model-deserialization-rce-and-gadget-hunting.md#ml-pickle-import-allowlisting-for-aiml-models-fickling). Η παθητική απαρίθμηση δεν πρέπει ποτέ να φορτώνει ή να αποσυμπιέζει το μοντέλο.

### Ανάλυση εκφράσεων stored input μέσω sudo

Ένα σταθερό Python script που εκτελείται ως root μέσω sudo μπορεί και πάλι να αξιολογεί κείμενο αποθηκευμένο από χρήστη χαμηλότερων προνομίων σε βάση δεδομένων εφαρμογής. Στο TensorFlow, μια κλήση `preprocess_input_exprs_arg_string(value, safe=False)` επιλέγει διαδρομή `eval`· η [συμβουλευτική του TensorFlow](https://github.com/tensorflow/tensorflow/security/advisories/GHSA-75c9-jrh4-79mc) περιγράφει τον μη ασφαλή parser και διόρθωση στον caller γραμμής εντολών του. Η ρητή κλήση `safe=False` μιας εφαρμογής απαιτεί ξεχωριστό έλεγχο ακόμη κι όταν αυτός ο caller γραμμής εντολών έχει διορθωθεί. Ελέγξτε τον ενεργό κανόνα sudo, ποιος μπορεί να τροποποιήσει την ακριβή εγγραφή εισόδου, αν φιλτράρισμα ή scoring επιτρέπει στην εγγραφή να φτάσει στην κλήση και τη συμπεριφορά της εγκατεστημένης συνάρτησης. Μια έκδοση TensorFlow, μια παραχώρηση sudo ή ένα hardcoded αρχείο μοντέλου από μόνα τους δεν αποδεικνύουν την αλυσίδα. Εξετάστε παθητικά το script και τη ροή δεδομένων· μην εκτελέσετε τον προνομιούχο helper ή υποβάλετε δοκιμαστικές εκφράσεις κατά την απαρίθμηση.

### Διαμόρφωση needrestart που επιτρέπεται από sudo

Το `needrestart -c` φορτώνει αρχείο διαμόρφωσης Perl επιλεγμένο από τον καλούντα και αξιολογεί τα περιεχόμενά του. Αν το `sudo -l` επιτρέπει το `needrestart` ως root με ορίσματα που επιτρέπουν το `-c`, και ο καλών μπορεί να επιλέξει αναγνώσιμο αρχείο διαμόρφωσης σε εγγράψιμη θέση, αυτή η άδεια μπορεί να οδηγήσει σε εκτέλεση κώδικα ως root. Ελέγξτε τον ακριβή χρήστη εκτέλεσης και τον κανόνα ορισμάτων sudo· κανόνας που επιτρέπει μόνο σταθερή λίστα ορισμάτων μπορεί να αποκλείει αυτή τη διαδρομή. Αυτό είναι ξεχωριστό από τις ευπάθειες σάρωσης διερμηνευτών του needrestart: η ενημέρωση του πακέτου ή η απενεργοποίηση του `interpscan` δεν καθιστά ασφαλή μια απεριόριστη παραχώρηση root `-c`.<sup>[[2]](#references)[[18]](#references)[[19]](#references)</sup>

### Python imports μέσω sudo σε άλλο λογαριασμό

Ένα σταθερό entry point Python μπορεί και πάλι να εισαγάγει module που ο καλών μπορεί να επεξεργαστεί ή να αντικαταστήσει, ακόμη κι όταν το sudo εκτελεί το script ως **μη-root** χρήστη υπηρεσίας. Για κυριολεκτικό `from utils import status`, εξετάστε τα τοπικά `utils/__init__.py` και `utils/status.py`, καθώς και τα δικαιώματα του καταλόγου πακέτου. Επιβεβαιώστε τη διαδρομή import του script, τα ακριβή επιτρεπόμενα ορίσματα sudo και αν η σχετική ενέργεια φτάνει σε αυτό το import πριν θεωρήσετε το εγγράψιμο αρχείο διαδρομή εκτέλεσης. Εξετάστε αρχεία και δικαιώματα χωρίς να κάνετε import ή να εκτελέσετε το script κατά την απαρίθμηση.<sup>[[2]](#references)[[3]](#references)</sup>

Ένας ακριβής κανόνας sudo για `python3 /absolute/script.py` απαιτεί μόνο να είναι αναγνώσιμο το script· δεν χρειάζεται να είναι εκτελέσιμο ή να έχει shebang. Εξετάστε επίσης **ελλείποντα** τοπικά modules: αν το script εισάγει module του οποίου το filename μπορεί να δημιουργηθεί σε κατάλογο script εγγράψιμο από τον καλούντα, η Python μπορεί να φορτώσει αυτό το αρχείο με την ταυτότητα RunAs. Επιβεβαιώστε τον ενεργό κανόνα sudo, την πραγματική [διαδρομή αναζήτησης modules](https://docs.python.org/3/library/sys_path_init.html) του διερμηνευτή, αν το module είναι ενσωματωμένο ή frozen και αν φτάνει στο import. Ένας άμεσος κανόνας sudo για το script έχει διαφορετικές απαιτήσεις bit εκτέλεσης και shebang. Ένας ξεχωριστός wrapper που προσθέτει tokens του καλούντος μετά το `sudo -u account` απαιτεί επίσης έλεγχο ροής ορισμάτων: ένα επιπλέον `-u` σε αυτά τα tokens έχει σημασία μόνο αν η πολιτική sudo της εκτελούμενης εντολής επιτρέπει την ταυτότητα που προκύπτει. Οι στατικές συμβολοσειρές από μόνες τους δεν αποδεικνύουν καμία από τις δύο διαδρομές.

### Apache μέσω sudo με διαμόρφωση ελεγχόμενη από τον καλούντα

Αν ένας κανόνας sudo επιτρέπει προνομιούχα κλήση `apachectl`, `apache2ctl` ή `httpd` με αρχείο διαμόρφωσης `-f` ελεγχόμενο από τον καλούντα, εξετάστε τα δικαιώματα αυτού του αρχείου και του γονικού του καταλόγου. Η οδηγία Apache [`LoadModule`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadmodule) παίρνει όνομα module και έπειτα το **filename του module**· το [`LoadFile`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadfile) φορτώνει επίσης αρχείο. Τα [`Include` και `IncludeOptional`](https://httpd.apache.org/docs/2.4/mod/core.html#include) μπορούν να επεκτείνουν τη διαμόρφωση ή να εκθέσουν περιεχόμενα αρχείων μέσω σφαλμάτων. Ένας προσαρμοσμένος wrapper μπορεί να επικυρώνει αυτές τις διαδρομές, να υποβιβάζει προνόμια ή να περιορίζει ορίσματα· επομένως μια εγγράψιμη διαμόρφωση είναι υποψήφια περίπτωση ελέγχου, όχι απόδειξη εκτέλεσης κώδικα. Ελέγξτε την κανονικοποίηση διαδρομών, τα symlink και την ανάλυση οδηγιών πριν καταλήξετε.

### nginx μέσω sudo με διαμόρφωση ελεγχόμενη από τον καλούντα

Ένας απεριόριστος κανόνας `nginx` με δυνατότητα root μπορεί να επιτρέψει στο [`-c` να επιλέξει άλλη διαμόρφωση](https://nginx.org/en/docs/switches.html). Εξετάστε τα ακριβή ορίσματα και τις εξαιρέσεις sudo, αν ο καλών μπορεί να παράσχει τη διαμόρφωση και αν ο master ή οι workers που προκύπτουν διατηρούν πρόσβαση σε προστατευμένες διαδρομές. Επιλεγμένο `root` μαζί με `autoindex` μπορεί να εκθέσει αρχεία μέσω νέου listener· το [`dav_methods PUT`](https://nginx.org/en/docs/http/ngx_http_dav_module.html) μπορεί να προσφέρει προνομιούχα διαδρομή εγγραφής αρχείων, αλλά το module DAV δεν γίνεται build από προεπιλογή και πρέπει να ελεγχθούν η παρουσία του, η προσβασιμότητα του listener, τα δικαιώματα αρχείων και η συμπεριφορά προσωρινών αρχείων. Η οδηγία [`error_log`](https://nginx.org/en/docs/ngx_core_module.html#error_log) μπορεί επίσης να στοχεύσει επιλεγμένο αρχείο· η εγγραφή logs σε ευαίσθητο αρχείο διαμόρφωσης, όπως το `/etc/ld.so.preload`, γίνεται διαδρομή κλιμάκωσης μόνο αν υπάρχει ενεργός προνομιούχος writer και ελεγχόμενη από τον καλούντα εγγραφή log. Η επισήμανση του εκτελέσιμου στο `sudo -l` είναι αφορμή για έλεγχο, όχι απόδειξη ότι κάποια διαδρομή λειτουργεί. Η παθητική απαρίθμηση δεν πρέπει να εκκινεί ή να επαναδιαμορφώνει το nginx.

### Σύγκριση pattern σε προνομιούχα Bash prompts

Όταν ένα Bash script που επιτρέπεται από το sudo διαβάζει τιμή από τον καλούντα και την ελέγχει με `[[ "$expected" == $entered ]]`, το Bash ερμηνεύει τον μη quoted δεξιό τελεστέο ως pattern. Επομένως, ένα wildcard μπορεί να ικανοποιήσει τη σύγκριση χωρίς να είναι γνωστή η αναμενόμενη τιμή. Με το quoting του τελεστέου (`[[ "$expected" == "$entered" ]]`) γίνεται σύγκριση κυριολεκτικών συμβολοσειρών. Εξετάστε τον ακριβή κανόνα sudo, αν είναι προσβάσιμο το prompt και τι κάνει το script μετά τη σύγκριση· η σύνταξη από μόνη της δεν αποδεικνύει εκμεταλλεύσιμη διαδρομή. Αποφύγετε να εμφανίσετε την αναμενόμενη τιμή κατά την απαρίθμηση. Δείτε την [αναφορά Bash για conditional constructs](https://www.gnu.org/software/bash/manual/html_node/Conditional-Constructs.html).

### Helpers μέσω sudo που κατεβάζουν και εκτελούν αρχείο

Μια απεριόριστη παραχώρηση sudo για προσαρμοσμένο helper με δυνατότητα root απαιτεί έλεγχο ροής δεδομένων, αν δέχεται URL επιλεγμένο από τον καλούντα, γράφει την απόκριση στον δίσκο και αργότερα εκτελεί αυτό το αρχείο με διερμηνευτή ή κέλυφος. Το [sudoers επιτρέπει αυθαίρετα ορίσματα όταν η καταχώριση εντολής δεν ορίζει κανένα](https://man7.org/linux/man-pages/man5/sudoers.5.html)· σταθερή διαδρομή εκτελέσιμου δεν περιορίζει τι μπορούν να επιλέξουν τα ορίσματά της. Επιβεβαιώστε την πραγματική επικύρωση URL, τη διαδρομή εξόδου, τον κλάδο επιτυχίας και τη μεταγενέστερη εκτέλεση στον εγκατεστημένο helper. Ένα αντίστοιχο import libcurl ή μια εκτυπώσιμη συμβολοσειρά από μόνη της δεν αποδεικνύει αυτή την αλυσίδα.

Ακόμη και σταθερό basename εξόδου μπορεί να αντικατασταθεί ανάμεσα στην εγγραφή και την εκτέλεση όταν ο helper χρησιμοποιεί **σχετική διαδρομή σε τρέχοντα κατάλογο ελεγχόμενο από τον καλούντα**. Η μετονομασία ή αντικατάσταση αρχείου που ανήκει στον root διέπεται από τα δικαιώματα εγγραφής και αναζήτησης του καταλόγου και τυχόν περιορισμούς sticky bit, όχι μόνο από τα δικαιώματα του αρχείου· δείτε το [`rename(2)`](https://man7.org/linux/man-pages/man2/rename.2.html). Ελέγξτε αν ο helper ανοίγει ξανά τη διαδρομή αργότερα ή χρησιμοποιεί ήδη ανοιχτό file descriptor, καθώς και αν μεταβαίνει σε έμπιστο κατάλογο πριν γράψει. Εξετάστε παθητικά την πολιτική sudo, τον helper και τα metadata του καταλόγου· μην εκτελέσετε την προνομιούχο λήψη ή race κατά την απαρίθμηση.

Ένας helper λήψης μέσω sudo ως root μπορεί επίσης να εκθέσει injection **ορισμάτων**, αν συνθέτει συμβολοσειρά εντολής Bash όπως `curl <είσοδος καλούντος> -o <σταθερή έξοδος>`. Ένα φίλτρο που απορρίπτει κενά αφήνει διαθέσιμη την [επέκταση αγκυλών του Bash](https://www.gnu.org/software/bash/manual/html_node/Brace-Expansion.html): στοιχεία διαχωρισμένα με κόμματα, χωρίς quoting, μπορούν να γίνουν ξεχωριστά ορίσματα curl. Αν η είσοδος φτάνει στο curl πριν από το σταθερό `-o`, επιλογή εξόδου που παρέχει ο καλών μπορεί να επιλέξει προορισμό για το πρώτο URL με την ταυτότητα του helper· το [curl συσχετίζει τις επιλογές εξόδου με τα URL με τη σειρά](https://curl.se/docs/manpage.html#-o). Επιβεβαιώστε το ακριβές κέλυφος, το quoting, την επικύρωση εισόδου, τον ενεργό κανόνα sudo, τη σειρά ορισμάτων curl και τα υποστηριζόμενα URL schemes, καθώς και αν ο καλών ελέγχει τα bytes που ανακτώνται ή μπορεί να διαβάσει το αποτέλεσμα. Ένα εκτελέσιμο συσκευασμένο με PyInstaller μπορεί να περιέχει λογική εφαρμογής Python, αλλά η ένδειξη συσκευασίας ή μια συμβολοσειρά `curl` από μόνη της δεν αποδεικνύει αυτή τη ροή δεδομένων. Εξετάστε εξουσιοδοτημένο, περιορισμένο offline αντίγραφο· η συνήθης απαρίθμηση δεν πρέπει να εκτελεί τον helper ή να ανακτά δεδομένα επιλεγμένα από επιτιθέμενο.

Ένα shell script που εκτελείται ως root μέσω sudo και καλεί [`mktemp -u` / `--dry-run`](https://www.gnu.org/software/coreutils/manual/html_node/mktemp-invocation.html) επιλέγει μόνο ένα μη χρησιμοποιούμενο όνομα· **δεν** δημιουργεί το αρχείο. Αν το script αργότερα δημιουργεί αυτό το όνομα σε κατάλογο που μπορεί να επηρεάσει άλλος χρήστης, έπειτα το ξανανοίγει και προσθέτει τα περιεχόμενά του σε προστατευμένο προορισμό, όπως το `authorized_keys` του root, εξετάστε πιθανό race προσωρινού αρχείου. Επιβεβαιώστε τον ακριβή κανόνα sudo, τους ιδιοκτήτες καταλόγου και αρχείου, τη σειρά δημιουργίας και επανανοίγματος, τις προστασίες πυρήνα και αν η προνομιούχα εγγραφή χρησιμοποιεί πράγματι bytes ελεγχόμενα από τον επιτιθέμενο. Μια συμβολοσειρά `mktemp -u` ή ένα εγγράψιμο `/tmp` από μόνο του δεν αποδεικνύει το race. Εξετάστε το script και τα metadata διαδρομών χωρίς να το εκτελέσετε ή να προκαλέσετε race στο προσωρινό αρχείο κατά την απαρίθμηση.

## Αμυντικές σημειώσεις

- Αποφύγετε να παραχωρείτε διερμηνευτές ή διαδραστικούς editors μέσω sudo.<sup>[[1]](#references)</sup>
- Μην παραχωρείτε γενικά προγράμματα εγγραφής αρχείων όπως το `tee` με απεριόριστα ορίσματα. Χρησιμοποιήστε wrapper που ανήκει στον root, επιλέγει σταθερό προορισμό και απορρίπτει διαδρομές ελεγχόμενες από τον καλούντα.<sup>[[2]](#references)</sup>
- Προτιμήστε σταθερούς wrappers που ανήκουν στον root και εκτελούν μία στενά καθορισμένη διοικητική ενέργεια.<sup>[[1]](#references)[[2]](#references)</sup>
- Αν είναι αναπόφευκτος ένας διερμηνευτής, περιορίστε την ακριβή διαδρομή του script και αποτρέψτε ορίσματα ελεγχόμενα από χρήστη, εγγράψιμα imports, `PYTHONPATH` και μη ασφαλή διατήρηση περιβάλλοντος.<sup>[[2]](#references)[[3]](#references)[[4]](#references)</sup>
- Αν απαιτείται επεξεργασία αρχείων, περιορίστε την ακριβή διαδρομή αρχείου και εξετάστε το `sudoedit` με διορθωμένες εκδόσεις sudo και αυστηρό χειρισμό περιβάλλοντος.<sup>[[1]](#references)[[2]](#references)</sup>
- Εξετάστε τα `SETENV`, `env_keep`, εγγράψιμους τρέχοντες καταλόγους, εγγράψιμες διαδρομές module/import, `NOEXEC`, `use_pty` και logging, αλλά μην τα θεωρείτε πλήρες sandbox.<sup>[[1]](#references)[[2]](#references)[[3]](#references)</sup>
