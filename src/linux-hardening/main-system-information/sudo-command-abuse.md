## Interpreta zinazoruhusiwa na Sudo

Ikiwa `sudo -l` inamruhusu mtumiaji kuendesha interpreter kama root, ichukulie kuwa ni utekelezaji wa msimbo wa moja kwa moja. Interpreters zimeundwa kutekeleza msimbo wowote, kwa hivyo kanuni inayoruhusu `python3`, `perl`, `ruby`, `lua`, `node`, au binary zinazofanana kwa kawaida ni sawa na kutekeleza amri kama root, isipokuwa hoja zimewekewa vizuizi na kuthibitishwa kwa makini.<sup>[[1]](#references)[[2]](#references)[[3]](#references)[[4]](#references)[[5]](#references)[[7]](#references)[[9]](#references)[[11]](#references)</sup>

Mtiririko wa kawaida wa ukaguzi: kwanza orodhesha ruhusa za mtumiaji, kisha tekeleza kauli ya Python ukitumia chaguo la interpreter `-c`.<sup>[[1]](#references)[[3]](#references)[[4]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/python3 -c 'import os; os.system("id")'
sudo /usr/bin/python3 -c 'import os; os.system("/bin/sh")'
```

Mifano mingine ya interpreters imeonyeshwa hapa chini; interpreters zilizoorodheshwa zinaandika kuhusu utekelezaji wa inline code au APIs za child process.<sup>[[5]](#references)[[6]](#references)[[7]](#references)[[8]](#references)[[9]](#references)[[10]](#references)[[11]](#references)</sup>

```bash
sudo /usr/bin/perl -e 'exec "/bin/sh";'
sudo /usr/bin/ruby -e 'exec "/bin/sh"'
sudo /usr/bin/node -e 'require("child_process").spawn("/bin/sh", {stdio: [0,1,2]})'
```

Njia kamili ni muhimu. Ikiwa sheria ya sudo inaruhusu `/usr/bin/python3`, tumia njia hiyo hiyo wakati wa uthibitishaji.<sup>[[2]](#references)</sup>

Glob ya sudo executable kama `/usr/bin/python*` inaweza pia kuruhusu Python 2 kwa script iliyoandikwa kwa Python 3. Ikiwa script itafikia `input()` yenye maandishi yanayodhibitiwa na mpigaji, [Python 2 hutathmini maandishi hayo kama expression](https://docs.python.org/2/library/functions.html#input); kuitisha interpreter moja kwa moja hubatilisha shebang ya script. Thibitisha binaries zinazolingana zilizosakinishwa, RunAs inayotumika na sera ya arguments, vizuizi, na input inayoweza kufikiwa kabla ya kuchukulia hili kama njia ya utekelezaji.

Njia ya script iliyowekwa maalumu katika sheria ya sudo yenye uwezo wa root haizuii kile script itakachoendesha. Kwa Bash wrapper inayosomeka, angalia kama amri yake ya kwanza inayotekelezeka inatumia positional parameter isiyowekwa kwenye quotes kama `$1` kama **command word**, huku sudo ikiruhusu mpigaji kuchagua arguments. Thibitisha utambulisho wa RunAs unaotumika, sera ya password na arguments, vizuizi vya baadaye, na tawi halisi la script; `NOEXEC`, orodha ya arguments salama isiyobadilika, au wrapper inayothibitisha amri yake inaweza kubadilisha matokeo. Kagua script fupi kwa njia tuli wakati wa enumeration badala ya kuiendesha kwa amri ya majaribio.

Sheria ya sudo isiyowekewa vikwazo yenye uwezo wa root kwa `dotnet` pia inafaa kukaguliwa kama interpreter. Ikiwa .NET SDK imesakinishwa, [`dotnet fsi` huendesha code ya F# kwa njia ya mwingiliano au kutoka kwenye script](https://learn.microsoft.com/en-us/dotnet/fsharp/tools/fsharp-interactive/), na [`dotnet run` huendesha project kutoka kwenye source](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-run). Thibitisha kwanza utambulisho wa RunAs unaotumika na sera kamili ya arguments: sheria iliyowekwa kwenye subcommand maalumu salama au application inayoaminika ni ruhusa tofauti, na usakinishaji wa runtime pekee huenda usiwe na amri za SDK. Jina la executable pekee ni kidokezo cha ukaguzi, si uthibitisho wa utekelezaji wa code.

```bash
sudo /usr/bin/python3 -c 'import os; os.setuid(0); os.setgid(0); os.system("/bin/sh")'
```

## Vihariri vinavyoruhusiwa na Sudo

Ikiwa `sudo -l` inaruhusu mtumiaji kuendesha kihariri shirikishi kama root, kichukulie kama njia ya kutekeleza amri, si ruhusa isiyo na madhara ya kuhariri faili. Mara nyingi vihariri vinaweza kutekeleza amri za shell, kusoma faili zozote, kuandika faili zozote au kuita zana za nje kutoka ndani ya kihariri.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

Utaratibu wa kawaida wa ukaguzi: orodhesha ruhusa za mtumiaji, kisha endesha kila kihariri au pager kinachoruhusiwa kupitia sudo.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/nano /etc/hosts
sudo /usr/bin/vim /etc/hosts
sudo /usr/bin/less /etc/hosts
```

### Nano command execution

Wakati nano inaruhusiwa kupitia sudo, command execution inaweza kufikiwa kupitia kiolesura cha kihariri.<sup>[[12]](#references)</sup>

```text
Ctrl+R
Ctrl+X
```

Kisha toa amri kama `id` au `/bin/sh` kwenye kidokezo cha amri cha nano.<sup>[[12]](#references)</sup>

```bash
id
/bin/sh
```

Ikiwa shell shirikishi haina mitiririko ya terminal inayoweza kutumika, umbo hili la uelekezaji upya hupeleka matokeo yake ya kawaida na makosa kwenye descriptor 0.<sup>[[15]](#references)</sup>

```bash
reset; /bin/sh 1>&0 2>&0
```

Mfuatano halisi wa vitufe unaweza kutofautiana kulingana na toleo la nano na chaguo za build, lakini tatizo la usalama ni lilelile: editor inaendeshwa kama root na inaweza kutekeleza amri za nje.<sup>[[1]](#references)[[12]](#references)</sup>

### Njia nyingine za kawaida za kutoka kwenye editor

Editor za mtindo wa Vim kwa kawaida huruhusu kutekeleza amri kupitia `:!`.<sup>[[13]](#references)</sup>

```text
:!/bin/sh
```

Pagers kama `less` pia zinaweza kufichua utekelezaji wa shell.<sup>[[14]](#references)</sup>

Sheria ya sudo inayoruhusu `apport-cli` kuendeshwa kama root inahitaji ukaguzi huohuo wa pager. Matoleo ya Apport yaliyoathiriwa yangeweza kufungua ripoti ya crash kwenye `less` kwa kutumia ukubwa wa terminal unaoweza kurekebishwa na mshambuliaji; pager ingeweza kisha kutoa root shell iwapo masharti maalum ya sudo na pager yangetimizwa. Kagua sheria ya sudo inayotumika, usanidi wa pager na marekebisho ya kifurushi cha distribution kabla ya kuhitimisha kuwa toleo pekee ndilo linaonyesha uwezekano wa kuathiriwa. Soma metadata ya kifurushi na sera bila kusababisha crash au kufungua ripoti yenye mapendeleo wakati wa uchunguzi tulivu. [Rekodi ya CVE ya Ubuntu](https://ubuntu.com/security/CVE-2023-1326) inaorodhesha matoleo ya vifurushi yaliyorekebishwa kwa kila toleo, yakiwemo marekebisho yaliyorejeshwa kwenye matoleo ya awali.

```text
!/bin/sh
```

## Hatari nyingine za sheria za sudo na doas

Anza na `sudo -l`, `sudo -V`, na sera yoyote ya `doas` inayotumika. Soma pamoja amri zinazoruhusiwa, mtumiaji wa RunAs, hoja, mazingira, na mipangilio ya chaguomsingi. Ruhusa ya kuendesha amri kama akaunti ya huduma isiyo root bado inaweza kufichua faili za akaunti hiyo au njia ya kufikia root.

Script ya Python iliyowekwa kuwa inaruhusiwa na sudo bado inaweza kuendesha amri ya shell chini ya utambulisho wake wa RunAs ikiwa ingizo shirikishi linalodhibitiwa na mpigaji simu litaunganishwa kwenye [`os.system()`](https://docs.python.org/3/library/os.html#os.system). Orodha ya kukataza alama za uakifishaji za shell haitoshi kuthibitisha usalama: [shell pia hutambua ubadilishaji wa amri wa `$(...)`](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html). Thibitisha kwamba hoja zinazoruhusiwa zinafika kwenye tawi la ingizo, kwamba ingizo linafika kwenye amri ya shell bila uthibitishaji salama, na kwamba sera ya sudo inayotumika inaruhusu mtumiaji wa RunAs aliyelengwa. Njia ya script au wito wa `os.system()` pekee ni kidokezo cha kukagua; kagua chanzo bila kuendesha script yenye upendeleo.

Ruhusa inayotumika ya root kupitia sudo kwa `chattr` inaweza kuondoa sifa ya faili isiyobadilika (`i`), lakini hilo pekee halitoi ruhusa ya kuandika wala utambulisho mpya. [Mwongozo wa `chattr`](https://man7.org/linux/man-pages/man1/chattr.1.html) unasema sifa hiyo huzuia marekebisho na ni root au mchakato wenye `CAP_LINUX_IMMUTABLE` pekee unaoweza kuibadilisha. Kagua sera halisi ya hoja za sudo na usaidizi wa mfumo wa faili, kisha thibitisha kivyake kwamba mpigaji simu anaweza kuandika faili baada ya sifa kuondolewa na kwamba mchakato wenye utambulisho wa juu huitumia. Kwa mfano, kubadilisha login shell pia kunahitaji akaunti lengwa ikubali vitambulisho hivyo na kuwe na login halisi kupitia shell hiyo. Kagua sera, sifa za faili, na ruhusa bila kuvibadilisha wakati wa uhesabuji.

Ikiwa sudo inaomba nywila na msimbo wa matumizi moja, zichukulie mahitaji hayo kando na ruhusa ya amri. Faili ya `.google_authenticator` inayosomeka ina nyenzo nyeti ya seed, ilhali hash ya zamani ya nywila ya programu au hifadhidata ni mgombea tu wa nywila ya akaunti ya sasa; hakuna kati ya hayo inayothibitisha kwamba kipengele kingine kinakubaliwa na usanidi wa PAM unaotumika. Baada ya kuidhinishwa, kagua RunAs na hoja halisi: ruhusa isiyo na vizuizi ya root kwa RubyGems `gem` inaweza kufichua amri yake ya editor ([GTFOBins](https://gtfobins.github.io/gtfobins/gem/)), lakini ruhusa yenye vizuizi au uthibitishaji ulioshindwa haiwezi. Uhesabuji wa kimyakimya unapaswa kuripoti njia na sera bila kuonyesha seed, kurejesha nywila, kuzalisha msimbo, au kuendesha amri yenye upendeleo.

Ruhusa isiyo na vizuizi ya sudo yenye uwezo wa root kwa `knife` ya Chef inastahili kukaguliwa katika kiwango cha interpreter: [Chef inaandika kwamba `knife exec -E` hutathmini string ya Ruby ndani ya kifaa](https://docs.chef.io/workstation/26/tools/knife/knife_exec/). Thibitisha kwamba sheria ya sudo inayotumika inaruhusu subcommand ya `exec` na hoja ya `-E` inayotolewa na mpigaji simu, utambulisho wa RunAs uliokusudiwa, na vizuizi vyovyote vya amri vinavyolingana au hoja zisizobadilika. Binary iliyosakinishwa au sheria iliyowekewa vizuizi kwa subcommands nyingine ni kidokezo tu. Uhesabuji wa kimyakimya unapaswa kuripoti sheria bila kuendesha `knife`.

Ruhusa halisi ya sudo yenye uwezo wa root kwa `msfconsole` shirikishi pia ni nyeti: [GTFOBins inaeleza console yake ya `irb`](https://gtfobins.org/gtfobins/msfconsole/), ambayo inaweza kurithi utambulisho wa sudo. Thibitisha mtumiaji wa RunAs anayefanya kazi, orodha ya hoja zinazoruhusiwa, vizuizi vya amri, `NOEXEC` au vizuizi vingine, tabia ya console iliyosakinishwa, na kama mpigaji simu anaweza kutoa ingizo shirikishi. Kuangaziwa kwa njia pekee ni kidokezo cha ukaguzi; uhesabuji wa kimyakimya haupaswi kuwasha console.

Kwenye FreeBSD, hata sheria ya sudo iliyowekewa kikomo kwa `pkg update` ya root na `pkg install *` inastahili kukaguliwa kwa uaminifu wa repository. Kagua kama mpigaji simu anaweza kuandika `/etc/hosts` na kama usanidi wa repository unaowezeshwa unaotumika *kwa kweli* unatumia jina la mwenyeji la HTTP lenye `signature_type: none`. [Mwongozo wa `pkg.conf` wa FreeBSD](https://man.freebsd.org/cgi/man.cgi?query=pkg.conf&sektion=5) unasema `none` huzima ukaguzi wa saini; `pkg+http` pekee haithibitishi hilo. [Package inaweza kuwa na install scripts](https://docs.freebsd.org/en/books/porters-handbook/pkg-files/), kwa hiyo mpigaji simu anayedhibiti endpoint ya repository na anayeweza kuchagua package anaweza kuvuka mpaka wa root. Thibitisha override za repository, uelekezaji wa SRV/mirror, hoja za sudo zinazotumika, uteuzi wa package, na utekelezaji wa script kabla ya kufikia hitimisho hilo. Kagua sera na faili ndogo za usanidi za ndani bila kuelekeza majina upya au kuendesha `pkg` wakati wa uhesabuji.

Ruhusa ya sudo yenye uwezo wa root kwa `apt-get update` na `apt-get upgrade` pia inahitaji kukaguliwa kwa uaminifu wa repository pale sudo inapohifadhi `http_proxy` inayodhibitiwa na mpigaji simu. Kagua kama usanidi wa APT unaotumika kwa kweli unatumia kigezo hicho na maombi gani ya repository yanayowezeshwa kinaweza kuathiri; proxy pekee haiwezi kubadilisha package kutoka kwenye archive iliyothibitishwa kwa ufunguo wa saini unaoaminika. [Mwongozo wa usafirishaji wa HTTP wa APT](https://manpages.debian.org/experimental/apt/apt-transport-http.1.en.html) unaeleza kipaumbele cha proxy, na [apt-secure](https://manpages.debian.org/experimental/apt/apt-secure.8.en.html) inaeleza ukaguzi wa saini, override za repository zisizo salama, na uthibitishaji wa package zisizothibitishwa. Thibitisha RunAs na hoja halisi za sudo, sera ya uthibitishaji wa repository, kukubali sharti lolote shirikishi, na kama upgrade iliyochaguliwa inaendesha package scripts kama root. Kagua sera na usanidi wa ndani kimyakimya; usielekeze upya trafiki ya package wala kuendesha upgrade wakati wa uhesabuji.

Sheria ya sudo yenye uwezo wa root kwa `snap install` inaweza kuvuka mpaka kati ya package na code ikiwa hoja zake zinamruhusu mpigaji simu kuchagua snap ya ndani na hali ya usakinishaji isiyo na vizuizi. [Snap inaandika](https://snapcraft.io/docs/explanation/snap-development/install-modes/) kwamba `--dangerous` huruka ukaguzi wa uthibitisho wa snap ya ndani na `--devmode` hurahisisha vizuizi; [install hook inaweza kuendeshwa wakati wa usakinishaji wa kwanza](https://snapcraft.io/docs/reference/development/supported-snap-hooks/). Kagua sera halisi ya hoja/RunAs ya sudo, nani anayedhibiti faili ya snap, kama hali hizi zinakubaliwa na snapd iliyosakinishwa, na utambulisho na vizuizi vinavyotumika kwa hook kabla ya kudai ufikiaji wa faili za host zilizolindwa. Binary ya `snap` au sheria inayoonekana kuwa na wildcard pekee haithibitishi mnyororo huu. Uhesabuji wa kimyakimya haupaswi kusakinisha package au kuendesha hook yake.

Kwa ruhusa halisi ya sudo kwa binary maalum ya kusoma vitambulisho ya akaunti **isiyo root**, kagua kwanza binary iliyopewa ruhusa na ruhusa zake za faili bila kuiendesha. Kizuizi cha nywila kilichopachikwa kinaweza kuonekana tu kama wide characters; [GNU `strings` inaandika kuhusu uchimbaji wa little-endian wa biti 16](https://sourceware.org/binutils/docs/binutils/strings.html). String inayoonekana haithibitishi kwamba ndiyo nywila inayokubalika au kwamba tawi la mafanikio hufichua kitambulisho cha sasa. Thibitisha tabia ya binary, ufikiaji wa akaunti lengwa kwa data iliyolindwa, uhalali wa kitambulisho, na mabadiliko yoyote ya baadaye ya akaunti au kundi kando. Ikiwa akaunti hiyo iko kwenye `docker`, thibitisha ufikiaji wa socket na utambulisho wa daemon wa rootful au rootless kabla ya kudhani ufikiaji wa root wa host; [Docker inaeleza athari za kiwango cha root za kundi lake](https://docs.docker.com/engine/install/linux-postinstall/). Uhesabuji wa kawaida unapaswa kuripoti sheria ya sudo na uanachama wa kundi bila kuendesha binary au kutoa strings zake.

Sheria ya sudo yenye wildcard kwa script za matengenezo za programu inahitaji ukaguzi unaozidi njia ya script. Kagua kama script inayoruhusiwa inakubali hoja zisizo na vizuizi au inasoma mipangilio inayoweza kuandikwa kupitia akaunti ya programu yenye upendeleo mdogo, kisha fuatilia thamani hizo hadi amri za shell au mazingira ya subprocess. Kwa mfano, ZoneMinder [`zmupdate.pl` hutengeneza amri ya `mysqldump` na kuitekeleza kupitia `qx`](https://github.com/ZoneMinder/ZoneMinder/blob/master/scripts/zmupdate.pl.in), huku [`zmdc.pl` ikinakili mipangilio ya `ZM_LD_PRELOAD` hadi `LD_PRELOAD`](https://github.com/ZoneMinder/ZoneMinder/blob/master/scripts/zmdc.pl.in) kabla ya kuwasha daemon. Sheria ya sudo inayoruhusu mojawapo ya script hizi kama root inaweza kuvuka mpaka wa uaminifu ikiwa ingizo husika linaweza kudhibitiwa na kufika kwenye code hiyo katika toleo lililosakinishwa. Kagua sheria halisi ya sudo, haki za usanidi wa programu, na chanzo cha script; wildcard au mpangilio pekee ni kidokezo cha ukaguzi, si uthibitisho wa utekelezaji.

- `SETENV`, `env_keep`, `secure_path`, na `LD_PRELOAD` vinaweza kubadilisha amri yenye vizuizi vinginevyo kuwa utekaji nyara wa import, library, au PATH. Angalia [mwongozo wa vigezo vya mazingira](../linux-basics/linux-environment-variables.md) na [matumizi mabaya ya SUID/linker](../interesting-files-permissions/suid-shared-library-and-linker-abuse.md).

Ruhusa halisi ya `SETENV` yenye uwezo wa root kwa shell wrapper pia inastahili ukaguzi wa hatua moja ikiwa wrapper inaanzisha script maalum ya Python yenye import halisi. `secure_path` hudhibiti utafutaji wa amri za shell, si [utafutaji wa moduli wa Python wa `PYTHONPATH`](https://docs.python.org/3/using/cmdline.html#envvar-PYTHONPATH); [`-E` na `-I`](https://docs.python.org/3/using/cmdline.html#cmdoption-E) hufanya Python ipuuze kigezo hicho cha mazingira. Thibitisha tag na vizuizi vinavyotumika vya sudo, tawi la wrapper, chaguo za interpreter, utatuzi wa import, na saraka ya utafutaji inayoweza kuandikwa na mpigaji simu kabla ya kuchukulia hili kama utekelezaji wa code. Kagua script fupi bila kuziendesha; usiendeshe wrapper yenye upendeleo.

Ruhusa halisi ya sudo ya `neofetch ""` yenye uwezo wa root bado inaweza kupakia usanidi wa shell ikiwa mipangilio ya chaguomsingi ya sudo inayotumika itahifadhi `XDG_CONFIG_HOME` inayodhibitiwa na mpigaji simu. [Kipakiaji usanidi cha Neofetch](https://github.com/dylanaraps/neofetch/blob/master/neofetch) hupakia `neofetch/config.conf` au `neofetch/config` chini ya saraka hiyo; orodha tupu ya hoja haizuii utafutaji huu. Thibitisha kipakiaji kilichosakinishwa, sera inayotumika ya RunAs na hoja, vizuizi vyovyote vya amri, kama sudo huhifadhi kweli kigezo kilichochaguliwa kwa amri hii, na kama mpigaji simu anadhibiti njia ya usanidi inayosomeka. Kigezo kilichohifadhiwa au Neofetch iliyosakinishwa pekee ni kidokezo cha ukaguzi. Kagua sera na metadata ya faili bila kuendesha amri yenye upendeleo au kuchapisha yaliyomo ya usanidi; angalia [ushughulikiaji wa mazingira wa sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf).

Sheria ya sudo isiyo na vizuizi yenye uwezo wa root kwa `facter` inastahili ukaguzi tofauti wa custom-fact. [Puppet inaandika](https://help.puppet.com/core/current/Content/PuppetCore/loading_custom_facts.htm) kwamba `--custom-dir` hupakia faili za Ruby fact kutoka saraka iliyochaguliwa. Kagua kama sheria halisi ya sudo inaruhusu chaguo hilo, kama Facter iliyosakinishwa inalikubali, na kama mpigaji simu anadhibiti saraka hiyo. Ruhusa yenye hoja zisizobadilika, katazo dhahiri la amri, au custom facts zilizozimwa zinaweza kubadilisha matokeo. Uhesabuji wa kimyakimya unapaswa kuripoti uwezekano wa sera bila kuendesha Facter au kusoma yaliyomo ya fact.

Kwa ruhusa halisi ya sudo ya script yenye uwezo wa root na `SETENV`, kagua majina tupu ya amri kama `find` na `PATH` inayotumika baada ya sera ya sudo na uanzishaji wa script. Faili ya Bash iliyosource pia inaweza kuendesha `enable -n [`: [Bash kisha hutafuta `[` ya nje katika `PATH`](https://www.gnu.org/software/bash/manual/html_node/Bash-Builtins.html) pale script inapotumia amri hiyo baadaye. Thibitisha [sheria za mazingira za sudoers na `secure_path`](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) zinazotumika, maingizo yoyote ya `NOSETENV`/`NOEXEC` au ya kukataza, mtiririko wa script na faili iliyosource, na saraka ya utafutaji inayoweza kutekelezeka na kudhibitiwa na mpigaji simu. Script inayosomeka yenye amri tupu ni kidokezo cha ukaguzi, si uthibitisho wa utekelezaji wenye upendeleo; ikague bila kutumia sheria ya sudo.
- Script yenye upendeleo inayopakua URL isiyobadilika kwa `curl` bado inaweza kupokea jibu lililochaguliwa na mpigaji simu ikiwa sheria ya sudo inayotumika huhifadhi `http_proxy` na ombi linatumwa kupitia proxy hiyo. Ikiwa script kisha hupitisha jibu kwa XML parser inayotatua external entities, jibu hasidi linaweza kufichua faili zinazosomeka na mchakato wenye upendeleo. Kagua sera halisi ya mazingira ya sudo, vizuizi vya `no_proxy`, URL inayoombwa, usanidi wa parser, na mahali matokeo yanapoandikwa; kigezo cha proxy au XML parser pekee si hatari ya kiusalama. Hati za [mazingira ya proxy ya curl](https://everything.curl.dev/usingcurl/proxies/env.html) zinaeleza tabia ya vigezo hivyo. Usitume maombi ya mtandao wala kuchanganua XML hasidi wakati wa uhesabuji wa kimyakimya.
- Script ya sudo yenye uwezo wa root inayounda faili ya PostScript kutokana na data iliyoathiriwa na mpigaji simu kisha kuendesha `ps2pdf -dNOSAFER` inastahili ukaguzi tofauti wa mtiririko wa ingizo. Ghostscript inaandika kwamba flag hii huzima SAFER hadi `.setsafe`, na kuruhusu shughuli za faili za PostScript ndani ya ruhusa za OS za mchakato. Hoja ya mtumiaji inayotumika kutengeneza SQL query inaweza kupitisha safu zinazodhibitiwa na mshambulizi kwenye template ya PostScript, lakini query string au wito wa `ps2pdf` pekee hauthibitishi kwamba data inafika kwenye sintaksia ya PostScript inayotekelezeka. Thibitisha sheria halisi ya sudo, njia kamili ya ingizo hadi template, escaping yoyote, tabia ya Ghostscript iliyosakinishwa, na kama SAFER inawashwa tena kabla hati haijatafsiriwa. Usifanye ubadilishaji wenye upendeleo wakati wa uhesabuji wa kimyakimya. Angalia [hati za Ghostscript za `-dNOSAFER`](https://ghostscript.readthedocs.io/en/master/Use.html).
- Kwa sheria ya sudo inayoendesha shell script, linganisha vigezo vilivyohifadhiwa na script yenyewe. Muundo kama `if $CHECK_CONTENT; then` huendesha thamani iliyopanuliwa kama amri, kwa hiyo kuhifadhi `CHECK_CONTENT` kunaweza kuruhusu utekelezaji wa amri hata kama njia na hoja za script hazibadiliki. Lazima uthibitishe kama tawi linafikiwa na kama mazingira yanahifadhiwa kweli kwa sheria husika.<sup>[[2]](#references)[[22]](#references)</sup>
- Script ya Python inayoruhusiwa na sudo inaweza ku-import code kutoka saraka inayoweza kuandikwa au faili ya `.pyc` iliyohifadhiwa kwenye cache. [Mwongozo wa privilege escalation](../linux-basics/linux-privilege-escalation/README.md) unaeleza hali ya cache.
- Script maalum ya Python inayoendeshwa kama root inaweza bado kufichua debugger shirikishi. Wito kama `pdb.set_trace()` au `pdb.post_mortem()` huruhusu kauli za Python katika muktadha wa mchakato unaochunguzwa wakati mpigaji simu anaweza kufikia breakpoint au exception handler **na kudhibiti mtiririko wa ingizo wa debugger**. Kagua sheria halisi ya RunAs ya sudo, uthibitishaji na masharti ya tawi, uwezekano wa kufikiwa kwa exception, umiliki wa terminal/ingizo, na kama debugger inaendeshwa ndani ya mchakato huo huo wenye upendeleo. Ombi la socket linalosababisha exception halitoi lenyewe ufikiaji wa debugger iliyounganishwa na terminal nyingine. [Python inaandika kuhusu tathmini ya kauli za debugger na hali ya post-mortem](https://docs.python.org/3/library/pdb.html); kagua script bila kuwasha handler yenye upendeleo wakati wa uhesabuji.

[Sehemu za uingizwaji zinaweza kufuata attributes na funguo za mapping](https://docs.python.org/3/library/string.html#format-string-syntax), kwa hiyo uga unaodhibitiwa na mshambulizi unaweza kukagua objects zilizopitishwa kwa `format()` na kufichua data inayoweza kufikiwa nazo ikiwa matokeo yatachapishwa au kuhifadhiwa mahali mpigaji simu anaweza kusoma. Kagua utambulisho wa RunAs unaotumika wa sudo, ruhusa ya kuandika rekodi husika, mtiririko wa data kuingia kwenye format string, objects zinazotolewa, na mwonekano wa matokeo. Hili si utekelezaji wa code wa moja kwa moja, na format string halisi inayoaminika yenye *values* zinazodhibitiwa na mshambulizi ni hali tofauti. Siri iliyofichuliwa huwa njia ya kubadili akaunti ya OS tu ikiwa akaunti hiyo inakubali siri hiyo. Kagua script na ruhusa za socket bila kuendesha operesheni yenye upendeleo.

GitPython iliongeza [kinga chaguomsingi dhidi ya protocol zisizo salama](https://github.com/gitpython-developers/GitPython/commit/2625ed9) katika toleo la 3.1.30; toleo la executable ya `git` ni jambo tofauti. Fuatilia kama hoja ya repository iliyochaguliwa na mpigaji simu inafika kwenye [`child_process.exec`](https://nodejs.org/api/child_process.html#child_processexeccommand-options-callback) ya Node.js au kijenzi kingine cha amri ya shell bila kutenganisha hoja kwa usalama; `exec` ya Node hutuma command string kwa shell. Thibitisha mtumiaji halisi wa RunAs, subcommands na hoja zinazoruhusiwa, code ya wrapper iliyosakinishwa, na uthibitishaji wa ingizo. Jina la zana ya repository au sheria ya sudo isiyo na vizuizi pekee havithibitishi sindikizo la amri. Kagua wrapper bila kuendesha clone yenye upendeleo wakati wa uhesabuji.
- Wrapper maalum inayomilikiwa na root inaweza kuonekana salama kwa sababu binaries na scripts zake haziandikiki, lakini uamuzi wake wa kuendesha kitendo chenye upendeleo unaweza kutegemea flag, thamani ya API ya ndani, au hali ya huduma ambayo mtumiaji asiye na upendeleo anaweza kubadilisha. Fuatilia kila sharti hadi kwenye ingizo lake na ukaguzi wa uidhinishaji. Wakati wa uhesabuji, kagua usanidi na ruhusa bila kubadilisha hali ya uendeshaji; wito wa `systemd-run` ndani ya wrapper ni muhimu tu ikiwa sharti hilo linaweza kuathiriwa.
- Client ya backup inayoruhusiwa kupitia sudo kama root inaweza kukubali faili ya usanidi iliyochaguliwa na mpigaji simu (kwa mfano, `npbackup-cli -c`). Kagua mtumiaji halisi wa run-as na hoja zinazoruhusiwa, kisha kama mpigaji simu anadhibiti njia ya usanidi, njia za chanzo cha backup, na chaguo za repository au usomaji/urejeshaji. Siri ya repository iliyosimbwa kwenye usanidi unaosomeka bado inaweza kutumiwa na client, lakini sheria pekee haithibitishi ufikiaji wa repository au ufichuaji wa faili za root. Thibitisha uidhinishaji bila kuendesha backup au kutoa yaliyomo yake.

[Wildcards za hoja za sudoers zinaweza kulingana na whitespace na slash](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf), kwa hiyo kagua wildcards za mwisho badala ya kudhani kwamba kiambishi awali kisichobadilika cha repository kinazuia chanzo. Ufunguo wa SSH uliohifadhiwa kwenye backup hutoa ufikiaji tu ikiwa akaunti lengwa inaukubali. Usifanye backup ili kujaribu hili wakati wa ukaguzi wa kimyakimya.
- Amri maalum isiyo na vizuizi ya matengenezo au backup inaweza kukubali njia ya matokeo au kuwa na kipanga kazi chake. Kwa njia ya kuandika faili, thibitisha sheria halisi ya sudo na mtumiaji wa run-as, kisha kama mpigaji simu anadhibiti data na lengwa. Kwa njia ya amri iliyopangwa, thibitisha utambulisho wa utekelezaji wa kipanga kazi, ingizo la amri, na sharti lolote la ziada la nywila au uidhinishaji. Jina la amri au `NOPASSWD` pekee havithibitishi njia yoyote. Angalia [kuandika kwenye faili zinazomilikiwa na root](../interesting-files-permissions/write-to-root.md) na [cron na systemd timers](../processes-crontab-systemd-dbus/cron-and-systemd-timers.md).
- Amri isiyobadilika ya sudo bado inaweza kupakia faili ya usanidi inayotabirika kutoka saraka ya pamoja inayoweza kuandikwa. Fuatilia kama mpigaji simu anaweza kubadilisha faili hiyo na kama sehemu zake za chanzo na lengwa zinadhibiti fetch au copy yenye upendeleo. URL ya faili ya ndani inaweza kufichua data inayosomeka na akaunti ya RunAs ya sudo pekee; chanzo kinachodhibitiwa na mpigaji simu pamoja na lengwa lililolindwa kinaweza kuunda njia ya kuandika. Thibitisha ushughulikiaji wa URL wa programu iliyosakinishwa, ukaguzi wa njia ya lengwa, sheria halisi ya sudo, na ufikivu wa matokeo. Njia ya usanidi inayoweza kuandikwa ndani ya `/tmp` pekee ni kidokezo cha ukaguzi, kwa hiyo kagua binary na metadata ya faili bila kuendesha uhamishaji wenye upendeleo.

[CVE-2023-23946](https://github.com/git/git/security/advisories/GHSA-r87m-v37r-cwfh) iliruhusu patch iliyotengenezwa kuunda symlink na kisha kuandika nje ya working tree, hata kama amri haikukubali `--unsafe-paths`. Kagua sheria halisi ya hoja za sudo, chanzo cha patch, ufikiaji wa working directory kwa akaunti ya RunAs, na marekebisho ya Git iliyosakinishwa au vendor backport. Sheria isiyo na vizuizi inayokubali `--unsafe-paths` ni hatari tofauti ya chaguo hilo; toleo la Git au ruhusa ya `git apply` pekee havithibitishi kwamba faili iliyolindwa inaweza kubadilishwa. Usitumie patch isiyoaminika wakati wa uhesabuji wa kimyakimya.
- Sheria yenye uwezo wa root ya `clamscan --debug` inaweza kuvuka mpaka wa usomaji ikiwa mtumiaji mwenye upendeleo mdogo anaweza kutoa picha ya DMG na parser iliyosakinishwa imeathiriwa na [CVE-2023-20052](https://blog.clamav.net/2023/02/clamav-01038-01052-and-101-patch.html), ambayo ingeweza kufichua yaliyomo ya faili kupitia matokeo ya debug. Thibitisha hoja halisi zinazoruhusiwa na njia ya kuchanganua, udhibiti wa ingizo, akaunti inayotumika ya RunAs, marekebisho ya engine/backport, na kama mpigaji simu anaweza kuona matokeo. Ikiwa sheria pana inaruhusu `--file-list`/`-f`, kagua tabia ya orodha hiyo kando; sera iliyowekewa `--debug <scan-path>` haikubali chaguo hilo. Kagua sera na metadata ya package bila kuchanganua faili iliyotengenezwa au kuchapisha matokeo yaliyolindwa wakati wa uhesabuji.
- Sheria yenye uwezo wa root ya sudo inayofungua picha ya diski iliyosimbwa iliyochaguliwa na mpigaji simu, pamoja na sheria ya pili inayoweka mapper iliyozalishwa, inaweza kuingiza faili zinazodhibitiwa na mpigaji simu kwenye mount namespace ya host. Thibitisha sheria zote mbili zinazotumika na hoja zake, udhibiti wa picha na jina la mapper, mount target halisi, na mmiliki na mode ya faili zinazozalishwa. Mabadiliko ya set-user-ID pia yanahitaji executable inayofikika, chaguo za mount zinazoruhusu ( `nosuid` huzuia hilo), na sera inayotumika ya mchakato au MAC; kufungua au kuweka picha pekee ni kidokezo cha ukaguzi. Njia tofauti kupitia backup iliyopo inahitaji ufunguo wake halisi na siri muhimu inayosomeka ndani yake. Kagua sera na njia bila kufungua au kuweka picha wakati wa uhesabuji wa kimyakimya. Angalia [mwongozo wa cryptsetup](https://gitlab.com/cryptsetup/cryptsetup/-/blob/main/man/cryptsetup.8.adoc) na [chaguo za mount](https://man7.org/linux/man-pages/man8/mount.8.html).
- Sheria ya sudo yenye uwezo wa root kwa shell au script ya Python inastahili ukaguzi wa working directory ikiwa script inaendesha `./helper` bila kwanza kuhamia kwenye saraka isiyobadilika. Orodha ya Python kama `['./helper']` inayopitishwa kwa `subprocess.run` inaweza kuwa na tabia hiyo hiyo ya working directory iliyochaguliwa na mpigaji simu. Mpigaji simu anaweza kuchagua saraka inayoweza kuandikwa na kuweka executable yenye jina hilo la relative humo; njia kamili mahali pengine kwenye script hailindi wito huu. Thibitisha sheria halisi, `runchdir` au sera nyingine ya kubadilisha saraka, mtiririko wa script na kufikiwa kwa tawi, saraka inayoweza kuandikwa na kutekelezeka, na vizuizi vya mount/`NOEXEC` kabla ya kuchukulia hili kama utekelezaji wa code. Script isiyosomeka huacha tabia hiyo bila kujulikana hadi chanzo chake kikaguliwe kupitia njia iliyoidhinishwa. Kagua script bila kuendesha helper. [Mwongozo wa sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) unaeleza sera ya working directory.

[Hati za Python za `eval()` zinaonya dhidi ya ingizo lisiloaminika](https://docs.python.org/3/library/functions.html#eval): ukaguzi wa kiambishi awali, kiambishi awali cha hesabu, au tawi la uthibitishaji si sandbox ikiwa usemi uliobaki unafika kwenye `eval`. Thibitisha sheria halisi ya sudo, kama mpigaji simu anaweza kuchagua na kudhibiti faili husika, masharti ya tawi la parser na uundaji wa usemi, na utambulisho wa mchakato wenye upendeleo kabla ya kuiita njia ya utekelezaji. Uwepo wa `eval` kwenye script inayosomeka ni kidokezo cha ukaguzi tu; kagua chanzo na ruhusa za faili bila kuendesha validator au kuwasilisha usemi wa majaribio wakati wa uhesabuji.
- Ruby wrapper yenye uwezo wa root kupitia sudo inayosoma jina relative la YAML, kama `YAML.load(File.read("dependencies.yml"))`, inaweza kupokea ingizo kutoka working directory ya mpigaji simu isipokuwa wrapper au sera ya sudo iweke saraka hiyo isibadilike. Kagua hoja halisi zinazoruhusiwa, ruhusa za saraka na faili, na tabia ya Psych iliyosakinishwa: matoleo ya zamani ya `YAML.load` yangeweza kurejesha objects zozote za Ruby, ilhali matoleo mapya huzuia classes kwa chaguomsingi. Sehemu ya wito tuli ni kidokezo cha ukaguzi tu; thibitisha kwamba faili kweli inatoka saraka inayoweza kuandikwa na mpigaji simu na kwamba loader iliyosakinishwa inakubali classes hatari. Pendelea `safe_load` yenye allowlist ndogo na dhahiri ya class kwa ingizo lisiloaminika. Angalia [hati za Ruby 3.0 Psych](https://docs.ruby-lang.org/en/3.0/Psych.html) na [hati za Ruby 3.1 Psych](https://ruby-doc.org/core-3.1.2/Psych.html).

- Ruhusa halisi ya root kupitia `sudo go run /absolute/file.go` inastahili ukaguzi wa working directory pale chanzo cha Go kinaposoma faili ya WASM relative na kinaweza kuendesha shell script relative baada ya kuchunguza matokeo yake. Thibitisha RunAs inayotumika, hoja za amri na vizuizi, current directory inayoweza kuandikwa na mpigaji simu, mtiririko wa data wa WASM hadi tawi, na kama tawi hilo huendesha helper. Sudo `runchdir` isiyobadilika, `os.Chdir`, au [`exec.Cmd.Dir`](https://pkg.go.dev/os/exec) zinaweza kubadilisha mahali pa utafutaji. Kutokea pamoja kwenye chanzo tuli ni mgombea tu; kagua chanzo bila kuendesha Go, WASM, au helper.
- `sudoedit` na wildcards za hoja zinahitaji ukaguzi wa toleo na sheria halisi; [checklist](linux-privilege-escalation-checklist.md) inajumuisha tatizo la kuhariri faili kupitia sudoedit. Kwa ruhusa ya `sudoedit` ya kuvuka watumiaji kwenye njia yenye wildcard, kagua mpangilio unaotumika wa `sudoedit_follow` au `FOLLOW`, `sudoedit_checkdir`, lengwa lililotatuliwa, na nani anayeweza kubadilisha kila ingizo la parent. Ya kwanza inaweza kuruhusu kufuata symlink, huku kuzima ya pili kukiondoa ukaguzi wa saraka zinazoweza kuandikwa; hakuna mpangilio unaothibitisha peke yake uandishi kwenye faili ya mtumiaji mwingine. Thibitisha sera ya sudo iliyosakinishwa na hoja halisi zinazolingana kabla ya kufikia hitimisho hilo. Angalia [ufafanuzi wa chaguo za sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf).

Sheria ya amri yenye uwezo wa kusoma na hoja kama `/restricted/*` inaweza kwa hiyo kuruhusu hoja ya ziada ya faili baada ya kiambishi awali kinacholingana. Kagua mtumiaji halisi wa run-as, njia ya amri, muundo wa hoja, na vizuizi vya baadaye; kusoma faili kumethibitishwa hakumaanishi utekelezaji wa amri. [Mwongozo wa sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) unatofautisha glob za hoja na glob za njia ya amri.

Kagua hoja halisi za sudo na vizuizi, toleo la qpdf, ufikiaji wa chanzo, na njia ya matokeo kabla ya kuhitimisha kwamba ufichuaji wa faili unawezekana. Kusoma ufunguo wa SSH wa root husaidia kuingia tu ikiwa ufunguo huo ni halali na uthibitishaji wa SSH wa root unaruhusiwa. ### Zana za build na package zinazoendeshwa kupitia sudo

Ruhusa isiyo na vizuizi ya sudo kwa `forge` ya Foundry inaweza kuwa na athari hata kama utambulisho wa RunAs ni mtumiaji mwingine asiye root. Chaguo za compiler kama `--use` zinaweza kuchagua executable ya ndani, na `forge flatten -o` huchagua faili ya matokeo. Kagua toleo la Forge lililosakinishwa, hoja halisi za sudo, project na njia za compiler zinazofikika, ruhusa za matokeo, na mazingira yanayotumika kabla ya kuchukulia ruhusa hiyo kuwa inaweza kutumiwa vibaya. Executable ya helper relative inayopatikana kupitia `PATH` ni njia inayotegemea toleo na mazingira, si tabia ya kudhaniwa kwa kila Forge build.<sup>[[23]](#references)[[24]](#references)</sup>

Ruhusa isiyo na vizuizi yenye uwezo wa root ya `pacman` inaruhusu zaidi ya maswali ya package: `-U` hukubali package ya ndani, package zinaweza kuwa na install scripts, na `--hookdir` huchagua saraka nyingine ya hook. Kagua sheria halisi ya sudo, vizuizi na vizuizi vya hoja kabla ya kujaribu; uhesabuji wa kimyakimya hauhitaji kusakinisha package au kuendesha hook.<sup>[[25]](#references)[[26]](#references)</sup>

Shell wrapper isiyobadilika ya sudo inaweza pia kusakinisha utegemezi wa npm uliotajwa kisha kuwasha programu ya Node. Kagua sheria yake halisi ya RunAs, kama package tayari imesakinishwa, `HOME` na `userconfig` za npm zinazotumika, usanidi wa project au override za command-line, na kama mtumiaji mwenye upendeleo mdogo anadhibiti registry au package inayopatikana kwa jina hilo. [npm inaandika kuhusu utafutaji wa `.npmrc` wa kila mtumiaji na kila project](https://docs.npmjs.com/cli/v6/configuring-npm/npmrc/); tabia ya `HOME` ya sudo hutegemea sera na distribution iliyosakinishwa, kwa hiyo `.npmrc` ya mtumiaji inayoweza kuandikwa inaweza kusomwa au kutosomwa na mchakato wa npm wenye upendeleo. Ikiwa package mpya iliyosakinishwa ita-importiwa na programu yenye upendeleo, module code yake inaweza kuendeshwa chini ya utambulisho wa programu hiyo. Install scripts ni njia tofauti inayotegemea toleo na usanidi; [npm inaandika kuhusu lifecycle na ushughulikiaji wa mtumiaji wake](https://docs.npmjs.com/cli/v6/using-npm/scripts/). Njia ya `.npmrc` au mstari wa `npm install` pekee ni kidokezo cha ukaguzi. Kagua sheria, wrapper fupi, njia za usanidi, na chanzo cha package bila kusakinisha au kuwasha programu wakati wa uhesabuji wa kimyakimya.

Ruhusa yenye uwezo wa root ya `pip` au `pip3 download` pia ni kidokezo cha kukagua package build ikiwa hoja zake zinamruhusu mpigaji simu kuchagua source distribution isiyoaminika, hata kama muundo wa URL unaiwekea kikomo kwenye huduma ya ndani na kiambishi tamati cha `.tar.gz`. `pip download` hukubali URL za archive na kutatua metadata ya package; kuandaa sdist kunaweza kuendesha build backend yake au code ya zamani ya `setup.py` kabla archive haijahifadhiwa tu. Thibitisha RunAs na sheria halisi ya hoja za sudo, kama mpigaji simu anaweza kuchapisha au kubadilisha archive iliyochaguliwa, na kama toleo hilo la pip kweli huandaa metadata yake. Archive au wheel inayoaminika isiyobadilika haithibitishi njia hii. Usipakue au kujenga package isiyoaminika wakati wa uhesabuji wa kimyakimya. Angalia [amri ya download ya pip](https://pip.pypa.io/en/stable/cli/pip_download/), [kiolesura cha build-system](https://pip.pypa.io/en/stable/reference/build-system/), na [mwongozo wa usakinishaji salama](https://pip.pypa.io/en/stable/topics/secure-installs/).

Sheria ya sudo inayoruhusu `pip install` yenye njia ya local project iliyochaguliwa na mpigaji simu ina mpaka wa build ulio wazi zaidi. [pip hukubali saraka za local project](https://pip.pypa.io/en/stable/topics/local-project-installs/) na kuendesha build system zake; [build backend huendesha build hooks zinazodhibitiwa na project](https://pip.pypa.io/en/stable/reference/build-system/). Thibitisha utambulisho wa RunAs unaotumika, vizuizi halisi vya hoja na vizuizi vya amri, udhibiti wa project iliyochaguliwa, na tabia ya pip/backend iliyosakinishwa kabla ya kuchukulia sheria hiyo kama utekelezaji wa code wenye upendeleo. Project inayoaminika isiyobadilika au sheria inayokataza njia zilizochaguliwa na mpigaji simu haithibitishi njia hii. Kagua sheria na metadata ya project bila kusakinisha package wakati wa uhesabuji wa kimyakimya.

Ruhusa isiyo na vizuizi yenye uwezo wa root ya `easy_install` ni kidokezo kingine kinachohusiana na package build ya zamani. [Setuptools inaandika](https://setuptools.pypa.io/en/stable/deprecated/easy_install.html) kwamba Easy Install hukubali saraka ya local project na kujenga source distributions; project inayodhibitiwa na mpigaji simu inaweza kuendesha `setup.py` yake wakati wa build hiyo chini ya utambulisho wa sudo. Thibitisha akaunti halisi ya RunAs, amri na vizuizi halisi vya hoja (pamoja na vizuizi vya baadaye), udhibiti wa project iliyochaguliwa, na tabia ya zana iliyosakinishwa. Project inayoaminika isiyobadilika au sera isiyoruhusu chanzo kilichochaguliwa na mpigaji simu haithibitishi njia hii. Kagua sheria na metadata ya project bila kusakinisha package wakati wa uhesabuji.

Python wrapper inayoruhusiwa na sudo na kutumia `setuptools.package_index.PackageIndex.download` yenye URL iliyochaguliwa na mpigaji simu ni hali tofauti ya ukaguzi na `pip download`: [setuptools GHSA-5rjg-fvgr-3xxf](https://github.com/pypa/setuptools/security/advisories/GHSA-5rjg-fvgr-3xxf) inaeleza jina la faili lililotokana na URL kukwepa saraka iliyokusudiwa ya upakuaji na kuandika kwa ruhusa za mchakato katika matoleo yaliyoathiriwa kabla ya 78.1.1. Thibitisha RunAs na sheria halisi ya hoja za sudo, kwamba wrapper hupitisha URL ya mpigaji simu kwa API hii hasa, build ya package iliyosakinishwa au vendor backport, na mahali njia inayozalishwa inapotatuliwa. String ya toleo au saraka ya upakuaji inayoweza kuandikwa pekee haithibitishi uandishi holela. Kagua wrapper fupi na metadata ya package bila kufetch URL au kuandika faili wakati wa uhesabuji.

Wrapper ya build inayoruhusiwa na sudo inayopitisha faili ya `.spec` iliyochaguliwa na mpigaji simu kwa PyInstaller inahitaji ukaguzi huo huo wa mpaka wa uaminifu. PyInstaller spec ni Python inayotekelezeka inayotathminiwa wakati wa **build**, na maingizo yake ya `datas` yanaweza kujumuisha kwenye artifact faili zinazosomeka na utambulisho wa build. Thibitisha mtumiaji halisi wa RunAs, sheria za hoja na vizuizi vya sudo, ushughulikiaji wa njia na matawi wa wrapper, udhibiti wa faili ya spec iliyochaguliwa, na ufikiaji wa artifact inayotokana. Kuruhusu ingizo la `.py` tu au kugundua PyInstaller ikiwa imesakinishwa hakuthibitishi udhibiti wa spec-file au utekelezaji wenye upendeleo. ### Wildcards za hoja kwenye zana za packet zenye upendeleo

Thibitisha sheria halisi ya sudo, build iliyosakinishwa, tabia ya kuondoa upendeleo, na kama mzunguko unaweza kutokea kabla ya kuchukulia sheria hiyo kama njia ya escalation. ### Python imports zinazoendeshwa kupitia sudo chini ya akaunti nyingine

Kagua faili na ruhusa bila ku-import au kuendesha script wakati wa uhesabuji.<sup>[[2]](#references)[[3]](#references)</sup>

Sheria halisi ya sudo ya `python3 /absolute/script.py` inahitaji tu script iweze kusomeka; faili haihitaji kuwa executable au kuwa na shebang. Kagua pia module za ndani **zinazokosekana**: ikiwa script ina-import module ambayo jina lake la faili linaweza kuundwa kwenye saraka ya script inayoweza kuandikwa na mpigaji simu, Python inaweza kupakia faili hiyo chini ya utambulisho wa RunAs. Thibitisha sheria halisi ya sudo, [njia halisi ya utafutaji wa module](https://docs.python.org/3/library/sys_path_init.html) ya interpreter, kama module hiyo imejengwa ndani au kufungwa kwenye binary, na kama import hiyo inafikiwa. Sheria ya sudo ya moja kwa moja kwa script ina mahitaji tofauti ya execute-bit na shebang. Wrapper tofauti inayoongeza tokens zilizotolewa na mpigaji simu baada ya `sudo -u account` pia inahitaji ukaguzi wa mtiririko wa hoja: `-u` nyingine ndani ya tokens hizo ni muhimu tu ikiwa sera ya sudo inaruhusu utambulisho unaotokana. Strings tuli pekee hazithibitishi njia yoyote kati ya hizo.

### Apache inayoendeshwa kupitia sudo yenye usanidi unaodhibitiwa na mpigaji simu

Ikiwa sheria ya sudo inaruhusu `apachectl`, `apache2ctl`, au `httpd` yenye upendeleo pamoja na faili ya usanidi ya `-f` inayodhibitiwa na mpigaji simu, kagua ruhusa za faili hiyo na parent directory yake. Directive ya Apache [`LoadModule`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadmodule) hukubali jina la module likifuatiwa na **jina la faili ya module**; [`LoadFile`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadfile) pia hupakia faili. [`Include` na `IncludeOptional`](https://httpd.apache.org/docs/2.4/mod/core.html#include) zinaweza kupanua usanidi au kufichua yaliyomo ya faili kupitia errors. Custom wrapper inaweza kuthibitisha njia hizi, kuondoa upendeleo, au kuzuia hoja, kwa hiyo usanidi unaoweza kuandikwa ni mgombea wa ukaguzi, si uthibitisho wa utekelezaji wa code. Kagua usanifishaji wa njia, symlinks, na uchanganuzi wa directives kabla ya kufikia hitimisho.

### nginx inayoendeshwa kupitia sudo yenye usanidi unaodhibitiwa na mpigaji simu

Sheria isiyo na vizuizi yenye uwezo wa root ya `nginx` inaweza kuruhusu [`-c` kuchagua usanidi mwingine](https://nginx.org/en/docs/switches.html). Kagua hoja halisi za sudo na vizuizi, kama mpigaji simu anaweza kutoa usanidi, na kama master au workers wanaotokana nao huhifadhi ufikiaji wa njia zilizolindwa. `root` iliyochaguliwa pamoja na `autoindex` inaweza kufichua faili kupitia listener mpya; [`dav_methods PUT`](https://nginx.org/en/docs/http/ngx_http_dav_module.html) inaweza kutoa njia ya kuandika faili yenye upendeleo, lakini DAV module haijengwi kwa chaguomsingi na uwepo wake, ufikivu wa listener, ruhusa za faili, na tabia ya temporary-file lazima vikaguliwe. Directive ya [`error_log`](https://nginx.org/en/docs/ngx_core_module.html#error_log) pia inaweza kulenga faili iliyochaguliwa; kuandika log kwenye faili nyeti ya usanidi, kama `/etc/ld.so.preload`, kunahitaji mwandishi mwenye upendeleo anayetumika na rekodi ya log inayoweza kudhibitiwa kabla haijawa njia ya escalation. Kuangaziwa kwa executable katika `sudo -l` ni kidokezo cha ukaguzi, si uthibitisho kwamba njia yoyote kati ya hizi inafanya kazi. Uhesabuji wa kimyakimya haupaswi kuwasha au kusanidi upya nginx.

### Ulinganishaji wa pattern kwenye Bash prompt zenye upendeleo

Script ya Bash inayoruhusiwa na sudo inaposoma thamani kutoka kwa mpigaji simu na kuikagua kwa `[[ "$expected" == $entered ]]`, Bash hutafsiri operand ya upande wa kulia isiyonukuliwa kama pattern. Kwa hiyo wildcard inaweza kukidhi ulinganisho bila kujua thamani inayotarajiwa. Kunukuu operand (`[[ "$expected" == "$entered" ]]`) hufanya ulinganisho wa string halisi. Kagua sheria halisi ya sudo, kama prompt inafikiwa, na script hufanya nini baada ya ulinganisho; sintaksia pekee haithibitishi njia inayoweza kutumiwa vibaya. Epuka kuchapisha thamani inayotarajiwa wakati wa uhesabuji. Angalia [marejeleo ya Bash conditional constructs](https://www.gnu.org/software/bash/manual/html_node/Conditional-Constructs.html).

### Helpers zinazoendeshwa kupitia sudo zinazopakua na kuendesha faili

Ruhusa isiyo na vizuizi yenye uwezo wa root ya sudo kwa helper maalum inastahili ukaguzi wa mtiririko wa data ikiwa inakubali URL iliyochaguliwa na mpigaji simu, inaandika jibu kwenye diski, na baadaye inaendesha faili hiyo kwa interpreter au shell. [Sudoers huruhusu hoja zozote ikiwa ingizo la amri haliorodheshi hoja](https://man7.org/linux/man-pages/man5/sudoers.5.html); njia isiyobadilika ya executable haizuii kile ambacho hoja zake zinaweza kuchagua. Thibitisha uthibitishaji halisi wa URL, njia ya matokeo, tawi la mafanikio, na utekelezaji unaofuata katika helper iliyosakinishwa. Import inayolingana ya libcurl au string inayochapishika pekee haithibitishi mnyororo huu.

Hata jina lisilobadilika la faili ya matokeo linaweza kubadilishwa kati ya uandishi na utekelezaji wakati helper inatumia **njia relative ndani ya working directory inayodhibitiwa na mpigaji simu**. Kubadilisha jina au kuweka faili nyingine badala ya faili inayomilikiwa na root hutegemea ufikiaji wa kuandika na kutafuta saraka pamoja na vizuizi vyovyote vya sticky bit, si mode ya faili pekee; angalia [`rename(2)`](https://man7.org/linux/man-pages/man2/rename.2.html). Kagua kama helper baadaye hufungua upya njia hiyo au hutumia file descriptor ambayo tayari imefunguliwa, na kama huhamia kwenye saraka inayoaminika kabla ya kuandika. Kagua sera ya sudo, helper, na metadata ya saraka kimyakimya; usiendeshe upakuaji wenye upendeleo au shindano wakati wa uhesabuji.

Helper ya upakuaji inayotumia sudo kama root inaweza pia kufichua sindikizo la **hoja** inapojenga string ya amri ya Bash kama `curl <caller input> -o <fixed output>`. Kichujio kinachokataa whitespace bado huacha [brace expansion ya Bash](https://www.gnu.org/software/bash/manual/html_node/Brace-Expansion.html): vipengele vilivyotenganishwa kwa koma na visivyonukuliwa vinaweza kuwa hoja tofauti za curl. Ikiwa ingizo linafika curl kabla ya `-o` isiyobadilika, chaguo la output lililotolewa na mpigaji simu linaweza kuchagua lengwa la URL ya kwanza chini ya utambulisho wa helper; [curl huhusisha chaguo za output na URL kwa mpangilio](https://curl.se/docs/manpage.html#-o). Thibitisha shell halisi, quoting, uthibitishaji wa ingizo, sheria halisi ya sudo, mpangilio wa hoja za curl na URL schemes zinazokubaliwa, na kama mpigaji simu anadhibiti baiti zilizopakuliwa au anaweza kusoma matokeo. Executable iliyofungwa na PyInstaller inaweza kuwa na mantiki ya programu ya Python, lakini alama ya packaging au string ya `curl` pekee haithibitishi mtiririko huu wa data. Kagua nakala ndogo ya offline ikiwa umeidhinishwa; uhesabuji wa kawaida haupaswi kuendesha helper au kupakua data iliyochaguliwa na mshambulizi.

Shell script inayotumia sudo kama root na kuita [`mktemp -u` / `--dry-run`](https://www.gnu.org/software/coreutils/manual/html_node/mktemp-invocation.html) huchagua jina lisilotumika tu; **haiundi** faili. Ikiwa script baadaye itaunda jina hilo kwenye saraka ambayo mtumiaji mwingine anaweza kuathiri, kisha kuifungua tena na kuongeza yaliyomo kwenye lengwa lililolindwa kama `authorized_keys` ya root, kagua uwezekano wa shindano la temporary-file. Thibitisha sheria halisi ya sudo, umiliki wa saraka na faili, mfuatano wa uundaji na ufunguaji upya, kinga za kernel, na kama uandishi wenye upendeleo kweli hutumia baiti zinazodhibitiwa na mshambulizi. String ya `mktemp -u` au `/tmp` inayoweza kuandikwa pekee haithibitishi shindano hilo. Kagua script na metadata ya njia bila kuiendesha au kushindania faili yake ya muda wakati wa uhesabuji.

## Vidokezo vya kujilinda

- Epuka kuruhusu interpreters au interactive editors kupitia sudo.<sup>[[1]](#references)</sup>

- Ikiwa interpreter haiwezi kuepukwa, weka vizuizi kwa njia halisi ya script na uzuie hoja zinazodhibitiwa na mtumiaji, imports zinazoweza kuandikwa, `PYTHONPATH`, na uhifadhi usio salama wa mazingira.<sup>[[2]](#references)[[3]](#references)[[4]](#references)</sup>
- Ikiwa kuhariri faili kunahitajika, weka vizuizi kwa njia halisi ya faili na zingatia `sudoedit` pamoja na matoleo ya sudo yaliyorekebishwa na ushughulikiaji mkali wa mazingira.<sup>[[1]](#references)[[2]](#references)</sup>
- Kagua `SETENV`, `env_keep`, working directories zinazoweza kuandikwa, module/import paths zinazoweza kuandikwa, `NOEXEC`, `use_pty`, na logging, lakini usizichukulie kama sandbox kamili.<sup>[[1]](#references)[[2]](#references)[[3]](#references)</sup>
