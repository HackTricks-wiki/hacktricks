## Interpreteri dozvoljeni kroz sudo

Ako `sudo -l` dozvoljava korisniku da pokrene interpreter kao root, tretirajte to kao direktno izvršavanje koda. Interpreteri su namenjeni izvršavanju proizvoljnog koda, pa je pravilo koje dozvoljava `python3`, `perl`, `ruby`, `lua`, `node` ili slične binarne datoteke obično ekvivalentno izvršavanju komandi kao root, osim ako su argumenti strogo ograničeni i provereni.<sup>[[1]](#references)[[2]](#references)[[3]](#references)[[4]](#references)[[5]](#references)[[7]](#references)[[9]](#references)[[11]](#references)</sup>

Uobičajeni tok provere: prvo izlistajte korisnikove privilegije, a zatim izvršite Python naredbu pomoću opcije `-c` interpretera.<sup>[[1]](#references)[[3]](#references)[[4]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/python3 -c 'import os; os.system("id")'
sudo /usr/bin/python3 -c 'import os; os.system("/bin/sh")'
```

Primeri drugih interpretera prikazani su u nastavku; dokumentacija navedenih interpretera opisuje izvršavanje koda direktno u interpreteru ili API-je za pokretanje podređenih procesa.<sup>[[5]](#references)[[6]](#references)[[7]](#references)[[8]](#references)[[9]](#references)[[10]](#references)[[11]](#references)</sup>

```bash
sudo /usr/bin/perl -e 'exec "/bin/sh";'
sudo /usr/bin/ruby -e 'exec "/bin/sh"'
sudo /usr/bin/node -e 'require("child_process").spawn("/bin/sh", {stdio: [0,1,2]})'
```

Tačna putanja je važna. Ako sudo pravilo dozvoljava `/usr/bin/python3`, koristite tu tačnu putanju tokom provere.<sup>[[2]](#references)</sup>

Glob za sudo izvršnu datoteku, kao što je `/usr/bin/python*`, može da dozvoli i Python 2 za skriptu napisanu za Python 3. Ako skripta dođe do `input()` sa tekstom koji kontroliše pozivalac, [Python 2 taj tekst evaluira kao izraz](https://docs.python.org/2/library/functions.html#input); eksplicitno pozivanje interpretera ima prednost nad shebang linijom skripte. Pre nego što ovo smatrate putem za izvršavanje koda, proverite instalirane binarne datoteke koje se podudaraju, efektivni RunAs i pravila za argumente, odbijanja i dostupnost ulaza.

Fiksna putanja skripte u sudo pravilu koje može da radi kao root ne ograničava ono što skripta izvršava. Za čitljivu Bash omotnicu proverite da li njena prva izvršna komanda koristi necitiran pozicioni parametar, kao što je `$1`, kao **reč komande**, dok sudo dozvoljava argumente koje bira pozivalac. Potvrdite efektivni RunAs identitet, pravila za lozinku i argumente, kasnija odbijanja i stvarnu granu skripte; `NOEXEC`, fiksna bezbedna lista argumenata ili omotnica koja proverava komandu mogu da promene ishod. Tokom enumeracije statički pregledajte kratku skriptu umesto da je pozivate sa probnom komandom.

Neograničeno sudo pravilo za `dotnet` koje može da radi kao root takođe treba proveriti sa stanovišta interpretera. Ako je instaliran .NET SDK, [`dotnet fsi` izvršava F# kod interaktivno ili iz skripte](https://learn.microsoft.com/en-us/dotnet/fsharp/tools/fsharp-interactive/), a [`dotnet run` izvršava projekat iz izvornog koda](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-run). Najpre potvrdite efektivni RunAs identitet i tačna pravila za argumente: pravilo ograničeno na određenu bezbednu podkomandu ili pouzdanu aplikaciju predstavlja drugačiju dozvolu, a instalacija koja sadrži samo runtime možda nema SDK komande. Sam naziv izvršne datoteke ukazuje na nešto što treba proveriti, ali nije dokaz izvršavanja koda.

```bash
sudo /usr/bin/python3 -c 'import os; os.setuid(0); os.setgid(0); os.system("/bin/sh")'
```

## Uređivači dozvoljeni kroz sudo

Ako `sudo -l` dozvoljava korisniku da pokrene interaktivni uređivač kao root, tretirajte ga kao površinu za izvršavanje komandi, a ne kao bezopasnu dozvolu za uređivanje datoteka. Uređivači često mogu da izvršavaju shell komande, čitaju proizvoljne datoteke, upisuju proizvoljne datoteke ili pozivaju spoljne pomoćne programe iz samog uređivača.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

Uobičajeni postupak provere: navedite korisnikove privilegije, a zatim pokrenite svaki dozvoljeni uređivač ili pager kroz sudo.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/nano /etc/hosts
sudo /usr/bin/vim /etc/hosts
sudo /usr/bin/less /etc/hosts
```

### Izvršavanje komandi pomoću Nano-a

Kada je `nano` dozvoljen preko sudo-a, izvršavanje komandi može biti dostupno iz interfejsa editora.<sup>[[12]](#references)</sup>

```text
Ctrl+R
Ctrl+X
```

Zatim unesite komandu kao što je `id` ili `/bin/sh` u komandni prompt programa nano.<sup>[[12]](#references)</sup>

```bash
id
/bin/sh
```

Ako interaktivna ljuska nema upotrebljive terminalne tokove, ovaj oblik preusmeravanja mapira njen standardni izlaz i greške na deskriptor 0.<sup>[[15]](#references)</sup>

```bash
reset; /bin/sh 1>&0 2>&0
```

Tačan niz tastera može da se razlikuje u zavisnosti od verzije nano-a i opcija za izgradnju, ali bezbednosni problem je isti: uređivač radi kao root i može da poziva spoljne komande.<sup>[[1]](#references)[[12]](#references)</sup>

### Drugi česti izlazi iz uređivača

Uređivači u stilu Vim-a obično omogućavaju izvršavanje komandi pomoću `:!`.<sup>[[13]](#references)</sup>

```text
:!/bin/sh
```

Programi za prikaz stranica kao što je `less` takođe mogu da omoguće pokretanje shell-a.<sup>[[14]](#references)</sup>

Sudo pravilo koje dozvoljava pokretanje `apport-cli` kao root zaslužuje istu proveru pager-a. Pogođene verzije Apport-a mogle su da otvore izveštaj o padu sistema u `less` uz veličinu terminala koju napadač može da podesi; pager je zatim mogao da omogući root shell ako su bili ispunjeni posebni uslovi za sudo i pager. Pre nego što verziju proglasite ranjivom, proverite efektivno sudo pravilo, konfiguraciju pager-a i ispravku paketa za datu distribuciju. Tokom pasivnog prikupljanja informacija, pregledajte metapodatke paketa i pravila bez izazivanja pada sistema ili otvaranja privilegovanog izveštaja. [Ubuntu-ov CVE zapis](https://ubuntu.com/security/CVE-2023-1326) navodi verzije paketa sa ispravkama za pojedinačna izdanja, uključujući ispravke prenete u starije verzije.

```text
!/bin/sh
```

## Ostale opasnosti od pravila sudo i doas

Počnite sa `sudo -l`, `sudo -V` i svim primenljivim pravilima `doas`. Posmatrajte zajedno dozvoljenu komandu, korisnika u čije ime se pokreće, argumente, okruženje i podrazumevane vrednosti. Dozvola za pokretanje komande kao ne-root servisni nalog i dalje može da otkrije datoteke tog naloga ili put do root pristupa.

Fiksna Python skripta dozvoljena kroz sudo i dalje može da pokrene shell komandu u identitetu RunAs ako se interaktivni unos pod kontrolom pozivaoca konkatenira u [`os.system()`](https://docs.python.org/3/library/os.html#os.system). Denylist interpunkcijskih znakova za shell nije dovoljan dokaz bezbednosti: [shell prepoznaje i supstituciju komandi `$(...)`](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html). Potvrdite da dozvoljeni argumenti stižu do grane za unos, da unos stiže do shell komande bez bezbedne validacije i da efektivna sudo politika dozvoljava nameravanog RunAs korisnika. Sama putanja skripte ili poziv `os.system()` samo su trag za proveru; pregledajte izvorni kod bez pokretanja privilegovane skripte.

Efektivna root sudo dozvola za `chattr` može da ukloni atribut nepromenljivosti (`i`) sa datoteke, ali to samo po sebi ne daje pravo upisa niti novi identitet. [Uputstvo za `chattr`](https://man7.org/linux/man-pages/man1/chattr.1.html) navodi da atribut blokira izmene i da ga može promeniti samo root ili proces sa `CAP_LINUX_IMMUTABLE`. Proverite tačnu sudo politiku argumenata i podršku datotečnog sistema, pa zatim zasebno utvrdite da li pozivalac može da upisuje u datoteku nakon uklanjanja atributa i da li je koristi proces višeg identiteta. Na primer, zamena login shell-a zahteva i važeće kredencijale ciljnog naloga i stvarnu prijavu kroz taj shell. Tokom enumeracije pregledajte politiku, atribute datoteke i dozvole, ali ih nemojte menjati.

Ako sudo traži i lozinku i jednokratni kod, te preduslove posmatrajte odvojeno od dozvole za komandu. Čitljiva datoteka `.google_authenticator` sadrži osetljiv seed, dok je stari hash lozinke aplikacije ili baze podataka samo mogući kandidat za trenutnu lozinku naloga; nijedno od toga ne dokazuje da efektivna PAM konfiguracija prihvata drugi faktor. Kada dobijete ovlašćenje, proverite tačan RunAs nalog i argumente: neograničena root dozvola za RubyGems `gem` može da izloži njegovu komandu za editor ([GTFOBins](https://gtfobins.github.io/gtfobins/gem/)), ali ograničena dozvola ili neuspešna autentikacija to ne omogućava. Pasivna enumeracija treba da prijavi putanje i politiku, a ne da ispisuje seed, vraća lozinku, generiše kod ili poziva privilegovanu komandu.

Neograničena sudo dozvola za `knife`, kojom se može dobiti root, zahteva pregled na nivou interpretera: [Chef navodi da `knife exec -E` lokalno evaluira Ruby string](https://docs.chef.io/workstation/26/tools/knife/knife_exec/). Proverite da li efektivno sudo pravilo dozvoljava podkomandu `exec` i argument `-E` koji zadaje pozivalac, željeni RunAs identitet i sva odgovarajuća odbijanja komandi ili fiksne argumente. Instalirani binarni fajl ili pravilo ograničeno na druge podkomande samo su trag za proveru. Pasivna enumeracija treba da prijavi pravilo bez pokretanja `knife`.

Tačna sudo dozvola za interaktivni `msfconsole`, kojom se može dobiti root, takođe je osetljiva: [GTFOBins dokumentuje njegovu `irb` konzolu](https://gtfobins.org/gtfobins/msfconsole/), koja može da nasledi sudo identitet. Potvrdite efektivnog RunAs korisnika, dozvoljenu listu argumenata, zabrane komandi, `NOEXEC` ili druga ograničenja, ponašanje instalirane konzole i mogućnost da pozivalac unese interaktivni ulaz. Istaknuta putanja samo je trag za proveru; tokom pasivne enumeracije nemojte pokretati konzolu.

Na FreeBSD-u, čak i sudo pravilo ograničeno na root komande `pkg update` i `pkg install *` zahteva proveru pouzdanosti repozitorijuma. Utvrdite da li pozivalac može da upisuje u `/etc/hosts` i da li efektivna konfiguracija uključenih repozitorijuma koristi HTTP hostname sa `signature_type: none`. [Uputstvo za FreeBSD `pkg.conf`](https://man.freebsd.org/cgi/man.cgi?query=pkg.conf&sektion=5) navodi da `none` isključuje proveru potpisa; sam `pkg+http` to ne dokazuje. Paket može da sadrži instalacione skripte ([FreeBSD Porter's Handbook](https://docs.freebsd.org/en/books/porters-handbook/pkg-files/)), pa pozivalac koji zaista kontroliše krajnju tačku repozitorijuma i može da izabere paket može da pređe granicu root privilegija. Pre tog zaključka proverite zamene repozitorijuma, SRV/mirror rezoluciju, efektivne sudo argumente, izbor paketa i izvršavanje skripti. Pregledajte politiku i male lokalne konfiguracione datoteke, bez preusmeravanja imena ili pokretanja `pkg` tokom enumeracije.

Sudo pravilo za `apt-get update` i `apt-get upgrade`, kojim se može dobiti root, takođe zahteva proveru pouzdanosti repozitorijuma ako sudo čuva `http_proxy` koji kontroliše pozivalac. Proverite da li efektivna APT proxy konfiguracija zaista koristi tu promenljivu i na koje omogućene zahteve ka repozitorijumima ona može da utiče; sam proxy ne može da zameni pakete iz arhive autentifikovane pouzdanim ključem za potpisivanje. [Uputstvo za APT HTTP transport](https://manpages.debian.org/experimental/apt/apt-transport-http.1.en.html) opisuje prioritet proxy-ja, a [apt-secure](https://manpages.debian.org/experimental/apt/apt-secure.8.en.html) opisuje provere potpisa, zamene za nepouzdane repozitorijume i potvrdu za neautentifikovane pakete. Potvrdite tačan sudo RunAs nalog i argumente, politiku autentifikacije repozitorijuma, potrebnu interaktivnu potvrdu i da li se izabranom nadogradnjom pokreću paketne skripte kao root. Pasivno pregledajte politiku i lokalnu konfiguraciju; tokom enumeracije nemojte preusmeravati saobraćaj paketa niti pokretati nadogradnju.

Root-capable sudo pravilo za `snap install` može da pređe granicu između paketa i koda ako argumenti omogućavaju pozivaocu da izabere lokalni snap i permisivan režim instalacije. [Snap dokumentuje](https://snapcraft.io/docs/explanation/snap-development/install-modes/) da `--dangerous` preskače provere attestacije lokalnog snap-a, a `--devmode` ublažava ograničenja; [install hook može da se pokrene prilikom početne instalacije](https://snapcraft.io/docs/reference/development/supported-snap-hooks/). Pre tvrdnje da je moguć pristup zaštićenim datotekama hosta, proverite tačnu sudo politiku za argumente/RunAs, ko kontroliše snap datoteku, da li instalirani snapd prihvata ove režime i identitet i ograničenja hook-a. Sam `snap` binarni fajl ili pravilo koje samo liči na wildcard ne dokazuju ovaj lanac. Pasivna enumeracija ne treba da instalira paket niti izvrši njegov hook.

Za tačnu sudo dozvolu za prilagođeni binarni fajl koji čita kredencijale ne-root naloga, prvo pregledajte dozvoljeni binarni fajl i njegove dozvole, bez pokretanja. Ugrađena provera lozinke može da bude vidljiva samo kao wide characters; [GNU `strings` dokumentuje izdvajanje 16-bit little-endian niza](https://sourceware.org/binutils/docs/binutils/strings.html). Vidljiv string ne dokazuje da je to prihvaćena lozinka niti da uspešna grana otkriva važeći kredencijal. Zasebno proverite ponašanje binarnog fajla, pristup ciljnog naloga zaštićenim podacima, važenje kredencijala i svaki kasniji prelazak naloga ili grupe. Ako taj nalog pripada grupi `docker`, proverite pristup socket-u i da li je identitet daemon-a rootful ili rootless pre zaključka o pristupu host root-u; [Docker dokumentuje implikacije članstva u ovoj grupi na nivou root-a](https://docs.docker.com/engine/install/linux-postinstall/). Rutinska enumeracija treba da prijavi sudo pravilo i članstvo u grupi, bez izvršavanja binarnog fajla ili ispisivanja njegovih stringova.

Wildcard sudo pravilo za skripte za održavanje aplikacije treba da se pregleda i izvan same putanje skripte. Proverite da li dozvoljena skripta prihvata neograničene argumente ili čita podešavanja koja može da menja nalog aplikacije sa nižim privilegijama, pa zatim pratite te vrednosti do shell komandi ili okruženja podprocesa. Na primer, ZoneMinder-ov [`zmupdate.pl` sastavlja komandu `mysqldump` i izvršava je pomoću `qx`](https://github.com/ZoneMinder/ZoneMinder/blob/master/scripts/zmupdate.pl.in), dok [`zmdc.pl` kopira podešavanje `ZM_LD_PRELOAD` u `LD_PRELOAD`](https://github.com/ZoneMinder/ZoneMinder/blob/master/scripts/zmdc.pl.in) pre pokretanja daemon-a. Sudo pravilo koje dozvoljava bilo koju od ovih skripti kao root može da pređe granicu poverenja ako se odgovarajući ulaz može kontrolisati i stiže do tog koda u instaliranoj verziji. Pregledajte efektivno sudo pravilo, dozvole za konfiguraciju aplikacije i izvorni kod skripte; wildcard ili samo podešavanje predstavljaju trag za proveru, ne dokaz izvršavanja.

- `SETENV`, `env_keep`, `secure_path` i `LD_PRELOAD` mogu da pretvore inače usko ograničenu komandu u napad preuzimanjem importa, biblioteke ili PATH-a. Pogledajte [vodič za environment variables](../linux-basics/linux-environment-variables.md) i [SUID/linker abuse](../interesting-files-permissions/suid-shared-library-and-linker-abuse.md).

Tačna root-capable `SETENV` dozvola za shell wrapper takođe zahteva proveru jednog koraka ako wrapper pokreće fiksnu Python skriptu sa doslovnim importom. `secure_path` ograničava pretragu shell komandi, a ne Python [`PYTHONPATH` pretragu modula](https://docs.python.org/3/using/cmdline.html#envvar-PYTHONPATH); [`-E` i `-I`](https://docs.python.org/3/using/cmdline.html#cmdoption-E) nalažu Python-u da ignoriše tu promenljivu okruženja. Pre nego što ovo tretirate kao izvršavanje koda, proverite efektivne sudo oznake i zabrane, granu wrapper-a, opcije interpretera, rezoluciju importa i direktorijum za pretragu u koji pozivalac može da upisuje. Kratke skripte pregledajte statički; nemojte pozivati privilegovani wrapper.

Tačna root-capable sudo dozvola za `neofetch ""` i dalje može da učita shell konfiguraciju ako odgovarajuće sudo podrazumevane vrednosti čuvaju `XDG_CONFIG_HOME` koji kontroliše pozivalac. [Učitavač konfiguracije Neofetch-a](https://github.com/dylanaraps/neofetch/blob/master/neofetch) učitava `neofetch/config.conf` ili `neofetch/config` ispod tog direktorijuma; prazna lista argumenata ne sprečava ovu pretragu. Proverite učitavač u instaliranoj verziji, efektivna RunAs i argument pravila, eventualne zabrane komandi, da li sudo zaista čuva izabranu promenljivu za ovu komandu i da li pozivalac kontroliše čitljivu putanju do konfiguracije. Sačuvana promenljiva ili instalirani Neofetch sami su samo trag za proveru. Pregledajte politiku i metapodatke datoteke, bez pokretanja privilegovane komande ili ispisivanja sadržaja konfiguracije; pogledajte [sudoers environment handling](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf).

Neograničeno root-capable sudo pravilo za `facter` zahteva zasebnu proveru custom fact-ova. [Puppet dokumentuje](https://help.puppet.com/core/current/Content/PuppetCore/loading_custom_facts.htm) da `--custom-dir` učitava Ruby fact datoteke iz izabranog direktorijuma. Proverite da li tačno sudo pravilo dozvoljava tu opciju, da li je prihvata instalirani Facter i da li pozivalac kontroliše direktorijum. Fiksni argumenti, izričita zabrana komande ili isključeni custom fact-ovi mogu da promene ishod. Pasivna enumeracija treba da prijavi kandidat u politici bez pokretanja Facter-a ili čitanja sadržaja fact datoteka.

Za tačnu sudo dozvolu za root-capable skriptu sa `SETENV`, proverite gole nazive komandi poput `find` i efektivni `PATH` nakon primene sudo politike i inicijalizacije skripte. Izvorni Bash fajl može da pokrene i `enable -n [`: [Bash zatim traži eksterni `[` kroz `PATH`](https://www.gnu.org/software/bash/manual/html_node/Bash-Builtins.html) kada skripta kasnije koristi tu komandu. Proverite odgovarajuća [sudoers pravila za okruženje i `secure_path`](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf), sva `NOSETENV`/`NOEXEC` ili pravila zabrane, tok izvršavanja skripte i izvornog fajla, kao i izvršni direktorijum za pretragu koji kontroliše pozivalac. Čitljiva skripta koja sadrži golu komandu samo je trag za proveru, a ne dokaz privilegovanog izvršavanja; pregledajte je bez pokretanja sudo pravila.
- Privilegovana skripta koja preuzima fiksni URL pomoću `curl` i dalje može da prihvati odgovor koji izabere pozivalac ako odgovarajuće sudo pravilo čuva `http_proxy` i zahtev prolazi kroz taj proxy. Ako skripta zatim prosledi odgovor XML parser-u koji razrešava eksterne entitete, zlonameran odgovor može da otkrije datoteke koje su čitljive privilegovanom procesu. Proverite tačnu sudo politiku okruženja, izuzetke `no_proxy`, traženi URL, konfiguraciju parser-a i odredište izlaza; samo proxy promenljiva ili XML parser nisu ranjivost. [Dokumentacija za curl proxy environment](https://everything.curl.dev/usingcurl/proxies/env.html) opisuje ponašanje promenljivih. Tokom pasivne enumeracije nemojte slati mrežne zahteve niti parsirati zlonameran XML.
- Root-capable sudo skripta koja pravi PostScript datoteku od podataka pod kontrolom pozivaoca, a zatim pokreće `ps2pdf -dNOSAFER`, zahteva zasebnu proveru toka ulaza. Ghostscript navodi da ova zastavica isključuje SAFER do poziva `.setsafe`, čime se dozvoljavaju PostScript operacije nad datotekama u okviru OS dozvola procesa. SQL upit sastavljen od argumenta pozivaoca može da prosledi redove pod kontrolom napadača PostScript šablonu, ali sam upit ili poziv `ps2pdf` ne dokazuju da podaci stižu do izvršive PostScript sintakse. Proverite efektivno sudo pravilo, tačan put od ulaza do šablona, escaping, ponašanje instaliranog Ghostscript-a i da li se SAFER ponovo uključuje pre interpretacije dokumenta. Tokom pasivne enumeracije nemojte pozivati privilegovanu konverziju. Pogledajte [Ghostscript dokumentaciju za `-dNOSAFER`](https://ghostscript.readthedocs.io/en/master/Use.html).
- Za sudo pravilo koje pokreće shell skriptu uporedite sačuvane promenljive i samu skriptu. Konstrukcija kao što je `if $CHECK_CONTENT; then` izvršava proširenu vrednost kao komandu, pa čuvanje `CHECK_CONTENT` može da omogući izvršavanje komandi čak i kada su putanja skripte i argumenti fiksni. Za konkretno pravilo treba proveriti da li je grana dostupna i da li se okruženje zaista čuva.<sup>[[2]](#references)[[22]](#references)</sup>
- Python skripta dozvoljena kroz sudo može da importa код из direktorijuma u koji može da se upisuje ili keširane `.pyc` datoteke. [Vodič za eskalaciju privilegija](../linux-basics/linux-privilege-escalation/README.md) opisuje slučaj sa kešom.
- Fiksna Python skripta dozvoljena kroz sudo kao root i dalje može da izloži interaktivni debugger. Pozivi kao što su `pdb.set_trace()` ili `pdb.post_mortem()` omogućavaju Python naredbe u kontekstu procesa koji se debaguje ako pozivalac može da dođe do breakpoint-a ili exception handler-a **i kontroliše ulazni tok debugger-a**. Proverite tačno sudo RunAs pravilo, autentikaciju i uslove grane, mogućnost dostizanja exception-a, vlasništvo nad terminalom/ulazom i da li debugger radi u tom istom privilegovanom procesu. Zahtev preko socket-a koji pokrene izuzetak sam po sebi ne daje pristup debugger-u povezanom sa drugim terminalom. [Python dokumentuje evaluaciju naredbi u debugger-u i post-mortem režim](https://docs.python.org/3/library/pdb.html); skriptu pregledajte statički umesto da tokom enumeracije pokrećete privilegovani handler.
- Fiksna Python skripta dozvoljena kroz sudo može i da pročita polje profila iz baze podataka ili Unix socket-a i doda ga u string koji kasnije postaje **format string** za `str.format()`. [Replacement fields mogu da prate atribute i ključeve mapiranja](https://docs.python.org/3/library/string.html#format-string-syntax), pa polje pod kontrolom napadača može da pregleda objekte prosleđene u `format()` i otkrije podatke do kojih ti objekti imaju pristup, ako se rezultat ispiše ili sačuva na mestu koje pozivalac može da čita. Proverite efektivni sudo RunAs identitet, pravo upisa u konkretan zapis, tok podataka do format string-a, prosleđene objekte i vidljivost izlaza. Ovo ne podrazumeva automatsko izvršavanje koda; literalni pouzdani format string sa vrednostima pod kontrolom napadača je drugačiji slučaj. Otkrivena tajna dovodi do prelaska na OS nalog samo ako taj nalog prihvata tu tajnu. Pregledajte skriptu i dozvole socket-a bez pozivanja privilegovane operacije.
- Root-capable Python wrapper može da prosledi URL koji izabere pozivalac funkciji `Repo.clone_from` iz GitPython-a. Ako wrapper takođe omogući Git-ov `protocol.ext.allow=always`, `ext::` udaljeni repozitorijum može da pozove eksterni helper. Proverite tačne sudo argumente, izvor URL-a, verziju GitPython paketa i stanje vendor zakrpa, kao i da li wrapper izričito dozvoljava nebezbedne protokole. GitPython je dodao [podrazumevanu zaštitu od nebezbednih protokola](https://github.com/gitpython-developers/GitPython/commit/2625ed9) u verziji 3.1.30; verzija izvršnog fajla `git` je zasebna činjenica. Pasivan pregled treba da obuhvati samo pravilo i ograničen deo izvornog koda, bez pokretanja kloniranja.
- Sudo dozvola za kloniranje repozitorijuma u ime drugog korisnika može da izloži zaseban put za shell-string injection. Pratite da li argument repozitorijuma koji zadaje pozivalac stiže do Node.js [`child_process.exec`](https://nodejs.org/api/child_process.html#child_processexeccommand-options-callback) ili drugog mehanizma za sastavljanje shell komandi bez bezbednog razdvajanja argumenata; Node `exec` prosleđuje komandni string shell-u. Potvrdite tačnog RunAs korisnika, dozvoljene podkomande i argumente, instalirani wrapper kod i validaciju ulaza. Ime repozitorijumskog alata ili neograničeno sudo pravilo samo po sebi ne dokazuju command injection. Pregledajte wrapper bez pokretanja privilegovanog kloniranja tokom enumeracije.
- Prilagođeni wrapper u vlasništvu root-a može delovati bezbedno jer njegovi binarni fajlovi i skripte nisu upisivi, ali odluka o privilegovanoj radnji može da zavisi od zastavice, lokalne API vrednosti ili stanja servisa koje neprivilegovani korisnik može da promeni. Pratite svaki uslov do njegovog ulaza i provera autorizacije. Tokom enumeracije pregledajte konfiguraciju i dozvole bez menjanja operativnog stanja; poziv `systemd-run` unutar wrapper-a relevantan je samo ako se na uslov može uticati.
- Klijent za rezervne kopije dozvoljen kroz sudo kao root može da prihvati konfiguracionu datoteku koju izabere pozivalac (na primer, `npbackup-cli -c`). Proverite tačnog RunAs korisnika i dozvoljene argumente, pa utvrdite da li pozivalac kontroliše putanju konfiguracije, izvorne putanje za backup i opcije repozitorijuma ili čitanja/obnove. Šifrovana tajna repozitorijuma u čitljivoj konfiguraciji i dalje može da bude upotrebljiva kroz klijent, ali samo pravilo ne dokazuje pristup repozitorijumu niti otkrivanje root datoteka. Proverite autorizaciju bez pokretanja backupa ili ispisivanja njegovog sadržaja.
- [Restic](https://github.com/restic/restic/blob/master/doc/030_preparing_a_new_repo.rst) podržava `--password-command`, koji poziva program za pribavljanje lozinke repozitorijuma. Ako sudo pravilo dozvoljava korisniku sa nižim privilegijama da pokrene restic kao root sa komandom za lozinku koju on zadaje i podkomandom kojoj je potrebna lozinka, taj helper može da se pokrene kao root. Pregledajte tačne sudo argumente i izuzetke; nemojte pozivati helper niti komandu za backup samo da biste proverili uslov.
- Privilegovana `restic backup` dozvola može i da pređe granicu čitanja datoteka ako sudo obrazac argumenata dozvoljava pozivaocu da izabere izvor i repozitorijum koji kasnije može da čita i dešifruje. [Wildcard-i argumenata u sudoers mogu da obuhvate razmake i kose crte](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf), pa pregledajte završne wildcard-e umesto da pretpostavite da fiksni prefiks repozitorijuma ograničava izvor. [Restic može da čuva rezervne kopije u lokalnim i udaljenim repozitorijumima](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html), ali lokalni repozitorijum može da sadrži novoupisane objekte dostupne samo root-u; pre zaključka da postoji otkrivanje podataka proverite efektivnu sudo politiku, pristup backend-u, lozinku repozitorijuma i dozvole za nastale objekte. SSH ključ iz rezervne kopije omogućava pristup samo ako ga ciljni nalog prihvata. Nemojte pokretati backup radi testiranja tokom pasivnog pregleda.
- Neograničena prilagođena komanda za održavanje ili backup može da prihvati putanju izlazne datoteke ili da ima sopstveni planer poslova. Kod upisa u datoteku proverite tačno sudo pravilo i RunAs korisnika, pa utvrdite da li pozivalac kontroliše i podatke i odredište. Kod planiranih komandi proverite identitet izvršavanja planera, ulaznu komandu i svaku dodatnu lozinku ili uslov autorizacije. Samo ime komande ili `NOPASSWD` ne dokazuje nijedan od ova dva puta. Pogledajte [pisanje u datoteke u vlasništvu root-a](../interesting-files-permissions/write-to-root.md) i [cron i systemd timers](../processes-crontab-systemd-dbus/cron-and-systemd-timers.md).
- Fiksna sudo komanda i dalje može da učita predvidljivu konfiguracionu datoteku iz direktorijuma u koji više korisnika može da upisuje. Proverite da li pozivalac može da zameni tu datoteku i da li njena polja za izvor i odredište kontrolišu privilegovano preuzimanje ili kopiranje. URL lokalne datoteke može da otkrije podatke čitljive samo RunAs nalogu sudo-a; izvor pod kontrolom pozivaoca u kombinaciji sa zaštićenim odredištem može da omogući upis. Potvrdite obradu URL-ova u instaliranom programu, provere putanje odredišta, efektivno sudo pravilo i dostupnost izlaza. Samo upisiva konfiguraciona putanja u `/tmp` predstavlja trag za proveru, pa pregledajte binarni fajl i metapodatke datoteke bez pokretanja privilegovanog prenosa.
- Sudo pravilo za `git apply` može da omogući RunAs nalogu da upisuje u datoteke koje izabere patch pod kontrolom pozivaoca. [CVE-2023-23946](https://github.com/git/git/security/advisories/GHSA-r87m-v37r-cwfh) omogućavao je da posebno napravljen patch kreira symlink, a zatim upisuje van radnog stabla, čak i kada komanda nije prihvatala `--unsafe-paths`. Proverite efektivno sudo pravilo argumenata, izvor patch-a, pristup radnom direktorijumu za RunAs nalog i ispravku za instalirani Git ili vendor backport. Neograničeno pravilo koje dozvoljava `--unsafe-paths` predstavlja zaseban rizik eksplicitne opcije; ni Git verzija ni sama `git apply` dozvola ne dokazuju da je moguće menjati zaštićenu datoteku. Tokom pasivne enumeracije nemojte primenjivati nepouzdan patch.
- Root-capable sudo pravilo za `clamscan --debug` može da pređe granicu čitanja ako korisnik sa nižim privilegijama može da dostavi DMG sliku, a instalirani parser je pogođen [CVE-2023-20052](https://blog.clamav.net/2023/02/clamav-01038-01052-and-101-patch.html), koja je mogla da otkrije sadržaj datoteka kroz debug izlaz. Potvrdite tačne dozvoljene argumente i putanju skeniranja, kontrolu ulaza, efektivni RunAs nalog, ispravku/backport engine-a i da li je izlaz vidljiv pozivaocu. Ako šire pravilo dozvoljava `--file-list`/`-f`, zasebno proverite ponašanje te liste; pravilo fiksirano na `--debug <scan-path>` to ne dozvoljava. Tokom enumeracije pregledajte politiku i metapodatke paketa, bez skeniranja posebno napravljene datoteke ili ispisivanja zaštićenog izlaza.
- Root-capable sudo pravilo koje otvara šifrovanu sliku diska koju je izabrao pozivalac, uz drugo pravilo koje montira dobijeni mapper, može da uveze datoteke pod kontrolom pozivaoca u mount namespace hosta. Potvrdite oba efektivna pravila i argumente, kontrolu nad slikom i imenom mapper-a, stvarnu tačku montiranja i vlasnika i režim dobijenih datoteka. Prelazak set-user-ID zahteva i dostupnu izvršnu datoteku, mount opcije koje ga poštuju (`nosuid` ga blokira) i odgovarajuću procesnu ili MAC politiku; samo otvaranje ili montiranje slike predstavlja tek trag za proveru. Zaseban put preko postojeće rezervne kopije zahteva njen stvarni ključ i korisnu čitljivu tajnu unutar nje. Pregledajte politiku i putanje bez otvaranja ili montiranja slike tokom pasivne enumeracije. Pogledajte [uputstvo za cryptsetup](https://gitlab.com/cryptsetup/cryptsetup/-/blob/main/man/cryptsetup.8.adoc) i [mount opcije](https://man7.org/linux/man-pages/man8/mount.8.html).
- Root-capable sudo pravilo za shell ili Python skriptu zahteva proveru radnog direktorijuma ako skripta poziva `./helper` bez prethodnog prelaska u fiksni direktorijum. Python lista kao što je `['./helper']` prosleđena u `subprocess.run` može da zavisi od radnog direktorijuma koji bira pozivalac na isti način. Pozivalac možda može da izabere direktorijum u koji sme da upisuje i da u njega postavi izvršnu datoteku sa tim relativnim imenom; apsolutna putanja na drugom mestu u skripti ne štiti ovaj poziv. Pre nego što ovo tretirate kao izvršavanje koda, potvrdite efektivno pravilo, `runchdir` ili drugu politiku promene direktorijuma, tok skripte i dostupnost grane, direktorijum u koji se može upisivati i koji je izvršan, kao i mount/`NOEXEC` ograničenja. Ako skripta nije čitljiva, ponašanje je nepoznato dok se njen izvor ne pregleda ovlašćenim putem. Skripte pregledajte statički umesto pokretanja helper-a. [sudoers uputstvo](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) opisuje politiku radnog direktorijuma.
- Fiksni root-capable Python validator i dalje može da evaluira datoteku sa podacima koju izabere pozivalac. [Python dokumentacija za `eval()` upozorava na nepouzdan unos](https://docs.python.org/3/library/functions.html#eval): provera sufiksa ulaza, aritmetičkog prefiksa ili grana za validaciju nije sandbox ako preostali izraz stigne do `eval`. Pre nego što ovo nazovete putem za izvršavanje, potvrdite efektivno sudo pravilo, da li pozivalac može da izabere i kontroliše tačnu datoteku, uslove grana parser-a i sastavljanje izraza, kao i identitet privilegovanog procesa. Prisustvo `eval` u čitljivoj skripti samo je povod za proveru; pregledajte izvorni kod i dozvole datoteka bez pokretanja validatora ili slanja testnog izraza tokom enumeracije.
- Root-capable sudo Ruby wrapper koji čita relativno YAML ime datoteke, kao što je `YAML.load(File.read("dependencies.yml"))`, može da preuzme ulaz iz radnog direktorijuma pozivaoca, osim ako wrapper ili sudo politika ne fiksiraju taj direktorijum. Proverite tačne dozvoljene argumente, dozvole direktorijuma i datoteke i ponašanje instaliranog Psych-a: starije implementacije `YAML.load` mogle su da deserijalizuju proizvoljne Ruby objekte, dok novija izdanja podrazumevano ograničavaju klase. Statički poziv samo je trag za proveru; potvrdite da datoteka zaista dolazi iz direktorijuma u koji pozivalac može da upisuje i da instalirani učitavač prihvata opasne klase. Za nepouzdan ulaz prednost dajte `safe_load` uz eksplicitnu minimalnu allowlist-u klasa. Pogledajte [Ruby 3.0 Psych dokumentaciju](https://docs.ruby-lang.org/en/3.0/Psych.html) i [Ruby 3.1 Psych dokumentaciju](https://ruby-doc.org/core-3.1.2/Psych.html).

- Tačna root-capable dozvola za `sudo go run /absolute/file.go` zahteva proveru radnog direktorijuma kada Go izvorni kod čita relativnu WASM datoteku i može da pokrene relativnu shell skriptu nakon pregleda njenog rezultata. Potvrdite efektivni RunAs, argumente komande i zabrane, radni direktorijum u koji pozivalac može da upisuje, tok podataka od WASM-a do grane i da li ta grana poziva helper. Fiksni sudo `runchdir`, `os.Chdir` ili [`exec.Cmd.Dir`](https://pkg.go.dev/os/exec) mogu da promene lokaciju pretrage. Statičko istovremeno pojavljivanje elemenata samo je kandidat; pregledajte izvorni kod bez pokretanja Go-a, WASM-a ili helper-a.
- Za `sudoedit` i wildcard-e argumenata neophodne su provere tačne verzije i pravila; [kontrolna lista](linux-privilege-escalation-checklist.md) obuhvata problem izmena datoteka preko sudoedit-a. Za cross-user `sudoedit` dozvolu za wildcard putanju proverite efektivno podešavanje `sudoedit_follow` ili `FOLLOW`, `sudoedit_checkdir`, razrešenu ciljnu putanju i ko može da zameni svaki roditeljski unos. Prvo podešavanje može da dozvoli praćenje symlink-a, dok isključivanje drugog uklanja provere upisivih direktorijuma; nijedno samo po sebi ne potvrđuje upis u datoteku drugog korisnika. Pre zaključka proverite instaliranu sudo politiku i tačno podudarne argumente. Pogledajte [sudoers definicije opcija](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf).
- U pravilu za komandu u sudoers-u, wildcard argumenta može da odgovara razmacima kao i znakovima putanje. Pravilo za komandu koja može da čita, sa argumentom poput `/restricted/*`, stoga može da dozvoli dodatni argument za datoteku nakon odgovarajućeg prefiksa. Proverite tačnog run-as korisnika, putanju komande, obrazac argumenata i kasnija odbijanja; dokazano čitanje datoteke ne podrazumeva izvršavanje komandi. [sudoers uputstvo](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) pravi razliku između glob-ova argumenata i glob-ova putanje komande.
- Glob argumenta koji liči na putanju može da odgovara i `../`. Na primer, root-capable `node /opt/scripts/*.js` pravilo može da dozvoli JavaScript datoteku koju kontroliše pozivalac izvan `/opt/scripts`, ako navedena putanja i dalje počinje sa `/opt/scripts/` i razrešava se kroz segmente roditeljskih direktorijuma. Ovo je glob **argumenta**; glob putanje komande za Node izvršni fajl ima drugačija pravila za poklapanje kosih crta. Proverite efektivno pravilo, kasnija odbijanja, razrešavanje putanje, kontrolu nad ciljnom datotekom i sva sudoers ograničenja pomoću regularnog izraza ili digest-a pre zaključka o izvršavanju koda. Pogledajte [sudoers wildcard pravila](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) i [Node dokumentaciju komandne linije](https://nodejs.org/api/cli.html).
- Programi za arhiviranje i drugi uslužni programi mogu da imaju hook-ove za izvršavanje. Proverite tačne dozvoljene argumente u [GTFOBins](https://gtfobins.github.io/) umesto da pretpostavite da samo shell-ovi ili interpreteri izvršavaju komande.
- Neograničeno root-capable `qpdf` pravilo može da otkrije privilegovanu datoteku kroz PDF priloge: qpdf 10.2 i novije verzije podržavaju `--empty` i `--add-attachment file ... --` uz izlazni PDF. Ako privilegovani proces može da čita izabrani izvor i upisuje PDF u putanju dostupnu pozivaocu, taj izlaz može da sadrži bajtove izvora. Pre zaključka da je otkrivanje datoteke moguće, pregledajte efektivne sudo argumente i izuzetke, qpdf verziju, pristup izvoru i putanju izlaza. Čitanje SSH ključa root-a korisno je za prijavu samo kada je ključ važeći i kada je root SSH autentikacija dozvoljena. Pogledajte [qpdf opcije za priloge](https://qpdf.readthedocs.io/en/stable/cli.html#embedded-files-attachments).
- Ponovno korišćenje sudo timestamp-a zavisi od politike keša, korisnika-vlasnika, terminala/sesije i dozvola. [Vodič za eskalaciju privilegija](../linux-basics/linux-privilege-escalation/README.md#reusing-sudo-tokens) opisuje provere.
- `doas` ima sopstvena pravila i konfiguraciju. Proverite dozvoljene komande i putanje konfiguracije u koje može da se upisuje, kako je opisano u [odeljku o doas](../linux-basics/linux-privilege-escalation/README.md#doas).

### Alati za izgradnju i pakete pokrenuti kroz sudo

Neograničena sudo dozvola za Foundry `forge` može biti važna čak i kada je RunAs identitet drugi ne-root korisnik. Opcije kompajlera kao što je `--use` mogu da izaberu lokalni izvršni fajl, a `forge flatten -o` bira izlaznu datoteku. Pre nego što dozvolu tretirate kao iskoristivu, proverite instaliranu Forge verziju, tačne sudo argumente, pristupačne putanje do projekta i kompajlera, dozvole izlaza i efektivno okruženje. Relativni pomoćni izvršni fajl pronađen preko `PATH` predstavlja put koji zavisi od verzije i okruženja, a ne svojstvo koje treba pretpostaviti za svaku Forge izgradnju.<sup>[[23]](#references)[[24]](#references)</sup>

Neograničena root-capable `pacman` dozvola omogućava više od upita o paketima: `-U` prihvata lokalni paket, paketi mogu da sadrže instalacione skripte, a `--hookdir` bira drugi direktorijum hook-ova. Pre testiranja pregledajte efektivno sudo pravilo, ograničenja argumenata i izuzetke; pasivna enumeracija ne zahteva instalaciju paketa ni pokretanje hook-a.<sup>[[25]](#references)[[26]](#references)</sup>

Fiksni sudo shell wrapper može i da instalira imenovanu npm zavisnost, a zatim pokrene Node aplikaciju. Pregledajte tačno RunAs pravilo, da li je paket već instaliran, efektivni `HOME` i npm `userconfig`, konfiguraciju projekta ili zamene komandne linije i da li korisnik sa nižim privilegijama kontroliše registry ili paket koji se dobija pod tim imenom. [npm dokumentuje pretragu `.npmrc` datoteka za svakog korisnika i projekat](https://docs.npmjs.com/cli/v6/configuring-npm/npmrc/); ponašanje sudo-a za `HOME` zavisi od instalirane politike i distribucije, pa `.npmrc` upisiv za korisnika možda čita privilegovani npm proces, a možda i ne. Ako novoinstalirani paket importuje privilegovana aplikacija, njegov kod modula može da se izvrši u identitetu te aplikacije. Skripte koje se pokreću pri instalaciji predstavljaju zaseban put koji zavisi od verzije i konfiguracije; [npm dokumentuje njihov životni ciklus i obradu korisnika](https://docs.npmjs.com/cli/v6/using-npm/scripts/). Putanja `.npmrc` ili linija `npm install` same su samo trag za proveru. Tokom pasivne enumeracije pregledajte pravilo, kratak wrapper, putanje konfiguracije i poreklo paketa bez instaliranja ili pokretanja aplikacije.

Root-capable `pip` ili `pip3 download` dozvola takođe je razlog za proveru izgradnje paketa ako argumenti omogućavaju pozivaocu da izabere nepouzdan source distribution, čak i kada obrazac URL-a ograničava izvor na lokalni servis i sufiks `.tar.gz`. `pip download` prihvata URL-ove arhiva i razrešava metapodatke paketa; priprema sdist-a može da pozove njegov build backend ili legacy `setup.py` kod pre nego što se arhiva samo sačuva. Potvrdite tačan sudo RunAs i pravilo argumenata, da li pozivalac može da objavi ili zameni izabranu arhivu i da li ta pip verzija zaista priprema njene metapodatke. Fiksna pouzdana arhiva ili wheel ne dokazuju ovaj put. Tokom pasivne enumeracije nemojte preuzimati niti izgrađivati nepouzdan paket. Pogledajte pip [komandu za preuzimanje](https://pip.pypa.io/en/stable/cli/pip_download/), [interfejs build sistema](https://pip.pypa.io/en/stable/reference/build-system/) i [uputstva za bezbednu instalaciju](https://pip.pypa.io/en/stable/topics/secure-installs/).

Sudo pravilo koje dozvoljava `pip install` uz putanju lokalnog projekta koju bira pozivalac postavlja neposredniju granicu izgradnje. [pip prihvata direktorijume lokalnih projekata](https://pip.pypa.io/en/stable/topics/local-project-installs/) i poziva njihov build sistem; [build backend izvršava hook-ove iz projekta](https://pip.pypa.io/en/stable/reference/build-system/). Pre nego što ovo tretirate kao privilegovano izvršavanje koda, potvrdite efektivni RunAs identitet, tačna ograničenja i zabrane argumenata, kontrolu nad izabranim projektom i ponašanje instaliranog pip/backend-a. Fiksni pouzdani projekat ili pravilo koje isključuje putanje koje bira pozivalac ne uspostavljaju ovaj put. Tokom pasivne enumeracije pregledajte pravilo i metapodatke projekta bez instaliranja paketa.

Neograničena root-capable `easy_install` dozvola predstavlja srodan legacy pokazatelj za proveru izgradnje paketa. [Setuptools dokumentuje](https://setuptools.pypa.io/en/stable/deprecated/easy_install.html) da Easy Install prihvata direktorijum lokalnog projekta i izgrađuje source distribution; projekat pod kontrolom pozivaoca može da izvrši `setup.py` tokom izgradnje u identitetu sudo-a. Potvrdite efektivni RunAs nalog, tačnu komandu i ograničenja argumenata (uključujući kasnija odbijanja), kontrolu nad izabranim projektom i ponašanje instaliranog alata. Fiksni pouzdani projekat ili politika koja ne dozvoljava izvor pod kontrolom pozivaoca ne uspostavljaju ovaj put. Tokom enumeracije pregledajte pravilo i metapodatke projekta bez instaliranja paketa.

Python wrapper dozvoljen kroz sudo koji koristi `setuptools.package_index.PackageIndex.download` sa URL-om koji bira pozivalac predstavlja drugačiji slučaj za proveru od `pip download`: [setuptools GHSA-5rjg-fvgr-3xxf](https://github.com/pypa/setuptools/security/advisories/GHSA-5rjg-fvgr-3xxf) opisuje kako je u ranjivim izdanjima pre verzije 78.1.1 ime izvedeno iz URL-a moglo da izađe iz predviđenog direktorijuma za preuzimanje i da se datoteka upiše uz dozvole procesa. Potvrdite efektivni sudo RunAs i pravilo argumenata, da wrapper prosleđuje URL pozivaoca baš ovom API-ju, instaliranu verziju ili vendor backport i gde se dobijena putanja razrešava. Sam string verzije ili direktorijum za preuzimanje u koji se može upisivati ne dokazuju proizvoljan upis. Pregledajte kratak wrapper i metapodatke paketa bez preuzimanja URL-a ili upisivanja datoteke tokom enumeracije.

Build wrapper dozvoljen kroz sudo koji prosleđuje PyInstaller-u `.spec` datoteku koju bira pozivalac zahteva istu proveru granice poverenja. PyInstaller spec je izvršivi Python koji se evaluira tokom **izgradnje**, a njegovi `datas` unosi mogu da uključe datoteke čitljive identitetu koji vrši izgradnju u artefakt. Potvrdite tačnog RunAs korisnika, sudo pravilo argumenata i zabrana, obradu putanje i grana u wrapper-u, kontrolu nad izabranom spec datotekom i pristup dobijenom artefaktu. Samo dozvola za `.py` ulaz ili instalirani PyInstaller ne dokazuju kontrolu nad spec datotekom niti privilegovano izvršavanje. Pasivan pregled treba da obuhvati samo ograničen broj bajtova wrapper datoteke i metapodatke; nemojte pokretati izgradnju. Pogledajte [PyInstaller dokumentaciju za spec datoteke](https://pyinstaller.org/en/stable/spec-files.html).

### Privilegovani wrapper-i za backup koji menjaju task datoteku pozivaoca

Shell wrapper pokrenut kao root može da prihvati task datoteku koju izabere pozivalac, ukloni `../` iz putanja izvora, proveri da li svaki rezultat počinje dozvoljenim direktorijumom, izmeni task datoteku, a zatim prosledi njen *naziv putanje* programu za backup. Pregledajte transformisanu putanju nakon potpunog kanonskog razrešavanja: jedan prolaz zamene stringova može da otkrije novu sekvencu za prolazak kroz direktorijume koju leksička provera prefiksa prihvata. Proverite i da li program za backup čita transformisane podatke iz memorije ili ponovo otvara datoteku. Ako je ponovo otvara, neuspešna izmena može da ostavi prvobitni ulaz.

Na Linux-u, `fs.protected_regular` može da odbije upis sa `O_CREAT` u regularnu datoteku drugog korisnika unutar world-writable sticky direktorijuma. To odbijanje je zaštitno, ali shell wrapper koji ignoriše grešku pri upisu može ipak da nastavi sa prvobitnom task datotekom. Proverite podešavanje, vlasnika datoteke i direktorijuma i da li se wrapper zaustavlja pri grešci. Putanja predstavlja kandidata za otkrivanje datoteka samo ako efektivno sudo pravilo dozvoljava wrapper kao privilegovanog korisnika, pozivalac kontroliše ulazni task i čitljivo odredište backupa, a uslužni program za backup zaista uključuje zaštićene izvore. Tokom enumeracije proverite ove uslove bez pokretanja backupa.

### Wildcard-i argumenata u privilegovanim alatima za pakete

U sudo pravilu za `tcpdump`, `*` u **obrascu argumenata** može da odgovara razmacima i kosim crtama, pa ograničenje koje liči na putanju i dalje može da dozvoli dodatni tekst opcije. To se razlikuje od wildcard-a u putanji izvršne datoteke komande; pregledajte kompletno RunAs pravilo i sva kasnija odbijanja. Ako se mogu ubaciti opcije, dozvoljena komanda i semantika opcija instaliranog [`tcpdump`](https://github.com/the-tcpdump-group/tcpdump/blob/master/tcpdump.1.in) određuju da li `-F`, `-V`, `-r`, `-w` ili `-Z` pruža koristan primitive za čitanje/upis. `-V` čita listu imena capture datoteka, a ne proizvoljan opšti ispis datoteka. AppArmor ili druga MAC politika može da blokira pristup datotekama čak i kada sudo dozvoljava komandu; sama datoteka profila na disku ne dokazuje da je profil učitan ili da se primenjuje. Pasivno pregledajte autorizaciju i politiku pre donošenja zaključka. [sudoers uputstvo](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) opisuje razliku između wildcard-a.

Root-capable sudo pravilo koje navodi samo izvršni fajl `tcpdump`, bez ograničenja argumenata, takođe zahteva proveru. [Uputstvo za tcpdump](https://github.com/the-tcpdump-group/tcpdump/blob/master/tcpdump.1.in) opisuje `-z` kao komandu koja se pokreće nakon rotacije kada `-C` ili `-G` rotira sačuvani capture; `-Z` ili podrazumevana vrednost pri kompajliranju mogu da uklone privilegije pre pokretanja te komande. Proverite efektivno sudo pravilo, instaliranu verziju, ponašanje pri uklanjanju privilegija i da li rotacija može da se dogodi pre nego što ovo tretirate kao put za eskalaciju. Istaknuto pravilo je kandidat za proveru, a ne dokaz izvršavanja komandi kao root.

### Nmap wrapper-i pokrenuti kroz sudo

Kada je `nmap` putanja dozvoljena kroz sudo zapravo shell wrapper, pregledajte tačnu dozvoljenu putanju i svaku opciju koju prosleđuje. [`--excludefile`](https://nmap.org/book/man-target-specification.html) predstavlja zaseban ulaz za čitanje datoteke; greške parser-a mogu da otkriju tekst. Tokom enumeracije proverite efektivno sudo pravilo, logiku wrapper-a, Nmap verziju, kontrolu direktorijuma i MAC politiku bez pokretanja skeniranja.

### Kopiranje arhiva pomoću rsync-a pokrenutog kroz sudo

Za `sudo rsync -a ... /writable/source/* /fixed/destination/`, `*` u **obrascu argumenata sudoers-a** može da odgovara razmacima i dozvoli dodatnu opciju između izvora i odredišta. Proverite tačnu [sudoers semantiku wildcard-a](https://man7.org/linux/man-pages/man5/sudoers.5.html), rsync verziju, kasnija odbijanja, `nosuid` datotečnog sistema i MAC politiku. Podudarno pravilo je kandidat za proveru, a ne dokaz uspešne eskalacije privilegija.

### Parsiranje izraza nad sačuvanim ulazom pokrenuto kroz sudo

Fiksna Python skripta pokrenuta kao root kroz sudo i dalje može da evaluira tekst koji korisnik sa nižim privilegijama može da sačuva u bazi podataka aplikacije. Proverite efektivno sudo pravilo, ko može da izmeni tačan ulazni red, da li filtriranje ili bodovanje omogućava da taj red stigne do poziva i ponašanje instalirane funkcije. TensorFlow verzija, sudo dozvola ili hardkodovana datoteka modela sami ne dokazuju lanac. ### Needrestart konfiguracija dozvoljena kroz sudo

### Python import-i pokrenuti kroz sudo u ime drugog naloga

Fiksna Python ulazna tačka i dalje može da importa modul koji pozivalac može da menja ili zameni, uključujući slučaj kada sudo pokreće skriptu kao **ne-root** servisni korisnik. Za doslovno `from utils import status`, pregledajte `utils/__init__.py` i `utils/status.py` u lokalnom direktorijumu, kao i dozvole direktorijuma paketa. Pre nego što upisivu datoteku tretirate kao put za izvršavanje, potvrdite putanju importa skripte, tačne dozvoljene sudo argumente i da li relevantna radnja stiže do importa. Tokom enumeracije pregledajte datoteke i dozvole bez importovanja ili pokretanja skripte.<sup>[[2]](#references)[[3]](#references)</sup>

Tačno sudo pravilo za `python3 /absolute/script.py` zahteva samo da skripta bude čitljiva; ne mora da bude izvršna niti da ima shebang. Pregledajte i **nedostajuće** lokalne module: ako skripta importa modul čije ime datoteke može da se kreira u direktorijumu skripte u koji pozivalac može da upisuje, Python može da učita tu datoteku u RunAs identitetu. Potvrdite efektivno sudo pravilo, stvarnu [putanju pretrage modula](https://docs.python.org/3/library/sys_path_init.html) interpretera, da li je modul ugrađen ili zamrznut i da li se import zaista izvršava. Direktno sudo pravilo za skriptu ima drugačije zahteve za execute bit i shebang. Zaseban wrapper koji dodaje tokene koje zadaje pozivalac posle `sudo -u account` takođe zahteva proveru toka argumenata: drugi `-u` u tim tokenima važan je samo ako pozvana sudo politika dozvoljava rezultujući identitet. Statički stringovi sami ne dokazuju nijedan put.

### Apache pokrenut kroz sudo sa konfiguracijom koju kontroliše pozivalac

Ako sudo pravilo dozvoljava privilegovani poziv `apachectl`, `apache2ctl` ili `httpd` sa konfiguracionom datotekom `-f` koju kontroliše pozivalac, pregledajte tu datoteku i dozvole njenog roditeljskog direktorijuma. Apache-ova direktiva [`LoadModule`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadmodule) prima ime modula praćeno **imenom datoteke modula**; [`LoadFile`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadfile) takođe učitava datoteku. [`Include` i `IncludeOptional`](https://httpd.apache.org/docs/2.4/mod/core.html#include) mogu da prošire konfiguraciju ili otkriju sadržaj datoteka kroz greške. Prilagođeni wrapper može da validira ove putanje, odbaci privilegije ili ograniči argumente, pa sama upisiva konfiguracija predstavlja kandidata za proveru, a ne dokaz izvršavanja koda. Pre zaključka proverite kanonikalizaciju putanje, symlink-ove i parsiranje direktiva.

### nginx pokrenut kroz sudo sa konfiguracijom koju kontroliše pozivalac

Neograničeno root-capable `nginx` pravilo može da dozvoli [`-c` za izbor druge konfiguracije](https://nginx.org/en/docs/switches.html). Pregledajte tačne sudo argumente i izuzetke, da li pozivalac može da dostavi konfiguraciju i da li master proces ili worker-i zadržavaju pristup zaštićenim putanjama. Izabrani `root` i `autoindex` mogu da izlože datoteke preko novog listener-a; [`dav_methods PUT`](https://nginx.org/en/docs/http/ngx_http_dav_module.html) može da omogući privilegovani upis u datoteku, ali DAV modul nije podrazumevano ugrađen i treba proveriti da li je prisutan, dostupnost listener-a, dozvole datoteka i ponašanje privremenih datoteka. Direktiva [`error_log`](https://nginx.org/en/docs/ngx_core_module.html#error_log) može i da cilja izabranu datoteku; upis logova u osetljivu konfiguracionu datoteku, kao što je `/etc/ld.so.preload`, postaje put za eskalaciju samo ako je aktivan privilegovani upisivač i može da se kontroliše zapis loga. Istaknuti izvršni fajl u `sudo -l` predstavlja razlog za proveru, a ne dokaz da neki od ovih puteva funkcioniše. Tokom pasivne enumeracije nemojte pokretati niti rekonfigurisati nginx.

### Poređenje obrazaca u privilegovanim Bash prompt-ovima

Kada Bash skripta dozvoljena kroz sudo pročita vrednost od pozivaoca i proveri je izrazom `[[ "$expected" == $entered ]]`, Bash tumači desni, nesačuvani operand kao obrazac. Zato wildcard može da zadovolji poređenje bez poznavanja očekivane vrednosti. Ako se operand stavi pod navodnike (`[[ "$expected" == "$entered" ]]`), poređenje tretira string doslovno. Pregledajte tačno sudo pravilo, dostupnost prompt-a i šta skripta radi nakon poređenja; sama sintaksa ne uspostavlja iskoristiv put. Tokom enumeracije izbegavajte ispisivanje očekivane vrednosti. Pogledajte [Bash referencu za uslovne konstrukcije](https://www.gnu.org/software/bash/manual/html_node/Conditional-Constructs.html).

### Helper-i pokrenuti kroz sudo koji preuzimaju i izvršavaju datoteku

Neograničena root-capable sudo dozvola za prilagođeni helper zahteva proveru toka podataka ako prihvata URL koji bira pozivalac, upisuje odgovor na disk, a zatim tu datoteku poziva pomoću interpretera ili shell-a. [sudoers dozvoljava proizvoljne argumente ako ih unos komande ne navodi](https://man7.org/linux/man-pages/man5/sudoers.5.html); fiksna putanja izvršnog fajla ne ograničava izbor koji omogućavaju njegovi argumenti. U instaliranom helper-u proverite stvarnu validaciju URL-a, putanju izlaza, granu uspeha i kasnije izvršavanje. Podudaran libcurl import ili štampiv string sami ne dokazuju ovaj lanac.

Čak i fiksno ime izlazne datoteke može da se zameni između upisa i izvršavanja kada helper koristi **relativnu putanju u radnom direktorijumu koji kontroliše pozivalac**. Preimenovanje ili zamena datoteke u vlasništvu root-a zavisi od prava upisa/pretrage direktorijuma i eventualnih ograničenja sticky bita, a ne samo od režima datoteke; pogledajte [`rename(2)`](https://man7.org/linux/man-pages/man2/rename.2.html). Proverite da li helper kasnije ponovo otvara putanju ili koristi već otvoreni descriptor i da li prelazi u pouzdan direktorijum pre upisa. Pasivno pregledajte sudo politiku, helper i metapodatke direktorijuma; tokom enumeracije nemojte pozivati privilegovano preuzimanje niti izvoditi race.

Root-sudo helper za preuzimanje može i da otkrije **injection argumenata** ako sastavlja Bash komandni string poput `curl <caller input> -o <fixed output>`. Filter koji odbacuje razmake i dalje ostavlja [Bash ekspanziju vitičastih zagrada](https://www.gnu.org/software/bash/manual/html_node/Brace-Expansion.html): elementi razdvojeni zarezima bez navodnika mogu da postanu zasebni curl argumenti. Ako ulaz stiže do curl-a pre fiksnog `-o`, izlazna opcija koju zadaje pozivalac može da izabere odredište za prvi URL u identitetu helper-a; [curl pridružuje izlazne opcije URL-ovima redom](https://curl.se/docs/manpage.html#-o). Potvrdite tačan shell, navodnike, validaciju ulaza, efektivno sudo pravilo, redosled curl argumenata i podržane URL šeme, kao i to da li pozivalac kontroliše preuzete bajtove ili može da čita rezultat. Izvršni fajl upakovan pomoću PyInstaller-a može da sadrži Python logiku aplikacije, ali oznaka pakovanja ili string `curl` sami ne dokazuju ovaj tok podataka. Kada je to ovlašćeno, pregledajte ograničenu offline kopiju; rutinska enumeracija ne treba da pokreće helper niti da preuzima podatke koje kontroliše napadač.

Root-sudo shell skripta koja poziva [`mktemp -u` / `--dry-run`](https://www.gnu.org/software/coreutils/manual/html_node/mktemp-invocation.html) samo bira nekorišćeno ime; **ne** kreira datoteku. Ako skripta kasnije kreira to ime u direktorijumu na koji drugi korisnik može da utiče, ponovo ga otvara i dodaje njegov sadržaj zaštićenom odredištu kao što je root `authorized_keys`, proverite mogući race sa privremenom datotekom. Potvrdite tačno sudo pravilo, vlasništvo nad direktorijumom i datotekom, redosled kreiranja i ponovnog otvaranja, zaštite jezgra i da li privilegovani upis zaista koristi bajtove pod kontrolom napadača. String `mktemp -u` ili upisivi `/tmp` sami ne dokazuju postojanje race-a. Pregledajte skriptu i metapodatke putanje bez pokretanja skripte ili izazivanja race-a tokom enumeracije.

## Bezbednosne napomene

- Izbegavajte da kroz sudo dozvoljavate interpretere ili interaktivne editore.<sup>[[1]](#references)</sup>
- Prednost dajte fiksnim wrapper-ima u vlasništvu root-a koji izvršavaju jednu usko ograničenu administrativnu radnju.<sup>[[1]](#references)[[2]](#references)</sup>
- Ako je interpreter neophodan, ograničite tačnu putanju skripte i sprečite argumente pod kontrolom korisnika, upisive import-e, `PYTHONPATH` i nebezbedno čuvanje okruženja.<sup>[[2]](#references)[[3]](#references)[[4]](#references)</sup>
- Ako je potrebno uređivanje datoteke, ograničite tačnu putanju datoteke i razmotrite `sudoedit` uz ispravljene sudo verzije i strogu obradu okruženja.<sup>[[1]](#references)[[2]](#references)</sup>
- Pregledajte `SETENV`, `env_keep`, upisive radne direktorijume, upisive putanje modula/importa, `NOEXEC`, `use_pty` i logging, ali ih ne smatrajte potpunim sandbox-om.<sup>[[1]](#references)[[2]](#references)[[3]](#references)</sup>
