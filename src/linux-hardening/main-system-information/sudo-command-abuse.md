## Διερμηνευτές που επιτρέπονται μέσω sudo

Αν το `sudo -l` επιτρέπει σε έναν χρήστη να εκτελέσει έναν διερμηνευτή ως root, αντιμετωπίστε το ως άμεση εκτέλεση κώδικα. Οι διερμηνευτές είναι σχεδιασμένοι να εκτελούν αυθαίρετο κώδικα, επομένως ένας κανόνας που επιτρέπει την εκτέλεση των `python3`, `perl`, `ruby`, `lua`, `node` ή παρόμοιων δυαδικών αρχείων ισοδυναμεί συνήθως με εκτέλεση εντολών ως root, εκτός αν τα ορίσματα είναι αυστηρά περιορισμένα και επικυρωμένα.<sup>[[1]](#references)[[2]](#references)[[3]](#references)[[4]](#references)[[5]](#references)[[7]](#references)[[9]](#references)[[11]](#references)</sup>

Συνηθισμένη διαδικασία ελέγχου: πρώτα απαριθμήστε τα δικαιώματα του χρήστη και στη συνέχεια εκτελέστε μια εντολή Python με την επιλογή `-c` του διερμηνευτή.<sup>[[1]](#references)[[3]](#references)[[4]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/python3 -c 'import os; os.system("id")'
sudo /usr/bin/python3 -c 'import os; os.system("/bin/sh")'
```

Παρακάτω παρουσιάζονται άλλα παραδείγματα διερμηνευτών· οι αναφερόμενοι διερμηνευτές τεκμηριώνουν την εκτέλεση inline κώδικα ή API θυγατρικών διεργασιών.<sup>[[5]](#references)[[6]](#references)[[7]](#references)[[8]](#references)[[9]](#references)[[10]](#references)[[11]](#references)</sup>

```bash
sudo /usr/bin/perl -e 'exec "/bin/sh";'
sudo /usr/bin/ruby -e 'exec "/bin/sh"'
sudo /usr/bin/node -e 'require("child_process").spawn("/bin/sh", {stdio: [0,1,2]})'
```

Η ακριβής διαδρομή έχει σημασία. Αν ο κανόνας sudo επιτρέπει το `/usr/bin/python3`, χρησιμοποιήστε αυτήν ακριβώς τη διαδρομή κατά την επικύρωση.<sup>[[2]](#references)</sup>

Ένα glob εκτελέσιμου sudo όπως το `/usr/bin/python*` μπορεί επίσης να επιτρέπει τη χρήση της Python 2 για ένα script γραμμένο για Python 3. Αν το script φτάσει στην `input()` με κείμενο που ελέγχεται από τον καλούντα, [η Python 2 αξιολογεί αυτό το κείμενο ως έκφραση](https://docs.python.org/2/library/functions.html#input)· η ρητή κλήση του interpreter υπερισχύει του shebang του script. Επαληθεύστε τα εγκατεστημένα δυαδικά αρχεία που ταιριάζουν, την ενεργή πολιτική RunAs και ορισμάτων, τις αρνήσεις και την προσβάσιμη είσοδο προτού θεωρήσετε ότι αυτή είναι διαδρομή εκτέλεσης.

Μια σταθερή διαδρομή script σε κανόνα sudo με δυνατότητες root δεν περιορίζει όσα εκτελεί το script. Για ένα αναγνώσιμο Bash wrapper, ελέγξτε αν η πρώτη εκτελέσιμη εντολή χρησιμοποιεί μια μη παρατεθειμένη positional parameter, όπως το `$1`, ως **command word**, ενώ το sudo επιτρέπει ορίσματα που επιλέγει ο καλών. Επιβεβαιώστε την ενεργή ταυτότητα RunAs, την πολιτική κωδικού πρόσβασης και ορισμάτων, τυχόν μεταγενέστερες αρνήσεις και τον κλάδο του script που εκτελείται στην πράξη· το `NOEXEC`, μια σταθερή ασφαλής λίστα ορισμάτων ή ένα wrapper που επικυρώνει την εντολή μπορούν να αλλάξουν το αποτέλεσμα. Επιθεωρήστε στατικά το σύντομο script κατά την απαρίθμηση, αντί να το καλέσετε με μια δοκιμαστική εντολή.

Ένας απεριόριστος κανόνας sudo με δυνατότητες root για το `dotnet` αξίζει επίσης έλεγχο ως προς τον interpreter. Με εγκατεστημένο .NET SDK, το [`dotnet fsi` εκτελεί κώδικα F# διαδραστικά ή από script](https://learn.microsoft.com/en-us/dotnet/fsharp/tools/fsharp-interactive/) και το [`dotnet run` εκτελεί ένα project από τον πηγαίο κώδικα](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-run). Επιβεβαιώστε πρώτα την ενεργή ταυτότητα RunAs και την ακριβή πολιτική ορισμάτων: ένας κανόνας που περιορίζεται σε συγκεκριμένη ασφαλή υποεντολή ή έμπιστη εφαρμογή αποτελεί διαφορετική παραχώρηση, ενώ μια εγκατάσταση μόνο runtime ενδέχεται να μην περιλαμβάνει εντολές SDK. Το όνομα του εκτελέσιμου είναι απλώς ένδειξη για έλεγχο, όχι απόδειξη εκτέλεσης κώδικα.

```bash
sudo /usr/bin/python3 -c 'import os; os.setuid(0); os.setgid(0); os.system("/bin/sh")'
```

## Επεξεργαστές που επιτρέπονται μέσω sudo

Αν το `sudo -l` επιτρέπει σε έναν χρήστη να εκτελέσει έναν διαδραστικό επεξεργαστή ως root, αντιμετωπίστε το ως επιφάνεια εκτέλεσης εντολών και όχι ως ακίνδυνη άδεια επεξεργασίας αρχείων. Οι επεξεργαστές συχνά μπορούν να εκτελούν εντολές shell, να διαβάζουν αυθαίρετα αρχεία, να γράφουν αυθαίρετα αρχεία ή να καλούν εξωτερικά βοηθητικά εργαλεία μέσα από τον επεξεργαστή.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

Συνήθης διαδικασία ελέγχου: καταγράψτε τα δικαιώματα του χρήστη και, στη συνέχεια, εκτελέστε κάθε επιτρεπόμενο επεξεργαστή ή pager μέσω sudo.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/nano /etc/hosts
sudo /usr/bin/vim /etc/hosts
sudo /usr/bin/less /etc/hosts
```

### Εκτέλεση εντολών μέσω της Nano

Όταν επιτρέπεται η χρήση της `nano` μέσω sudo, ενδέχεται να είναι δυνατή η εκτέλεση εντολών από τη διεπαφή του επεξεργαστή.<sup>[[12]](#references)</sup>

```text
Ctrl+R
Ctrl+X
```

Στη συνέχεια, δώστε μια εντολή όπως `id` ή `/bin/sh` στη γραμμή εντολών του nano.<sup>[[12]](#references)</sup>

```bash
id
/bin/sh
```

Αν ένα interactive shell δεν διαθέτει χρησιμοποιήσιμες ροές τερματικού, αυτή η μορφή ανακατεύθυνσης αντιστοιχίζει την τυπική έξοδο και το σφάλμα του στον descriptor 0.<sup>[[15]](#references)</sup>

```bash
reset; /bin/sh 1>&0 2>&0
```

Η ακριβής ακολουθία πλήκτρων μπορεί να διαφέρει ανάλογα με την έκδοση του nano και τις επιλογές κατά το build, αλλά το ζήτημα ασφαλείας παραμένει το ίδιο: ο editor εκτελείται ως root και μπορεί να καλέσει εξωτερικές εντολές.<sup>[[1]](#references)[[12]](#references)</sup>

### Άλλοι συνηθισμένοι τρόποι διαφυγής από editor

Οι editor τύπου Vim συνήθως επιτρέπουν την εκτέλεση εντολών μέσω του `:!`.<sup>[[13]](#references)</sup>

```text
:!/bin/sh
```

Οι pagers όπως το `less` μπορούν επίσης να επιτρέψουν την εκτέλεση shell.<sup>[[14]](#references)</sup>

Ένας κανόνας sudo που επιτρέπει την εκτέλεση του `apport-cli` ως root απαιτεί αντίστοιχο έλεγχο για pager. Σε ευάλωτες εκδόσεις του Apport, μπορούσε να ανοίξει μια αναφορά κατάρρευσης στο `less` με μέγεθος τερματικού που μπορούσε να ρυθμίσει ο επιτιθέμενος· στη συνέχεια, ο pager μπορούσε να δώσει πρόσβαση σε root shell, εφόσον πληρούνταν οι ειδικές προϋποθέσεις για το sudo και τον pager. Ελέγξτε τον ενεργό κανόνα sudo, τη ρύθμιση του pager και τη διόρθωση του πακέτου της διανομής πριν θεωρήσετε ευάλωτη την έκδοση και μόνο. Κατά την παθητική απαρίθμηση, διαβάστε τα μεταδεδομένα του πακέτου και της πολιτικής χωρίς να προκαλέσετε κατάρρευση ή να ανοίξετε την αναφορά με αυξημένα δικαιώματα. Η [καταχώριση CVE του Ubuntu](https://ubuntu.com/security/CVE-2023-1326) αναφέρει τις διορθωμένες εκδόσεις πακέτων ανά έκδοση διανομής, συμπεριλαμβανομένων διορθώσεων που έχουν μεταφερθεί σε παλαιότερες εκδόσεις.

```text
!/bin/sh
```

## Άλλοι κίνδυνοι στους κανόνες sudo και doas

Ξεκινήστε με `sudo -l`, `sudo -V` και τυχόν εφαρμοζόμενη πολιτική `doas`. Διαβάστε μαζί την επιτρεπόμενη εντολή, τον χρήστη RunAs, τα ορίσματα, το περιβάλλον και τις προεπιλογές. Η άδεια εκτέλεσης ως μη-root λογαριασμός υπηρεσίας μπορεί και πάλι να εκθέσει τα αρχεία αυτού του λογαριασμού ή μια διαδρομή προς root.

Ένα σταθερό Python script που επιτρέπεται από το sudo μπορεί και πάλι να εκτελέσει μια shell command με την ταυτότητα RunAs, αν η διαδραστική είσοδος που ελέγχει ο καλών συνενώνεται με το [`os.system()`](https://docs.python.org/3/library/os.html#os.system). Μια denylist σημείων στίξης του shell δεν αρκεί για να αποδείξει ασφάλεια: το [shell αναγνωρίζει επίσης command substitution με `$(...)`](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html). Επιβεβαιώστε ότι τα επιτρεπόμενα ορίσματα φτάνουν στον κλάδο εισόδου, ότι η είσοδος φτάνει στην shell command χωρίς ασφαλή επικύρωση και ότι η ενεργή πολιτική sudo επιτρέπει τον προβλεπόμενο χρήστη RunAs. Η διαδρομή του script ή μια κλήση στο `os.system()` είναι μόνο ένδειξη για περαιτέρω έλεγχο· εξετάστε τον πηγαίο κώδικα χωρίς να εκτελέσετε το προνομιούχο script.

Μια αποτελεσματική άδεια sudo ως root για το `chattr` μπορεί να αφαιρέσει το immutable (`i`) file attribute, αλλά αυτό από μόνο του δεν παρέχει δικαίωμα εγγραφής ή νέα ταυτότητα. Το [εγχειρίδιο του `chattr`](https://man7.org/linux/man-pages/man1/chattr.1.html) αναφέρει ότι το attribute εμποδίζει τις τροποποιήσεις και ότι μόνο το root ή μια διεργασία με `CAP_LINUX_IMMUTABLE` μπορεί να το αλλάξει. Ελέγξτε την ακριβή πολιτική ορισμάτων sudo και την υποστήριξη του filesystem, και στη συνέχεια επαληθεύστε ξεχωριστά ότι ο καλών μπορεί να γράψει στο αρχείο αφού καθαριστεί το attribute και ότι κάποιος καταναλωτής με υψηλότερη ταυτότητα το χρησιμοποιεί. Για παράδειγμα, η αντικατάσταση ενός login shell απαιτεί επίσης τα διαπιστευτήρια που αποδέχεται ο λογαριασμός-στόχος και πραγματική σύνδεση μέσω αυτού του shell. Εξετάστε την πολιτική, τα file attributes και τα δικαιώματα χωρίς να τα αλλάξετε κατά την απογραφή.

Αν το sudo ζητά και κωδικό πρόσβασης και κωδικό μίας χρήσης, αντιμετωπίστε αυτές τις προϋποθέσεις ξεχωριστά από την άδεια της εντολής. Ένα αναγνώσιμο αρχείο `.google_authenticator` περιέχει ευαίσθητο seed material, ενώ ένα παλιό hash κωδικού εφαρμογής ή βάσης δεδομένων είναι απλώς υποψήφιος κωδικός πρόσβασης για τον τρέχοντα λογαριασμό· κανένα από τα δύο δεν αποδεικνύει ότι ο άλλος παράγοντας γίνεται αποδεκτός από την ενεργή διαμόρφωση PAM. Μόλις έχετε εξουσιοδότηση, εξετάστε τον ακριβή χρήστη RunAs και τα ορίσματα: μια απεριόριστη άδεια root για το RubyGems `gem` μπορεί να εκθέσει την εντολή editor του ([GTFOBins](https://gtfobins.github.io/gtfobins/gem/)), αλλά μια περιορισμένη άδεια ή αποτυχημένη πιστοποίηση δεν το κάνει. Η παθητική απογραφή πρέπει να αναφέρει διαδρομές και πολιτική χωρίς να εμφανίζει το seed, να ανακτά κωδικό πρόσβασης, να δημιουργεί κωδικό ή να εκτελεί την προνομιούχο εντολή.

Μια απεριόριστη άδεια sudo ως root για το Chef `knife` αξίζει έλεγχο σε επίπεδο interpreter: [το Chef τεκμηριώνει ότι το `knife exec -E` αξιολογεί τοπικά ένα Ruby string](https://docs.chef.io/workstation/26/tools/knife/knife_exec/). Επαληθεύστε ότι ο ενεργός κανόνας sudo επιτρέπει το subcommand `exec` και το όρισμα `-E` που παρέχει ο καλών, την προβλεπόμενη ταυτότητα RunAs και τυχόν αντίστοιχες απαγορεύσεις εντολών ή σταθερά ορίσματα. Το εγκατεστημένο binary ή ένας κανόνας που περιορίζεται σε άλλα subcommands αποτελεί μόνο ένδειξη. Η παθητική απογραφή πρέπει να αναφέρει τον κανόνα χωρίς να εκτελεί το `knife`.

Μια ακριβής άδεια sudo ως root για διαδραστικό `msfconsole` είναι εξίσου ευαίσθητη: το [GTFOBins τεκμηριώνει την κονσόλα `irb`](https://gtfobins.org/gtfobins/msfconsole/), η οποία μπορεί να κληρονομήσει την ταυτότητα sudo. Επιβεβαιώστε τον ενεργό χρήστη RunAs, τη λίστα επιτρεπόμενων ορισμάτων, τις απαγορεύσεις εντολών, το `NOEXEC` ή άλλους περιορισμούς, τη συμπεριφορά της εγκατεστημένης κονσόλας και αν ο καλών μπορεί να παρέχει διαδραστική είσοδο. Μια επισήμανση διαδρομής είναι μόνο ένδειξη για έλεγχο· η παθητική απογραφή δεν πρέπει να εκκινεί την κονσόλα.

Στο FreeBSD, ακόμη και ένας κανόνας sudo που περιορίζεται στα `pkg update` και `pkg install *` ως root αξίζει έλεγχο εμπιστοσύνης των repositories. Ελέγξτε αν ο καλών μπορεί να γράψει στο `/etc/hosts` και αν η *ενεργή* διαμόρφωση ενεργοποιημένων repositories χρησιμοποιεί hostname HTTP με `signature_type: none`. Το [εγχειρίδιο `pkg.conf` του FreeBSD](https://man.freebsd.org/cgi/man.cgi?query=pkg.conf&sektion=5) αναφέρει ότι το `none` απενεργοποιεί τους ελέγχους υπογραφής· το `pkg+http` από μόνο του δεν το αποδεικνύει. Ένα package μπορεί να περιέχει install scripts ([FreeBSD Porter's Handbook](https://docs.freebsd.org/en/books/porters-handbook/pkg-files/)), οπότε ένας καλών που ελέγχει πραγματικά το endpoint του repository και μπορεί να επιλέξει package ενδέχεται να περάσει το όριο root. Επαληθεύστε τις παρακάμψεις repository, την επίλυση SRV/mirror, τα ενεργά ορίσματα sudo, την επιλογή package και την εκτέλεση script προτού καταλήξετε σε αυτό το συμπέρασμα. Εξετάστε την πολιτική και μικρά τοπικά αρχεία ρυθμίσεων χωρίς να ανακατευθύνετε ονόματα ή να εκτελέσετε το `pkg` κατά την απογραφή.

Μια άδεια sudo ως root για `apt-get update` και `apt-get upgrade` χρειάζεται επίσης έλεγχο εμπιστοσύνης των repositories όταν το sudo διατηρεί `http_proxy` που ελέγχει ο καλών. Ελέγξτε αν η ενεργή διαμόρφωση APT χρησιμοποιεί πράγματι αυτή τη μεταβλητή και ποια αιτήματα προς ενεργοποιημένα repositories μπορεί να επηρεάσει· ένας proxy από μόνος του δεν μπορεί να αντικαταστήσει packages από archive που έχει πιστοποιηθεί με έμπιστο signing key. Το [εγχειρίδιο HTTP transport του APT](https://manpages.debian.org/experimental/apt/apt-transport-http.1.en.html) τεκμηριώνει την προτεραιότητα των proxy, ενώ το [apt-secure](https://manpages.debian.org/experimental/apt/apt-secure.8.en.html) τεκμηριώνει τους ελέγχους υπογραφής, τις παρακάμψεις μη ασφαλών repositories και την επιβεβαίωση για μη πιστοποιημένα packages. Επιβεβαιώστε τον ακριβή χρήστη RunAs και τα ορίσματα sudo, την πολιτική πιστοποίησης των repositories, τυχόν απαιτούμενη διαδραστική αποδοχή και αν το επιλεγμένο upgrade εκτελεί scripts package ως root. Εξετάστε παθητικά την πολιτική και την τοπική διαμόρφωση· μην ανακατευθύνετε την κίνηση των packages και μην εκτελείτε upgrade κατά την απογραφή.

Ένας κανόνας sudo ως root για `snap install` μπορεί να δημιουργήσει όριο package-to-code, αν τα ορίσματά του επιτρέπουν στον καλούντα να επιλέξει τοπικό snap και χαλαρό τρόπο εγκατάστασης. Το [Snap τεκμηριώνει](https://snapcraft.io/docs/explanation/snap-development/install-modes/) ότι το `--dangerous` παρακάμπτει τους ελέγχους assertion των τοπικών snap και ότι το `--devmode` χαλαρώνει τον περιορισμό· [ένα install hook μπορεί να εκτελεστεί κατά την αρχική εγκατάσταση](https://snapcraft.io/docs/reference/development/supported-snap-hooks/). Ελέγξτε την ακριβή πολιτική ορισμάτων/RunAs του sudo, ποιος ελέγχει το αρχείο snap, αν το εγκατεστημένο snapd δέχεται αυτούς τους τρόπους και την ενεργή ταυτότητα και confinement του hook προτού ισχυριστείτε πρόσβαση σε προστατευμένα αρχεία του host. Ένα binary `snap` ή ένας κανόνας που μοιάζει να έχει wildcard δεν αποδεικνύει από μόνο του αυτή την αλυσίδα. Η παθητική απογραφή δεν πρέπει να εγκαθιστά package ή να εκτελεί το hook.

Για μια ακριβή άδεια sudo σε binary που διαβάζει διαπιστευτήρια και εκτελείται ως **μη-root** λογαριασμός, εξετάστε πρώτα το binary και τα δικαιώματα του αρχείου του χωρίς να το εκτελέσετε. Ένα ενσωματωμένο password gate μπορεί να εμφανίζεται μόνο ως wide characters· το [GNU `strings` τεκμηριώνει εξαγωγή 16-bit little-endian](https://sourceware.org/binutils/docs/binutils/strings.html). Μια ορατή συμβολοσειρά δεν αποδεικνύει ότι είναι ο αποδεκτός κωδικός πρόσβασης ή ότι ο κλάδος επιτυχίας εκθέτει κάποιο τρέχον διαπιστευτήριο. Επιβεβαιώστε ξεχωριστά τη συμπεριφορά του binary, την πρόσβαση του λογαριασμού-στόχου στα προστατευμένα δεδομένα, την εγκυρότητα των διαπιστευτηρίων και τυχόν μεταγενέστερη μετάβαση λογαριασμού ή ομάδας. Αν αυτός ο λογαριασμός ανήκει στην ομάδα `docker`, επαληθεύστε την πρόσβαση στο socket και αν ο daemon εκτελείται ως rootful ή rootless πριν συμπεράνετε ότι υπάρχει πρόσβαση ως root στο host· το [Docker τεκμηριώνει τις επιπτώσεις της ομάδας σε επίπεδο root](https://docs.docker.com/engine/install/linux-postinstall/). Η συνήθης απογραφή πρέπει να αναφέρει τον κανόνα sudo και τη συμμετοχή στην ομάδα χωρίς να εκτελεί το binary ή να εμφανίζει τα strings του.

Ένας κανόνας sudo με wildcard για scripts συντήρησης μιας εφαρμογής χρειάζεται έλεγχο πέρα από τη διαδρομή του script. Ελέγξτε αν το επιτρεπόμενο script δέχεται απεριόριστα ορίσματα ή διαβάζει ρυθμίσεις στις οποίες μπορεί να γράψει ένας λογαριασμός εφαρμογής χαμηλότερων δικαιωμάτων, και στη συνέχεια ακολουθήστε αυτές τις τιμές μέχρι shell commands ή το περιβάλλον μιας subprocess. Για παράδειγμα, το ZoneMinder [`zmupdate.pl` συνθέτει μια εντολή `mysqldump` και την εκτελεί μέσω `qx`](https://github.com/ZoneMinder/ZoneMinder/blob/master/scripts/zmupdate.pl.in), ενώ το [`zmdc.pl` αντιγράφει τη ρύθμιση `ZM_LD_PRELOAD` στο `LD_PRELOAD`](https://github.com/ZoneMinder/ZoneMinder/blob/master/scripts/zmdc.pl.in) προτού εκκινήσει daemons. Ένας κανόνας sudo που επιτρέπει οποιοδήποτε από τα δύο scripts ως root μπορεί να περάσει όριο εμπιστοσύνης αν η αντίστοιχη είσοδος ελέγχεται και φτάνει σε αυτόν τον κώδικα στην εγκατεστημένη έκδοση. Εξετάστε την πολιτική και τα metadata του package χωρίς να σαρώσετε ειδικά διαμορφωμένο αρχείο ή να εμφανίσετε προστατευμένη έξοδο κατά την απογραφή.
- Ένας κανόνας sudo ως root που ανοίγει εικόνα κρυπτογραφημένου δίσκου που επιλέγει ο καλών, μαζί με δεύτερο κανόνα που προσαρτά τον mapper που προκύπτει, μπορεί να εισαγάγει αρχεία ελεγχόμενα από τον καλούντα στο mount namespace του host. Επιβεβαιώστε και τους δύο ενεργούς κανόνες και τα ορίσματα, τον έλεγχο της εικόνας και του ονόματος mapper, τον πραγματικό mount target και τον ιδιοκτήτη και τρόπο πρόσβασης των αρχείων που προκύπτουν. Μια μετάβαση set-user-ID απαιτεί επίσης προσβάσιμο εκτελέσιμο, επιλογές mount που την επιτρέπουν (`nosuid` την μπλοκάρει) και την εφαρμοζόμενη πολιτική διεργασίας ή MAC· το άνοιγμα ή το mount μιας εικόνας από μόνο του είναι απλώς ένδειξη για έλεγχο. Μια ξεχωριστή διαδρομή μέσω υπάρχοντος backup απαιτεί το πραγματικό κλειδί του και χρήσιμο αναγνώσιμο μυστικό μέσα σε αυτό. Εξετάστε την πολιτική και τις διαδρομές χωρίς να ανοίξετε ή να προσαρτήσετε εικόνα κατά την παθητική απογραφή. Δείτε το [εγχειρίδιο cryptsetup](https://gitlab.com/cryptsetup/cryptsetup/-/blob/main/man/cryptsetup.8.adoc) και τις [επιλογές mount](https://man7.org/linux/man-pages/man8/mount.8.html).
- Ένας κανόνας sudo ως root για shell ή Python script αξίζει έλεγχο working directory αν το script καλεί `./helper` χωρίς προηγουμένως να μεταβεί σε σταθερό κατάλογο. Μια Python λίστα όπως `['./helper']` που περνά στο `subprocess.run` μπορεί να έχει την ίδια συμπεριφορά ως προς τον working directory που επιλέγει ο καλών. Ο καλών ενδέχεται να μπορεί να επιλέξει εγγράψιμο κατάλογο και να τοποθετήσει εκεί εκτελέσιμο με αυτό το σχετικό όνομα· μια απόλυτη διαδρομή αλλού στο script δεν προστατεύει αυτή την κλήση. Επιβεβαιώστε τον ενεργό κανόνα, το `runchdir` ή άλλη πολιτική αλλαγής καταλόγου, τη ροή του script και αν ο κλάδος είναι προσβάσιμος, έναν εγγράψιμο και εκτελέσιμο κατάλογο, καθώς και περιορισμούς mount/`NOEXEC`, προτού το θεωρήσετε εκτέλεση κώδικα. Αν το script δεν είναι αναγνώσιμο, η συμπεριφορά παραμένει άγνωστη μέχρι να εξεταστεί ο πηγαίος κώδικας μέσω εξουσιοδοτημένης διαδρομής. Εξετάστε στατικά τα scripts αντί να εκτελέσετε το helper. Το [εγχειρίδιο sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) τεκμηριώνει την πολιτική working-directory.
- Ένας σταθερός Python validator με δυνατότητες root μπορεί και πάλι να αξιολογήσει αρχείο δεδομένων που επιλέγει ο καλών. Η [τεκμηρίωση του `eval()` στην Python προειδοποιεί κατά μη έμπιστης εισόδου](https://docs.python.org/3/library/functions.html#eval): έλεγχος κατάληξης εισόδου, αριθμητικό πρόθεμα ή κλάδος επικύρωσης δεν αποτελούν sandbox αν η υπόλοιπη έκφραση φτάσει στο `eval`. Επιβεβαιώστε τον ενεργό κανόνα sudo, αν ο καλών μπορεί να επιλέξει και να ελέγξει το ακριβές αρχείο, τις συνθήκες κλάδου του parser και τη δημιουργία της έκφρασης, καθώς και την ταυτότητα της προνομιούχας διεργασίας προτού το θεωρήσετε διαδρομή εκτέλεσης. Η παρουσία του `eval` σε αναγνώσιμο script από μόνη της είναι μόνο αφορμή για έλεγχο· εξετάστε τον πηγαίο κώδικα και τα δικαιώματα αρχείου χωρίς να εκτελέσετε τον validator ή να υποβάλετε δοκιμαστική έκφραση κατά την απογραφή.
- Ένα Ruby wrapper sudo ως root που διαβάζει σχετικό όνομα αρχείου YAML, όπως `YAML.load(File.read("dependencies.yml"))`, μπορεί να λάβει είσοδο από τον working directory του καλούντος, εκτός αν το wrapper ή η πολιτική sudo ορίζει σταθερό κατάλογο. Ελέγξτε τα ακριβή επιτρεπόμενα ορίσματα, τα δικαιώματα καταλόγου και αρχείου και τη συμπεριφορά της εγκατεστημένης έκδοσης Psych: παλαιότερες υλοποιήσεις του `YAML.load` μπορούσαν να αποσειριοποιήσουν αυθαίρετα Ruby objects, ενώ νεότερες εκδόσεις περιορίζουν τις κλάσεις από προεπιλογή. Ένα στατικό σημείο κλήσης είναι μόνο ένδειξη για έλεγχο· επιβεβαιώστε ότι το αρχείο πράγματι προέρχεται από κατάλογο εγγράψιμο από τον καλούντα και ότι ο εγκατεστημένος loader δέχεται επικίνδυνες κλάσεις. Για μη έμπιστη είσοδο προτιμήστε `safe_load` με ρητή, ελάχιστη allowlist κλάσεων. Δείτε την [τεκμηρίωση Psych για Ruby 3.0](https://docs.ruby-lang.org/en/3.0/Psych.html) και την [τεκμηρίωση Psych για Ruby 3.1](https://ruby-doc.org/core-3.1.2/Psych.html).

- Μια ακριβής άδεια sudo ως root για `sudo go run /absolute/file.go` αξίζει έλεγχο working directory όταν ο Go source διαβάζει σχετικό αρχείο WASM και μπορεί να εκτελέσει σχετικό shell script αφού εξετάσει το αποτέλεσμά του. Επιβεβαιώστε τον ενεργό RunAs, τα ορίσματα και τις απαγορεύσεις εντολών, έναν τρέχοντα κατάλογο εγγράψιμο από τον καλούντα, τη ροή δεδομένων από WASM στον κλάδο και αν αυτός ο κλάδος καλεί το helper. Σταθερό sudo `runchdir`, `os.Chdir` ή [`exec.Cmd.Dir`](https://pkg.go.dev/os/exec) μπορεί να αλλάξει τη θέση αναζήτησης. Η στατική συνύπαρξη αυτών των στοιχείων είναι μόνο υποψήφια ένδειξη· εξετάστε τον πηγαίο κώδικα χωρίς να εκτελέσετε Go, WASM ή το helper.
- Τα `sudoedit` και τα wildcards ορισμάτων απαιτούν έλεγχο της ακριβούς έκδοσης και του κανόνα· η [checklist](linux-privilege-escalation-checklist.md) περιλαμβάνει το ζήτημα επεξεργασίας αρχείων sudoedit. Για δια-user άδεια `sudoedit` σε wildcard διαδρομή, εξετάστε τη ρύθμιση `sudoedit_follow` ή `FOLLOW`, το `sudoedit_checkdir`, τον επιλυμένο στόχο και ποιος μπορεί να αντικαταστήσει κάθε parent entry. Η πρώτη μπορεί να επιτρέψει ακολούθηση symlink, ενώ η απενεργοποίηση της δεύτερης αφαιρεί τους ελέγχους εγγράψιμων καταλόγων· καμία ρύθμιση από μόνη της δεν αποδεικνύει εγγραφή σε αρχείο άλλου χρήστη. Επιβεβαιώστε την εγκατεστημένη πολιτική sudo και τα ακριβή ορίσματα που αντιστοιχούν στον κανόνα πριν καταλήξετε σε αυτό το συμπέρασμα. Δείτε τους [ορισμούς επιλογών του sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf).
- Σε κανόνα εντολής sudoers, ένα wildcard ορίσματος μπορεί να ταιριάξει whitespace καθώς και χαρακτήρες διαδρομής. Ένας κανόνας για εντολή που μπορεί να διαβάζει αρχεία, με όρισμα όπως `/restricted/*`, μπορεί επομένως να επιτρέπει επιπλέον όρισμα αρχείου μετά από ταιριαστό πρόθεμα. Εξετάστε τον ακριβή χρήστη run-as, τη διαδρομή εντολής, το μοτίβο ορισμάτων και τυχόν μεταγενέστερες απαγορεύσεις· η επίδειξη ανάγνωσης αρχείου δεν συνεπάγεται εκτέλεση εντολών. Το [εγχειρίδιο sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) διακρίνει τα argument globs από τα command-path globs.
- Ένα argument glob που μοιάζει με διαδρομή μπορεί επίσης να ταιριάξει `../`. Για παράδειγμα, ένας κανόνας root-capable `node /opt/scripts/*.js` μπορεί να επιτρέψει JavaScript αρχείο που επιλέγει ο καλών εκτός του `/opt/scripts`, αν η παρεχόμενη διαδρομή αρχίζει ακόμη με `/opt/scripts/` και επιλύεται μέσω parent-directory segments. Αυτό είναι **argument** glob· το command-path glob για το εκτελέσιμο Node έχει διαφορετικούς κανόνες αντιστοίχισης καθέτων. Ελέγξτε τον ενεργό κανόνα, τις μεταγενέστερες απαγορεύσεις, την επίλυση διαδρομής, τον έλεγχο του αρχείου-στόχου και τυχόν περιορισμούς regular-expression ή digest του sudoers προτού καταλήξετε σε εκτέλεση κώδικα. Δείτε τους [κανόνες wildcard του sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) και την [τεκμηρίωση γραμμής εντολών του Node](https://nodejs.org/api/cli.html).
- Archivers και άλλα utility programs μπορεί να διαθέτουν execution hooks. Ελέγξτε τα ακριβή επιτρεπόμενα ορίσματα στο [GTFOBins](https://gtfobins.github.io/) αντί να υποθέσετε ότι μόνο shells ή interpreters εκτελούν εντολές.
- Ένας απεριόριστος κανόνας sudo `qpdf` με δυνατότητες root μπορεί να εκθέσει προνομιούχο αρχείο μέσω PDF attachments: το qpdf 10.2 και μεταγενέστερες εκδόσεις υποστηρίζουν `--empty` και `--add-attachment file ... --` με PDF εξόδου. Αν η προνομιούχος διεργασία μπορεί να διαβάσει την επιλεγμένη πηγή και να γράψει το PDF σε διαδρομή προσβάσιμη από τον καλούντα, η έξοδος μπορεί να περιέχει τα bytes της πηγής. Εξετάστε τα ενεργά ορίσματα και τις εξαιρέσεις sudo, την έκδοση qpdf, την πρόσβαση στην πηγή και τη διαδρομή εξόδου προτού συμπεράνετε ότι είναι δυνατή η αποκάλυψη αρχείου. Η ανάγνωση root SSH key είναι χρήσιμη για σύνδεση μόνο αν το κλειδί είναι έγκυρο και επιτρέπεται SSH authentication ως root. Δείτε τις [επιλογές attachments του qpdf](https://qpdf.readthedocs.io/en/stable/cli.html#embedded-files-attachments).
- Η επαναχρησιμοποίηση sudo timestamp εξαρτάται από την πολιτική cache, τον ιδιοκτήτη χρήστη, το terminal/session και τα δικαιώματα. Ο [οδηγός privilege escalation](../linux-basics/linux-privilege-escalation/README.md#reusing-sudo-tokens) καλύπτει τους ελέγχους.
- Το `doas` έχει δικούς του κανόνες και configuration. Ελέγξτε τις επιτρεπόμενες εντολές και τις διαδρομές configuration που είναι εγγράψιμες, όπως περιγράφεται στην [ενότητα doas](../linux-basics/linux-privilege-escalation/README.md#doas).

### Εργαλεία build και package που εκτελούνται μέσω sudo

Μια απεριόριστη άδεια sudo για το Foundry `forge` μπορεί να έχει σημασία ακόμη κι όταν η ταυτότητα RunAs είναι άλλος μη-root χρήστης. Επιλογές compiler όπως το `--use` μπορούν να επιλέξουν τοπικό εκτελέσιμο, ενώ το `forge flatten -o` επιλέγει αρχείο εξόδου. Ελέγξτε την εγκατεστημένη έκδοση Forge, τα ακριβή ορίσματα sudo, τα προσβάσιμα project και compiler paths, τα δικαιώματα εξόδου και το ενεργό περιβάλλον προτού θεωρήσετε την άδεια εκμεταλλεύσιμη. Ένα σχετικό helper executable που εντοπίζεται μέσω `PATH` είναι διαδρομή που εξαρτάται από την έκδοση και το περιβάλλον, όχι κάτι που πρέπει να θεωρείται δεδομένο για κάθε Forge build.<sup>[[23]](#references)[[24]](#references)</sup>

Μια απεριόριστη άδεια `pacman` με δυνατότητες root επιτρέπει περισσότερα από package queries: το `-U` δέχεται τοπικό package, τα packages μπορεί να περιέχουν install scripts και το `--hookdir` επιλέγει διαφορετικό κατάλογο hooks. Εξετάστε τον ενεργό κανόνα sudo, τους περιορισμούς και τις εξαιρέσεις ορισμάτων προτού δοκιμάσετε· η παθητική απογραφή δεν χρειάζεται να εγκαταστήσει package ή να εκτελέσει hook.<sup>[[25]](#references)[[26]](#references)</sup>

Ένα σταθερό shell wrapper sudo μπορεί επίσης να εγκαταστήσει ονομασμένη npm dependency και έπειτα να εκκινήσει Node application. Εξετάστε τον ακριβή κανόνα RunAs, αν το package είναι ήδη εγκατεστημένο, τα ενεργά `HOME` και npm `userconfig`, τα project configuration ή τις παρακάμψεις γραμμής εντολών, καθώς και αν χρήστης χαμηλότερων δικαιωμάτων ελέγχει το registry ή το package που επιστρέφεται για αυτό το όνομα. Το [npm τεκμηριώνει την αναζήτηση `.npmrc` ανά χρήστη και project](https://docs.npmjs.com/cli/v6/configuring-npm/npmrc/)· η συμπεριφορά του `HOME` στο sudo εξαρτάται από την εγκατεστημένη πολιτική και τη διανομή, επομένως ένα `.npmrc` εγγράψιμο από χρήστη μπορεί να διαβάζεται ή να μη διαβάζεται από την προνομιούχο διεργασία npm. Αν το νεοεγκατεστημένο package γίνει import από την προνομιούχο εφαρμογή, ο κώδικας του module μπορεί να εκτελεστεί με την ταυτότητα της εφαρμογής. Τα install-time scripts αποτελούν ξεχωριστή διαδρομή, που εξαρτάται από την έκδοση και τη διαμόρφωση· το [npm τεκμηριώνει τον κύκλο ζωής τους και τον χειρισμό χρήστη](https://docs.npmjs.com/cli/v6/using-npm/scripts/). Μια διαδρομή `.npmrc` ή μια γραμμή `npm install` από μόνη της είναι μόνο ένδειξη για έλεγχο. Εξετάστε τον κανόνα, το σύντομο wrapper, τις διαδρομές configuration και την προέλευση του package χωρίς να εγκαταστήσετε package ή να εκκινήσετε την εφαρμογή κατά την παθητική απογραφή.

Μια άδεια sudo ως root για `pip` ή `pip3 download` αποτελεί επίσης αφορμή για έλεγχο package build όταν τα ορίσματά της επιτρέπουν στον καλούντα να επιλέξει μη έμπιστο source distribution, ακόμη κι αν το μοτίβο URL το περιορίζει σε τοπική υπηρεσία και κατάληξη `.tar.gz`. Το `pip download` δέχεται URLs αρχείων και επιλύει metadata package· η προετοιμασία ενός sdist μπορεί να εκτελέσει build backend ή κώδικα legacy `setup.py` προτού απλώς αποθηκευτεί το archive. Επιβεβαιώστε τον ακριβή κανόνα RunAs και ορισμάτων sudo, αν ο καλών μπορεί να δημοσιεύσει ή να αντικαταστήσει το επιλεγμένο archive και αν αυτή η έκδοση pip πράγματι προετοιμάζει τα metadata του. Ένα σταθερό έμπιστο archive ή wheel δεν αποδεικνύει αυτή τη διαδρομή. Μην κάνετε fetch ή build μη έμπιστου package κατά την παθητική απογραφή. Δείτε την [εντολή download του pip](https://pip.pypa.io/en/stable/cli/pip_download/), τη [διεπαφή build-system](https://pip.pypa.io/en/stable/reference/build-system/) και τις [οδηγίες ασφαλούς εγκατάστασης](https://pip.pypa.io/en/stable/topics/secure-installs/).

Ένας κανόνας sudo που επιτρέπει `pip install` με διαδρομή τοπικού project που επιλέγει ο καλών δημιουργεί πιο άμεσο όριο build. Το [pip δέχεται τοπικούς καταλόγους project](https://pip.pypa.io/en/stable/topics/local-project-installs/) και καλεί το build system τους· το [build backend εκτελεί build hooks που ελέγχει το project](https://pip.pypa.io/en/stable/reference/build-system/). Επιβεβαιώστε την ενεργή ταυτότητα RunAs, τους ακριβείς περιορισμούς και τις απαγορεύσεις ορισμάτων, τον έλεγχο του επιλεγμένου project και τη συμπεριφορά του εγκατεστημένου pip/backend προτού θεωρήσετε τον κανόνα προνομιούχα εκτέλεση κώδικα. Ένα σταθερό έμπιστο project ή κανόνας που αποκλείει διαδρομές που επιλέγει ο καλών δεν αποδεικνύει αυτή τη διαδρομή. Εξετάστε τον κανόνα και τα metadata του project χωρίς να εγκαταστήσετε package κατά την παθητική απογραφή.

Μια απεριόριστη άδεια sudo ως root για `easy_install` αποτελεί παρόμοια ένδειξη για legacy package build. Το [Setuptools τεκμηριώνει](https://setuptools.pypa.io/en/stable/deprecated/easy_install.html) ότι το Easy Install δέχεται τοπικό κατάλογο project και κάνει build source distributions· ένα project που ελέγχει ο καλών μπορεί να εκτελέσει το `setup.py` κατά τη διάρκεια αυτού του build με την ταυτότητα sudo. Επιβεβαιώστε τον ενεργό λογαριασμό RunAs, την ακριβή εντολή και τους περιορισμούς ορισμάτων (μαζί με τυχόν μεταγενέστερες απαγορεύσεις), τον έλεγχο του επιλεγμένου project και τη συμπεριφορά του εγκατεστημένου εργαλείου. Ένα σταθερό έμπιστο project ή πολιτική που δεν επιτρέπει πηγή επιλεγμένη από τον καλούντα δεν αποδεικνύει αυτή τη διαδρομή. Εξετάστε τον κανόνα και τα metadata του project χωρίς να εγκαταστήσετε package κατά την απογραφή.

Ένα Python wrapper που επιτρέπεται από το sudo και χρησιμοποιεί `setuptools.package_index.PackageIndex.download` με URL που επιλέγει ο καλών είναι διαφορετική περίπτωση ελέγχου από το `pip download`: το [setuptools GHSA-5rjg-fvgr-3xxf](https://github.com/pypa/setuptools/security/advisories/GHSA-5rjg-fvgr-3xxf) περιγράφει filename που προκύπτει από URL και ξεφεύγει από τον προβλεπόμενο κατάλογο download, γράφοντας με τα δικαιώματα της διεργασίας σε επηρεαζόμενες εκδόσεις πριν από την 78.1.1. Επιβεβαιώστε τον ενεργό χρήστη RunAs και τον κανόνα ορισμάτων sudo, ότι το wrapper περνά το URL του καλούντος σε αυτό ακριβώς το API, το εγκατεστημένο build ή vendor backport και πού επιλύεται η προκύπτουσα διαδρομή. Ένα version string ή ένας εγγράψιμος κατάλογος download από μόνος του δεν αποδεικνύει αυθαίρετη εγγραφή. Εξετάστε το σύντομο wrapper και τα metadata του package χωρίς να κάνετε fetch το URL ή να γράψετε αρχείο κατά την απογραφή.

Ένα build wrapper που επιτρέπεται από το sudo και περνά αρχείο `.spec` που επιλέγει ο καλών στο PyInstaller χρειάζεται αντίστοιχο έλεγχο ορίου εμπιστοσύνης. Ένα PyInstaller spec είναι εκτελέσιμο Python που αξιολογείται κατά το **build**, ενώ οι καταχωρίσεις του `datas` μπορούν να ενσωματώσουν σε artifact αρχεία που διαβάζει η ταυτότητα build. Επιβεβαιώστε τον ακριβή χρήστη RunAs, τους κανόνες ορισμάτων και απαγορεύσεων sudo, τον χειρισμό διαδρομής και κλάδων του wrapper, τον έλεγχο του επιλεγμένου spec file και την πρόσβαση στο παραγόμενο artifact. Το ότι επιτρέπεται είσοδος `.py` ή είναι εγκατεστημένο το PyInstaller δεν αποδεικνύει έλεγχο spec file ή προνομιούχα εκτέλεση. Η παθητική εξέταση πρέπει να διαβάζει μόνο περιορισμένο τμήμα του wrapper και metadata· δεν πρέπει να εκτελεί build. Δείτε την [τεκμηρίωση spec files του PyInstaller](https://pyinstaller.org/en/stable/spec-files.html).

### Loaders preset και plugin που εκτελούνται μέσω sudo

Python tools που δέχονται preset ή κατάλογο plugin που επιλέγει ο καλών μπορεί να κάνουν import κώδικα με τα δικαιώματα που παρέχει το sudo. Για παράδειγμα, το BBOT δέχεται preset με `-p`, ενώ η [τεκμηρίωση custom modules](https://www.blacklanternsecurity.com/bbot/Stable/dev/module_howto/#load-modules-from-custom-locations) περιγράφει καταχωρίσεις `module_dirs` που επιλέγουν επιπλέον καταλόγους Python modules. ### Προνομιούχα backup wrappers που ξαναγράφουν task file του καλούντος

Επαληθεύστε τον ενεργό κανόνα sudo, το εγκατεστημένο build, τη συμπεριφορά υποβιβασμού δικαιωμάτων και αν μπορεί να συμβεί rotation πριν θεωρήσετε τον κανόνα διαδρομή escalation. Ένας επισημασμένος κανόνας είναι υποψήφια περίπτωση, όχι απόδειξη εκτέλεσης εντολής ως root.

Αν το `sudo -l` επιτρέπει το `needrestart` ως root με ορίσματα που επιτρέπουν το `-c` και ο καλών μπορεί να επιλέξει αναγνώσιμο αρχείο configuration σε εγγράψιμη τοποθεσία, αυτή η άδεια μπορεί να οδηγήσει σε εκτέλεση κώδικα ως root. Ελέγξτε τον ακριβή κανόνα sudo run-as και ορισμάτων· ένας κανόνας που επιτρέπει μόνο σταθερή λίστα ορισμάτων μπορεί να μπλοκάρει αυτή τη διαδρομή. Αυτό είναι ξεχωριστό από τις ευπάθειες σάρωσης interpreters του needrestart: η ενημέρωση του package ή η απενεργοποίηση του `interpscan` δεν καθιστά ασφαλή μια απεριόριστη άδεια root `-c`.<sup>[[2]](#references)[[18]](#references)[[19]](#references)</sup>

### Python imports μέσω sudo με ταυτότητα άλλου λογαριασμού

Ένα σταθερό Python entry point μπορεί και πάλι να κάνει import module που ο καλών μπορεί να τροποποιήσει ή να αντικαταστήσει, ακόμη και όταν το sudo εκτελεί το script ως **μη-root** χρήστη υπηρεσίας. Για ένα literal `from utils import status`, εξετάστε τα τοπικά `utils/__init__.py` και `utils/status.py`, καθώς και τα δικαιώματα του καταλόγου package. Επιβεβαιώστε τη διαδρομή import του script, τα ακριβή επιτρεπόμενα ορίσματα sudo και αν η σχετική ενέργεια φτάνει σε αυτό το import προτού θεωρήσετε το εγγράψιμο αρχείο διαδρομή εκτέλεσης. Εξετάστε αρχεία και δικαιώματα χωρίς να κάνετε import ή να εκτελέσετε το script κατά την απογραφή.<sup>[[2]](#references)[[3]](#references)</sup>

Ένας ακριβής κανόνας sudo για `python3 /absolute/script.py` χρειάζεται μόνο αναγνώσιμο script· το αρχείο δεν χρειάζεται να είναι εκτελέσιμο ή να έχει shebang. Εξετάστε και **τοπικά modules που λείπουν**: αν το script κάνει import module του οποίου το όνομα αρχείου μπορεί να δημιουργηθεί σε κατάλογο script εγγράψιμο από τον καλούντα, η Python μπορεί να φορτώσει αυτό το αρχείο με την ταυτότητα RunAs. Επιβεβαιώστε τον ενεργό κανόνα sudo, την πραγματική [διαδρομή αναζήτησης modules](https://docs.python.org/3/library/sys_path_init.html) του interpreter, αν το module είναι built-in ή frozen και αν εκτελείται το import. Ένας άμεσος κανόνας sudo για το script έχει διαφορετικές απαιτήσεις για execute bit και shebang. Ένα ξεχωριστό wrapper που προσθέτει tokens του καλούντος μετά το `sudo -u account` χρειάζεται επίσης έλεγχο ροής ορισμάτων: ένα επιπλέον `-u` σε αυτά τα tokens έχει σημασία μόνο αν η πολιτική sudo της εντολής που καλείται επιτρέπει την προκύπτουσα ταυτότητα. Στατικά strings από μόνα τους δεν αποδεικνύουν καμία από τις δύο διαδρομές.

### Apache μέσω sudo με configuration που ελέγχει ο καλών

Αν ένας κανόνας sudo επιτρέπει προνομιούχα κλήση `apachectl`, `apache2ctl` ή `httpd` με αρχείο configuration `-f` που ελέγχει ο καλών, εξετάστε αυτό το αρχείο και τα δικαιώματα του γονικού καταλόγου του. Η οδηγία [`LoadModule`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadmodule) του Apache παίρνει όνομα module και έπειτα το **filename του module**· και η [`LoadFile`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadfile) φορτώνει επίσης αρχείο. Τα [`Include` και `IncludeOptional`](https://httpd.apache.org/docs/2.4/mod/core.html#include) μπορούν να επεκτείνουν το configuration ή να εκθέσουν περιεχόμενα αρχείων μέσω σφαλμάτων. Ένα custom wrapper μπορεί να επικυρώνει αυτές τις διαδρομές, να υποβιβάζει δικαιώματα ή να περιορίζει ορίσματα, επομένως ένα εγγράψιμο configuration είναι υποψήφιο για έλεγχο και όχι απόδειξη εκτέλεσης κώδικα. Ελέγξτε την canonicalization διαδρομών, τα symlinks και το parsing των directives πριν καταλήξετε σε συμπέρασμα.

### nginx μέσω sudo με configuration που ελέγχει ο καλών

Ένας απεριόριστος κανόνας sudo `nginx` με δυνατότητες root μπορεί να επιτρέψει στο [`-c` να επιλέξει άλλο configuration](https://nginx.org/en/docs/switches.html). Εξετάστε τα ακριβή ορίσματα και τις εξαιρέσεις sudo, αν ο καλών μπορεί να παρέχει το configuration και αν ο προκύπτων master ή οι workers διατηρούν πρόσβαση σε προστατευμένες διαδρομές. Ένα επιλεγμένο `root` μαζί με `autoindex` μπορεί να εκθέσει αρχεία μέσω νέου listener· το [`dav_methods PUT`](https://nginx.org/en/docs/http/ngx_http_dav_module.html) μπορεί να προσφέρει προνομιούχα διαδρομή εγγραφής αρχείων, αλλά το DAV module δεν γίνεται build από προεπιλογή και πρέπει να ελεγχθούν η παρουσία του, η προσβασιμότητα του listener, τα δικαιώματα αρχείων και η συμπεριφορά προσωρινών αρχείων. Η οδηγία [`error_log`](https://nginx.org/en/docs/ngx_core_module.html#error_log) μπορεί επίσης να στοχεύει επιλεγμένο αρχείο· η εγγραφή logs σε ευαίσθητο configuration file, όπως το `/etc/ld.so.preload`, απαιτεί ενεργό προνομιούχο writer και ελεγχόμενη εγγραφή log προτού γίνει διαδρομή escalation. Η επισήμανση του εκτελέσιμου στο `sudo -l` είναι αφορμή για έλεγχο, όχι απόδειξη ότι λειτουργεί κάποια από αυτές τις διαδρομές. Η παθητική απογραφή δεν πρέπει να εκκινεί ή να επαναδιαμορφώνει το nginx.

### Σύγκριση μοτίβων σε προνομιούχα Bash prompts

Όταν ένα Bash script που επιτρέπεται από το sudo διαβάζει τιμή από τον καλούντα και την ελέγχει με `[[ "$expected" == $entered ]]`, το Bash ερμηνεύει το μη quoted δεξί operand ως pattern. Επομένως, ένα wildcard μπορεί να ικανοποιήσει τη σύγκριση χωρίς να είναι γνωστή η αναμενόμενη τιμή. Αν γίνει quote στο operand (`[[ "$expected" == "$entered" ]]`), η σύγκριση γίνεται με literal string. Εξετάστε τον ακριβή κανόνα sudo, αν είναι προσβάσιμο το prompt και τι κάνει το script μετά τη σύγκριση· η σύνταξη από μόνη της δεν αποδεικνύει εκμεταλλεύσιμη διαδρομή. Αποφύγετε να εμφανίσετε την αναμενόμενη τιμή κατά την απογραφή. Δείτε την [αναφορά conditional constructs του Bash](https://www.gnu.org/software/bash/manual/html_node/Conditional-Constructs.html).

### Helpers μέσω sudo που κάνουν download και εκτελούν αρχείο

Μια απεριόριστη άδεια sudo ως root για custom helper αξίζει έλεγχο ροής δεδομένων αν δέχεται URL που επιλέγει ο καλών, γράφει την απόκριση στον δίσκο και αργότερα εκτελεί αυτό το αρχείο με interpreter ή shell. Το [sudoers επιτρέπει αυθαίρετα ορίσματα όταν μια καταχώριση εντολής δεν αναφέρει κανένα](https://man7.org/linux/man-pages/man5/sudoers.5.html)· μια σταθερή διαδρομή εκτελέσιμου δεν περιορίζει το τι μπορούν να επιλέξουν τα ορίσματά του. Επιβεβαιώστε την πραγματική επικύρωση URL, τη διαδρομή εξόδου, τον κλάδο επιτυχίας και τη μεταγενέστερη εκτέλεση στο εγκατεστημένο helper. Ένα αντίστοιχο import libcurl ή ένα εκτυπώσιμο string από μόνο του δεν αποδεικνύει αυτή την αλυσίδα.

Ακόμη και σταθερό basename εξόδου μπορεί να αντικατασταθεί ανάμεσα στην εγγραφή και την εκτέλεση όταν το helper χρησιμοποιεί **σχετική διαδρομή σε working directory που ελέγχει ο καλών**. Η μετονομασία ή αντικατάσταση αρχείου ιδιοκτησίας root διέπεται από δικαιώματα εγγραφής/αναζήτησης του καταλόγου και τυχόν περιορισμούς sticky bit, όχι μόνο από τον τρόπο πρόσβασης του αρχείου· δείτε την [`rename(2)`](https://man7.org/linux/man-pages/man2/rename.2.html). Ελέγξτε αν το helper ανοίγει ξανά τη διαδρομή αργότερα ή χρησιμοποιεί ήδη ανοιχτό descriptor, καθώς και αν μεταβαίνει σε έμπιστο κατάλογο πριν γράψει. Εξετάστε παθητικά την πολιτική sudo, το helper και τα metadata καταλόγου· μην εκτελέσετε την προνομιούχο λήψη ή race κατά την απογραφή.

Ένα helper download με sudo ως root μπορεί επίσης να εκθέσει **injection ορισμάτων** όταν δημιουργεί Bash command string όπως `curl <caller input> -o <fixed output>`. Ένα φίλτρο που απορρίπτει whitespace αφήνει ακόμη το [brace expansion του Bash](https://www.gnu.org/software/bash/manual/html_node/Brace-Expansion.html): στοιχεία χωρισμένα με κόμματα χωρίς quotes μπορούν να γίνουν ξεχωριστά ορίσματα curl. Αν η είσοδος φτάνει στο curl πριν από το σταθερό `-o`, μια επιλογή εξόδου που παρέχει ο καλών μπορεί να επιλέξει τον προορισμό για το πρώτο URL με την ταυτότητα του helper· το [curl αντιστοιχίζει τις επιλογές εξόδου στα URL με τη σειρά](https://curl.se/docs/manpage.html#-o). Επιβεβαιώστε το ακριβές shell, το quoting, την επικύρωση εισόδου, τον ενεργό κανόνα sudo, τη σειρά ορισμάτων curl και τα υποστηριζόμενα URL schemes, καθώς και αν ο καλών ελέγχει τα bytes που λαμβάνονται ή μπορεί να διαβάσει το αποτέλεσμα. Ένα εκτελέσιμο που έχει συσκευαστεί με PyInstaller μπορεί να περιέχει λογική Python application, αλλά το packaging marker ή ένα string `curl` από μόνο του δεν αποδεικνύει αυτή τη ροή δεδομένων. Εξετάστε offline αντίγραφο περιορισμένου μεγέθους, εφόσον έχετε εξουσιοδότηση· η συνήθης απογραφή δεν πρέπει να εκτελεί το helper ή να κάνει fetch δεδομένα που επιλέγει ο επιτιθέμενος.

Ένα shell script sudo ως root που καλεί [`mktemp -u` / `--dry-run`](https://www.gnu.org/software/coreutils/manual/html_node/mktemp-invocation.html) απλώς επιλέγει ένα αχρησιμοποίητο όνομα· **δεν** δημιουργεί το αρχείο. Αν το script αργότερα δημιουργήσει αυτό το όνομα σε κατάλογο που μπορεί να επηρεάσει άλλος χρήστης, το ανοίξει ξανά και προσθέσει τα περιεχόμενά του σε προστατευμένο προορισμό όπως το `authorized_keys` του root, εξετάστε πιθανό race προσωρινού αρχείου. Επιβεβαιώστε τον ακριβή κανόνα sudo, την ιδιοκτησία καταλόγου και αρχείου, τη σειρά δημιουργίας και επανανοίγματος, τις προστασίες του kernel και αν η προνομιούχα εγγραφή χρησιμοποιεί πράγματι bytes που ελέγχει ο επιτιθέμενος. Ένα string `mktemp -u` ή ένα εγγράψιμο `/tmp` από μόνο του δεν αποδεικνύει το race. Εξετάστε το script και τα metadata διαδρομής χωρίς να το εκτελέσετε ή να προκαλέσετε race στο προσωρινό αρχείο κατά την απογραφή.

## Αμυντικές σημειώσεις

- Αποφύγετε να δίνετε interpreters ή διαδραστικούς editors μέσω sudo.<sup>[[1]](#references)</sup>
- Προτιμήστε σταθερά wrappers ιδιοκτησίας root που εκτελούν μία στενά ορισμένη διοικητική ενέργεια.<sup>[[1]](#references)[[2]](#references)</sup>
- Αν ένας interpreter είναι αναπόφευκτος, περιορίστε την ακριβή διαδρομή script και αποτρέψτε ορίσματα, imports και `PYTHONPATH` που ελέγχει ο χρήστης, καθώς και μη ασφαλή διατήρηση περιβάλλοντος.<sup>[[2]](#references)[[3]](#references)[[4]](#references)</sup>
- Αν απαιτείται επεξεργασία αρχείων, περιορίστε την ακριβή διαδρομή αρχείου και εξετάστε το `sudoedit` με διορθωμένες εκδόσεις sudo και αυστηρό χειρισμό περιβάλλοντος.<sup>[[1]](#references)[[2]](#references)</sup>
- Εξετάστε τα `SETENV`, `env_keep`, τους εγγράψιμους working directories, τις εγγράψιμες διαδρομές modules/imports, το `NOEXEC`, το `use_pty` και το logging, αλλά μην τα θεωρείτε πλήρες sandbox.<sup>[[1]](#references)[[2]](#references)[[3]](#references)</sup>
