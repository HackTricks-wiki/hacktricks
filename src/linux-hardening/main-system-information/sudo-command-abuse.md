## Διερμηνευτές που επιτρέπονται μέσω Sudo

Αν το `sudo -l` επιτρέπει σε έναν χρήστη να εκτελέσει έναν διερμηνευτή ως root, αντιμετωπίστε το ως άμεση εκτέλεση κώδικα. Οι διερμηνευτές έχουν σχεδιαστεί για την εκτέλεση αυθαίρετου κώδικα, επομένως ένας κανόνας που επιτρέπει τα `python3`, `perl`, `ruby`, `lua`, `node` ή παρόμοια δυαδικά αρχεία ισοδυναμεί συνήθως με εκτέλεση εντολών ως root, εκτός αν τα ορίσματα είναι αυστηρά περιορισμένα και επικυρωμένα.<sup>[[1]](#references)[[2]](#references)[[3]](#references)[[4]](#references)[[5]](#references)[[7]](#references)[[9]](#references)[[11]](#references)</sup>

Συνήθης ροή ελέγχου: πρώτα καταγράψτε τα δικαιώματα του χρήστη και έπειτα εκτελέστε μια δήλωση Python με την επιλογή `-c` του διερμηνευτή.<sup>[[1]](#references)[[3]](#references)[[4]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/python3 -c 'import os; os.system("id")'
sudo /usr/bin/python3 -c 'import os; os.system("/bin/sh")'
```

Άλλα παραδείγματα διερμηνευτών παρουσιάζονται παρακάτω· οι αναφερόμενοι διερμηνευτές τεκμηριώνουν την εκτέλεση inline κώδικα ή API θυγατρικών διεργασιών.<sup>[[5]](#references)[[6]](#references)[[7]](#references)[[8]](#references)[[9]](#references)[[10]](#references)[[11]](#references)</sup>

```bash
sudo /usr/bin/perl -e 'exec "/bin/sh";'
sudo /usr/bin/ruby -e 'exec "/bin/sh"'
sudo /usr/bin/node -e 'require("child_process").spawn("/bin/sh", {stdio: [0,1,2]})'
```

Η ακριβής διαδρομή έχει σημασία. Αν ο κανόνας sudo επιτρέπει το `/usr/bin/python3`, χρησιμοποιήστε αυτήν ακριβώς τη διαδρομή κατά την επικύρωση.<sup>[[2]](#references)</sup>

Ένα glob για εκτελέσιμο sudo, όπως το `/usr/bin/python*`, μπορεί επίσης να επιτρέπει την Python 2 για ένα script γραμμένο για Python 3. Αν το script φτάνει στην `input()` με κείμενο που ελέγχει ο καλών, [Python 2 evaluates that text as an expression](https://docs.python.org/2/library/functions.html#input); η ρητή κλήση του interpreter υπερισχύει του shebang του script. Επαληθεύστε τα εγκατεστημένα δυαδικά αρχεία που ταιριάζουν, την αποτελεσματική ταυτότητα RunAs και την πολιτική ορισμάτων, τις απορρίψεις και το αν είναι προσβάσιμη η είσοδος, προτού θεωρήσετε ότι αυτό αποτελεί διαδρομή εκτέλεσης.

Μια σταθερή διαδρομή script σε κανόνα sudo με δυνατότητα εκτέλεσης ως root δεν περιορίζει όσα εκτελεί το script. Για ένα αναγνώσιμο Bash wrapper, ελέγξτε αν η πρώτη εντολή που εκτελεί χρησιμοποιεί μια μη περιφραγμένη positional parameter, όπως η `$1`, ως **λέξη εντολής**, ενώ το sudo επιτρέπει ορίσματα που επιλέγει ο καλών. Επιβεβαιώστε την αποτελεσματική ταυτότητα RunAs, την πολιτική κωδικού πρόσβασης και ορισμάτων, τις μεταγενέστερες απορρίψεις και τον κλάδο που ακολουθεί πράγματι το script· τα `NOEXEC`, μια σταθερή λίστα ασφαλών ορισμάτων ή ένα wrapper που επικυρώνει την εντολή μπορούν να αλλάξουν το αποτέλεσμα. Επιθεωρήστε στατικά το σύντομο script κατά την απαρίθμηση, αντί να το εκτελέσετε με μια δοκιμαστική εντολή.

Ένας απεριόριστος κανόνας sudo με δυνατότητα εκτέλεσης του `dotnet` ως root αξίζει επίσης έλεγχο ως προς τη χρήση του ως interpreter. Αν είναι εγκατεστημένο το .NET SDK, το [`dotnet fsi` runs F# code interactively or from a script](https://learn.microsoft.com/en-us/dotnet/fsharp/tools/fsharp-interactive/) και το [`dotnet run` executes a project from source](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-run). Επιβεβαιώστε πρώτα την αποτελεσματική ταυτότητα RunAs και την ακριβή πολιτική ορισμάτων: ένας κανόνας περιορισμένος σε συγκεκριμένη ασφαλή υποεντολή ή έμπιστη εφαρμογή αποτελεί διαφορετική παραχώρηση, ενώ μια εγκατάσταση μόνο runtime μπορεί να μην περιλαμβάνει εντολές του SDK. Το όνομα του εκτελέσιμου είναι ένδειξη για έλεγχο, όχι απόδειξη εκτέλεσης κώδικα.

```bash
sudo /usr/bin/python3 -c 'import os; os.setuid(0); os.setgid(0); os.system("/bin/sh")'
```

## `tee` που επιτρέπεται από το sudo: αυθαίρετη εγγραφή αρχείων με προνόμια

Το GNU `tee` αντιγράφει την τυπική είσοδο σε κάθε διαδρομή που παρέχεται ως τελεστέος αρχείου. Επομένως, ένας κανόνας sudo που επιτρέπει την εκτέλεση του `/usr/bin/tee` ως root με ορίσματα που ελέγχει ο καλών παρέχει τη δυνατότητα δημιουργίας ή αντικατάστασης οποιουδήποτε αρχείου ως root. Η προσθήκη του `-a` αλλάζει τη δυνατότητα σε προσθήκη στο τέλος του αρχείου. Μια ετικέτα `PASSWD:` αφορά τον έλεγχο ταυτότητας του sudo· από μόνη της δεν περιορίζει τον προορισμό ή τα byte που διαβάζονται από την τυπική είσοδο.<sup>[[2]](#references)[[27]](#references)[[28]](#references)</sup>

Επιθεωρήστε πρώτα τον ακριβή κανόνα. Σε εξουσιοδοτημένο δοκιμαστικό σύστημα, επικυρώστε τη δυνατότητα μόνο με έναν προσωρινό προορισμό που είναι ασφαλές να δημιουργηθεί. Το τελικό `>/dev/null` απλώς αποτρέπει την εμφάνιση στην τυπική έξοδο του αντιγράφου που δημιουργεί το `tee`.<sup>[[28]](#references)</sup>

```bash
sudo -l
printf '%s\n' 'controlled-write' | sudo /usr/bin/tee /root/tee-proof >/dev/null
printf '%s\n' 'appended-line' | sudo /usr/bin/tee -a /root/tee-proof >/dev/null
```

Η τοποθέτηση του `sudo` πριν από την εντολή παραγωγής δεν αναβαθμίζει τα δικαιώματα μιας μεταγενέστερης ανακατεύθυνσης εξόδου του shell, επειδή το shell του καλούντος ανοίγει τον προορισμό. Η εγγραφή πρέπει να γίνεται από την προνομιούχα διεργασία, όπως στο παραπάνω pipeline.<sup>[[1]](#references)[[15]](#references)</sup>

Αφού επιβεβαιώσετε την εγγραφή, επιλέξτε έναν κατάλληλο στόχο εκτέλεσης κώδικα ως root από την ενότητα [Arbitrary File Write to Root](../interesting-files-permissions/write-to-root.md). Μια αλυσίδα που παρατηρήθηκε χρησιμοποίησε το `tee` ως root για να δημιουργήσει ένα αρχείο βραχύβιας διάρκειας στον κατάλογο `/etc/cron.d/`, να εκκινήσει ένα backdoor μέσω ενός script ελεγχόμενου από τον χρήστη και να διαγράψει το αρχείο cron μετά την εκτέλεση. Η αφαίρεση του αρχείου cron απέτρεψε τη μακροχρόνια παραμονή του ως καταχώριση persistence, αν και τα system logs διατήρησαν στοιχεία της δραστηριότητας.<sup>[[27]](#references)</sup>

## Επεξεργαστές που επιτρέπονται μέσω sudo

Αν το `sudo -l` επιτρέπει σε έναν χρήστη να εκτελεί έναν διαδραστικό επεξεργαστή ως root, αντιμετωπίστε το ως επιφάνεια εκτέλεσης εντολών και όχι ως ακίνδυνο δικαίωμα επεξεργασίας αρχείων. Οι επεξεργαστές συχνά μπορούν να εκτελούν εντολές shell, να διαβάζουν αυθαίρετα αρχεία, να γράφουν αυθαίρετα αρχεία ή να καλούν εξωτερικά βοηθητικά προγράμματα από το εσωτερικό τους.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

Συνήθης ροή ελέγχου: απαριθμήστε τα δικαιώματα του χρήστη και, στη συνέχεια, εκκινήστε μέσω sudo κάθε επιτρεπόμενο επεξεργαστή ή pager.<sup>[[1]](#references)[[12]](#references)[[13]](#references)[[14]](#references)</sup>

```bash
sudo -l
sudo /usr/bin/nano /etc/hosts
sudo /usr/bin/vim /etc/hosts
sudo /usr/bin/less /etc/hosts
```

### Εκτέλεση εντολών από την εντολή nano

Όταν επιτρέπεται η χρήση του `nano` μέσω sudo, μπορεί να είναι δυνατή η εκτέλεση εντολών από το περιβάλλον του editor.<sup>[[12]](#references)</sup>

```text
Ctrl+R
Ctrl+X
```

Έπειτα καταχωρίστε μια εντολή όπως `id` ή `/bin/sh` στη γραμμή εντολών του nano.<sup>[[12]](#references)</sup>

```bash
id
/bin/sh
```

Αν ένα interactive shell δεν έχει χρησιμοποιήσιμες ροές terminal, αυτή η μορφή ανακατεύθυνσης αντιστοιχίζει την τυπική έξοδο και το σφάλμα του στον descriptor 0.<sup>[[15]](#references)</sup>

```bash
reset; /bin/sh 1>&0 2>&0
```

Η ακριβής ακολουθία πλήκτρων μπορεί να διαφέρει ανάλογα με την έκδοση του nano και τις επιλογές build, αλλά το ζήτημα ασφάλειας παραμένει το ίδιο: ο editor εκτελείται ως root και μπορεί να εκτελεί εξωτερικές εντολές.<sup>[[1]](#references)[[12]](#references)</sup>

### Άλλοι συνηθισμένοι τρόποι διαφυγής από editor

Οι editor τύπου Vim συνήθως επιτρέπουν την εκτέλεση εντολών μέσω του `:!`.<sup>[[13]](#references)</sup>

```text
:!/bin/sh
```

Οι pagers όπως το `less` μπορούν επίσης να επιτρέψουν την εκτέλεση shell.<sup>[[14]](#references)</sup>

Ένας κανόνας sudo που επιτρέπει την εκτέλεση του `apport-cli` ως root χρειάζεται αντίστοιχο έλεγχο για pager. Οι επηρεαζόμενες εκδόσεις του Apport μπορούσαν να ανοίξουν μια αναφορά κατάρρευσης στο `less` με μέγεθος τερματικού που μπορούσε να οριστεί από επιτιθέμενο· το pager μπορούσε τότε να παρέχει root shell, αν πληρούνταν οι ειδικές προϋποθέσεις για το sudo και το pager. Ελέγξτε τον ενεργό κανόνα sudo, τη ρύθμιση του pager και την επιδιόρθωση του πακέτου της διανομής προτού θεωρήσετε ευάλωτη μια έκδοση μόνο βάσει του αριθμού της. Κατά την παθητική απαρίθμηση, διαβάστε τα μεταδεδομένα του πακέτου και της πολιτικής χωρίς να δημιουργήσετε αναφορά κατάρρευσης ή να ανοίξετε την προνομιούχα αναφορά. Το [αρχείο CVE του Ubuntu](https://ubuntu.com/security/CVE-2023-1326) παραθέτει τις διορθωμένες εκδόσεις πακέτων ανά έκδοση, συμπεριλαμβανομένων των διορθώσεων που έχουν ενσωματωθεί σε παλαιότερες εκδόσεις.

```text
!/bin/sh
```

## Άλλοι κίνδυνοι από κανόνες sudo και doas

Ξεκινήστε με `sudo -l`, `sudo -V` και κάθε σχετική πολιτική `doas`. Εξετάστε μαζί την επιτρεπόμενη εντολή, τον χρήστη RunAs, τα ορίσματα, το περιβάλλον και τις προεπιλογές. Η άδεια εκτέλεσης ως μη root service account μπορεί και πάλι να εκθέσει τα αρχεία αυτού του λογαριασμού ή να προσφέρει διαδρομή προς root.

Ένα σταθερό Python script που επιτρέπεται μέσω sudo μπορεί και πάλι να εκτελέσει shell command με την ταυτότητα RunAs του, αν συνενώσει διαδραστική είσοδο ελεγχόμενη από τον καλούντα στο [`os.system()`](https://docs.python.org/3/library/os.html#os.system). Μια denylist σημείων στίξης του shell δεν αρκεί για να τεκμηριώσει ασφάλεια: το [shell αναγνωρίζει επίσης την υποκατάσταση εντολών `$(...)`](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html). Επιβεβαιώστε ότι τα επιτρεπόμενα ορίσματα φτάνουν στον κλάδο εισόδου, ότι η είσοδος περνά στην εντολή shell χωρίς ασφαλή επικύρωση και ότι η ενεργή πολιτική sudo επιτρέπει τον προβλεπόμενο χρήστη RunAs. Η διαδρομή του script ή μια κλήση στο `os.system()` αποτελούν μόνο αφορμή για έλεγχο· εξετάστε τον πηγαίο κώδικα χωρίς να εκτελέσετε το προνομιούχο script.

Μια ενεργή παραχώρηση sudo ως root για το `chattr` μπορεί να αφαιρέσει το immutable (`i`) attribute ενός αρχείου, αλλά αυτό από μόνο του δεν παρέχει δικαίωμα εγγραφής ή νέα ταυτότητα. Το [εγχειρίδιο του `chattr`](https://man7.org/linux/man-pages/man1/chattr.1.html) αναφέρει ότι το attribute εμποδίζει την τροποποίηση και ότι μόνο το root ή μια διεργασία με `CAP_LINUX_IMMUTABLE` μπορεί να το αλλάξει. Ελέγξτε την ακριβή πολιτική ορισμάτων sudo και την υποστήριξη του filesystem και, στη συνέχεια, επαληθεύστε ξεχωριστά ότι ο καλών μπορεί να γράψει στο αρχείο αφού αφαιρεθεί το attribute και ότι κάποιος καταναλωτής με υψηλότερη ταυτότητα το χρησιμοποιεί. Για παράδειγμα, η αντικατάσταση κελύφους σύνδεσης απαιτεί επίσης τα αποδεκτά διαπιστευτήρια του στοχευόμενου λογαριασμού και πραγματική σύνδεση μέσω αυτού του κελύφους. Κατά την απαρίθμηση, ελέγξτε την πολιτική, τα attributes των αρχείων και τα δικαιώματα χωρίς να τα αλλάξετε.

Αν το sudo ζητά και κωδικό πρόσβασης και κωδικό μίας χρήσης, εξετάστε αυτές τις προϋποθέσεις ξεχωριστά από την παραχώρηση εντολής. Ένα αναγνώσιμο αρχείο `.google_authenticator` περιέχει ευαίσθητο υλικό seed, ενώ ένα παλιό hash κωδικού πρόσβασης εφαρμογής ή βάσης δεδομένων είναι απλώς υποψήφιος κωδικός για τον τρέχοντα λογαριασμό· κανένα από τα δύο δεν αποδεικνύει ότι ο άλλος παράγοντας γίνεται αποδεκτός από την ενεργή ρύθμιση PAM. Μόνο όταν υπάρχει εξουσιοδότηση, εξετάστε τον ακριβή χρήστη RunAs και τα ορίσματα: μια απεριόριστη παραχώρηση ως root για το RubyGems `gem` μπορεί να εκθέσει την εντολή editor του ([GTFOBins](https://gtfobins.github.io/gtfobins/gem/)), αλλά μια περιορισμένη παραχώρηση ή αποτυχημένη αυθεντικοποίηση δεν το επιτρέπει. Η παθητική απαρίθμηση πρέπει να αναφέρει διαδρομές και πολιτική χωρίς να εμφανίζει το seed, να ανακτά κωδικό πρόσβασης, να δημιουργεί κωδικό ή να εκτελεί την προνομιούχο εντολή.

Μια απεριόριστη παραχώρηση sudo με δυνατότητα root για το `knife` του Chef χρειάζεται έλεγχο σε επίπεδο interpreter: [το Chef τεκμηριώνει ότι το `knife exec -E` αξιολογεί τοπικά μια συμβολοσειρά Ruby](https://docs.chef.io/workstation/26/tools/knife/knife_exec/). Επαληθεύστε ότι ο ενεργός κανόνας sudo επιτρέπει το υπο-command `exec` και το όρισμα `-E` που παρέχει ο καλών, την προβλεπόμενη ταυτότητα RunAs και τυχόν αντίστοιχες αρνήσεις εντολών ή σταθερά ορίσματα. Το εγκατεστημένο binary ή ένας κανόνας περιορισμένος σε άλλα subcommands αποτελούν μόνο αφορμή για έλεγχο. Η παθητική απαρίθμηση πρέπει να αναφέρει τον κανόνα χωρίς να εκτελέσει το `knife`.

Μια ακριβής παραχώρηση sudo με δυνατότητα root για διαδραστικό `msfconsole` είναι εξίσου ευαίσθητη: το [GTFOBins τεκμηριώνει την κονσόλα `irb`](https://gtfobins.org/gtfobins/msfconsole/), η οποία μπορεί να κληρονομήσει την ταυτότητα sudo. Επιβεβαιώστε τον ενεργό χρήστη RunAs, τη λίστα επιτρεπόμενων ορισμάτων, τις αρνήσεις εντολών, το `NOEXEC` ή άλλους περιορισμούς, τη συμπεριφορά της εγκατεστημένης κονσόλας και το αν ο καλών μπορεί να δώσει διαδραστική είσοδο. Μια απλή επισήμανση διαδρομής αποτελεί μόνο αφορμή για έλεγχο· η παθητική απαρίθμηση δεν πρέπει να εκκινήσει την κονσόλα.

Στο FreeBSD, ακόμη και ένας κανόνας sudo που περιορίζεται σε `pkg update` και `pkg install *` ως root χρειάζεται έλεγχο εμπιστοσύνης των repositories. Ελέγξτε αν ο καλών μπορεί να γράψει στο `/etc/hosts` και αν η *ενεργή* ρύθμιση repository που είναι ενεργοποιημένη χρησιμοποιεί hostname HTTP με `signature_type: none`. Το [εγχειρίδιο `pkg.conf` του FreeBSD](https://man.freebsd.org/cgi/man.cgi?query=pkg.conf&sektion=5) αναφέρει ότι το `none` απενεργοποιεί τους ελέγχους υπογραφής· το `pkg+http` από μόνο του δεν αρκεί για να τεκμηριώσει κάτι τέτοιο. Ένα package μπορεί να περιέχει install scripts ([FreeBSD Porter's Handbook](https://docs.freebsd.org/en/books/porters-handbook/pkg-files/)), επομένως ένας καλών που ελέγχει πραγματικά το endpoint του repository και μπορεί να επιλέξει package ενδέχεται να ξεπεράσει το όριο root. Επαληθεύστε τις παρακάμψεις repository, την επίλυση SRV/mirror, τα ενεργά ορίσματα sudo, την επιλογή package και την εκτέλεση script προτού καταλήξετε σε αυτό το συμπέρασμα. Εξετάστε την πολιτική και μικρά τοπικά αρχεία ρυθμίσεων χωρίς να ανακατευθύνετε ονόματα ή να εκτελέσετε `pkg` κατά την απαρίθμηση.

Μια παραχώρηση sudo με δυνατότητα root για `apt-get update` και `apt-get upgrade` χρειάζεται επίσης έλεγχο εμπιστοσύνης των repositories όταν το sudo διατηρεί `http_proxy` που ελέγχει ο καλών. Ελέγξτε αν η ενεργή ρύθμιση proxy του APT χρησιμοποιεί πράγματι αυτή τη μεταβλητή και ποια ενεργοποιημένα αιτήματα repository μπορεί να επηρεάσει· ένα proxy από μόνο του δεν μπορεί να αντικαταστήσει packages από archive που έχει επαληθευτεί με έμπιστο signing key. Το [εγχειρίδιο HTTP transport του APT](https://manpages.debian.org/experimental/apt/apt-transport-http.1.en.html) τεκμηριώνει την προτεραιότητα των proxy και το [apt-secure](https://manpages.debian.org/experimental/apt/apt-secure.8.en.html) τεκμηριώνει τους ελέγχους υπογραφής, τις παρακάμψεις μη ασφαλών repositories και την επιβεβαίωση για μη πιστοποιημένα packages. Επιβεβαιώστε τον ακριβή χρήστη RunAs και τα ορίσματα sudo, την πολιτική αυθεντικοποίησης του repository, τυχόν απαιτούμενη διαδραστική αποδοχή και αν η επιλεγμένη αναβάθμιση εκτελεί scripts package ως root. Εξετάστε παθητικά την πολιτική και τις τοπικές ρυθμίσεις· μην ανακατευθύνετε την κίνηση των packages και μην εκτελέσετε αναβάθμιση κατά την απαρίθμηση.

Ένας κανόνας sudo με δυνατότητα root για `snap install` μπορεί να δημιουργήσει όριο package-to-code, αν τα ορίσματά του επιτρέπουν στον καλούντα να επιλέξει τοπικό snap και permissive τρόπο εγκατάστασης. Το [Snap τεκμηριώνει](https://snapcraft.io/docs/explanation/snap-development/install-modes/) ότι το `--dangerous` παραλείπει τους ελέγχους assertion για τοπικό snap και το `--devmode` χαλαρώνει τον περιορισμό· [ένα install hook μπορεί να εκτελεστεί κατά την αρχική εγκατάσταση](https://snapcraft.io/docs/reference/development/supported-snap-hooks/). Ελέγξτε την ακριβή πολιτική ορισμάτων/RunAs του sudo, ποιος ελέγχει το αρχείο snap, αν το εγκατεστημένο snapd δέχεται αυτούς τους τρόπους και την ενεργή ταυτότητα και απομόνωση του hook προτού ισχυριστείτε ότι υπάρχει πρόσβαση σε προστατευμένα αρχεία του host. Για διαδρομή προγραμματισμένης εντολής, επαληθεύστε την ταυτότητα εκτέλεσης του scheduler, την είσοδο εντολής και τυχόν πρόσθετη απαίτηση κωδικού ή εξουσιοδότησης. Το όνομα εντολής ή το `NOPASSWD` από μόνο του δεν αποδεικνύει καμία από τις δύο διαδρομές. Δείτε την [εγγραφή σε αρχεία που ανήκουν στο root](../interesting-files-permissions/write-to-root.md) και τους [χρονοδιακόπτες cron και systemd](../processes-crontab-systemd-dbus/cron-and-systemd-timers.md).
- Μια σταθερή εντολή sudo μπορεί και πάλι να φορτώνει προβλέψιμο αρχείο ρυθμίσεων από κοινόχρηστο εγγράψιμο κατάλογο. Ελέγξτε αν ο καλών μπορεί να αντικαταστήσει αυτό το αρχείο και αν τα πεδία source και destination του ελέγχουν προνομιούχο fetch ή copy. Ένα URL τοπικού αρχείου μπορεί να εκθέσει δεδομένα αναγνώσιμα μόνο από τον χρήστη RunAs του sudo· μια πηγή ελεγχόμενη από τον καλούντα σε συνδυασμό με προστατευμένο προορισμό μπορεί να δημιουργήσει διαδρομή εγγραφής. Επιβεβαιώστε τη διαχείριση URL από το εγκατεστημένο πρόγραμμα, τους ελέγχους διαδρομής προορισμού, τον ενεργό κανόνα sudo και την προσβασιμότητα εξόδου. Ένα εγγράψιμο αρχείο ρυθμίσεων στο `/tmp` αποτελεί μόνο αφορμή για έλεγχο· εξετάστε το binary και τα metadata αρχείων χωρίς να εκτελέσετε την προνομιούχο μεταφορά.
- Ένας κανόνας sudo για `git apply` μπορεί να επιτρέψει στον λογαριασμό RunAs να γράψει αρχεία που επιλέγει patch ελεγχόμενο από τον καλούντα. Το [CVE-2023-23946](https://github.com/git/git/security/advisories/GHSA-r87m-v37r-cwfh) επέτρεπε σε κακόβουλα διαμορφωμένο patch να δημιουργήσει symlink και στη συνέχεια να γράψει έξω από το working tree, ακόμη κι όταν η εντολή δεν δεχόταν `--unsafe-paths`. Ελέγξτε τον ενεργό κανόνα ορισμάτων sudo, την πηγή του patch, την πρόσβαση του λογαριασμού RunAs στον κατάλογο εργασίας και τη διόρθωση ή το vendor backport του εγκατεστημένου Git. Ένας απεριόριστος κανόνας που επιτρέπει `--unsafe-paths` αποτελεί ξεχωριστό κίνδυνο ρητής επιλογής· ούτε μια έκδοση Git ούτε η άδεια `git apply` από μόνη της αποδεικνύει ότι μπορεί να τροποποιηθεί προστατευμένο αρχείο. Μην εφαρμόσετε μη έμπιστο patch κατά την παθητική απαρίθμηση.
- Ένας κανόνας sudo για `clamscan --debug` με δυνατότητα root μπορεί να ξεπεράσει όριο ανάγνωσης, αν χρήστης με χαμηλότερα προνόμια μπορεί να δώσει εικόνα DMG και ο εγκατεστημένος parser επηρεάζεται από το [CVE-2023-20052](https://blog.clamav.net/2023/02/clamav-01038-01052-and-101-patch.html), το οποίο θα μπορούσε να αποκαλύψει περιεχόμενα αρχείων στην έξοδο debug. Επιβεβαιώστε τα ακριβή επιτρεπόμενα ορίσματα και τη διαδρομή σάρωσης, τον έλεγχο της εισόδου, τον ενεργό λογαριασμό RunAs, τη διόρθωση/backport του engine και αν ο καλών βλέπει την έξοδο. Αν ένας ευρύτερος κανόνας επιτρέπει `--file-list`/`-f`, εξετάστε ξεχωριστά αυτή τη συμπεριφορά· μια πολιτική σταθερή σε `--debug <scan-path>` δεν επιτρέπει αυτή την επιλογή. Εξετάστε την πολιτική και τα metadata των packages χωρίς να σαρώσετε κακόβουλα διαμορφωμένο αρχείο ή να εμφανίσετε προστατευμένη έξοδο κατά την απαρίθμηση.
- Ένας κανόνας sudo με δυνατότητα root που ανοίγει εικόνα κρυπτογραφημένου δίσκου επιλεγμένη από τον καλούντα και ένας δεύτερος κανόνας που προσαρτά το mapper που προκύπτει μπορούν να εισαγάγουν αρχεία ελεγχόμενα από τον καλούντα στο mount namespace του host. Επιβεβαιώστε και τους δύο ενεργούς κανόνες και τα ορίσματά τους, τον έλεγχο της εικόνας και του ονόματος mapper, το πραγματικό σημείο προσάρτησης και τον ιδιοκτήτη και τρόπο των αρχείων που προκύπτουν. Μια μετάβαση set-user-ID απαιτεί επιπλέον εκτελέσιμο αρχείο με κατάλληλη πρόσβαση, επιλογές προσάρτησης που το ενεργοποιούν (το `nosuid` την εμποδίζει) και εφαρμοστέα πολιτική διεργασίας ή MAC· το άνοιγμα ή η προσάρτηση εικόνας από μόνα τους αποτελούν μόνο αφορμή για έλεγχο. Ξεχωριστή διαδρομή μέσω υπάρχοντος backup απαιτεί το πραγματικό κλειδί και ένα χρήσιμο, αναγνώσιμο μυστικό στο εσωτερικό του. Εξετάστε την πολιτική και τις διαδρομές χωρίς να ανοίξετε ή να προσαρτήσετε εικόνα κατά την παθητική απαρίθμηση. Δείτε το [εγχειρίδιο του cryptsetup](https://gitlab.com/cryptsetup/cryptsetup/-/blob/main/man/cryptsetup.8.adoc) και τις [επιλογές mount](https://man7.org/linux/man-pages/man8/mount.8.html).
- Ένας κανόνας sudo με δυνατότητα root για shell ή Python script χρειάζεται έλεγχο του working directory, αν το script εκτελεί `./helper` χωρίς πρώτα να μεταβεί σε σταθερό κατάλογο. Μια λίστα Python όπως `['./helper']` που περνά στο `subprocess.run` μπορεί να έχει την ίδια συμπεριφορά επιλογής working directory από τον καλούντα. Ο καλών ενδέχεται να μπορεί να επιλέξει εγγράψιμο κατάλογο και να τοποθετήσει εκεί εκτελέσιμο με αυτό το σχετικό όνομα· μια απόλυτη διαδρομή αλλού στο script δεν προστατεύει αυτή την κλήση. Επιβεβαιώστε τον ενεργό κανόνα, το `runchdir` ή άλλη πολιτική αλλαγής καταλόγου, τη ροή του script και την προσβασιμότητα του κλάδου, εγγράψιμο και εκτελέσιμο κατάλογο, καθώς και περιορισμούς mount/`NOEXEC` προτού το θεωρήσετε εκτέλεση κώδικα. Αν το script δεν είναι αναγνώσιμο, η συμπεριφορά του παραμένει άγνωστη μέχρι να εξεταστεί ο πηγαίος κώδικας μέσω εξουσιοδοτημένης διαδρομής. Εξετάστε στατικά τα scripts αντί να εκτελέσετε το helper. Το [εγχειρίδιο sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) τεκμηριώνει την πολιτική working directory.
- Ένας σταθερός Python validator με δυνατότητα root μπορεί και πάλι να αξιολογήσει αρχείο δεδομένων που επιλέγει ο καλών. Η [τεκμηρίωση της Python για την `eval()` προειδοποιεί κατά της μη έμπιστης εισόδου](https://docs.python.org/3/library/functions.html#eval): ένας έλεγχος κατάληξης εισόδου, ένα αριθμητικό πρόθεμα ή ένας κλάδος επικύρωσης δεν αποτελούν sandbox, αν η υπόλοιπη έκφραση φτάνει στην `eval`. Επιβεβαιώστε τον ενεργό κανόνα sudo, αν ο καλών μπορεί να επιλέξει και να ελέγξει το συγκεκριμένο αρχείο, τις συνθήκες κλάδων του parser και τη δημιουργία της έκφρασης, καθώς και την ταυτότητα της προνομιούχου διεργασίας προτού το χαρακτηρίσετε διαδρομή εκτέλεσης. Η παρουσία της `eval` σε αναγνώσιμο script αποτελεί μόνο ένδειξη για έλεγχο· εξετάστε τον κώδικα και τα δικαιώματα αρχείων χωρίς να εκτελέσετε τον validator ή να υποβάλετε δοκιμαστική έκφραση κατά την απαρίθμηση.
- Ένα Ruby wrapper με δυνατότητα root που διαβάζει σχετικό όνομα YAML, όπως `YAML.load(File.read("dependencies.yml"))`, μπορεί να πάρει είσοδο από τον working directory του καλούντος, εκτός αν το wrapper ή η πολιτική sudo ορίζουν σταθερό κατάλογο. Ελέγξτε τα ακριβή επιτρεπόμενα ορίσματα, τα δικαιώματα καταλόγου και αρχείου και τη συμπεριφορά της εγκατεστημένης Psych: παλαιότερες υλοποιήσεις της `YAML.load` μπορούσαν να αποσειριοποιήσουν αυθαίρετα αντικείμενα Ruby, ενώ νεότερες εκδόσεις περιορίζουν τις κλάσεις από προεπιλογή. Ένα στατικό σημείο κλήσης αποτελεί μόνο αφορμή για έλεγχο· επιβεβαιώστε ότι το αρχείο προέρχεται πράγματι από κατάλογο που μπορεί να γράψει ο καλών και ότι ο εγκατεστημένος loader δέχεται επικίνδυνες κλάσεις. Προτιμήστε `safe_load` με ρητή, ελάχιστη allowlist κλάσεων για μη έμπιστη είσοδο. Δείτε την [τεκμηρίωση Psych του Ruby 3.0](https://docs.ruby-lang.org/en/3.0/Psych.html) και την [τεκμηρίωση Psych του Ruby 3.1](https://ruby-doc.org/core-3.1.2/Psych.html).

- Μια ακριβής παραχώρηση `sudo go run /absolute/file.go` με δυνατότητα root απαιτεί έλεγχο του working directory όταν ο πηγαίος κώδικας Go διαβάζει σχετικό αρχείο WASM και μπορεί να εκτελέσει σχετικό shell script αφού εξετάσει το αποτέλεσμα. Επιβεβαιώστε τον ενεργό χρήστη RunAs, τα ορίσματα εντολής και τις αρνήσεις, έναν τρέχοντα κατάλογο που μπορεί να γράψει ο καλών, τη ροή δεδομένων WASM προς τον κλάδο και αν αυτός ο κλάδος καλεί το helper. Το σταθερό sudo `runchdir`, το `os.Chdir` ή το [`exec.Cmd.Dir`](https://pkg.go.dev/os/exec) μπορούν να αλλάξουν την τοποθεσία αναζήτησης. Η στατική συνύπαρξη αυτών των στοιχείων είναι μόνο υποψήφια περίπτωση· εξετάστε τον πηγαίο κώδικα χωρίς να εκτελέσετε Go, WASM ή το helper.
- Το `sudoedit` και τα wildcards ορισμάτων απαιτούν ακριβείς ελέγχους έκδοσης και κανόνα· η [checklist](linux-privilege-escalation-checklist.md) περιλαμβάνει το ζήτημα επεξεργασίας αρχείου του sudoedit. Για διαπαραλογαριασμική παραχώρηση `sudoedit` σε διαδρομή wildcard, εξετάστε τη ρύθμιση `sudoedit_follow` ή `FOLLOW`, το `sudoedit_checkdir`, τον επιλυμένο στόχο και ποιος μπορεί να αντικαταστήσει κάθε εγγραφή γονικού καταλόγου. Το πρώτο μπορεί να επιτρέψει την παρακολούθηση symlink, ενώ η απενεργοποίηση του δεύτερου αφαιρεί τους ελέγχους εγγράψιμων καταλόγων· καμία από τις δύο ρυθμίσεις από μόνη της δεν τεκμηριώνει εγγραφή σε αρχείο άλλου χρήστη. Επιβεβαιώστε την εγκατεστημένη πολιτική sudo και τα ακριβή ορίσματα που ταιριάζουν προτού καταλήξετε σε αυτό το συμπέρασμα. Δείτε τους [ορισμούς επιλογών sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf).
- Σε κανόνα εντολής sudoers, ένα wildcard ορίσματος μπορεί να ταιριάξει whitespace καθώς και χαρακτήρες διαδρομής. Ένας κανόνας για εντολή που μπορεί να διαβάζει αρχεία, με όρισμα όπως `/restricted/*`, μπορεί επομένως να επιτρέπει επιπλέον όρισμα αρχείου μετά από πρόθεμα που ταιριάζει. Εξετάστε τον ακριβή χρήστη run-as, τη διαδρομή εντολής, το μοτίβο ορισμάτων και μεταγενέστερες αρνήσεις· η απόδειξη ανάγνωσης αρχείου δεν συνεπάγεται εκτέλεση εντολής. Το [εγχειρίδιο sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) διακρίνει τα glob ορισμάτων από τα glob της διαδρομής εντολής.
- Ένα glob ορίσματος που μοιάζει με διαδρομή μπορεί επίσης να ταιριάξει `../`. Για παράδειγμα, ένας κανόνας `node /opt/scripts/*.js` με δυνατότητα root μπορεί να επιτρέπει αρχείο JavaScript ελεγχόμενο από τον καλούντα έξω από το `/opt/scripts`, αν η παρεχόμενη διαδρομή αρχίζει ακόμη με `/opt/scripts/` και επιλύεται μέσω τμημάτων γονικών καταλόγων. Πρόκειται για glob **ορίσματος**· το glob της διαδρομής εντολής για το εκτελέσιμο Node έχει διαφορετικούς κανόνες αντιστοίχισης κάθετων. Ελέγξτε τον ενεργό κανόνα, μεταγενέστερες αρνήσεις, την επίλυση διαδρομής, τον έλεγχο του αρχείου-στόχου και τυχόν περιορισμούς regex ή digest του sudoers προτού συμπεράνετε εκτέλεση κώδικα. Δείτε τους [κανόνες wildcard του sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf) και την [τεκμηρίωση γραμμής εντολών του Node](https://nodejs.org/api/cli.html).
- Τα προγράμματα αρχειοθέτησης και άλλα βοηθητικά προγράμματα μπορεί να έχουν hooks εκτέλεσης. Ελέγξτε τα ακριβή επιτρεπόμενα ορίσματα στο [GTFOBins](https://gtfobins.github.io/) αντί να υποθέσετε ότι μόνο shells ή interpreters εκτελούν εντολές.
- Ένας απεριόριστος κανόνας `qpdf` με δυνατότητα root μπορεί να εκθέσει προνομιούχο αρχείο μέσω συνημμένων PDF: το qpdf 10.2 και νεότερο υποστηρίζει `--empty` και `--add-attachment file ... --` με PDF εξόδου. Αν η προνομιούχος διεργασία μπορεί να διαβάσει την επιλεγμένη πηγή και να γράψει το PDF σε διαδρομή προσβάσιμη από τον καλούντα, η έξοδος μπορεί να περιέχει τα bytes της πηγής. Εξετάστε τα ενεργά ορίσματα και τις εξαιρέσεις sudo, την έκδοση qpdf, την πρόσβαση στην πηγή και τη διαδρομή εξόδου προτού καταλήξετε ότι είναι δυνατή η αποκάλυψη αρχείου. Η ανάγνωση ενός SSH key του root είναι χρήσιμη για σύνδεση μόνο όταν το κλειδί είναι έγκυρο και επιτρέπεται αυθεντικοποίηση SSH του root. Δείτε τις [επιλογές συνημμένων του qpdf](https://qpdf.readthedocs.io/en/stable/cli.html#embedded-files-attachments).
- Η επαναχρησιμοποίηση χρονικής σήμανσης sudo εξαρτάται από την πολιτική cache, τον χρήστη στον οποίο ανήκει, το terminal/session και τα δικαιώματα. Ο [οδηγός privilege escalation](../linux-basics/linux-privilege-escalation/README.md#reusing-sudo-tokens) καλύπτει τους ελέγχους.
- Το `doas` έχει δικούς του κανόνες και ρυθμίσεις. Ελέγξτε τις επιτρεπόμενες εντολές και τις εγγράψιμες διαδρομές ρυθμίσεων όπως περιγράφεται στην [ενότητα doas](../linux-basics/linux-privilege-escalation/README.md#doas).

### Εργαλεία build και package που εκτελούνται μέσω sudo

Μια απεριόριστη παραχώρηση sudo για το `forge` του Foundry μπορεί να έχει σημασία ακόμη κι όταν η ταυτότητα RunAs είναι άλλος μη root χρήστης. Επιλογές compiler όπως το `--use` μπορούν να επιλέξουν τοπικό εκτελέσιμο και το `forge flatten -o` επιλέγει αρχείο εξόδου. Ελέγξτε την εγκατεστημένη έκδοση Forge, τα ακριβή ορίσματα sudo, τα προσβάσιμα paths project και compiler, τα δικαιώματα εξόδου και το ενεργό περιβάλλον προτού θεωρήσετε ότι η παραχώρηση είναι εκμεταλλεύσιμη. Ένα σχετικό helper executable που βρίσκεται μέσω `PATH` είναι διαδρομή εξαρτώμενη από την έκδοση και το περιβάλλον, όχι συμπεριφορά που πρέπει να θεωρείται δεδομένη σε κάθε build Forge.<sup>[[23]](#references)[[24]](#references)</sup>

Μια απεριόριστη παραχώρηση `pacman` με δυνατότητα root επιτρέπει περισσότερα από ερωτήματα για packages: το `-U` δέχεται τοπικό package, τα packages μπορεί να περιέχουν install scripts και το `--hookdir` επιλέγει διαφορετικό κατάλογο hooks. Εξετάστε τον ενεργό κανόνα sudo, τους περιορισμούς και τις εξαιρέσεις ορισμάτων πριν από οποιαδήποτε δοκιμή· η παθητική απαρίθμηση δεν απαιτεί εγκατάσταση package ή εκτέλεση hook.<sup>[[25]](#references)[[26]](#references)</sup>

Ένα σταθερό shell wrapper sudo μπορεί επίσης να εγκαθιστά μια ονομασμένη npm εξάρτηση και στη συνέχεια να ξεκινά εφαρμογή Node. Εξετάστε τον ακριβή κανόνα RunAs, αν το package είναι ήδη εγκατεστημένο, το ενεργό `HOME` και το npm `userconfig`, τις ρυθμίσεις project ή τις παρακάμψεις γραμμής εντολών και αν χρήστης με χαμηλότερα προνόμια ελέγχει το registry ή το package που επιστρέφεται για αυτό το όνομα. Το [npm τεκμηριώνει την αναζήτηση `.npmrc` ανά χρήστη και ανά project](https://docs.npmjs.com/cli/v6/configuring-npm/npmrc/)· η συμπεριφορά του `HOME` στο sudo εξαρτάται από την εγκατεστημένη πολιτική και τη διανομή, επομένως ένα `.npmrc` εγγράψιμο από τον χρήστη μπορεί να διαβαστεί ή να μη διαβαστεί από το προνομιούχο npm process. Αν το νεοεγκατεστημένο package εισαχθεί από την προνομιούχο εφαρμογή, ο κώδικας του module μπορεί να εκτελεστεί με την ταυτότητα της εφαρμογής. Τα install-time scripts είναι ξεχωριστή διαδρομή που εξαρτάται από την έκδοση και τη ρύθμιση· το [npm τεκμηριώνει τον κύκλο ζωής τους και τον χειρισμό χρηστών](https://docs.npmjs.com/cli/v6/using-npm/scripts/). Μια διαδρομή `.npmrc` ή μια γραμμή `npm install` από μόνη της αποτελεί μόνο αφορμή για έλεγχο. Εξετάστε τον κανόνα, το σύντομο wrapper, τις διαδρομές ρυθμίσεων και την προέλευση του package χωρίς να εγκαταστήσετε package ή να ξεκινήσετε την εφαρμογή κατά την παθητική απαρίθμηση.

Μια παραχώρηση `pip` ή `pip3 download` με δυνατότητα root αποτελεί επίσης αφορμή για έλεγχο build package, όταν τα ορίσματά της επιτρέπουν στον καλούντα να επιλέξει μη έμπιστη source distribution, ακόμη κι αν το μοτίβο URL περιορίζεται σε τοπική υπηρεσία και κατάληξη `.tar.gz`. Το `pip download` δέχεται URL αρχείων και επιλύει metadata package· η προετοιμασία sdist μπορεί να καλέσει το build backend ή κώδικα legacy `setup.py` πριν απλώς αποθηκευτεί το archive. Επιβεβαιώστε τον ακριβή κανόνα sudo RunAs και ορισμάτων, αν ο καλών μπορεί να δημοσιεύσει ή να αντικαταστήσει το επιλεγμένο archive και αν η συγκεκριμένη έκδοση pip προετοιμάζει πράγματι τα metadata του. Ένα σταθερό έμπιστο archive ή wheel δεν τεκμηριώνει αυτή τη διαδρομή. Μην κάνετε fetch ή build μη έμπιστου package κατά την παθητική απαρίθμηση. Δείτε την [εντολή download του pip](https://pip.pypa.io/en/stable/cli/pip_download/), τη [διεπαφή build-system](https://pip.pypa.io/en/stable/reference/build-system/) και τις [οδηγίες ασφαλούς εγκατάστασης](https://pip.pypa.io/en/stable/topics/secure-installs/).

Ένας κανόνας sudo που επιτρέπει `pip install` με διαδρομή τοπικού project επιλεγμένη από τον καλούντα δημιουργεί πιο άμεσο όριο build. Το [pip δέχεται καταλόγους τοπικών project](https://pip.pypa.io/en/stable/topics/local-project-installs/) και καλεί το build system τους· το [build backend εκτελεί hooks build που ελέγχει το project](https://pip.pypa.io/en/stable/reference/build-system/). Πρέπει να ισχύουν όλα: παραχώρηση sudo, εγγράψιμη διαδρομή πηγής, προνομιούχα ανάγνωση και αναγνώσιμη έξοδος· ένα εγγράψιμο log ή όνομα profile από μόνο του δεν αρκεί. Εξετάστε τα ενεργά δικαιώματα και τα metadata των links χωρίς να αντικαταστήσετε αρχεία ή να δημιουργήσετε profile κατά την απαρίθμηση. Οι [οδηγίες υποστήριξης του Nagios XI](https://support.nagios.com/forum/viewtopic.php?t=62758) τεκμηριώνουν το script profile που εκτελείται ως root και το archive εξόδου του, δείχνοντας γιατί αυτά τα bundles χρειάζονται περιορισμένες εισόδους και πρόσβαση εξόδου.

### Scripts επαναφοράς Python archive που εκτελούνται ως root

Ένας αυστηρά περιορισμένος κανόνας sudo για Python script επαναφοράς χρειάζεται και πάλι έλεγχο της εισόδου archive. Αν ο καλών μπορεί να επιλέξει ή να αντικαταστήσει το archive και το script το εξάγει ως root με `tarfile.extractall(filter="data")`, ελέγξτε τις ενημερώσεις ασφαλείας του interpreter προτού εμπιστευτείτε το φίλτρο. Το CPython διόρθωσε αρκετές παρακάμψεις φίλτρων symlink και hard-link, συμπεριλαμβανομένου του CVE-2025-4517, στις εκδόσεις 3.9.23, 3.10.18, 3.11.13, 3.12.11 και 3.13.4. Backports διανομών μπορούν να διορθώσουν παλαιότερη έκδοση, επομένως η εμφανιζόμενη έκδοση interpreter από μόνη της δεν αποδεικνύει έκθεση.<sup>[[16]](#references)[[17]](#references)</sup>

Για παθητική εξέταση, διαβάστε την ακριβή εντολή sudo και το script, ακολουθήστε το όρισμα που επιλέγει το archive και ελέγξτε αν ο τρέχων χρήστης μπορεί να γράψει στο archive ή στον περιέχοντα κατάλογο. Επιβεβαιώστε ξεχωριστά το vendor patch που είναι εγκατεστημένο και τον προορισμό εξαγωγής· το `filter="data"` δεν καθιστά ασφαλές κάθε μη έμπιστο archive.<sup>[[16]](#references)[[17]](#references)</sup>

### Loaders μοντέλων machine learning που εκτελούνται μέσω sudo

Ένας κανόνας sudo που επιτρέπει στον καλούντα να επιλέξει αρχείο `.pt`, `.pth` ή `.ckpt` χρειάζεται έλεγχο όταν προνομιούχο script περνά αυτό το αρχείο στο [`torch.load`](https://docs.pytorch.org/docs/stable/generated/torch.load.html), στο `pickle.load` ή σε άλλον loader βασισμένο σε pickle. Ελέγξτε τον ενεργό κανόνα RunAs, αν ο καλών μπορεί να δημιουργήσει ή να αντικαταστήσει το επιλεγμένο μοντέλο και την πραγματική ροή ορισμάτων μέσω τυχόν shell wrapper προς το Python helper. Η κατάληξη `.pth` ονομάζει επίσης άσχετα αρχεία ρυθμίσεων Python site, επομένως η κατάληξη από μόνη της δεν αποτελεί ένδειξη φόρτωσης μοντέλου. Μια σάρωση archive ή στατική σάρωση pickle δεν αποδεικνύει ότι η μεταγενέστερη φόρτωση είναι ασφαλής· εξετάστε τη συμπεριφορά `weights_only` ανάλογα με την [έκδοση](https://docs.pytorch.org/docs/stable/notes/serialization.html) και τυχόν allowlisting. Δείτε τις [σημειώσεις για ML pickle και Fickling](../../generic-methodologies-and-resources/python/keras-model-deserialization-rce-and-gadget-hunting.md). Η παθητική απαρίθμηση δεν πρέπει ποτέ να φορτώσει ή να αποσυμπιέσει το μοντέλο.

### Ανάλυση εκφράσεων αποθηκευμένης εισόδου μέσω sudo

Ένα σταθερό Python script που εκτελείται ως root μέσω sudo μπορεί και πάλι να αξιολογήσει κείμενο που μπορεί να αποθηκεύσει χρήστης με χαμηλότερα προνόμια σε βάση δεδομένων εφαρμογής. Στο TensorFlow, μια κλήση `preprocess_input_exprs_arg_string(value, safe=False)` επιλέγει διαδρομή `eval`· η [συμβουλευτική ανακοίνωση του TensorFlow](https://github.com/tensorflow/tensorflow/security/advisories/GHSA-75c9-jrh4-79mc) περιγράφει τον μη ασφαλή parser και μια διόρθωση στον καλούντα γραμμής εντολών. Μια ρητή κλήση `safe=False` από εφαρμογή χρειάζεται ξεχωριστό έλεγχο ακόμη κι όταν έχει διορθωθεί αυτός ο καλών γραμμής εντολών. Ελέγξτε τον ενεργό κανόνα sudo, ποιος μπορεί να τροποποιήσει την ακριβή εγγραφή εισόδου, αν το φιλτράρισμα ή η βαθμολόγηση επιτρέπει στην εγγραφή να φτάσει στην κλήση και τη συμπεριφορά της εγκατεστημένης συνάρτησης. Μια έκδοση TensorFlow, μια παραχώρηση sudo ή ένα hardcoded αρχείο μοντέλου από μόνα τους δεν αποδεικνύουν την αλυσίδα. Εξετάστε παθητικά το script και τη ροή δεδομένων· μην εκτελέσετε το προνομιούχο helper ή υποβάλετε δοκιμαστικές εκφράσεις κατά την απαρίθμηση.

### Ρύθμιση needrestart που επιτρέπεται μέσω sudo

Το `needrestart -c` φορτώνει αρχείο ρυθμίσεων Perl που επιλέγει ο καλών και αξιολογεί το περιεχόμενό του. Αν το `sudo -l` επιτρέπει το `needrestart` ως root με ορίσματα που επιτρέπουν το `-c` και ο καλών μπορεί να επιλέξει αναγνώσιμο αρχείο ρυθμίσεων σε εγγράψιμη τοποθεσία, αυτή η άδεια μπορεί να οδηγήσει σε εκτέλεση κώδικα ως root. Ελέγξτε τον ακριβή κανόνα sudo run-as και ορισμάτων· ένας κανόνας που επιτρέπει μόνο σταθερή λίστα ορισμάτων μπορεί να αποκλείει αυτή τη διαδρομή. Αυτό είναι ξεχωριστό από τις ευπάθειες σάρωσης interpreter του needrestart: η ενημέρωση του package ή η απενεργοποίηση του `interpscan` δεν καθιστούν ασφαλή μια απεριόριστη παραχώρηση `-c` ως root.<sup>[[2]](#references)[[18]](#references)[[19]](#references)</sup>

### Python imports μέσω sudo με εκτέλεση ως άλλος λογαριασμός

Ένα σταθερό entry point Python μπορεί και πάλι να εισαγάγει module που μπορεί να επεξεργαστεί ή να αντικαταστήσει ο καλών, ακόμη κι όταν το sudo εκτελεί το script ως **μη root** service user. Για ένα literal `from utils import status`, εξετάστε τα τοπικά `utils/__init__.py` και `utils/status.py`, καθώς και τα δικαιώματα του καταλόγου package. Επιβεβαιώστε τη διαδρομή import του script, τα ακριβή επιτρεπόμενα ορίσματα sudo και αν η σχετική ενέργεια φτάνει στο import προτού θεωρήσετε το εγγράψιμο αρχείο διαδρομή εκτέλεσης. Εξετάστε αρχεία και δικαιώματα χωρίς να εισαγάγετε ή να εκτελέσετε το script κατά την απαρίθμηση.<sup>[[2]](#references)[[3]](#references)</sup>

Ένας ακριβής κανόνας sudo για `python3 /absolute/script.py` απαιτεί μόνο αναγνώσιμο script· το αρχείο δεν χρειάζεται να είναι εκτελέσιμο ή να έχει shebang. Εξετάστε και τα **ελλείποντα** τοπικά modules: αν το script εισάγει module του οποίου το όνομα αρχείου μπορεί να δημιουργηθεί σε κατάλογο script εγγράψιμο από τον καλούντα, η Python ενδέχεται να φορτώσει αυτό το αρχείο με την ταυτότητα RunAs. Επιβεβαιώστε τον ενεργό κανόνα sudo, την πραγματική [διαδρομή αναζήτησης module](https://docs.python.org/3/library/sys_path_init.html) του interpreter, αν το module είναι built-in ή frozen και αν γίνεται το import. Ένας άμεσος κανόνας sudo για το script έχει διαφορετικές απαιτήσεις για execute bit και shebang. Ένα ξεχωριστό wrapper που προσθέτει tokens του καλούντος μετά το `sudo -u account` χρειάζεται επίσης έλεγχο ροής ορισμάτων: ένα επιπλέον `-u` σε αυτά τα tokens έχει σημασία μόνο αν η πολιτική sudo επιτρέπει την ταυτότητα που προκύπτει. Στατικά strings από μόνα τους δεν αποδεικνύουν καμία από τις δύο διαδρομές.

### Apache μέσω sudo με ρυθμίσεις ελεγχόμενες από τον καλούντα

Αν ένας κανόνας sudo επιτρέπει προνομιούχο `apachectl`, `apache2ctl` ή `httpd` με αρχείο ρυθμίσεων `-f` που ελέγχει ο καλών, εξετάστε τα δικαιώματα αυτού του αρχείου και του γονικού καταλόγου του. Η οδηγία Apache [`LoadModule`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadmodule) δέχεται όνομα module και στη συνέχεια το **όνομα αρχείου του module**· το [`LoadFile`](https://httpd.apache.org/docs/2.4/mod/mod_so.html#loadfile) επίσης φορτώνει αρχείο. Τα [`Include` και `IncludeOptional`](https://httpd.apache.org/docs/2.4/mod/core.html#include) μπορούν να επεκτείνουν τις ρυθμίσεις ή να εκθέσουν περιεχόμενα αρχείων μέσω σφαλμάτων. Ένα προσαρμοσμένο wrapper μπορεί να επικυρώνει αυτές τις διαδρομές, να αφαιρεί προνόμια ή να περιορίζει τα ορίσματα, επομένως μια εγγράψιμη ρύθμιση αποτελεί υποψήφια περίπτωση για έλεγχο, όχι απόδειξη εκτέλεσης κώδικα. Ελέγξτε την κανονικοποίηση διαδρομής, τα symlinks και την ανάλυση των οδηγιών πριν καταλήξετε σε συμπέρασμα.

### nginx μέσω sudo με ρυθμίσεις ελεγχόμενες από τον καλούντα

Ένας απεριόριστος κανόνας `nginx` με δυνατότητα root μπορεί να επιτρέπει στο [`-c` να επιλέξει διαφορετικό αρχείο ρυθμίσεων](https://nginx.org/en/docs/switches.html). Εξετάστε τα ακριβή ορίσματα και τις εξαιρέσεις sudo, αν ο καλών μπορεί να δώσει το αρχείο ρυθμίσεων και αν το master ή τα workers που προκύπτουν διατηρούν πρόσβαση σε προστατευμένες διαδρομές. Ένα επιλεγμένο `root` μαζί με `autoindex` μπορεί να εκθέσει αρχεία μέσω νέου listener· το [`dav_methods PUT`](https://nginx.org/en/docs/http/ngx_http_dav_module.html) μπορεί να προσφέρει προνομιούχα διαδρομή εγγραφής αρχείων, αλλά το DAV module δεν περιλαμβάνεται από προεπιλογή και πρέπει να ελεγχθούν η παρουσία του, η προσβασιμότητα του listener, τα δικαιώματα αρχείων και η συμπεριφορά προσωρινών αρχείων. Η οδηγία [`error_log`](https://nginx.org/en/docs/ngx_core_module.html#error_log) μπορεί επίσης να στοχεύει επιλεγμένο αρχείο· η εγγραφή logs σε ευαίσθητο αρχείο ρυθμίσεων, όπως το `/etc/ld.so.preload`, απαιτεί ενεργό προνομιούχο writer και ελεγχόμενη εγγραφή log προτού αποτελέσει διαδρομή κλιμάκωσης. Η επισήμανση του εκτελέσιμου στο `sudo -l` είναι αφορμή για έλεγχο, όχι απόδειξη ότι λειτουργεί κάποια από αυτές τις διαδρομές. Η παθητική απαρίθμηση δεν πρέπει να ξεκινήσει ή να επαναρυθμίσει το nginx.

### Σύγκριση μοτίβων σε προνομιούχα Bash prompts

Όταν ένα Bash script που επιτρέπεται μέσω sudo διαβάζει τιμή από τον καλούντα και την ελέγχει με `[[ "$expected" == $entered ]]`, το Bash ερμηνεύει το μη quoted δεξί operand ως pattern. Ένα wildcard μπορεί επομένως να ικανοποιήσει τη σύγκριση χωρίς να είναι γνωστή η αναμενόμενη τιμή. Η παράθεση του operand (`[[ "$expected" == "$entered" ]]`) το μετατρέπει σε κυριολεκτική σύγκριση συμβολοσειρών. Εξετάστε τον ακριβή κανόνα sudo, αν το prompt είναι προσβάσιμο και τι κάνει το script μετά τη σύγκριση· η σύνταξη από μόνη της δεν τεκμηριώνει εκμεταλλεύσιμη διαδρομή. Αποφύγετε την εμφάνιση της αναμενόμενης τιμής κατά την απαρίθμηση. Δείτε την [αναφορά conditional constructs του Bash](https://www.gnu.org/software/bash/manual/html_node/Conditional-Constructs.html).

### Helpers μέσω sudo που κατεβάζουν και εκτελούν αρχείο

Μια απεριόριστη παραχώρηση sudo σε προσαρμοσμένο helper με δυνατότητα root χρειάζεται έλεγχο ροής δεδομένων, αν δέχεται URL επιλεγμένο από τον καλούντα, γράφει την απόκριση σε δίσκο και στη συνέχεια καλεί το αρχείο με interpreter ή shell. Το [sudoers επιτρέπει αυθαίρετα ορίσματα όταν η καταχώριση εντολής δεν αναφέρει κανένα](https://man7.org/linux/man-pages/man5/sudoers.5.html)· μια σταθερή διαδρομή εκτελέσιμου δεν περιορίζει τις επιλογές των ορισμάτων. Επιβεβαιώστε την πραγματική επικύρωση URL, τη διαδρομή εξόδου, τον κλάδο επιτυχίας και την επακόλουθη εκτέλεση στο εγκατεστημένο helper. Ένα αντίστοιχο import libcurl ή μια εκτυπώσιμη συμβολοσειρά από μόνα τους δεν αποδεικνύουν αυτή την αλυσίδα.

Ακόμη και ένα σταθερό βασικό όνομα εξόδου μπορεί να αντικατασταθεί ανάμεσα στην εγγραφή και την εκτέλεση, όταν το helper χρησιμοποιεί **σχετική διαδρομή σε working directory που ελέγχει ο καλών**. Η μετονομασία ή αντικατάσταση αρχείου που ανήκει στο root διέπεται από την πρόσβαση εγγραφής και αναζήτησης στον κατάλογο και από τυχόν περιορισμούς sticky bit, όχι μόνο από το mode του αρχείου· δείτε το [`rename(2)`](https://man7.org/linux/man-pages/man2/rename.2.html). Ελέγξτε αν το helper ξανανοίγει αργότερα τη διαδρομή ή χρησιμοποιεί τον ήδη ανοιχτό descriptor και αν μεταβαίνει σε έμπιστο κατάλογο πριν γράψει. Εξετάστε παθητικά την πολιτική sudo, το helper και τα metadata του καταλόγου· μην εκτελέσετε προνομιούχο download ή race κατά την απαρίθμηση.

Ένα helper download που εκτελείται μέσω sudo ως root μπορεί επίσης να εκθέσει injection **ορίσματος**, αν δημιουργεί συμβολοσειρά εντολής Bash όπως `curl <caller input> -o <fixed output>`. Ένα φίλτρο που απορρίπτει whitespace αφήνει διαθέσιμη την [επέκταση ακολουθίας χαρακτήρων του Bash](https://www.gnu.org/software/bash/manual/html_node/Brace-Expansion.html): στοιχεία χωρισμένα με κόμματα, όταν δεν βρίσκονται μέσα σε εισαγωγικά, μπορούν να γίνουν ξεχωριστά ορίσματα curl. Αν η είσοδος φτάνει στο curl πριν από το σταθερό `-o`, μια επιλογή εξόδου που παρέχει ο καλών μπορεί να επιλέξει τον προορισμό για το πρώτο URL με την ταυτότητα του helper· το [curl συσχετίζει τις επιλογές εξόδου με τα URL με τη σειρά](https://curl.se/docs/manpage.html#-o). Επιβεβαιώστε το ακριβές shell, τα εισαγωγικά, την επικύρωση εισόδου, τον ενεργό κανόνα sudo, τη σειρά ορισμάτων curl και τα υποστηριζόμενα URL schemes, καθώς και αν ο καλών ελέγχει τα bytes που ανακτώνται ή μπορεί να διαβάσει το αποτέλεσμα. Ένα εκτελέσιμο πακεταρισμένο με PyInstaller μπορεί να περιέχει λογική εφαρμογής Python, αλλά το marker πακεταρίσματος ή ένα string `curl` από μόνο του δεν αποδεικνύει αυτή τη ροή δεδομένων. Εξετάστε ένα περιορισμένο offline αντίγραφο όταν υπάρχει εξουσιοδότηση· η συνήθης απαρίθμηση δεν πρέπει να εκτελεί το helper ή να ανακτά δεδομένα επιλεγμένα από επιτιθέμενο.

Ένα shell script που εκτελείται μέσω sudo ως root και καλεί [`mktemp -u` / `--dry-run`](https://www.gnu.org/software/coreutils/manual/html_node/mktemp-invocation.html) επιλέγει απλώς ένα αχρησιμοποίητο όνομα· **δεν** δημιουργεί το αρχείο. Αν το script στη συνέχεια δημιουργεί το όνομα σε κατάλογο που μπορεί να επηρεάσει άλλος χρήστης, το ξανανοίγει και προσθέτει το περιεχόμενό του σε προστατευμένο προορισμό όπως το `authorized_keys` του root, εξετάστε πιθανό race προσωρινού αρχείου. Επιβεβαιώστε τον ακριβή κανόνα sudo, την ιδιοκτησία καταλόγου και αρχείου, τη σειρά δημιουργίας και επανανοίγματος, τις προστασίες του kernel και αν η προνομιούχα εγγραφή χρησιμοποιεί πράγματι bytes ελεγχόμενα από τον επιτιθέμενο. Μια συμβολοσειρά `mktemp -u` ή ένα εγγράψιμο `/tmp` από μόνα τους δεν αποδεικνύουν race. Εξετάστε το script και τα metadata διαδρομών χωρίς να το εκτελέσετε ή να προκαλέσετε race στο προσωρινό αρχείο κατά την απαρίθμηση.

## Αμυντικές σημειώσεις

- Αποφύγετε να παραχωρείτε interpreters ή διαδραστικούς editors μέσω sudo.<sup>[[1]](#references)</sup>
- Μην παραχωρείτε γενικούς file writers όπως το `tee` με απεριόριστα operands. Χρησιμοποιήστε wrapper που ανήκει στο root, επιλέγει σταθερό προορισμό και απορρίπτει διαδρομές που ελέγχει ο καλών.<sup>[[2]](#references)</sup>
- Προτιμήστε σταθερά wrappers που ανήκουν στο root και εκτελούν μία περιορισμένη διοικητική ενέργεια.<sup>[[1]](#references)[[2]](#references)</sup>
- Αν δεν μπορεί να αποφευχθεί ένας interpreter, περιορίστε την ακριβή διαδρομή script και αποτρέψτε ορίσματα, imports με είσοδο ελεγχόμενη από χρήστη, `PYTHONPATH` και μη ασφαλή διατήρηση περιβάλλοντος.<sup>[[2]](#references)[[3]](#references)[[4]](#references)</sup>
- Αν απαιτείται επεξεργασία αρχείων, περιορίστε την ακριβή διαδρομή αρχείου και εξετάστε το `sudoedit` με διορθωμένες εκδόσεις sudo και αυστηρή διαχείριση περιβάλλοντος.<sup>[[1]](#references)[[2]](#references)</sup>
- Εξετάστε τα `SETENV`, `env_keep`, εγγράψιμους working directories, εγγράψιμες διαδρομές module/import, `NOEXEC`, `use_pty` και logging, αλλά μην τα θεωρείτε πλήρες sandbox.<sup>[[1]](#references)[[2]](#references)[[3]](#references)</sup>
