# SUSE Session and Disk-Service Escalation Indicators

{{#include ../../banners/hacktricks-training.md}}

## SSH session authorization through PAM

CVE-2025-6018 affected SUSE 15 PAM configurations in which an SSH authentication stack loaded `pam_env` before the session stack loaded `pam_systemd`. When `pam_env` read a user's `.pam_environment`, that user could supply `XDG_SEAT` and `XDG_VTNR` values that made an SSH session appear physically active to Polkit. An `allow_active=yes` action could then become available to a remote user. This changes session authorization; it does not by itself guarantee root access. SUSE fixed the default user-environment behavior in `pam` and the module placement generated by `pam-config`.<sup>[[1]](#references)[[2]](#references)</sup>

Inspect the effective `/etc/pam.d/sshd` include chain, the order of `pam_env.so` and `pam_systemd.so`, and any explicit `user_readenv=1` option. A patched `pam` package changes the default, but an explicit option can still request user-environment reading. A newer `pam-config` package does not prove that a locally modified or stale PAM stack was regenerated. Check the vendor package release and the actual configuration together.<sup>[[1]](#references)[[2]](#references)</sup>

## Active-user disk-service path

CVE-2025-6019 was an escalation path in `libblockdev` used through `udisks2`: during an XFS resize, an attacker-supplied filesystem could temporarily be mounted without the expected `nosuid` restriction. The route needs a usable UDisks D-Bus service, XFS resize support, a relevant Polkit action available to the caller, and an affected library package. CVE-2025-6018 is one way to gain an active-user session, but an already active user can reach the disk-service path independently.<sup>[[3]](#references)</sup>

For a passive review, check the UDisks service metadata, `org.freedesktop.udisks2.modify-device` policy, `xfs_growfs`, and the installed `libbd_fs2` package. SUSE lists `libbd_fs2` version `2.26-150400.3.5.1` as fixed for openSUSE Leap 15.6; the exact fixed release depends on the product. Policy and package presence alone are leads, not proof that a caller can mount or resize a device. Avoid changing mounts or invoking D-Bus methods during enumeration.<sup>[[3]](#references)</sup>
