# Συμβολικοί σύνδεσμοι, hardlinks και file descriptors

{{#include ../../banners/hacktricks-training.md}}

Μια διαδρομή ονομάζει ένα αντικείμενο τη στιγμή που επιλύεται· ένα ανοιχτό file descriptor διατηρεί αναφορά στο αντικείμενο αφού αλλάξει το όνομα της διαδρομής. Αυτή η διαφορά εξηγεί τα symlink races, τα κρυφά hardlinks, την ανάκτηση διαγραμμένων αρχείων και τις διαρροές κληρονομημένων file descriptors. Ανατρέξτε στο [σύστημα αρχείων, inodes και ανάκτηση](filesystem-inodes-and-recovery.md) για πληροφορίες σχετικά με τα inodes και τα mounts.

## Επιθεώρηση συνδέσμων και ιδιοκτησίας διαδρομών

```bash
namei -l /path/to/privileged/input
stat -c '%D %i %h %U:%G %a %n' /path/to/file
readlink -f /path/to/link
find /path/to/tree -type l -ls 2>/dev/null
find /path/to/tree -type f -links +1 -ls 2>/dev/null
```

Ένα symlink ανακατευθύνει την επίλυση διαδρομής· ένα hardlink είναι ένα άλλο όνομα για το ίδιο inode στο ίδιο filesystem. Αν μια προνομιούχα εργασία διαβάζει ή γράφει σε μια προβλέψιμη διαδρομή μέσα σε κατάλογο όπου μπορεί να γράψει ένας χρήστης, ο χρήστης ενδέχεται να μπορεί να ανακατευθύνει αυτή τη διαδρομή προς έναν ευαίσθητο στόχο. Ελέγξτε την ιδιοκτησία και τα δικαιώματα σε κάθε γονικό κατάλογο, όχι μόνο στο τελικό αρχείο. Τα `fs.protected_symlinks` και `fs.protected_hardlinks` περιορίζουν συνηθισμένες επιθέσεις μεταξύ χρηστών, αλλά δεν καθιστούν ασφαλείς όλες τις εγγράψιμες διαδρομές.

Για μια προνομιούχα εργασία που αλλάζει δικαιώματα με shell glob, διακρίνετε τους συνδέσμους που επεκτείνονται σε **ορίσματα γραμμής εντολών** από εκείνους που εντοπίζονται αργότερα κατά την αναδρομική διάσχιση. [Το GNU `chmod` ενεργεί στο αντικείμενο αναφοράς ενός symlink που δίνεται στη γραμμή εντολών](https://www.gnu.org/software/coreutils/manual/html_node/chmod-invocation.html), ενώ συνήθως αγνοεί τα symlink που συναντά κατά την αναδρομή· το `-R` από μόνο του δεν καθιστά τις δύο περιπτώσεις ισοδύναμες. Εξετάστε την πραγματική ταυτότητα και εντολή που εκτελείται προγραμματισμένα, αν ένας μη έμπιστος χρήστης μπορεί να δημιουργήσει καταχώριση που να ταιριάζει στο glob, τη συμπεριφορά και τις επιλογές του εγκατεστημένου `chmod`, καθώς και τα δικαιώματα πρόσβασης που θα προκύψουν για τον προτεινόμενο στόχο. Ένας εγγράψιμος κατάλογος ή ένα symlink από μόνο του δεν αποδεικνύει ότι θα γίνει προνομιούχα αλλαγή δικαιωμάτων. Εξετάστε το script και τα μεταδεδομένα της διαδρομής χωρίς να τοποθετήσετε σύνδεσμο ή να ενεργοποιήσετε την εργασία κατά την παθητική απαρίθμηση.

Μια προνομιούχα προγραμματισμένη διεργασία εγγραφής μπορεί να έχει προβλέψιμη διαδρομή εξόδου, ακόμη κι όταν το όνομα αρχείου περιέχει ένα hash που μοιάζει τυχαίο: η [C `rand()` επαναλαμβάνει την ακολουθία της για την ίδια τιμή seed του `srand()`](https://man7.org/linux/man-pages/man3/rand.3.html), ακόμη και όταν το seed προκύπτει από γνωστή ώρα εκτέλεσης. Αν η εργασία διαβάζει επίσης εγγραφές βάσης δεδομένων στις οποίες μπορεί να γράψει ο καλών, για να κατασκευάσει αυτό το όνομα, επαληθεύστε τον ακριβή αλγόριθμο μετατροπής εγγραφής σε όνομα, το seed και τη συμπεριφορά της libc, το πρόγραμμα εκτέλεσης, τα δικαιώματα του καλούντος για εγγραφή εγγραφών και δημιουργία καταλόγων, καθώς και αν μπορεί να τοποθετηθεί προϋπάρχον symlink πριν από το προνομιούχο άνοιγμα. Η [`fopen(..., "w")` δημιουργεί ή περικόπτει το αρχείο στο οποίο επιλύεται η διαδρομή](https://man7.org/linux/man-pages/man3/fopen.3.html)· ελέγξτε την πραγματική υλοποίηση για flags ασφαλούς ανοίγματος έναντι συνδέσμων ή ατομικής αντικατάστασης, την ταυτότητα με την οποία γίνεται η εγγραφή, τα δικαιώματα του στόχου και την πολιτική symlink για καταλόγους με sticky bit. Ένα προβλέψιμο όνομα ή μια εγγράψιμη εγγραφή από μόνα τους αποτελούν μόνο αφορμή για περαιτέρω έλεγχο. Εξετάστε τον κώδικα, το πρόγραμμα εκτέλεσης και τα μεταδεδομένα χωρίς να εισαγάγετε εγγραφές ή να εκτελέσετε την εργασία κατά την παθητική απαρίθμηση.

Για μια υπηρεσία μετατροπής αρχείων που εκτελείται ως άλλος χρήστης, εξετάστε αν ο καλών μπορεί να επιλέξει διαδρομή ή επέκταση εξόδου και αν ο μετατροπέας ακολουθεί ένα προϋπάρχον symlink εξόδου. Ορισμένοι μετατροπείς επιλέγουν τη μορφή εξόδου από την επέκταση της διαδρομής· ένας σύνδεσμος με αποδεκτή επέκταση μπορεί και πάλι να δείχνει σε ευαίσθητο στόχο χωρίς επέκταση. Για να είναι επιτυχής μια εγγραφή μεταξύ χρηστών απαιτούνται προσβάσιμη υπηρεσία, έλεγχος της διαδρομής και του συνδέσμου από τον καλούντα, άνοιγμα του συνδέσμου για εγγραφή από τον μετατροπέα και δικαίωμα εγγραφής για την ταυτότητα της υπηρεσίας. Το Linux `fs.protected_symlinks=1` περιορίζει την ακολούθηση συνδέσμου άλλου χρήστη μέσα σε **sticky κατάλογο εγγράψιμο από όλους**· δεν παρέχει την ίδια προστασία για σύνδεσμο σε συνηθισμένο κατάλογο που ανήκει σε χρήστη. Εξετάστε την επιλυμένη διαδρομή και την ιδιοκτησία των γονικών καταλόγων πριν καταλήξετε σε συμπέρασμα. Δείτε τη [συμπεριφορά του calibre για τα αρχεία εξόδου](https://manual.calibre-ebook.com/generated/en/ebook-convert.html) και την [πολιτική symlink του Linux](https://www.kernel.org/doc/html/latest/admin-guide/sysctl/fs.html#protected-symlinks).

Ένα wrapper λήψεων που επιτρέπεται μέσω sudo χρειάζεται τον ίδιο έλεγχο διαδρομής εξόδου, αν λαμβάνει δεδομένα που επιλέγει ο καλών ενώ διατηρεί κατάλογο εργασίας που ελέγχεται από τον καλούντα. Εξετάστε το πραγματικό πρόγραμμα λήψης και αν το επιλεγμένο όνομα βάσης, ο χειρισμός συγκρούσεων ή ένα προϋπάρχον symlink μπορούν να ανακατευθύνουν μια προνομιούχα εγγραφή· η επιλογή URL ή ένα symlink από μόνα τους δεν αρκούν. Το [Axel τεκμηριώνει ένα `~/.axelrc` ανά χρήστη](https://github.com/axel-download-accelerator/axel/blob/master/doc/axel.txt), ενώ το [παράδειγμα διαμόρφωσής του περιλαμβάνει τα `default_filename` και `no_clobber`](https://github.com/axel-download-accelerator/axel/blob/master/doc/axelrc.example), επομένως ένα wrapper που χρησιμοποιεί Axel μπορεί επίσης να κληρονομήσει από αυτό το αρχείο την επιλογή ονόματος εξόδου. Επιβεβαιώστε την ενεργή τιμή του `HOME`: το [sudo μπορεί να την επαναφέρει ή να τη διατηρήσει ανάλογα με την πολιτική](https://man7.org/linux/man-pages/man8/sudo.8.html), και το `.axelrc` ενός χρήστη είναι σχετικό μόνο αν το προνομιούχο πρόγραμμα λήψης διαβάζει πράγματι αυτό το αρχείο. Ελέγξτε τον κανόνα, το wrapper, τη διαδρομή και τα δικαιώματα του αρχείου διαμόρφωσης, το τελικό όνομα εξόδου και την κατάσταση του αρχείου-στόχου, χωρίς να ξεκινήσετε λήψη κατά την παθητική απαρίθμηση.

Για ένα wrapper ACL που επιτρέπεται μέσω sudo, εξετάστε πώς επικυρώνει το αρχείο που επιλέγει ο καλών πριν καλέσει το `setfacl`. Ένας έλεγχος λεξικού προθέματος και η απόρριψη του `..` δεν εμποδίζουν ένα symlink μέσα στον επιτρεπόμενο κατάλογο να επιλυθεί εκτός αυτού· και το `test -f` ακολουθεί επίσης τον σύνδεσμο. Επιβεβαιώστε ότι το wrapper φτάνει στην πράξη ACL με επαρκή προνόμια, ότι ο καλών ελέγχει τον σύνδεσμο και ότι η ACL που προκύπτει παρέχει την απαιτούμενη πρόσβαση στον στόχο **και στους γονικούς καταλόγους του**. Ορισμένα προγράμματα που χρησιμοποιούν τα αρχεία απορρίπτουν αρχεία με εγγράψιμες ACL ή χαλαρά δικαιώματα, επομένως μια αλλαγή ACL από μόνη της δεν αποδεικνύει ότι υπάρχει λειτουργική διαδρομή κλιμάκωσης προνομίων.

## Έλεγχος προνομιούχων εγγραφών σε προσαρτημένα από χρήστες filesystem FUSE

Μια ενεργή, αυτόνομη γραμμή `user_allow_other` στο `/etc/fuse.conf` επιτρέπει σε μη-root χρήστη να ζητήσει `allow_other` ή `allow_root` σε ένα mount FUSE. Αυτές οι επιλογές mount μπορούν να επιτρέψουν σε μια διεργασία root να προσπελάσει ένα filesystem που υλοποιείται από τον χρήστη που το προσάρτησε. Αν ένα βοηθητικό πρόγραμμα που επιτρέπεται μέσω sudo γράφει ένα αρχείο καταγραφής που περιέχει μυστικά ή άλλο αρχείο εξόδου, χρησιμοποιώντας σχετική διαδρομή ως προς κατάλογο εργασίας που ελέγχεται από τον καλούντα, εξετάστε αν αυτός ο κατάλογος μπορεί να είναι filesystem FUSE προσαρτημένο από χρήστη. Η υλοποίηση FUSE μπορεί να παρατηρεί τις εγγραφές, ακόμη κι αν το αρχείο που προκύπτει εμφανίζεται ως ιδιοκτησίας root ή με mode `0600` σε ένα συνηθισμένο filesystem.

```bash
grep -n '^[[:space:]]*user_allow_other[[:space:]]*$' /etc/fuse.conf 2>/dev/null
sudo -l
```

Αυτό αποτελεί **ένδειξη**, όχι απόδειξη διαρροής. Επιβεβαιώστε την πραγματική ταυτότητα sudo/run-as και τα ορίσματα, τη διαδρομή εξόδου και το ευαίσθητο περιεχόμενο του helper, την πρόσβαση στο `/dev/fuse`, την επιτυχή προσάρτηση με `allow_other` ή `allow_root`, καθώς και το αν η προνομιούχα διεργασία μπορεί να εισέλθει στο mount. Μην εκτελείτε το προνομιούχο helper και μην προσαρτάτε filesystem κατά τη συνήθη καταγραφή. Δείτε την [περιγραφή πολιτικής του libfuse](https://github.com/libfuse/libfuse/blob/master/util/fuse.conf) και τις [συχνές ερωτήσεις πρόσβασης του libfuse](https://github.com/libfuse/libfuse/wiki/FAQ#why-dont-other-users-have-access-to-the-mounted-filesystem).

## Αναζητήστε races διαδρομών

Το επικίνδυνο μοτίβο είναι ένα προνομιούχο πρόγραμμα να ελέγχει ένα pathname και αργότερα να ανοίγει το ίδιο pathname χωρίς να διατηρεί ασφαλή αναφορά στο ελεγμένο αντικείμενο. Ένας attacker που ελέγχει έναν γονικό κατάλογο μπορεί να αντικαταστήσει ένα αρχείο ή symlink ανάμεσα στις δύο ενέργειες. Το ίδιο πρόβλημα εμφανίζεται σε προσωρινά αρχεία, scripts που εκτελούνται από timers, εξαγωγή αρχείων και διαδικασίες backup. Επιβεβαιώστε την πραγματική λειτουργία ανάγνωσης/εγγραφής και τα permissions του στόχου προτού ισχυριστείτε ότι υπάρχει επίπτωση.

Η **δημιουργία** archive μπορεί επίσης να αποκαλύψει αρχεία μεταξύ διαφορετικών ταυτοτήτων. Το Info-ZIP `zip -r` συνήθως ακολουθεί ένα symlink που έχει τοποθετηθεί μέσα στο δέντρο πηγής και αποθηκεύει τα περιεχόμενα του στόχου· το `-y`/`--symlinks` αποθηκεύει αντί γι' αυτό το ίδιο το link. Αν ένας χρήστης με χαμηλότερα προνόμια μπορεί να προσθέσει ένα link σε κατάλογο που γίνεται backup, ελέγξτε τον ακριβή archiver/τις επιλογές, την ταυτότητα ανάγνωσης της εργασίας backup και αν το παραγόμενο archive είναι αναγνώσιμο από αυτόν τον χρήστη. Ένας εγγράψιμος κατάλογος πηγής ή ένα symlink από μόνο του δεν αποδεικνύει διαρροή. Εξετάστε τα metadata των links και του archive χωρίς να ενεργοποιήσετε το backup ή να εξαγάγετε μυστικό περιεχόμενο κατά την καταγραφή. Δείτε την [τεκμηρίωση επιλογών του Info-ZIP](https://sources.debian.org/src/zip/3.0-3/man/zip.1/#L1638).

Το GNU `tar` έχει διαφορετική προεπιλεγμένη συμπεριφορά: συνήθως αποθηκεύει ένα symlink ως link, ενώ το [`-h` / `--dereference` το ακολουθεί κατά τη δημιουργία του archive](https://www.gnu.org/software/tar/manual/html_node/dereference.html). Για ένα προνομιούχο προγραμματισμένο backup, εξετάστε την ακριβή κλήση του `tar`, αν ένας χρήστης με χαμηλότερα προνόμια μπορεί να αντικαταστήσει ένα pathname εισόδου πριν το διαβάσει το `tar` και αν το παραγόμενο archive είναι προσβάσιμο σε αυτόν τον χρήστη. Ένα προσωρινό checksum ή άλλο sidecar σε εγγράψιμο κατάλογο staging μπορεί να γίνει τέτοια είσοδος, όταν δηλωθεί ρητά σε μεταγενέστερη εντολή `tar -h`. Πρέπει να επαληθευτούν το χρονικό παράθυρο του race, η ταυτότητα της εργασίας, η πολιτική για symlink, η αναγνωσιμότητα του στόχου από αυτή την ταυτότητα και τα ACL του archive. Μην αντικαθιστάτε αρχεία, μην εκτελείτε την εργασία και μην αποσυσκευάζετε ευαίσθητα archives κατά τους παθητικούς ελέγχους.

Η **εξαγωγή** archive υπερβαίνει ένα διαφορετικό όριο, όταν μια προνομιούχα εργασία διαβάζει archive που μπορεί να αντικαταστήσει χρήστης με χαμηλότερα προνόμια. Το [GNU tar συνήθως επαναφέρει την ιδιοκτησία που έχει αποθηκευτεί στο archive όταν εκτελείται από τον superuser](https://www.gnu.org/software/tar/manual/html_node/Option-Summary.html), ενώ οι [επιλογές επαναφοράς permissions](https://www.gnu.org/software/tar/manual/html_node/Setting-Access-Permissions.html) επηρεάζουν τα mode bits των εξαγόμενων αρχείων. Εξετάστε τον ακριβή extractor και τις flags, το χρονικό παράθυρο αντικατάστασης του archive, τα metadata αριθμητικού owner και mode, τα permissions του καταλόγου εξαγωγής και αν ο καθαρισμός αφήνει το αποτέλεσμα προσβάσιμο. Ένα μέλος SUID που ανήκει στον root αποτελεί ζήτημα μόνο αν το mode του διατηρηθεί κατά την εξαγωγή και η πολιτική του target mount και της διεργασίας επιτρέπει την αλλαγή ταυτότητας· ένα μη έμπιστο archive ή ένα εγγράψιμο path staging από μόνο του δεν το αποδεικνύει. Εξετάστε την εργασία και τα metadata χωρίς να αντικαταστήσετε ή να εξαγάγετε archive κατά την παθητική καταγραφή.

Ένα εξαγόμενο symlink μπορεί επίσης να αποκαλύψει ένα προστατευμένο αρχείο μέσω μεταγενέστερης προνομιούχας σύγκρισης. Το [GNU `diff` συνήθως ακολουθεί symlinks κατά τη σύγκριση καταλόγων](https://www.gnu.org/software/diffutils/manual/html_node/Special-Files.html), επομένως ένα `diff -r` που εκτελείται ως root πάνω σε μη έμπιστο εξαγόμενο δέντρο μπορεί να διαβάσει τον στόχο ενός link και να συμπεριλάβει στο αποτέλεσμά του περιεχόμενο που διαφέρει. Επιβεβαιώστε ότι το archive μπορεί να αντικατασταθεί, ότι το link οδηγεί σε διαδρομή την οποία πράγματι εξετάζει η σύγκριση, ότι η εργασία έχει δικαίωμα ανάγνωσης του στόχου και ότι το αποτέλεσμα της σύγκρισης ή το error log είναι αναγνώσιμο από τον χρήστη με χαμηλότερα προνόμια. Το link ή το archive από μόνο του δεν αποδεικνύει διαρροή· εξετάστε την εργασία, τα metadata της διαδρομής και τα permissions των logs χωρίς να εκτελέσετε τη σύγκριση ή να διαβάσετε προστατευμένο περιεχόμενο κατά την καταγραφή.

Μια επαναλαμβανόμενη μεταφορά από το host μπορεί να μετατρέψει ένα μη έμπιστο μέλος archive σε μεταγενέστερη διαδρομή εξόδου. Αν μια εργασία με υψηλότερα προνόμια αντιγράφει archive από container χαμηλότερου επιπέδου εμπιστοσύνης, εξάγει ένα symlink με όνομα ίδιο με το basename του προορισμού της επόμενης μεταφοράς και αργότερα γράφει στο ίδιο pathname, η μεταγενέστερη εγγραφή μπορεί να καταλήξει στον στόχο του link. Ελέγξτε το όνομα και τον στόχο του μέλους archive, τις flags εξαγωγής και τον κατάλογο, αν ο extractor αφήνει πράγματι αυτό το link στη θέση του, τον τρόπο με τον οποίο η υλοποίηση μεταφοράς χειρίζεται ένα υπάρχον link προορισμού και την effective ταυτότητα εγγραφής της εργασίας του host. Το [GNU tar τεκμηριώνει τον τρόπο με τον οποίο η εξαγωγή χειρίζεται υπάρχοντα αρχεία και symlinks](https://www.gnu.org/software/tar/manual/html_section/extract-options.html)· το [OpenSSH scp χρησιμοποιεί SFTP από προεπιλογή στις σύγχρονες εκδόσεις](https://man.openbsd.org/scp.1), επομένως επαληθεύστε τη συμπεριφορά της εγκατεστημένης υλοποίησης μεταφοράς αντί να υποθέτετε ότι όλες οι εκδόσεις του `scp` γράφουν μέσω ενός link. Μια διεργασία `scp` ορατή μέσα σε container ή ένα εγγράψιμο archive από μόνο του δεν αποδεικνύει την εξαγωγή στο host και τη μεταγενέστερη εγγραφή. Εξετάστε την εργασία και τα metadata της διαδρομής χωρίς να μεταφέρετε ή να εξαγάγετε κατασκευασμένο archive κατά την καταγραφή.

Το Ansible [`synchronize` module](https://docs.ansible.com/projects/ansible/latest/collections/ansible/posix/synchronize_module.html) περιτυλίγει το rsync· το `copy_links: true` αντιγράφει τον στόχο ενός symlink αντί για το ίδιο το link. Για ένα προγραμματισμένο backup, ελέγξτε αν ένας χρήστης με χαμηλότερα προνόμια μπορεί να δημιουργήσει ένα link μέσα στο ακριβές δέντρο πηγής, αν η ταυτότητα συγχρονισμού μπορεί να διαβάσει τον στόχο του και αν το αντίγραφο ή το archive που προκύπτει είναι αναγνώσιμο από αυτόν τον χρήστη. Το playbook, η τοποθέτηση του link, η ταυτότητα run-as και τα permissions εξόδου πρέπει να συνδυάζονται· ένας εγγράψιμος κατάλογος upload ή η ρύθμιση `copy_links` από μόνη της είναι απλώς αφορμή για έλεγχο. Εξετάστε τα metadata και το playbook χωρίς να δημιουργήσετε links ή να ενεργοποιήσετε την εργασία.

## Επιθεωρήστε ανοιχτούς file descriptors

```bash
ls -l /proc/<PID>/fd 2>/dev/null
lsof -p <PID> 2>/dev/null
lsof +L1 2>/dev/null
```

Μια διεργασία μπορεί να διατηρήσει πρόσβαση σε ένα αρχείο αφού αυτό διαγραφεί ή μετονομαστεί. Μια διεργασία με αυξημένα προνόμια μπορεί επίσης να μεταβιβάσει έναν descriptor μέσω ενός Unix socket ή να τον αφήσει ακούσια ανοιχτό κατά το `execve()`, αν λείπει το close-on-exec. Εξετάστε τους στόχους στο `/proc/<PID>/fd` για ευαίσθητα αρχεία, διαγραμμένα αρχεία, διαδρομές του host που είναι ορατές μέσα σε ένα container και μη αναμενόμενα sockets. Η αποαναφορά των descriptors μιας άλλης διεργασίας υπόκειται στους ελέγχους πρόσβασης του kernel· ένας ορατός συμβολικός σύνδεσμος δεν εγγυάται ότι το περιεχόμενό του μπορεί να διαβαστεί.

Ένα προσαρμοσμένο SUID helper μπορεί να ανοίξει μια προστατευμένη διαδρομή, να απορρίψει το effective UID του και να αφήσει τον descriptor ανοιχτό. Αν έπειτα ορίσει τον εαυτό του ως dumpable, η ιδιοκτησία και η πρόσβαση στο `/proc/<PID>/fd` μπορεί να αλλάξουν· ελέγξτε την ακριβή μετάβαση διαπιστευτηρίων, το [`PR_SET_DUMPABLE`](https://man7.org/linux/man-pages/man2/PR_SET_DUMPABLE.2const.html), την πολιτική procfs/ptrace και τα δικαιώματα του αρχείου-στόχου. Το εκ νέου άνοιγμα μιας διαδρομής descriptor μπορεί να παρακάμψει έναν μη προσβάσιμο **γονικό κατάλογο**, αλλά και πάλι να αποτύχει αν ο καλών δεν μπορεί να διαβάσει το αρχείο. Ένας ορατός στόχος descriptor ή μόνο το bit SUID δεν αποδεικνύει διαρροή.

Τα artifacts από crash αποτελούν ξεχωριστό στοιχείο προς διερεύνηση: ένα core dump μπορεί να περιέχει τη μνήμη μιας διεργασίας, συμπεριλαμβανομένων δεδομένων που διαβάστηκαν προηγουμένως υπό ταυτότητα με αυξημένα προνόμια. Στο Ubuntu, το [Apport αποθηκεύει συνήθως τις αναφορές στο `/var/crash`](https://documentation.ubuntu.com/project/contributors/debugging/apport/)· άλλα συστήματα μπορεί να χρησιμοποιούν διαφορετικό handler του `core_pattern` ή αποθήκευση μέσω systemd. Κατά τη συνήθη απογραφή, ελέγχετε μόνο τις διαδρομές των αναφορών, τον ιδιοκτήτη, τα δικαιώματα και αν είναι αναγνώσιμες. Μια αναφορά έχει σημασία μόνο αν η σχετική διεργασία ήταν dumpable, ο handler crash διατήρησε τα ευαίσθητα bytes και ο τρέχων χρήστης μπορεί να αποκτήσει πρόσβαση στην αναφορά. Μην προκαλείτε crash σε helper και μην αποσυσκευάζετε ένα dump στο πλαίσιο παθητικής απογραφής. Δείτε το [`core(5)`](https://man7.org/linux/man-pages/man5/core.5.html) για τις συνθήκες SUID και δημιουργίας dump.

Όταν μια υπηρεσία χρησιμοποιεί έναν κληρονομημένο descriptor, ελέγξτε την αλυσίδα εκκίνησής της και τους αριθμούς των descriptors πριν δοκιμάσετε ανακατεύθυνση shell ή `/proc/self/fd/<N>`. Αν ένα αρχείο έχει διαγραφεί αλλά παραμένει ανοιχτό, η [ανάκτηση διαγραμμένων αρχείων](filesystem-inodes-and-recovery.md#deleted-file-recovery-through-open-fds) μπορεί να διατηρήσει στοιχεία ή να ανακτήσει περιεχόμενο. Για διαλογή σε επίπεδο διεργασιών, συνεχίστε με την [απογραφή διεργασιών και τις διαδρομές υπηρεσιών](../processes-crontab-systemd-dbus/process-enumeration-and-service-paths.md).
