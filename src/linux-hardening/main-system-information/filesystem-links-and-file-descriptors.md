# Συμβολικοί σύνδεσμοι, hard links και file descriptors

{{#include ../../banners/hacktricks-training.md}}

Μια διαδρομή ονομάζει ένα αντικείμενο τη στιγμή που επιλύεται· ένα ανοιχτό file descriptor διατηρεί αναφορά στο αντικείμενο ακόμη κι αν αλλάξει το όνομα της διαδρομής. Αυτή η διαφορά εξηγεί τα symlink races, τα κρυφά hard links, την ανάκτηση διαγραμμένων αρχείων και τις διαρροές κληρονομημένων descriptors. Δείτε το [filesystem, inodes and recovery](filesystem-inodes-and-recovery.md) για πληροφορίες σχετικά με τα inode και τα mounts.

## Έλεγχος συνδέσμων και ιδιοκτησίας διαδρομών

```bash
namei -l /path/to/privileged/input
stat -c '%D %i %h %U:%G %a %n' /path/to/file
readlink -f /path/to/link
find /path/to/tree -type l -ls 2>/dev/null
find /path/to/tree -type f -links +1 -ls 2>/dev/null
```

Ένα symlink ανακατευθύνει την επίλυση ενός pathname· ένα hardlink είναι ένα ακόμη όνομα για το ίδιο inode στο ίδιο filesystem. Αν μια προνομιούχα εργασία διαβάζει ή γράφει σε ένα προβλέψιμο path μέσα σε κατάλογο εγγράψιμο από χρήστη, ο χρήστης ενδέχεται να μπορεί να ανακατευθύνει αυτό το path σε έναν ευαίσθητο στόχο. Ελέγξτε την ιδιοκτησία και τα δικαιώματα σε κάθε γονικό κατάλογο, όχι μόνο στο τελικό αρχείο. Τα `fs.protected_symlinks` και `fs.protected_hardlinks` περιορίζουν συνήθεις επιθέσεις μεταξύ χρηστών, αλλά δεν καθιστούν ασφαλή οποιαδήποτε εγγράψιμα paths.

Για μια προνομιούχα εργασία που αλλάζει δικαιώματα με shell glob, διακρίνετε τα links που επεκτείνονται σε **ορίσματα γραμμής εντολών** από τα links που εντοπίζονται αργότερα κατά την αναδρομική διάσχιση. [Το GNU `chmod` ενεργεί στο referent ενός symlink που δηλώνεται στη γραμμή εντολών](https://www.gnu.org/software/coreutils/manual/html_node/chmod-invocation.html), ενώ συνήθως αγνοεί τα symlinks που συναντά κατά την αναδρομή· το `-R` από μόνο του δεν καθιστά ισοδύναμες αυτές τις δύο περιπτώσεις. Ελέγξτε την πραγματική ταυτότητα και εντολή της προγραμματισμένης εργασίας, αν ένας μη έμπιστος χρήστης μπορεί να δημιουργήσει μια εγγραφή που ταιριάζει στο glob, τη συμπεριφορά και τις επιλογές του εγκατεστημένου `chmod`, καθώς και την πρόσβαση που θα αποκτήσει τελικά ο προτεινόμενος στόχος. Ένας εγγράψιμος κατάλογος ή ένα symlink από μόνο του δεν αποδεικνύει προνομιούχα αλλαγή mode. Επιθεωρήστε το script και τα metadata των paths χωρίς να δημιουργήσετε link ή να ενεργοποιήσετε την εργασία κατά την παθητική απογραφή.

Μια προγραμματισμένη προνομιούχα διεργασία εγγραφής μπορεί να έχει προβλέψιμο path εξόδου ακόμη κι όταν το όνομα αρχείου περιέχει ένα hash που φαίνεται τυχαίο: [η C `rand()` επαναλαμβάνει την ακολουθία της για την ίδια τιμή seed του `srand()`](https://man7.org/linux/man-pages/man3/rand.3.html), συμπεριλαμβανομένου seed που προκύπτει από γνωστό χρόνο εκτέλεσης. Αν η εργασία διαβάζει επίσης γραμμές βάσης δεδομένων εγγράψιμες από τον καλούντα κατά τη δημιουργία αυτού του ονόματος, επαληθεύστε τον ακριβή αλγόριθμο μετατροπής γραμμής σε όνομα, το seed και τη συμπεριφορά της libc, το πρόγραμμα εκτέλεσης, τα δικαιώματα του καλούντος για εγγραφή γραμμών και δημιουργία καταλόγου, καθώς και αν μπορεί να τοποθετηθεί ένα προϋπάρχον symlink πριν από το προνομιούχο άνοιγμα. Το [`fopen(..., "w")` δημιουργεί ή περικόπτει το αρχείο που επιλύεται](https://man7.org/linux/man-pages/man3/fopen.3.html)· ελέγξτε την πραγματική υλοποίηση για flags ανοίγματος ασφαλή έναντι links ή ατομική αντικατάσταση, την ταυτότητα που χρησιμοποιείται για την εγγραφή, τα δικαιώματα του στόχου και την πολιτική symlink σε καταλόγους sticky. Ένα προβλέψιμο όνομα ή μια εγγράψιμη γραμμή από μόνα τους αποτελούν μόνο αφορμή για έλεγχο. Επιθεωρήστε τον κώδικα, το πρόγραμμα εκτέλεσης και τα metadata χωρίς να εισαγάγετε γραμμές ή να εκτελέσετε την εργασία κατά την παθητική απογραφή.

Για μια υπηρεσία μετατροπής αρχείων που εκτελείται ως άλλος χρήστης, εξετάστε αν ο καλών μπορεί να επιλέξει path ή επέκταση εξόδου και αν ο μετατροπέας ακολουθεί ένα προϋπάρχον symlink εξόδου. Ορισμένοι μετατροπείς επιλέγουν τη μορφή εξόδου από την επέκταση του pathname· ένα link με αποδεκτή επέκταση μπορεί και πάλι να δείχνει σε έναν ευαίσθητο στόχο χωρίς επέκταση. Για επιτυχημένη εγγραφή μεταξύ χρηστών απαιτούνται προσβάσιμη υπηρεσία, έλεγχος του path και του link από τον καλούντα, άνοιγμα του link για εγγραφή από τον μετατροπέα και δικαίωμα εγγραφής για την ταυτότητα της υπηρεσίας. Το Linux `fs.protected_symlinks=1` περιορίζει την ακολούθηση link άλλου χρήστη σε έναν **sticky κατάλογο εγγράψιμο από όλους**· δεν παρέχει την ίδια προστασία για link σε συνηθισμένο κατάλογο που ανήκει σε χρήστη. Ελέγξτε το path που επιλύεται και την ιδιοκτησία των γονικών καταλόγων πριν καταλήξετε σε συμπέρασμα. Δείτε τη [συμπεριφορά αρχείου εξόδου του calibre](https://manual.calibre-ebook.com/generated/en/ebook-convert.html) και την [πολιτική symlink του Linux](https://www.kernel.org/doc/html/latest/admin-guide/sysctl/fs.html#protected-symlinks).

Ένα wrapper λήψης που επιτρέπεται μέσω sudo χρειάζεται τον ίδιο έλεγχο του path εξόδου, αν λαμβάνει δεδομένα που επιλέγει ο καλών ενώ διατηρεί έναν κατάλογο εργασίας που ελέγχεται από τον καλούντα. Επιθεωρήστε το πραγματικό πρόγραμμα λήψης και αν το επιλεγμένο basename, η διαχείριση συγκρούσεων ή ένα προϋπάρχον symlink μπορούν να ανακατευθύνουν μια προνομιούχα εγγραφή· η επιλογή URL ή ένα symlink από μόνο του δεν αρκεί. Το [Axel τεκμηριώνει ένα `~/.axelrc` ανά χρήστη](https://github.com/axel-download-accelerator/axel/blob/master/doc/axel.txt), ενώ το [παράδειγμα ρύθμισής του περιλαμβάνει τα `default_filename` και `no_clobber`](https://github.com/axel-download-accelerator/axel/blob/master/doc/axelrc.example), επομένως ένα wrapper που χρησιμοποιεί Axel μπορεί επίσης να κληρονομήσει από αυτό το αρχείο την επιλογή ονόματος εξόδου. Επιβεβαιώστε το πραγματικό `HOME`: [το sudo μπορεί να το επαναφέρει ή να το διατηρήσει ανάλογα με την πολιτική](https://man7.org/linux/man-pages/man8/sudo.8.html), και το `.axelrc` ενός χρήστη έχει σημασία μόνο αν το προνομιούχο πρόγραμμα λήψης το διαβάζει πράγματι. Ελέγξτε τον κανόνα, το wrapper, το path και τα δικαιώματα του αρχείου ρυθμίσεων, το τελικό όνομα εξόδου και την κατάσταση του αρχείου-στόχου, χωρίς να ξεκινήσετε λήψη κατά την παθητική απογραφή.

Για ένα wrapper ACL που επιτρέπεται μέσω sudo, εξετάστε πώς επικυρώνει ένα αρχείο που επιλέγει ο καλών πριν καλέσει το `setfacl`. Ένας λεξικός έλεγχος προθέματος και η απόρριψη του `..` δεν εμποδίζουν ένα symlink μέσα στον επιτρεπόμενο κατάλογο να επιλυθεί εκτός αυτού· και το `test -f` ακολουθεί το link. Επιβεβαιώστε ότι το wrapper φτάνει στην ενέργεια ACL με επαρκή προνόμια, ότι ο καλών ελέγχει το link και ότι το ACL που προκύπτει παρέχει την απαιτούμενη πρόσβαση στον στόχο **και στους γονικούς καταλόγους του**. Ορισμένοι καταναλωτές απορρίπτουν αρχεία με εγγράψιμα ACL ή χαλαρά modes, επομένως μια αλλαγή ACL από μόνη της δεν αποδεικνύει λειτουργική διαδρομή κλιμάκωσης.

## Ελέγξτε τις προνομιούχες εγγραφές σε συστήματα αρχείων FUSE που έχουν προσαρτηθεί από χρήστη

Μια ενεργή, αυτόνομη γραμμή `user_allow_other` στο `/etc/fuse.conf` επιτρέπει σε μη root χρήστη να ζητήσει `allow_other` ή `allow_root` σε ένα FUSE mount. Αυτές οι επιλογές mount μπορούν να επιτρέψουν σε μια root διεργασία να αποκτήσει πρόσβαση σε filesystem που υλοποιείται από τον χρήστη που το προσάρτησε. Αν ένα βοηθητικό πρόγραμμα που επιτρέπεται μέσω sudo γράφει ένα log με ευαίσθητα δεδομένα ή άλλο output σχετικό με κατάλογο εργασίας που ελέγχει ο καλών, εξετάστε αν αυτός ο κατάλογος μπορεί να είναι FUSE filesystem προσαρτημένο από χρήστη. Η υλοποίηση FUSE μπορεί να παρατηρεί τις εγγραφές ακόμη κι όταν το αρχείο που προκύπτει φαίνεται να ανήκει στον root ή να έχει mode `0600` σε ένα συνηθισμένο filesystem.

```bash
grep -n '^[[:space:]]*user_allow_other[[:space:]]*$' /etc/fuse.conf 2>/dev/null
sudo -l
```

Αυτό είναι **υποψήφιο εύρημα**, όχι απόδειξη διαρροής. Επιβεβαιώστε την πραγματική ταυτότητα sudo/run-as και τα ορίσματα, τη διαδρομή εξόδου και το ευαίσθητο περιεχόμενο του helper, την πρόσβαση στο `/dev/fuse`, την επιτυχή προσάρτηση με `allow_other` ή `allow_root` και το αν η προνομιούχα διεργασία μπορεί να εισέλθει στο mount. Μην εκτελείτε το προνομιούχο helper και μην προσαρτάτε filesystem κατά τη συνήθη απαρίθμηση. Δείτε την [περιγραφή πολιτικής του libfuse](https://github.com/libfuse/libfuse/blob/master/util/fuse.conf) και τις [συχνές ερωτήσεις του libfuse για την πρόσβαση](https://github.com/libfuse/libfuse/wiki/FAQ#why-dont-other-users-have-access-to-the-mounted-filesystem).

## Αναζητήστε race conditions σε διαδρομές

Το επικίνδυνο μοτίβο είναι ένα προνομιούχο πρόγραμμα να ελέγχει ένα pathname και αργότερα να ανοίγει το ίδιο pathname χωρίς να διατηρεί ασφαλή αναφορά στο ελεγμένο αντικείμενο. Ένας attacker που ελέγχει έναν γονικό κατάλογο μπορεί να αντικαταστήσει ένα αρχείο ή symlink ανάμεσα στις δύο ενέργειες. Το ίδιο πρόβλημα εμφανίζεται σε προσωρινά αρχεία, scripts που εκτελούνται βάσει χρονοδιακόπτη, εξαγωγή αρχείων και ροές εργασίας backup. Επιβεβαιώστε την πραγματική λειτουργία ανάγνωσης/εγγραφής και τα δικαιώματα του στόχου πριν ισχυριστείτε ότι υπάρχει αντίκτυπος.

Η **δημιουργία** archive μπορεί επίσης να αποκαλύψει αρχεία μεταξύ διαφορετικών ταυτοτήτων. Το Info-ZIP `zip -r` συνήθως ακολουθεί ένα symlink που βρίσκεται μέσα στο δέντρο προέλευσης και αποθηκεύει τα περιεχόμενα του στόχου· το `-y`/`--symlinks` αποθηκεύει αντί γι’ αυτά τον ίδιο τον σύνδεσμο. Αν ένας χρήστης με χαμηλότερα προνόμια μπορεί να προσθέσει έναν σύνδεσμο σε κατάλογο για τον οποίο δημιουργείται backup, ελέγξτε τον ακριβή archiver και τις επιλογές του, την ταυτότητα ανάγνωσης της εργασίας backup και αν το παραγόμενο archive είναι αναγνώσιμο από αυτόν τον χρήστη. Ένας εγγράψιμος κατάλογος προέλευσης ή ένα symlink από μόνο του δεν αποδεικνύει διαρροή. Εξετάστε τα μεταδεδομένα συνδέσμων και archive χωρίς να ενεργοποιήσετε το backup ή να εξαγάγετε ευαίσθητο περιεχόμενο κατά την απαρίθμηση. Δείτε την [τεκμηρίωση επιλογών του Info-ZIP](https://sources.debian.org/src/zip/3.0-3/man/zip.1/#L1638).

Το GNU `tar` έχει διαφορετική προεπιλεγμένη συμπεριφορά: συνήθως αποθηκεύει ένα symlink ως σύνδεσμο, ενώ το [`-h` / `--dereference` ακολουθεί τον σύνδεσμο κατά τη δημιουργία του archive](https://www.gnu.org/software/tar/manual/html_node/dereference.html). Για ένα προνομιούχο προγραμματισμένο backup, εξετάστε την ακριβή κλήση του `tar`, αν ένας χρήστης με χαμηλότερα προνόμια μπορεί να αντικαταστήσει ένα pathname εισόδου πριν το διαβάσει το `tar` και αν το παραγόμενο archive είναι προσβάσιμο σε αυτόν τον χρήστη. Ένα προσωρινό checksum ή άλλο sidecar σε εγγράψιμο κατάλογο staging μπορεί να γίνει τέτοια είσοδος, αν κατονομαστεί ρητά σε μεταγενέστερη εντολή `tar -h`. Πρέπει να επαληθευτούν το χρονικό παράθυρο του race condition, η ταυτότητα της εργασίας, η πολιτική symlink, η αναγνωσιμότητα του στόχου από αυτήν την ταυτότητα και το ACL του archive. Μην αντικαθιστάτε αρχεία, μην εκτελείτε την εργασία και μην αποσυσκευάζετε ευαίσθητα archives κατά τους παθητικούς ελέγχους.

Η **εξαγωγή** archive υπερβαίνει ένα διαφορετικό όριο, όταν μια προνομιούχα εργασία διαβάζει ένα archive που μπορεί να αντικαταστήσει χρήστης με χαμηλότερα προνόμια. [Το GNU tar συνήθως επαναφέρει την ιδιοκτησία των αρχειοθετημένων αρχείων όταν εκτελείται από τον superuser](https://www.gnu.org/software/tar/manual/html_node/Option-Summary.html), ενώ οι [επιλογές επαναφοράς δικαιωμάτων](https://www.gnu.org/software/tar/manual/html_node/Setting-Access-Permissions.html) επηρεάζουν τα mode bits των εξαγόμενων αρχείων. Εξετάστε τον ακριβή extractor και τις σημαίες του, το χρονικό παράθυρο αντικατάστασης του archive, τα μεταδεδομένα αριθμητικού owner και mode, τα δικαιώματα του καταλόγου εξαγωγής και το αν ο καθαρισμός αφήνει το αποτέλεσμα προσβάσιμο. Ένα μέλος SUID με owner root αποτελεί κίνδυνο μόνο αν το mode του διατηρηθεί κατά την εξαγωγή και η πολιτική του mount και της διεργασίας-στόχου επιτρέπει την αλλαγή ταυτότητας· ένα μη έμπιστο archive ή μια εγγράψιμη διαδρομή staging από μόνα τους δεν το αποδεικνύουν. Εξετάστε την εργασία και τα μεταδεδομένα χωρίς να αντικαταστήσετε ή να εξαγάγετε archive κατά την παθητική απαρίθμηση.

Ένα εξαγόμενο symlink μπορεί επίσης να αποκαλύψει ένα προστατευμένο αρχείο μέσω μεταγενέστερης προνομιούχας σύγκρισης. [Το GNU `diff` συνήθως ακολουθεί symlinks όταν συγκρίνει καταλόγους](https://www.gnu.org/software/diffutils/manual/html_node/Special-Files.html), επομένως ένα `diff -r` που εκτελείται ως root σε ένα μη έμπιστο δέντρο που έχει εξαχθεί μπορεί να διαβάσει τον στόχο ενός συνδέσμου και να συμπεριλάβει στο αποτέλεσμά του περιεχόμενο που διαφέρει. Επιβεβαιώστε ότι μπορεί να αντικατασταθεί το archive, ότι ο σύνδεσμος καταλήγει σε διαδρομή την οποία πράγματι εξετάζει η σύγκριση, ότι ο στόχος είναι αναγνώσιμος από την εργασία και ότι το αποτέλεσμα της σύγκρισης ή το error log είναι αναγνώσιμο από τον χρήστη με χαμηλότερα προνόμια. Ο σύνδεσμος ή το archive από μόνο του δεν αποδεικνύει διαρροή· εξετάστε την εργασία, τα μεταδεδομένα της διαδρομής και τα δικαιώματα του log, χωρίς να εκτελέσετε τη σύγκριση ή να διαβάσετε προστατευμένο περιεχόμενο κατά την απαρίθμηση.

Μια επαναλαμβανόμενη μεταφορά από το host μπορεί να μετατρέψει ένα μη έμπιστο μέλος archive σε μεταγενέστερη διαδρομή εξόδου. Αν μια εργασία με υψηλότερα προνόμια αντιγράφει ένα archive από container χαμηλότερης εμπιστοσύνης, εξάγει ένα symlink με όνομα ίδιο με το basename του προορισμού της επόμενης μεταφοράς και αργότερα γράφει στο ίδιο pathname, η μεταγενέστερη εγγραφή μπορεί να καταλήξει στον στόχο του συνδέσμου. Ελέγξτε το όνομα και τον στόχο του μέλους archive, τις επιλογές και τον κατάλογο εξαγωγής, αν ο extractor αφήνει πράγματι αυτόν τον σύνδεσμο στη θέση του, τον τρόπο με τον οποίο η υλοποίηση της μεταφοράς χειρίζεται έναν υπάρχοντα σύνδεσμο προορισμού και την αποτελεσματική ταυτότητα εγγραφής της εργασίας στο host. [Το GNU tar τεκμηριώνει τον τρόπο με τον οποίο η εξαγωγή χειρίζεται υπάρχοντα αρχεία και symlinks](https://www.gnu.org/software/tar/manual/html_section/extract-options.html)· [το OpenSSH scp χρησιμοποιεί από προεπιλογή SFTP στις σύγχρονες εκδόσεις](https://man.openbsd.org/scp.1), επομένως επαληθεύστε τη συμπεριφορά της εγκατεστημένης υλοποίησης μεταφοράς αντί να υποθέτετε ότι όλες οι εκδόσεις του `scp` γράφουν μέσω ενός συνδέσμου. Μια διεργασία `scp` ορατή στο container ή ένα εγγράψιμο archive από μόνο του δεν αποδεικνύει την εξαγωγή στο host και τη μεταγενέστερη εγγραφή. Εξετάστε την εργασία και τα μεταδεδομένα της διαδρομής χωρίς να μεταφέρετε ή να εξαγάγετε ειδικά διαμορφωμένο archive κατά την απαρίθμηση.

Το Ansible [`synchronize` module](https://docs.ansible.com/projects/ansible/latest/collections/ansible/posix/synchronize_module.html) χρησιμοποιεί το rsync· το `copy_links: true` αντιγράφει τον στόχο ενός symlink αντί για τον ίδιο τον σύνδεσμο. Για ένα προγραμματισμένο backup, ελέγξτε αν ένας χρήστης με χαμηλότερα προνόμια μπορεί να δημιουργήσει σύνδεσμο μέσα στο ακριβές δέντρο προέλευσης, αν η ταυτότητα συγχρονισμού μπορεί να διαβάσει τον στόχο του και αν το αντίγραφο ή archive που προκύπτει είναι αναγνώσιμο από αυτόν τον χρήστη. Το playbook, η θέση του συνδέσμου, η ταυτότητα run-as και τα δικαιώματα εξόδου πρέπει να συνάδουν όλα· ένας εγγράψιμος κατάλογος upload ή η ρύθμιση `copy_links` από μόνα τους είναι απλώς ένα στοιχείο προς διερεύνηση. Εξετάστε τα μεταδεδομένα και το playbook χωρίς να δημιουργήσετε συνδέσμους ή να ενεργοποιήσετε την εργασία.

## Εξετάστε ανοιχτούς file descriptors

```bash
ls -l /proc/<PID>/fd 2>/dev/null
lsof -p <PID> 2>/dev/null
lsof +L1 2>/dev/null
```

Μια διεργασία μπορεί να διατηρήσει πρόσβαση σε ένα αρχείο αφού αυτό διαγραφεί ή μετονομαστεί. Μια διεργασία με προνόμια μπορεί επίσης να μεταβιβάσει έναν descriptor μέσω Unix socket ή να τον αφήσει ακούσια ανοιχτό κατά το `execve()` αν λείπει η ρύθμιση close-on-exec. Ελέγξτε τους στόχους του `/proc/<PID>/fd` για ευαίσθητα αρχεία, διαγραμμένα αρχεία, διαδρομές του host που είναι ορατές μέσα σε ένα container και μη αναμενόμενα sockets. Η αποαναφορά των descriptors μιας άλλης διεργασίας υπόκειται στους ελέγχους πρόσβασης του kernel· ένας ορατός συμβολικός σύνδεσμος δεν εγγυάται ότι τα περιεχόμενά του είναι αναγνώσιμα.

Ένα προσαρμοσμένο SUID helper μπορεί να ανοίξει ένα προστατευμένο pathname, να απορρίψει το effective UID του και να αφήσει τον descriptor ανοιχτό. Αν στη συνέχεια καταστήσει τον εαυτό του dumpable, μπορεί να αλλάξουν η ιδιοκτησία και η πρόσβαση στο `/proc/<PID>/fd`· εξετάστε την ακριβή μετάβαση διαπιστευτηρίων, το [`PR_SET_DUMPABLE`](https://man7.org/linux/man-pages/man2/PR_SET_DUMPABLE.2const.html), την πολιτική procfs/ptrace και τα δικαιώματα του αρχείου-στόχου. Το εκ νέου άνοιγμα μιας διαδρομής descriptor μπορεί να παρακάμψει έναν μη προσβάσιμο **γονικό κατάλογο**, αλλά και πάλι να αποτύχει αν ο καλών δεν έχει δικαίωμα ανάγνωσης του αρχείου. Ένας ορατός στόχος descriptor ή το bit SUID από μόνο του δεν αποδεικνύει διαρροή δεδομένων.

Τα τεχνουργήματα από καταρρεύσεις αποτελούν ξεχωριστό στοιχείο προς διερεύνηση: ένα core dump μπορεί να περιέχει μνήμη διεργασίας, συμπεριλαμβανομένων δεδομένων που είχαν προηγουμένως διαβαστεί με υψηλότερη ταυτότητα. Στο Ubuntu, το [Apport συνήθως τοποθετεί τις αναφορές στο `/var/crash`](https://documentation.ubuntu.com/project/contributors/debugging/apport/)· άλλα συστήματα μπορεί να χρησιμοποιούν διαφορετικό χειριστή `core_pattern` ή αποθήκευση systemd. Κατά τη συνήθη καταγραφή, ελέγχετε μόνο τις διαδρομές των αναφορών, τον ιδιοκτήτη, τα δικαιώματα και την αναγνωσιμότητά τους. Μια αναγνώσιμη αναφορά έχει σημασία μόνο αν η σχετική διεργασία ήταν dumpable, ο χειριστής της κατάρρευσης διατήρησε τα ευαίσθητα bytes και ο τρέχων χρήστης έχει πρόσβαση σε αυτή την αναφορά. Μην προκαλείτε κατάρρευση σε helper και μην αποσυμπιέζετε dump στο πλαίσιο παθητικής καταγραφής. Δείτε το [`core(5)`](https://man7.org/linux/man-pages/man5/core.5.html) για τις συνθήκες SUID και δημιουργίας dump.

Όταν μια υπηρεσία χρησιμοποιεί κληρονομημένο descriptor, εξετάστε την αλυσίδα εκκίνησής της και τους αριθμούς των descriptors πριν δοκιμάσετε ανακατεύθυνση shell ή το `/proc/self/fd/<N>`. Αν ένα αρχείο έχει διαγραφεί αλλά παραμένει ανοιχτό, η [ανάκτηση διαγραμμένου αρχείου](filesystem-inodes-and-recovery.md#deleted-file-recovery-through-open-fds) μπορεί να διατηρήσει στοιχεία ή να ανακτήσει περιεχόμενο. Για διαλογή σε επίπεδο διεργασίας, συνεχίστε με την [καταγραφή διεργασιών και τις διαδρομές υπηρεσιών](../processes-crontab-systemd-dbus/process-enumeration-and-service-paths.md).
