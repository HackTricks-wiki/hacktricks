# Συμβολικοί σύνδεσμοι, hardlinks και περιγραφείς αρχείων

{{#include ../../banners/hacktricks-training.md}}

Μια διαδρομή ονομάζει ένα αντικείμενο τη στιγμή που επιλύεται· ένας ανοιχτός περιγραφέας αρχείου διατηρεί αναφορά στο αντικείμενο ακόμη κι όταν αλλάξει το όνομα διαδρομής. Αυτή η διαφορά εξηγεί τις συνθήκες ανταγωνισμού με symlink, τα κρυφά hardlinks, την ανάκτηση διαγραμμένων αρχείων και τις διαρροές κληρονομημένων περιγραφέων. Δείτε την ενότητα [filesystem, inodes and recovery](filesystem-inodes-and-recovery.md) για πληροφορίες σχετικά με τα inode και τα mounts.

## Επιθεώρηση συνδέσμων και ιδιοκτησίας διαδρομών

```bash
namei -l /path/to/privileged/input
stat -c '%D %i %h %U:%G %a %n' /path/to/file
readlink -f /path/to/link
find /path/to/tree -type l -ls 2>/dev/null
find /path/to/tree -type f -links +1 -ls 2>/dev/null
```

Ένα symlink ανακατευθύνει την επίλυση pathname· ένα hardlink είναι ένα άλλο όνομα για το ίδιο inode στο ίδιο filesystem. Αν μια προνομιούχα εργασία διαβάζει ή γράφει σε προβλέψιμο path μέσα σε κατάλογο εγγράψιμο από χρήστη, ο χρήστης ενδέχεται να μπορεί να ανακατευθύνει αυτό το path σε ευαίσθητο στόχο. Ελέγξτε την ιδιοκτησία και τα δικαιώματα σε κάθε γονικό κατάλογο, όχι μόνο στο τελικό αρχείο. Τα `fs.protected_symlinks` και `fs.protected_hardlinks` περιορίζουν συνηθισμένες επιθέσεις μεταξύ χρηστών, αλλά δεν καθιστούν ασφαλή οποιαδήποτε εγγράψιμα paths.

Για μια προνομιούχα εργασία που αλλάζει δικαιώματα με shell glob, διακρίνετε τους συνδέσμους που επεκτείνονται σε **ορίσματα γραμμής εντολών** από τους συνδέσμους που εντοπίζονται αργότερα κατά τη recursive traversal. Η [GNU `chmod` ενεργεί στον στόχο ενός symlink που αναφέρεται στη γραμμή εντολών](https://www.gnu.org/software/coreutils/manual/html_node/chmod-invocation.html), ενώ συνήθως αγνοεί symlinks που συναντά κατά την αναδρομή· το `-R` από μόνο του δεν καθιστά τις δύο περιπτώσεις ισοδύναμες. Εξετάστε την πραγματική ταυτότητα και εντολή της προγραμματισμένης εργασίας, αν ένας μη έμπιστος χρήστης μπορεί να δημιουργήσει μια καταχώριση που αντιστοιχεί στο glob, τη συμπεριφορά και τις επιλογές της εγκατεστημένης `chmod`, καθώς και τα δικαιώματα πρόσβασης που θα προκύψουν για τον προτεινόμενο στόχο. Ένας εγγράψιμος κατάλογος ή ένα symlink από μόνο του δεν αποδεικνύει προνομιούχα αλλαγή δικαιωμάτων. Εξετάστε το script και τα metadata του path χωρίς να τοποθετήσετε σύνδεσμο ή να ενεργοποιήσετε την εργασία κατά την παθητική αναγνώριση.

Μια προγραμματισμένη προνομιούχα διεργασία εγγραφής μπορεί να έχει προβλέψιμο path εξόδου, ακόμη κι όταν το όνομα αρχείου περιέχει ένα hash που μοιάζει τυχαίο: η [C `rand()` επαναλαμβάνει την ακολουθία της για το ίδιο seed του `srand()`](https://man7.org/linux/man-pages/man3/rand.3.html), συμπεριλαμβανομένου ενός seed που προκύπτει από γνωστή ώρα εκτέλεσης. Αν η εργασία διαβάζει επίσης γραμμές βάσης δεδομένων εγγράψιμες από τον καλούντα για να κατασκευάσει αυτό το όνομα, επαληθεύστε τον ακριβή αλγόριθμο μετατροπής γραμμής σε όνομα, το seed και τη συμπεριφορά της libc, το χρονοδιάγραμμα, τα δικαιώματα του καλούντα για εγγραφή σε γραμμές και δημιουργία καταλόγου, καθώς και αν μπορεί να τοποθετηθεί ένα προϋπάρχον symlink πριν από το προνομιούχο άνοιγμα. Το [`fopen(..., "w")` δημιουργεί ή περικόπτει το αρχείο που προκύπτει από την επίλυση του path](https://man7.org/linux/man-pages/man3/fopen.3.html)· ελέγξτε την πραγματική υλοποίηση για ασφαλή έναντι συνδέσμων flags ανοίγματος ή ατομική αντικατάσταση, την ταυτότητα που χρησιμοποιείται για την εγγραφή, τα δικαιώματα του στόχου και την πολιτική symlink για sticky directories. Ένα προβλέψιμο όνομα ή μια εγγράψιμη γραμμή από μόνα τους αποτελούν απλώς ένδειξη προς διερεύνηση. Εξετάστε τον κώδικα, το χρονοδιάγραμμα και τα metadata χωρίς να εισαγάγετε γραμμές ή να εκτελέσετε την εργασία κατά την παθητική αναγνώριση.

Για μια υπηρεσία μετατροπής αρχείων που εκτελείται ως άλλος χρήστης, εξετάστε αν ο καλών μπορεί να επιλέξει path ή επέκταση εξόδου και αν ο converter ακολουθεί ένα προϋπάρχον symlink εξόδου. Ορισμένοι converters επιλέγουν τη μορφή εξόδου από την επέκταση του pathname· ένας σύνδεσμος με αποδεκτή επέκταση μπορεί και πάλι να δείχνει σε ευαίσθητο στόχο χωρίς επέκταση. Για να είναι επιτυχής μια εγγραφή μεταξύ χρηστών, απαιτούνται υπηρεσία προσβάσιμη στον καλούντα, έλεγχος του path και του συνδέσμου από τον καλούντα, άνοιγμα του συνδέσμου για εγγραφή από τον converter και δικαίωμα εγγραφής για την ταυτότητα της υπηρεσίας. Το Linux `fs.protected_symlinks=1` περιορίζει την ακολούθηση συνδέσμου άλλου χρήστη μέσα σε **sticky κατάλογο εγγράψιμο από όλους**· δεν παρέχει την ίδια προστασία για σύνδεσμο σε έναν συνηθισμένο κατάλογο που ανήκει σε χρήστη. Εξετάστε το path που προκύπτει και την ιδιοκτησία των γονικών καταλόγων πριν καταλήξετε σε συμπέρασμα. Δείτε τη [συμπεριφορά του calibre για το αρχείο εξόδου](https://manual.calibre-ebook.com/generated/en/ebook-convert.html) και την [πολιτική symlink του Linux](https://www.kernel.org/doc/html/latest/admin-guide/sysctl/fs.html#protected-symlinks).

Ένα wrapper λήψης που επιτρέπεται μέσω sudo χρειάζεται τον ίδιο έλεγχο του path εξόδου, αν ανακτά δεδομένα που επιλέγει ο καλών ενώ διατηρεί έναν κατάλογο εργασίας ελεγχόμενο από τον καλούντα. Εξετάστε τον πραγματικό downloader και αν το επιλεγμένο basename, ο χειρισμός συγκρούσεων ή ένα προϋπάρχον symlink μπορεί να ανακατευθύνει μια προνομιούχα εγγραφή· η επιλογή URL ή ένα symlink από μόνα τους δεν αρκούν. Το [Axel τεκμηριώνει ένα `~/.axelrc` ανά χρήστη](https://github.com/axel-download-accelerator/axel/blob/master/doc/axel.txt), ενώ το [παράδειγμα διαμόρφωσής του περιλαμβάνει τα `default_filename` και `no_clobber`](https://github.com/axel-download-accelerator/axel/blob/master/doc/axelrc.example), επομένως ένα wrapper που χρησιμοποιεί Axel μπορεί επίσης να κληρονομήσει από αυτό το αρχείο μια επιλογή ονόματος εξόδου. Επιβεβαιώστε το ενεργό `HOME`: το [sudo μπορεί να το επαναφέρει ή να το διατηρήσει ανάλογα με την πολιτική](https://man7.org/linux/man-pages/man8/sudo.8.html), και το `.axelrc` ενός χρήστη έχει σημασία μόνο αν ο προνομιούχος downloader όντως το διαβάζει. Ελέγξτε τον κανόνα, το wrapper, το path και τα δικαιώματα του αρχείου διαμόρφωσης, το τελικό όνομα εξόδου και την κατάσταση του αρχείου-στόχου, χωρίς να ξεκινήσετε λήψη κατά την παθητική αναγνώριση.

Για ένα wrapper ACL που επιτρέπεται μέσω sudo, εξετάστε πώς επικυρώνει ένα αρχείο που επιλέγει ο καλών πριν καλέσει το `setfacl`. Ένας έλεγχος λεξικού προθέματος και η απόρριψη του `..` δεν εμποδίζουν ένα symlink μέσα στον επιτρεπόμενο κατάλογο να επιλύεται εκτός αυτού· και το `test -f` ακολουθεί επίσης τον σύνδεσμο. Επιβεβαιώστε ότι το wrapper φτάνει στην ενέργεια ACL με επαρκή προνόμια, ότι ο καλών ελέγχει τον σύνδεσμο και ότι η ACL που προκύπτει παρέχει την απαραίτητη πρόσβαση στον στόχο **και στους γονικούς καταλόγους του**. Ορισμένοι καταναλωτές απορρίπτουν αρχεία με εγγράψιμες ACL ή χαλαρά δικαιώματα, επομένως μια αλλαγή ACL από μόνη της δεν αποδεικνύει λειτουργική διαδρομή κλιμάκωσης προνομίων.

## Εξέταση προνομιούχων εγγραφών σε user-mounted FUSE filesystems

Μια ενεργή, αυτόνομη γραμμή `user_allow_other` στο `/etc/fuse.conf` επιτρέπει σε μη-root χρήστη να ζητήσει `allow_other` ή `allow_root` σε mount FUSE. Αυτές οι επιλογές mount μπορούν να επιτρέψουν σε διεργασία root να αποκτήσει πρόσβαση σε filesystem που υλοποιείται από τον χρήστη που το έκανε mount. Αν ένα βοηθητικό πρόγραμμα που επιτρέπεται μέσω sudo γράφει αρχείο καταγραφής που περιέχει μυστικά ή άλλη έξοδο σε path σχετικό με κατάλογο εργασίας ελεγχόμενο από τον καλούντα, εξετάστε αν αυτός ο κατάλογος μπορεί να είναι user-mounted filesystem FUSE. Η υλοποίηση FUSE μπορεί να παρατηρεί τις εγγραφές, ακόμη κι όταν το αρχείο που προκύπτει εμφανίζεται ως ιδιοκτησία root ή με mode `0600` σε ένα συνηθισμένο filesystem.

```bash
grep -n '^[[:space:]]*user_allow_other[[:space:]]*$' /etc/fuse.conf 2>/dev/null
sudo -l
```

Αυτό είναι **υποψήφιο εύρημα**, όχι απόδειξη διαρροής. Επιβεβαιώστε την πραγματική ταυτότητα sudo/run-as και τα ορίσματα, τη διαδρομή εξόδου του helper και το ευαίσθητο περιεχόμενο, την πρόσβαση στο `/dev/fuse`, την επιτυχή προσάρτηση με `allow_other` ή `allow_root`, καθώς και αν η προνομιούχα διεργασία μπορεί να εισέλθει στο mount. Μην εκτελείτε τον προνομιούχο helper και μην προσαρτάτε filesystem κατά τη συνήθη απαρίθμηση. Δείτε την [περιγραφή πολιτικής του libfuse](https://github.com/libfuse/libfuse/blob/master/util/fuse.conf) και τις [Συχνές ερωτήσεις του libfuse σχετικά με την πρόσβαση](https://github.com/libfuse/libfuse/wiki/FAQ#why-dont-other-users-have-access-to-the-mounted-filesystem).

## Αναζητήστε path races

Το επικίνδυνο μοτίβο είναι ένα προνομιούχο πρόγραμμα να ελέγχει ένα pathname και αργότερα να ανοίγει το ίδιο pathname χωρίς να διατηρεί ασφαλή αναφορά στο ελεγμένο αντικείμενο. Ένας attacker που ελέγχει έναν γονικό κατάλογο μπορεί να αντικαταστήσει ένα αρχείο ή symlink μεταξύ των δύο ενεργειών. Το ίδιο πρόβλημα εμφανίζεται σε προσωρινά αρχεία, scripts που εκτελούνται μέσω timer, εξαγωγή αρχείων και διαδικασίες backup. Επιβεβαιώστε την πραγματική λειτουργία ανάγνωσης/εγγραφής και τα δικαιώματα του στόχου πριν ισχυριστείτε ότι υπάρχει επίπτωση.

Η **δημιουργία** archive μπορεί επίσης να αποκαλύψει αρχεία μεταξύ διαφορετικών ταυτοτήτων. Το Info-ZIP `zip -r` συνήθως ακολουθεί ένα symlink που βρίσκεται μέσα στο δέντρο πηγής και αποθηκεύει τα περιεχόμενα του στόχου· αντίθετα, το `-y`/`--symlinks` αποθηκεύει το ίδιο το link. Αν ένας χρήστης με χαμηλότερα προνόμια μπορεί να προσθέσει ένα link σε κατάλογο που περιλαμβάνεται σε backup, ελέγξτε τον ακριβή archiver και τις επιλογές του, την ταυτότητα ανάγνωσης της εργασίας backup και αν ο χρήστης μπορεί να διαβάσει το παραγόμενο archive. Ένας εγγράψιμος κατάλογος πηγής ή ένα symlink από μόνο του δεν αποδεικνύει διαρροή. Εξετάστε τα metadata των link και archive χωρίς να ενεργοποιήσετε το backup ή να εξαγάγετε ευαίσθητο περιεχόμενο κατά την απαρίθμηση. Δείτε την [τεκμηρίωση επιλογών του Info-ZIP](https://sources.debian.org/src/zip/3.0-3/man/zip.1/#L1638).

Το GNU `tar` έχει διαφορετική προεπιλεγμένη συμπεριφορά: συνήθως αποθηκεύει ένα symlink ως link, ενώ το [`-h` / `--dereference` το ακολουθεί κατά τη δημιουργία του archive](https://www.gnu.org/software/tar/manual/html_node/dereference.html). Για ένα προνομιούχο προγραμματισμένο backup, εξετάστε την ακριβή κλήση του `tar`, αν ένας χρήστης με χαμηλότερα προνόμια μπορεί να αντικαταστήσει ένα pathname εισόδου πριν το διαβάσει το `tar`, και αν ο χρήστης αυτός μπορεί να έχει πρόσβαση στο archive που προκύπτει. Ένα προσωρινό checksum ή άλλο sidecar σε εγγράψιμο κατάλογο προετοιμασίας μπορεί να γίνει τέτοια είσοδος, όταν αναφέρεται ρητά σε μεταγενέστερη εντολή `tar -h`. Πρέπει να επαληθευτούν το παράθυρο race, η ταυτότητα της εργασίας, η πολιτική symlink, η αναγνωσιμότητα του στόχου από αυτή την ταυτότητα και τα ACL του archive. Μην αντικαθιστάτε αρχεία, μην εκτελείτε την εργασία και μην αποσυσκευάζετε ευαίσθητα archives κατά τους παθητικούς ελέγχους.

Η **εξαγωγή** archive διασχίζει διαφορετικό όριο, όταν μια προνομιούχα εργασία διαβάζει archive που μπορεί να αντικαταστήσει ένας χρήστης με χαμηλότερα προνόμια. Το [GNU tar συνήθως επαναφέρει την ιδιοκτησία που έχει αποθηκευτεί στο archive όταν εκτελείται από τον superuser](https://www.gnu.org/software/tar/manual/html_node/Option-Summary.html), ενώ οι [επιλογές επαναφοράς δικαιωμάτων](https://www.gnu.org/software/tar/manual/html_node/Setting-Access-Permissions.html) επηρεάζουν τα mode bits των εξαγόμενων αρχείων. Εξετάστε τον ακριβή extractor και τις επιλογές του, το χρονικό παράθυρο αντικατάστασης του archive, τα metadata αριθμητικού owner και mode, τα δικαιώματα του καταλόγου εξαγωγής και αν ο καθαρισμός αφήνει το αποτέλεσμα προσβάσιμο. Ένα μέλος SUID με ιδιοκτήτη root προκαλεί ανησυχία μόνο αν το mode του διατηρηθεί κατά την εξαγωγή και η πολιτική του mount και της διεργασίας επιτρέπει την αλλαγή ταυτότητας· ένα μη έμπιστο archive ή μια εγγράψιμη διαδρομή προετοιμασίας από μόνα τους δεν το αποδεικνύουν. Εξετάστε την εργασία και τα metadata χωρίς να αντικαταστήσετε ή να εξαγάγετε archive κατά την παθητική απαρίθμηση.

Ένα εξαγμένο symlink μπορεί επίσης να αποκαλύψει ένα προστατευμένο αρχείο μέσω μεταγενέστερης προνομιούχας σύγκρισης. Το [GNU `diff` συνήθως ακολουθεί τα symlink κατά τη σύγκριση καταλόγων](https://www.gnu.org/software/diffutils/manual/html_node/Special-Files.html), επομένως ένα `diff -r` που εκτελείται ως root πάνω σε μη έμπιστο δέντρο εξαγωγής μπορεί να διαβάσει τον στόχο του link και να συμπεριλάβει διαφορετικό περιεχόμενο στην έξοδό του. Επιβεβαιώστε ότι μπορεί να αντικατασταθεί το archive, ότι το link οδηγεί σε διαδρομή την οποία επισκέπτεται πράγματι η σύγκριση, ότι ο στόχος είναι αναγνώσιμος από την εργασία και ότι ο χρήστης με χαμηλότερα προνόμια μπορεί να διαβάσει την έξοδο της σύγκρισης ή το αρχείο καταγραφής σφαλμάτων. Το link ή το archive από μόνο του δεν αποδεικνύει διαρροή· εξετάστε την εργασία, τα metadata της διαδρομής και τα δικαιώματα των logs χωρίς να εκτελέσετε τη σύγκριση ή να διαβάσετε προστατευμένο περιεχόμενο κατά την απαρίθμηση.

Μια επαναλαμβανόμενη μεταφορά από την πλευρά του host μπορεί να μετατρέψει ένα μη έμπιστο μέλος archive σε μεταγενέστερη διαδρομή εξόδου. Αν μια εργασία με υψηλότερα προνόμια αντιγράφει archive από container χαμηλότερης εμπιστοσύνης, εξάγει ένα symlink με όνομα που ταιριάζει στο basename του προορισμού της επόμενης μεταφοράς και αργότερα γράφει στο ίδιο pathname, η μεταγενέστερη εγγραφή μπορεί να καταλήξει στον στόχο του link. Ελέγξτε το όνομα και τον στόχο του μέλους archive, τις επιλογές εξαγωγής και τον κατάλογο, αν ο extractor αφήνει πράγματι το link στη θέση του, τον τρόπο με τον οποίο η υλοποίηση μεταφοράς χειρίζεται ένα υπάρχον link προορισμού και την αποτελεσματική ταυτότητα εγγραφής της εργασίας του host. Το [GNU tar τεκμηριώνει τον χειρισμό υπαρχόντων αρχείων και symlink κατά την εξαγωγή](https://www.gnu.org/software/tar/manual/html_section/extract-options.html)· το [OpenSSH scp χρησιμοποιεί SFTP ως προεπιλογή στις σύγχρονες εκδόσεις](https://man.openbsd.org/scp.1), επομένως επαληθεύστε τη συμπεριφορά της εγκατεστημένης μεταφοράς αντί να υποθέτετε ότι όλες οι εκδόσεις του `scp` γράφουν μέσω ενός link. Μια διεργασία `scp` ορατή μέσα σε container ή ένα εγγράψιμο archive από μόνα τους δεν αποδεικνύουν την εξαγωγή από τον host και τη μεταγενέστερη εγγραφή. Εξετάστε την εργασία και τα metadata της διαδρομής χωρίς να μεταφέρετε ή να εξαγάγετε κατασκευασμένο archive κατά την απαρίθμηση.

Το [`synchronize` module του Ansible](https://docs.ansible.com/projects/ansible/latest/collections/ansible/posix/synchronize_module.html) χρησιμοποιεί rsync· το `copy_links: true` αντιγράφει τον στόχο ενός symlink αντί για το link. Για ένα προγραμματισμένο backup, ελέγξτε αν ένας χρήστης με χαμηλότερα προνόμια μπορεί να δημιουργήσει link μέσα στο ακριβές δέντρο πηγής, αν η ταυτότητα συγχρονισμού μπορεί να διαβάσει τον στόχο του και αν ο χρήστης αυτός μπορεί να διαβάσει το αντίγραφο ή το archive που προκύπτει. Το playbook, η θέση του link, η ταυτότητα run-as και τα δικαιώματα εξόδου πρέπει να συντρέχουν· ένας εγγράψιμος κατάλογος μεταφόρτωσης ή η ρύθμιση `copy_links` από μόνη της αποτελεί μόνο ένδειξη προς διερεύνηση. Εξετάστε τα metadata και το playbook χωρίς να δημιουργήσετε links ή να ενεργοποιήσετε την εργασία.

## Εξετάστε τους ανοιχτούς descriptors

```bash
ls -l /proc/<PID>/fd 2>/dev/null
lsof -p <PID> 2>/dev/null
lsof +L1 2>/dev/null
```

Μια διεργασία μπορεί να διατηρήσει πρόσβαση σε ένα αρχείο αφού αυτό διαγραφεί ή μετονομαστεί. Μια διεργασία με αυξημένα δικαιώματα μπορεί επίσης να μεταβιβάσει έναν descriptor μέσω ενός Unix socket ή να τον αφήσει ακούσια ανοιχτό κατά το `execve()` αν δεν έχει οριστεί το close-on-exec. Ελέγξτε τους στόχους στο `/proc/<PID>/fd` για ευαίσθητα αρχεία, διαγραμμένα αρχεία, διαδρομές του host που είναι ορατές μέσα σε ένα container και μη αναμενόμενα sockets. Η αποαναφορά στους descriptors μιας άλλης διεργασίας υπόκειται στους ελέγχους πρόσβασης του kernel· ένας ορατός συμβολικός σύνδεσμος δεν εγγυάται ότι τα περιεχόμενά του είναι αναγνώσιμα.

Ένα προσαρμοσμένο SUID helper μπορεί να ανοίξει ένα προστατευμένο pathname, να απορρίψει το effective UID του και να αφήσει τον descriptor ανοιχτό. Αν στη συνέχεια ορίσει τον εαυτό του ως dumpable, η ιδιοκτησία και η πρόσβαση στο `/proc/<PID>/fd` μπορεί να αλλάξουν· εξετάστε την ακριβή μετάβαση διαπιστευτηρίων, το [`PR_SET_DUMPABLE`](https://man7.org/linux/man-pages/man2/PR_SET_DUMPABLE.2const.html), την πολιτική procfs/ptrace και τα δικαιώματα του αρχείου-στόχου. Το ξανάνοιγμα μιας διαδρομής descriptor μπορεί να παρακάμψει έναν μη προσβάσιμο **γονικό κατάλογο**, αλλά και πάλι να αποτύχει αν ο καλών δεν έχει δικαίωμα ανάγνωσης του αρχείου. Ένας ορατός στόχος descriptor ή το SUID bit από μόνο του δεν αποδεικνύει ότι υπάρχει διαρροή δεδομένων.

Τα τεχνουργήματα από crash αποτελούν ξεχωριστό στοιχείο διερεύνησης: ένα core dump μπορεί να περιέχει μνήμη διεργασίας, συμπεριλαμβανομένων δεδομένων που είχαν προηγουμένως αναγνωστεί με υψηλότερη ταυτότητα. Στο Ubuntu, το [Apport αποθηκεύει συνήθως τις αναφορές στο `/var/crash`](https://documentation.ubuntu.com/project/contributors/debugging/apport/)· άλλα συστήματα μπορεί να χρησιμοποιούν διαφορετικό χειριστή `core_pattern` ή αποθήκευση μέσω systemd. Κατά τη συνήθη απαρίθμηση, ελέγχετε μόνο τις διαδρομές των αναφορών, τον ιδιοκτήτη, τα δικαιώματα και την αναγνωσιμότητά τους. Μια αναγνώσιμη αναφορά έχει σημασία μόνο αν η σχετική διεργασία ήταν dumpable, ο χειριστής του crash διατήρησε τα ευαίσθητα bytes και ο τρέχων χρήστης έχει πρόσβαση σε αυτήν την αναφορά. Μην προκαλείτε crash σε helper και μην αποσυσκευάζετε dump στο πλαίσιο παθητικής απαρίθμησης. Δείτε το [`core(5)`](https://man7.org/linux/man-pages/man5/core.5.html) για τις προϋποθέσεις SUID και δημιουργίας dump.

Όταν μια υπηρεσία χρησιμοποιεί κληρονομημένο descriptor, εξετάστε την αλυσίδα εκκίνησής της και τους αριθμούς των descriptors πριν δοκιμάσετε ανακατεύθυνση shell ή το `/proc/self/fd/<N>`. Αν ένα αρχείο έχει διαγραφεί αλλά παραμένει ανοιχτό, η [ανάκτηση διαγραμμένων αρχείων](filesystem-inodes-and-recovery.md#deleted-file-recovery-through-open-fds) μπορεί να διατηρήσει στοιχεία ή να ανακτήσει περιεχόμενο. Για διαλογή σε επίπεδο διεργασίας, συνεχίστε με την [απαρίθμηση διεργασιών και τις διαδρομές υπηρεσιών](../processes-crontab-systemd-dbus/process-enumeration-and-service-paths.md).
