# Χρήστες, συνεδρίες και τεκμήρια διαπιστευτηρίων

{{#include ../../banners/hacktricks-training.md}}

Ξεκινήστε από την ταυτότητα στην οποία ανήκει το τρέχον shell και, στη συνέχεια, απαριθμήστε τους υπόλοιπους χρήστες, τις ομάδες, τις ενεργές συνεδρίες και τα αποθετήρια διαπιστευτηρίων. Η σελίδα [πραγματικό, ενεργό και αποθηκευμένο αναγνωριστικό χρήστη](euid-ruid-suid.md) εξηγεί γιατί τα ενεργά δικαιώματα μιας διεργασίας μπορεί να διαφέρουν από τον λογαριασμό σύνδεσής της.

## Απαρίθμηση ταυτοτήτων και πρόσβασης βάσει ομάδων

```bash
id
getent passwd
getent group
whoami
stat -c '%A %U:%G %n' /etc/passwd /etc/shadow /etc/group
```

Το `getent` περιλαμβάνει λογαριασμούς που προέρχονται από καταλόγους και μπορεί να μην εμφανίζονται με απλή ανάγνωση του `/etc/passwd`. Ελέγξτε τους λογαριασμούς UID 0, τα κελύφη σύνδεσης, τους προσωπικούς καταλόγους, τις συμπληρωματικές ομάδες και τους λογαριασμούς των οποίων οι ρυθμίσεις επιτρέπουν απροσδόκητα διαδραστική σύνδεση. Η σελίδα [interesting groups](interesting-groups-linux-pe/README.md) καλύπτει εκχωρημένη πρόσβαση, όπως `sudo`, `docker`, `disk` και `shadow`. Ελέγξτε τα πραγματικά ACL του συστήματος αρχείων και την τοπική πολιτική προτού θεωρήσετε ένα όνομα ομάδας προνόμιο.

Αν το [NSS αντιστοιχίζει αναζητήσεις `passwd`, `group` ή `shadow`](https://man7.org/linux/man-pages/man5/nsswitch.conf.5.html) σε βάση δεδομένων, ελέγξτε τον ενεργό πάροχο και τη διαδρομή ρυθμίσεών του προτού αξιολογήσετε ταυτότητες που βασίζονται σε βάση δεδομένων. Για εγκαταστάσεις PostgreSQL NSS, τα `/etc/nss-pgsql.conf` και `/etc/nss-pgsql-root.conf` είναι ενδείξεις μόνο ως προς τις διαδρομές, επειδή οι ρυθμίσεις σύνδεσης μπορεί να περιέχουν διαπιστευτήρια. Ένας ρόλος βάσης δεδομένων έχει σημασία μόνο αν μπορεί να αλλάξει εγγραφές που επιστρέφει πράγματι ο ενεργός πάροχος NSS και αν ένας λογαριασμός μπορεί να πιστοποιηθεί χρησιμοποιώντας αυτές. Ένα κύριο GID ίσο με 0 παρέχει συμμετοχή στην ομάδα root, όχι UID 0· η αντιστοίχιση σε ομάδα sudo απαιτεί έναν ενεργό [κανόνα ομάδας sudoers](https://man7.org/linux/man-pages/man5/sudoers.5.html) και οποιαδήποτε απαιτούμενη πιστοποίηση. Η αντιστοίχιση UID 0 αποτελεί διαφορετικό όριο ταυτότητας. Μην εμφανίζετε συμβολοσειρές σύνδεσης και μην αλλάζετε εγγραφές λογαριασμών κατά την παθητική enumeration.

Επίσης, συγκρίνετε τα αριθμητικά UID μεταξύ των τοπικών ονομάτων λογαριασμών. Δύο ονόματα στο [`/etc/passwd`](https://man7.org/linux/man-pages/man5/passwd.5.html) μπορεί να αναφέρονται στην ίδια ταυτότητα αρχείου Unix, ενώ οι εγγραφές πιστοποίησης σύνδεσής τους μπορεί να διαφέρουν. Επομένως, ένα alias που προστέθηκε πρόσφατα και μοιράζεται μη μηδενικό UID μπορεί να οδηγήσει στα αρχεία ή τις διεργασίες άλλου χρήστη μετά από επιτυχή πιστοποίηση· δεν παρέχει root, εκτός αν αυτό το UID ή μια ξεχωριστή διαδρομή προνομίων το επιτρέπει. Τα κοινόχρηστα UID μπορεί να είναι σκόπιμα. Επαληθεύστε την πηγή του λογαριασμού (`/etc/passwd` έναντι NSS), το ιστορικό δημιουργίας, το κέλυφος και τον προσωπικό κατάλογο, την πραγματική πολιτική πιστοποίησης και αν οι λογαριασμοί έχουν εξουσιοδοτηθεί να μοιράζονται την ταυτότητα. Ένας έλεγχος μόνο για τοπικούς λογαριασμούς δεν μπορεί να αποκλείσει ένα alias που προέρχεται από κατάλογο.

## Εύρεση ενεργών και πρόσφατων συνεδριών

```bash
who -a
w
last -a | head
loginctl list-sessions 2>/dev/null
ps -eo user,pid,ppid,tty,cmd --sort=user | head -80
screen -ls 2>/dev/null
tmux ls 2>/dev/null
```

Ένα socket `screen` ή `tmux` μπορεί να εκθέσει ένα υπάρχον shell, αν τα δικαιώματά του επιτρέπουν στον τρέχοντα χρήστη να συνδεθεί σε αυτό. Ελέγξτε τον ιδιοκτήτη και τα δικαιώματα του socket πριν επιχειρήσετε πρόσβαση· η συνεδρία άλλου χρήστη δεν είναι αυτομάτως προσβάσιμη. Μπορεί επίσης να έχει σημασία ένα ενεργό χρονικό αποτύπωμα sudo ή ένα socket SSH agent, αλλά η επαναχρησιμοποίησή τους εξαρτάται από την ταυτότητα του χρήστη, τα δικαιώματα και την πολιτική. Για κατάχρηση προώθησης agent, δείτε το [SSH forwarding agent exploitation](ssh-forward-agent-exploitation.md).

Ένα [OpenSSH multiplex control socket](https://man.openbsd.org/ssh_config#ControlMaster) είναι διαφορετικό από το `SSH_AUTH_SOCK`: τα `ControlMaster` και `ControlPath` επιτρέπουν σε μεταγενέστερους SSH clients να χρησιμοποιούν από κοινού μια ήδη πιστοποιημένη σύνδεση, ενώ το `ControlPersist` μπορεί να διατηρήσει διαθέσιμο τον master μετά τη λήξη της πρώτης συνεδρίας. Ελέγξτε το `.ssh/config` του τρέχοντος χρήστη και τα socket paths σε μικρό βάθος μέσα στο `.ssh`, συμπεριλαμβανομένων του ιδιοκτήτη και των δικαιωμάτων. Το όνομα ενός socket από μόνο του δεν αποδεικνύει ότι ο master είναι ενεργός, ότι ο τρέχων χρήστης μπορεί να συνδεθεί ή ποιον απομακρυσμένο λογαριασμό χρησιμοποιεί.

## Εξέταση τεχνουργημάτων χρήστη

```bash
find /home -maxdepth 3 -type f \( -name 'authorized_keys' -o -name 'id_*' -o -name '*history' -o -name '.netrc' -o -name '.git-credentials' \) -ls 2>/dev/null
find /home -maxdepth 3 -type f \( -name '.bashrc' -o -name '.profile' -o -name '.zshrc' \) -ls 2>/dev/null
printenv SSH_AUTH_SOCK KRB5CCNAME GNUPGHOME 2>/dev/null
```

Το ιστορικό του shell, τα αρχεία εκκίνησης, τα κλειδιά SSH, οι ρυθμίσεις εφαρμογών, τα keyring του GPG και οι cache του Kerberos μπορεί να αποκαλύψουν διαπιστευτήρια ή εγγράψιμα σημεία persistence. Ένα εγγράψιμο `authorized_keys` ή αρχείο εκκίνησης shell για λογαριασμό με περισσότερα προνόμια αξίζει να εξεταστεί. Η [σελίδα post-exploitation](../post-exploitation/README.md) καλύπτει τη μετεγκατάσταση του GPG homedir και την αναζήτηση διαπιστευτηρίων· η [ενότητα Linux Active Directory](linux-active-directory.md) καλύπτει την επαναχρησιμοποίηση cache και keytab του Kerberos. Η [σελίδα PAM](../software-information/pam-pluggable-authentication-modules.md) εξηγεί τους κινδύνους των πολιτικών ελέγχου ταυτότητας.
