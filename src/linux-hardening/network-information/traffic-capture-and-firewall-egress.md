# Traffic Capture, Firewall, and Egress Triage

{{#include ../../banners/hacktricks-training.md}}

After locating [local listeners and Unix sockets](local-network-and-socket-triage.md), inspect which interfaces carry their traffic and which firewall or proxy rules affect reachability. A loopback-only service may carry sensitive HTTP headers even when it is not reachable from another host.

## Check capture permissions and choose an interface

```bash
ip -br addr
ip route
getcap "$(command -v dumpcap)" 2>/dev/null
tcpdump -D 2>/dev/null
```

`dumpcap` may have packet-capture capabilities even when the current user has no sudo access. Check the executable's actual capabilities and group permissions. Capture the smallest useful interface, duration, and filter; a capture can contain credentials or personal data.

```bash
sudo tcpdump -i lo -s 0 -w /tmp/loopback.pcap 'tcp port 8080'
tshark -r /tmp/loopback.pcap -Y 'http.request' -T fields -e ip.src -e http.host -e http.request.uri
tcpflow -r /tmp/loopback.pcap 2>/dev/null
```

`tcpflow` reconstructs plaintext TCP streams; `tshark` can filter and extract fields from a capture. For TLS traffic, decryption requires endpoint keys or a supported client configured for `SSLKEYLOGFILE` before the connection. The [local network triage page](local-network-and-socket-triage.md#tls-key-logging) shows that workflow. Do not treat an encrypted capture as readable plaintext.

## Identify firewall layers

```bash
sudo nft list ruleset 2>/dev/null
sudo iptables-save 2>/dev/null
sudo ufw status verbose 2>/dev/null
sudo firewall-cmd --list-all 2>/dev/null
```

`nftables` and `iptables` may be exposed through distribution wrappers such as UFW or firewalld. Read the active rules and the wrapper's persisted configuration; a rule visible in one representation may have been generated by another tool. Inspect interface, direction, source, destination, protocol, port, and connection state before attributing a blocked service to a particular rule. See [nftables rule review](local-network-and-socket-triage.md#nftables-review-and-authorized-rule-changes) for a focused example.

## Test egress and proxy behavior

```bash
ip route get 1.1.1.1
getent hosts example.com
curl -I --connect-timeout 3 https://example.com/
printenv http_proxy https_proxy all_proxy no_proxy 2>/dev/null
```

Separate DNS failure from TCP, TLS, or proxy failure. Test the specific destination and protocol relevant to the assessment; ICMP reachability does not imply that TCP or UDP is permitted. If a proxy is configured, compare the intended proxied request with the same target under the applicable `no_proxy` rules. A local port forward can also make a loopback service available elsewhere, so review active listeners and SSH tunnels when the firewall view and observed exposure disagree.
