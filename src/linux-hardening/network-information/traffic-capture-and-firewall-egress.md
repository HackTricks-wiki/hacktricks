# Διαλογή καταγραφής κίνησης, firewall και εξερχόμενης κίνησης

{{#include ../../banners/hacktricks-training.md}}

Αφού εντοπίσετε [τοπικούς listeners και Unix sockets](local-network-and-socket-triage.md), ελέγξτε ποιες διεπαφές μεταφέρουν την κίνησή τους και ποιοι κανόνες firewall ή proxy επηρεάζουν την προσβασιμότητα. Μια υπηρεσία που είναι προσβάσιμη μόνο μέσω loopback μπορεί να μεταφέρει ευαίσθητες κεφαλίδες HTTP, ακόμη κι αν δεν είναι προσβάσιμη από άλλον host.

## Έλεγχος δικαιωμάτων καταγραφής και επιλογή διεπαφής

```bash
ip -br addr
ip route
getcap "$(command -v dumpcap)" 2>/dev/null
tcpdump -D 2>/dev/null
```

Το `dumpcap` μπορεί να έχει δυνατότητες καταγραφής πακέτων ακόμη κι όταν ο τρέχων χρήστης δεν έχει πρόσβαση sudo. Ελέγξτε τις πραγματικές δυνατότητες του εκτελέσιμου και τα δικαιώματα της ομάδας. Καταγράψτε μόνο την απολύτως απαραίτητη διεπαφή, διάρκεια και φίλτρο· η καταγραφή μπορεί να περιέχει διαπιστευτήρια ή προσωπικά δεδομένα.

```bash
sudo tcpdump -i lo -s 0 -w /tmp/loopback.pcap 'tcp port 8080'
tshark -r /tmp/loopback.pcap -Y 'http.request' -T fields -e ip.src -e http.host -e http.request.uri
tcpflow -r /tmp/loopback.pcap 2>/dev/null
```

`tcpflow` ανασυνθέτει plaintext TCP streams· το `tshark` μπορεί να φιλτράρει και να εξάγει πεδία από ένα capture. Για TLS traffic, η αποκρυπτογράφηση απαιτεί κλειδιά endpoint ή έναν υποστηριζόμενο client ρυθμισμένο για `SSLKEYLOGFILE` πριν από τη σύνδεση. Η [σελίδα διαλογής τοπικού δικτύου](local-network-and-socket-triage.md#tls-key-logging) παρουσιάζει αυτή τη διαδικασία. Μην θεωρείτε ότι ένα κρυπτογραφημένο capture περιέχει αναγνώσιμο plaintext.

Τα αποθηκευμένα τεχνουργήματα περιστατικού ενδέχεται να αλλάξουν αυτή την εκτίμηση. Ένα [Linux core dump είναι εικόνα της μνήμης μιας διεργασίας](https://man7.org/linux/man-pages/man5/core.5.html), η οποία ενδέχεται να διατηρεί ένα session key· αν ένα αναγνώσιμο dump και ένα packet capture προήλθαν από την ίδια διεργασία και συνεδρία, ένας αναλυτής ενδέχεται να μπορέσει να αποκρυπτογραφήσει αυτή την κίνηση. Καταγράψτε πρώτα τις διαδρομές και τα δικαιώματα πρόσβασης των τεχνουργημάτων και, στη συνέχεια, επαληθεύστε ξεχωριστά την ταυτότητα της διεργασίας, την ώρα της καταγραφής, το πρωτόκολλο και τη μορφή του κλειδιού. Η αποκρυπτογραφημένη κίνηση ή ένα ανακτημένο αρχείο αρχειοθήκης αποτελεί ένδειξη πιθανής αποκάλυψης, όχι απόδειξη πρόσβασης σε λογαριασμό άλλου χρήστη: τυχόν μερικό υλικό SSH key πρέπει ακόμη να ανασυντεθεί, να αντιστοιχιστεί με το αντίστοιχο public key και να γίνει αποδεκτό από την πολιτική SSH του συγκεκριμένου λογαριασμού. Αποφύγετε την εμφάνιση περιεχομένων core dump ή payloads capture σε αποτελέσματα ευρείας απαρίθμησης.

## Identify firewall layers

```bash
sudo nft list ruleset 2>/dev/null
sudo iptables-save 2>/dev/null
sudo ufw status verbose 2>/dev/null
sudo firewall-cmd --list-all 2>/dev/null
```

Τα `nftables` και `iptables` μπορεί να είναι προσβάσιμα μέσω wrappers της διανομής, όπως το UFW ή το firewalld. Διαβάστε τους ενεργούς κανόνες και την αποθηκευμένη ρύθμιση του wrapper· ένας κανόνας που εμφανίζεται σε μία αναπαράσταση μπορεί να έχει δημιουργηθεί από άλλο εργαλείο. Ελέγξτε τη διεπαφή, την κατεύθυνση, την πηγή, τον προορισμό, το πρωτόκολλο, τη θύρα και την κατάσταση σύνδεσης πριν αποδώσετε τον αποκλεισμό μιας υπηρεσίας σε συγκεκριμένο κανόνα. Δείτε την [επισκόπηση κανόνων nftables](local-network-and-socket-triage.md#nftables-review-and-authorized-rule-changes) για ένα συγκεκριμένο παράδειγμα.

## Δοκιμή της εξερχόμενης κίνησης και της συμπεριφοράς του proxy

```bash
ip route get 1.1.1.1
getent hosts example.com
curl -I --connect-timeout 3 https://example.com/
printenv http_proxy https_proxy all_proxy no_proxy 2>/dev/null
```

Διαχωρίστε την αποτυχία DNS από την αποτυχία TCP, TLS ή proxy. Δοκιμάστε τον συγκεκριμένο προορισμό και το πρωτόκολλο που σχετίζονται με την αξιολόγηση· η προσβασιμότητα μέσω ICMP δεν σημαίνει ότι επιτρέπεται το TCP ή το UDP. Αν έχει ρυθμιστεί proxy, συγκρίνετε το προβλεπόμενο proxied request με το ίδιο target υπό τους ισχύοντες κανόνες `no_proxy`. Μια τοπική προώθηση θύρας μπορεί επίσης να κάνει μια υπηρεσία loopback διαθέσιμη αλλού, οπότε ελέγξτε τους ενεργούς listeners και τα SSH tunnels όταν η εικόνα του firewall και η παρατηρούμενη έκθεση διαφωνούν.
