# Διαλογή καταγραφής κίνησης, firewall και εξερχόμενης κίνησης

{{#include ../../banners/hacktricks-training.md}}

Αφού εντοπίσετε [τοπικούς listeners και Unix sockets](local-network-and-socket-triage.md), ελέγξτε ποιες διεπαφές μεταφέρουν την κίνησή τους και ποιοι κανόνες firewall ή proxy επηρεάζουν την προσβασιμότητα. Μια υπηρεσία που είναι προσβάσιμη μόνο μέσω loopback μπορεί να μεταφέρει ευαίσθητες HTTP headers, ακόμη κι αν δεν είναι προσβάσιμη από άλλον host.

## Ελέγξτε τα δικαιώματα καταγραφής και επιλέξτε διεπαφή

```bash
ip -br addr
ip route
getcap "$(command -v dumpcap)" 2>/dev/null
tcpdump -D 2>/dev/null
```

Το `dumpcap` μπορεί να έχει δυνατότητες καταγραφής πακέτων, ακόμη κι αν ο τρέχων χρήστης δεν έχει πρόσβαση μέσω sudo. Ελέγξτε τις πραγματικές δυνατότητες του εκτελέσιμου αρχείου και τα δικαιώματα της ομάδας. Καταγράψτε μόνο το απολύτως απαραίτητο περιβάλλον δικτύου, τη διάρκεια και το φίλτρο· η καταγραφή μπορεί να περιέχει διαπιστευτήρια ή προσωπικά δεδομένα.

```bash
sudo tcpdump -i lo -s 0 -w /tmp/loopback.pcap 'tcp port 8080'
tshark -r /tmp/loopback.pcap -Y 'http.request' -T fields -e ip.src -e http.host -e http.request.uri
tcpflow -r /tmp/loopback.pcap 2>/dev/null
```

Το `tcpflow` ανασυνθέτει ροές TCP σε plaintext· το `tshark` μπορεί να φιλτράρει και να εξάγει πεδία από μια καταγραφή. Για την αποκρυπτογράφηση κίνησης TLS απαιτούνται κλειδιά endpoint ή ένας υποστηριζόμενος client ρυθμισμένος με `SSLKEYLOGFILE` πριν από τη σύνδεση. Η [σελίδα διαλογής τοπικού δικτύου και socket](local-network-and-socket-triage.md#tls-key-logging) παρουσιάζει αυτή τη διαδικασία. Μην θεωρείτε ότι μια κρυπτογραφημένη καταγραφή είναι αναγνώσιμο plaintext.

Τα αποθηκευμένα τεχνουργήματα περιστατικών μπορούν να αλλάξουν αυτή την εκτίμηση. Ένα [Linux core dump είναι εικόνα της μνήμης μιας διεργασίας](https://man7.org/linux/man-pages/man5/core.5.html), η οποία μπορεί να διατηρεί ένα κλειδί συνεδρίας· αν ένα αναγνώσιμο dump και μια καταγραφή πακέτων προήλθαν από την ίδια διεργασία και συνεδρία, ένας αναλυτής ενδέχεται να μπορέσει να αποκρυπτογραφήσει αυτή την κίνηση. Καταγράψτε πρώτα τις διαδρομές και τα δικαιώματα πρόσβασης των τεχνουργημάτων και, στη συνέχεια, επαληθεύστε ξεχωριστά την ταυτότητα της διεργασίας, τον χρόνο καταγραφής, το πρωτόκολλο και τη μορφή του κλειδιού. Η αποκρυπτογραφημένη κίνηση ή ένα αρχείο αρχειοθέτησης που ανακτήθηκε αποτελούν ένδειξη πιθανής αποκάλυψης, όχι απόδειξη πρόσβασης σε λογαριασμό άλλου χρήστη: τυχόν μερικό υλικό κλειδιού SSH πρέπει πρώτα να ανασυντεθεί, να αντιστοιχιστεί με το αντίστοιχο δημόσιο κλειδί και να γίνει αποδεκτό από την πολιτική SSH αυτού του λογαριασμού. Αποφύγετε την εμφάνιση περιεχομένων core dump ή payload καταγραφών σε έξοδο ευρείας απαρίθμησης.

## Εντοπισμός επιπέδων firewall

```bash
sudo nft list ruleset 2>/dev/null
sudo iptables-save 2>/dev/null
sudo ufw status verbose 2>/dev/null
sudo firewall-cmd --list-all 2>/dev/null
```

`nftables` και `iptables` μπορεί να είναι προσβάσιμα μέσω wrappers της διανομής, όπως το UFW ή το firewalld. Διαβάστε τους ενεργούς κανόνες και την αποθηκευμένη ρύθμιση του wrapper· ένας κανόνας που εμφανίζεται σε μία αναπαράσταση μπορεί να έχει δημιουργηθεί από άλλο εργαλείο. Ελέγξτε τη διεπαφή, την κατεύθυνση, την προέλευση, τον προορισμό, το πρωτόκολλο, τη θύρα και την κατάσταση σύνδεσης πριν αποδώσετε τον αποκλεισμό μιας υπηρεσίας σε συγκεκριμένο κανόνα. Δείτε το [nftables rule review](local-network-and-socket-triage.md#nftables-review-and-authorized-rule-changes) για ένα συγκεκριμένο παράδειγμα.

## Δοκιμή εξερχόμενης κίνησης και συμπεριφοράς proxy

```bash
ip route get 1.1.1.1
getent hosts example.com
curl -I --connect-timeout 3 https://example.com/
printenv http_proxy https_proxy all_proxy no_proxy 2>/dev/null
```

Διαχωρίστε την αποτυχία DNS από την αποτυχία TCP, TLS ή proxy. Δοκιμάστε τον συγκεκριμένο προορισμό και το πρωτόκολλο που σχετίζονται με την αξιολόγηση· η προσβασιμότητα μέσω ICMP δεν σημαίνει ότι επιτρέπεται το TCP ή το UDP. Αν έχει ρυθμιστεί proxy, συγκρίνετε το προβλεπόμενο αίτημα μέσω proxy με το ίδιο αίτημα προς τον ίδιο προορισμό, εφαρμόζοντας τους σχετικούς κανόνες `no_proxy`. Μια τοπική προώθηση θύρας μπορεί επίσης να καταστήσει μια υπηρεσία loopback διαθέσιμη αλλού, επομένως ελέγξτε τους ενεργούς listeners και τα SSH tunnels όταν η εικόνα του firewall διαφέρει από την παρατηρούμενη έκθεση.
