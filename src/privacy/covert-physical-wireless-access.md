## Επίθεση κοντινών γειτόνων

Η Volexity κατέγραψε μια επιχείρηση APT28/GRU το 2022, στην οποία ο δράστης βρισκόταν μακριά από τον τελικό στόχο του. Έκανε password spraying στη δημόσια υπηρεσία του στόχου για να αποκτήσει έγκυρα διαπιστευτήρια, αλλά το MFA απέτρεπε την απευθείας σύνδεση από το Internet. Το εταιρικό Wi-Fi του στόχου δεχόταν αυτά τα διαπιστευτήρια χωρίς MFA. Ο δράστης παραβίασε οργανισμούς που βρίσκονταν φυσικά κοντά στον στόχο, εντόπισε ένα dual-homed σύστημα με ασύρματη εμβέλεια και χρησιμοποίησε αυτό το σύστημα για να πιστοποιηθεί στο Wi-Fi του στόχου. Η Volexity ονόμασε αυτή την τεχνική **Nearest Neighbor Attack**.<sup>[[1]](#references)</sup>

```text
remote operator
      |
compromised organization C
      |
compromised organization B -- Wi-Fi radio --> target organization A
                                               |
                                        internal service
```

Η καινοτομία βρίσκεται στον συνδυασμό. Κανένας operator δεν μεταβαίνει στον στόχο και το MFA της υπηρεσίας που είναι εκτεθειμένη στο Internet εξακολουθεί να λειτουργεί. Ο παραβιασμένος γείτονας παρέχει φυσική εγγύτητα· το κλεμμένο credential του στόχου παρέχει λογική πρόσβαση· το Wi-Fi του στόχου γίνεται η διαδρομή για τη διέλευση του ορίου.

### Προϋποθέσεις και ορατότητα

- Ένα κοντινό σύστημα πρέπει να μπορεί να ελεγχθεί απομακρυσμένα και να διαθέτει συμβατό radio ή πρόσβαση σε άλλο κοντινό pivot.
- Το SSID του στόχου πρέπει να είναι προσβάσιμο από αυτό το σύστημα και η πρόσβαση στο Wi-Fi πρέπει να δέχεται επαναχρησιμοποιήσιμο credential/πιστοποιητικό/κατάσταση συσκευής.
- Το pivot συχνά χρειάζεται δύο ταυτόχρονες διαδρομές: μία πίσω στον operator και μία προς το WLAN του στόχου.
- Ο στόχος μπορεί να βλέπει ένα νέο station MAC και ένα έγκυρο username, αλλά να μην υπάρχει αντίστοιχο πιστοποιητικό managed device, posture, ιστορικό ή αναμενόμενη είσοδος στο κτίριο.
- Τα endpoint logs του γείτονα μπορεί να δείχνουν ασύρματες σαρώσεις, νέα profiles, αλλαγές interface, tunneling και δραστηριότητα remote control.

### Εντοπισμός και πρόληψη

1. Απαιτήστε EAP-TLS με πιστοποιητικό και posture managed device για εταιρικό Wi-Fi· μην επιτρέπετε σε έναν κωδικό πρόσβασης που απέτυχε στο MFA μέσω Internet να αρκεί μόνο και μόνο επειδή χρησιμοποιείται μέσω radio.
2. Συσχετίστε το RADIUS authentication με την ταυτότητα MDM/NAC, το ιστορικό station/device binding, την τοποθεσία AP, τα συμβάντα φυσικής πρόσβασης και τις ταυτόχρονες συνεδρίες.
3. Ειδοποιήστε όταν ένας λογαριασμός συνδέεται για πρώτη φορά από ασυνήθιστο άκρο AP, χωρίς managed certificate ή ενώ η ίδια ταυτότητα είναι ενεργή αλλού.
4. Παρακολουθείτε endpoints που μπορούν να γεφυρώνουν interfaces. Σε Windows, Linux και network appliances, διερευνήστε απρόσμενα WLAN profiles, ρυθμίσεις forwarding/NAT, virtual adapters και persistent tunnels.
5. Περιορίστε την περιττή διαρροή σήματος με σωστή τοποθέτηση AP και σχεδιασμό ισχύος. Αυτό είναι συμπληρωματικό μέτρο, όχι έλεγχος ταυτοποίησης.
6. Συντονίστε την απόκριση σε περιστατικά με τους γειτονικούς ενοίκους: η τελική πηγή radio μπορεί να είναι και η ίδια θύμα.

Το [εργαστήριο δύο οργανισμών με εξουσιοδοτημένα συστήματα](authorized-adversary-emulation-labs.md#lab-4-nearest-neighbor-wireless-pivot) αναπαράγει αυτά τα παρατηρήσιμα στοιχεία χωρίς επίθεση σε γείτονα.

### Επικύρωση διαδρομής pivot Windows

Ένας dual-homed host Windows δεν γεφυρώνει αυτόματα τα interfaces του. Απογράψτε πρώτα τους adapters, τις routes και την κατάσταση WLAN και, στη συνέχεια, συνδεθείτε μόνο μέσω εγκεκριμένου profile. Το όρισμα `name` της εντολής `netsh wlan connect` προσδιορίζει ένα εγκατεστημένο profile, όχι ένα αυθαίρετο SSID και password. Συγκρίνετε τον πίνακα δρομολόγησης πριν και μετά τη σύνδεση, ώστε μια νέα default route να μην διακόψει τη διαδρομή ελέγχου ή να ακυρώσει το αποτέλεσμα. Συνεχίστε με τους [ελέγχους μετά τη σύνδεση](../generic-methodologies-and-resources/pentesting-wifi/wifi-post-association-and-client-isolation-attacks.md) μόνο αφού επιβεβαιώσετε το προβλεπόμενο interface και route.<sup>[[1]](#references)[[6]](#references)</sup>

```powershell
Get-NetAdapter -Physical | Sort-Object Status -Descending
Get-NetIPConfiguration
Get-NetRoute -AddressFamily IPv4 | Sort-Object InterfaceIndex,RouteMetric

netsh wlan show interfaces
netsh wlan show networks mode=bssid
netsh wlan show profiles

# Connect only with an approved profile already installed on the endpoint.
netsh wlan connect name="<approved-profile>" interface="Wi-Fi"
Get-NetConnectionProfile
```

Η δημοσιευμένη τεκμηρίωση περιστατικού της Volexity δείχνει μια ακόμη χρήσιμη διάκριση. Ο ενσωματωμένος κώδικας C# ανοίγει το WLAN API, απαριθμεί διεπαφές, διαβάζει EAP XML από τον δίσκο και καλεί το `WlanSetProfileEapXmlUserData` για ένα κατονομασμένο προφίλ στην πρώτη ασύρματη διεπαφή. Το API ορίζει διαπιστευτήρια χρήστη EAP σε ένα υπάρχον προφίλ 802.1X, αλλά το δημοσιευμένο στοιχείο δεν περιέχει ούτε `WlanConnect` ούτε τη λογική ανακάλυψης που περιγράφεται στην αναφορά. Αντιμετωπίστε το ως παροχή προφίλ και όχι ως πλήρη connector, και ελέγξτε το προφίλ που προκύπτει στο πλαίσιο της [αξιολόγησης client και supplicant](../generic-methodologies-and-resources/pentesting-wifi/wifi-client-and-supplicant-assessment.md).<sup>[[5]](#references)[[7]](#references)</sup>

## Δημόσιοι χώροι και Wi-Fi τρίτων

Η χρήση Wi-Fi σε καφέ, ξενοδοχείο, αεροδρόμιο ή δημοτικό δίκτυο αλλάζει τη διεύθυνση IP που βλέπει ένας προορισμός. Δεν εξασφαλίζει ανωνυμία. Ο χώρος ή ο πάροχός του μπορεί να διατηρεί αρχεία συσχέτισης με AP, MAC συσκευής, μίσθωσης DHCP, λογαριασμού captive portal, επαλήθευσης SMS/email και ροών. Τα αρχεία φυσικής εισόδου, CCTV, αγορών, τοποθεσίας κινητού και ταξιδιών μπορούν να συνδέσουν το ψηφιακό συμβάν με ένα άτομο.

Ένας δράστης μπορεί να προσπαθήσει να μειώσει τη σύνδεση με ένα στοιχείο ταυτοποίησης χρησιμοποιώντας τυχαιοποιημένες διευθύνσεις MAC, ξεχωριστή συσκευή, μετρητά ή tunnel. Ωστόσο, η συσχέτιση μεταξύ διαφορετικών επιπέδων παραμένει δυνατή μέσω της ώρας άφιξης, επαναλαμβανόμενων μοτίβων επίσκεψης, αποτυπωμάτων ραδιοσυχνοτήτων, συμπεριφοράς στην πύλη, χρονισμού κίνησης, βίντεο από κάμερες και παρόχου tunnel. Ένα VPN μεταφέρει επίσης τα δεδομένα προορισμού από τα αρχεία του χώρου στα αρχεία του VPN· δεν αποκρύπτει από τον χώρο ότι η συσκευή ήταν εκεί.

Οι υπεύθυνοι δημόσιων δικτύων πρέπει να απομονώνουν τους clients, να αποκλείουν την πλευρική κίνηση, να χρησιμοποιούν WPA2/3-Enterprise ή κλειδιά ανά συσκευή όπου είναι εφικτό, να διατηρούν αναλογικά αρχεία DHCP/RADIUS/ασφάλειας, να προστατεύουν τα captive portals και να δημοσιεύουν διαδικασία αναφοράς κατάχρησης. Οι red teams πρέπει να χρησιμοποιούν τέτοιους χώρους μόνο όταν το επιτρέπουν οι όροι χρήσης και η ανάθεση· η παράκαμψη πύλης, η κλοπή πρόσβασης ή η στόχευση άλλων επισκεπτών δεν αποτελούν εξουσιοδοτημένη συντόμευση δοκιμών.

## Κρυφές συσκευές drop και warshipping

Ένα drop είναι ένα μικρό σύστημα που τοποθετείται σε έναν χώρο ή παραδίδεται εκεί και στη συνέχεια ελέγχεται μέσω εξερχόμενου Ethernet, Wi-Fi ή κινητής σύνδεσης. Το «warshipping» συσκευάζει τη συσκευή έτσι ώστε μια συνηθισμένη παράδοση να τη μεταφέρει εντός της περιμέτρου ραδιοκάλυψης. Το πιθανό υλικό κυμαίνεται από υπολογιστή μίας πλακέτας έως τροποποιημένο φορτιστή, περιφερειακό USB, συσκευή δικτύου ή modem με μπαταρία.

Λειτουργική αρχιτεκτονική:

```text
operator -> controlled rendezvous <- outbound encrypted tunnel <- drop
                                                        |
                                             scoped local interface
```

Η συσκευή μπορεί να παρέχει απομακρυσμένη πρόσβαση, να εκτελεί ασύρματες μετρήσεις, να προσομοιώνει ένα περιφερειακό εξουσιοδοτημένης άσκησης ή να αναμεταδίδει κίνηση. Φαίνεται να βρίσκεται τοπικά, αλλά αφήνει φυσικά ίχνη: σειριακούς αριθμούς, συσκευασίες, δακτυλικά αποτυπώματα, κάμερες, αρχεία καταγραφής πρόσβασης, κατανάλωση ενέργειας, περιγραφές USB, διαπραγμάτευση switchport, αποτυπώματα DHCP, συμπεριφορά OUI/randomization MAC, εκπομπές RF και επαναλαμβανόμενες συνδέσεις rendezvous.

### Αμυντικά μέτρα

- Διατηρήστε διαδικασίες για τους χώρους παραλαβής και την απογραφή περιουσιακών στοιχείων· ελέγχετε απροσδόκητες ηλεκτρονικές συσκευές και δέματα που απευθύνονται σε ανύπαρκτους υπαλλήλους.
- Χρησιμοποιήστε 802.1X/NAC για ενσύρματη και ασύρματη πρόσβαση, απενεργοποιήστε τις αχρησιμοποίητες θύρες και τοποθετήστε άγνωστες συσκευές σε περιορισμένο VLAN αποκατάστασης.
- Ενεργοποιήστε ειδοποιήσεις για νέα αποτυπώματα DHCP, διευθύνσεις MAC με τοπική διαχείριση που παραμένουν σταθερές, νέες συσκευές δικτύου/HID USB, μη εξουσιοδοτημένα Wi-Fi Direct/Bluetooth και εξερχόμενες σήραγγες μεγάλης διάρκειας.
- Καταγράψτε τη συνήθη συμπεριφορά των switchport, Power over Ethernet, DNS και TLS. Ένας μικροσκοπικός host χωρίς εγγραφή απογραφής που πραγματοποιεί περιοδικές κρυπτογραφημένες συνδέσεις αποτελεί ισχυρότερη ένδειξη από ένα απλό «Raspberry Pi OUI».
- Κατά τη διάρκεια μιας άσκησης, απογράψτε, επισημάνετε και οριοθετήστε τη συσκευή, κρυπτογραφήστε την, παρέχετε δυνατότητα απομακρυσμένης απενεργοποίησης, ορίστε προθεσμία ανάκτησης και βεβαιωθείτε ότι η απώλειά της δεν μπορεί να εκθέσει επαναχρησιμοποιήσιμα διαπιστευτήρια.

## Κυψελοειδής σύνδεση backhaul και eSIM

Ένα κυψελοειδές modem παρακάμπτει την πύλη Internet του στόχου και μπορεί να διατηρεί ένα drop προσβάσιμο πίσω από carrier NAT μέσω μιας εξερχόμενης σύνδεσης rendezvous. Οι διευθύνσεις κινητής τηλεφωνίας μπορεί να αλλάζουν ή να είναι κοινόχρηστες· ωστόσο, ο κυψελοειδής πάροχος διατηρεί ισχυρά στοιχεία συνδρομητή και δικτύου: ταυτότητα SIM/eSIM, IMSI, IMEI συσκευής, εκχωρημένες διευθύνσεις/θύρες, χρονικά στοιχεία κυψέλης/τομέα, καθώς και αρχεία λογαριασμού/πληρωμών και περιαγωγής.

Από την πλευρά της επιχείρησης, εντοπίστε απροσδόκητα modem και προσωπικά hotspots με ασύρματες/RF επιθεωρήσεις, απογραφή USB/PCI στα endpoint, περιορισμούς MDM, παρακολούθηση μη εξουσιοδοτημένων SSID και φυσικό έλεγχο. Ένα drop που χρησιμοποιεί κυψελοειδή σύνδεση για έλεγχο μπορεί και πάλι να εντοπιστεί από τη συμπεριφορά του σε τοπικό Ethernet/Wi-Fi και τις ραδιοεκπομπές του.

Για εξουσιοδοτημένες ασκήσεις, ο οργανισμός πρέπει να έχει στην κατοχή του τη συνδρομή και το modem, να καταγράφει τα αναγνωριστικά μαζί με τον controller και να επαληθεύει ότι οι όροι του παρόχου και του δικτύου επιτρέπουν την κίνηση. Η αγορά με προπληρωμένη κάρτα ή κρυπτονόμισμα δεν διαγράφει τα αρχεία πύργων κινητής τηλεφωνίας, συσκευών ή καταστημάτων λιανικής.

## Τυχαιοποίηση MAC και αποτυπώματα συσκευών

Τα σύγχρονα συστήματα μπορούν να χρησιμοποιούν τυχαιοποιημένη MAC με τοπική διαχείριση για κάθε δίκτυο. Αυτό περιορίζει την παθητική μακροχρόνια παρακολούθηση μέσω μιας σταθερής εργοστασιακής MAC· δεν αποκρύπτει:

- τον χρονισμό των probe/association και το σύνολο των ζητούμενων δυνατοτήτων δικτύου·
- τα information elements του 802.11, τους υποστηριζόμενους ρυθμούς και τη συμπεριφορά που αφορά συγκεκριμένους κατασκευαστές·
- τις επιλογές/το hostname του DHCP, τα αναγνωριστικά IPv6 και το αποτύπωμα captive portal/browser·
- την ταυτότητα ή το πιστοποιητικό του ελέγχου ταυτότητας 802.1X·
- λογαριασμούς υψηλότερου επιπέδου, σήραγγες και μοτίβα κίνησης· ή
- τη φυσική παρατήρηση.

Οι αμυνόμενοι δεν πρέπει να χρησιμοποιούν λίστες επιτρεπόμενων MAC για έλεγχο ταυτότητας. Συσχετίστε την ασύρματη ταυτότητα με το πιστοποιητικό/την κατάσταση ασφαλείας της συσκευής και αντιμετωπίστε τις μεταβαλλόμενες MAC ως φυσιολογικές, εκτός αν υπάρχουν ανωμαλίες σε άλλα στοιχεία.

## Παραβίαση δορυφορικής σύνδεσης

Η Kaspersky κατέγραψε ότι η Turla εκμεταλλεύτηκε αδυναμίες σε παλαιότερη μονόδρομη δορυφορική πρόσβαση DVB-S στο Internet. Σύμφωνα με το μοντέλο που περιγράφηκε, ένας νόμιμος απομακρυσμένος συνδρομητής έστελνε εξερχόμενα αιτήματα μέσω επίγειας σύνδεσης, αλλά λάμβανε τα δεδομένα downstream μέσω μη κρυπτογραφημένης δορυφορικής μετάδοσης ευρείας κάλυψης. Ένας επιτιθέμενος εντός της κάλυψης του δορυφόρου μπορούσε να παρακολουθήσει τη μετάδοση downlink, να επιλέξει την IP ενός ενεργού συνδρομητή και να φροντίσει ώστε οι απαντήσεις C2 να απευθύνονται σε αυτήν την IP. Τόσο ο νόμιμος συνδρομητής όσο και ο επιτιθέμενος λάμβαναν τη μετάδοση· ο επιτιθέμενος εξήγαγε την κίνηση για την επιλεγμένη θύρα, ενώ ο νόμιμος συνδρομητής απέρριπτε τα ανεπιθύμητα πακέτα. Στη συνέχεια, ο χειριστής C2 φαινόταν να χρησιμοποιεί διεύθυνση παρόχου δορυφορικών υπηρεσιών σε άλλη γεωγραφική περιοχή.<sup>[[2]](#references)</sup>

```text
actor uplink request -> C2 server -> Internet -> satellite gateway
                                           satellite broadcast
                                  +--------------+-------------+
                                  |                            |
                         legitimate subscriber          actor receiver
```

Αυτό αφορούσε συγκεκριμένο πρωτόκολλο/υπηρεσία, είχε περιορισμένο bandwidth και δεν ισοδυναμούσε με παραβίαση ενός σύγχρονου αμφίδρομου κρυπτογραφημένου δορυφορικού τερματικού. Επίσης, δεν έκρυβε τη διαδρομή των εξερχόμενων αιτημάτων του δράστη από έναν παρατηρητή με επαρκείς δυνατότητες. Οι ευκαιρίες εντοπισμού περιλαμβάνουν ασύμμετρη/αδύνατη δρομολόγηση, κίνηση προς συνδρομητή που δεν ξεκίνησε τη ροή, ασυνήθιστες θύρες προορισμού, τηλεμετρία παρόχου, διερεύνηση της τοποθεσίας του δέκτη/RF και τη διαμόρφωση του malware. Χρησιμοποιήστε αυτή την περίπτωση για να αμφισβητήσετε την υπόθεση ότι ο γεωεντοπισμός μιας IP C2 εντοπίζει γεωγραφικά τον χειριστή της — όχι ως οδηγό κατασκευής.

## Φύλλο εργασίας συσχέτισης φυσικού και ψηφιακού κόσμου

Όταν μια πηγή που φαίνεται τοπική είναι ύποπτη, δημιουργήστε ένα ενιαίο χρονολόγιο:

1. κανονικοποιήστε τα ρολόγια AP, RADIUS, DHCP, DNS, proxy, VPN, EDR, switch και φυσικού ελέγχου πρόσβασης·
2. εντοπίστε την πρώτη σύνδεση μέσω radio ή ενεργοποίηση της σύνδεσης, όχι μόνο την πρώτη ειδοποίηση·
3. συσχετίστε το station με πιστοποιητικό, κατάσταση συσκευής, αποτύπωμα DHCP και θέση switch/AP·
4. αναζητήστε ταυτόχρονη δραστηριότητα απομακρυσμένου ελέγχου/tunnel σε κοντινά συστήματα·
5. εξετάστε παραδόσεις, επισκέπτες, αποκλίσεις απογραφής, κάμερες και ευρήματα RF σύμφωνα με την ισχύουσα πολιτική/νομοθεσία·
6. διατηρήστε την ύποπτη συσκευή και την πτητική κατάσταση του δικτύου· μην κάνετε επανεκκίνηση στα τυφλά·
7. εξακριβώστε αν η φαινομενική πηγή είναι υποδομή υπό τον έλεγχο του δράστη ή άλλο θύμα.
