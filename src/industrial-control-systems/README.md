# 산업 제어 시스템 해킹

{{#include ../banners/hacktricks-training.md}}

## 이 섹션 소개

이 섹션에서는 산업 제어 시스템(ICS)의 구성 요소, 아키텍처, 프로토콜 및 보안 평가 방법을 소개합니다. ICS는 물리적 프로세스를 모니터링하거나 변경하는 프로그래밍 가능한 시스템과 장치를 아우르는 더 넓은 운영 기술(OT) 영역에 속합니다. 대표적인 예로 감시 제어 및 데이터 수집(SCADA) 시스템, 분산 제어 시스템(DCS), 프로그래머블 로직 컨트롤러(PLC)가 있습니다.<sup>[[1]](#references)</sup>

이러한 환경의 보안 작업은 공정 안전, 신뢰성, 가용성, 결정론적 운영, 장비 수명 주기 등 기존 IT와 다른 요구 사항을 고려해야 합니다. 기술적으로 유효한 보안 제어라도 물리적 프로세스를 방해한다면 적합하지 않을 수 있으므로, 테스트와 개선 작업은 시스템 소유자 및 운영 담당자와 협의하여 진행해야 합니다.<sup>[[1]](#references)</sup>

침해 또는 우발적인 중단은 생산을 멈추거나, 장비를 손상시키거나, 유해 물질을 방출하거나, 환경에 피해를 주거나, 부상 및 인명 손실을 초래할 수 있습니다. 이러한 물리적 영향의 가능성 때문에 능동적인 테스트에 앞서 제어 대상 프로세스와 안전 운전 한계를 이해해야 합니다.<sup>[[1]](#references)</sup>

많은 OT 환경에서는 장비의 수명이 길고 변경 시 운영 및 안전 테스트가 필요하기 때문에 레거시 운영 체제, 애플리케이션, 프로토콜을 계속 사용합니다. 일부 프로토콜은 최신 인증이나 암호화 없이 설계되었으며, 공급업체 지원이나 유지보수 기간의 제약으로 패치가 어려울 수 있습니다. 직접 업그레이드가 불가능한 경우에는 네트워크 분할, 접근 제어, 모니터링으로 위험을 보완하세요.<sup>[[1]](#references)</sup>

## 평가 우선순위

먼저 제어 대상 프로세스, 시스템 경계, 네트워크 토폴로지, 자산, 데이터 흐름, 신뢰 관계, 외부 연결을 파악하세요. 같은 종류의 장치도 사이트마다 기능이 다를 수 있으므로, 한 환경의 아키텍처나 영향 모델이 다른 환경에도 적용된다고 가정하지 마세요.<sup>[[1]](#references)</sup>

가능하면 수동 탐색과 기존 엔지니어링 문서를 우선 활용하세요. 모든 능동 스캔이나 익스플로잇은 안전 제약, 유지보수 기간, 복구 절차, 중단 조건을 정의한 승인된 테스트 계획에 따라 수행해야 합니다. 발견 사항은 사이버 보안 영향과 물리적 프로세스에 미칠 수 있는 영향을 모두 고려해 평가해야 합니다.<sup>[[1]](#references)</sup>

이러한 아키텍처 지식은 자산 인벤토리, 네트워크 분할, 모니터링, 인시던트 대응, 위험 기반 취약점 관리와 같은 방어 활동에도 활용됩니다.<sup>[[1]](#references)</sup>
