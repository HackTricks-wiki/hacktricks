# 産業用制御システムのハッキング

{{#include ../banners/hacktricks-training.md}}

## このセクションについて

このセクションでは、産業用制御システム（ICS）のコンポーネント、アーキテクチャ、プロトコル、セキュリティ評価方法を紹介します。ICSは、物理プロセスを監視したり、その状態を変化させたりするプログラム可能なシステムやデバイスを含む、より広範な運用技術（OT）分野の一部です。一般的な例として、監視制御およびデータ取得（SCADA）システム、分散制御システム（DCS）、プログラマブルロジックコントローラー（PLC）があります。<sup>[[1]](#references)</sup>

こうした環境でのセキュリティ作業では、プロセスの安全性、信頼性、可用性、決定論的な動作、機器のライフサイクルなど、従来のITとは異なる要件を考慮する必要があります。技術的に有効なセキュリティ制御であっても、物理プロセスを妨げる場合は適切とは限りません。そのため、テストと修正はシステム所有者や運用担当者と調整して行う必要があります。<sup>[[1]](#references)</sup>

侵害や偶発的な妨害により、生産停止、機器の損傷、有害物質の放出、環境への被害、負傷、さらには人命の損失が発生するおそれがあります。こうした物理的な影響が生じ得るため、能動的なテストの前に、制御対象のプロセスと安全な運転限界を理解する必要があります。<sup>[[1]](#references)</sup>

機器の耐用年数が長く、変更にも運用面と安全面のテストが必要となるため、多くのOT環境ではレガシーOS、アプリケーション、プロトコルが使われ続けています。一部のプロトコルは、最新の認証や暗号化を備えずに設計されており、ベンダーのサポートや保守時間枠の制約によってパッチ適用が難しい場合があります。直接アップグレードが現実的でない場合は、セグメンテーション、アクセス制御、監視で補完してください。<sup>[[1]](#references)</sup>

## 評価の優先事項

まず、制御対象のプロセス、システム境界、ネットワークトポロジー、資産、データフロー、信頼関係、外部接続を把握します。同じ種類のデバイスでもサイトによって機能が異なる場合があるため、ある環境のアーキテクチャや影響モデルが別の環境にも当てはまると決めつけないでください。<sup>[[1]](#references)</sup>

可能な限り、パッシブな探索や既存のエンジニアリング文書を優先してください。アクティブスキャンやエクスプロイトを行う場合は、安全上の制約、保守時間枠、復旧手順、中止条件を定めた承認済みテスト計画に従ってください。発見事項は、サイバーセキュリティへの影響と物理プロセスに及ぼす可能性のある影響の両面から評価する必要があります。<sup>[[1]](#references)</sup>

同じアーキテクチャの知識は、資産インベントリ、ネットワークセグメンテーション、監視、インシデント対応、リスクベースの脆弱性管理などの防御活動にも役立ちます。<sup>[[1]](#references)</sup>

## 監視冷凍システムコントローラーの悪用

冷凍システムマネージャーは、コンプレッサーとケースコントローラーを調整しますが、それ自体がケースを冷却するわけではありません。そのため、管理インターフェースにアクセスできると、通常の設定配布を通じて多数の下位デバイスを制御できる場合があります。これは、1台のサーモスタットを変更したり、コンプレッサーを直接駆動したりするのとは異なります。<sup>[[3]](#references)[[4]](#references)</sup>

### 日付から生成されるメンテナンスコードによるログイン

影響を受けるDanfossシステムマネージャーでは、別のXMLログインがアカウントパスワードの代わりに、コントローラーの日付から生成されたコードを受け入れます。<sup>[[2]](#references)[[3]](#references)</sup> SM800およびSC255について、Synacktivは`eds_only`属性と`quantum_only`属性を`xml_load_file`および`check_authorize`を通じて`check_code_of_day`まで追跡しました。また、そのアドバイザリーでは、`xml.cgi`の`read_date_time`が認証なしでコントローラーの日付を開示することも示されています。<sup>[[2]](#references)</sup> ClarotyはAK-SM 800Aにも対応する`getauth`経路があることを発見しましたが、そのトリガー属性は伏せられています。旧モデルの属性名がこのプラットフォームでも使えると決めつけてはいけません。<sup>[[3]](#references)</sup>

Synacktivは、認証不要の日付照会を次のように説明しています。<sup>[[2]](#references)</sup>

```bash
curl -k -d '<cmd action="read_date_time"/>' https://<controller>/xml.cgi
```

コードにデバイス固有の秘密情報はありません。[firmware](../hardware-physical-access/firmware-analysis/)からアルゴリズムを復元すれば、同じ影響を受ける実装を使用するデバイスで有効な日付ベースの認証情報を生成できる可能性があります。<sup>[[2]](#references)[[3]](#references)</sup> まずモデルとfirmwareを確認してください。日付に応じた応答が得られただけでは、別のログイン方法が存在することや、セッションを取得できたことの証明にはなりません。

### 一括設定と除霜ヒーターの悪用

管理者アクセスを取得したら、システムマネージャーに紐付けられたショーケースコントローラーを特定し、設定配信機能で複数のコントローラーをまとめて更新できるか確認してください。通常、ショーケースの設定温度を変更しても、庫内温度は室温に近づく程度です。周囲温度を超えて加熱するには、ショーケースコントローラーの電気式蒸発器除霜ヒーターを制御します。除霜中は冷却が停止し、センサーまたはタイマーがサイクルを終了するまでヒーターが作動します。除霜方式、スケジュール、終了温度、時間制限を変更すれば、代わりにヒーターを作動し続けさせることができます。マネージャーから複数のショーケースにこれらの変更を配信し、関連アラームを抑制すれば、1つの監視系への侵害が店舗全体のプロセス変更につながります。<sup>[[4]](#references)</sup>

これは物理プロセスに関わる危険であり、稼働中のシステムで安全に実施できる概念実証ではありません。熱遮断器があればヒーターの作動を制限できる場合もありますが、連続運転によって既存の電気接続の弱い箇所が過熱する可能性は残ります。設定と影響の検証は、承認済みのラボ、またはオペレーターのプロセス安全計画に従ってのみ行ってください。<sup>[[4]](#references)</sup>
