# 産業制御システムのハッキング

{{#include ../banners/hacktricks-training.md}}

## このセクションについて

このセクションでは、産業制御システム（ICS）のコンポーネント、アーキテクチャ、プロトコル、およびセキュリティ評価の方法を紹介します。ICSは、物理プロセスを監視したり、その状態を変化させたりするプログラム可能なシステムやデバイスを含む、より広範な運用技術（OT）領域の一部です。一般的な例として、監視制御・データ収集（SCADA）システム、分散制御システム（DCS）、プログラマブルロジックコントローラー（PLC）があります。<sup>[[1]](#references)</sup>

これらの環境でセキュリティ業務を行う際は、プロセスの安全性、信頼性、可用性、決定論的な動作、設備のライフサイクルなど、従来のITとは異なる要件を考慮する必要があります。技術的に有効なセキュリティ対策であっても、物理プロセスを妨げる場合は適切でないことがあります。そのため、テストや修正はシステム所有者および運用担当者と調整して行う必要があります。<sup>[[1]](#references)</sup>

侵害や偶発的な障害は、生産停止、設備の損傷、有害物質の放出、環境への被害、負傷、さらには人命の損失につながる可能性があります。こうした物理的影響が起こり得るため、能動的なテストを始める前に、制御対象のプロセスとその安全な運転限界を理解することが重要です。<sup>[[1]](#references)</sup>

設備の耐用年数が長く、変更には運用面と安全面のテストが必要となるため、多くのOT環境ではレガシーOS、アプリケーション、プロトコルが使われ続けています。一部のプロトコルは最新の認証や暗号化を備えずに設計されており、ベンダーのサポートやメンテナンス時間の制約によりパッチ適用が難しい場合もあります。直接アップグレードができない場合は、ネットワーク分割、アクセス制御、監視で補完してください。<sup>[[1]](#references)</sup>

## 評価の優先事項

まず、制御対象のプロセス、システム境界、ネットワークトポロジー、資産、データフロー、信頼関係、外部接続を把握します。同じ種類のデバイスでも、拠点によって機能が異なる場合があります。ある環境のアーキテクチャや影響モデルが別の環境にも当てはまると決めつけないでください。<sup>[[1]](#references)</sup>

可能な場合は、受動的な探索や既存のエンジニアリング資料を優先してください。能動的なスキャンやエクスプロイトは、制約、安全上の要件、メンテナンス時間、復旧手順、中止条件を定めた承認済みテスト計画に従って実施してください。発見事項は、サイバーセキュリティへの影響と物理プロセスに及ぼす可能性のある影響の両方から評価する必要があります。<sup>[[1]](#references)</sup>

同じアーキテクチャの知識は、資産のインベントリ作成、ネットワーク分割、監視、インシデント対応、リスクに基づく脆弱性管理などの防御活動にも役立ちます。<sup>[[1]](#references)</sup>

- [OPC UAのテスト](../network-services-pentesting/4840-pentesting-opc-ua.md)では、産業用データ交換サービスを扱います。
