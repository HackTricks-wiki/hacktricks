# Стеганографія зображень

{{#include ../../banners/hacktricks-training.md}}

Більшість стеганографічних завдань із зображеннями в CTF зводяться до одного з таких типів:

- LSB/бітові площини (PNG/BMP)
- Payload у метаданих/коментарях
- Дивні PNG chunk-и / відновлення пошкоджених файлів
- Інструменти для домену DCT JPEG (OutGuess тощо)
- На основі кадрів (GIF/APNG)

## Швидке сортування

Спершу перевірте докази на рівні контейнера, а вже потім переходьте до глибокого аналізу вмісту:

- Перевірте файл і дослідіть структуру: `file`, `magick identify -verbose`, валідатори форматів (наприклад, `pngcheck`).
- Витягніть метадані та видимі рядки: `exiftool -a -u -g1`, `strings`.
- Перевірте наявність вбудованого/дописаного вмісту: `binwalk` і дані в кінці файла (`tail | xxd`).
- Визначте тип контейнера:
  - PNG/BMP: бітові площини/LSB і аномалії на рівні chunk-ів.
  - JPEG: метадані та інструменти для домену DCT (сімейства на кшталт OutGuess/F5).
  - GIF/APNG: витягування кадрів, порівняння кадрів, хитрощі з палітрою.

## Бітові площини / LSB

### Техніка

PNG/BMP популярні в CTF, оскільки зберігають пікселі так, що це спрощує **маніпуляції на рівні бітів**. Класичний механізм приховування/витягування даних такий:

- Кожен канал пікселя (R/G/B/A) містить кілька бітів.
- **Найменш значущий біт** (LSB) кожного каналу майже не змінює зображення.
- Зловмисники приховують дані в цих молодших бітах, іноді використовуючи крок, перестановку або вибір окремих каналів.

Чого очікувати в завданнях:

- Payload міститься лише в одному каналі (наприклад, у LSB каналу `R`).
- Payload міститься в альфа-каналі.
- Payload стискається/кодується після витягування.
- Повідомлення розподілено між площинами або приховано за допомогою XOR між площинами.

Додаткові сімейства, з якими можна зіткнутися (залежно від реалізації):

- **LSB matching** (не просто перемикання біта, а зміна значення на +/-1, щоб отримати цільовий біт)
- **Приховування на основі палітри/індексів** (індексовані PNG/GIF: payload міститься в індексах кольорів, а не в необроблених значеннях RGB)
- **Payload лише в альфа-каналі** (повністю невидимий у режимі перегляду RGB)

### Інструменти

#### zsteg

`zsteg` перебирає багато шаблонів витягування LSB/бітових площин для PNG/BMP:

```bash
zsteg -a file.png
```

Repo: https://github.com/zed-0xff/zsteg

#### StegoVeritas / Stegsolve

- `stegoVeritas`: запускає набір перетворень (метадані, перетворення зображення, брутфорс варіантів LSB).
- `stegsolve`: ручні візуальні фільтри (ізоляція каналів, перегляд площин, XOR тощо).

Завантажити Stegsolve: https://github.com/eugenekolo/sec-tools/tree/master/stego/stegsolve/stegsolve

#### Прийоми виявлення на основі FFT

FFT — це не витягування LSB; його використовують, коли вміст навмисно приховано в частотному просторі або тонких візерунках.

- Демонстрація EPFL: http://bigwww.epfl.ch/demo/ip/demos/FFT/
- Fourifier: https://www.ejectamenta.com/Fourifier-fullscreen/
- FFTStegPic: https://github.com/0xcomposure/FFTStegPic

Вебінструменти для первинного аналізу, які часто використовують у CTF:

- Aperi’Solve: https://aperisolve.com/
- StegOnline: https://stegonline.georgeom.net/

## Внутрішня будова PNG: чанки, пошкодження та приховані дані

### Техніка

PNG — це формат із чанками. У багатьох завданнях payload зберігається на рівні контейнера/чанків, а не в значеннях пікселів:

- **Зайві байти після `IEND`** (багато переглядачів ігнорують кінцеві байти)
- **Нестандартні допоміжні чанки**, що містять payload; див. [Обхід чанків PNG і робочий процес карвінгу](../../generic-methodologies-and-resources/basic-forensic-methodology/specific-software-file-type-tricks/png-tricks.md#extract-ancillary-chunk-payloads).
- **Пошкоджені заголовки**, що приховують розміри або порушують роботу парсерів, доки їх не виправити

Важливі чанки, які варто перевірити:

- `tEXt` / `iTXt` / `zTXt` (текстові метадані, іноді стиснені)
- `iCCP` (профіль ICC) та інші допоміжні чанки, що використовуються як носії даних
- `eXIf` (дані EXIF у PNG)

### Команди для первинного аналізу

```bash
magick identify -verbose file.png
pngcheck -v file.png
```

На що звертати увагу:

- Незвичні комбінації ширини/висоти/глибини кольору/типу кольору
- Помилки CRC/чанків (pngcheck зазвичай вказує точне зміщення)
- Попередження про додаткові дані після `IEND`

Якщо потрібен детальніший перегляд чанків:

```bash
pngcheck -vp file.png
exiftool -a -u -g1 file.png
```

Корисні довідкові матеріали:

- Специфікація PNG (структура, chunks): https://www.w3.org/TR/PNG/
- Прийоми роботи з форматами файлів (граничні випадки PNG/JPEG/GIF): https://github.com/corkami/docs

## JPEG: метадані, інструменти для DCT-домену та обмеження ELA

### Техніка

JPEG зберігається не як необроблені пікселі, а стискається в DCT-домені. Тому інструменти для стеганографії в JPEG відрізняються від інструментів для PNG LSB:

- Payload метаданих і коментарів зберігається на рівні файлу (легко помітити й швидко перевірити)
- Інструменти стеганографії для DCT-домену вбудовують біти в частотні коефіцієнти

На практиці розглядайте JPEG як:

- Контейнер для сегментів метаданих (легко помітити й швидко перевірити)
- Стиснений сигнальний домен (DCT-коефіцієнти), у якому працюють спеціалізовані інструменти стеганографії

### Швидкі перевірки

```bash
exiftool file.jpg
strings -n 6 file.jpg | head
binwalk file.jpg
```

Високоінформативні місця:

- Метадані EXIF/XMP/IPTC
- Сегмент коментаря JPEG (`COM`)
- Сегменти застосунків (`APP1` для EXIF, `APPn` для даних виробника)

### Поширені інструменти

- OutGuess: https://github.com/resurrecting-open-source-projects/outguess
- OpenStego: https://www.openstego.com/

Якщо ви маєте справу саме з payloads steghide у JPEG-файлах, скористайтеся `stegseek` (він швидше виконує bruteforce, ніж старі скрипти):

- [https://github.com/RickdeJager/stegseek](https://github.com/RickdeJager/stegseek)

### Error Level Analysis

ELA підсвічує артефакти повторного стиснення; це може вказати на ділянки, які редагували, але сама по собі ця методика не виявляє stego:

- [https://29a.ch/sandbox/2012/imageerrorlevelanalysis/](https://29a.ch/sandbox/2012/imageerrorlevelanalysis/)

## Анімовані зображення

### Методика

Для анімованих зображень припускайте, що повідомлення:

- Міститься в одному кадрі (просто), або
- Розподілене між кадрами (порядок має значення), або
- Видиме лише під час diff послідовних кадрів

### Витягування кадрів

```bash
ffmpeg -i anim.gif frame_%04d.png
```

Потім обробляйте кадри як звичайні PNG: `zsteg`, `pngcheck`, ізоляція каналів.

Альтернативні інструменти:

- `gifsicle --explode anim.gif` (швидке вилучення кадрів)
- `imagemagick`/`magick` для перетворень кожного кадру

Порівняння кадрів часто дає вирішальний результат:

```bash
magick frame_0001.png frame_0002.png -compose difference -composite diff.png
```

### APNG-кодування кількістю пікселів

- Визначте контейнери APNG: `exiftool -a -G1 file.png | grep -i animation` або `file`.
- Витягніть кадри без зміни часу показу: `ffmpeg -i file.png -vsync 0 frames/frame_%03d.png`.
- Відновіть дані, закодовані кількістю пікселів у кожному кадрі:

```python
from PIL import Image
import glob
out = []
for f in sorted(glob.glob('frames/frame_*.png')):
    counts = Image.open(f).getcolors()
    target = dict(counts).get((255, 0, 255, 255))  # adjust the target color
    out.append(target or 0)
print(bytes(out).decode('latin1'))
```

Анімовані завдання можуть кодувати кожен байт як кількість пікселів певного кольору в кожному кадрі; об’єднання цих кількостей відновлює повідомлення.<sup>[[1]](#references)</sup>

## Вбудовування із захистом паролем

Якщо ви підозрюєте, що дані вбудовані за допомогою парольної фрази, а не через маніпуляції на рівні пікселів, зазвичай це найшвидший шлях.

### steghide

Підтримує `JPEG, BMP, WAV, AU` і дає змогу вбудовувати та витягувати зашифровані дані.

```bash
steghide info file
steghide extract -sf file --passphrase 'password'
```

Repo: https://github.com/StefanoDeVuono/steghide

### StegCracker

```bash
stegcracker file.jpg wordlist.txt
```

Repo: https://github.com/Paradoxis/StegCracker

### stegpy

Підтримує PNG/BMP/GIF/WebP/WAV.

Repo: https://github.com/dhsdshdhk/stegpy
