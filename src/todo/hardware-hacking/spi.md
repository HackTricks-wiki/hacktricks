## Основна інформація

SPI (Serial Peripheral Interface) - це синхронний протокол послідовного зв'язку, який використовується у вбудованих системах для зв'язку між IC (Integrated Circuits) на коротких відстанях. Протокол зв'язку SPI використовує архітектуру master-slave, робота якої координується сигналами Clock і Chip Select. Архітектура master-slave складається з master (зазвичай мікропроцесора), який керує зовнішніми периферійними пристроями, такими як EEPROM, сенсори, пристрої керування тощо, які вважаються slave.

До одного master можна підключити кілька slave, але slave не можуть обмінюватися даними один з одним. Робота slave керується двома контактами: clock і chip select. Оскільки SPI є синхронним протоколом зв'язку, вхідні та вихідні контакти дотримуються сигналів clock. Chip select використовується master для вибору slave та взаємодії з ним. Коли chip select має високий рівень, slave-пристрій не вибраний, а коли він має низький рівень, chip вибраний і master взаємодіє зі slave.

MOSI (Master Out, Slave In) і MISO (Master In, Slave Out) відповідають за надсилання та отримання даних. Дані надсилаються до slave-пристрою через контакт MOSI, поки chip select має низький рівень. Вхідні дані містять інструкції, адреси пам'яті або дані відповідно до datasheet від постачальника slave-пристрою. Після отримання коректних вхідних даних контакт MISO відповідає за передавання даних до master. Вихідні дані надсилаються рівно в наступному такті clock після завершення введення. Контакти MISO передають дані, доки всі дані не буде передано або master не встановить високий рівень на контакті chip select (у такому разі slave припинить передавання, а master не прийматиме дані після цього такту clock).

## Отримання firmware з EEPROM

Отримання firmware може бути корисним для аналізу firmware та пошуку вразливостей у ньому. Часто firmware недоступна в інтернеті або є нерелевантною через такі фактори, як номер моделі, версія тощо. Тому безпосереднє вилучення firmware із фізичного пристрою може бути корисним для точнішого пошуку загроз.

Отримання Serial Console може бути корисним, але часто файли доступні лише для читання. Це обмежує аналіз з різних причин. Наприклад, у firmware можуть бути відсутні інструменти, необхідні для надсилання та отримання пакетів. Тому вилучення бінарних файлів для reverse engineering є недоцільним. Отже, отримання повної копії firmware у системі та вилучення бінарних файлів для аналізу може бути дуже корисним.

Також під час red teaming і отримання фізичного доступу до пристроїв отримання firmware може допомогти змінювати файли або впроваджувати шкідливі файли, а потім повторно записувати їх у пам'ять, що може бути корисним для встановлення backdoor у пристрої. Таким чином, отримання firmware відкриває численні можливості.

### CH341A EEPROM Programmer and Reader

Цей пристрій є недорогим інструментом для отримання firmware з EEPROM, а також для повторного запису в них файлів firmware. Він став популярним вибором для роботи з BIOS-чипами комп'ютерів (які фактично є EEPROM). Цей пристрій підключається через USB і потребує мінімального набору інструментів для початку роботи. Крім того, зазвичай він швидко виконує завдання, тому може бути корисним і під час фізичного доступу до пристроїв.

![drawing](../../images/board_image_ch341a.jpg)

Підключіть пам'ять EEPROM до CH341a Programmer і під'єднайте пристрій до комп'ютера. Якщо пристрій не визначається, спробуйте встановити драйвери на комп'ютер. Також переконайтеся, що EEPROM підключено правильною стороною (зазвичай контакт VCC потрібно розташувати у зворотній орієнтації відносно USB-конектора), інакше software не зможе виявити chip. За потреби зверніться до схеми:

![drawing](../../images/connect_wires_ch341a.jpg) ![drawing](../../images/eeprom_plugged_ch341a.jpg)

Нарешті, використайте software на кшталт flashrom, G-Flash (GUI) тощо для отримання firmware. G-Flash - це мінімалістичний GUI-інструмент, який працює швидко та автоматично виявляє EEPROM. Це може бути корисним, якщо firmware потрібно швидко вилучити без тривалого вивчення документації.

![drawing](../../images/connected_status_ch341a.jpg)

Після отримання firmware аналіз можна виконувати над бінарними файлами. Такі інструменти, як strings, hexdump, xxd, binwalk тощо, можна використовувати для вилучення великої кількості інформації про firmware, а також про всю файлову систему.

Для вилучення вмісту firmware можна використовувати binwalk. Binwalk аналізує hex-сигнатури, ідентифікує файли в бінарному файлі та може їх вилучати.
```
binwalk -e <filename>
```
Файл може мати розширення `.bin` або `.rom` залежно від використовуваних інструментів і конфігурацій.

> [!CAUTION]
> Зверніть увагу, що вилучення firmware є делікатним процесом і потребує великого терпіння. Будь-яке неправильне поводження може пошкодити firmware або навіть повністю стерти його та зробити пристрій непридатним до використання. Перед спробою вилучити firmware рекомендується вивчити конкретний пристрій.

### Bus Pirate + flashrom

![Програматор і зчитувач CH341A EEPROM - Bus Pirate + flashrom: Bus Pirate + flashrom](<../../images/image (910).png>)

Зверніть увагу, що навіть якщо PINOUT Pirate Bus містить контакти **MOSI** і **MISO** для підключення до SPI, деякі SPI можуть позначати контакти як DI і DO. **MOSI -> DI, MISO -> DO**

![Програматор і зчитувач CH341A EEPROM - Bus Pirate + flashrom: Зверніть увагу, що навіть якщо PINOUT Pirate Bus містить контакти MOSI і MISO для підключення до SPI, деякі SPI можуть...](<../../images/image (360).png>)

У Windows або Linux можна використовувати програму [**`flashrom`**](https://www.flashrom.org/Flashrom), щоб зчитати вміст flash memory, виконавши щось на кшталт:
```bash
# In this command we are indicating:
# -VV Verbose
# -c <chip> The chip (if you know it better, if not, don'tindicate it and the program might be able to find it)
# -p <programmer> In this case how to contact th chip via the Bus Pirate
# -r <file> Image to save in the filesystem
flashrom -VV -c "W25Q64.V" -p buspirate_spi:dev=COM3 -r flash_content.img
```
