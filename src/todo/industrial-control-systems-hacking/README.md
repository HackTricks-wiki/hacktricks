# 産業制御システムのハッキング

{{#include ../../banners/hacktricks-training.md}}

## このセクションについて

このセクションでは、産業制御システム（ICS）のコンポーネント、アーキテクチャ、プロトコル、およびセキュリティ評価手法について説明します。ICSは、物理プロセスを監視または変更するプログラム可能なシステムやデバイスを含む、より広範なオペレーショナルテクノロジー（OT）領域の一部です。一般的な例として、監視制御およびデータ収集（SCADA）システム、分散制御システム（DCS）、プログラマブルロジックコントローラー（PLC）などがあります。<sup>[[1]](#references)</sup>

これらの環境でのセキュリティ作業では、従来のITとは異なる要件を考慮する必要があります。これには、プロセスの安全性、信頼性、可用性、決定論的な動作、設備のライフサイクルなどが含まれます。技術的に有効なセキュリティ制御であっても、物理プロセスを妨害する場合は適切でない可能性があるため、テストと修正対応はシステム所有者および運用担当者と調整して実施する必要があります。<sup>[[1]](#references)</sup>

## 評価の優先事項

まず、制御対象のプロセス、システム境界、ネットワークトポロジー、資産、データフロー、信頼関係、外部接続を把握します。類似したデバイス種別でもサイトごとに異なる機能を担う可能性があるため、ある導入環境のアーキテクチャや影響モデルが別の環境にも当てはまると仮定しないでください。<sup>[[1]](#references)</sup>

可能な場合は、パッシブな探索と既存のエンジニアリング文書を優先します。アクティブスキャンやexploitの実行は、通常、安全上の制約、メンテナンス期間、復旧手順、停止条件を定義した承認済みのテスト計画に従って実施する必要があります。発見事項は、サイバーセキュリティへの影響だけでなく、物理プロセスに及ぼす可能性のある影響も考慮して評価します。<sup>[[1]](#references)</sup>

同じアーキテクチャに関する知識は、資産インベントリ、ネットワークセグメンテーション、モニタリング、インシデントレスポンス、リスクベースの脆弱性管理などの防御活動にも役立ちます。<sup>[[1]](#references)</sup>
