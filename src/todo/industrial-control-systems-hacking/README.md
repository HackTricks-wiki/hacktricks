# 산업 제어 시스템 Hacking

## 이 섹션 정보

이 섹션에서는 산업 제어 시스템(ICS) 구성 요소, 아키텍처, 프로토콜 및 보안 평가 방법을 소개합니다. ICS는 물리적 프로세스를 모니터링하거나 변경을 유발하는 프로그래밍 가능한 시스템 및 장치를 포함하는 더 광범위한 운영 기술(OT) 영역의 일부입니다. 일반적인 예로는 감시 제어 및 데이터 수집(SCADA) 시스템, 분산 제어 시스템(DCSs), 프로그래머블 로직 컨트롤러(PLCs)가 있습니다.<sup>[[1]](#references)</sup>

이러한 환경에서의 보안 작업은 기존 IT와 다른 요구 사항을 고려해야 합니다. 여기에는 프로세스 안전성, 신뢰성, 가용성, 결정론적 운영, 장비 수명 주기 등이 포함됩니다. 기술적으로 유효한 보안 제어라도 물리적 프로세스를 방해한다면 적합하지 않을 수 있으므로, 테스트와 개선 조치는 시스템 소유자 및 운영 담당자와 조율해야 합니다.<sup>[[1]](#references)</sup>

## 평가 우선순위

제어되는 프로세스, 시스템 경계, 네트워크 토폴로지, 자산, 데이터 흐름, 신뢰 관계 및 외부 연결을 파악하는 것부터 시작합니다. 유사한 장치 유형이라도 사이트마다 서로 다른 기능을 수행할 수 있으므로, 한 배포 환경의 아키텍처나 영향 모델이 다른 환경에도 적용된다고 가정하지 마십시오.<sup>[[1]](#references)</sup>

가능한 경우 수동 검색과 기존 엔지니어링 문서를 우선 사용합니다. 모든 능동 스캔 또는 익스플로잇은 안전 제약 조건, 유지 관리 기간, 복구 절차 및 중지 조건을 정의한 승인된 테스트 계획에 따라 수행해야 합니다. 발견 사항은 사이버 보안 영향과 물리적 프로세스에 미칠 수 있는 잠재적 영향을 모두 고려하여 평가해야 합니다.<sup>[[1]](#references)</sup>

동일한 아키텍처 지식은 자산 인벤토리, 네트워크 세분화, 모니터링, 사고 대응 및 위험 기반 취약점 관리와 같은 방어 활동에도 활용됩니다.<sup>[[1]](#references)</sup>
