## Σχετικά με αυτήν την ενότητα

Αυτή η ενότητα παρουσιάζει τα στοιχεία, τις αρχιτεκτονικές, τα πρωτόκολλα και τις μεθόδους αξιολόγησης ασφάλειας των industrial control systems (ICS). Το ICS αποτελεί μέρος του ευρύτερου πεδίου operational technology (OT): προγραμματιζόμενα συστήματα και συσκευές που παρακολουθούν ή προκαλούν αλλαγές σε φυσικές διεργασίες. Συνήθη παραδείγματα περιλαμβάνουν συστήματα supervisory control and data acquisition (SCADA), distributed control systems (DCSs) και programmable logic controllers (PLCs).<sup>[[1]](#references)</sup>

Η εργασία ασφάλειας σε αυτά τα περιβάλλοντα πρέπει να λαμβάνει υπόψη απαιτήσεις που διαφέρουν από τις συμβατικές IT, όπως η ασφάλεια διεργασιών, η αξιοπιστία, η διαθεσιμότητα, η ντετερμινιστική λειτουργία και οι κύκλοι ζωής του εξοπλισμού. Ένα τεχνικά έγκυρο security control μπορεί να είναι ακατάλληλο αν διαταράξει τη φυσική διεργασία, επομένως οι δοκιμές και η αποκατάσταση πρέπει να συντονίζονται με τον ιδιοκτήτη του συστήματος και το προσωπικό λειτουργίας.<sup>[[1]](#references)</sup>

Ένας συμβιβασμός ή μια τυχαία διαταραχή μπορεί να σταματήσει την παραγωγή, να προκαλέσει ζημιά στον εξοπλισμό, να απελευθερώσει επικίνδυνο υλικό, να βλάψει το περιβάλλον ή να προκαλέσει τραυματισμό και απώλεια ζωής. Αυτός ο πιθανός φυσικός αντίκτυπος είναι ο λόγος για τον οποίο η κατανόηση της ελεγχόμενης διεργασίας και των ασφαλών ορίων λειτουργίας της πρέπει να προηγείται οποιουδήποτε active testing.<sup>[[1]](#references)</sup>

Πολλές OT εγκαταστάσεις εξακολουθούν να χρησιμοποιούν legacy λειτουργικά συστήματα, εφαρμογές και πρωτόκολλα, επειδή ο εξοπλισμός έχει μεγάλη διάρκεια ζωής και οι αλλαγές απαιτούν δοκιμές λειτουργίας και ασφάλειας. Ορισμένα πρωτόκολλα σχεδιάστηκαν χωρίς σύγχρονο authentication ή encryption, ενώ το patching μπορεί να περιορίζεται από την υποστήριξη του προμηθευτή ή τα παράθυρα συντήρησης· όπου οι άμεσες αναβαθμίσεις δεν είναι εφικτές, η αντιστάθμιση πρέπει να γίνεται με segmentation, access control και monitoring.<sup>[[1]](#references)</sup>

## Προτεραιότητες αξιολόγησης

Ξεκινήστε κατανοώντας την ελεγχόμενη διεργασία, τα όρια του συστήματος, την τοπολογία του δικτύου, τα assets, τις ροές δεδομένων, τις σχέσεις εμπιστοσύνης και τις εξωτερικές συνδέσεις. Παρόμοιοι τύποι συσκευών μπορεί να εξυπηρετούν διαφορετικές λειτουργίες σε διαφορετικές εγκαταστάσεις, επομένως μην υποθέτετε ότι η αρχιτεκτονική ή το μοντέλο επιπτώσεων μιας εγκατάστασης ισχύει και για κάποια άλλη.<sup>[[1]](#references)</sup>

Προτιμήστε το passive discovery και την υπάρχουσα τεκμηρίωση μηχανικής, όπου είναι δυνατό. Κάθε active scanning ή exploitation πρέπει να ακολουθεί ένα εγκεκριμένο test plan που καθορίζει περιορισμούς ασφάλειας, παράθυρα συντήρησης, διαδικασίες ανάκτησης και συνθήκες διακοπής. Τα ευρήματα πρέπει να αξιολογούνται τόσο ως προς τον αντίκτυπο στην cybersecurity όσο και ως προς τις πιθανές επιπτώσεις στη φυσική διεργασία.<sup>[[1]](#references)</sup>

Η ίδια αρχιτεκτονική γνώση υποστηρίζει defensive δραστηριότητες, όπως asset inventory, network segmentation, monitoring, incident response και risk-based vulnerability management.<sup>[[1]](#references)</sup>
