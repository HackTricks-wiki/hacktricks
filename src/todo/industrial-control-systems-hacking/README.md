# 工业控制系统 Hacking

{{#include ../../banners/hacktricks-training.md}}

## 关于本节

本节介绍工业控制系统（ICS）的组件、架构、协议和安全评估方法。ICS 属于更广泛的运营技术（OT）领域：用于监控物理过程或使物理过程发生变化的可编程系统和设备。常见示例包括监控与数据采集（SCADA）系统、分布式控制系统（DCS）和可编程逻辑控制器（PLC）。<sup>[[1]](#references)</sup>

这些环境中的安全工作必须考虑不同于传统 IT 的要求，包括过程安全、可靠性、可用性、确定性运行以及设备生命周期。即使技术上有效的安全控制措施，如果会干扰物理过程，也可能不适用。因此，测试和修复工作应与系统所有者及运维人员协调进行。<sup>[[1]](#references)</sup>

系统遭到入侵或意外中断可能导致生产停止、设备损坏、危险材料泄漏、环境受损，或造成人员伤害和生命损失。正因为可能产生这种物理影响，在进行主动测试前，必须先了解受控过程及其安全运行限制。<sup>[[1]](#references)</sup>

许多 OT 部署仍保留旧版操作系统、应用程序和协议，因为设备使用寿命较长，而变更需要经过运行和安全测试。一些协议在设计时并未包含现代身份验证或加密机制；此外，厂商支持或维护窗口也可能限制补丁安装。在无法直接升级的情况下，应通过网络分段、访问控制和监控来弥补。<sup>[[1]](#references)</sup>

## 评估重点

首先了解受控过程、系统边界、网络拓扑、资产、数据流、信任关系和外部连接。相似的设备类型在不同站点可能承担不同功能，因此不要假设一个部署的架构或影响模型适用于另一个部署。<sup>[[1]](#references)</sup>

在可能的情况下，优先采用被动发现和现有工程文档。任何主动扫描或 exploitation 都应遵循经过批准的测试计划，其中明确安全限制、维护窗口、恢复流程和停止条件。评估发现时，既要考虑网络安全影响，也要考虑对物理过程可能造成的影响。<sup>[[1]](#references)</sup>

相同的架构知识也可支持资产清单、网络分段、监控、事件响应和基于风险的漏洞管理等防御活动。<sup>[[1]](#references)</sup>
