# Πληροφορίες σε εκτυπωτές

{{#include ../../banners/hacktricks-training.md}}

Ένας εκτυπωτής με αποθηκευμένα διαπιστευτήρια LDAP μπορεί να τα αποκαλύψει, αν αλλάξει η ρύθμιση του server του και στη συνέχεια πραγματοποιήσει authentication σε ένα κακόβουλο endpoint.<sup>[[2]](#references)</sup> Το αποτέλεσμα εξαρτάται από τη μέθοδο bind: ένα μη προστατευμένο simple bind αποκαλύπτει τον κωδικό πρόσβασης, ενώ ένα SASL challenge-response bind δεν τον αποκαλύπτει ως απλό κείμενο.<sup>[[8]](#references)</sup> Δείτε [LDAP authentication και ασφάλεια μεταφοράς](../../network-services-pentesting/pentesting-ldap.md#cleartext-credentials-and-tls-downgrade-risks).

Επίσης, αρκετοί εκτυπωτές περιέχουν **logs με usernames** ή μπορεί ακόμη και να μπορούν να **κατεβάσουν όλα τα usernames** από τον Domain Controller.

Όλες αυτές οι **ευαίσθητες πληροφορίες** και η συνηθισμένη **έλλειψη ασφάλειας** κάνουν τους εκτυπωτές πολύ ενδιαφέροντες για τους attackers.

## Ρύθμιση εκτυπωτή

- **Τοποθεσία**: Η λίστα LDAP server βρίσκεται συνήθως στο web interface (π.χ. *Network ➜ LDAP Setting ➜ Setting Up LDAP*).
- **Συμπεριφορά**: Πολλοί ενσωματωμένοι web server επιτρέπουν την τροποποίηση των LDAP server **χωρίς να απαιτείται η εκ νέου εισαγωγή διαπιστευτηρίων** (λειτουργία ευκολίας → κίνδυνος ασφάλειας).
- **Exploit**: Ανακατευθύνετε τη διεύθυνση του LDAP server σε έναν host που ελέγχει ο attacker και χρησιμοποιήστε το κουμπί *Test Connection* / *Address Book Sync* για να αναγκάσετε τον εκτυπωτή να κάνει bind σε εσάς.

## Συλλογή διαπιστευτηρίων

### Μέθοδος 1 – Netcat Listener

```bash
sudo nc -k -v -l -p 389     # Plain LDAP only
```

Ένα απλό BindRequest μπορεί να αποκαλύψει το bind DN και τον κωδικό πρόσβασης στη ροή BER, ακόμη κι αν ο server απορρίψει αργότερα τη σύνδεση. Μια ανώνυμη αναζήτηση ή μόνο η διαπραγμάτευση SASL δεν αποκαλύπτει τον αποθηκευμένο κωδικό πρόσβασης.<sup>[[8]](#references)</sup>

Ένας απλός listener `nc` στις θύρες 636/3269 βλέπει μια χειραψία TLS, όχι ένα bind LDAP. Το LDAPS απαιτεί endpoint με υποστήριξη TLS. Η επικύρωση πιστοποιητικού από μόνη της δεν εμποδίζει το pass-back, αν ο εκτυπωτής αποδέχεται αλλαγή hostname και το νέο endpoint διαθέτει έγκυρο πιστοποιητικό για αυτό το hostname· ο client πρέπει επίσης να περιορίζει ποιος server είναι εξουσιοδοτημένος να λάβει τα αποθηκευμένα διαπιστευτήρια.<sup>[[8]](#references)</sup>

### Μέθοδος 2 – Πλήρης Rogue LDAP server (συνιστάται)

Ένας εκτυπωτής μπορεί να απαιτεί έγκυρη απάντηση LDAP πριν επιχειρήσει bind.<sup>[[10]](#references)</sup> Ένας πλήρης LDAP server μπορεί να χειριστεί αυτή την προκαταρκτική ανταλλαγή, αλλά δεν μπορεί να κάνει έναν client που είναι δεσμευμένος σε ισχυρό μηχανισμό SASL ή στον προβλεπόμενο TLS server να αποκαλύψει τον κωδικό πρόσβασής του.<sup>[[8]](#references)[[10]](#references)</sup>

```bash
# Debian/Ubuntu example
sudo apt install slapd ldap-utils
sudo dpkg-reconfigure slapd   # use a base DN compatible with the printer lookup

# run slapd in foreground / debug 2
slapd -d 2 -h "ldap:///"      # only LDAP, no LDAPS
```

Αντιμετωπίστε μια αναζήτηση ως ένδειξη σύνδεσης, όχι ως απόδειξη αποκάλυψης κωδικού πρόσβασης. Ένας κωδικός πρόσβασης εκτίθεται μόνο αν ο client στείλει bind που περιέχει κωδικό πρόσβασης σε plaintext· ελέγξτε τον πραγματικό μηχανισμό bind και την κατάσταση TLS.<sup>[[8]](#references)</sup>

> 💡  Το Responder περιλαμβάνει rogue υπηρεσίες LDAP και SMB authentication. Ένα απλό LDAP bind μπορεί να εκθέσει τον διαμορφωμένο κωδικό πρόσβασης, ενώ το NTLM authentication παράγει υλικό challenge-response· μην περιγράφετε και τα δύο αποτελέσματα ως κωδικό πρόσβασης σε clear text.

### Επιλογή μηχανισμού SASL

Ορισμένοι LDAP clients εκτυπωτών επιλέγουν από τους μηχανισμούς που διαφημίζει ένας LDAP server.<sup>[[8]](#references)[[10]](#references)</sup> Η έρευνα έδειξε ότι ένας client που δέχεται έναν διαφημιζόμενο μηχανισμό SASL plaintext θα μπορούσε να στείλει έναν κωδικό πρόσβασης, ενώ η συνήθης διαπραγμάτευση NTLM θα απέδιδε μόνο δεδομένα challenge-response.<sup>[[9]](#references)[[10]](#references)</sup> Πρόκειται για **αστοχία πολιτικής client**, όχι για ιδιότητα όλων των SASL binds: ένας client που απαιτεί ισχυρότερο μηχανισμό ή κάνει pin τον προβλεπόμενο TLS server θα πρέπει αντί γι' αυτό να αποτυγχάνει με ασφάλεια.<sup>[[8]](#references)</sup> Το OpenLDAP απενεργοποιεί από προεπιλογή τους μηχανισμούς SASL που υποστηρίζουν plaintext, επομένως ένας daemon με τις προεπιλεγμένες ρυθμίσεις δεν αποδεικνύει ότι αυτή η συμπεριφορά υπάρχει σε έναν εκτυπωτή.<sup>[[11]](#references)</sup>

## Πρόσφατα τρωτά σημεία Pass-Back (2024-2025)

Το Pass-back *δεν* είναι θεωρητικό ζήτημα – οι προμηθευτές συνεχίζουν να δημοσιεύουν advisories το 2024/2025 που περιγράφουν ακριβώς αυτή την κατηγορία επίθεσης.

### Xerox VersaLink – CVE-2024-12510 & CVE-2024-12511

Το firmware ≤ 57.69.91 των MFP Xerox VersaLink C70xx επέτρεπε σε έναν authenticated admin (ή σε οποιονδήποτε, αν παρέμεναν τα προεπιλεγμένα διαπιστευτήρια) να:

* **CVE-2024-12510 – LDAP pass-back**: αλλάξει τη διεύθυνση του LDAP server και να προκαλέσει μια αναζήτηση, με αποτέλεσμα η συσκευή να κάνει leak τα διαμορφωμένα διαπιστευτήρια Windows προς τον host που ελέγχει ο επιτιθέμενος.
* **CVE-2024-12511 – SMB/FTP pass-back**: ίδιο ζήτημα μέσω προορισμών *scan-to-folder*, με διαρροή διαπιστευτηρίων NetNTLMv2 ή FTP σε clear text.<sup>[[2]](#references)</sup>

Ένας απλός listener όπως:

```bash
sudo nc -k -v -l -p 389     # capture LDAP bind
```

ή ένας κακόβουλος SMB server (`impacket-smbserver`) αρκεί για την υποκλοπή των διαπιστευτηρίων.  

### Canon imageRUNNER / imageCLASS – Συμβουλευτική ανακοίνωση, 20 Μαΐου 2025

Η Canon επιβεβαίωσε μια ευπάθεια **SMTP/LDAP pass-back** σε δεκάδες σειρές προϊόντων Laser & MFP. Ένας εισβολέας με πρόσβαση διαχειριστή μπορεί να τροποποιήσει τη διαμόρφωση του server και να ανακτήσει τα αποθηκευμένα διαπιστευτήρια για LDAP **ή** SMTP (πολλοί οργανισμοί χρησιμοποιούν προνομιούχο λογαριασμό για τη λειτουργία σάρωσης προς email).<sup>[[3]](#references)</sup>

Οι οδηγίες του κατασκευαστή συνιστούν ρητά:

1. Ενημέρωση στο διορθωμένο firmware μόλις γίνει διαθέσιμο.
2. Χρήση ισχυρών, μοναδικών κωδικών πρόσβασης διαχειριστή.
3. Αποφυγή χρήσης προνομιούχων λογαριασμών AD για την ενσωμάτωση εκτυπωτών.

### Συσκευές Brother και παραλλαγές OEM – πρόσβαση διαχειριστή βάσει σειριακού αριθμού σε διαπιστευτήρια υπηρεσιών

Μια συντονισμένη αποκάλυψη του 2025 παρουσίασε μια ιδιαίτερα χρήσιμη αλυσίδα επίθεσης σε επηρεαζόμενες συσκευές Brother· μέρος του συνόλου ευπαθειών επηρεάζει επίσης μοντέλα OEM, επομένως επαληθεύστε το ακριβές μοντέλο με βάση τη συμβουλευτική ανακοίνωση του κατασκευαστή του. Ένας μη πιστοποιημένος εισβολέας μπορεί να αποκτήσει τον σειριακό αριθμό της συσκευής μέσω HTTP/HTTPS/IPP σε ευάλωτο firmware, ενώ οι σειριακοί αριθμοί μπορεί επίσης να είναι διαθέσιμοι μέσω πρωτοκόλλων διαχείρισης όπως SNMP ή PJL. Αν ο εργοστασιακός κωδικός πρόσβασης δεν έχει αλλάξει ποτέ, ο σειριακός αριθμός επιτρέπει τον ντετερμινιστικό υπολογισμό του κωδικού πρόσβασης διαχειριστή. Μετά την πιστοποίηση, η ξεχωριστή ευπάθεια pass-back CVE-2024-51984 εκθέτει σε απλό κείμενο τους κωδικούς πρόσβασης για εξωτερικές υπηρεσίες που έχουν διαμορφωθεί, όπως LDAP ή FTP, μετατρέποντας την πρόσβαση στη διαχείριση του εκτυπωτή σε επαναχρησιμοποιήσιμα διαπιστευτήρια δικτύου. Το firmware διορθώνει την αποκάλυψη κωδικών πρόσβασης υπηρεσιών, αλλά για συσκευές που έχουν ήδη κατασκευαστεί, ο χειριστής πρέπει να αντικαταστήσει τον αρχικό κωδικό πρόσβασης διαχειριστή που προκύπτει από τον σειριακό αριθμό.<sup>[[6]](#references)</sup>

Η τρέχουσα έκδοση του Metasploit περιλαμβάνει ένα auxiliary module που εντοπίζει τον σειριακό αριθμό μέσω HTTP, SNMP ή PJL, δημιουργεί έναν πιθανό αρχικό κωδικό πρόσβασης και προαιρετικά τον επαληθεύει στην web console. Το `DiscoverSerialVia=AUTO` δοκιμάζει τις υποστηριζόμενες μεθόδους εντοπισμού· χρησιμοποιήστε αντ’ αυτού το `TargetSerial` όταν ο σειριακός αριθμός περιλαμβάνεται ήδη στο μητρώο των συσκευών.<sup>[[7]](#references)</sup>

```text
msfconsole -q
use auxiliary/admin/misc/brother_default_admin_auth_bypass_cve_2024_51978
set RHOSTS <printer-ip>
set DiscoverSerialVia AUTO
run
```

Χρησιμοποιήστε το αποτέλεσμα μόνο για την επικύρωση εξουσιοδοτημένων συστημάτων. Το αν λειτουργεί ο κωδικός πρόσβασης εξαρτάται από το ακριβές μοντέλο και, κυρίως, από το αν έχει ήδη αλλάξει ο εργοστασιακός κωδικός πρόσβασης διαχειριστή.<sup>[[6]](#references)[[7]](#references)</sup>

## Ενίσχυση Ασφάλειας & Ανίχνευση

1. **Εφαρμόζετε ενημερώσεις κώδικα / ενημερώνετε το firmware** των MFPs άμεσα (ελέγχετε τα δελτία PSIRT των προμηθευτών).
2. **Αντικαθιστάτε τους εργοστασιακούς κωδικούς πρόσβασης διαχειριστή** – το firmware από μόνο του δεν καταργεί τους αρχικούς κωδικούς πρόσβασης που παράγονται από τον σειριακό αριθμό σε συσκευές Brother/OEM που κατασκευάστηκαν προηγουμένως και επηρεάζονται.<sup>[[6]](#references)</sup>
3. **Λογαριασμοί υπηρεσιών με ελάχιστα δικαιώματα** – μη χρησιμοποιείτε ποτέ Domain Admin για LDAP/SMB/SMTP· περιορίστε την πρόσβαση σε OU μόνο για ανάγνωση.
4. **Περιορίζετε την πρόσβαση διαχείρισης** – τοποθετήστε τις διεπαφές ιστού/IPP/SNMP του εκτυπωτή σε VLAN διαχείρισης ή πίσω από ACL/VPN.
5. **Περιορίστε την εξερχόμενη κίνηση του εκτυπωτή** – επιτρέψτε σε κάθε συσκευή να επικοινωνεί μόνο με τους αναμενόμενους προορισμούς DC/LDAP, αλληλογραφίας, DNS/NTP, εκτύπωσης και αρχείων σάρωσης. Το Pass-Back απαιτεί callback σε endpoint που επιλέγει ο επιτιθέμενος.
6. **Απενεργοποιείτε τα μη χρησιμοποιούμενα πρωτόκολλα** – FTP, Telnet, raw-9100, παλαιότερα SSL ciphers.
7. **Ενεργοποιείτε την καταγραφή ελέγχου** – ορισμένες συσκευές μπορούν να καταγράφουν αποτυχίες LDAP/SMTP μέσω syslog· συσχετίζετε μη αναμενόμενα binds.
8. **Παρακολουθείτε τους προορισμούς ελέγχου ταυτότητας** – δημιουργείτε ειδοποίηση όταν ένας εκτυπωτής ξεκινά σύνδεση LDAP, SMB, SMTP ή FTP προς host εκτός της allowlist του, ειδικά αμέσως μετά από σύνδεση διαχείρισης ή αλλαγή ρύθμισης.
9. **SNMPv3 ή απενεργοποίηση του SNMP** – η κοινότητα `public` συχνά διαρρέει πληροφορίες συσκευής και σειριακού αριθμού.
