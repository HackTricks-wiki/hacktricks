# Інформація у принтерах

{{#include ../../banners/hacktricks-training.md}}

Принтер зі збереженими обліковими даними LDAP може їх розкрити, якщо змінити налаштування сервера, після чого принтер автентифікується на підробленому кінцевому вузлі.<sup>[[2]](#references)</sup> Результат залежить від методу прив’язки: незахищена проста прив’язка розкриває пароль, тоді як прив’язка SASL із відповіддю на виклик не розкриває його у відкритому тексті.<sup>[[8]](#references)</sup> Див. [Автентифікація LDAP і безпека транспорту](../../network-services-pentesting/pentesting-ldap.md#cleartext-credentials-and-tls-downgrade-risks).

Крім того, на багатьох принтерах зберігаються **журнали з іменами користувачів**, або ж вони можуть **завантажувати всі імена користувачів** із контролера домену.

Уся ця **конфіденційна інформація** та поширена **відсутність безпеки** роблять принтери дуже привабливими для зловмисників.

## Налаштування принтера

- **Розташування**: список серверів LDAP зазвичай можна знайти у вебінтерфейсі (наприклад, *Мережа ➜ Налаштування LDAP ➜ Налаштування LDAP*).
- **Поведінка**: багато вбудованих вебсерверів дають змогу змінювати сервер LDAP **без повторного введення облікових даних** (зручність → ризик для безпеки).
- **Експлуатація**: перенаправте адресу сервера LDAP на контрольований зловмисником хост і натисніть кнопку *Перевірити з’єднання* / *Синхронізувати адресну книгу*, щоб змусити принтер виконати прив’язку до вас.

## Перехоплення облікових даних

### Метод 1 – Слухач Netcat

```bash
sudo nc -k -v -l -p 389     # Plain LDAP only
```

Простий BindRequest може розкрити bind DN і пароль у потоці BER, навіть якщо сервер згодом відхилить вхід. Сам по собі анонімний пошук або узгодження SASL не розкриває збережений пароль.<sup>[[8]](#references)</sup>

Звичайний прослуховувач `nc` на порту 636/3269 бачить TLS-handshake, а не LDAP bind. Для LDAPS потрібна кінцева точка з підтримкою TLS. Сама лише перевірка сертифіката не запобігає pass-back, якщо принтер приймає зміну імені хоста, а нова кінцева точка має дійсний сертифікат для цього імені; клієнт також має обмежувати перелік серверів, яким дозволено отримувати збережені облікові дані.<sup>[[8]](#references)</sup>

### Метод 2 – Повноцінний rogue LDAP-сервер (рекомендовано)

Принтер може вимагати дійсну відповідь LDAP, перш ніж спробує виконати bind.<sup>[[10]](#references)</sup> Повноцінний LDAP-сервер може обробити цей попередній обмін, але він не змусить клієнта, прив’язаного до надійного механізму SASL або заданого TLS-сервера, розкрити пароль.<sup>[[8]](#references)[[10]](#references)</sup>

```bash
# Debian/Ubuntu example
sudo apt install slapd ldap-utils
sudo dpkg-reconfigure slapd   # use a base DN compatible with the printer lookup

# run slapd in foreground / debug 2
slapd -d 2 -h "ldap:///"      # only LDAP, no LDAPS
```

Розглядайте lookup як свідчення з’єднання, а не як доказ розкриття пароля. Пароль стає доступним лише тоді, коли клієнт надсилає bind із паролем у відкритому тексті; перевірте фактичний механізм bind і стан TLS.<sup>[[8]](#references)</sup>

> 💡  Responder містить шахрайські служби автентифікації LDAP і SMB. Простий LDAP bind може розкрити налаштований пароль, тоді як автентифікація NTLM надає матеріал challenge-response; не описуйте обидва результати як пароль у відкритому тексті.

### Вибір механізму SASL

Деякі LDAP-клієнти принтерів обирають один із механізмів, які рекламує LDAP-сервер.<sup>[[8]](#references)[[10]](#references)</sup> Дослідження показало, що клієнт, готовий прийняти рекламований механізм SASL із передаванням даних у відкритому тексті, може надіслати пароль, тоді як за звичайного узгодження NTLM він надав би лише дані challenge-response.<sup>[[9]](#references)[[10]](#references)</sup> Це **помилка політики клієнта**, а не властивість усіх SASL bind: клієнт, який вимагає надійніший механізм або закріплює сертифікат належного TLS-сервера, натомість має безпечно відмовити в з’єднанні.<sup>[[8]](#references)</sup> OpenLDAP за замовчуванням вимикає механізми SASL, що можуть передавати дані у відкритому тексті, тому стандартний демон не доводить наявності такої поведінки на принтері.<sup>[[11]](#references)</sup>

## Нещодавні вразливості Pass-Back (2024-2025)

Pass-back — це *не* теоретична проблема: у 2024/2025 роках постачальники й далі публікують рекомендації, що точно описують цей клас атак.

### Xerox VersaLink – CVE-2024-12510 і CVE-2024-12511

Прошивки версії ≤ 57.69.91 для МФП Xerox VersaLink C70xx дозволяли автентифікованому адміністратору (або будь-кому, якщо залишилися облікові дані за замовчуванням):

* **CVE-2024-12510 – LDAP pass-back**: змінити адресу LDAP-сервера й запустити lookup, через що пристрій надсилав налаштовані облікові дані Windows на контрольований зловмисником хост.
* **CVE-2024-12511 – SMB/FTP pass-back**: та сама проблема через призначення *scan-to-folder*, що розкривала облікові дані NetNTLMv2 або FTP у відкритому тексті.<sup>[[2]](#references)</sup>

Простий listener, наприклад:

```bash
sudo nc -k -v -l -p 389     # capture LDAP bind
```

або шахрайського SMB-сервера (`impacket-smbserver`) достатньо, щоб викрасти облікові дані.

### Canon imageRUNNER / imageCLASS – рекомендації від 20 травня 2025 року

Canon підтвердила вразливість **SMTP/LDAP pass-back** у десятках лінійок лазерних і багатофункціональних пристроїв. Зловмисник із правами адміністратора може змінити конфігурацію сервера й отримати збережені облікові дані LDAP **або** SMTP (багато організацій використовують привілейований обліковий запис для функції сканування й надсилання поштою).<sup>[[3]](#references)</sup>

У рекомендаціях виробника прямо зазначено:

1. Щойно стане доступна, встановити виправлену прошивку.
2. Використовувати надійні й унікальні паролі адміністратора.
3. Не використовувати привілейовані облікові записи AD для інтеграції принтерів.

### Пристрої Brother і OEM-варіанти – доступ до облікових даних служб за серійним номером

У ході скоординованого розкриття вразливостей у 2025 році було продемонстровано особливо корисний ланцюжок атак на вразливих пристроях Brother; частина набору вразливостей також стосується OEM-моделей, тому перевірте точну модель за рекомендаціями її виробника. На вразливій прошивці зловмисник без автентифікації може отримати серійний номер пристрою через HTTP/HTTPS/IPP, а серійні номери можуть бути доступні також через протоколи керування, як-от SNMP або PJL. Якщо заводський пароль не змінили, серійний номер дає змогу однозначно визначити пароль адміністратора. Після автентифікації окрема вразливість pass-back CVE-2024-51984 розкриває налаштовані паролі зовнішніх служб, як-от LDAP або FTP, у відкритому тексті, перетворюючи доступ до керування принтером на придатні для повторного використання мережеві облікові дані. Прошивка усуває розкриття паролів служб, але для пристроїв, виготовлених раніше, оператору все одно потрібно замінити початковий пароль адміністратора, який визначається за серійним номером.<sup>[[6]](#references)</sup>

У поточній версії Metasploit є допоміжний модуль, який знаходить серійний номер через HTTP, SNMP або PJL, генерує можливий початковий пароль і, за бажанням, перевіряє його через вебконсоль. `DiscoverSerialVia=AUTO` пробує доступні способи виявлення; якщо серійний номер уже є в інвентарі пристроїв, замість цього вкажіть `TargetSerial`.<sup>[[7]](#references)</sup>

```text
msfconsole -q
use auxiliary/admin/misc/brother_default_admin_auth_bypass_cve_2024_51978
set RHOSTS <printer-ip>
set DiscoverSerialVia AUTO
run
```

Використовуйте результат лише для перевірки авторизованих ресурсів. Чи спрацює пароль, залежить від точної моделі та, що особливо важливо, від того, чи було вже змінено заводський пароль адміністратора.<sup>[[6]](#references)[[7]](#references)</sup>

## Інструменти автоматизованого переліку та експлуатації

| Інструмент | Призначення | Приклад |
|------|---------|---------|
| **PRET** (Printer Exploitation Toolkit) | Зловживання PostScript/PJL/PCL, доступ до файлової системи, перевірка облікових даних за замовчуванням, *виявлення SNMP*; див. [оцінювання PJL](../../network-services-pentesting/9100-pjl.md) | `python pret.py 192.168.1.50 pjl` |
| **Praeda** | Збір конфігурації (зокрема адресних книг і облікових даних LDAP) через HTTP/HTTPS | `perl praeda.pl -t 192.168.1.50` |
| **Responder / ntlmrelayx** | Запуск підроблених служб автентифікації та перехоплення/ретрансляція NetNTLM через зворотні виклики SMB | `sudo responder -I eth0 -v` |
| **Модуль Metasploit для Brother** | Виявлення серійного номера, визначення можливого заводського пароля адміністратора та перевірка доступу до вебконсолі | `use auxiliary/admin/misc/brother_default_admin_auth_bypass_cve_2024_51978` |

## Посилення захисту та виявлення

1. **Встановлюйте виправлення / оновлюйте прошивку** MFP своєчасно (перевіряйте бюлетені PSIRT виробників).
2. **Замініть заводські паролі адміністратора** — сама прошивка не видаляє початкові паролі, що визначаються за серійним номером, на раніше виготовлених пристроях Brother/OEM, які зазнали впливу вразливості.<sup>[[6]](#references)</sup>
3. **Облікові записи служб із мінімальними привілеями** — ніколи не використовуйте Domain Admin для LDAP/SMB/SMTP; обмежуйте доступ до OU лише для *читання*.
4. **Обмежте доступ до керування** — розмістіть вебінтерфейси принтера/IPP/SNMP у VLAN керування або за ACL/VPN.
5. **Обмежте вихідний трафік принтера** — дозвольте кожному пристрою з’єднуватися лише з очікуваними адресами DC/LDAP, пошти, DNS/NTP, друку та файлових ресурсів сканування. Для Pass-back потрібен зворотний виклик на кінцеву точку, вибрану зловмисником.
6. **Вимкніть невикористовувані протоколи** — FTP, Telnet, raw-9100, застарілі шифри SSL.
7. **Увімкніть аудит** — деякі пристрої можуть надсилати помилки LDAP/SMTP до syslog; зіставляйте неочікувані прив’язки.
8. **Відстежуйте адресати автентифікації** — надсилайте сповіщення, коли принтер ініціює LDAP, SMB, SMTP або FTP-з’єднання з вузлом поза списком дозволених адрес, особливо одразу після входу в інтерфейс керування або зміни конфігурації.
9. **Використовуйте SNMPv3 або вимкніть SNMP** — спільнота `public` часто спричиняє витік відомостей про пристрій і його серійний номер.
