# Інформація в принтерах

{{#include ../../banners/hacktricks-training.md}}

В Інтернеті є кілька блогів, які **висвітлюють небезпеку використання принтерами LDAP із типовими/слабкими** обліковими даними для входу.  \
Це пов’язано з тим, що зловмисник може **обманом змусити принтер пройти автентифікацію на шахрайському LDAP-сервері** (зазвичай достатньо `nc -vv -l -p 389` або `slapd -d 2`) і перехопити **облікові дані принтера у відкритому вигляді**.

Крім того, деякі принтери зберігають **журнали з іменами користувачів** або навіть можуть **завантажити всі імена користувачів** із контролера домену.

Уся ця **чутлива інформація** та поширена **відсутність захисту** роблять принтери дуже цікавими для зловмисників.

## Налаштування принтера

- **Розташування**: список LDAP-серверів зазвичай можна знайти у вебінтерфейсі (наприклад, *Мережа ➜ Налаштування LDAP ➜ Налаштування LDAP*).
- **Поведінка**: багато вбудованих вебсерверів дають змогу змінювати LDAP-сервер **без повторного введення облікових даних** (зручність використання → ризик для безпеки).
- **Експлуатація**: перенаправте адресу LDAP-сервера на контрольований зловмисником вузол і скористайтеся кнопкою *Перевірити з’єднання* / *Синхронізувати адресну книгу*, щоб змусити принтер виконати bind-запит до вас.

---

## Перехоплення облікових даних

### Метод 1 – Netcat Listener

```bash
sudo nc -k -v -l -p 389     # Plain LDAP only
```

Невеликі/старі MFP можуть надсилати простий *simple-bind*, у якому DN прив’язки та пароль видно в необробленому потоці BER. Сучасні пристрої зазвичай спочатку виконують анонімний запит, а потім намагаються виконати прив’язку, тому результати різняться.<sup>[[1]](#references)</sup>

Звичайний слухач `nc` на портах 636/3269 отримує лише TLS-шифротекст; для тестування LDAPS потрібна кінцева точка LDAP із підтримкою TLS, а перенаправлення має завершитися невдало, якщо пристрій правильно перевіряє сертифікат сервера.

### Метод 2 – Повноцінний Rogue LDAP server (рекомендовано)

Оскільки багато пристроїв виконують анонімний пошук *перед* автентифікацією, запуск справжнього демона LDAP дає набагато надійніші результати:<sup>[[1]](#references)</sup>

```bash
# Debian/Ubuntu example
sudo apt install slapd ldap-utils
sudo dpkg-reconfigure slapd   # set any base-DN – it will not be validated

# run slapd in foreground / debug 2
slapd -d 2 -h "ldap:///"      # only LDAP, no LDAPS
```

Коли принтер виконує пошук, ви побачите облікові дані у відкритому вигляді у виводі налагодження.

> 💡 Responder містить підроблені служби автентифікації LDAP і SMB. Простий bind LDAP може розкрити налаштований пароль, тоді як автентифікація NTLM надає матеріал challenge-response; не описуйте обидва результати як пароль у відкритому вигляді.

## Нещодавні вразливості Pass-Back (2024-2025)

Pass-back — це *не* теоретична проблема: у 2024/2025 роках постачальники й далі публікують рекомендації, що точно описують цей клас атак.

### Xerox VersaLink — CVE-2024-12510 і CVE-2024-12511

Прошивка версії ≤ 57.69.91 для БФП Xerox VersaLink C70xx дозволяла автентифікованому адміністратору (або будь-кому, якщо залишилися облікові дані за замовчуванням):

* **CVE-2024-12510 — LDAP pass-back**: змінити адресу сервера LDAP і запустити пошук, унаслідок чого пристрій передасть налаштовані облікові дані Windows на контрольований зловмисником хост.
* **CVE-2024-12511 — SMB/FTP pass-back**: та сама проблема через призначення *сканування в папку*, що призводить до витоку NetNTLMv2 або облікових даних FTP у відкритому вигляді.<sup>[[2]](#references)</sup>

Наприклад, простий listener:

```bash
sudo nc -k -v -l -p 389     # capture LDAP bind
```

або rogue SMB server (`impacket-smbserver`) достатньо, щоб зібрати облікові дані.  

### Canon imageRUNNER / imageCLASS – рекомендації від 20 травня 2025 року

Canon підтвердила наявність вразливості **SMTP/LDAP pass-back** у десятках лінійок лазерних принтерів і БФП. Зловмисник із правами адміністратора може змінити конфігурацію сервера й отримати збережені облікові дані LDAP **або** SMTP (багато організацій використовують привілейований обліковий запис для надсилання сканів електронною поштою).<sup>[[3]](#references)</sup>

Виробник прямо рекомендує:

1. Щойно стане доступна, встановити прошивку з виправленням.
2. Використовувати надійні унікальні паролі адміністратора.
3. Не використовувати привілейовані облікові записи AD для інтеграції принтера.

### Пристрої Brother і варіанти OEM – отримання доступу адміністратора та облікових даних служб на основі серійного номера

У межах скоординованого розкриття вразливостей у 2025 році було продемонстровано особливо корисний ланцюжок атак на вразливих пристроях Brother. Частина набору вразливостей також зачіпає моделі OEM, тому перевірте точну модель за рекомендаціями її виробника. На вразливій прошивці неавтентифікований зловмисник може отримати серійний номер пристрою через HTTP/HTTPS/IPP; крім того, серійні номери можуть бути доступні через протоколи керування, як-от SNMP або PJL. Якщо заводський пароль не змінювали, за серійним номером можна однозначно обчислити пароль адміністратора. Після автентифікації окрема вразливість pass-back CVE-2024-51984 розкриває у відкритому вигляді налаштовані паролі зовнішніх служб, як-от LDAP або FTP, перетворюючи доступ до керування принтером на облікові дані мережі, придатні для повторного використання. Прошивка усуває розкриття паролів служб, але на вже виготовлених пристроях оператору все одно потрібно замінити початковий пароль адміністратора, похідний від серійного номера.<sup>[[6]](#references)</sup>

У поточній версії Metasploit є допоміжний модуль, який виявляє серійний номер через HTTP, SNMP або PJL, генерує можливий початковий пароль і за бажанням перевіряє його у вебконсолі. `DiscoverSerialVia=AUTO` перебирає підтримувані способи виявлення; якщо серійний номер уже є в інвентарі активів, замість цього вкажіть `TargetSerial`.<sup>[[7]](#references)</sup>

```text
msfconsole -q
use auxiliary/admin/misc/brother_default_admin_auth_bypass_cve_2024_51978
set RHOSTS <printer-ip>
set DiscoverSerialVia AUTO
run
```

Використовуйте результат лише для перевірки авторизованих активів. Чи спрацює пароль, залежить від конкретної моделі та, що особливо важливо, від того, чи змінювали заводський пароль адміністратора.<sup>[[6]](#references)[[7]](#references)</sup>

## Інструменти автоматизованого перерахування / експлуатації

| Інструмент | Призначення | Приклад |
|------|---------|---------|
| **PRET** (Printer Exploitation Toolkit) | Зловживання PostScript/PJL/PCL, доступ до файлової системи, перевірка облікових даних за замовчуванням, *виявлення SNMP* | `python pret.py 192.168.1.50 pjl` |
| **Praeda** | Збір конфігурації (зокрема адресних книг і облікових даних LDAP) через HTTP/HTTPS | `perl praeda.pl -t 192.168.1.50` |
| **Responder / ntlmrelayx** | Запуск підроблених служб автентифікації та перехоплення/ретрансляція NetNTLM через зворотні підключення SMB | `sudo responder -I eth0 -v` |
| **Модуль Brother auxiliary у Metasploit** | Виявлення серійного номера, обчислення ймовірного заводського пароля адміністратора та перевірка доступу до вебконсолі | `use auxiliary/admin/misc/brother_default_admin_auth_bypass_cve_2024_51978` |

## Посилення захисту та виявлення

1. **Встановлюйте виправлення / оновлюйте прошивку** MFP без зволікань (перевіряйте бюлетені PSIRT виробника).
2. **Замініть заводські паролі адміністратора** — сама прошивка не видаляє початкові паролі, обчислені за серійним номером, на раніше виготовлених уразливих пристроях Brother/OEM.<sup>[[6]](#references)</sup>
3. **Облікові записи служб із мінімальними привілеями** — ніколи не використовуйте Domain Admin для LDAP/SMB/SMTP; обмежте доступ лише *для читання* потрібними областями OU.
4. **Обмежте доступ до керування** — розмістіть вебінтерфейси принтерів та інтерфейси IPP/SNMP в окремій VLAN керування або за ACL/VPN.
5. **Обмежте вихідний трафік принтерів** — дозвольте кожному пристрою з’єднуватися лише з очікуваними адресами DC/LDAP, пошти, DNS/NTP, друку та сканування у файли. Для Pass-Back потрібне зворотне підключення до вибраної зловмисником кінцевої точки.
6. **Вимкніть невикористовувані протоколи** — FTP, Telnet, raw-9100, старі набори шифрів SSL.
7. **Увімкніть журналювання аудиту** — деякі пристрої можуть надсилати помилки LDAP/SMTP у syslog; зіставляйте неочікувані прив’язки.
8. **Відстежуйте адресати автентифікації** — створюйте сповіщення, коли принтер ініціює LDAP, SMB, SMTP або FTP-з’єднання з вузлом поза списком дозволених, особливо одразу після входу до інтерфейсу керування або зміни конфігурації.
9. **Використовуйте SNMPv3 або вимкніть SNMP** — спільнота `public` часто розкриває відомості про пристрій і його серійний номер.
