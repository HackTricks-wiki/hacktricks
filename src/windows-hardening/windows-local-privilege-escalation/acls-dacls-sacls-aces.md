## **Access Control List (ACL)**

Access Control List (ACL) は、オブジェクトとそのプロパティに対する保護を定める Access Control Entries (ACEs) の順序付きセットです。つまり ACL は、特定のオブジェクトに対して、どのセキュリティプリンシパル（ユーザーまたはグループ）がどの操作を許可または拒否されるかを定義します。

ACL には 2 種類あります。

- **Discretionary Access Control List (DACL):** オブジェクトへのアクセスを許可される、または許可されないユーザーとグループを指定します。
- **System Access Control List (SACL):** オブジェクトへのアクセス試行の監査を管理します。

ファイルにアクセスする際、システムはオブジェクトのセキュリティ記述子とユーザーの access token を照合し、アクセスを許可するかどうか、および ACEs に基づいてどの範囲のアクセスを許可するかを判断します。<sup>[[1]](#references)</sup>

親ディレクトリが Full Control を許可していても、子ファイルが読み取りを拒否する場合は、**子ファイル自体の**有効な DACL、所有者、継承を個別に確認してください。そのファイルの DACL を変更するには、ファイルに対する `WRITE_DAC` または該当する所有者権限が必要です。[Microsoft は `WRITE_DAC` を定義し](https://learn.microsoft.com/en-us/windows/win32/secauthz/standard-access-rights)、[所有者が暗黙的に持つアクセス権を説明しています](https://learn.microsoft.com/en-us/windows/win32/secauthz/owner-of-a-new-object)。親ディレクトリの権限だけでは、子ファイルを読み取れることや、その DACL を変更できることの根拠にはなりません。

### **主な構成要素**

- **DACL:** オブジェクトに対するアクセス権をユーザーやグループに許可または拒否する ACEs を含みます。基本的に、アクセス権を定める主要な ACL です。
- **SACL:** オブジェクトへのアクセスを監査するために使用されます。ACEs は、Security Event Log に記録するアクセスの種類を定義します。不正なアクセス試行の検出やアクセス問題のトラブルシューティングに非常に役立ちます。<sup>[[1]](#references)</sup>

### **ACL とシステムの連携**

各ユーザーセッションには、そのセッションに関連するセキュリティ情報（ユーザーやグループの ID、権限など）を含む access token が関連付けられています。この token には、セッションを一意に識別する logon SID も含まれます。

Local Security Authority (LSASS) は、アクセスを試みるセキュリティプリンシパルに一致する ACEs が DACL にあるかを調べ、オブジェクトへのアクセス要求を処理します。該当する ACEs がなければ、アクセスは直ちに許可されます。それ以外の場合、LSASS は ACEs と access token 内のセキュリティプリンシパルの SID を照合し、アクセスが許可されるかどうかを判断します。<sup>[[1]](#references)</sup>

### **処理の概要**

- **ACLs:** DACLs でアクセス権を、SACLs で監査ルールを定義します。
- **Access Token:** セッションのユーザー、グループ、権限に関する情報を含みます。
- **アクセス判断:** DACL の ACEs と access token を照合して行います。SACLs は監査に使用されます。<sup>[[1]](#references)</sup>

### ACEs

Access Control Entries (ACEs) には、主に**次の 3 種類があります**。<sup>[[1]](#references)</sup>

- **Access Denied ACE**: DACL 内で、指定されたユーザーまたはグループによるオブジェクトへのアクセスを明示的に拒否します。
- **Access Allowed ACE**: DACL 内で、指定されたユーザーまたはグループによるオブジェクトへのアクセスを明示的に許可します。
- **System Audit ACE**: System Access Control List (SACL) 内に配置され、ユーザーまたはグループによるオブジェクトへのアクセス試行時に監査ログを生成します。アクセスが許可されたか拒否されたか、およびアクセスの種類を記録します。

各 ACE には、重要な要素が**4 つあります**。<sup>[[1]](#references)</sup>

1. ユーザーまたはグループの **Security Identifier (SID)**（または、グラフィカルな表示でのプリンシパル名）。
2. ACE の種類（アクセス拒否、アクセス許可、またはシステム監査）を識別する **flag**。
3. 子オブジェクトが親から ACE を継承できるかを定める **Inheritance flags**。
4. オブジェクトに付与する権限を指定する 32 ビット値の [**access mask**](https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-dtyp/7a53f60e-e730-4dfe-bbe9-b21b62eb790b?redirectedfrom=MSDN)。

アクセスの可否は、次のいずれかに該当するまで各 ACE を順番に調べて判断します。<sup>[[1]](#references)</sup>

- access token 内で識別された trustee に対し、要求された権限を **Access-Denied ACE** が明示的に拒否する。
- access token 内の trustee に対し、**Access-Allowed ACE(s)** が要求されたすべての権限を明示的に許可する。
- すべての ACEs を確認しても、要求された権限のいずれかが**明示的に許可されていない**場合、アクセスは暗黙的に**拒否**される。

### ACEs の順序

**ACEs**（何に誰がアクセスできるかを定めるルール）を **DACL** 内にどのように並べるかは非常に重要です。システムはこれらのルールに基づいてアクセスを許可または拒否すると、残りのルールを確認しないためです。<sup>[[1]](#references)</sup>

ACEs の最適な並べ方は **「canonical order」** と呼ばれます。この方法により、処理がスムーズかつ適切に行われます。**Windows 2000** や **Windows Server 2003** などのシステムでは、次のように並べます。

- まず、親フォルダーなど別の場所から継承されたルールよりも、**このオブジェクトに固有の**ルールを先に配置します。
- 固有のルールの中では、**「拒否」**するルールを**「許可」**するルールより先に配置します。
- 継承されたルールは、**最も近い親**からのものを先にし、そこから順に配置します。この場合も、**「拒否」**を**「許可」**より先に配置します。

この順序には、主に 2 つの利点があります。

- 他の**「許可」**ルールが存在しても、明示的な**「拒否」**が優先されます。
- 親フォルダーなどから継承されたルールが適用される前に、オブジェクトの所有者がアクセス権を**最終的に決定**できます。

このように設定すれば、ファイルやフォルダーの所有者は誰にアクセスを許可するかを正確に指定し、許可すべきユーザーにはアクセスを許可し、それ以外には拒否できます。

![NTFS access control entry の順序を示す図](https://www.ntfs.com/images/screenshots/ACEs.gif)

このように **「canonical order」** は、オブジェクト固有のルールを先に配置し、アクセスルールを適切に整理して、明確かつ正しく機能させるためのものです。

### アクセス制御を簡単に説明

フォルダーなどのリソースへのアクセスを管理するには、Access Control Lists (ACLs) と Access Control Entries (ACEs) と呼ばれるリストやルールを使用します。これらは、特定のデータに誰がアクセスできるか、できないかを定義します。<sup>[[1]](#references)</sup>

#### 特定のグループによるアクセスを拒否する

Cost という名前のフォルダーがあり、マーケティングチーム以外の全員にアクセスを許可したいとします。ルールを適切に設定すれば、他の全員にアクセスを許可する前に、マーケティングチームのアクセスを明示的に拒否できます。そのためには、全員にアクセスを許可するルールよりも前に、マーケティングチームのアクセスを拒否するルールを配置します。

#### 拒否対象のグループに属する特定のメンバーにアクセスを許可する

マーケティングディレクターの Bob は、マーケティングチーム全般にはアクセスを許可しない場合でも、Cost フォルダーへのアクセスが必要だとします。Bob のアクセスを許可する特定のルール（ACE）を追加し、マーケティングチームのアクセスを拒否するルールより前に配置できます。これにより、チーム全体に制限が適用されていても、Bob はアクセスできます。

#### Access Control Entries を理解する

ACEs は ACL 内の個々のルールです。ユーザーやグループを識別し、許可または拒否するアクセスの内容を指定し、サブアイテムへのルールの適用方法（継承）を定めます。ACEs には主に 2 種類あります。

- **Generic ACEs**: すべての種類のオブジェクトに広く適用するか、コンテナー（フォルダーなど）と非コンテナー（ファイルなど）を区別するだけのルールです。たとえば、フォルダーの内容を見ることは許可する一方で、その中のファイルへのアクセスは許可しないルールです。
- **Object-Specific ACEs**: より細かな制御を実現します。特定の種類のオブジェクトや、オブジェクト内の個々のプロパティにルールを設定できます。たとえば、ユーザーのディレクトリで、電話番号の更新は許可し、ログオン時間の変更は許可しないルールを設定できます。

各 ACE には、ルールの適用対象（Security Identifier または SID を使用）、許可または拒否する内容（access mask を使用）、他のオブジェクトへの継承方法などの重要な情報が含まれます。

#### ACE の種類による主な違い

- **Generic ACEs** は、オブジェクトのすべての要素、またはコンテナー内のすべてのオブジェクトに同じルールを適用する、シンプルなアクセス制御に適しています。
- **Object-Specific ACEs** は、より複雑なシナリオで使用されます。特に Active Directory のような環境では、オブジェクトの特定のプロパティごとに異なるアクセス制御が必要になる場合があります。

まとめると、ACLs と ACEs を使用すると、正しい個人やグループだけが機密情報やリソースにアクセスできるよう、アクセス制御を細かく定義できます。また、個々のプロパティやオブジェクトの種類ごとにアクセス権を調整できます。

### Access Control Entry のレイアウト

| ACE Field   | 説明                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Type        | ACE の種類を示す flag。Windows 2000 と Windows Server 2003 は、6 種類の ACE をサポートします。すべてのセキュリティ保護可能なオブジェクトに関連付けられる汎用 ACE が 3 種類、Active Directory オブジェクトに使用されるオブジェクト固有 ACE が 3 種類です。                                                                                                                                                                                                                                                            |
| Flags       | 継承と監査を制御するビット flag のセット。                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Size        | ACE に割り当てられたメモリのバイト数。                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Access mask | ビットがオブジェクトへのアクセス権に対応する 32 ビット値。ビットはオンまたはオフに設定できますが、その意味は ACE の種類によって異なります。たとえば、アクセス許可を読み取る権限に対応するビットがオンで、ACE の種類が Deny の場合、その ACE はオブジェクトのアクセス許可を読み取る権限を拒否します。同じビットがオンでも ACE の種類が Allow の場合、その ACE はオブジェクトのアクセス許可を読み取る権限を許可します。Access mask の詳細は次の表を参照してください。 |
| SID         | この ACE によってアクセスを制御または監視されるユーザーやグループを識別します。                                                                                                                                                                                                                                                                                                                                                                                                                                 |

### Access Mask のレイアウト

| Bit (Range) | 意味                               | 説明/例                                  |
| ----------- | ---------------------------------- | ----------------------------------------- |
| 0 - 15      | オブジェクト固有のアクセス権       | データの読み取り、実行、データの追加      |
| 16 - 22     | 標準アクセス権                     | 削除、ACL の書き込み、所有者の書き込み    |
| 23          | セキュリティ ACL にアクセス可能    |                                           |
| 24 - 27     | 予約済み                           |                                           |
| 28          | Generic ALL（読み取り、書き込み、実行） | 以下のすべて                              |
| 29          | Generic Execute                    | プログラムの実行に必要なすべての操作      |
| 30          | Generic Write                      | ファイルへの書き込みに必要なすべての操作  |
| 31          | Generic Read                       | ファイルの読み取りに必要なすべての操作    |
