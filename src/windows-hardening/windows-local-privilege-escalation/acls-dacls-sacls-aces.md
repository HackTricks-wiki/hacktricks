## **Access Control List (ACL)**

Μια Access Control List (ACL) αποτελείται από ένα διατεταγμένο σύνολο Access Control Entries (ACEs), οι οποίες καθορίζουν τις προστασίες για ένα αντικείμενο και τις ιδιότητές του. Ουσιαστικά, μια ACL ορίζει ποιες ενέργειες από ποιους security principals (χρήστες ή groups) επιτρέπονται ή απορρίπτονται σε ένα δεδομένο αντικείμενο.

Υπάρχουν δύο τύποι ACL:

- **Discretionary Access Control List (DACL):** Καθορίζει ποιοι χρήστες και groups έχουν ή δεν έχουν πρόσβαση σε ένα αντικείμενο.
- **System Access Control List (SACL):** Ελέγχει την καταγραφή των προσπαθειών πρόσβασης σε ένα αντικείμενο.

Η διαδικασία πρόσβασης σε ένα αρχείο περιλαμβάνει τον έλεγχο από το σύστημα του security descriptor του αντικειμένου σε σχέση με το access token του χρήστη, ώστε να καθοριστεί αν θα επιτραπεί η πρόσβαση και σε ποιον βαθμό, με βάση τα ACEs.<sup>[[1]](#references)</sup>

### **Βασικά στοιχεία**

- **DACL:** Περιέχει ACEs που επιτρέπουν ή απορρίπτουν δικαιώματα πρόσβασης σε χρήστες και groups για ένα αντικείμενο. Ουσιαστικά είναι η κύρια ACL που καθορίζει τα δικαιώματα πρόσβασης.
- **SACL:** Χρησιμοποιείται για auditing της πρόσβασης σε αντικείμενα, όπου τα ACEs καθορίζουν τους τύπους πρόσβασης που θα καταγραφούν στο Security Event Log. Αυτό μπορεί να είναι πολύ χρήσιμο για τον εντοπισμό μη εξουσιοδοτημένων προσπαθειών πρόσβασης ή για την αντιμετώπιση προβλημάτων πρόσβασης.<sup>[[1]](#references)</sup>

### **Αλληλεπίδραση του συστήματος με τις ACLs**

Κάθε user session συσχετίζεται με ένα access token που περιέχει πληροφορίες ασφαλείας σχετικές με τη συγκεκριμένη session, συμπεριλαμβανομένων των identities του χρήστη και των groups, καθώς και των privileges. Αυτό το token περιλαμβάνει επίσης ένα logon SID που αναγνωρίζει μοναδικά τη session.

Το Local Security Authority (LSASS) επεξεργάζεται τα access requests προς αντικείμενα εξετάζοντας τη DACL για ACEs που αντιστοιχούν στον security principal που επιχειρεί την πρόσβαση. Η πρόσβαση επιτρέπεται αμέσως αν δεν βρεθούν σχετικά ACEs. Διαφορετικά, το LSASS συγκρίνει τα ACEs με το SID του security principal στο access token για να καθορίσει αν πληρούνται οι προϋποθέσεις πρόσβασης.<sup>[[1]](#references)</sup>

### **Συνοπτική διαδικασία**

- **ACLs:** Καθορίζουν τα δικαιώματα πρόσβασης μέσω των DACLs και τους κανόνες auditing μέσω των SACLs.
- **Access Token:** Περιέχει πληροφορίες χρήστη, group και privilege για μια session.
- **Access Decision:** Λαμβάνεται μέσω της σύγκρισης των DACL ACEs με το access token· οι SACLs χρησιμοποιούνται για auditing.<sup>[[1]](#references)</sup>

### ACEs

Υπάρχουν **τρεις κύριοι τύποι Access Control Entries (ACEs)**:<sup>[[1]](#references)</sup>

- **Access Denied ACE**: Αυτό το ACE απορρίπτει ρητά την πρόσβαση σε ένα αντικείμενο για συγκεκριμένους χρήστες ή groups (σε μια DACL).
- **Access Allowed ACE**: Αυτό το ACE παρέχει ρητά πρόσβαση σε ένα αντικείμενο για συγκεκριμένους χρήστες ή groups (σε μια DACL).
- **System Audit ACE**: Τοποθετημένο μέσα σε μια System Access Control List (SACL), αυτό το ACE είναι υπεύθυνο για τη δημιουργία audit logs κατά τις προσπάθειες πρόσβασης σε ένα αντικείμενο από χρήστες ή groups. Καταγράφει αν η πρόσβαση επιτράπηκε ή απορρίφθηκε, καθώς και τη φύση της πρόσβασης.

Κάθε ACE έχει **τέσσερα κρίσιμα στοιχεία**:<sup>[[1]](#references)</sup>

1. Το **Security Identifier (SID)** του χρήστη ή του group (ή το principal name του σε γραφική αναπαράσταση).
2. Ένα **flag** που προσδιορίζει τον τύπο του ACE (access denied, allowed ή system audit).
3. **Inheritance flags** που καθορίζουν αν τα child objects μπορούν να κληρονομήσουν το ACE από το parent.
4. Ένα [**access mask**](https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-dtyp/7a53f60e-e730-4dfe-bbe9-b21b62eb790b?redirectedfrom=MSDN), μια τιμή 32-bit που καθορίζει τα παραχωρημένα δικαιώματα του αντικειμένου.

Ο προσδιορισμός της πρόσβασης πραγματοποιείται εξετάζοντας διαδοχικά κάθε ACE μέχρι να συμβεί ένα από τα εξής:<sup>[[1]](#references)</sup>

- Ένα **Access-Denied ACE** απορρίπτει ρητά τα ζητούμενα δικαιώματα για έναν trustee που αναγνωρίζεται στο access token.
- Ένα ή περισσότερα **Access-Allowed ACE(s)** παρέχουν ρητά όλα τα ζητούμενα δικαιώματα σε έναν trustee που υπάρχει στο access token.
- Μετά τον έλεγχο όλων των ACEs, αν οποιοδήποτε ζητούμενο δικαίωμα **δεν έχει επιτραπεί ρητά**, η πρόσβαση **απορρίπτεται** έμμεσα.

### Σειρά των ACEs

Ο τρόπος με τον οποίο τα **ACEs** (κανόνες που καθορίζουν ποιος μπορεί ή δεν μπορεί να αποκτήσει πρόσβαση σε κάτι) τοποθετούνται σε μια λίστα που ονομάζεται **DACL** είναι πολύ σημαντικός. Αυτό συμβαίνει επειδή, μόλις το σύστημα επιτρέψει ή απορρίψει την πρόσβαση βάσει αυτών των κανόνων, σταματά να εξετάζει τους υπόλοιπους.<sup>[[1]](#references)</sup>

Υπάρχει ένας βέλτιστος τρόπος οργάνωσης αυτών των ACEs, ο οποίος ονομάζεται **"canonical order."** Αυτή η μέθοδος βοηθά ώστε όλα να λειτουργούν ομαλά και με προβλέψιμο τρόπο. Για συστήματα όπως τα **Windows 2000** και **Windows Server 2003**, ισχύουν τα εξής:

- Αρχικά, τοποθετούνται όλοι οι κανόνες που έχουν δημιουργηθεί **ειδικά για αυτό το αντικείμενο**, πριν από εκείνους που προέρχονται από αλλού, όπως έναν parent folder.
- Μέσα σε αυτούς τους ειδικούς κανόνες, τοποθετούνται πρώτα όσοι λένε **"όχι" (deny)** και μετά όσοι λένε **"ναι" (allow)**.
- Για τους κανόνες που προέρχονται από αλλού, ξεκινούν πρώτα εκείνοι από την **πλησιέστερη πηγή**, όπως ο parent, και στη συνέχεια εξετάζονται οι πιο απομακρυσμένες πηγές. Και εδώ, το **"όχι"** τοποθετείται πριν από το **"ναι."**

Αυτή η διάταξη βοηθά με δύο σημαντικούς τρόπους:

- Εξασφαλίζει ότι ένα συγκεκριμένο **"όχι"** θα γίνει σεβαστό, ανεξάρτητα από τους υπόλοιπους κανόνες **"ναι"**.
- Επιτρέπει στον owner ενός αντικειμένου να έχει τον **τελευταίο λόγο** σχετικά με το ποιος αποκτά πρόσβαση, πριν εφαρμοστούν κανόνες από parent folders ή από πιο απομακρυσμένες πηγές.

Με αυτή τη διάταξη, ο owner ενός αρχείου ή folder μπορεί να καθορίσει με μεγάλη ακρίβεια ποιος αποκτά πρόσβαση, διασφαλίζοντας ότι τα σωστά άτομα μπορούν να εισέλθουν και τα λάθος όχι.

![Διάγραμμα σειράς των NTFS access control entries](https://www.ntfs.com/images/screenshots/ACEs.gif)

Επομένως, το **"canonical order"** αφορά τη διασφάλιση ότι οι κανόνες πρόσβασης είναι σαφείς και λειτουργούν σωστά, τοποθετώντας πρώτα τους ειδικούς κανόνες και οργανώνοντας τα πάντα με συστηματικό τρόπο.

### Επεξήγηση του Access Control με απλοποιημένο τρόπο

Κατά τη διαχείριση της πρόσβασης σε resources, όπως ένα folder, χρησιμοποιούμε λίστες και κανόνες που ονομάζονται Access Control Lists (ACLs) και Access Control Entries (ACEs). Αυτά καθορίζουν ποιος μπορεί ή δεν μπορεί να αποκτήσει πρόσβαση σε συγκεκριμένα δεδομένα.<sup>[[1]](#references)</sup>

#### Απόρριψη πρόσβασης σε συγκεκριμένο group

Φανταστείτε ότι έχετε ένα folder με όνομα Cost και θέλετε να μπορούν όλοι να αποκτήσουν πρόσβαση σε αυτό, εκτός από μια marketing team. Με τη σωστή ρύθμιση των κανόνων, μπορούμε να εξασφαλίσουμε ότι η marketing team θα απορρίπτεται ρητά πριν επιτραπεί η πρόσβαση σε όλους τους υπόλοιπους. Αυτό γίνεται τοποθετώντας τον κανόνα που απορρίπτει την πρόσβαση στη marketing team πριν από τον κανόνα που επιτρέπει την πρόσβαση σε όλους.

#### Παραχώρηση πρόσβασης σε συγκεκριμένο μέλος ενός απορριφθέντος group

Ας υποθέσουμε ότι ο Bob, ο marketing director, χρειάζεται πρόσβαση στο folder Cost, παρότι η marketing team δεν θα έπρεπε γενικά να έχει πρόσβαση. Μπορούμε να προσθέσουμε έναν ειδικό κανόνα (ACE) για τον Bob που του παρέχει πρόσβαση και να τον τοποθετήσουμε πριν από τον κανόνα που απορρίπτει την πρόσβαση στη marketing team. Έτσι, ο Bob αποκτά πρόσβαση παρά τον γενικό περιορισμό που ισχύει για το group του.

#### Κατανόηση των Access Control Entries

Τα ACEs είναι οι επιμέρους κανόνες μιας ACL. Αναγνωρίζουν χρήστες ή groups, καθορίζουν ποια πρόσβαση επιτρέπεται ή απορρίπτεται και καθορίζουν τον τρόπο εφαρμογής αυτών των κανόνων σε sub-items (inheritance). Υπάρχουν δύο κύριοι τύποι ACEs:

- **Generic ACEs**: Εφαρμόζονται ευρέως, επηρεάζοντας όλους τους τύπους αντικειμένων ή διακρίνοντας μόνο μεταξύ containers (όπως folders) και non-containers (όπως αρχεία). Για παράδειγμα, ένας κανόνας που επιτρέπει στους χρήστες να βλέπουν τα περιεχόμενα ενός folder, αλλά όχι να αποκτούν πρόσβαση στα αρχεία που περιέχει.
- **Object-Specific ACEs**: Παρέχουν ακριβέστερο έλεγχο, επιτρέποντας τον ορισμό κανόνων για συγκεκριμένους τύπους αντικειμένων ή ακόμη και για μεμονωμένες ιδιότητες μέσα σε ένα αντικείμενο. Για παράδειγμα, σε έναν κατάλογο χρηστών, ένας κανόνας μπορεί να επιτρέπει σε έναν χρήστη να ενημερώνει τον αριθμό τηλεφώνου του, αλλά όχι τις ώρες σύνδεσής του.

Κάθε ACE περιέχει σημαντικές πληροφορίες, όπως σε ποιον εφαρμόζεται ο κανόνας (με χρήση ενός Security Identifier ή SID), τι επιτρέπει ή απορρίπτει ο κανόνας (με χρήση ενός access mask) και πώς κληρονομείται από άλλα αντικείμενα.

#### Βασικές διαφορές μεταξύ των τύπων ACE

- Τα **Generic ACEs** είναι κατάλληλα για απλά σενάρια access control, όπου ο ίδιος κανόνας εφαρμόζεται σε όλες τις πτυχές ενός αντικειμένου ή σε όλα τα αντικείμενα μέσα σε ένα container.
- Τα **Object-Specific ACEs** χρησιμοποιούνται σε πιο σύνθετα σενάρια, ειδικά σε περιβάλλοντα όπως το Active Directory, όπου μπορεί να χρειάζεται να ελέγχεται διαφορετικά η πρόσβαση σε συγκεκριμένες ιδιότητες ενός αντικειμένου.

Συνοπτικά, οι ACLs και τα ACEs βοηθούν στον καθορισμό ακριβών access controls, εξασφαλίζοντας ότι μόνο τα σωστά άτομα ή groups έχουν πρόσβαση σε ευαίσθητες πληροφορίες ή resources, με τη δυνατότητα προσαρμογής των δικαιωμάτων πρόσβασης μέχρι το επίπεδο μεμονωμένων ιδιοτήτων ή τύπων αντικειμένων.

### Διάταξη Access Control Entry

| Πεδίο ACE   | Περιγραφή                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Type        | Flag που υποδεικνύει τον τύπο του ACE. Τα Windows 2000 και Windows Server 2003 υποστηρίζουν έξι τύπους ACE: τρεις generic τύπους ACE που συνδέονται με όλα τα securable objects και τρεις object-specific τύπους ACE που μπορούν να εμφανιστούν σε αντικείμενα του Active Directory.                                                                                                                                                                                                                                                            |
| Flags       | Σύνολο από bit flags που ελέγχουν το inheritance και το auditing.                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Size        | Αριθμός bytes μνήμης που έχουν δεσμευτεί για το ACE.                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Access mask | Τιμή 32-bit, τα bits της οποίας αντιστοιχούν στα δικαιώματα πρόσβασης του αντικειμένου. Τα bits μπορούν να είναι ενεργοποιημένα ή απενεργοποιημένα, αλλά η σημασία της ρύθμισης εξαρτάται από τον τύπο του ACE. Για παράδειγμα, αν το bit που αντιστοιχεί στο δικαίωμα ανάγνωσης permissions είναι ενεργοποιημένο και ο τύπος του ACE είναι Deny, το ACE απορρίπτει το δικαίωμα ανάγνωσης των permissions του αντικειμένου. Αν το ίδιο bit είναι ενεργοποιημένο και ο τύπος του ACE είναι Allow, το ACE παρέχει το δικαίωμα ανάγνωσης των permissions του αντικειμένου. Περισσότερες λεπτομέρειες σχετικά με το Access mask εμφανίζονται στον επόμενο πίνακα. |
| SID         | Αναγνωρίζει έναν χρήστη ή group του οποίου η πρόσβαση ελέγχεται ή παρακολουθείται από αυτό το ACE.                                                                                                                                                                                                                                                                                                                                                                                                                                 |

### Διάταξη Access Mask

| Bit (Range) | Σημασία                            | Περιγραφή/Παράδειγμα                       |
| ----------- | ---------------------------------- | ----------------------------------------- |
| 0 - 15      | Object Specific Access Rights      | Ανάγνωση δεδομένων, Execute, Append data           |
| 16 - 22     | Standard Access Rights             | Delete, Write ACL, Write Owner            |
| 23          | Μπορεί να αποκτήσει πρόσβαση στη security ACL            |                                           |
| 24 - 27     | Reserved                           |                                           |
| 28          | Generic ALL (Read, Write, Execute) | Όλα τα παρακάτω                          |
| 29          | Generic Execute                    | Όλα όσα είναι απαραίτητα για την εκτέλεση ενός προγράμματος |
| 30          | Generic Write                      | Όλα όσα είναι απαραίτητα για την εγγραφή σε ένα αρχείο   |
| 31          | Generic Read                       | Όλα όσα είναι απαραίτητα για την ανάγνωση ενός αρχείου       |
