## **Λίστα Ελέγχου Πρόσβασης (ACL)**

Μια Λίστα Ελέγχου Πρόσβασης (ACL) αποτελείται από ένα ταξινομημένο σύνολο Καταχωρίσεων Ελέγχου Πρόσβασης (ACEs), οι οποίες καθορίζουν την προστασία ενός αντικειμένου και των ιδιοτήτων του. Ουσιαστικά, μια ACL καθορίζει ποιες ενέργειες επιτρέπονται ή απαγορεύονται σε συγκεκριμένες οντότητες ασφαλείας (χρήστες ή ομάδες) για ένα δεδομένο αντικείμενο.

Υπάρχουν δύο τύποι ACL:

- **Λίστα Διακριτικού Ελέγχου Πρόσβασης (DACL):** Καθορίζει ποιοι χρήστες και ομάδες έχουν ή δεν έχουν πρόσβαση σε ένα αντικείμενο.
- **Λίστα Ελέγχου Πρόσβασης Συστήματος (SACL):** Διαχειρίζεται την καταγραφή των προσπαθειών πρόσβασης σε ένα αντικείμενο.

Κατά την πρόσβαση σε ένα αρχείο, το σύστημα ελέγχει τον περιγραφέα ασφαλείας του αντικειμένου σε σχέση με το διακριτικό πρόσβασης του χρήστη, για να καθορίσει αν θα επιτραπεί η πρόσβαση και σε ποιο βαθμό, με βάση τις ACEs.<sup>[[1]](#references)</sup>

Όταν ένας γονικός κατάλογος παρέχει Full Control, αλλά ένα θυγατρικό αρχείο αρνείται την ανάγνωση, ελέγξτε χωριστά την αποτελεσματική DACL, τον κάτοχο και την κληρονόμηση του **θυγατρικού αρχείου**. Για να αλλάξετε την DACL αυτού του αρχείου απαιτείται `WRITE_DAC` στο αρχείο ή το αντίστοιχο δικαίωμα κατόχου· η [Microsoft ορίζει το `WRITE_DAC`](https://learn.microsoft.com/en-us/windows/win32/secauthz/standard-access-rights) και [τεκμηριώνει την έμμεση πρόσβαση του κατόχου](https://learn.microsoft.com/en-us/windows/win32/secauthz/owner-of-a-new-object). Τα δικαιώματα στον γονικό κατάλογο από μόνα τους δεν αποδεικνύουν ότι το θυγατρικό αρχείο μπορεί να διαβαστεί ή ότι μπορεί να αλλάξει η DACL του.

### **Βασικά Στοιχεία**

- **DACL:** Περιέχει ACEs που παραχωρούν ή αρνούνται δικαιώματα πρόσβασης σε χρήστες και ομάδες για ένα αντικείμενο. Είναι ουσιαστικά η κύρια ACL που καθορίζει τα δικαιώματα πρόσβασης.
- **SACL:** Χρησιμοποιείται για την καταγραφή της πρόσβασης σε αντικείμενα. Οι ACEs ορίζουν τους τύπους πρόσβασης που θα καταγράφονται στο Security Event Log. Αυτό μπορεί να είναι πολύτιμο για τον εντοπισμό μη εξουσιοδοτημένων προσπαθειών πρόσβασης ή για την αντιμετώπιση προβλημάτων πρόσβασης.<sup>[[1]](#references)</sup>

### **Αλληλεπίδραση του Συστήματος με τις ACLs**

Κάθε συνεδρία χρήστη συνδέεται με ένα διακριτικό πρόσβασης, το οποίο περιέχει πληροφορίες ασφαλείας σχετικές με τη συγκεκριμένη συνεδρία, όπως ταυτότητες χρηστών και ομάδων, καθώς και δικαιώματα. Το διακριτικό περιλαμβάνει επίσης ένα logon SID που προσδιορίζει μοναδικά τη συνεδρία.

Η Local Security Authority (LSASS) επεξεργάζεται τα αιτήματα πρόσβασης σε αντικείμενα, εξετάζοντας την DACL για ACEs που αντιστοιχούν στην οντότητα ασφαλείας που επιχειρεί την πρόσβαση. Αν δεν εντοπιστούν σχετικές ACEs, η πρόσβαση παραχωρείται αμέσως. Διαφορετικά, η LSASS συγκρίνει τις ACEs με το SID της οντότητας ασφαλείας στο διακριτικό πρόσβασης, για να καθορίσει αν επιτρέπεται η πρόσβαση.<sup>[[1]](#references)</sup>

### **Συνοπτική Διαδικασία**

- **ACLs:** Ορίζουν τα δικαιώματα πρόσβασης μέσω των DACLs και τους κανόνες ελέγχου μέσω των SACLs.
- **Διακριτικό πρόσβασης:** Περιέχει πληροφορίες χρήστη, ομάδων και δικαιωμάτων για μια συνεδρία.
- **Απόφαση πρόσβασης:** Λαμβάνεται συγκρίνοντας τις ACEs της DACL με το διακριτικό πρόσβασης· οι SACLs χρησιμοποιούνται για έλεγχο και καταγραφή.<sup>[[1]](#references)</sup>

### ACEs

Υπάρχουν **τρεις κύριοι τύποι Καταχωρίσεων Ελέγχου Πρόσβασης (ACEs)**:<sup>[[1]](#references)</sup>

- **Access Denied ACE**: Αυτή η ACE αρνείται ρητά την πρόσβαση σε ένα αντικείμενο για συγκεκριμένους χρήστες ή ομάδες (σε μια DACL).
- **Access Allowed ACE**: Αυτή η ACE παραχωρεί ρητά πρόσβαση σε ένα αντικείμενο για συγκεκριμένους χρήστες ή ομάδες (σε μια DACL).
- **System Audit ACE**: Τοποθετείται σε μια Λίστα Ελέγχου Πρόσβασης Συστήματος (SACL) και είναι υπεύθυνη για τη δημιουργία αρχείων καταγραφής ελέγχου όταν χρήστες ή ομάδες επιχειρούν να αποκτήσουν πρόσβαση σε ένα αντικείμενο. Καταγράφει αν η πρόσβαση επιτράπηκε ή απορρίφθηκε, καθώς και τη φύση της.

Κάθε ACE έχει **τέσσερα κρίσιμα στοιχεία**:<sup>[[1]](#references)</sup>

1. Το **Αναγνωριστικό Ασφαλείας (SID)** του χρήστη ή της ομάδας (ή το κύριο όνομά τους σε γραφική αναπαράσταση).
2. Μια **σημαία** που προσδιορίζει τον τύπο της ACE (άρνηση πρόσβασης, παραχώρηση πρόσβασης ή έλεγχος συστήματος).
3. **Σημαίες κληρονόμησης** που καθορίζουν αν τα θυγατρικά αντικείμενα μπορούν να κληρονομήσουν την ACE από το γονικό αντικείμενο.
4. Μια [**μάσκα πρόσβασης**](https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-dtyp/7a53f60e-e730-4dfe-bbe9-b21b62eb790b?redirectedfrom=MSDN), μια τιμή 32 bit που προσδιορίζει τα δικαιώματα που παραχωρούνται στο αντικείμενο.

Ο προσδιορισμός της πρόσβασης γίνεται εξετάζοντας διαδοχικά κάθε ACE μέχρι να συμβεί ένα από τα εξής:<sup>[[1]](#references)</sup>

- Μια **Access-Denied ACE** αρνηθεί ρητά τα ζητούμενα δικαιώματα σε έναν αποδέκτη που προσδιορίζεται στο διακριτικό πρόσβασης.
- Μία ή περισσότερες **Access-Allowed ACEs** παραχωρήσουν ρητά όλα τα ζητούμενα δικαιώματα σε έναν αποδέκτη στο διακριτικό πρόσβασης.
- Αφού ελεγχθούν όλες οι ACEs, αν οποιοδήποτε ζητούμενο δικαίωμα **δεν έχει επιτραπεί ρητά**, η πρόσβαση **απορρίπτεται** έμμεσα.

### Σειρά ACEs

Η σειρά με την οποία τοποθετούνται οι **ACEs** (κανόνες που καθορίζουν ποιος μπορεί ή δεν μπορεί να αποκτήσει πρόσβαση σε κάτι) σε μια λίστα που ονομάζεται **DACL** είναι πολύ σημαντική. Αυτό συμβαίνει επειδή, μόλις το σύστημα παραχωρήσει ή αρνηθεί την πρόσβαση βάσει αυτών των κανόνων, σταματά να εξετάζει τους υπόλοιπους.<sup>[[1]](#references)</sup>

Υπάρχει ένας βέλτιστος τρόπος οργάνωσης αυτών των ACEs, ο οποίος ονομάζεται **«κανονική σειρά»**. Αυτή η μέθοδος συμβάλλει στην ομαλή και ορθή λειτουργία. Για συστήματα όπως τα **Windows 2000** και **Windows Server 2003**, η σειρά είναι η εξής:

- Πρώτα τοποθετήστε όλους τους κανόνες που έχουν δημιουργηθεί **ειδικά για αυτό το αντικείμενο**, πριν από τους κανόνες που προέρχονται από αλλού, όπως από έναν γονικό φάκελο.
- Στους συγκεκριμένους κανόνες, τοποθετήστε πρώτα όσους λένε **«όχι» (άρνηση)** και μετά όσους λένε **«ναι» (παραχώρηση)**.
- Για τους κανόνες που προέρχονται από αλλού, ξεκινήστε με αυτούς από την **πλησιέστερη πηγή**, όπως ο γονικός φάκελος, και συνεχίστε προς τις πιο απομακρυσμένες πηγές. Και πάλι, τοποθετήστε πρώτα το **«όχι»** και μετά το **«ναι»**.

Αυτή η ρύθμιση βοηθά με δύο σημαντικούς τρόπους:

- Διασφαλίζει ότι ένα συγκεκριμένο **«όχι»** γίνεται σεβαστό, ανεξάρτητα από τους άλλους κανόνες **«ναι»**.
- Επιτρέπει στον κάτοχο ενός αντικειμένου να έχει τον **τελικό λόγο** για το ποιος αποκτά πρόσβαση, πριν τεθούν σε ισχύ κανόνες από γονικούς φακέλους ή άλλες πιο απομακρυσμένες πηγές.

Με αυτόν τον τρόπο, ο κάτοχος ενός αρχείου ή φακέλου μπορεί να καθορίζει με ακρίβεια ποιος αποκτά πρόσβαση, διασφαλίζοντας ότι έχουν πρόσβαση τα κατάλληλα άτομα και όχι τα υπόλοιπα.

![Διάγραμμα σειράς καταχωρίσεων ελέγχου πρόσβασης NTFS](https://www.ntfs.com/images/screenshots/ACEs.gif)

Έτσι, η **«κανονική σειρά»** διασφαλίζει ότι οι κανόνες πρόσβασης είναι σαφείς και λειτουργούν σωστά: τοποθετεί πρώτα τους συγκεκριμένους κανόνες και οργανώνει τα πάντα με έξυπνο τρόπο.

### Επεξήγηση του Ελέγχου Πρόσβασης με Απλό Τρόπο

Κατά τη διαχείριση της πρόσβασης σε πόρους, όπως ένας φάκελος, χρησιμοποιούμε λίστες και κανόνες που ονομάζονται Λίστες Ελέγχου Πρόσβασης (ACLs) και Καταχωρίσεις Ελέγχου Πρόσβασης (ACEs). Αυτά καθορίζουν ποιος μπορεί ή δεν μπορεί να αποκτήσει πρόσβαση σε συγκεκριμένα δεδομένα.<sup>[[1]](#references)</sup>

#### Άρνηση Πρόσβασης σε Συγκεκριμένη Ομάδα

Ας υποθέσουμε ότι έχετε έναν φάκελο με όνομα Cost και θέλετε να έχουν όλοι πρόσβαση εκτός από την ομάδα μάρκετινγκ. Ρυθμίζοντας σωστά τους κανόνες, μπορούμε να διασφαλίσουμε ότι η πρόσβαση στην ομάδα μάρκετινγκ θα απορριφθεί ρητά πριν επιτραπεί σε όλους τους υπόλοιπους. Αυτό γίνεται τοποθετώντας τον κανόνα που αρνείται την πρόσβαση στην ομάδα μάρκετινγκ πριν από τον κανόνα που επιτρέπει την πρόσβαση σε όλους.

#### Παραχώρηση Πρόσβασης σε Συγκεκριμένο Μέλος μιας Ομάδας στην Οποία Απαγορεύεται η Πρόσβαση

Ας υποθέσουμε ότι ο Bob, διευθυντής μάρκετινγκ, χρειάζεται πρόσβαση στον φάκελο Cost, παρόλο που γενικά η ομάδα μάρκετινγκ δεν πρέπει να έχει πρόσβαση. Μπορούμε να προσθέσουμε έναν συγκεκριμένο κανόνα (ACE) για τον Bob που του παραχωρεί πρόσβαση και να τον τοποθετήσουμε πριν από τον κανόνα που αρνείται την πρόσβαση στην ομάδα μάρκετινγκ. Με αυτόν τον τρόπο, ο Bob αποκτά πρόσβαση παρά τον γενικό περιορισμό για την ομάδα του.

#### Κατανόηση των Καταχωρίσεων Ελέγχου Πρόσβασης

Οι ACEs είναι οι επιμέρους κανόνες μιας ACL. Προσδιορίζουν χρήστες ή ομάδες, ορίζουν ποια πρόσβαση επιτρέπεται ή απαγορεύεται και καθορίζουν πώς εφαρμόζονται αυτοί οι κανόνες στα θυγατρικά στοιχεία (κληρονόμηση). Υπάρχουν δύο κύριοι τύποι ACEs:

- **Γενικές ACEs**: Εφαρμόζονται ευρέως, είτε σε όλους τους τύπους αντικειμένων είτε διακρίνοντας μόνο μεταξύ κοντέινερ (όπως φακέλων) και αντικειμένων που δεν είναι κοντέινερ (όπως αρχείων). Για παράδειγμα, ένας κανόνας που επιτρέπει στους χρήστες να βλέπουν τα περιεχόμενα ενός φακέλου, αλλά όχι να αποκτούν πρόσβαση στα αρχεία που περιέχει.
- **ACEs ειδικές για αντικείμενα**: Παρέχουν ακριβέστερο έλεγχο, επιτρέποντας τον ορισμό κανόνων για συγκεκριμένους τύπους αντικειμένων ή ακόμη και για μεμονωμένες ιδιότητες ενός αντικειμένου. Για παράδειγμα, σε έναν κατάλογο χρηστών, ένας κανόνας μπορεί να επιτρέπει σε έναν χρήστη να ενημερώνει τον αριθμό τηλεφώνου του, αλλά όχι τις ώρες σύνδεσής του.

Κάθε ACE περιέχει σημαντικές πληροφορίες, όπως σε ποιον εφαρμόζεται ο κανόνας (μέσω ενός Αναγνωριστικού Ασφαλείας ή SID), τι επιτρέπει ή απαγορεύει ο κανόνας (μέσω μιας μάσκας πρόσβασης) και πώς κληρονομείται από άλλα αντικείμενα.

#### Βασικές Διαφορές Μεταξύ των Τύπων ACE

- Οι **Γενικές ACEs** είναι κατάλληλες για απλά σενάρια ελέγχου πρόσβασης, όπου ο ίδιος κανόνας εφαρμόζεται σε όλες τις πτυχές ενός αντικειμένου ή σε όλα τα αντικείμενα ενός κοντέινερ.
- Οι **ACEs ειδικές για αντικείμενα** χρησιμοποιούνται σε πιο σύνθετα σενάρια, ιδίως σε περιβάλλοντα όπως το Active Directory, όπου μπορεί να χρειάζεται να ελέγχετε διαφορετικά την πρόσβαση σε συγκεκριμένες ιδιότητες ενός αντικειμένου.

Συνοπτικά, οι ACLs και οι ACEs συμβάλλουν στον ακριβή ορισμό των ελέγχων πρόσβασης, διασφαλίζοντας ότι μόνο τα κατάλληλα άτομα ή ομάδες έχουν πρόσβαση σε ευαίσθητες πληροφορίες ή πόρους. Παρέχουν επίσης τη δυνατότητα προσαρμογής των δικαιωμάτων πρόσβασης έως και σε επίπεδο μεμονωμένων ιδιοτήτων ή τύπων αντικειμένων.

### Διάταξη Καταχώρισης Ελέγχου Πρόσβασης

| Πεδίο ACE   | Περιγραφή                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Type        | Σημαία που υποδεικνύει τον τύπο της ACE. Τα Windows 2000 και Windows Server 2003 υποστηρίζουν έξι τύπους ACE: τρεις γενικούς τύπους ACE που συνδέονται με όλα τα αντικείμενα που επιδέχονται ασφάλεια και τρεις τύπους ACE ειδικούς για αντικείμενα, οι οποίοι μπορούν να εμφανιστούν σε αντικείμενα Active Directory.                                                                                                                                                                                                                                                            |
| Flags       | Σύνολο σημαιών bit που ελέγχουν την κληρονόμηση και τον έλεγχο.                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Size        | Αριθμός byte μνήμης που δεσμεύονται για την ACE.                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Access mask | Τιμή 32 bit, τα bit της οποίας αντιστοιχούν σε δικαιώματα πρόσβασης για το αντικείμενο. Τα bit μπορούν να ενεργοποιηθούν ή να απενεργοποιηθούν, αλλά η σημασία της ρύθμισης εξαρτάται από τον τύπο της ACE. Για παράδειγμα, αν ενεργοποιηθεί το bit που αντιστοιχεί στο δικαίωμα ανάγνωσης δικαιωμάτων και ο τύπος ACE είναι Deny, η ACE αρνείται το δικαίωμα ανάγνωσης των δικαιωμάτων του αντικειμένου. Αν ενεργοποιηθεί το ίδιο bit και ο τύπος ACE είναι Allow, η ACE παραχωρεί το δικαίωμα ανάγνωσης των δικαιωμάτων του αντικειμένου. Περισσότερες λεπτομέρειες για τη μάσκα πρόσβασης παρατίθενται στον επόμενο πίνακα. |
| SID         | Προσδιορίζει τον χρήστη ή την ομάδα των οποίων η πρόσβαση ελέγχεται ή παρακολουθείται από αυτήν την ACE.                                                                                                                                                                                                                                                                                                                                                                                                                                 |

### Διάταξη Μάσκας Πρόσβασης

| Bit (Εύρος) | Σημασία                            | Περιγραφή/Παράδειγμα                       |
| ----------- | ---------------------------------- | ----------------------------------------- |
| 0 - 15      | Ειδικά δικαιώματα πρόσβασης αντικειμένου      | Ανάγνωση δεδομένων, Εκτέλεση, Προσθήκη δεδομένων           |
| 16 - 22     | Τυπικά δικαιώματα πρόσβασης             | Διαγραφή, Εγγραφή ACL, Εγγραφή κατόχου            |
| 23          | Δυνατότητα πρόσβασης στην ACL ασφαλείας            |                                           |
| 24 - 27     | Δεσμευμένα                           |                                           |
| 28          | Γενική πρόσβαση ALL (Ανάγνωση, Εγγραφή, Εκτέλεση) | Όλα τα παρακάτω                          |
| 29          | Γενική πρόσβαση Execute                    | Όλα όσα απαιτούνται για την εκτέλεση ενός προγράμματος |
| 30          | Γενική πρόσβαση Write                      | Όλα όσα απαιτούνται για την εγγραφή σε ένα αρχείο   |
| 31          | Γενική πρόσβαση Read                       | Όλα όσα απαιτούνται για την ανάγνωση ενός αρχείου       |
