## LoRA 개선

> [!TIP]
> LoRA는 pretrained model을 fine-tuning하는 데 필요한 trainable parameter 수와 optimizer memory를 크게 줄일 수 있습니다.

LoRA를 사용하면 모델의 **작은 부분**만 변경하여 **대규모 모델**을 효율적으로 fine-tuning할 수 있습니다. 학습해야 하는 parameter 수를 줄여 **memory**와 **computational resources**를 절약합니다. 그 이유는 다음과 같습니다.<sup>[[1]](#references)</sup>

1. **trainable parameter 수 감소**: LoRA는 원래 weight `W`를 고정하고, additive update를 일반적으로 `ΔW = B A`로 표현되는 두 개의 trainable low-rank matrix의 곱으로 나타냅니다. 이때 rank `r`은 input/output dimension보다 훨씬 작습니다.<sup>[[3]](#references)</sup>

1. 이는 layer (matrix)의 전체 weight update를 계산하는 대신, 이를 더 작은 2개 matrix의 곱으로 근사하여 계산해야 하는 update를 줄이기 때문입니다:\

2. **원래 model weights 유지**: adapter matrix만 optimized됩니다. weight를 고정하면 base checkpoint가 직접 수정되는 것을 방지할 수 있지만, inference 시 adapter 동작이 기존 knowledge를 override하거나 저하시킬 수 있습니다.
3. **효율적인 Task-Specific Fine-Tuning**: 모델을 **새 task**에 맞게 조정하려는 경우, 나머지 model은 그대로 유지하면서 **작은 LoRA matrix** (A와 B)만 학습하면 됩니다. 이는 전체 model을 다시 학습하는 것보다 **훨씬 효율적**입니다.
4. **Storage Efficiency**: fine-tuning 후 각 task마다 **전체 새 model**을 저장하는 대신, 전체 model에 비해 매우 작은 **LoRA matrix**만 저장하면 됩니다. 따라서 storage를 과도하게 사용하지 않고도 model을 여러 task에 더 쉽게 적용할 수 있습니다.

다음의 최소 구현은 인용된 notebook을 기반으로 수정한 것입니다. `B`를 0으로 초기화하므로 adapter는 no-op 상태로 시작하며, LoRA의 표준 `alpha / rank` scaling을 사용합니다. 이 code는 factor를 input-major shape (`A`는 `in_dim x rank`, `B`는 `rank x out_dim`)로 저장하므로 forward path는 `xAB`로 작성됩니다. 이는 논문의 `BA` 표기법과 동등한 transposed-shape 표현입니다.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
