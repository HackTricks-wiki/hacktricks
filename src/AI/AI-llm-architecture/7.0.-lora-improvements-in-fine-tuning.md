## LoRA Improvements

> [!TIP]
> **LoRA का उपयोग पहले से trained models को fine tune करने के लिए आवश्यक computation को काफी कम कर देता है।**

LoRA केवल model के **छोटे हिस्से** को बदलकर **large models** को प्रभावी ढंग से fine-tune करना संभव बनाता है। यह train किए जाने वाले parameters की संख्या को कम करता है, जिससे **memory** और **computational resources** की बचत होती है। ऐसा इसलिए होता है क्योंकि:<sup>[[1]](#references)</sup>

1. **Trainable Parameters की संख्या कम करता है**: Model में पूरे weight matrix को update करने के बजाय, LoRA weight matrix को दो छोटे matrices (जिन्हें **A** और **B** कहा जाता है) में **विभाजित** करता है। इससे training **तेज़** होती है और **कम memory** की आवश्यकता होती है, क्योंकि कम parameters को update करना पड़ता है।<sup>[[3]](#references)</sup>

1. ऐसा इसलिए है क्योंकि किसी layer (matrix) के complete weight update की गणना करने के बजाय, यह उसे 2 छोटे matrices के product के रूप में approximate करता है, जिससे calculate किए जाने वाले update का आकार कम हो जाता है:\

2. **Original Model Weights को अपरिवर्तित रखता है**: LoRA आपको original model weights को समान बनाए रखने और केवल **नई छोटी matrices** (A और B) को update करने की अनुमति देता है। यह उपयोगी है क्योंकि इससे model का original knowledge सुरक्षित रहता है और केवल आवश्यक चीज़ों में बदलाव किया जाता है।
3. **Efficient Task-Specific Fine-Tuning**: जब आप model को किसी **new task** के लिए adapt करना चाहते हैं, तो आप बाकी model को जैसा है वैसा रखते हुए केवल **छोटी LoRA matrices** (A और B) को train कर सकते हैं। यह पूरे model को retrain करने की तुलना में **काफी अधिक efficient** है।
4. **Storage Efficiency**: Fine-tuning के बाद, प्रत्येक task के लिए **पूरा नया model** save करने के बजाय, आपको केवल **LoRA matrices** store करने की आवश्यकता होती है, जो पूरे model की तुलना में बहुत छोटी होती हैं। इससे बहुत अधिक storage का उपयोग किए बिना model को कई tasks के लिए adapt करना आसान हो जाता है।

Fine tuning के दौरान Linear layers के बजाय LoraLayers implement करने के लिए, यह code यहाँ प्रस्तावित किया गया है [https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb):<sup>[[2]](#references)</sup>
```python
import math

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.alpha = alpha

def forward(self, x):
x = self.alpha * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
