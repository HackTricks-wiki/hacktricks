## Cải tiến LoRA

> [!TIP]
> LoRA có thể giảm đáng kể số lượng tham số cần huấn luyện và bộ nhớ dành cho optimizer khi fine-tune mô hình đã được huấn luyện trước.

LoRA giúp fine-tune **các mô hình lớn** một cách hiệu quả bằng cách chỉ thay đổi **một phần nhỏ** của mô hình. Phương pháp này giảm số lượng tham số cần huấn luyện, tiết kiệm **bộ nhớ** và **tài nguyên tính toán**. Điều này là do:<sup>[[1]](#references)</sup>

1. **Giảm số lượng tham số cần huấn luyện**: LoRA đóng băng trọng số gốc `W` và biểu diễn một cập nhật cộng thêm dưới dạng tích của hai ma trận hạng thấp có thể huấn luyện, thường là `ΔW = B A`, với hạng `r` nhỏ hơn nhiều so với các chiều đầu vào/đầu ra.<sup>[[3]](#references)</sup>

   1. Điều này là do thay vì tính toán toàn bộ cập nhật trọng số của một lớp (ma trận), phương pháp này xấp xỉ cập nhật đó bằng tích của 2 ma trận nhỏ hơn, giúp giảm lượng tính toán cần thiết:\

      <figure><img src="../../images/image (9) (1).png" alt=""><figcaption></figcaption></figure>

2. **Giữ nguyên trọng số của mô hình gốc**: Chỉ các ma trận adapter được tối ưu hóa. Việc đóng băng trọng số ngăn checkpoint cơ sở bị sửa đổi trực tiếp, dù hành vi của adapter vẫn có thể ghi đè hoặc làm suy giảm kiến thức tại thời điểm suy luận.
3. **Fine-tune hiệu quả cho từng tác vụ**: Khi muốn điều chỉnh mô hình cho **một tác vụ mới**, bạn chỉ cần huấn luyện **các ma trận LoRA nhỏ** (A và B), đồng thời giữ nguyên phần còn lại của mô hình. Cách này **hiệu quả hơn nhiều** so với việc huấn luyện lại toàn bộ mô hình.
4. **Hiệu quả lưu trữ**: Sau khi fine-tune, thay vì lưu **toàn bộ mô hình mới** cho từng tác vụ, bạn chỉ cần lưu **các ma trận LoRA**, vốn rất nhỏ so với toàn bộ mô hình. Nhờ đó, việc điều chỉnh mô hình cho nhiều tác vụ trở nên dễ dàng hơn mà không tốn quá nhiều dung lượng lưu trữ.

Phần triển khai tối giản sau đây điều chỉnh notebook được trích dẫn. Phần này khởi tạo `B` bằng 0 để adapter bắt đầu ở trạng thái no-op và dùng hệ số tỷ lệ chuẩn `alpha / rank` của LoRA. Mã lưu các thừa số theo dạng input-major (`A` có kích thước `in_dim x rank` và `B` có kích thước `rank x out_dim`), nên đường truyền thuận được viết là `xAB`; đây là dạng tương đương với ký hiệu `BA` trong bài báo nhưng có hình dạng ma trận chuyển vị.<sup>[[2]](#references)[[3]](#references)</sup>

```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
    def __init__(self, in_dim, out_dim, rank, alpha):
        super().__init__()
        self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
        torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
        self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
        self.scaling = alpha / rank

    def forward(self, x):
        x = self.scaling * (x @ self.A @ self.B)
        return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
    def __init__(self, linear, rank, alpha):
        super().__init__()
        self.linear = linear
        self.lora = LoRALayer(
            linear.in_features, linear.out_features, rank, alpha
        )

    def forward(self, x):
        return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
    for name, module in model.named_children():
        if isinstance(module, torch.nn.Linear):
            # Replace the Linear layer with LinearWithLoRA
            setattr(model, name, LinearWithLoRA(module, rank, alpha))
        else:
            # Recursively apply the same function to child modules
            replace_linear_with_lora(module, rank, alpha)
```
