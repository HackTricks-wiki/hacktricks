## Améliorations de LoRA

> [!TIP]
> L'utilisation de **LoRA réduit considérablement les calculs** nécessaires pour effectuer le **fine-tuning** de modèles déjà entraînés.

LoRA permet d'effectuer efficacement le fine-tuning de **grands modèles** en ne modifiant qu'une **petite partie** du modèle. Il réduit le nombre de paramètres à entraîner, ce qui permet d'économiser de la **mémoire** et des **ressources de calcul**. Cela s'explique par les raisons suivantes :<sup>[[1]](#references)</sup>

1. **Réduction du nombre de paramètres entraînables** : au lieu de mettre à jour l'ensemble de la matrice de poids du modèle, LoRA **divise** la matrice de poids en deux matrices plus petites (appelées **A** et **B**). L'entraînement est ainsi **plus rapide** et nécessite **moins de mémoire**, car moins de paramètres doivent être mis à jour.<sup>[[3]](#references)</sup>

1. En effet, au lieu de calculer la mise à jour complète des poids d'une couche (matrice), celle-ci est approximée par le produit de 2 matrices plus petites, ce qui réduit la mise à jour à calculer :\

2. **Conservation des poids du modèle original** : LoRA permet de conserver les poids du modèle original inchangés et de ne mettre à jour que les **nouvelles petites matrices** (A et B). Cela est utile, car les connaissances originales du modèle sont ainsi préservées et seuls les éléments nécessaires sont ajustés.
3. **Fine-tuning efficace spécifique à une tâche** : lorsque vous souhaitez adapter le modèle à une **nouvelle tâche**, vous pouvez simplement entraîner les **petites matrices LoRA** (A et B) tout en laissant le reste du modèle inchangé. Cette méthode est **beaucoup plus efficace** que le réentraînement du modèle entier.
4. **Efficacité du stockage** : après le fine-tuning, au lieu d'enregistrer un **nouveau modèle complet** pour chaque tâche, il suffit de stocker les **matrices LoRA**, qui sont très petites comparées au modèle entier. Il devient ainsi plus facile d'adapter le modèle à de nombreuses tâches sans utiliser trop d'espace de stockage.

Pour implémenter des LoraLayers à la place des couches Linear lors d'un fine-tuning, ce code est proposé ici [https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb) :<sup>[[2]](#references)</sup>
```python
import math

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.alpha = alpha

def forward(self, x):
x = self.alpha * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
