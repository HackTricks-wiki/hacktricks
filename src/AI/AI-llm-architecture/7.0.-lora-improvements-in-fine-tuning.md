## Maboresho ya LoRA

> [!TIP]
> LoRA inaweza kupunguza kwa kiasi kikubwa idadi ya parameters zinazoweza kufunzwa na memory ya optimizer inayohitajika kwa fine-tuning ya model iliyofunzwa awali.

LoRA hufanya iwezekane kufanya fine-tuning ya **large models** kwa ufanisi kwa kubadilisha tu **sehemu ndogo** ya model. Hupunguza idadi ya parameters unazohitaji kufunza, hivyo kuokoa **memory** na **computational resources**. Hii ni kwa sababu:<sup>[[1]](#references)</sup>

1. **Hupunguza idadi ya parameters zinazoweza kufunzwa**: LoRA hugandisha uzito wa awali `W` na kuwakilisha update ya nyongeza kama product ya low-rank matrices mbili zinazoweza kufunzwa, kwa kawaida `ΔW = B A`, ambapo rank `r` ni ndogo zaidi kuliko vipimo vya input/output.<sup>[[3]](#references)</sup>

1. Hii ni kwa sababu badala ya kukokotoa update kamili ya uzito wa layer (matrix), huikadiria kama product ya matrices 2 ndogo, hivyo kupunguza update inayohitaji kukokotolewa:\

2. **Huhifadhi uzito wa awali wa model bila kubadilika**: Ni adapter matrices pekee zinazoboreshwa. Kugandisha uzito huzuia urekebishaji wa moja kwa moja wa base checkpoint, ingawa tabia ya adapter bado inaweza kubatilisha au kudhoofisha knowledge wakati wa inference.
3. **Efficient Task-Specific Fine-Tuning**: Unapotaka kuibadilisha model kwa **task mpya**, unaweza kufunza tu **LoRA matrices ndogo** (A na B) huku ukiacha sehemu nyingine ya model kama ilivyo. Hii ni **yenye ufanisi zaidi** kuliko kufunza upya model nzima.
4. **Ufanisi wa Storage**: Baada ya fine-tuning, badala ya kuhifadhi **model nzima mpya** kwa kila task, unahitaji kuhifadhi tu **LoRA matrices**, ambazo ni ndogo sana ikilinganishwa na model nzima. Hii hurahisisha kuibadilisha model kwa tasks nyingi bila kutumia storage nyingi.

Utekelezaji mdogo ufuatao umebadilishwa kutoka notebook iliyotajwa. Huanzisha `B` kuwa sifuri ili adapter ianze bila kufanya mabadiliko, na hutumia scaling ya kawaida ya `alpha / rank` kutoka LoRA. Code huhifadhi factors katika maumbo ya input-major (`A` ni `in_dim x rank` na `B` ni `rank x out_dim`), hivyo forward path yake imeandikwa kama `xAB`; hii ni sawa na notation ya `BA` ya paper, lakini ikiwa na maumbo yaliyotranspose.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
