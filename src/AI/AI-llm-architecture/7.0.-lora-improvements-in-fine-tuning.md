## Poboljšanja LoRA

> [!TIP]
> LoRA može značajno smanjiti broj parametara koji se mogu trenirati i količinu memorije optimizer-a potrebnu za fine-tuning pretrained modela.

LoRA omogućava efikasan fine-tuning **velikih modela** tako što menja samo **mali deo** modela. Smanjuje broj parametara koje treba trenirati, čime štedi **memoriju** i **računarske resurse**. To je zato što:<sup>[[1]](#references)</sup>

1. **Smanjuje broj parametara koji se mogu trenirati**: LoRA zamrzava originalne težine `W` i predstavlja aditivnu izmenu kao proizvod dve trenirajuće matrice niskog ranga, najčešće `ΔW = B A`, pri čemu je rang `r` mnogo manji od ulaznih/izlaznih dimenzija.<sup>[[3]](#references)</sup>

1. To je zato što, umesto izračunavanja kompletne izmene težina jednog sloja (matrice), ona aproksimira tu izmenu proizvodom 2 manje matrice, čime se smanjuje količina izmena koju treba izračunati:\

2. **Zadržava nepromenjene originalne težine modela**: Optimizuju se samo adapter matrice. Zamrzavanje težina sprečava direktnu izmenu osnovnog checkpoint-a, iako ponašanje adaptera i dalje može nadjačati ili degradirati znanje tokom inference-a.
3. **Efikasan fine-tuning specifičan za zadatak**: Kada želite da prilagodite model **novom zadatku**, možete trenirati samo **male LoRA matrice** (A i B), dok ostatak modela ostaje nepromenjen. To je **mnogo efikasnije** od ponovnog treniranja celog modela.
4. **Efikasno skladištenje**: Nakon fine-tuning-a, umesto čuvanja **celog novog modela** za svaki zadatak, potrebno je sačuvati samo **LoRA matrice**, koje su veoma male u poređenju sa celim modelom. To olakšava prilagođavanje modela mnogim zadacima bez korišćenja previše prostora za skladištenje.

Sledeća minimalna implementacija prilagođava navedeni notebook. Ona inicijalizuje `B` na nulu, tako da adapter počinje kao no-op, i koristi standardno `alpha / rank` skaliranje iz LoRA pristupa. Kod čuva faktore u oblicima input-major (`A` je `in_dim x rank`, a `B` je `rank x out_dim`), pa je njegova forward putanja napisana kao `xAB`; to je ekvivalent notaciji `BA` iz rada sa transponovanim oblicima.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
