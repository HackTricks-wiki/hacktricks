## Maboresho ya LoRA

> [!TIP]
> LoRA inaweza kupunguza kwa kiasi kikubwa idadi ya parameters zinazoweza kufunzwa na memory ya optimizer inayohitajika kufanya fine-tune ya modeli iliyofunzwa awali.

LoRA hufanya iwezekane kufanya fine-tune ya **modeli kubwa** kwa ufanisi kwa kubadilisha sehemu **ndogo tu** ya modeli. Hupunguza idadi ya parameters unazohitaji kufunza, hivyo kuokoa **memory** na **computational resources**. Hii ni kwa sababu:<sup>[[1]](#references)</sup>

1. **Hupunguza idadi ya parameters zinazoweza kufunzwa**: LoRA hugandisha uzito wa awali `W` na kuwakilisha update ya kuongeza kama zao la low-rank matrices mbili zinazoweza kufunzwa, kwa kawaida `ΔW = B A`, ambapo rank `r` ni ndogo zaidi kuliko vipimo vya input/output.<sup>[[3]](#references)</sup>

1. Hii ni kwa sababu badala ya kukokotoa update kamili ya uzito wa layer (matrix), huikadiria kama zao la matrices 2 madogo, na hivyo kupunguza update inayohitaji kukokotolewa:\

2. **Huacha uzito wa modeli ya awali bila kubadilishwa**: Ni matrices za adapter pekee zinazoboreshwa. Kugandisha uzito huzuia urekebishaji wa moja kwa moja wa base checkpoint, ingawa tabia ya adapter bado inaweza kubatilisha au kudhoofisha maarifa wakati wa inference.
3. **Efficient Task-Specific Fine-Tuning**: Unapotaka kuibadilisha modeli kwa **task mpya**, unaweza kufunza tu **matrices ndogo za LoRA** (A na B) huku ukiacha sehemu iliyobaki ya modeli kama ilivyo. Hii ni **yenye ufanisi zaidi** kuliko kufunza upya modeli nzima.
4. **Ufanisi wa Kuhifadhi**: Baada ya fine-tuning, badala ya kuhifadhi **modeli mpya nzima** kwa kila task, unahitaji kuhifadhi tu **matrices za LoRA**, ambazo ni ndogo sana ikilinganishwa na modeli nzima. Hii hurahisisha kuibadilisha modeli kwa tasks nyingi bila kutumia storage nyingi.

Utekelezaji huu mdogo unaobadilisha d notebook huanzisha `B` kuwa sifuri ili adapter ianze kama no-op, na hutumia scaling ya kawaida ya `alpha / rank` kutoka LoRA. Code huhifadhi factors katika shapes za input-major (`A` ni `in_dim x rank` na `B` ni `rank x out_dim`), kwa hivyo forward path yake imeandikwa kama `xAB`; hii ni sawa na notation ya `BA` ya paper, lakini ikiwa na shapes zilizotranspose.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
