## Mejoras de LoRA

> [!TIP]
> El uso de **LoRA reduce mucho la computación** necesaria para **ajustar finamente** modelos ya entrenados.

LoRA permite ajustar finamente **modelos grandes** de forma eficiente cambiando únicamente una **pequeña parte** del modelo. Reduce el número de parámetros que es necesario entrenar, ahorrando **memoria** y **recursos computacionales**. Esto se debe a que:<sup>[[1]](#references)</sup>

1. **Reduce el número de parámetros entrenables**: En lugar de actualizar toda la matriz de pesos del modelo, LoRA **divide** la matriz de pesos en dos matrices más pequeñas (llamadas **A** y **B**). Esto hace que el entrenamiento sea **más rápido** y requiera **menos memoria**, porque es necesario actualizar menos parámetros.<sup>[[3]](#references)</sup>

1. Esto se debe a que, en lugar de calcular la actualización completa de los pesos de una capa (matriz), la aproxima mediante el producto de 2 matrices más pequeñas, reduciendo la actualización que se debe calcular:\

2. **Mantiene sin cambios los pesos del modelo original**: LoRA permite mantener iguales los pesos originales del modelo y actualizar únicamente las **nuevas matrices pequeñas** (A y B). Esto resulta útil porque preserva el conocimiento original del modelo y solo modifica lo necesario.
3. **Ajuste fino eficiente y específico para cada tarea**: Cuando quieres adaptar el modelo a una **nueva tarea**, solo tienes que entrenar las **matrices pequeñas de LoRA** (A y B), dejando el resto del modelo sin cambios. Esto es **mucho más eficiente** que volver a entrenar el modelo completo.
4. **Eficiencia de almacenamiento**: Después del ajuste fino, en lugar de guardar un **modelo nuevo completo** para cada tarea, solo necesitas almacenar las **matrices de LoRA**, que son muy pequeñas en comparación con el modelo completo. Esto facilita adaptar el modelo a muchas tareas sin utilizar demasiado almacenamiento.

Para implementar LoraLayers en lugar de capas Linear durante un ajuste fino, aquí se propone este código [https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb):<sup>[[2]](#references)</sup>
```python
import math

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.alpha = alpha

def forward(self, x):
x = self.alpha * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
