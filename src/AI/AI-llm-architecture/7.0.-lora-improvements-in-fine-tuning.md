## Ulepszenia LoRA

> [!TIP]
> Użycie **LoRA znacznie zmniejsza obliczenia** wymagane do **fine-tuning** już wytrenowanych modeli.

LoRA umożliwia wydajne przeprowadzanie fine-tuning **dużych modeli** poprzez zmianę tylko **niewielkiej części** modelu. Zmniejsza liczbę parametrów, które trzeba trenować, oszczędzając **pamięć** i **zasoby obliczeniowe**. Dzieje się tak, ponieważ:<sup>[[1]](#references)</sup>

1. **Zmniejsza liczbę trenowalnych parametrów**: Zamiast aktualizować całą macierz wag w modelu, LoRA **dzieli** macierz wag na dwie mniejsze macierze (nazywane **A** i **B**). Dzięki temu trening jest **szybszy** i wymaga **mniej pamięci**, ponieważ aktualizowanych jest mniej parametrów.<sup>[[3]](#references)</sup>

1. Dzieje się tak, ponieważ zamiast obliczać kompletną aktualizację wag warstwy (macierzy), przybliża ją za pomocą iloczynu 2 mniejszych macierzy, zmniejszając ilość obliczeń wymaganych do aktualizacji:\

<figure><img src="../../images/image (9) (1).png" alt=""><figcaption></figcaption></figure>

2. **Zachowuje niezmienione wagi oryginalnego modelu**: LoRA pozwala zachować oryginalne wagi modelu bez zmian i aktualizować tylko **nowe małe macierze** (A i B). Jest to pomocne, ponieważ oznacza, że oryginalna wiedza modelu zostaje zachowana, a modyfikowane jest tylko to, co jest niezbędne.
3. **Wydajny fine-tuning dostosowany do konkretnego zadania**: Gdy chcesz dostosować model do **nowego zadania**, możesz trenować tylko **małe macierze LoRA** (A i B), pozostawiając resztę modelu bez zmian. Jest to **znacznie wydajniejsze** niż ponowne trenowanie całego modelu.
4. **Wydajne wykorzystanie pamięci masowej**: Po zakończeniu fine-tuning, zamiast zapisywać **cały nowy model** dla każdego zadania, wystarczy przechowywać **macierze LoRA**, które są bardzo małe w porównaniu z całym modelem. Ułatwia to dostosowanie modelu do wielu zadań bez wykorzystywania zbyt dużej ilości pamięci masowej.

Aby podczas fine-tuning zaimplementować LoraLayers zamiast warstw Linear, zaproponowano tutaj następujący kod [https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb):<sup>[[2]](#references)</sup>
```python
import math

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.alpha = alpha

def forward(self, x):
x = self.alpha * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
