## Ulepszenia LoRA

> [!TIP]
> LoRA może znacząco zmniejszyć liczbę trenowalnych parametrów oraz pamięć optymalizatora potrzebną do fine-tuning wstępnie wytrenowanego modelu.

LoRA umożliwia wydajny fine-tuning **dużych modeli**, zmieniając tylko **niewielką część** modelu. Zmniejsza liczbę parametrów, które trzeba trenować, oszczędzając **pamięć** i **zasoby obliczeniowe**. Dzieje się tak, ponieważ:<sup>[[1]](#references)</sup>

1. **Zmniejsza liczbę trenowalnych parametrów**: LoRA zamraża oryginalną wagę `W` i przedstawia addytywną aktualizację jako iloczyn dwóch trenowalnych macierzy niskiego rzędu, zwykle `ΔW = B A`, gdzie rząd `r` jest znacznie mniejszy niż wymiary wejściowe/wyjściowe.<sup>[[3]](#references)</sup>

1. Dzieje się tak, ponieważ zamiast obliczać pełną aktualizację wag warstwy (macierzy), przybliża ją za pomocą iloczynu 2 mniejszych macierzy, zmniejszając aktualizację, którą trzeba obliczyć:\

2. **Zachowuje niezmienione oryginalne wagi modelu**: Optymalizowane są tylko macierze adaptera. Zamrożenie wag zapobiega bezpośredniej modyfikacji bazowego checkpointu, chociaż zachowanie adaptera może nadal nadpisywać wiedzę lub pogarszać ją w czasie inferencji.
3. **Wydajny fine-tuning specyficzny dla zadania**: Gdy chcesz dostosować model do **nowego zadania**, możesz trenować tylko **małe macierze LoRA** (A i B), pozostawiając resztę modelu bez zmian. Jest to **znacznie wydajniejsze** niż ponowne trenowanie całego modelu.
4. **Wydajne przechowywanie**: Po fine-tuning, zamiast zapisywać **cały nowy model** dla każdego zadania, musisz przechowywać tylko **macierze LoRA**, które są bardzo małe w porównaniu z całym modelem. Ułatwia to dostosowanie modelu do wielu zadań bez wykorzystywania zbyt dużej ilości miejsca.

Poniższa minimalna implementacja jest adaptacją cytowanego notebooka. Inicjalizuje `B` zerami, dzięki czemu adapter zaczyna działanie jako no-op, oraz wykorzystuje standardowe skalowanie `alpha / rank` z LoRA. Kod przechowuje czynniki w kształtach głównych względem wejścia (`A` ma wymiary `in_dim x rank`, a `B` ma wymiary `rank x out_dim`), dlatego jego ścieżka forward jest zapisana jako `xAB`; jest to odpowiednik notacji `BA` z artykułu, przy użyciu transponowanych kształtów.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
