## Maboresho ya LoRA

> [!TIP]
> Matumizi ya **LoRA hupunguza kwa kiasi kikubwa computation** inayohitajika ili **fine tune** models zilizofunzwa tayari.

LoRA huwezesha kufanya fine-tuning ya **models kubwa** kwa ufanisi kwa kubadilisha tu **sehemu ndogo** ya model. Hupunguza idadi ya parameters unazohitaji kufunza, hivyo kuokoa **memory** na **computational resources**. Hii ni kwa sababu:<sup>[[1]](#references)</sup>

1. **Hupunguza Idadi ya Parameters Zinazoweza Kufunzwa**: Badala ya kusasisha matrix nzima ya uzani katika model, LoRA **hugawanya** matrix ya uzani katika matrices mbili ndogo (zinazoitwa **A** na **B**). Hii hufanya training iwe **haraka zaidi** na ihitaji **memory kidogo** kwa sababu parameters chache ndizo zinahitaji kusasishwa.<sup>[[3]](#references)</sup>

1. Hii ni kwa sababu badala ya kukokotoa update kamili ya uzani ya layer (matrix), huikadiria kama product ya matrices 2 madogo, hivyo kupunguza update inayohitaji kukokotolewa:\

2. **Huhifadhi Uzani wa Awali wa Model Bila Kubadilika**: LoRA hukuwezesha kuweka uzani wa awali wa model kama ulivyo, na kusasisha tu **matrices ndogo mpya** (A na B). Hii ni muhimu kwa sababu inamaanisha kwamba maarifa ya awali ya model yanahifadhiwa, na unabadilisha tu kile kinachohitajika.
3. **Fine-Tuning Yenye Ufanisi kwa Kazi Maalum**: Unapotaka kuibadilisha model ili itumike kwenye **kazi mpya**, unaweza kufunza tu **matrices ndogo za LoRA** (A na B) huku ukiacha sehemu iliyobaki ya model kama ilivyo. Hii ina **ufanisi mkubwa zaidi** kuliko kufunza upya model nzima.
4. **Ufanisi wa Uhifadhi**: Baada ya fine-tuning, badala ya kuhifadhi **model mpya nzima** kwa kila kazi, unahitaji kuhifadhi tu **matrices za LoRA**, ambazo ni ndogo sana ikilinganishwa na model nzima. Hii hurahisisha kuibadilisha model kwa kazi nyingi bila kutumia storage nyingi.

Ili kutekeleza LoraLayers badala ya Linear wakati wa fine-tuning, msimbo huu unapendekezwa hapa [https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb):<sup>[[2]](#references)</sup>
```python
import math

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.alpha = alpha

def forward(self, x):
x = self.alpha * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
