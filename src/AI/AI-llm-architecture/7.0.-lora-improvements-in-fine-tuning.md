## LoRA İyileştirmeleri

> [!TIP]
> LoRA, pretrained bir modeli fine-tune etmek için gereken trainable parameter sayısını ve optimizer memory miktarını önemli ölçüde azaltabilir.

LoRA, modelin yalnızca **küçük bir bölümünü** değiştirerek **large models** modellerin verimli şekilde fine-tune edilmesini mümkün kılar. Train etmeniz gereken parameter sayısını azaltarak **memory** ve **computational resources** tasarrufu sağlar. Bunun nedeni şudur:<sup>[[1]](#references)</sup>

1. **Trainable parameter sayısını azaltır**: LoRA, orijinal weight `W` değerini dondurur ve additive update işlemini, rank `r` değerinin input/output boyutlarından çok daha küçük olduğu, trainable iki low-rank matrix'in çarpımı olarak ifade eder; bu genellikle `ΔW = B A` şeklindedir.<sup>[[3]](#references)</sup>

1. Bunun nedeni, bir layer'ın (matrix) complete weight update işlemini hesaplamak yerine, bunu 2 daha küçük matrix'in çarpımıyla yaklaşık olarak ifade ederek hesaplanacak update miktarını azaltmasıdır:\

<figure><img src="../../images/image (9) (1).png" alt=""><figcaption></figcaption></figure>

2. **Orijinal model weights değerlerini değiştirmeden korur**: Yalnızca adapter matrices optimize edilir. Weights değerlerini dondurmak, base checkpoint'in doğrudan değiştirilmesini önler; ancak adapter davranışı inference sırasında yine de bilgiyi geçersiz kılabilir veya bozabilir.
3. **Efficient Task-Specific Fine-Tuning**: Modeli **new task** için adapte etmek istediğinizde, modelin geri kalanını olduğu gibi bırakarak yalnızca **small LoRA matrices** (A ve B) üzerinde train işlemi gerçekleştirebilirsiniz. Bu, entire model'i yeniden train etmekten **çok daha verimlidir**.
4. **Storage Efficiency**: Fine-tuning sonrasında her task için **whole new model** kaydetmek yerine, entire model ile karşılaştırıldığında çok küçük olan yalnızca **LoRA matrices** değerlerini depolamanız gerekir. Bu, çok fazla storage kullanmadan modeli birçok task'e adapte etmeyi kolaylaştırır.

Aşağıdaki minimal implementation, d notebook'unu adapte eder. Adapter'ın no-op olarak başlaması için `B` değerini sıfıra initialize eder ve LoRA'daki standart `alpha / rank` scaling yöntemini kullanır. Code, factor'leri input-major shapes biçiminde depolar (`A`, `in_dim x rank` ve `B`, `rank x out_dim` şeklindedir); bu nedenle forward path `xAB` olarak yazılmıştır. Bu, paper'daki `BA` notation'ının transposed-shape equivalent'idir.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
