## LoRA-verbeterings

> [!TIP]
> Die gebruik van **LoRA verminder die berekening** wat nodig is om reeds opgeleide modelle te **fine-tune** aansienlik.

LoRA maak dit moontlik om **groot modelle** doeltreffend te fine-tune deur slegs ’n **klein deel** van die model te verander. Dit verminder die aantal parameters wat jy moet train, en bespaar **geheue** en **berekeningshulpbronne**. Dit is omdat:<sup>[[1]](#references)</sup>

1. **Verminder die aantal trainbare parameters**: In plaas daarvan om die volledige gewigsmatriks in die model by te werk, **verdeel** LoRA die gewigsmatriks in twee kleiner matrikse (genoem **A** en **B**). Dit maak training **vinniger** en vereis **minder geheue**, omdat minder parameters bygewerk moet word.<sup>[[3]](#references)</sup>

1. Dit is omdat, in plaas daarvan om die volledige gewigsopdatering van ’n laag (matriks) te bereken, dit benader word as die produk van 2 kleiner matrikse, wat die opdatering wat bereken moet word, verminder:\

2. **Hou die oorspronklike modelgewigte onveranderd**: LoRA laat jou toe om die oorspronklike modelgewigte dieselfde te hou, en slegs die **nuwe klein matrikse** (A en B) by te werk. Dit is nuttig omdat dit beteken dat die model se oorspronklike kennis behoue bly, en dat jy slegs aanpas wat nodig is.
3. **Doeltreffende taakspesifieke fine-tuning**: Wanneer jy die model by ’n **nuwe taak** wil aanpas, kan jy net die **klein LoRA-matrikse** (A en B) train terwyl die res van die model onveranderd bly. Dit is **baie meer doeltreffend** as om die hele model weer te train.
4. **Bergingsdoeltreffendheid**: Nadat jy gefine-tune het, hoef jy nie ’n **volledige nuwe model** vir elke taak te stoor nie; jy hoef slegs die **LoRA-matrikse** te stoor, wat baie klein is in vergelyking met die hele model. Dit maak dit makliker om die model by baie take aan te pas sonder om te veel bergingspasie te gebruik.

Om LoraLayers in plaas van Linear-lae tydens ’n fine-tuning te implementeer, word hierdie kode hier voorgestel [https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb):<sup>[[2]](#references)</sup>
```python
import math

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.alpha = alpha

def forward(self, x):
x = self.alpha * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
