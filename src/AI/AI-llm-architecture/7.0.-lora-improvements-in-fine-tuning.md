## LoRA İyileştirmeleri

> [!TIP]
> LoRA, pretrained bir modeli fine-tune etmek için gereken eğitilebilir parametre sayısını ve optimizer belleğini önemli ölçüde azaltabilir.

LoRA, modelin yalnızca **küçük bir bölümünü** değiştirerek **büyük modellerin** verimli şekilde fine-tune edilmesini mümkün kılar. Eğitmeniz gereken parametre sayısını azaltarak **bellekten** ve **hesaplama kaynaklarından** tasarruf sağlar. Bunun nedeni şudur:<sup>[[1]](#references)</sup>

1. **Eğitilebilir parametre sayısını azaltır**: LoRA, özgün ağırlık `W` değerini dondurur ve ek bir güncellemeyi, genellikle `ΔW = B A` biçiminde, giriş/çıkış boyutlarından çok daha küçük bir rank `r` değerine sahip iki eğitilebilir low-rank matrisin çarpımı olarak temsil eder.<sup>[[3]](#references)</sup>

1. Bunun nedeni, bir katmanın (matrisin) eksiksiz ağırlık güncellemesini hesaplamak yerine, bunu 2 daha küçük matrisin çarpımıyla yaklaşık olarak ifade ederek hesaplanacak güncellemeyi azaltmasıdır:\

<figure><img src="../../images/image (9) (1).png" alt=""><figcaption></figcaption></figure>

2. **Özgün model ağırlıklarını değiştirmeden korur**: Yalnızca adapter matrisleri optimize edilir. Ağırlıkların dondurulması, base checkpoint'in doğrudan değiştirilmesini önler; ancak adapter davranışı inference sırasında bilgiyi yine de geçersiz kılabilir veya bozabilir.
3. **Göreve Özel Verimli Fine-Tuning**: Modeli **yeni bir göreve** uyarlamak istediğinizde, modelin geri kalanını olduğu gibi bırakarak yalnızca **küçük LoRA matrislerini** (A ve B) eğitebilirsiniz. Bu, tüm modeli yeniden eğitmekten **çok daha verimlidir**.
4. **Depolama Verimliliği**: Fine-tuning sonrasında her görev için **tamamen yeni bir model** kaydetmek yerine, tüm modele kıyasla çok küçük olan yalnızca **LoRA matrislerini** depolamanız yeterlidir. Bu, çok fazla depolama alanı kullanmadan modeli birçok göreve uyarlamayı kolaylaştırır.

Aşağıdaki minimal uygulama, atıfta bulunulan notebook'u uyarlar. Adapter'ın no-op olarak başlaması için `B` değerini sıfıra başlatır ve LoRA'daki standart `alpha / rank` ölçeklendirmesini kullanır. Kod, faktörleri input-major şekillerde depolar (`A`, `in_dim x rank` ve `B`, `rank x out_dim` şeklindedir); bu nedenle forward yolu `xAB` olarak yazılmıştır. Bu, makaledeki `BA` gösteriminin transpoze-şekil eşdeğeridir.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
