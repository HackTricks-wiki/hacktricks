## LoRA İyileştirmeleri

> [!TIP]
> LoRA, önceden eğitilmiş bir modeli fine-tuning işleminden geçirmek için gereken trainable parameter sayısını ve optimizer memory miktarını önemli ölçüde azaltabilir.

LoRA, modelin yalnızca **küçük bir bölümünü** değiştirerek **large models** modellerin verimli şekilde fine-tuning işleminden geçirilmesini mümkün kılar. Eğitmeniz gereken parameter sayısını azaltarak **memory** ve **computational resources** tasarrufu sağlar. Bunun nedeni şudur:<sup>[[1]](#references)</sup>

1. **Trainable parameter sayısını azaltır**: LoRA, orijinal weight `W` değerini dondurur ve additive update işlemini, rank `r` değeri input/output dimensions değerlerinden çok daha küçük olan, trainable iki low-rank matrix'in çarpımı olarak temsil eder. Bu genellikle `ΔW = B A` şeklindedir.<sup>[[3]](#references)</sup>

1. Bunun nedeni, bir layer'ın (matrix) complete weight update değerini hesaplamak yerine, bunu 2 küçük matrix'in çarpımı olarak yaklaşık hesaplayarak yapılacak update işlemini azaltmasıdır:\

2. **Orijinal model weight değerlerini değiştirmeden korur**: Yalnızca adapter matrices optimize edilir. Weight değerlerinin dondurulması, base checkpoint üzerinde doğrudan değişiklik yapılmasını önler; ancak adapter davranışı inference sırasında knowledge değerini yine de geçersiz kılabilir veya bozabilir.
3. **Efficient Task-Specific Fine-Tuning**: Modeli **new task** için uyarlamak istediğinizde, modelin geri kalanını olduğu gibi bırakarak yalnızca **small LoRA matrices** (A ve B) üzerinde training yapabilirsiniz. Bu, entire model'i yeniden training işleminden geçirmekten **much more efficient** bir yöntemdir.
4. **Storage Efficiency**: Fine-tuning işleminden sonra her task için **whole new model** kaydetmek yerine yalnızca entire model'e kıyasla çok küçük olan **LoRA matrices** değerlerini saklamanız gerekir. Bu, çok fazla storage kullanmadan modeli birçok task'e uyarlamayı kolaylaştırır.

Aşağıdaki minimal implementation, belirtilen notebook'u uyarlar. Adapter'ın no-op olarak başlaması için `B` değerini zero olarak başlatır ve LoRA'daki standart `alpha / rank` scaling değerini kullanır. Code, factor değerlerini input-major shapes biçiminde saklar (`A`, `in_dim x rank` ve `B`, `rank x out_dim` şeklindedir); bu nedenle forward path `xAB` olarak yazılmıştır. Bu, paper'daki `BA` notation ifadesinin transposed-shape eşdeğeridir.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
