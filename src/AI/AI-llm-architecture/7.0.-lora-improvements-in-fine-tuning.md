## LoRA Improvements

> [!TIP]
> LoRA, pretrained model को fine-tune करने के लिए आवश्यक trainable parameters की संख्या और optimizer memory को काफी कम कर सकता है।

LoRA केवल model के **छोटे हिस्से** को बदलकर **large models** को कुशलतापूर्वक fine-tune करना संभव बनाता है। यह train करने के लिए आवश्यक parameters की संख्या कम करता है, जिससे **memory** और **computational resources** की बचत होती है। ऐसा इसलिए होता है:<sup>[[1]](#references)</sup>

1. **Trainable parameters की संख्या कम करता है**: LoRA मूल weight `W` को freeze करता है और additive update को दो trainable low-rank matrices के product के रूप में दर्शाता है, सामान्यतः `ΔW = B A`, जिसमें rank `r`, input/output dimensions की तुलना में बहुत छोटा होता है।<sup>[[3]](#references)</sup>

1. ऐसा इसलिए है क्योंकि किसी layer (matrix) के complete weight update की गणना करने के बजाय, यह उसे 2 छोटी matrices के product के रूप में approximate करता है, जिससे calculate करने वाला update कम हो जाता है:\

2. **Original model weights को अपरिवर्तित रखता है**: केवल adapter matrices को optimize किया जाता है। Weights को freeze करने से base checkpoint में सीधे modification नहीं होता, हालांकि inference के समय adapter behavior knowledge को override या degrade कर सकता है।
3. **Efficient Task-Specific Fine-Tuning**: जब आप model को किसी **new task** के लिए adapt करना चाहते हैं, तो बाकी model को वैसा ही रखते हुए केवल **small LoRA matrices** (A और B) को train कर सकते हैं। यह पूरे model को retrain करने की तुलना में **बहुत अधिक efficient** है।
4. **Storage Efficiency**: fine-tuning के बाद, प्रत्येक task के लिए **whole new model** save करने के बजाय, आपको केवल **LoRA matrices** store करनी होती हैं, जो पूरे model की तुलना में बहुत छोटी होती हैं। इससे बहुत अधिक storage का उपयोग किए बिना model को कई tasks के लिए adapt करना आसान हो जाता है।

निम्न minimal implementation d notebook को adapt करता है। यह `B` को zero पर initialize करता है, जिससे adapter शुरुआत में no-op के रूप में शुरू होता है, और LoRA के standard `alpha / rank` scaling का उपयोग करता है। Code factors को input-major shapes (`A` का आकार `in_dim x rank` और `B` का आकार `rank x out_dim`) में store करता है, इसलिए इसका forward path `xAB` के रूप में लिखा गया है; यह paper के `BA` notation के transposed-shape equivalent है।<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
