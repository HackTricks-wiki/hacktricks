## Ulepszenia LoRA

> [!TIP]
> LoRA może znacznie zmniejszyć liczbę trenowalnych parametrów oraz ilość pamięci optymalizatora potrzebną do dostrajania pretrained modelu.

LoRA umożliwia wydajne dostrajanie **dużych modeli** poprzez zmianę tylko **niewielkiej części** modelu. Zmniejsza liczbę parametrów, które trzeba trenować, oszczędzając **pamięć** i **zasoby obliczeniowe**. Dzieje się tak, ponieważ:<sup>[[1]](#references)</sup>

1. **Zmniejsza liczbę trenowalnych parametrów**: LoRA zamraża oryginalne wagi `W` i reprezentuje addytywną aktualizację jako iloczyn dwóch trenowalnych macierzy niskiego rzędu, zwykle `ΔW = B A`, gdzie ranga `r` jest znacznie mniejsza niż wymiary wejścia/wyjścia.<sup>[[3]](#references)</sup>

1. Dzieje się tak, ponieważ zamiast obliczać kompletną aktualizację wag warstwy (macierzy), przybliża ją iloczynem 2 mniejszych macierzy, zmniejszając aktualizację, którą trzeba obliczyć:\

<figure><img src="../../images/image (9) (1).png" alt=""><figcaption></figcaption></figure>

2. **Zachowuje niezmienione oryginalne wagi modelu**: Optymalizowane są tylko macierze adaptera. Zamrożenie wag zapobiega bezpośredniej modyfikacji bazowego checkpointu, chociaż działanie adaptera nadal może podczas inference nadpisywać wiedzę lub pogarszać jej jakość.
3. **Wydajne dostrajanie do konkretnego zadania**: Gdy chcesz dostosować model do **nowego zadania**, możesz trenować tylko **małe macierze LoRA** (A i B), pozostawiając resztę modelu bez zmian. Jest to **znacznie wydajniejsze** niż ponowne trenowanie całego modelu.
4. **Wydajne przechowywanie**: Po dostrojeniu, zamiast zapisywać **cały nowy model** dla każdego zadania, wystarczy przechowywać **macierze LoRA**, które są bardzo małe w porównaniu z całym modelem. Ułatwia to dostosowywanie modelu do wielu zadań bez wykorzystywania zbyt dużej ilości miejsca.

Poniższa minimalna implementacja dostosowuje notebook d. Inicjalizuje `B` wartością zero, dzięki czemu adapter zaczyna działanie jako no-op, oraz wykorzystuje standardowe skalowanie `alpha / rank` z LoRA. Kod przechowuje czynniki w kształtach z wymiarem wejściowym na pierwszym miejscu (`A` ma kształt `in_dim x rank`, a `B` ma kształt `rank x out_dim`), dlatego jego ścieżka forward jest zapisana jako `xAB`; jest to odpowiednik notacji `BA` z artykułu, w której kształty są transponowane.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
