## Βελτιώσεις του LoRA

> [!TIP]
> Το LoRA μπορεί να μειώσει σημαντικά τον αριθμό των εκπαιδεύσιμων παραμέτρων και τη μνήμη του optimizer που απαιτούνται για το fine-tuning ενός pretrained model.

Το LoRA καθιστά εφικτό το αποδοτικό fine-tuning **μεγάλων μοντέλων**, αλλάζοντας μόνο ένα **μικρό μέρος** του μοντέλου. Μειώνει τον αριθμό των παραμέτρων που πρέπει να εκπαιδευτούν, εξοικονομώντας **μνήμη** και **υπολογιστικούς πόρους**. Αυτό συμβαίνει επειδή:<sup>[[1]](#references)</sup>

1. **Μειώνει τον αριθμό των εκπαιδεύσιμων παραμέτρων**: Το LoRA παγώνει το αρχικό βάρος `W` και αναπαριστά μια προσθετική ενημέρωση ως το γινόμενο δύο εκπαιδεύσιμων low-rank matrices, συνήθως `ΔW = B A`, με rank `r` πολύ μικρότερο από τις διαστάσεις εισόδου/εξόδου.<sup>[[3]](#references)</sup>

1. Αυτό συμβαίνει επειδή, αντί να υπολογίζει ολόκληρη την ενημέρωση βάρους ενός layer (matrix), την προσεγγίζει ως το γινόμενο 2 μικρότερων matrices, μειώνοντας την ενημέρωση που πρέπει να υπολογιστεί:\

<figure><img src="../../images/image (9) (1).png" alt=""><figcaption></figcaption></figure>

2. **Διατηρεί τα αρχικά βάρη του μοντέλου αμετάβλητα**: Βελτιστοποιούνται μόνο τα adapter matrices. Το πάγωμα των βαρών αποτρέπει την άμεση τροποποίηση του base checkpoint, αν και η συμπεριφορά του adapter μπορεί να παρακάμψει ή να υποβαθμίσει τη γνώση κατά το inference.
3. **Αποδοτικό Task-Specific Fine-Tuning**: Όταν θέλετε να προσαρμόσετε το μοντέλο σε ένα **νέο task**, μπορείτε απλώς να εκπαιδεύσετε τα **μικρά LoRA matrices** (A και B), αφήνοντας το υπόλοιπο μοντέλο ως έχει. Αυτό είναι **πολύ πιο αποδοτικό** από την επανεκπαίδευση ολόκληρου του μοντέλου.
4. **Αποδοτικότητα αποθήκευσης**: Μετά το fine-tuning, αντί να αποθηκεύετε ένα **ολόκληρο νέο μοντέλο** για κάθε task, χρειάζεται να αποθηκεύετε μόνο τα **LoRA matrices**, τα οποία είναι πολύ μικρά σε σύγκριση με ολόκληρο το μοντέλο. Αυτό διευκολύνει την προσαρμογή του μοντέλου σε πολλά tasks χωρίς να χρησιμοποιείται υπερβολικός αποθηκευτικός χώρος.

Η ακόλουθη ελάχιστη υλοποίηση προσαρμόζει το d notebook. Αρχικοποιεί το `B` σε μηδέν, ώστε ο adapter να ξεκινά ως no-op, και χρησιμοποιεί το τυπικό scaling `alpha / rank` του LoRA. Ο κώδικας αποθηκεύει τους factors σε input-major shapes (`A` είναι `in_dim x rank` και `B` είναι `rank x out_dim`), επομένως η forward path του γράφεται ως `xAB`. Αυτό είναι το ισοδύναμο με transposed shapes της σημειογραφίας `BA` του paper.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
