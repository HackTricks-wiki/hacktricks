## LoRA İyileştirmeleri

> [!TIP]
> **LoRA kullanımı**, zaten eğitilmiş modelleri **fine-tune etmek** için gereken **hesaplama miktarını büyük ölçüde azaltır**.

LoRA, modelin yalnızca **küçük bir bölümünü** değiştirerek **büyük modellerin** verimli şekilde fine-tune edilmesini mümkün kılar. Eğitmeniz gereken parametre sayısını azaltarak **bellek** ve **hesaplama kaynaklarından** tasarruf sağlar. Bunun nedeni şunlardır:<sup>[[1]](#references)</sup>

1. **Eğitilebilir Parametre Sayısını Azaltır**: Modeldeki ağırlık matrisinin tamamını güncellemek yerine LoRA, ağırlık matrisini iki daha küçük matrise (**A** ve **B** olarak adlandırılır) **böler**. Bu, güncellenmesi gereken parametre sayısı daha az olduğu için eğitimi **hızlandırır** ve **daha az bellek** gerektirir.<sup>[[3]](#references)</sup>

1. Bunun nedeni, bir katmanın (matrisin) ağırlık güncellemesinin tamamını hesaplamak yerine, bunu 2 daha küçük matrisin çarpımı olarak yaklaşık hesaplaması ve böylece hesaplanacak güncellemeyi azaltmasıdır:\

2. **Orijinal Model Ağırlıklarını Değiştirmeden Korur**: LoRA, orijinal model ağırlıklarını aynı tutmanıza ve yalnızca **yeni küçük matrisleri** (A ve B) güncellemenize olanak tanır. Bu faydalıdır çünkü modelin orijinal bilgisi korunur ve yalnızca gerekli kısımlarda değişiklik yapılır.
3. **Göreve Özel Verimli Fine-Tuning**: Modeli **yeni bir göreve** uyarlamak istediğinizde, modelin geri kalanını olduğu gibi bırakıp yalnızca **küçük LoRA matrislerini** (A ve B) eğitebilirsiniz. Bu, modelin tamamını yeniden eğitmekten **çok daha verimlidir**.
4. **Depolama Verimliliği**: Fine-tuning işleminden sonra her görev için **tamamen yeni bir model** kaydetmek yerine, tüm modele kıyasla çok küçük olan yalnızca **LoRA matrislerini** depolamanız yeterlidir. Bu, çok fazla depolama alanı kullanmadan modeli birçok göreve uyarlamayı kolaylaştırır.

Fine-tuning sırasında Linear katmanları yerine LoraLayers uygulamak için bu kod burada önerilmektedir [https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb):<sup>[[2]](#references)</sup>
```python
import math

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.alpha = alpha

def forward(self, x):
x = self.alpha * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
