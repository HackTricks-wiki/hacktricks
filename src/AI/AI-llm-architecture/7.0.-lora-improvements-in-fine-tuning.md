## LoRAの改善

> [!TIP]
> LoRAは、pretrained modelのfine-tuningに必要なtrainable parameter数とoptimizer memoryを大幅に削減できます。

LoRAは、モデルの**小さな一部**だけを変更することで、**large models**を効率的にfine-tuningできるようにします。trainする必要があるparameter数を減らし、**memory**と**computational resources**を節約します。これは次の理由によるものです。<sup>[[1]](#references)</sup>

1. **trainable parameter数を削減**: LoRAは元のweight `W`をfreezeし、加算的なupdateを、2つのtrainableなlow-rank matrixの積として表現します。一般的には `ΔW = B A` で表し、rank `r`はinput/output dimensionsよりもはるかに小さくします。<sup>[[3]](#references)</sup>

1. これは、layer（matrix）の完全なweight updateを計算する代わりに、2つの小さなmatrixの積として近似し、計算するupdateを削減するためです。:\

<figure><img src="../../images/image (9) (1).png" alt=""><figcaption></figcaption></figure>

2. **元のmodel weightsを変更せずに維持**: 最適化されるのはadapter matricesだけです。weightsをfreezeすることで、base checkpointが直接変更されるのを防げます。ただし、inference時にはadapterの挙動によって、知識がoverrideされたり劣化したりする可能性があります。
3. **Task-Specific Fine-Tuningを効率化**: モデルを**新しいtask**に適応させたい場合、モデルの残りの部分をそのままにして、**小さなLoRA matrices**（AとB）だけをtrainできます。これはモデル全体をretrainするよりも**はるかに効率的**です。
4. **Storage Efficiency**: fine-tuning後、各task用に**モデル全体**を保存する代わりに、モデル全体と比較して非常に小さい**LoRA matrices**だけを保存すれば済みます。これにより、storageを過剰に使用することなく、モデルを多くのtaskに適応させやすくなります。

以下のminimal implementationは、d notebookを応用したものです。`B`をzeroに初期化するため、adapterはno-opとして開始され、LoRA標準の`alpha / rank` scalingを使用します。コードはfactorをinput-major shape（`A`は`in_dim x rank`、`B`は`rank x out_dim`）で保存するため、forward pathは`xAB`として記述されています。これは、paperで使われている`BA` notationと同等のtransposed-shape形式です。<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
