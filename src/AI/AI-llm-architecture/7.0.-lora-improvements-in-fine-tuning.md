## Maboresho ya LoRA

> [!TIP]
> LoRA inaweza kupunguza kwa kiasi kikubwa idadi ya parameters zinazoweza kufunzwa na memory ya optimizer inayohitajika ili kufanya fine-tune ya model iliyofunzwa awali.

LoRA hufanya iwezekane kufanya fine-tune ya **large models** kwa ufanisi kwa kubadilisha tu **sehemu ndogo** ya model. Hupunguza idadi ya parameters unazohitaji kufunza, hivyo kuokoa **memory** na **computational resources**. Hii ni kwa sababu:<sup>[[1]](#references)</sup>

1. **Hupunguza idadi ya parameters zinazoweza kufunzwa**: LoRA hufungia uzito wa awali `W` na kuwakilisha update ya kuongezwa kama product ya matrices mbili za low-rank zinazoweza kufunzwa, kwa kawaida `ΔW = B A`, huku rank `r` ikiwa ndogo zaidi kuliko vipimo vya input/output.<sup>[[3]](#references)</sup>

1. Hii ni kwa sababu badala ya kukokotoa update kamili ya uzito wa layer (matrix), huikadiria kuwa product ya matrices 2 madogo, hivyo kupunguza update inayopaswa kukokotolewa:\

2. **Huweka uzito wa awali wa model bila kubadilishwa**: Ni matrices za adapter pekee zinazoboreshwa. Kufungia uzito huzuia modification ya moja kwa moja ya base checkpoint, ingawa tabia ya adapter bado inaweza kupuuza au kudhoofisha knowledge wakati wa inference.
3. **Efficient Task-Specific Fine-Tuning**: Unapotaka kuibadilisha model ili itumike kwenye **task mpya**, unaweza kufunza tu **LoRA matrices ndogo** (A na B) huku ukiacha sehemu nyingine ya model kama ilivyo. Hii ni **yenye ufanisi zaidi** kuliko kufanya retrain ya model nzima.
4. **Ufanisi wa Storage**: Baada ya fine-tuning, badala ya kuhifadhi **model mpya nzima** kwa kila task, unahitaji kuhifadhi tu **LoRA matrices**, ambazo ni ndogo sana ikilinganishwa na model nzima. Hii hurahisisha kuibadilisha model kwa tasks nyingi bila kutumia storage nyingi.

Implementation ifuatayo ya kiwango cha chini inabadilisha notebook iliyotajwa. Huanzisha `B` kuwa sifuri ili adapter ianze ikiwa no-op, na hutumia scaling ya kawaida ya `alpha / rank` kutoka LoRA. Code huhifadhi factors katika shapes za input-major (`A` ni `in_dim x rank` na `B` ni `rank x out_dim`), kwa hiyo forward path yake imeandikwa kama `xAB`; hii ni sawa na notation ya `BA` ya paper, lakini ikiwa na shapes zilizotranspose.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
