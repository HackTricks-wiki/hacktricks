## Melhorias do LoRA

> [!TIP]
> O uso do **LoRA reduz bastante a computação** necessária para o **ajuste fino** de modelos já treinados.

O LoRA torna possível realizar o ajuste fino de **modelos grandes** de forma eficiente, alterando apenas uma **pequena parte** do modelo. Ele reduz o número de parâmetros que você precisa treinar, economizando **memória** e **recursos computacionais**. Isso acontece porque:<sup>[[1]](#references)</sup>

1. **Reduz o número de parâmetros treináveis**: em vez de atualizar toda a matriz de pesos do modelo, o LoRA **divide** a matriz de pesos em duas matrizes menores (chamadas **A** e **B**). Isso torna o treinamento **mais rápido** e requer **menos memória**, pois menos parâmetros precisam ser atualizados.<sup>[[3]](#references)</sup>

1. Isso acontece porque, em vez de calcular a atualização completa dos pesos de uma camada (matriz), ela é aproximada pelo produto de 2 matrizes menores, reduzindo a atualização a ser calculada:\

2. **Mantém os pesos originais do modelo inalterados**: o LoRA permite manter os pesos originais do modelo iguais e atualizar apenas as **novas matrizes pequenas** (A e B). Isso é útil porque significa que o conhecimento original do modelo é preservado, e você altera apenas o que é necessário.
3. **Ajuste fino eficiente e específico para tarefas**: quando você quiser adaptar o modelo a uma **nova tarefa**, basta treinar as **pequenas matrizes do LoRA** (A e B), mantendo o restante do modelo como está. Isso é **muito mais eficiente** do que treinar novamente o modelo inteiro.
4. **Eficiência de armazenamento**: após o ajuste fino, em vez de salvar um **modelo completamente novo** para cada tarefa, você só precisa armazenar as **matrizes do LoRA**, que são muito pequenas em comparação com o modelo inteiro. Isso facilita a adaptação do modelo a várias tarefas sem usar muito armazenamento.

Para implementar LoraLayers em vez de camadas Linear durante um ajuste fino, este código é proposto aqui [https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb):<sup>[[2]](#references)</sup>
```python
import math

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.alpha = alpha

def forward(self, x):
x = self.alpha * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
