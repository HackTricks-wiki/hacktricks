## Βελτιώσεις του LoRA

> [!TIP]
> Η χρήση του **LoRA μειώνει σημαντικά τους υπολογισμούς** που απαιτούνται για το **fine-tune** ήδη εκπαιδευμένων μοντέλων.

Το LoRA καθιστά δυνατή την αποτελεσματική προσαρμογή **μεγάλων μοντέλων** αλλάζοντας μόνο ένα **μικρό μέρος** του μοντέλου. Μειώνει τον αριθμό των παραμέτρων που πρέπει να εκπαιδευτούν, εξοικονομώντας **μνήμη** και **υπολογιστικούς πόρους**. Αυτό συμβαίνει επειδή:<sup>[[1]](#references)</sup>

1. **Μειώνει τον αριθμό των εκπαιδεύσιμων παραμέτρων**: Αντί να ενημερώνεται ολόκληρος ο πίνακας βαρών του μοντέλου, το LoRA **διαχωρίζει** τον πίνακα βαρών σε δύο μικρότερους πίνακες (που ονομάζονται **A** και **B**). Αυτό κάνει την εκπαίδευση **ταχύτερη** και απαιτεί **λιγότερη μνήμη**, επειδή πρέπει να ενημερωθούν λιγότερες παράμετροι.<sup>[[3]](#references)</sup>

1. Αυτό συμβαίνει επειδή, αντί να υπολογίζεται η πλήρης ενημέρωση βαρών ενός layer (πίνακα), αυτή προσεγγίζεται ως γινόμενο 2 μικρότερων πινάκων, μειώνοντας την ενημέρωση που πρέπει να υπολογιστεί:\

2. **Διατηρεί τα αρχικά βάρη του μοντέλου αμετάβλητα**: Το LoRA σάς επιτρέπει να διατηρείτε τα αρχικά βάρη του μοντέλου ίδια και να ενημερώνετε μόνο τους **νέους μικρούς πίνακες** (A και B). Αυτό είναι χρήσιμο, επειδή σημαίνει ότι διατηρείται η αρχική γνώση του μοντέλου και αλλάζει μόνο ό,τι είναι απαραίτητο.
3. **Αποτελεσματικό fine-tuning για συγκεκριμένες εργασίες**: Όταν θέλετε να προσαρμόσετε το μοντέλο σε μια **νέα εργασία**, μπορείτε απλώς να εκπαιδεύσετε τους **μικρούς πίνακες LoRA** (A και B), αφήνοντας το υπόλοιπο μοντέλο ως έχει. Αυτό είναι **πολύ πιο αποτελεσματικό** από την επανεκπαίδευση ολόκληρου του μοντέλου.
4. **Αποδοτικότητα αποθήκευσης**: Μετά το fine-tuning, αντί να αποθηκεύετε ένα **ολόκληρο νέο μοντέλο** για κάθε εργασία, χρειάζεται να αποθηκεύετε μόνο τους **πίνακες LoRA**, οι οποίοι είναι πολύ μικροί σε σύγκριση με ολόκληρο το μοντέλο. Αυτό διευκολύνει την προσαρμογή του μοντέλου σε πολλές εργασίες χωρίς να χρησιμοποιείται υπερβολικός χώρος αποθήκευσης.

Για να υλοποιηθούν LoraLayers αντί για Linear κατά τη διάρκεια ενός fine-tuning, προτείνεται ο κώδικας εδώ [https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb):<sup>[[2]](#references)</sup>
```python
import math

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.alpha = alpha

def forward(self, x):
x = self.alpha * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
