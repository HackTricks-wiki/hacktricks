## Miglioramenti di LoRA

> [!TIP]
> L'uso di **LoRA riduce notevolmente il calcolo** necessario per eseguire il **fine-tuning** di modelli già addestrati.

LoRA rende possibile eseguire il fine-tuning in modo efficiente di **modelli di grandi dimensioni**, modificando solo una **piccola parte** del modello. Riduce il numero di parametri da addestrare, risparmiando **memoria** e **risorse computazionali**. Questo perché:<sup>[[1]](#references)</sup>

1. **Riduce il numero di parametri addestrabili**: invece di aggiornare l'intera matrice dei pesi nel modello, LoRA **suddivide** la matrice dei pesi in due matrici più piccole (chiamate **A** e **B**). Questo rende l'addestramento **più veloce** e richiede **meno memoria**, perché devono essere aggiornati meno parametri.<sup>[[3]](#references)</sup>

1. Questo perché, invece di calcolare l'aggiornamento completo dei pesi di un layer (matrice), lo approssima come il prodotto di 2 matrici più piccole, riducendo l'aggiornamento da calcolare:\

2. **Mantiene invariati i pesi del modello originale**: LoRA consente di mantenere invariati i pesi del modello originale e aggiorna solo le **nuove matrici di piccole dimensioni** (A e B). Questo è utile perché significa che la conoscenza originale del modello viene preservata e che vengono apportate modifiche solo dove necessario.
3. **Fine-tuning efficiente e specifico per l'attività**: quando vuoi adattare il modello a una **nuova attività**, puoi addestrare solo le **piccole matrici LoRA** (A e B), lasciando invariato il resto del modello. Questo è **molto più efficiente** rispetto al riaddestramento dell'intero modello.
4. **Efficienza dello spazio di archiviazione**: dopo il fine-tuning, invece di salvare un **modello completamente nuovo** per ogni attività, devi solo memorizzare le **matrici LoRA**, che sono molto piccole rispetto al modello completo. Questo rende più semplice adattare il modello a molte attività senza utilizzare troppo spazio di archiviazione.

Per implementare LoraLayers invece di layer Linear durante un fine-tuning, viene proposto qui questo codice [https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb):<sup>[[2]](#references)</sup>
```python
import math

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.alpha = alpha

def forward(self, x):
x = self.alpha * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
