## LoRA-Verbesserungen

> [!TIP]
> LoRA kann die Anzahl der trainierbaren Parameter und den für das Fine-Tuning eines vortrainierten Modells benötigten Optimizer-Speicher erheblich reduzieren.

LoRA ermöglicht es, **große Modelle** effizient einem Fine-Tuning zu unterziehen, indem nur ein **kleiner Teil** des Modells geändert wird. Es reduziert die Anzahl der Parameter, die trainiert werden müssen, und spart dadurch **Speicher** und **Rechenressourcen**. Das liegt daran:<sup>[[1]](#references)</sup>

1. **Reduziert die Anzahl der trainierbaren Parameter**: LoRA friert die ursprünglichen Gewichte `W` ein und stellt ein additives Update als Produkt zweier trainierbarer Matrizen mit niedrigem Rang dar, üblicherweise `ΔW = B A`, wobei der Rang `r` deutlich kleiner ist als die Eingabe-/Ausgabedimensionen.<sup>[[3]](#references)</sup>

1. Das liegt daran, dass das vollständige Gewichtsupdate einer Schicht (Matrix) nicht berechnet wird, sondern durch das Produkt zweier kleinerer Matrizen angenähert wird, wodurch das zu berechnende Update reduziert wird:\

<figure><img src="../../images/image (9) (1).png" alt=""><figcaption></figcaption></figure>

2. **Behält die ursprünglichen Modellgewichte unverändert bei**: Nur die Adaptermatrizen werden optimiert. Das Einfrieren der Gewichte verhindert eine direkte Änderung des Base-Checkpoints, obwohl das Verhalten des Adapters das Wissen während der Inferenz weiterhin überschreiben oder verschlechtern kann.
3. **Effizientes aufgabenspezifisches Fine-Tuning**: Wenn du das Modell an eine **neue Aufgabe** anpassen möchtest, kannst du einfach die **kleinen LoRA-Matrizen** (A und B) trainieren, während der Rest des Modells unverändert bleibt. Das ist **wesentlich effizienter**, als das gesamte Modell neu zu trainieren.
4. **Speichereffizienz**: Nach dem Fine-Tuning musst du nicht für jede Aufgabe ein **vollständig neues Modell** speichern, sondern nur die **LoRA-Matrizen**, die im Vergleich zum gesamten Modell sehr klein sind. Dadurch lässt sich das Modell leichter an viele Aufgaben anpassen, ohne zu viel Speicherplatz zu verwenden.

Die folgende minimale Implementierung passt das zitierte Notebook an. Sie initialisiert `B` mit Null, sodass der Adapter zunächst als No-op beginnt, und verwendet die standardmäßige `alpha / rank`-Skalierung von LoRA. Der Code speichert die Faktoren in eingabemajorierten Formen (`A` ist `in_dim x rank` und `B` ist `rank x out_dim`), sodass der Forward-Pfad als `xAB` geschrieben ist; dies entspricht der Notation `BA` des Papers mit transponierten Dimensionen.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
