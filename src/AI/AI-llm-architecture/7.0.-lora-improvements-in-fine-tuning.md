## Mejoras de LoRA

> [!TIP]
> LoRA puede reducir sustancialmente la cantidad de parámetros entrenables y la memoria del optimizador necesarias para realizar fine-tuning de un modelo preentrenado.

LoRA permite realizar fine-tuning de **modelos grandes** de forma eficiente modificando únicamente una **pequeña parte** del modelo. Reduce la cantidad de parámetros que necesitas entrenar, ahorrando **memoria** y **recursos computacionales**. Esto se debe a que:<sup>[[1]](#references)</sup>

1. **Reduce la cantidad de parámetros entrenables**: LoRA congela el peso original `W` y representa una actualización aditiva como el producto de dos matrices entrenables de bajo rango, normalmente `ΔW = B A`, con un rango `r` mucho menor que las dimensiones de entrada/salida.<sup>[[3]](#references)</sup>

1. Esto se debe a que, en lugar de calcular la actualización completa del peso de una capa (matriz), la aproxima mediante el producto de 2 matrices más pequeñas, reduciendo la actualización que se debe calcular:\

<figure><img src="../../images/image (9) (1).png" alt=""><figcaption></figcaption></figure>

2. **Mantiene sin cambios los pesos del modelo original**: Solo se optimizan las matrices del adapter. Congelar los pesos evita la modificación directa del checkpoint base, aunque el comportamiento del adapter aún puede sobrescribir o degradar el conocimiento durante la inferencia.
3. **Fine-Tuning eficiente y específico para cada tarea**: Cuando quieres adaptar el modelo a una **nueva tarea**, solo tienes que entrenar las **pequeñas matrices de LoRA** (A y B), dejando el resto del modelo tal como está. Esto es **mucho más eficiente** que volver a entrenar el modelo completo.
4. **Eficiencia de almacenamiento**: Después del fine-tuning, en lugar de guardar un **modelo nuevo completo** para cada tarea, solo necesitas almacenar las **matrices de LoRA**, que son muy pequeñas en comparación con el modelo completo. Esto facilita la adaptación del modelo a muchas tareas sin utilizar demasiado almacenamiento.

La siguiente implementación mínima adapta el cuaderno d. Inicializa `B` a cero para que el adapter comience sin efecto, y utiliza el escalado estándar `alpha / rank` de LoRA. El código almacena los factores con formas orientadas a la entrada (`A` es `in_dim x rank` y `B` es `rank x out_dim`), por lo que su ruta forward está escrita como `xAB`; este es el equivalente, con las formas transpuestas, de la notación `BA` del artículo.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
