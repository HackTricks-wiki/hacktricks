## Βελτιώσεις του LoRA

> [!TIP]
> Το LoRA μπορεί να μειώσει σημαντικά τον αριθμό των trainable παραμέτρων και τη μνήμη του optimizer που απαιτούνται για το fine-tuning ενός pretrained model.

Το LoRA καθιστά δυνατή την αποτελεσματική προσαρμογή μεγάλων μοντέλων, αλλάζοντας μόνο ένα μικρό μέρος του μοντέλου. Μειώνει τον αριθμό των παραμέτρων που χρειάζεται να εκπαιδεύσετε, εξοικονομώντας **μνήμη** και **υπολογιστικούς πόρους**. Αυτό συμβαίνει επειδή:<sup>[[1]](#references)</sup>

1. **Μειώνει τον αριθμό των trainable παραμέτρων**: Το LoRA παγώνει το αρχικό βάρος `W` και αναπαριστά μια προσθετική ενημέρωση ως το γινόμενο δύο trainable low-rank πινάκων, συνήθως `ΔW = B A`, με rank `r` πολύ μικρότερο από τις διαστάσεις εισόδου/εξόδου.<sup>[[3]](#references)</sup>

1. Αυτό συμβαίνει επειδή, αντί να υπολογίζει ολόκληρη την ενημέρωση βάρους ενός layer (πίνακα), την προσεγγίζει ως γινόμενο 2 μικρότερων πινάκων, μειώνοντας την ενημέρωση που πρέπει να υπολογιστεί:\

2. **Διατηρεί αμετάβλητα τα αρχικά βάρη του μοντέλου**: Βελτιστοποιούνται μόνο οι adapter πίνακες. Το πάγωμα των βαρών αποτρέπει την άμεση τροποποίηση του base checkpoint, αν και η συμπεριφορά του adapter μπορεί να παρακάμψει ή να υποβαθμίσει τη γνώση κατά το inference.
3. **Αποτελεσματικό Fine-Tuning για Συγκεκριμένες Εργασίες**: Όταν θέλετε να προσαρμόσετε το μοντέλο σε μια **νέα εργασία**, μπορείτε απλώς να εκπαιδεύσετε τους **μικρούς πίνακες LoRA** (A και B), αφήνοντας το υπόλοιπο μοντέλο ως έχει. Αυτό είναι **πολύ πιο αποδοτικό** από την επανεκπαίδευση ολόκληρου του μοντέλου.
4. **Αποδοτικότητα αποθήκευσης**: Μετά το fine-tuning, αντί να αποθηκεύετε ένα **ολόκληρο νέο μοντέλο** για κάθε εργασία, χρειάζεται να αποθηκεύετε μόνο τους **πίνακες LoRA**, οι οποίοι είναι πολύ μικροί σε σύγκριση με ολόκληρο το μοντέλο. Αυτό διευκολύνει την προσαρμογή του μοντέλου σε πολλές εργασίες χωρίς να χρησιμοποιείται υπερβολικός αποθηκευτικός χώρος.

Η ακόλουθη minimal υλοποίηση προσαρμόζει το notebook που αναφέρεται. Αρχικοποιεί το `B` σε μηδέν, ώστε ο adapter να ξεκινά ως no-op, και χρησιμοποιεί το τυπικό scaling `alpha / rank` του LoRA. Ο κώδικας αποθηκεύει τους factors σε input-major σχήματα (`A` είναι `in_dim x rank` και `B` είναι `rank x out_dim`), επομένως η forward διαδρομή του γράφεται ως `xAB`. Αυτό είναι το ισοδύναμο σχήμα με transposition της σημειογραφίας `BA` του paper.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
