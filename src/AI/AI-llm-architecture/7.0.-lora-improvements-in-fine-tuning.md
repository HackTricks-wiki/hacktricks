## Améliorations de LoRA

> [!TIP]
> LoRA peut réduire considérablement le nombre de paramètres entraînables et la mémoire de l'optimiseur nécessaires pour effectuer l'ajustement fin d'un modèle préentraîné.

LoRA permet d'effectuer efficacement l'ajustement fin de **grands modèles** en ne modifiant qu'une **petite partie** du modèle. Il réduit le nombre de paramètres que vous devez entraîner, ce qui économise de la **mémoire** et des **ressources de calcul**. Cela s'explique par les raisons suivantes :<sup>[[1]](#references)</sup>

1. **Réduit le nombre de paramètres entraînables** : LoRA gèle le poids original `W` et représente une mise à jour additive comme le produit de deux matrices entraînables de faible rang, généralement `ΔW = B A`, avec un rang `r` bien inférieur aux dimensions d'entrée/sortie.<sup>[[3]](#references)</sup>

1. Cela s'explique par le fait qu'au lieu de calculer la mise à jour complète des poids d'une couche (matrice), elle est approximée par le produit de 2 matrices plus petites, ce qui réduit la mise à jour à calculer :\

<figure><img src="../../images/image (9) (1).png" alt=""><figcaption></figcaption></figure>

2. **Conserve les poids du modèle original inchangés** : Seules les matrices de l'adaptateur sont optimisées. Le gel des poids empêche la modification directe du checkpoint de base, bien que le comportement de l'adaptateur puisse toujours remplacer ou dégrader les connaissances au moment de l'inférence.
3. **Ajustement fin efficace spécifique à la tâche** : Lorsque vous souhaitez adapter le modèle à une **nouvelle tâche**, vous pouvez simplement entraîner les **petites matrices LoRA** (A et B) tout en laissant le reste du modèle tel quel. C'est **beaucoup plus efficace** que de réentraîner l'intégralité du modèle.
4. **Efficacité du stockage** : Après l'ajustement fin, au lieu d'enregistrer un **nouveau modèle complet** pour chaque tâche, vous devez uniquement stocker les **matrices LoRA**, qui sont très petites comparées à l'ensemble du modèle. Cela facilite l'adaptation du modèle à de nombreuses tâches sans utiliser trop d'espace de stockage.

L'implémentation minimale suivante adapte le notebook cité. Elle initialise `B` à zéro afin que l'adaptateur commence comme une opération nulle, et utilise la mise à l'échelle standard `alpha / rank` de LoRA. Le code stocke les facteurs selon des formes majorées par l'entrée (`A` est `in_dim x rank` et `B` est `rank x out_dim`), de sorte que son chemin de propagation avant est écrit `xAB` ; il s'agit de l'équivalent transposé de la notation `BA` de l'article.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
