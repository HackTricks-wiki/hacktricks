## LoRA-Verbesserungen

> [!TIP]
> Die Verwendung von **LoRA reduziert den Rechenaufwand** für das **fine-tuning** bereits trainierter Modelle erheblich.

LoRA ermöglicht das effiziente fine-tuning **großer Modelle**, indem nur ein **kleiner Teil** des Modells verändert wird. Dadurch wird die Anzahl der zu trainierenden Parameter reduziert, wodurch **Speicher** und **Rechenressourcen** eingespart werden. Dies liegt daran:<sup>[[1]](#references)</sup>

1. **Reduziert die Anzahl trainierbarer Parameter**: Anstatt die gesamte Gewichtsmatrix im Modell zu aktualisieren, **teilt** LoRA die Gewichtsmatrix in zwei kleinere Matrizen (genannt **A** und **B**) auf. Dadurch wird das Training **schneller** und benötigt **weniger Speicher**, da weniger Parameter aktualisiert werden müssen.<sup>[[3]](#references)</sup>

1. Dies liegt daran, dass die vollständige Gewichtsaktualisierung einer Schicht (Matrix) nicht berechnet, sondern durch das Produkt aus 2 kleineren Matrizen angenähert wird, wodurch die zu berechnende Aktualisierung reduziert wird:\

<figure><img src="../../images/image (9) (1).png" alt=""><figcaption></figcaption></figure>

2. **Behält die ursprünglichen Modellgewichte unverändert bei**: Mit LoRA können die ursprünglichen Modellgewichte unverändert bleiben, während nur die **neuen kleinen Matrizen** (A und B) aktualisiert werden. Dies ist hilfreich, da das ursprüngliche Wissen des Modells erhalten bleibt und nur die notwendigen Anpassungen vorgenommen werden.
3. **Effizientes aufgabenspezifisches fine-tuning**: Wenn du das Modell an eine **neue Aufgabe** anpassen möchtest, kannst du einfach die **kleinen LoRA-Matrizen** (A und B) trainieren und den Rest des Modells unverändert lassen. Dies ist **wesentlich effizienter**, als das gesamte Modell neu zu trainieren.
4. **Speichereffizienz**: Nach dem fine-tuning musst du nicht für jede Aufgabe ein **vollständig neues Modell** speichern, sondern nur die **LoRA-Matrizen**, die im Vergleich zum gesamten Modell sehr klein sind. Dadurch lässt sich das Modell einfacher an viele Aufgaben anpassen, ohne zu viel Speicherplatz zu verwenden.

Um während eines fine-tuning LoraLayers anstelle von Linear-Layern zu implementieren, wird hier dieser Code vorgeschlagen [https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/appendix-E/01_main-chapter-code/appendix-E.ipynb):<sup>[[2]](#references)</sup>
```python
import math

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.alpha = alpha

def forward(self, x):
x = self.alpha * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
