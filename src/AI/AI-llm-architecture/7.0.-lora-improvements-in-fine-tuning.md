## Покращення LoRA

> [!TIP]
> LoRA може суттєво зменшити кількість параметрів, які навчаються, і обсяг пам’яті оптимізатора, необхідний для fine-tuning попередньо навченої моделі.

LoRA дає змогу ефективно виконувати fine-tuning **великих моделей**, змінюючи лише **невелику частину** моделі. Вона зменшує кількість параметрів, які потрібно навчати, заощаджуючи **пам’ять** і **обчислювальні ресурси**. Це відбувається тому, що:<sup>[[1]](#references)</sup>

1. **Зменшує кількість параметрів, які навчаються**: LoRA фіксує початкові ваги `W` і представляє адитивне оновлення як добуток двох навчуваних матриць низького рангу, зазвичай `ΔW = B A`, де ранг `r` набагато менший за вхідні/вихідні розмірності.<sup>[[3]](#references)</sup>

1. Це відбувається тому, що замість обчислення повного оновлення ваг шару (матриці) воно апроксимується як добуток 2 менших матриць, що зменшує обсяг оновлення для обчислення:\

2. **Зберігає початкові ваги моделі без змін**: оптимізуються лише матриці адаптера. Фіксація ваг запобігає прямій зміні базового checkpoint, хоча поведінка адаптера під час inference все одно може перевизначати або погіршувати наявні знання.
3. **Ефективний task-specific fine-tuning**: коли потрібно адаптувати модель до **нового завдання**, можна навчати лише **невеликі матриці LoRA** (A і B), залишаючи решту моделі без змін. Це **набагато ефективніше**, ніж повторне навчання всієї моделі.
4. **Ефективність зберігання**: після fine-tuning замість збереження **цілої нової моделі** для кожного завдання потрібно зберегти лише **матриці LoRA**, які є дуже малими порівняно з усією моделлю. Це спрощує адаптацію моделі до багатьох завдань без використання надмірного обсягу сховища.

Наведена нижче мінімальна реалізація адаптує згаданий notebook. Вона ініціалізує `B` нулем, тому адаптер починає роботу як no-op, і використовує стандартне масштабування `alpha / rank` з LoRA. Код зберігає множники у формах, де першою є вхідна розмірність (`A` має форму `in_dim x rank`, а `B` — `rank x out_dim`), тому його forward path записано як `xAB`; це еквівалент форми з транспонованими розмірами для нотації `BA` у статті.<sup>[[2]](#references)[[3]](#references)</sup>
```python
import math
import torch

# Create the LoRA layer with the 2 matrices and the alpha
class LoRALayer(torch.nn.Module):
def __init__(self, in_dim, out_dim, rank, alpha):
super().__init__()
self.A = torch.nn.Parameter(torch.empty(in_dim, rank))
torch.nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))  # similar to standard weight initialization
self.B = torch.nn.Parameter(torch.zeros(rank, out_dim))
self.scaling = alpha / rank

def forward(self, x):
x = self.scaling * (x @ self.A @ self.B)
return x

# Combine it with the linear layer
class LinearWithLoRA(torch.nn.Module):
def __init__(self, linear, rank, alpha):
super().__init__()
self.linear = linear
self.lora = LoRALayer(
linear.in_features, linear.out_features, rank, alpha
)

def forward(self, x):
return self.linear(x) + self.lora(x)

# Replace linear layers with LoRA ones
def replace_linear_with_lora(model, rank, alpha):
for name, module in model.named_children():
if isinstance(module, torch.nn.Linear):
# Replace the Linear layer with LinearWithLoRA
setattr(model, name, LinearWithLoRA(module, rank, alpha))
else:
# Recursively apply the same function to child modules
replace_linear_with_lora(module, rank, alpha)
```
