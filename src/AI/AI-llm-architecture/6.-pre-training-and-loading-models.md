## Sinh văn bản

Để huấn luyện một mô hình, ta cần mô hình đó có thể sinh token mới. Sau đó, ta sẽ so sánh các token được sinh với những token mong đợi để huấn luyện mô hình **học cách sinh các token cần thiết**.

Vì trong các ví dụ trước, ta đã dự đoán một số token, nên có thể dùng lại hàm đó cho mục đích này.

> [!TIP]
> Mục tiêu của giai đoạn thứ sáu này rất đơn giản: **Huấn luyện mô hình từ đầu**. Để làm việc này, ta sẽ dùng kiến trúc LLM ở phần trước, cùng một số vòng lặp duyệt qua các tập dữ liệu bằng các hàm mất mát và bộ tối ưu hóa đã xác định để huấn luyện tất cả tham số của mô hình.

## Đánh giá văn bản

Để huấn luyện chính xác, cần kiểm tra mức độ chính xác của các dự đoán so với token mong đợi. Mục tiêu của quá trình huấn luyện là tối đa hóa khả năng token chính xác được chọn, tức là tăng xác suất của token đó so với các token khác.

Để tối đa hóa xác suất của token chính xác, cần điều chỉnh trọng số của mô hình sao cho xác suất đó được tối đa hóa. Việc cập nhật trọng số được thực hiện thông qua **lan truyền ngược**. Quá trình này cần một **hàm mất mát cần tối đa hóa**. Trong trường hợp này, hàm sẽ là **độ chênh lệch giữa dự đoán được đưa ra và giá trị mong muốn**.

Tuy nhiên, thay vì làm việc với các dự đoán thô, ta sẽ dùng logarit cơ số *n*. Ví dụ, nếu xác suất dự đoán hiện tại của token mong đợi là 7.4541e-05, thì logarit tự nhiên (cơ số *e*) của **7.4541e-05** xấp xỉ **-9.5042**.\
Sau đó, với mỗi mục có độ dài ngữ cảnh là 5 token, chẳng hạn, mô hình cần dự đoán 5 token: 4 token đầu là token cuối cùng của đầu vào, còn token thứ năm là token được dự đoán. Vì vậy, trong trường hợp này, mỗi mục sẽ có 5 dự đoán (dù 4 token đầu đã có trong đầu vào, mô hình không biết điều đó), cùng 5 token mong đợi và do đó có 5 xác suất cần tối đa hóa.

Vì vậy, sau khi tính logarit tự nhiên cho từng dự đoán, ta tính **giá trị trung bình**, **bỏ dấu trừ** (đây được gọi là _cross entropy loss_), và thu được **giá trị cần giảm xuống càng gần 0 càng tốt**, vì logarit tự nhiên của 1 bằng 0:

Một cách khác để đánh giá mô hình hoạt động tốt đến đâu được gọi là perplexity. **Perplexity** là một chỉ số dùng để đánh giá mức độ một mô hình xác suất dự đoán một mẫu. Trong mô hình hóa ngôn ngữ, chỉ số này thể hiện **mức độ không chắc chắn của mô hình** khi dự đoán token tiếp theo trong một chuỗi.\
Ví dụ, perplexity bằng 48725 có nghĩa là khi cần dự đoán một token, mô hình không chắc token nào trong số 48.725 token của bộ từ vựng là phù hợp.

```python
import tiktoken
import torch
import torch.nn as nn
from torch.utils.data import Dataset, DataLoader


class GPTDatasetV1(Dataset):
    def __init__(self, txt, tokenizer, max_length, stride):
        self.input_ids = []
        self.target_ids = []

        # Tokenize the entire text
        token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

        # Use a sliding window to chunk the book into overlapping sequences of max_length
        for i in range(0, len(token_ids) - max_length, stride):
            input_chunk = token_ids[i:i + max_length]
            target_chunk = token_ids[i + 1: i + max_length + 1]
            self.input_ids.append(torch.tensor(input_chunk))
            self.target_ids.append(torch.tensor(target_chunk))

    def __len__(self):
        return len(self.input_ids)

    def __getitem__(self, idx):
        return self.input_ids[idx], self.target_ids[idx]


def create_dataloader_v1(txt, batch_size=4, max_length=256,
                         stride=128, shuffle=True, drop_last=True, num_workers=0):
    # Initialize the tokenizer
    tokenizer = tiktoken.get_encoding("gpt2")

    # Create dataset
    dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)

    # Create dataloader
    dataloader = DataLoader(
        dataset, batch_size=batch_size, shuffle=shuffle, drop_last=drop_last, num_workers=num_workers)

    return dataloader


class MultiHeadAttention(nn.Module):
    def __init__(self, d_in, d_out, context_length, dropout, num_heads, qkv_bias=False):
        super().__init__()
        assert d_out % num_heads == 0, "d_out must be divisible by n_heads"

        self.d_out = d_out
        self.num_heads = num_heads
        self.head_dim = d_out // num_heads  # Reduce the projection dim to match desired output dim

        self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
        self.W_key = nn.Linear(d_in, d_out, bias=qkv_bias)
        self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
        self.out_proj = nn.Linear(d_out, d_out)  # Linear layer to combine head outputs
        self.dropout = nn.Dropout(dropout)
        self.register_buffer('mask', torch.triu(torch.ones(context_length, context_length), diagonal=1))

    def forward(self, x):
        b, num_tokens, d_in = x.shape

        keys = self.W_key(x)  # Shape: (b, num_tokens, d_out)
        queries = self.W_query(x)
        values = self.W_value(x)

        # We implicitly split the matrix by adding a `num_heads` dimension
        # Unroll last dim: (b, num_tokens, d_out) -> (b, num_tokens, num_heads, head_dim)
        keys = keys.view(b, num_tokens, self.num_heads, self.head_dim)
        values = values.view(b, num_tokens, self.num_heads, self.head_dim)
        queries = queries.view(b, num_tokens, self.num_heads, self.head_dim)

        # Transpose: (b, num_tokens, num_heads, head_dim) -> (b, num_heads, num_tokens, head_dim)
        keys = keys.transpose(1, 2)
        queries = queries.transpose(1, 2)
        values = values.transpose(1, 2)

        # Compute scaled dot-product attention (aka self-attention) with a causal mask
        attn_scores = queries @ keys.transpose(2, 3)  # Dot product for each head

        # Original mask truncated to the number of tokens and converted to boolean
        mask_bool = self.mask.bool()[:num_tokens, :num_tokens]

        # Use the mask to fill attention scores
        attn_scores.masked_fill_(mask_bool, -torch.inf)

        attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)
        attn_weights = self.dropout(attn_weights)

        # Shape: (b, num_tokens, num_heads, head_dim)
        context_vec = (attn_weights @ values).transpose(1, 2)

        # Combine heads, where self.d_out = self.num_heads * self.head_dim
        context_vec = context_vec.reshape(b, num_tokens, self.d_out)
        context_vec = self.out_proj(context_vec)  # optional projection

        return context_vec


class LayerNorm(nn.Module):
    def __init__(self, emb_dim):
        super().__init__()
        self.eps = 1e-5
        self.scale = nn.Parameter(torch.ones(emb_dim))
        self.shift = nn.Parameter(torch.zeros(emb_dim))

    def forward(self, x):
        mean = x.mean(dim=-1, keepdim=True)
        var = x.var(dim=-1, keepdim=True, unbiased=False)
        norm_x = (x - mean) / torch.sqrt(var + self.eps)
        return self.scale * norm_x + self.shift


class GELU(nn.Module):
    def __init__(self):
        super().__init__()

    def forward(self, x):
        return 0.5 * x * (1 + torch.tanh(
            torch.sqrt(torch.tensor(2.0 / torch.pi)) *
            (x + 0.044715 * torch.pow(x, 3))
        ))


class FeedForward(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.layers = nn.Sequential(
            nn.Linear(cfg["emb_dim"], 4 * cfg["emb_dim"]),
            GELU(),
            nn.Linear(4 * cfg["emb_dim"], cfg["emb_dim"]),
        )

    def forward(self, x):
        return self.layers(x)


class TransformerBlock(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.att = MultiHeadAttention(
            d_in=cfg["emb_dim"],
            d_out=cfg["emb_dim"],
            context_length=cfg["context_length"],
            num_heads=cfg["n_heads"],
            dropout=cfg["drop_rate"],
            qkv_bias=cfg["qkv_bias"])
        self.ff = FeedForward(cfg)
        self.norm1 = LayerNorm(cfg["emb_dim"])
        self.norm2 = LayerNorm(cfg["emb_dim"])
        self.drop_shortcut = nn.Dropout(cfg["drop_rate"])

    def forward(self, x):
        # Shortcut connection for attention block
        shortcut = x
        x = self.norm1(x)
        x = self.att(x)   # Shape [batch_size, num_tokens, emb_size]
        x = self.drop_shortcut(x)
        x = x + shortcut  # Add the original input back

        # Shortcut connection for feed-forward block
        shortcut = x
        x = self.norm2(x)
        x = self.ff(x)
        x = self.drop_shortcut(x)
        x = x + shortcut  # Add the original input back

        return x


class GPTModel(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.tok_emb = nn.Embedding(cfg["vocab_size"], cfg["emb_dim"])
        self.pos_emb = nn.Embedding(cfg["context_length"], cfg["emb_dim"])
        self.drop_emb = nn.Dropout(cfg["drop_rate"])

        self.trf_blocks = nn.Sequential(
            *[TransformerBlock(cfg) for _ in range(cfg["n_layers"])])

        self.final_norm = LayerNorm(cfg["emb_dim"])
        self.out_head = nn.Linear(cfg["emb_dim"], cfg["vocab_size"], bias=False)

    def forward(self, in_idx):
        batch_size, seq_len = in_idx.shape
        tok_embeds = self.tok_emb(in_idx)
        pos_embeds = self.pos_emb(torch.arange(seq_len, device=in_idx.device))
        x = tok_embeds + pos_embeds  # Shape [batch_size, num_tokens, emb_size]
        x = self.drop_emb(x)
        x = self.trf_blocks(x)
        x = self.final_norm(x)
        logits = self.out_head(x)
        return logits
```

```python
    flat = token_ids.squeeze(0) # remove batch dimension

# Define loss functions
def calc_loss_batch(input_batch, target_batch, model, device):
    input_batch, target_batch = input_batch.to(device), target_batch.to(device)
    logits = model(input_batch)
    loss = torch.nn.functional.cross_entropy(logits.flatten(0, 1), target_batch.flatten())
    return loss


def calc_loss_loader(data_loader, model, device, num_batches=None):
    total_loss = 0.
    if len(data_loader) == 0:
        return float("nan")
    elif num_batches is None:
        num_batches = len(data_loader)
    else:
        # Reduce the number of batches to match the total number of batches in the data loader
        # if num_batches exceeds the number of batches in the data loader
        num_batches = min(num_batches, len(data_loader))
    for i, (input_batch, target_batch) in enumerate(data_loader):
        if i < num_batches:
            loss = calc_loss_batch(input_batch, target_batch, model, device)
            total_loss += loss.item()
        else:
            break
    return total_loss / num_batches

# Functions to train the data
def train_model_simple(model, train_loader, val_loader, optimizer, device, num_epochs,
                       eval_freq, eval_iter, start_context, tokenizer):
    # Initialize lists to track losses and tokens seen
    train_losses, val_losses, track_tokens_seen = [], [], []
    tokens_seen, global_step = 0, -1

    # Main training loop
    for epoch in range(num_epochs):
        model.train()  # Set model to training mode

        for input_batch, target_batch in train_loader:
            optimizer.zero_grad() # Reset loss gradients from previous batch iteration
            loss = calc_loss_batch(input_batch, target_batch, model, device)
            loss.backward() # Calculate loss gradients
            optimizer.step() # Update model weights using loss gradients
            tokens_seen += input_batch.numel()
            global_step += 1

            # Optional evaluation step
            if global_step % eval_freq == 0:
                train_loss, val_loss = evaluate_model(
                    model, train_loader, val_loader, device, eval_iter)
                train_losses.append(train_loss)
                val_losses.append(val_loss)
                track_tokens_seen.append(tokens_seen)
                print(f"Ep {epoch+1} (Step {global_step:06d}): "
                      f"Train loss {train_loss:.3f}, Val loss {val_loss:.3f}")

        # Print a sample text after each epoch
        generate_and_print_sample(
            model, tokenizer, device, start_context
        )

    return train_losses, val_losses, track_tokens_seen


def evaluate_model(model, train_loader, val_loader, device, eval_iter):
    model.eval()
    with torch.no_grad():
        train_loss = calc_loss_loader(train_loader, model, device, num_batches=eval_iter)
        val_loss = calc_loss_loader(val_loader, model, device, num_batches=eval_iter)
    model.train()
    return train_loss, val_loss

    context_size = model.pos_emb.weight.shape[0]
```

### Các hàm chuyển đổi văn bản <--> ID

Đây là một số hàm đơn giản có thể dùng để chuyển đổi văn bản trong từ vựng thành ID và ngược lại. Việc này cần thiết ở đầu quá trình xử lý văn bản và cuối quá trình dự đoán:

```python
# Functions to transform from tokens to ids and from to ids to tokens
def text_to_token_ids(text, tokenizer):
    encoded = tokenizer.encode(text, allowed_special={'<|endoftext|>'})
    encoded_tensor = torch.tensor(encoded).unsqueeze(0) # add batch dimension
    return encoded_tensor

def token_ids_to_text(token_ids, tokenizer):
    flat = token_ids.squeeze(0) # remove batch dimension
    return tokenizer.decode(flat.tolist())
```

### Hàm tạo văn bản

Trong phần trước, ta đã tạo một hàm chỉ lấy **token có xác suất cao nhất** sau khi nhận được logits. Tuy nhiên, điều này có nghĩa là với mỗi đầu vào, luôn tạo ra cùng một kết quả, khiến quá trình rất tất định.

Hàm `generate_text` sau đây sẽ áp dụng các khái niệm `top-k`, `temperature` và `multinomial`.

- **`top-k`** nghĩa là ta sẽ đặt xác suất của tất cả token, trừ k token đứng đầu, thành `-inf`. Vì vậy, nếu k=3, trước khi đưa ra quyết định, chỉ 3 token có xác suất cao nhất mới có xác suất khác `-inf`.
- **`temperature`** nghĩa là mỗi xác suất sẽ được chia cho giá trị temperature. Giá trị `0.1` sẽ làm tăng chênh lệch giữa xác suất cao nhất và thấp nhất, trong khi temperature bằng `5` chẳng hạn sẽ khiến phân bố phẳng hơn. Điều này giúp tăng sự đa dạng trong các phản hồi mà ta muốn LLM tạo ra.
- Sau khi áp dụng temperature, hàm **`softmax`** được áp dụng lần nữa để tổng xác suất của tất cả token còn lại bằng 1.
- Cuối cùng, thay vì chọn token có xác suất cao nhất, hàm **`multinomial`** được áp dụng để **dự đoán token tiếp theo theo các xác suất cuối cùng**. Ví dụ, nếu token 1 có xác suất 70%, token 2 có xác suất 20% và token 3 có xác suất 10%, thì token 1 sẽ được chọn 70% số lần, token 2 sẽ được chọn 20% số lần và token 3 sẽ được chọn 10% số lần.

```python
# Generate text function
def generate_text(model, idx, max_new_tokens, context_size, temperature=0.0, top_k=None, eos_id=None):

    # For-loop is the same as before: Get logits, and only focus on last time step
    for _ in range(max_new_tokens):
        idx_cond = idx[:, -context_size:]
        with torch.no_grad():
            logits = model(idx_cond)
        logits = logits[:, -1, :]

        # New: Filter logits with top_k sampling
        if top_k is not None:
            # Keep only top_k values
            top_logits, _ = torch.topk(logits, top_k)
            min_val = top_logits[:, -1]
            logits = torch.where(logits < min_val, torch.tensor(float("-inf")).to(logits.device), logits)

        # New: Apply temperature scaling
        if temperature > 0.0:
            logits = logits / temperature

            # Apply softmax to get probabilities
            probs = torch.softmax(logits, dim=-1)  # (batch_size, context_len)

            # Sample from the distribution
            idx_next = torch.multinomial(probs, num_samples=1)  # (batch_size, 1)

        # Otherwise same as before: get idx of the vocab entry with the highest logits value
        else:
            idx_next = torch.argmax(logits, dim=-1, keepdim=True)  # (batch_size, 1)

        if idx_next == eos_id:  # Stop generating early if end-of-sequence token is encountered and eos_id is specified
            break

        # Same as before: append sampled index to the running sequence
        idx = torch.cat((idx, idx_next), dim=1)  # (batch_size, num_tokens+1)

    return idx
```

> [!TIP]
> Có một phương pháp thay thế phổ biến cho `top-k` gọi là [**`top-p`**](https://en.wikipedia.org/wiki/Top-p_sampling), còn được gọi là nucleus sampling. Thay vì lấy k mẫu có xác suất cao nhất, phương pháp này **sắp xếp** toàn bộ **vocabulary** theo xác suất rồi **cộng dồn** từ xác suất cao nhất đến thấp nhất cho đến khi **đạt ngưỡng**.
>
> Sau đó, chỉ **những từ đó** trong vocabulary mới được xét theo xác suất tương đối của chúng.
>
> Nhờ vậy, không cần chọn số lượng k mẫu, vì k tối ưu có thể khác nhau trong từng trường hợp; thay vào đó, chỉ cần chọn **một ngưỡng**.
>
> _Lưu ý rằng cải tiến này không có trong đoạn code trước._

> [!TIP]
> Một cách khác để cải thiện văn bản được tạo ra là dùng **Beam search** thay cho greedy search được sử dụng trong ví dụ này.\
> Không giống greedy search, vốn chọn từ tiếp theo có xác suất cao nhất ở mỗi bước và tạo một chuỗi duy nhất, **beam search theo dõi k chuỗi một phần có điểm số cao nhất** (gọi là “beam”) ở mỗi bước. Bằng cách đồng thời khám phá nhiều khả năng, phương pháp này cân bằng giữa hiệu quả và chất lượng, tăng khả năng **tìm được chuỗi tổng thể tốt hơn** mà greedy search có thể bỏ lỡ do đưa ra những lựa chọn chưa tối ưu quá sớm.

### Hàm loss

Hàm **`calc_loss_batch`** tính cross entropy cho một dự đoán trong một batch.\
Hàm **`calc_loss_loader`** tính cross entropy của tất cả các batch rồi tính **cross entropy trung bình**.

```python
# Define loss functions
def calc_loss_batch(input_batch, target_batch, model, device):
    input_batch, target_batch = input_batch.to(device), target_batch.to(device)
    logits = model(input_batch)
    loss = torch.nn.functional.cross_entropy(logits.flatten(0, 1), target_batch.flatten())
    return loss

def calc_loss_loader(data_loader, model, device, num_batches=None):
    total_loss = 0.
    if len(data_loader) == 0:
        return float("nan")
    elif num_batches is None:
        num_batches = len(data_loader)
    else:
        # Reduce the number of batches to match the total number of batches in the data loader
        # if num_batches exceeds the number of batches in the data loader
        num_batches = min(num_batches, len(data_loader))
    for i, (input_batch, target_batch) in enumerate(data_loader):
        if i < num_batches:
            loss = calc_loss_batch(input_batch, target_batch, model, device)
            total_loss += loss.item()
        else:
            break
    return total_loss / num_batches
```

> [!TIP]
> **Gradient clipping** là một kỹ thuật được dùng để tăng **độ ổn định khi huấn luyện** các mạng nơ-ron lớn bằng cách đặt **ngưỡng tối đa** cho độ lớn của gradient. Khi gradient vượt quá `max_norm` được xác định trước, chúng sẽ được giảm tỷ lệ tương ứng để đảm bảo các cập nhật tham số của mô hình nằm trong phạm vi có thể kiểm soát, ngăn các vấn đề như gradient bùng nổ và giúp quá trình huấn luyện ổn định, có kiểm soát hơn.

### Các hàm huấn luyện

Hàm `generate_and_print_sample` chỉ lấy một ngữ cảnh rồi tạo một số token để đánh giá sơ bộ chất lượng của mô hình tại thời điểm đó. Hàm này được `train_model_simple` gọi ở mỗi bước.

Hàm `evaluate_model` được gọi với tần suất do hàm huấn luyện chỉ định và dùng để đo loss trên tập huấn luyện và tập validation tại thời điểm đó trong quá trình huấn luyện mô hình.

Hàm lớn `train_model_simple` là hàm thực sự huấn luyện mô hình. Hàm này cần:

- Data loader của tập huấn luyện (dữ liệu đã được tách và chuẩn bị để huấn luyện)
- Data loader của tập validation
- **Optimizer** sẽ dùng trong quá trình huấn luyện: Đây là hàm sử dụng gradient và cập nhật các tham số để giảm loss. Trong trường hợp này, như bạn sẽ thấy, `AdamW` được sử dụng, nhưng còn nhiều optimizer khác.
  - `optimizer.zero_grad()` được gọi ở mỗi vòng lặp để đặt lại gradient, tránh tích lũy chúng.
  - Tham số **`lr`** là **learning rate**, quyết định **kích thước bước** được thực hiện trong quá trình tối ưu hóa khi cập nhật các tham số của mô hình. Learning rate **nhỏ hơn** nghĩa là optimizer cập nhật trọng số **ít hơn**, có thể giúp hội tụ **chính xác hơn** nhưng cũng khiến quá trình huấn luyện **chậm hơn**. Learning rate **lớn hơn** có thể tăng tốc quá trình huấn luyện nhưng **có nguy cơ vượt quá** điểm cực tiểu của hàm loss (**nhảy qua** điểm mà hàm loss đạt giá trị nhỏ nhất).
  - **Weight Decay** điều chỉnh bước **tính loss** bằng cách thêm một số hạng phụ phạt các trọng số lớn. Điều này khuyến khích optimizer tìm ra các nghiệm có trọng số nhỏ hơn, tạo sự cân bằng giữa việc khớp dữ liệu tốt và giữ mô hình đơn giản, đồng thời ngăn ngừa overfitting trong các mô hình machine learning bằng cách hạn chế việc mô hình gán quá nhiều tầm quan trọng cho bất kỳ đặc trưng riêng lẻ nào.
    - Các optimizer truyền thống như SGD với L2 regularization kết hợp weight decay với gradient của hàm loss. Tuy nhiên, **AdamW** (một biến thể của Adam optimizer) tách weight decay khỏi bước cập nhật gradient, giúp regularization hiệu quả hơn.
- Thiết bị dùng để huấn luyện
- Số epoch: Số lần duyệt qua dữ liệu huấn luyện
- Tần suất đánh giá: Tần suất gọi `evaluate_model`
- Số vòng lặp đánh giá: Số batch dùng để đánh giá trạng thái hiện tại của mô hình khi gọi `generate_and_print_sample`
- Ngữ cảnh ban đầu: Câu bắt đầu sẽ dùng khi gọi `generate_and_print_sample`
- Tokenizer

```python
# Functions to train the data
def train_model_simple(model, train_loader, val_loader, optimizer, device, num_epochs,
                       eval_freq, eval_iter, start_context, tokenizer):
    # Initialize lists to track losses and tokens seen
    train_losses, val_losses, track_tokens_seen = [], [], []
    tokens_seen, global_step = 0, -1

    # Main training loop
    for epoch in range(num_epochs):
        model.train()  # Set model to training mode

        for input_batch, target_batch in train_loader:
            optimizer.zero_grad() # Reset loss gradients from previous batch iteration
            loss = calc_loss_batch(input_batch, target_batch, model, device)
            loss.backward() # Calculate loss gradients
            optimizer.step() # Update model weights using loss gradients
            tokens_seen += input_batch.numel()
            global_step += 1

            # Optional evaluation step
            if global_step % eval_freq == 0:
                train_loss, val_loss = evaluate_model(
                    model, train_loader, val_loader, device, eval_iter)
                train_losses.append(train_loss)
                val_losses.append(val_loss)
                track_tokens_seen.append(tokens_seen)
                print(f"Ep {epoch+1} (Step {global_step:06d}): "
                      f"Train loss {train_loss:.3f}, Val loss {val_loss:.3f}")

        # Print a sample text after each epoch
        generate_and_print_sample(
            model, tokenizer, device, start_context
        )

    return train_losses, val_losses, track_tokens_seen


def evaluate_model(model, train_loader, val_loader, device, eval_iter):
    model.eval() # Set in eval mode to avoid dropout
    with torch.no_grad():
        train_loss = calc_loss_loader(train_loader, model, device, num_batches=eval_iter)
        val_loss = calc_loss_loader(val_loader, model, device, num_batches=eval_iter)
    model.train() # Back to training model applying all the configurations
    return train_loss, val_loss


def generate_and_print_sample(model, tokenizer, device, start_context):
    model.eval() # Set in eval mode to avoid dropout
    context_size = model.pos_emb.weight.shape[0]
    encoded = text_to_token_ids(start_context, tokenizer).to(device)
    with torch.no_grad():
        token_ids = generate_text(
            model=model, idx=encoded,
            max_new_tokens=50, context_size=context_size
        )
    decoded_text = token_ids_to_text(token_ids, tokenizer)
    print(decoded_text.replace("\n", " "))  # Compact print format
    model.train() # Back to training model applying all the configurations
```

> [!TIP]
> Để cải thiện learning rate, có một vài kỹ thuật phù hợp gọi là **linear warmup** và **cosine decay.**
>
> **Linear warmup** gồm việc xác định learning rate ban đầu và learning rate tối đa, sau đó cập nhật đều đặn sau mỗi epoch. Điều này là vì bắt đầu quá trình huấn luyện với các lần cập nhật trọng số nhỏ hơn sẽ giảm nguy cơ mô hình gặp phải các lần cập nhật lớn, gây mất ổn định trong giai đoạn huấn luyện.\
> **Cosine decay** là kỹ thuật **giảm dần learning rate** theo một đường cong nửa cosine **sau giai đoạn warmup**, làm chậm các lần cập nhật trọng số để **giảm thiểu nguy cơ vượt quá** các điểm cực tiểu của loss và đảm bảo quá trình huấn luyện ổn định trong các giai đoạn sau.
>
> _Lưu ý rằng những cải tiến này không được đưa vào đoạn mã trước đó._


### Lưu model

Bạn có thể lưu model + optimizer nếu muốn tiếp tục huấn luyện sau này:

```python
# Save the model and the optimizer for later training
torch.save({
    "model_state_dict": model.state_dict(),
    "optimizer_state_dict": optimizer.state_dict(),
    },
"/tmp/model_and_optimizer.pth"
)
# Note that this model with the optimizer occupied close to 2GB

# Restore model and optimizer for training
checkpoint = torch.load("/tmp/model_and_optimizer.pth", map_location=device, weights_only=True)

model = GPTModel(GPT_CONFIG_124M)
model.load_state_dict(checkpoint["model_state_dict"])
optimizer = torch.optim.AdamW(model.parameters(), lr=5e-4, weight_decay=0.1)
optimizer.load_state_dict(checkpoint["optimizer_state_dict"])
model.train(); # Put in training mode
```

Hoặc chỉ tải mô hình nếu bạn chỉ định sử dụng nó:

```python
# Save the model
torch.save(model.state_dict(), "model.pth")

# Load it
model = GPTModel(GPT_CONFIG_124M)

model.load_state_dict(torch.load("model.pth", map_location=device, weights_only=True))

model.eval() # Put in eval mode
```

### Các cải tiến thực tiễn cho quá trình huấn luyện hiện đại

Vòng lặp trước đủ để hiểu cơ chế, nhưng quá trình pre-training hiện đại thường bổ sung một số tối ưu hóa để cải thiện thông lượng và độ ổn định:

- **Mixed precision (`bfloat16` / `float16`)** để giảm mức sử dụng bộ nhớ và tăng tốc phép nhân ma trận. Trong thực tế, `bfloat16` thường được ưu tiên trên các GPU datacenter NVIDIA đời mới vì có dải số mũ rộng hơn và thường không cần gradient scaling, trong khi `float16` thường dùng `GradScaler`.
- **Gradient accumulation** để mô phỏng global batch size lớn hơn khi toàn bộ batch không vừa VRAM.
- **Gradient clipping** (ví dụ `clip_grad_norm_`) để ngăn các cập nhật tăng vọt, đặc biệt là trong giai đoạn đầu huấn luyện.
- **Activation checkpointing** để đánh đổi thêm năng lực tính toán lấy mức sử dụng bộ nhớ thấp hơn nhiều bằng cách tính toán lại một phần forward pass trong quá trình backpropagation.
- **Fused / memory-efficient attention** (`scaled_dot_product_attention`) để giảm chi phí của attention với các context window dài hơn.
- **Sharded training/checkpointing** (ví dụ FSDP / distributed checkpoints) khi model hoặc optimizer states không còn vừa trên một GPU.

Một ví dụ tối giản trong PyTorch kết hợp một số ý tưởng này trông như sau:

```python
accum_steps = 8
scaler = torch.amp.GradScaler("cuda")
optimizer.zero_grad(set_to_none=True)

for step, (input_batch, target_batch) in enumerate(train_loader, start=1):
    with torch.autocast(device_type="cuda", dtype=torch.float16):
        loss = calc_loss_batch(input_batch, target_batch, model, device)
        loss = loss / accum_steps

    scaler.scale(loss).backward()

    if step % accum_steps == 0:
        scaler.unscale_(optimizer)
        torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
        scaler.step(optimizer)
        scaler.update()
        optimizer.zero_grad(set_to_none=True)
```

> [!WARNING]
> Khi tiền huấn luyện từ checkpoint hoặc repository bên thứ ba, hãy xem **đường dẫn tải mô hình là một phần của bề mặt tấn công**. Ưu tiên tải các tệp `state_dict` hoặc `safetensors` thay vì toàn bộ đối tượng Python được pickle, giữ `trust_remote_code=False` trừ khi bạn đã kiểm tra repository, và xem [../AI-Models-RCE.md](../AI-Models-RCE.md) để biết các ví dụ RCE khi tải mô hình.

### Tải checkpoint an toàn hơn và tiết kiệm bộ nhớ hơn

Với checkpoint lớn, chuỗi thao tác đơn giản `torch.load(...)` + `load_state_dict(...)` có thể tạm thời nhân đôi mức sử dụng bộ nhớ (các tham số đã khởi tạo + trọng số đã tải). Các phiên bản PyTorch gần đây đã bổ sung một số tùy chọn rất hữu ích. Từ PyTorch 2.6, `weights_only=True` là mặc định của `torch.load()` khi không truyền mô-đun pickle tùy chỉnh, nhưng vẫn nên ghi rõ tùy chọn này trong các ví dụ<sup>[[1]](#references)</sup>:

- `weights_only=True`: giới hạn giải tuần tự hóa ở tensor / đối tượng nguyên thủy, thay vì các đối tượng Python được pickle tùy ý.
- `mmap=True`: ánh xạ bộ nhớ các vùng lưu trữ tensor từ đĩa thay vì đọc ngay toàn bộ vào RAM.
- `with torch.device("meta"):`: trước tiên tạo mô-đun với các tensor rỗng.
- `load_state_dict(..., assign=True)`: gán trực tiếp các tensor đã tải vào mô-đun được khởi tạo bằng `meta`.

```python
state_dict = torch.load(
    "model.pth",
    map_location="cpu",
    weights_only=True,
    mmap=True,
)

with torch.device("meta"):
    model = GPTModel(GPT_CONFIG_124M)

model.load_state_dict(state_dict, assign=True)
model.to(device)
model.eval()
```

Điều này đặc biệt hữu ích khi tải các checkpoint nhiều GB trên máy trạm vì giúp giảm đột biến RAM trong quá trình khởi động.

## Tải trọng số GPT2

Có 2 script nhanh để tải trọng số GPT2 trên máy cục bộ. Với cả hai, bạn có thể clone repository [https://github.com/rasbt/LLMs-from-scratch](https://github.com/rasbt/LLMs-from-scratch) về máy, sau đó:

- Script [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch05/01_main-chapter-code/gpt_generate.py](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch05/01_main-chapter-code/gpt_generate.py) sẽ tải xuống toàn bộ trọng số và chuyển đổi định dạng từ OpenAI sang định dạng mà LLM của chúng ta yêu cầu. Script cũng được chuẩn bị sẵn cấu hình cần thiết cùng prompt: "Every effort moves you"
- Script [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch05/02_alternative_weight_loading/weight-loading-hf-transformers.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch05/02_alternative_weight_loading/weight-loading-hf-transformers.ipynb) cho phép bạn tải cục bộ bất kỳ bộ trọng số GPT2 nào (chỉ cần thay đổi biến `CHOOSE_MODEL`) và dự đoán văn bản từ một số prompt.

Nếu thay vì GPT-2, bạn muốn tải một checkpoint mã nguồn mở hiện đại hơn từ Hugging Face, cách làm thông thường là để `transformers` tự động bố trí model và ưu tiên trọng số `safetensors` nếu có<sup>[[2]](#references)</sup>:

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model_id = "google/gemma-7b"

tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype=torch.bfloat16,
    device_map="auto",
    low_cpu_mem_usage=True,
    trust_remote_code=False,
)
```

`device_map="auto"` rất hữu ích khi toàn bộ checkpoint không vừa trong một accelerator, vì loader có thể phân bổ các layer giữa bộ nhớ GPU / CPU. Với các repository lớn, `save_pretrained(..., max_shard_size="5GB")` hoặc các checkpoint tương đương trên Hub tạo ra **checkpoint phân mảnh** cùng một tệp index, cho phép tải chúng theo từng phần thay vì cần một tệp khổng lồ trong RAM<sup>[[2]](#references)</sup>.

Nếu cần kiểm tra hoặc trích một phần tensor mà không tải toàn bộ tệp, `safetensors` cũng hỗ trợ đọc một phần<sup>[[3]](#references)</sup>:

```python
from safetensors import safe_open

with safe_open("model.safetensors", framework="pt", device="cpu") as f:
    emb_slice = f.get_slice("model.embed_tokens.weight")
    vocab_size, hidden_dim = emb_slice.get_shape()
    first_half = emb_slice[:, : hidden_dim // 2]
```
