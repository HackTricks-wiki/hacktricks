## Generowanie tekstu

Aby wytrenować model, będziemy potrzebować, aby był on w stanie generować nowe tokeny. Następnie porównamy wygenerowane tokeny z oczekiwanymi, aby wytrenować model w **uczeniu się tokenów, które powinien generować**.

Ponieważ w poprzednich przykładach przewidzieliśmy już kilka tokenów, możliwe jest ponowne wykorzystanie tej funkcji do tego celu.

> [!TIP]
> Cel tej szóstej fazy jest bardzo prosty: **wytrenować model od podstaw**. W tym celu zostanie wykorzystana wcześniejsza architektura LLM wraz z pętlami przechodzącymi przez zbiory danych, używając zdefiniowanych funkcji straty i optymalizatora do trenowania wszystkich parametrów modelu.

## Ewaluacja tekstu

Aby przeprowadzić prawidłowe trenowanie, należy mierzyć i sprawdzać predykcje uzyskane dla oczekiwanego tokena. Celem trenowania jest maksymalizacja prawdopodobieństwa poprawnego tokena, co obejmuje zwiększenie jego prawdopodobieństwa względem innych tokenów.

Aby zmaksymalizować prawdopodobieństwo poprawnego tokena, należy zmodyfikować wagi modelu tak, aby to prawdopodobieństwo było maksymalne. Aktualizowanie wag odbywa się za pomocą **backpropagation**. Wymaga to **funkcji straty do maksymalizacji**. W tym przypadku funkcją będzie **różnica między wykonaną predykcją a oczekiwaną wartością**.

Jednak zamiast pracować z surowymi predykcjami, zostanie użyty logarytm o podstawie n. Jeśli więc bieżąca predykcja oczekiwanego tokena wynosiła 7.4541e-05, logarytm naturalny (o podstawie *e*) z **7.4541e-05** wynosi w przybliżeniu **-9.5042**.\
Następnie dla każdego przykładu o długości kontekstu wynoszącej na przykład 5 tokenów model będzie musiał przewidzieć 5 tokenów: pierwsze 4 tokeny będą ostatnim tokenem wejścia, a piąty będzie przewidywanym tokenem. Dlatego w takim przypadku dla każdego przykładu będziemy mieć 5 predykcji (nawet jeśli pierwsze 4 znajdowały się na wejściu, model o tym nie wie), z 5 oczekiwanymi tokenami, a tym samym z 5 prawdopodobieństwami do maksymalizacji.

Dlatego po obliczeniu logarytmu naturalnego dla każdej predykcji obliczana jest **średnia**, usuwany jest **symbol minusa** (nazywa się to _cross entropy loss_), a następnie otrzymujemy **liczbę, którą należy zmniejszyć możliwie najbardziej w kierunku 0**, ponieważ logarytm naturalny z 1 wynosi 0:

import tiktoken
import torch
import torch.nn as nn
from torch.utils.data import Dataset, DataLoader


class GPTDatasetV1(Dataset):
def __init__(self, txt, tokenizer, max_length, stride):
self.input_ids = []
self.target_ids = []

# Tokenize the entire text
token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

# Use a sliding window to chunk the book into overlapping sequences of max_length
for i in range(0, len(token_ids) - max_length, stride):
input_chunk = token_ids[i:i + max_length]
target_chunk = token_ids[i + 1: i + max_length + 1]
self.input_ids.append(torch.tensor(input_chunk))
self.target_ids.append(torch.tensor(target_chunk))

def __len__(self):
return len(self.input_ids)

def __getitem__(self, idx):
return self.input_ids[idx], self.target_ids[idx]


def create_dataloader_v1(txt, batch_size=4, max_length=256,
stride=128, shuffle=True, drop_last=True, num_workers=0):
# Initialize the tokenizer
tokenizer = tiktoken.get_encoding("gpt2")

# Create dataset
dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)

# Create dataloader
dataloader = DataLoader(
dataset, batch_size=batch_size, shuffle=shuffle, drop_last=drop_last, num_workers=num_workers)

return dataloader


class MultiHeadAttention(nn.Module):
def __init__(self, d_in, d_out, context_length, dropout, num_heads, qkv_bias=False):
super().__init__()
assert d_out % num_heads == 0, "d_out must be divisible by n_heads"

self.d_out = d_out
self.num_heads = num_heads
self.head_dim = d_out // num_heads  # Reduce the projection dim to match desired output dim

self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.out_proj = nn.Linear(d_out, d_out)  # Linear layer to combine head outputs
self.dropout = nn.Dropout(dropout)
self.register_buffer('mask', torch.triu(torch.ones(context_length, context_length), diagonal=1))

def forward(self, x):
b, num_tokens, d_in = x.shape

keys = self.W_key(x)  # Shape: (b, num_tokens, d_out)
queries = self.W_query(x)
values = self.W_value(x)

# We implicitly split the matrix by adding a `num_heads` dimension
# Unroll last dim: (b, num_tokens, d_out) -> (b, num_tokens, num_heads, head_dim)
keys = keys.view(b, num_tokens, self.num_heads, self.head_dim)
values = values.view(b, num_tokens, self.num_heads, self.head_dim)
queries = queries.view(b, num_tokens, self.num_heads, self.head_dim)

# Transpose: (b, num_tokens, num_heads, head_dim) -> (b, num_heads, num_tokens, head_dim)
keys = keys.transpose(1, 2)
queries = queries.transpose(1, 2)
values = values.transpose(1, 2)

# Compute scaled dot-product attention (aka self-attention) with a causal mask
attn_scores = queries @ keys.transpose(2, 3)  # Dot product for each head

# Original mask truncated to the number of tokens and converted to boolean
mask_bool = self.mask.bool()[:num_tokens, :num_tokens]

# Use the mask to fill attention scores
attn_scores.masked_fill_(mask_bool, -torch.inf)

attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)
attn_weights = self.dropout(attn_weights)

# Shape: (b, num_tokens, num_heads, head_dim)
context_vec = (attn_weights @ values).transpose(1, 2)

# Combine heads, where self.d_out = self.num_heads * self.head_dim
context_vec = context_vec.reshape(b, num_tokens, self.d_out)
context_vec = self.out_proj(context_vec)  # optional projection

return context_vec


class LayerNorm(nn.Module):
def __init__(self, emb_dim):
super().__init__()
self.eps = 1e-5
self.scale = nn.Parameter(torch.ones(emb_dim))
self.shift = nn.Parameter(torch.zeros(emb_dim))

def forward(self, x):
mean = x.mean(dim=-1, keepdim=True)
var = x.var(dim=-1, keepdim=True, unbiased=False)
norm_x = (x - mean) / torch.sqrt(var + self.eps)
return self.scale * norm_x + self.shift


class GELU(nn.Module):
def __init__(self):
super().__init__()

def forward(self, x):
return 0.5 * x * (1 + torch.tanh(
torch.sqrt(torch.tensor(2.0 / torch.pi)) *
(x + 0.044715 * torch.pow(x, 3))
))


class FeedForward(nn.Module):
def __init__(self, cfg):
super().__init__()
self.layers = nn.Sequential(
nn.Linear(cfg["emb_dim"], 4 * cfg["emb_dim"]),
GELU(),
nn.Linear(4 * cfg["emb_dim"], cfg["emb_dim"]),
)

def forward(self, x):
return self.layers(x)


class TransformerBlock(nn.Module):
def __init__(self, cfg):
super().__init__()
self.att = MultiHeadAttention(
d_in=cfg["emb_dim"],
d_out=cfg["emb_dim"],
context_length=cfg["context_length"],
num_heads=cfg["n_heads"],
dropout=cfg["drop_rate"],
qkv_bias=cfg["qkv_bias"])
self.ff = FeedForward(cfg)
self.norm1 = LayerNorm(cfg["emb_dim"])
self.norm2 = LayerNorm(cfg["emb_dim"])
self.drop_shortcut = nn.Dropout(cfg["drop_rate"])

def forward(self, x):
# Shortcut connection for attention block
shortcut = x
x = self.norm1(x)
x = self.att(x)   # Shape [batch_size, num_tokens, emb_size]
x = self.drop_shortcut(x)
x = x + shortcut  # Add the original input back

# Shortcut connection for feed-forward block
shortcut = x
x = self.norm2(x)
x = self.ff(x)
x = self.drop_shortcut(x)
x = x + shortcut  # Add the original input back

return x


class GPTModel(nn.Module):
def __init__(self, cfg):
super().__init__()
self.tok_emb = nn.Embedding(cfg["vocab_size"], cfg["emb_dim"])
self.pos_emb = nn.Embedding(cfg["context_length"], cfg["emb_dim"])
self.drop_emb = nn.Dropout(cfg["drop_rate"])

self.trf_blocks = nn.Sequential(
*[TransformerBlock(cfg) for _ in range(cfg["n_layers"])])

self.final_norm = LayerNorm(cfg["emb_dim"])
self.out_head = nn.Linear(cfg["emb_dim"], cfg["vocab_size"], bias=False)

def forward(self, in_idx):
batch_size, seq_len = in_idx.shape
tok_embeds = self.tok_emb(in_idx)
pos_embeds = self.pos_emb(torch.arange(seq_len, device=in_idx.device))
x = tok_embeds + pos_embeds  # Shape [batch_size, num_tokens, emb_size]
x = self.drop_emb(x)
x = self.trf_blocks(x)
x = self.final_norm(x)
logits = self.out_head(x)
return logits

### Funkcje generujące tekst

W poprzedniej sekcji przedstawiono funkcję, która po uzyskaniu wartości **logits** wybierała jedynie **najbardziej prawdopodobny token**. Oznacza to jednak, że dla każdego wejścia zawsze będzie generowany taki sam wynik, co sprawia, że proces jest bardzo deterministyczny.

Poniższa funkcja `generate_text` wykorzystuje koncepcje `top-k`, `temperature` i `multinomial`.

- **`top-k`** oznacza, że zaczniemy zmniejszać do `-inf` prawdopodobieństwa wszystkich tokenów z wyjątkiem `k` tokenów o najwyższym prawdopodobieństwie. Jeśli więc k=3, przed podjęciem decyzji tylko 3 tokeny o najwyższym prawdopodobieństwie będą miały prawdopodobieństwo różne od `-inf`.
- **`temperature`** oznacza, że każde prawdopodobieństwo zostanie podzielone przez wartość temperatury. Wartość `0.1` zwiększy różnicę między najwyższym a najniższym prawdopodobieństwem, natomiast temperatura równa na przykład `5` sprawi, że rozkład będzie bardziej wyrównany. Pomaga to zwiększyć różnorodność odpowiedzi, jakiej oczekujemy od LLM.
- Po zastosowaniu temperatury ponownie stosowana jest funkcja **`softmax`**, aby wszystkie pozostałe tokeny miały łączne prawdopodobieństwo równe 1.
- Na koniec, zamiast wybierać token o największym prawdopodobieństwie, funkcja **`multinomial`** jest stosowana do **przewidywania następnego tokenu zgodnie z końcowymi prawdopodobieństwami**. Jeśli więc token 1 miał prawdopodobieństwo 70%, token 2 — 20%, a token 3 — 10%, w 70% przypadków zostanie wybrany token 1, w 20% przypadków token 2, a w 10% przypadków token 3.
```python
# Generate text function
def generate_text(model, idx, max_new_tokens, context_size, temperature=0.0, top_k=None, eos_id=None):

# For-loop is the same as before: Get logits, and only focus on last time step
for _ in range(max_new_tokens):
idx_cond = idx[:, -context_size:]
with torch.no_grad():
logits = model(idx_cond)
logits = logits[:, -1, :]

# New: Filter logits with top_k sampling
if top_k is not None:
# Keep only top_k values
top_logits, _ = torch.topk(logits, top_k)
min_val = top_logits[:, -1]
logits = torch.where(logits < min_val, torch.tensor(float("-inf")).to(logits.device), logits)

# New: Apply temperature scaling
if temperature > 0.0:
logits = logits / temperature

# Apply softmax to get probabilities
probs = torch.softmax(logits, dim=-1)  # (batch_size, context_len)

# Sample from the distribution
idx_next = torch.multinomial(probs, num_samples=1)  # (batch_size, 1)

# Otherwise same as before: get idx of the vocab entry with the highest logits value
else:
idx_next = torch.argmax(logits, dim=-1, keepdim=True)  # (batch_size, 1)

if idx_next == eos_id:  # Stop generating early if end-of-sequence token is encountered and eos_id is specified
break

# Same as before: append sampled index to the running sequence
idx = torch.cat((idx, idx_next), dim=1)  # (batch_size, num_tokens+1)

return idx
```
> [!TIP]
> Istnieje powszechna alternatywa dla `top-k` o nazwie [**`top-p`**](https://en.wikipedia.org/wiki/Top-p_sampling), znana również jako nucleus sampling, która zamiast pobierać k próbek o najwyższym prawdopodobieństwie, **porządkuje** całe wynikowe **vocabulary** według prawdopodobieństw i **sumuje** je od najwyższego prawdopodobieństwa do najniższego, aż do **osiągnięcia progu**.
>
> Następnie **tylko te słowa** z vocabulary będą brane pod uwagę zgodnie z ich względnymi prawdopodobieństwami
>
> Dzięki temu nie trzeba wybierać liczby `k` próbek, ponieważ optymalne k może być różne w każdym przypadku, lecz wystarczy **próg**.
>
> _Zauważ, że to ulepszenie nie zostało uwzględnione w poprzednim kodzie._

> [!TIP]
> Innym sposobem na ulepszenie generowanego tekstu jest użycie **Beam search** zamiast greedy search zastosowanego w tym przykładzie.\
> W przeciwieństwie do greedy search, który na każdym kroku wybiera najbardziej prawdopodobne następne słowo i buduje pojedynczą sekwencję, **beam search śledzi 𝑘 k częściowych sekwencji o najwyższych wynikach** (nazywanych „beamami”) na każdym kroku. Dzięki jednoczesnemu analizowaniu wielu możliwości metoda ta zapewnia równowagę między wydajnością a jakością, zwiększając szanse na **znalezienie lepszej całościowej** sekwencji, którą greedy search może pominąć z powodu wczesnych, nieoptymalnych wyborów.
>
> _Zauważ, że to ulepszenie nie zostało uwzględnione w poprzednim kodzie._

### Funkcje straty

Funkcja **`calc_loss_batch`** oblicza cross entropy predykcji dla pojedynczego batcha.\
Funkcja **`calc_loss_loader`** pobiera cross entropy wszystkich batchy i oblicza **średnią cross entropy**.
```python
# Define loss functions
def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)
loss = torch.nn.functional.cross_entropy(logits.flatten(0, 1), target_batch.flatten())
return loss

def calc_loss_loader(data_loader, model, device, num_batches=None):
total_loss = 0.
if len(data_loader) == 0:
return float("nan")
elif num_batches is None:
num_batches = len(data_loader)
else:
# Reduce the number of batches to match the total number of batches in the data loader
# if num_batches exceeds the number of batches in the data loader
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
loss = calc_loss_batch(input_batch, target_batch, model, device)
total_loss += loss.item()
else:
break
return total_loss / num_batches
```
> [!TIP]
> **Gradient clipping** to technika używana do zwiększenia **stabilności treningu** dużych sieci neuronowych poprzez ustawienie **maksymalnego progu** dla wartości gradientów. Gdy gradienty przekraczają wcześniej zdefiniowaną wartość `max_norm`, są proporcjonalnie zmniejszane, aby zapewnić, że aktualizacje parametrów modelu pozostaną w możliwym do opanowania zakresie, zapobiegając problemom takim jak exploding gradients i zapewniając bardziej kontrolowany oraz stabilny trening.
>
> _Pamiętaj, że to ulepszenie nie zostało uwzględnione w poprzednim kodzie._

### Funkcje treningowe

Funkcja `generate_and_print_sample` pobiera kontekst i generuje kilka tokenów, aby uzyskać wyobrażenie o tym, jak dobry jest model w danym momencie. Jest wywoływana przez `train_model_simple` na każdym kroku.

Funkcja `evaluate_model` jest wywoływana z częstotliwością określoną w funkcji treningowej i służy do pomiaru train loss oraz validation loss w danym momencie treningu modelu.

Następnie duża funkcja `train_model_simple` faktycznie trenuje model. Oczekuje:

- Data loadera treningowego (z danymi już rozdzielonymi i przygotowanymi do treningu)
- Validator loadera
- **optimizera**, który ma być używany podczas treningu: jest to funkcja wykorzystująca gradienty i aktualizująca parametry w celu zmniejszenia loss. W tym przypadku, jak zobaczysz, używany jest `AdamW`, ale istnieje wiele innych optimizerów.
- `optimizer.zero_grad()` jest wywoływane w celu zresetowania gradientów w każdej rundzie, aby nie były kumulowane.
- Parametr **`lr`** to **learning rate**, który określa **rozmiar kroków** wykonywanych podczas procesu optymalizacji przy aktualizowaniu parametrów modelu. **Mniejszy** learning rate oznacza, że optimizer wykonuje **mniejsze aktualizacje** wag, co może prowadzić do bardziej **precyzyjnej** zbieżności, ale może również **spowolnić** trening. **Większy** learning rate może przyspieszyć trening, ale wiąże się z ryzykiem **przeskoczenia minimum** funkcji loss (**przeskoczenia** punktu, w którym funkcja loss jest minimalizowana).
- **Weight Decay** modyfikuje krok **obliczania Loss**, dodając dodatkowy składnik, który nakłada karę na duże wagi. Zachęca to optimizer do znajdowania rozwiązań z mniejszymi wagami, równoważąc dobre dopasowanie do danych z zachowaniem prostoty modelu i zapobiegając overfittingowi w modelach machine learning poprzez zniechęcanie modelu do przypisywania zbyt dużego znaczenia pojedynczej cesze.
- Tradycyjne optimizery, takie jak SGD z regularyzacją L2, łączą weight decay z gradientem funkcji loss. Jednak **AdamW** (wariant optimizera Adam) oddziela weight decay od aktualizacji gradientu, co prowadzi do skuteczniejszej regularyzacji.
- Urządzenia, które ma być używane do treningu
- Liczba epok: liczba przejść przez dane treningowe
- Częstotliwość ewaluacji: częstotliwość wywoływania `evaluate_model`
- Liczba iteracji ewaluacji: liczba batchy używanych podczas oceny bieżącego stanu modelu przy wywoływaniu `generate_and_print_sample`
- Początkowy kontekst: zdanie początkowe używane podczas wywoływania `generate_and_print_sample`
- Tokenizer
```python
# Functions to train the data
def train_model_simple(model, train_loader, val_loader, optimizer, device, num_epochs,
eval_freq, eval_iter, start_context, tokenizer):
# Initialize lists to track losses and tokens seen
train_losses, val_losses, track_tokens_seen = [], [], []
tokens_seen, global_step = 0, -1

# Main training loop
for epoch in range(num_epochs):
model.train()  # Set model to training mode

for input_batch, target_batch in train_loader:
optimizer.zero_grad() # Reset loss gradients from previous batch iteration
loss = calc_loss_batch(input_batch, target_batch, model, device)
loss.backward() # Calculate loss gradients
optimizer.step() # Update model weights using loss gradients
tokens_seen += input_batch.numel()
global_step += 1

# Optional evaluation step
if global_step % eval_freq == 0:
train_loss, val_loss = evaluate_model(
model, train_loader, val_loader, device, eval_iter)
train_losses.append(train_loss)
val_losses.append(val_loss)
track_tokens_seen.append(tokens_seen)
print(f"Ep {epoch+1} (Step {global_step:06d}): "
f"Train loss {train_loss:.3f}, Val loss {val_loss:.3f}")

# Print a sample text after each epoch
generate_and_print_sample(
model, tokenizer, device, start_context
)

return train_losses, val_losses, track_tokens_seen


def evaluate_model(model, train_loader, val_loader, device, eval_iter):
model.eval() # Set in eval mode to avoid dropout
with torch.no_grad():
train_loss = calc_loss_loader(train_loader, model, device, num_batches=eval_iter)
val_loss = calc_loss_loader(val_loader, model, device, num_batches=eval_iter)
model.train() # Back to training model applying all the configurations
return train_loss, val_loss


def generate_and_print_sample(model, tokenizer, device, start_context):
model.eval() # Set in eval mode to avoid dropout
context_size = model.pos_emb.weight.shape[0]
encoded = text_to_token_ids(start_context, tokenizer).to(device)
with torch.no_grad():
token_ids = generate_text(
model=model, idx=encoded,
max_new_tokens=50, context_size=context_size
)
decoded_text = token_ids_to_text(token_ids, tokenizer)
print(decoded_text.replace("\n", " "))  # Compact print format
model.train() # Back to training model applying all the configurations
```
> [!TIP]
> Aby poprawić tempo uczenia, istnieje kilka odpowiednich technik o nazwach **linear warmup** i **cosine decay.**
>
> **Linear warmup** polega na zdefiniowaniu początkowego i maksymalnego tempa uczenia oraz jego konsekwentnej aktualizacji po każdej epoce. Dzieje się tak dlatego, że rozpoczęcie treningu od mniejszych aktualizacji wag zmniejsza ryzyko wystąpienia przez model dużych, destabilizujących aktualizacji podczas fazy treningu.\
> **Cosine decay** to technika, która **stopniowo zmniejsza tempo uczenia**, podążając za krzywą połowy cosinusa **po fazie warmup**, spowalniając aktualizacje wag, aby **zminimalizować ryzyko przekroczenia** minimów funkcji straty i zapewnić stabilność treningu w jego późniejszych fazach.
>
> _Należy pamiętać, że te usprawnienia nie zostały uwzględnione w poprzednim kodzie._

### Praktyczne usprawnienia współczesnego treningu

Poprzednia pętla wystarcza do zrozumienia mechaniki, ale współczesny pre-training zwykle dodaje kilka optymalizacji poprawiających przepustowość i stabilność:

- **Mixed precision (`bfloat16` / `float16`)** w celu zmniejszenia zużycia pamięci i przyspieszenia mnożenia macierzy. W praktyce `bfloat16` jest zwykle preferowany na nowszych datacenter GPU firmy NVIDIA, ponieważ zachowuje szerszy zakres wykładnika i zazwyczaj nie wymaga skalowania gradientów, podczas gdy `float16` często korzysta z `GradScaler`.
- **Gradient accumulation** w celu symulowania większego globalnego rozmiaru batcha, gdy cały batch nie mieści się w VRAM.
- **Gradient clipping** (na przykład `clip_grad_norm_`) w celu zapobiegania eksplodującym aktualizacjom, szczególnie na początku treningu.
- **Activation checkpointing** w celu wymiany dodatkowych obliczeń na znacznie mniejsze zużycie pamięci poprzez ponowne obliczanie części forward pass podczas backpropagation.
- **Fused / memory-efficient attention** (`scaled_dot_product_attention`) w celu zmniejszenia kosztu attention dla dłuższych context windows.
- **Sharded training/checkpointing** (na przykład FSDP / distributed checkpoints), gdy model lub stany optymalizatora przestają mieścić się na pojedynczym GPU.

Minimalny przykład łączący niektóre z tych koncepcji w PyTorch wygląda następująco:
```python
accum_steps = 8
scaler = torch.amp.GradScaler("cuda")
optimizer.zero_grad(set_to_none=True)

for step, (input_batch, target_batch) in enumerate(train_loader, start=1):
with torch.autocast(device_type="cuda", dtype=torch.float16):
loss = calc_loss_batch(input_batch, target_batch, model, device)
loss = loss / accum_steps

scaler.scale(loss).backward()

if step % accum_steps == 0:
scaler.unscale_(optimizer)
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
scaler.step(optimizer)
scaler.update()
optimizer.zero_grad(set_to_none=True)
```
> [!WARNING]
> Podczas pre-trainingu z checkpointów lub repozytoriów stron trzecich traktuj **loading path jako część attack surface**. Preferuj ładowanie plików `state_dict` lub `safetensors` zamiast całych spakowanych obiektów Python, pozostawiaj `trust_remote_code=False`, chyba że przeprowadziłeś audyt repozytorium, i sprawdź [../AI-Models-RCE.md](../AI-Models-RCE.md), aby zapoznać się z przykładami RCE podczas ładowania modeli.

### Bezpieczniejsze i bardziej efektywne pamięciowo ładowanie checkpointów

W przypadku dużych checkpointów naiwna sekwencja `torch.load(...)` + `load_state_dict(...)` może tymczasowo podwoić zużycie pamięci (zainicjalizowane parametry + załadowane wagi). Nowsze wersje PyTorch dodały kilka bardzo przydatnych opcji. Począwszy od PyTorch 2.6, `weights_only=True` jest wartością domyślną dla `torch.load()`, gdy nie przekazano niestandardowego modułu pickle, ale w przykładach nadal warto podawać ją jawnie<sup>[[1]](#references)</sup>:

- `weights_only=True`: ogranicza deserializację do tensorów / obiektów prymitywnych zamiast dowolnych spakowanych obiektów Python.
- `mmap=True`: mapuje magazyny tensorów z dysku w pamięci zamiast od razu odczytywać wszystko do RAM.
- `with torch.device("meta"):`: najpierw tworzy moduł z pustymi tensorami.
- `load_state_dict(..., assign=True)`: bezpośrednio przypisuje załadowane tensory do modułu zainicjalizowanego za pomocą `meta`.
```python
state_dict = torch.load(
"model.pth",
map_location="cpu",
weights_only=True,
mmap=True,
)

with torch.device("meta"):
model = GPTModel(GPT_CONFIG_124M)

model.load_state_dict(state_dict, assign=True)
model.to(device)
model.eval()
```
Jest to szczególnie przydatne podczas ładowania checkpointów o rozmiarze wielu GB na workstation, ponieważ ogranicza skoki zużycia RAM podczas uruchamiania.

## Ładowanie wag GPT2

Istnieją 2 szybkie skrypty do lokalnego ładowania wag GPT2. W obu przypadkach możesz najpierw sklonować lokalnie repozytorium [https://github.com/rasbt/LLMs-from-scratch](https://github.com/rasbt/LLMs-from-scratch), a następnie:

- Skrypt [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch05/01_main-chapter-code/gpt_generate.py](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch05/01_main-chapter-code/gpt_generate.py) pobierze wszystkie wagi i przekształci formaty z OpenAI na formaty oczekiwane przez nasz LLM. Skrypt zawiera również wymaganą konfigurację oraz prompt: "Every effort moves you"
- Skrypt [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch05/02_alternative_weight_loading/weight-loading-hf-transformers.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch05/02_alternative_weight_loading/weight-loading-hf-transformers.ipynb) pozwala lokalnie załadować dowolne wagi GPT2 (wystarczy zmienić zmienną `CHOOSE_MODEL`) i przewidywać tekst na podstawie wybranych promptów.

Jeśli zamiast GPT-2 chcesz załadować bardziej nowoczesny open-source checkpoint z Hugging Face, standardowy wzorzec polega na pozwoleniu `transformers` na automatyczne rozmieszczenie modelu oraz preferowaniu wag `safetensors`, gdy są dostępne<sup>[[2]](#references)</sup>:
```python
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model_id = "google/gemma-7b"

tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
model_id,
torch_dtype=torch.bfloat16,
device_map="auto",
low_cpu_mem_usage=True,
trust_remote_code=False,
)
```
`device_map="auto"` jest bardzo przydatne, gdy pełny checkpoint nie mieści się na jednym akceleratorze, ponieważ loader może rozmieścić warstwy w pamięci GPU / CPU. W przypadku dużych repozytoriów `save_pretrained(..., max_shard_size="5GB")` lub równoważne checkpointy Hub generują **sharded checkpoints** oraz indeks, dzięki czemu można je ładować przyrostowo, zamiast wymagać jednego ogromnego pliku w pamięci RAM<sup>[[2]](#references)</sup>.

Jeśli potrzebujesz sprawdzać lub wycinać tensory bez ładowania całego pliku, `safetensors` obsługuje również częściowe odczyty<sup>[[3]](#references)</sup>:
```python
from safetensors import safe_open

with safe_open("model.safetensors", framework="pt", device="cpu") as f:
emb_slice = f.get_slice("model.embed_tokens.weight")
vocab_size, hidden_dim = emb_slice.get_shape()
first_half = emb_slice[:, : hidden_dim // 2]
```
