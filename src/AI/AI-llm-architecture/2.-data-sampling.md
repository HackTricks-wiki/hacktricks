## **Datamonsterneming**

**Datamonsterneming** is 'n belangrike proses in die voorbereiding van data vir die opleiding van groot taalmodelle (LLM's) soos GPT. Dit behels die organisering van teksdata in input- en target-sekwense wat die model gebruik om te leer hoe om die volgende woord (of token) op grond van die voorafgaande woorde te voorspel. Behoorlike datamonsterneming verseker dat die model taalpatrone en afhanklikhede doeltreffend vaslê.

> [!TIP]
> Die doel van hierdie tweede fase is baie eenvoudig: **Monster die input-data en berei dit voor vir die opleidingsfase, gewoonlik deur die dataset in sinne van 'n spesifieke lengte te verdeel en ook die verwagte respons te genereer.**

### **Waarom datamonsterneming belangrik is**

LLM's soos GPT word opgelei om teks te genereer of te voorspel deur die konteks wat deur vorige woorde verskaf word, te verstaan. Om dit te bereik, moet die opleidingsdata op so 'n manier gestruktureer word dat die model die verband tussen woordreekse en die daaropvolgende woorde kan aanleer. Hierdie gestruktureerde benadering stel die model in staat om te veralgemeen en samehangende teks wat kontekstueel relevant is, te genereer.

### **Sleutelkonsepte in datamonsterneming**

1. **Tokenization:** Die opbreek van teks in kleiner eenhede wat tokens genoem word (bv. woorde, subwoorde of karakters).
2. **Sequence Length (max_length):** Die aantal tokens in elke input-sekwens.
3. **Sliding Window:** 'n Metode om oorvleuelende input-sekwense te skep deur 'n venster oor die getokeniseerde teks te verskuif.
4. **Stride:** Die aantal tokens wat die Sliding Window vorentoe beweeg om die volgende sekwens te skep.

### **Stap-vir-stap-voorbeeld**

Kom ons loop deur 'n voorbeeld om datamonsterneming te illustreer.

**Voorbeeldteks**
```arduino
"Lorem ipsum dolor sit amet, consectetur adipiscing elit."
```
**Tokenisering**

Gestel ons gebruik ’n **basiese tokenizer** wat die teks in woorde en leestekens verdeel:
```vbnet
Tokens: ["Lorem", "ipsum", "dolor", "sit", "amet,", "consectetur", "adipiscing", "elit."]
```
**Parameters**

- **Maksimum reeks-lengte (max_length):** 4 tokens
- **Skuifvenster-stapgrootte:** 1 token

**Skep van Invoer- en Teikenreekse**

1. **Skuifvenster-benadering:**
- **Invoerreekse:** Elke invoerreeks bestaan uit `max_length` tokens.
- **Teikenreekse:** Elke teikenreeks bestaan uit die tokens wat onmiddellik op die ooreenstemmende invoerreeks volg.
2. **Genereer van reekse:**

3. **Resulterende invoer- en teikenskikkings:**

- **Invoer:**

```python
[
["Lorem", "ipsum", "dolor", "sit"],
["ipsum", "dolor", "sit", "amet,"],
["dolor", "sit", "amet,", "consectetur"],
["sit", "amet,", "consectetur", "adipiscing"],
]
```

- **Teiken:**

```python
[
["ipsum", "dolor", "sit", "amet,"],
["dolor", "sit", "amet,", "consectetur"],
```

**Visuele voorstelling**

**Skuifvenster met stapgrootte 1:**

- **Eerste venster (Posisies 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Teiken:** \["ipsum", "dolor", "sit", "amet,"]
- **Tweede venster (Posisies 2-5):** \["ipsum", "dolor", "sit", "amet,"] → **Teiken:** \["dolor", "sit", "amet,", "consectetur"]
- **Derde venster (Posisies 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Teiken:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Vierde venster (Posisies 4-7):** \["sit", "amet,", "consectetur", "adipiscing"] → **Teiken:** \["amet,", "consectetur", "adipiscing", "elit."]

**Verstaan van stapgrootte**

- **Stapgrootte van 1:** Die venster beweeg elke keer een token vorentoe, wat hoogs oorvleuelende reekse tot gevolg het. Dit kan lei tot beter aanleer van kontekstuele verhoudings, maar kan die risiko van oorpassing verhoog omdat soortgelyke datapunte herhaal word.
- **Stapgrootte van 2:** Die venster beweeg elke keer twee tokens vorentoe, wat oorvleueling verminder. Dit verminder oortolligheid en berekeningslading, maar kan sommige kontekstuele nuanses mis.
- **Stapgrootte gelyk aan max_length:** Die venster beweeg met die volle venstergrootte vorentoe, wat nie-oorvleuelende reekse tot gevolg het. Dit beperk data-oortolligheid, maar kan die model se vermoë om afhanklikhede oor reekse heen aan te leer, beperk.

**Voorbeeld met stapgrootte 2:**

Gebruik dieselfde getokeniseerde teks en `max_length` van 4:

- **Eerste venster (Posisies 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Teiken:** \["ipsum", "dolor", "sit", "amet,"]
- **Tweede venster (Posisies 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Teiken:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Derde venster (Posisies 5-8):** \["amet,", "consectetur", "adipiscing", "elit."] → **Teiken:** \["consectetur", "adipiscing", "elit.", "sed"] _(Met voortsetting aanvaar)_

```python
# Download the text to pre-train the LLM
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

"""
Create a class that receives parameters such as a tokenizer and text
and will prepare the input chunks and the target chunks to prepare
the LLM to learn which next token to generate
"""
import torch
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
def __init__(self, txt, tokenizer, max_length, stride):
self.input_ids = []
self.target_ids = []

# Tokenize the entire text
token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

# Use a sliding window to chunk the book into overlapping sequences of max_length
for i in range(0, len(token_ids) - max_length, stride):
input_chunk = token_ids[i:i + max_length]
target_chunk = token_ids[i + 1: i + max_length + 1]
self.input_ids.append(torch.tensor(input_chunk))
self.target_ids.append(torch.tensor(target_chunk))

def __len__(self):
return len(self.input_ids)

def __getitem__(self, idx):
return self.input_ids[idx], self.target_ids[idx]


"""
Create a data loader which given the text and some params will
prepare the inputs and targets with the previous class and
then create a torch DataLoader with the info
"""

import tiktoken

def create_dataloader_v1(txt, batch_size=4, max_length=256,
stride=128, shuffle=True, drop_last=True,
num_workers=0):

# Initialize the tokenizer
tokenizer = tiktoken.get_encoding("gpt2")

# Create dataset
dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)

# Create dataloader
dataloader = DataLoader(
dataset,
batch_size=batch_size,
shuffle=shuffle,
drop_last=drop_last,
num_workers=num_workers
)

return dataloader


"""
Finally, create the data loader with the params we want:
- The used text for training
- batch_size: The size of each batch
- max_length: The size of each entry on each batch
- stride: The sliding window (how many tokens should the next entry advance compared to the previous one). The smaller the more overfitting, usually this is equals to the max_length so the same tokens aren't repeated.
- shuffle: Re-order randomly
"""
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=4, stride=1, shuffle=False
)

data_iter = iter(dataloader)
first_batch = next(data_iter)
print(first_batch)

# Note the batch_size of 8, the max_length of 4 and the stride of 1
```

## Gevorderde Sampling-strategieë (2023-2025)

### 1. Temperature-Based Mixture Weighting
State-of-the-art LLM's word selde op slegs een corpus opgelei. In plaas daarvan sample hulle uit verskeie heterogene databronne (kode, web, akademiese referate, forums…). Die relatiewe verhouding van elke bron kan downstream-prestasie sterk beïnvloed. Onlangse open-source-modelle soos Llama 2 het ’n **temperature-based sampling scheme** bekendgestel, waar die waarskynlikheid om ’n dokument uit corpus *i* te trek, word
```
p(i) = \frac{w_i^{\alpha}}{\sum_j w_j^{\alpha}}
```
• *w<sub>i</sub>* – rou tokenpersentasie van korpus *i*  
• *α* ("temperature") – ’n waarde in (0,1]. α < 1 maak die verspreiding platter, wat meer gewig aan kleiner korpusse van hoë gehalte gee.

Met `α < 1` maak hierdie weging die verspreiding platter en verhoog dit die relatiewe sampling-waarskynlikheid van kleiner korpusse. Temperature-based sampling word wyd gebruik om meertalige pretraining-data te balanseer, hoewel herhalingslimiete nodig is om oorpassing op klein bronne te voorkom.<sup>[[4]](#references)</sup>
```python
from collections import Counter

def temperature_sample(corpus_ids, alpha=0.7):
counts = Counter(corpus_ids)           # number of tokens seen per corpus
probs  = {c: c_count**alpha for c, c_count in counts.items()}
Z = sum(probs.values())
probs = {c: p/Z for c, p in probs.items()}
# Now draw according to probs to fill every batch
```
### 2. Sequence Packing / Dynamic Batching
GPU-geheue word vermors wanneer elke sequence in 'n batch tot die langste voorbeeld opgevul word. **Packing** groepeer verskeie korter voorbeelde in blokke met 'n vaste lengte. 'n Konvensionele packed implementasie gebruik 'n segmentbewuste of blokdiagonale `attention_mask` sodat tokens nie oor voorbeeldgrense heen kan attend nie; padding-free implementasies kan eerder die batch flatten en grense met posisie-inligting behou. Hugging Face TRL stel packing beskikbaar deur `SFTConfig(packing=True)` en dokumenteer die beskikbare strategieë.<sup>[[5]](#references)</sup>

Vir 'n konkrete TRL-konfigurasie definieer `max_length` die grootte van die packed blok, en `packing_strategy` kies óf best-fit decreasing (`"bfd"`) óf wrapped packing. Best-fit decreasing maak padding-free batches moontlik; eksplisiete `padding_free=True` word met FlashAttention 2 of 3 ondersteun. Moenie `pad_to_multiple_of` met packing verwar nie: dit rond slegs padded sequence-lengtes af tot 'n gekose veelvoud.<sup>[[5]](#references)</sup>

**Dynamic of length-aware batching is 'n aparte optimalisering:** dit concateneer nie voorbeelde nie. In plaas daarvan groepeer dit voorbeelde met soortgelyke lengtes sodat elke dinamies padded batch minder padding-tokens bevat. Huidige Hugging Face Transformers stel dit beskikbaar as `train_sampling_strategy="group_by_length"`; 'n voorafberekende `length`-kolom wat deur `length_column_name` gekies word, vermy die berekening van elke voorbeeld se lengte wanneer training begin.<sup>[[8]](#references)</sup>

### 3. Deduplication & Quality Filtering
Herhaalde passasies veroorsaak memorization en bied 'n maklike kanaal vir data poisoning. 'n Verdedigbare cleaning pipeline kombineer dus:

1. **Exact en near-duplicate detection:** hash genormaliseerde dokumente, gebruik MinHash/LSH oor token n-grams vir skaalbare near-duplicate discovery, en gebruik exact-substring-metodes wanneer lang herhaalde passasies verwyder moet word.<sup>[[6]](#references)</sup>
2. **Quality filtering:** verwerp ongeldige encodings, beskadigde markup, patologiese herhaling en dokumente in die verkeerde taal. Reference-model perplexity kan 'n verdere sein wees, maar die drempel daarvan moet vir die corpus gekalibreer word eerder as om dit as 'n universele afsnypunt te behandel.<sup>[[2]](#references)</sup>
3. **Sensitive-data filtering:** skandeer vir credentials en PII met deterministiese patrone plus entity detection, en plaas matches in quarantine vir review sodat false positives nie nuttige training data stilweg uitwis nie.<sup>[[7]](#references)</sup>

Die Llama 2-paper beskryf deduplication en source filtering as deel van corpus construction.<sup>[[2]](#references)</sup> Onafhanklike navorsing het bevind dat deduplicating van language-model training data verbatim memorization verminder en minder training steps vir gelyke of beter akkuraatheid kan vereis.<sup>[[6]](#references)</sup>

## Security & Privacy Considerations During Sampling

### Data-Poisoning / Backdoor Attacks
Navorsers het getoon dat die invoeging van <1 % backdoored sentences 'n model kan laat gehoorsaam aan 'n versteekte trigger ("PoisonGPT", 2023).<sup>[[3]](#references)</sup>  Aanbevole mitigations:

* **Shuffled mixing** – maak seker dat aangrensende training examples uit verskillende bronne afkomstig is; dit verdun die gradient alignment van kwaadwillige spans.
* **Gradient similarity scoring** – bereken die cosine similarity van die example gradient teenoor die batch average; outliers is kandidate vir verwydering.
* **Dataset versioning & hashes** – vries immutable tarballs en verifieer SHA-256 voor elke training run.

### Membership-Inference & Memorization
Lang overlap tussen sliding-window samples herhaal skaars strings soos telefoonnommers of secret keys, wat hul effektiewe frekwensie verhoog. Navorsing oor training-data privacy toon dat duplicated sequences buite verhouding geregenereer word en dat deduplication hierdie blootstelling wesenlik verminder.<sup>[[7]](#references)</sup>

Praktiese aanbevelings:

* Vermy onnodige overlap wanneer dit sensitiewe of unieke strings herhaaldelik sou blootstel.
* Deduplicate voor data gesplit word sodat near-identical samples nie tussen training- en evaluation-sets kan leak nie.
