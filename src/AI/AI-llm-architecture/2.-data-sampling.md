## **Δειγματοληψία δεδομένων**

Η **δειγματοληψία δεδομένων** είναι μια κρίσιμη διαδικασία για την προετοιμασία δεδομένων κατά την εκπαίδευση μεγάλων γλωσσικών μοντέλων (LLMs), όπως το GPT. Περιλαμβάνει την οργάνωση των δεδομένων κειμένου σε ακολουθίες εισόδου και στόχου, τις οποίες το μοντέλο χρησιμοποιεί για να μάθει να προβλέπει την επόμενη λέξη (ή token) με βάση τις προηγούμενες λέξεις. Η σωστή δειγματοληψία δεδομένων διασφαλίζει ότι το μοντέλο αποτυπώνει αποτελεσματικά τα γλωσσικά μοτίβα και τις εξαρτήσεις.

> [!TIP]
> Ο στόχος αυτής της δεύτερης φάσης είναι πολύ απλός: **Να γίνει δειγματοληψία των δεδομένων εισόδου και να προετοιμαστούν για τη φάση εκπαίδευσης, συνήθως διαχωρίζοντας το dataset σε προτάσεις συγκεκριμένου μήκους και δημιουργώντας επίσης την αναμενόμενη απόκριση.**

### **Γιατί έχει σημασία η δειγματοληψία δεδομένων**

Τα LLMs, όπως το GPT, εκπαιδεύονται ώστε να δημιουργούν ή να προβλέπουν κείμενο κατανοώντας το πλαίσιο που παρέχουν οι προηγούμενες λέξεις. Για να επιτευχθεί αυτό, τα δεδομένα εκπαίδευσης πρέπει να είναι δομημένα με τρόπο που επιτρέπει στο μοντέλο να μαθαίνει τη σχέση μεταξύ ακολουθιών λέξεων και των λέξεων που ακολουθούν. Αυτή η δομημένη προσέγγιση επιτρέπει στο μοντέλο να γενικεύει και να δημιουργεί συνεκτικό και συναφές με το πλαίσιο κείμενο.

### **Βασικές έννοιες στη δειγματοληψία δεδομένων**

1. **Tokenization:** Διάσπαση του κειμένου σε μικρότερες μονάδες που ονομάζονται tokens (π.χ. λέξεις, υπολέξεις ή χαρακτήρες).
2. **Μήκος ακολουθίας (max_length):** Ο αριθμός των tokens σε κάθε ακολουθία εισόδου.
3. **Sliding Window:** Μια μέθοδος δημιουργίας αλληλεπικαλυπτόμενων ακολουθιών εισόδου, με μετακίνηση ενός παραθύρου πάνω από το κείμενο που έχει υποστεί tokenization.
4. **Stride:** Ο αριθμός των tokens κατά τον οποίο μετακινείται το sliding window για τη δημιουργία της επόμενης ακολουθίας.

**Sliding Window με Βήμα 1:**

- **Πρώτο Window (Θέσεις 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Στόχος:** \["ipsum", "dolor", "sit", "amet,"]
- **Δεύτερο Window (Θέσεις 2-5):** \["ipsum", "dolor", "sit", "amet,"] → **Στόχος:** \["dolor", "sit", "amet,", "consectetur"]

**Κατανόηση του Βήματος**

- **Βήμα 1:** Το window μετακινείται προς τα εμπρός κατά ένα token κάθε φορά, με αποτέλεσμα ακολουθίες με σημαντική επικάλυψη. Αυτό μπορεί να οδηγήσει σε καλύτερη εκμάθηση των σχέσεων συμφραζομένων, αλλά μπορεί να αυξήσει τον κίνδυνο overfitting, καθώς επαναλαμβάνονται παρόμοια σημεία δεδομένων.
- **Βήμα 2:** Το window μετακινείται προς τα εμπρός κατά δύο tokens κάθε φορά, μειώνοντας την επικάλυψη. Αυτό μειώνει την πλεονασματικότητα και το υπολογιστικό φορτίο, αλλά ενδέχεται να παραλείψει ορισμένες αποχρώσεις των συμφραζομένων.
- **Βήμα ίσο με max_length:** Το window μετακινείται προς τα εμπρός κατά ολόκληρο το μέγεθος του window, με αποτέλεσμα ακολουθίες χωρίς επικάλυψη. Αυτό ελαχιστοποιεί την πλεονασματικότητα των δεδομένων, αλλά μπορεί να περιορίσει την ικανότητα του μοντέλου να μαθαίνει εξαρτήσεις μεταξύ ακολουθιών.

"""
Create a class that receives parameters such as a tokenizer and text
and will prepare the input chunks and the target chunks to prepare
the LLM to learn which next token to generate
"""
import torch
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
def __init__(self, txt, tokenizer, max_length, stride):
self.input_ids = []
self.target_ids = []

# Tokenize the entire text
token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

# Use a sliding window to chunk the book into overlapping sequences of max_length
for i in range(0, len(token_ids) - max_length, stride):
input_chunk = token_ids[i:i + max_length]
target_chunk = token_ids[i + 1: i + max_length + 1]
self.input_ids.append(torch.tensor(input_chunk))
self.target_ids.append(torch.tensor(target_chunk))

def __len__(self):
return len(self.input_ids)

def __getitem__(self, idx):
return self.input_ids[idx], self.target_ids[idx]


"""
Create a data loader which given the text and some params will
prepare the inputs and targets with the previous class and
then create a torch DataLoader with the info
"""

import tiktoken

def create_dataloader_v1(txt, batch_size=4, max_length=256,
stride=128, shuffle=True, drop_last=True,
num_workers=0):

# Initialize the tokenizer

# Create dataset

# Create dataloader
dataloader = DataLoader(
dataset,
batch_size=batch_size,
shuffle=shuffle,
drop_last=drop_last,
num_workers=num_workers
)

return dataloader


"""

- The used text for training

- max_length: The size of each entry on each batch

dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=4, stride=1, shuffle=False

## Προηγμένες στρατηγικές δειγματοληψίας (2023-2025)

### 1. Στάθμιση μίγματος βάσει θερμοκρασίας
Τα υπερσύγχρονα LLM εκπαιδεύονται σπάνια σε ένα μόνο corpus. Αντίθετα, πραγματοποιούν δειγματοληψία από διάφορες ετερογενείς πηγές δεδομένων (code, web, ακαδημαϊκές εργασίες, forums…). Η σχετική αναλογία κάθε πηγής μπορεί να επηρεάσει σημαντικά την απόδοση σε downstream εργασίες. Πρόσφατα open-source μοντέλα, όπως το Llama 2, εισήγαγαν ένα **temperature‐based sampling scheme**, όπου η πιθανότητα επιλογής ενός document από το corpus *i* γίνεται
```
p(i) = \frac{w_i^{\alpha}}{\sum_j w_j^{\alpha}}
```
• *w<sub>i</sub>*  – ακατέργαστο ποσοστό tokens του corpus *i*
• *α* ("temperature") – μια τιμή στο (0,1]. Το α < 1 ισοπεδώνει την κατανομή, δίνοντας μεγαλύτερο βάρος σε μικρότερα corpora υψηλής ποιότητας.

Με `α < 1`, αυτή η στάθμιση ισοπεδώνει την κατανομή και αυξάνει τη σχετική πιθανότητα δειγματοληψίας μικρότερων corpora. Η δειγματοληψία βάσει temperature έχει χρησιμοποιηθεί ευρέως για την εξισορρόπηση multilingual pretraining data, αν και απαιτούνται όρια επανάληψης για την αποφυγή overfitting σε μικρές πηγές.<sup>[[4]](#references)</sup>
```python
from collections import Counter

def temperature_sample(corpus_ids, alpha=0.7):
counts = Counter(corpus_ids)           # number of tokens seen per corpus
probs  = {c: c_count**alpha for c, c_count in counts.items()}
Z = sum(probs.values())
probs = {c: p/Z for c, p in probs.items()}
# Now draw according to probs to fill every batch
```
### 2. Sequence Packing / Dynamic Batching
Η μνήμη GPU σπαταλιέται όταν κάθε sequence σε ένα batch γίνεται padding μέχρι το μήκος του μεγαλύτερου παραδείγματος. Το **Packing** ομαδοποιεί πολλά μικρότερα παραδείγματα σε blocks σταθερού μήκους. Μια συμβατική υλοποίηση packed χρησιμοποιεί ένα segment-aware ή block-diagonal `attention_mask`, ώστε τα tokens να μην μπορούν να κάνουν attend πέρα από τα όρια των παραδειγμάτων· οι padding-free υλοποιήσεις μπορούν, αντίθετα, να κάνουν flatten το batch και να διατηρούν τα όρια μέσω position information. Το Hugging Face TRL παρέχει packing μέσω του `SFTConfig(packing=True)` και τεκμηριώνει τις διαθέσιμες στρατηγικές.<sup>[[5]](#references)</sup>

Σε μια συγκεκριμένη διαμόρφωση TRL, το `max_length` ορίζει το μέγεθος του packed block και το `packing_strategy` επιλέγει είτε best-fit decreasing (`"bfd"`) είτε wrapped packing. Το best-fit decreasing επιτρέπει padding-free batches· υποστηρίζεται ρητά το `padding_free=True` με FlashAttention 2 ή 3. Μην συγχέετε το `pad_to_multiple_of` με το packing: απλώς στρογγυλοποιεί τα padded sequence lengths στο επιλεγμένο multiple.<sup>[[5]](#references)</sup>

**Το Dynamic ή length-aware batching είναι ξεχωριστή βελτιστοποίηση:** δεν κάνει concatenate τα παραδείγματα. Αντίθετα, ομαδοποιεί παραδείγματα παρόμοιου μήκους, ώστε κάθε dynamically padded batch να περιέχει λιγότερα padding tokens. Το τρέχον Hugging Face Transformers το εκθέτει ως `train_sampling_strategy="group_by_length"`· μια προϋπολογισμένη στήλη `length`, επιλεγμένη μέσω του `length_column_name`, αποφεύγει τον υπολογισμό του μήκους κάθε παραδείγματος κατά την έναρξη του training.<sup>[[8]](#references)</sup>

### 3. Deduplication & Quality Filtering
Τα επαναλαμβανόμενα passages προκαλούν memorization και παρέχουν ένα εύκολο κανάλι για data poisoning. Επομένως, ένα defensible cleaning pipeline συνδυάζει:

1. **Exact και near-duplicate detection:** κάντε hash στα normalized documents, χρησιμοποιήστε MinHash/LSH πάνω σε token n-grams για scalable near-duplicate discovery και χρησιμοποιήστε exact-substring methods όταν πρέπει να αφαιρεθούν μεγάλα επαναλαμβανόμενα passages.<sup>[[6]](#references)</sup>
2. **Quality filtering:** απορρίψτε invalid encodings, garbled markup, pathological repetition και documents σε λάθος γλώσσα. Το perplexity ενός reference model μπορεί να αποτελέσει ακόμη ένα signal, αλλά το threshold του πρέπει να βαθμονομείται για το corpus και όχι να αντιμετωπίζεται ως universal cutoff.<sup>[[2]](#references)</sup>
3. **Sensitive-data filtering:** κάντε scan για credentials και PII με deterministic patterns μαζί με entity detection και, στη συνέχεια, θέστε τα matches σε quarantine για review, ώστε τα false positives να μην διαγράφουν σιωπηρά χρήσιμα training data.<sup>[[7]](#references)</sup>

Το paper του Llama 2 περιγράφει το deduplication και το source filtering ως μέρος της κατασκευής του corpus.<sup>[[2]](#references)</sup> Ανεξάρτητη έρευνα διαπίστωσε ότι το deduplication των training data των language models μειώνει το verbatim memorization και μπορεί να απαιτεί λιγότερα training steps για ίδια ή καλύτερη accuracy.<sup>[[6]](#references)</sup>

## Security & Privacy Considerations During Sampling

### Data-Poisoning / Backdoor Attacks

Αντιμετωπίστε το corpus discovery, το materialization, το filtering και το sampling ως μία ενιαία supply chain. Ένα manifest που περιέχει μόνο URLs δεν αποτελεί immutable training data:

* **Split-view poisoning:** ένας attacker κάνει έναν resource να φαίνεται benign όταν ένας curator τον κάνει index και, στη συνέχεια, αλλάζει αυτό που κατεβάζουν αργότερα οι training clients. Αυτό εκμεταλλεύεται το χρονικό κενό μεταξύ dataset creation και materialization.
* **Frontrunning poisoning:** ένας attacker τροποποιεί προσωρινά μια crowd-edited source αμέσως πριν από ένα predictable snapshot ή crawl και την επαναφέρει μετά. Το malicious sample παραμένει στο snapshot, παρότι η live page εμφανίζεται αργότερα καθαρή.

Και οι δύο τεχνικές στοχεύουν **το πότε γίνεται fetch ενός sample** και όχι κάποια parser vulnerability. Ερευνητές τις απέδειξαν ενάντια στις trust assumptions πολλαπλών web-scale datasets, συμπεριλαμβανομένων των URL expiry/re-registration και των time-bounded edits.<sup>[[9]](#references)</sup>

**Το Sampling μπορεί να ενισχύσει ένα μικρό poisoned cluster.** Το σχετικό metric δεν είναι απλώς `poison_documents / raw_documents`, αλλά ο αριθμός των φορών που αυτά τα documents μετατρέπονται σε optimization examples μετά από source weighting, repetition, chunking και overlapping windows. Σε μεγάλα pre-training experiments, 250 poisoned documents παρήγαγαν συγκρίσιμο backdoor effect σε models από 600M έως 13B parameters, εκπαιδευμένα σε 6B έως 260B clean tokens· επομένως, ένα percentage-only alert threshold μπορεί να γίνεται ασθενέστερο όσο μεγαλώνει το corpus.<sup>[[10]](#references)</sup>

Για ένα ingestion audit, διατηρήστε τόσο το **unique-document count** όσο και το **effective exposure count**.<sup>[[10]](#references)</sup>
```text
effective_exposure(doc) =
epochs × source_sampling_weight × repetitions × emitted_chunks(doc)
```
Πρακτικοί έλεγχοι που προκύπτουν από αυτές τις αστοχίες κατά την εισαγωγή και την έκθεση περιλαμβάνουν:<sup>[[9]](#references)[[10]](#references)</sup>

* «Πάγωσε» τα content-addressed artifacts αντί να ανακτάς ξανά μεταβλητά URLs. Αποθήκευσε το αρχικό URL, τη χρονική σήμανση ανάκτησης, το μήκος σε bytes, το digest και την έκδοση μετασχηματισμού· χρησιμοποίησε fail closed σε περίπτωση ασυμφωνίας digest.
* Υπολόγισε hash στα bytes τόσο πριν όσο και μετά την κανονικοποίηση. Το πρώτο digest αποδεικνύει την ακεραιότητα της πηγής· το δεύτερο καθιστά δυνατά το deduplication και τη μεταγενέστερη αναπαραγωγή.
* Κάνε deduplicate πριν από το mixture upsampling και τη δημιουργία windows και, στη συνέχεια, περιόρισε την έκθεση ανά cluster ακριβών/σχεδόν διπλότυπων και ανά προέλευση. Το shuffling αλλάζει τη σειρά, αλλά δεν αφαιρεί ένα poison.
* Κατέγραψε ένα σταθερό `document_id` σε κάθε sequence που παράγεται, ώστε μια ύποπτη συμπεριφορά του model να μπορεί να ιχνηλατηθεί πίσω, μέσω των packed batches, στα source documents.
* Πριν από το training, επαλήθευσε απευθείας το frozen manifest, για παράδειγμα με `sha256sum -c corpus.sha256`· μην κατεβάζεις σιωπηρά αντικατάσταση για ένα αντικείμενο που λείπει ή έχει αλλάξει.

### Membership-Inference & Απομνημόνευση
Η μεγάλη επικάλυψη μεταξύ sliding-window samples επαναλαμβάνει σπάνιες συμβολοσειρές, όπως αριθμούς τηλεφώνου ή secret keys, αυξάνοντας την αποτελεσματική συχνότητά τους. Η έρευνα σχετικά με το privacy των training data δείχνει ότι τα duplicated sequences αναπαράγονται δυσανάλογα συχνά και ότι το deduplication μειώνει ουσιαστικά αυτή την έκθεση.<sup>[[7]](#references)</sup>

Πρακτικές συστάσεις:

* Απόφυγε την περιττή επικάλυψη όταν αυτή θα εξέθετε επανειλημμένα ευαίσθητες ή μοναδικές συμβολοσειρές.
* Κάνε deduplicate πριν από το splitting των data, ώστε τα σχεδόν πανομοιότυπα samples να μην κάνουν leak μεταξύ των training και evaluation sets.
