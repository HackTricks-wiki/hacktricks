## **Data Sampling**

**Data Sampling** large language models (LLMs) जैसे GPT की training के लिए data तैयार करने की एक महत्वपूर्ण प्रक्रिया है। इसमें text data को input और target sequences में व्यवस्थित किया जाता है, जिनका उपयोग model यह सीखने के लिए करता है कि पिछले words के आधार पर अगला word (या token) कैसे predict किया जाए। उचित data sampling यह सुनिश्चित करता है कि model language patterns और dependencies को प्रभावी ढंग से समझे।

> [!TIP]
> इस दूसरे phase का लक्ष्य बहुत सरल है: **input data को sample करना और उसे training phase के लिए तैयार करना, आमतौर पर dataset को एक निश्चित length वाले sentences में अलग करके और expected response भी generate करके।**

### **Data Sampling क्यों महत्वपूर्ण है**

GPT जैसे LLMs पिछले words द्वारा प्रदान किए गए context को समझकर text generate या predict करने के लिए train किए जाते हैं। इसे प्राप्त करने के लिए, training data को इस तरह structure किया जाना चाहिए कि model words के sequences और उनके बाद आने वाले words के बीच संबंध सीख सके। यह structured approach model को generalize करने और coherent तथा contextually relevant text generate करने में सक्षम बनाती है।

### **Data Sampling में मुख्य अवधारणाएँ**

1. **Tokenization:** Text को tokens नामक छोटी units में विभाजित करना (जैसे words, subwords या characters)।
2. **Sequence Length (max_length):** प्रत्येक input sequence में tokens की संख्या।
3. **Sliding Window:** Tokenized text पर एक window को move करके overlapping input sequences बनाने की method।
4. **Stride:** अगला sequence बनाने के लिए sliding window जितने tokens आगे move करती है।

### **Step-by-Step Example**

Data sampling को समझाने के लिए एक example देखते हैं।

**Example Text**
```arduino
"Lorem ipsum dolor sit amet, consectetur adipiscing elit."
```
**टोकनीकरण**

मान लें कि हम एक **basic tokenizer** का उपयोग करते हैं, जो टेक्स्ट को शब्दों और विराम चिह्नों में विभाजित करता है:
```vbnet
Tokens: ["Lorem", "ipsum", "dolor", "sit", "amet,", "consectetur", "adipiscing", "elit."]
```
**पैरामीटर**

- **Max Sequence Length (max_length):** 4 tokens
- **Sliding Window Stride:** 1 token

**Input और Target Sequences बनाना**

1. **Sliding Window Approach:**
- **Input Sequences:** प्रत्येक input sequence में `max_length` tokens होते हैं।
- **Target Sequences:** प्रत्येक target sequence में संबंधित input sequence के तुरंत बाद आने वाले tokens होते हैं।

**Stride 1 के साथ Sliding Window:**

- **First Window (Positions 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Target:** \["ipsum", "dolor", "sit", "amet,"]
- **Second Window (Positions 2-5):** \["ipsum", "dolor", "sit", "amet,"] → **Target:** \["dolor", "sit", "amet,", "consectetur"]
- **Third Window (Positions 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Target:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Fourth Window (Positions 4-7):** \["sit", "amet,", "consectetur", "adipiscing"] → **Target:** \["amet,", "consectetur", "adipiscing", "elit."]

**Stride को समझना**

- **Stride of 1:** Window हर बार एक token आगे बढ़ती है, जिससे अत्यधिक overlapping sequences बनते हैं। इससे contextual relationships की बेहतर learning हो सकती है, लेकिन overfitting का जोखिम बढ़ सकता है क्योंकि समान data points दोहराए जाते हैं।
- **Stride of 2:** Window हर बार दो tokens आगे बढ़ती है, जिससे overlap कम होता है। इससे redundancy और computational load कम होता है, लेकिन कुछ contextual nuances छूट सकते हैं।
- **Stride Equal to max_length:** Window पूरे window size के बराबर आगे बढ़ती है, जिससे non-overlapping sequences बनते हैं। इससे data redundancy कम से कम होती है, लेकिन sequences के बीच dependencies सीखने की model की क्षमता सीमित हो सकती है।

**Stride of 2 का उदाहरण:**

उसी tokenized text और `max_length` 4 का उपयोग करते हुए:

- **First Window (Positions 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Target:** \["ipsum", "dolor", "sit", "amet,"]
- **Second Window (Positions 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Target:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Third Window (Positions 5-8):** \["amet,", "consectetur", "adipiscing", "elit."] → **Target:** \["consectetur", "adipiscing", "elit.", "sed"] _(Continuation मानते हुए)_

import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

"""
Create a class that receives parameters such as a tokenizer and text
and will prepare the input chunks and the target chunks to prepare
the LLM to learn which next token to generate
"""
import torch
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
def __init__(self, txt, tokenizer, max_length, stride):
self.input_ids = []
self.target_ids = []

# Tokenize the entire text
token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

# Use a sliding window to chunk the book into overlapping sequences of max_length
for i in range(0, len(token_ids) - max_length, stride):
input_chunk = token_ids[i:i + max_length]
target_chunk = token_ids[i + 1: i + max_length + 1]
self.input_ids.append(torch.tensor(input_chunk))
self.target_ids.append(torch.tensor(target_chunk))

def __len__(self):
return len(self.input_ids)

def __getitem__(self, idx):
return self.input_ids[idx], self.target_ids[idx]


"""
Create a data loader which given the text and some params will
prepare the inputs and targets with the previous class and
then create a torch DataLoader with the info
"""

import tiktoken

def create_dataloader_v1(txt, batch_size=4, max_length=256,
stride=128, shuffle=True, drop_last=True,
num_workers=0):

# Initialize the tokenizer
tokenizer = tiktoken.get_encoding("gpt2")

# Create dataset
dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)

# Create dataloader
dataloader = DataLoader(
dataset,
batch_size=batch_size,
shuffle=shuffle,
drop_last=drop_last,
num_workers=num_workers
)

return dataloader


"""
Finally, create the data loader with the params we want:
- The used text for training
- batch_size: The size of each batch
- max_length: The size of each entry on each batch
- stride: The sliding window (how many tokens should the next entry advance compared to the previous one). The smaller the more overfitting, usually this is equals to the max_length so the same tokens aren't repeated.
- shuffle: Re-order randomly
"""
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=4, stride=1, shuffle=False
)

data_iter = iter(dataloader)
first_batch = next(data_iter)
print(first_batch)

# Note the batch_size of 8, the max_length of 4 and the stride of 1

## Advanced Sampling Strategies (2023-2025)

### 1. Temperature-Based Mixture Weighting
State-of-the-art LLMs को शायद ही कभी किसी एक corpus पर train किया जाता है। इसके बजाय, वे कई heterogeneous data sources (code, web, academic papers, forums…) से sample करते हैं। प्रत्येक source का relative proportion downstream performance को काफी प्रभावित कर सकता है। Llama 2 जैसे हाल के open-source models ने **temperature‐based sampling scheme** पेश की, जिसमें corpus *i* से किसी document को draw करने की probability становится
```
p(i) = \frac{w_i^{\alpha}}{\sum_j w_j^{\alpha}}
```
• *w<sub>i</sub>*  – corpus *i* का raw token प्रतिशत  
• *α* ("temperature") – (0,1] में एक मान। α < 1 distribution को flatten करता है, जिससे छोटे high-quality corpora को अधिक weight मिलता है।

`α < 1` के साथ, यह weighting distribution को flatten करती है और छोटे corpora की relative sampling probability बढ़ाती है। Temperature-based sampling का multilingual pretraining data को balance करने के लिए व्यापक रूप से उपयोग किया गया है, हालांकि छोटे sources पर overfitting से बचने के लिए repetition limits आवश्यक हैं।<sup>[[4]](#references)</sup>
```python
from collections import Counter

def temperature_sample(corpus_ids, alpha=0.7):
counts = Counter(corpus_ids)           # number of tokens seen per corpus
probs  = {c: c_count**alpha for c, c_count in counts.items()}
Z = sum(probs.values())
probs = {c: p/Z for c, p in probs.items()}
# Now draw according to probs to fill every batch
```
### 2. Sequence Packing / Dynamic Batching
जब batch में हर sequence को सबसे लंबे example के अनुसार pad किया जाता है, तो GPU memory व्यर्थ जाती है। **Packing** कई छोटे examples को fixed-length blocks में समूहित करता है। पारंपरिक packed implementation segment-aware या block-diagonal `attention_mask` का उपयोग करती है, ताकि tokens अलग-अलग example boundaries के पार attend न कर सकें; padding-free implementations इसके बजाय batch को flatten कर सकती हैं और position information के माध्यम से boundaries बनाए रख सकती हैं। Hugging Face TRL `SFTConfig(packing=True)` के माध्यम से packing उपलब्ध कराता है और उपलब्ध strategies का दस्तावेजीकरण करता है।<sup>[[5]](#references)</sup>

एक ठोस TRL configuration में, `max_length` packed block size निर्धारित करता है और `packing_strategy` best-fit decreasing (`"bfd"`) या wrapped packing में से किसी एक को चुनता है। Best-fit decreasing padding-free batches को सक्षम करता है; स्पष्ट `padding_free=True` का उपयोग FlashAttention 2 या 3 के साथ समर्थित है। `pad_to_multiple_of` को packing न समझें: यह केवल padded sequence lengths को चुने गए multiple तक round करता है।<sup>[[5]](#references)</sup>

**Dynamic या length-aware batching एक अलग optimization है:** यह examples को concatenate नहीं करता। इसके बजाय, यह समान lengths वाले examples को समूहित करता है, ताकि प्रत्येक dynamically padded batch में padding tokens कम हों। वर्तमान Hugging Face Transformers इसे `train_sampling_strategy="group_by_length"` के रूप में उपलब्ध कराता है; `length_column_name` के माध्यम से चुना गया precomputed `length` column training शुरू होने पर हर example की length calculate करने की आवश्यकता से बचाता है।<sup>[[8]](#references)</sup>

### 3. Deduplication & Quality Filtering
दोहराए गए passages memorization का कारण बनते हैं और data poisoning के लिए आसान channel प्रदान करते हैं। इसलिए एक विश्वसनीय cleaning pipeline में निम्नलिखित शामिल होने चाहिए:

1. **Exact और near-duplicate detection:** normalized documents का hash बनाएं, scalable near-duplicate discovery के लिए token n-grams पर MinHash/LSH का उपयोग करें, और जब लंबे दोहराए गए passages हटाने हों तो exact-substring methods का उपयोग करें।<sup>[[6]](#references)</sup>
2. **Quality filtering:** invalid encodings, garbled markup, pathological repetition और गलत-language documents को अस्वीकार करें। Reference-model perplexity एक अन्य signal हो सकता है, लेकिन इसके threshold को corpus के लिए calibrate किया जाना चाहिए, न कि इसे universal cutoff माना जाना चाहिए।<sup>[[2]](#references)</sup>
3. **Sensitive-data filtering:** deterministic patterns और entity detection के साथ credentials और PII को scan करें, फिर matches को review के लिए quarantine करें, ताकि false positives उपयोगी training data को चुपचाप न मिटा दें।<sup>[[7]](#references)</sup>

Llama 2 paper corpus construction के हिस्से के रूप में deduplication और source filtering का वर्णन करता है।<sup>[[2]](#references)</sup> Independent research में पाया गया कि language-model training data को deduplicate करने से verbatim memorization कम होती है और समान या बेहतर accuracy के लिए कम training steps की आवश्यकता पड़ सकती है।<sup>[[6]](#references)</sup>

## Sampling के दौरान Security & Privacy Considerations

### Data-Poisoning / Backdoor Attacks

Corpus discovery, materialization, filtering और sampling को एक ही supply chain का हिस्सा मानें। केवल URLs वाली manifest immutable training data नहीं होती:

* **Split-view poisoning:** attacker किसी resource को curator द्वारा index किए जाने के समय benign दिखाता है, फिर बाद में training clients द्वारा download की जाने वाली सामग्री बदल देता है। यह dataset creation और materialization के बीच के time gap का लाभ उठाता है।
* **Frontrunning poisoning:** attacker किसी predictable snapshot या crawl से ठीक पहले crowd-edited source को थोड़े समय के लिए बदलता है और बाद में उसे restore कर देता है। Malicious sample snapshot में बना रहता है, भले ही live page बाद में साफ दिखाई दे।

दोनों techniques इस बात को target करती हैं कि **sample कब fetch किया जाता है**, न कि parser vulnerability को। Researchers ने URL expiry/re-registration और time-bounded edits सहित कई web-scale datasets की trust assumptions के विरुद्ध इनका प्रदर्शन किया।<sup>[[9]](#references)</sup>

**Sampling एक छोटे poisoned cluster को बढ़ा सकता है।** Relevant metric केवल `poison_documents / raw_documents` नहीं है, बल्कि source weighting, repetition, chunking और overlapping windows के बाद उन documents के optimization examples बनने की संख्या है। Large pre-training experiments में, 250 poisoned documents ने 6B से 260B clean tokens पर trained 600M से 13B parameters वाले models में comparable backdoor effect उत्पन्न किया; इसलिए corpus के बढ़ने के साथ percentage-only alert threshold कमजोर हो सकता है।<sup>[[10]](#references)</sup>

Ingestion audit के लिए **unique-document count** और **effective exposure count**, दोनों बनाए रखें।<sup>[[10]](#references)</sup>
```text
effective_exposure(doc) =
epochs × source_sampling_weight × repetitions × emitted_chunks(doc)
```
इन ingestion और exposure failures से प्राप्त practical controls में शामिल हैं:<sup>[[9]](#references)[[10]](#references)</sup>

* mutable URLs को दोबारा fetch करने के बजाय content-addressed artifacts को freeze करें। मूल URL, retrieval timestamp, byte length, digest और transformation version store करें; digest mismatch होने पर fail closed करें।
* normalization से पहले और बाद में bytes को hash करें। पहला digest source integrity सिद्ध करता है; दूसरा deduplication और बाद में reproduction संभव बनाता है।
* mixture upsampling और window generation से पहले deduplicate करें, फिर प्रत्येक exact/near-duplicate cluster और origin के लिए exposure सीमित करें। Shuffling केवल order बदलता है, poison को हटाता नहीं है।
* प्रत्येक emitted sequence में एक stable `document_id` log करें, ताकि किसी संदिग्ध model behavior को packed batches के माध्यम से source documents तक trace किया जा सके।
* training से पहले frozen manifest को सीधे verify करें, उदाहरण के लिए `sha256sum -c corpus.sha256` से; missing या बदले हुए object के लिए replacement को silently download न करें।

### Membership-Inference & Memorization
Sliding-window samples के बीच लंबा overlap telephone numbers या secret keys जैसे rare strings को दोहराता है, जिससे उनकी effective frequency बढ़ती है। Training-data privacy पर research से पता चलता है कि duplicated sequences को disproportionate रूप से अधिक बार regenerate किया जाता है और deduplication इस exposure को materially कम करता है।<sup>[[7]](#references)</sup>

Practical recommendations:

* जब इससे sensitive या unique strings बार-बार expose हों, तो अनावश्यक overlap से बचें।
* Data splitting से पहले deduplicate करें, ताकि near-identical samples training और evaluation sets के बीच leak न हों।
