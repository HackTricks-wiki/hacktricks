## **Data Sampling**

**Data Sampling** बड़े language models (LLMs) जैसे GPT के training के लिए data तैयार करने की एक महत्वपूर्ण प्रक्रिया है। इसमें text data को input और target sequences में व्यवस्थित किया जाता है, जिनका उपयोग model यह सीखने के लिए करता है कि पिछले words के आधार पर अगला word (या token) कैसे predict किया जाए। उचित data sampling यह सुनिश्चित करता है कि model language patterns और dependencies को प्रभावी ढंग से समझ सके।

> [!TIP]
> इस दूसरे चरण का लक्ष्य बहुत सरल है: **input data को sample करना और उसे training phase के लिए तैयार करना, आमतौर पर dataset को एक निश्चित लंबाई वाले sentences में अलग करके और अपेक्षित response भी generate करके।**

### **Why Data Sampling Matters**

GPT जैसे LLMs पिछले words द्वारा दिए गए context को समझकर text generate या predict करने के लिए train किए जाते हैं। इसे प्राप्त करने के लिए training data को इस तरह structured होना चाहिए कि model words के sequences और उनके बाद आने वाले words के बीच संबंध सीख सके। यह structured approach model को coherent और contextually relevant text को generalize और generate करने में सक्षम बनाती है।

### **Key Concepts in Data Sampling**

1. **Tokenization:** Text को tokens नामक छोटी units में विभाजित करना (जैसे words, subwords या characters)।
2. **Sequence Length (max_length):** प्रत्येक input sequence में tokens की संख्या।
3. **Sliding Window:** Tokenized text पर एक window को आगे बढ़ाकर overlapping input sequences बनाने की method।
4. **Stride:** अगला sequence बनाने के लिए sliding window जितने tokens आगे बढ़ती है, उनकी संख्या।

### **Step-by-Step Example**

आइए data sampling को समझाने के लिए एक example देखते हैं।

**Example Text**
```arduino
"Lorem ipsum dolor sit amet, consectetur adipiscing elit."
```
**Tokenization**

मान लें कि हम एक **basic tokenizer** का उपयोग करते हैं, जो टेक्स्ट को शब्दों और विराम चिह्नों में विभाजित करता है:
```vbnet
Tokens: ["Lorem", "ipsum", "dolor", "sit", "amet,", "consectetur", "adipiscing", "elit."]
```
**Parameters**

- **Max Sequence Length (max_length):** 4 tokens
- **Sliding Window Stride:** 1 token

**Creating Input and Target Sequences**

1. **Sliding Window Approach:**
- **Input Sequences:** प्रत्येक input sequence में `max_length` tokens होते हैं।
- **Target Sequences:** प्रत्येक target sequence में संबंधित input sequence के तुरंत बाद आने वाले tokens होते हैं।
2. **Generating Sequences:**

```python
["dolor", "sit", "amet,", "consectetur"],
```

**Sliding Window with Stride 1:**

- **First Window (Positions 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Target:** \["ipsum", "dolor", "sit", "amet,"]
- **Second Window (Positions 2-5):** \["ipsum", "dolor", "sit", "amet,"] → **Target:** \["dolor", "sit", "amet,", "consectetur"]
- **Third Window (Positions 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Target:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Fourth Window (Positions 4-7):** \["sit", "amet,", "consectetur", "adipiscing"] → **Target:** \["amet,", "consectetur", "adipiscing", "elit."]

**Understanding Stride**

- **Stride of 1:** Window हर बार एक token आगे बढ़ता है, जिससे sequences में बहुत अधिक overlap होता है। इससे contextual relationships की बेहतर learning हो सकती है, लेकिन overfitting का risk बढ़ सकता है क्योंकि समान data points दोहराए जाते हैं।
- **Stride of 2:** Window हर बार दो tokens आगे बढ़ता है, जिससे overlap कम हो जाता है। इससे redundancy और computational load कम होते हैं, लेकिन कुछ contextual nuances छूट सकते हैं।
- **Stride Equal to max_length:** Window अपने पूरे आकार के बराबर आगे बढ़ता है, जिससे non-overlapping sequences बनते हैं। इससे data redundancy कम होती है, लेकिन sequences के बीच dependencies सीखने की model की क्षमता सीमित हो सकती है।

**Example with Stride of 2:**

उसी tokenized text और `max_length` को 4 रखते हुए:

- **First Window (Positions 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Target:** \["ipsum", "dolor", "sit", "amet,"]
- **Second Window (Positions 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Target:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Third Window (Positions 5-8):** \["amet,", "consectetur", "adipiscing", "elit."] → **Target:** \["consectetur", "adipiscing", "elit.", "sed"] _(continuation मानते हुए)_

## Code Example

इसे [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb) के code example से बेहतर समझते हैं:<sup>[[1]](#references)</sup>
```python
# Download the text to pre-train the LLM
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

"""
Create a class that receives parameters such as a tokenizer and text
and will prepare the input chunks and the target chunks to prepare
the LLM to learn which next token to generate
"""
import torch
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
def __init__(self, txt, tokenizer, max_length, stride):
self.input_ids = []
self.target_ids = []

# Tokenize the entire text
token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

# Use a sliding window to chunk the book into overlapping sequences of max_length
for i in range(0, len(token_ids) - max_length, stride):
input_chunk = token_ids[i:i + max_length]
target_chunk = token_ids[i + 1: i + max_length + 1]
self.input_ids.append(torch.tensor(input_chunk))
self.target_ids.append(torch.tensor(target_chunk))

def __len__(self):
return len(self.input_ids)

def __getitem__(self, idx):
return self.input_ids[idx], self.target_ids[idx]


"""
Create a data loader which given the text and some params will
prepare the inputs and targets with the previous class and
then create a torch DataLoader with the info
"""

import tiktoken

def create_dataloader_v1(txt, batch_size=4, max_length=256,
stride=128, shuffle=True, drop_last=True,
num_workers=0):

# Initialize the tokenizer
tokenizer = tiktoken.get_encoding("gpt2")

# Create dataset
dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)

# Create dataloader
dataloader = DataLoader(
dataset,
batch_size=batch_size,
shuffle=shuffle,
drop_last=drop_last,
num_workers=num_workers
)

return dataloader


"""
Finally, create the data loader with the params we want:
- The used text for training
- batch_size: The size of each batch
- max_length: The size of each entry on each batch
- stride: The sliding window (how many tokens should the next entry advance compared to the previous one). The smaller the more overfitting, usually this is equals to the max_length so the same tokens aren't repeated.
- shuffle: Re-order randomly
"""
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=4, stride=1, shuffle=False
)

data_iter = iter(dataloader)
first_batch = next(data_iter)
print(first_batch)

# Note the batch_size of 8, the max_length of 4 and the stride of 1
[

[  367,  2885,  1464,  1807],
```

## उन्नत Sampling Strategies (2023-2025)

### 1. Temperature-Based Mixture Weighting
State-of-the-art LLMs को शायद ही कभी केवल एक corpus पर train किया जाता है। इसके बजाय, वे कई heterogeneous data sources (code, web, academic papers, forums…) से sample करते हैं। प्रत्येक source का relative proportion downstream performance को महत्वपूर्ण रूप से प्रभावित कर सकता है। Llama 2 जैसे हाल के open-source models ने एक **temperature-based sampling scheme** पेश की, जिसमें corpus *i* से document चुनने की probability становится
```
p(i) = \frac{w_i^{\alpha}}{\sum_j w_j^{\alpha}}
```
• *w<sub>i</sub>*  – corpus *i* का raw token प्रतिशत  
• *α* ("temperature") – (0,1] में एक मान। α < 1 distribution को flatten करता है, जिससे छोटे high-quality corpora को अधिक weight मिलता है।

`α < 1` के साथ, यह weighting distribution को flatten करती है और छोटे corpora की relative sampling probability बढ़ाती है। Temperature-based sampling का multilingual pretraining data को balance करने के लिए व्यापक रूप से उपयोग किया गया है, हालांकि छोटे sources को overfitting से बचाने के लिए repetition limits आवश्यक हैं।<sup>[[4]](#references)</sup>
```python
from collections import Counter

def temperature_sample(corpus_ids, alpha=0.7):
counts = Counter(corpus_ids)           # number of tokens seen per corpus
probs  = {c: c_count**alpha for c, c_count in counts.items()}
Z = sum(probs.values())
probs = {c: p/Z for c, p in probs.items()}
# Now draw according to probs to fill every batch
```
### 2. Sequence Packing / Dynamic Batching
जब किसी batch में हर sequence को सबसे लंबे example तक pad किया जाता है, तो GPU memory व्यर्थ होती है। **Packing** कई छोटे examples को fixed-length blocks में समूहित करता है। एक conventional packed implementation segment-aware या block-diagonal `attention_mask` का उपयोग करती है, ताकि tokens अलग-अलग example boundaries के पार attend न कर सकें; padding-free implementations इसके बजाय batch को flatten कर सकती हैं और position information के माध्यम से boundaries बनाए रख सकती हैं। Hugging Face TRL, `SFTConfig(packing=True)` के माध्यम से packing उपलब्ध कराता है और उपलब्ध strategies को document करता है।<sup>[[5]](#references)</sup>

एक concrete TRL configuration में, `max_length` packed block size निर्धारित करता है और `packing_strategy` best-fit decreasing (`"bfd"`) या wrapped packing में से किसी एक को चुनता है। Best-fit decreasing padding-free batches को सक्षम करता है; explicit `padding_free=True` FlashAttention 2 या 3 के साथ supported है। `pad_to_multiple_of` को packing समझने की गलती न करें: यह केवल padded sequence lengths को चुने गए multiple तक round करता है।<sup>[[5]](#references)</sup>

**Dynamic या length-aware batching एक अलग optimization है:** यह examples को concatenate नहीं करता। इसके बजाय, यह समान lengths वाले examples को समूहित करता है, ताकि प्रत्येक dynamically padded batch में padding tokens कम हों। वर्तमान Hugging Face Transformers इसे `train_sampling_strategy="group_by_length"` के रूप में उपलब्ध कराता है; `length_column_name` के माध्यम से चुना गया precomputed `length` column training शुरू होने पर प्रत्येक example की length calculate करने से बचाता है।<sup>[[8]](#references)</sup>

### 3. Deduplication & Quality Filtering
दोहराए गए passages memorization का कारण बनते हैं और data poisoning के लिए आसान channel उपलब्ध कराते हैं। इसलिए एक defensible cleaning pipeline में निम्नलिखित शामिल होते हैं:

1. **Exact और near-duplicate detection:** normalized documents का hash बनाएं, scalable near-duplicate discovery के लिए token n-grams पर MinHash/LSH का उपयोग करें, और जब लंबे दोहराए गए passages हटाने हों तो exact-substring methods का उपयोग करें।<sup>[[6]](#references)</sup>
2. **Quality filtering:** invalid encodings, garbled markup, pathological repetition और गलत-language documents को reject करें। Reference-model perplexity एक अन्य signal हो सकता है, लेकिन इसके threshold को corpus के लिए calibrate किया जाना चाहिए, न कि इसे universal cutoff माना जाना चाहिए।<sup>[[2]](#references)</sup>
3. **Sensitive-data filtering:** deterministic patterns और entity detection के साथ credentials तथा PII के लिए scan करें, फिर matches को review के लिए quarantine करें, ताकि false positives उपयोगी training data को चुपचाप न मिटा दें।<sup>[[7]](#references)</sup>

Llama 2 paper corpus construction के हिस्से के रूप में deduplication और source filtering का वर्णन करता है।<sup>[[2]](#references)</sup> Independent research में पाया गया कि language-model training data को deduplicate करने से verbatim memorization कम होती है और समान या बेहतर accuracy के लिए कम training steps की आवश्यकता हो सकती है।<sup>[[6]](#references)</sup>

## Sampling के दौरान Security & Privacy Considerations

### Data-Poisoning / Backdoor Attacks
Researchers ने दिखाया कि <1 % backdoored sentences डालने से model किसी hidden trigger ("PoisonGPT", 2023) का पालन कर सकता है।<sup>[[3]](#references)</sup>  Recommended mitigations:

* **Shuffled mixing** – सुनिश्चित करें कि adjacent training examples अलग-अलग sources से आए हों; इससे malicious spans का gradient alignment dilute होता है।
* **Gradient similarity scoring** – example gradient और batch average की cosine similarity calculate करें; outliers removal के candidates होते हैं।
* **Dataset versioning & hashes** – immutable tarballs freeze करें और प्रत्येक training run से पहले SHA-256 verify करें।

### Membership-Inference & Memorization
Sliding-window samples के बीच लंबा overlap telephone numbers या secret keys जैसे rare strings को दोहराता है, जिससे उनकी effective frequency बढ़ती है। Training-data privacy पर research से पता चलता है कि duplicated sequences अनुपातहीन रूप से अधिक बार regenerate होती हैं और deduplication इस exposure को materially कम करती है।<sup>[[7]](#references)</sup>

Practical recommendations:

* अनावश्यक overlap से बचें, जब इससे sensitive या unique strings बार-बार expose हों।
* Data splitting से पहले deduplicate करें, ताकि near-identical samples training और evaluation sets के बीच leak न हों।
