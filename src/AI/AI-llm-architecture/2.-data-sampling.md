## **Δειγματοληψία Δεδομένων**

Η **Δειγματοληψία Δεδομένων** είναι μια κρίσιμη διαδικασία για την προετοιμασία δεδομένων κατά την εκπαίδευση μεγάλων γλωσσικών μοντέλων (LLMs), όπως το GPT. Περιλαμβάνει την οργάνωση δεδομένων κειμένου σε ακολουθίες εισόδου και στόχου, τις οποίες χρησιμοποιεί το μοντέλο για να μάθει να προβλέπει την επόμενη λέξη (ή token) με βάση τις προηγούμενες λέξεις. Η σωστή δειγματοληψία δεδομένων διασφαλίζει ότι το μοντέλο αποτυπώνει αποτελεσματικά τα γλωσσικά μοτίβα και τις εξαρτήσεις.

> [!TIP]
> Ο στόχος αυτής της δεύτερης φάσης είναι πολύ απλός: **Να γίνει δειγματοληψία των δεδομένων εισόδου και να προετοιμαστούν για τη φάση εκπαίδευσης, συνήθως διαχωρίζοντας το dataset σε προτάσεις συγκεκριμένου μήκους και δημιουργώντας επίσης την αναμενόμενη απόκριση.**

### **Γιατί έχει σημασία η Δειγματοληψία Δεδομένων**

Τα LLMs, όπως το GPT, εκπαιδεύονται ώστε να δημιουργούν ή να προβλέπουν κείμενο κατανοώντας το context που παρέχουν οι προηγούμενες λέξεις. Για να επιτευχθεί αυτό, τα δεδομένα εκπαίδευσης πρέπει να είναι δομημένα με τρόπο που επιτρέπει στο μοντέλο να μάθει τη σχέση μεταξύ ακολουθιών λέξεων και των λέξεων που τις ακολουθούν. Αυτή η δομημένη προσέγγιση επιτρέπει στο μοντέλο να γενικεύει και να δημιουργεί συνεκτικό και συναφές με το context κείμενο.

### **Βασικές Έννοιες στη Δειγματοληψία Δεδομένων**

1. **Tokenization:** Διάσπαση του κειμένου σε μικρότερες μονάδες που ονομάζονται tokens (π.χ. λέξεις, υπολέξεις ή χαρακτήρες).
2. **Μήκος Ακολουθίας (max_length):** Ο αριθμός των tokens σε κάθε ακολουθία εισόδου.
3. **Sliding Window:** Μια μέθοδος δημιουργίας επικαλυπτόμενων ακολουθιών εισόδου, μετακινώντας ένα παράθυρο πάνω από το tokenized κείμενο.
4. **Stride:** Ο αριθμός των tokens κατά τον οποίο μετακινείται προς τα εμπρός το sliding window για τη δημιουργία της επόμενης ακολουθίας.

- **Μέγιστο Μήκος Ακολουθίας (max_length):** 4 tokens

- **Ακολουθίες Εισόδου:** Κάθε ακολουθία εισόδου αποτελείται από `max_length` tokens.
- **Ακολουθίες Στόχου:** Κάθε ακολουθία στόχου αποτελείται από τα tokens που ακολουθούν αμέσως την αντίστοιχη ακολουθία εισόδου.

**Sliding Window με Βήμα 1:**

- **Πρώτο Παράθυρο (Θέσεις 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Στόχος:** \["ipsum", "dolor", "sit", "amet,"]
- **Δεύτερο Παράθυρο (Θέσεις 2-5):** \["ipsum", "dolor", "sit", "amet,"] → **Στόχος:** \["dolor", "sit", "amet,", "consectetur"]
- **Τρίτο Παράθυρο (Θέσεις 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Στόχος:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Τέταρτο Παράθυρο (Θέσεις 4-7):** \["sit", "amet,", "consectetur", "adipiscing"] → **Στόχος:** \["amet,", "consectetur", "adipiscing", "elit."]

**Κατανόηση του Βήματος**

- **Βήμα 1:** Το παράθυρο μετακινείται προς τα εμπρός κατά ένα token κάθε φορά, με αποτέλεσμα ακολουθίες που επικαλύπτονται σε μεγάλο βαθμό. Αυτό μπορεί να οδηγήσει σε καλύτερη εκμάθηση των σχέσεων συμφραζομένων, αλλά μπορεί επίσης να αυξήσει τον κίνδυνο overfitting, καθώς επαναλαμβάνονται παρόμοια σημεία δεδομένων.
- **Βήμα 2:** Το παράθυρο μετακινείται προς τα εμπρός κατά δύο tokens κάθε φορά, μειώνοντας την επικάλυψη. Αυτό μειώνει τον πλεονασμό και το υπολογιστικό φορτίο, αλλά ενδέχεται να παραλείψει ορισμένες λεπτές αποχρώσεις των συμφραζομένων.
- **Βήμα ίσο με max_length:** Το παράθυρο μετακινείται προς τα εμπρός κατά ολόκληρο το μέγεθος του παραθύρου, με αποτέλεσμα ακολουθίες χωρίς επικάλυψη. Αυτό ελαχιστοποιεί τον πλεονασμό δεδομένων, αλλά μπορεί να περιορίσει την ικανότητα του μοντέλου να μαθαίνει εξαρτήσεις μεταξύ ακολουθιών.

**Παράδειγμα με Βήμα 2:**

Χρησιμοποιώντας το ίδιο tokenized κείμενο και `max_length` ίσο με 4:

- **Πρώτο Παράθυρο (Θέσεις 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Στόχος:** \["ipsum", "dolor", "sit", "amet,"]
- **Δεύτερο Παράθυρο (Θέσεις 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Στόχος:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Τρίτο Παράθυρο (Θέσεις 5-8):** \["amet,", "consectetur", "adipiscing", "elit."] → **Στόχος:** \["consectetur", "adipiscing", "elit.", "sed"] _(Με την υπόθεση ότι υπάρχει συνέχεια)_

## Code Example

Ας το κατανοήσουμε καλύτερα μέσω ενός παραδείγματος κώδικα από το [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[1]](#references)</sup>
```python
# Download the text to pre-train the LLM
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

"""
Create a class that receives parameters such as a tokenizer and text
and will prepare the input chunks and the target chunks to prepare
the LLM to learn which next token to generate
"""
import torch
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
def __init__(self, txt, tokenizer, max_length, stride):
self.input_ids = []
self.target_ids = []

# Tokenize the entire text
token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

# Use a sliding window to chunk the book into overlapping sequences of max_length
for i in range(0, len(token_ids) - max_length, stride):
input_chunk = token_ids[i:i + max_length]
target_chunk = token_ids[i + 1: i + max_length + 1]
self.input_ids.append(torch.tensor(input_chunk))
self.target_ids.append(torch.tensor(target_chunk))

def __len__(self):
return len(self.input_ids)

def __getitem__(self, idx):
return self.input_ids[idx], self.target_ids[idx]


"""
Create a data loader which given the text and some params will
prepare the inputs and targets with the previous class and
then create a torch DataLoader with the info
"""

import tiktoken

def create_dataloader_v1(txt, batch_size=4, max_length=256,
stride=128, shuffle=True, drop_last=True,
num_workers=0):

# Initialize the tokenizer
tokenizer = tiktoken.get_encoding("gpt2")

# Create dataset
dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)

# Create dataloader
dataloader = DataLoader(
dataset,
batch_size=batch_size,
shuffle=shuffle,
drop_last=drop_last,
num_workers=num_workers
)

return dataloader


"""
Finally, create the data loader with the params we want:
- The used text for training
- batch_size: The size of each batch
- max_length: The size of each entry on each batch
- stride: The sliding window (how many tokens should the next entry advance compared to the previous one). The smaller the more overfitting, usually this is equals to the max_length so the same tokens aren't repeated.
- shuffle: Re-order randomly
"""
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=4, stride=1, shuffle=False
)

data_iter = iter(dataloader)
first_batch = next(data_iter)
print(first_batch)

# Note the batch_size of 8, the max_length of 4 and the stride of 1
[
```

## Προηγμένες στρατηγικές δειγματοληψίας (2023-2025)

### 1. Δειγματοληψία βάσει θερμοκρασίας για στάθμιση μειγμάτων
Τα σύγχρονα LLM σπάνια εκπαιδεύονται σε ένα μόνο corpus. Αντίθετα, πραγματοποιούν δειγματοληψία από αρκετές ετερογενείς πηγές δεδομένων (κώδικας, web, ακαδημαϊκές εργασίες, forums…). Η σχετική αναλογία κάθε πηγής μπορεί να επηρεάσει σημαντικά την απόδοση downstream. Πρόσφατα open-source μοντέλα, όπως το Llama 2, εισήγαγαν ένα **temperature‐based sampling scheme**, όπου η πιθανότητα επιλογής ενός εγγράφου από το corpus *i* γίνεται
```
p(i) = \frac{w_i^{\alpha}}{\sum_j w_j^{\alpha}}
```
• *w<sub>i</sub>*  – ακατέργαστο ποσοστό token του corpus *i*
• *α* ("temperature") – μια τιμή στο (0,1]. Το α < 1 ισοπεδώνει την κατανομή, δίνοντας μεγαλύτερο βάρος σε μικρότερα corpora υψηλής ποιότητας.

Με `α < 1`, αυτή η στάθμιση ισοπεδώνει την κατανομή και αυξάνει τη σχετική πιθανότητα δειγματοληψίας μικρότερων corpora. Η δειγματοληψία βάσει temperature έχει χρησιμοποιηθεί ευρέως για την εξισορρόπηση multilingual pretraining data, αν και απαιτούνται όρια επανάληψης για την αποφυγή overfitting σε μικρές πηγές.<sup>[[4]](#references)</sup>
```python
from collections import Counter

def temperature_sample(corpus_ids, alpha=0.7):
counts = Counter(corpus_ids)           # number of tokens seen per corpus
probs  = {c: c_count**alpha for c, c_count in counts.items()}
Z = sum(probs.values())
probs = {c: p/Z for c, p in probs.items()}
# Now draw according to probs to fill every batch
```
### 2. Sequence Packing / Dynamic Batching
Η μνήμη της GPU σπαταλιέται όταν κάθε sequence σε ένα batch γίνεται padding στο μήκος του μεγαλύτερου παραδείγματος. Το **Packing** ομαδοποιεί πολλά μικρότερα παραδείγματα σε blocks σταθερού μήκους. Μια συμβατική υλοποίηση packed χρησιμοποιεί ένα segment-aware ή block-diagonal `attention_mask`, ώστε τα tokens να μην μπορούν να κάνουν attend πέρα από τα όρια των παραδειγμάτων· οι padding-free υλοποιήσεις μπορούν, αντί γι' αυτό, να κάνουν flatten το batch και να διατηρούν τα όρια μέσω πληροφοριών θέσης. Το Hugging Face TRL παρέχει packing μέσω του `SFTConfig(packing=True)` και τεκμηριώνει τις διαθέσιμες στρατηγικές.<sup>[[5]](#references)</sup>

Για μια συγκεκριμένη ρύθμιση TRL, το `max_length` ορίζει το μέγεθος του packed block και το `packing_strategy` επιλέγει είτε best-fit decreasing (`"bfd"`) είτε wrapped packing. Το best-fit decreasing επιτρέπει padding-free batches· υποστηρίζεται επίσης ρητά το `padding_free=True` με FlashAttention 2 ή 3. Μην συγχέετε το `pad_to_multiple_of` με το packing: απλώς στρογγυλοποιεί τα padded sequence lengths στο επιλεγμένο πολλαπλάσιο.<sup>[[5]](#references)</sup>

**Το Dynamic ή length-aware batching είναι ξεχωριστή βελτιστοποίηση:** δεν κάνει concatenate τα παραδείγματα. Αντίθετα, ομαδοποιεί παραδείγματα παρόμοιου μήκους, ώστε κάθε dynamically padded batch να περιέχει λιγότερα padding tokens. Το τρέχον Hugging Face Transformers το εκθέτει ως `train_sampling_strategy="group_by_length"`· μια προϋπολογισμένη στήλη `length`, επιλεγμένη μέσω του `length_column_name`, αποφεύγει τον υπολογισμό του μήκους κάθε παραδείγματος κατά την έναρξη του training.<sup>[[8]](#references)</sup>

### 3. Deduplication & Quality Filtering
Τα επαναλαμβανόμενα αποσπάσματα προκαλούν memorization και παρέχουν ένα εύκολο κανάλι για data poisoning. Επομένως, ένα υπερασπίσιμο pipeline καθαρισμού συνδυάζει:

1. **Εντοπισμό exact και near-duplicates:** κάντε hash σε normalized documents, χρησιμοποιήστε MinHash/LSH πάνω σε token n-grams για scalable ανακάλυψη near-duplicates και χρησιμοποιήστε μεθόδους exact-substring όταν πρέπει να αφαιρεθούν μεγάλα επαναλαμβανόμενα αποσπάσματα.<sup>[[6]](#references)</sup>
2. **Quality filtering:** απορρίψτε invalid encodings, κατεστραμμένο markup, pathological repetition και documents σε λάθος γλώσσα. Η perplexity ενός reference model μπορεί να αποτελέσει ένα ακόμη signal, όμως το threshold της πρέπει να calibrate-ριστεί για το corpus και όχι να αντιμετωπίζεται ως καθολικό cutoff.<sup>[[2]](#references)</sup>
3. **Sensitive-data filtering:** κάντε scan για credentials και PII με deterministic patterns σε συνδυασμό με entity detection και, στη συνέχεια, θέστε τα matches σε quarantine για review, ώστε τα false positives να μην διαγράφουν σιωπηρά χρήσιμα training data.<sup>[[7]](#references)</sup>

Το paper του Llama 2 περιγράφει το deduplication και το source filtering ως μέρος της κατασκευής του corpus.<sup>[[2]](#references)</sup> Ανεξάρτητη έρευνα διαπίστωσε ότι το deduplication των training data γλωσσικών μοντέλων μειώνει το verbatim memorization και μπορεί να απαιτεί λιγότερα training steps για ίση ή καλύτερη ακρίβεια.<sup>[[6]](#references)</sup>

## Ζητήματα Ασφάλειας & Privacy κατά το Sampling

### Επιθέσεις Data-Poisoning / Backdoor
Ερευνητές έδειξαν ότι η εισαγωγή <1 % backdoored sentences μπορεί να κάνει ένα μοντέλο να υπακούει σε ένα κρυφό trigger ("PoisonGPT", 2023).<sup>[[3]](#references)</sup> Συνιστώμενα mitigations:

* **Shuffled mixing** – βεβαιωθείτε ότι τα adjacent training examples προέρχονται από διαφορετικές πηγές· αυτό αραιώνει το gradient alignment των malicious spans.
* **Gradient similarity scoring** – υπολογίστε την cosine similarity του gradient του παραδείγματος προς τον μέσο όρο του batch· τα outliers είναι υποψήφια για αφαίρεση.
* **Dataset versioning & hashes** – παγώστε immutable tarballs και επαληθεύστε το SHA-256 πριν από κάθε training run.

### Membership-Inference & Memorization
Η μεγάλη επικάλυψη μεταξύ sliding-window samples επαναλαμβάνει σπάνια strings, όπως αριθμούς τηλεφώνου ή secret keys, αυξάνοντας την effective frequency τους. Η έρευνα σχετικά με το training-data privacy δείχνει ότι τα duplicated sequences αναπαράγονται δυσανάλογα συχνά και ότι το deduplication μειώνει ουσιαστικά αυτή την έκθεση.<sup>[[7]](#references)</sup>

Πρακτικές συστάσεις:

* Αποφύγετε την περιττή επικάλυψη όταν αυτή θα εξέθετε επανειλημμένα sensitive ή unique strings.
* Κάντε deduplicate πριν από το splitting των data, ώστε near-identical samples να μην κάνουν leak μεταξύ των training και evaluation sets.
