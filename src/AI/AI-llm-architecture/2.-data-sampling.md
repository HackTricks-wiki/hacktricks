## **数据采样**

**数据采样** 是准备数据以训练 GPT 等大型语言模型（LLM）的关键过程。它涉及将文本数据组织成输入序列和目标序列，模型通过这些序列学习如何根据前面的单词预测下一个单词（或 token）。适当的数据采样可确保模型有效捕捉语言模式和依赖关系。

> [!TIP]
> 这一阶段的目标非常简单：**对输入数据进行采样，并通过通常将数据集拆分为特定长度的句子，同时生成预期响应，为训练阶段做好准备。**

### **数据采样为何重要**

GPT 等 LLM 通过理解前面单词提供的上下文来生成或预测文本。为实现这一点，训练数据必须以一种模型能够学习单词序列与其后续单词之间关系的方式进行组织。这种结构化方法使模型能够泛化，并生成连贯且符合上下文的文本。

### **数据采样中的关键概念**

1. **Tokenization：** 将文本拆分为称为 token 的更小单位（例如单词、子词或字符）。
2. **Sequence Length (max_length)：** 每个输入序列中的 token 数量。
3. **Sliding Window：** 通过在经过 tokenization 的文本上移动窗口来创建重叠输入序列的方法。
4. **Stride：** 滑动窗口向前移动以创建下一个序列时所移动的 token 数量。

### **分步示例**

下面通过一个示例来说明数据采样。

**示例文本**
```arduino
"Lorem ipsum dolor sit amet, consectetur adipiscing elit."
```
**Tokenization**

假设我们使用一种将文本拆分为单词和标点符号的**基本分词器**：
```vbnet
Tokens: ["Lorem", "ipsum", "dolor", "sit", "amet,", "consectetur", "adipiscing", "elit."]
```
**参数**

- **最大序列长度 (max_length)：** 4 个 tokens
- **滑动窗口步长：** 1 个 token

**创建输入和目标序列**

1. **滑动窗口方法：**
- **输入序列：** 每个输入序列由 `max_length` 个 tokens 组成。
- **目标序列：** 每个目标序列由紧跟在相应输入序列之后的 tokens 组成。
2. **生成序列：**

<table><thead><tr><th width="177">窗口位置</th><th>输入序列</th><th>目标序列</th></tr></thead><tbody><tr><td>1</td><td>["Lorem", "ipsum", "dolor", "sit"]</td><td>["ipsum", "dolor", "sit", "amet,"]</td></tr><tr><td>2</td><td>["ipsum", "dolor", "sit", "amet,"]</td><td>["dolor", "sit", "amet,", "consectetur"]</td></tr><tr><td>3</td><td>["dolor", "sit", "amet,", "consectetur"]</td><td>["sit", "amet,", "consectetur", "adipiscing"]</td></tr><tr><td>4</td><td>["sit", "amet,", "consectetur", "adipiscing"]</td><td>["amet,", "consectetur", "adipiscing", "elit."]</td></tr></tbody></table>

3. **生成的输入和目标数组：**

- **输入：**

```python
[
["Lorem", "ipsum", "dolor", "sit"],
["ipsum", "dolor", "sit", "amet,"],
["dolor", "sit", "amet,", "consectetur"],
["sit", "amet,", "consectetur", "adipiscing"],
]
```

- **目标：**

```python
[
["ipsum", "dolor", "sit", "amet,"],
["dolor", "sit", "amet,", "consectetur"],
["sit", "amet,", "consectetur", "adipiscing"],
["amet,", "consectetur", "adipiscing", "elit."],
]
```

**可视化表示**

<table><thead><tr><th width="222">Token 位置</th><th>Token</th></tr></thead><tbody><tr><td>1</td><td>Lorem</td></tr><tr><td>2</td><td>ipsum</td></tr><tr><td>3</td><td>dolor</td></tr><tr><td>4</td><td>sit</td></tr><tr><td>5</td><td>amet,</td></tr><tr><td>6</td><td>consectetur</td></tr><tr><td>7</td><td>adipiscing</td></tr><tr><td>8</td><td>elit.</td></tr></tbody></table>

**步长为 1 的滑动窗口：**

- **第一个窗口（位置 1-4）：** \["Lorem", "ipsum", "dolor", "sit"] → **目标：** \["ipsum", "dolor", "sit", "amet,"]
- **第二个窗口（位置 2-5）：** \["ipsum", "dolor", "sit", "amet,"] → **目标：** \["dolor", "sit", "amet,", "consectetur"]
- **第三个窗口（位置 3-6）：** \["dolor", "sit", "amet,", "consectetur"] → **目标：** \["sit", "amet,", "consectetur", "adipiscing"]
- **第四个窗口（位置 4-7）：** \["sit", "amet,", "consectetur", "adipiscing"] → **目标：** \["amet,", "consectetur", "adipiscing", "elit."]

**理解步长**

- **步长为 1：** 窗口每次向前移动一个 token，从而产生高度重叠的序列。这有助于更好地学习上下文关系，但由于相似数据点被重复使用，可能会增加 overfitting 的风险。
- **步长为 2：** 窗口每次向前移动两个 tokens，从而减少重叠。这会降低冗余和计算负载，但可能会错过一些上下文细节。
- **步长等于 max_length：** 窗口每次向前移动整个窗口大小，从而产生不重叠的序列。这可以最大限度地减少数据冗余，但可能会限制模型学习跨序列依赖关系的能力。

**步长为 2 的示例：**

使用相同的 tokenized 文本和 `max_length` 4：

- **第一个窗口（位置 1-4）：** \["Lorem", "ipsum", "dolor", "sit"] → **目标：** \["ipsum", "dolor", "sit", "amet,"]
- **第二个窗口（位置 3-6）：** \["dolor", "sit", "amet,", "consectetur"] → **目标：** \["sit", "amet,", "consectetur", "adipiscing"]
- **第三个窗口（位置 5-8）：** \["amet,", "consectetur", "adipiscing", "elit."] → **目标：** \["consectetur", "adipiscing", "elit.", "sed"] _(假设存在后续内容)_

## Code Example

让我们通过来自 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb) 的代码示例进一步理解这一点：<sup>[[1]](#references)</sup>。
```python
# Download the text to pre-train the LLM
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

"""
Create a class that receives parameters such as a tokenizer and text
and will prepare the input chunks and the target chunks to prepare
the LLM to learn which next token to generate
"""
import torch
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
def __init__(self, txt, tokenizer, max_length, stride):
self.input_ids = []
self.target_ids = []

# Tokenize the entire text
token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

# Use a sliding window to chunk the book into overlapping sequences of max_length
for i in range(0, len(token_ids) - max_length, stride):
input_chunk = token_ids[i:i + max_length]
target_chunk = token_ids[i + 1: i + max_length + 1]
self.input_ids.append(torch.tensor(input_chunk))
self.target_ids.append(torch.tensor(target_chunk))

def __len__(self):
return len(self.input_ids)

def __getitem__(self, idx):
return self.input_ids[idx], self.target_ids[idx]


"""
Create a data loader which given the text and some params will
prepare the inputs and targets with the previous class and
then create a torch DataLoader with the info
"""

import tiktoken

def create_dataloader_v1(txt, batch_size=4, max_length=256,
stride=128, shuffle=True, drop_last=True,
num_workers=0):

# Initialize the tokenizer
tokenizer = tiktoken.get_encoding("gpt2")

# Create dataset
dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)

# Create dataloader
dataloader = DataLoader(
dataset,
batch_size=batch_size,
shuffle=shuffle,
drop_last=drop_last,
num_workers=num_workers
)

return dataloader


"""
Finally, create the data loader with the params we want:
- The used text for training
- batch_size: The size of each batch
- max_length: The size of each entry on each batch
- stride: The sliding window (how many tokens should the next entry advance compared to the previous one). The smaller the more overfitting, usually this is equals to the max_length so the same tokens aren't repeated.
- shuffle: Re-order randomly
"""
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=4, stride=1, shuffle=False
)

data_iter = iter(dataloader)
first_batch = next(data_iter)
print(first_batch)

# Note the batch_size of 8, the max_length of 4 and the stride of 1
[
```

## 高级采样策略（2023-2025）

### 1. 基于 Temperature 的混合权重
最先进的 LLM 很少仅使用单一语料库进行训练。相反，它们会从多个异构数据源（代码、web、学术论文、论坛……）中进行采样。每个数据源的相对比例会显著影响下游性能。近期的开源模型（例如 Llama 2）引入了一种**基于 Temperature 的采样方案**，其中从语料库 *i* 中抽取文档的概率变为
```
p(i) = \frac{w_i^{\alpha}}{\sum_j w_j^{\alpha}}
```
• *w<sub>i</sub>*  – 语料库 *i* 的原始 token 百分比  
• *α*（“temperature”）– 取值范围为 (0,1]。α < 1 会压平分布，使较小的高质量语料库获得更高的权重。

当 `α < 1` 时，这种加权方式会压平分布，并提高较小语料库的相对采样概率。基于 temperature 的 sampling 已广泛用于平衡多语言预训练数据，但需要设置重复次数限制，以避免对较小来源过拟合。<sup>[[4]](#references)</sup>
```python
from collections import Counter

def temperature_sample(corpus_ids, alpha=0.7):
counts = Counter(corpus_ids)           # number of tokens seen per corpus
probs  = {c: c_count**alpha for c, c_count in counts.items()}
Z = sum(probs.values())
probs = {c: p/Z for c, p in probs.items()}
# Now draw according to probs to fill every batch
```
### 2. Sequence Packing / Dynamic Batching
当 batch 中的每个 sequence 都填充到最长样本的长度时，GPU memory 会被浪费。**Packing** 会将多个较短样本组合成固定长度的 block。传统的 packed 实现使用 segment-aware 或 block-diagonal 的 `attention_mask`，使 tokens 无法跨越样本边界；padding-free 实现则可以将 batch 展平，并通过 position information 保留边界。Hugging Face TRL 通过 `SFTConfig(packing=True)` 提供 packing 功能，并记录了可用的策略。<sup>[[5]](#references)</sup>

对于具体的 TRL 配置，`max_length` 定义 packed block 的大小，而 `packing_strategy` 选择 best-fit decreasing（`"bfd"`）或 wrapped packing。Best-fit decreasing 支持 padding-free batches；在 FlashAttention 2 或 3 中也支持显式设置 `padding_free=True`。不要将 `pad_to_multiple_of` 与 packing 混淆：它只会将 padded sequence 的长度向上调整为指定的倍数。<sup>[[5]](#references)</sup>

**Dynamic 或 length-aware batching 是一种独立的优化：**它不会拼接样本，而是将长度相近的样本分组，使每个 dynamically padded batch 包含更少的 padding tokens。当前的 Hugging Face Transformers 通过 `train_sampling_strategy="group_by_length"` 提供此功能；通过 `length_column_name` 选择预先计算的 `length` 列，可以避免训练开始时计算每个样本的长度。<sup>[[8]](#references)</sup>

### 3. Deduplication & Quality Filtering
重复段落会导致 memorization，并提供一个易于利用的数据 poisoning channel。因此，一个合理的 cleaning pipeline 应结合以下措施：

1. **Exact and near-duplicate detection：**对规范化文档进行 hash，使用基于 token n-grams 的 MinHash/LSH 来进行可扩展的 near-duplicate discovery，并在必须删除较长重复段落时使用 exact-substring methods。<sup>[[6]](#references)</sup>
2. **Quality filtering：**拒绝无效编码、损坏的 markup、病态重复以及错误语言的文档。Reference-model perplexity 也可以作为一种信号，但其 threshold 必须针对 corpus 进行校准，而不能视为通用 cutoff。<sup>[[2]](#references)</sup>
3. **Sensitive-data filtering：**使用 deterministic patterns 加上 entity detection 扫描 credentials 和 PII，然后将匹配结果隔离以供审核，避免 false positives 悄悄删除有用的 training data。<sup>[[7]](#references)</sup>

Llama 2 paper 将 deduplication 和 source filtering 描述为 corpus construction 的组成部分。<sup>[[2]](#references)</sup> 独立研究发现，对 language-model training data 进行 deduplication 可以减少 verbatim memorization，并且在达到相同或更高准确率时可能需要更少的 training steps。<sup>[[6]](#references)</sup>

## Security & Privacy Considerations During Sampling

### Data-Poisoning / Backdoor Attacks
研究人员证明，插入少于 1 % 的 backdoored sentences 就可以使 model 服从隐藏的 trigger（“PoisonGPT”，2023）。<sup>[[3]](#references)</sup> 推荐的 mitigations：

* **Shuffled mixing** – 确保相邻的 training examples 来自不同的 sources；这会稀释恶意 spans 的 gradient alignment。
* **Gradient similarity scoring** – 计算 example gradient 与 batch average 之间的 cosine similarity；outliers 可作为待删除对象。
* **Dataset versioning & hashes** – 固定 immutable tarballs，并在每次 training run 前验证 SHA-256。

### Membership-Inference & Memorization
sliding-window samples 之间的较长 overlap 会重复 telephone numbers 或 secret keys 等稀有字符串，从而提高它们的 effective frequency。关于 training-data privacy 的研究表明，duplicated sequences 被不成比例地频繁重新生成，而 deduplication 能实质性降低这种 exposure。<sup>[[7]](#references)</sup>

实际建议：

* 在不必要的 overlap 会反复暴露 sensitive 或 unique strings 时，避免使用这种 overlap。
* 在 splitting data 之前进行 deduplicate，避免 near-identical samples 在 training set 和 evaluation set 之间发生 leak。
