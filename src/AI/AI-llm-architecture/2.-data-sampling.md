## **Uzorkovanje podataka**

**Uzorkovanje podataka** je ključan proces u pripremi podataka za treniranje velikih jezičkih modela (LLM), kao što je GPT. Ono obuhvata organizovanje tekstualnih podataka u ulazne i ciljne sekvence koje model koristi da nauči kako da predvidi sledeću reč (ili token) na osnovu prethodnih reči. Pravilno uzorkovanje podataka omogućava modelu da efikasno prepozna jezičke obrasce i zavisnosti.

> [!TIP]
> Cilj ove druge faze je veoma jednostavan: **Uzorkovati ulazne podatke i pripremiti ih za fazu treniranja, obično razdvajanjem skupa podataka na rečenice određene dužine i generisanjem očekivanog odgovora.**

### **Zašto je uzorkovanje podataka važno**

LLM modeli, kao što je GPT, treniraju se za generisanje ili predviđanje teksta tako što razumeju kontekst koji pružaju prethodne reči. Da bi se to postiglo, podaci za treniranje moraju biti strukturirani tako da model može da nauči odnos između sekvenci reči i reči koje slede. Ovakav strukturirani pristup omogućava modelu da uopštava i generiše koherentan tekst relevantan za dati kontekst.

### **Ključni koncepti uzorkovanja podataka**

1. **Tokenizacija:** Razlaganje teksta na manje jedinice koje se nazivaju tokeni (npr. reči, podreči ili karakteri).
2. **Dužina sekvence (max_length):** Broj tokena u svakoj ulaznoj sekvenci.
3. **Klizni prozor:** Metod za kreiranje preklapajućih ulaznih sekvenci pomeranjem prozora preko tokenizovanog teksta.
4. **Korak:** Broj tokena za koji se klizni prozor pomera unapred da bi se kreirala sledeća sekvenca.

### **Primer korak po korak**

Pogledajmo primer koji ilustruje uzorkovanje podataka.

**Tekst primera**
```arduino
"Lorem ipsum dolor sit amet, consectetur adipiscing elit."
```
**Tokenizacija**

Pretpostavimo da koristimo **osnovni tokenizer** koji deli tekst na reči i znakove interpunkcije:
```vbnet
Tokens: ["Lorem", "ipsum", "dolor", "sit", "amet,", "consectetur", "adipiscing", "elit."]
```
**Parametri**

- **Maksimalna dužina sekvence (max_length):** 4 tokena
- **Korak kliznog prozora:** 1 token

**Kreiranje ulaznih i ciljnih sekvenci**

1. **Pristup kliznog prozora:**
- **Ulazne sekvence:** Svaka ulazna sekvenca sastoji se od `max_length` tokena.
- **Ciljne sekvence:** Svaka ciljna sekvenca sastoji se od tokena koji neposredno slede odgovarajuću ulaznu sekvencu.
2. **Generisanje sekvenci:**

- **Ulaz:**

```python
["dolor", "sit", "amet,", "consectetur"],
```

**Klizni prozor sa korakom 1:**

- **Prvi prozor (pozicije 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Cilj:** \["ipsum", "dolor", "sit", "amet,"]
- **Drugi prozor (pozicije 2-5):** \["ipsum", "dolor", "sit", "amet,"] → **Cilj:** \["dolor", "sit", "amet,", "consectetur"]
- **Treći prozor (pozicije 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Cilj:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Četvrti prozor (pozicije 4-7):** \["sit", "amet,", "consectetur", "adipiscing"] → **Cilj:** \["amet,", "consectetur", "adipiscing", "elit."]

**Razumevanje koraka**

- **Korak 1:** Prozor se svaki put pomera unapred za jedan token, što rezultuje sekvencama sa velikim preklapanjem. Ovo može dovesti do boljeg učenja kontekstualnih odnosa, ali može povećati rizik od overfitting-a jer se slične tačke podataka ponavljaju.
- **Korak 2:** Prozor se svaki put pomera unapred za dva tokena, čime se smanjuje preklapanje. Ovo smanjuje redundantnost i computational load, ali može izostaviti neke kontekstualne nijanse.
- **Korak jednak vrednosti max_length:** Prozor se pomera unapred za svoju ukupnu veličinu, što rezultuje sekvencama bez preklapanja. Ovo svodi redundantnost podataka na minimum, ali može ograničiti sposobnost modela da uči zavisnosti između sekvenci.

**Primer sa korakom 2:**

Koristeći isti tokenizovani tekst i `max_length` od 4:

- **Prvi prozor (pozicije 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Cilj:** \["ipsum", "dolor", "sit", "amet,"]
- **Drugi prozor (pozicije 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Cilj:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Treći prozor (pozicije 5-8):** \["amet,", "consectetur", "adipiscing", "elit."] → **Cilj:** \["consectetur", "adipiscing", "elit.", "sed"] _(Pod pretpostavkom nastavka)_

```python
# Download the text to pre-train the LLM
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

"""
Create a class that receives parameters such as a tokenizer and text
and will prepare the input chunks and the target chunks to prepare
the LLM to learn which next token to generate
"""
import torch
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
def __init__(self, txt, tokenizer, max_length, stride):
self.input_ids = []
self.target_ids = []

# Tokenize the entire text
token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

# Use a sliding window to chunk the book into overlapping sequences of max_length
for i in range(0, len(token_ids) - max_length, stride):
input_chunk = token_ids[i:i + max_length]
target_chunk = token_ids[i + 1: i + max_length + 1]
self.input_ids.append(torch.tensor(input_chunk))
self.target_ids.append(torch.tensor(target_chunk))

def __len__(self):
return len(self.input_ids)

def __getitem__(self, idx):
return self.input_ids[idx], self.target_ids[idx]


"""
Create a data loader which given the text and some params will
prepare the inputs and targets with the previous class and
then create a torch DataLoader with the info
"""

import tiktoken

def create_dataloader_v1(txt, batch_size=4, max_length=256,
stride=128, shuffle=True, drop_last=True,
num_workers=0):

# Initialize the tokenizer
tokenizer = tiktoken.get_encoding("gpt2")

# Create dataset
dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)

# Create dataloader
dataloader = DataLoader(
dataset,
batch_size=batch_size,
shuffle=shuffle,
drop_last=drop_last,
num_workers=num_workers
)

return dataloader


"""
Finally, create the data loader with the params we want:
- The used text for training
- batch_size: The size of each batch
- max_length: The size of each entry on each batch
- stride: The sliding window (how many tokens should the next entry advance compared to the previous one). The smaller the more overfitting, usually this is equals to the max_length so the same tokens aren't repeated.
- shuffle: Re-order randomly
"""
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=4, stride=1, shuffle=False
)

data_iter = iter(dataloader)
first_batch = next(data_iter)
print(first_batch)

# Note the batch_size of 8, the max_length of 4 and the stride of 1
```

## Napredne strategije uzorkovanja (2023-2025)

### 1. Mešovito ponderisanje zasnovano na temperaturi
Najnapredniji LLM-ovi se retko treniraju na samo jednom korpusu. Umesto toga, uzorkuju podatke iz nekoliko heterogenih izvora podataka (code, web, akademski radovi, forumi…). Relativni udeo svakog izvora može značajno uticati na performanse u narednim fazama. Noviji open-source modeli, kao što je Llama 2, uveli su **šemu uzorkovanja zasnovanu na temperaturi**, u kojoj verovatnoća odabira dokumenta iz korpusa *i* postaje
```
p(i) = \frac{w_i^{\alpha}}{\sum_j w_j^{\alpha}}
```
• *w<sub>i</sub>* – sirovi procenat tokena korpusa *i*  
• *α* („temperature“) – vrednost u (0,1]. α < 1 izravnava distribuciju, dajući veću težinu manjim korpusima visokog kvaliteta.

Sa `α < 1`, ovo ponderisanje izravnava distribuciju i povećava relativnu verovatnoću uzorkovanja manjih korpusa. Temperature-based sampling se široko koristi za balansiranje multilingual pretraining podataka, mada su ograničenja ponavljanja potrebna kako bi se izbegao overfitting malih izvora.<sup>[[4]](#references)</sup>
```python
from collections import Counter

def temperature_sample(corpus_ids, alpha=0.7):
counts = Counter(corpus_ids)           # number of tokens seen per corpus
probs  = {c: c_count**alpha for c, c_count in counts.items()}
Z = sum(probs.values())
probs = {c: p/Z for c, p in probs.items()}
# Now draw according to probs to fill every batch
```
### 2. Sequence Packing / Dynamic Batching
GPU memorija se rasipa kada se svaka sekvenca u batch-u dopunjava do dužine najdužeg primera. **Packing** grupiše više kraćih primera u blokove fiksne dužine. Konvencionalna implementacija packed režima koristi `attention_mask` koja uzima u obzir segmente ili blokove, tako da tokeni ne mogu da obraćaju pažnju na sadržaj izvan granica primera; implementacije bez padding-a umesto toga mogu da spljošte batch i očuvaju granice pomoću informacija o poziciji. Hugging Face TRL omogućava packing kroz `SFTConfig(packing=True)` i dokumentuje dostupne strategije.<sup>[[5]](#references)</sup>

U konkretnoj TRL konfiguraciji, `max_length` definiše veličinu packed bloka, a `packing_strategy` bira ili best-fit decreasing (`"bfd"`) ili wrapped packing. Best-fit decreasing omogućava batch-eve bez padding-a; eksplicitni `padding_free=True` podržan je uz FlashAttention 2 ili 3. Nemojte mešati `pad_to_multiple_of` sa packing-om: on samo zaokružuje dužine sekvenci sa padding-om na izabrani umnožak.<sup>[[5]](#references)</sup>

**Dynamic ili length-aware batching je zasebna optimizacija:** ne spaja primere. Umesto toga, grupiše primere sličnih dužina, tako da svaki batch sa dinamičkim padding-om sadrži manje padding tokena. Aktuelni Hugging Face Transformers ovo izlaže kroz `train_sampling_strategy="group_by_length"`; unapred izračunata kolona `length`, izabrana preko `length_column_name`, izbegava izračunavanje dužine svakog primera pri pokretanju treninga.<sup>[[8]](#references)</sup>

### 3. Deduplication & Quality Filtering
Ponovljeni odlomci uzrokuju memorisanje i predstavljaju jednostavan kanal za data poisoning. Pouzdan pipeline za čišćenje zato kombinuje:

1. **Detekciju identičnih i skoro identičnih duplikata:** hash-ujte normalizovane dokumente, koristite MinHash/LSH nad token n-gramima za skalabilno otkrivanje skoro identičnih duplikata i koristite metode za pronalaženje identičnih podniski kada je potrebno ukloniti duge ponovljene odlomke.<sup>[[6]](#references)</sup>
2. **Quality filtering:** odbacite nevažeća kodiranja, oštećen markup, patološko ponavljanje i dokumente na pogrešnom jeziku. Perplexity referentnog modela može biti dodatni signal, ali njegov prag mora biti kalibrisan za konkretan korpus, a ne tretiran kao univerzalna granica.<sup>[[2]](#references)</sup>
3. **Sensitive-data filtering:** skenirajte credentials i PII pomoću determinističkih obrazaca i detekcije entiteta, a zatim matches stavite u karantin radi provere kako false positives ne bi neprimetno izbrisali korisne training podatke.<sup>[[7]](#references)</sup>

Llama 2 rad opisuje deduplikaciju i filtriranje izvora kao deo izgradnje korpusa.<sup>[[2]](#references)</sup> Nezavisno istraživanje pokazalo je da deduplikacija training podataka za language model smanjuje memorisanje sadržaja verbatim i može zahtevati manje training koraka za jednaku ili bolju tačnost.<sup>[[6]](#references)</sup>

## Security & Privacy Considerations During Sampling

### Data-Poisoning / Backdoor Attacks

Tretirajte otkrivanje korpusa, materijalizaciju, filtriranje i sampling kao jedinstveni supply chain. Manifest koji sadrži samo URL-ove nije nepromenljiv training data:

* **Split-view poisoning:** napadač učini da resurs izgleda bezazleno kada ga curator indeksira, a zatim promeni ono što kasniji training klijenti preuzimaju. Ovo iskorišćava vremenski jaz između kreiranja dataset-a i materijalizacije.
* **Frontrunning poisoning:** napadač nakratko izmeni izvor koji uređuje zajednica neposredno pre predvidivog snapshot-a ili crawl-a, a zatim ga vrati u prethodno stanje. Malicious sample ostaje u snapshot-u iako live stranica kasnije izgleda čisto.

Obe tehnike ciljaju **trenutak preuzimanja sample-a**, a ne ranjivost parsera. Istraživači su ih demonstrirali protiv trust pretpostavki više web-scale dataset-ova, uključujući isticanje/ponovnu registraciju URL-ova i vremenski ograničene izmene.<sup>[[9]](#references)</sup>

**Sampling može pojačati mali poisoned cluster.** Relevantna metrika nije samo `poison_documents / raw_documents`, već broj puta kada ti dokumenti postanu optimization examples nakon source weighting-a, repetition-a, chunking-a i preklapajućih prozora. U velikim pre-training eksperimentima, 250 poisoned dokumenata proizvelo je uporediv backdoor efekat kroz modele od 600M do 13B parametara trenirane na 6B do 260B clean tokena; zato threshold upozorenja zasnovan samo na procentu može postati slabiji kako korpus raste.<sup>[[10]](#references)</sup>

Za audit ingestion-a čuvajte i **broj jedinstvenih dokumenata** i **broj efektivnih izlaganja**.<sup>[[10]](#references)</sup>
```text
effective_exposure(doc) =
epochs × source_sampling_weight × repetitions × emitted_chunks(doc)
```
Praktične kontrole izvedene iz ovih grešaka pri ingestion-u i izlaganju uključuju:<sup>[[9]](#references)[[10]](#references)</sup>

* Zamrznite content-addressed artifacts umesto ponovnog preuzimanja mutable URL-ova. Sačuvajte originalni URL, vreme preuzimanja, dužinu u bajtovima, digest i verziju transformacije; prekinite obradu ako se digest ne podudara.
* Izračunajte hash bajtova i pre i posle normalizacije. Prvi digest potvrđuje integritet izvora; drugi omogućava deduplikaciju i kasniju reprodukciju.
* Izvršite deduplikaciju pre mixture upsampling-a i generisanja prozora, zatim ograničite izlaganje po klasteru exact/near-duplicate podataka i po poreklu. Mešanje menja redosled, ali ne uklanja poison.
* Zabeležite stabilan `document_id` u svaku emitovanu sekvencu kako bi se sumnjivo ponašanje modela moglo pratiti kroz packed batches do izvornih dokumenata.
* Pre treninga direktno proverite zamrznuti manifest, na primer pomoću `sha256sum -c corpus.sha256`; nemojte nečujno preuzimati zamenu za objekat koji nedostaje ili je izmenjen.

### Membership-Inference & Memorization
Veliko preklapanje između sliding-window uzoraka ponavlja retke stringove kao što su telefonski brojevi ili secret keys, čime se povećava njihova efektivna učestalost. Istraživanja o privatnosti training data pokazuju da se duplicated sequences nesrazmerno često regenerišu i da deduplikacija značajno smanjuje ovu izloženost.<sup>[[7]](#references)</sup>

Praktične preporuke:

* Izbegavajte nepotrebno preklapanje kada bi ono više puta izlagalo osetljive ili jedinstvene stringove.
* Izvršite deduplikaciju pre podele podataka kako near-identical samples ne bi leak-ovali između training i evaluation setova.
