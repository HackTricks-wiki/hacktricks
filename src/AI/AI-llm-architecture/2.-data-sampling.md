## **Δειγματοληψία Δεδομένων**

Η **Δειγματοληψία Δεδομένων** είναι μια κρίσιμη διαδικασία για την προετοιμασία δεδομένων εκπαίδευσης μεγάλων γλωσσικών μοντέλων (LLMs), όπως το GPT. Περιλαμβάνει την οργάνωση δεδομένων κειμένου σε ακολουθίες εισόδου και στόχου, τις οποίες χρησιμοποιεί το μοντέλο για να μάθει πώς να προβλέπει την επόμενη λέξη (ή token) με βάση τις προηγούμενες λέξεις. Η σωστή δειγματοληψία δεδομένων διασφαλίζει ότι το μοντέλο καταγράφει αποτελεσματικά τα γλωσσικά μοτίβα και τις εξαρτήσεις.

> [!TIP]
> Ο στόχος αυτής της δεύτερης φάσης είναι πολύ απλός: **Να γίνει δειγματοληψία των δεδομένων εισόδου και να προετοιμαστούν για τη φάση εκπαίδευσης, συνήθως διαχωρίζοντας το dataset σε προτάσεις συγκεκριμένου μήκους και δημιουργώντας επίσης την αναμενόμενη απάντηση.**

### **Γιατί είναι σημαντική η Δειγματοληψία Δεδομένων**

Τα LLMs, όπως το GPT, εκπαιδεύονται ώστε να δημιουργούν ή να προβλέπουν κείμενο κατανοώντας το context που παρέχουν οι προηγούμενες λέξεις. Για να επιτευχθεί αυτό, τα δεδομένα εκπαίδευσης πρέπει να είναι δομημένα με τρόπο που επιτρέπει στο μοντέλο να μάθει τη σχέση μεταξύ ακολουθιών λέξεων και των επόμενων λέξεών τους. Αυτή η δομημένη προσέγγιση επιτρέπει στο μοντέλο να γενικεύει και να δημιουργεί συνεκτικό και συναφές με το context κείμενο.

### **Βασικές Έννοιες στη Δειγματοληψία Δεδομένων**

1. **Tokenization:** Διαχωρισμός του κειμένου σε μικρότερες μονάδες που ονομάζονται tokens (π.χ. λέξεις, υπολέξεις ή χαρακτήρες).
2. **Sequence Length (max_length):** Ο αριθμός των tokens σε κάθε sequence εισόδου.
3. **Sliding Window:** Μέθοδος δημιουργίας επικαλυπτόμενων sequences εισόδου, με μετακίνηση ενός παραθύρου πάνω από το tokenized κείμενο.
4. **Stride:** Ο αριθμός των tokens κατά τον οποίο μετακινείται το sliding window προς τα εμπρός για τη δημιουργία του επόμενου sequence.

### **Παράδειγμα Βήμα προς Βήμα**

Ας δούμε ένα παράδειγμα για να παρουσιάσουμε τη δειγματοληψία δεδομένων.

**Παράδειγμα Κειμένου**
```arduino
"Lorem ipsum dolor sit amet, consectetur adipiscing elit."
```
**Tokenization**

Ας υποθέσουμε ότι χρησιμοποιούμε έναν **basic tokenizer** που χωρίζει το κείμενο σε λέξεις και σημεία στίξης:
```vbnet
Tokens: ["Lorem", "ipsum", "dolor", "sit", "amet,", "consectetur", "adipiscing", "elit."]
```
**Παράμετροι**

- **Μέγιστο μήκος ακολουθίας (max_length):** 4 tokens
- **Βήμα sliding window:** 1 token

**Δημιουργία ακολουθιών εισόδου και στόχου**

1. **Προσέγγιση sliding window:**
- **Ακολουθίες εισόδου:** Κάθε ακολουθία εισόδου αποτελείται από `max_length` tokens.
- **Ακολουθίες στόχου:** Κάθε ακολουθία στόχου αποτελείται από τα tokens που ακολουθούν αμέσως την αντίστοιχη ακολουθία εισόδου.
2. **Δημιουργία ακολουθιών:**

**Sliding window με βήμα 1:**

- **Πρώτο παράθυρο (Θέσεις 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Στόχος:** \["ipsum", "dolor", "sit", "amet,"]
- **Δεύτερο παράθυρο (Θέσεις 2-5):** \["ipsum", "dolor", "sit", "amet,"] → **Στόχος:** \["dolor", "sit", "amet,", "consectetur"]
- **Τρίτο παράθυρο (Θέσεις 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Στόχος:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Τέταρτο παράθυρο (Θέσεις 4-7):** \["sit", "amet,", "consectetur", "adipiscing"] → **Στόχος:** \["amet,", "consectetur", "adipiscing", "elit."]

**Κατανόηση του βήματος**

- **Βήμα 1:** Το παράθυρο μετακινείται προς τα εμπρός κατά ένα token κάθε φορά, με αποτέλεσμα ακολουθίες που επικαλύπτονται σε μεγάλο βαθμό. Αυτό μπορεί να οδηγήσει σε καλύτερη εκμάθηση των σχέσεων συμφραζομένων, αλλά μπορεί επίσης να αυξήσει τον κίνδυνο overfitting, καθώς επαναλαμβάνονται παρόμοια σημεία δεδομένων.
- **Βήμα 2:** Το παράθυρο μετακινείται προς τα εμπρός κατά δύο tokens κάθε φορά, μειώνοντας την επικάλυψη. Αυτό μειώνει τον πλεονασμό και το υπολογιστικό φορτίο, αλλά μπορεί να παραλείψει ορισμένες λεπτές αποχρώσεις των συμφραζομένων.
- **Βήμα ίσο με max_length:** Το παράθυρο μετακινείται προς τα εμπρός κατά ολόκληρο το μέγεθος του παραθύρου, με αποτέλεσμα ακολουθίες χωρίς επικάλυψη. Αυτό ελαχιστοποιεί τον πλεονασμό δεδομένων, αλλά μπορεί να περιορίσει την ικανότητα του μοντέλου να μαθαίνει εξαρτήσεις μεταξύ ακολουθιών.

**Παράδειγμα με βήμα 2:**

Χρησιμοποιώντας το ίδιο tokenized κείμενο και `max_length` ίσο με 4:

- **Πρώτο παράθυρο (Θέσεις 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Στόχος:** \["ipsum", "dolor", "sit", "amet,"]
- **Δεύτερο παράθυρο (Θέσεις 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Στόχος:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Τρίτο παράθυρο (Θέσεις 5-8):** \["amet,", "consectetur", "adipiscing", "elit."] → **Στόχος:** \["consectetur", "adipiscing", "elit.", "sed"] _(Με την υπόθεση ότι υπάρχει συνέχεια)_

with open("the-verdict.txt", "r", encoding="utf-8") as f:

"""
Create a class that will receive some params lie tokenizer and text
and will prepare the input chunks and the target chunks to prepare
the LLM to learn which next token to generate
"""
import torch
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
def __init__(self, txt, tokenizer, max_length, stride):
self.input_ids = []
self.target_ids = []

# Tokenize the entire text
token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

# Use a sliding window to chunk the book into overlapping sequences of max_length
for i in range(0, len(token_ids) - max_length, stride):
input_chunk = token_ids[i:i + max_length]
target_chunk = token_ids[i + 1: i + max_length + 1]
self.input_ids.append(torch.tensor(input_chunk))
self.target_ids.append(torch.tensor(target_chunk))

def __len__(self):
return len(self.input_ids)

def __getitem__(self, idx):
return self.input_ids[idx], self.target_ids[idx]


"""
Create a data loader which given the text and some params will
prepare the inputs and targets with the previous class and
then create a torch DataLoader with the info
"""

import tiktoken

def create_dataloader_v1(txt, batch_size=4, max_length=256,
stride=128, shuffle=True, drop_last=True,
num_workers=0):

# Initialize the tokenizer
tokenizer = tiktoken.get_encoding("gpt2")

# Create dataset
dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)

# Create dataloader
dataloader = DataLoader(
dataset,
batch_size=batch_size,
shuffle=shuffle,
drop_last=drop_last,
num_workers=num_workers
)

return dataloader


"""
Finally, create the data loader with the params we want:
- The used text for training
- batch_size: The size of each batch
- max_length: The size of each entry on each batch
- stride: The sliding window (how many tokens should the next entry advance compared to the previous one). The smaller the more overfitting, usually this is equals to the max_length so the same tokens aren't repeated.
- shuffle: Re-order randomly
"""
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=4, stride=1, shuffle=False
)

data_iter = iter(dataloader)
first_batch = next(data_iter)
print(first_batch)

## Προηγμένες στρατηγικές sampling (2023-2025)

### 1. Temperature-Based Mixture Weighting
Τα state-of-the-art LLMs σπάνια εκπαιδεύονται σε ένα μόνο corpus. Αντίθετα, κάνουν sampling από πολλές ετερογενείς πηγές δεδομένων (code, web, ακαδημαϊκές εργασίες, forums…). Η σχετική αναλογία κάθε πηγής μπορεί να επηρεάσει σημαντικά την downstream επίδοση. Πρόσφατα open-source μοντέλα, όπως το Llama 2, εισήγαγαν ένα **temperature-based sampling scheme**, όπου η πιθανότητα επιλογής ενός document από το corpus *i* γίνεται
```
p(i) = \frac{w_i^{\alpha}}{\sum_j w_j^{\alpha}}
```
• *w<sub>i</sub>*  – ακατέργαστο ποσοστό tokens του corpus *i*
• *α* («temperature») – μια τιμή στο (0,1].  Το α < 1 εξομαλύνει την κατανομή, δίνοντας μεγαλύτερο βάρος σε μικρότερα corpora υψηλής ποιότητας.

Το Llama 2 χρησιμοποίησε α = 0.7 και έδειξε ότι η μείωση του α αύξησε τις βαθμολογίες αξιολόγησης σε tasks με έντονη απαίτηση γνώσεων, διατηρώντας παράλληλα σταθερό το training mix.<sup>[[2]](#references)</sup>  Το ίδιο trick υιοθετείται από τα Mistral (2023) και Claude 3.
```python
from collections import Counter

def temperature_sample(corpus_ids, alpha=0.7):
counts = Counter(corpus_ids)           # number of tokens seen per corpus
probs  = {c: c_count**alpha for c, c_count in counts.items()}
Z = sum(probs.values())
probs = {c: p/Z for c, p in probs.items()}
# Now draw according to probs to fill every batch

### 2. Sequence Packing / Dynamic Batching
GPU memory is wasted when every sequence in a batch is padded to the longest example.  "Packing" concatenates multiple shorter sequences until the **exact** `max_length` is reached and builds a parallel `attention_mask` so that tokens do not attend across segment boundaries.  Packing can improve throughput by 20–40 % with no gradient change and is supported out-of-the-box in

* PyTorch `torchtext.experimental.agents.PackedBatch`
* HuggingFace `DataCollatorForLanguageModeling(pad_to_multiple_of=…)`

Dynamic batching frameworks (e.g. FlashAttention 2, vLLM 2024) combine sequence packing with just-in-time kernel selection, enabling thousand-token context training at 400+ K tokens/s on A100-80G.

### 3. Deduplication & Quality Filtering
Repeated passages cause memorization and provide an easy channel for data-poisoning.  Modern pipelines therefore:

1. MinHash/FAISS near-duplicate detection at **document** and **128-gram** level.
2. Filter documents whose perplexity under a small reference model is > µ + 3σ (noisy OCR, garbled HTML).
3. Block-list documents that contain PII or CWE keywords using regex & spaCy NER.

The Llama 2 team deduplicated with 8-gram MinHash and removed ~15 % of CommonCrawl before sampling.<sup>[[2]](#references)</sup>  OpenAI’s 2024 "Deduplicate Everything" paper demonstrates ≤0.04 duplicate ratio reduces over-fitting and speeds convergence.

## Security & Privacy Considerations During Sampling

### Data-Poisoning / Backdoor Attacks
Researchers showed that inserting <1 % backdoored sentences can make a model obey a hidden trigger ("PoisonGPT", 2023).<sup>[[3]](#references)</sup>  Recommended mitigations:

* **Shuffled mixing** – make sure adjacent training examples originate from different sources; this dilutes gradient alignment of malicious spans.
* **Gradient similarity scoring** – compute cosine similarity of example gradient to batch average; outliers are candidates for removal.
* **Dataset versioning & hashes** – freeze immutable tarballs and verify SHA-256 before each training run.

### Membership-Inference & Memorization
Long overlap between sliding-window samples increases the chance that rare strings (telephone numbers, secret keys) are memorized.  OpenAI’s 2024 study on ChatGPT memorization reports that raising stride from 1 × `max_length` to 4 × reduces verbatim leakage by ≈50 % with negligible loss in perplexity.

Practical recommendations:

* Use **stride ≥ max_length** except for <1B parameter models where data volume is scarce.
* Add random masking of 1-3 tokens per window during training; this lowers memorization while preserving utility.
