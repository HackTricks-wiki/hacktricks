## **데이터 샘플링**

**데이터 샘플링**은 GPT와 같은 large language models(LLMs)을 training하기 위한 데이터를 준비하는 데 중요한 process입니다. 이는 model이 앞에 나오는 단어를 기반으로 다음 단어(또는 token)를 예측하는 방법을 학습할 수 있도록 text data를 input 및 target sequence로 구성하는 작업입니다. 적절한 데이터 샘플링은 model이 language pattern과 dependency를 효과적으로 파악하도록 합니다.

> [!TIP]
> 이 두 번째 단계의 목표는 매우 간단합니다. **input data를 샘플링하고, 일반적으로 dataset을 특정 길이의 sentence로 분리한 다음 예상 response도 생성하여 training phase에 사용할 수 있도록 준비하는 것입니다.**

### **데이터 샘플링이 중요한 이유**

GPT와 같은 LLM은 이전 단어가 제공하는 context를 이해하여 text를 생성하거나 예측하도록 training됩니다. 이를 위해 training data는 model이 단어 sequence와 그 뒤에 이어지는 단어 간의 relationship을 학습할 수 있는 방식으로 구성되어야 합니다. 이러한 구조화된 접근 방식을 통해 model은 일관성 있고 context에 적합한 text를 generalize하고 생성할 수 있습니다.

### **데이터 샘플링의 핵심 개념**

1. **Tokenization:** text를 token이라고 하는 더 작은 단위(예: 단어, subword 또는 character)로 나누는 작업입니다.
2. **Sequence Length (max_length):** 각 input sequence에 포함되는 token의 수입니다.
3. **Sliding Window:** tokenized text 위에서 window를 이동하여 서로 겹치는 input sequence를 생성하는 방법입니다.
4. **Stride:** 다음 sequence를 생성하기 위해 sliding window가 앞으로 이동하는 token의 수입니다.

### **단계별 예시**

데이터 샘플링을 설명하기 위해 예시를 살펴보겠습니다.

**Example Text**
```arduino
"Lorem ipsum dolor sit amet, consectetur adipiscing elit."
```
**토큰화**

텍스트를 단어와 문장 부호로 분할하는 **basic tokenizer**를 사용한다고 가정합니다:
```vbnet
Tokens: ["Lorem", "ipsum", "dolor", "sit", "amet,", "consectetur", "adipiscing", "elit."]
```
**Parameters**

- **Max Sequence Length (max_length):** 4 tokens
- **Sliding Window Stride:** 1 token

**Creating Input and Target Sequences**

1. **Sliding Window Approach:**
- **Input Sequences:** 각 input sequence는 `max_length`개의 token으로 구성됩니다.
- **Target Sequences:** 각 target sequence는 해당 input sequence 바로 다음에 오는 token으로 구성됩니다.
2. **Generating Sequences:**

3. **Resulting Input and Target Arrays:**

- **Input:**

```python
[
["Lorem", "ipsum", "dolor", "sit"],
["ipsum", "dolor", "sit", "amet,"],
["dolor", "sit", "amet,", "consectetur"],
["sit", "amet,", "consectetur", "adipiscing"],
]
```

- **Target:**

```python
[
["ipsum", "dolor", "sit", "amet,"],
["dolor", "sit", "amet,", "consectetur"],
["sit", "amet,", "consectetur", "adipiscing"],
["amet,", "consectetur", "adipiscing", "elit."],
]
```

**Visual Representation**

**Sliding Window with Stride 1:**

- **First Window (Positions 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Target:** \["ipsum", "dolor", "sit", "amet,"]
- **Second Window (Positions 2-5):** \["ipsum", "dolor", "sit", "amet,"] → **Target:** \["dolor", "sit", "amet,", "consectetur"]
- **Third Window (Positions 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Target:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Fourth Window (Positions 4-7):** \["sit", "amet,", "consectetur", "adipiscing"] → **Target:** \["amet,", "consectetur", "adipiscing", "elit."]

**Understanding Stride**

- **Stride of 1:** window가 매번 한 token씩 앞으로 이동하므로 서로 많이 겹치는 sequence가 생성됩니다. 이를 통해 contextual relationship을 더 잘 학습할 수 있지만, 유사한 data point가 반복되므로 overfitting 위험이 증가할 수 있습니다.
- **Stride of 2:** window가 매번 두 token씩 앞으로 이동하므로 overlap이 줄어듭니다. 이렇게 하면 redundancy와 computational load가 감소하지만, 일부 contextual nuance를 놓칠 수 있습니다.
- **Stride Equal to max_length:** window가 전체 window size만큼 앞으로 이동하므로 서로 겹치지 않는 sequence가 생성됩니다. 이를 통해 data redundancy를 최소화할 수 있지만, sequence 간 dependency를 학습하는 model의 능력이 제한될 수 있습니다.

**Example with Stride of 2:**

동일한 tokenized text와 `max_length` 4를 사용합니다.

- **First Window (Positions 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Target:** \["ipsum", "dolor", "sit", "amet,"]
- **Second Window (Positions 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Target:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Third Window (Positions 5-8):** \["amet,", "consectetur", "adipiscing", "elit."] → **Target:** \["consectetur", "adipiscing", "elit.", "sed"] _(continuation을 가정)_

## Code Example

다음 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb)의 code example을 통해 더 자세히 살펴보겠습니다:<sup>[[1]](#references)</sup>
```python
# Download the text to pre-train the LLM
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

"""
Create a class that receives parameters such as a tokenizer and text
and will prepare the input chunks and the target chunks to prepare
the LLM to learn which next token to generate
"""
import torch
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
def __init__(self, txt, tokenizer, max_length, stride):
self.input_ids = []
self.target_ids = []

# Tokenize the entire text
token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

# Use a sliding window to chunk the book into overlapping sequences of max_length
for i in range(0, len(token_ids) - max_length, stride):
input_chunk = token_ids[i:i + max_length]
target_chunk = token_ids[i + 1: i + max_length + 1]
self.input_ids.append(torch.tensor(input_chunk))
self.target_ids.append(torch.tensor(target_chunk))

def __len__(self):
return len(self.input_ids)

def __getitem__(self, idx):
return self.input_ids[idx], self.target_ids[idx]


"""
Create a data loader which given the text and some params will
prepare the inputs and targets with the previous class and
then create a torch DataLoader with the info
"""

import tiktoken

def create_dataloader_v1(txt, batch_size=4, max_length=256,
stride=128, shuffle=True, drop_last=True,
num_workers=0):

# Initialize the tokenizer
tokenizer = tiktoken.get_encoding("gpt2")

# Create dataset
dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)

# Create dataloader
dataloader = DataLoader(
dataset,
batch_size=batch_size,
shuffle=shuffle,
drop_last=drop_last,
num_workers=num_workers
)

return dataloader


"""
Finally, create the data loader with the params we want:
- The used text for training
- batch_size: The size of each batch
- max_length: The size of each entry on each batch
- stride: The sliding window (how many tokens should the next entry advance compared to the previous one). The smaller the more overfitting, usually this is equals to the max_length so the same tokens aren't repeated.
- shuffle: Re-order randomly
"""
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=4, stride=1, shuffle=False
)

data_iter = iter(dataloader)
first_batch = next(data_iter)
print(first_batch)

# Note the batch_size of 8, the max_length of 4 and the stride of 1
[

[  367,  2885,  1464,  1807],
```

## 고급 Sampling 전략 (2023-2025)

### 1. Temperature-Based Mixture Weighting
최첨단 LLM은 단일 corpus로 학습되는 경우가 드뭅니다. 대신 여러 이질적인 data source(code, web, academic papers, forums…)에서 샘플링합니다. 각 source의 상대적 비율은 downstream performance에 큰 영향을 미칠 수 있습니다. Llama 2와 같은 최신 open-source model은 **temperature-based sampling scheme**을 도입했습니다. 이 방식에서는 corpus *i*에서 document를 추출할 확률이
```
p(i) = \frac{w_i^{\alpha}}{\sum_j w_j^{\alpha}}
```
• *w<sub>i</sub>*  – 코퍼스 *i*의 raw token 비율  
• *α* ("temperature") – (0,1] 범위의 값. α < 1은 분포를 평탄화하여 더 작은 고품질 코퍼스에 더 많은 가중치를 부여합니다.

`α < 1`이면 이 가중치가 분포를 평탄화하고 더 작은 코퍼스의 상대적 sampling probability를 높입니다. Temperature-based sampling은 multilingual pretraining data의 균형을 맞추는 데 널리 사용되어 왔지만, 작은 source의 overfitting을 방지하려면 repetition limit가 필요합니다.<sup>[[4]](#references)</sup>
```python
from collections import Counter

def temperature_sample(corpus_ids, alpha=0.7):
counts = Counter(corpus_ids)           # number of tokens seen per corpus
probs  = {c: c_count**alpha for c, c_count in counts.items()}
Z = sum(probs.values())
probs = {c: p/Z for c, p in probs.items()}
# Now draw according to probs to fill every batch
```
### 2. Sequence Packing / Dynamic Batching
배치의 모든 sequence를 가장 긴 example에 맞춰 padding하면 GPU memory가 낭비됩니다. **Packing**은 여러 개의 짧은 example을 고정 길이 block으로 그룹화합니다. 일반적인 packed 구현은 segment-aware 또는 block-diagonal `attention_mask`를 사용하여 token이 example 경계를 넘어 attend할 수 없도록 합니다. 반면 padding-free 구현은 batch를 flatten하고 position information으로 경계를 유지할 수 있습니다. Hugging Face TRL은 `SFTConfig(packing=True)`를 통해 packing을 제공하며, 사용 가능한 strategy를 문서화합니다.<sup>[[5]](#references)</sup>

구체적인 TRL configuration에서 `max_length`는 packed block size를 정의하고, `packing_strategy`는 best-fit decreasing (`"bfd"`) 또는 wrapped packing 중 하나를 선택합니다. Best-fit decreasing은 padding-free batch를 활성화하며, FlashAttention 2 또는 3에서는 명시적인 `padding_free=True`도 지원됩니다. `pad_to_multiple_of`를 packing과 혼동하지 마세요. 이는 padding된 sequence length를 선택한 multiple로 반올림할 뿐입니다.<sup>[[5]](#references)</sup>

**Dynamic 또는 length-aware batching은 별도의 optimization입니다:** example을 concatenate하지 않습니다. 대신 길이가 비슷한 example을 그룹화하여 각 dynamically padded batch에 포함되는 padding token 수를 줄입니다. 현재 Hugging Face Transformers에서는 이를 `train_sampling_strategy="group_by_length"`로 제공합니다. `length_column_name`을 통해 미리 계산된 `length` column을 지정하면 training 시작 시 모든 example의 길이를 계산하지 않아도 됩니다.<sup>[[8]](#references)</sup>

### 3. Deduplication & Quality Filtering
반복되는 passage는 memorization을 유발하고 data poisoning을 위한 쉬운 channel을 제공합니다. 따라서 방어 가능한 cleaning pipeline은 다음을 결합합니다.

1. **Exact 및 near-duplicate detection:** normalized document를 hash하고, 확장 가능한 near-duplicate 탐색을 위해 token n-gram에 MinHash/LSH를 사용하며, 긴 반복 passage를 제거해야 할 때는 exact-substring method를 사용합니다.<sup>[[6]](#references)</sup>
2. **Quality filtering:** 유효하지 않은 encoding, 손상된 markup, 병리적인 repetition 및 잘못된 language의 document를 거부합니다. Reference-model perplexity도 또 다른 signal이 될 수 있지만, threshold는 universal cutoff로 취급하지 말고 corpus에 맞게 calibration해야 합니다.<sup>[[2]](#references)</sup>
3. **Sensitive-data filtering:** deterministic pattern과 entity detection을 함께 사용하여 credential 및 PII를 scan한 다음, false positive로 인해 유용한 training data가 조용히 삭제되지 않도록 match를 review를 위해 quarantine합니다.<sup>[[7]](#references)</sup>

Llama 2 paper는 corpus construction의 일부로 deduplication 및 source filtering을 설명합니다.<sup>[[2]](#references)</sup> 독립적인 research에서는 language-model training data를 deduplicating하면 verbatim memorization이 감소하고, 동일하거나 더 나은 accuracy를 위해 필요한 training step 수가 줄어들 수 있음을 확인했습니다.<sup>[[6]](#references)</sup>

## Security & Privacy Considerations During Sampling

### Data-Poisoning / Backdoor Attacks
연구자들은 <1 %의 backdoored sentence를 삽입하면 model이 hidden trigger ("PoisonGPT", 2023)에 따르도록 만들 수 있음을 보였습니다.<sup>[[3]](#references)</sup> 권장되는 mitigation은 다음과 같습니다.

* **Shuffled mixing** – 인접한 training example이 서로 다른 source에서 생성되도록 하여 malicious span의 gradient alignment를 희석합니다.
* **Gradient similarity scoring** – example gradient와 batch average의 cosine similarity를 계산합니다. Outlier는 제거 후보입니다.
* **Dataset versioning & hashes** – immutable tarball을 고정하고 각 training run 전에 SHA-256을 검증합니다.

### Membership-Inference & Memorization
sliding-window sample 간의 긴 overlap은 telephone number 또는 secret key와 같은 rare string을 반복하여 effective frequency를 높입니다. Training-data privacy에 관한 research는 duplicated sequence가 불균형적으로 자주 재생성되며 deduplication이 이러한 exposure를 실질적으로 줄인다는 것을 보여줍니다.<sup>[[7]](#references)</sup>

실용적인 권장 사항:

* 민감하거나 고유한 string을 반복적으로 노출하게 되는 불필요한 overlap을 피합니다.
* Data를 split하기 전에 deduplicate하여 거의 동일한 sample이 training set와 evaluation set 사이에서 leak되지 않도록 합니다.
