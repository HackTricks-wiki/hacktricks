## **Sampuli za Data**

**Data Sampling** ni mchakato muhimu katika kuandaa data kwa ajili ya training ya large language models (LLMs) kama GPT. Unahusisha kupanga data ya maandishi kuwa mfuatano wa input na target ambao model hutumia kujifunza jinsi ya kutabiri neno (au token) linalofuata kulingana na maneno yaliyotangulia. Data sampling inayofaa huhakikisha kuwa model inatambua ipasavyo mifumo na utegemezi wa lugha.

> [!TIP]
> Lengo la awamu hii ya pili ni rahisi sana: **Chukua sampuli za data ya input na uiandae kwa awamu ya training, kwa kawaida kwa kugawanya dataset kuwa sentensi zenye urefu maalum na pia kuzalisha response inayotarajiwa.**

### **Kwa Nini Data Sampling ni Muhimu**

LLMs kama GPT hufunzwa kuzalisha au kutabiri maandishi kwa kuelewa muktadha unaotolewa na maneno yaliyotangulia. Ili kufanikisha hili, data ya training lazima ipangwe kwa njia ambayo inaiwezesha model kujifunza uhusiano kati ya mfuatano wa maneno na maneno yanayofuata. Mtazamo huu uliopangwa huiwezesha model kufanya generalization na kuzalisha maandishi yenye mshikamano na yanayohusiana na muktadha.

### **Dhana Muhimu katika Data Sampling**

1. **Tokenization:** Kugawanya maandishi kuwa vipande vidogo vinavyoitwa tokens (kwa mfano, maneno, subwords, au herufi).
2. **Sequence Length (max_length):** Idadi ya tokens katika kila input sequence.
3. **Sliding Window:** Mbinu ya kuunda input sequences zinazoingiliana kwa kusogeza window juu ya maandishi yaliyofanyiwa tokenization.
4. **Stride:** Idadi ya tokens ambazo sliding window husogea mbele ili kuunda sequence inayofuata.

### **Mfano wa Hatua kwa Hatua**

Hebu tupitie mfano ili kueleza data sampling.

**Maandishi ya Mfano**
```arduino
"Lorem ipsum dolor sit amet, consectetur adipiscing elit."
```
**Uwekaji wa tokeni**

Tuchukulie kuwa tunatumia **tokenizer ya msingi** inayogawanya maandishi kuwa maneno na alama za uakifishaji:
```vbnet
Tokens: ["Lorem", "ipsum", "dolor", "sit", "amet,", "consectetur", "adipiscing", "elit."]
```
**Parameters**

- **Urefu wa Juu wa Sequence (max_length):** tokens 4
- **Stride ya Sliding Window:** token 1

**Kuunda Input na Target Sequences**

1. **Mbinu ya Sliding Window:**
- **Input Sequences:** Kila input sequence ina tokens `max_length`.
- **Target Sequences:** Kila target sequence ina tokens zinazofuata mara moja input sequence inayolingana.

**Sliding Window yenye Stride ya 1:**

- **Window ya Kwanza (Nafasi 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Target:** \["ipsum", "dolor", "sit", "amet,"]
- **Window ya Pili (Nafasi 2-5):** \["ipsum", "dolor", "sit", "amet,"] → **Target:** \["dolor", "sit", "amet,", "consectetur"]
- **Window ya Tatu (Nafasi 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Target:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Window ya Nne (Nafasi 4-7):** \["sit", "amet,", "consectetur", "adipiscing"] → **Target:** \["amet,", "consectetur", "adipiscing", "elit."]

**Kuelewa Stride**

- **Stride ya 1:** Window husogea mbele kwa token moja kila mara, hivyo kusababisha sequences zinazoingiliana sana. Hii inaweza kusaidia kujifunza vizuri zaidi mahusiano ya kimuktadha, lakini inaweza kuongeza hatari ya overfitting kwa sababu data points zinazofanana hurudiwa.
- **Stride ya 2:** Window husogea mbele kwa tokens mbili kila mara, hivyo kupunguza mwingiliano. Hii hupunguza redundancy na mzigo wa computational, lakini huenda ikakosa baadhi ya nuances za kimuktadha.
- **Stride Sawa na max_length:** Window husogea mbele kwa ukubwa wote wa window, hivyo kusababisha sequences zisizoingiliana. Hii hupunguza redundancy ya data, lakini inaweza kupunguza uwezo wa model kujifunza dependencies kati ya sequences.

**Mfano wenye Stride ya 2:**

Kwa kutumia maandishi yaleyale yenye tokenization na `max_length` ya 4:

- **Window ya Kwanza (Nafasi 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Target:** \["ipsum", "dolor", "sit", "amet,"]
- **Window ya Pili (Nafasi 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Target:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Window ya Tatu (Nafasi 5-8):** \["amet,", "consectetur", "adipiscing", "elit."] → **Target:** \["consectetur", "adipiscing", "elit.", "sed"] _(Tukidhani kuna mwendelezo)_

```python
# Download the text to pre-train the LLM
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

"""
Create a class that receives parameters such as a tokenizer and text
and will prepare the input chunks and the target chunks to prepare
the LLM to learn which next token to generate
"""
import torch
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
def __init__(self, txt, tokenizer, max_length, stride):
self.input_ids = []
self.target_ids = []

# Tokenize the entire text
token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

# Use a sliding window to chunk the book into overlapping sequences of max_length
for i in range(0, len(token_ids) - max_length, stride):
input_chunk = token_ids[i:i + max_length]
target_chunk = token_ids[i + 1: i + max_length + 1]
self.input_ids.append(torch.tensor(input_chunk))
self.target_ids.append(torch.tensor(target_chunk))

def __len__(self):
return len(self.input_ids)

def __getitem__(self, idx):
return self.input_ids[idx], self.target_ids[idx]


"""
Create a data loader which given the text and some params will
prepare the inputs and targets with the previous class and
then create a torch DataLoader with the info
"""

import tiktoken

def create_dataloader_v1(txt, batch_size=4, max_length=256,
stride=128, shuffle=True, drop_last=True,
num_workers=0):

# Initialize the tokenizer
tokenizer = tiktoken.get_encoding("gpt2")

# Create dataset
dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)

# Create dataloader
dataloader = DataLoader(
dataset,
batch_size=batch_size,
shuffle=shuffle,
drop_last=drop_last,
num_workers=num_workers
)

return dataloader


"""
Finally, create the data loader with the params we want:
- The used text for training
- batch_size: The size of each batch
- max_length: The size of each entry on each batch
- stride: The sliding window (how many tokens should the next entry advance compared to the previous one). The smaller the more overfitting, usually this is equals to the max_length so the same tokens aren't repeated.
- shuffle: Re-order randomly
"""
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=4, stride=1, shuffle=False
)

data_iter = iter(dataloader)
first_batch = next(data_iter)
print(first_batch)

# Note the batch_size of 8, the max_length of 4 and the stride of 1
[
```

## Mikakati ya Juu ya Sampling (2023-2025)

### 1. Uzani wa Mchanganyiko unaotegemea Temperature
LLM za kisasa zaidi kwa kawaida hazifunzwi kwenye corpus moja pekee.  Badala yake, hufanya sampling kutoka kwenye vyanzo kadhaa vya data visivyo sawa (code, web, machapisho ya kitaaluma, forums…).  Uwiano wa kila chanzo unaweza kuathiri kwa kiwango kikubwa utendaji wa downstream.  Models za open-source za hivi karibuni kama vile Llama 2 zilianzisha **temperature‐based sampling scheme** ambapo uwezekano wa kuchora document kutoka corpus *i* huwa
```
p(i) = \frac{w_i^{\alpha}}{\sum_j w_j^{\alpha}}
```
• *w<sub>i</sub>*  – asilimia ya token ghafi ya korpasi *i*
• *α* ("temperature") – thamani katika (0,1].  α < 1 husawazisha usambazaji, hivyo kuzipa korpasi ndogo zenye ubora wa juu uzito zaidi.

Kwa `α < 1`, uzani huu husawazisha usambazaji na kuongeza uwezekano wa kadiri wa kusampuli kutoka kwenye korpasi ndogo. Usampulishaji unaotegemea temperature umetumika sana kusawazisha data ya pretraining ya lugha nyingi, ingawa mipaka ya marudio inahitajika ili kuepuka overfitting kwenye vyanzo vidogo.<sup>[[4]](#references)</sup>
```python
from collections import Counter

def temperature_sample(corpus_ids, alpha=0.7):
counts = Counter(corpus_ids)           # number of tokens seen per corpus
probs  = {c: c_count**alpha for c, c_count in counts.items()}
Z = sum(probs.values())
probs = {c: p/Z for c, p in probs.items()}
# Now draw according to probs to fill every batch
```
### 2. Sequence Packing / Dynamic Batching
Kumbukumbu ya GPU hupotea wakati kila sequence kwenye batch inaongezewa padding hadi kufikia mfano mrefu zaidi. **Packing** huunganisha mifano mifupi mingi katika blocks zenye urefu uliowekwa. Utekelezaji wa kawaida wa packed hutumia `attention_mask` inayotambua segments au iliyo katika mfumo wa block-diagonal, ili tokens zisiweze kuhudhuria mifano iliyo nje ya mipaka yao; utekelezaji usio na padding unaweza badala yake ku-flatten batch na kuhifadhi mipaka kwa kutumia taarifa za position. Hugging Face TRL hutoa packing kupitia `SFTConfig(packing=True)` na huandika mikakati inayopatikana.<sup>[[5]](#references)</sup>

Kwa usanidi mahususi wa TRL, `max_length` hufafanua ukubwa wa packed block na `packing_strategy` huchagua best-fit decreasing (`"bfd"`) au wrapped packing. Best-fit decreasing huwezesha batches zisizo na padding; `padding_free=True` ya moja kwa moja inaungwa mkono na FlashAttention 2 au 3. Usichanganye `pad_to_multiple_of` na packing: hii huzungusha tu urefu wa sequences zenye padding hadi kwenye multiple iliyochaguliwa.<sup>[[5]](#references)</sup>

**Dynamic au length-aware batching ni optimization tofauti:** haiunganishi mifano. Badala yake, huweka pamoja mifano yenye urefu unaofanana ili kila batch yenye padding inayoongezwa dynamically iwe na tokens chache za padding. Hugging Face Transformers ya sasa hutoa hii kama `train_sampling_strategy="group_by_length"`; column ya `length` iliyokokotolewa mapema na kuchaguliwa kupitia `length_column_name` huepusha kuhesabu urefu wa kila mfano wakati training inapoanza.<sup>[[8]](#references)</sup>

### 3. Deduplication & Quality Filtering
Passages zinazorudiwa husababisha memorization na hutoa channel rahisi ya data poisoning. Kwa hiyo, pipeline ya cleaning inayoweza kutetewa inachanganya:

1. **Ugunduzi wa duplicates kamili na zinazokaribiana:** hash documents zilizosanifishwa, tumia MinHash/LSH juu ya token n-grams kwa ugunduzi unaoweza kupanuka wa near-duplicates, na tumia mbinu za exact-substring wakati passages ndefu zinazorudiwa zinapaswa kuondolewa.<sup>[[6]](#references)</sup>
2. **Quality filtering:** kata encoding zisizo halali, markup iliyoharibika, marudio yasiyo ya kawaida, na documents za lugha isiyo sahihi. Perplexity ya reference-model inaweza kuwa signal nyingine, lakini threshold yake lazima isanifishwe kwa corpus husika badala ya kuchukuliwa kuwa cutoff ya jumla.<sup>[[2]](#references)</sup>
3. **Sensitive-data filtering:** tafuta credentials na PII kwa kutumia patterns za deterministic pamoja na entity detection, kisha weka matches karantini kwa ajili ya review ili false positives zisifute kimya kimya training data yenye manufaa.<sup>[[7]](#references)</sup>

Karatasi ya Llama 2 inaeleza deduplication na source filtering kama sehemu ya ujenzi wa corpus.<sup>[[2]](#references)</sup> Utafiti huru uligundua kuwa kudeduplicate language-model training data hupunguza memorization ya verbatim na kunaweza kuhitaji training steps chache ili kupata accuracy iliyo sawa au bora.<sup>[[6]](#references)</sup>

## Security & Privacy Considerations During Sampling

### Data-Poisoning / Backdoor Attacks
Watafiti walionyesha kuwa kuingiza sentensi zenye backdoor za chini ya <1 % kunaweza kufanya model itii trigger iliyofichwa ("PoisonGPT", 2023).<sup>[[3]](#references)</sup> Mitigation zinazopendekezwa:

* **Shuffled mixing** – hakikisha mifano ya training iliyo karibu inatoka kwenye sources tofauti; hii hupunguza gradient alignment ya spans hasidi.
* **Gradient similarity scoring** – kokotoa cosine similarity ya gradient ya mfano dhidi ya wastani wa batch; outliers ni wagombea wa kuondolewa.
* **Dataset versioning & hashes** – ganda tarballs zisizobadilika na thibitisha SHA-256 kabla ya kila training run.

### Membership-Inference & Memorization
Overlap ndefu kati ya samples za sliding-window hurudia strings adimu kama namba za simu au secret keys, na hivyo kuongeza frequency yake halisi. Utafiti kuhusu privacy ya training data unaonyesha kuwa sequences zilizoduplicatiwa huzalishwa upya mara nyingi kupita kiasi na kwamba deduplication hupunguza kwa kiasi kikubwa exposure hii.<sup>[[7]](#references)</sup>

Mapendekezo ya vitendo:

* Epuka overlap isiyo ya lazima pale ambapo itafichua tena na tena strings nyeti au za kipekee.
* Deduplika kabla ya kugawa data ili samples zinazofanana sana zisileak kati ya training na evaluation sets.
