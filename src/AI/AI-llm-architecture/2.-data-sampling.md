## **데이터 샘플링**

**데이터 샘플링**은 GPT와 같은 대규모 언어 모델(LLM) 학습을 위한 데이터를 준비하는 데 중요한 과정입니다. 여기에는 모델이 앞에 나온 단어를 기반으로 다음 단어(또는 토큰)를 예측하는 방법을 학습하는 데 사용할 입력 및 대상 시퀀스로 텍스트 데이터를 구성하는 작업이 포함됩니다. 적절한 데이터 샘플링은 모델이 언어 패턴과 종속성을 효과적으로 포착하도록 합니다.

> [!TIP]
> 이 두 번째 단계의 목표는 매우 간단합니다. **입력 데이터를 샘플링하고, 일반적으로 데이터셋을 특정 길이의 문장으로 분리한 다음 예상 응답도 생성하여 학습 단계에 사용할 수 있도록 준비하는 것입니다.**

### **데이터 샘플링이 중요한 이유**

GPT와 같은 LLM은 이전 단어가 제공하는 문맥을 이해하여 텍스트를 생성하거나 예측하도록 학습됩니다. 이를 위해서는 모델이 단어 시퀀스와 그 뒤에 이어지는 단어 간의 관계를 학습할 수 있도록 학습 데이터를 구조화해야 합니다. 이러한 구조화된 접근 방식은 모델이 일관되고 문맥에 적합한 텍스트를 일반화하고 생성할 수 있도록 합니다.

### **데이터 샘플링의 핵심 개념**

1. **토큰화(Tokenization):** 텍스트를 토큰이라고 하는 더 작은 단위(예: 단어, 서브워드 또는 문자)로 나누는 작업입니다.
2. **시퀀스 길이(max_length):** 각 입력 시퀀스에 포함되는 토큰의 수입니다.
3. **슬라이딩 윈도우:** 토큰화된 텍스트 위에서 윈도우를 이동하여 서로 겹치는 입력 시퀀스를 생성하는 방법입니다.
4. **Stride:** 다음 시퀀스를 생성하기 위해 슬라이딩 윈도우가 앞으로 이동하는 토큰의 수입니다.

### **단계별 예시**

데이터 샘플링을 설명하기 위해 예시를 살펴보겠습니다.

**예시 텍스트**
```arduino
"Lorem ipsum dolor sit amet, consectetur adipiscing elit."
```
**토큰화**

텍스트를 단어와 문장 부호로 분할하는 **기본 tokenizer**를 사용한다고 가정해 보겠습니다:
```vbnet
Tokens: ["Lorem", "ipsum", "dolor", "sit", "amet,", "consectetur", "adipiscing", "elit."]
```
**매개변수**

- **최대 시퀀스 길이 (max_length):** 4 tokens
- **Sliding Window Stride:** 1 token

**Input 및 Target 시퀀스 생성**

1. **Sliding Window 방식:**
- **Input 시퀀스:** 각 input 시퀀스는 `max_length`개의 tokens로 구성됩니다.
- **Target 시퀀스:** 각 target 시퀀스는 해당 input 시퀀스 바로 뒤에 오는 tokens로 구성됩니다.
2. **시퀀스 생성:**

3. **생성된 Input 및 Target 배열:**

- **Input:**

```python
[
["Lorem", "ipsum", "dolor", "sit"],
["ipsum", "dolor", "sit", "amet,"],
["dolor", "sit", "amet,", "consectetur"],
["sit", "amet,", "consectetur", "adipiscing"],
]
```

- **Target:**

```python
[
["ipsum", "dolor", "sit", "amet,"],
["dolor", "sit", "amet,", "consectetur"],
["sit", "amet,", "consectetur", "adipiscing"],
["amet,", "consectetur", "adipiscing", "elit."],
]
```

**시각적 표현**

**Stride 1을 사용하는 Sliding Window:**

- **첫 번째 Window (위치 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Target:** \["ipsum", "dolor", "sit", "amet,"]
- **두 번째 Window (위치 2-5):** \["ipsum", "dolor", "sit", "amet,"] → **Target:** \["dolor", "sit", "amet,", "consectetur"]
- **세 번째 Window (위치 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Target:** \["sit", "amet,", "consectetur", "adipiscing"]
- **네 번째 Window (위치 4-7):** \["sit", "amet,", "consectetur", "adipiscing"] → **Target:** \["amet,", "consectetur", "adipiscing", "elit."]

**Stride 이해하기**

- **Stride 1:** Window가 매번 한 token씩 앞으로 이동하므로, 서로 많이 겹치는 시퀀스가 생성됩니다. 이를 통해 contextual relationship을 더 잘 학습할 수 있지만, 유사한 data point가 반복되므로 overfitting 위험이 증가할 수 있습니다.
- **Stride 2:** Window가 매번 두 tokens씩 앞으로 이동하므로, 겹침이 줄어듭니다. 따라서 redundancy와 computational load가 감소하지만, 일부 contextual nuance를 놓칠 수 있습니다.
- **Stride가 max_length와 같음:** Window가 전체 window 크기만큼 앞으로 이동하므로, 겹치지 않는 시퀀스가 생성됩니다. 이를 통해 data redundancy를 최소화할 수 있지만, 시퀀스 간 dependencies를 학습하는 model의 능력이 제한될 수 있습니다.

**Stride 2를 사용하는 예시:**

동일한 tokenized text와 `max_length` 4를 사용합니다.

- **첫 번째 Window (위치 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Target:** \["ipsum", "dolor", "sit", "amet,"]
- **두 번째 Window (위치 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Target:** \["sit", "amet,", "consectetur", "adipiscing"]
- **세 번째 Window (위치 5-8):** \["amet,", "consectetur", "adipiscing", "elit."] → **Target:** \["consectetur", "adipiscing", "elit.", "sed"] _(계속 이어진다고 가정)_

Create a class that receives parameters such as a tokenizer and text
and will prepare the input chunks and the target chunks to prepare
the LLM to learn which next token to generate

import torch
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
def __init__(self, txt, tokenizer, max_length, stride):
self.input_ids = []
self.target_ids = []

# Tokenize the entire text
token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

# Use a sliding window to chunk the book into overlapping sequences of max_length
for i in range(0, len(token_ids) - max_length, stride):
input_chunk = token_ids[i:i + max_length]
target_chunk = token_ids[i + 1: i + max_length + 1]
self.input_ids.append(torch.tensor(input_chunk))
self.target_ids.append(torch.tensor(target_chunk))

def __len__(self):
return len(self.input_ids)

def __getitem__(self, idx):
return self.input_ids[idx], self.target_ids[idx]


"""
Create a data loader which given the text and some params will
prepare the inputs and targets with the previous class and
then create a torch DataLoader with the info
"""

import tiktoken

stride=128, shuffle=True, drop_last=True,
num_workers=0):

dataloader = DataLoader(
dataset,
batch_size=batch_size,
shuffle=shuffle,
drop_last=drop_last,
num_workers=num_workers
)

return dataloader

## 고급 Sampling 전략 (2023-2025)

### 1. Temperature-Based Mixture Weighting
최첨단 LLM은 단일 corpus로 학습되는 경우가 드뭅니다. 대신 여러 이질적인 데이터 소스(code, web, academic papers, forums…)에서 sampling합니다. 각 소스의 상대적 비율은 downstream 성능에 큰 영향을 미칠 수 있습니다. Llama 2와 같은 최근 open-source 모델은 **temperature-based sampling scheme**을 도입했으며, corpus *i*에서 document를 가져올 확률은
```
p(i) = \frac{w_i^{\alpha}}{\sum_j w_j^{\alpha}}
```
• *w<sub>i</sub>*  – 코퍼스 *i*의 원시 토큰 비율  
• *α* ("temperature") – (0,1] 범위의 값. α < 1이면 분포가 평탄해져 규모가 작고 품질이 높은 코퍼스에 더 큰 가중치가 부여됩니다.

`α < 1`인 경우 이 가중치는 분포를 평탄하게 만들어 소규모 코퍼스의 상대적 sampling probability를 높입니다. Temperature-based sampling은 multilingual pretraining data의 균형을 맞추는 데 널리 사용되어 왔지만, 소규모 소스의 overfitting을 방지하려면 repetition limits가 필요합니다.<sup>[[4]](#references)</sup>
```python
from collections import Counter

def temperature_sample(corpus_ids, alpha=0.7):
counts = Counter(corpus_ids)           # number of tokens seen per corpus
probs  = {c: c_count**alpha for c, c_count in counts.items()}
Z = sum(probs.values())
probs = {c: p/Z for c, p in probs.items()}
# Now draw according to probs to fill every batch
```
### 2. Sequence Packing / Dynamic Batching
배치의 모든 sequence를 가장 긴 example에 맞춰 padding하면 GPU memory가 낭비됩니다. **Packing**은 여러 개의 짧은 example을 고정 길이 block으로 그룹화합니다. 일반적인 packed 구현은 segment-aware 또는 block-diagonal `attention_mask`를 사용하여 token이 example 경계를 넘어 서로 attend하지 못하도록 합니다. padding-free 구현에서는 대신 batch를 flatten하고 position information으로 경계를 보존할 수 있습니다. Hugging Face TRL은 `SFTConfig(packing=True)`를 통해 packing을 제공하며, 사용 가능한 strategy를 문서화합니다.<sup>[[5]](#references)</sup>

구체적인 TRL configuration에서 `max_length`는 packed block의 크기를 정의하고, `packing_strategy`는 best-fit decreasing (`"bfd"`) 또는 wrapped packing 중 하나를 선택합니다. Best-fit decreasing은 padding-free batch를 활성화하며, FlashAttention 2 또는 3에서는 명시적인 `padding_free=True`도 지원됩니다. `pad_to_multiple_of`를 packing과 혼동하지 마십시오. 이는 padding된 sequence length를 선택한 multiple로 반올림할 뿐입니다.<sup>[[5]](#references)</sup>

**Dynamic 또는 length-aware batching은 별도의 optimization입니다.** 이는 example을 concatenate하지 않습니다. 대신 길이가 비슷한 example을 그룹화하여 각 dynamically padded batch에 포함되는 padding token 수를 줄입니다. 현재 Hugging Face Transformers에서는 이를 `train_sampling_strategy="group_by_length"`로 사용할 수 있습니다. `length_column_name`을 통해 미리 계산된 `length` column을 지정하면 training 시작 시 모든 example의 길이를 계산하는 작업을 피할 수 있습니다.<sup>[[8]](#references)</sup>

### 3. Deduplication & Quality Filtering
반복되는 passage는 memorization을 유발하고 data poisoning을 위한 쉬운 channel을 제공합니다. 따라서 방어 가능한 cleaning pipeline은 다음을 결합해야 합니다.

1. **Exact 및 near-duplicate detection:** normalized document를 hash하고, 확장 가능한 near-duplicate 검색을 위해 token n-gram에 MinHash/LSH를 사용하며, 긴 반복 passage를 제거해야 할 때는 exact-substring method를 사용합니다.<sup>[[6]](#references)</sup>
2. **Quality filtering:** 잘못된 encoding, 손상된 markup, 병적인 repetition, 잘못된 언어의 document를 거부합니다. Reference-model perplexity도 signal로 사용할 수 있지만, threshold는 universal cutoff로 취급하지 말고 corpus에 맞게 calibration해야 합니다.<sup>[[2]](#references)</sup>
3. **Sensitive-data filtering:** deterministic pattern과 entity detection을 함께 사용하여 credential과 PII를 검색한 다음, false positive가 유용한 training data를 조용히 삭제하지 않도록 match된 항목을 검토를 위해 quarantine합니다.<sup>[[7]](#references)</sup>

Llama 2 paper는 corpus construction의 일부로 deduplication과 source filtering을 설명합니다.<sup>[[2]](#references)</sup> Independent research에 따르면 language-model training data를 deduplicate하면 verbatim memorization이 감소하고, 같거나 더 나은 accuracy를 위해 필요한 training step 수가 줄어들 수 있습니다.<sup>[[6]](#references)</sup>

## Sampling 중 Security & Privacy 고려 사항

### Data-Poisoning / Backdoor Attacks

Corpus discovery, materialization, filtering, sampling을 하나의 supply chain으로 취급하십시오. URL만 포함하는 manifest는 immutable training data가 아닙니다.

* **Split-view poisoning:** 공격자는 curator가 resource를 index할 때는 해당 resource가 정상적으로 보이게 만든 뒤, 이후 training client가 download하는 내용을 변경합니다. 이는 dataset creation과 materialization 사이의 시간 차이를 악용합니다.
* **Frontrunning poisoning:** 공격자는 예측 가능한 snapshot 또는 crawl 직전에 crowd-edited source를 잠시 수정한 다음 이후에 원래대로 복구합니다. 이후 live page가 정상적으로 보이더라도 malicious sample은 snapshot에 남습니다.

두 기법 모두 parser vulnerability가 아니라 **sample이 fetch되는 시점**을 공격합니다. Researchers는 URL expiry/re-registration과 time-bounded edit를 포함하여 여러 web-scale dataset의 trust assumption을 대상으로 이러한 공격을 입증했습니다.<sup>[[9]](#references)</sup>

**Sampling은 소규모 poisoned cluster를 증폭할 수 있습니다.** 관련 metric은 단순히 `poison_documents / raw_documents`가 아니라, source weighting, repetition, chunking, overlapping window를 거친 후 해당 document가 optimization example이 되는 횟수입니다. 대규모 pre-training experiment에서 250개의 poisoned document는 6B~260B개의 clean token으로 training된 600M~13B parameter model 전반에서 comparable한 backdoor effect를 유발했습니다. 따라서 corpus가 커질수록 percentage-only alert threshold는 약해질 수 있습니다.<sup>[[10]](#references)</sup>

Ingestion audit를 위해 **unique-document count**와 **effective exposure count**를 모두 보관하십시오.<sup>[[10]](#references)</sup>
```text
effective_exposure(doc) =
epochs × source_sampling_weight × repetitions × emitted_chunks(doc)
```
이러한 ingestion 및 exposure 실패에서 도출되는 실질적인 제어 방법은 다음과 같습니다:<sup>[[9]](#references)[[10]](#references)</sup>

* 변경 가능한 URL을 다시 가져오는 대신 content-addressed artifact를 동결합니다. 원본 URL, retrieval timestamp, byte length, digest 및 transformation version을 저장하고, digest 불일치 시 fail closed를 적용합니다.
* normalization 전후에 모두 byte를 hash합니다. 첫 번째 digest는 source integrity를 입증하고, 두 번째 digest는 deduplication 및 이후 reproduction을 가능하게 합니다.
* mixture upsampling 및 window generation 전에 deduplicate한 다음, 각 exact/near-duplicate cluster와 origin별 exposure를 제한합니다. Shuffling은 순서만 변경할 뿐 poison을 제거하지는 않습니다.
* 모든 emitted sequence에 안정적인 `document_id`를 기록하여, 의심스러운 model behavior를 packed batch를 거쳐 source document까지 추적할 수 있도록 합니다.
* training 전에 동결된 manifest를 직접 검증합니다. 예를 들어 `sha256sum -c corpus.sha256`를 사용합니다. 누락되거나 변경된 object를 대체하기 위해 조용히 다시 download하지 마십시오.

### Membership-Inference & Memorization
sliding-window sample 간의 긴 overlap은 telephone number나 secret key와 같은 희귀한 string을 반복하여 effective frequency를 높입니다. training-data privacy에 관한 연구에 따르면 duplicated sequence는 불균형적으로 자주 재생성되며, deduplication은 이러한 exposure를 실질적으로 줄입니다.<sup>[[7]](#references)</sup>

실질적인 권장 사항:

* 민감하거나 고유한 string을 반복적으로 exposure할 수 있는 불필요한 overlap을 피합니다.
* data splitting 전에 deduplicate하여 near-identical sample이 training set와 evaluation set 사이에서 leak되지 않도록 합니다.
