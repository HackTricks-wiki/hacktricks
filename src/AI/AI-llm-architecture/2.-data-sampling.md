## **Muestreo de datos**

El **muestreo de datos** es un proceso crucial para preparar datos para entrenar large language models (LLMs) como GPT. Consiste en organizar los datos de texto en secuencias de entrada y objetivo que el modelo utiliza para aprender a predecir la siguiente palabra (o token) basándose en las palabras anteriores. Un muestreo de datos adecuado garantiza que el modelo capture eficazmente los patrones y las dependencias del lenguaje.

> [!TIP]
> El objetivo de esta segunda fase es muy sencillo: **Muestrear los datos de entrada y prepararlos para la fase de entrenamiento, normalmente separando el dataset en oraciones de una longitud específica y generando también la respuesta esperada.**

### **Por qué es importante el muestreo de datos**

Los LLMs, como GPT, se entrenan para generar o predecir texto comprendiendo el contexto proporcionado por las palabras anteriores. Para lograrlo, los datos de entrenamiento deben estructurarse de forma que el modelo pueda aprender la relación entre las secuencias de palabras y las palabras posteriores. Este enfoque estructurado permite al modelo generalizar y generar texto coherente y contextualmente relevante.

### **Conceptos clave del muestreo de datos**

1. **Tokenización:** Dividir el texto en unidades más pequeñas llamadas tokens (por ejemplo, palabras, subpalabras o caracteres).
2. **Longitud de secuencia (max_length):** El número de tokens de cada secuencia de entrada.
3. **Ventana deslizante:** Un método para crear secuencias de entrada superpuestas moviendo una ventana sobre el texto tokenizado.
4. **Stride:** El número de tokens que la ventana deslizante avanza para crear la siguiente secuencia.

### **Ejemplo paso a paso**

Veamos un ejemplo para ilustrar el muestreo de datos.

**Texto de ejemplo**
```arduino
"Lorem ipsum dolor sit amet, consectetur adipiscing elit."
```
**Tokenización**

Supongamos que usamos un **tokenizador básico** que divide el texto en palabras y signos de puntuación:
```vbnet
Tokens: ["Lorem", "ipsum", "dolor", "sit", "amet,", "consectetur", "adipiscing", "elit."]
```
**Parámetros**

- **Longitud máxima de secuencia (max_length):** 4 tokens
- **Paso de la ventana deslizante:** 1 token

**Creación de secuencias de entrada y objetivo**

1. **Enfoque de ventana deslizante:**
- **Secuencias de entrada:** Cada secuencia de entrada consta de `max_length` tokens.
- **Secuencias objetivo:** Cada secuencia objetivo consta de los tokens que siguen inmediatamente a la secuencia de entrada correspondiente.
2. **Generación de secuencias:**

3. **Arrays de entrada y objetivo resultantes:**

- **Entrada:**

```python
[
["Lorem", "ipsum", "dolor", "sit"],
["ipsum", "dolor", "sit", "amet,"],
["dolor", "sit", "amet,", "consectetur"],
["sit", "amet,", "consectetur", "adipiscing"],
]
```

- **Objetivo:**

```python
[
["ipsum", "dolor", "sit", "amet,"],
["dolor", "sit", "amet,", "consectetur"],
["sit", "amet,", "consectetur", "adipiscing"],
["amet,", "consectetur", "adipiscing", "elit."],
]
```

**Representación visual**

**Ventana deslizante con paso 1:**

- **Primera ventana (posiciones 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Objetivo:** \["ipsum", "dolor", "sit", "amet,"]
- **Segunda ventana (posiciones 2-5):** \["ipsum", "dolor", "sit", "amet,"] → **Objetivo:** \["dolor", "sit", "amet,", "consectetur"]
- **Tercera ventana (posiciones 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Objetivo:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Cuarta ventana (posiciones 4-7):** \["sit", "amet,", "consectetur", "adipiscing"] → **Objetivo:** \["amet,", "consectetur", "adipiscing", "elit."]

**Comprender el paso**

- **Paso de 1:** La ventana avanza un token cada vez, lo que da como resultado secuencias con mucha superposición. Esto puede conducir a un mejor aprendizaje de las relaciones contextuales, pero puede aumentar el riesgo de overfitting, ya que se repiten puntos de datos similares.
- **Paso de 2:** La ventana avanza dos tokens cada vez, reduciendo la superposición. Esto disminuye la redundancia y la carga computacional, pero podría omitir algunos matices contextuales.
- **Paso igual a max_length:** La ventana avanza el tamaño completo de la ventana, lo que da como resultado secuencias sin superposición. Esto minimiza la redundancia de datos, pero puede limitar la capacidad del modelo para aprender dependencias entre secuencias.

**Ejemplo con un paso de 2:**

Usando el mismo texto tokenizado y un `max_length` de 4:

- **Primera ventana (posiciones 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Objetivo:** \["ipsum", "dolor", "sit", "amet,"]
- **Segunda ventana (posiciones 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Objetivo:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Tercera ventana (posiciones 5-8):** \["amet,", "consectetur", "adipiscing", "elit."] → **Objetivo:** \["consectetur", "adipiscing", "elit.", "sed"] _(Suponiendo una continuación)_

## Ejemplo de código

Entendamos esto mejor a partir de un ejemplo de código de [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[1]](#references)</sup>
```python
# Download the text to pre-train the LLM
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

"""
Create a class that receives parameters such as a tokenizer and text
and will prepare the input chunks and the target chunks to prepare
the LLM to learn which next token to generate
"""
import torch
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
def __init__(self, txt, tokenizer, max_length, stride):
self.input_ids = []
self.target_ids = []

# Tokenize the entire text
token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

# Use a sliding window to chunk the book into overlapping sequences of max_length
for i in range(0, len(token_ids) - max_length, stride):
input_chunk = token_ids[i:i + max_length]
target_chunk = token_ids[i + 1: i + max_length + 1]
self.input_ids.append(torch.tensor(input_chunk))
self.target_ids.append(torch.tensor(target_chunk))

def __len__(self):
return len(self.input_ids)

def __getitem__(self, idx):
return self.input_ids[idx], self.target_ids[idx]


"""
Create a data loader which given the text and some params will
prepare the inputs and targets with the previous class and
then create a torch DataLoader with the info
"""

import tiktoken

def create_dataloader_v1(txt, batch_size=4, max_length=256,
stride=128, shuffle=True, drop_last=True,
num_workers=0):

# Initialize the tokenizer
tokenizer = tiktoken.get_encoding("gpt2")

# Create dataset
dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)

# Create dataloader
dataloader = DataLoader(
dataset,
batch_size=batch_size,
shuffle=shuffle,
drop_last=drop_last,
num_workers=num_workers
)

return dataloader


"""
Finally, create the data loader with the params we want:
- The used text for training
- batch_size: The size of each batch
- max_length: The size of each entry on each batch
- stride: The sliding window (how many tokens should the next entry advance compared to the previous one). The smaller the more overfitting, usually this is equals to the max_length so the same tokens aren't repeated.
- shuffle: Re-order randomly
"""
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=4, stride=1, shuffle=False
)

data_iter = iter(dataloader)
first_batch = next(data_iter)
print(first_batch)

# Note the batch_size of 8, the max_length of 4 and the stride of 1
[

tensor([[  367,  2885,  1464,  1807],
```

## Estrategias avanzadas de muestreo (2023-2025)

### 1. Ponderación de mezcla basada en temperatura
Los LLM de última generación rara vez se entrenan con un único corpus. En su lugar, toman muestras de varias fuentes de datos heterogéneas (código, web, artículos académicos, foros…). La proporción relativa de cada fuente puede afectar significativamente al rendimiento posterior. Modelos open source recientes, como Llama 2, introdujeron un **esquema de muestreo basado en temperatura** en el que la probabilidad de extraer un documento del corpus *i* pasa a ser
```
p(i) = \frac{w_i^{\alpha}}{\sum_j w_j^{\alpha}}
```
• *w<sub>i</sub>*  – porcentaje bruto de tokens del corpus *i*
• *α* ("temperature") – un valor en (0,1]. α < 1 aplana la distribución, dando más peso a los corpus pequeños y de alta calidad.

Con `α < 1`, esta ponderación aplana la distribución y aumenta la probabilidad relativa de muestreo de los corpus más pequeños. El muestreo basado en temperature se ha utilizado ampliamente para equilibrar los datos de preentrenamiento multilingües, aunque se necesitan límites de repetición para evitar el sobreajuste de las fuentes pequeñas.<sup>[[4]](#references)</sup>
```python
from collections import Counter

def temperature_sample(corpus_ids, alpha=0.7):
counts = Counter(corpus_ids)           # number of tokens seen per corpus
probs  = {c: c_count**alpha for c, c_count in counts.items()}
Z = sum(probs.values())
probs = {c: p/Z for c, p in probs.items()}
# Now draw according to probs to fill every batch
```
### 2. Empaquetado de secuencias / Dynamic Batching
La memoria de la GPU se desperdicia cuando cada secuencia de un batch se rellena hasta alcanzar la longitud del ejemplo más largo. El **packing** agrupa varios ejemplos más cortos en bloques de longitud fija. Una implementación convencional de packed utiliza una `attention_mask` consciente de segmentos o en bloques diagonales para impedir que los tokens atiendan a otros ejemplos; las implementaciones sin padding pueden, en su lugar, aplanar el batch y conservar los límites mediante información de posición. Hugging Face TRL expone el packing mediante `SFTConfig(packing=True)` y documenta las estrategias disponibles.<sup>[[5]](#references)</sup>

En una configuración concreta de TRL, `max_length` define el tamaño del bloque packed y `packing_strategy` selecciona best-fit decreasing (`"bfd"`) o wrapped packing. Best-fit decreasing permite batches sin padding; `padding_free=True` explícito es compatible con FlashAttention 2 o 3. No se debe confundir `pad_to_multiple_of` con packing: solo redondea las longitudes de las secuencias con padding al múltiplo seleccionado.<sup>[[5]](#references)</sup>

**El batching dinámico o basado en la longitud es una optimización independiente:** no concatena ejemplos. En su lugar, agrupa ejemplos de longitudes similares para que cada batch con padding dinámico contenga menos tokens de padding. Las versiones actuales de Hugging Face Transformers lo exponen como `train_sampling_strategy="group_by_length"`; una columna `length` precalculada y seleccionada mediante `length_column_name` evita calcular la longitud de cada ejemplo cuando comienza el entrenamiento.<sup>[[8]](#references)</sup>

### 3. Deduplicación y filtrado de calidad
Los pasajes repetidos provocan memorización y proporcionan un canal sencillo para el data poisoning. Por tanto, una pipeline de limpieza defendible combina:

1. **Detección de duplicados exactos y casi duplicados:** aplicar hash a los documentos normalizados, usar MinHash/LSH sobre n-gramas de tokens para descubrir casi duplicados de forma escalable y utilizar métodos de subcadenas exactas cuando sea necesario eliminar pasajes repetidos largos.<sup>[[6]](#references)</sup>
2. **Filtrado de calidad:** rechazar codificaciones no válidas, markup corrupto, repeticiones patológicas y documentos en el idioma incorrecto. La perplexity de un modelo de referencia puede ser otra señal, pero su umbral debe calibrarse para el corpus en lugar de tratarse como un límite universal.<sup>[[2]](#references)</sup>
3. **Filtrado de datos sensibles:** buscar credenciales y PII mediante patrones deterministas junto con detección de entidades, y poner en cuarentena las coincidencias para revisarlas, de modo que los falsos positivos no eliminen silenciosamente datos de entrenamiento útiles.<sup>[[7]](#references)</sup>

El artículo de Llama 2 describe la deduplicación y el filtrado de fuentes como parte de la construcción del corpus.<sup>[[2]](#references)</sup> Investigaciones independientes concluyeron que deduplicar los datos de entrenamiento de modelos de lenguaje reduce la memorización literal y puede requerir menos pasos de entrenamiento para lograr una precisión igual o superior.<sup>[[6]](#references)</sup>

## Consideraciones de seguridad y privacidad durante el muestreo

### Data-Poisoning / Backdoor Attacks

Trata el descubrimiento, la materialización, el filtrado y el muestreo del corpus como una única supply chain. Un manifiesto que solo contiene URLs no constituye datos de entrenamiento inmutables:

* **Split-view poisoning:** un atacante hace que un recurso parezca benigno cuando un curator lo indexa y después cambia lo que descargan los clientes de entrenamiento. Esto explota la brecha temporal entre la creación del dataset y su materialización.
* **Frontrunning poisoning:** un atacante modifica brevemente una fuente editada por la comunidad justo antes de un snapshot o crawl predecible y la restaura después. El sample malicioso persiste en el snapshot aunque la página activa parezca limpia posteriormente.

Ambas técnicas apuntan a **cuándo se obtiene un sample**, no a una vulnerabilidad del parser. Investigadores las demostraron contra las suposiciones de confianza de varios datasets a escala web, incluyendo la caducidad y el registro por terceros de URLs, así como ediciones limitadas en el tiempo.<sup>[[9]](#references)</sup>

**El muestreo puede amplificar un pequeño cluster poisoned.** La métrica relevante no es simplemente `poison_documents / raw_documents`, sino el número de veces que esos documentos se convierten en ejemplos de optimización después del source weighting, la repetición, el chunking y las ventanas superpuestas. En grandes experimentos de pre-training, 250 documentos poisoned produjeron un efecto de backdoor comparable en modelos de entre 600M y 13B parámetros entrenados con entre 6B y 260B tokens limpios; por tanto, un umbral de alerta basado únicamente en porcentajes puede debilitarse a medida que crece el corpus.<sup>[[10]](#references)</sup>

Para una auditoría de ingestion, conserva tanto el **recuento de documentos únicos** como el **recuento de exposición efectiva**.<sup>[[10]](#references)</sup>
```text
effective_exposure(doc) =
epochs × source_sampling_weight × repetitions × emitted_chunks(doc)
```
Los controles prácticos derivados de estos fallos de ingestión y exposición incluyen:<sup>[[9]](#references)[[10]](#references)</sup>

* Congela los artefactos direccionados por contenido en lugar de volver a obtener URLs mutables. Almacena la URL original, la marca de tiempo de obtención, la longitud en bytes, el digest y la versión de transformación; falla de forma cerrada ante una discrepancia del digest.
* Calcula un hash de los bytes tanto antes como después de la normalización. El primer digest demuestra la integridad de la fuente; el segundo permite la deduplicación y la reproducción posterior.
* Deduplica antes del upsampling de la mezcla y de la generación de ventanas; después, limita la exposición por clúster de duplicados exactos o casi duplicados y por origen. Barajar cambia el orden, pero no elimina un poison.
* Registra un `document_id` estable en cada secuencia emitida para que un comportamiento sospechoso del modelo pueda rastrearse desde los batches empaquetados hasta los documentos de origen.
* Antes del entrenamiento, verifica directamente el manifiesto congelado, por ejemplo con `sha256sum -c corpus.sha256`; no descargues silenciosamente un reemplazo para un objeto ausente o modificado.

### Membership-Inference y memorización
La gran superposición entre muestras de ventanas deslizantes repite cadenas poco frecuentes, como números de teléfono o claves secretas, lo que aumenta su frecuencia efectiva. La investigación sobre la privacidad de los datos de entrenamiento demuestra que las secuencias duplicadas se regeneran de forma desproporcionada y que la deduplicación reduce considerablemente esta exposición.<sup>[[7]](#references)</sup>

Recomendaciones prácticas:

* Evita la superposición innecesaria cuando exponga repetidamente cadenas sensibles o únicas.
* Deduplica antes de dividir los datos para que las muestras casi idénticas no hagan leak entre los conjuntos de entrenamiento y evaluación.
