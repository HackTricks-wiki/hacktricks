## **データサンプリング**

**データサンプリング**は、GPTのような大規模言語モデル（LLM）のトレーニング用データを準備するうえで重要なプロセスです。これは、モデルが前の単語（またはトークン）に基づいて次の単語を予測する方法を学習するために使用する入力シーケンスとターゲットシーケンスへ、テキストデータを整理する作業です。適切なデータサンプリングにより、モデルは言語のパターンや依存関係を効果的に捉えられるようになります。

> [!TIP]
> この第2段階の目的は非常にシンプルです。**入力データをサンプリングし、通常はデータセットを特定の長さの文に分割して、期待される応答も生成することで、トレーニングフェーズ用に準備します。**

### **データサンプリングが重要な理由**

GPTなどのLLMは、前の単語によって提供されるコンテキストを理解することで、テキストを生成または予測するようにトレーニングされます。これを実現するには、モデルが単語のシーケンスと、その後に続く単語との関係を学習できるような形で、トレーニングデータを構造化する必要があります。この構造化されたアプローチにより、モデルは一貫性があり、コンテキストに適したテキストを一般化して生成できるようになります。

### **データサンプリングにおける主要な概念**

1. **トークン化:** テキストをトークンと呼ばれる小さな単位（単語、サブワード、文字など）に分割すること。
2. **シーケンス長（max_length）:** 各入力シーケンスに含まれるトークン数。
3. **Sliding Window:** トークン化されたテキスト上でウィンドウを移動させ、重複する入力シーケンスを作成する方法。
4. **Stride:** 次のシーケンスを作成するためにSliding Windowを前方へ移動させるトークン数。

### **ステップごとの例**

データサンプリングを説明するために、例を見ていきましょう。

**サンプルテキスト**
```arduino
"Lorem ipsum dolor sit amet, consectetur adipiscing elit."
```
**Tokenization**

テキストを単語と句読点に分割する**basic tokenizer**を使用すると仮定します：
```vbnet
Tokens: ["Lorem", "ipsum", "dolor", "sit", "amet,", "consectetur", "adipiscing", "elit."]
```
**Parameters**

- **Max Sequence Length (max_length):** 4 tokens
- **Sliding Window Stride:** 1 token

**InputおよびTarget Sequenceの作成**

1. **Sliding Window Approach:**
- **Input Sequences:** 各Input Sequenceは`max_length`個のtokenで構成されます。
- **Target Sequences:** 各Target Sequenceは、対応するInput Sequenceの直後に続くtokenで構成されます。
2. **Sequenceの生成:**

<table><thead><tr><th width="177">Window Position</th><th>Input Sequence</th><th>Target Sequence</th></tr></thead><tbody><tr><td>1</td><td>["Lorem", "ipsum", "dolor", "sit"]</td><td>["ipsum", "dolor", "sit", "amet,"]</td></tr><tr><td>2</td><td>["ipsum", "dolor", "sit", "amet,"]</td><td>["dolor", "sit", "amet,", "consectetur"]</td></tr><tr><td>3</td><td>["dolor", "sit", "amet,", "consectetur"]</td><td>["sit", "amet,", "consectetur", "adipiscing"]</td></tr><tr><td>4</td><td>["sit", "amet,", "consectetur", "adipiscing"]</td><td>["amet,", "consectetur", "adipiscing", "elit."]</td></tr></tbody></table>

3. **結果として得られるInputおよびTarget Array:**

- **Input:**

```python
[
["Lorem", "ipsum", "dolor", "sit"],
["ipsum", "dolor", "sit", "amet,"],
["dolor", "sit", "amet,", "consectetur"],
["sit", "amet,", "consectetur", "adipiscing"],
]
```

- **Target:**

```python
[
["ipsum", "dolor", "sit", "amet,"],
["dolor", "sit", "amet,", "consectetur"],
["sit", "amet,", "consectetur", "adipiscing"],
["amet,", "consectetur", "adipiscing", "elit."],
]
```

**視覚的表現**

<table><thead><tr><th width="222">Token Position</th><th>Token</th></tr></thead><tbody><tr><td>1</td><td>Lorem</td></tr><tr><td>2</td><td>ipsum</td></tr><tr><td>3</td><td>dolor</td></tr><tr><td>4</td><td>sit</td></tr><tr><td>5</td><td>amet,</td></tr><tr><td>6</td><td>consectetur</td></tr><tr><td>7</td><td>adipiscing</td></tr><tr><td>8</td><td>elit.</td></tr></tbody></table>

**Stride 1のSliding Window:**

- **First Window (Positions 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Target:** \["ipsum", "dolor", "sit", "amet,"]
- **Second Window (Positions 2-5):** \["ipsum", "dolor", "sit", "amet,"] → **Target:** \["dolor", "sit", "amet,", "consectetur"]
- **Third Window (Positions 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Target:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Fourth Window (Positions 4-7):** \["sit", "amet,", "consectetur", "adipiscing"] → **Target:** \["amet,", "consectetur", "adipiscing", "elit."]

**Strideの理解**

- **Stride of 1:** Windowは毎回1 token分前に進むため、大きく重複するSequenceが生成されます。これによりcontext上の関係をより適切に学習できますが、類似したデータポイントが繰り返されるため、overfittingのリスクが高まる可能性があります。
- **Stride of 2:** Windowは毎回2 token分前に進むため、重複が減少します。これにより冗長性と計算負荷が低下しますが、一部のcontext上の細かなニュアンスを見落とす可能性があります。
- **Stride Equal to max_length:** WindowはWindow全体のサイズ分前に進むため、重複しないSequenceが生成されます。これによりデータの冗長性は最小限になりますが、Sequence間の依存関係を学習するモデルの能力が制限される可能性があります。

**Stride of 2の例:**

同じtokenized textと`max_length` 4を使用します。

- **First Window (Positions 1-4):** \["Lorem", "ipsum", "dolor", "sit"] → **Target:** \["ipsum", "dolor", "sit", "amet,"]
- **Second Window (Positions 3-6):** \["dolor", "sit", "amet,", "consectetur"] → **Target:** \["sit", "amet,", "consectetur", "adipiscing"]
- **Third Window (Positions 5-8):** \["amet,", "consectetur", "adipiscing", "elit."] → **Target:** \["consectetur", "adipiscing", "elit.", "sed"] _(続きがあると仮定)_

## Code Example

次の[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb)のCode Exampleを使って、これをさらに理解しましょう。<sup>[[1]](#references)</sup>
```python
# Download the text to pre-train the LLM
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

"""
Create a class that receives parameters such as a tokenizer and text
and will prepare the input chunks and the target chunks to prepare
the LLM to learn which next token to generate
"""
import torch
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
def __init__(self, txt, tokenizer, max_length, stride):
self.input_ids = []
self.target_ids = []

# Tokenize the entire text
token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})

# Use a sliding window to chunk the book into overlapping sequences of max_length
for i in range(0, len(token_ids) - max_length, stride):
input_chunk = token_ids[i:i + max_length]
target_chunk = token_ids[i + 1: i + max_length + 1]
self.input_ids.append(torch.tensor(input_chunk))
self.target_ids.append(torch.tensor(target_chunk))

def __len__(self):
return len(self.input_ids)

def __getitem__(self, idx):
return self.input_ids[idx], self.target_ids[idx]


"""
Create a data loader which given the text and some params will
prepare the inputs and targets with the previous class and
then create a torch DataLoader with the info
"""

import tiktoken

def create_dataloader_v1(txt, batch_size=4, max_length=256,
stride=128, shuffle=True, drop_last=True,
num_workers=0):

# Initialize the tokenizer
tokenizer = tiktoken.get_encoding("gpt2")

# Create dataset
dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)

# Create dataloader
dataloader = DataLoader(
dataset,
batch_size=batch_size,
shuffle=shuffle,
drop_last=drop_last,
num_workers=num_workers
)

return dataloader


"""
Finally, create the data loader with the params we want:
- The used text for training
- batch_size: The size of each batch
- max_length: The size of each entry on each batch
- stride: The sliding window (how many tokens should the next entry advance compared to the previous one). The smaller the more overfitting, usually this is equals to the max_length so the same tokens aren't repeated.
- shuffle: Re-order randomly
"""
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=4, stride=1, shuffle=False
)

data_iter = iter(dataloader)
first_batch = next(data_iter)
print(first_batch)

# Note the batch_size of 8, the max_length of 4 and the stride of 1
[
# Input

[  367,  2885,  1464,  1807],
```

## Advanced Sampling Strategies (2023-2025)

### 1. Temperature-Based Mixture Weighting
最新のLLMは、単一のcorpusで学習されることはほとんどありません。 その代わりに、複数の異種データソース（code、web、academic papers、forums…）からサンプリングします。 各ソースの相対的な割合は、下流タスクの性能に大きな影響を与える可能性があります。 Llama 2などの近年のopen-source modelでは、**temperature-based sampling scheme**が導入され、corpus *i*からdocumentを抽出する確率が次のようになります
```
p(i) = \frac{w_i^{\alpha}}{\sum_j w_j^{\alpha}}
```
• *w<sub>i</sub>*  – コーパス *i* の生トークン比率
• *α*（「temperature」）– (0,1] の値。 α < 1 にすると分布が平坦化され、小規模で高品質なコーパスにより大きな重みが与えられます。

`α < 1` にすると、この重み付けによって分布が平坦化され、小規模なコーパスの相対的なサンプリング確率が高まります。Temperature-based sampling は、多言語の事前学習データのバランス調整に広く使用されていますが、小規模なソースの過学習を避けるには反復回数の制限が必要です。<sup>[[4]](#references)</sup>
```python
from collections import Counter

def temperature_sample(corpus_ids, alpha=0.7):
counts = Counter(corpus_ids)           # number of tokens seen per corpus
probs  = {c: c_count**alpha for c, c_count in counts.items()}
Z = sum(probs.values())
probs = {c: p/Z for c, p in probs.items()}
# Now draw according to probs to fill every batch
```
### 2. Sequence Packing / Dynamic Batching
バッチ内のすべての sequence を最長の example に合わせて padding すると、GPU memory が無駄になります。**Packing** は、複数の短い example を固定長の block にまとめます。従来の packed 実装では、segment-aware または block-diagonal な `attention_mask` を使用し、token が example の境界を越えて attend できないようにします。一方、padding-free 実装では、バッチを flatten し、position 情報によって境界を維持できます。Hugging Face TRL は `SFTConfig(packing=True)` による packing を提供し、利用可能な strategy をドキュメント化しています。<sup>[[5]](#references)</sup>

具体的な TRL configuration では、`max_length` が packed block の size を定義し、`packing_strategy` が best-fit decreasing (`"bfd"`) または wrapped packing のいずれかを選択します。Best-fit decreasing は padding-free batch を有効にします。明示的な `padding_free=True` は FlashAttention 2 または 3 でサポートされています。`pad_to_multiple_of` と packing を混同しないでください。これは padded sequence length を指定した multiple に丸めるだけです。<sup>[[5]](#references)</sup>

**Dynamic または length-aware batching は別の optimization です:** example を連結することはありません。代わりに、似た length の example をまとめ、各 dynamically padded batch に含まれる padding token を少なくします。現在の Hugging Face Transformers では、これを `train_sampling_strategy="group_by_length"` として利用できます。`length_column_name` で選択した事前計算済みの `length` column を使うと、training 開始時に各 example の length を計算する必要がなくなります。<sup>[[8]](#references)</sup>

### 3. Deduplication & Quality Filtering
重複した passage は memorization を引き起こし、data poisoning の容易な channel になります。そのため、妥当性を説明できる cleaning pipeline では、次の要素を組み合わせます。

1. **Exact および near-duplicate detection:** 正規化した document を hash し、token n-gram に対して MinHash/LSH を使用して scalable な near-duplicate discovery を行い、長い重複 passage を削除する必要がある場合は exact-substring method を使用します。<sup>[[6]](#references)</sup>
2. **Quality filtering:** 無効な encoding、壊れた markup、病的な repetition、誤った language の document を reject します。Reference-model perplexity も別の signal になり得ますが、その threshold は universal な cutoff として扱うのではなく、corpus に合わせて calibrate する必要があります。<sup>[[2]](#references)</sup>
3. **Sensitive-data filtering:** deterministic pattern と entity detection を併用して credential と PII を scan し、false positive によって有用な training data が気付かないうちに消去されないよう、match を review 用に quarantine します。<sup>[[7]](#references)</sup>

Llama 2 paper では、corpus construction の一部として deduplication と source filtering が説明されています。<sup>[[2]](#references)</sup> 独立した research では、language-model training data の deduplication により verbatim memorization が減少し、同等以上の accuracy に必要な training step 数も少なくできることが示されています。<sup>[[6]](#references)</sup>

## Security & Privacy Considerations During Sampling

### Data-Poisoning / Backdoor Attacks
Researchers は、<1 % の backdoored sentence を挿入することで、model に hidden trigger（"PoisonGPT", 2023）へ従わせられることを示しました。<sup>[[3]](#references)</sup> 推奨される mitigation:

* **Shuffled mixing** – 隣接する training example が異なる source に由来するようにします。これにより、悪意のある span の gradient alignment が希釈されます。
* **Gradient similarity scoring** – example の gradient と batch average の cosine similarity を計算します。outlier は removal の候補です。
* **Dataset versioning & hashes** – immutable な tarball を freeze し、各 training run の前に SHA-256 を verify します。

### Membership-Inference & Memorization
sliding-window sample 間の長い overlap は、telephone number や secret key などの rare string を繰り返し、実質的な frequency を増加させます。training-data privacy に関する research では、duplicated sequence が不均衡に何度も regenerate され、deduplication によってこの exposure が大幅に減少することが示されています。<sup>[[7]](#references)</sup>

実践的な推奨事項:

* sensitive または unique な string を繰り返し expose することになる場合は、不要な overlap を避けます。
* data を split する前に deduplicate し、ほぼ同一の sample が training set と evaluation set の間で leak しないようにします。
