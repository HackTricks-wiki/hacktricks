## Neural NetworkにおけるAttention MechanismsとSelf-Attention

Attention mechanismsにより、ニューラルネットワークは**出力の各部分を生成する際に、入力の特定の部分に f**ocus できる**ようになります。入力ごとに異なる重みを割り当てることで、現在のタスクに最も関連性の高い入力をモデルが判断できるようにします。これは、正確な翻訳のために文全体のコンテキストを理解する必要があるmachine translationなどのタスクで重要です。<sup>[[1]](#references)</sup>

> [!TIP]
> この第4フェーズの目的は非常にシンプルです。**いくつかのattention mechanismsを適用する**ことです。これらは多数の**繰り返しレイヤー**で構成され、**LLMのtrainに使用されている現在の文において、語彙内の単語とその近傍の単語との関係を捉える**ようになります。\
> このために多数のレイヤーが使用され、多数のtrainable parametersがこの情報を捉えることになります。

### Attention Mechanismsを理解する

言語翻訳に使用される従来のsequence-to-sequenceモデルでは、モデルは入力シーケンスを固定サイズのcontext vectorにエンコードします。しかし、このアプローチは長い文に対して問題が生じます。固定サイズのcontext vectorでは、必要な情報をすべて捉えられない可能性があるためです。Attention mechanismsは、各出力トークンを生成する際に、モデルがすべての入力トークンを考慮できるようにすることで、この制限に対処します。

#### Example: Machine Translation

ドイツ語の文「Kannst du mir helfen diesen Satz zu übersetzen」を英語に翻訳する場合を考えてみましょう。言語間の文法構造の違いにより、単語ごとに翻訳するだけでは文法的に正しい英語の文になりません。Attention mechanismにより、モデルは出力文の各単語を生成する際に、入力文の関連性の高い部分に注目できます。その結果、より正確で一貫性のある翻訳が可能になります。

### Self-Attentionの概要

Self-attention、またはintra-attentionは、単一のシーケンス内でattentionを適用し、そのシーケンスの表現を計算するmechanismです。シーケンス内の各トークンが他のすべてのトークンにattentionできるため、シーケンス内の距離に関係なく、トークン間の依存関係をモデルが捉えられるようになります。

#### Key Concepts

- **Tokens**: 入力シーケンスの個々の要素（例: 文中の単語）。
- **Embeddings**: トークンのベクトル表現で、意味情報を捉えます。
- **Attention Weights**: 各トークンが他のトークンと比較してどの程度重要かを決定する値。

### Processの概要

1. **Attention Scoresを計算**: 対象単語のembeddingと、シーケンス内のすべての単語のembeddingとのdot productを使用します。
2. **Scoresを正規化してAttention Weightsを取得**: attention scoresにsoftmax functionを適用し、合計が1になるweightsを取得します。
3. **Context Vectorを計算**: 各単語のembeddingにそのattention weightを掛け、結果を合計します。

## Trainable Weightsを使用したSelf-Attention

実際には、self-attention mechanismsは**trainable weights**を使用して、query、key、valueに最適な表現を学習します。これには3つのweight matricesの導入が含まれます。<sup>[[1]](#references)</sup>

<figure><img src="../../images/image (10) (1) (1).png" alt="" width="239"><figcaption></figcaption></figure>

queryは先ほどと同様に使用するデータですが、keysとvaluesのmatricesは単なるrandom-trainable matricesです。

#### Step 1: Queries、Keys、Valuesの計算

各トークンは、定義されたmatricesによって各次元の値を乗算することで、それぞれ独自のquery、key、value matrixを持ちます。

<figure><img src="../../images/image (11).png" alt="" width="253"><figcaption></figcaption></figure>

これらのmatricesは、元のembeddingsをattentionの計算に適した新しい空間へ変換します。

**Example**

以下を前提とします。

- Input dimension `din=3`（embedding size）
- Output dimension `dout=2`（queries、keys、valuesに必要なdimension）

weight matricesを初期化します。
```python
import torch.nn as nn

d_in = 3
d_out = 2

W_query = nn.Parameter(torch.rand(d_in, d_out))
W_key = nn.Parameter(torch.rand(d_in, d_out))
W_value = nn.Parameter(torch.rand(d_in, d_out))
```
クエリ、キー、バリューの計算:
```python
queries = torch.matmul(inputs, W_query)
keys = torch.matmul(inputs, W_key)
values = torch.matmul(inputs, W_value)
```
#### Step 2: Scaled Dot-Product Attentionを計算する

**Attention Scoresを計算する**

先ほどの例と同様ですが、今回はトークンの次元の値を使用する代わりに、トークンのkey matrix（すでに次元を使用して計算済み）を使用します。したがって、各query `qi`​ とkey `kj​` について、次のようになります。

<figure><img src="../../images/image (12).png" alt=""><figcaption></figcaption></figure>

**Scoresをスケーリングする**

dot productが大きくなりすぎるのを防ぐため、key dimension `dk`​ の平方根でスケーリングします。

<figure><img src="../../images/image (13).png" alt="" width="295"><figcaption></figcaption></figure>

> [!TIP]
> dot productは非常に大きくなる可能性があるため、スコアを次元数の平方根で割ることで、値を適切な範囲に調整できます。

**Softmaxを適用してAttention Weightsを取得する:** 最初の例と同様に、すべての値の合計が1になるように正規化します。

<figure><img src="../../images/image (14).png" alt="" width="295"><figcaption></figcaption></figure>

#### Step 3: Context Vectorsを計算する

最初の例と同様に、すべてのvalue matricesにそれぞれのattention weightを掛けて合計します。

<figure><img src="../../images/image (15).png" alt="" width="328"><figcaption></figcaption></figure>

### Code Example

[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb) の例を使うと、ここで説明したself-attendant functionalityを実装する次のclassを確認できます。<sup>[[2]](#references)</sup>
```python
import torch

inputs = torch.tensor(
[[0.43, 0.15, 0.89], # Your     (x^1)
[0.55, 0.87, 0.66], # journey  (x^2)
[0.57, 0.85, 0.64], # starts   (x^3)
[0.22, 0.58, 0.33], # with     (x^4)
[0.77, 0.25, 0.10], # one      (x^5)
[0.05, 0.80, 0.55]] # step     (x^6)
)

import torch.nn as nn
class SelfAttention_v2(nn.Module):

def __init__(self, d_in, d_out, qkv_bias=False):
super().__init__()
self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)

def forward(self, x):
keys = self.W_key(x)
queries = self.W_query(x)
values = self.W_value(x)

attn_scores = queries @ keys.T
attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)

context_vec = attn_weights @ values
return context_vec

d_in=3
d_out=2
torch.manual_seed(789)
sa_v2 = SelfAttention_v2(d_in, d_out)
print(sa_v2(inputs))
```
> [!TIP]
> 行列をランダムな値で初期化する代わりに、`nn.Linear` を使用して、すべての重みを学習対象のパラメータとしてマークしている点に注意してください。

## Causal Attention: 未来の単語を隠す

LLM では、モデルが **次の token を予測**するために、現在の位置より前に現れる token だけを考慮するようにします。**Causal attention** は **masked attention** とも呼ばれ、attention mechanism を変更して未来の token へのアクセスを防ぐことで、これを実現します。<sup>[[1]](#references)</sup>

### Causal Attention Mask の適用

causal attention を実装するには、**softmax operation の前**に attention scores に mask を適用し、残りの値の合計が 1 になるようにします。この mask は未来の token の attention scores を負の無限大に設定し、softmax の後にそれらの attention weights が 0 になるようにします。

**手順**

1. **Attention Scores の計算**: これまでと同じです。
2. **Mask の適用**: 対角線より上を負の無限大で埋めた上三角行列を使用します。

```python
mask = torch.triu(torch.ones(seq_len, seq_len), diagonal=1) * float('-inf')
masked_scores = attention_scores + mask
```

3. **Softmax の適用**: masked scores を使用して attention weights を計算します。

```python
attention_weights = torch.softmax(masked_scores, dim=-1)
```

### Dropout による追加の Attention Weights の Masking

**過学習を防ぐ**ために、softmax operation の後の attention weights に **dropout** を適用できます。Dropout は、training 中に **一部の attention weights をランダムに 0 にします**。
```python
dropout = nn.Dropout(p=0.5)
attention_weights = dropout(attention_weights)
```
通常のdropout率は約10〜20%です。

### コード例

[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb)のコード例：<sup>[[2]](#references)</sup>
```python
import torch
import torch.nn as nn

inputs = torch.tensor(
[[0.43, 0.15, 0.89], # Your     (x^1)
[0.55, 0.87, 0.66], # journey  (x^2)
[0.57, 0.85, 0.64], # starts   (x^3)
[0.22, 0.58, 0.33], # with     (x^4)
[0.77, 0.25, 0.10], # one      (x^5)
[0.05, 0.80, 0.55]] # step     (x^6)
)

batch = torch.stack((inputs, inputs), dim=0)
print(batch.shape)

class CausalAttention(nn.Module):

def __init__(self, d_in, d_out, context_length,
dropout, qkv_bias=False):
super().__init__()
self.d_out = d_out
self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.dropout = nn.Dropout(dropout)
self.register_buffer('mask', torch.triu(torch.ones(context_length, context_length), diagonal=1)) # New

def forward(self, x):
b, num_tokens, d_in = x.shape
# b is the num of batches
# num_tokens is the number of tokens per batch
# d_in is the dimensions er token

keys = self.W_key(x) # This generates the keys of the tokens
queries = self.W_query(x)
values = self.W_value(x)

attn_scores = queries @ keys.transpose(1, 2) # Moves the third dimension to the second one and the second one to the third one to be able to multiply
attn_scores.masked_fill_(  # New, _ ops are in-place
self.mask.bool()[:num_tokens, :num_tokens], -torch.inf)  # `:num_tokens` to account for cases where the number of tokens in the batch is smaller than the supported context_size
attn_weights = torch.softmax(
attn_scores / keys.shape[-1]**0.5, dim=-1
)
attn_weights = self.dropout(attn_weights)

context_vec = attn_weights @ values
return context_vec

torch.manual_seed(123)

context_length = batch.shape[1]
d_in = 3
d_out = 2
ca = CausalAttention(d_in, d_out, context_length, 0.0)

context_vecs = ca(batch)

print(context_vecs)
print("context_vecs.shape:", context_vecs.shape)
```
## Single-Head Attention から Multi-Head Attention への拡張

**Multi-head attention** は実用上、**self-attention** 関数の複数のインスタンスを実行することで構成され、それぞれが**独自の重み**を持つため、異なる最終ベクトルが計算されます。<sup>[[1]](#references)</sup>

### コード例

以前のコードを再利用し、それを複数回起動するラッパーを追加することもできます。しかし、これは [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb) の、すべての head を同時に処理する、より最適化されたバージョンです（負荷の高い for ループの数を削減します）。コードから分かるように、各 token の次元は head の数に応じて異なる次元に分割されます。たとえば、token が 8 次元で、3 つの head を使用したい場合、次元は 4 次元の配列 2 つに分割され、各 head はそのうちの 1 つを使用します。<sup>[[2]](#references)</sup>
```python
class MultiHeadAttention(nn.Module):
def __init__(self, d_in, d_out, context_length, dropout, num_heads, qkv_bias=False):
super().__init__()
assert (d_out % num_heads == 0), \
"d_out must be divisible by num_heads"

self.d_out = d_out
self.num_heads = num_heads
self.head_dim = d_out // num_heads # Reduce the projection dim to match desired output dim

self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.out_proj = nn.Linear(d_out, d_out)  # Linear layer to combine head outputs
self.dropout = nn.Dropout(dropout)
self.register_buffer(
"mask",
torch.triu(torch.ones(context_length, context_length),
diagonal=1)
)

def forward(self, x):
b, num_tokens, d_in = x.shape
# b is the num of batches
# num_tokens is the number of tokens per batch
# d_in is the dimensions er token

keys = self.W_key(x) # Shape: (b, num_tokens, d_out)
queries = self.W_query(x)
values = self.W_value(x)

# We implicitly split the matrix by adding a `num_heads` dimension
# Unroll last dim: (b, num_tokens, d_out) -> (b, num_tokens, num_heads, head_dim)
keys = keys.view(b, num_tokens, self.num_heads, self.head_dim)
values = values.view(b, num_tokens, self.num_heads, self.head_dim)
queries = queries.view(b, num_tokens, self.num_heads, self.head_dim)

# Transpose: (b, num_tokens, num_heads, head_dim) -> (b, num_heads, num_tokens, head_dim)
keys = keys.transpose(1, 2)
queries = queries.transpose(1, 2)
values = values.transpose(1, 2)

# Compute scaled dot-product attention (aka self-attention) with a causal mask
attn_scores = queries @ keys.transpose(2, 3)  # Dot product for each head

# Original mask truncated to the number of tokens and converted to boolean
mask_bool = self.mask.bool()[:num_tokens, :num_tokens]

# Use the mask to fill attention scores
attn_scores.masked_fill_(mask_bool, -torch.inf)

attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)
attn_weights = self.dropout(attn_weights)

# Shape: (b, num_tokens, num_heads, head_dim)
context_vec = (attn_weights @ values).transpose(1, 2)

# Combine heads, where self.d_out = self.num_heads * self.head_dim
context_vec = context_vec.contiguous().view(b, num_tokens, self.d_out)
context_vec = self.out_proj(context_vec) # optional projection

return context_vec

torch.manual_seed(123)

batch_size, context_length, d_in = batch.shape
d_out = 2
mha = MultiHeadAttention(d_in, d_out, context_length, 0.0, num_heads=2)

context_vecs = mha(batch)

print(context_vecs)
print("context_vecs.shape:", context_vecs.shape)

```
別のコンパクトで効率的な実装には、PyTorch の [`torch.nn.MultiheadAttention`](https://pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html) クラスを使用できます。

> [!TIP]
> トークンの各次元をすべての head に割り当てるのではなく、トークンの次元を head 間で分割する方が優れている理由についての ChatGPT の短い回答:
>
> 各 head がすべての embedding 次元を処理できれば、各 head が完全な情報にアクセスできるため有利に思えるかもしれません。しかし、標準的な手法では **embedding 次元を head 間で分割します**。この方法は、計算効率とモデル性能のバランスを取り、各 head が多様な表現を学習することを促します。そのため、各 head がすべての次元を確認するよりも、embedding 次元を分割する方が一般的に好まれます。
