## Neural Network의 Attention 메커니즘과 Self-Attention

Attention 메커니즘은 neural network가 **출력의 각 부분을 생성할 때 입력의 특정 부분에 집중**할 수 있도록 합니다. 서로 다른 입력에 서로 다른 가중치를 할당하여, 모델이 현재 작업에 가장 관련성 높은 입력을 결정하도록 돕습니다. 이는 정확한 번역을 위해 전체 문장의 맥락을 이해해야 하는 machine translation과 같은 작업에서 매우 중요합니다.<sup>[[1]](#references)</sup>

> [!TIP]
> 이 네 번째 단계의 목표는 매우 간단합니다: **일부 attention 메커니즘을 적용하는 것**입니다. 이러한 메커니즘은 **현재 LLM을 학습시키는 데 사용되는 문장에서 vocabulary의 단어와 그 이웃 단어 간의 관계를 포착하는** 많은 **반복 레이어**로 구성됩니다.\
> 이를 위해 많은 레이어가 사용되므로, 많은 trainable parameter가 이 정보를 포착하게 됩니다.

### Attention 메커니즘 이해하기

언어 번역에 사용되는 전통적인 sequence-to-sequence 모델에서는 모델이 입력 sequence를 고정된 크기의 context vector로 인코딩합니다. 그러나 고정된 크기의 context vector가 필요한 모든 정보를 포착하지 못할 수 있기 때문에 긴 문장에서는 이 접근 방식이 어려움을 겪습니다. Attention 메커니즘은 모델이 각 출력 token을 생성할 때 모든 입력 token을 고려할 수 있도록 하여 이러한 한계를 해결합니다.

#### 예시: Machine Translation

독일어 문장 "Kannst du mir helfen diesen Satz zu übersetzen"을 영어로 번역한다고 가정해 보겠습니다. 언어마다 문법 구조가 다르기 때문에 단어별 번역으로는 문법적으로 올바른 영어 문장을 만들 수 없습니다. Attention 메커니즘을 사용하면 모델이 출력 문장의 각 단어를 생성할 때 입력 문장의 관련 부분에 집중할 수 있으므로, 더 정확하고 일관성 있는 번역을 얻을 수 있습니다.

### Self-Attention 소개

Self-attention 또는 intra-attention은 하나의 sequence 내부에 attention을 적용하여 해당 sequence의 representation을 계산하는 메커니즘입니다. 이를 통해 sequence의 각 token이 다른 모든 token에 attention을 적용할 수 있으며, sequence에서의 거리에 관계없이 token 간 dependency를 모델이 포착할 수 있도록 합니다.

#### 핵심 개념

- **Tokens**: 입력 sequence의 개별 요소(예: 문장의 단어).
- **Embeddings**: token의 vector representation으로, semantic information을 포착합니다.
- **Attention Weights**: 각 token이 다른 token에 비해 얼마나 중요한지를 결정하는 값입니다.

## Trainable Weights를 사용한 Self-Attention

실제로 self-attention 메커니즘은 **trainable weights**를 사용하여 query, key, value에 대한 최적의 representation을 학습합니다. 여기에는 세 개의 weight matrix가 도입됩니다:<sup>[[1]](#references)</sup>

#### Step 1: Queries, Keys, Values 계산

각 token은 dimension 값을 정의된 matrix와 곱하여 고유한 query, key, value matrix를 갖게 됩니다.

**예시**

다음과 같다고 가정합니다.

- 입력 dimension `din=3` (embedding size)
- 출력 dimension `dout=2` (query, key, value에 사용할 원하는 dimension)

Weight matrix 초기화:

import torch.nn as nn

d_in = 3

### Code Example

[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb)의 예시를 사용하면, 앞에서 설명한 self-attention 기능을 구현하는 이 class를 확인할 수 있습니다:<sup>[[2]](#references)</sup>
```python
import torch

inputs = torch.tensor(
[[0.43, 0.15, 0.89], # Your     (x^1)
[0.55, 0.87, 0.66], # journey  (x^2)
[0.57, 0.85, 0.64], # starts   (x^3)
[0.22, 0.58, 0.33], # with     (x^4)
[0.77, 0.25, 0.10], # one      (x^5)
[0.05, 0.80, 0.55]] # step     (x^6)
)

import torch.nn as nn
class SelfAttention_v2(nn.Module):

def __init__(self, d_in, d_out, qkv_bias=False):
super().__init__()
self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)

def forward(self, x):
keys = self.W_key(x)
queries = self.W_query(x)
values = self.W_value(x)

attn_scores = queries @ keys.T
attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)

context_vec = attn_weights @ values
return context_vec

d_in=3
d_out=2
torch.manual_seed(789)
sa_v2 = SelfAttention_v2(d_in, d_out)
print(sa_v2(inputs))
```

> 행렬을 random 값으로 초기화하는 대신 `nn.Linear`를 사용하여 모든 weight를 학습할 parameter로 표시한다는 점에 유의하세요.

## Causal Attention: 미래 단어 숨기기

LLM에서는 **다음 token을 예측**하기 위해 모델이 현재 위치보다 앞에 나타나는 token만 고려하도록 해야 합니다. **Causal attention**은 **masked attention**이라고도 하며, 미래 token에 접근하지 못하도록 attention mechanism을 수정하여 이를 구현합니다.<sup>[[1]](#references)</sup>

### Causal Attention Mask 적용

Causal attention을 구현하려면 **softmax 연산 전에** attention scores에 mask를 적용하여 나머지 값들의 합이 계속 1이 되도록 합니다. 이 mask는 미래 token의 attention scores를 negative infinity로 설정하여 softmax 이후 해당 attention weights가 0이 되도록 합니다.

**단계**

1. **Attention Scores 계산**: 이전과 동일합니다.
2. **Mask 적용**: 대각선 위가 negative infinity로 채워진 upper triangular matrix를 사용합니다.

```python
mask = torch.triu(torch.ones(seq_len, seq_len), diagonal=1) * float('-inf')
masked_scores = attention_scores + mask
```

3. **Softmax 적용**: masked scores를 사용하여 attention weights를 계산합니다.

```python
attention_weights = torch.softmax(masked_scores, dim=-1)
```

### Dropout을 사용하여 추가 Attention Weights Masking

**overfitting을 방지**하기 위해 softmax 연산 후 attention weights에 **dropout**을 적용할 수 있습니다. Dropout은 training 중 **일부 attention weights를 무작위로 0으로 설정**합니다.
```python
dropout = nn.Dropout(p=0.5)
attention_weights = dropout(attention_weights)
```
일반적인 dropout은 약 10~20%입니다.

### 코드 예시

[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb)의 코드 예시:<sup>[[2]](#references)</sup>
```python
import torch
import torch.nn as nn

inputs = torch.tensor(
[[0.43, 0.15, 0.89], # Your     (x^1)
[0.55, 0.87, 0.66], # journey  (x^2)
[0.57, 0.85, 0.64], # starts   (x^3)
[0.22, 0.58, 0.33], # with     (x^4)
[0.77, 0.25, 0.10], # one      (x^5)
[0.05, 0.80, 0.55]] # step     (x^6)
)

batch = torch.stack((inputs, inputs), dim=0)
print(batch.shape)

class CausalAttention(nn.Module):

def __init__(self, d_in, d_out, context_length,
dropout, qkv_bias=False):
super().__init__()
self.d_out = d_out
self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.dropout = nn.Dropout(dropout)
self.register_buffer('mask', torch.triu(torch.ones(context_length, context_length), diagonal=1)) # New

def forward(self, x):
b, num_tokens, d_in = x.shape
# b is the num of batches
# num_tokens is the number of tokens per batch
# d_in is the dimensions er token

keys = self.W_key(x) # This generates the keys of the tokens
queries = self.W_query(x)
values = self.W_value(x)

attn_scores = queries @ keys.transpose(1, 2) # Moves the third dimension to the second one and the second one to the third one to be able to multiply
attn_scores.masked_fill_(  # New, _ ops are in-place
self.mask.bool()[:num_tokens, :num_tokens], -torch.inf)  # `:num_tokens` to account for cases where the number of tokens in the batch is smaller than the supported context_size
attn_weights = torch.softmax(
attn_scores / keys.shape[-1]**0.5, dim=-1
)
attn_weights = self.dropout(attn_weights)

context_vec = attn_weights @ values
return context_vec

torch.manual_seed(123)

context_length = batch.shape[1]
d_in = 3
d_out = 2
ca = CausalAttention(d_in, d_out, context_length, 0.0)

context_vecs = ca(batch)

print(context_vecs)
print("context_vecs.shape:", context_vecs.shape)
```
## Single-Head Attention을 Multi-Head Attention으로 확장하기

실용적인 관점에서 **multi-head attention**은 여러 self-attention head를 실행하며, 각 head는 **고유한 학습된 projection**을 사용하고 그 출력을 결합합니다.<sup>[[1]](#references)</sup>

### 코드 예시

이전 구현은 wrapping한 후 head마다 한 번씩 호출할 수 있었지만, 다음 최적화된 버전은 모든 head를 함께 처리하여 비용이 큰 Python loop를 피합니다. embedding dimension은 head 수에 따라 균등하게 나뉩니다. 예를 들어 8차원 token embedding을 두 개의 head로 나누면 각 head에 4개의 dimension이 할당됩니다. 따라서 `d_out`은 `num_heads`로 나누어떨어져야 합니다.<sup>[[2]](#references)</sup>
```python
class MultiHeadAttention(nn.Module):
def __init__(self, d_in, d_out, context_length, dropout, num_heads, qkv_bias=False):
super().__init__()
assert (d_out % num_heads == 0), \
"d_out must be divisible by num_heads"

self.d_out = d_out
self.num_heads = num_heads
self.head_dim = d_out // num_heads # Reduce the projection dim to match desired output dim

self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.out_proj = nn.Linear(d_out, d_out)  # Linear layer to combine head outputs
self.dropout = nn.Dropout(dropout)
self.register_buffer(
"mask",
torch.triu(torch.ones(context_length, context_length),
diagonal=1)
)

def forward(self, x):
b, num_tokens, d_in = x.shape
# b is the num of batches
# num_tokens is the number of tokens per batch
# d_in is the dimensions er token

keys = self.W_key(x) # Shape: (b, num_tokens, d_out)
queries = self.W_query(x)
values = self.W_value(x)

# We implicitly split the matrix by adding a `num_heads` dimension
# Unroll last dim: (b, num_tokens, d_out) -> (b, num_tokens, num_heads, head_dim)
keys = keys.view(b, num_tokens, self.num_heads, self.head_dim)
values = values.view(b, num_tokens, self.num_heads, self.head_dim)
queries = queries.view(b, num_tokens, self.num_heads, self.head_dim)

# Transpose: (b, num_tokens, num_heads, head_dim) -> (b, num_heads, num_tokens, head_dim)
keys = keys.transpose(1, 2)
queries = queries.transpose(1, 2)
values = values.transpose(1, 2)

# Compute scaled dot-product attention (aka self-attention) with a causal mask
attn_scores = queries @ keys.transpose(2, 3)  # Dot product for each head

# Original mask truncated to the number of tokens and converted to boolean
mask_bool = self.mask.bool()[:num_tokens, :num_tokens]

# Use the mask to fill attention scores
attn_scores.masked_fill_(mask_bool, -torch.inf)

attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)
attn_weights = self.dropout(attn_weights)

# Shape: (b, num_tokens, num_heads, head_dim)
context_vec = (attn_weights @ values).transpose(1, 2)

# Combine heads, where self.d_out = self.num_heads * self.head_dim
context_vec = context_vec.contiguous().view(b, num_tokens, self.d_out)
context_vec = self.out_proj(context_vec) # optional projection

return context_vec

torch.manual_seed(123)

batch_size, context_length, d_in = batch.shape
d_out = 2
mha = MultiHeadAttention(d_in, d_out, context_length, 0.0, num_heads=2)

context_vecs = mha(batch)

print(context_vecs)
print("context_vecs.shape:", context_vecs.shape)

```
또 다른 compact하고 효율적인 구현을 위해 PyTorch의 [`torch.nn.MultiheadAttention`](https://pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html) class를 사용할 수 있습니다.

> [!TIP]
> 각 head가 모든 token의 모든 dimension을 확인하도록 하는 대신 token의 dimension을 head 간에 나누는 것이 더 나은 이유에 대한 ChatGPT의 간단한 답변:
>
> 각 head가 모든 embedding dimension을 처리하도록 하면 각 head가 전체 정보에 접근할 수 있어 유리해 보일 수 있지만, 일반적으로는 **embedding dimension을 head 간에 나눕니다**. 이 접근 방식은 computational efficiency와 model performance 사이의 균형을 맞추고, 각 head가 다양한 representation을 학습하도록 유도합니다. 따라서 각 head가 모든 dimension을 확인하도록 하는 것보다 embedding dimension을 나누는 방식이 일반적으로 선호됩니다.
