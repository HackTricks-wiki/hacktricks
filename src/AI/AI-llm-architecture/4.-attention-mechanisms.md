## Meccanismi di Attention e Self-Attention nelle Reti Neurali

I meccanismi di attention consentono alle reti neurali di c**oncentrarsi su parti specifiche dell'input durante la generazione di ogni parte dell'output**. Assegnano pesi diversi ai vari input, aiutando il modello a decidere quali siano più rilevanti per il compito in questione. Questo è fondamentale in attività come la traduzione automatica, dove comprendere il contesto dell'intera frase è necessario per ottenere una traduzione accurata.<sup>[[1]](#references)</sup>

> [!TIP]
> L'obiettivo di questa quarta fase è molto semplice: **Applicare alcuni meccanismi di attention**. Questi saranno costituiti da numerosi **layer ripetuti** che **cattureranno la relazione tra una parola del vocabolario e i suoi vicini nella frase corrente utilizzata per addestrare l'LLM**.\
> Per questo vengono utilizzati molti layer, quindi numerosi parametri addestrabili acquisiranno queste informazioni.

### Comprendere i Meccanismi di Attention

Nei tradizionali modelli sequence-to-sequence utilizzati per la traduzione linguistica, il modello codifica una sequenza di input in un vettore di contesto di dimensione fissa. Tuttavia, questo approccio presenta difficoltà con le frasi lunghe, perché il vettore di contesto a dimensione fissa potrebbe non contenere tutte le informazioni necessarie. I meccanismi di attention affrontano questa limitazione consentendo al modello di considerare tutti i token di input durante la generazione di ogni token di output.

#### Esempio: Traduzione Automatica

Consideriamo la traduzione in inglese della frase tedesca "Kannst du mir helfen diesen Satz zu übersetzen". Una traduzione parola per parola non produrrebbe una frase inglese grammaticalmente corretta a causa delle differenze nelle strutture grammaticali tra le lingue. Un meccanismo di attention consente al modello di concentrarsi sulle parti rilevanti della frase di input durante la generazione di ogni parola della frase di output, producendo una traduzione più accurata e coerente.

### Introduzione alla Self-Attention

La self-attention, o intra-attention, è un meccanismo in cui l'attention viene applicata all'interno di una singola sequenza per calcolare una rappresentazione di tale sequenza. Consente a ogni token della sequenza di prestare attention a tutti gli altri token, aiutando il modello a catturare le dipendenze tra i token indipendentemente dalla loro distanza nella sequenza.

#### Concetti Chiave

- **Token**: singoli elementi della sequenza di input (ad esempio, le parole di una frase).
- **Embedding**: rappresentazioni vettoriali dei token, che catturano informazioni semantiche.
- **Pesi di Attention**: valori che determinano l'importanza di ogni token rispetto agli altri.

1. **Calcolare gli Attention Score**: utilizzare il prodotto scalare tra l'embedding della parola target e gli embedding di tutte le parole della sequenza.
2. **Normalizzare gli Score per Ottenere i Pesi di Attention**: applicare la funzione softmax agli attention score per ottenere pesi la cui somma sia pari a 1.
3. **Calcolare il Vettore di Contesto**: moltiplicare l'embedding di ogni parola per il relativo peso di attention e sommare i risultati.

## Self-Attention con Pesi Addestrabili

In pratica, i meccanismi di self-attention utilizzano **pesi addestrabili** per apprendere le rappresentazioni migliori per query, key e value. Questo comporta l'introduzione di tre matrici di pesi:<sup>[[1]](#references)</sup>

<figure><img src="../../images/image (10) (1) (1).png" alt="" width="239"><figcaption></figcaption></figure>

La query rappresenta i dati da utilizzare come in precedenza, mentre le matrici key e value sono semplicemente matrici casuali e addestrabili.

#### Passo 1: Calcolare Query, Key e Value

Ogni token avrà una propria matrice query, key e value, ottenuta moltiplicando i valori delle sue dimensioni per le matrici definite:

<figure><img src="../../images/image (11).png" alt="" width="253"><figcaption></figcaption></figure>

Queste matrici trasformano gli embedding originali in un nuovo spazio adatto al calcolo dell'attention.

**Esempio**

Supponiamo:

- Dimensione dell'input `din=3` (dimensione dell'embedding)
- Dimensione dell'output `dout=2` (dimensione desiderata per query, key e value)

Inizializziamo le matrici dei pesi:
```python
import torch.nn as nn

d_in = 3
d_out = 2

W_query = nn.Parameter(torch.rand(d_in, d_out))
W_key = nn.Parameter(torch.rand(d_in, d_out))
W_value = nn.Parameter(torch.rand(d_in, d_out))
```
Calcolo di query, chiavi e valori:
```python
queries = torch.matmul(inputs, W_query)
keys = torch.matmul(inputs, W_key)
values = torch.matmul(inputs, W_value)
```

### Esempio di codice

Prendendo un esempio da [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb), puoi consultare questa classe che implementa la funzionalità self-attention di cui abbiamo parlato:<sup>[[2]](#references)</sup>
```python
import torch

inputs = torch.tensor(
[[0.43, 0.15, 0.89], # Your     (x^1)
[0.55, 0.87, 0.66], # journey  (x^2)
[0.57, 0.85, 0.64], # starts   (x^3)
[0.22, 0.58, 0.33], # with     (x^4)
[0.77, 0.25, 0.10], # one      (x^5)
[0.05, 0.80, 0.55]] # step     (x^6)
)

import torch.nn as nn
class SelfAttention_v2(nn.Module):

def __init__(self, d_in, d_out, qkv_bias=False):
super().__init__()
self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)

def forward(self, x):
keys = self.W_key(x)
queries = self.W_query(x)
values = self.W_value(x)

attn_scores = queries @ keys.T
attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)

context_vec = attn_weights @ values
return context_vec

d_in=3
d_out=2
torch.manual_seed(789)
sa_v2 = SelfAttention_v2(d_in, d_out)
print(sa_v2(inputs))
```
> [!TIP]
> Nota che, invece di inizializzare le matrici con valori casuali, `nn.Linear` viene utilizzato per contrassegnare tutti i pesi come parametri da addestrare.

## Causal Attention: Nascondere le parole future

Per gli LLM vogliamo che il modello consideri solo i token che compaiono prima della posizione corrente per **predire il token successivo**. La **causal attention**, nota anche come **masked attention**, raggiunge questo obiettivo modificando il meccanismo di attention per impedire l'accesso ai token futuri.<sup>[[1]](#references)</sup>

### Applicazione di una maschera di Causal Attention

Per implementare la causal attention, applichiamo una maschera agli attention score **prima dell'operazione softmax**, in modo che quelli rimanenti continuino a sommare 1. Questa maschera imposta gli attention score dei token futuri a infinito negativo, assicurando che, dopo la softmax, i loro attention weight siano pari a zero.

**Passaggi**

1. **Calcolo degli Attention Score**: come in precedenza.
2. **Applicazione della maschera**: usa una matrice triangolare superiore riempita con infinito negativo sopra la diagonale.

```python
mask = torch.triu(torch.ones(seq_len, seq_len), diagonal=1) * float('-inf')
masked_scores = attention_scores + mask
```

3. **Applicazione della Softmax**: calcola gli attention weight usando gli score mascherati.

```python
attention_weights = torch.softmax(masked_scores, dim=-1)
```

### Mascheramento di Attention Weight aggiuntivi con Dropout

Per **prevenire l'overfitting**, possiamo applicare il **dropout** agli attention weight dopo l'operazione softmax. Il dropout **imposta casualmente a zero alcuni attention weight** durante l'addestramento.
```python
dropout = nn.Dropout(p=0.5)
attention_weights = dropout(attention_weights)
```
Un dropout standard è circa del 10-20%.

### Esempio di codice

Esempio di codice tratto da [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb):<sup>[[2]](#references)</sup>
```python
import torch
import torch.nn as nn

inputs = torch.tensor(
[[0.43, 0.15, 0.89], # Your     (x^1)
[0.55, 0.87, 0.66], # journey  (x^2)
[0.57, 0.85, 0.64], # starts   (x^3)
[0.22, 0.58, 0.33], # with     (x^4)
[0.77, 0.25, 0.10], # one      (x^5)
[0.05, 0.80, 0.55]] # step     (x^6)
)

batch = torch.stack((inputs, inputs), dim=0)
print(batch.shape)

class CausalAttention(nn.Module):

def __init__(self, d_in, d_out, context_length,
dropout, qkv_bias=False):
super().__init__()
self.d_out = d_out
self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.dropout = nn.Dropout(dropout)
self.register_buffer('mask', torch.triu(torch.ones(context_length, context_length), diagonal=1)) # New

def forward(self, x):
b, num_tokens, d_in = x.shape
# b is the num of batches
# num_tokens is the number of tokens per batch
# d_in is the dimensions er token

keys = self.W_key(x) # This generates the keys of the tokens
queries = self.W_query(x)
values = self.W_value(x)

attn_scores = queries @ keys.transpose(1, 2) # Moves the third dimension to the second one and the second one to the third one to be able to multiply
attn_scores.masked_fill_(  # New, _ ops are in-place
self.mask.bool()[:num_tokens, :num_tokens], -torch.inf)  # `:num_tokens` to account for cases where the number of tokens in the batch is smaller than the supported context_size
attn_weights = torch.softmax(
attn_scores / keys.shape[-1]**0.5, dim=-1
)
attn_weights = self.dropout(attn_weights)

context_vec = attn_weights @ values
return context_vec

torch.manual_seed(123)

context_length = batch.shape[1]
d_in = 3
d_out = 2
ca = CausalAttention(d_in, d_out, context_length, 0.0)

context_vecs = ca(batch)

print(context_vecs)
print("context_vecs.shape:", context_vecs.shape)
```
## Estendere la Single-Head Attention alla Multi-Head Attention

In termini pratici, la **Multi-Head Attention** consiste nell'eseguire **più istanze** della funzione di self-attention, ciascuna con i **propri pesi**, in modo da calcolare vettori finali diversi.<sup>[[1]](#references)</sup>

### Esempio di codice

Sarebbe possibile riutilizzare il codice precedente e aggiungere semplicemente un wrapper che lo avvii più volte, ma questa è una versione più ottimizzata tratta da [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb), che elabora tutte le head contemporaneamente, riducendo il numero di costosi cicli `for`. Come si può vedere nel codice, le dimensioni di ciascun token vengono suddivise in dimensioni diverse in base al numero di head. In questo modo, se un token ha 8 dimensioni e vogliamo utilizzare 3 head, le dimensioni verranno suddivise in 2 array da 4 dimensioni e ogni head ne utilizzerà uno:<sup>[[2]](#references)</sup>
```python
class MultiHeadAttention(nn.Module):
def __init__(self, d_in, d_out, context_length, dropout, num_heads, qkv_bias=False):
super().__init__()
assert (d_out % num_heads == 0), \
"d_out must be divisible by num_heads"

self.d_out = d_out
self.num_heads = num_heads
self.head_dim = d_out // num_heads # Reduce the projection dim to match desired output dim

self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.out_proj = nn.Linear(d_out, d_out)  # Linear layer to combine head outputs
self.dropout = nn.Dropout(dropout)
self.register_buffer(
"mask",
torch.triu(torch.ones(context_length, context_length),
diagonal=1)
)

def forward(self, x):
b, num_tokens, d_in = x.shape
# b is the num of batches
# num_tokens is the number of tokens per batch
# d_in is the dimensions er token

keys = self.W_key(x) # Shape: (b, num_tokens, d_out)
queries = self.W_query(x)
values = self.W_value(x)

# We implicitly split the matrix by adding a `num_heads` dimension
# Unroll last dim: (b, num_tokens, d_out) -> (b, num_tokens, num_heads, head_dim)
keys = keys.view(b, num_tokens, self.num_heads, self.head_dim)
values = values.view(b, num_tokens, self.num_heads, self.head_dim)
queries = queries.view(b, num_tokens, self.num_heads, self.head_dim)

# Transpose: (b, num_tokens, num_heads, head_dim) -> (b, num_heads, num_tokens, head_dim)
keys = keys.transpose(1, 2)
queries = queries.transpose(1, 2)
values = values.transpose(1, 2)

# Compute scaled dot-product attention (aka self-attention) with a causal mask
attn_scores = queries @ keys.transpose(2, 3)  # Dot product for each head

# Original mask truncated to the number of tokens and converted to boolean
mask_bool = self.mask.bool()[:num_tokens, :num_tokens]

# Use the mask to fill attention scores
attn_scores.masked_fill_(mask_bool, -torch.inf)

attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)
attn_weights = self.dropout(attn_weights)

# Shape: (b, num_tokens, num_heads, head_dim)
context_vec = (attn_weights @ values).transpose(1, 2)

# Combine heads, where self.d_out = self.num_heads * self.head_dim
context_vec = context_vec.contiguous().view(b, num_tokens, self.d_out)
context_vec = self.out_proj(context_vec) # optional projection

return context_vec

torch.manual_seed(123)

batch_size, context_length, d_in = batch.shape
d_out = 2
mha = MultiHeadAttention(d_in, d_out, context_length, 0.0, num_heads=2)

context_vecs = mha(batch)

print(context_vecs)
print("context_vecs.shape:", context_vecs.shape)

```
Per un'altra implementazione compatta ed efficiente, potresti usare la classe [`torch.nn.MultiheadAttention`](https://pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html) in PyTorch.

> [!TIP]
> Risposta breve di ChatGPT sul motivo per cui è meglio dividere le dimensioni dei token tra le heads invece di fare in modo che ogni head controlli tutte le dimensioni di tutti i token:
>
> Sebbene consentire a ogni head di elaborare tutte le dimensioni dell'embedding possa sembrare vantaggioso, perché ogni head avrebbe accesso a tutte le informazioni, la pratica standard consiste nel **dividere le dimensioni dell'embedding tra le heads**. Questo approccio bilancia l'efficienza computazionale con le prestazioni del modello e incoraggia ogni head ad apprendere rappresentazioni diverse. Pertanto, dividere le dimensioni dell'embedding è generalmente preferibile rispetto a fare in modo che ogni head controlli tutte le dimensioni.
