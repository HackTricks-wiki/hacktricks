## Механізми уваги та self-attention у нейронних мережах

Механізми уваги дають змогу нейронним мережам **зосереджуватися на певних частинах вхідних даних під час генерування кожної частини вихідних даних**. Вони призначають різні ваги різним вхідним даним, допомагаючи моделі визначати, які з них є найбільш релевантними для поточного завдання. Це особливо важливо для таких завдань, як машинний переклад, де для точного перекладу необхідно розуміти контекст усього речення.<sup>[[1]](#references)</sup>

> [!TIP]
> Мета цієї четвертої фази дуже проста: **застосувати певні механізми уваги**. Це будуть численні **повторювані шари**, які мають **виявляти зв'язок слова у словнику з його сусідами в поточному реченні, що використовується для навчання LLM**.\
> Для цього використовується багато шарів, тому велика кількість trainable параметрів буде фіксувати цю інформацію.

### Розуміння механізмів уваги

У традиційних sequence-to-sequence моделях, що використовуються для перекладу тексту, модель кодує вхідну послідовність у контекстний вектор фіксованого розміру. Однак цей підхід погано працює з довгими реченнями, оскільки контекстний вектор фіксованого розміру може не містити всієї необхідної інформації. Механізми уваги усувають це обмеження, даючи моделі змогу враховувати всі вхідні токени під час генерування кожного вихідного токена.

#### Приклад: машинний переклад

Розглянемо переклад німецького речення "Kannst du mir helfen diesen Satz zu übersetzen" англійською мовою. Дослівний переклад кожного слова не дасть граматично правильного англійського речення через відмінності в граматичних структурах мов. Механізм уваги дає моделі змогу зосереджуватися на релевантних частинах вхідного речення під час генерування кожного слова вихідного речення, що забезпечує точніший і зв'язніший переклад.

### Вступ до self-attention

Self-attention, або intra-attention, — це механізм, у якому увага застосовується в межах однієї послідовності для обчислення її представлення. Він дає змогу кожному токену звертати увагу на всі інші токени послідовності, допомагаючи моделі виявляти залежності між токенами незалежно від відстані між ними в послідовності.

#### Основні поняття

- **Токени**: окремі елементи вхідної послідовності (наприклад, слова в реченні).
- **Embeddings**: векторні представлення токенів, що містять семантичну інформацію.
- **Ваги уваги**: значення, які визначають важливість кожного токена відносно інших.

Взявши приклад із [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb), ви можете переглянути цей клас, який реалізує функціональність self-attention, про яку ми говорили:<sup>[[2]](#references)</sup>
```python
import torch

inputs = torch.tensor(
[[0.43, 0.15, 0.89], # Your     (x^1)
[0.55, 0.87, 0.66], # journey  (x^2)
[0.57, 0.85, 0.64], # starts   (x^3)
[0.22, 0.58, 0.33], # with     (x^4)
[0.77, 0.25, 0.10], # one      (x^5)
[0.05, 0.80, 0.55]] # step     (x^6)
)

import torch.nn as nn
class SelfAttention_v2(nn.Module):

def __init__(self, d_in, d_out, qkv_bias=False):
super().__init__()
self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)

def forward(self, x):
keys = self.W_key(x)
queries = self.W_query(x)
values = self.W_value(x)

attn_scores = queries @ keys.T
attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)

context_vec = attn_weights @ values
return context_vec

d_in=3
d_out=2
torch.manual_seed(789)
sa_v2 = SelfAttention_v2(d_in, d_out)
print(sa_v2(inputs))
```

## Каузальна увага: приховування майбутніх слів

Для LLM ми хочемо, щоб модель враховувала лише токени, які з'являються перед поточною позицією, щоб **передбачити наступний токен**. **Каузальна увага**, також відома як **маскована увага**, досягає цього шляхом модифікації механізму уваги, щоб запобігти доступу до майбутніх токенів.<sup>[[1]](#references)</sup>

### Застосування маски каузальної уваги

Щоб реалізувати каузальну увагу, ми застосовуємо маску до оцінок уваги **перед операцією softmax**, щоб решта значень у сумі дорівнювала 1. Ця маска встановлює оцінки уваги майбутніх токенів у від'ємну нескінченність, гарантуючи, що після softmax їхні ваги уваги дорівнюватимуть нулю.

**Кроки**

1. **Обчислення оцінок уваги**: так само, як і раніше.
2. **Застосування маски**: використовуйте верхню трикутну матрицю, заповнену від'ємною нескінченністю над діагоналлю.

```python
mask = torch.triu(torch.ones(seq_len, seq_len), diagonal=1) * float('-inf')
masked_scores = attention_scores + mask
```

3. **Застосування Softmax**: обчисліть ваги уваги, використовуючи замасковані оцінки.

```python
attention_weights = torch.softmax(masked_scores, dim=-1)
```

### Маскування додаткових ваг уваги за допомогою Dropout

Щоб **запобігти перенавчанню**, ми можемо застосувати **dropout** до ваг уваги після операції softmax. Dropout **випадково обнуляє деякі ваги уваги** під час навчання.
```python
dropout = nn.Dropout(p=0.5)
attention_weights = dropout(attention_weights)
```
Звичайний dropout становить близько 10–20%.

```python
import torch
import torch.nn as nn

inputs = torch.tensor(
[[0.43, 0.15, 0.89], # Your     (x^1)
[0.55, 0.87, 0.66], # journey  (x^2)
[0.57, 0.85, 0.64], # starts   (x^3)
[0.22, 0.58, 0.33], # with     (x^4)
[0.77, 0.25, 0.10], # one      (x^5)
[0.05, 0.80, 0.55]] # step     (x^6)
)

batch = torch.stack((inputs, inputs), dim=0)
print(batch.shape)

class CausalAttention(nn.Module):

def __init__(self, d_in, d_out, context_length,
dropout, qkv_bias=False):
super().__init__()
self.d_out = d_out
self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.dropout = nn.Dropout(dropout)
self.register_buffer('mask', torch.triu(torch.ones(context_length, context_length), diagonal=1)) # New

def forward(self, x):
b, num_tokens, d_in = x.shape
# b is the num of batches
# num_tokens is the number of tokens per batch
# d_in is the dimensions er token

keys = self.W_key(x) # This generates the keys of the tokens
queries = self.W_query(x)
values = self.W_value(x)

attn_scores = queries @ keys.transpose(1, 2) # Moves the third dimension to the second one and the second one to the third one to be able to multiply
attn_scores.masked_fill_(  # New, _ ops are in-place
self.mask.bool()[:num_tokens, :num_tokens], -torch.inf)  # `:num_tokens` to account for cases where the number of tokens in the batch is smaller than the supported context_size
attn_weights = torch.softmax(
attn_scores / keys.shape[-1]**0.5, dim=-1
)
attn_weights = self.dropout(attn_weights)

context_vec = attn_weights @ values
return context_vec

torch.manual_seed(123)

context_length = batch.shape[1]
d_in = 3
d_out = 2
ca = CausalAttention(d_in, d_out, context_length, 0.0)

context_vecs = ca(batch)

print(context_vecs)
print("context_vecs.shape:", context_vecs.shape)
```
## Розширення однохолової уваги до багатохолової уваги

На практиці **багатоголова увага** виконує кілька голів self-attention, кожна з яких має **власні навчені проєкції**, і об’єднує їхні результати.<sup>[[1]](#references)</sup>

### Приклад коду

Попередню реалізацію можна було обгорнути та викликати один раз для кожної голови, але наведена нижче оптимізована версія обробляє всі голови разом і уникає дорогих циклів Python. Розмірність embedding ділиться порівну між головами: наприклад, embedding токена розмірністю вісім із двома головами дає кожній голові чотири розмірності. Отже, `d_out` має ділитися без остачі на `num_heads`.<sup>[[2]](#references)</sup>
```python
class MultiHeadAttention(nn.Module):
def __init__(self, d_in, d_out, context_length, dropout, num_heads, qkv_bias=False):
super().__init__()
assert (d_out % num_heads == 0), \
"d_out must be divisible by num_heads"

self.d_out = d_out
self.num_heads = num_heads
self.head_dim = d_out // num_heads # Reduce the projection dim to match desired output dim

self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.out_proj = nn.Linear(d_out, d_out)  # Linear layer to combine head outputs
self.dropout = nn.Dropout(dropout)
self.register_buffer(
"mask",
torch.triu(torch.ones(context_length, context_length),
diagonal=1)
)

def forward(self, x):
b, num_tokens, d_in = x.shape
# b is the num of batches
# num_tokens is the number of tokens per batch
# d_in is the dimensions er token

keys = self.W_key(x) # Shape: (b, num_tokens, d_out)
queries = self.W_query(x)
values = self.W_value(x)

# We implicitly split the matrix by adding a `num_heads` dimension
# Unroll last dim: (b, num_tokens, d_out) -> (b, num_tokens, num_heads, head_dim)
keys = keys.view(b, num_tokens, self.num_heads, self.head_dim)
values = values.view(b, num_tokens, self.num_heads, self.head_dim)
queries = queries.view(b, num_tokens, self.num_heads, self.head_dim)

# Transpose: (b, num_tokens, num_heads, head_dim) -> (b, num_heads, num_tokens, head_dim)
keys = keys.transpose(1, 2)
queries = queries.transpose(1, 2)
values = values.transpose(1, 2)

# Compute scaled dot-product attention (aka self-attention) with a causal mask
attn_scores = queries @ keys.transpose(2, 3)  # Dot product for each head

# Original mask truncated to the number of tokens and converted to boolean
mask_bool = self.mask.bool()[:num_tokens, :num_tokens]

# Use the mask to fill attention scores
attn_scores.masked_fill_(mask_bool, -torch.inf)

attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)
attn_weights = self.dropout(attn_weights)

# Shape: (b, num_tokens, num_heads, head_dim)
context_vec = (attn_weights @ values).transpose(1, 2)

# Combine heads, where self.d_out = self.num_heads * self.head_dim
context_vec = context_vec.contiguous().view(b, num_tokens, self.d_out)
context_vec = self.out_proj(context_vec) # optional projection

return context_vec

torch.manual_seed(123)

batch_size, context_length, d_in = batch.shape
d_out = 2
mha = MultiHeadAttention(d_in, d_out, context_length, 0.0, num_heads=2)

context_vecs = mha(batch)

print(context_vecs)
print("context_vecs.shape:", context_vecs.shape)

```
Для іншої компактної та ефективної реалізації можна використати клас [`torch.nn.MultiheadAttention`](https://pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html) у PyTorch.

> [!TIP]
> Коротка відповідь ChatGPT про те, чому краще розподіляти dimensions токенів між головами, а не дозволяти кожній голові перевіряти всі dimensions усіх токенів:
>
> Хоча дозвіл кожній голові обробляти всі embedding dimensions може здаватися перевагою, оскільки кожна голова матиме доступ до повної інформації, стандартною практикою є **розподіл embedding dimensions між головами**. Такий підхід забезпечує баланс між обчислювальною ефективністю та продуктивністю моделі й заохочує кожну голову вивчати різні представлення. Тому розподіл embedding dimensions зазвичай є кращим, ніж дозвіл кожній голові перевіряти всі dimensions.
