## Meccanismi di attenzione e self-attention nelle reti neurali

I meccanismi di attenzione consentono alle reti neurali di **concentrarsi su parti specifiche dell'input durante la generazione di ogni parte dell'output**. Assegnano pesi diversi ai vari input, aiutando il modello a decidere quali siano più rilevanti per il compito in questione. Questo è fondamentale in attività come la traduzione automatica, dove comprendere il contesto dell'intera frase è necessario per ottenere una traduzione accurata.<sup>[[1]](#references)</sup>

> [!TIP]
> L'obiettivo di questa quarta fase è molto semplice: **applicare alcuni meccanismi di attenzione**. Questi saranno costituiti da numerosi **layer ripetuti** che **cattureranno la relazione di una parola nel vocabolario con le parole vicine nella frase corrente utilizzata per addestrare l'LLM**.\
> Per questo vengono utilizzati numerosi layer, quindi molti parametri addestrabili acquisiranno queste informazioni.

### Comprendere i meccanismi di attenzione

Nei tradizionali modelli sequence-to-sequence utilizzati per la traduzione linguistica, il modello codifica una sequenza di input in un vettore di contesto di dimensione fissa. Tuttavia, questo approccio presenta difficoltà con le frasi lunghe, perché il vettore di contesto di dimensione fissa potrebbe non contenere tutte le informazioni necessarie. I meccanismi di attenzione risolvono questa limitazione consentendo al modello di considerare tutti i token di input durante la generazione di ciascun token di output.

#### Esempio: traduzione automatica

Consideriamo la traduzione della frase tedesca "Kannst du mir helfen diesen Satz zu übersetzen" in inglese. Una traduzione parola per parola non produrrebbe una frase inglese grammaticalmente corretta a causa delle differenze nelle strutture grammaticali tra le lingue. Un meccanismo di attenzione consente al modello di concentrarsi sulle parti rilevanti della frase di input durante la generazione di ogni parola della frase di output, ottenendo una traduzione più accurata e coerente.

### Introduzione al self-attention

Il self-attention, o intra-attention, è un meccanismo in cui l'attenzione viene applicata all'interno di una singola sequenza per calcolare una rappresentazione di tale sequenza. Consente a ciascun token della sequenza di prestare attenzione a tutti gli altri token, aiutando il modello a catturare le dipendenze tra i token indipendentemente dalla loro distanza nella sequenza.

#### Concetti chiave

- **Token**: singoli elementi della sequenza di input, ad esempio le parole di una frase.
- **Embedding**: rappresentazioni vettoriali dei token che catturano informazioni semantiche.
- **Pesi di attenzione**: valori che determinano l'importanza di ciascun token rispetto agli altri.

1. **Calcolare i punteggi di attenzione**: utilizzare il prodotto scalare tra l'embedding della parola target e gli embedding di tutte le parole della sequenza.
2. **Normalizzare i punteggi per ottenere i pesi di attenzione**: applicare la funzione softmax ai punteggi di attenzione per ottenere pesi la cui somma sia pari a 1.
3. **Calcolare il vettore di contesto**: moltiplicare l'embedding di ogni parola per il relativo peso di attenzione e sommare i risultati.

## Self-attention con pesi addestrabili

In pratica, i meccanismi di self-attention utilizzano **pesi addestrabili** per imparare le rappresentazioni migliori per query, key e value. Questo comporta l'introduzione di tre matrici di pesi:<sup>[[1]](#references)</sup>

<figure><img src="../../images/image (10) (1) (1).png" alt="" width="239"><figcaption></figcaption></figure>

La query rappresenta i dati da utilizzare come prima, mentre le matrici key e value sono semplicemente matrici casuali e addestrabili.

#### Passaggio 1: calcolare query, key e value

Ogni token avrà la propria matrice query, key e value, ottenuta moltiplicando i valori delle sue dimensioni per le matrici definite:

<figure><img src="../../images/image (11).png" alt="" width="253"><figcaption></figcaption></figure>

Queste matrici trasformano gli embedding originali in un nuovo spazio adatto al calcolo dell'attenzione.

**Esempio**

Supponiamo:

- Dimensione dell'input `din=3` (dimensione dell'embedding)
- Dimensione dell'output `dout=2` (dimensione desiderata per query, key e value)

Inizializziamo le matrici dei pesi:
```python
import torch.nn as nn

d_in = 3
d_out = 2

W_query = nn.Parameter(torch.rand(d_in, d_out))
W_key = nn.Parameter(torch.rand(d_in, d_out))
W_value = nn.Parameter(torch.rand(d_in, d_out))
```
Calcolo di query, chiavi e valori:
```python
queries = torch.matmul(inputs, W_query)
keys = torch.matmul(inputs, W_key)
values = torch.matmul(inputs, W_value)
```

### Esempio di codice

Prendendo un esempio da [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb), puoi consultare questa classe che implementa la funzionalità di self-attention di cui abbiamo parlato:<sup>[[2]](#references)</sup>
```python
import torch

inputs = torch.tensor(
[[0.43, 0.15, 0.89], # Your     (x^1)
[0.55, 0.87, 0.66], # journey  (x^2)
[0.57, 0.85, 0.64], # starts   (x^3)
[0.22, 0.58, 0.33], # with     (x^4)
[0.77, 0.25, 0.10], # one      (x^5)
[0.05, 0.80, 0.55]] # step     (x^6)
)

import torch.nn as nn
class SelfAttention_v2(nn.Module):

def __init__(self, d_in, d_out, qkv_bias=False):
super().__init__()
self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)

def forward(self, x):
keys = self.W_key(x)
queries = self.W_query(x)
values = self.W_value(x)

attn_scores = queries @ keys.T
attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)

context_vec = attn_weights @ values
return context_vec

d_in=3
d_out=2
torch.manual_seed(789)
sa_v2 = SelfAttention_v2(d_in, d_out)
print(sa_v2(inputs))
```
> [!TIP]
> Nota che, invece di inizializzare le matrici con valori casuali, `nn.Linear` viene usato per contrassegnare tutti i pesi come parametri da addestrare.

## Causal Attention: Nascondere le parole future

Per gli LLM vogliamo che il modello consideri solo i token che compaiono prima della posizione corrente, in modo da **prevedere il token successivo**. La **causal attention**, nota anche come **masked attention**, raggiunge questo obiettivo modificando il meccanismo di attention per impedire l'accesso ai token futuri.<sup>[[1]](#references)</sup>

### Applicare una Causal Attention Mask

Per implementare la causal attention, applichiamo una mask agli attention scores **prima dell'operazione softmax**, in modo che quelli rimanenti continuino a sommare a 1. Questa mask imposta gli attention scores dei token futuri a infinito negativo, assicurando che, dopo la softmax, i loro attention weights siano pari a zero.

**Passaggi**

1. **Calcolare gli Attention Scores**: come prima.
2. **Applicare la Mask**: usare una matrice triangolare superiore riempita con infinito negativo sopra la diagonale.

```python
mask = torch.triu(torch.ones(seq_len, seq_len), diagonal=1) * float('-inf')
masked_scores = attention_scores + mask
```

3. **Applicare la Softmax**: calcolare gli attention weights usando i masked scores.

```python
attention_weights = torch.softmax(masked_scores, dim=-1)
```

### Applicare il Dropout a Ulteriori Attention Weights con il Dropout

Per **prevenire l'overfitting**, possiamo applicare il **dropout** agli attention weights dopo l'operazione softmax. Il dropout **imposta casualmente a zero alcuni attention weights** durante l'addestramento.
```python
dropout = nn.Dropout(p=0.5)
attention_weights = dropout(attention_weights)
```
Un dropout standard è circa del 10-20%.

### Esempio di codice

Esempio di codice tratto da [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb):<sup>[[2]](#references)</sup>
```python
import torch
import torch.nn as nn

inputs = torch.tensor(
[[0.43, 0.15, 0.89], # Your     (x^1)
[0.55, 0.87, 0.66], # journey  (x^2)
[0.57, 0.85, 0.64], # starts   (x^3)
[0.22, 0.58, 0.33], # with     (x^4)
[0.77, 0.25, 0.10], # one      (x^5)
[0.05, 0.80, 0.55]] # step     (x^6)
)

batch = torch.stack((inputs, inputs), dim=0)
print(batch.shape)

class CausalAttention(nn.Module):

def __init__(self, d_in, d_out, context_length,
dropout, qkv_bias=False):
super().__init__()
self.d_out = d_out
self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.dropout = nn.Dropout(dropout)
self.register_buffer('mask', torch.triu(torch.ones(context_length, context_length), diagonal=1)) # New

def forward(self, x):
b, num_tokens, d_in = x.shape
# b is the num of batches
# num_tokens is the number of tokens per batch
# d_in is the dimensions er token

keys = self.W_key(x) # This generates the keys of the tokens
queries = self.W_query(x)
values = self.W_value(x)

attn_scores = queries @ keys.transpose(1, 2) # Moves the third dimension to the second one and the second one to the third one to be able to multiply
attn_scores.masked_fill_(  # New, _ ops are in-place
self.mask.bool()[:num_tokens, :num_tokens], -torch.inf)  # `:num_tokens` to account for cases where the number of tokens in the batch is smaller than the supported context_size
attn_weights = torch.softmax(
attn_scores / keys.shape[-1]**0.5, dim=-1
)
attn_weights = self.dropout(attn_weights)

context_vec = attn_weights @ values
return context_vec

torch.manual_seed(123)

context_length = batch.shape[1]
d_in = 3
d_out = 2
ca = CausalAttention(d_in, d_out, context_length, 0.0)

context_vecs = ca(batch)

print(context_vecs)
print("context_vecs.shape:", context_vecs.shape)
```
## Estendere la Single-Head Attention alla Multi-Head Attention

In termini pratici, la **multi-head attention** esegue più head di self-attention, ciascuno con le **proprie proiezioni apprese**, e combina i relativi output.<sup>[[1]](#references)</sup>

### Esempio di codice

L'implementazione precedente poteva essere racchiusa e invocata una volta per ogni head, ma la versione ottimizzata seguente elabora tutti gli head insieme ed evita costosi cicli Python. La dimensione dell'embedding viene suddivisa equamente tra gli head: per esempio, un embedding dei token di otto dimensioni con due head assegna quattro dimensioni a ciascun head. Di conseguenza, `d_out` deve essere divisibile per `num_heads`.<sup>[[2]](#references)</sup>
```python
class MultiHeadAttention(nn.Module):
def __init__(self, d_in, d_out, context_length, dropout, num_heads, qkv_bias=False):
super().__init__()
assert (d_out % num_heads == 0), \
"d_out must be divisible by num_heads"

self.d_out = d_out
self.num_heads = num_heads
self.head_dim = d_out // num_heads # Reduce the projection dim to match desired output dim

self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.out_proj = nn.Linear(d_out, d_out)  # Linear layer to combine head outputs
self.dropout = nn.Dropout(dropout)
self.register_buffer(
"mask",
torch.triu(torch.ones(context_length, context_length),
diagonal=1)
)

def forward(self, x):
b, num_tokens, d_in = x.shape
# b is the num of batches
# num_tokens is the number of tokens per batch
# d_in is the dimensions er token

keys = self.W_key(x) # Shape: (b, num_tokens, d_out)
queries = self.W_query(x)
values = self.W_value(x)

# We implicitly split the matrix by adding a `num_heads` dimension
# Unroll last dim: (b, num_tokens, d_out) -> (b, num_tokens, num_heads, head_dim)
keys = keys.view(b, num_tokens, self.num_heads, self.head_dim)
values = values.view(b, num_tokens, self.num_heads, self.head_dim)
queries = queries.view(b, num_tokens, self.num_heads, self.head_dim)

# Transpose: (b, num_tokens, num_heads, head_dim) -> (b, num_heads, num_tokens, head_dim)
keys = keys.transpose(1, 2)
queries = queries.transpose(1, 2)
values = values.transpose(1, 2)

# Compute scaled dot-product attention (aka self-attention) with a causal mask
attn_scores = queries @ keys.transpose(2, 3)  # Dot product for each head

# Original mask truncated to the number of tokens and converted to boolean
mask_bool = self.mask.bool()[:num_tokens, :num_tokens]

# Use the mask to fill attention scores
attn_scores.masked_fill_(mask_bool, -torch.inf)

attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)
attn_weights = self.dropout(attn_weights)

# Shape: (b, num_tokens, num_heads, head_dim)
context_vec = (attn_weights @ values).transpose(1, 2)

# Combine heads, where self.d_out = self.num_heads * self.head_dim
context_vec = context_vec.contiguous().view(b, num_tokens, self.d_out)
context_vec = self.out_proj(context_vec) # optional projection

return context_vec

torch.manual_seed(123)

batch_size, context_length, d_in = batch.shape
d_out = 2
mha = MultiHeadAttention(d_in, d_out, context_length, 0.0, num_heads=2)

context_vecs = mha(batch)

print(context_vecs)
print("context_vecs.shape:", context_vecs.shape)

```
Per un'altra implementazione compatta ed efficiente, potresti usare la classe [`torch.nn.MultiheadAttention`](https://pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html) in PyTorch.

> [!TIP]
> Risposta breve di ChatGPT sul perché sia meglio dividere le dimensioni dei token tra le heads invece di fare in modo che ogni head controlli tutte le dimensioni di tutti i token:
>
> Sebbene consentire a ogni head di elaborare tutte le dimensioni degli embedding possa sembrare vantaggioso, perché ogni head avrebbe accesso all'intera informazione, la pratica standard consiste nel **dividere le dimensioni degli embedding tra le heads**. Questo approccio bilancia l'efficienza computazionale con le prestazioni del modello e incoraggia ogni head ad apprendere rappresentazioni diverse. Pertanto, dividere le dimensioni degli embedding è generalmente preferibile rispetto a fare in modo che ogni head controlli tutte le dimensioni.
