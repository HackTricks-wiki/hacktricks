## Mechanizmy uwagi i self-attention w sieciach neuronowych

Mechanizmy uwagi umożliwiają sieciom neuronowym **skupienie się na określonych częściach danych wejściowych podczas generowania każdej części danych wyjściowych**. Przypisują różne wagi różnym danym wejściowym, pomagając modelowi określić, które dane wejściowe są najbardziej istotne dla danego zadania. Ma to kluczowe znaczenie w zadaniach takich jak tłumaczenie maszynowe, gdzie zrozumienie kontekstu całego zdania jest konieczne do uzyskania poprawnego tłumaczenia.<sup>[[1]](#references)</sup>

> [!TIP]
> Cel tej czwartej fazy jest bardzo prosty: **zastosować pewne mechanizmy uwagi**. Będą to liczne **powtarzające się warstwy**, które będą **wychwytywać relację słowa ze słownika z jego sąsiadami w bieżącym zdaniu używanym do trenowania LLM**.\
> Wykorzystuje się do tego wiele warstw, dlatego wiele trenowalnych parametrów będzie przechwytywać te informacje.

### Zrozumienie mechanizmów uwagi

W tradycyjnych modelach sequence-to-sequence używanych do tłumaczenia języków model koduje sekwencję wejściową do wektora kontekstu o stałym rozmiarze. Takie podejście ma jednak trudności z długimi zdaniami, ponieważ wektor kontekstu o stałym rozmiarze może nie zawierać wszystkich niezbędnych informacji. Mechanizmy uwagi rozwiązują to ograniczenie, umożliwiając modelowi uwzględnianie wszystkich tokenów wejściowych podczas generowania każdego tokena wyjściowego.

#### Przykład: tłumaczenie maszynowe

Rozważmy tłumaczenie niemieckiego zdania „Kannst du mir helfen diesen Satz zu übersetzen” na język angielski. Tłumaczenie słowo po słowie nie dałoby gramatycznie poprawnego zdania angielskiego ze względu na różnice w strukturach gramatycznych między językami. Mechanizm uwagi umożliwia modelowi skupienie się na istotnych częściach zdania wejściowego podczas generowania każdego słowa zdania wyjściowego, co prowadzi do dokładniejszego i bardziej spójnego tłumaczenia.

### Wprowadzenie do self-attention

Self-attention, czyli intra-attention, to mechanizm, w którym uwaga jest stosowana w obrębie pojedynczej sekwencji w celu obliczenia jej reprezentacji. Umożliwia każdemu tokenowi w sekwencji zwracanie uwagi na wszystkie pozostałe tokeny, pomagając modelowi wychwytywać zależności między tokenami niezależnie od dzielącej ich odległości w sekwencji.

#### Kluczowe pojęcia

- **Tokeny**: Pojedyncze elementy sekwencji wejściowej (np. słowa w zdaniu).
- **Embeddingi**: Wektorowe reprezentacje tokenów zawierające informacje semantyczne.
- **Wagi uwagi**: Wartości określające znaczenie każdego tokena względem pozostałych.

### Podsumowanie procesu

1. **Oblicz wyniki uwagi**: Użyj iloczynu skalarnego między embeddingiem docelowego słowa a embeddingami wszystkich słów w sekwencji.
2. **Znormalizuj wyniki, aby uzyskać wagi uwagi**: Zastosuj funkcję softmax do wyników uwagi, aby uzyskać wagi, których suma wynosi 1.
3. **Oblicz wektor kontekstu**: Pomnóż embedding każdego słowa przez jego wagę uwagi i dodaj wyniki.

## Self-attention z trenowalnymi wagami

W praktyce mechanizmy self-attention wykorzystują **trenowalne wagi**, aby nauczyć się najlepszych reprezentacji dla zapytań, kluczy i wartości. Wiąże się to z wprowadzeniem trzech macierzy wag:<sup>[[1]](#references)</sup>

<figure><img src="../../images/image (10) (1) (1).png" alt="" width="239"><figcaption></figcaption></figure>

Zapytanie to dane używane tak jak wcześniej, natomiast macierze kluczy i wartości są po prostu losowymi, trenowalnymi macierzami.

#### Krok 1: Obliczanie zapytań, kluczy i wartości

Każdy token będzie miał własną macierz zapytania, klucza i wartości, uzyskaną przez pomnożenie wartości jego wymiarów przez zdefiniowane macierze:

<figure><img src="../../images/image (11).png" alt="" width="253"><figcaption></figcaption></figure>

Macierze te przekształcają oryginalne embeddingi w nową przestrzeń odpowiednią do obliczania uwagi.

**Przykład**

Załóżmy:

- Wymiar wejściowy `din=3` (rozmiar embeddingu)
- Wymiar wyjściowy `dout=2` (żądany wymiar zapytań, kluczy i wartości)

Zainicjalizuj macierze wag:
```python
import torch.nn as nn

d_in = 3
d_out = 2

W_query = nn.Parameter(torch.rand(d_in, d_out))
W_key = nn.Parameter(torch.rand(d_in, d_out))
W_value = nn.Parameter(torch.rand(d_in, d_out))
```
Oblicz zapytania, klucze i wartości:
```python
queries = torch.matmul(inputs, W_query)
keys = torch.matmul(inputs, W_key)
values = torch.matmul(inputs, W_value)
```

### Przykład kodu

Korzystając z przykładu z [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb), możesz sprawdzić tę klasę, która implementuje omażwianą funkcjonalność self-attention:<sup>[[2]](#references)</sup>
```python
import torch

inputs = torch.tensor(
[[0.43, 0.15, 0.89], # Your     (x^1)
[0.55, 0.87, 0.66], # journey  (x^2)
[0.57, 0.85, 0.64], # starts   (x^3)
[0.22, 0.58, 0.33], # with     (x^4)
[0.77, 0.25, 0.10], # one      (x^5)
[0.05, 0.80, 0.55]] # step     (x^6)
)

import torch.nn as nn
class SelfAttention_v2(nn.Module):

def __init__(self, d_in, d_out, qkv_bias=False):
super().__init__()
self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)

def forward(self, x):
keys = self.W_key(x)
queries = self.W_query(x)
values = self.W_value(x)

attn_scores = queries @ keys.T
attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)

context_vec = attn_weights @ values
return context_vec

d_in=3
d_out=2
torch.manual_seed(789)
sa_v2 = SelfAttention_v2(d_in, d_out)
print(sa_v2(inputs))
```
> [!TIP]
> Zauważ, że zamiast inicjalizowania macierzy losowymi wartościami używany jest `nn.Linear`, aby oznaczyć wszystkie wagi jako parametry do trenowania.

## Uwaga przyczynowa: ukrywanie przyszłych słów

W przypadku LLM chcemy, aby model uwzględniał tylko tokeny znajdujące się przed bieżącą pozycją, aby **przewidywać następny token**. **Uwaga przyczynowa**, znana również jako **uwaga maskowana**, osiąga ten cel poprzez modyfikację mechanizmu uwagi w taki sposób, aby uniemożliwić dostęp do przyszłych tokenów.<sup>[[1]](#references)</sup>

### Stosowanie maski uwagi przyczynowej

Aby zaimplementować uwagę przyczynową, stosujemy maskę do wyników uwagi **przed operacją softmax**, dzięki czemu pozostałe wartości nadal będą sumować się do 1. Maska ta ustawia wyniki uwagi dla przyszłych tokenów na ujemną nieskończoność, zapewniając, że po zastosowaniu softmax ich wagi uwagi będą równe zero.

**Kroki**

1. **Oblicz wyniki uwagi**: Tak samo jak wcześniej.
2. **Zastosuj maskę**: Użyj górnej macierzy trójkątnej wypełnionej ujemną nieskończonością powyżej przekątnej.

```python
mask = torch.triu(torch.ones(seq_len, seq_len), diagonal=1) * float('-inf')
masked_scores = attention_scores + mask
```

3. **Zastosuj softmax**: Oblicz wagi uwagi, korzystając z zamaskowanych wyników.

```python
attention_weights = torch.softmax(masked_scores, dim=-1)
```

### Maskowanie dodatkowych wag uwagi za pomocą Dropout

Aby **zapobiegać przeuczeniu**, możemy zastosować **dropout** do wag uwagi po operacji softmax. Dropout **losowo zeruje niektóre wagi uwagi** podczas trenowania.
```python
dropout = nn.Dropout(p=0.5)
attention_weights = dropout(attention_weights)
```
Standardowy dropout wynosi około 10–20%.

### Przykład kodu

Przykład kodu z [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb):<sup>[[2]](#references)</sup>
```python
import torch
import torch.nn as nn

inputs = torch.tensor(
[[0.43, 0.15, 0.89], # Your     (x^1)
[0.55, 0.87, 0.66], # journey  (x^2)
[0.57, 0.85, 0.64], # starts   (x^3)
[0.22, 0.58, 0.33], # with     (x^4)
[0.77, 0.25, 0.10], # one      (x^5)
[0.05, 0.80, 0.55]] # step     (x^6)
)

batch = torch.stack((inputs, inputs), dim=0)
print(batch.shape)

class CausalAttention(nn.Module):

def __init__(self, d_in, d_out, context_length,
dropout, qkv_bias=False):
super().__init__()
self.d_out = d_out
self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.dropout = nn.Dropout(dropout)
self.register_buffer('mask', torch.triu(torch.ones(context_length, context_length), diagonal=1)) # New

def forward(self, x):
b, num_tokens, d_in = x.shape
# b is the num of batches
# num_tokens is the number of tokens per batch
# d_in is the dimensions er token

keys = self.W_key(x) # This generates the keys of the tokens
queries = self.W_query(x)
values = self.W_value(x)

attn_scores = queries @ keys.transpose(1, 2) # Moves the third dimension to the second one and the second one to the third one to be able to multiply
attn_scores.masked_fill_(  # New, _ ops are in-place
self.mask.bool()[:num_tokens, :num_tokens], -torch.inf)  # `:num_tokens` to account for cases where the number of tokens in the batch is smaller than the supported context_size
attn_weights = torch.softmax(
attn_scores / keys.shape[-1]**0.5, dim=-1
)
attn_weights = self.dropout(attn_weights)

context_vec = attn_weights @ values
return context_vec

torch.manual_seed(123)

context_length = batch.shape[1]
d_in = 3
d_out = 2
ca = CausalAttention(d_in, d_out, context_length, 0.0)

context_vecs = ca(batch)

print(context_vecs)
print("context_vecs.shape:", context_vecs.shape)
```
## Rozszerzenie mechanizmu Single-Head Attention do Multi-Head Attention

W praktyce **multi-head attention** wykonuje wiele głów self-attention, z których każda ma **własne wyuczone projekcje**, a następnie łączy ich wyniki.<sup>[[1]](#references)</sup>

### Przykład kodu

Poprzednią implementację można było opakować i wywołać raz dla każdej głowy, jednak poniższa zoptymalizowana wersja przetwarza wszystkie głowy jednocześnie i unika kosztownych pętli w Pythonie. Wymiar embeddingu jest dzielony równo między głowy: na przykład ośmiowymiarowy embedding tokenu przy dwóch głowach daje każdej głowie cztery wymiary. W związku z tym `d_out` musi być podzielne przez `num_heads`.<sup>[[2]](#references)</sup>
```python
class MultiHeadAttention(nn.Module):
def __init__(self, d_in, d_out, context_length, dropout, num_heads, qkv_bias=False):
super().__init__()
assert (d_out % num_heads == 0), \
"d_out must be divisible by num_heads"

self.d_out = d_out
self.num_heads = num_heads
self.head_dim = d_out // num_heads # Reduce the projection dim to match desired output dim

self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.out_proj = nn.Linear(d_out, d_out)  # Linear layer to combine head outputs
self.dropout = nn.Dropout(dropout)
self.register_buffer(
"mask",
torch.triu(torch.ones(context_length, context_length),
diagonal=1)
)

def forward(self, x):
b, num_tokens, d_in = x.shape
# b is the num of batches
# num_tokens is the number of tokens per batch
# d_in is the dimensions er token

keys = self.W_key(x) # Shape: (b, num_tokens, d_out)
queries = self.W_query(x)
values = self.W_value(x)

# We implicitly split the matrix by adding a `num_heads` dimension
# Unroll last dim: (b, num_tokens, d_out) -> (b, num_tokens, num_heads, head_dim)
keys = keys.view(b, num_tokens, self.num_heads, self.head_dim)
values = values.view(b, num_tokens, self.num_heads, self.head_dim)
queries = queries.view(b, num_tokens, self.num_heads, self.head_dim)

# Transpose: (b, num_tokens, num_heads, head_dim) -> (b, num_heads, num_tokens, head_dim)
keys = keys.transpose(1, 2)
queries = queries.transpose(1, 2)
values = values.transpose(1, 2)

# Compute scaled dot-product attention (aka self-attention) with a causal mask
attn_scores = queries @ keys.transpose(2, 3)  # Dot product for each head

# Original mask truncated to the number of tokens and converted to boolean
mask_bool = self.mask.bool()[:num_tokens, :num_tokens]

# Use the mask to fill attention scores
attn_scores.masked_fill_(mask_bool, -torch.inf)

attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)
attn_weights = self.dropout(attn_weights)

# Shape: (b, num_tokens, num_heads, head_dim)
context_vec = (attn_weights @ values).transpose(1, 2)

# Combine heads, where self.d_out = self.num_heads * self.head_dim
context_vec = context_vec.contiguous().view(b, num_tokens, self.d_out)
context_vec = self.out_proj(context_vec) # optional projection

return context_vec

torch.manual_seed(123)

batch_size, context_length, d_in = batch.shape
d_out = 2
mha = MultiHeadAttention(d_in, d_out, context_length, 0.0, num_heads=2)

context_vecs = mha(batch)

print(context_vecs)
print("context_vecs.shape:", context_vecs.shape)

```
For another compact and efficient implementation you could use klasę [`torch.nn.MultiheadAttention`](https://pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html) w PyTorch.

> [!TIP]
> Krótka odpowiedź ChatGPT na pytanie, dlaczego lepiej dzielić wymiary tokenów między heads, zamiast pozwalać każdemu head sprawdzać wszystkie wymiary wszystkich tokenów:
>
> Chociaż umożliwienie każdemu head przetwarzania wszystkich wymiarów embeddingu może wydawać się korzystne, ponieważ każdy head miałby dostęp do pełnej informacji, standardową praktyką jest **dzielenie wymiarów embeddingu między heads**. Takie podejście zapewnia równowagę między wydajnością obliczeniową a skutecznością modelu oraz zachęca każdy head do uczenia się zróżnicowanych reprezentacji. Dlatego dzielenie wymiarów embeddingu jest zazwyczaj preferowane zamiast pozwalania każdemu head sprawdzać wszystkie wymiary.
