## Neural Network의 Attention 메커니즘과 Self-Attention

Attention 메커니즘은 Neural Network가 **출력의 각 부분을 생성할 때 입력의 특정 부분에 집중**할 수 있도록 합니다. 서로 다른 입력에 서로 다른 가중치를 할당하여, 모델이 현재 작업에 가장 관련성이 높은 입력을 판단하도록 돕습니다. 이는 정확한 번역을 위해 전체 문장의 맥락을 이해해야 하는 machine translation과 같은 작업에서 매우 중요합니다.<sup>[[1]](#references)</sup>

> [!TIP]
> 이 네 번째 단계의 목표는 매우 간단합니다: **일부 attention 메커니즘을 적용하는 것**입니다. 이는 **반복되는 여러 레이어**로 구성되며, **LLM을 학습하는 데 사용되는 현재 문장에서 어휘의 한 단어와 그 주변 단어 간의 관계를 포착**합니다.\
> 이를 위해 많은 레이어가 사용되므로, 많은 trainable parameters가 이 정보를 포착하게 됩니다.

### Attention 메커니즘 이해하기

언어 번역에 사용되는 전통적인 sequence-to-sequence 모델에서는 입력 sequence를 고정된 크기의 context vector로 인코딩합니다. 그러나 고정된 크기의 context vector가 필요한 모든 정보를 담지 못할 수 있기 때문에, 이 방식은 긴 문장에서 어려움을 겪습니다. Attention 메커니즘은 모델이 각 출력 token을 생성할 때 모든 입력 token을 고려할 수 있도록 하여 이러한 한계를 해결합니다.

#### 예시: Machine Translation

독일어 문장 "Kannst du mir helfen diesen Satz zu übersetzen"을 영어로 번역한다고 가정해 보겠습니다. 언어 간 문법 구조의 차이 때문에 단어 대 단어 번역은 문법적으로 올바른 영어 문장을 만들지 못합니다. Attention 메커니즘을 사용하면 모델이 출력 문장의 각 단어를 생성할 때 입력 문장의 관련 부분에 집중할 수 있으므로, 더 정확하고 일관된 번역을 생성할 수 있습니다.

### Self-Attention 소개

Self-attention 또는 intra-attention은 하나의 sequence 내부에 attention을 적용하여 해당 sequence의 표현을 계산하는 메커니즘입니다. 이를 통해 sequence의 각 token은 다른 모든 token에 attention할 수 있으며, sequence에서의 거리에 관계없이 token 간의 dependency를 모델이 포착하도록 돕습니다.

#### 핵심 개념

- **Tokens**: 입력 sequence의 개별 요소(예: 문장의 단어).
- **Embeddings**: token의 vector 표현으로, semantic information을 담고 있습니다.
- **Attention Weights**: 다른 token과 비교했을 때 각 token의 중요도를 결정하는 값입니다.

3. **Context Vector 계산**: 각 단어의 embedding에 해당 attention weight를 곱한 다음 결과를 모두 더합니다.

## Trainable Weights를 사용한 Self-Attention

실제로 self-attention 메커니즘은 **trainable weights**를 사용하여 query, key, value에 대한 최적의 표현을 학습합니다. 여기에는 세 개의 weight matrix가 도입됩니다:<sup>[[1]](#references)</sup>

<figure><img src="../../images/image (10) (1) (1).png" alt="" width="239"><figcaption></figcaption></figure>

query는 앞에서 사용한 data이며, keys와 values matrix는 단순한 random-trainable matrix입니다.

#### Step 1: Queries, Keys, Values 계산

각 token은 정의된 matrix에 해당 dimension 값을 곱하여 고유한 query, key, value matrix를 갖게 됩니다.

<figure><img src="../../images/image (11).png" alt="" width="253"><figcaption></figcaption></figure>

이 matrix들은 원래 embedding을 attention 계산에 적합한 새로운 space로 변환합니다.

**예시**

다음과 같다고 가정합니다.

- Input dimension `din=3` (embedding size)
- Output dimension `dout=2` (query, key, value에 사용할 원하는 dimension)

Weight matrix 초기화:
```python
import torch.nn as nn

d_in = 3
d_out = 2

W_query = nn.Parameter(torch.rand(d_in, d_out))
W_key = nn.Parameter(torch.rand(d_in, d_out))
W_value = nn.Parameter(torch.rand(d_in, d_out))
```
쿼리, 키, 값 계산:
```python
queries = torch.matmul(inputs, W_query)
keys = torch.matmul(inputs, W_key)
values = torch.matmul(inputs, W_value)
```

### Code Example

[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb)의 예제를 사용하면, 앞에서 설명한 self-attention 기능을 구현하는 다음 class를 확인할 수 있습니다:<sup>[[2]](#references)</sup>
```python
import torch

inputs = torch.tensor(
[[0.43, 0.15, 0.89], # Your     (x^1)
[0.55, 0.87, 0.66], # journey  (x^2)
[0.57, 0.85, 0.64], # starts   (x^3)
[0.22, 0.58, 0.33], # with     (x^4)
[0.77, 0.25, 0.10], # one      (x^5)
[0.05, 0.80, 0.55]] # step     (x^6)
)

import torch.nn as nn
class SelfAttention_v2(nn.Module):

def __init__(self, d_in, d_out, qkv_bias=False):
super().__init__()
self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)

def forward(self, x):
keys = self.W_key(x)
queries = self.W_query(x)
values = self.W_value(x)

attn_scores = queries @ keys.T
attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)

context_vec = attn_weights @ values
return context_vec

d_in=3
d_out=2
torch.manual_seed(789)
sa_v2 = SelfAttention_v2(d_in, d_out)
print(sa_v2(inputs))
```
> [!TIP]
> 행렬을 random 값으로 초기화하는 대신 `nn.Linear`를 사용하여 모든 weight를 학습할 parameters로 표시합니다.

## Causal Attention: 미래 단어 숨기기

LLM에서는 **다음 token을 예측**하기 위해 현재 위치보다 앞에 나타나는 token만 고려하도록 모델을 구성해야 합니다. **Causal attention**은 **masked attention**이라고도 하며, 미래 token에 접근하지 못하도록 attention mechanism을 수정하여 이를 구현합니다.<sup>[[1]](#references)</sup>

### Causal Attention Mask 적용

Causal attention을 구현하려면 **softmax 연산 전에** attention scores에 mask를 적용하여 나머지 scores의 합이 계속 1이 되도록 합니다. 이 mask는 미래 token의 attention scores를 negative infinity로 설정하여 softmax 이후 해당 attention weights가 0이 되도록 합니다.

**단계**

1. **Attention Scores 계산**: 이전과 동일합니다.
2. **Mask 적용**: 대각선 위를 negative infinity로 채운 upper triangular matrix를 사용합니다.

```python
mask = torch.triu(torch.ones(seq_len, seq_len), diagonal=1) * float('-inf')
masked_scores = attention_scores + mask
```

3. **Softmax 적용**: masked scores를 사용하여 attention weights를 계산합니다.

```python
attention_weights = torch.softmax(masked_scores, dim=-1)
```

### Dropout을 사용하여 추가 Attention Weights Masking

**overfitting을 방지**하기 위해 softmax 연산 후 attention weights에 **dropout**을 적용할 수 있습니다. Dropout은 training 중 **일부 attention weights를 무작위로 0으로 설정**합니다.
```python
dropout = nn.Dropout(p=0.5)
attention_weights = dropout(attention_weights)
```
일반적인 dropout 비율은 약 10~20%입니다.

### 코드 예제

[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb)의 코드 예제:<sup>[[2]](#references)</sup>
```python
import torch
import torch.nn as nn

inputs = torch.tensor(
[[0.43, 0.15, 0.89], # Your     (x^1)
[0.55, 0.87, 0.66], # journey  (x^2)
[0.57, 0.85, 0.64], # starts   (x^3)
[0.22, 0.58, 0.33], # with     (x^4)
[0.77, 0.25, 0.10], # one      (x^5)
[0.05, 0.80, 0.55]] # step     (x^6)
)

batch = torch.stack((inputs, inputs), dim=0)
print(batch.shape)

class CausalAttention(nn.Module):

def __init__(self, d_in, d_out, context_length,
dropout, qkv_bias=False):
super().__init__()
self.d_out = d_out
self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.dropout = nn.Dropout(dropout)
self.register_buffer('mask', torch.triu(torch.ones(context_length, context_length), diagonal=1)) # New

def forward(self, x):
b, num_tokens, d_in = x.shape
# b is the num of batches
# num_tokens is the number of tokens per batch
# d_in is the dimensions er token

keys = self.W_key(x) # This generates the keys of the tokens
queries = self.W_query(x)
values = self.W_value(x)

attn_scores = queries @ keys.transpose(1, 2) # Moves the third dimension to the second one and the second one to the third one to be able to multiply
attn_scores.masked_fill_(  # New, _ ops are in-place
self.mask.bool()[:num_tokens, :num_tokens], -torch.inf)  # `:num_tokens` to account for cases where the number of tokens in the batch is smaller than the supported context_size
attn_weights = torch.softmax(
attn_scores / keys.shape[-1]**0.5, dim=-1
)
attn_weights = self.dropout(attn_weights)

context_vec = attn_weights @ values
return context_vec

torch.manual_seed(123)

context_length = batch.shape[1]
d_in = 3
d_out = 2
ca = CausalAttention(d_in, d_out, context_length, 0.0)

context_vecs = ca(batch)

print(context_vecs)
print("context_vecs.shape:", context_vecs.shape)
```
## Single-Head Attention을 Multi-Head Attention으로 확장하기

실질적인 의미에서 **Multi-head attention**은 **self-attention** 함수를 여러 인스턴스로 실행하는 것으로, 각 인스턴스는 **자체 가중치**를 사용하여 서로 다른 최종 벡터를 계산합니다.<sup>[[1]](#references)</sup>

### Code Example

이전 코드를 재사용하고 이를 여러 번 실행하는 wrapper만 추가할 수도 있지만, 다음은 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch03/01_main-chapter-code/ch03.ipynb)의 더 최적화된 버전으로, 모든 head를 동시에 처리합니다(비용이 큰 for loops의 수를 줄임). 코드에서 볼 수 있듯이 각 token의 dimensions는 head의 수에 따라 서로 다른 dimensions로 나뉩니다. 따라서 token이 8개의 dimensions를 가지고 있고 3개의 head를 사용하려는 경우, dimensions는 4개의 dimensions를 가진 2개의 배열로 나뉘며 각 head는 그중 하나를 사용합니다.<sup>[[2]](#references)</sup>
```python
class MultiHeadAttention(nn.Module):
def __init__(self, d_in, d_out, context_length, dropout, num_heads, qkv_bias=False):
super().__init__()
assert (d_out % num_heads == 0), \
"d_out must be divisible by num_heads"

self.d_out = d_out
self.num_heads = num_heads
self.head_dim = d_out // num_heads # Reduce the projection dim to match desired output dim

self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_key = nn.Linear(d_in, d_out, bias=qkv_bias)
self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
self.out_proj = nn.Linear(d_out, d_out)  # Linear layer to combine head outputs
self.dropout = nn.Dropout(dropout)
self.register_buffer(
"mask",
torch.triu(torch.ones(context_length, context_length),
diagonal=1)
)

def forward(self, x):
b, num_tokens, d_in = x.shape
# b is the num of batches
# num_tokens is the number of tokens per batch
# d_in is the dimensions er token

keys = self.W_key(x) # Shape: (b, num_tokens, d_out)
queries = self.W_query(x)
values = self.W_value(x)

# We implicitly split the matrix by adding a `num_heads` dimension
# Unroll last dim: (b, num_tokens, d_out) -> (b, num_tokens, num_heads, head_dim)
keys = keys.view(b, num_tokens, self.num_heads, self.head_dim)
values = values.view(b, num_tokens, self.num_heads, self.head_dim)
queries = queries.view(b, num_tokens, self.num_heads, self.head_dim)

# Transpose: (b, num_tokens, num_heads, head_dim) -> (b, num_heads, num_tokens, head_dim)
keys = keys.transpose(1, 2)
queries = queries.transpose(1, 2)
values = values.transpose(1, 2)

# Compute scaled dot-product attention (aka self-attention) with a causal mask
attn_scores = queries @ keys.transpose(2, 3)  # Dot product for each head

# Original mask truncated to the number of tokens and converted to boolean
mask_bool = self.mask.bool()[:num_tokens, :num_tokens]

# Use the mask to fill attention scores
attn_scores.masked_fill_(mask_bool, -torch.inf)

attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)
attn_weights = self.dropout(attn_weights)

# Shape: (b, num_tokens, num_heads, head_dim)
context_vec = (attn_weights @ values).transpose(1, 2)

# Combine heads, where self.d_out = self.num_heads * self.head_dim
context_vec = context_vec.contiguous().view(b, num_tokens, self.d_out)
context_vec = self.out_proj(context_vec) # optional projection

return context_vec

torch.manual_seed(123)

batch_size, context_length, d_in = batch.shape
d_out = 2
mha = MultiHeadAttention(d_in, d_out, context_length, 0.0, num_heads=2)

context_vecs = mha(batch)

print(context_vecs)
print("context_vecs.shape:", context_vecs.shape)

```
또 다른 compact하고 효율적인 구현을 위해 PyTorch의 [`torch.nn.MultiheadAttention`](https://pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html) 클래스를 사용할 수 있습니다.

> [!TIP]
> 각 head가 모든 token의 모든 차원을 확인하도록 하는 대신 token의 차원을 head 간에 나누는 것이 더 나은 이유에 대한 ChatGPT의 간단한 답변:
>
> 각 head가 모든 embedding 차원을 처리하도록 하면 각 head가 전체 정보에 접근할 수 있어 유리해 보일 수 있지만, 일반적으로는 **embedding 차원을 head 간에 나눕니다**. 이 방식은 계산 효율성과 모델 성능 사이의 균형을 맞추고, 각 head가 서로 다른 representation을 학습하도록 유도합니다. 따라서 각 head가 모든 차원을 확인하도록 하는 것보다 embedding 차원을 나누는 방식이 일반적으로 선호됩니다.
