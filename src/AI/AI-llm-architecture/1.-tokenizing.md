## Tokenisierung

**Tokenisierung** ist der Prozess, Daten wie Text in kleinere, handhabbare Einheiten, sogenannte _Tokens_, zu zerlegen. Jedem Token wird anschließend eine eindeutige numerische Kennung (ID) zugewiesen. Dies ist ein grundlegender Schritt bei der Vorbereitung von Text für die Verarbeitung durch Machine-Learning-Modelle, insbesondere bei der Verarbeitung natürlicher Sprache (NLP).<sup>[[1]](#references)</sup>

> [!TIP]
> Das Ziel dieser anfänglichen Phase ist einfach: **Die Eingabe auf nützliche Weise in Tokens (IDs) aufzuteilen**.

### **Wie Tokenisierung funktioniert**

1. **Aufteilen des Textes:**
- **Basic Tokenizer:** Ein einfacher Tokenizer könnte Text in einzelne Wörter und Satzzeichen aufteilen und Leerzeichen entfernen.
- _Beispiel:_\
Text: `"Hello, world!"`\
Tokens: `["Hello", ",", "world", "!"]`
2. **Erstellen eines Vokabulars:**
- Um Tokens in numerische IDs umzuwandeln, wird ein **Vokabular** erstellt. Dieses Vokabular listet alle eindeutigen Tokens (Wörter und Symbole) auf und weist jedem eine bestimmte ID zu.
- **Special Tokens:** Dies sind spezielle Symbole, die dem Vokabular hinzugefügt werden, um verschiedene Szenarien zu behandeln:
- `[BOS]` (Beginning of Sequence): Kennzeichnet den Beginn eines Textes.
- `[EOS]` (End of Sequence): Kennzeichnet das Ende eines Textes.
- `[PAD]` (Padding): Wird verwendet, um alle Sequenzen in einem Batch auf dieselbe Länge zu bringen.
- `[UNK]` (Unknown): Repräsentiert Tokens, die nicht im Vokabular enthalten sind.
- _Beispiel:_\
Wenn `"Hello"` die ID `64`, `","` die ID `455`, `"world"` die ID `78` und `"!"` die ID `467` zugewiesen wird, dann gilt:\
`"Hello, world!"` → `[64, 455, 78, 467]`
- **Umgang mit unbekannten Wörtern:**\
Wenn ein Wort wie `"Bye"` nicht im Vokabular enthalten ist, wird es durch `[UNK]` ersetzt.\
`"Bye, world!"` → `["[UNK]", ",", "world", "!"]` → `[987, 455, 78, 467]`\
_(Angenommen, `[UNK]` hat die ID `987`)_

### **Fortgeschrittene Tokenisierungsmethoden**

Während der Basic Tokenizer für einfache Texte gut funktioniert, weist er Einschränkungen auf, insbesondere bei großen Vokabularen und beim Umgang mit neuen oder seltenen Wörtern. Fortgeschrittene Tokenisierungsmethoden beheben diese Probleme, indem sie Text in kleinere Untereinheiten zerlegen oder den Tokenisierungsprozess optimieren.

1. **Byte Pair Encoding (BPE):**
- **Zweck:** Reduziert die Größe des Vokabulars und verarbeitet seltene oder unbekannte Wörter, indem sie in häufig vorkommende Byte-Paare zerlegt werden.
- **Funktionsweise:**
- Beginnt mit einzelnen Zeichen als Tokens.
- Führt iterativ die häufigsten Token-Paare zu einem einzelnen Token zusammen.
- Fährt fort, bis keine häufigen Paare mehr zusammengeführt werden können.
- **Vorteile:**
- Ein Byte-Level-BPE-Tokenizer mit einem vollständigen Byte-Alphabet kann beliebige Eingaben ohne ein `[UNK]`-Token darstellen; zeichenbasierte Varianten hängen weiterhin von ihrem Basisalphabet ab.
- Effizienteres und flexibleres Vokabular.
- _Beispiel:_\
`"playing"` könnte als `["play", "ing"]` tokenisiert werden, wenn `"play"` und `"ing"` häufig vorkommende Subwords sind.
2. **WordPiece:**
- **Verwendet von:** Modellen wie BERT.
- **Zweck:** Ähnlich wie BPE zerlegt es Wörter in Subword-Einheiten, um unbekannte Wörter zu verarbeiten und die Vokabulargröße zu reduzieren.
- **Funktionsweise:**
- Beginnt mit einem Basisvokabular aus einzelnen Zeichen.
- Fügt iterativ das häufigste Subword hinzu, das die Wahrscheinlichkeit der Trainingsdaten maximiert.
- Verwendet ein probabilistisches Modell, um zu entscheiden, welche Subwords zusammengeführt werden.
- **Vorteile:**
- Stellt ein Gleichgewicht zwischen einer handhabbaren Vokabulargröße und der effektiven Darstellung von Wörtern her.
- Verarbeitet seltene und zusammengesetzte Wörter effizient.
- _Beispiel:_\
`"unhappiness"` könnte abhängig vom Vokabular als `["un", "happiness"]` oder `["un", "happy", "ness"]` tokenisiert werden.
3. **Unigram Language Model:**
- **Verwendet von:** Modellen wie SentencePiece.
- **Zweck:** Verwendet ein probabilistisches Modell, um die wahrscheinlichste Menge an Subword-Tokens zu bestimmen.
- **Funktionsweise:**
- Beginnt mit einer großen Menge potenzieller Tokens.
- Entfernt iterativ die Tokens, die die Wahrscheinlichkeit des Modells für die Trainingsdaten am wenigsten verbessern.
- Finalisiert ein Vokabular, in dem jedes Wort durch die wahrscheinlichsten Subword-Einheiten dargestellt wird.
- **Vorteile:**
- Ist flexibel und kann Sprache natürlicher modellieren.
- Führt häufig zu effizienteren und kompakteren Tokenisierungen.
- _Beispiel:_\
`"internationalization"` könnte in kleinere, bedeutungsvolle Subwords wie `["international", "ization"]` tokenisiert werden.

## Codebeispiel

Sehen wir uns dies anhand eines Codebeispiels aus [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb) genauer an:<sup>[[2]](#references)</sup>
```python
# Download a text to pre-train the model
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

# Tokenize the code using GPT2 tokenizer version
import tiktoken
token_ids = tiktoken.get_encoding("gpt2").encode(raw_text)

# Print first 50 tokens
print(token_ids[:50])
#[40, 367, 2885, 1464, 1807, 3619, 402, 271, 10899, 2138, 257, 7026, 15632, 438, 2016, 257, 922, 5891, 1576, 438, 568, 340, 373, 645, 1049, 5975, 284, 502, 284, 3285, 326, 11, 287, 262, 6001, 286, 465, 13476, 11, 339, 550, 5710, 465, 12036, 11, 6405, 257, 5527, 27075, 11]
```
