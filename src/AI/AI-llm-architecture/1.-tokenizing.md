## Tokenizing

Το **Tokenizing** είναι η διαδικασία διάσπασης δεδομένων, όπως κειμένου, σε μικρότερα, διαχειρίσιμα τμήματα που ονομάζονται _tokens_. Σε κάθε token αντιστοιχεί στη συνέχεια ένα μοναδικό αριθμητικό αναγνωριστικό (ID). Αυτό είναι ένα θεμελιώδες βήμα για την προετοιμασία κειμένου προς επεξεργασία από μοντέλα machine learning, ιδιαίτερα στην επεξεργασία φυσικής γλώσσας (NLP).<sup>[[1]](#references)</sup>

> [!TIP]
> Ο στόχος αυτής της αρχικής φάσης είναι απλός: **διαχωρισμός του input σε tokens (IDs) με χρήσιμο τρόπο**.

### **Πώς λειτουργεί το Tokenizing**

1. **Διάσπαση του κειμένου:**
- **Basic Tokenizer:** Ένα απλό tokenizer μπορεί να διαχωρίζει το κείμενο σε μεμονωμένες λέξεις και σημεία στίξης, αφαιρώντας τα κενά.
- _Παράδειγμα:_\
Κείμενο: `"Hello, world!"`\
Tokens: `["Hello", ",", "world", "!"]`
2. **Δημιουργία Vocabulary:**
- Για τη μετατροπή των tokens σε αριθμητικά IDs, δημιουργείται ένα **vocabulary**. Αυτό το vocabulary περιλαμβάνει όλα τα μοναδικά tokens (λέξεις και σύμβολα) και αντιστοιχίζει σε καθένα ένα συγκεκριμένο ID.
- **Special Tokens:** Πρόκειται για ειδικά σύμβολα που προστίθενται στο vocabulary για τη διαχείριση διαφόρων σεναρίων:
- `[BOS]` (Beginning of Sequence): Υποδεικνύει την αρχή ενός κειμένου.
- `[EOS]` (End of Sequence): Υποδεικνύει το τέλος ενός κειμένου.
- `[PAD]` (Padding): Χρησιμοποιείται ώστε όλες οι sequences σε ένα batch να έχουν το ίδιο μήκος.
- `[UNK]` (Unknown): Αναπαριστά tokens που δεν υπάρχουν στο vocabulary.
- _Παράδειγμα:_\
Αν στο `"Hello"` αντιστοιχεί το ID `64`, στο `","` το `455`, στο `"world"` το `78` και στο `"!"` το `467`, τότε:\
`"Hello, world!"` → `[64, 455, 78, 467]`
- **Διαχείριση άγνωστων λέξεων:**\
Αν μια λέξη όπως η `"Bye"` δεν υπάρχει στο vocabulary, αντικαθίσταται από `[UNK]`.\
`"Bye, world!"` → `["[UNK]", ",", "world", "!"]` → `[987, 455, 78, 467]`\
_(Με την υπόθεση ότι το `[UNK]` έχει ID `987`)_

### **Προηγμένες μέθοδοι Tokenizing**

Ενώ το basic tokenizer λειτουργεί καλά για απλά κείμενα, έχει περιορισμούς, ιδιαίτερα με μεγάλα vocabularies και στη διαχείριση νέων ή σπάνιων λέξεων. Οι προηγμένες μέθοδοι tokenizing αντιμετωπίζουν αυτά τα ζητήματα διασπώντας το κείμενο σε μικρότερες υπομονάδες ή βελτιστοποιώντας τη διαδικασία tokenization.

1. **Byte Pair Encoding (BPE):**
- **Σκοπός:** Μειώνει το μέγεθος του vocabulary και διαχειρίζεται σπάνιες ή άγνωστες λέξεις διασπώντας τες σε byte pairs που εμφανίζονται συχνά.
- **Πώς λειτουργεί:**
- Ξεκινά με μεμονωμένους χαρακτήρες ως tokens.
- Συγχωνεύει επαναληπτικά τα συχνότερα ζεύγη tokens σε ένα ενιαίο token.
- Συνεχίζει μέχρι να μην είναι δυνατή η συγχώνευση άλλων συχνών ζευγών.
- **Οφέλη:**
- Ένα byte-level BPE tokenizer με πλήρες byte alphabet μπορεί να αναπαραστήσει αυθαίρετο input χωρίς token `[UNK]`· οι character-based παραλλαγές εξακολουθούν να εξαρτώνται από το βασικό alphabet τους.
- Αποδοτικότερο και πιο ευέλικτο vocabulary.
- _Παράδειγμα:_\
Το `"playing"` μπορεί να γίνει tokenize ως `["play", "ing"]` αν τα `"play"` και `"ing"` είναι συχνά subwords.
2. **WordPiece:**
- **Χρησιμοποιείται από:** Μοντέλα όπως το BERT.
- **Σκοπός:** Παρόμοια με το BPE, διασπά τις λέξεις σε subword units για τη διαχείριση άγνωστων λέξεων και τη μείωση του μεγέθους του vocabulary.
- **Πώς λειτουργεί:**
- Ξεκινά με ένα βασικό vocabulary μεμονωμένων χαρακτήρων.
- Προσθέτει επαναληπτικά το συχνότερο subword που μεγιστοποιεί την πιθανότητα των training data.
- Χρησιμοποιεί probabilistic model για να αποφασίσει ποια subwords θα συγχωνευτούν.
- **Οφέλη:**
- Ισορροπεί μεταξύ ενός διαχειρίσιμου μεγέθους vocabulary και της αποτελεσματικής αναπαράστασης λέξεων.
- Διαχειρίζεται αποτελεσματικά σπάνιες και σύνθετες λέξεις.
- _Παράδειγμα:_\
Το `"unhappiness"` μπορεί να γίνει tokenize ως `["un", "happiness"]` ή `["un", "happy", "ness"]`, ανάλογα με το vocabulary.
3. **Unigram Language Model:**
- **Χρησιμοποιείται από:** Μοντέλα όπως το SentencePiece.
- **Σκοπός:** Χρησιμοποιεί ένα probabilistic model για να προσδιορίσει το πιθανότερο σύνολο subword tokens.
- **Πώς λειτουργεί:**
- Ξεκινά με ένα μεγάλο σύνολο πιθανών tokens.
- Αφαιρεί επαναληπτικά τα tokens που βελτιώνουν λιγότερο την πιθανότητα του μοντέλου για τα training data.
- Οριστικοποιεί ένα vocabulary όπου κάθε λέξη αναπαρίσταται από τις πιθανότερες subword units.
- **Οφέλη:**
- Είναι ευέλικτο και μπορεί να μοντελοποιεί τη γλώσσα πιο φυσικά.
- Συχνά οδηγεί σε αποδοτικότερα και πιο συμπαγή tokenizations.
- _Παράδειγμα:_\
Το `"internationalization"` μπορεί να γίνει tokenize σε μικρότερα, νοηματικά subwords όπως `["international", "ization"]`.

## Παράδειγμα Κώδικα

Ας το κατανοήσουμε καλύτερα μέσα από ένα παράδειγμα κώδικα από το [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[2]](#references)</sup>
```python
# Download a text to pre-train the model
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

# Tokenize the code using GPT2 tokenizer version
import tiktoken
token_ids = tiktoken.get_encoding("gpt2").encode(raw_text)

# Print first 50 tokens
print(token_ids[:50])
#[40, 367, 2885, 1464, 1807, 3619, 402, 271, 10899, 2138, 257, 7026, 15632, 438, 2016, 257, 922, 5891, 1576, 438, 568, 340, 373, 645, 1049, 5975, 284, 502, 284, 3285, 326, 11, 287, 262, 6001, 286, 465, 13476, 11, 339, 550, 5710, 465, 12036, 11, 6405, 257, 5527, 27075, 11]
```
