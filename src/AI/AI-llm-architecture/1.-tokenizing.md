## Tokenizing

**Tokenizing** डेटा, जैसे text, को _tokens_ नामक छोटे, प्रबंधनीय हिस्सों में विभाजित करने की प्रक्रिया है। इसके बाद प्रत्येक token को एक विशिष्ट संख्यात्मक identifier (ID) दिया जाता है। यह text को machine learning models, विशेष रूप से natural language processing (NLP), द्वारा processing के लिए तैयार करने का एक मूलभूत चरण है।<sup>[[1]](#references)</sup>

> [!TIP]
> इस प्रारंभिक चरण का लक्ष्य सरल है: **input को उपयोगी तरीके से tokens (IDs) में विभाजित करना**।

### **Tokenizing कैसे काम करता है**

1. **Text को विभाजित करना:**
- **Basic Tokenizer:** एक सरल tokenizer text को अलग-अलग words और punctuation marks में विभाजित कर सकता है और spaces को हटा सकता है।
- _Example:_\
Text: `"Hello, world!"`\
Tokens: `["Hello", ",", "world", "!"]`
2. **Vocabulary बनाना:**
- Tokens को numerical IDs में बदलने के लिए एक **vocabulary** बनाई जाती है। यह vocabulary सभी unique tokens (words और symbols) की सूची बनाती है और प्रत्येक को एक specific ID देती है।
- **Special Tokens:** ये vocabulary में जोड़े गए special symbols होते हैं, जो विभिन्न scenarios को संभालते हैं:
- `[BOS]` (Beginning of Sequence): text की शुरुआत दर्शाता है।
- `[EOS]` (End of Sequence): text का अंत दर्शाता है।
- `[PAD]` (Padding): batch में सभी sequences की length समान बनाने के लिए उपयोग किया जाता है।
- `[UNK]` (Unknown): उन tokens को दर्शाता है जो vocabulary में मौजूद नहीं हैं।
- _Example:_\
यदि `"Hello"` को ID `64`, `","` को `455`, `"world"` को `78`, और `"!"` को `467` दिया गया है, तो:\
`"Hello, world!"` → `[64, 455, 78, 467]`
- **Unknown Words को संभालना:**\
यदि `"Bye"` जैसा कोई word vocabulary में नहीं है, तो उसे `[UNK]` से replace कर दिया जाता है।\
`"Bye, world!"` → `["[UNK]", ",", "world", "!"]` → `[987, 455, 78, 467]`\
_(मानते हुए कि `[UNK]` की ID `987` है)_

### **Advanced Tokenizing Methods**

Basic tokenizer सरल texts के लिए अच्छी तरह काम करता है, लेकिन इसकी कुछ limitations हैं, विशेष रूप से बड़ी vocabularies और नए या rare words को संभालने में। Advanced tokenizing methods text को छोटे subunits में विभाजित करके या tokenization process को optimize करके इन समस्याओं को हल करते हैं।

1. **Byte Pair Encoding (BPE):**
- **Purpose:** vocabulary का size कम करता है और rare या unknown words को frequently occurring byte pairs में विभाजित करके संभालता है।
- **How It Works:**
- Individual characters को tokens के रूप में लेकर शुरू करता है।
- Tokens के सबसे frequent pairs को iteratively merge करके एक single token बनाता है।
- तब तक जारी रहता है जब तक कोई और frequent pair merge न किया जा सके।
- **Benefits:**
- Complete byte alphabet वाला byte-level BPE tokenizer किसी `[UNK]` token के बिना arbitrary input को represent कर सकता है; character-based variants अभी भी अपने base alphabet पर निर्भर करते हैं।
- अधिक efficient और flexible vocabulary।
- _Example:_\
`"playing"` को `["play", "ing"]` के रूप में tokenize किया जा सकता है, यदि `"play"` और `"ing"` frequent subwords हों।
2. **WordPiece:**
- **Used By:** BERT जैसे Models।
- **Purpose:** BPE के समान, यह unknown words को संभालने और vocabulary size कम करने के लिए words को subword units में विभाजित करता है।
- **How It Works:**
- Individual characters की base vocabulary से शुरू होता है।
- Training data की likelihood को अधिकतम करने वाले सबसे frequent subword को iteratively add करता है।
- यह तय करने के लिए probabilistic model का उपयोग करता है कि किन subwords को merge किया जाए।
- **Benefits:**
- Manageable vocabulary size और words को effectively represent करने के बीच संतुलन बनाता है।
- Rare और compound words को efficiently संभालता है।
- _Example:_\
`"unhappiness"` को vocabulary के आधार पर `["un", "happiness"]` या `["un", "happy", "ness"]` के रूप में tokenize किया जा सकता है।
3. **Unigram Language Model:**
- **Used By:** SentencePiece जैसे Models।
- **Purpose:** subword tokens के सबसे संभावित set को निर्धारित करने के लिए probabilistic model का उपयोग करता है।
- **How It Works:**
- Potential tokens के एक बड़े set से शुरू होता है।
- उन tokens को iteratively remove करता है जो training data की model probability में सबसे कम सुधार करते हैं।
- ऐसी vocabulary को finalize करता है जिसमें प्रत्येक word को सबसे probable subword units द्वारा represent किया जाता है।
- **Benefits:**
- Flexible है और language को अधिक naturally model कर सकता है।
- अक्सर अधिक efficient और compact tokenizations उत्पन्न करता है।
- _Example:_\
`"internationalization"` को छोटे, meaningful subwords जैसे `["international", "ization"]` में tokenize किया जा सकता है।

## Code Example

आइए इसे [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb) के code example से बेहतर समझते हैं:<sup>[[2]](#references)</sup>
```python
# Download a text to pre-train the model
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

# Tokenize the code using GPT2 tokenizer version
import tiktoken
token_ids = tiktoken.get_encoding("gpt2").encode(raw_text)

# Print first 50 tokens
print(token_ids[:50])
#[40, 367, 2885, 1464, 1807, 3619, 402, 271, 10899, 2138, 257, 7026, 15632, 438, 2016, 257, 922, 5891, 1576, 438, 568, 340, 373, 645, 1049, 5975, 284, 502, 284, 3285, 326, 11, 287, 262, 6001, 286, 465, 13476, 11, 339, 550, 5710, 465, 12036, 11, 6405, 257, 5527, 27075, 11]
```
