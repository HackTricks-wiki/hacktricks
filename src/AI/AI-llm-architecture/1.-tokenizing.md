## Tokenizing

**Tokenizing**은 텍스트와 같은 데이터를 _tokens_라고 하는 더 작고 관리하기 쉬운 단위로 나누는 과정입니다. 그런 다음 각 token에는 고유한 숫자 식별자(ID)가 할당됩니다. 이는 특히 자연어 처리(NLP)에서 machine learning model이 텍스트를 처리할 수 있도록 준비하는 기본 단계입니다.<sup>[[1]](#references)</sup>

> [!TIP]
> 이 초기 단계의 목표는 간단합니다. **입력을 유용한 방식으로 tokens (IDs)로 나누는 것**입니다.

### **Tokenizing 작동 방식**

1. **텍스트 분할:**
- **Basic Tokenizer:** 간단한 tokenizer는 텍스트를 개별 단어와 구두점으로 나누고 공백을 제거할 수 있습니다.
- _예시:_\
텍스트: `"Hello, world!"`\
Tokens: `["Hello", ",", "world", "!"]`
2. **Vocabulary 생성:**
- Tokens를 숫자 ID로 변환하려면 **vocabulary**를 생성합니다. 이 vocabulary에는 모든 고유한 tokens (단어와 기호)이 나열되며, 각 token에 특정 ID가 할당됩니다.
- **Special Tokens:** 다양한 상황을 처리하기 위해 vocabulary에 추가되는 특수 기호입니다.
- `[BOS]` (Beginning of Sequence): 텍스트의 시작을 나타냅니다.
- `[EOS]` (End of Sequence): 텍스트의 끝을 나타냅니다.
- `[PAD]` (Padding): batch의 모든 sequence를 동일한 길이로 만드는 데 사용됩니다.
- `[UNK]` (Unknown): vocabulary에 없는 tokens를 나타냅니다.
- _예시:_\
`"Hello"`에 ID `64`, `","`에 `455`, `"world"`에 `78`, `"!"`에 `467`이 할당되었다면 다음과 같습니다:\
`"Hello, world!"` → `[64, 455, 78, 467]`
- **알 수 없는 단어 처리:**\
`"Bye"`와 같은 단어가 vocabulary에 없으면 `[UNK]`로 대체됩니다.\
`"Bye, world!"` → `["[UNK]", ",", "world", "!"]` → `[987, 455, 78, 467]`\
_(`[UNK]`의 ID가 `987`이라고 가정)_

### **Advanced Tokenizing Methods**

Basic tokenizer는 단순한 텍스트에서 잘 작동하지만, 특히 큰 vocabulary를 사용하거나 새 단어 및 드문 단어를 처리할 때 한계가 있습니다. Advanced tokenizing methods는 텍스트를 더 작은 하위 단위로 나누거나 tokenization 프로세스를 최적화하여 이러한 문제를 해결합니다.

1. **Byte Pair Encoding (BPE):**
- **목적:** vocabulary의 크기를 줄이고, 자주 나타나는 byte pair로 분해하여 드물거나 알 수 없는 단어를 처리합니다.
- **작동 방식:**
- 개별 문자를 tokens로 사용하여 시작합니다.
- 가장 빈번하게 나타나는 token 쌍을 반복적으로 하나의 token으로 병합합니다.
- 더 이상 빈번한 쌍을 병합할 수 없을 때까지 계속합니다.
- **장점:**
- 완전한 byte alphabet을 사용하는 byte-level BPE tokenizer는 `[UNK]` token 없이 임의의 입력을 나타낼 수 있습니다. 반면 character-based variant는 여전히 기본 alphabet에 의존합니다.
- 더 효율적이고 유연한 vocabulary를 제공합니다.
- _예시:_\
`"playing"`은 `"play"`와 `"ing"`이 자주 나타나는 subword인 경우 `["play", "ing"]`로 tokenized될 수 있습니다.
2. **WordPiece:**
- **사용 모델:** BERT와 같은 model.
- **목적:** BPE와 유사하게 단어를 subword 단위로 나누어 알 수 없는 단어를 처리하고 vocabulary 크기를 줄입니다.
- **작동 방식:**
- 개별 문자로 구성된 기본 vocabulary에서 시작합니다.
- training data의 likelihood를 최대화하는 가장 빈번한 subword를 반복적으로 추가합니다.
- probabilistic model을 사용하여 어떤 subword를 병합할지 결정합니다.
- **장점:**
- 관리 가능한 vocabulary 크기와 단어의 효과적인 표현 사이에서 균형을 유지합니다.
- 드물거나 복합적인 단어를 효율적으로 처리합니다.
- _예시:_\
`"unhappiness"`는 vocabulary에 따라 `["un", "happiness"]` 또는 `["un", "happy", "ness"]`로 tokenized될 수 있습니다.
3. **Unigram Language Model:**
- **사용 모델:** SentencePiece와 같은 model.
- **목적:** 가장 가능성 높은 subword tokens 집합을 결정하기 위해 probabilistic model을 사용합니다.
- **작동 방식:**
- 가능한 tokens의 대규모 집합에서 시작합니다.
- training data의 model probability를 가장 적게 향상시키는 tokens를 반복적으로 제거합니다.
- 각 단어가 가장 가능성 높은 subword 단위로 표현되는 vocabulary를 확정합니다.
- **장점:**
- 유연하며 언어를 더 자연스럽게 model링할 수 있습니다.
- 더 효율적이고 간결한 tokenization 결과를 내는 경우가 많습니다.
- _예시:_\
`"internationalization"`은 `["international", "ization"]`과 같이 더 작고 의미 있는 subwords로 tokenized될 수 있습니다.

## Code Example

다음 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb)의 code example을 통해 이를 더 자세히 알아보겠습니다:<sup>[[2]](#references)</sup>
```python
# Download a text to pre-train the model
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

# Tokenize the code using GPT2 tokenizer version
import tiktoken
token_ids = tiktoken.get_encoding("gpt2").encode(raw_text)

# Print first 50 tokens
print(token_ids[:50])
#[40, 367, 2885, 1464, 1807, 3619, 402, 271, 10899, 2138, 257, 7026, 15632, 438, 2016, 257, 922, 5891, 1576, 438, 568, 340, 373, 645, 1049, 5975, 284, 502, 284, 3285, 326, 11, 287, 262, 6001, 286, 465, 13476, 11, 339, 550, 5710, 465, 12036, 11, 6405, 257, 5527, 27075, 11]
```
