## Tokenizing

**Tokenizing** とは、テキストなどのデータを、_tokens_ と呼ばれる、より小さく扱いやすい単位に分割するプロセスです。各 token には、一意の数値識別子（ID）が割り当てられます。これは、特に自然言語処理（NLP）において、machine learning model がテキストを処理できるよう準備するための基本的な手順です。<sup>[[1]](#references)</sup>

> [!TIP]
> この初期フェーズの目的は単純です。**入力を有用な方法で tokens（IDs）に分割すること**です。

### **Tokenizing の仕組み**

1. **テキストの分割:**
- **Basic Tokenizer:** 単純な tokenizer は、スペースを削除しながら、テキストを個々の単語と句読点に分割します。
- _例:_\
Text: `"Hello, world!"`\
Tokens: `["Hello", ",", "world", "!"]`
2. **Vocabulary の作成:**
- tokens を数値 ID に変換するため、**vocabulary** が作成されます。この vocabulary には、すべての一意な tokens（単語と記号）が一覧化され、それぞれに固有の ID が割り当てられます。
- **Special Tokens:** さまざまな状況に対応するため、vocabulary に追加される特殊な記号です。
- `[BOS]` (Beginning of Sequence): テキストの開始を示します。
- `[EOS]` (End of Sequence): テキストの終了を示します。
- `[PAD]` (Padding): batch 内のすべての sequence を同じ長さにするために使用されます。
- `[UNK]` (Unknown): vocabulary に含まれていない tokens を表します。
- _例:_\
`"Hello"` に ID `64`、`","` に `455`、`"world"` に `78`、`"!"` に `467` が割り当てられている場合:\
`"Hello, world!"` → `[64, 455, 78, 467]`
- **未知の単語の処理:**\
`"Bye"` のような単語が vocabulary に含まれていない場合、`[UNK]` に置き換えられます。\
`"Bye, world!"` → `["[UNK]", ",", "world", "!"]` → `[987, 455, 78, 467]`\
_（`[UNK]` の ID が `987` であると仮定）_

### **Advanced Tokenizing Methods**

Basic tokenizer は単純なテキストでは適切に機能しますが、大規模な vocabulary や、新しい単語・まれな単語の処理には制限があります。Advanced tokenizing methods は、テキストをより小さな subunits に分割したり、tokenization process を最適化したりすることで、これらの問題に対処します。

1. **Byte Pair Encoding (BPE):**
- **目的:** vocabulary のサイズを削減し、頻繁に出現する byte pairs に分解することで、まれな単語や未知の単語を処理します。
- **仕組み:**
- 個々の characters を tokens として開始します。
- 最も頻繁に出現する tokens の pair を、単一の token に繰り返し merge します。
- これ以上、頻出する pair を merge できなくなるまで続けます。
- **利点:**
- 完全な byte alphabet を持つ byte-level BPE tokenizer は、`[UNK]` token なしで任意の入力を表現できます。一方、character-based variant は、引き続き base alphabet に依存します。
- より効率的で柔軟な vocabulary。
- _例:_\
`"playing"` は、`"play"` と `"ing"` が頻出する subwords である場合、`["play", "ing"]` として tokenized される可能性があります。
2. **WordPiece:**
- **使用例:** BERT のような models。
- **目的:** BPE と同様に、未知の単語を処理し vocabulary のサイズを削減するため、単語を subword units に分割します。
- **仕組み:**
- 個々の characters からなる base vocabulary から開始します。
- training data の尤度を最大化する、最も頻出する subword を繰り返し追加します。
- probabilistic model を使用して、どの subwords を merge するかを決定します。
- **利点:**
- 扱いやすい vocabulary size と、単語を効果的に表現する能力のバランスを取ります。
- まれな単語や複合語を効率的に処理します。
- _例:_\
`"unhappiness"` は、vocabulary に応じて `["un", "happiness"]` または `["un", "happy", "ness"]` として tokenized される可能性があります。
3. **Unigram Language Model:**
- **使用例:** SentencePiece のような models。
- **目的:** 最も可能性の高い subword tokens の組み合わせを決定するため、probabilistic model を使用します。
- **仕組み:**
- 潜在的な tokens の大規模な set から開始します。
- training data に対する model の確率を最も改善しない tokens を繰り返し削除します。
- 各単語が最も確率の高い subword units で表現される vocabulary を確定します。
- **利点:**
- 柔軟で、より自然に language を model 化できます。
- より効率的で compact な tokenizations になることがよくあります。
- _例:_\
`"internationalization"` は、`["international", "ization"]` のような、より小さく意味のある subwords に tokenized される可能性があります。

## Code Example

[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb) の code example で、これをさらに理解しましょう:<sup>[[2]](#references)</sup>
```python
# Download a text to pre-train the model
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

# Tokenize the code using GPT2 tokenizer version
import tiktoken
token_ids = tiktoken.get_encoding("gpt2").encode(raw_text)

# Print first 50 tokens
print(token_ids[:50])
#[40, 367, 2885, 1464, 1807, 3619, 402, 271, 10899, 2138, 257, 7026, 15632, 438, 2016, 257, 922, 5891, 1576, 438, 568, 340, 373, 645, 1049, 5975, 284, 502, 284, 3285, 326, 11, 287, 262, 6001, 286, 465, 13476, 11, 339, 550, 5710, 465, 12036, 11, 6405, 257, 5527, 27075, 11]
```
