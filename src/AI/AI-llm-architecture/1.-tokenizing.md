## Tokenização

**Tokenização** é o processo de dividir dados, como texto, em partes menores e gerenciáveis chamadas _tokens_. Cada token recebe um identificador numérico (ID) exclusivo. Essa é uma etapa fundamental na preparação de texto para processamento por modelos de machine learning, especialmente em processamento de linguagem natural (NLP).<sup>[[1]](#references)</sup>

> [!TIP]
> O objetivo dessa fase inicial é simples: **dividir a entrada em tokens (IDs) de uma maneira útil**.

### **Como a Tokenização Funciona**

1. **Dividindo o Texto:**
- **Basic Tokenizer:** Um tokenizer simples pode dividir o texto em palavras individuais e sinais de pontuação, removendo os espaços.
- _Exemplo:_\
Texto: `"Hello, world!"`\
Tokens: `["Hello", ",", "world", "!"]`
2. **Criando um Vocabulário:**
- Para converter tokens em IDs numéricos, um **vocabulário** é criado. Esse vocabulário lista todos os tokens exclusivos (palavras e símbolos) e atribui um ID específico a cada um.
- **Special Tokens:** São símbolos especiais adicionados ao vocabulário para lidar com vários cenários:
- `[BOS]` (Beginning of Sequence): Indica o início de um texto.
- `[EOS]` (End of Sequence): Indica o fim de um texto.
- `[PAD]` (Padding): Usado para fazer com que todas as sequências de um batch tenham o mesmo tamanho.
- `[UNK]` (Unknown): Representa tokens que não estão no vocabulário.
- _Exemplo:_\
Se `"Hello"` receber o ID `64`, `","` for `455`, `"world"` for `78` e `"!"` for `467`, então:\
`"Hello, world!"` → `[64, 455, 78, 467]`
- **Lidando com Palavras Desconhecidas:**\
Se uma palavra como `"Bye"` não estiver no vocabulário, ela será substituída por `[UNK]`.\
`"Bye, world!"` → `["[UNK]", ",", "world", "!"]` → `[987, 455, 78, 467]`\
_(Supondo que `[UNK]` tenha o ID `987`)_

### **Métodos Avançados de Tokenização**

Embora o tokenizer básico funcione bem para textos simples, ele tem limitações, especialmente com vocabulários grandes e ao lidar com palavras novas ou raras. Métodos avançados de tokenização resolvem esses problemas dividindo o texto em subunidades menores ou otimizando o processo de tokenização.

1. **Byte Pair Encoding (BPE):**
- **Objetivo:** Reduz o tamanho do vocabulário e lida com palavras raras ou desconhecidas dividindo-as em pares de bytes que ocorrem com frequência.
- **Como Funciona:**
- Começa com caracteres individuais como tokens.
- Mescla iterativamente os pares de tokens mais frequentes em um único token.
- Continua até que não seja possível mesclar mais pares frequentes.
- **Benefícios:**
- Um tokenizer BPE em nível de bytes com um alfabeto completo de bytes pode representar qualquer entrada arbitrária sem um token `[UNK]`; variantes baseadas em caracteres ainda dependem de seu alfabeto base.
- Vocabulário mais eficiente e flexível.
- _Exemplo:_\
`"playing"` pode ser tokenizado como `["play", "ing"]` se `"play"` e `"ing"` forem subpalavras frequentes.
2. **WordPiece:**
- **Usado Por:** Modelos como BERT.
- **Objetivo:** Assim como o BPE, divide palavras em unidades de subpalavras para lidar com palavras desconhecidas e reduzir o tamanho do vocabulário.
- **Como Funciona:**
- Começa com um vocabulário base de caracteres individuais.
- Adiciona iterativamente a subpalavra mais frequente que maximiza a probabilidade dos dados de treinamento.
- Usa um modelo probabilístico para decidir quais subpalavras mesclar.
- **Benefícios:**
- Equilibra um tamanho de vocabulário gerenciável com a representação eficaz de palavras.
- Lida eficientemente com palavras raras e compostas.
- _Exemplo:_\
`"unhappiness"` pode ser tokenizado como `["un", "happiness"]` ou `["un", "happy", "ness"]`, dependendo do vocabulário.
3. **Unigram Language Model:**
- **Usado Por:** Modelos como SentencePiece.
- **Objetivo:** Usa um modelo probabilístico para determinar o conjunto mais provável de tokens de subpalavras.
- **Como Funciona:**
- Começa com um grande conjunto de tokens potenciais.
- Remove iterativamente os tokens que menos melhoram a probabilidade dos dados de treinamento para o modelo.
- Finaliza um vocabulário no qual cada palavra é representada pelas unidades de subpalavras mais prováveis.
- **Benefícios:**
- É flexível e pode modelar a linguagem de maneira mais natural.
- Frequentemente resulta em tokenizações mais eficientes e compactas.
- _Exemplo:_\
`"internationalization"` pode ser tokenizado em subpalavras menores e significativas, como `["international", "ization"]`.

## Exemplo de Código

Vamos entender isso melhor a partir de um exemplo de código de [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[2]](#references)</sup>
```python
# Download a text to pre-train the model
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

# Tokenize the code using GPT2 tokenizer version
import tiktoken
token_ids = tiktoken.get_encoding("gpt2").encode(raw_text)

# Print first 50 tokens
print(token_ids[:50])
#[40, 367, 2885, 1464, 1807, 3619, 402, 271, 10899, 2138, 257, 7026, 15632, 438, 2016, 257, 922, 5891, 1576, 438, 568, 340, 373, 645, 1049, 5975, 284, 502, 284, 3285, 326, 11, 287, 262, 6001, 286, 465, 13476, 11, 339, 550, 5710, 465, 12036, 11, 6405, 257, 5527, 27075, 11]
```
