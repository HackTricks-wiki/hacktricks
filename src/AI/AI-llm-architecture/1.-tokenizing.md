## Токенізація

**Токенізація** — це процес розбиття даних, наприклад тексту, на менші керовані частини, які називаються _токенами_. Потім кожному токену призначається унікальний числовий ідентифікатор (ID). Це фундаментальний етап підготовки тексту до обробки моделями машинного навчання, особливо в обробці природної мови (NLP).<sup>[[1]](#references)</sup>

> [!TIP]
> Мета цього початкового етапу проста: **розділити вхідні дані на токени (ID) корисним способом**.

### **Як працює токенізація**

1. **Розбиття тексту:**
- **Базовий токенізатор:** Простий токенізатор може розділити текст на окремі слова та розділові знаки, видаливши пробіли.
- _Приклад:_\
Текст: `"Hello, world!"`\
Токени: `["Hello", ",", "world", "!"]`
2. **Створення словника:**
- Щоб перетворити токени на числові ID, створюється **словник**. Цей словник містить усі унікальні токени (слова та символи) і призначає кожному з них певний ID.
- **Спеціальні токени:** Це спеціальні символи, додані до словника для обробки різних сценаріїв:
- `[BOS]` (Beginning of Sequence): Позначає початок тексту.
- `[EOS]` (End of Sequence): Позначає кінець тексту.
- `[PAD]` (Padding): Використовується, щоб зробити всі послідовності в пакеті однакової довжини.
- `[UNK]` (Unknown): Представляє токени, яких немає у словнику.
- _Приклад:_\
Якщо `"Hello"` має ID `64`, `","` — `455`, `"world"` — `78`, а `"!"` — `467`, тоді:\
`"Hello, world!"` → `[64, 455, 78, 467]`
- **Обробка невідомих слів:**\
Якщо такого слова, як `"Bye"`, немає у словнику, воно замінюється на `[UNK]`.\
`"Bye, world!"` → `["[UNK]", ",", "world", "!"]` → `[987, 455, 78, 467]`\
_(Якщо припустити, що `[UNK]` має ID `987`)_

### **Розширені методи токенізації**

Хоча базовий токенізатор добре працює з простими текстами, він має обмеження, особливо під час роботи з великими словниками та новими або рідкісними словами. Розширені методи токенізації вирішують ці проблеми, розбиваючи текст на менші підрозділи або оптимізуючи процес токенізації.

1. **Byte Pair Encoding (BPE):**
- **Мета:** Зменшує розмір словника та обробляє рідкісні або невідомі слова, розбиваючи їх на часто вживані пари байтів.
- **Як це працює:**
- Починає з окремих символів як токенів.
- Ітеративно об'єднує найчастіші пари токенів в один токен.
- Продовжує роботу, доки більше немає частих пар, які можна об'єднати.
- **Переваги:**
- BPE-токенізатор на рівні байтів із повним алфавітом байтів може представляти довільні вхідні дані без токена `[UNK]`; варіанти на основі символів усе ще залежать від свого базового алфавіту.
- Ефективніший і гнучкіший словник.
- _Приклад:_\
`"playing"` може бути токенізовано як `["play", "ing"]`, якщо `"play"` та `"ing"` є частими підсловами.
2. **WordPiece:**
- **Використовується:** Моделями на кшталт BERT.
- **Мета:** Подібно до BPE, розбиває слова на підсловні одиниці для обробки невідомих слів і зменшення розміру словника.
- **Як це працює:**
- Починає з базового словника окремих символів.
- Ітеративно додає найчастіше підслово, яке максимізує ймовірність навчальних даних.
- Використовує імовірнісну модель для визначення підслів, які потрібно об'єднати.
- **Переваги:**
- Забезпечує баланс між керованим розміром словника та ефективним представленням слів.
- Ефективно обробляє рідкісні та складні слова.
- _Приклад:_\
`"unhappiness"` може бути токенізовано як `["un", "happiness"]` або `["un", "happy", "ness"]` залежно від словника.
3. **Unigram Language Model:**
- **Використовується:** Моделями на кшталт SentencePiece.
- **Мета:** Використовує імовірнісну модель для визначення найімовірнішого набору підсловних токенів.
- **Як це працює:**
- Починає з великого набору потенційних токенів.
- Ітеративно видаляє токени, які найменше покращують імовірність навчальних даних моделі.
- Формує словник, у якому кожне слово представлено найімовірнішими підсловними одиницями.
- **Переваги:**
- Гнучкий і може природніше моделювати мову.
- Часто створює ефективніші та компактніші токенізації.
- _Приклад:_\
`"internationalization"` може бути токенізовано на менші змістовні підслова, наприклад `["international", "ization"]`.

## Приклад коду

Розглянемо це детальніше на прикладі коду з [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[2]](#references)</sup>
```python
# Download a text to pre-train the model
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

# Tokenize the code using GPT2 tokenizer version
import tiktoken
token_ids = tiktoken.get_encoding("gpt2").encode(raw_text)

# Print first 50 tokens
print(token_ids[:50])
#[40, 367, 2885, 1464, 1807, 3619, 402, 271, 10899, 2138, 257, 7026, 15632, 438, 2016, 257, 922, 5891, 1576, 438, 568, 340, 373, 645, 1049, 5975, 284, 502, 284, 3285, 326, 11, 287, 262, 6001, 286, 465, 13476, 11, 339, 550, 5710, 465, 12036, 11, 6405, 257, 5527, 27075, 11]
```
