## Tokenización

**La tokenización** es el proceso de dividir datos, como texto, en piezas más pequeñas y manejables llamadas _tokens_. A cada token se le asigna un identificador numérico (ID) único. Este es un paso fundamental para preparar texto para su procesamiento por modelos de machine learning, especialmente en el procesamiento del lenguaje natural (NLP).<sup>[[1]](#references)</sup>

> [!TIP]
> El objetivo de esta fase inicial es sencillo: **dividir la entrada en tokens (IDs) de una forma útil**.

### **Cómo funciona la tokenización**

1. **División del texto:**
- **Tokenizador básico:** Un tokenizador sencillo puede dividir el texto en palabras individuales y signos de puntuación, eliminando los espacios.
- _Ejemplo:_\
Texto: `"Hello, world!"`\
Tokens: `["Hello", ",", "world", "!"]`
2. **Creación de un vocabulario:**
- Para convertir los tokens en IDs numéricos, se crea un **vocabulario**. Este vocabulario enumera todos los tokens únicos (palabras y símbolos) y asigna a cada uno un ID específico.
- **Tokens especiales:** Son símbolos especiales añadidos al vocabulario para gestionar varios escenarios:
- `[BOS]` (Beginning of Sequence): Indica el inicio de un texto.
- `[EOS]` (End of Sequence): Indica el final de un texto.
- `[PAD]` (Padding): Se utiliza para que todas las secuencias de un batch tengan la misma longitud.
- `[UNK]` (Unknown): Representa tokens que no están en el vocabulario.
- _Ejemplo:_\
Si `"Hello"` tiene asignado el ID `64`, `","` es `455`, `"world"` es `78` y `"!"` es `467`, entonces:\
`"Hello, world!"` → `[64, 455, 78, 467]`
- **Gestión de palabras desconocidas:**\
Si una palabra como `"Bye"` no está en el vocabulario, se reemplaza por `[UNK]`.\
`"Bye, world!"` → `["[UNK]", ",", "world", "!"]` → `[987, 455, 78, 467]`\
_(Suponiendo que `[UNK]` tiene el ID `987`)_

### **Métodos avanzados de tokenización**

Aunque el tokenizador básico funciona bien para textos sencillos, tiene limitaciones, especialmente con vocabularios grandes y al gestionar palabras nuevas o poco frecuentes. Los métodos avanzados de tokenización abordan estos problemas dividiendo el texto en subunidades más pequeñas u optimizando el proceso de tokenización.

1. **Byte Pair Encoding (BPE):**
- **Objetivo:** Reduce el tamaño del vocabulario y gestiona palabras poco frecuentes o desconocidas dividiéndolas en pares de bytes que aparecen con frecuencia.
- **Cómo funciona:**
- Comienza con caracteres individuales como tokens.
- Combina iterativamente los pares de tokens más frecuentes en un único token.
- Continúa hasta que no se puedan combinar más pares frecuentes.
- **Ventajas:**
- Un tokenizador BPE basado en bytes con un alfabeto de bytes completo puede representar cualquier entrada sin un token `[UNK]`; las variantes basadas en caracteres siguen dependiendo de su alfabeto base.
- Vocabulario más eficiente y flexible.
- _Ejemplo:_\
`"playing"` podría tokenizarse como `["play", "ing"]` si `"play"` y `"ing"` son subpalabras frecuentes.
2. **WordPiece:**
- **Utilizado por:** Modelos como BERT.
- **Objetivo:** Al igual que BPE, divide las palabras en subunidades para gestionar palabras desconocidas y reducir el tamaño del vocabulario.
- **Cómo funciona:**
- Comienza con un vocabulario base de caracteres individuales.
- Añade iterativamente la subpalabra más frecuente que maximiza la probabilidad de los datos de entrenamiento.
- Utiliza un modelo probabilístico para decidir qué subpalabras combinar.
- **Ventajas:**
- Equilibra un tamaño de vocabulario manejable con una representación eficaz de las palabras.
- Gestiona eficazmente palabras poco frecuentes y compuestas.
- _Ejemplo:_\
`"unhappiness"` podría tokenizarse como `["un", "happiness"]` o `["un", "happy", "ness"]`, dependiendo del vocabulario.
3. **Modelo de lenguaje Unigram:**
- **Utilizado por:** Modelos como SentencePiece.
- **Objetivo:** Utiliza un modelo probabilístico para determinar el conjunto más probable de tokens de subpalabras.
- **Cómo funciona:**
- Comienza con un conjunto grande de tokens potenciales.
- Elimina iterativamente los tokens que menos mejoran la probabilidad de los datos de entrenamiento del modelo.
- Finaliza un vocabulario en el que cada palabra está representada por las subunidades más probables.
- **Ventajas:**
- Es flexible y puede modelar el lenguaje de forma más natural.
- A menudo produce tokenizaciones más eficientes y compactas.
- _Ejemplo:_\
`"internationalization"` podría tokenizarse en subpalabras más pequeñas y significativas como `["international", "ization"]`.

## Ejemplo de código

Entendamos esto mejor mediante un ejemplo de código de [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[2]](#references)</sup>
```python
# Download a text to pre-train the model
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

# Tokenize the code using GPT2 tokenizer version
import tiktoken
token_ids = tiktoken.get_encoding("gpt2").encode(raw_text)

# Print first 50 tokens
print(token_ids[:50])
#[40, 367, 2885, 1464, 1807, 3619, 402, 271, 10899, 2138, 257, 7026, 15632, 438, 2016, 257, 922, 5891, 1576, 438, 568, 340, 373, 645, 1049, 5975, 284, 502, 284, 3285, 326, 11, 287, 262, 6001, 286, 465, 13476, 11, 339, 550, 5710, 465, 12036, 11, 6405, 257, 5527, 27075, 11]
```
