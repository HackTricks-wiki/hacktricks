## Tokenizing

**Tokenizing** is die proses om data, soos teks, op te breek in kleiner, hanteerbare dele wat _tokens_ genoem word. Aan elke token word dan ’n unieke numeriese identifiseerder (ID) toegeken. Dit is ’n fundamentele stap in die voorbereiding van teks vir verwerking deur machine learning-modelle, veral in natural language processing (NLP).<sup>[[1]](#references)</sup>

> [!TIP]
> Die doel van hierdie aanvanklike fase is eenvoudig: **deel die invoer op in tokens (IDs) op ’n nuttige manier**.

### **Hoe Tokenizing Werk**

1. **Opdeling van die Teks:**
- **Basic Tokenizer:** ’n Eenvoudige tokenizer kan teks in individuele woorde en leestekens opdeel en spasies verwyder.
- _Voorbeeld:_\
Teks: `"Hello, world!"`\
Tokens: `["Hello", ",", "world", "!"]`
2. **Skep van ’n Vocabulary:**
- Om tokens na numeriese IDs om te skakel, word ’n **vocabulary** geskep. Hierdie vocabulary lys alle unieke tokens (woorde en simbole) en ken aan elkeen ’n spesifieke ID toe.
- **Special Tokens:** Dit is spesiale simbole wat by die vocabulary gevoeg word om verskeie scenario’s te hanteer:
- `[BOS]` (Beginning of Sequence): Dui die begin van ’n teks aan.
- `[EOS]` (End of Sequence): Dui die einde van ’n teks aan.
- `[PAD]` (Padding): Word gebruik om alle sequences in ’n batch dieselfde lengte te maak.
- `[UNK]` (Unknown): Verteenwoordig tokens wat nie in die vocabulary is nie.
- _Voorbeeld:_\
As `"Hello"` ID `64` toegeken is, `","` `455` is, `"world"` `78` is, en `"!"` `467` is, dan:\
`"Hello, world!"` → `[64, 455, 78, 467]`
- **Hantering van Onbekende Woorde:**\
As ’n woord soos `"Bye"` nie in die vocabulary is nie, word dit met `[UNK]` vervang.\
`"Bye, world!"` → `["[UNK]", ",", "world", "!"]` → `[987, 455, 78, 467]`\
_(Met die aanname dat `[UNK]` ID `987` het)_

### **Gevorderde Tokenizing-metodes**

Hoewel die basic tokenizer goed vir eenvoudige tekste werk, het dit beperkings, veral met groot vocabularies en die hantering van nuwe of seldsame woorde. Gevorderde tokenizing-metodes spreek hierdie kwessies aan deur teks in kleiner subeenhede op te breek of die tokenization-proses te optimaliseer.

1. **Byte Pair Encoding (BPE):**
- **Doel:** Verminder die grootte van die vocabulary en hanteer seldsame of onbekende woorde deur dit in gereeld voorkomende byte-pare op te breek.
- **Hoe Dit Werk:**
- Begin met individuele karakters as tokens.
- Voeg die mees frekwente pare tokens iteratief saam tot ’n enkele token.
- Gaan voort totdat geen meer frekwente pare saamgevoeg kan word nie.
- **Voordele:**
- ’n Byte-level BPE tokenizer met ’n volledige byte-alfabet kan arbitrêre invoer sonder ’n `[UNK]`-token verteenwoordig; karaktergebaseerde variante bly egter afhanklik van hul basisalfabet.
- Meer doeltreffende en buigsame vocabulary.
- _Voorbeeld:_\
`"playing"` kan as `["play", "ing"]` getokenizeer word as `"play"` en `"ing"` gereelde subwords is.
2. **WordPiece:**
- **Gebruik Deur:** Modelle soos BERT.
- **Doel:** Soortgelyk aan BPE breek dit woorde in subword-eenhede op om onbekende woorde te hanteer en die vocabulary-grootte te verminder.
- **Hoe Dit Werk:**
- Begin met ’n basis-vocabulary van individuele karakters.
- Voeg iteratief die mees frekwente subword by wat die waarskynlikheid van die training data maksimeer.
- Gebruik ’n probabilistiese model om te besluit watter subwords saamgevoeg moet word.
- **Voordele:**
- Balanseer ’n hanteerbare vocabulary-grootte met die effektiewe voorstelling van woorde.
- Hanteer seldsame en saamgestelde woorde doeltreffend.
- _Voorbeeld:_\
`"unhappiness"` kan as `["un", "happiness"]` of `["un", "happy", "ness"]` getokenizeer word, afhangend van die vocabulary.
3. **Unigram Language Model:**
- **Gebruik Deur:** Modelle soos SentencePiece.
- **Doel:** Gebruik ’n probabilistiese model om die waarskynlikste stel subword-tokens te bepaal.
- **Hoe Dit Werk:**
- Begin met ’n groot stel potensiële tokens.
- Verwyder iteratief tokens wat die model se waarskynlikheid van die training data die minste verbeter.
- Finaliseer ’n vocabulary waarin elke woord deur die waarskynlikste subword-eenhede verteenwoordig word.
- **Voordele:**
- Buigsaam en kan taal meer natuurlik modelleer.
- Lei dikwels tot meer doeltreffende en kompakte tokenizations.
- _Voorbeeld:_\
`"internationalization"` kan in kleiner, betekenisvolle subwords soos `["international", "ization"]` getokenizeer word.

## Code Example

Kom ons verstaan dit beter aan die hand van ’n code example uit [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[2]](#references)</sup>
```python
# Download a text to pre-train the model
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

# Tokenize the code using GPT2 tokenizer version
import tiktoken
token_ids = tiktoken.get_encoding("gpt2").encode(raw_text)

# Print first 50 tokens
print(token_ids[:50])
#[40, 367, 2885, 1464, 1807, 3619, 402, 271, 10899, 2138, 257, 7026, 15632, 438, 2016, 257, 922, 5891, 1576, 438, 568, 340, 373, 645, 1049, 5975, 284, 502, 284, 3285, 326, 11, 287, 262, 6001, 286, 465, 13476, 11, 339, 550, 5710, 465, 12036, 11, 6405, 257, 5527, 27075, 11]
```
