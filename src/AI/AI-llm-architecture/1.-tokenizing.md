## 分词

**Tokenizing** 是将数据（例如文本）拆分成更小、易于管理的部分（称为 _tokens_）的过程。随后，每个 token 都会被分配一个唯一的数字标识符（ID）。这是准备文本以供 machine learning models 处理的基础步骤，尤其适用于 natural language processing (NLP)。<sup>[[1]](#references)</sup>

> [!TIP]
> 此初始阶段的目标很简单：**以有用的方式将输入拆分为 tokens (IDs)**。

### **分词的工作方式**

1. **拆分文本：**
- **Basic Tokenizer：** 一个简单的 tokenizer 可能会将文本拆分为单独的单词和标点符号，并移除空格。
- _示例：_\
文本：`"Hello, world!"`\
Tokens：`["Hello", ",", "world", "!"]`
2. **创建词汇表：**
- 要将 tokens 转换为数字 ID，需要创建一个**词汇表**。该词汇表列出所有唯一的 tokens（单词和符号），并为每个 token 分配一个特定的 ID。
- **特殊 Tokens：** 这些是添加到词汇表中的特殊符号，用于处理各种情况：
- `[BOS]` (Beginning of Sequence)：表示文本的开始。
- `[EOS]` (End of Sequence)：表示文本的结束。
- `[PAD]` (Padding)：用于使一个 batch 中的所有序列具有相同长度。
- `[UNK]` (Unknown)：表示不在词汇表中的 tokens。
- _示例：_\
如果 `"Hello"` 被分配 ID `64`，`","` 是 `455`，`"world"` 是 `78`，而 `"!"` 是 `467`，那么：\
`"Hello, world!"` → `[64, 455, 78, 467]`
- **处理未知单词：**\
如果 `"Bye"` 这样的单词不在词汇表中，它会被替换为 `[UNK]`。\
`"Bye, world!"` → `["[UNK]", ",", "world", "!"]` → `[987, 455, 78, 467]`\
_（假设 `[UNK]` 的 ID 为 `987`）_

### **高级分词方法**

虽然 basic tokenizer 对简单文本效果很好，但它存在一些限制，尤其是在处理大型词汇表以及新词或罕见词时。高级分词方法通过将文本拆分成更小的子单元，或优化 tokenization 过程来解决这些问题。

1. **Byte Pair Encoding (BPE)：**
- **目的：** 通过将罕见或未知单词拆分为经常出现的字节对，减少词汇表大小并处理罕见或未知单词。
- **工作方式：**
- 从单个字符作为 tokens 开始。
- 反复将出现频率最高的 token 对合并为单个 token。
- 持续执行，直到没有更多高频 token 对可以合并。
- **优点：**
- 具有完整字节字母表的 byte-level BPE tokenizer 可以表示任意输入，而无需使用 `[UNK]` token；基于字符的变体仍取决于其基础字母表。
- 词汇表更加高效且灵活。
- _示例：_\
如果 `"play"` 和 `"ing"` 是高频子词，`"playing"` 可能会被 tokenized 为 `["play", "ing"]`。
2. **WordPiece：**
- **使用者：** BERT 等 models。
- **目的：** 与 BPE 类似，它将单词拆分为子词单元，以处理未知单词并减少词汇表大小。
- **工作方式：**
- 从由单个字符组成的基础词汇表开始。
- 反复添加能够最大化 training data 似然的最高频子词。
- 使用概率模型决定要合并的子词。
- **优点：**
- 在可管理的词汇表大小与有效表示单词之间取得平衡。
- 能够高效处理罕见词和复合词。
- _示例：_\
根据词汇表的不同，`"unhappiness"` 可能会被 tokenized 为 `["un", "happiness"]` 或 `["un", "happy", "ness"]`。
3. **Unigram Language Model：**
- **使用者：** SentencePiece 等 models。
- **目的：** 使用概率模型确定最有可能的子词 tokens 集合。
- **工作方式：**
- 从一组大量潜在 tokens 开始。
- 反复移除对 training data 概率提升最小的 tokens。
- 最终确定一个词汇表，其中每个单词都由概率最高的子词单元表示。
- **优点：**
- 灵活，并且能够以更自然的方式对语言建模。
- 通常能够生成更高效、更紧凑的 tokenizations。
- _示例：_\
`"internationalization"` 可能会被 tokenized 为更小且有意义的子词，例如 `["international", "ization"]`。

## 代码示例

让我们通过来自 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb) 的代码示例进一步理解这一点：<sup>[[2]](#references)</sup>
```python
# Download a text to pre-train the model
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

# Tokenize the code using GPT2 tokenizer version
import tiktoken
token_ids = tiktoken.get_encoding("gpt2").encode(raw_text)

# Print first 50 tokens
print(token_ids[:50])
#[40, 367, 2885, 1464, 1807, 3619, 402, 271, 10899, 2138, 257, 7026, 15632, 438, 2016, 257, 922, 5891, 1576, 438, 568, 340, 373, 645, 1049, 5975, 284, 502, 284, 3285, 326, 11, 287, 262, 6001, 286, 465, 13476, 11, 339, 550, 5710, 465, 12036, 11, 6405, 257, 5527, 27075, 11]
```
