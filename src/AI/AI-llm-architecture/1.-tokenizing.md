## Tokenizing

**Tokenizing** とは、テキストなどのデータを、_tokens_ と呼ばれる、より小さく扱いやすい単位に分割するプロセスです。各 token には、一意の数値識別子（ID）が割り当てられます。これは、機械学習モデル、特に自然言語処理（NLP）でテキストを処理するための準備における基本的なステップです。<sup>[[1]](#references)</sup>

> [!TIP]
> この初期フェーズの目的は非常にシンプルです。**入力を、意味のある方法で tokens（ids）に分割すること**です。

### **Tokenizing の仕組み**

1. **テキストの分割:**
- **Basic Tokenizer:** 単純な tokenizer は、スペースを削除しながら、テキストを個々の単語と句読点に分割します。
- _例:_\
テキスト: `"Hello, world!"`\
Tokens: `["Hello", ",", "world", "!"]`
2. **Vocabulary の作成:**
- tokens を数値 ID に変換するために、**vocabulary** が作成されます。この vocabulary には、すべての一意な tokens（単語と記号）が一覧化され、それぞれに固有の ID が割り当てられます。
- **Special Tokens:** さまざまな状況に対応するため、vocabulary に追加される特別な記号です。
- `[BOS]` (Beginning of Sequence): テキストの開始を示します。
- `[EOS]` (End of Sequence): テキストの終了を示します。
- `[PAD]` (Padding): batch 内のすべての sequence を同じ長さにするために使用されます。
- `[UNK]` (Unknown): vocabulary に存在しない tokens を表します。
- _例:_\
`"Hello"` に ID `64`、`","` に `455`、`"world"` に `78`、`"!"` に `467` が割り当てられている場合:\
`"Hello, world!"` → `[64, 455, 78, 467]`
- **未知の単語の処理:**\
`"Bye"` のような単語が vocabulary に存在しない場合、`[UNK]` に置き換えられます。\
`"Bye, world!"` → `["[UNK]", ",", "world", "!"]` → `[987, 455, 78, 467]`\
_（`[UNK]` の ID が `987` であると仮定）_

### **Advanced Tokenizing Methods**

Basic tokenizer は単純なテキストでは適切に機能しますが、大規模な vocabulary や、新しい単語またはまれな単語の処理には、特に制限があります。Advanced tokenizing methods は、テキストをより小さな subunit に分割したり、tokenization プロセスを最適化したりすることで、これらの問題に対処します。

1. **Byte Pair Encoding (BPE):**
- **目的:** vocabulary のサイズを削減し、頻繁に出現する byte pair に分割することで、まれな単語や未知の単語を処理します。
- **仕組み:**
- 個々の文字を tokens として開始します。
- 最も頻繁に出現する tokens のペアを、1つの token に反復的に結合します。
- 頻度の高いペアをこれ以上結合できなくなるまで続けます。
- **利点:**
- 既存の subword tokens を組み合わせることで、すべての単語を表現できるため、`[UNK]` token が不要になります。
- より効率的で柔軟な vocabulary になります。
- _例:_\
`"playing"` は、`"play"` と `"ing"` が頻出する subwords である場合、`["play", "ing"]` として tokenized されることがあります。
2. **WordPiece:**
- **使用するモデル:** BERT などのモデル。
- **目的:** BPE と同様に、単語を subword units に分割して未知の単語を処理し、vocabulary のサイズを削減します。
- **仕組み:**
- 個々の文字からなる base vocabulary から開始します。
- training data の尤度を最大化する、最も頻繁に出現する subword を反復的に追加します。
- probabilistic model を使用して、どの subwords を結合するかを決定します。
- **利点:**
- 扱いやすい vocabulary サイズと、単語を効果的に表現する能力のバランスを取ります。
- まれな単語や複合語を効率的に処理します。
- _例:_\
`"unhappiness"` は、vocabulary に応じて `["un", "happiness"]` または `["un", "happy", "ness"]` として tokenized されることがあります。
3. **Unigram Language Model:**
- **使用するモデル:** SentencePiece などのモデル。
- **目的:** 最も可能性の高い subword tokens の組み合わせを決定するために、probabilistic model を使用します。
- **仕組み:**
- 候補となる大量の tokens から開始します。
- training data に対するモデルの確率をほとんど改善しない tokens を、反復的に削除します。
- 各単語が、最も可能性の高い subword units で表現される vocabulary を確定します。
- **利点:**
- 柔軟で、より自然な方法で言語をモデル化できます。
- より効率的でコンパクトな tokenizations になることが多くあります。
- _例:_\
`"internationalization"` は、`["international", "ization"]` のような、より小さく意味のある subwords に tokenized されることがあります。
