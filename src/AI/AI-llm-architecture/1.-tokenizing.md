## Tokenizzazione

La **tokenizzazione** è il processo di suddivisione dei dati, come il testo, in parti più piccole e gestibili chiamate _token_. A ogni token viene quindi assegnato un identificatore numerico (ID) univoco. Questo è un passaggio fondamentale nella preparazione del testo per l'elaborazione da parte dei modelli di machine learning, soprattutto nell'elaborazione del linguaggio naturale (NLP).<sup>[[1]](#references)</sup>

> [!TIP]
> L'obiettivo di questa fase iniziale è semplice: **suddividere l'input in token (ID) in modo utile**.

### **Come funziona la tokenizzazione**

1. **Suddivisione del testo:**
- **Tokenizer di base:** Un tokenizer semplice può suddividere il testo in singole parole e segni di punteggiatura, rimuovendo gli spazi.
- _Esempio:_\
Testo: `"Hello, world!"`\
Token: `["Hello", ",", "world", "!"]`
2. **Creazione di un vocabolario:**
- Per convertire i token in ID numerici, viene creato un **vocabolario**. Questo vocabolario elenca tutti i token univoci (parole e simboli) e assegna a ciascuno un ID specifico.
- **Token speciali:** Sono simboli speciali aggiunti al vocabolario per gestire diversi scenari:
- `[BOS]` (Beginning of Sequence): Indica l'inizio di un testo.
- `[EOS]` (End of Sequence): Indica la fine di un testo.
- `[PAD]` (Padding): Utilizzato per rendere tutte le sequenze di un batch della stessa lunghezza.
- `[UNK]` (Unknown): Rappresenta i token che non fanno parte del vocabolario.
- _Esempio:_\
Se a `"Hello"` viene assegnato l'ID `64`, a `","` `455`, a `"world"` `78` e a `"!"` `467`, allora:\
`"Hello, world!"` → `[64, 455, 78, 467]`
- **Gestione delle parole sconosciute:**\
Se una parola come `"Bye"` non è presente nel vocabolario, viene sostituita con `[UNK]`.\
`"Bye, world!"` → `["[UNK]", ",", "world", "!"]` → `[987, 455, 78, 467]`\
_(Supponendo che `[UNK]` abbia ID `987`)_

### **Metodi avanzati di tokenizzazione**

Sebbene il tokenizer di base funzioni bene per i testi semplici, presenta dei limiti, soprattutto con i vocabolari di grandi dimensioni e nella gestione di parole nuove o rare. I metodi avanzati di tokenizzazione affrontano questi problemi suddividendo il testo in unità più piccole o ottimizzando il processo di tokenizzazione.

1. **Byte Pair Encoding (BPE):**
- **Scopo:** Riduce le dimensioni del vocabolario e gestisce le parole rare o sconosciute suddividendole in coppie di byte frequenti.
- **Come funziona:**
- Inizia con i singoli caratteri come token.
- Unisce iterativamente le coppie di token più frequenti in un singolo token.
- Continua fino a quando non è più possibile unire coppie frequenti.
- **Vantaggi:**
- Un tokenizer BPE a livello di byte con un alfabeto completo di byte può rappresentare input arbitrari senza un token `[UNK]`; le varianti basate sui caratteri dipendono ancora dal proprio alfabeto di base.
- Vocabolario più efficiente e flessibile.
- _Esempio:_\
`"playing"` potrebbe essere tokenizzato come `["play", "ing"]` se `"play"` e `"ing"` sono sottoparole frequenti.
2. **WordPiece:**
- **Utilizzato da:** Modelli come BERT.
- **Scopo:** Analogamente a BPE, suddivide le parole in unità di sottoparole per gestire le parole sconosciute e ridurre le dimensioni del vocabolario.
- **Come funziona:**
- Inizia con un vocabolario di base composto da singoli caratteri.
- Aggiunge iterativamente la sottoparola più frequente che massimizza la probabilità dei dati di training.
- Utilizza un modello probabilistico per decidere quali sottoparole unire.
- **Vantaggi:**
- Bilancia la necessità di mantenere una dimensione del vocabolario gestibile con quella di rappresentare efficacemente le parole.
- Gestisce in modo efficiente le parole rare e composte.
- _Esempio:_\
`"unhappiness"` potrebbe essere tokenizzato come `["un", "happiness"]` o `["un", "happy", "ness"]` a seconda del vocabolario.
3. **Unigram Language Model:**
- **Utilizzato da:** Modelli come SentencePiece.
- **Scopo:** Utilizza un modello probabilistico per determinare l'insieme più probabile di token di sottoparole.
- **Come funziona:**
- Inizia con un ampio insieme di token potenziali.
- Rimuove iterativamente i token che migliorano meno la probabilità del modello sui dati di training.
- Finalizza un vocabolario in cui ogni parola è rappresentata dalle unità di sottoparole più probabili.
- **Vantaggi:**
- È flessibile e può modellare il linguaggio in modo più naturale.
- Spesso produce tokenizzazioni più efficienti e compatte.
- _Esempio:_\
`"internationalization"` potrebbe essere tokenizzato in sottoparole più piccole e significative come `["international", "ization"]`.

## Esempio di codice

Comprendiamolo meglio attraverso un esempio di codice tratto da [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[2]](#references)</sup>
```python
# Download a text to pre-train the model
import urllib.request
url = ("https://raw.githubusercontent.com/rasbt/LLMs-from-scratch/main/ch02/01_main-chapter-code/the-verdict.txt")
file_path = "the-verdict.txt"
urllib.request.urlretrieve(url, file_path)

with open("the-verdict.txt", "r", encoding="utf-8") as f:
raw_text = f.read()

# Tokenize the code using GPT2 tokenizer version
import tiktoken
token_ids = tiktoken.get_encoding("gpt2").encode(raw_text)

# Print first 50 tokens
print(token_ids[:50])
#[40, 367, 2885, 1464, 1807, 3619, 402, 271, 10899, 2138, 257, 7026, 15632, 438, 2016, 257, 922, 5891, 1576, 438, 568, 340, 373, 645, 1049, 5975, 284, 502, 284, 3285, 326, 11, 287, 262, 6001, 286, 465, 13476, 11, 339, 550, 5710, 465, 12036, 11, 6405, 257, 5527, 27075, 11]
```
