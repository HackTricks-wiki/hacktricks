## Embeddings de tokens

Después de tokenizar los datos de texto, el siguiente paso crítico para preparar los datos para entrenar modelos de lenguaje grandes (LLMs), como GPT, es crear **embeddings de tokens**. Los embeddings de tokens transforman tokens discretos (como palabras o subpalabras) en vectores numéricos continuos que el modelo puede procesar y de los que puede aprender. Esta explicación desglosa los embeddings de tokens, su inicialización y uso, así como el papel de los embeddings posicionales para mejorar la comprensión que tiene el modelo de las secuencias de tokens.<sup>[[1]](#references)</sup>

> [!TIP]
> El objetivo de esta tercera fase es muy sencillo: **Asignar a cada uno de los tokens anteriores del vocabulario un vector con las dimensiones deseadas para entrenar el modelo.** Cada palabra del vocabulario será un punto en un espacio de X dimensiones.\
> Ten en cuenta que inicialmente la posición de cada palabra en el espacio simplemente se inicializa de forma "aleatoria" y estas posiciones son parámetros entrenables (se mejorarán durante el entrenamiento).
>
> Además, durante el embedding de tokens, **se crea otra capa de embeddings** que representa (en este caso) la **posición absoluta de la palabra en la frase de entrenamiento**. De esta forma, una palabra en diferentes posiciones de la frase tendrá una representación (significado) diferente.

### **¿Qué son los embeddings de tokens?**

Los **embeddings de tokens** son representaciones numéricas de tokens en un espacio vectorial continuo. Cada token del vocabulario está asociado a un vector único de dimensiones fijas. Estos vectores capturan información semántica y sintáctica sobre los tokens, lo que permite al modelo comprender las relaciones y los patrones presentes en los datos.

- **Tamaño del vocabulario:** El número total de tokens únicos (por ejemplo, palabras o subpalabras) en el vocabulario del modelo.
- **Dimensiones del embedding:** El número de valores numéricos (dimensiones) del vector de cada token. Un mayor número de dimensiones puede capturar información más detallada, pero requiere más recursos computacionales.

**Ejemplo:**

- **Tamaño del vocabulario:** 6 tokens \[1, 2, 3, 4, 5, 6]
- **Dimensiones del embedding:** 3 (x, y, z)

### **Inicialización de los embeddings de tokens**

Al comienzo del entrenamiento, los embeddings de tokens suelen inicializarse con valores aleatorios pequeños. Estos valores iniciales se ajustan (se perfeccionan) durante el entrenamiento para representar mejor los significados de los tokens según los datos de entrenamiento.

**Ejemplo en PyTorch:**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Cómo funcionan los Token Embeddings durante el entrenamiento**

Durante el entrenamiento, cada token de los datos de entrada se convierte en su vector de embedding correspondiente. Estos vectores se utilizan después en varios cálculos dentro del modelo, como mecanismos de atención y capas de redes neuronales.

**Escenario de ejemplo:**

- **Tamaño del batch:** 8 (número de muestras procesadas simultáneamente)
- **Longitud máxima de la secuencia:** 4 (número de tokens por muestra)
- **Dimensiones del embedding:** 256

**Estructura de los datos:**

- Cada batch está representado por un tensor 3D con la forma `(batch_size, max_length, embedding_dim)`.
- Para nuestro ejemplo, la forma sería `(8, 4, 256)`.

## **Embeddings posicionales: añadir contexto a los embeddings de los tokens**

Aunque los embeddings de los tokens capturan el significado de cada token individual, no codifican inherentemente la posición de los tokens dentro de una secuencia. Comprender el orden de los tokens es crucial para la comprensión del lenguaje. Aquí es donde entran en juego los **embeddings posicionales**.

### **Por qué se necesitan los embeddings posicionales:**

- **El orden de los tokens importa:** En las frases, el significado suele depender del orden de las palabras. Por ejemplo, "El gato se sentó sobre la alfombra" frente a "La alfombra se sentó sobre el gato".
- **Limitación de los embeddings:** Sin información posicional, el modelo trata los tokens como una "bolsa de palabras", ignorando su secuencia.

### **Tipos de embeddings posicionales:**

1. **Embeddings posicionales absolutos:**
- Asignan un vector de posición único a cada posición de la secuencia.
- **Ejemplo:** El primer token de cualquier secuencia tiene el mismo embedding posicional, el segundo token tiene otro, y así sucesivamente.
- **Usados por:** Los modelos GPT de OpenAI.
2. **Embeddings posicionales relativos:**
- Codifican la distancia relativa entre los tokens en lugar de sus posiciones absolutas.
- **Ejemplo:** Indican qué tan separados están dos tokens, independientemente de sus posiciones absolutas en la secuencia.
- **Usados por:** Modelos como Transformer-XL y algunas variantes de BERT.

### **Cómo se integran los embeddings posicionales:**

- **Mismas dimensiones:** Los embeddings posicionales tienen la misma dimensionalidad que los embeddings de los tokens.
- **Suma:** Se suman a los embeddings de los tokens, combinando la identidad del token con la información posicional sin aumentar la dimensionalidad total.

**Ejemplo de suma de embeddings posicionales:**

Supongamos que un vector de embedding de un token es `[0.5, -0.2, 0.1]` y que su vector de embedding posicional es `[0.1, 0.3, -0.1]`. El embedding combinado utilizado por el modelo sería:
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**Beneficios de los embeddings posicionales:**

- **Conciencia contextual:** El modelo puede diferenciar entre tokens en función de sus posiciones.
- **Comprensión de secuencias:** Permite al modelo comprender la gramática, la sintaxis y los significados dependientes del contexto.

## **Embeddings posicionales en los LLM modernos**

### **Rotary Positional Embeddings (RoPE)**

RoPE codifica la posición aplicando una rotación dependiente de la posición a pares de dimensiones en los vectores de query/key, convirtiendo las posiciones absolutas en diferencias de fase relativas. Esto proporciona información sobre la posición relativa mientras mantiene sin cambios la dimensionalidad del embedding y se utiliza ampliamente en los LLM recientes que solo tienen decoder.<sup>[[2]](#references)</sup>

Para saber cómo se combinan los embeddings de tokens y posicionales dentro del modelo, consulta [la página de arquitectura de los LLM](5.-llm-architecture.md).

### **Ampliación de las ventanas de contexto en modelos basados en RoPE**

Trabajos recientes muestran que la longitud del contexto suele estar limitada por el esquema de codificación posicional, en lugar de por la propia matriz de embeddings de tokens.

- **Interpolación de posiciones (PI):** Reescala los índices de posición para que las secuencias más largas se asignen al rango observado durante el entrenamiento, lo que permite ampliar la longitud con un fine-tuning mínimo.<sup>[[3]](#references)</sup> Ejemplo:
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** Una estrategia de extensión de RoPE eficiente en cuanto a cómputo que modifica el escalado/interpolación de RoPE para extrapolar a contextos más largos con menos pasos de entrenamiento adicionales.<sup>[[4]](#references)</sup>

## Ejemplo de código

A continuación, se muestra el ejemplo de código de [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[5]](#references)</sup>
```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
