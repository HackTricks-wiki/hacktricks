## Token Embeddings

Nach der Tokenisierung von Textdaten besteht der nächste entscheidende Schritt bei der Vorbereitung von Daten für das Training großer Sprachmodelle (LLMs) wie GPT in der Erstellung von **Token Embeddings**. Token Embeddings wandeln diskrete Tokens (z. B. Wörter oder Subwörter) in kontinuierliche numerische Vektoren um, die das Modell verarbeiten und aus denen es lernen kann. Diese Erklärung behandelt Token Embeddings, ihre Initialisierung und Verwendung sowie die Rolle von Positions-Embeddings bei der Verbesserung des Verständnisses von Token-Sequenzen durch das Modell.<sup>[[1]](#references)</sup>

> [!TIP]
> Das Ziel dieser dritten Phase ist sehr einfach: **Jedem der vorherigen Tokens im Vokabular einen Vektor mit den gewünschten Dimensionen zuzuweisen, um das Modell zu trainieren.** Jedes Wort im Vokabular wird zu einem Punkt in einem Raum mit X Dimensionen.\
> Beachte, dass die Position jedes Wortes im Raum anfangs lediglich „zufällig“ initialisiert wird und diese Positionen trainierbare Parameter sind (sie werden während des Trainings verbessert).
>
> Außerdem wird während des Token Embeddings **eine weitere Embedding-Schicht erstellt**, die (in diesem Fall) die **absolute Position des Wortes im Trainingssatz** darstellt. Auf diese Weise erhält ein Wort an unterschiedlichen Positionen im Satz eine unterschiedliche Repräsentation (Bedeutung).

### **Was sind Token Embeddings?**

**Token Embeddings** sind numerische Repräsentationen von Tokens in einem kontinuierlichen Vektorraum. Jedes Token im Vokabular ist einem eindeutigen Vektor mit festen Dimensionen zugeordnet. Diese Vektoren erfassen semantische und syntaktische Informationen über die Tokens und ermöglichen es dem Modell, Beziehungen und Muster in den Daten zu verstehen.

- **Vokabulargröße:** Die Gesamtzahl der eindeutigen Tokens (z. B. Wörter oder Subwörter) im Vokabular des Modells.
- **Embedding-Dimensionen:** Die Anzahl numerischer Werte (Dimensionen) im Vektor jedes Tokens. Höhere Dimensionen können detailliertere Informationen erfassen, erfordern jedoch mehr Rechenressourcen.

**Beispiel:**

- **Vokabulargröße:** 6 Tokens \[1, 2, 3, 4, 5, 6]
- **Embedding-Dimensionen:** 3 (x, y, z)

### **Initialisieren von Token Embeddings**

Zu Beginn des Trainings werden Token Embeddings typischerweise mit kleinen Zufallswerten initialisiert. Diese Anfangswerte werden während des Trainings angepasst (feinabgestimmt), um die Bedeutung der Tokens auf Grundlage der Trainingsdaten besser darzustellen.

**PyTorch-Beispiel:**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Funktionsweise von Token Embeddings während des Trainings**

Während des Trainings wird jedes Token in den Eingabedaten in den entsprechenden Embedding-Vektor umgewandelt. Diese Vektoren werden anschließend in verschiedenen Berechnungen innerhalb des Modells verwendet, beispielsweise in Attention-Mechanismen und neuronalen Netzwerkschichten.

**Beispielszenario:**

- **Batch Size:** 8 (Anzahl der gleichzeitig verarbeiteten Samples)
- **Max Sequence Length:** 4 (Anzahl der Tokens pro Sample)
- **Embedding Dimensions:** 256

**Datenstruktur:**

- Jeder Batch wird als 3D-Tensor mit der Form `(batch_size, max_length, embedding_dim)` dargestellt.
- In unserem Beispiel wäre die Form `(8, 4, 256)`.

## **Positions-Embeddings: Kontext zu Token-Embeddings hinzufügen**

Während Token-Embeddings die Bedeutung einzelner Tokens erfassen, codieren sie nicht automatisch die Position der Tokens innerhalb einer Sequenz. Das Verständnis der Reihenfolge von Tokens ist für das Sprachverständnis entscheidend. Hier kommen **Positions-Embeddings** zum Einsatz.

### **Warum Positions-Embeddings benötigt werden:**

- **Die Reihenfolge der Tokens ist wichtig:** In Sätzen hängt die Bedeutung häufig von der Reihenfolge der Wörter ab. Zum Beispiel: „Die Katze saß auf der Matte“ im Vergleich zu „Die Matte saß auf der Katze.“
- **Einschränkung von Embeddings:** Ohne Positionsinformationen behandelt das Modell Tokens wie eine „bag of words“ und ignoriert ihre Reihenfolge.

### **Arten von Positions-Embeddings:**

1. **Absolute Positions-Embeddings:**
- Weisen jeder Position in der Sequenz einen eindeutigen Positionsvektor zu.
- **Beispiel:** Der erste Token in jeder Sequenz hat dasselbe Positions-Embedding, der zweite Token ein anderes und so weiter.
- **Verwendet von:** OpenAI’s GPT-Modellen.
2. **Relative Positions-Embeddings:**
- Codieren die relative Entfernung zwischen Tokens anstelle ihrer absoluten Positionen.
- **Beispiel:** Geben an, wie weit zwei Tokens voneinander entfernt sind, unabhängig von ihren absoluten Positionen in der Sequenz.
- **Verwendet von:** Modellen wie Transformer-XL und einigen Varianten von BERT.

### **Wie Positions-Embeddings integriert werden:**

- **Gleiche Dimensionen:** Positions-Embeddings haben dieselbe Dimensionalität wie Token-Embeddings.
- **Addition:** Sie werden zu den Token-Embeddings addiert, wodurch Token-Identität und Positionsinformationen kombiniert werden, ohne die Gesamtdimensionalität zu erhöhen.

**Beispiel für das Addieren von Positions-Embeddings:**

Angenommen, ein Token-Embedding-Vektor ist `[0.5, -0.2, 0.1]` und sein Positions-Embedding-Vektor ist `[0.1, 0.3, -0.1]`. Das vom Modell verwendete kombinierte Embedding wäre:
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**Vorteile von Positional Embeddings:**

- **Kontextbewusstsein:** Das Modell kann Tokens anhand ihrer Positionen unterscheiden.
- **Sequenzverständnis:** Ermöglicht dem Modell, Grammatik, Syntax und kontextabhängige Bedeutungen zu verstehen.

## **Positional Embeddings in modernen LLMs**

### **Rotary Positional Embeddings (RoPE)**

RoPE kodiert die Position, indem eine positionsabhängige Rotation auf Paare von Dimensionen in den Query-/Key-Vektoren angewendet wird. Dadurch werden absolute Positionen in relative Phasendifferenzen umgewandelt. Dies liefert Informationen über relative Positionen, während die Dimensionalität der Embeddings unverändert bleibt, und wird häufig in aktuellen Decoder-only-LLMs verwendet.<sup>[[2]](#references)</sup>

Wie Token- und Positional-Embeddings innerhalb des Modells kombiniert werden, erfahren Sie auf [der LLM-Architektur-Seite](5.-llm-architecture.md).

### **Erweitern von Context Windows in RoPE-basierten Modellen**

Aktuelle Forschung zeigt, dass die Context Length häufig durch das Positional-Encoding-Schema und nicht durch die Token-Embedding-Matrix selbst begrenzt wird.

- **Position Interpolation (PI):** Skaliert Positionsindizes neu, sodass längere Sequenzen in den während des Trainings beobachteten Bereich abgebildet werden. Dadurch wird eine Erweiterung mit minimalem Fine-tuning ermöglicht.<sup>[[3]](#references)</sup> Beispiel:
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** Eine recheneffiziente RoPE-Erweiterungsstrategie, die die RoPE-Skalierung/Interpolation anpasst, um mit weniger zusätzlichen Trainingsschritten auf längere Kontexte zu extrapolieren.<sup>[[4]](#references)</sup>

## Codebeispiel

Das folgende Codebeispiel stammt aus [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[5]](#references)</sup>
```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
