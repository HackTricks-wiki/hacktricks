## Token-inbeddings

Nadat teksdata getokeniseer is, is die volgende kritieke stap in die voorbereiding van data vir die training van large language models (LLMs) soos GPT, die skep van **token-inbeddings**. Token-inbeddings transformeer diskrete tokens (soos woorde of subwoorde) in kontinue numeriese vektore wat die model kan verwerk en waaruit dit kan leer. Hierdie verduideliking ontleed token-inbeddings, hul initialisering en gebruik, asook die rol van posisionele inbeddings om die model se begrip van tokenreekse te verbeter.<sup>[[1]](#references)</sup>

> [!TIP]
> Die doel van hierdie derde fase is baie eenvoudig: **Ken aan elkeen van die vorige tokens in die woordeskat 'n vektor van die verlangde dimensies toe om die model te train.** Elke woord in die woordeskat sal 'n punt in 'n ruimte van X dimensies wees.\
> Let daarop dat die posisie van elke woord in die ruimte aanvanklik bloot "lukraak" geïnisialiseer word en dat hierdie posisies trainbare parameters is (dit sal tydens die training verbeter word).
>
> Verder word daar tydens die token-inbedding **nog 'n laag van inbeddings geskep** wat (in hierdie geval) die **absolute posisie van die woord in die training-sin** verteenwoordig. Op hierdie manier sal 'n woord in verskillende posisies in die sin 'n verskillende voorstelling (betekenis) hê.

### **Wat Is Token-inbeddings?**

**Token-inbeddings** is numeriese voorstellings van tokens in 'n kontinue vektorruimte. Elke token in die woordeskat word met 'n unieke vektor van vaste dimensies geassosieer. Hierdie vektore bevat semantiese en sintaktiese inligting oor die tokens, wat die model in staat stel om verhoudings en patrone in die data te verstaan.

- **Woordeskadgrootte:** Die totale aantal unieke tokens (bv. woorde, subwoorde) in die model se woordeskat.
- **Inbeddingsdimensies:** Die aantal numeriese waardes (dimensies) in elke token se vektor. Hoër dimensies kan meer genuanseerde inligting vasvang, maar vereis meer computational resources.

**Voorbeeld:**

- **Woordeskadgrootte:** 6 tokens \[1, 2, 3, 4, 5, 6]
- **Inbeddingsdimensies:** 3 (x, y, z)

### **Initialisering van Token-inbeddings**

Aan die begin van die training word token-inbeddings tipies met klein lukrake waardes geïnisialiseer. Hierdie aanvanklike waardes word tydens die training aangepas (fyn ingestel) om die tokens se betekenisse beter op grond van die training-data voor te stel.

**PyTorch-voorbeeld:**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Hoe Token Embeddings Tydens Training Werk**

Tydens training word elke token in die inputdata na sy ooreenstemmende embedding vector omgeskakel. Hierdie vektore word dan in verskeie berekeninge binne die model gebruik, soos aandagmeganismes en neural network-lae.

**Voorbeeldscenario:**

- **Batch Size:** 8 (aantal samples wat gelyktydig verwerk word)
- **Max Sequence Length:** 4 (aantal tokens per sample)
- **Embedding Dimensions:** 256

**Datastruktuur:**

- Elke batch word voorgestel as 'n 3D-tensor met die vorm `(batch_size, max_length, embedding_dim)`.
- Vir ons voorbeeld sal die vorm `(8, 4, 256)` wees.

## **Posisionele Embeddings: Voeg Konteks by Token Embeddings**

Hoewel token embeddings die betekenis van individuele tokens vaslê, kodeer hulle nie inherent die posisie van tokens binne ’n volgorde nie. Om die volgorde van tokens te verstaan, is noodsaaklik vir taalbegrip. Dit is waar **positional embeddings** ter sprake kom.

### **Waarom Positional Embeddings Nodig Is:**

- **Tokenvolgorde Is Belangrik:** In sinne hang die betekenis dikwels van die volgorde van woorde af. Byvoorbeeld, "The cat sat on the mat" teenoor "The mat sat on the cat."
- **Beperking van Embeddings:** Sonder posisionele inligting behandel die model tokens as ’n "bag of words" en ignoreer dit hul volgorde.

### **Tipes Positional Embeddings:**

1. **Absolute Positional Embeddings:**
- Ken ’n unieke posisie-vektor aan elke posisie in die volgorde toe.
- **Voorbeeld:** Die eerste token in enige volgorde het dieselfde positional embedding, die tweede token het ’n ander een, ensovoorts.
- **Gebruik Deur:** OpenAI se GPT-modelle.
2. **Relative Positional Embeddings:**
- Kodeer die relatiewe afstand tussen tokens eerder as hul absolute posisies.
- **Voorbeeld:** Dui aan hoe ver twee tokens van mekaar af is, ongeag hul absolute posisies in die volgorde.
- **Gebruik Deur:** Modelle soos Transformer-XL en sommige variante van BERT.

### **Hoe Positional Embeddings Geïntegreer Word:**

- **Dieselfde Dimensies:** Positional embeddings het dieselfde dimensionaliteit as token embeddings.
- **Optelling:** Hulle word by token embeddings getel, wat token-identiteit met posisionele inligting kombineer sonder om die algehele dimensionaliteit te verhoog.

**Voorbeeld van die Optelling van Positional Embeddings:**

Gestel ’n token-embedding-vektor is `[0.5, -0.2, 0.1]` en sy positional-embedding-vektor is `[0.1, 0.3, -0.1]`. Die gekombineerde embedding wat deur die model gebruik word, sal wees:
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**Voordele van Posisionele Embeddings:**

- **Kontekstuele Bewustheid:** Die model kan tussen tokens onderskei op grond van hul posisies.
- **Volgorde-begrip:** Stel die model in staat om grammatika, sintaksis en konteksafhanklike betekenisse te verstaan.

## **Posisionele Embeddings in Moderne LLMs**

### **Rotary Positional Embeddings (RoPE)**

RoPE enkodeer posisie deur ’n posisieafhanklike rotasie op pare dimensies in die query/key-vektore toe te pas, wat absolute posisies in relatiewe faseverskille omskakel. Dit verskaf relatiewe posisie-inligting terwyl die embedding-dimensie onveranderd bly en word wyd in onlangse decoder-only LLMs gebruik.<sup>[[2]](#references)</sup>

Vir hoe token- en posisionele embeddings binne die model gekombineer word, sien [die LLM-argitektuurbladsy](5.-llm-architecture.md).

### **Uitbreiding van Konteksvensters in RoPE-Gebaseerde Modelle**

Onlangse werk toon dat kontekslengte dikwels deur die posisionele encoding-skema beperk word eerder as deur die token embedding-matriks self.

- **Position Interpolation (PI):** Skaal posisie-indekse מחדש sodat langer sekwense binne die reeks val wat tydens opleiding gesien is, wat uitbreiding met minimale fine-tuning moontlik maak.<sup>[[3]](#references)</sup> Voorbeeld:
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** ’n Berekeningsdoeltreffende RoPE-uitbreidingstrategie wat RoPE-skalering/interpolasie wysig om na langer kontekste te ekstrapoleer met minder bykomende trainingstappe.<sup>[[4]](#references)</sup>

```python
# Use previous code...

# Create dimensional emdeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
