## Incrustaciones de tokens

Después de tokenizar los datos de texto, el siguiente paso fundamental para preparar los datos con los que se entrenarán modelos de lenguaje grandes (LLM), como GPT, es crear **incrustaciones de tokens**. Estas transforman tokens discretos (como palabras o subpalabras) en vectores numéricos continuos que el modelo puede procesar y de los que puede aprender. Esta explicación desglosa las incrustaciones de tokens, su inicialización, uso y el papel de las incrustaciones posicionales para mejorar la comprensión del modelo de las secuencias de tokens.<sup>[[1]](#references)</sup>

> [!TIP]
> El objetivo de esta tercera fase es muy sencillo: **Asignar a cada uno de los tokens anteriores del vocabulario un vector con las dimensiones deseadas para entrenar el modelo.** Cada palabra del vocabulario será un punto en un espacio de X dimensiones.\
> Ten en cuenta que, al principio, la posición de cada palabra en el espacio se inicializa de forma «aleatoria», y estas posiciones son parámetros entrenables (se mejorarán durante el entrenamiento).
>
> Además, durante la incrustación de tokens, **se crea otra capa de incrustaciones** que representa (en este caso) la **posición absoluta de la palabra en la oración de entrenamiento**. De esta manera, una palabra en distintas posiciones de la oración tendrá una representación (significado) diferente.

### **¿Qué son las incrustaciones de tokens?**

Las **incrustaciones de tokens** son representaciones numéricas de los tokens en un espacio vectorial continuo. A cada token del vocabulario se le asocia un vector único de dimensiones fijas. Estos vectores capturan información semántica y sintáctica sobre los tokens, lo que permite al modelo comprender relaciones y patrones en los datos.

- **Tamaño del vocabulario:** El número total de tokens únicos (por ejemplo, palabras o subpalabras) del vocabulario del modelo.
- **Dimensiones de la incrustación:** El número de valores numéricos (dimensiones) del vector de cada token. Las dimensiones más altas pueden captar información más sutil, pero requieren más recursos computacionales.

**Ejemplo:**

- **Tamaño del vocabulario:** 6 tokens \[1, 2, 3, 4, 5, 6]
- **Dimensiones de la incrustación:** 3 (x, y, z)

### **Inicialización de las incrustaciones de tokens**

Al comenzar el entrenamiento, las incrustaciones de tokens suelen inicializarse con valores aleatorios pequeños. Estos valores iniciales se ajustan durante el entrenamiento para representar mejor el significado de los tokens según los datos de entrenamiento.

**Ejemplo en PyTorch:**

```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

**Salida:**

- Por ejemplo, el token en el índice `3` tiene el vector de embedding `[-0.4015, 0.9666, -1.1481]`.

**Acceso al embedding de un token:**

# Retrieve the embedding for the token at index 3

- El token en el índice `3` se representa mediante el vector `[-0.4015, 0.9666, -1.1481]`.
- Estos valores son parámetros entrenables que el modelo ajustará durante el entrenamiento para representar mejor el contexto y el significado del token.

### **Cómo funcionan los embeddings de tokens durante el entrenamiento**

Durante el entrenamiento, cada token de los datos de entrada se convierte en su vector de embedding correspondiente. Estos vectores se usan después en varios cálculos dentro del modelo, como los mecanismos de atención y las capas de redes neuronales.

**Escenario de ejemplo:**

- **Tamaño del lote:** 8 (número de muestras procesadas simultáneamente)
- **Longitud máxima de la secuencia:** 4 (número de tokens por muestra)
- **Dimensiones del embedding:** 256

**Estructura de los datos:**

- Cada lote se representa como un tensor 3D con la forma `(batch_size, max_length, embedding_dim)`.
- Para nuestro ejemplo, la forma sería `(8, 4, 256)`.

- El modelo procesa estos embeddings para aprender patrones lingüísticos y generar predicciones.

## **Embeddings posicionales: añadir contexto a los embeddings de tokens**

Aunque los embeddings de tokens capturan el significado de cada token, no codifican de forma inherente la posición de los tokens dentro de una secuencia. Comprender el orden de los tokens es crucial para entender el lenguaje. Aquí es donde entran en juego los **embeddings posicionales**.

### **Por qué se necesitan los embeddings posicionales:**

- **El orden de los tokens importa:** En las oraciones, el significado suele depender del orden de las palabras. Por ejemplo, «El gato se sentó en la alfombra» frente a «La alfombra se sentó sobre el gato».
- **Limitación de los embeddings:** Sin información posicional, el modelo trata los tokens como una «bolsa de palabras» e ignora su secuencia.

### **Tipos de embeddings posicionales:**

1. **Embeddings posicionales absolutos:**
   - Asignan un vector posicional único a cada posición de la secuencia.
   - **Ejemplo:** El primer token de cualquier secuencia tiene el mismo embedding posicional, el segundo token tiene otro, y así sucesivamente.
   - **Usados por:** Los modelos GPT de OpenAI.
2. **Embeddings posicionales relativos:**
   - Codifican la distancia relativa entre los tokens, en lugar de sus posiciones absolutas.
   - **Ejemplo:** Indican cuán separados están dos tokens, independientemente de sus posiciones absolutas en la secuencia.
   - **Usados por:** Modelos como Transformer-XL y algunas variantes de BERT.

### **Cómo se integran los embeddings posicionales:**

- **Las mismas dimensiones:** Los embeddings posicionales tienen la misma dimensionalidad que los embeddings de tokens.
- **Suma:** Se suman a los embeddings de tokens, combinando la identidad del token con la información posicional sin aumentar la dimensionalidad total.

**Ejemplo de suma de embeddings posicionales:**

Supongamos que un vector de embedding de token es `[0.5, -0.2, 0.1]` y su vector de embedding posicional es `[0.1, 0.3, -0.1]`. El embedding combinado que usará el modelo sería:

```css
Combined Embedding = Token Embedding + Positional Embedding
                   = [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
                   = [0.6, 0.1, 0.0]
```

**Beneficios de los embeddings posicionales:**

- **Conciencia contextual:** El modelo puede diferenciar los tokens según sus posiciones.
- **Comprensión de secuencias:** Permite al modelo comprender la gramática, la sintaxis y los significados que dependen del contexto.

## **Embeddings posicionales en los LLM modernos**

### **Embeddings posicionales rotatorios (RoPE)**

RoPE codifica la posición aplicando una rotación que depende de la posición a pares de dimensiones de los vectores query/key, convirtiendo las posiciones absolutas en diferencias de fase relativas. Esto proporciona información sobre la posición relativa sin cambiar la dimensionalidad de los embeddings y se usa ampliamente en los LLM recientes de solo decodificador.<sup>[[2]](#references)</sup>

Para saber cómo se combinan los embeddings de tokens y posicionales dentro del modelo, consulta [la página sobre la arquitectura de los LLM](5.-llm-architecture.md).

### **Ampliación de las ventanas de contexto en modelos basados en RoPE**

Trabajos recientes muestran que la longitud del contexto suele estar limitada por el esquema de codificación posicional, más que por la propia matriz de embeddings de tokens.

- **Interpolación de posiciones (PI):** Reescala los índices de posición para que las secuencias más largas se ajusten al rango observado durante el entrenamiento, lo que permite ampliarlo con un ajuste fino mínimo.<sup>[[3]](#references)</sup> Ejemplo:

```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```

- **YaRN:** Una estrategia de extensión de RoPE eficiente en términos de cómputo que modifica el escalado/interpolación de RoPE para extrapolar a contextos más largos con menos pasos de entrenamiento adicionales.<sup>[[4]](#references)</sup>

## Ejemplo de código

A continuación, se muestra el ejemplo de código de [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[5]](#references)</sup>

```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
    raw_text, batch_size=8, max_length=max_length,
    stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
