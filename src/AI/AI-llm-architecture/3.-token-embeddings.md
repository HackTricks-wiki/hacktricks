## Token-inbeddings

Nadat teksdata getokeniseer is, is die volgende kritieke stap in die voorbereiding van data vir die opleiding van groot taalmodelle (LLMs) soos GPT, die skep van **token-inbeddings**. Token-inbeddings transformeer diskrete tokens (soos woorde of subwoorde) in deurlopende numeriese vektore wat die model kan verwerk en waaruit dit kan leer. Hierdie verduideliking breek token-inbeddings, hul inisialisering en gebruik, asook die rol van posisionele inbeddings af om die model se begrip van tokenreekse te verbeter.<sup>[[1]](#references)</sup>

> [!TIP]
> Die doel van hierdie derde fase is baie eenvoudig: **Ken aan elkeen van die vorige tokens in die woordeskat ’n vektor met die verlangde dimensies toe om die model op te lei.** Elke woord in die woordeskat sal ’n punt in ’n ruimte met X dimensies wees.\
> Let daarop dat die posisie van elke woord in die ruimte aanvanklik bloot “lukraak” geïnisialiseer word, en dat hierdie posisies trainable parameters is (dit sal tydens die opleiding verbeter word).
>
> Boonop word daar tydens die token-inbedding **nog ’n laag van inbeddings geskep** wat (in hierdie geval) die **absolute posisie van die woord in die opleidingsin** verteenwoordig. Op hierdie manier sal ’n woord op verskillende posisies in die sin ’n verskillende voorstelling (betekenis) hê.

### **Wat is token-inbeddings?**

**Token-inbeddings** is numeriese voorstellings van tokens in ’n deurlopende vektorruimte. Elke token in die woordeskat word met ’n unieke vektor van vaste dimensies geassosieer. Hierdie vektore bevat semantiese en sintaktiese inligting oor die tokens, wat die model in staat stel om verhoudings en patrone in die data te verstaan.

- **Woordeskatgrootte:** Die totale aantal unieke tokens (bv. woorde, subwoorde) in die model se woordeskat.
- **Inbeddingsdimensies:** Die aantal numeriese waardes (dimensies) in elke token se vektor. Hoër dimensies kan meer genuanseerde inligting vasvang, maar vereis meer computational resources.

**Voorbeeld:**

- **Woordeskatgrootte:** 6 tokens \[1, 2, 3, 4, 5, 6]
- **Inbeddingsdimensies:** 3 (x, y, z)

### **Initialisering van token-inbeddings**

Aan die begin van opleiding word token-inbeddings tipies met klein lukrake waardes geïnisialiseer. Hierdie aanvanklike waardes word tydens opleiding aangepas (fine-tuned) om die betekenis van die tokens beter volgens die opleidingsdata voor te stel.

**PyTorch-voorbeeld:**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Hoe Token Embeddings Tydens Opleiding Werk**

Tydens opleiding word elke token in die invoerdata na sy ooreenstemmende embedding-vektor omgeskakel. Hierdie vektore word dan in verskeie berekeninge binne die model gebruik, soos aandagmeganismes en neurale netwerklae.

**Voorbeeldscenario:**

- **Batch Size:** 8 (aantal monsters wat gelyktydig verwerk word)
- **Max Sequence Length:** 4 (aantal tokens per monster)
- **Embedding Dimensions:** 256

**Datastruktuur:**

- Elke batch word as ’n 3D-tensor met die vorm `(batch_size, max_length, embedding_dim)` voorgestel.
- Vir ons voorbeeld sal die vorm `(8, 4, 256)` wees.

## **Posisionele inbeddings: Voeg konteks by token-inbeddings**

Hoewel token-inbeddings die betekenis van individuele tokens vasvang, kodeer hulle nie inherent die posisie van tokens binne ’n volgorde nie. Dit is noodsaaklik om die volgorde van tokens te verstaan vir taalbegrip. Dit is waar **posisionele inbeddings** ter sprake kom.

### **Waarom posisionele inbeddings nodig is:**

- **Tokenvolgorde is belangrik:** In sinne hang die betekenis dikwels van die volgorde van woorde af. Byvoorbeeld, "Die kat het op die mat gesit" teenoor "Die mat het op die kat gesit."
- **Beperking van inbeddings:** Sonder posisionele inligting behandel die model tokens as ’n "sak woorde" en ignoreer dit hul volgorde.

### **Tipes posisionele inbeddings:**

1. **Absolute posisionele inbeddings:**
- Ken ’n unieke posisievektor aan elke posisie in die volgorde toe.
- **Voorbeeld:** Die eerste token in enige volgorde het dieselfde posisionele inbedding, die tweede token het ’n ander een, ensovoorts.
- **Gebruik deur:** OpenAI se GPT-modelle.
2. **Relatiewe posisionele inbeddings:**
- Kodeer die relatiewe afstand tussen tokens eerder as hul absolute posisies.
- **Voorbeeld:** Dui aan hoe ver twee tokens van mekaar af is, ongeag hul absolute posisies in die volgorde.
- **Gebruik deur:** Modelle soos Transformer-XL en sommige variante van BERT.

### **Hoe posisionele inbeddings geïntegreer word:**

- **Dieselfde dimensies:** Posisionele inbeddings het dieselfde dimensionaliteit as token-inbeddings.
- **Optelling:** Hulle word by token-inbeddings getel, wat token-identiteit met posisionele inligting kombineer sonder om die algehele dimensionaliteit te verhoog.

**Voorbeeld van die optelling van posisionele inbeddings:**

Gestel ’n token-inbeddingsvektor is `[0.5, -0.2, 0.1]` en sy posisionele inbeddingsvektor is `[0.1, 0.3, -0.1]`. Die gekombineerde inbedding wat deur die model gebruik word, sou wees:
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**Voordele van Posisionele Embeddings:**

- **Konteksbewustheid:** Die model kan tussen tokens onderskei op grond van hul posisies.
- **Volgordebegrip:** Stel die model in staat om grammatika, sintaksis en konteksafhanklike betekenisse te verstaan.

## **Posisionele Embeddings in Moderne LLMs**

### **Rotary Positional Embeddings (RoPE)**

RoPE kodeer posisie deur ’n posisieafhanklike rotasie op pare dimensies in die query/key-vektore toe te pas, wat absolute posisies in relatiewe faseverskille omskakel. Dit verskaf relatiewe posisie-inligting terwyl die embedding-dimensie onveranderd bly en word wyd in onlangse decoder-only LLMs gebruik.<sup>[[2]](#references)</sup>

Vir hoe token- en posisionele embeddings binne die model gekombineer word, sien [die LLM-argitektuurbladsy](5.-llm-architecture.md).

### **Uitbreiding van Konteksvensters in RoPE-gebaseerde Modelle**

Onlangse werk toon dat kontekslengte dikwels deur die posisionele enkoderingskema eerder as die token-embedding-matriks self beperk word.

- **Position Interpolation (PI):** Skaal posisie-indekse מחדש sodat langer sekwense binne die reeks val wat tydens opleiding gesien is, wat uitbreiding met minimale fine-tuning moontlik maak.<sup>[[3]](#references)</sup> Voorbeeld:
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** ’n Berekeningsdoeltreffende RoPE-uitbreidingstrategie wat RoPE-skalering/interpolasie wysig om na langer kontekste te ekstrapoleer met minder bykomende opleidingstappe.<sup>[[4]](#references)</sup>

```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
