## Embedding dei token

Dopo aver eseguito il tokenizing dei dati testuali, il successivo passaggio fondamentale nella preparazione dei dati per l'addestramento di large language models (LLM) come GPT consiste nella creazione degli **embedding dei token**. Gli embedding dei token trasformano i token discreti (come parole o subword) in vettori numerici continui che il modello può elaborare e da cui può apprendere. Questa spiegazione analizza gli embedding dei token, la loro inizializzazione e il loro utilizzo, oltre al ruolo degli embedding posizionali nel migliorare la comprensione da parte del modello delle sequenze di token.<sup>[[1]](#references)</sup>

> [!TIP]
> L'obiettivo di questa terza fase è molto semplice: **assegnare a ciascuno dei token precedenti nel vocabolario un vettore delle dimensioni desiderate per addestrare il modello.** Ogni parola nel vocabolario sarà un punto in uno spazio di X dimensioni.\
> Nota che inizialmente la posizione di ogni parola nello spazio viene semplicemente inizializzata in modo "casuale" e queste posizioni sono parametri addestrabili (che verranno migliorati durante l'addestramento).
>
> Inoltre, durante il token embedding **viene creato un altro layer di embedding** che rappresenta (in questo caso) la **posizione assoluta della parola nella frase di addestramento**. In questo modo, una parola in posizioni diverse della frase avrà una rappresentazione (significato) diversa.

### **Cosa sono gli embedding dei token?**

Gli **embedding dei token** sono rappresentazioni numeriche dei token in uno spazio vettoriale continuo. A ogni token del vocabolario è associato un vettore univoco di dimensioni fisse. Questi vettori acquisiscono informazioni semantiche e sintattiche sui token, consentendo al modello di comprendere relazioni e pattern nei dati.

- **Dimensione del vocabolario:** il numero totale di token univoci (ad esempio parole o subword) presenti nel vocabolario del modello.
- **Dimensioni dell'embedding:** il numero di valori numerici (dimensioni) nel vettore di ciascun token. Dimensioni maggiori possono acquisire informazioni più sfumate, ma richiedono più risorse computazionali.

**Esempio:**

- **Dimensione del vocabolario:** 6 token \[1, 2, 3, 4, 5, 6]
- **Dimensioni dell'embedding:** 3 (x, y, z)

### **Inizializzazione degli embedding dei token**

All'inizio dell'addestramento, gli embedding dei token vengono generalmente inizializzati con piccoli valori casuali. Questi valori iniziali vengono modificati (fine-tuned) durante l'addestramento per rappresentare meglio i significati dei token sulla base dei dati di addestramento.

**Esempio in PyTorch:**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Come funzionano i Token Embeddings durante il Training**

Durante il training, ogni token nei dati di input viene convertito nel vettore di embedding corrispondente. Questi vettori vengono quindi utilizzati in vari calcoli all'interno del modello, come i meccanismi di attention e i layer della rete neurale.

**Scenario di esempio:**

- **Batch Size:** 8 (numero di sample elaborati simultaneamente)
- **Max Sequence Length:** 4 (numero di token per sample)
- **Embedding Dimensions:** 256

**Struttura dei dati:**

- Ogni batch è rappresentato da un tensore 3D con shape `(batch_size, max_length, embedding_dim)`.
- Per il nostro esempio, la shape sarebbe `(8, 4, 256)`.

## **Positional Embeddings: aggiungere il contesto agli embeddings dei token**

Sebbene gli embeddings dei token catturino il significato dei singoli token, non codificano intrinsecamente la posizione dei token all'interno di una sequenza. Comprendere l'ordine dei token è fondamentale per la comprensione del linguaggio. È qui che entrano in gioco gli **positional embeddings**.

### **Perché sono necessari gli positional embeddings:**

- **L'ordine dei token è importante:** nelle frasi, il significato spesso dipende dall'ordine delle parole. Ad esempio, "The cat sat on the mat" rispetto a "The mat sat on the cat."
- **Limite degli embeddings:** senza informazioni posizionali, il modello tratta i token come un "bag of words", ignorando la loro sequenza.

### **Tipi di positional embeddings:**

1. **Absolute Positional Embeddings:**
- Assegnano un vettore di posizione univoco a ogni posizione nella sequenza.
- **Esempio:** il primo token di qualsiasi sequenza ha lo stesso positional embedding, il secondo token ne ha un altro, e così via.
- **Utilizzati da:** i modelli GPT di OpenAI.
2. **Relative Positional Embeddings:**
- Codificano la distanza relativa tra i token anziché le loro posizioni assolute.
- **Esempio:** indicano quanto sono distanti due token, indipendentemente dalle loro posizioni assolute nella sequenza.
- **Utilizzati da:** modelli come Transformer-XL e alcune varianti di BERT.

### **Come vengono integrati gli positional embeddings:**

- **Stesse dimensioni:** gli positional embeddings hanno la stessa dimensionalità degli embeddings dei token.
- **Addizione:** vengono aggiunti agli embeddings dei token, combinando l'identità del token con le informazioni posizionali senza aumentare la dimensionalità complessiva.

**Esempio di addizione degli positional embeddings:**

Supponiamo che un vettore di embedding del token sia `[0.5, -0.2, 0.1]` e che il suo vettore di embedding posizionale sia `[0.1, 0.3, -0.1]`. L'embedding combinato utilizzato dal modello sarebbe:
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**Vantaggi degli embeddings posizionali:**

- **Consapevolezza contestuale:** Il modello può distinguere tra i token in base alle loro posizioni.
- **Comprensione della sequenza:** Consente al modello di comprendere grammatica, sintassi e significati dipendenti dal contesto.

## **Embeddings posizionali nei moderni LLM**

### **Rotary Positional Embeddings (RoPE)**

RoPE codifica la posizione applicando una rotazione dipendente dalla posizione a coppie di dimensioni nei vettori query/key, trasformando le posizioni assolute in differenze di fase relative. Ciò fornisce informazioni sulla posizione relativa mantenendo invariata la dimensionalità degli embeddings ed è ampiamente utilizzato nei recenti LLM decoder-only.<sup>[[2]](#references)</sup>

Per sapere come vengono combinati gli embeddings dei token e quelli posizionali all'interno del modello, consulta [la pagina sull'architettura degli LLM](5.-llm-architecture.md).

### **Estensione delle finestre di contesto nei modelli basati su RoPE**

Lavori recenti mostrano che la lunghezza del contesto è spesso limitata dallo schema di codifica posizionale, anziché dalla matrice degli embeddings dei token.

- **Position Interpolation (PI):** Ridimensiona gli indici di posizione in modo che le sequenze più lunghe rientrino nell'intervallo osservato durante il training, consentendo un'estensione con un fine-tuning minimo.<sup>[[3]](#references)</sup> Esempio:
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** Una strategia di estensione di RoPE efficiente dal punto di vista computazionale che modifica lo scaling/l'interpolazione di RoPE per estrapolare contesti più lunghi con un numero inferiore di passaggi di training aggiuntivi.<sup>[[4]](#references)</sup>

## Esempio di codice

Proseguendo con l'esempio di codice da [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[5]](#references)</sup>
```python
# Use previous code...

# Create dimensional emdeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
