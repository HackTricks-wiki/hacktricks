## Токенові вбудовування

Після токенізації текстових даних наступним важливим кроком у підготовці даних для навчання великих мовних моделей (LLM), таких як GPT, є створення **токенових вбудовувань**. Токенові вбудовування перетворюють дискретні токени (наприклад, слова або підслова) на неперервні числові вектори, які модель може обробляти й на яких може навчатися. У цьому поясненні розглянуто токенові вбудовування, їх ініціалізацію та використання, а також роль позиційних вбудовувань у покращенні розуміння моделлю послідовностей токенів.<sup>[[1]](#references)</sup>

> [!TIP]
> Мета цього третього етапу дуже проста: **призначити кожному з попередніх токенів у словнику вектор потрібної розмірності для навчання моделі.** Кожне слово у словнику буде точкою у просторі з X вимірами.\
> Зверніть увагу, що спочатку позиція кожного слова у просторі просто ініціалізується «випадково», а ці позиції є параметрами, які можна навчати (їх буде вдосконалено під час навчання).
>
> Крім того, під час створення токенових вбудовувань **створюється ще один шар вбудовувань**, який представляє (у цьому випадку) **абсолютну позицію слова в реченні для навчання**. Завдяки цьому слово в різних позиціях речення матиме різне представлення (значення).

### **Що таке токенові вбудовування?**

**Токенові вбудовування** — це числові представлення токенів у неперервному векторному просторі. Кожному токену у словнику відповідає унікальний вектор фіксованої розмірності. Ці вектори містять семантичну та синтаксичну інформацію про токени, що дає змогу моделі розуміти зв’язки та закономірності в даних.

- **Розмір словника:** загальна кількість унікальних токенів (наприклад, слів або підслів) у словнику моделі.
- **Розмірність вбудовування:** кількість числових значень (вимірів) у векторі кожного токена. Більша розмірність дає змогу врахувати більше нюансів, але потребує більше обчислювальних ресурсів.

**Приклад:**

- **Розмір словника:** 6 токенів \[1, 2, 3, 4, 5, 6]
- **Розмірність вбудовування:** 3 (x, y, z)

### **Ініціалізація токенових вбудовувань**

На початку навчання токенові вбудовування зазвичай ініціалізуються малими випадковими значеннями. Ці початкові значення коригуються (донастроюються) під час навчання, щоб краще передавати значення токенів на основі навчальних даних.

**Приклад для PyTorch:**

```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Як працюють token embeddings під час навчання**

Під час навчання кожен токен у вхідних даних перетворюється на відповідний вектор embedding. Потім ці вектори використовуються в різних обчисленнях усередині моделі, зокрема в механізмах уваги та шарах нейронної мережі.

**Приклад:**

- **Розмір батчу:** 8 (кількість зразків, що обробляються одночасно)
- **Максимальна довжина послідовності:** 4 (кількість токенів у кожному зразку)
- **Розмірність embedding:** 256

**Структура даних:**

- Кожен батч представлений 3D-тензором із формою `(batch_size, max_length, embedding_dim)`.
- У нашому прикладі форма буде `(8, 4, 256)`.

**Візуалізація:**

## **Позиційні embeddings: додавання контексту до embeddings токенів**

Хоча embeddings токенів передають значення окремих токенів, вони самі по собі не кодують позицію токенів у послідовності. Розуміння порядку токенів має вирішальне значення для сприйняття мови. Саме тут стають у пригоді **позиційні embeddings**.

### **Навіщо потрібні позиційні embeddings:**

- **Порядок токенів має значення:** У реченнях значення часто залежить від порядку слів. Наприклад, «Кіт сидів на килимку» та «Килимок сидів на коті».
- **Обмеження embeddings:** Без позиційної інформації модель сприймає токени як «мішок слів», ігноруючи їхню послідовність.

### **Типи позиційних embeddings:**

1. **Абсолютні позиційні embeddings:**
   - Призначають унікальний позиційний вектор кожній позиції в послідовності.
   - **Приклад:** Перший токен у будь-якій послідовності має однаковий позиційний embedding, другий токен — інший, і так далі.
   - **Використовують:** моделі GPT від OpenAI.
2. **Відносні позиційні embeddings:**
   - Кодують відносну відстань між токенами, а не їхні абсолютні позиції.
   - **Приклад:** Показують, наскільки далеко один від одного розташовані два токени, незалежно від їхніх абсолютних позицій у послідовності.
   - **Використовують:** моделі на кшталт Transformer-XL і деякі варіанти BERT.

### **Як інтегруються позиційні embeddings:**

- **Однакова розмірність:** Позиційні embeddings мають ту саму розмірність, що й embeddings токенів.
- **Додавання:** Їх додають до embeddings токенів, поєднуючи ідентичність токена з позиційною інформацією без збільшення загальної розмірності.

**Приклад додавання позиційних embeddings:**

Припустімо, що embedding-вектор токена дорівнює `[0.5, -0.2, 0.1]`, а його позиційний embedding-вектор — `[0.1, 0.3, -0.1]`. Об’єднаний embedding, який використовує модель, дорівнюватиме:

```css
Combined Embedding = Token Embedding + Positional Embedding
                   = [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
                   = [0.6, 0.1, 0.0]
```

**Переваги позиційних ембеддингів:**

- **Контекстна обізнаність:** Модель може розрізняти токени за їхніми позиціями.
- **Розуміння послідовностей:** Дає змогу моделі розуміти граматику, синтаксис і залежні від контексту значення.

## **Позиційні ембеддинги в сучасних LLM**

### **Ротаційні позиційні ембеддинги (RoPE)**

RoPE кодує позицію, застосовуючи залежне від позиції обертання до пар вимірів у векторах query/key, перетворюючи абсолютні позиції на відносні різниці фаз. Це забезпечує інформацію про відносні позиції, не змінюючи розмірність ембеддингу, і широко використовується в сучасних LLM лише з декодером.<sup>[[2]](#references)</sup>

Щоб дізнатися, як токенні та позиційні ембеддинги поєднуються всередині моделі, див. [сторінку про архітектуру LLM](5.-llm-architecture.md).

### **Розширення контекстних вікон у моделях на основі RoPE**

Недавні дослідження показують, що довжина контексту часто обмежена схемою позиційного кодування, а не самою матрицею токенних ембеддингів.

- **Інтерполяція позицій (PI):** Масштабує індекси позицій так, щоб довші послідовності відповідали діапазону, який модель бачила під час навчання, даючи змогу розширити контекст із мінімальним донавчанням.<sup>[[3]](#references)</sup> Приклад:

```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```

- **YaRN:** Обчислювально ефективна стратегія розширення RoPE, яка змінює масштабування/інтерполяцію RoPE, щоб підтримувати довші контексти з меншою кількістю додаткових кроків навчання.<sup>[[4]](#references)</sup>

```python
# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
    raw_text, batch_size=8, max_length=max_length,
    stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
