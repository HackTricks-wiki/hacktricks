## Token Embeddings

テキストデータをtokenizeした後、GPTのような大規模言語モデル（LLM）のtraining用データを準備する際の、次の重要なステップは**token embeddings**の作成です。Token embeddingsは、離散的なtoken（単語やsubwordなど）を、モデルが処理して学習できる連続的な数値ベクトルへ変換します。ここでは、token embeddings、その初期化と使用方法、さらにモデルがtoken sequenceをより深く理解するためのpositional embeddingsの役割について説明します。<sup>[[1]](#references)</sup>

> [!TIP]
> この第3フェーズの目的は非常にシンプルです。**vocabulary内の以前の各tokenに、モデルのtrainingに使用する指定された次元数のベクトルを割り当てます。** Vocabulary内の各単語は、X次元空間上の1点になります。\
> 初期状態では、空間内の各単語の位置は「ランダムに」初期化され、これらの位置はtrainable parametersです（training中に改善されます）。
>
> さらに、token embeddingの際には、（この場合）training sentence内の**単語の絶対位置**を表す**別のembedding layerが作成されます**。これにより、sentence内の異なる位置にある単語は、異なる表現（意味）を持つようになります。

### **Token Embeddingsとは？**

**Token Embeddings**は、連続ベクトル空間におけるtokenの数値表現です。Vocabulary内の各tokenには、固定された次元数の一意のベクトルが対応付けられます。これらのベクトルはtokenの意味的情報および構文的情報を捉え、モデルがデータ内の関係やパターンを理解できるようにします。

- **Vocabulary Size:** モデルのvocabularyに含まれる一意のtoken（単語、subwordなど）の総数。
- **Embedding Dimensions:** 各tokenのベクトルに含まれる数値（次元）の数。次元数が多いほど、より微妙な情報を捉えられますが、より多くの計算リソースが必要になります。

**例:**

- **Vocabulary Size:** 6 tokens \[1, 2, 3, 4, 5, 6]
- **Embedding Dimensions:** 3 (x, y, z)

### **Token Embeddingsの初期化**

Trainingの開始時、token embeddingsは通常、小さなランダム値で初期化されます。これらの初期値はtraining中に調整（fine-tuning）され、training dataに基づいてtokenの意味をより適切に表現できるようになります。

**PyTorch Example:**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Training 中の Token Embeddings の仕組み**

training 中、input data 内の各 token は、対応する embedding vector に変換されます。これらの vector は、attention mechanisms や neural network layers など、model 内のさまざまな計算で使用されます。

**Example Scenario:**

- **Batch Size:** 8（同時に処理されるサンプル数）
- **Max Sequence Length:** 4（各サンプルの token 数）
- **Embedding Dimensions:** 256

**Data Structure:**

- 各 batch は、`(batch_size, max_length, embedding_dim)` の shape を持つ 3D tensor で表されます。
- この例では、shape は `(8, 4, 256)` になります。

## **Positional Embeddings: Token Embeddings にコンテキストを追加**

Token embeddings は個々の token の意味を捉えますが、シーケンス内における token の位置を本質的にはエンコードしません。言語を理解するには、token の順序を把握することが重要です。ここで **positional embeddings** が役立ちます。

### **Positional Embeddings が必要な理由:**

- **Token の順序は重要:** 文では、意味が単語の順序に依存することがよくあります。例えば、「The cat sat on the mat」と「The mat sat on the cat」では意味が異なります。
- **Embedding の制限:** 位置情報がなければ、モデルは token を「bag of words」として扱い、シーケンスを無視します。

### **Positional Embeddings の種類:**

1. **Absolute Positional Embeddings:**
- シーケンス内の各位置に固有の位置ベクトルを割り当てます。
- **例:** どのシーケンスでも最初の token には同じ positional embedding が割り当てられ、2 番目の token には別の positional embedding が割り当てられます。
- **使用例:** OpenAI の GPT models。
2. **Relative Positional Embeddings:**
- 絶対的な位置ではなく、token 間の相対的な距離をエンコードします。
- **例:** シーケンス内の絶対位置に関係なく、2 つの token がどれだけ離れているかを示します。
- **使用例:** Transformer-XL や一部の BERT variants などの models。

### **Positional Embeddings の統合方法:**

- **同じ次元:** Positional embeddings は token embeddings と同じ dimensionality を持ちます。
- **加算:** Token の identity と位置情報を組み合わせるために token embeddings に加算されます。これにより、全体の dimensionality は増加しません。

**Positional Embeddings の加算例:**

Token embedding vector が `[0.5, -0.2, 0.1]` で、その positional embedding vector が `[0.1, 0.3, -0.1]` だとします。モデルが使用する combined embedding は次のようになります。
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**Positional Embeddingsの利点:**

- **Contextual Awareness:** モデルは、位置に基づいてtokenを区別できます。
- **Sequence Understanding:** モデルが文法、構文、そしてcontextに依存する意味を理解できるようになります。

## **Modern LLMにおけるPositional Embeddings**

### **Rotary Positional Embeddings (RoPE)**

RoPEは、query/key vectors内の次元のペアに位置依存の回転を適用することで位置をエンコードし、absolute positionsをrelative phase differencesに変換します。これにより、embeddingの次元数を変更せずにrelative position informationを提供でき、近年のdecoder-only LLMで広く使用されています。<sup>[[2]](#references)</sup>

モデル内部でtoken embeddingsとpositional embeddingsがどのように組み合わされるかについては、[LLM architecture page](5.-llm-architecture.md)を参照してください。

### **RoPE-Based ModelsにおけるContext Windowsの拡張**

最近の研究では、context lengthはtoken embedding matrix自体ではなく、positional encoding schemeによって制限されることが多いと示されています。

- **Position Interpolation (PI):** position indicesを再スケーリングし、より長いsequenceをtraining時に確認された範囲にマッピングすることで、最小限のfine-tuningで拡張を可能にします。<sup>[[3]](#references)</sup> 例:
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** RoPE の scaling/interpolation を変更し、追加の学習ステップを少なくして、より長いコンテキストへ外挿する、compute-efficient な RoPE 拡張戦略。<sup>[[4]](#references)</sup>

## Code Example

[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb) の code example に続いて説明します。<sup>[[5]](#references)</sup>
```python
# Use previous code...

# Create dimensional emdeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
