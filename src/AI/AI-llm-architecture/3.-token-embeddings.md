## Embedding dei token

Dopo aver tokenizzato i dati testuali, il passaggio critico successivo nella preparazione dei dati per l'addestramento di large language models (LLM) come GPT consiste nella creazione degli **embedding dei token**. Gli embedding dei token trasformano i token discreti (come parole o sottoparti di parole) in vettori numerici continui che il modello può elaborare e dai quali può apprendere. Questa spiegazione analizza gli embedding dei token, la loro inizializzazione e il loro utilizzo, oltre al ruolo degli embedding posizionali nel migliorare la comprensione delle sequenze di token da parte del modello.<sup>[[1]](#references)</sup>

> [!TIP]
> L'obiettivo di questa terza fase è molto semplice: **Assegnare a ciascuno dei token precedenti nel vocabolario un vettore delle dimensioni desiderate per addestrare il modello.** Ogni parola del vocabolario sarà un punto in uno spazio di X dimensioni.\
> Nota che inizialmente la posizione di ogni parola nello spazio viene semplicemente inizializzata in modo "casuale" e queste posizioni sono parametri addestrabili (che verranno migliorati durante l'addestramento).
>
> Inoltre, durante l'**embedding dei token viene creato un altro livello di embedding** che rappresenta (in questo caso) la **posizione assoluta della parola nella frase di addestramento**. In questo modo, una parola che si trova in posizioni diverse nella frase avrà una rappresentazione (un significato) differente.

### **Cosa sono gli embedding dei token?**

Gli **embedding dei token** sono rappresentazioni numeriche dei token in uno spazio vettoriale continuo. Ogni token del vocabolario è associato a un vettore univoco di dimensioni fisse. Questi vettori catturano informazioni semantiche e sintattiche sui token, consentendo al modello di comprendere le relazioni e gli schemi presenti nei dati.

- **Dimensione del vocabolario:** il numero totale di token univoci (ad esempio, parole o sottoparti di parole) nel vocabolario del modello.
- **Dimensioni dell'embedding:** il numero di valori numerici (dimensioni) nel vettore di ciascun token. Dimensioni maggiori possono catturare informazioni più dettagliate, ma richiedono più risorse computazionali.

**Esempio:**

- **Dimensione del vocabolario:** 6 token \[1, 2, 3, 4, 5, 6]
- **Dimensioni dell'embedding:** 3 (x, y, z)

### **Inizializzazione degli embedding dei token**

All'inizio dell'addestramento, gli embedding dei token vengono generalmente inizializzati con piccoli valori casuali. Questi valori iniziali vengono regolati (ottimizzati) durante l'addestramento per rappresentare meglio il significato dei token sulla base dei dati di addestramento.

**Esempio in PyTorch:**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Come funzionano i token embeddings durante l'addestramento**

Durante l'addestramento, ogni token nei dati di input viene convertito nel relativo vettore di embedding. Questi vettori vengono quindi utilizzati in vari calcoli all'interno del modello, ad esempio nei meccanismi di attenzione e nei layer delle reti neurali.

**Scenario di esempio:**

- **Batch Size:** 8 (numero di campioni elaborati simultaneamente)
- **Max Sequence Length:** 4 (numero di token per campione)
- **Embedding Dimensions:** 256

**Struttura dei dati:**

- Ogni batch è rappresentato come un tensore 3D con forma `(batch_size, max_length, embedding_dim)`.
- Nel nostro esempio, la forma sarebbe `(8, 4, 256)`.

## **Positional Embeddings: Aggiungere il contesto agli embeddings dei token**

Sebbene gli embeddings dei token catturino il significato dei singoli token, non codificano intrinsecamente la posizione dei token all'interno di una sequenza. Comprendere l'ordine dei token è fondamentale per la comprensione del linguaggio. È qui che entrano in gioco i **positional embeddings**.

### **Perché sono necessari i positional embeddings:**

- **L'ordine dei token è importante:** nelle frasi, il significato spesso dipende dall'ordine delle parole. Ad esempio, "The cat sat on the mat" rispetto a "The mat sat on the cat."
- **Limite degli embeddings:** senza informazioni posizionali, il modello tratta i token come un "bag of words", ignorando la loro sequenza.

### **Tipi di positional embeddings:**

1. **Absolute Positional Embeddings:**
- Assegnano un vettore posizionale univoco a ogni posizione nella sequenza.
- **Esempio:** il primo token di qualsiasi sequenza ha lo stesso positional embedding, il secondo token ne ha un altro, e così via.
- **Utilizzati da:** i modelli GPT di OpenAI.
2. **Relative Positional Embeddings:**
- Codificano la distanza relativa tra i token invece delle loro posizioni assolute.
- **Esempio:** indicano quanto sono distanti due token, indipendentemente dalle loro posizioni assolute nella sequenza.
- **Utilizzati da:** modelli come Transformer-XL e alcune varianti di BERT.

### **Come vengono integrati i positional embeddings:**

- **Stesse dimensioni:** i positional embeddings hanno la stessa dimensionalità degli embeddings dei token.
- **Addizione:** vengono aggiunti agli embeddings dei token, combinando l'identità del token con le informazioni posizionali senza aumentare la dimensionalità complessiva.

**Esempio di addizione dei positional embeddings:**

Supponiamo che un vettore di token embedding sia `[0.5, -0.2, 0.1]` e che il suo vettore di positional embedding sia `[0.1, 0.3, -0.1]`. L'embedding combinato utilizzato dal modello sarebbe:
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**Vantaggi degli embedding posizionali:**

- **Consapevolezza contestuale:** Il modello può distinguere tra i token in base alle loro posizioni.
- **Comprensione della sequenza:** Consente al modello di comprendere la grammatica, la sintassi e i significati dipendenti dal contesto.

## **Embedding posizionali nei moderni LLM**

### **Embedding posizionali rotativi (RoPE)**

RoPE codifica la posizione applicando una rotazione dipendente dalla posizione a coppie di dimensioni nei vettori query/key, trasformando le posizioni assolute in differenze di fase relative. Ciò fornisce informazioni sulla posizione relativa mantenendo invariata la dimensionalità dell'embedding ed è ampiamente utilizzato nei recenti LLM decoder-only.<sup>[[2]](#references)</sup>

Per informazioni su come gli embedding dei token e quelli posizionali vengono combinati all'interno del modello, consulta [la pagina sull'architettura degli LLM](5.-llm-architecture.md).

### **Estensione delle finestre di contesto nei modelli basati su RoPE**

Lavori recenti mostrano che la lunghezza del contesto è spesso limitata dallo schema di codifica posizionale anziché dalla matrice degli embedding dei token.

- **Interpolazione della posizione (PI):** Ridimensiona gli indici di posizione in modo che le sequenze più lunghe rientrino nell'intervallo osservato durante l'addestramento, consentendo l'estensione con un fine-tuning minimo.<sup>[[3]](#references)</sup> Esempio:
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** Una strategia di estensione di RoPE efficiente dal punto di vista computazionale, che modifica lo scaling/l'interpolazione di RoPE per estrapolare contesti più lunghi con un numero inferiore di passaggi di training aggiuntivi.<sup>[[4]](#references)</sup>

## Esempio di codice

Segue l'esempio di codice tratto da [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[5]](#references)</sup>
```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
