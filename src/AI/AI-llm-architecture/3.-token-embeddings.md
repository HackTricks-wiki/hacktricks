## Embeddingi tokenów

Po tokenizacji danych tekstowych kolejnym kluczowym krokiem w przygotowywaniu danych do trenowania dużych modeli językowych (LLM), takich jak GPT, jest tworzenie **embeddingów tokenów**. Embeddingi tokenów przekształcają dyskretne tokeny (takie jak słowa lub podwyrazy) w ciągłe wektory liczbowe, które model może przetwarzać i na ich podstawie się uczyć. To wyjaśnienie omawia embeddingi tokenów, ich inicjalizację i użycie, a także rolę embeddingów pozycyjnych w poprawie rozumienia przez model sekwencji tokenów.<sup>[[1]](#references)</sup>

> [!TIP]
> Cel tej trzeciej fazy jest bardzo prosty: **Przypisanie każdemu z poprzednich tokenów w słowniku wektora o żądanych wymiarach, aby wytrenować model.** Każde słowo w słowniku będzie punktem w przestrzeni o X wymiarach.\
> Należy zauważyć, że początkowo pozycja każdego słowa w przestrzeni jest inicjalizowana „losowo”, a pozycje te są parametrami podlegającymi trenowaniu (będą ulepszane podczas trenowania).
>
> Ponadto podczas tworzenia embeddingów tokenów **tworzona jest kolejna warstwa embeddingów**, która reprezentuje (w tym przypadku) **bezwzględną pozycję słowa w zdaniu treningowym**. Dzięki temu słowo znajdujące się na różnych pozycjach w zdaniu będzie miało inną reprezentację (znaczenie).

### **Czym są embeddingi tokenów?**

**Embeddingi tokenów** to liczbowe reprezentacje tokenów w ciągłej przestrzeni wektorowej. Każdy token w słowniku jest powiązany z unikalnym wektorem o stałej liczbie wymiarów. Wektory te przechwytują informacje semantyczne i składniowe dotyczące tokenów, umożliwiając modelowi rozumienie zależności i wzorców w danych.

- **Rozmiar słownika:** Całkowita liczba unikalnych tokenów (np. słów lub podwyrazów) w słowniku modelu.
- **Wymiary embeddingu:** Liczba wartości liczbowych (wymiarów) w wektorze każdego tokenu. Większa liczba wymiarów może uchwycić bardziej szczegółowe informacje, ale wymaga większych zasobów obliczeniowych.

**Przykład:**

- **Rozmiar słownika:** 6 tokenów \[1, 2, 3, 4, 5, 6]
- **Wymiary embeddingu:** 3 (x, y, z)

### **Inicjalizowanie embeddingów tokenów**

Na początku trenowania embeddingi tokenów są zazwyczaj inicjalizowane za pomocą małych losowych wartości. Te początkowe wartości są dostosowywane (dostrajane) podczas trenowania, aby lepiej reprezentowały znaczenie tokenów na podstawie danych treningowych.

**Przykład w PyTorch:**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Jak działają embeddingi tokenów podczas treningu**

Podczas treningu każdy token w danych wejściowych jest konwertowany na odpowiadający mu wektor embeddingu. Wektory te są następnie używane w różnych obliczeniach wykonywanych w modelu, takich jak mechanizmy attention i warstwy sieci neuronowej.

**Przykładowy scenariusz:**

- **Rozmiar batcha:** 8 (liczba próbek przetwarzanych jednocześnie)
- **Maksymalna długość sekwencji:** 4 (liczba tokenów w jednej próbce)
- **Wymiary embeddingu:** 256

**Struktura danych:**

- Każdy batch jest reprezentowany jako tensor 3D o kształcie `(batch_size, max_length, embedding_dim)`.
- W naszym przykładzie kształt wynosiłby `(8, 4, 256)`.

**Wizualizacja:**

## **Embeddingi pozycyjne: dodawanie kontekstu do embeddingów tokenów**

Chociaż embeddingi tokenów odwzorowują znaczenie poszczególnych tokenów, nie kodują bezpośrednio pozycji tokenów w sekwencji. Zrozumienie kolejności tokenów ma kluczowe znaczenie dla rozumienia języka. Właśnie tutaj zastosowanie znajdują **embeddingi pozycyjne**.

### **Dlaczego embeddingi pozycyjne są potrzebne:**

- **Kolejność tokenów ma znaczenie:** W zdaniach znaczenie często zależy od kolejności słów. Na przykład: „The cat sat on the mat” vs. „The mat sat on the cat.”
- **Ograniczenie embeddingów:** Bez informacji o pozycji model traktuje tokeny jak „bag of words”, ignorując ich kolejność.

### **Rodzaje embeddingów pozycyjnych:**

1. **Absolutne embeddingi pozycyjne:**
- Przypisują unikalny wektor pozycji do każdej pozycji w sekwencji.
- **Przykład:** Pierwszy token w każdej sekwencji ma ten sam embedding pozycyjny, drugi token ma inny i tak dalej.
- **Używane przez:** Modele GPT firmy OpenAI.
2. **Relatywne embeddingi pozycyjne:**
- Kodują względną odległość między tokenami, a nie ich absolutne pozycje.
- **Przykład:** Wskazują, jak daleko od siebie znajdują się dwa tokeny, niezależnie od ich absolutnych pozycji w sekwencji.
- **Używane przez:** Modele takie jak Transformer-XL oraz niektóre warianty BERT.

### **Jak integrowane są embeddingi pozycyjne:**

- **Te same wymiary:** Embeddingi pozycyjne mają taki sam wymiar jak embeddingi tokenów.
- **Dodawanie:** Są dodawane do embeddingów tokenów, łącząc tożsamość tokenu z informacją o jego pozycji bez zwiększania całkowitego wymiaru.

**Przykład dodawania embeddingów pozycyjnych:**

Załóżmy, że wektor embeddingu tokenu to `[0.5, -0.2, 0.1]`, a jego wektor embeddingu pozycyjnego to `[0.1, 0.3, -0.1]`. Połączony embedding używany przez model będzie następujący:
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**Zalety osadzeń pozycyjnych:**

- **Świadomość kontekstu:** Model może rozróżniać tokeny na podstawie ich pozycji.
- **Rozumienie sekwencji:** Umożliwia modelowi rozumienie gramatyki, składni i znaczeń zależnych od kontekstu.

## **Osadzenia pozycyjne we współczesnych LLM-ach**

### **Rotacyjne osadzenia pozycyjne (RoPE)**

RoPE koduje pozycję poprzez zastosowanie zależnego od pozycji obrotu do par wymiarów w wektorach query/key, przekształcając pozycje absolutne w względne różnice faz. Zapewnia to informacje o względnej pozycji bez zmiany wymiarowości osadzeń i jest szeroko stosowane we współczesnych decoder-only LLM-ach.<sup>[[2]](#references)</sup>

Informacje o tym, jak osadzenia tokenów i pozycji są łączone wewnątrz modelu, znajdziesz na [stronie dotyczącej architektury LLM](5.-llm-architecture.md).

### **Rozszerzanie okien kontekstu w modelach opartych na RoPE**

Najnowsze badania pokazują, że długość kontekstu jest często ograniczona przez schemat kodowania pozycyjnego, a nie przez samą macierz osadzeń tokenów.

- **Interpolacja pozycji (PI):** Przeskalowuje indeksy pozycji, dzięki czemu dłuższe sekwencje mieszczą się w zakresie obserwowanym podczas treningu, umożliwiając rozszerzenie przy minimalnym fine-tuningu.<sup>[[3]](#references)</sup> Przykład:
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** Efektywna obliczeniowo strategia rozszerzania RoPE, która modyfikuje skalowanie/interpolację RoPE w celu ekstrapolacji do dłuższych kontekstów przy użyciu mniejszej liczby dodatkowych kroków treningowych.<sup>[[4]](#references)</sup>

## Przykład kodu

Kontynuując przykład kodu z [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[5]](#references)</sup>
```python
# Use previous code...

# Create dimensional emdeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
