## Token Embeddings

对文本数据进行分词后，为 GPT 等大型语言模型（LLM）准备训练数据的下一个关键步骤是创建**令牌嵌入**。令牌嵌入会将离散令牌（例如单词或子词）转换为连续的数值向量，供模型处理和学习。本文将介绍令牌嵌入的定义、初始化和用法，以及位置嵌入如何帮助模型更好地理解令牌序列。<sup>[[1]](#references)</sup>

> [!TIP]
> 第三个阶段的目标非常简单：**为词汇表中的每个先前令牌分配一个所需维度的向量，以便训练模型。** 词汇表中的每个单词都是 X 维空间中的一个点。\
> 请注意，最初每个单词在空间中的位置只是“随机”初始化的，并且这些位置是可训练参数（会在训练过程中得到改进）。
>
> 此外，在令牌嵌入过程中，**还会创建另一层嵌入**，用于表示（在本例中）**单词在训练句子中的绝对位置**。这样，单词在句子中的不同位置就会有不同的表示（含义）。

### **什么是令牌嵌入？**

**令牌嵌入**是令牌在连续向量空间中的数值表示。词汇表中的每个令牌都对应一个固定维度的唯一向量。这些向量包含有关令牌的语义和句法信息，使模型能够理解数据中的关系和模式。

- **词汇表大小：** 模型词汇表中不同令牌（例如单词、子词）的总数。
- **嵌入维度：** 每个令牌向量中的数值（维度）数量。更高的维度可以捕捉更细致的信息，但需要更多计算资源。

**示例：**

- **词汇表大小：** 6 个令牌 \[1, 2, 3, 4, 5, 6]
- **嵌入维度：** 3（x、y、z）

### **初始化令牌嵌入**

在训练开始时，令牌嵌入通常会使用较小的随机值进行初始化。在训练过程中，这些初始值会被调整（微调），使其根据训练数据更好地表示令牌的含义。

**PyTorch 示例：**

```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

**输出：**

- 这些值是可训练参数，模型会在训练过程中调整它们，以更好地表示该 token 的上下文和含义。

### **Token Embedding 在训练中的工作方式**

训练期间，输入数据中的每个 token 都会转换为对应的 embedding 向量。随后，这些向量会用于模型中的各种计算，例如注意力机制和神经网络层。

**示例场景：**

- **批次大小：** 8（同时处理的样本数）
- **最大序列长度：** 4（每个样本中的 token 数）
- **Embedding 维度：** 256

**数据结构：**

- 每个批次都用一个形状为 `(batch_size, max_length, embedding_dim)` 的三维张量表示。
- 在本例中，形状为 `(8, 4, 256)`。

**可视化：**

## **位置嵌入：为 token 嵌入添加上下文**

token 嵌入能够捕捉单个 token 的含义，但它们本身并不编码 token 在序列中的位置。理解 token 的顺序对语言理解至关重要。这正是**位置嵌入**发挥作用的地方。

### **为什么需要位置嵌入：**

- **token 顺序很重要：**在句子中，含义通常取决于词语的顺序。例如，“The cat sat on the mat”和“The mat sat on the cat”。
- **嵌入的局限性：**没有位置信息时，模型会将 token 视为“词袋”，忽略它们的顺序。

### **位置嵌入的类型：**

1. **绝对位置嵌入：**
   - 为序列中的每个位置分配一个唯一的位置向量。
   - **示例：**任何序列中的第一个 token 都使用相同的位置嵌入，第二个 token 使用另一个位置嵌入，依此类推。
   - **应用于：**OpenAI 的 GPT 模型。
2. **相对位置嵌入：**
   - 编码 token 之间的相对距离，而不是它们的绝对位置。
   - **示例：**表示两个 token 相距多远，而不受它们在序列中绝对位置的影响。
   - **应用于：**Transformer-XL 等模型以及 BERT 的一些变体。

### **如何整合位置嵌入：**

- **维度相同：**位置嵌入与 token 嵌入具有相同的维度。
- **相加：**将位置嵌入加到 token 嵌入上，从而结合 token 身份和位置信息，而不增加总体维度。

**添加位置嵌入的示例：**

假设一个 token 嵌入向量为 `[0.5, -0.2, 0.1]`，其位置嵌入向量为 `[0.1, 0.3, -0.1]`。模型使用的组合嵌入将是：

```css
Combined Embedding = Token Embedding + Positional Embedding
                   = [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
                   = [0.6, 0.1, 0.0]
```

**位置嵌入的优势：**

- **上下文感知：**模型可以根据 token 的位置区分它们。
- **序列理解：**使模型能够理解语法、句法和依赖上下文的含义。

## **现代 LLM 中的位置嵌入**

### **旋转位置嵌入（RoPE）**

RoPE 通过对 query/key 向量中的维度对应用依赖位置的旋转来编码位置信息，将绝对位置转换为相对相位差。这种方法在保持嵌入维度不变的同时提供相对位置信息，并广泛用于近期的 decoder-only LLM。<sup>[[2]](#references)</sup>

有关 token 嵌入和位置嵌入如何在模型内部组合，请参阅 [LLM 架构页面](5.-llm-architecture.md)。

### **扩展基于 RoPE 的模型的上下文窗口**

近期研究表明，上下文长度通常受位置编码方案限制，而非 token 嵌入矩阵本身。

- **位置插值（PI）：**重新缩放位置索引，使更长的序列映射到训练期间见过的范围内，从而只需少量微调即可扩展上下文窗口。<sup>[[3]](#references)</sup> 示例：

```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```

- **YaRN:** 一种计算效率高的 RoPE 扩展策略，通过修改 RoPE 缩放/插值方式，在减少额外训练步数的同时扩展上下文长度。<sup>[[4]](#references)</sup>

## 代码示例

以下代码示例来自 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb)：<sup>[[5]](#references)</sup>

```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
    raw_text, batch_size=8, max_length=max_length,
    stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
