## Embeddings tokenów

Po tokenizacji danych tekstowych kolejnym kluczowym krokiem w przygotowywaniu danych do trenowania dużych modeli językowych (LLM), takich jak GPT, jest tworzenie **embeddingów tokenów**. Embeddingi tokenów przekształcają dyskretne tokeny (takie jak słowa lub podtokeny) w ciągłe wektory liczbowe, które model może przetwarzać i na ich podstawie się uczyć. To wyjaśnienie przedstawia embeddingi tokenów, ich inicjalizację i zastosowanie, a także rolę embeddingów pozycyjnych w ulepszaniu rozumienia przez model sekwencji tokenów.<sup>[[1]](#references)</sup>

> [!TIP]
> Cel tej trzeciej fazy jest bardzo prosty: **Przypisać każdemu z poprzednich tokenów w słowniku wektor o pożądanych wymiarach, aby wytrenować model.** Każde słowo w słowniku będzie punktem w przestrzeni o X wymiarach.\
> Należy pamiętać, że początkowo pozycja każdego słowa w przestrzeni jest inicjalizowana „losowo”, a te pozycje są parametrami podlegającymi trenowaniu (zostaną ulepszone podczas trenowania).
>
> Ponadto podczas tworzenia embeddingów tokenów **tworzona jest kolejna warstwa embeddingów**, która reprezentuje (w tym przypadku) **absolutną pozycję słowa w trenowanym zdaniu**. Dzięki temu słowo znajdujące się na różnych pozycjach w zdaniu będzie miało inną reprezentację (znaczenie).

### **Czym są embeddingi tokenów?**

**Embeddingi tokenów** to liczbowe reprezentacje tokenów w ciągłej przestrzeni wektorowej. Każdy token w słowniku jest powiązany z unikalnym wektorem o stałej liczbie wymiarów. Wektory te przechowują informacje semantyczne i syntaktyczne dotyczące tokenów, umożliwiając modelowi rozumienie zależności i wzorców w danych.

- **Rozmiar słownika:** Całkowita liczba unikalnych tokenów (np. słów, podtokenów) w słowniku modelu.
- **Wymiary embeddingu:** Liczba wartości liczbowych (wymiarów) w wektorze każdego tokenu. Większa liczba wymiarów może przechowywać bardziej szczegółowe informacje, ale wymaga większych zasobów obliczeniowych.

**Przykład:**

- **Rozmiar słownika:** 6 tokenów \[1, 2, 3, 4, 5, 6]
- **Wymiary embeddingu:** 3 (x, y, z)

### **Inicjalizacja embeddingów tokenów**

Na początku trenowania embeddingi tokenów są zazwyczaj inicjalizowane za pomocą małych losowych wartości. Te początkowe wartości są dostosowywane (dostrajane) podczas trenowania, aby lepiej reprezentować znaczenie tokenów na podstawie danych treningowych.

**Przykład w PyTorch:**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Jak działają embeddingi tokenów podczas treningu**

Podczas treningu każdy token w danych wejściowych jest konwertowany na odpowiadający mu wektor embeddingu. Wektory te są następnie wykorzystywane w różnych obliczeniach wewnątrz modelu, takich jak mechanizmy attention i warstwy sieci neuronowej.

**Przykładowy scenariusz:**

- **Rozmiar batcha:** 8 (liczba próbek przetwarzanych jednocześnie)
- **Maksymalna długość sekwencji:** 4 (liczba tokenów na próbkę)
- **Wymiary embeddingu:** 256

**Struktura danych:**

- Każdy batch jest reprezentowany jako tensor 3D o kształcie `(batch_size, max_length, embedding_dim)`.
- W naszym przykładzie kształt wynosiłby `(8, 4, 256)`.

**Wizualizacja:**

## **Embeddings pozycyjne: dodawanie kontekstu do embeddings tokenów**

Chociaż embeddings tokenów oddają znaczenie poszczególnych tokenów, nie kodują w sposób wrodzony pozycji tokenów w sekwencji. Zrozumienie kolejności tokenów ma kluczowe znaczenie dla rozumienia języka. W tym miejscu do akcji wkraczają **embeddings pozycyjne**.

### **Dlaczego embeddings pozycyjne są potrzebne:**

- **Kolejność tokenów ma znaczenie:** W zdaniach znaczenie często zależy od kolejności słów. Na przykład: „The cat sat on the mat” vs. „The mat sat on the cat”.
- **Ograniczenie embeddings:** Bez informacji o pozycji model traktuje tokeny jak „worek słów”, ignorując ich kolejność.

### **Typy embeddings pozycyjnych:**

1. **Absolutne embeddings pozycyjne:**
- Przypisują unikalny wektor pozycji każdej pozycji w sekwencji.
- **Przykład:** Pierwszy token w każdej sekwencji ma ten sam embedding pozycyjny, drugi token ma inny i tak dalej.
- **Używane przez:** Modele GPT firmy OpenAI.
2. **Względne embeddings pozycyjne:**
- Kodują względną odległość między tokenami zamiast ich absolutnych pozycji.
- **Przykład:** Wskazują, jak daleko od siebie znajdują się dwa tokeny, niezależnie od ich absolutnych pozycji w sekwencji.
- **Używane przez:** Modele takie jak Transformer-XL i niektóre warianty BERT.

### **Jak integrowane są embeddings pozycyjne:**

- **Te same wymiary:** Embeddings pozycyjne mają taki sam wymiar jak embeddings tokenów.
- **Dodawanie:** Są dodawane do embeddings tokenów, łącząc tożsamość tokenu z informacją o jego pozycji bez zwiększania ogólnego wymiaru.

**Przykład dodawania embeddings pozycyjnych:**

Załóżmy, że wektor embeddingu tokenu to `[0.5, -0.2, 0.1]`, a jego wektor embeddingu pozycyjnego to `[0.1, 0.3, -0.1]`. Połączony embedding używany przez model będzie wynosić:
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**Korzyści z osadzeń pozycyjnych:**

- **Świadomość kontekstu:** Model może rozróżniać tokeny na podstawie ich pozycji.
- **Rozumienie sekwencji:** Umożliwia modelowi rozumienie gramatyki, składni i znaczeń zależnych od kontekstu.

## **Osadzenia pozycyjne w nowoczesnych LLM-ach**

### **Rotary Positional Embeddings (RoPE)**

RoPE koduje pozycję poprzez zastosowanie zależnej od pozycji rotacji do par wymiarów w wektorach query/key, przekształcając pozycje bezwzględne w względne różnice faz. Zapewnia to informacje o pozycji względnej przy zachowaniu niezmienionej liczby wymiarów osadzeń i jest powszechnie stosowane w najnowszych modelach LLM typu decoder-only.<sup>[[2]](#references)</sup>

Informacje o tym, jak osadzenia tokenów i osadzenia pozycyjne są łączone wewnątrz modelu, znajdziesz na [stronie poświęconej architekturze LLM](5.-llm-architecture.md).

### **Rozszerzanie okien kontekstu w modelach opartych na RoPE**

Najnowsze prace pokazują, że długość kontekstu jest często ograniczona przez schemat kodowania pozycji, a nie przez samą macierz osadzeń tokenów.

- **Interpolacja pozycji (PI):** Przeskalowuje indeksy pozycji, aby dłuższe sekwencje mieściły się w zakresie obserwowanym podczas trenowania, umożliwiając rozszerzenie przy minimalnym fine-tuning.<sup>[[3]](#references)</sup> Przykład:
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** Efektywna obliczeniowo strategia rozszerzania RoPE, która modyfikuje skalowanie/interpolację RoPE w celu ekstrapolacji do dłuższych kontekstów przy mniejszej liczbie dodatkowych kroków treningowych.<sup>[[4]](#references)</sup>

## Przykład kodu

Poniżej znajduje się przykład kodu z [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[5]](#references)</sup>
```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
