## Token Embeddings

Text data को tokenize करने के बाद, GPT जैसे large language models (LLMs) को train करने के लिए data तैयार करने का अगला महत्वपूर्ण चरण **token embeddings** बनाना है। Token embeddings, discrete tokens (जैसे शब्द या subwords) को continuous numerical vectors में बदलते हैं, जिन्हें model प्रोसेस कर सकता है और जिनसे सीख सकता है। यह स्पष्टीकरण token embeddings, उनका initialization और उपयोग, और token sequences की model की समझ को बेहतर बनाने में positional embeddings की भूमिका को विस्तार से बताता है।<sup>[[1]](#references)</sup>

> [!TIP]
> इस तीसरे चरण का लक्ष्य बहुत सरल है: **vocabulary के पिछले हर token को model train करने के लिए वांछित dimensions का एक vector देना।** Vocabulary का हर शब्द X dimensions वाले space में एक point होगा।\
> ध्यान दें कि शुरुआत में space में हर शब्द की position बस "randomly" initialize की जाती है, और ये positions trainable parameters होते हैं (training के दौरान बेहतर किए जाएंगे)।
>
> इसके अलावा, token embedding के दौरान **embeddings की एक और layer बनाई जाती है**, जो (इस मामले में) **training sentence में शब्द की absolute position को दर्शाती है**। इस तरह sentence में अलग-अलग positions पर मौजूद एक ही शब्द की representations (और अर्थ) अलग-अलग होंगे।

### **Token Embeddings क्या हैं?**

**Token Embeddings**, continuous vector space में tokens के numerical representations होते हैं। Vocabulary के हर token से एक निश्चित dimensions वाला unique vector जुड़ा होता है। ये vectors tokens के semantic और syntactic information को दर्शाते हैं, जिससे model data में relationships और patterns समझ पाता है।

- **Vocabulary Size:** Model की vocabulary में मौजूद unique tokens (जैसे शब्द, subwords) की कुल संख्या।
- **Embedding Dimensions:** हर token के vector में numerical values (dimensions) की संख्या। अधिक dimensions से अधिक सूक्ष्म जानकारी दर्शाई जा सकती है, लेकिन इनके लिए अधिक computational resources की आवश्यकता होती है।

**उदाहरण:**

- **Vocabulary Size:** 6 tokens \[1, 2, 3, 4, 5, 6]
- **Embedding Dimensions:** 3 (x, y, z)

### **Token Embeddings को initialize करना**

Training की शुरुआत में, token embeddings को आम तौर पर छोटे random values से initialize किया जाता है। Training के दौरान इन शुरुआती values को training data के आधार पर tokens के अर्थों को बेहतर ढंग से दर्शाने के लिए adjust (fine-tune) किया जाता है।

**PyTorch उदाहरण:**

```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **प्रशिक्षण के दौरान टोकन एम्बेडिंग कैसे काम करते हैं**

## **Positional Embeddings: Token Embeddings में संदर्भ जोड़ना**

जहाँ token embeddings अलग-अलग tokens का अर्थ दर्शाते हैं, वहीं वे अनुक्रम में tokens की स्थिति को अपने आप encode नहीं करते। भाषा को समझने के लिए tokens का क्रम समझना महत्वपूर्ण है। यहीं **positional embeddings** काम आते हैं।

### **Positional Embeddings की आवश्यकता क्यों है:**

- **Token का क्रम महत्वपूर्ण है:** वाक्यों में अर्थ अक्सर शब्दों के क्रम पर निर्भर करता है। उदाहरण के लिए, "The cat sat on the mat" बनाम "The mat sat on the cat."
- **Embedding की सीमा:** स्थिति की जानकारी के बिना, मॉडल tokens को "शब्दों के समूह" की तरह मानता है और उनके क्रम को अनदेखा करता है।

### **Positional Embeddings के प्रकार:**

1. **Absolute Positional Embeddings:**
   - अनुक्रम में हर स्थिति को एक अलग position vector देते हैं।
   - **उदाहरण:** किसी भी अनुक्रम के पहले token का positional embedding समान होता है, दूसरे token का अलग, और इसी तरह आगे।
   - **इस्तेमाल करने वाले:** OpenAI के GPT models।
2. **Relative Positional Embeddings:**
   - tokens की absolute positions के बजाय उनके बीच की सापेक्ष दूरी encode करते हैं।
   - **उदाहरण:** यह दर्शाते हैं कि अनुक्रम में उनकी absolute positions चाहे जो हों, दो tokens एक-दूसरे से कितनी दूर हैं।
   - **इस्तेमाल करने वाले:** Transformer-XL और BERT के कुछ variants जैसे models।

### **Positional Embeddings को कैसे एकीकृत किया जाता है:**

- **समान आयाम:** Positional embeddings के आयाम token embeddings के समान होते हैं।
- **जोड़ना:** कुल आयाम बढ़ाए बिना, token identity और स्थिति की जानकारी को मिलाने के लिए इन्हें token embeddings में जोड़ा जाता है।

**Positional Embeddings जोड़ने का उदाहरण:**

मान लें कि एक token embedding vector `[0.5, -0.2, 0.1]` है और उसका positional embedding vector `[0.1, 0.3, -0.1]` है। मॉडल द्वारा इस्तेमाल किया जाने वाला संयुक्त embedding यह होगा:

```css
Combined Embedding = Token Embedding + Positional Embedding
                   = [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
                   = [0.6, 0.1, 0.0]
```

**Positional Embeddings के लाभ:**

- **संदर्भगत जागरूकता:** मॉडल tokens के बीच उनकी positions के आधार पर अंतर कर सकता है।
- **Sequence की समझ:** मॉडल को grammar, syntax और संदर्भ-निर्भर अर्थ समझने में सक्षम बनाता है।

## **आधुनिक LLMs में Positional Embeddings**

### **Rotary Positional Embeddings (RoPE)**

RoPE, query/key vectors में dimensions के जोड़ों पर position-dependent rotation लागू करके position को encode करता है। इससे absolute positions, relative phase differences में बदल जाती हैं। यह embedding dimensionality को अपरिवर्तित रखते हुए relative position की जानकारी देता है और हाल के decoder-only LLMs में व्यापक रूप से उपयोग किया जाता है।<sup>[[2]](#references)</sup>

मॉडल के भीतर token और positional embeddings को कैसे जोड़ा जाता है, इसके लिए [LLM architecture page](5.-llm-architecture.md) देखें।

### **RoPE-आधारित Models में Context Windows का विस्तार**

हालिया शोध से पता चलता है कि context length अक्सर token embedding matrix के बजाय positional encoding scheme से सीमित होती है।

- **Position Interpolation (PI):** Position indices को rescale करता है, ताकि लंबी sequences training के दौरान देखी गई range में map हों। इससे बहुत कम fine-tuning के साथ विस्तार संभव होता है।<sup>[[3]](#references)</sup> उदाहरण:

```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```

- **YaRN:** एक गणना-कुशल RoPE विस्तार रणनीति, जो कम अतिरिक्त प्रशिक्षण चरणों में लंबे contexts तक extrapolate करने के लिए RoPE scaling/interpolation को संशोधित करती है।<sup>[[4]](#references)</sup>

## Code Example

[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb) से code example आगे दिया गया है:<sup>[[5]](#references)</sup>

```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
    raw_text, batch_size=8, max_length=max_length,
    stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
