## Token-inbeddings

Nadat teksdata getokeniseer is, is die volgende kritieke stap in die voorbereiding van data vir die opleiding van groot taalmodelle (LLM's) soos GPT om **token-inbeddings** te skep. Token-inbeddings omskep diskrete tokens (soos woorde of subwoorde) in aaneenlopende numeriese vektore wat die model kan verwerk en waaruit dit kan leer. Hierdie verduideliking breek token-inbeddings, hul inisialisering, gebruik en die rol van posisionele inbeddings in die verbetering van die model se begrip van tokenreekse af.<sup>[[1]](#references)</sup>

> [!TIP]
> Die doel van hierdie derde fase is baie eenvoudig: **Ken aan elkeen van die vorige tokens in die woordeskat 'n vektor met die verlangde dimensies toe om die model op te lei.** Elke woord in die woordeskat sal 'n punt in 'n ruimte met X dimensies wees.\
> Let daarop dat die posisie van elke woord in die ruimte aanvanklik bloot "lukraak" geïnitialiseer word, en dat hierdie posisies opleibare parameters is (wat tydens opleiding verbeter sal word).
>
> Boonop word tydens die token-inbedding **'n ander laag inbeddings geskep** wat (in hierdie geval) die **absolute posisie van die woord in die opleiding-sin** voorstel. Op hierdie manier sal 'n woord op verskillende posisies in die sin 'n verskillende voorstelling (betekenis) hê.

### **Wat is token-inbeddings?**

**Token-inbeddings** is numeriese voorstellings van tokens in 'n aaneenlopende vektorruimte. Elke token in die woordeskat word met 'n unieke vektor van vaste dimensies geassosieer. Hierdie vektore vang semantiese en sintaktiese inligting oor die tokens vas, wat die model in staat stel om verwantskappe en patrone in die data te verstaan.

- **Woordeskatgrootte:** Die totale aantal unieke tokens (bv. woorde, subwoorde) in die model se woordeskat.
- **Inbeddingsdimensies:** Die aantal numeriese waardes (dimensies) in elke token se vektor. Hoër dimensies kan meer genuanseerde inligting vasvang, maar verg meer rekenaarhulpbronne.

**Voorbeeld:**

- **Woordeskatgrootte:** 6 tokens \[1, 2, 3, 4, 5, 6]
- **Inbeddingsdimensies:** 3 (x, y, z)

### **Inisialisering van token-inbeddings**

Aan die begin van opleiding word token-inbeddings gewoonlik met klein lukrake waardes geïnitialiseer. Hierdie aanvanklike waardes word tydens opleiding aangepas (fyn ingestel) om die betekenisse van die tokens beter volgens die opleidingsdata voor te stel.

**PyTorch-voorbeeld:**

```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Hoe token-inbeddings tydens opleiding werk**

Tydens opleiding word elke token in die insetdata omgeskakel na die ooreenstemmende inbedvektor. Hierdie vektore word dan in verskeie berekeninge binne die model gebruik, soos aandagmeganismes en neurale netwerklae.

**Voorbeeldscenario:**

- **Bondelgrootte:** 8 (aantal voorbeelde wat gelyktydig verwerk word)
- **Maksimum sekwenslengte:** 4 (aantal tokens per voorbeeld)
- **Inbeddingsdimensies:** 256

**Datastruktuur:**

- Elke bondel word voorgestel as ’n 3D-tensor met vorm `(batch_size, max_length, embedding_dim)`.
- In ons voorbeeld sal die vorm `(8, 4, 256)` wees.

## **Posisionele inbeddings: Konteks by token-inbeddings voeg**

Hoewel token-inbeddings die betekenis van individuele tokens vasvang, kodeer hulle nie vanself die posisie van tokens binne ’n reeks nie. Dit is noodsaaklik om die volgorde van tokens te verstaan om taal te begryp. Dit is waar **posisionele inbeddings** ter sprake kom.

### **Waarom posisionele inbeddings nodig is:**

- **Tokenvolgorde maak saak:** In sinne hang die betekenis dikwels af van die volgorde van woorde. Byvoorbeeld: "The cat sat on the mat" teenoor "The mat sat on the cat."
- **Beperking van inbeddings:** Sonder posisionele inligting behandel die model tokens as ’n "bag of words" en ignoreer dit hul volgorde.

### **Tipes posisionele inbeddings:**

1. **Absolute posisionele inbeddings:**
   - Ken ’n unieke posisievektor aan elke posisie in die reeks toe.
   - **Voorbeeld:** Die eerste token in enige reeks het dieselfde posisionele inbedding, die tweede token het ’n ander een, ensovoorts.
   - **Gebruik deur:** OpenAI se GPT-modelle.
2. **Relatiewe posisionele inbeddings:**
   - Kodeer die relatiewe afstand tussen tokens eerder as hul absolute posisies.
   - **Voorbeeld:** Dui aan hoe ver twee tokens van mekaar af is, ongeag hul absolute posisies in die reeks.
   - **Gebruik deur:** Modelle soos Transformer-XL en sommige variante van BERT.

### **Hoe posisionele inbeddings geïntegreer word:**

- **Dieselfde dimensies:** Posisionele inbeddings het dieselfde dimensionaliteit as token-inbeddings.
- **Optelling:** Hulle word by token-inbeddings getel, wat tokenidentiteit met posisionele inligting kombineer sonder om die algehele dimensionaliteit te verhoog.

**Voorbeeld van die optelling van posisionele inbeddings:**

Gestel ’n token-inbeddingsvektor is `[0.5, -0.2, 0.1]` en sy posisionele inbeddingsvektor is `[0.1, 0.3, -0.1]`. Die gekombineerde inbedding wat die model gebruik, sal wees:

```css
Combined Embedding = Token Embedding + Positional Embedding
                   = [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
                   = [0.6, 0.1, 0.0]
```

**Voordele van posisionele inbeddings:**

- **Kontekstuele bewustheid:** Die model kan tussen tokens onderskei op grond van hul posisies.
- **Reeksbegrip:** Stel die model in staat om grammatika, sintaksis en konteksafhanklike betekenisse te verstaan.

## **Posisionele inbeddings in moderne LLM's**

### **Rotary Positional Embeddings (RoPE)**

RoPE enkodeer posisie deur ’n posisieafhanklike rotasie toe te pas op pare dimensies in die query/key-vektore, wat absolute posisies in relatiewe faseverskille omskakel. Dit verskaf relatiewe posisie-inligting sonder om die inbeddingsdimensionaliteit te verander en word wyd in onlangse decoder-only LLM's gebruik.<sup>[[2]](#references)</sup>

Sien [die LLM-argitektuurbladsy](5.-llm-architecture.md) vir hoe token- en posisionele inbeddings binne die model gekombineer word.

### **Konteksvensters in RoPE-gebaseerde modelle uitbrei**

Onlangse werk toon dat die kontekstlengte dikwels deur die posisionele enkoderingskema beperk word, eerder as deur die token-inbeddingsmatriks self.

- **Position Interpolation (PI):** Skaal posisie-indekse om sodat langer reekse binne die reeks val wat tydens opleiding gesien is, wat uitbreiding met minimale fyninstelling moontlik maak.<sup>[[3]](#references)</sup> Voorbeeld:

```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```

- **YaRN:** ’n Berekeningsdoeltreffende RoPE-uitbreidingstrategie wat RoPE-skaalvergroting/interpolasie aanpas om na langer kontekste te ekstrapoleer met minder bykomende opleidingstappe.<sup>[[4]](#references)</sup>

## Kodevoorbeeld

Hier volg die kodevoorbeeld van [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[5]](#references)</sup>

```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
    raw_text, batch_size=8, max_length=max_length,
    stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
