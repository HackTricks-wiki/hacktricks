## Token Embeddings

텍스트 데이터를 tokenizing한 후, GPT와 같은 large language models(LLMs)의 training을 위한 데이터를 준비하는 다음 핵심 단계는 **token embeddings**를 생성하는 것입니다. Token embeddings는 이산적인 token(예: 단어 또는 subword)을 모델이 처리하고 학습할 수 있는 연속적인 수치 벡터로 변환합니다. 이 설명에서는 token embeddings, 초기화, 사용 방식 및 token sequence에 대한 모델의 이해를 향상시키는 positional embeddings의 역할을 단계적으로 설명합니다.<sup>[[1]](#references)</sup>

> [!TIP]
> 이 세 번째 단계의 목표는 매우 간단합니다. **vocabulary의 각 이전 token에 training할 모델이 원하는 차원의 벡터를 할당하는 것입니다.** vocabulary의 각 단어는 X차원 공간의 한 점이 됩니다.\
> 처음에는 공간에서 각 단어의 위치가 단순히 "무작위로" 초기화된다는 점에 유의해야 합니다. 이러한 위치는 trainable parameters이며 training 중에 개선됩니다.
>
> 또한 token embedding 중에 **또 다른 embedding layer가 생성되며**, 이 layer는 (이 경우) training 문장에서 **단어의 절대 위치**를 나타냅니다. 이를 통해 문장에서 서로 다른 위치에 있는 단어는 서로 다른 표현(의미)을 갖게 됩니다.

### **Token Embeddings란 무엇인가?**

**Token Embeddings**는 연속적인 벡터 공간에서 token을 수치로 표현한 것입니다. vocabulary의 각 token은 고정된 차원의 고유한 벡터와 연결됩니다. 이러한 벡터는 token의 의미적 및 구문적 정보를 포착하여 모델이 데이터의 관계와 패턴을 이해할 수 있도록 합니다.

- **Vocabulary Size:** 모델 vocabulary에 포함된 고유 token(예: 단어, subword)의 총 개수입니다.
- **Embedding Dimensions:** 각 token 벡터에 포함된 수치(차원)의 개수입니다. 차원이 높을수록 더 세밀한 정보를 포착할 수 있지만 더 많은 computational resources가 필요합니다.

**예시:**

- **Vocabulary Size:** 6 tokens \[1, 2, 3, 4, 5, 6]
- **Embedding Dimensions:** 3 (x, y, z)

### **Token Embeddings 초기화**

Training을 시작할 때 token embeddings는 일반적으로 작은 무작위 값으로 초기화됩니다. 이러한 초기값은 training data를 기반으로 token의 의미를 더 잘 표현하도록 training 중에 조정(fine-tuning)됩니다.

**PyTorch 예시:**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```
번역할 원문이 제공되지 않았습니다.

**설명:**

- 인덱스 `3`의 token은 벡터 `[-0.4015, 0.9666, -1.1481]`로 표현됩니다.
- 이러한 값은 trainable parameter이며, model은 training 중 token의 context와 의미를 더 잘 표현하도록 이 값을 조정합니다.

### **Training 중 Token Embeddings의 작동 방식**

Training 중에는 input data의 각 token이 해당 embedding vector로 변환됩니다. 그런 다음 이 vector는 attention mechanism과 neural network layer 등 model 내부의 다양한 연산에 사용됩니다.

**예시 시나리오:**

- **Batch Size:** 8 (동시에 처리되는 sample 수)
- **Max Sequence Length:** 4 (sample당 token 수)
- **Embedding Dimensions:** 256

**Data Structure:**

- 각 batch는 `(batch_size, max_length, embedding_dim)` 형태의 3D tensor로 표현됩니다.
- 이 예시에서 shape은 `(8, 4, 256)`입니다.

**시각화:**

## **Positional Embeddings: Token Embeddings에 Context 추가**

Token embeddings는 개별 token의 의미를 포착하지만, 시퀀스 내 token의 위치를 본질적으로 인코딩하지는 않습니다. 언어를 이해하려면 token의 순서를 파악하는 것이 중요합니다. 이때 **positional embeddings**가 사용됩니다.

### **Positional Embeddings가 필요한 이유:**

- **Token 순서는 중요함:** 문장에서 의미는 단어의 순서에 따라 달라지는 경우가 많습니다. 예를 들어, "The cat sat on the mat"과 "The mat sat on the cat"을 비교해 보세요.
- **Embedding의 한계:** 위치 정보가 없으면 모델은 token을 시퀀스를 무시한 "bag of words"로 처리합니다.

### **Positional Embeddings의 유형:**

1. **Absolute Positional Embeddings:**
- 시퀀스의 각 위치에 고유한 position vector를 할당합니다.
- **예시:** 모든 시퀀스에서 첫 번째 token은 동일한 positional embedding을 갖고, 두 번째 token은 또 다른 positional embedding을 갖는 방식입니다.
- **사용 모델:** OpenAI의 GPT 모델.
2. **Relative Positional Embeddings:**
- token의 절대 위치가 아니라 token 간 상대적인 거리를 인코딩합니다.
- **예시:** 시퀀스 내 절대 위치와 관계없이 두 token이 얼마나 떨어져 있는지를 나타냅니다.
- **사용 모델:** Transformer-XL과 일부 BERT 변형 모델.

### **Positional Embeddings가 통합되는 방식:**

- **동일한 차원:** Positional embeddings는 token embeddings와 동일한 차원 수를 가집니다.
- **더하기:** Token의 정체성과 위치 정보를 결합하면서 전체 차원 수를 늘리지 않도록 token embeddings에 positional embeddings를 더합니다.

**Positional Embeddings 더하기 예시:**

Token embedding vector가 `[0.5, -0.2, 0.1]`이고 positional embedding vector가 `[0.1, 0.3, -0.1]`이라고 가정해 보겠습니다. 모델이 사용하는 결합된 embedding은 다음과 같습니다:
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**Positional Embeddings의 이점:**

- **Contextual Awareness:** 모델이 위치를 기준으로 토큰을 구분할 수 있습니다.
- **Sequence Understanding:** 모델이 문법, 구문 및 문맥에 따라 달라지는 의미를 이해할 수 있습니다.

## **Modern LLMs에서의 Positional Embeddings**

### **Rotary Positional Embeddings (RoPE)**

RoPE는 query/key vectors의 차원 쌍에 위치에 따른 rotation을 적용하여 위치를 인코딩하고, absolute positions를 relative phase differences로 변환합니다. 이를 통해 embedding dimensionality를 변경하지 않고 relative position 정보를 제공하며, 최근 decoder-only LLMs에서 널리 사용됩니다.<sup>[[2]](#references)</sup>

모델 내부에서 token과 positional embeddings가 결합되는 방식은 [LLM architecture 페이지](5.-llm-architecture.md)를 참조하세요.

### **RoPE-Based Models에서 Context Windows 확장**

최근 연구에 따르면 context length는 token embedding matrix 자체보다 positional encoding scheme에 의해 제한되는 경우가 많습니다.

- **Position Interpolation (PI):** position indices를 재조정하여 더 긴 sequence가 training 중 확인된 범위에 매핑되도록 함으로써, 최소한의 fine-tuning으로 확장할 수 있습니다.<sup>[[3]](#references)</sup> 예:
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** 더 적은 추가 training step으로 더 긴 context로 extrapolate할 수 있도록 RoPE scaling/interpolation을 수정하는, compute-efficient한 RoPE 확장 전략입니다.<sup>[[4]](#references)</sup>

## Code Example

[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb)의 code example을 이어서 살펴보겠습니다:<sup>[[5]](#references)</sup>
```python
# Use previous code...

# Create dimensional emdeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
