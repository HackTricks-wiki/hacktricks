## Token Embeddings

Nakon tokenizacije tekstualnih podataka, sledeći ključni korak u pripremi podataka za treniranje velikih jezičkih modela (LLM), kao što je GPT, jeste kreiranje **token embeddings**. Token embeddings pretvaraju diskretne tokene (kao što su reči ili podreči) u neprekidne numeričke vektore koje model može da obrađuje i iz kojih može da uči. Ovo objašnjenje razlaže token embeddings, njihovu inicijalizaciju i upotrebu, kao i ulogu positional embeddings u poboljšanju razumevanja sekvenci tokena od strane modela.<sup>[[1]](#references)</sup>

> [!TIP]
> Cilj ove treće faze je veoma jednostavan: **Dodeliti svakom od prethodnih tokena u vokabularu vektor željenih dimenzija kako bi se model trenirao.** Svaka reč u vokabularu biće tačka u prostoru sa X dimenzija.\
> Imajte na umu da se u početku pozicija svake reči u prostoru inicijalizuje na „nasumičan“ način i da su te pozicije trainable parameters (biće poboljšane tokom treniranja).
>
> Štaviše, tokom token embedding **kreira se još jedan sloj embeddings** koji predstavlja (u ovom slučaju) **apsolutnu poziciju reči u rečenici za treniranje**. Na ovaj način reč na različitim pozicijama u rečenici imaće različitu reprezentaciju (značenje).

### **Šta su Token Embeddings?**

**Token Embeddings** su numeričke reprezentacije tokena u neprekidnom vektorskom prostoru. Svaki token u vokabularu povezan je sa jedinstvenim vektorom fiksnih dimenzija. Ovi vektori obuhvataju semantičke i sintaksičke informacije o tokenima, omogućavajući modelu da razume odnose i obrasce u podacima.

- **Veličina vokabulara:** Ukupan broj jedinstvenih tokena (npr. reči, podreči) u vokabularu modela.
- **Dimenzije embeddinga:** Broj numeričkih vrednosti (dimenzija) u vektoru svakog tokena. Veći broj dimenzija može da obuhvati nijansiranije informacije, ali zahteva više računarskih resursa.

**Primer:**

- **Veličina vokabulara:** 6 tokena \[1, 2, 3, 4, 5, 6]
- **Dimenzije embeddinga:** 3 (x, y, z)

### **Inicijalizacija Token Embeddings**

Na početku treniranja, token embeddings se obično inicijalizuju malim nasumičnim vrednostima. Ove početne vrednosti se prilagođavaju (fine-tune) tokom treniranja kako bi bolje predstavljale značenja tokena na osnovu podataka za treniranje.

**PyTorch primer:**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Kako token embeddings funkcionišu tokom treninga**

Tokom treninga, svaki token u ulaznim podacima pretvara se u odgovarajući embedding vektor. Ovi vektori se zatim koriste u različitim izračunavanjima unutar modela, kao što su mehanizmi pažnje i slojevi neuronske mreže.

**Primer scenarija:**

- **Veličina batch-a:** 8 (broj uzoraka koji se obrađuju istovremeno)
- **Maksimalna dužina sekvence:** 4 (broj tokena po uzorku)
- **Dimenzije embeddinga:** 256

**Struktura podataka:**

- Svaki batch predstavljen je 3D tenzorom oblika `(batch_size, max_length, embedding_dim)`.
- U našem primeru, oblik bi bio `(8, 4, 256)`.

**Vizualizacija:**

## **Pozicioni Embeddings: Dodavanje konteksta token embeddingsima**

Dok token embeddings obuhvataju značenje pojedinačnih tokena, oni sami po sebi ne kodiraju poziciju tokena unutar sekvence. Razumevanje redosleda tokena ključno je za razumevanje jezika. Tu na scenu stupaju **pozicioni embeddings**.

### **Zašto su pozicioni embeddings potrebni:**

- **Redosled tokena je važan:** U rečenicama značenje često zavisi od redosleda reči. Na primer, "The cat sat on the mat" naspram "The mat sat on the cat."
- **Ograničenje embeddinga:** Bez pozicionih informacija, model tretira tokene kao "vreću reči", zanemarujući njihov redosled.

### **Tipovi pozicionih embeddingsa:**

1. **Apsolutni pozicioni embeddings:**
- Dodeljuju jedinstveni pozicioni vektor svakoj poziciji u sekvenci.
- **Primer:** Prvi token u bilo kojoj sekvenci ima isti pozicioni embedding, drugi token ima drugi, i tako dalje.
- **Koriste ih:** OpenAI-jevi GPT modeli.
2. **Relativni pozicioni embeddings:**
- Kodiraju relativnu udaljenost između tokena, a ne njihove apsolutne pozicije.
- **Primer:** Označavaju koliko su dva tokena udaljena, bez obzira na njihove apsolutne pozicije u sekvenci.
- **Koriste ih:** Modeli kao što su Transformer-XL i neke varijante modela BERT.

### **Kako se pozicioni embeddings integrišu:**

- **Iste dimenzije:** Pozicioni embeddings imaju istu dimenzionalnost kao token embeddings.
- **Sabiranje:** Dodaju se token embeddingsima, čime se identitet tokena kombinuje sa pozicionim informacijama bez povećanja ukupne dimenzionalnosti.

**Primer dodavanja pozicionih embeddingsa:**

Pretpostavimo da je vektor token embeddinga `[0.5, -0.2, 0.1]`, a njegov vektor pozicionog embeddinga `[0.1, 0.3, -0.1]`. Kombinovani embedding koji model koristi bio bi:
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**Prednosti positional embeddings:**

- **Svest o kontekstu:** Model može da razlikuje tokene na osnovu njihovih pozicija.
- **Razumevanje sekvence:** Omogućava modelu da razume gramatiku, sintaksu i značenja zavisna od konteksta.

## **Positional Embeddings u modernim LLM-ovima**

### **Rotary Positional Embeddings (RoPE)**

RoPE kodira poziciju primenom rotacije zavisne od pozicije na parove dimenzija u query/key vektorima, pretvarajući apsolutne pozicije u relativne fazne razlike. Na ovaj način pruža informacije o relativnim pozicijama, uz zadržavanje nepromenjene dimenzionalnosti embeddinga, i široko se koristi u novijim decoder-only LLM-ovima.<sup>[[2]](#references)</sup>

Za informacije o tome kako se token i positional embeddings kombinuju unutar modela, pogledajte [stranicu o LLM arhitekturi](5.-llm-architecture.md).

### **Proširivanje context windows u modelima zasnovanim na RoPE-u**

Nedavna istraživanja pokazuju da je dužina konteksta često ograničena šemom positional encodinga, a ne samom matricom token embeddinga.

- **Position Interpolation (PI):** Ponovo skalira indekse pozicija tako da se duže sekvence mapiraju u opseg viđen tokom treninga, čime se omogućava proširivanje uz minimalan fine-tuning.<sup>[[3]](#references)</sup> Primer:
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** Compute-efficient RoPE strategija proširenja koja menja RoPE scaling/interpolaciju kako bi se kontekst proširio na veće dužine uz manji broj dodatnih training koraka.<sup>[[4]](#references)</sup>

```python
# Use previous code...

# Create dimensional emdeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
