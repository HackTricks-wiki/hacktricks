## Plongements de tokens

Après avoir tokenisé les données textuelles, l’étape critique suivante dans la préparation des données pour l’entraînement de grands modèles de langage (LLM) comme GPT consiste à créer des **plongements de tokens**. Les plongements de tokens transforment les tokens discrets (tels que les mots ou les sous-mots) en vecteurs numériques continus que le modèle peut traiter et exploiter pour apprendre. Cette explication détaille les plongements de tokens, leur initialisation, leur utilisation, ainsi que le rôle des plongements positionnels dans l’amélioration de la compréhension des séquences de tokens par le modèle.<sup>[[1]](#references)</sup>

> [!TIP]
> L’objectif de cette troisième phase est très simple : **Attribuer à chacun des tokens précédents du vocabulaire un vecteur des dimensions souhaitées afin d’entraîner le modèle.** Chaque mot du vocabulaire constituera un point dans un espace à X dimensions.\
> Notez qu’au départ, la position de chaque mot dans l’espace est simplement initialisée « aléatoirement », et ces positions sont des paramètres entraînables (elles seront améliorées pendant l’entraînement).
>
> De plus, pendant le **plongement des tokens**, **une autre couche de plongements est créée** afin de représenter (dans ce cas) la **position absolue du mot dans la phrase d’entraînement**. Ainsi, un mot situé à des positions différentes dans la phrase aura une représentation (un sens) différent.

### **Que sont les plongements de tokens ?**

Les **plongements de tokens** sont des représentations numériques des tokens dans un espace vectoriel continu. Chaque token du vocabulaire est associé à un vecteur unique de dimensions fixes. Ces vecteurs capturent les informations sémantiques et syntaxiques des tokens, permettant au modèle de comprendre les relations et les patterns présents dans les données.

- **Taille du vocabulaire :** Le nombre total de tokens uniques (par exemple, des mots ou des sous-mots) dans le vocabulaire du modèle.
- **Dimensions du plongement :** Le nombre de valeurs numériques (dimensions) dans le vecteur de chaque token. Des dimensions plus élevées peuvent capturer des informations plus nuancées, mais nécessitent davantage de ressources de calcul.

**Exemple :**

- **Taille du vocabulaire :** 6 tokens \[1, 2, 3, 4, 5, 6]
- **Dimensions du plongement :** 3 (x, y, z)

### **Initialisation des plongements de tokens**

Au début de l’entraînement, les plongements de tokens sont généralement initialisés avec de petites valeurs aléatoires. Ces valeurs initiales sont ajustées (affinées) pendant l’entraînement afin de mieux représenter la signification des tokens en fonction des données d’entraînement.

**Exemple PyTorch :**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Fonctionnement des embeddings de tokens pendant l’entraînement**

Pendant l’entraînement, chaque token des données d’entrée est converti en son vecteur d’embedding correspondant. Ces vecteurs sont ensuite utilisés dans divers calculs au sein du modèle, notamment les mécanismes d’attention et les couches de réseaux neuronaux.

**Exemple :**

- **Taille du batch :** 8 (nombre d’échantillons traités simultanément)
- **Longueur maximale de la séquence :** 4 (nombre de tokens par échantillon)
- **Dimensions de l’embedding :** 256

**Structure des données :**

- Chaque batch est représenté par un tenseur 3D de forme `(batch_size, max_length, embedding_dim)`.
- Dans notre exemple, la forme serait `(8, 4, 256)`.

## **Embeddings positionnels : ajouter du contexte aux embeddings de tokens**

Alors que les embeddings de tokens capturent la signification de chaque token, ils n'encodent pas intrinsèquement la position des tokens au sein d'une séquence. Comprendre l'ordre des tokens est essentiel à la compréhension du langage. C'est là qu'interviennent les **embeddings positionnels**.

### **Pourquoi les embeddings positionnels sont nécessaires :**

- **L'ordre des tokens est important :** dans les phrases, la signification dépend souvent de l'ordre des mots. Par exemple, « The cat sat on the mat » et « The mat sat on the cat ».
- **Limitation des embeddings :** sans information positionnelle, le modèle traite les tokens comme un « sac de mots », en ignorant leur séquence.

### **Types d'embeddings positionnels :**

1. **Embeddings positionnels absolus :**
- Attribuent un vecteur de position unique à chaque position de la séquence.
- **Exemple :** le premier token de toute séquence possède le même embedding positionnel, le deuxième token en possède un autre, et ainsi de suite.
- **Utilisés par :** les modèles GPT d'OpenAI.
2. **Embeddings positionnels relatifs :**
- Encodent la distance relative entre les tokens plutôt que leurs positions absolues.
- **Exemple :** indiquent la distance entre deux tokens, quelles que soient leurs positions absolues dans la séquence.
- **Utilisés par :** des modèles comme Transformer-XL et certaines variantes de BERT.

### **Comment les embeddings positionnels sont intégrés :**

- **Mêmes dimensions :** les embeddings positionnels ont la même dimensionalité que les embeddings de tokens.
- **Addition :** ils sont ajoutés aux embeddings de tokens, combinant l'identité du token avec l'information positionnelle sans augmenter la dimensionalité globale.

**Exemple d'ajout d'embeddings positionnels :**

Supposons qu'un vecteur d'embedding de token soit `[0.5, -0.2, 0.1]` et que son vecteur d'embedding positionnel soit `[0.1, 0.3, -0.1]`. L'embedding combiné utilisé par le modèle serait :
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**Avantages des embeddings positionnels :**

- **Conscience contextuelle :** Le modèle peut différencier les tokens en fonction de leur position.
- **Compréhension des séquences :** Permet au modèle de comprendre la grammaire, la syntaxe et les significations dépendantes du contexte.

## **Embeddings positionnels dans les LLM modernes**

### **Embeddings positionnels rotatifs (RoPE)**

RoPE encode la position en appliquant une rotation dépendante de la position à des paires de dimensions dans les vecteurs query/key, transformant les positions absolues en différences de phase relatives. Cela fournit des informations de position relative tout en conservant la dimensionnalité de l'embedding et est largement utilisé dans les LLM récents de type decoder-only.<sup>[[2]](#references)</sup>

Pour savoir comment les embeddings de tokens et les embeddings positionnels sont combinés à l'intérieur du modèle, consultez [la page sur l'architecture des LLM](5.-llm-architecture.md).

### **Extension des fenêtres de contexte dans les modèles basés sur RoPE**

Des travaux récents montrent que la longueur du contexte est souvent limitée par le schéma d'encodage positionnel plutôt que par la matrice d'embeddings des tokens elle-même.

- **Interpolation de position (PI) :** Redimensionne les indices de position afin que les séquences plus longues soient mappées dans la plage observée pendant l'entraînement, permettant une extension avec un fine-tuning minimal.<sup>[[3]](#references)</sup> Exemple :
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** Une stratégie d’extension de RoPE efficace en termes de calcul, qui modifie la mise à l’échelle/interpolation de RoPE afin d’extrapoler vers des contextes plus longs avec moins d’étapes d’entraînement supplémentaires.<sup>[[4]](#references)</sup>

Poursuivons avec l’exemple de code de [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[5]](#references)</sup>
```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
