## トークン埋め込み

テキストデータをトークン化した後、大規模言語モデル（LLM）をトレーニングするための次の重要なステップは、**トークン埋め込み**の作成です。トークン埋め込みは、離散的なトークン（単語やサブワードなど）を、モデルが処理して学習できる連続的な数値ベクトルに変換します。この解説では、トークン埋め込み、その初期化と使用方法、さらにトークン列に対するモデルの理解を深める位置埋め込みの役割について説明します。<sup>[[1]](#references)</sup>

> [!TIP]
> この第3段階の目的はとてもシンプルです。**語彙内の各トークンに、モデルをトレーニングするための指定された次元数のベクトルを割り当てます。** 語彙内の各単語は、X次元空間内の一点になります。\
> 初期状態では、空間内の各単語の位置は「ランダムに」初期化されているだけであり、これらの位置はトレーニング可能なパラメーターです（トレーニング中に改善されます）。
>
> さらに、トークン埋め込みの作成時に、（この場合は）トレーニング文内での単語の**絶対位置**を表す**別の埋め込みレイヤー**も作成されます。これにより、文中の異なる位置にある単語は、それぞれ異なる表現（意味）を持つようになります。

### **トークン埋め込みとは？**

**トークン埋め込み**は、連続的なベクトル空間におけるトークンの数値表現です。語彙内の各トークンには、固定次元数の固有のベクトルが割り当てられます。これらのベクトルはトークンの意味的・構文的な情報を捉え、モデルがデータ内の関係やパターンを理解できるようにします。

- **語彙サイズ:** モデルの語彙内にある一意なトークン（単語、サブワードなど）の総数。
- **埋め込み次元数:** 各トークンのベクトルに含まれる数値の個数（次元数）。次元数を増やすと、より細かな情報を捉えられますが、より多くの計算リソースが必要になります。

**例:**

- **語彙サイズ:** 6トークン \[1, 2, 3, 4, 5, 6]
- **埋め込み次元数:** 3（x, y, z）

### **トークン埋め込みの初期化**

トレーニングの開始時に、通常、トークン埋め込みは小さなランダム値で初期化されます。これらの初期値は、トレーニングデータに基づいてトークンの意味をより適切に表すよう、トレーニング中に調整（微調整）されます。

**PyTorchの例:**

```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

**出力:**


**説明:**

- 各行は語彙内のトークンに対応します。
- 各列は埋め込みベクトルの次元を表します。
- たとえば、インデックス `3` のトークンの埋め込みベクトルは `[-0.4015, 0.9666, -1.1481]` です。

**トークンの埋め込みへのアクセス:**

```python
# Retrieve the embedding for the token at index 3
token_index = torch.tensor([3])
```

- インデックス `3` の token は、ベクトル `[-0.4015, 0.9666, -1.1481]` で表されます。
- これらの値は学習可能なパラメータであり、token の文脈や意味をより適切に表現するため、学習中にモデルが調整します。

### **学習中の Token Embedding の仕組み**

学習中、入力データ内の各 token は対応する embedding vector に変換されます。これらのベクトルは、attention mechanism やニューラルネットワーク層など、モデル内のさまざまな計算で使用されます。

**例:**

- **バッチサイズ:** 8（同時に処理するサンプル数）
- **最大シーケンス長:** 4（サンプルあたりの token 数）
- **Embedding 次元数:** 256

**データ構造:**

- 各バッチは、形状が `(batch_size, max_length, embedding_dim)` の3Dテンソルで表されます。
- この例では、形状は `(8, 4, 256)` となります。

**可視化:**

## **位置埋め込み: トークン埋め込みへの文脈の追加**

トークン埋め込みは個々のトークンの意味を捉えますが、シーケンス内におけるトークンの位置は本質的には符号化しません。言語を理解するには、トークンの順序を把握することが重要です。ここで**位置埋め込み**が役立ちます。

### **位置埋め込みが必要な理由:**

- **トークンの順序は重要:** 文では、意味が単語の順序に依存することがよくあります。たとえば、「猫がマットの上に座った」と「マットが猫の上に座った」の違いです。
- **埋め込みの限界:** 位置情報がなければ、モデルはトークンを「単語の袋」として扱い、順序を無視します。

### **位置埋め込みの種類:**

1. **絶対位置埋め込み:**
   - シーケンス内の各位置に固有の位置ベクトルを割り当てます。
   - **例:** どのシーケンスでも、最初のトークンには同じ位置埋め込みが割り当てられ、2番目のトークンには別の埋め込みが割り当てられます。
   - **使用例:** OpenAIのGPTモデル。
2. **相対位置埋め込み:**
   - トークンの絶対位置ではなく、トークン間の相対距離を符号化します。
   - **例:** シーケンス内での絶対位置に関係なく、2つのトークン間の距離を示します。
   - **使用例:** Transformer-XLや一部のBERT派生モデル。

### **位置埋め込みの統合方法:**

- **同じ次元数:** 位置埋め込みはトークン埋め込みと同じ次元数です。
- **加算:** トークンの識別情報と位置情報を組み合わせるため、全体の次元数を増やさずに位置埋め込みをトークン埋め込みに加算します。

**位置埋め込みを加算する例:**

トークン埋め込みベクトルが`[0.5, -0.2, 0.1]`で、その位置埋め込みベクトルが`[0.1, 0.3, -0.1]`だとします。モデルで使用される結合後の埋め込みは次のようになります。

```css
Combined Embedding = Token Embedding + Positional Embedding
                   = [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
                   = [0.6, 0.1, 0.0]
```

**位置埋め込みの利点:**

- **文脈認識:** モデルは、位置に基づいてトークンを区別できます。
- **系列の理解:** モデルが文法、構文、文脈に依存する意味を理解できるようになります。

## **最新のLLMにおける位置埋め込み**

### **Rotary Positional Embeddings (RoPE)**

RoPEは、クエリ/キーのベクトル内の次元ペアに位置依存の回転を適用して位置を符号化し、絶対位置を相対的な位相差に変換します。埋め込みの次元数を変えずに相対位置情報を提供できるため、近年のdecoder-only LLMで広く使われています。<sup>[[2]](#references)</sup>

モデル内部でトークン埋め込みと位置埋め込みをどのように組み合わせるかについては、[LLM architectureのページ](5.-llm-architecture.md)を参照してください。

### **RoPEベースのモデルでのコンテキストウィンドウの拡張**

近年の研究によると、コンテキスト長はトークン埋め込み行列そのものではなく、位置エンコーディング方式によって制限されることがよくあります。

- **Position Interpolation (PI):** 位置インデックスを再スケーリングして、より長い系列が学習時に見た範囲内に収まるようにし、最小限のファインチューニングで拡張を可能にします。<sup>[[3]](#references)</sup> 例:

```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```

- **YaRN:** 追加の学習ステップを少なく抑えながら、RoPEのスケーリング／補間を変更して長いコンテキストへ外挿する、計算効率の高いRoPE拡張手法。<sup>[[4]](#references)</sup>

## コード例

[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb)のコード例に従います。<sup>[[5]](#references)</sup>

```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
    raw_text, batch_size=8, max_length=max_length,
    stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
