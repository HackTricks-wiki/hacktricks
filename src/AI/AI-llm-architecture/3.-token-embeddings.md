## Osadzenia tokenów

Po tokenizacji danych tekstowych kolejnym kluczowym krokiem w przygotowywaniu danych do trenowania dużych modeli językowych (LLM), takich jak GPT, jest tworzenie **osadzeń tokenów**. Osadzenia tokenów przekształcają dyskretne tokeny (takie jak słowa lub podwyrazy) w ciągłe wektory liczbowe, które model może przetwarzać i na których może się uczyć. Poniżej omówiono osadzenia tokenów, ich inicjalizację i wykorzystanie oraz rolę osadzeń pozycyjnych w lepszym rozumieniu przez model sekwencji tokenów.<sup>[[1]](#references)</sup>

> [!TIP]
> Cel tej trzeciej fazy jest bardzo prosty: **Przypisz każdemu z wcześniejszych tokenów w słowniku wektor o żądanych wymiarach, aby wytrenować model.** Każde słowo w słowniku będzie punktem w przestrzeni o X wymiarach.\
> Pamiętaj, że początkowo położenie każdego słowa w przestrzeni jest jedynie „losowe”, a te położenia są trenowalnymi parametrami (będą ulepszane podczas treningu).
>
> Ponadto podczas tworzenia osadzeń tokenów **tworzona jest kolejna warstwa osadzeń**, która reprezentuje (w tym przypadku) **bezwzględną pozycję słowa w zdaniu treningowym**. Dzięki temu słowo występujące w różnych miejscach zdania będzie miało inną reprezentację (znaczenie).

### **Czym są osadzenia tokenów?**

**Osadzenia tokenów** to liczbowe reprezentacje tokenów w ciągłej przestrzeni wektorowej. Każdemu tokenowi w słowniku przypisany jest unikalny wektor o ustalonych wymiarach. Wektory te odwzorowują informacje semantyczne i składniowe dotyczące tokenów, umożliwiając modelowi rozpoznawanie zależności i wzorców w danych.

- **Rozmiar słownika:** Łączna liczba unikalnych tokenów (np. słów, podwyrazów) w słowniku modelu.
- **Wymiary osadzenia:** Liczba wartości liczbowych (wymiarów) w wektorze każdego tokenu. Większa liczba wymiarów może pozwolić na odwzorowanie bardziej subtelnych informacji, ale wymaga większych zasobów obliczeniowych.

**Przykład:**

- **Rozmiar słownika:** 6 tokenów \[1, 2, 3, 4, 5, 6]
- **Wymiary osadzenia:** 3 (x, y, z)

### **Inicjalizacja osadzeń tokenów**

Na początku treningu osadzenia tokenów są zwykle inicjalizowane małymi wartościami losowymi. Wartości początkowe są dostosowywane (dostrajane) podczas treningu, aby lepiej odwzorowywały znaczenie tokenów na podstawie danych treningowych.

**Przykład w PyTorch:**

```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

**Wynik:**

```lua

```

**Wyjaśnienie:**

- Każdy wiersz odpowiada tokenowi w słowniku.
- Każda kolumna reprezentuje wymiar w wektorze embeddingowym.
- Na przykład token o indeksie `3` ma wektor embeddingowy `[-0.4015, 0.9666, -1.1481]`.

**Dostęp do embeddingu tokena:**

```python
# Retrieve the embedding for the token at index 3
token_index = torch.tensor([3])
print(embedding_layer(token_index))
```

**Wynik:**

```lua

```

**Interpretacja:**

- Token o indeksie `3` jest reprezentowany przez wektor `[-0.4015, 0.9666, -1.1481]`.
- Te wartości to trenowalne parametry, które model dostosowuje podczas treningu, aby lepiej reprezentować kontekst i znaczenie tokena.

### **Jak działają osadzenia tokenów podczas treningu**

Podczas treningu każdy token w danych wejściowych jest konwertowany na odpowiadający mu wektor osadzenia. Wektory te są następnie wykorzystywane w różnych obliczeniach w modelu, takich jak mechanizmy uwagi i warstwy sieci neuronowej.

**Przykładowy scenariusz:**

- **Rozmiar batcha:** 8 (liczba próbek przetwarzanych jednocześnie)
- **Maksymalna długość sekwencji:** 4 (liczba tokenów w każdej próbce)
- **Wymiary osadzenia:** 256

**Struktura danych:**

- Każdy batch jest reprezentowany jako tensor 3D o kształcie `(batch_size, max_length, embedding_dim)`.
- W naszym przykładzie kształt wynosiłby `(8, 4, 256)`.

**Wizualizacja:**

- Model przetwarza te embeddingi, aby uczyć się wzorców językowych i generować predykcje.

## **Embeddingi pozycyjne: dodawanie kontekstu do embeddingów tokenów**

Embeddingi tokenów oddają znaczenie poszczególnych tokenów, ale same z siebie nie kodują ich pozycji w sekwencji. Zrozumienie kolejności tokenów ma kluczowe znaczenie dla rozumienia języka. W tym pomagają **embeddingi pozycyjne**.

### **Dlaczego embeddingi pozycyjne są potrzebne:**

- **Kolejność tokenów ma znaczenie:** W zdaniach znaczenie często zależy od kolejności słów. Na przykład: „Kot siedział na macie” vs. „Mata siedziała na kocie”.
- **Ograniczenie embeddingów:** Bez informacji o pozycji model traktuje tokeny jak „worek słów”, ignorując ich kolejność.

### **Rodzaje embeddingów pozycyjnych:**

1. **Absolutne embeddingi pozycyjne:**
   - Przypisują unikatowy wektor pozycyjny każdej pozycji w sekwencji.
   - **Przykład:** Pierwszy token w każdej sekwencji ma ten sam embedding pozycyjny, drugi token ma inny i tak dalej.
   - **Używane przez:** modele GPT firmy OpenAI.
2. **Względne embeddingi pozycyjne:**
   - Kodują względną odległość między tokenami, a nie ich pozycje bezwzględne.
   - **Przykład:** Wskazują, jak daleko od siebie znajdują się dwa tokeny, niezależnie od ich bezwzględnych pozycji w sekwencji.
   - **Używane przez:** modele takie jak Transformer-XL i niektóre warianty BERT.

### **Jak integrowane są embeddingi pozycyjne:**

- **Te same wymiary:** Embeddingi pozycyjne mają taki sam wymiar jak embeddingi tokenów.
- **Dodawanie:** Są dodawane do embeddingów tokenów, łącząc tożsamość tokenu z informacją o jego pozycji bez zwiększania łącznego wymiaru.

**Przykład dodawania embeddingów pozycyjnych:**

Załóżmy, że wektor embeddingu tokenu to `[0.5, -0.2, 0.1]`, a jego wektor embeddingu pozycyjnego to `[0.1, 0.3, -0.1]`. Połączony embedding używany przez model będzie wynosić:

```css
Combined Embedding = Token Embedding + Positional Embedding
                   = [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
                   = [0.6, 0.1, 0.0]
```

**Zalety osadzeń pozycyjnych:**

- **Świadomość kontekstu:** Model może rozróżniać tokeny na podstawie ich pozycji.
- **Rozumienie sekwencji:** Umożliwia modelowi rozumienie gramatyki, składni i znaczeń zależnych od kontekstu.

## **Osadzenia pozycyjne we współczesnych LLM-ach**

### **Rotacyjne osadzenia pozycyjne (RoPE)**

RoPE koduje pozycję, stosując zależny od pozycji obrót do par wymiarów w wektorach query/key, zamieniając pozycje bezwzględne na względne różnice faz. Zapewnia to informacje o pozycjach względnych bez zmiany wymiarowości osadzeń i jest szeroko stosowane w najnowszych modelach LLM typu decoder-only.<sup>[[2]](#references)</sup>

Informacje o tym, jak osadzenia tokenów i pozycji są łączone wewnątrz modelu, znajdziesz na [stronie poświęconej architekturze LLM](5.-llm-architecture.md).

### **Rozszerzanie okien kontekstu w modelach opartych na RoPE**

Najnowsze badania pokazują, że długość kontekstu jest często ograniczona przez schemat kodowania pozycji, a nie przez samą macierz osadzeń tokenów.

- **Interpolacja pozycji (PI):** Przeskalowuje indeksy pozycji, aby dłuższe sekwencje mieściły się w zakresie obserwowanym podczas treningu, umożliwiając rozszerzenie przy minimalnym dostrajaniu.<sup>[[3]](#references)</sup> Przykład:

```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```

- **YaRN:** Wydajna obliczeniowo strategia rozszerzania RoPE, która modyfikuje skalowanie/interpolację RoPE, aby umożliwić ekstrapolację do dłuższych kontekstów przy mniejszej liczbie dodatkowych kroków treningowych.<sup>[[4]](#references)</sup>

## Przykład kodu

Poniżej znajduje się przykład kodu z [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[5]](#references)</sup>

```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
    raw_text, batch_size=8, max_length=max_length,
    stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
