## Векторні представлення токенів

Після токенізації текстових даних наступним важливим кроком підготовки даних для навчання великих мовних моделей (LLM), таких як GPT, є створення **векторних представлень токенів**. Векторні представлення токенів перетворюють дискретні токени (наприклад, слова або субслова) на неперервні числові вектори, які модель може обробляти та на яких може навчатися. Це пояснення охоплює векторні представлення токенів, їх ініціалізацію та використання, а також роль позиційних векторних представлень у покращенні розуміння моделлю послідовностей токенів.<sup>[[1]](#references)</sup>

> [!TIP]
> Мета цієї третьої фази дуже проста: **призначити кожному з попередніх токенів у словнику вектор бажаних розмірностей для навчання моделі.** Кожне слово у словнику буде точкою у просторі з X вимірами.\
> Зауважте, що спочатку позиція кожного слова у просторі просто ініціалізується «випадково», і ці позиції є параметрами, які навчаються (їх буде покращено під час навчання).
>
> Крім того, під час створення векторних представлень токенів **створюється ще один шар векторних представлень**, який представляє (у цьому випадку) **абсолютну позицію слова в навчальному реченні**. Таким чином, слово на різних позиціях у реченні матиме різне представлення (значення).

### **Що таке векторні представлення токенів?**

**Векторні представлення токенів** — це числові представлення токенів у неперервному векторному просторі. Кожному токену у словнику відповідає унікальний вектор фіксованої розмірності. Ці вектори містять семантичну та синтаксичну інформацію про токени, даючи моделі змогу розуміти зв’язки та закономірності в даних.

- **Розмір словника:** загальна кількість унікальних токенів (наприклад, слів або субслів) у словнику моделі.
- **Розмірність векторного представлення:** кількість числових значень (вимірів) у векторі кожного токена. Більша розмірність дає змогу зберігати більше нюансів інформації, але потребує більше обчислювальних ресурсів.

**Приклад:**

- **Розмір словника:** 6 токенів \[1, 2, 3, 4, 5, 6]
- **Розмірність векторного представлення:** 3 (x, y, z)

### **Ініціалізація векторних представлень токенів**

На початку навчання векторні представлення токенів зазвичай ініціалізуються малими випадковими значеннями. Ці початкові значення коригуються (доопрацьовуються) під час навчання, щоб краще відображати значення токенів на основі навчальних даних.

**Приклад у PyTorch:**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Як працюють embedding токенів під час навчання**

Під час навчання кожен токен у вхідних даних перетворюється на відповідний embedding-вектор. Потім ці вектори використовуються в різних обчисленнях усередині моделі, зокрема в механізмах уваги та шарах нейронної мережі.

**Приклад сценарію:**

- **Розмір batch:** 8 (кількість зразків, що обробляються одночасно)
- **Максимальна довжина послідовності:** 4 (кількість токенів у кожному зразку)
- **Розмірність embedding:** 256

**Структура даних:**

- Кожен batch представлений 3D-тензором із формою `(batch_size, max_length, embedding_dim)`.
- Для нашого прикладу форма буде `(8, 4, 256)`.

**Візуалізація:**

## **Позиційні embeddings: додавання контексту до token embeddings**

Хоча token embeddings відображають значення окремих token, вони не кодують позицію token у послідовності. Розуміння порядку token має вирішальне значення для розуміння мови. Саме тут у гру вступають **позиційні embeddings**.

### **Навіщо потрібні позиційні embeddings:**

- **Порядок token має значення:** У реченнях значення часто залежить від порядку слів. Наприклад, "Кіт сидів на килимку" проти "Килимок сидів на коті."
- **Обмеження embeddings:** Без позиційної інформації модель сприймає token як "набір слів", ігноруючи їхню послідовність.

### **Типи позиційних embeddings:**

1. **Абсолютні позиційні embeddings:**
- Призначають унікальний вектор позиції кожній позиції в послідовності.
- **Приклад:** Перший token у будь-якій послідовності має однаковий positional embedding, другий token має інший і так далі.
- **Використовуються:** моделями GPT від OpenAI.
2. **Відносні позиційні embeddings:**
- Кодують відносну відстань між token, а не їхні абсолютні позиції.
- **Приклад:** Вказують, наскільки далеко один від одного розташовані два token, незалежно від їхніх абсолютних позицій у послідовності.
- **Використовуються:** такими моделями, як Transformer-XL, і деякими варіантами BERT.

### **Як інтегруються позиційні embeddings:**

- **Однакова розмірність:** Позиційні embeddings мають таку саму розмірність, як і token embeddings.
- **Додавання:** Вони додаються до token embeddings, поєднуючи ідентичність token із позиційною інформацією без збільшення загальної розмірності.

**Приклад додавання позиційних embeddings:**

Припустімо, що вектор token embedding має вигляд `[0.5, -0.2, 0.1]`, а його positional embedding — `[0.1, 0.3, -0.1]`. Об’єднаний embedding, який використовує модель, матиме вигляд:
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**Переваги Positional Embeddings:**

- **Контекстна обізнаність:** модель може розрізняти токени на основі їхніх позицій.
- **Розуміння послідовності:** дає змогу моделі розуміти граматику, синтаксис і значення, що залежать від контексту.

## **Positional Embeddings у сучасних LLMs**

### **Rotary Positional Embeddings (RoPE)**

RoPE кодує позицію, застосовуючи залежний від позиції поворот до пар вимірів у векторах query/key, перетворюючи абсолютні позиції на відносні фазові різниці. Це забезпечує інформацію про відносні позиції, зберігаючи незмінною розмірність embedding, і широко використовується в нових decoder-only LLMs.<sup>[[2]](#references)</sup>

Щоб дізнатися, як token і positional embeddings комбінуються всередині моделі, див. [сторінку про архітектуру LLM](5.-llm-architecture.md).

### **Розширення контекстних вікон у моделях на основі RoPE**

Нещодавні дослідження показують, що довжина контексту часто обмежується схемою positional encoding, а не самою матрицею token embedding.

- **Position Interpolation (PI):** масштабує індекси позицій так, щоб довші послідовності відображалися в діапазоні, який використовувався під час навчання, що дає змогу розширити контекст із мінімальним fine-tuning.<sup>[[3]](#references)</sup> Приклад:
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** обчислювально ефективна стратегія розширення RoPE, яка модифікує масштабування/інтерполяцію RoPE для екстраполяції до довших контекстів із меншою кількістю додаткових кроків навчання.<sup>[[4]](#references)</sup>

Нижче наведено приклад коду з [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[5]](#references)</sup>
```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
