## Token Embeddings

Baada ya kuweka tokeni katika vipande vya maandishi, hatua inayofuata muhimu katika kuandaa data ya kufundishia large language models (LLMs) kama GPT ni kuunda **token embeddings**. Token embeddings hubadilisha tokeni za kipekee (kama vile maneno au sehemu za maneno) kuwa vekta za namba zinazoendelea ambazo model inaweza kuchakata na kujifunza kutokana nazo. Maelezo haya yanafafanua token embeddings, uanzishaji wake, matumizi yake, na jukumu la positional embeddings katika kuboresha uelewa wa model kuhusu mfuatano wa tokeni.<sup>[[1]](#references)</sup>

> [!TIP]
> Lengo la awamu hii ya tatu ni rahisi sana: **Kukabidhi kila tokeni ya awali katika vocabulary vekta yenye vipimo vinavyohitajika ili kufundisha model.** Kila neno katika vocabulary litakuwa nukta katika nafasi yenye vipimo X.\
> Kumbuka kwamba mwanzoni nafasi ya kila neno katika nafasi hiyo huanzishwa tu "bila mpangilio", na nafasi hizi ni vigezo vinavyoweza kufundishwa (vitaboreshwa wakati wa mafunzo).
>
> Zaidi ya hayo, wakati wa token embedding **tabaka jingine la embeddings huundwa** ambalo huwakilisha (katika hali hii) **nafasi kamili ya neno katika sentensi ya mafunzo**. Kwa njia hii, neno lililo katika nafasi tofauti ndani ya sentensi litakuwa na uwakilishi (maana) tofauti.

### **Token Embeddings Ni Nini?**

**Token Embeddings** ni uwakilishi wa namba wa tokeni katika nafasi ya vekta inayoendelea. Kila tokeni katika vocabulary inahusishwa na vekta ya kipekee yenye vipimo vilivyowekwa. Vekta hizi hunasa taarifa za kisemantiki na kisintaksia kuhusu tokeni, na kuiwezesha model kuelewa mahusiano na mifumo katika data.

- **Ukubwa wa Vocabulary:** Jumla ya tokeni za kipekee (kwa mfano, maneno au sehemu za maneno) katika vocabulary ya model.
- **Vipimo vya Embedding:** Idadi ya thamani za namba (vipimo) katika vekta ya kila tokeni. Vipimo vya juu vinaweza kunasa taarifa zenye muktadha zaidi, lakini vinahitaji rasilimali nyingi zaidi za kimahesabu.

**Mfano:**

- **Ukubwa wa Vocabulary:** tokeni 6 \[1, 2, 3, 4, 5, 6]
- **Vipimo vya Embedding:** 3 (x, y, z)

### **Kuanzisha Token Embeddings**

Mwanzoni mwa mafunzo, token embeddings kwa kawaida huanzishwa kwa thamani ndogo za nasibu. Thamani hizi za awali hurekebishwa (fine-tuned) wakati wa mafunzo ili kuwakilisha vyema zaidi maana za tokeni kulingana na data ya mafunzo.

**Mfano wa PyTorch:**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Jinsi Token Embeddings Zinavyofanya Kazi Wakati wa Training**

Wakati wa training, kila token katika data ya input hubadilishwa kuwa embedding vector yake inayolingana. Vector hizi hutumika katika mahesabu mbalimbali ndani ya model, kama vile attention mechanisms na neural network layers.

**Mfano wa Hali:**

- **Batch Size:** 8 (idadi ya samples zinazochakatwa kwa wakati mmoja)
- **Max Sequence Length:** 4 (idadi ya tokens kwa kila sample)
- **Embedding Dimensions:** 256

**Muundo wa Data:**

- Kila batch inawakilishwa na 3D tensor yenye shape `(batch_size, max_length, embedding_dim)`.
- Kwa mfano wetu, shape itakuwa `(8, 4, 256)`.

## **Positional Embeddings: Kuongeza Muktadha kwenye Token Embeddings**

Ingawa token embeddings hunasa maana ya token mahususi, hazisimbii moja kwa moja nafasi za token ndani ya mfululizo. Kuelewa mpangilio wa token ni muhimu kwa uelewa wa lugha. Hapa ndipo **positional embeddings** hutumika.

### **Kwa Nini Positional Embeddings Zinahitajika:**

- **Mpangilio wa Token ni Muhimu:** Katika sentensi, maana mara nyingi hutegemea mpangilio wa maneno. Kwa mfano, "The cat sat on the mat" dhidi ya "The mat sat on the cat."
- **Kikomo cha Embedding:** Bila taarifa ya nafasi, model huzichukulia token kama "mfuko wa maneno," ikipuuza mfuatano wake.

### **Aina za Positional Embeddings:**

1. **Absolute Positional Embeddings:**
- Hupanga vector ya nafasi ya kipekee kwa kila nafasi katika mfululizo.
- **Mfano:** Token ya kwanza katika mfululizo wowote huwa na positional embedding ileile, token ya pili huwa na nyingine, na kadhalika.
- **Hutumika na:** GPT models za OpenAI.
2. **Relative Positional Embeddings:**
- Husimba umbali wa kulinganisha kati ya token badala ya nafasi zake kamili.
- **Mfano:** Huonyesha umbali kati ya token mbili, bila kujali nafasi zake kamili katika mfululizo.
- **Hutumika na:** Models kama Transformer-XL na baadhi ya variants za BERT.

### **Jinsi Positional Embeddings Zinavyounganishwa:**

- **Vipimo Vinavyofanana:** Positional embeddings zina dimensionality sawa na token embeddings.
- **Kuongeza:** Huongezwa kwenye token embeddings, zikiunganisha utambulisho wa token na taarifa ya nafasi bila kuongeza dimensionality ya jumla.

**Mfano wa Kuongeza Positional Embeddings:**

Tuseme vector ya token embedding ni `[0.5, -0.2, 0.1]` na vector yake ya positional embedding ni `[0.1, 0.3, -0.1]`. Embedding iliyounganishwa inayotumiwa na model itakuwa:
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**Faida za Positional Embeddings:**

- **Uelewa wa Muktadha:** Modeli inaweza kutofautisha token kulingana na nafasi zake.
- **Uelewa wa Mfuatano:** Huwezesha modeli kuelewa sarufi, sintaksia na maana zinazotegemea muktadha.

## **Positional Embeddings katika LLMs za Kisasa**

### **Rotary Positional Embeddings (RoPE)**

RoPE huweka nafasi kwa kutumia mzunguko unaotegemea nafasi kwenye jozi za vipimo vya vekta za query/key, na kubadilisha nafasi kamili kuwa tofauti za awamu zinazohusiana. Hii hutoa taarifa ya nafasi inayohusiana huku ikidumisha ukubwa wa embedding bila kubadilika, na hutumiwa sana katika LLMs za hivi karibuni za decoder-only.<sup>[[2]](#references)</sup>

Kwa maelezo kuhusu jinsi token na positional embeddings zinavyounganishwa ndani ya modeli, angalia [ukurasa wa usanifu wa LLM](5.-llm-architecture.md).

### **Kupanua Context Windows katika Modeli Zinazotumia RoPE**

Utafiti wa hivi karibuni unaonyesha kuwa urefu wa context mara nyingi huzuiwa na mbinu ya positional encoding badala ya token embedding matrix yenyewe.

- **Position Interpolation (PI):** Hurekebisha upya faharasa za nafasi ili mfuatano mirefu uingie kwenye masafa yaliyoonekana wakati wa training, na hivyo kuwezesha upanuzi kwa fine-tuning ndogo.<sup>[[3]](#references)</sup> Mfano:
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** Mkakati wa RoPE wenye ufanisi wa kimahesabu unaorekebisha scaling/interpolation ya RoPE ili extrapolate hadi contexts ndefu kwa hatua chache za ziada za training.<sup>[[4]](#references)</sup>

```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
