## Token-Embeddings

Nach dem Tokenisieren von Textdaten besteht der nächste wichtige Schritt bei der Vorbereitung von Daten für das Training großer Sprachmodelle (LLMs) wie GPT darin, **Token-Embeddings** zu erstellen. Token-Embeddings wandeln diskrete Tokens (wie Wörter oder Teilwörter) in kontinuierliche numerische Vektoren um, die das Modell verarbeiten und aus denen es lernen kann. Diese Erklärung erläutert Token-Embeddings, ihre Initialisierung und Verwendung sowie die Rolle von Positions-Embeddings bei der Verbesserung des Verständnisses von Token-Sequenzen durch das Modell.<sup>[[1]](#references)</sup>

> [!TIP]
> Das Ziel dieser dritten Phase ist ganz einfach: **Jedem der zuvor im Vokabular enthaltenen Tokens einen Vektor mit den gewünschten Dimensionen zuzuweisen, um das Modell zu trainieren.** Jedes Wort im Vokabular wird zu einem Punkt in einem Raum mit X Dimensionen.\
> Beachte, dass die Position jedes Wortes im Raum zunächst einfach „zufällig“ initialisiert wird und diese Positionen trainierbare Parameter sind (sie werden während des Trainings verbessert).
>
> Außerdem wird während der Token-Embedding-Phase **eine weitere Embedding-Schicht erstellt**, die (in diesem Fall) die **absolute Position des Wortes im Trainingssatz** darstellt. Dadurch erhält ein Wort an verschiedenen Positionen im Satz jeweils eine andere Repräsentation (Bedeutung).

### **Was sind Token-Embeddings?**

**Token-Embeddings** sind numerische Repräsentationen von Tokens in einem kontinuierlichen Vektorraum. Jedem Token im Vokabular ist ein eindeutiger Vektor mit festen Dimensionen zugeordnet. Diese Vektoren erfassen semantische und syntaktische Informationen über die Tokens und ermöglichen es dem Modell, Beziehungen und Muster in den Daten zu verstehen.

- **Vokabulargröße:** Die Gesamtzahl der eindeutigen Tokens (z. B. Wörter, Teilwörter) im Vokabular des Modells.
- **Embedding-Dimensionen:** Die Anzahl numerischer Werte (Dimensionen) in jedem Token-Vektor. Höhere Dimensionen können mehr nuancierte Informationen erfassen, erfordern aber mehr Rechenressourcen.

**Beispiel:**

- **Vokabulargröße:** 6 Tokens \[1, 2, 3, 4, 5, 6]
- **Embedding-Dimensionen:** 3 (x, y, z)

### **Token-Embeddings initialisieren**

Zu Beginn des Trainings werden Token-Embeddings normalerweise mit kleinen Zufallswerten initialisiert. Diese Anfangswerte werden während des Trainings angepasst (feinabgestimmt), damit sie die Bedeutungen der Tokens auf Grundlage der Trainingsdaten besser repräsentieren.

**PyTorch-Beispiel:**

```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

**Ausgabe:**

- Jede Spalte stellt eine Dimension im Embedding-Vektor dar.
- Zum Beispiel hat das Token am Index `3` den Embedding-Vektor `[-0.4015, 0.9666, -1.1481]`.

- Das Token am Index `3` wird durch den Vektor `[-0.4015, 0.9666, -1.1481]` dargestellt.
- Diese Werte sind trainierbare Parameter, die das Modell während des Trainings anpasst, um den Kontext und die Bedeutung des Tokens besser darzustellen.

### **So funktionieren Token-Embeddings während des Trainings**

Während des Trainings wird jedes Token in den Eingabedaten in seinen entsprechenden Embedding-Vektor umgewandelt. Diese Vektoren werden dann bei verschiedenen Berechnungen innerhalb des Modells verwendet, etwa in Attention-Mechanismen und neuronalen Netzwerkschichten.

**Beispielszenario:**

- **Batch-Größe:** 8 (Anzahl der gleichzeitig verarbeiteten Samples)
- **Maximale Sequenzlänge:** 4 (Anzahl der Tokens pro Sample)
- **Embedding-Dimensionen:** 256

**Datenstruktur:**

- Jeder Batch wird als 3D-Tensor mit der Form `(batch_size, max_length, embedding_dim)` dargestellt.
- Für unser Beispiel wäre die Form `(8, 4, 256)`.

- Das Modell verarbeitet diese Einbettungen, um Sprachmuster zu erlernen und Vorhersagen zu generieren.

## **Positions-Einbettungen: Token-Einbettungen um Kontext ergänzen**

Während Token-Einbettungen die Bedeutung einzelner Tokens erfassen, kodieren sie nicht von sich aus die Position der Tokens innerhalb einer Sequenz. Die Reihenfolge der Tokens zu verstehen, ist entscheidend für das Sprachverständnis. Hier kommen **Positions-Einbettungen** ins Spiel.

### **Warum Positions-Einbettungen erforderlich sind:**

- **Die Reihenfolge der Tokens ist wichtig:** In Sätzen hängt die Bedeutung oft von der Reihenfolge der Wörter ab. Zum Beispiel: „Die Katze saß auf der Matte“ im Vergleich zu „Die Matte saß auf der Katze.“
- **Einschränkung von Einbettungen:** Ohne Positionsinformationen behandelt das Modell Tokens wie eine „Worttüte“ und ignoriert ihre Reihenfolge.

### **Arten von Positions-Einbettungen:**

1. **Absolute Positions-Einbettungen:**
   - Weisen jeder Position in der Sequenz einen eindeutigen Positionsvektor zu.
   - **Beispiel:** Der erste Token in jeder Sequenz hat dieselbe Positions-Einbettung, der zweite Token eine andere und so weiter.
   - **Verwendet von:** OpenAI-GPT-Modellen.
2. **Relative Positions-Einbettungen:**
   - Kodieren den relativen Abstand zwischen Tokens statt ihrer absoluten Positionen.
   - **Beispiel:** Geben an, wie weit zwei Tokens voneinander entfernt sind, unabhängig von ihren absoluten Positionen in der Sequenz.
   - **Verwendet von:** Modellen wie Transformer-XL und einigen Varianten von BERT.

### **Integration von Positions-Einbettungen:**

- **Gleiche Dimensionen:** Positions-Einbettungen haben dieselbe Dimensionalität wie Token-Einbettungen.
- **Addition:** Sie werden zu Token-Einbettungen addiert, um die Token-Identität mit Positionsinformationen zu kombinieren, ohne die Gesamtdimensionalität zu erhöhen.

**Beispiel für die Addition von Positions-Einbettungen:**

Angenommen, ein Token-Einbettungsvektor lautet `[0.5, -0.2, 0.1]` und sein Positions-Einbettungsvektor lautet `[0.1, 0.3, -0.1]`. Die vom Modell verwendete kombinierte Einbettung wäre:

```css
Combined Embedding = Token Embedding + Positional Embedding
                   = [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
                   = [0.6, 0.1, 0.0]
```

**Vorteile positioneller Einbettungen:**

- **Kontextuelles Bewusstsein:** Das Modell kann Tokens anhand ihrer Position unterscheiden.
- **Sequenzverständnis:** Ermöglicht dem Modell, Grammatik, Syntax und kontextabhängige Bedeutungen zu verstehen.

## **Positionelle Einbettungen in modernen LLMs**

### **Rotary Positional Embeddings (RoPE)**

RoPE kodiert die Position, indem eine positionsabhängige Rotation auf Dimensionspaare in den Query-/Key-Vektoren angewendet wird. Dadurch werden absolute Positionen in relative Phasendifferenzen umgewandelt. So werden Informationen über relative Positionen bereitgestellt, während die Dimensionalität der Einbettungen unverändert bleibt. RoPE wird häufig in neueren Decoder-only-LLMs verwendet.<sup>[[2]](#references)</sup>

Wie Token- und positionelle Einbettungen im Modell kombiniert werden, erfahren Sie auf der [LLM-Architektur-Seite](5.-llm-architecture.md).

### **Erweiterung der Kontextfenster in RoPE-basierten Modellen**

Neuere Arbeiten zeigen, dass die Kontextlänge häufig eher durch das Positionskodierungsschema als durch die Token-Einbettungsmatrix selbst begrenzt wird.

- **Position Interpolation (PI):** Skaliert Positionsindizes neu, sodass längere Sequenzen in den während des Trainings gesehenen Bereich abgebildet werden. Dadurch ist eine Erweiterung mit minimalem Fine-Tuning möglich.<sup>[[3]](#references)</sup> Beispiel:

```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```

- **YaRN:** Eine rechenzeiteffiziente RoPE-Erweiterungsstrategie, die die RoPE-Skalierung/Interpolation anpasst, um längere Kontexte mit weniger zusätzlichen Trainingsschritten zu ermöglichen.<sup>[[4]](#references)</sup>

## Codebeispiel

Das folgende Codebeispiel stammt aus [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb):<sup>[[5]](#references)</sup>

```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
    raw_text, batch_size=8, max_length=max_length,
    stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
