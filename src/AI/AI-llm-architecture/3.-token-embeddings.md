## 토큰 임베딩

텍스트 데이터를 토큰화한 후, GPT와 같은 대규모 언어 모델(LLM)을 학습하기 위해 데이터를 준비하는 다음 핵심 단계는 **토큰 임베딩**을 만드는 것입니다. 토큰 임베딩은 이산 토큰(단어 또는 부분 단어 등)을 모델이 처리하고 학습할 수 있는 연속적인 숫자 벡터로 변환합니다. 이 설명에서는 토큰 임베딩의 초기화와 사용 방법, 그리고 토큰 시퀀스에 대한 모델의 이해를 높이는 위치 임베딩의 역할을 살펴봅니다.<sup>[[1]](#references)</sup>

> [!TIP]
> 이 세 번째 단계의 목표는 매우 간단합니다. **어휘집에 있는 각 토큰에 앞서 지정한 차원의 벡터를 할당하여 모델을 학습시키는 것입니다.** 어휘집의 각 단어는 X차원 공간의 한 점이 됩니다.\
> 처음에는 공간에서 각 단어의 위치가 "무작위로" 초기화되며, 이 위치는 학습 가능한 매개변수이므로 학습 중에 개선됩니다.
>
> 또한 토큰 임베딩 과정에서 **또 다른 임베딩 계층이 생성되며**, 이 계층은 (이 경우) **학습 문장 내 단어의 절대 위치**를 나타냅니다. 따라서 문장 내 위치가 서로 다른 단어는 각기 다른 표현(의미)을 갖게 됩니다.

### **토큰 임베딩이란?**

**토큰 임베딩**은 연속적인 벡터 공간에서 토큰을 숫자로 표현한 것입니다. 어휘집의 각 토큰에는 고정된 차원의 고유 벡터가 연결됩니다. 이러한 벡터는 토큰의 의미 및 구문 정보를 포착하여 모델이 데이터의 관계와 패턴을 이해할 수 있게 합니다.

- **어휘집 크기:** 모델의 어휘집에 포함된 고유 토큰(예: 단어, 부분 단어)의 총개수.
- **임베딩 차원:** 각 토큰 벡터에 포함된 숫자 값(차원)의 개수. 차원이 높을수록 더 세밀한 정보를 포착할 수 있지만 더 많은 연산 리소스가 필요합니다.

**예시:**

- **어휘집 크기:** 토큰 6개 \[1, 2, 3, 4, 5, 6]
- **임베딩 차원:** 3 (x, y, z)

### **토큰 임베딩 초기화**

학습을 시작할 때 토큰 임베딩은 일반적으로 작은 무작위 값으로 초기화됩니다. 학습이 진행되는 동안 이 초기 값은 학습 데이터에 기반해 토큰의 의미를 더 잘 표현하도록 조정(미세 조정)됩니다.

**PyTorch 예시:**

```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

**출력:**

```lua
luaCopy codeParameter containing:
tensor([[ 0.3374, -0.1778, -0.1690],
        [ 0.9178,  1.5810,  1.3010],

        [-1.1589,  0.3255, -0.6315],
        [-2.8400, -0.7849, -1.4096]], requires_grad=True)
```

**설명:**

- 각 행은 vocabulary의 토큰 하나에 해당합니다.
- 각 열은 embedding vector의 차원 하나를 나타냅니다.
- 예를 들어, 인덱스 `3`의 토큰은 `[-0.4015, 0.9666, -1.1481]` embedding vector를 가집니다.

**토큰의 임베딩에 액세스하기:**

```python
# Retrieve the embedding for the token at index 3
token_index = torch.tensor([3])
print(embedding_layer(token_index))
```

**출력:**

```lua
tensor([[-0.4015,  0.9666, -1.1481]], grad_fn=<EmbeddingBackward0>)
```

**해석:**

- 인덱스 `3`의 토큰은 벡터 `[-0.4015, 0.9666, -1.1481]`로 표현됩니다.
- 이 값들은 학습 가능한 매개변수이며, 모델은 토큰의 문맥과 의미를 더 잘 표현하도록 학습 중에 값을 조정합니다.

### **학습 중 Token Embedding 작동 방식**

학습 중에는 입력 데이터의 각 토큰이 해당 임베딩 벡터로 변환됩니다. 그런 다음 이 벡터는 attention 메커니즘과 신경망 계층 등 모델 내부의 다양한 연산에 사용됩니다.

**예시 시나리오:**

- **Batch Size:** 8 (동시에 처리되는 샘플 수)
- **최대 Sequence Length:** 4 (샘플당 토큰 수)
- **Embedding Dimensions:** 256

**데이터 구조:**

- 각 배치는 `(batch_size, max_length, embedding_dim)` 형태의 3D 텐서로 표현됩니다.
- 이 예시에서 형태는 `(8, 4, 256)`입니다.

**시각화:**

## **위치 임베딩: 토큰 임베딩에 문맥 추가하기**

토큰 임베딩은 개별 토큰의 의미를 담지만, 시퀀스 내 토큰의 위치를 본질적으로 인코딩하지는 않습니다. 토큰의 순서를 이해하는 것은 언어 이해에 매우 중요합니다. 이때 **위치 임베딩**이 사용됩니다.

### **위치 임베딩이 필요한 이유:**

- **토큰 순서가 중요함:** 문장에서 의미는 단어의 순서에 따라 달라지는 경우가 많습니다. 예를 들어, "The cat sat on the mat"과 "The mat sat on the cat"이 그렇습니다.
- **임베딩의 한계:** 위치 정보가 없으면 모델은 토큰을 시퀀스를 무시한 "단어 모음"으로 취급합니다.

### **위치 임베딩의 유형:**

1. **절대 위치 임베딩:**
   - 시퀀스의 각 위치에 고유한 위치 벡터를 할당합니다.
   - **예시:** 어떤 시퀀스에서든 첫 번째 토큰에는 같은 위치 임베딩이 사용되고, 두 번째 토큰에는 또 다른 위치 임베딩이 사용되는 식입니다.
   - **사용 모델:** OpenAI의 GPT 모델.
2. **상대 위치 임베딩:**
   - 토큰의 절대 위치가 아니라 토큰 간 상대적인 거리를 인코딩합니다.
   - **예시:** 시퀀스 내 절대 위치와 관계없이 두 토큰이 얼마나 떨어져 있는지 나타냅니다.
   - **사용 모델:** Transformer-XL과 일부 BERT 변형 모델.

### **위치 임베딩 통합 방법:**

- **동일한 차원:** 위치 임베딩은 토큰 임베딩과 차원이 같습니다.
- **덧셈:** 토큰 임베딩에 위치 임베딩을 더해 전체 차원을 늘리지 않고 토큰의 정체성과 위치 정보를 결합합니다.

**위치 임베딩 덧셈 예시:**

토큰 임베딩 벡터가 `[0.5, -0.2, 0.1]`이고 위치 임베딩 벡터가 `[0.1, 0.3, -0.1]`이라고 가정해 보겠습니다. 모델에서 사용하는 결합 임베딩은 다음과 같습니다.

```css
Combined Embedding = Token Embedding + Positional Embedding
                   = [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
                   = [0.6, 0.1, 0.0]
```

**위치 임베딩의 이점:**

- **문맥 인식:** 모델이 토큰의 위치를 기준으로 토큰을 구분할 수 있습니다.
- **시퀀스 이해:** 모델이 문법, 구문, 문맥에 따라 달라지는 의미를 이해할 수 있습니다.

## **최신 LLM의 위치 임베딩**

### **회전 위치 임베딩(RoPE)**

RoPE는 쿼리/키 벡터의 차원 쌍에 위치에 따라 달라지는 회전을 적용해 위치를 인코딩하고, 절대 위치를 상대적인 위상 차이로 변환합니다. 이를 통해 임베딩 차원을 그대로 유지하면서 상대 위치 정보를 제공하며, 최근의 decoder-only LLM에서 널리 사용됩니다.<sup>[[2]](#references)</sup>

모델 내부에서 토큰 임베딩과 위치 임베딩을 결합하는 방식은 [LLM 아키텍처 페이지](5.-llm-architecture.md)를 참조하세요.

### **RoPE 기반 모델의 컨텍스트 윈도우 확장**

최근 연구에 따르면 컨텍스트 길이는 토큰 임베딩 행렬 자체보다는 위치 인코딩 방식에 의해 제한되는 경우가 많습니다.

- **위치 보간(PI):** 위치 인덱스를 재조정해 더 긴 시퀀스를 학습 시 본 범위에 맞추므로, 최소한의 파인튜닝으로 확장할 수 있습니다.<sup>[[3]](#references)</sup> 예:

```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```

- **YaRN:** 추가 학습 단계를 더 적게 거치면서 더 긴 컨텍스트로 외삽할 수 있도록 RoPE 스케일링/보간을 수정하는 계산 효율적인 RoPE 확장 전략입니다.<sup>[[4]](#references)</sup>

## 코드 예제

[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb)의 코드 예제를 살펴보겠습니다:<sup>[[5]](#references)</sup>

```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
    raw_text, batch_size=8, max_length=max_length,
    stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
