## Token Embeddings

在对文本数据进行 tokenization 后，为 GPT 等大型语言模型（LLM）准备训练数据的下一个关键步骤是创建 **token embeddings**。Token embeddings 将离散的 token（例如单词或子词）转换为模型可以处理和学习的连续数值向量。本说明将分解介绍 token embeddings、其初始化和使用方式，以及 positional embeddings 在增强模型对 token 序列理解方面所发挥的作用。<sup>[[1]](#references)</sup>

> [!TIP]
> 第三个阶段的目标非常简单：**为词汇表中的每个前述 token 分配一个具有所需维度的向量，以训练模型。** 词汇表中的每个单词都将成为 X 维空间中的一个点。\
> 请注意，最初每个单词在空间中的位置只是被“随机”初始化的，而这些位置属于可训练参数（会在训练过程中得到改进）。
>
> 此外，在 token embedding 过程中，**还会创建另一层 embeddings**，用于表示（在本例中）**单词在训练句子中的绝对位置**。这样，同一个单词在句子中的不同位置就会具有不同的表示（含义）。

### **什么是 Token Embeddings？**

**Token Embeddings** 是 token 在连续向量空间中的数值表示。词汇表中的每个 token 都与一个具有固定维度的唯一向量相关联。这些向量捕捉 token 的语义和句法信息，使模型能够理解数据中的关系和模式。

- **词汇表大小：** 模型词汇表中唯一 token 的总数（例如单词、子词）。
- **Embedding 维度：** 每个 token 向量中数值的数量（维度）。更高的维度可以捕捉更细致的信息，但需要更多计算资源。

**示例：**

- **词汇表大小：** 6 个 token \[1, 2, 3, 4, 5, 6]
- **Embedding 维度：** 3（x、y、z）

### **初始化 Token Embeddings**

在训练开始时，token embeddings 通常使用较小的随机值进行初始化。在训练过程中，这些初始值会被调整（微调），从而根据训练数据更好地表示 token 的含义。

**PyTorch 示例：**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **Token Embeddings 在训练期间的工作方式**

在训练期间，输入数据中的每个 token 都会被转换为对应的 embedding 向量。随后，这些向量会用于模型内部的各种计算，例如 attention 机制和神经网络层。

**示例场景：**

- **Batch Size：** 8（同时处理的样本数量）
- **Max Sequence Length：** 4（每个样本中的 token 数量）
- **Embedding Dimensions：** 256

**数据结构：**

- 每个 batch 都表示为一个形状为 `(batch_size, max_length, embedding_dim)` 的 3D tensor。
- 在本例中，形状为 `(8, 4, 256)`。

## **位置 Embeddings：为 Token Embeddings 添加上下文**

虽然 token embeddings 能够捕获单个 token 的含义，但它们本身并不会编码 token 在序列中的位置。理解 token 的顺序对于语言理解至关重要。这就是 **位置 embeddings** 发挥作用的地方。

### **为什么需要位置 Embeddings：**

- **Token 顺序很重要：** 在句子中，含义通常取决于单词的顺序。例如，"The cat sat on the mat" 与 "The mat sat on the cat."
- **Embedding 的局限性：** 没有位置信息时，模型会将 token 视为一个“词袋”，忽略它们的序列。

### **位置 Embeddings 的类型：**

1. **绝对位置 Embeddings：**
- 为序列中的每个位置分配一个唯一的位置向量。
- **示例：** 任意序列中的第一个 token 都具有相同的位置 embedding，第二个 token 具有另一个位置 embedding，依此类推。
- **使用者：** OpenAI 的 GPT models。
2. **相对位置 Embeddings：**
- 对 token 之间的相对距离进行编码，而不是编码它们的绝对位置。
- **示例：** 指示两个 token 相距多远，而不考虑它们在序列中的绝对位置。
- **使用者：** Transformer-XL 等 models，以及 BERT 的一些变体。

### **位置 Embeddings 如何集成：**

- **维度相同：** 位置 embeddings 与 token embeddings 具有相同的维度。
- **相加：** 它们会与 token embeddings 相加，将 token 身份信息与位置信息结合起来，同时不会增加整体维度。

**添加位置 Embeddings 的示例：**

假设一个 token embedding 向量为 `[0.5, -0.2, 0.1]`，其位置 embedding 向量为 `[0.1, 0.3, -0.1]`。模型使用的组合 embedding 将是：
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**位置嵌入的优势：**

- **上下文感知：** 模型可以根据 token 的位置区分不同的 token。
- **序列理解：** 使模型能够理解语法、句法和依赖上下文的含义。

## **现代 LLM 中的位置嵌入**

### **旋转位置嵌入（RoPE）**

RoPE 通过对 query/key 向量中的成对维度应用依赖位置的旋转来编码位置，将绝对位置转换为相对相位差。这样既能提供相对位置信息，又能保持 embedding 维度不变，因此被广泛用于近期的 decoder-only LLM 中。<sup>[[2]](#references)</sup>

有关 token 和位置嵌入如何在模型内部组合，请参阅 [LLM 架构页面](5.-llm-architecture.md)。

### **扩展基于 RoPE 的模型的上下文窗口**

近期研究表明，上下文长度通常受位置编码方案限制，而不是 token embedding 矩阵本身限制。

- **位置插值（PI）：** 重新缩放位置索引，使更长的序列映射到训练期间见过的范围内，从而只需极少的 fine-tuning 即可扩展上下文长度。<sup>[[3]](#references)</sup> 示例：
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN：**一种计算高效的 RoPE 扩展策略，通过修改 RoPE 的缩放/插值方式，在仅需较少额外训练步骤的情况下外推到更长的上下文。<sup>[[4]](#references)</sup>

## 代码示例

以下代码示例来自 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb)：<sup>[[5]](#references)</sup>
```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
