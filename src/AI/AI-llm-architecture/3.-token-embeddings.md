## Token Embeddings

テキストデータをtokenizeした後、GPTのような大規模言語モデル（LLM）のtraining用データを準備する次の重要なステップは、**token embeddings**の作成です。Token embeddingsは、離散的なtoken（単語やsubwordなど）を、モデルが処理および学習できる連続的な数値ベクトルへ変換します。ここでは、token embeddings、その初期化と使用方法、およびtoken sequenceに対するモデルの理解を高めるposition embeddingsの役割について説明します。<sup>[[1]](#references)</sup>

> [!TIP]
> この第3段階の目的は非常に単純です。**vocabulary内の各previous tokenに、モデルのtrainingに使用する指定された次元数のベクトルを割り当てます。** vocabulary内の各単語は、X次元空間上の1点になります。\
> 初期状態では、空間内の各単語の位置は「random」に初期化されるだけであり、これらの位置はtrainable parametersです（training中に改善されます）。
>
> さらに、token embeddingの際には、（この場合）training sentence内における**単語のabsolute position**を表す**別のembedding layerが作成されます**。これにより、sentence内の異なる位置にある単語は、異なるrepresentation（意味）を持つことになります。

### **Token Embeddingsとは？**

**Token Embeddings**は、連続的なベクトル空間におけるtokenの数値表現です。vocabulary内の各tokenには、固定された次元数の一意のベクトルが関連付けられます。これらのベクトルはtokenに関するsemanticおよびsyntactic情報を捉え、モデルがデータ内の関係性やpatternを理解できるようにします。

- **Vocabulary Size:** モデルのvocabularyに含まれる一意のtoken（単語、subwordなど）の総数。
- **Embedding Dimensions:** 各tokenのベクトルに含まれる数値の数（次元数）。次元数が多いほど、より微妙な情報を捉えられますが、より多くの計算リソースが必要になります。

**例:**

- **Vocabulary Size:** 6 tokens \[1, 2, 3, 4, 5, 6]
- **Embedding Dimensions:** 3 (x, y, z)

### **Token Embeddingsの初期化**

trainingの開始時、token embeddingsは通常、小さなrandom値で初期化されます。これらの初期値は、training dataに基づいてtokenの意味をより適切に表現できるよう、training中に調整（fine-tuning）されます。

**PyTorch Example:**
```python
import torch

# Set a random seed for reproducibility
torch.manual_seed(123)

# Create an embedding layer with 6 tokens and 3 dimensions
embedding_layer = torch.nn.Embedding(6, 3)

# Display the initial weights (embeddings)
print(embedding_layer.weight)
```

### **トレーニング中の Token Embeddings の仕組み**

トレーニング中、入力データ内の各 token は、対応する embedding vector に変換されます。これらのベクトルは、attention mechanisms や neural network layers など、モデル内部のさまざまな計算で使用されます。

**例:**

- **Batch Size:** 8（同時に処理されるサンプル数）
- **Max Sequence Length:** 4（サンプルあたりの token 数）
- **Embedding Dimensions:** 256

**データ構造:**

- 各 batch は、`(batch_size, max_length, embedding_dim)` の shape を持つ 3D tensor で表されます。
- この例では、shape は `(8, 4, 256)` になります。

## **Positional Embeddings: Token Embeddings へのコンテキストの追加**

Token embeddings は個々の token の意味を捉えますが、シーケンス内における token の位置を本質的にエンコードするわけではありません。token の順序を理解することは、言語を理解するうえで重要です。ここで **positional embeddings** が役立ちます。

### **Positional Embeddings が必要な理由:**

- **Token の順序は重要:** 文では、意味が単語の順序に依存することがよくあります。たとえば、"The cat sat on the mat" と "The mat sat on the cat." では意味が異なります。
- **Embedding の制限:** 位置情報がなければ、モデルは token を「bag of words」として扱い、シーケンスを無視します。

### **Positional Embeddings の種類:**

1. **Absolute Positional Embeddings:**
- シーケンス内の各位置に固有の position vector を割り当てます。
- **例:** どのシーケンスでも、最初の token には同じ positional embedding が割り当てられ、2 番目の token には別の positional embedding が割り当てられます。
- **使用例:** OpenAI の GPT models。
2. **Relative Positional Embeddings:**
- token の絶対位置ではなく、token 間の相対的な距離をエンコードします。
- **例:** シーケンス内の絶対位置に関係なく、2 つの token がどれだけ離れているかを示します。
- **使用例:** Transformer-XL や一部の BERT variants などの models。

### **Positional Embeddings の統合方法:**

- **同じ次元数:** Positional embeddings は token embeddings と同じ dimensionality を持ちます。
- **加算:** token の identity と位置情報を組み合わせるために token embeddings に加算されます。これにより、全体の dimensionality は増加しません。

**Positional Embeddings の加算例:**

token embedding vector が `[0.5, -0.2, 0.1]` で、その positional embedding vector が `[0.1, 0.3, -0.1]` だとします。モデルが使用する combined embedding は次のようになります。
```css
Combined Embedding = Token Embedding + Positional Embedding
= [0.5 + 0.1, -0.2 + 0.3, 0.1 + (-0.1)]
= [0.6, 0.1, 0.0]
```
**位置埋め込みの利点:**

- **文脈認識:** モデルは位置に基づいてトークンを区別できます。
- **シーケンス理解:** モデルが文法、構文、文脈依存の意味を理解できるようにします。

## **現代のLLMにおける位置埋め込み**

### **Rotary Positional Embeddings (RoPE)**

RoPEは、query/keyベクトル内の次元のペアに位置依存の回転を適用することで位置を符号化し、絶対位置を相対的な位相差に変換します。これにより、embeddingの次元数を維持したまま相対位置情報を提供でき、近年のdecoder-only LLMで広く使用されています。<sup>[[2]](#references)</sup>

モデル内部でtoken embeddingと位置embeddingがどのように結合されるかについては、[LLM architectureのページ](5.-llm-architecture.md)を参照してください。

### **RoPEベースのモデルにおけるContext Windowの拡張**

近年の研究では、context lengthはtoken embedding matrix自体よりも、位置encoding schemeによって制限されることが多いことが示されています。

- **Position Interpolation (PI):** 位置インデックスを再スケーリングし、より長いシーケンスを学習時に見た範囲内にマッピングすることで、最小限のfine-tuningで拡張を可能にします。<sup>[[3]](#references)</sup> 例：
```python
# Position Interpolation (PI) intuition
orig_ctx = 2048
new_ctx = 8192
scaled_pos = pos * (orig_ctx / new_ctx)
```
- **YaRN:** RoPE の scaling/interpolation を変更し、追加の学習ステップを少なくして、より長いコンテキストへ外挿できるようにする、compute-efficient な RoPE 拡張戦略。<sup>[[4]](#references)</sup>

## コード例

[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch02/01_main-chapter-code/ch02.ipynb) のコード例を見ていきます。<sup>[[5]](#references)</sup>
```python
# Use previous code...

# Create token embeddings
"""
BPE uses a vocabulary of 50257 words
Let's supose we want to use 256 dimensions (instead of the millions used by LLMs)
"""

vocab_size = 50257
output_dim = 256
token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)

## Generate the dataloader like before
max_length = 4
dataloader = create_dataloader_v1(
raw_text, batch_size=8, max_length=max_length,
stride=max_length, shuffle=False
)
data_iter = iter(dataloader)
inputs, targets = next(data_iter)

# Apply embeddings
token_embeddings = token_embedding_layer(inputs)
print(token_embeddings.shape)
torch.Size([8, 4, 256]) # 8 x 4 x 256

# Generate absolute embeddings
context_length = max_length
pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

pos_embeddings = pos_embedding_layer(torch.arange(max_length))

input_embeddings = token_embeddings + pos_embeddings
print(input_embeddings.shape) # torch.Size([8, 4, 256])
```
