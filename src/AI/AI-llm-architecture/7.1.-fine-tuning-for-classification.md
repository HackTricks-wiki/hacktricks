# 7.1. Classification の Fine-Tuning

{{#include ../../banners/hacktricks-training.md}}

## 概要

Fine-tuning とは、膨大なデータから**一般的な言語パターン**を学習した**pre-trained model**を取得し、**特定のタスク**を実行したり、ドメイン固有の言語を理解したりできるように**適応**させるプロセスです。これは、より小規模なタスク固有のデータセットでモデルのトレーニングを継続し、新しいデータの特性により適合するようパラメータを調整することで実現します。その際、モデルがすでに獲得している幅広い知識を活用できます。Fine-tuning により、新しいモデルをゼロからトレーニングすることなく、専門的なアプリケーションでより正確かつ関連性の高い結果を提供できるようになります。

> [!TIP]
> テキストを「理解」する LLM の pre-training は非常にコストが高いため、通常は、目的の特定のタスクを実行できるように、open source の pre-trained model を fine-tune する方が簡単で安価です。

> [!TIP]
> このセクションの目的は、すでに pre-trained model であるモデルを fine-tune し、新しいテキストを生成する代わりに、LLM が**与えられたテキストが各カテゴリーに分類される確率**を示すようにする方法を説明することです（テキストが spam かどうかなど）。

## データセットの準備

### データセットのサイズ

当然ながら、モデルを fine-tune するには、LLM を特化させるための構造化データが必要です。[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb)で提案されている例では、[https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._ のデータを使用して、GPT2 をメールが spam かどうか検出できるよう fine-tune します。

このデータセットには、spam である例よりも「spam ではない」例の方がはるかに多く含まれています。そのため、本では**「spam ではない」例を「spam」例と同じ数だけ使用する**ことを提案しています（つまり、余分な例をすべて training data から削除します）。この場合、それぞれ 747 例でした。<sup>[[1]](#references)</sup>

次に、データセットの**70%**を**training**、**10%**を**validation**、**20%**を**testing**に使用します。

- **validation set**は training phase 中に使用され、モデルの**hyperparameters**を fine-tune し、モデルアーキテクチャに関する判断を行います。これにより、モデルが未知のデータに対してどのように動作するかについてフィードバックが得られ、overfitting の防止に役立ちます。また、最終評価にバイアスをかけることなく、反復的な改善が可能になります。
- つまり、このデータセットに含まれるデータは training に直接使用されませんが、最適な**hyperparameters**の調整には使用されます。そのため、このセットは testing set のようにモデルの性能評価に使用することはできません。
- これに対して、**test set**は、モデルの training が完全に終了し、すべての調整が完了した**後にのみ**使用されます。これは、新しく未知のデータに対するモデルの汎化能力をバイアスなく評価するものです。test set に対するこの最終評価により、実際のアプリケーションでモデルがどの程度の性能を発揮すると予想されるかを現実的に確認できます。

### エントリの長さ

training example では同じ長さのエントリ（この場合はメールのテキスト）が必要となるため、`<|endoftext|>` の id を padding として追加し、すべてのエントリを最大のエントリと同じ長さにすることにしました。<sup>[[1]](#references)</sup>

### モデルの初期化

open source の pre-trained weights を使用して、training 対象のモデルを初期化します。これは以前にも行っており、[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb)の手順に従えば簡単に実行できます。

## Classification head

この具体例（テキストが spam かどうかの予測）では、GPT2 の完全な vocabulary に基づいて fine-tune することには関心がなく、新しいモデルにメールが spam（1）か、そうでない（0）かだけを判定させたいと考えています。そのため、vocabulary の各 token に対する確率を出力する**最終層を変更し**、spam である確率または spam ではない確率だけを出力する層に置き換えます（つまり、2 単語の vocabulary のようなものです）。<sup>[[1]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## 調整するパラメータ

高速に fine tune するには、すべてのパラメータを fine tune するのではなく、最後の一部のパラメータだけを対象にするほうが簡単です。これは、下位層が一般的に、適用可能な基本的な言語構造と意味論を捉えていることが知られているためです。そのため、**最後の層だけを fine tune するだけで、通常は十分かつ高速です**。<sup>[[1]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## トレーニングに使用するエントリ

前のセクションでは、モデルが言語をより適切に理解できるように、予測されたほぼすべての token が入力文に含まれていたにもかかわらず（最後の 1 つだけが実際に予測された）、予測されたすべての token の loss を減らすことで LLM をトレーニングしました。

今回は、モデルが入力が spam かどうかを予測できることだけが重要であるため、最後に予測された token のみを考慮します。したがって、前の training loss functions を、その token のみを考慮するように変更する必要があります。<sup>[[1]](#references)</sup>

これは [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) で次のように実装されています:
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
各バッチでは、**最後に予測された token の logits のみ**に関心があることに注意してください。
