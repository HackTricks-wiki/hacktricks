# 7.1. 用于分类的 Fine-Tuning

{{#include ../../banners/hacktricks-training.md}}

## 什么是 Fine-Tuning？

Fine-tuning 是指将一个通过海量数据学习了**通用语言模式**的**预训练模型**，调整为执行**特定任务**或理解特定领域语言的过程。其实现方式是继续使用规模较小、面向特定任务的数据集训练模型，使其调整参数，从而更好地适应新数据的细微特征，同时利用它已经获得的广泛知识。Fine-tuning 使模型能够在专业应用中提供更准确、更相关的结果，而无需从头开始训练新模型。

> [!TIP]
> 预训练 LLM 的成本很高，因此对于特定任务，Fine-tuning 开源预训练模型通常更简单、更便宜。

> [!TIP]
> 本节介绍如何对预训练模型进行 Fine-tuning 以完成分类。模型不会生成新文本，而是返回**已配置类别的 logits**，例如 spam 和非 spam。<sup>[[1]](#references)[[2]](#references)</sup>

## 准备数据集

### 数据集大小

当然，要对模型进行 Fine-tuning，你需要一些结构化数据，用于使 LLM 专门适应该任务。在 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) 中提出的示例里，GPT2 使用来自 [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip) 的数据进行 Fine-tuning，以检测电子邮件是否为 spam_._<sup>[[2]](#references)[[3]](#references)</sup>

该数据集包含的“非 spam”示例远多于“spam”示例。该示例通过保留每个类别相同数量的示例来平衡类别：每个类别各 747 个示例。<sup>[[1]](#references)[[2]](#references)</sup>

随后，该示例将平衡后的数据集中的 **70%** 用于**训练**，**10%** 用于**验证**，**20%** 用于**测试**。<sup>[[2]](#references)</sup>

- **验证集**在训练阶段使用，用于调整模型的**超参数**并对模型架构做出决策；它通过提供模型在未见数据上的表现反馈，有效帮助防止过拟合。验证集允许进行迭代改进，而不会使最终评估产生偏差。
- 这意味着，尽管该数据集中的数据不会直接用于训练，但会用于调整最佳的**超参数**，因此不能像测试集一样使用该数据集评估模型性能。
- 相比之下，**测试集**仅在模型完成全部训练且所有调整结束后使用；它能够无偏地评估模型对新的、未见数据的泛化能力。通过测试集进行的最终评估，可以真实反映模型在实际应用中的预期表现。

### 条目长度

由于训练示例要求条目（本例中为电子邮件文本）具有相同长度，因此决定通过添加 `<|endoftext|>` 的 id 作为 padding，将每个条目扩展到与最长条目相同的大小。<sup>[[2]](#references)</sup>

### 初始化模型

按照所引用的 notebook，使用开源预训练权重初始化模型。<sup>[[2]](#references)</sup>

## 分类头

对于二元 spam 分类，模型不再需要词汇表大小的输出 logits。将最终输出头替换为一个线性层，使其输出两个类别的 logits：非 spam（`0`）和 spam（`1`）。<sup>[[2]](#references)</sup>
```python
# Replace the final layer with a linear layer that has two outputs
num_classes = 2
model.out_head = torch.nn.Linear(
in_features=BASE_CONFIG["emb_dim"],
out_features=num_classes,
)
```
## 要调优的参数

为降低此示例中的训练成本，冻结大部分模型参数，仅对最后一个 transformer block、最终归一化层和新初始化的输出头进行 fine-tune。这样可以复用前层学习到的通用表示，并大幅减少可训练参数的数量；解冻更多层可以在更高的计算成本和过拟合代价下，实现更强的任务适应能力。<sup>[[1]](#references)[[2]](#references)</sup>
```python
# Freeze all existing model parameters
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():
param.requires_grad = True
```
## 用于训练的条目

在前面的章节中，语言模型预训练会计算整个序列上的下一个 token 损失，使模型能够学习语言结构。

对于序列分类，该示例使用模型在最后一个输入位置的输出作为表示，并将其传入分类头。损失会将这两个类别的 logits 与消息标签进行比较；它并不是在预测最后一个 token 本身是否为 spam。<sup>[[2]](#references)</sup>

该过程在 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) 中实现为：<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
对于每个 batch，仅使用最终输入位置的 **class logits**。
