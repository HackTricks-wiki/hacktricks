## Ni nini

Fine-tuning ni mchakato wa kuchukua **pre-trained model** ambayo imejifunza **mifumo ya jumla ya lugha** kutoka kwa kiasi kikubwa cha data na **kuibadilisha** ili itekeleze **kazi maalum** au kuelewa lugha ya kikoa maalum. Hili hufanikishwa kwa kuendelea kuifundisha model kwa kutumia dataset ndogo maalum kwa kazi hiyo, na kuiruhusu kurekebisha parameters zake ili iendane vyema na nuances za data mpya huku ikitumia maarifa mapana ambayo tayari imejifunza. Fine-tuning huwezesha model kutoa matokeo sahihi na yanayohusiana zaidi katika matumizi maalum bila hitaji la kuunda model mpya kuanzia mwanzo.

> [!TIP]
> Kwa kuwa pre-training ya LLM ambayo "inaelewa" maandishi ni ghali sana, kwa kawaida ni rahisi na nafuu zaidi kufanya fine-tune ya open source pre-trained models ili itekeleze kazi maalum tunayotaka itekeleze.

> [!TIP]
> Lengo la sehemu hii ni kuonyesha jinsi ya kufanya fine-tune ya model ambayo tayari imefanyiwa pre-training ili badala ya kutengeneza maandishi mapya, LLM ichague na kutoa **probabilities za maandishi yaliyotolewa kuainishwa katika kila mojawapo ya categories zilizotolewa** (kwa mfano, ikiwa maandishi ni spam au si spam).

## Kuandaa data set

### Ukubwa wa data set

Bila shaka, ili kufanya fine-tune ya model unahitaji data iliyopangwa ya kutumia ili kuifanya LLM yako iwe maalum. Katika mfano uliopendekezwa kwenye [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), GPT2 inafanyiwa fine-tune ili kutambua ikiwa email ni spam au si spam kwa kutumia data kutoka [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup>

Data set hii ina mifano mingi zaidi ya "si spam" kuliko ya "spam", kwa hiyo kitabu kinapendekeza **kutumia mifano ya "si spam" yenye idadi sawa na ya mifano ya "spam"** (hivyo, kuondoa kwenye training data mifano yote ya ziada). Katika hali hii, hiyo ilikuwa mifano 747 ya kila aina.<sup>[[2]](#references)[[1]](#references)</sup>

Kisha, **70%** ya data set hutumika kwa **training**, **10%** kwa **validation** na **20%** kwa **testing**.

- **Validation set** hutumika wakati wa awamu ya training kufanya fine-tune ya **hyperparameters** za model na kufanya maamuzi kuhusu architecture ya model, hivyo kusaidia kuzuia overfitting kwa kutoa feedback kuhusu jinsi model inavyofanya kazi kwenye data ambayo haijaonekana. Huwezesha maboresho ya kurudia bila kuathiri tathmini ya mwisho.
- Hii inamaanisha kuwa ingawa data iliyojumuishwa kwenye data set hii haitumiki moja kwa moja kwa training, hutumika kurekebisha **hyperparameters** bora, kwa hiyo set hii haiwezi kutumika kutathmini performance ya model kama testing set.
- Kinyume chake, **test set** hutumika **baada tu ya** model kufundishwa kikamilifu na marekebisho yote kukamilika; hutoa tathmini isiyo na upendeleo ya uwezo wa model ku-generalize kwenye data mpya ambayo haijaonekana. Tathmini hii ya mwisho kwenye test set hutoa makadirio halisi ya jinsi model inavyotarajiwa kufanya kazi katika matumizi ya ulimwengu halisi.

## Classification head

Katika mfano huu maalum (kutabiri ikiwa maandishi ni spam au si spam), hatupendezwi na kufanya fine-tune kulingana na vocabulary kamili ya GPT2, bali tunataka model mpya iseme tu ikiwa email ni spam (1) au si spam (0). Kwa hiyo, tutaenda **kurekebisha layer ya mwisho ambayo** hutoa probabilities kwa kila token ya vocabulary na kuibadilisha iwe inayotoa probabilities za kuwa spam au si spam pekee (kama vocabulary yenye maneno 2).<sup>[[2]](#references)</sup>

## Parameters za kutune

Ili kufanya fine tuning kwa haraka, ni rahisi kutofanya fine tuning ya parameters zote, bali baadhi ya parameters za mwisho pekee. Hii ni kwa sababu inajulikana kuwa layers za chini kwa ujumla hunasa miundo na semantics za msingi za lugha zinazoweza kutumika. Kwa hiyo, **kufanya fine tuning ya layers za mwisho pekee kwa kawaida hutosha na huwa haraka zaidi**.<sup>[[2]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Entries to use for training

Katika sehemu zilizotangulia, LLM ilifunzwa kwa kupunguza loss ya kila token iliyotabiriwa, ingawa karibu token zote zilizotabiriwa zilikuwa katika sentensi ya ingizo (ni token 1 tu mwishoni ndiyo iliyotabiriwa kwa kweli), ili model ielewe lugha vizuri zaidi.

Katika hali hii, tunachojali ni uwezo wa model kutabiri ikiwa model ni spam au la, kwa hiyo tunajali tu token ya mwisho iliyotabiriwa. Kwa hivyo, inahitajika kurekebisha loss functions zetu za awali za training ili zizingatie token hiyo pekee.

Hili limewekwa katika [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) kama:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Kumbuka kwamba kwa kila batch tunavutiwa tu na **logits za token ya mwisho iliyotabiriwa**.
