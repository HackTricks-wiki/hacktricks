# 7.1. Fine-Tuning vir Klassifikasie

{{#include ../../banners/hacktricks-training.md}}

## Wat is

Fine-tuning is die proses om ’n **voorafopgeleide model** wat **algemene taalpatrone** uit groot hoeveelhede data geleer het, te neem en dit aan te pas om ’n **spesifieke taak** uit te voer of domeinspesifieke taal te verstaan. Dit word bereik deur die model se training voort te sit op ’n kleiner, taakspesifieke datastel, sodat dit sy parameters kan aanpas om beter by die nuanses van die nuwe data te pas, terwyl dit die breë kennis benut wat dit reeds verwerf het. Fine-tuning stel die model in staat om akkurater en meer relevante resultate in gespesialiseerde toepassings te lewer sonder dat ’n nuwe model van nuuts af af opgelei hoef te word.

> [!TIP]
> Omdat dit redelik duur is om ’n LLM wat die teks “verstaan” vooraf op te lei, is dit gewoonlik makliker en goedkoper om open source voorafopgeleide modelle te fine-tune om ’n spesifieke taak uit te voer wat ons wil hê dit moet uitvoer.

> [!TIP]
> Die doel van hierdie afdeling is om te wys hoe om ’n reeds voorafopgeleide model te fine-tune sodat die LLM, in plaas daarvan om nuwe teks te genereer, die **waarskynlikhede sal gee van die gegewe teks se kategorisering in elk van die gegewe kategorieë** (byvoorbeeld of ’n teks spam is of nie).

## Voorbereiding van die datastel

### Datastelgrootte

Natuurlik het jy, om ’n model te fine-tune, gestruktureerde data nodig om jou LLM te spesialiseer. In die voorbeeld wat voorgestel word by [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), word GPT2 gefine-tune om op te spoor of ’n e-pos spam is of nie, met behulp van die data van [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup>

Hierdie datastel bevat baie meer voorbeelde van “nie spam nie” as van “spam”; daarom stel die boek voor dat **slegs soveel voorbeelde van “nie spam nie” as van “spam” gebruik word** (dus word al die ekstra voorbeelde uit die trainingdata verwyder). In hierdie geval was dit 747 voorbeelde van elk.<sup>[[2]](#references)[[1]](#references)</sup>

Daarna word **70%** van die datastel vir **training**, **10%** vir **validasie** en **20%** vir **testing** gebruik.

- Die **validasiestel** word gedurende die trainingfase gebruik om die model se **hiperparameters** te fine-tune en besluite oor modelargitektuur te neem; dit help effektief om overfitting te voorkom deur terugvoer te gee oor hoe die model op ongesiene data presteer. Dit maak iteratiewe verbeterings moontlik sonder om die finale evaluering te beïnvloed.
- Dit beteken dat hoewel die data in hierdie datastel nie direk vir die training gebruik word nie, dit gebruik word om die beste **hiperparameters** te bepaal; hierdie stel kan dus nie gebruik word om die model se werkverrigting te evalueer soos die testingstel nie.
- In teenstelling hiermee word die **teststel** **slegs nadat** die model volledig opgelei is en alle aanpassings voltooi is, gebruik; dit verskaf ’n onbevooroordeelde beoordeling van die model se vermoë om na nuwe, ongesiene data te generaliseer. Hierdie finale evaluering op die teststel gee ’n realistiese aanduiding van hoe die model na verwagting in werklike toepassings sal presteer.

## Klassifikasie-head

In hierdie spesifieke voorbeeld (om te voorspel of ’n teks spam is of nie), stel ons nie daarin belang om volgens GPT2 se volledige woordeskat te fine-tune nie; ons wil slegs hê die nuwe model moet sê of die e-pos spam (1) of nie (0) is. Daarom gaan ons die **finale laag wat** die waarskynlikhede per token van die woordeskat gee, **wysig** na een wat slegs die waarskynlikhede gee dat dit spam is of nie (dus soos ’n woordeskat van 2 woorde).<sup>[[2]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## Parameters om te fine-tune

Om vinnig te fine-tune, is dit makliker om nie al die parameters te fine-tune nie, maar slegs sommige van die laaste parameters. Dit is omdat dit bekend is dat die laer lae gewoonlik basiese taalstrukture en semantiek vaslê wat toepaslik is. Daarom is dit gewoonlik genoeg en vinniger om **slegs die laaste lae te fine-tune**.<sup>[[2]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Inskrywings om vir opleiding te gebruik

In vorige afdelings is die LLM opgelei deur die verlies van elke voorspelde token te verminder, alhoewel byna al die voorspelde tokens in die invoersin was (slegs 1 aan die einde is werklik voorspel), sodat die model die taal beter kon verstaan.

In hierdie geval gee ons slegs om of die model kan voorspel of die model spam is of nie, dus gee ons slegs om oor die laaste voorspelde token. Daarom moet ons ons vorige opleidingsverliesfunksies wysig om slegs daardie token in ag te neem.

Dit word in [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) geïmplementeer as:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Let daarop dat ons vir elke batch slegs belangstel in die **logits van die laaste voorspelde token**.
