## Ni nini

Fine-tuning ni mchakato wa kuchukua **pre-trained model** ambayo imejifunza **mifumo ya jumla ya lugha** kutoka kwa kiasi kikubwa cha data na **kuibadilisha** ili itekeleze **kazi mahususi** au ielewe lugha ya kikoa mahususi. Hili hufanikishwa kwa kuendelea kuifundisha model kwenye dataset ndogo mahususi kwa kazi hiyo, na kuiwezesha kurekebisha vigezo vyake ili iendane vyema na nuances za data mpya huku ikitumia maarifa mapana ambayo tayari imeyapata. Fine-tuning huwezesha model kutoa matokeo sahihi na yanayohusiana zaidi katika matumizi maalum bila kuhitaji kufundisha model mpya kuanzia mwanzo.

> [!TIP]
> Kwa kuwa ku-pre-train LLM ambayo "inaelewa" maandishi ni ghali sana, kwa kawaida ni rahisi na nafuu zaidi kufanya fine-tune kwa open source pre-trained models ili zitekeleze kazi mahususi tunayotaka zitekeleze.

> [!TIP]
> Lengo la sehemu hii ni kuonyesha jinsi ya kufanya fine-tune kwa model ambayo tayari imefanyiwa pre-training ili badala ya kuzalisha maandishi mapya, LLM itoe **probabilities za maandishi yaliyotolewa kuainishwa katika kila mojawapo ya kategoria zilizotolewa** (kama maandishi ni spam au la).

## Kuandaa seti ya data

### Ukubwa wa seti ya data

Bila shaka, ili kufanya fine-tune kwa model unahitaji data iliyopangwa ya kutumia ili kuibobeza LLM yako. Katika mfano uliopendekezwa kwenye [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), GPT2 imefanyiwa fine-tune ili kutambua kama barua pepe ni spam au la kwa kutumia data kutoka [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._

Seti hii ya data ina mifano mingi zaidi ya "si spam" kuliko ya "spam", kwa hiyo kitabu kinapendekeza **kutumia mifano mingi tu ya "si spam" kama ilivyo ya "spam"** (hivyo, kuondoa mifano yote ya ziada kutoka kwenye data ya training). Katika hali hii, ilikuwa mifano 747 ya kila aina.<sup>[[1]](#references)</sup>

Kisha, **70%** ya seti ya data hutumika kwa **training**, **10%** kwa **validation** na **20%** kwa **testing**.

- **Validation set** hutumika wakati wa awamu ya training kufanya fine-tune kwa **hyperparameters** za model na kufanya maamuzi kuhusu usanifu wa model, na hivyo kusaidia kuzuia overfitting kwa kutoa mrejesho kuhusu jinsi model inavyofanya kazi kwenye data ambayo haijaonekana. Huruhusu maboresho ya kurudiwa bila kuathiri tathmini ya mwisho.
- Hii inamaanisha kuwa ingawa data iliyojumuishwa kwenye seti hii ya data haitumiki moja kwa moja kwa training, hutumika kurekebisha **hyperparameters** bora, kwa hiyo seti hii haiwezi kutumika kutathmini utendaji wa model kama ilivyo kwa testing set.
- Kinyume chake, **test set** hutumika **baada tu ya** model kufundishwa kikamilifu na marekebisho yote kukamilika; hutoa tathmini isiyo na upendeleo ya uwezo wa model ku-generalize kwa data mpya ambayo haijaonekana. Tathmini hii ya mwisho kwenye test set hutoa dalili halisi ya jinsi model inavyotarajiwa kufanya kazi katika matumizi ya ulimwengu halisi.

## Classification head

Katika mfano huu mahususi (kutabiri kama maandishi ni spam au la), hatupendi kufanya fine-tune kulingana na vocabulary kamili ya GPT2, bali tunataka model mpya iseme tu kama barua pepe ni spam (1) au la (0). Kwa hiyo, tutafanya **marekebisho kwenye layer ya mwisho ambayo** hutoa probabilities kwa kila token ya vocabulary, na kuibadilisha iwe layer inayotoa probabilities za kuwa spam au la pekee (kama vocabulary yenye maneno 2).<sup>[[1]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```

## Parameters za kurekebisha

Ili kufanya fine-tune kwa haraka, ni rahisi kutofanya fine-tune kwa parameters zote, bali baadhi ya parameters za mwisho pekee. Hii ni kwa sababu inajulikana kuwa layers za chini kwa kawaida hunasa miundo ya msingi ya lugha na semantics zinazotumika kwa ujumla. Kwa hiyo, **kufanya fine-tune kwenye layers za mwisho pekee kwa kawaida hutosha na huwa haraka zaidi**.<sup>[[1]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Entries to use for training

Katika sehemu zilizotangulia, LLM ilifundishwa kwa kupunguza loss ya kila token iliyotabiriwa, ingawa karibu token zote zilizotabiriwa zilikuwa kwenye sentensi ya input (ni moja tu mwishoni ndiyo iliyotabiriwa kwa kweli), ili kuufanya model uelewe lugha vizuri zaidi.

Katika hali hii, tunajali tu uwezo wa model kutabiri ikiwa model ni spam au la, kwa hiyo tunajali tu token ya mwisho iliyotabiriwa. Kwa hivyo, tunahitaji kurekebisha functions zetu za awali za training loss ili zizingatie token hiyo pekee.<sup>[[1]](#references)</sup>

Hili limetekelezwa katika [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) kama:
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Kumbuka kwamba kwa kila batch tunavutiwa tu na **logits za token ya mwisho iliyotabiriwa**.
