# 7.1. Dostrajanie do klasyfikacji

{{#include ../../banners/hacktricks-training.md}}

## Czym jest dostrajanie?

Dostrajanie to proces polegający na wykorzystaniu **wstępnie wytrenowanego modelu**, który nauczył się **ogólnych wzorców językowych** na podstawie ogromnych ilości danych, i **dostosowaniu** go do wykonywania **konkretnego zadania** lub rozumienia języka specyficznego dla danej domeny. Osiąga się to przez kontynuowanie treningu modelu na mniejszym, przeznaczonym do konkretnego zadania zbiorze danych, co pozwala mu dostosować parametry do specyfiki nowych danych, jednocześnie wykorzystując zdobytą wcześniej szeroką wiedzę. Dostrajanie umożliwia modelowi uzyskiwanie dokładniejszych i bardziej trafnych wyników w wyspecjalizowanych zastosowaniach bez konieczności trenowania nowego modelu od podstaw.

> [!TIP]
> Wstępne trenowanie LLM jest kosztowne, dlatego zazwyczaj łatwiej i taniej jest dostroić wstępnie wytrenowany model open source do konkretnego zadania.

> [!TIP]
> Ta sekcja pokazuje, jak dostroić wstępnie wytrenowany model do klasyfikacji. Zamiast generować nowy tekst, model zwraca **logity dla skonfigurowanych kategorii**, takich jak spam i brak spamu.<sup>[[1]](#references)[[2]](#references)</sup>

## Przygotowanie zbioru danych

### Rozmiar zbioru danych

Oczywiście, aby dostroić model, potrzebujesz uporządkowanych danych, które posłużą do specjalizacji LLM. W przykładzie przedstawionym w [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) GPT2 jest dostrajany do wykrywania, czy wiadomość e-mail jest spamem, czy nie, z wykorzystaniem danych z [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup>

Ten zbiór danych zawiera znacznie więcej przykładów „braku spamu” niż przykładów „spamu”. W przykładzie wyrównano liczebność klas, zachowując taką samą liczbę przykładów z każdej klasy: po 747 przykładów.<sup>[[1]](#references)[[2]](#references)</sup>

Następnie w przykładzie wykorzystano **70%** zrównoważonego zbioru danych do **treningu**, **10%** do **walidacji** i **20%** do **testowania**.<sup>[[2]](#references)</sup>

- **Zbiór walidacyjny** jest używany podczas fazy treningu do dostrajania **hiperparametrów** modelu i podejmowania decyzji dotyczących jego architektury, skutecznie pomagając zapobiegać przeuczeniu przez dostarczanie informacji zwrotnych na temat działania modelu na niewidzianych danych. Umożliwia iteracyjne ulepszanie modelu bez obciążania końcowej oceny.
- Oznacza to, że chociaż dane zawarte w tym zbiorze nie są używane bezpośrednio do treningu, służą do dostrajania najlepszych **hiperparametrów**, więc ten zbiór nie może być używany do oceny wydajności modelu tak jak zbiór testowy.
- Z kolei **zbiór testowy** jest używany **dopiero po** pełnym wytrenowaniu modelu i zakończeniu wszystkich dostosowań; zapewnia bezstronną ocenę zdolności modelu do generalizacji na nowe, niewidziane dane. Ta końcowa ocena na zbiorze testowym realistycznie wskazuje, jak model powinien działać w rzeczywistych zastosowaniach.

### Długość wpisów

Ponieważ przykład treningowy wymaga wpisów (w tym przypadku tekstów wiadomości e-mail) o tej samej długości, zdecydowano, aby każdy wpis miał rozmiar największego wpisu przez dodanie identyfikatorów `<|endoftext|>` jako paddingu.<sup>[[2]](#references)</sup>

### Inicjalizacja modelu

Zainicjalizuj model za pomocą wstępnie wytrenowanych wag open source, zgodnie z przywołanym notebookiem.<sup>[[2]](#references)</sup>

## Głowica klasyfikacyjna

W przypadku binarnej klasyfikacji spamu model nie potrzebuje już logitów wyjściowych o rozmiarze słownika. Zastąp końcową głowicę wyjściową warstwą liniową, która generuje dwa logity klas: brak spamu (`0`) i spam (`1`).<sup>[[2]](#references)</sup>
```python
# Replace the final layer with a linear layer that has two outputs
num_classes = 2
model.out_head = torch.nn.Linear(
in_features=BASE_CONFIG["emb_dim"],
out_features=num_classes,
)
```
## Parametry do dostrojenia

Aby zmniejszyć koszt trenowania w tym przykładzie, zamroź większość parametrów modelu i dostrój wyłącznie ostatni blok transformera, końcową warstwę normalizacji oraz nowo zainicjalizowaną głowicę wyjściową. Wykorzystuje to ogólne reprezentacje wyuczone przez wcześniejsze warstwy i znacznie zmniejsza liczbę trenowalnych parametrów; odmrożenie większej liczby warstw może zapewnić lepsze dostosowanie do zadania, ale wiąże się z większym kosztem obliczeniowym i ryzykiem overfittingu.<sup>[[1]](#references)[[2]](#references)</sup>
```python
# Freeze all existing model parameters
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():
param.requires_grad = True
```
## Wpisy używane do trenowania

W poprzednich sekcjach podczas pretrainingu modelu językowego obliczano stratę dla kolejnego tokena w całej sekwencji, aby model mógł nauczyć się struktury języka.

W przypadku klasyfikacji sekwencji przykład wykorzystuje wynik modelu z końcowej pozycji wejściowej jako reprezentację przekazywaną przez głowicę klasyfikacyjną. Strata porównuje te dwa logity klas z etykietą wiadomości; model nie przewiduje, czy sam końcowy token jest spamem.<sup>[[2]](#references)</sup>

Zostało to zaimplementowane w [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) jako:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Dla każdego batcha używane są tylko **class logits na końcowej pozycji wejściowej**.
