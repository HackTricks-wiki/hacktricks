# 7.1. Fine-Tuning para clasificación

{{#include ../../banners/hacktricks-training.md}}

## ¿Qué es el Fine-Tuning?

Fine-tuning es el proceso de tomar un **modelo preentrenado** que ha aprendido **patrones generales del lenguaje** a partir de grandes cantidades de datos y **adaptarlo** para realizar una **tarea específica** o comprender lenguaje específico de un dominio. Esto se consigue continuando el entrenamiento del modelo con un conjunto de datos más pequeño y específico para la tarea, lo que permite ajustar sus parámetros para adaptarse mejor a los matices de los nuevos datos, aprovechando al mismo tiempo el amplio conocimiento que ya ha adquirido. El fine-tuning permite que el modelo proporcione resultados más precisos y relevantes en aplicaciones especializadas sin necesidad de entrenar un modelo nuevo desde cero.

> [!TIP]
> Preentrenar un LLM es costoso, por lo que normalmente es más fácil y barato hacer fine-tuning de un modelo preentrenado open source para una tarea específica.

> [!TIP]
> Esta sección muestra cómo hacer fine-tuning de un modelo preentrenado para clasificación. En lugar de generar texto nuevo, el modelo devuelve **logits para las categorías configuradas**, como spam y no spam.<sup>[[1]](#references)[[2]](#references)</sup>

## Preparación del conjunto de datos

### Tamaño del conjunto de datos

Por supuesto, para hacer fine-tuning de un modelo necesitas algunos datos estructurados que utilizar para especializar tu LLM. En el ejemplo propuesto en [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), se hace fine-tuning de GPT2 para detectar si un email es spam o no utilizando los datos de [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup>

Este conjunto de datos contiene muchos más ejemplos de "no spam" que de "spam". El ejemplo práctico equilibra las clases conservando el mismo número de elementos de cada clase: 747 ejemplos de cada una.<sup>[[1]](#references)[[2]](#references)</sup>

A continuación, el ejemplo utiliza el **70%** del conjunto de datos equilibrado para **entrenamiento**, el **10%** para **validación** y el **20%** para **pruebas**.<sup>[[2]](#references)</sup>

- El **conjunto de validación** se utiliza durante la fase de entrenamiento para ajustar los **hiperparámetros** del modelo y tomar decisiones sobre su arquitectura, ayudando eficazmente a evitar el overfitting al proporcionar feedback sobre el rendimiento del modelo con datos no vistos. Permite realizar mejoras iterativas sin sesgar la evaluación final.
- Esto significa que, aunque los datos incluidos en este conjunto de datos no se utilizan directamente para el entrenamiento, sí se utilizan para ajustar los mejores **hiperparámetros**, por lo que este conjunto no puede utilizarse para evaluar el rendimiento del modelo como se hace con el conjunto de pruebas.
- En cambio, el **conjunto de pruebas** se utiliza **solo después** de que el modelo se haya entrenado por completo y todos los ajustes se hayan completado; proporciona una evaluación imparcial de la capacidad del modelo para generalizar a datos nuevos no vistos. Esta evaluación final con el conjunto de pruebas ofrece una indicación realista de cómo se espera que funcione el modelo en aplicaciones del mundo real.

### Longitud de las entradas

Como el ejemplo de entrenamiento espera entradas (el texto de los emails en este caso) con la misma longitud, se decidió hacer que cada entrada tuviera el tamaño de la más grande añadiendo como padding los ids de `<|endoftext|>`.<sup>[[2]](#references)</sup>

Inicializa el modelo con los pesos preentrenados open source, siguiendo el notebook de referencia.<sup>[[2]](#references)</sup>

## Cabeza de clasificación

Para la clasificación binaria de spam, el modelo ya no necesita logits de salida del tamaño del vocabulario. Sustituye la cabeza de salida final por una capa lineal que emita dos logits de clase: no spam (`0`) y spam (`1`).<sup>[[2]](#references)</sup>
```python
# Replace the final layer with a linear layer that has two outputs
num_classes = 2
model.out_head = torch.nn.Linear(
in_features=BASE_CONFIG["emb_dim"],
out_features=num_classes,
)
```
## Parámetros que se deben ajustar

Para reducir el coste de entrenamiento en este ejemplo, congela la mayoría de los parámetros del modelo y realiza fine-tuning únicamente sobre el último bloque transformer, la capa de normalización final y la output head recién inicializada. Esto reutiliza las representaciones generales aprendidas por las capas anteriores y reduce considerablemente el número de parámetros entrenables; descongelar más capas puede proporcionar una mayor adaptación a la tarea, pero con un coste superior de cómputo y de overfitting.<sup>[[1]](#references)[[2]](#references)</sup>
```python
# Freeze all existing model parameters
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():
param.requires_grad = True
```
## Entradas que se usarán para el entrenamiento

En las secciones anteriores, el pretraining de language models calculaba la pérdida del siguiente token a lo largo de la secuencia para que el modelo pudiera aprender la estructura del lenguaje.

Para la clasificación de secuencias, el ejemplo utiliza la salida del modelo en la posición de entrada final como la representación que pasa por el classification head. La pérdida compara esos dos logits de clase con la etiqueta del mensaje; no predice si el token final en sí es spam.<sup>[[2]](#references)</sup>

Esto se implementa en [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) de la siguiente manera:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Para cada batch, solo se utilizan los **class logits en la posición de entrada final**.
