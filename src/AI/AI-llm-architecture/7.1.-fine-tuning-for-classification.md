# 7.1. Fine-Tuning для класифікації

{{#include ../../banners/hacktricks-training.md}}

## Що це таке

Fine-tuning — це процес, під час якого беруть **попередньо навчену модель**, яка вивчила **загальні мовні закономірності** на величезних обсягах даних, і **адаптують** її для виконання **конкретного завдання** або розуміння специфічної для певної предметної області мови. Це досягається продовженням навчання моделі на меншому наборі даних, специфічному для завдання, що дає їй змогу налаштувати свої параметри для кращої відповідності особливостям нових даних, використовуючи вже набуті широкі знання. Fine-tuning дає змогу моделі надавати точніші та релевантніші результати у спеціалізованих застосунках без необхідності навчати нову модель з нуля.

> [!TIP]
> Оскільки попереднє навчання LLM, яка «розуміє» текст, є досить дорогим, зазвичай простіше й дешевше виконати fine-tuning попередньо навчених моделей з відкритим кодом для виконання потрібного нам конкретного завдання.

> [!TIP]
> Мета цього розділу — показати, як виконати fine-tuning уже попередньо навченої моделі, щоб замість генерування нового тексту LLM визначала **ймовірності того, що заданий текст належить до кожної із заданих категорій** (наприклад, чи є текст spam).

## Підготовка набору даних

### Розмір набору даних

Звичайно, щоб виконати fine-tuning моделі, потрібні структуровані дані для спеціалізації вашої LLM. У запропонованому прикладі з [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) GPT2 налаштовується для визначення того, чи є email spam, використовуючи дані з [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup>

Цей набір даних містить набагато більше прикладів «not spam», ніж «spam», тому в книзі пропонується **використовувати лише стільки прикладів «not spam», скільки є прикладів «spam»** (тобто видалити з навчальних даних усі зайві приклади). У цьому випадку це становило по 747 прикладів кожного типу.<sup>[[2]](#references)[[1]](#references)</sup>

Потім **70%** набору даних використовується для **навчання**, **10%** — для **валідації**, а **20%** — для **тестування**.

- **Набір валідації** використовується під час етапу навчання для налаштування **гіперпараметрів** моделі та ухвалення рішень щодо її архітектури, фактично допомагаючи запобігти перенавчанню завдяки зворотному зв’язку про те, як модель працює на невидимих даних. Він дає змогу поступово вдосконалювати модель без упередження підсумкової оцінки.
- Це означає, що хоча дані з цього набору безпосередньо не використовуються для навчання, вони застосовуються для налаштування найкращих **гіперпараметрів**, тому цей набір не можна використовувати для оцінювання продуктивності моделі, як тестовий набір.
- На відміну від нього, **тестовий набір** використовується **лише після** повного навчання моделі та завершення всіх налаштувань; він забезпечує неупереджену оцінку здатності моделі узагальнювати дані на нові, невідомі приклади. Ця підсумкова оцінка на тестовому наборі дає реалістичне уявлення про очікувану продуктивність моделі в реальних застосунках.

### Довжина записів

Оскільки навчальний приклад передбачає записи (у цьому випадку текст email) однакової довжини, було вирішено зробити кожен запис таким самим великим, як і найбільший, додавши як padding ідентифікатори `<|endoftext|>`.<sup>[[2]](#references)</sup>

### Ініціалізація моделі

Використовуючи попередньо навчені ваги з відкритим кодом, ініціалізуйте модель для навчання. Ми вже робили це раніше, і, дотримуючись інструкцій з [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), ви легко зможете це виконати.<sup>[[2]](#references)</sup>

## Classification head

У цьому конкретному прикладі (визначення того, чи є текст spam) нас не цікавить fine-tuning відповідно до повного словника GPT2 — ми лише хочемо, щоб нова модель визначала, чи є email spam (1), чи ні (0). Тому ми збираємося **змінити фінальний шар, який** надає ймовірності для кожного токена словника, на шар, який надає лише ймовірності того, що текст є spam або ні (тобто для словника з 2 слів).<sup>[[2]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## Параметри для налаштування

Щоб швидко виконати донавчання, простіше донавчати не всі параметри, а лише деякі останні. Це пояснюється тим, що нижні шари зазвичай уже фіксують базові мовні структури та семантику, які можна застосовувати. Тому **донавчання лише останніх шарів зазвичай є достатнім і швидшим**.<sup>[[2]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Записи для використання в навчанні

У попередніх розділах LLM навчалася шляхом зменшення втрат для кожного передбаченого токена, хоча майже всі передбачені токени вже були вхідним реченням (лише 1 токен у кінці справді передбачався), щоб модель краще розуміла мову.

У цьому випадку нас цікавить лише здатність моделі передбачати, чи є текст spam, тому нас цікавить лише останній передбачений токен. Отже, потрібно змінити попередні функції втрат під час навчання, щоб вони враховували лише цей токен.

Це реалізовано в [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) як:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Зверніть увагу, що для кожного batch нас цікавлять лише **logits останнього передбаченого токена**.
