# 7.1. Fine-Tuning für Klassifikation

{{#include ../../banners/hacktricks-training.md}}

## Was ist das?

Fine-Tuning ist der Prozess, ein **vortrainiertes Modell**, das aus riesigen Datenmengen **allgemeine Sprachmuster** gelernt hat, zu übernehmen und es für eine **spezifische Aufgabe** anzupassen oder darauf zu trainieren, domänenspezifische Sprache zu verstehen. Dies wird erreicht, indem das Modell mit einem kleineren, aufgabenspezifischen Datensatz weitertrainiert wird. Dadurch kann es seine Parameter besser an die Feinheiten der neuen Daten anpassen und gleichzeitig das umfassende Wissen nutzen, das es bereits erworben hat. Fine-Tuning ermöglicht es dem Modell, in spezialisierten Anwendungen genauere und relevantere Ergebnisse zu liefern, ohne ein neues Modell von Grund auf trainieren zu müssen.

> [!TIP]
> Da das Vortrainieren eines LLM, das den Text „versteht“, ziemlich teuer ist, ist es normalerweise einfacher und günstiger, vortrainierte Open-Source-Modelle zu fine-tunen, damit sie eine bestimmte gewünschte Aufgabe ausführen.

> [!TIP]
> Das Ziel dieses Abschnitts ist zu zeigen, wie man ein bereits vortrainiertes Modell fine-tuned, sodass das LLM nicht neuen Text generiert, sondern die **Wahrscheinlichkeiten dafür angibt, dass der gegebene Text in jede der vorgegebenen Kategorien eingeordnet wird** (zum Beispiel, ob ein Text Spam ist oder nicht).

## Vorbereiten des Datensatzes

### Größe des Datensatzes

Um ein Modell fine-tunen zu können, benötigt man natürlich strukturierte Daten, mit denen man das LLM spezialisieren kann. Im Beispiel aus [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) wird GPT2 anhand der Daten aus [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._ darauf fine-tuned, zu erkennen, ob eine E-Mail Spam ist oder nicht.

Dieser Datensatz enthält deutlich mehr Beispiele für „kein Spam“ als für „Spam“. Daher schlägt das Buch vor, **nur so viele Beispiele für „kein Spam“ wie für „Spam“ zu verwenden** (also alle zusätzlichen Beispiele aus den Trainingsdaten zu entfernen). In diesem Fall waren es jeweils 747 Beispiele.<sup>[[1]](#references)</sup>

Anschließend werden **70 %** des Datensatzes für das **Training**, **10 %** für die **Validierung** und **20 %** für das **Testing** verwendet.

- Der **Validierungsdatensatz** wird während der Trainingsphase verwendet, um die **Hyperparameter** des Modells fine-tunen und Entscheidungen über die Modellarchitektur treffen zu können. Dadurch wird effektiv Overfitting verhindert, da Rückmeldung darüber gegeben wird, wie das Modell mit unbekannten Daten abschneidet. Er ermöglicht iterative Verbesserungen, ohne die abschließende Bewertung zu beeinflussen.
- Das bedeutet, dass die in diesem Datensatz enthaltenen Daten zwar nicht direkt für das Training verwendet werden, jedoch zum Abstimmen der besten **Hyperparameter** dienen. Daher kann dieser Datensatz nicht wie der Testing-Datensatz zur Bewertung der Leistung des Modells verwendet werden.
- Im Gegensatz dazu wird der **Testdatensatz** **erst verwendet, nachdem** das Modell vollständig trainiert und alle Anpassungen abgeschlossen wurden. Er liefert eine unverfälschte Einschätzung der Fähigkeit des Modells, auf neue, unbekannte Daten zu generalisieren. Diese abschließende Bewertung anhand des Testdatensatzes gibt einen realistischen Hinweis darauf, wie das Modell voraussichtlich in realen Anwendungen abschneiden wird.

### Länge der Einträge

Da das Trainingsbeispiel Einträge (in diesem Fall E-Mail-Texte) gleicher Länge erwartet, wurde beschlossen, jeden Eintrag durch das Hinzufügen der IDs von `<|endoftext|>` als Padding so groß wie den längsten Eintrag zu machen.<sup>[[1]](#references)</sup>

### Initialisieren des Modells

Initialisiere das zu trainierende Modell anhand der vortrainierten Open-Source-Gewichte. Wir haben dies bereits zuvor getan. Wenn du den Anweisungen aus [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) folgst, kannst du dies problemlos durchführen.

## Klassifikationskopf

In diesem speziellen Beispiel (der Vorhersage, ob ein Text Spam ist oder nicht) sind wir nicht daran interessiert, ein Fine-Tuning anhand des vollständigen Vokabulars von GPT2 durchzuführen. Stattdessen soll das neue Modell lediglich angeben, ob die E-Mail Spam (1) ist oder nicht (0). Daher werden wir **die letzte Schicht, die** die Wahrscheinlichkeiten für jedes Token des Vokabulars liefert, durch eine Schicht **ersetzen, die nur die Wahrscheinlichkeiten dafür liefert, ob es sich um Spam handelt oder nicht** (also etwa wie ein Vokabular mit 2 Wörtern).<sup>[[1]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## Zu optimierende Parameter

Um schnell zu fine-tunen, ist es einfacher, nicht alle Parameter, sondern nur einige der letzten Parameter zu fine-tunen. Der Grund dafür ist, dass die unteren Layer im Allgemeinen grundlegende Sprachstrukturen und anwendbare Semantik erfassen. Daher ist es normalerweise ausreichend und schneller, nur die letzten Layer zu **fine-tunen**.<sup>[[1]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Einträge für das Training

In den vorherigen Abschnitten wurde das LLM trainiert, indem der Loss für jedes vorhergesagte Token reduziert wurde, obwohl sich fast alle vorhergesagten Tokens im Eingabesatz befanden (nur 1 Token am Ende wurde tatsächlich vorhergesagt), damit das Modell die Sprache besser versteht.

In diesem Fall ist uns nur wichtig, dass das Modell vorhersagen kann, ob es sich um spam handelt oder nicht. Daher interessiert uns nur das zuletzt vorhergesagte Token. Deshalb müssen wir unsere bisherigen Trainings-Loss-Funktionen so anpassen, dass nur dieses Token berücksichtigt wird.<sup>[[1]](#references)</sup>

Dies ist in [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) folgendermaßen implementiert:
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Beachte, dass wir für jeden Batch nur an den **Logits des vorhergesagten letzten Tokens** interessiert sind.
