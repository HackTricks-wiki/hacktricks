# 7.1. ClassificationのFine-Tuning

{{#include ../../banners/hacktricks-training.md}}

## Fine-Tuningとは？

Fine-tuningとは、膨大なデータから**一般的な言語パターン**を学習した**pre-trained model**を取得し、**特定のタスク**を実行したり、ドメイン固有の言語を理解したりできるように**適応**させるプロセスです。これは、タスク固有の小規模なデータセットでモデルのトレーニングを継続することで実現します。これにより、すでに獲得している幅広い知識を活用しながら、新しいデータの細かな特徴により適合するようパラメータを調整できます。Fine-tuningを使用すると、モデルをゼロから新たにトレーニングする必要なく、専門的なアプリケーションでより正確かつ関連性の高い結果を提供できます。

> [!TIP]
> LLMのPre-trainingにはコストがかかるため、特定のタスク向けにオープンソースのpretrained modelをfine-tuneする方が、通常は簡単で安価です。

> [!TIP]
> このセクションでは、classification向けにpretrained modelをfine-tuneする方法を説明します。新しいテキストを生成する代わりに、モデルはspamやnot spamなど、設定されたカテゴリの**logits**を返します。<sup>[[1]](#references)[[2]](#references)</sup>

## データセットの準備

### データセットのサイズ

当然ながら、モデルをfine-tuneするには、LLMを特化させるために使用する構造化データが必要です。[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb)で提案されている例では、[https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)のデータを使用して、メールがspamかどうかを検出するようGPT2をfine-tuneしています_._<sup>[[2]](#references)[[3]](#references)</sup>

このデータセットには、"spam"の例よりもはるかに多くの"not spam"の例が含まれています。実行例では、各クラスから同じ数を保持することでクラスのバランスを調整しています。各クラスの例は747件です。<sup>[[1]](#references)[[2]](#references)</sup>

次に、このバランス調整済みデータセットの**70%**を**training**、**10%**を**validation**、**20%**を**testing**に使用します。<sup>[[2]](#references)</sup>

- **validation set**はtrainingフェーズで使用され、モデルの**hyperparameters**をfine-tuneしたり、モデルアーキテクチャについて判断したりします。これは、モデルが未知のデータに対してどのように動作するかについてフィードバックを提供することで、overfittingの防止に役立ちます。また、最終評価に偏りを生じさせずに、反復的な改善を行うことができます。
- つまり、このデータセットに含まれるデータはtrainingに直接使用されませんが、最適な**hyperparameters**の調整に使用されるため、このセットをtesting setのようにモデルの性能評価に使用することはできません。
- これに対して、**test set**はモデルが完全にtrainingされ、すべての調整が完了した**後にのみ**使用されます。test setは、未知の新しいデータに対するモデルのgeneralize能力を偏りなく評価します。test setでのこの最終評価により、実際のアプリケーションでモデルがどのように動作すると予想されるかを現実的に把握できます。

## Classification head

binary spam classificationでは、モデルはvocabularyサイズのoutput logitsを必要としなくなります。最終的なoutput headを、2つのclass logitsを出力するlinear layerに置き換えます。not spam（`0`）とspam（`1`）です。<sup>[[2]](#references)</sup>
```python
# Replace the final layer with a linear layer that has two outputs
num_classes = 2
model.out_head = torch.nn.Linear(
in_features=BASE_CONFIG["emb_dim"],
out_features=num_classes,
)
```
## チューニングするパラメータ

この例では training cost を削減するため、model parameters の大部分を freeze し、最後の Transformer block、final normalization layer、および新しく初期化した output head のみを fine-tune します。これにより、前の layers で学習された汎用的な representations を再利用でき、trainable parameters の数を大幅に削減できます。より多くの layers の freeze を解除すると、より高い compute cost と overfitting のリスクを伴う一方で、task への適応度を高められます。<sup>[[1]](#references)[[2]](#references)</sup>
```python
# Freeze all existing model parameters
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():
param.requires_grad = True
```
## 学習に使用するエントリ

前のセクションでは、language-model pretraining においてシーケンス全体で next-token loss を計算し、モデルが言語構造を学習できるようにしていました。

sequence classification では、入力の最終位置におけるモデル出力を、classification head に渡す representation として使用します。loss はその2つの class logits とメッセージラベルを比較するものであり、最終 token 自体が spam かどうかを予測するものではありません。<sup>[[2]](#references)</sup>

これは [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) で次のように実装されています。<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
各バッチでは、最終入力位置の **class logits** のみが使用されます。
