# 7.1. Fine-Tuning für Klassifizierung

{{#include ../../banners/hacktricks-training.md}}

## Was ist Fine-Tuning?

Fine-Tuning ist der Prozess, bei dem ein **vortrainiertes Modell**, das aus großen Datenmengen **allgemeine Sprachmuster** gelernt hat, übernommen und für die Ausführung einer **spezifischen Aufgabe** oder das Verständnis domänenspezifischer Sprache **angepasst** wird. Dies wird erreicht, indem das Training des Modells mit einem kleineren, aufgabenspezifischen Datensatz fortgesetzt wird. Dadurch kann es seine Parameter besser an die Besonderheiten der neuen Daten anpassen und gleichzeitig das bereits erworbene umfangreiche Wissen nutzen. Fine-Tuning ermöglicht es dem Modell, in spezialisierten Anwendungen genauere und relevantere Ergebnisse zu liefern, ohne ein neues Modell von Grund auf trainieren zu müssen.

> [!TIP]
> Das Pre-Training eines LLM ist teuer. Daher ist es normalerweise einfacher und kostengünstiger, ein vortrainiertes Open-Source-Modell für eine bestimmte Aufgabe per Fine-Tuning anzupassen.

> [!TIP]
> Dieser Abschnitt zeigt, wie ein vortrainiertes Modell für die Klassifizierung per Fine-Tuning angepasst wird. Statt neuen Text zu generieren, gibt das Modell **Logits für die konfigurierten Kategorien** zurück, beispielsweise Spam und kein Spam.<sup>[[1]](#references)[[2]](#references)</sup>

## Vorbereiten des Datensatzes

### Größe des Datensatzes

Um ein Modell per Fine-Tuning anzupassen, benötigt man natürlich strukturierte Daten, mit denen das LLM spezialisiert werden kann. Im Beispiel aus [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) wird GPT2 anhand der Daten aus [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup> per Fine-Tuning darauf angepasst, zu erkennen, ob eine E-Mail Spam ist oder nicht.

Dieser Datensatz enthält deutlich mehr Beispiele für „kein Spam“ als für „Spam“. Das ausgearbeitete Beispiel gleicht die Klassen aus, indem es aus jeder Klasse dieselbe Anzahl beibehält: jeweils 747 Beispiele.<sup>[[1]](#references)[[2]](#references)</sup>

Anschließend verwendet das Beispiel **70 %** des ausgeglichenen Datensatzes zum **Training**, **10 %** zur **Validierung** und **20 %** zum **Testen**.<sup>[[2]](#references)</sup>

- Der **Validierungsdatensatz** wird während der Trainingsphase verwendet, um die **Hyperparameter** des Modells per Fine-Tuning anzupassen und Entscheidungen über die Modellarchitektur zu treffen. Dadurch hilft er effektiv, Overfitting zu verhindern, indem er Feedback zur Leistung des Modells bei bisher unbekannten Daten liefert. Er ermöglicht iterative Verbesserungen, ohne die abschließende Bewertung zu verzerren.
- Das bedeutet, dass die in diesem Datensatz enthaltenen Daten zwar nicht direkt für das Training verwendet werden, aber zur Anpassung der besten **Hyperparameter** dienen. Daher kann dieser Datensatz nicht wie der Testdatensatz zur Bewertung der Leistung des Modells verwendet werden.
- Im Gegensatz dazu wird der **Testdatensatz** **erst verwendet, nachdem** das Modell vollständig trainiert und alle Anpassungen abgeschlossen wurden. Er liefert eine unverzerrte Bewertung der Fähigkeit des Modells, auf neue, bisher unbekannte Daten zu generalisieren. Diese abschließende Bewertung anhand des Testdatensatzes vermittelt einen realistischen Eindruck davon, wie das Modell voraussichtlich in realen Anwendungen abschneiden wird.

### Länge der Einträge

Da das Trainingsbeispiel Einträge (in diesem Fall E-Mail-Texte) gleicher Länge erwartet, wurde beschlossen, jeden Eintrag durch Hinzufügen der IDs von `<|endoftext|>` als Padding auf die Länge des längsten Eintrags zu bringen.<sup>[[2]](#references)</sup>

## Klassifizierungskopf

Für die binäre Spam-Klassifizierung benötigt das Modell keine Output-Logits mehr, deren Größe dem Vokabular entspricht. Ersetze den finalen Output-Head durch eine lineare Schicht, die zwei Klassen-Logits ausgibt: kein Spam (`0`) und Spam (`1`).<sup>[[2]](#references)</sup>
```python
# Replace the final layer with a linear layer that has two outputs
num_classes = 2
model.out_head = torch.nn.Linear(
in_features=BASE_CONFIG["emb_dim"],
out_features=num_classes,
)
```
## Zu optimierende Parameter

Um die Trainingskosten in diesem Beispiel zu reduzieren, werden die meisten Modellparameter eingefroren und nur der letzte Transformer-Block, die abschließende Normalisierungsschicht und der neu initialisierte Output-Head per Fine-Tuning angepasst. Dadurch werden die von den früheren Schichten erlernten allgemeinen Repräsentationen wiederverwendet und die Anzahl der trainierbaren Parameter wird erheblich reduziert. Das Freigeben weiterer Schichten kann eine stärkere Anpassung an die Aufgabe ermöglichen, jedoch bei höheren Rechenkosten und einem größeren Overfitting-Risiko.<sup>[[1]](#references)[[2]](#references)</sup>
```python
# Freeze all existing model parameters
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():
param.requires_grad = True
```
## Einträge für das Training

In vorherigen Abschnitten wurde beim Pretraining von language models der Next-Token-Loss über die Sequenz berechnet, damit das Modell die Sprachstruktur erlernen konnte.

Bei der sequence classification verwendet das Beispiel die Modellausgabe an der letzten Eingabeposition als Repräsentation, die durch den classification head geleitet wird. Der Loss vergleicht diese beiden class logits mit dem Nachrichtenlabel; er sagt nicht voraus, ob das letzte Token selbst Spam ist.<sup>[[2]](#references)</sup>

Dies wird in [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) folgendermaßen implementiert:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Für jedes Batch werden nur die **Klassen-Logits an der finalen Eingabeposition** verwendet.
