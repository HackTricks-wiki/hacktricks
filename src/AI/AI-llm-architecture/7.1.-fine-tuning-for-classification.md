# 7.1. Fine-Tuning para Classificação

{{#include ../../banners/hacktricks-training.md}}

## O que é

Fine-tuning é o processo de pegar um **modelo pré-treinado** que aprendeu **padrões gerais de linguagem** a partir de grandes quantidades de dados e **adaptá-lo** para executar uma **tarefa específica** ou compreender uma linguagem específica de um domínio. Isso é obtido continuando o treinamento do modelo em um conjunto de dados menor e específico da tarefa, permitindo que ele ajuste seus parâmetros para se adequar melhor às nuances dos novos dados, enquanto aproveita o amplo conhecimento que já adquiriu. O fine-tuning permite que o modelo forneça resultados mais precisos e relevantes em aplicações especializadas, sem a necessidade de treinar um novo modelo do zero.

> [!TIP]
> Como o pré-treinamento de um LLM que "entende" o texto é bastante caro, geralmente é mais fácil e barato fazer fine-tuning de modelos pré-treinados open source para executar uma tarefa específica que queremos que ele realize.

> [!TIP]
> O objetivo desta seção é mostrar como fazer fine-tuning de um modelo já pré-treinado para que, em vez de gerar novos textos, o LLM selecione e forneça as **probabilidades de o texto fornecido ser categorizado em cada uma das categorias fornecidas** (por exemplo, se um texto é spam ou não).

## Preparando o conjunto de dados

### Tamanho do conjunto de dados

É claro que, para fazer fine-tuning de um modelo, você precisa de alguns dados estruturados para usar na especialização do seu LLM. No exemplo proposto em [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), o GPT2 recebe fine-tuning para detectar se um email é spam ou não usando os dados de [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._

Esse conjunto de dados contém muito mais exemplos de "não spam" do que de "spam"; portanto, o livro sugere **usar apenas a mesma quantidade de exemplos de "não spam" e de "spam"** (removendo, assim, todos os exemplos extras dos dados de treinamento). Nesse caso, eram 747 exemplos de cada.<sup>[[1]](#references)</sup>

Em seguida, **70%** do conjunto de dados é usado para **treinamento**, **10%** para **validação** e **20%** para **teste**.

- O **conjunto de validação** é usado durante a fase de treinamento para ajustar os **hiperparâmetros** do modelo e tomar decisões sobre a arquitetura do modelo, ajudando efetivamente a evitar overfitting ao fornecer feedback sobre o desempenho do modelo em dados não vistos. Ele permite melhorias iterativas sem influenciar a avaliação final.
- Isso significa que, embora os dados incluídos nesse conjunto de dados não sejam usados diretamente no treinamento, eles são usados para ajustar os melhores **hiperparâmetros**; portanto, esse conjunto não pode ser usado para avaliar o desempenho do modelo como o conjunto de teste.
- Em contraste, o **conjunto de teste** é usado **somente após** o modelo ter sido completamente treinado e todos os ajustes terem sido concluídos; ele fornece uma avaliação imparcial da capacidade do modelo de generalizar para dados novos e não vistos. Essa avaliação final no conjunto de teste fornece uma indicação realista de como se espera que o modelo desempenhe em aplicações do mundo real.

### Comprimento das entradas

Como o exemplo de treinamento espera entradas (textos de emails, neste caso) com o mesmo comprimento, decidiu-se tornar cada entrada tão grande quanto a maior delas, adicionando os ids de `<|endoftext|>` como padding.<sup>[[1]](#references)</sup>

### Inicializar o modelo

Usando os pesos pré-treinados open source, inicialize o modelo para o treinamento. Já fizemos isso antes e, seguindo as instruções de [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), você pode fazer isso facilmente.

## Cabeçalho de classificação

Neste exemplo específico (prever se um texto é spam ou não), não estamos interessados em fazer fine-tuning de acordo com o vocabulário completo do GPT2, mas queremos apenas que o novo modelo diga se o email é spam (1) ou não (0). Portanto, vamos **modificar a camada final que** fornece as probabilidades por token do vocabulário para uma que forneça apenas as probabilidades de ser spam ou não (como se fosse um vocabulário de 2 palavras).<sup>[[1]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## Parâmetros a ajustar

Para fazer o ajuste fino rapidamente, é mais fácil não ajustar todos os parâmetros, mas apenas alguns dos últimos. Isso ocorre porque se sabe que as camadas inferiores geralmente capturam estruturas e semânticas básicas da linguagem que são aplicáveis. Portanto, **fazer o ajuste fino apenas das últimas camadas geralmente é suficiente e mais rápido**.<sup>[[1]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Entradas a usar para o treinamento

Nas seções anteriores, o LLM foi treinado reduzindo o loss de cada token previsto, embora quase todos os tokens previstos estivessem na frase de entrada (apenas 1 no final tenha sido realmente previsto), para que o modelo compreendesse melhor a linguagem.

Neste caso, só nos importa que o modelo consiga prever se a mensagem é spam ou não, portanto, só nos importa o último token previsto. Por isso, é necessário modificar nossas funções de loss do treinamento anterior para levar em conta apenas esse token.<sup>[[1]](#references)</sup>

Isso é implementado em [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) como:
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Observe que, para cada batch, estamos interessados apenas nos **logits do último token previsto**.
