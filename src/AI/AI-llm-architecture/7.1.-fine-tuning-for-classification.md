# 7.1. Classification के लिए Fine-Tuning

{{#include ../../banners/hacktricks-training.md}}

## यह क्या है

Fine-tuning, एक **pre-trained model** को लेने की प्रक्रिया है, जिसने विशाल मात्रा में data से **सामान्य language patterns** सीखे हैं, और उसे **किसी विशिष्ट task** को करने या domain-specific language समझने के लिए **अनुकूलित** करना है। यह model की training को एक छोटे, task-specific dataset पर जारी रखकर किया जाता है, जिससे वह नए data की बारीकियों के अनुसार अपने parameters को बेहतर ढंग से समायोजित कर सके और साथ ही पहले से प्राप्त व्यापक knowledge का लाभ उठा सके। Fine-tuning, नए model को शुरू से train करने की आवश्यकता के बिना, specialized applications में अधिक सटीक और relevant results देने में सक्षम बनाता है।

> [!TIP]
> किसी ऐसे LLM को pre-train करना जो text को "समझता" हो, काफी महंगा होता है। इसलिए आमतौर पर open source pre-trained models को हमारे इच्छित किसी specific task को करने के लिए fine-tune करना अधिक आसान और सस्ता होता है।

> [!TIP]
> इस section का उद्देश्य यह दिखाना है कि पहले से pre-trained model को कैसे fine-tune किया जाए, ताकि नया text generate करने के बजाय LLM यह **probabilities दे कि दिया गया text दी गई categories में से प्रत्येक में categorize होने की कितनी संभावना रखता है** (जैसे कोई text spam है या नहीं)।

## Data set तैयार करना

### Data set का आकार

बेशक, किसी model को fine-tune करने के लिए आपको अपने LLM को specialize करने हेतु कुछ structured data की आवश्यकता होती है। [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) में दिए गए example में, GPT2 को [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup> के data का उपयोग करके यह detect करने के लिए fine-tune किया गया है कि कोई email spam है या नहीं।

इस data set में "spam" की तुलना में "not spam" के कहीं अधिक examples हैं। इसलिए book में सुझाव दिया गया है कि **"not spam" के उतने ही examples का उपयोग किया जाए जितने "spam" के हैं** (अर्थात training data से सभी अतिरिक्त examples हटा दिए जाएं)। इस मामले में, प्रत्येक के 747 examples थे।<sup>[[2]](#references)[[1]](#references)</sup>

इसके बाद, data set के **70%** का उपयोग **training** के लिए, **10%** का **validation** के लिए और **20%** का **testing** के लिए किया जाता है।

- **validation set** का उपयोग training phase के दौरान model के **hyperparameters** को fine-tune करने और model architecture के बारे में decisions लेने के लिए किया जाता है। यह unseen data पर model के performance के बारे में feedback देकर overfitting को रोकने में प्रभावी रूप से सहायता करता है।
- इसका अर्थ है कि हालांकि इस data set में शामिल data का सीधे training के लिए उपयोग नहीं किया जाता, लेकिन इसका उपयोग सर्वोत्तम **hyperparameters** को tune करने के लिए किया जाता है। इसलिए इस set का उपयोग model के performance का evaluation करने के लिए testing set की तरह नहीं किया जा सकता।
- इसके विपरीत, **test set** का उपयोग **केवल तब किया जाता है जब** model पूरी तरह train हो चुका हो और सभी adjustments पूरे हो गए हों। यह नए, unseen data पर generalize करने की model की क्षमता का unbiased assessment प्रदान करता है। Test set पर किया गया यह अंतिम evaluation इस बात का realistic indication देता है कि real-world applications में model के performance की अपेक्षा कैसी की जा सकती है।

### Entries की length

चूंकि training example में entries (इस मामले में email text) समान length की अपेक्षा की जाती है, इसलिए प्रत्येक entry को सबसे बड़ी entry जितना बड़ा बनाने का निर्णय लिया गया। इसके लिए `<|endoftext|>` के ids को padding के रूप में जोड़ा गया।<sup>[[2]](#references)</sup>

### Model को initialize करना

Open-source pre-trained weights का उपयोग करके train किए जाने वाले model को initialize करें। हम यह पहले कर चुके हैं, और [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) के instructions का पालन करके आप इसे आसानी से कर सकते हैं।<sup>[[2]](#references)</sup>

## Classification head

इस specific example में (यह predict करना कि कोई text spam है या नहीं), हमें GPT2 की complete vocabulary के अनुसार fine-tune करने में रुचि नहीं है। हम केवल चाहते हैं कि नया model बताए कि email spam (1) है या नहीं (0)। इसलिए, हम **अंतिम layer को modify करने जा रहे हैं**, जो vocabulary के प्रत्येक token के लिए probabilities देती है, और उसकी जगह ऐसी layer लगाएंगे जो केवल spam होने या न होने की probabilities दे (अर्थात 2 words वाली vocabulary के समान)।<sup>[[2]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## ट्यून करने के लिए पैरामीटर

तेज़ी से fine tune करने के लिए सभी पैरामीटर को fine tune करने के बजाय केवल कुछ अंतिम पैरामीटर को fine tune करना आसान होता है। ऐसा इसलिए है क्योंकि यह ज्ञात है कि निचली layers आम तौर पर लागू होने वाली मूल भाषा संरचनाओं और semantics को capture करती हैं। इसलिए, केवल **अंतिम layers को fine tune करना आम तौर पर पर्याप्त और तेज़ होता है**।<sup>[[2]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Training के लिए उपयोग की जाने वाली Entries

पिछले sections में LLM को प्रत्येक predicted token के loss को कम करके train किया गया था, हालांकि लगभग सभी predicted tokens input sentence में ही मौजूद थे (अंत में केवल 1 token ही वास्तव में predict किया गया था), ताकि model भाषा को बेहतर ढंग से समझ सके।

इस मामले में हमें केवल इस बात की चिंता है कि model यह predict कर सके कि input spam है या नहीं, इसलिए हमें केवल अंतिम predicted token की चिंता है। इसलिए, हमारे पिछले training loss functions को इस तरह modify करना आवश्यक है कि वे केवल उस token को ध्यान में रखें।

इसे [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) में इस प्रकार implement किया गया है:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
ध्यान दें कि प्रत्येक batch के लिए हमारी रुचि केवल **पूर्वानुमानित अंतिम token के logits** में होती है।
