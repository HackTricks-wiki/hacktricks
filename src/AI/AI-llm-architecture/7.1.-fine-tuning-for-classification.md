# 7.1. Fine-Tuning per la classificazione

{{#include ../../banners/hacktricks-training.md}}

## Che cos'è

Il fine-tuning è il processo di prendere un **modello pre-addestrato** che ha appreso **pattern linguistici generali** da enormi quantità di dati e di **adattarlo** per eseguire un **compito specifico** o comprendere un linguaggio specifico del dominio. Questo risultato si ottiene continuando l'addestramento del modello su un dataset più piccolo e specifico per il compito, permettendogli di regolare i propri parametri per adattarsi meglio alle caratteristiche dei nuovi dati, sfruttando al contempo l'ampia conoscenza già acquisita. Il fine-tuning consente al modello di fornire risultati più accurati e pertinenti in applicazioni specializzate, senza dover addestrare un nuovo modello da zero.

> [!TIP]
> Poiché il pre-training di un LLM che "comprende" il testo è piuttosto costoso, di solito è più semplice ed economico eseguire il fine-tuning di modelli open source pre-addestrati per fargli svolgere un compito specifico.

> [!TIP]
> L'obiettivo di questa sezione è mostrare come eseguire il fine-tuning di un modello già pre-addestrato affinché, invece di generare nuovo testo, l'LLM selezioni e fornisca le **probabilità che il testo fornito appartenga a ciascuna delle categorie indicate** (ad esempio, se un testo è spam oppure no).

## Preparazione del dataset

### Dimensione del dataset

Naturalmente, per eseguire il fine-tuning di un modello sono necessari dati strutturati da utilizzare per specializzare il proprio LLM. Nell'esempio proposto in [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), GPT2 viene sottoposto a fine-tuning per rilevare se un'email è spam oppure no, utilizzando i dati disponibili in [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._

Questo dataset contiene molti più esempi di "non spam" rispetto a quelli di "spam"; pertanto, il libro suggerisce di **utilizzare solo tanti esempi di "non spam" quanti sono quelli di "spam"** (rimuovendo quindi dal training data tutti gli esempi aggiuntivi). In questo caso, si trattava di 747 esempi per ciascuna categoria.<sup>[[1]](#references)</sup>

Successivamente, il **70%** del dataset viene utilizzato per il **training**, il **10%** per la **validazione** e il **20%** per il **testing**.

- Il **validation set** viene utilizzato durante la fase di training per regolare gli **iperparametri** del modello e prendere decisioni sull'architettura del modello, contribuendo efficacemente a prevenire l'overfitting fornendo feedback sulle prestazioni del modello su dati non visti. Consente miglioramenti iterativi senza influenzare la valutazione finale.
- Ciò significa che, sebbene i dati inclusi in questo dataset non vengano utilizzati direttamente per il training, vengono utilizzati per regolare i migliori **iperparametri**; pertanto, questo set non può essere utilizzato per valutare le prestazioni del modello come avviene con il testing set.
- Al contrario, il **test set** viene utilizzato **solo dopo** che il modello è stato completamente addestrato e tutte le modifiche sono state completate; fornisce una valutazione imparziale della capacità del modello di generalizzare a dati nuovi e non visti. Questa valutazione finale sul test set fornisce un'indicazione realistica di come ci si aspetta che il modello si comporti nelle applicazioni del mondo reale.

### Lunghezza delle entry

Poiché l'esempio di training richiede entry (in questo caso, il testo delle email) della stessa lunghezza, si è deciso di rendere ogni entry grande quanto quella più lunga, aggiungendo gli id di `<|endoftext|>` come padding.<sup>[[1]](#references)</sup>

### Inizializzazione del modello

Utilizzando i pesi open source pre-addestrati, inizializzare il modello da addestrare. Lo abbiamo già fatto in precedenza e, seguendo le istruzioni di [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), è possibile farlo facilmente.

## Classification head

In questo esempio specifico (prevedere se un testo è spam oppure no), non ci interessa eseguire il fine-tuning in base all'intero vocabolario di GPT2, ma vogliamo solo che il nuovo modello indichi se l'email è spam (1) oppure no (0). Pertanto, andremo a **modificare il layer finale che** fornisce le probabilità per ciascun token del vocabolario sostituendolo con uno che fornisca solo le probabilità che l'email sia spam oppure no (come se fosse un vocabolario di 2 parole).<sup>[[1]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## Parametri da ottimizzare

Per eseguire il fine-tuning rapidamente, è più semplice non ottimizzare tutti i parametri, ma solo alcuni degli ultimi. Questo perché è noto che i layer inferiori generalmente catturano strutture e semantica di base del linguaggio, applicabili in generale. Pertanto, **eseguire il fine-tuning solo sugli ultimi layer è solitamente sufficiente e più rapido**.<sup>[[1]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Voci da usare per l'addestramento

Nelle sezioni precedenti, l'LLM veniva addestrato riducendo la loss di ogni token previsto, anche se quasi tutti i token previsti erano presenti nella frase di input (solo 1 alla fine veniva realmente previsto), affinché il modello comprendesse meglio il linguaggio.

In questo caso ci interessa solo che il modello sia in grado di prevedere se l'input è spam o meno, quindi consideriamo solo l'ultimo token previsto. Pertanto, è necessario modificare le nostre precedenti funzioni di loss dell'addestramento in modo che tengano conto solo di quel token.<sup>[[1]](#references)</sup>

Questo è implementato in [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) come:
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Nota che per ogni batch ci interessano solo i **logits dell'ultimo token predetto**.
