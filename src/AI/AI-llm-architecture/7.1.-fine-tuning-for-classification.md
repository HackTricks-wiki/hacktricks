# 7.1. Classification के लिए Fine-Tuning

## Fine-Tuning क्या है?

Fine-tuning एक **pre-trained model** को लेने की प्रक्रिया है, जिसने विशाल मात्रा में डेटा से **सामान्य language patterns** सीखे हैं, और उसे किसी **विशिष्ट task** को करने या domain-specific language को समझने के लिए **अनुकूलित** करने की प्रक्रिया है। यह model की training को एक छोटे, task-specific dataset पर जारी रखकर किया जाता है, जिससे model अपने parameters को नए डेटा की बारीकियों के अनुसार बेहतर ढंग से समायोजित कर सके और साथ ही पहले से अर्जित व्यापक ज्ञान का लाभ उठा सके। Fine-tuning model को specialized applications में अधिक सटीक और प्रासंगिक परिणाम देने में सक्षम बनाता है, और इसके लिए नए model को scratch से train करने की आवश्यकता नहीं होती।

> [!TIP]
> LLM को pre-train करना महंगा होता है, इसलिए किसी विशिष्ट task के लिए open-source pretrained model को fine-tune करना आमतौर पर अधिक आसान और सस्ता होता है।

> [!TIP]
> यह section classification के लिए pretrained model को fine-tune करने का तरीका दिखाता है। नया text generate करने के बजाय, model **configured categories के लिए logits** लौटाता है, जैसे spam और not spam।<sup>[[1]](#references)[[2]](#references)</sup>

## Dataset तैयार करना

### Dataset का आकार

बेशक, किसी model को fine-tune करने के लिए आपको अपने LLM को specialize करने हेतु कुछ structured data की आवश्यकता होती है। [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) में दिए गए example में, [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip) के डेटा का उपयोग करके GPT2 को यह detect करने के लिए fine-tune किया गया है कि कोई email spam है या नहीं_._<sup>[[2]](#references)[[3]](#references)</sup>

इस dataset में "spam नहीं" वाले examples की संख्या "spam" वाले examples से बहुत अधिक है। Worked example प्रत्येक class से समान संख्या बनाए रखकर classes को balance करता है: प्रत्येक class के 747 examples।<sup>[[1]](#references)[[2]](#references)</sup>

इसके बाद example balanced dataset का **70%** **training**, **10%** **validation**, और **20%** **testing** के लिए उपयोग करता है।<sup>[[2]](#references)</sup>

- **validation set** का उपयोग training phase के दौरान model के **hyperparameters** को fine-tune करने और model architecture के बारे में निर्णय लेने के लिए किया जाता है। यह unseen data पर model के प्रदर्शन के बारे में feedback देकर overfitting को रोकने में सहायता करता है। इससे final evaluation को bias किए बिना iterative improvements किए जा सकते हैं।
- इसका अर्थ है कि हालांकि इस dataset में शामिल data का उपयोग सीधे training के लिए नहीं किया जाता, लेकिन इसका उपयोग सर्वोत्तम **hyperparameters** को tune करने के लिए किया जाता है। इसलिए इस set का उपयोग testing set की तरह model के performance का evaluation करने के लिए नहीं किया जा सकता।
- इसके विपरीत, **test set** का उपयोग **केवल तब किया जाता है जब** model पूरी तरह train हो चुका हो और सभी adjustments पूरे हो चुके हों। यह नए और unseen data पर model की generalize करने की क्षमता का unbiased assessment प्रदान करता है। Test set पर यह final evaluation इस बात का वास्तविक संकेत देता है कि real-world applications में model से कैसा प्रदर्शन अपेक्षित है।

### Entry Length

चूंकि training example में entries (इस मामले में email text) की length समान होना आवश्यक है, इसलिए प्रत्येक entry को सबसे बड़ी entry जितना बड़ा बनाने का निर्णय लिया गया। इसके लिए `<|endoftext|>` के ids को padding के रूप में जोड़ा गया।<sup>[[2]](#references)</sup>

### Model Initialize करना

Referenced notebook का अनुसरण करते हुए, open-source pretrained weights के साथ model को initialize करें।<sup>[[2]](#references)</sup>

## Classification head

Binary spam classification के लिए, model को अब vocabulary-sized output logits की आवश्यकता नहीं होती। अंतिम output head को एक linear layer से replace करें, जो दो class logits emit करती है: not spam (`0`) और spam (`1`)।<sup>[[2]](#references)</sup>
```python
# Replace the final layer with a linear layer that has two outputs
num_classes = 2
model.out_head = torch.nn.Linear(
in_features=BASE_CONFIG["emb_dim"],
out_features=num_classes,
)
```
## ट्यून किए जाने वाले Parameters

इस उदाहरण में training cost कम करने के लिए, अधिकांश model parameters को freeze करें और केवल अंतिम transformer block, final normalization layer और newly initialized output head को fine-tune करें। इससे पहले की layers द्वारा सीखी गई general representations का पुनः उपयोग होता है और trainable parameters की संख्या काफी कम हो जाती है; अधिक layers को unfreeze करने से अधिक compute और overfitting cost पर task adaptation बेहतर हो सकता है।<sup>[[1]](#references)[[2]](#references)</sup>
```python
# Freeze all existing model parameters
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():
param.requires_grad = True
```
## प्रशिक्षण के लिए उपयोग की जाने वाली प्रविष्टियाँ

पिछले अनुभागों में, language-model pretraining के दौरान sequence में next-token loss की गणना की जाती थी, ताकि model language structure सीख सके।

Sequence classification के लिए, उदाहरण classification head से गुज़ारी जाने वाली representation के रूप में अंतिम input position पर model output का उपयोग करता है। Loss उन दो class logits की तुलना message label से करता है; यह यह predict नहीं करता कि अंतिम token स्वयं spam है या नहीं।<sup>[[2]](#references)</sup>

इसे [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) में इस प्रकार implement किया गया है:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
प्रत्येक batch के लिए, केवल **अंतिम input position पर class logits** का उपयोग किया जाता है।
