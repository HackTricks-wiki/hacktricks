# 7.1. Дообучення для класифікації

{{#include ../../banners/hacktricks-training.md}}

## Що таке дообучення?

Дообучення — це процес, під час якого береться **попередньо навчена модель**, що вивчила **загальні мовні закономірності** на величезних обсягах даних, і **адаптується** для виконання **конкретного завдання** або розуміння специфічної для певної галузі мови. Це досягається продовженням навчання моделі на меншому наборі даних, специфічному для завдання, що дає їй змогу скоригувати свої параметри для кращої відповідності особливостям нових даних, використовуючи вже набуті широкі знання. Дообучення дає змогу моделі надавати точніші та релевантніші результати у спеціалізованих застосунках без потреби навчати нову модель з нуля.

> [!TIP]
> Попереднє навчання LLM є дорогим, тому зазвичай простіше й дешевше донавчити попередньо навчену модель з відкритим кодом для конкретного завдання.

> [!TIP]
> У цьому розділі показано, як донавчити попередньо навчену модель для класифікації. Замість генерування нового тексту модель повертає **логіти для налаштованих категорій**, наприклад спам і не спам.<sup>[[1]](#references)[[2]](#references)</sup>

## Підготовка набору даних

### Розмір набору даних

Звичайно, щоб донавчити модель, потрібні структуровані дані для спеціалізації вашої LLM. У прикладі, запропонованому в [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), GPT2 донавчається для визначення того, чи є електронний лист спамом, використовуючи дані з [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup>

Цей набір даних містить набагато більше прикладів «не спаму», ніж прикладів «спаму». У прикладі класи балансуються шляхом збереження однакової кількості прикладів для кожного класу: по 747 прикладів кожного.<sup>[[1]](#references)[[2]](#references)</sup>

Потім у прикладі використовується **70%** збалансованого набору даних для **навчання**, **10%** для **валідації** та **20%** для **тестування**.<sup>[[2]](#references)</sup>

- **Набір валідації** використовується під час етапу навчання для налаштування **гіперпараметрів** моделі та прийняття рішень щодо її архітектури, фактично допомагаючи запобігати перенавчанню завдяки зворотному зв'язку про те, як модель працює на невідомих їй даних. Він дає змогу поступово вдосконалювати модель без упередження підсумкової оцінки.
- Це означає, що хоча дані з цього набору даних безпосередньо не використовуються для навчання, вони використовуються для налаштування найкращих **гіперпараметрів**, тому цей набір не можна використовувати для оцінювання продуктивності моделі так, як тестовий набір.
- Натомість **тестовий набір** використовується **лише після** повного навчання моделі та завершення всіх налаштувань; він забезпечує неупереджену оцінку здатності моделі узагальнювати знання на нові, невідомі їй дані. Ця підсумкова оцінка на тестовому наборі дає реалістичне уявлення про очікувану продуктивність моделі в реальних застосунках.

### Довжина запису

Оскільки приклад навчання передбачає, що записи (у цьому випадку тексти електронних листів) мають однакову довжину, було вирішено збільшити кожен запис до довжини найбільшого, додавши ідентифікатори `<|endoftext|>` як padding.<sup>[[2]](#references)</sup>

### Ініціалізація моделі

Ініціалізуйте модель попередньо навченими вагами з відкритим кодом, дотримуючись інструкцій із наведеного notebook.<sup>[[2]](#references)</sup>

## Класифікаційна голова

Для бінарної класифікації спаму моделі більше не потрібні вихідні логіти розміром зі словник. Замініть фінальну вихідну голову лінійним шаром, який видає два логіти класів: не спам (`0`) і спам (`1`).<sup>[[2]](#references)</sup>
```python
# Replace the final layer with a linear layer that has two outputs
num_classes = 2
model.out_head = torch.nn.Linear(
in_features=BASE_CONFIG["emb_dim"],
out_features=num_classes,
)
```
## Параметри для налаштування

Щоб зменшити вартість навчання в цьому прикладі, заморозьте більшість параметрів моделі й виконайте fine-tuning лише останнього transformer block, фінального шару нормалізації та нової output head. Це дає змогу повторно використати загальні представлення, вивчені на попередніх шарах, і значно зменшує кількість параметрів, що навчаються; розморожування більшої кількості шарів може забезпечити кращу адаптацію до завдання, але потребує більше обчислювальних ресурсів і підвищує ризик перенавчання.<sup>[[1]](#references)[[2]](#references)</sup>
```python
# Freeze all existing model parameters
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():
param.requires_grad = True
```
## Записи для використання під час навчання

У попередніх розділах під час pretraining мовної моделі loss наступного токена обчислювався для всієї послідовності, щоб модель могла вивчати структуру мови.

Для sequence classification приклад використовує вихід моделі на останній вхідній позиції як представлення, яке передається через classification head. Loss порівнює два logits класів із міткою повідомлення; модель не передбачає, чи є сам останній токен spam.<sup>[[2]](#references)</sup>

Це реалізовано в [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) так:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Для кожного batch використовуються лише **class logits на фінальній позиції input**.
