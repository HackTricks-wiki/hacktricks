# 7.1. Sınıflandırma için Fine-Tuning

{{#include ../../banners/hacktricks-training.md}}

## Nedir

Fine-tuning, büyük miktarda veriden **genel dil kalıplarını** öğrenmiş bir **önceden eğitilmiş modeli** alıp, onu **belirli bir görevi** gerçekleştirecek veya alana özgü dili anlayacak şekilde **uyarlama** sürecidir. Bu işlem, modelin daha küçük ve göreve özgü bir veri seti üzerinde eğitilmeye devam edilmesiyle gerçekleştirilir. Böylece model, hâlihazırda edindiği geniş bilgiden yararlanırken parametrelerini yeni verilerin inceliklerine daha iyi uyacak şekilde ayarlayabilir. Fine-tuning, yeni bir modeli sıfırdan eğitmeye gerek kalmadan, modelin uzmanlaşmış uygulamalarda daha doğru ve ilgili sonuçlar sunmasını sağlar.

> [!TIP]
> Metni "anlayan" bir LLM'i önceden eğitmek oldukça pahalı olduğundan, belirli bir görevi gerçekleştirmesini istediğimiz open source önceden eğitilmiş modelleri fine-tune etmek genellikle daha kolay ve daha ucuzdur.

> [!TIP]
> Bu bölümün amacı, hâlihazırda önceden eğitilmiş bir modelin nasıl fine-tune edileceğini göstermektir. Böylece LLM yeni metinler üretmek yerine, **verilen metnin her bir kategoriye göre sınıflandırılma olasılıklarını** verecektir (örneğin bir metnin spam olup olmadığını belirlemek).

## Veri setinin hazırlanması

### Veri seti boyutu

Elbette, bir modeli fine-tune etmek için LLM'inizi özelleştirmek üzere kullanabileceğiniz yapılandırılmış verilere ihtiyacınız vardır. [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) adresinde önerilen örnekte, GPT2'nin bir e-postanın spam olup olmadığını tespit etmesi, [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip) verileri kullanılarak sağlanmıştır._._<sup>[[2]](#references)[[3]](#references)</sup>

Bu veri seti, "spam" örneklerine kıyasla çok daha fazla "spam değil" örneği içerir. Bu nedenle kitap, **"spam değil" örneklerinden yalnızca "spam" örnekleri kadar kullanılmasını** önermektedir (dolayısıyla eğitim verilerindeki tüm fazla örnekler çıkarılır). Bu durumda her kategoriden 747 örnek kullanılmıştır.<sup>[[2]](#references)[[1]](#references)</sup>

Ardından veri setinin **%70'i** **eğitim**, **%10'u** **validation** ve **%20'si** **testing** için kullanılır.

- **Validation set**, eğitim aşamasında modelin **hyperparameter**'larını fine-tune etmek ve model mimarisi hakkında kararlar almak için kullanılır. Modelin görülmemiş veriler üzerindeki performansı hakkında geri bildirim sağlayarak overfitting'in önlenmesine yardımcı olur. Nihai değerlendirmeyi yanlı hâle getirmeden yinelemeli iyileştirmeler yapılmasını sağlar.
- Bu, bu veri setinde bulunan veriler eğitimde doğrudan kullanılmasa da en iyi **hyperparameter**'ları ayarlamak için kullanıldığı anlamına gelir. Bu nedenle bu set, testing seti gibi modelin performansını değerlendirmek için kullanılamaz.
- Buna karşılık **test set**, yalnızca model tamamen eğitildikten ve tüm ayarlamalar tamamlandıktan **sonra** kullanılır. Modelin yeni ve görülmemiş verilere genelleme yapabilme yeteneğinin tarafsız bir değerlendirmesini sağlar. Test seti üzerindeki bu nihai değerlendirme, modelin gerçek dünya uygulamalarında nasıl performans göstermesinin beklendiğine dair gerçekçi bir gösterge sunar.

### Girdi uzunluğu

Eğitim örneği girdilerin (bu durumda e-posta metinlerinin) aynı uzunlukta olmasını beklediğinden, her girdinin `<|endoftext|>` ID'leri padding olarak eklenerek en uzun girdi kadar büyük yapılmasına karar verilmiştir.<sup>[[2]](#references)</sup>

## Sınıflandırma head'i

Bu özel örnekte (bir metnin spam olup olmadığını tahmin ederken), GPT2'nin tamamını kapsayan vocabulary'ye göre fine-tuning yapmakla ilgilenmiyoruz; yalnızca yeni modelin e-postanın spam (1) olup olmadığını veya spam olmadığını (0) söylemesini istiyoruz. Bu nedenle, vocabulary'deki her token için olasılıkları veren **son katmanı**, yalnızca spam olma veya spam olmama olasılıklarını veren bir katmanla (yani 2 kelimelik bir vocabulary gibi) **değiştireceğiz**.<sup>[[2]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## Ayarlanacak parametreler

Fast fine-tuning gerçekleştirmek için tüm parametreleri fine-tune etmek yerine yalnızca bazı son parametreleri fine-tune etmek daha kolaydır. Bunun nedeni, alt katmanların genellikle uygulanabilir temel dil yapılarını ve anlambilimi yakalamasının biliniyor olmasıdır. Bu nedenle, yalnızca **son katmanları fine-tune etmek genellikle yeterli ve daha hızlıdır**.<sup>[[2]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Eğitimde kullanılacak girdiler

Önceki bölümlerde LLM, modelin dili daha iyi anlayabilmesi için her tahmin edilen token'ın loss değerini azaltacak şekilde eğitildi; ancak tahmin edilen token'ların neredeyse tamamı girdi cümlesinde yer alıyordu (sondaki yalnızca 1 token gerçekten tahmin ediliyordu).

Bu durumda yalnızca modelin girdinin spam olup olmadığını tahmin edebilmesini önemsiyoruz; bu nedenle sadece tahmin edilen son token ile ilgileniyoruz. Dolayısıyla önceki training loss functions'larımızı yalnızca bu token'ı dikkate alacak şekilde değiştirmemiz gerekiyor.

Bu işlem [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) içinde şu şekilde uygulanmıştır:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Her batch için yalnızca **tahmin edilen son token'ın logits değerleriyle** ilgilendiğimizi unutmayın.
