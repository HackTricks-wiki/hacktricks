# 7.1. 用于分类的 Fine-Tuning

{{#include ../../banners/hacktricks-training.md}}

## 什么是 Fine-Tuning

Fine-tuning 是指获取一个已经学习了**通用语言模式**的**预训练模型**，并对其进行**适配**，使其执行**特定任务**或理解特定领域的语言。实现方式是在较小的、面向特定任务的数据集上继续训练模型，使其调整参数，从而更好地适应新数据的细微特征，同时利用已经获得的广泛知识。Fine-tuning 使模型能够在专业应用中提供更准确、更相关的结果，而无需从头开始训练新模型。

> [!TIP]
> 由于预训练一个能够“理解”文本的 LLM 成本非常高，因此通常更容易、更经济的做法是对开源预训练模型进行 fine-tune，使其执行我们所需的特定任务。

> [!TIP]
> 本节的目标是展示如何对一个已经预训练的模型进行 fine-tune，使其不再生成新文本，而是给出**给定文本被归类到每个给定类别中的概率**（例如判断一段文本是否为 spam）。

## 准备数据集

### 数据集大小

当然，要对模型进行 fine-tune，你需要一些结构化数据来专门训练你的 LLM。在 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) 中提出的示例里，GPT2 使用 [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip) 中的数据来检测一封电子邮件是否为 spam_._<sup>[[2]](#references)[[3]](#references)</sup>

该数据集中“not spam”示例的数量远多于“spam”示例，因此书中建议**只使用与“spam”示例数量相同的“not spam”示例**（也就是说，从训练数据中移除所有多余的示例）。在本例中，每类有 747 个示例。<sup>[[2]](#references)[[1]](#references)</sup>

接着，数据集中的**70%**用于**训练**，**10%**用于**验证**，**20%**用于**测试**。

- **验证集**在训练阶段使用，用于微调模型的**超参数**并对模型架构做出决策。它通过提供模型在未见过的数据上的表现反馈，有效帮助防止过拟合。验证集允许进行迭代改进，同时不会使最终评估产生偏差。
- 这意味着，尽管该数据集中的数据不会直接用于训练，但会用于调整最佳的**超参数**，因此不能像测试集那样使用该数据集来评估模型性能。
- 相比之下，**测试集**仅在模型完成训练且所有调整都结束后使用；它可以无偏地评估模型泛化到新的、未见过的数据上的能力。在测试集上进行的最终评估能够真实反映模型在实际应用中的预期表现。

### 条目长度

由于训练示例要求条目（本例中为电子邮件文本）具有相同长度，因此决定通过添加 `<|endoftext|>` 的 id 作为 padding，将每个条目扩展到最大条目的长度。<sup>[[2]](#references)</sup>

### 初始化模型

使用开源预训练权重初始化要训练的模型。我们之前已经完成过这一过程；按照 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) 中的说明即可轻松完成。<sup>[[2]](#references)</sup>

## 分类头

在这个具体示例中（预测文本是否为 spam），我们并不关心根据 GPT2 的完整词汇表进行 fine-tune，而只希望新模型判断电子邮件是否为 spam（1）或不是 spam（0）。因此，我们将**修改最终层**：该层原本为词汇表中的每个 token 提供概率，现在将其修改为只提供文本为 spam 或不是 spam 的概率（相当于只有 2 个词的词汇表）。<sup>[[2]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## 要调优的参数

为了快速进行 fine tuning，通常不必调优所有参数，而只需调优最后几层。这是因为已知较低层通常会捕获通用的基础语言结构和语义。因此，**通常只 fine tuning 最后几层就足够了，而且速度更快**。<sup>[[2]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## 用于训练的条目

在前面的章节中，LLM 通过降低每个预测 token 的 loss 进行训练，即使几乎所有预测的 token 都位于输入句子中（只有末尾的 1 个 token 才是真正被预测的），以便模型更好地理解语言。

在本例中，我们只关心模型能否预测该模型是否为 spam，因此只关心最后一个被预测的 token。因此，需要修改之前的训练 loss 函数，使其只考虑该 token。

该过程在 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) 中实现，如下所示：<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
注意，对于每个 batch，我们只关注预测的**最后一个 token 的 logits**。
