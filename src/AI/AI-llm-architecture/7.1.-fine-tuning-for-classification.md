# 7.1. Дообучення для класифікації

{{#include ../../banners/hacktricks-training.md}}

## Що це таке

Дообучення — це процес взяття **попередньо навченої моделі**, яка засвоїла **загальні мовні закономірності** з величезних обсягів даних, і **адаптації** її для виконання **конкретного завдання** або розуміння предметно-специфічної мови. Це досягається продовженням навчання моделі на меншому наборі даних, призначеному для конкретного завдання, що дає їй змогу налаштувати свої параметри для кращої відповідності особливостям нових даних, водночас використовуючи вже набуті широкі знання. Дообучення дає змогу моделі забезпечувати точніші та релевантніші результати у спеціалізованих застосунках без необхідності навчати нову модель з нуля.

> [!TIP]
> Оскільки попереднє навчання LLM, яка "розуміє" текст, є досить дорогим, зазвичай простіше та дешевше виконати дообучення попередньо навчених моделей з відкритим кодом для виконання конкретного завдання.

> [!TIP]
> Мета цього розділу — показати, як виконати дообучення вже попередньо навченої моделі, щоб замість генерування нового тексту LLM визначала **ймовірності того, що наданий текст належить до кожної з указаних категорій** (наприклад, чи є текст спамом).

## Підготовка набору даних

### Розмір набору даних

Звісно, щоб виконати дообучення моделі, потрібні структуровані дані для спеціалізації LLM. У прикладі, запропонованому в [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), GPT2 дообучується для визначення того, чи є електронний лист спамом, використовуючи дані з [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._

Цей набір даних містить значно більше прикладів "не спаму", ніж "спаму", тому в книзі пропонується **використовувати стільки ж прикладів "не спаму", скільки й "спаму"** (тобто видалити з навчальних даних усі додаткові приклади). У цьому випадку це становило 747 прикладів кожного типу.<sup>[[1]](#references)</sup>

Потім **70%** набору даних використовується для **навчання**, **10%** — для **валідації**, а **20%** — для **тестування**.

- **Набір для валідації** використовується під час етапу навчання для налаштування **гіперпараметрів** моделі та ухвалення рішень щодо її архітектури, фактично допомагаючи запобігти перенавчанню завдяки зворотному зв'язку про роботу моделі на невідомих даних. Він дає змогу ітеративно вдосконалювати модель, не створюючи упередженості під час остаточного оцінювання.
- Це означає, що хоча дані з цього набору безпосередньо не використовуються для навчання, вони застосовуються для налаштування найкращих **гіперпараметрів**, тому цей набір не можна використовувати для оцінювання продуктивності моделі, як тестовий набір.
- На відміну від нього, **тестовий набір** використовується **лише після** повного навчання моделі та завершення всіх налаштувань; він забезпечує неупереджену оцінку здатності моделі узагальнювати результати для нових, невідомих даних. Це остаточне оцінювання на тестовому наборі дає реалістичне уявлення про те, як модель, імовірно, працюватиме в реальних застосунках.

### Довжина записів

Оскільки навчальний приклад передбачає записи (у цьому випадку текст електронних листів) однакової довжини, було вирішено зробити кожен запис таким самим великим, як найбільший із них, додавши ідентифікатори `<|endoftext|>` як padding.<sup>[[1]](#references)</sup>

### Ініціалізація моделі

Використовуючи попередньо навчені ваги з відкритим кодом, ініціалізуйте модель для навчання. Ми вже робили це раніше, і, дотримуючись інструкцій із [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), ви легко зможете це виконати.

## Classification head

У цьому конкретному прикладі (визначення того, чи є текст спамом) нас не цікавить дообучення відповідно до повного словника GPT2; ми лише хочемо, щоб нова модель визначала, чи є електронний лист спамом (1) чи ні (0). Тому ми збираємося **змінити фінальний шар, який** визначає ймовірності для кожного токена словника, на шар, який визначатиме лише ймовірності того, чи є текст спамом (тобто ніби словник складається з 2 слів).<sup>[[1]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## Параметри для налаштування

Щоб швидко виконати тонке налаштування, простіше налаштовувати не всі параметри, а лише деякі останні. Це пояснюється тим, що нижні шари зазвичай захоплюють базові мовні структури та семантику, які можна застосовувати надалі. Тому **тонкого налаштування останніх шарів зазвичай достатньо, і воно виконується швидше**.<sup>[[1]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Записи для використання під час навчання

У попередніх розділах LLM навчалася шляхом зменшення loss для кожного передбаченого токена, хоча майже всі передбачені токени вже містилися у вхідному реченні (лише 1 токен у кінці справді передбачався), щоб модель краще розуміла мову.

У цьому випадку нас цікавить лише здатність моделі передбачати, чи є повідомлення spam, чи ні, тому нас цікавить лише останній передбачений токен. Отже, потрібно змінити попередні функції loss так, щоб вони враховували лише цей токен.<sup>[[1]](#references)</sup>

Це реалізовано в [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) так:
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Зверніть увагу, що для кожного batch нас цікавлять лише **logits останнього передбаченого токена**.
