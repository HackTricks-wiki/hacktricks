# 7.1. Fine-Tuning για Classification

{{#include ../../banners/hacktricks-training.md}}

## Τι είναι

Το Fine-tuning είναι η διαδικασία κατά την οποία λαμβάνεται ένα **pre-trained model** που έχει μάθει **γενικά γλωσσικά μοτίβα** από τεράστιες ποσότητες δεδομένων και **προσαρμόζεται** ώστε να εκτελεί μια **συγκεκριμένη εργασία** ή να κατανοεί γλώσσα συγκεκριμένου τομέα. Αυτό επιτυγχάνεται συνεχίζοντας την εκπαίδευση του model σε ένα μικρότερο, ειδικά σχεδιασμένο για την εργασία dataset, επιτρέποντάς του να προσαρμόσει τις παραμέτρους του ώστε να ανταποκρίνεται καλύτερα στις ιδιαιτερότητες των νέων δεδομένων, αξιοποιώντας παράλληλα την ευρεία γνώση που έχει ήδη αποκτήσει. Το Fine-tuning επιτρέπει στο model να παρέχει ακριβέστερα και πιο σχετικά αποτελέσματα σε εξειδικευμένες εφαρμογές, χωρίς να χρειάζεται η εκπαίδευση ενός νέου model από την αρχή.

> [!TIP]
> Καθώς το pre-training ενός LLM που «κατανοεί» το κείμενο είναι αρκετά ακριβό, συνήθως είναι ευκολότερο και φθηνότερο να κάνουμε fine-tune σε open source pre-trained models, ώστε να εκτελούν μια συγκεκριμένη εργασία που θέλουμε.

> [!TIP]
> Ο στόχος αυτής της ενότητας είναι να δείξει πώς γίνεται fine-tune σε ένα ήδη pre-trained model, ώστε αντί να δημιουργεί νέο κείμενο, το LLM να επιλέγει και να δίνει τις **πιθανότητες του δεδομένου κειμένου να ταξινομηθεί σε καθεμία από τις δεδομένες κατηγορίες** (όπως αν ένα κείμενο είναι spam ή όχι).

## Προετοιμασία του dataset

### Μέγεθος dataset

Φυσικά, για να κάνετε fine-tune σε ένα model χρειάζεστε κάποια δομημένα δεδομένα που θα χρησιμοποιήσετε για να εξειδικεύσετε το LLM σας. Στο παράδειγμα που προτείνεται στο [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), το GPT2 γίνεται fine-tune ώστε να εντοπίζει αν ένα email είναι spam ή όχι, χρησιμοποιώντας τα δεδομένα από το [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._

Αυτό το dataset περιέχει πολύ περισσότερα παραδείγματα «όχι spam» από ό,τι «spam», επομένως το βιβλίο προτείνει να **χρησιμοποιούνται μόνο τόσα παραδείγματα «όχι spam» όσα και «spam»** (άρα να αφαιρούνται από τα δεδομένα εκπαίδευσης όλα τα επιπλέον παραδείγματα). Σε αυτή την περίπτωση, αυτό αντιστοιχούσε σε 747 παραδείγματα από κάθε κατηγορία.<sup>[[1]](#references)</sup>

Στη συνέχεια, το **70%** του dataset χρησιμοποιείται για **training**, το **10%** για **validation** και το **20%** για **testing**.

- Το **validation set** χρησιμοποιείται κατά τη φάση του training για το fine-tuning των **hyperparameters** του model και τη λήψη αποφάσεων σχετικά με την αρχιτεκτονική του model, βοηθώντας ουσιαστικά στην αποτροπή του overfitting, παρέχοντας feedback σχετικά με την απόδοση του model σε δεδομένα που δεν έχει δει. Επιτρέπει επαναληπτικές βελτιώσεις χωρίς να μεροληπτεί η τελική αξιολόγηση.
- Αυτό σημαίνει ότι, παρόλο που τα δεδομένα που περιλαμβάνονται σε αυτό το dataset δεν χρησιμοποιούνται άμεσα για το training, χρησιμοποιούνται για τη ρύθμιση των βέλτιστων **hyperparameters**. Επομένως, αυτό το set δεν μπορεί να χρησιμοποιηθεί για την αξιολόγηση της απόδοσης του model όπως το testing set.
- Αντίθετα, το **test set** χρησιμοποιείται **μόνο μετά** την πλήρη εκπαίδευση του model και την ολοκλήρωση όλων των προσαρμογών. Παρέχει μια αμερόληπτη αξιολόγηση της ικανότητας του model να γενικεύει σε νέα, μη γνωστά δεδομένα. Αυτή η τελική αξιολόγηση στο test set δείχνει ρεαλιστικά πώς αναμένεται να αποδίδει το model σε εφαρμογές πραγματικού κόσμου.

### Μήκος των entries

Καθώς το training example απαιτεί entries (σε αυτή την περίπτωση, κείμενα email) ίδιου μήκους, αποφασίστηκε να γίνει κάθε entry τόσο μεγάλο όσο το μεγαλύτερο, προσθέτοντας τα ids του `<|endoftext|>` ως padding.<sup>[[1]](#references)</sup>

## Classification head

Σε αυτό το συγκεκριμένο παράδειγμα (πρόβλεψη του αν ένα κείμενο είναι spam ή όχι), δεν μας ενδιαφέρει να κάνουμε fine-tune σύμφωνα με ολόκληρο το vocabulary του GPT2, αλλά θέλουμε το νέο model να δηλώνει μόνο αν το email είναι spam (1) ή όχι (0). Επομένως, πρόκειται να **τροποποιήσουμε το τελικό layer που** δίνει τις πιθανότητες ανά token του vocabulary, αντικαθιστώντας το με ένα που δίνει μόνο τις πιθανότητες να είναι spam ή όχι (σαν ένα vocabulary 2 λέξεων).<sup>[[1]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## Παράμετροι προς ρύθμιση

Για να γίνει γρήγορα το fine-tuning, είναι ευκολότερο να μη ρυθμιστούν όλες οι παράμετροι, αλλά μόνο κάποιες από τις τελευταίες. Αυτό συμβαίνει επειδή είναι γνωστό ότι τα χαμηλότερα επίπεδα γενικά αποτυπώνουν βασικές γλωσσικές δομές και σημασιολογία που μπορούν να εφαρμοστούν. Επομένως, η **ρύθμιση μόνο των τελευταίων επιπέδων είναι συνήθως αρκετή και ταχύτερη**.<sup>[[1]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Entries to use for training

Στις προηγούμενες ενότητες, το LLM εκπαιδευόταν μειώνοντας το loss κάθε προβλεπόμενου token, παρόλο που σχεδόν όλα τα προβλεπόμενα tokens υπήρχαν ήδη στην πρόταση εισόδου (μόνο 1 στο τέλος είχε πραγματικά προβλεφθεί), ώστε το μοντέλο να κατανοεί καλύτερα τη γλώσσα.

Σε αυτή την περίπτωση, μας ενδιαφέρει μόνο το μοντέλο να μπορεί να προβλέψει αν η είσοδος είναι spam ή όχι, επομένως μας ενδιαφέρει μόνο το τελευταίο token που προβλέπεται. Συνεπώς, χρειάζεται να τροποποιήσουμε τις προηγούμενες συναρτήσεις loss της εκπαίδευσής μας, ώστε να λαμβάνουν υπόψη μόνο αυτό το token.<sup>[[1]](#references)</sup>

Αυτό υλοποιείται στο [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) ως εξής:
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Σημειώστε ότι για κάθε batch μας ενδιαφέρουν μόνο τα **logits του τελευταίου προβλεπόμενου token**.
