# 7.1. Fine-Tuning per la classificazione

{{#include ../../banners/hacktricks-training.md}}

## Che cos'è il Fine-Tuning?

Il fine-tuning è il processo che consiste nel prendere un **pre-trained model** che ha appreso **pattern linguistici generali** da enormi quantità di dati e **adattarlo** per eseguire un **task specifico** o comprendere il linguaggio specifico di un dominio. Questo risultato si ottiene continuando l'addestramento del modello su un dataset più piccolo e specifico per il task, consentendogli di modificare i propri parametri per adattarsi meglio alle caratteristiche dei nuovi dati, sfruttando al contempo l'ampia conoscenza già acquisita. Il fine-tuning consente al modello di fornire risultati più accurati e pertinenti in applicazioni specializzate, senza dover addestrare un nuovo modello da zero.

> [!TIP]
> Il pre-training di un LLM è costoso, quindi di solito è più semplice ed economico eseguire il fine-tuning di un modello pretrained open-source per un task specifico.

> [!TIP]
> Questa sezione mostra come eseguire il fine-tuning di un modello pretrained per la classificazione. Invece di generare nuovo testo, il modello restituisce i **logits per le categorie configurate**, come spam e not spam.<sup>[[1]](#references)[[2]](#references)</sup>

## Preparazione del dataset

### Dimensioni del dataset

Naturalmente, per eseguire il fine-tuning di un modello sono necessari dati strutturati da utilizzare per specializzare il proprio LLM. Nell'esempio proposto in [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), GPT2 viene sottoposto a fine-tuning per rilevare se un'email è spam o meno utilizzando i dati presenti in [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup>

Questo dataset contiene molti più esempi di "not spam" rispetto a quelli di "spam". L'esempio pratico bilancia le classi conservando lo stesso numero di elementi per ciascuna classe: 747 esempi per classe.<sup>[[1]](#references)[[2]](#references)</sup>

L'esempio utilizza quindi il **70%** del dataset bilanciato per il **training**, il **10%** per la **validation** e il **20%** per il **testing**.<sup>[[2]](#references)</sup>

- Il **validation set** viene utilizzato durante la fase di training per eseguire il fine-tuning degli **hyperparameters** del modello e prendere decisioni sull'architettura del modello, contribuendo di fatto a prevenire l'overfitting fornendo un feedback sulle prestazioni del modello su dati non osservati. Consente miglioramenti iterativi senza introdurre bias nella valutazione finale.
- Ciò significa che, sebbene i dati inclusi in questo dataset non vengano utilizzati direttamente per il training, vengono utilizzati per ottimizzare i migliori **hyperparameters**; pertanto, questo set non può essere utilizzato per valutare le prestazioni del modello come avviene con il test set.
- Al contrario, il **test set** viene utilizzato **solo dopo** che il modello è stato completamente addestrato e tutte le modifiche sono state completate; fornisce una valutazione imparziale della capacità del modello di generalizzare a dati nuovi e non osservati. Questa valutazione finale sul test set offre un'indicazione realistica delle prestazioni attese del modello nelle applicazioni del mondo reale.

### Lunghezza degli elementi

Poiché l'esempio di training prevede elementi (in questo caso, il testo delle email) della stessa lunghezza, si è deciso di rendere ogni elemento grande quanto il più lungo, aggiungendo gli id di `<|endoftext|>` come padding.<sup>[[2]](#references)</sup>

### Inizializzazione del modello

Inizializzare il modello con i pesi pretrained open-source, seguendo il notebook indicato nei riferimenti.<sup>[[2]](#references)</sup>

## Classification head

Per la classificazione binaria dello spam, il modello non ha più bisogno di logits di output delle dimensioni del vocabolario. Sostituire la head di output finale con un layer lineare che emetta due logits di classe: not spam (`0`) e spam (`1`).<sup>[[2]](#references)</sup>
```python
# Replace the final layer with a linear layer that has two outputs
num_classes = 2
model.out_head = torch.nn.Linear(
in_features=BASE_CONFIG["emb_dim"],
out_features=num_classes,
)
```
## Parametri da ottimizzare

Per ridurre il costo dell'addestramento in questo esempio, congela la maggior parte dei parametri del modello ed esegui il fine-tuning solo sull'ultimo blocco transformer, sul layer di normalizzazione finale e sull'output head appena inizializzato. In questo modo riutilizzi le rappresentazioni generali apprese dai layer precedenti e riduci notevolmente il numero di parametri addestrabili; sbloccare più layer può fornire un maggiore adattamento al task, a fronte di un costo computazionale e di un rischio di overfitting più elevati.<sup>[[1]](#references)[[2]](#references)</sup>
```python
# Freeze all existing model parameters
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():
param.requires_grad = True
```
## Voci da usare per il training

Nelle sezioni precedenti, il pretraining del language model calcolava la loss del token successivo sull'intera sequenza, consentendo al modello di apprendere la struttura del linguaggio.

Per la classificazione di sequenze, l'esempio utilizza l'output del modello nell'ultima posizione dell'input come rappresentazione da passare attraverso la classification head. La loss confronta i due logits delle classi con l'etichetta del messaggio; non prevede se l'ultimo token in sé sia spam.<sup>[[2]](#references)</sup>

Questo viene implementato in [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) come segue:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Per ogni batch, vengono utilizzati solo i **class logits nella posizione finale dell'input**.
