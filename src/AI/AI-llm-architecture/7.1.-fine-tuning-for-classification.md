## Fine-Tuning Nedir?

Fine-tuning, büyük miktarda veriden **genel dil kalıplarını** öğrenmiş bir **pre-trained model** alıp onu **belirli bir görevi** gerçekleştirecek veya alana özgü dili anlayacak şekilde **uyarlama** sürecidir. Bu işlem, modelin daha küçük ve göreve özgü bir veri seti üzerinde eğitilmeye devam edilmesiyle gerçekleştirilir. Böylece model, zaten edindiği geniş bilgiden yararlanırken parametrelerini yeni verilerin özelliklerine daha uygun olacak şekilde ayarlayabilir. Fine-tuning, yeni bir modeli sıfırdan eğitmeye gerek kalmadan modelin özelleştirilmiş uygulamalarda daha doğru ve ilgili sonuçlar sunmasını sağlar.

> [!TIP]
> Bir LLM'i pre-training aşamasında eğitmek pahalıdır; bu nedenle belirli bir görev için open-source bir pretrained modeli fine-tune etmek genellikle daha kolay ve ucuzdur.

> [!TIP]
> Bu bölümde, bir pretrained modelin classification için nasıl fine-tune edileceği gösterilmektedir. Yeni metin üretmek yerine model, spam ve spam değil gibi **yapılandırılmış kategoriler için logits** döndürür.<sup>[[1]](#references)[[2]](#references)</sup>

## Veri setinin hazırlanması

### Veri seti boyutu

Elbette bir modeli fine-tune etmek için LLM'inizi özelleştirmek üzere kullanabileceğiniz yapılandırılmış verilere ihtiyacınız vardır. [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) adresindeki örnekte GPT2, [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip) verileri kullanılarak bir e-postanın spam olup olmadığını tespit edecek şekilde fine-tune edilmiştir_._<sup>[[2]](#references)[[3]](#references)</sup>

Bu veri setinde "spam değil" örnekleri, "spam" örneklerinden çok daha fazladır. Uygulamalı örnek, her sınıftan aynı sayıda örnek, yani 747 örnek tutarak sınıfları dengeler.<sup>[[1]](#references)[[2]](#references)</sup>

Örnek daha sonra dengelenmiş veri setinin **%70**'ini **training**, **%10**'unu **validation** ve **%20**'sini **testing** için kullanır.<sup>[[2]](#references)</sup>

- **Validation set**, training aşamasında modelin **hyperparameters** değerlerini fine-tune etmek ve model mimarisi hakkında kararlar almak için kullanılır. Modelin görülmemiş veriler üzerindeki performansı hakkında geri bildirim sağlayarak overfitting'in önlenmesine etkili şekilde yardımcı olur. Nihai değerlendirmeyi önyargılı hâle getirmeden yinelemeli iyileştirmelere olanak tanır.
- Bu, bu veri setinde bulunan verilerin training için doğrudan kullanılmamasına rağmen en iyi **hyperparameters** değerlerini ayarlamak için kullanıldığı anlamına gelir; bu nedenle bu set, testing seti gibi modelin performansını değerlendirmek için kullanılamaz.
- Buna karşılık **test set**, yalnızca model tamamen eğitildikten ve tüm ayarlamalar tamamlandıktan **sonra** kullanılır; modelin yeni ve görülmemiş verilere genelleme yapabilme yeteneğinin tarafsız bir değerlendirmesini sağlar. Test seti üzerindeki bu nihai değerlendirme, modelin gerçek dünya uygulamalarında nasıl performans göstermesinin beklendiğine dair gerçekçi bir gösterge sunar.

## Classification head

İkili spam classification için modelin artık vocabulary boyutunda output logits değerlerine ihtiyacı yoktur. Son output head'i, iki sınıf logiti üreten bir linear layer ile değiştirin: spam değil (`0`) ve spam (`1`).<sup>[[2]](#references)</sup>
```python
# Replace the final layer with a linear layer that has two outputs
num_classes = 2
model.out_head = torch.nn.Linear(
in_features=BASE_CONFIG["emb_dim"],
out_features=num_classes,
)
```
## Ayarlanacak parametreler

Bu örnekte training cost'u azaltmak için model parametrelerinin çoğunu dondurun ve yalnızca son transformer block'u, final normalization layer'ı ve yeni başlatılmış output head'i fine-tune edin. Bu yaklaşım, önceki layer'lar tarafından öğrenilen genel temsilleri yeniden kullanır ve trainable parametrelerin sayısını büyük ölçüde azaltır; daha fazla layer'ın kilidini açmak, daha yüksek compute ve overfitting maliyeti karşılığında task adaptation'ı artırabilir.<sup>[[1]](#references)[[2]](#references)</sup>
```python
# Freeze all existing model parameters
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():
param.requires_grad = True
```
## Eğitim için kullanılacak girdiler

Önceki bölümlerde, language-model pretraining sırasında modelin dil yapısını öğrenebilmesi için dizi boyunca next-token loss hesaplanıyordu.

Sequence classification için örnekte, classification head üzerinden geçirilen temsil olarak son input position'daki model output'u kullanılır. Loss, bu iki class logit'ini message label ile karşılaştırır; son token'ın kendisinin spam olup olmadığını tahmin etmez.<sup>[[2]](#references)</sup>

Bu işlem [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) içinde şu şekilde uygulanır:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Her batch için yalnızca son input position'daki class logits kullanılır.
