# 7.1. Ajuste fino para clasificación

{{#include ../../banners/hacktricks-training.md}}

## Qué es

El ajuste fino es el proceso de tomar un **modelo pre-entrenado** que ha aprendido **patrones generales del lenguaje** a partir de grandes cantidades de datos y **adaptarlo** para realizar una **tarea específica** o comprender lenguaje específico de un dominio. Esto se logra continuando el entrenamiento del modelo con un conjunto de datos más pequeño y específico para la tarea, lo que le permite ajustar sus parámetros para adaptarse mejor a los matices de los nuevos datos, aprovechando al mismo tiempo el amplio conocimiento que ya ha adquirido. El ajuste fino permite al modelo ofrecer resultados más precisos y relevantes en aplicaciones especializadas sin necesidad de entrenar un modelo nuevo desde cero.

> [!TIP]
> Como pre-entrenar un LLM que "comprenda" el texto es bastante caro, normalmente es más fácil y barato hacer ajuste fino de modelos pre-entrenados open source para que realicen una tarea específica que queramos que realicen.

> [!TIP]
> El objetivo de esta sección es mostrar cómo hacer ajuste fino de un modelo ya pre-entrenado para que, en lugar de generar texto nuevo, el LLM seleccione y proporcione las **probabilidades de que el texto dado sea categorizado en cada una de las categorías indicadas** (por ejemplo, si un texto es spam o no).

## Preparación del conjunto de datos

### Tamaño del conjunto de datos

Por supuesto, para hacer ajuste fino de un modelo se necesitan datos estructurados que se puedan utilizar para especializar el LLM. En el ejemplo propuesto en [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), GPT2 se ajusta para detectar si un email es spam o no utilizando los datos de [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._

Este conjunto de datos contiene muchos más ejemplos de "no spam" que de "spam"; por lo tanto, el libro sugiere **utilizar únicamente tantos ejemplos de "no spam" como de "spam"** (eliminando así del conjunto de datos de entrenamiento todos los ejemplos adicionales). En este caso, eran 747 ejemplos de cada tipo.<sup>[[1]](#references)</sup>

Después, el **70%** del conjunto de datos se utiliza para **entrenamiento**, el **10%** para **validación** y el **20%** para **testing**.

- El **conjunto de validación** se utiliza durante la fase de entrenamiento para ajustar los **hiperparámetros** del modelo y tomar decisiones sobre su arquitectura, ayudando eficazmente a evitar el overfitting al proporcionar feedback sobre cómo funciona el modelo con datos no vistos. Permite realizar mejoras iterativas sin sesgar la evaluación final.
- Esto significa que, aunque los datos incluidos en este conjunto no se utilizan directamente para el entrenamiento, sí se utilizan para ajustar los mejores **hiperparámetros**, por lo que este conjunto no se puede utilizar para evaluar el rendimiento del modelo como se hace con el conjunto de testing.
- En cambio, el **conjunto de testing** se utiliza **únicamente después** de que el modelo se haya entrenado por completo y todos los ajustes se hayan completado; proporciona una evaluación imparcial de la capacidad del modelo para generalizar a datos nuevos y no vistos. Esta evaluación final con el conjunto de testing ofrece una indicación realista de cómo se espera que funcione el modelo en aplicaciones del mundo real.

### Longitud de las entradas

Como el ejemplo de entrenamiento espera entradas (en este caso, textos de emails) de la misma longitud, se decidió hacer que cada entrada tuviera el tamaño de la más grande añadiendo como padding los ids de `<|endoftext|>`.<sup>[[1]](#references)</sup>

### Inicializar el modelo

Utilizando los pesos pre-entrenados open source, inicializa el modelo que se va a entrenar. Ya hemos hecho esto anteriormente y, siguiendo las instrucciones de [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), puedes hacerlo fácilmente.

## Capa de clasificación

En este ejemplo concreto (predecir si un texto es spam o no), no nos interesa hacer ajuste fino según el vocabulario completo de GPT2, sino que solo queremos que el nuevo modelo indique si el email es spam (1) o no (0). Por lo tanto, vamos a **modificar la capa final que** proporciona las probabilidades por token del vocabulario por otra que solo proporcione las probabilidades de que sea spam o no (como si fuera un vocabulario de 2 palabras).<sup>[[1]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## Parámetros que ajustar

Para realizar el fine-tuning rápidamente, es más sencillo no ajustar todos los parámetros, sino solo algunos de los últimos. Esto se debe a que se sabe que las capas inferiores generalmente capturan estructuras y semántica básicas del lenguaje que son aplicables. Por lo tanto, **ajustar solo las últimas capas suele ser suficiente y más rápido**.<sup>[[1]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Entradas que se utilizarán para el entrenamiento

En las secciones anteriores, el LLM se entrenaba reduciendo la pérdida de cada token predicho, aunque casi todos los tokens predichos estaban en la oración de entrada (solo se predecía realmente 1 al final), para que el modelo comprendiera mejor el lenguaje.

En este caso, solo nos importa que el modelo pueda predecir si el modelo es spam o no, por lo que solo nos importa el último token predicho. Por lo tanto, es necesario modificar nuestras funciones de pérdida de entrenamiento anteriores para que solo tengan en cuenta ese token.<sup>[[1]](#references)</sup>

Esto se implementa en [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) de la siguiente manera:
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Ten en cuenta que para cada batch solo nos interesan los **logits del último token predicho**.
