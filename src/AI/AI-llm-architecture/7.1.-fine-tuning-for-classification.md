## यह क्या है

Fine-tuning एक ऐसी प्रक्रिया है जिसमें एक **pre-trained model**, जिसने बहुत बड़ी मात्रा में data से **general language patterns** सीखे हैं, को किसी **specific task** के लिए perform करने या domain-specific language को समझने के लिए **adapt** किया जाता है। यह model की training को एक छोटे, task-specific dataset पर जारी रखकर किया जाता है, जिससे model अपने parameters को नए data की विशेषताओं के अनुसार बेहतर ढंग से समायोजित कर सके और साथ ही पहले से प्राप्त व्यापक knowledge का लाभ उठा सके। Fine-tuning model को specialized applications में अधिक accurate और relevant results देने में सक्षम बनाता है, बिना किसी नए model को शुरुआत से train करने की आवश्यकता के।

> [!TIP]
> ऐसे LLM को pre-train करना जो text को "समझता" हो, काफी महंगा होता है। इसलिए आमतौर पर open source pre-trained models को fine-tune करके उन्हें किसी specific task के लिए perform करवाना आसान और सस्ता होता है।

> [!TIP]
> इस section का goal यह दिखाना है कि पहले से pre-trained model को fine-tune कैसे किया जाए, ताकि text generate करने के बजाय LLM दिए गए text के प्रत्येक category में categorize होने की **probabilities** बताए (जैसे कि कोई text spam है या नहीं)।

## Data set तैयार करना

### Data set का आकार

बेशक, किसी model को fine-tune करने के लिए आपको अपने LLM को specialize करने हेतु कुछ structured data की आवश्यकता होती है। [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) में दिए गए example में, [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._ के data का उपयोग करके GPT2 को यह detect करने के लिए fine-tune किया गया है कि कोई email spam है या नहीं।

इस data set में "spam नहीं" वाले examples की संख्या "spam" वाले examples से काफी अधिक है। इसलिए book में सुझाव दिया गया है कि **"spam नहीं" वाले उतने ही examples का उपयोग किया जाए जितने "spam" वाले examples हैं** (अर्थात training data से सभी अतिरिक्त examples हटा दिए जाएं)। इस case में प्रत्येक के 747 examples थे।<sup>[[1]](#references)</sup>

इसके बाद, data set के **70%** का उपयोग **training** के लिए, **10%** का **validation** के लिए और **20%** का **testing** के लिए किया जाता है।

- **validation set** का उपयोग training phase के दौरान model के **hyperparameters** को fine-tune करने और model architecture से जुड़े decisions लेने के लिए किया जाता है। यह effectively unseen data पर model के performance के बारे में feedback देकर overfitting को रोकने में सहायता करता है। इससे final evaluation को bias किए बिना iterative improvements किए जा सकते हैं।
- इसका अर्थ है कि हालांकि इस data set में शामिल data का उपयोग सीधे training के लिए नहीं किया जाता, लेकिन इसका उपयोग सबसे अच्छे **hyperparameters** को tune करने के लिए किया जाता है। इसलिए इस set का उपयोग model के performance को evaluate करने के लिए testing set की तरह नहीं किया जा सकता।
- इसके विपरीत, **test set** का उपयोग **केवल तब किया जाता है जब** model पूरी तरह train हो चुका हो और सभी adjustments पूरे हो चुके हों। यह नए और unseen data पर generalize करने की model की ability का unbiased assessment प्रदान करता है। Test set पर किया गया यह final evaluation इस बात का realistic indication देता है कि real-world applications में model से कैसा performance अपेक्षित है।

### Entries की length

चूंकि training example में entries (इस case में emails का text) समान length की होने की अपेक्षा की जाती है, इसलिए हर entry को सबसे बड़ी entry के बराबर बड़ा करने का निर्णय लिया गया। इसके लिए `<|endoftext|>` के ids को padding के रूप में जोड़ा गया।<sup>[[1]](#references)</sup>

### Model initialize करना

Open-source pre-trained weights का उपयोग करके train किए जाने वाले model को initialize करें। हम यह पहले कर चुके हैं और [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) के instructions का पालन करके आप इसे आसानी से कर सकते हैं।

## Classification head

इस specific example में (यह predict करना कि कोई text spam है या नहीं), हमें GPT2 की पूरी vocabulary के अनुसार fine-tune करने में रुचि नहीं है। हम केवल यह चाहते हैं कि नया model बताए कि email spam (1) है या नहीं (0)। इसलिए हम **final layer को modify करेंगे, जो** vocabulary के प्रत्येक token की probabilities देती है, और उसकी जगह ऐसी layer लगाएंगे जो केवल spam होने या न होने की probabilities दे (अर्थात 2 words वाली vocabulary जैसी)।<sup>[[1]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## ट्यून करने के लिए Parameters

तेज़ी से fine-tune करने के लिए सभी Parameters को fine-tune न करना, बल्कि केवल कुछ अंतिम Parameters को fine-tune करना आसान होता है। ऐसा इसलिए है क्योंकि यह ज्ञात है कि निचली layers आमतौर पर बुनियादी language structures और लागू होने वाली semantics को capture करती हैं। इसलिए, **अंतिम layers को fine-tune करना आमतौर पर पर्याप्त और तेज़ होता है**।<sup>[[1]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Training के लिए उपयोग की जाने वाली Entries

पिछले sections में LLM को प्रत्येक predicted token के loss को कम करके train किया गया था, भले ही लगभग सभी predicted tokens input sentence में मौजूद थे (अंत में केवल 1 token वास्तव में predict किया गया था), ताकि model भाषा को बेहतर ढंग से समझ सके।

इस मामले में हमें केवल इस बात की परवाह है कि model यह predict कर सके कि input spam है या नहीं, इसलिए हमें केवल अंतिम predicted token की परवाह है। इसलिए, हमारे पिछले training loss functions को इस तरह modify करना आवश्यक है कि वे केवल उस token को ध्यान में रखें।<sup>[[1]](#references)</sup>

इसे [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) में इस प्रकार implement किया गया है:
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
ध्यान दें कि प्रत्येक batch के लिए हमारी रुचि केवल **पूर्वानुमानित अंतिम token के logits** में है।
