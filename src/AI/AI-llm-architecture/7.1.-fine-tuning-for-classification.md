# 7.1. Fine-Tuning pour la classification

{{#include ../../banners/hacktricks-training.md}}

## Qu'est-ce que le Fine-Tuning ?

Le Fine-Tuning est le processus qui consiste à prendre un **modèle pré-entraîné** ayant appris des **schémas linguistiques généraux** à partir de vastes quantités de données et à l'**adapter** pour effectuer une **tâche spécifique** ou comprendre un langage propre à un domaine. Cela est réalisé en poursuivant l'entraînement du modèle sur un jeu de données plus réduit et spécifique à la tâche, ce qui lui permet d'ajuster ses paramètres afin de mieux s'adapter aux nuances des nouvelles données tout en tirant parti des vastes connaissances déjà acquises. Le Fine-Tuning permet au modèle de fournir des résultats plus précis et pertinents dans des applications spécialisées, sans avoir besoin d'entraîner un nouveau modèle à partir de zéro.

> [!TIP]
> Le pré-entraînement d'un LLM est coûteux. Il est donc généralement plus simple et moins cher d'effectuer un Fine-Tuning d'un modèle pré-entraîné open-source pour une tâche spécifique.

> [!TIP]
> Cette section montre comment effectuer le Fine-Tuning d'un modèle pré-entraîné pour la classification. Au lieu de générer du nouveau texte, le modèle renvoie des **logits pour les catégories configurées**, telles que spam et non-spam.<sup>[[1]](#references)[[2]](#references)</sup>

## Préparation du jeu de données

### Taille du jeu de données

Bien sûr, pour effectuer le Fine-Tuning d'un modèle, vous avez besoin de données structurées à utiliser pour spécialiser votre LLM. Dans l'exemple proposé dans [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), GPT2 est fine-tuné pour détecter si un e-mail est un spam ou non, en utilisant les données de [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup>

Ce jeu de données contient beaucoup plus d'exemples « non-spam » que d'exemples « spam ». L'exemple présenté équilibre les classes en conservant le même nombre d'éléments dans chaque classe : 747 exemples de chaque.<sup>[[1]](#references)[[2]](#references)</sup>

L'exemple utilise ensuite **70 %** du jeu de données équilibré pour l'**entraînement**, **10 %** pour la **validation** et **20 %** pour les **tests**.<sup>[[2]](#references)</sup>

- L'**ensemble de validation** est utilisé pendant la phase d'entraînement pour affiner les **hyperparamètres** du modèle et prendre des décisions concernant son architecture, contribuant ainsi à éviter le surapprentissage en fournissant des retours sur les performances du modèle avec des données inédites. Il permet des améliorations itératives sans introduire de biais dans l'évaluation finale.
- Cela signifie que, bien que les données incluses dans cet ensemble de données ne soient pas utilisées directement pour l'entraînement, elles servent à ajuster les meilleurs **hyperparamètres**. Cet ensemble ne peut donc pas être utilisé pour évaluer les performances du modèle comme l'ensemble de test.
- En revanche, l'**ensemble de test** est utilisé **uniquement après** l'entraînement complet du modèle et une fois tous les ajustements terminés ; il fournit une évaluation impartiale de la capacité du modèle à généraliser à de nouvelles données inédites. Cette évaluation finale sur l'ensemble de test donne une indication réaliste des performances attendues du modèle dans des applications concrètes.

### Longueur des entrées

Comme l'exemple d'entraînement attend des entrées (le texte des e-mails dans ce cas) de même longueur, il a été décidé de rendre chaque entrée aussi grande que la plus longue en ajoutant les identifiants de `<|endoftext|>` comme padding.<sup>[[2]](#references)</sup>

### Initialisation du modèle

Initialisez le modèle avec les poids pré-entraînés open-source, en suivant le notebook référencé.<sup>[[2]](#references)</sup>

## Tête de classification

Pour la classification binaire des spams, le modèle n'a plus besoin de logits de sortie de taille égale au vocabulaire. Remplacez la tête de sortie finale par une couche linéaire qui émet deux logits de classe : non-spam (`0`) et spam (`1`).<sup>[[2]](#references)</sup>
```python
# Replace the final layer with a linear layer that has two outputs
num_classes = 2
model.out_head = torch.nn.Linear(
in_features=BASE_CONFIG["emb_dim"],
out_features=num_classes,
)
```
## Paramètres à ajuster

Pour réduire le coût de l'entraînement dans cet exemple, gelez la plupart des paramètres du modèle et effectuez un fine-tuning uniquement du dernier bloc transformer, de la couche de normalisation finale et de la nouvelle output head initialisée. Cela réutilise les représentations générales apprises par les couches précédentes et réduit considérablement le nombre de paramètres entraînables ; dégeler davantage de couches peut permettre une meilleure adaptation à la tâche, au prix d'une augmentation des besoins en calcul et du risque de surapprentissage.<sup>[[1]](#references)[[2]](#references)</sup>
```python
# Freeze all existing model parameters
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():
param.requires_grad = True
```
## Entrées à utiliser pour l'entraînement

Dans les sections précédentes, le préentraînement d'un language model calculait la loss du token suivant sur l'ensemble de la séquence afin que le modèle puisse apprendre la structure du langage.

Pour la classification de séquences, l'exemple utilise la sortie du modèle à la dernière position d'entrée comme représentation transmise à la classification head. La loss compare ces deux logits de classe au label du message ; elle ne prédit pas si le dernier token lui-même est un spam.<sup>[[2]](#references)</sup>

Ceci est implémenté dans [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) comme suit :<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Pour chaque batch, seuls les **logits de classe à la position d’entrée finale** sont utilisés.
