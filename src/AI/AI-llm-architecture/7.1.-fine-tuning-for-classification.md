# 7.1. Fine-Tuning para classificação

{{#include ../../banners/hacktricks-training.md}}

## O que é Fine-Tuning?

Fine-tuning é o processo de usar um **modelo pré-treinado** que aprendeu **padrões gerais de linguagem** a partir de grandes quantidades de dados e **adaptá-lo** para executar uma **tarefa específica** ou compreender linguagem específica de um domínio. Isso é obtido continuando o treinamento do modelo em um conjunto de dados menor e específico da tarefa, permitindo que ele ajuste seus parâmetros para se adequar melhor às nuances dos novos dados, enquanto aproveita o amplo conhecimento que já adquiriu. O fine-tuning permite que o modelo forneça resultados mais precisos e relevantes em aplicações especializadas, sem a necessidade de treinar um novo modelo do zero.

> [!TIP]
> O pré-treinamento de um LLM é caro, portanto, geralmente é mais fácil e barato fazer fine-tuning de um modelo pré-treinado open source para uma tarefa específica.

> [!TIP]
> Esta seção mostra como fazer fine-tuning de um modelo pré-treinado para classificação. Em vez de gerar novo texto, o modelo retorna **logits para as categorias configuradas**, como spam e não spam.<sup>[[1]](#references)[[2]](#references)</sup>

## Preparando o conjunto de dados

### Tamanho do conjunto de dados

Naturalmente, para fazer fine-tuning de um modelo, você precisa de alguns dados estruturados para usar na especialização do seu LLM. No exemplo proposto em [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), o GPT2 é ajustado para detectar se um e-mail é spam ou não usando os dados de [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup>

Esse conjunto de dados contém muito mais exemplos de "não spam" do que de "spam". O exemplo prático equilibra as classes mantendo o mesmo número de cada classe: 747 exemplos de cada uma.<sup>[[1]](#references)[[2]](#references)</sup>

O exemplo então usa **70%** do conjunto de dados equilibrado para **treinamento**, **10%** para **validação** e **20%** para **teste**.<sup>[[2]](#references)</sup>

- O **conjunto de validação** é usado durante a fase de treinamento para ajustar os **hiperparâmetros** do modelo e tomar decisões sobre sua arquitetura, ajudando efetivamente a evitar overfitting ao fornecer feedback sobre o desempenho do modelo em dados não vistos. Ele permite melhorias iterativas sem influenciar a avaliação final.
- Isso significa que, embora os dados incluídos neste conjunto de dados não sejam usados diretamente no treinamento, eles são usados para ajustar os melhores **hiperparâmetros**; portanto, esse conjunto não pode ser usado para avaliar o desempenho do modelo como o conjunto de teste.
- Em contraste, o **conjunto de teste** é usado **somente após** o modelo ter sido completamente treinado e todos os ajustes terem sido concluídos; ele fornece uma avaliação imparcial da capacidade do modelo de generalizar para dados novos e não vistos. Essa avaliação final no conjunto de teste oferece uma indicação realista de como se espera que o modelo funcione em aplicações do mundo real.

### Comprimento da entrada

Como o exemplo de treinamento espera entradas (o texto dos e-mails, neste caso) com o mesmo comprimento, decidiu-se tornar cada entrada tão grande quanto a maior delas, adicionando os ids de `<|endoftext|>` como padding.<sup>[[2]](#references)</sup>

### Inicializar o modelo

Inicialize o modelo com os pesos pré-treinados open source, seguindo o notebook referenciado.<sup>[[2]](#references)</sup>

## Cabeçalho de classificação

Para a classificação binária de spam, o modelo não precisa mais de logits de saída do tamanho do vocabulário. Substitua o cabeçalho de saída final por uma camada linear que emita dois logits de classe: não spam (`0`) e spam (`1`).<sup>[[2]](#references)</sup>
```python
# Replace the final layer with a linear layer that has two outputs
num_classes = 2
model.out_head = torch.nn.Linear(
in_features=BASE_CONFIG["emb_dim"],
out_features=num_classes,
)
```
## Parâmetros a ajustar

Para reduzir o custo de treinamento neste exemplo, congele a maioria dos parâmetros do modelo e faça fine-tuning apenas do último bloco transformer, da camada de normalização final e da output head recém-inicializada. Isso reutiliza as representações gerais aprendidas pelas camadas anteriores e reduz significativamente o número de parâmetros treináveis; descongelar mais camadas pode proporcionar uma adaptação maior à tarefa, ao custo de um maior uso de recursos computacionais e risco de overfitting.<sup>[[1]](#references)[[2]](#references)</sup>
```python
# Freeze all existing model parameters
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():
param.requires_grad = True
```
## Entradas a serem usadas para treinamento

Nas seções anteriores, o pretraining de language models calculava a loss do próximo token ao longo da sequência para que o modelo pudesse aprender a estrutura da linguagem.

Para a classificação de sequências, o exemplo usa a saída do modelo na posição de entrada final como a representação passada pela classification head. A loss compara esses dois logits de classe com o rótulo da mensagem; ela não prevê se o próprio token final é spam.<sup>[[2]](#references)</sup>

Isso é implementado em [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) como:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Para cada batch, somente os **logits de classe na posição final da entrada** são usados.
