# 7.1. 分類のためのFine-Tuning

{{#include ../../banners/hacktricks-training.md}}

## 概要

Fine-tuningとは、膨大なデータから**一般的な言語パターン**を学習した**pre-trained model**を取り上げ、**特定のタスク**を実行したり、特定のドメインの言語を理解したりできるように**適応**させるプロセスです。これは、タスク固有の小規模なデータセットを使用してモデルのトレーニングを継続し、すでに獲得している幅広い知識を活用しながら、新しいデータの特徴により適合するようパラメータを調整することで実現します。Fine-tuningにより、新しいモデルをゼロからトレーニングする必要なく、専門的な用途でより正確かつ関連性の高い結果をモデルに提供させることができます。

> [!TIP]
> テキストを「理解する」LLMのpre-trainingは非常に高コストであるため、特定のタスクを実行できるよう、open sourceのpre-trained modelをFine-tuningする方が、通常は簡単かつ安価です。

> [!TIP]
> このセクションの目的は、すでにpre-trainedされたモデルをFine-tuningし、新しいテキストを生成する代わりに、LLMが**与えられたテキストが各カテゴリに分類される確率**（テキストがspamかどうかなど）を選択して示す方法を説明することです。

## データセットの準備

### データセットのサイズ

当然ながら、モデルをFine-tuningするには、LLMを特化させるための構造化データが必要です。[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb)で提案されている例では、[https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup>のデータを使用して、メールがspamかどうかを検出するようGPT2をFine-tuningしています。

このデータセットには「spam」よりも「not spam」の例がはるかに多く含まれています。そのため、この書籍では、**「spam」と同数の「not spam」の例だけを使用する**ことを推奨しています（つまり、余分な例をすべてトレーニングデータから削除します）。この場合、それぞれ747例でした。<sup>[[2]](#references)[[1]](#references)</sup>

次に、データセットの**70%**を**training**、**10%**を**validation**、**20%**を**testing**に使用します。

- **validation set**はtrainingフェーズ中に使用され、モデルの**hyperparameters**をFine-tuningし、モデルアーキテクチャに関する判断を行います。これは、モデルが未知のデータに対してどのように動作するかについてフィードバックを提供することで、overfittingの防止に役立ちます。また、最終評価にバイアスをかけずに反復的な改善を可能にします。
- つまり、このデータセットに含まれるデータはtrainingに直接使用されませんが、最適な**hyperparameters**の調整に使用されるため、このセットはtesting setのようにモデルの性能評価に使用できません。
- 一方、**test set**は、モデルのtrainingが完全に完了し、すべての調整が終了した**後にのみ**使用されます。これは、未知の新しいデータに対するモデルの汎化能力を偏りなく評価するためのものです。test setで行うこの最終評価により、実際のアプリケーションでモデルがどの程度の性能を発揮すると予想されるかを現実的に把握できます。

### エントリの長さ

training exampleでは同じ長さのエントリ（この場合はメール本文）が必要となるため、`<|endoftext|>`のIDをpaddingとして追加し、すべてのエントリを最も長いエントリと同じサイズにすることにしました。<sup>[[2]](#references)</sup>

### モデルの初期化

open sourceのpre-trained weightsを使用して、trainingするモデルを初期化します。これは以前にも行っており、[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb)の手順に従えば簡単に実行できます。<sup>[[2]](#references)</sup>

## Classification head

この具体例（テキストがspamかどうかを予測する場合）では、GPT2の完全な語彙に基づいてFine-tuningすることには関心がなく、新しいモデルにメールがspam（1）か、そうでないか（0）だけを示させたいと考えています。したがって、語彙内の各tokenの確率を出力する**final layer**を、spamである確率またはspamでない確率だけを出力するもの（2単語の語彙のようなもの）に**modify**します。<sup>[[2]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## チューニングするパラメータ

高速に fine-tune するには、すべてのパラメータを fine-tune するのではなく、最後のいくつかのパラメータだけを対象にするほうが簡単です。これは、下位層が一般的に、適用可能な基本的な言語構造や意味論を捉えていることが知られているためです。そのため、**通常は最後の層だけを fine-tune すれば十分で、処理も高速になります**。<sup>[[2]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## トレーニングに使用するエントリ

前のセクションでは、モデルが言語をより適切に理解できるように、予測されたほぼすべての token が入力文に含まれていたにもかかわらず（末尾の 1 つだけが実際に予測された）、予測されたすべての token の loss を減らすことで LLM をトレーニングしました。

この場合、私たちが重視するのは、モデルが入力が spam かどうかを予測できることだけなので、最後に予測された token のみを考慮します。したがって、その token だけを考慮するように、以前の training loss functions を変更する必要があります。

これは、[https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) で次のように実装されています。<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
各バッチでは、**予測された最後のトークンの logits のみ**に関心がある点に注目してください。
