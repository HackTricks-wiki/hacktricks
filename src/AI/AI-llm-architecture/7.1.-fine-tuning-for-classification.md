# 7.1. Classification을 위한 Fine-Tuning

{{#include ../../banners/hacktricks-training.md}}

## 개요

Fine-tuning은 방대한 양의 데이터에서 **일반적인 언어 패턴**을 학습한 **pre-trained model**을 가져와 **특정 작업**을 수행하거나 도메인별 언어를 이해하도록 **조정**하는 과정입니다. 이는 더 작은 작업별 데이터 세트로 모델을 계속 학습시켜 수행하며, 모델이 이미 습득한 폭넓은 지식을 활용하면서 새로운 데이터의 특성에 더 적합하도록 파라미터를 조정할 수 있게 합니다. Fine-tuning을 사용하면 새로운 모델을 처음부터 학습할 필요 없이 전문 애플리케이션에서 더 정확하고 관련성 높은 결과를 제공할 수 있습니다.

> [!TIP]
> 텍스트를 "이해하는" LLM을 pre-training하는 데는 상당한 비용이 들기 때문에, 일반적으로 특정 작업을 수행하도록 open source pre-trained model을 fine-tune하는 것이 더 쉽고 저렴합니다.

> [!TIP]
> 이 섹션의 목표는 이미 pre-trained된 모델을 fine-tune하여 새로운 텍스트를 생성하는 대신 LLM이 **주어진 텍스트가 각 주어진 카테고리로 분류될 확률**을 선택해 제공하도록 하는 방법을 보여주는 것입니다(예: 텍스트가 spam인지 아닌지).

## 데이터 세트 준비

### 데이터 세트 크기

물론 모델을 fine-tune하려면 LLM을 특화하는 데 사용할 구조화된 데이터가 필요합니다. [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb)에서 제안하는 예제에서는 [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._의 데이터를 사용하여 GPT2를 이메일이 spam인지 아닌지 탐지하도록 fine-tune합니다.

이 데이터 세트에는 "spam"보다 "not spam"의 예제가 훨씬 더 많이 포함되어 있으므로, 책에서는 **"spam"의 예제 수만큼만 "not spam"의 예제를 사용하도록** 제안합니다(따라서 학습 데이터에서 추가 예제를 모두 제거합니다). 이 경우 각각 747개의 예제가 사용되었습니다.<sup>[[1]](#references)</sup>

그런 다음 데이터 세트의 **70%**는 **training**, **10%**는 **validation**, **20%**는 **testing**에 사용됩니다.

- **validation set**은 training 단계에서 모델의 **hyperparameters**를 fine-tune하고 모델 아키텍처에 관한 결정을 내리는 데 사용됩니다. 또한 모델이 보지 못한 데이터에서 어떻게 동작하는지에 대한 피드백을 제공하여 overfitting을 방지하는 데 효과적으로 도움을 줍니다. 이를 통해 최종 평가에 편향을 주지 않고 반복적으로 개선할 수 있습니다.
- 즉, 이 데이터 세트에 포함된 데이터는 training에 직접 사용되지는 않지만 최적의 **hyperparameters**를 조정하는 데 사용되므로, testing set처럼 모델의 성능을 평가하는 데 사용할 수 없습니다.
- 반면 **test set**은 모델이 완전히 학습되고 모든 조정이 완료된 **후에만** 사용됩니다. test set은 새롭고 보지 못한 데이터에 일반화하는 모델의 능력을 편향 없이 평가합니다. test set에 대한 이 최종 평가는 실제 애플리케이션에서 모델이 어떻게 동작할 것으로 예상되는지 현실적으로 보여줍니다.

### 항목 길이

training 예제에서는 항목(이 경우 이메일 텍스트)이 동일한 길이여야 하므로, `<|endoftext|>`의 id를 padding으로 추가하여 모든 항목을 가장 긴 항목과 동일한 크기로 만들기로 했습니다.<sup>[[1]](#references)</sup>

### 모델 초기화

open-source pre-trained weights를 사용하여 학습할 모델을 초기화합니다. 이전에 이미 이 작업을 수행했으며, [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb)의 지침을 따르면 쉽게 수행할 수 있습니다.

## Classification head

이 특정 예제(텍스트가 spam인지 예측하는 경우)에서는 GPT2의 전체 vocabulary에 따라 fine-tune하는 데 관심이 없으며, 새로운 모델이 이메일이 spam인지(1) 아닌지(0)만 알려주기를 원합니다. 따라서 vocabulary의 각 token에 대한 확률을 제공하는 **final layer를 수정하여**, spam인지 아닌지에 대한 확률만 제공하도록 할 것입니다(즉, 2개 단어로 이루어진 vocabulary와 같은 형태입니다).<sup>[[1]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## 조정할 Parameters

빠르게 fine-tuning하려면 모든 parameters를 fine-tuning하지 않고 마지막 일부만 조정하는 것이 더 쉽습니다. 일반적으로 하위 layers가 적용 가능한 기본적인 언어 구조와 semantics를 포착한다는 사실이 알려져 있기 때문입니다. 따라서 **마지막 layers만 fine-tuning하는 것으로 충분한 경우가 많으며 더 빠릅니다**.<sup>[[1]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Training에 사용할 Entries

이전 섹션에서는 모델이 언어를 더 잘 이해하도록 하기 위해, 예측된 거의 모든 token이 입력 문장에 포함되어 있었음에도 불구하고(끝부분의 1개만 실제로 예측됨) 모든 예측 token의 loss를 줄이는 방식으로 LLM을 training했습니다.

이 경우에는 모델이 해당 모델이 spam인지 아닌지만 예측할 수 있으면 되므로, 마지막에 예측된 token에만 관심이 있습니다. 따라서 이전 training loss functions를 해당 token만 고려하도록 수정해야 합니다.<sup>[[1]](#references)</sup>

이는 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb)에서 다음과 같이 구현됩니다:
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
각 batch에서는 예측된 **마지막 토큰의 logits만** 관심 대상이라는 점에 유의하세요.
