## Fine-Tuning이란?

Fine-tuning은 방대한 양의 데이터에서 **일반적인 언어 패턴**을 학습한 **pre-trained model**을 가져와 **특정 작업**을 수행하거나 도메인별 언어를 이해하도록 **조정**하는 과정입니다. 이는 더 작은 작업별 데이터 세트로 모델을 계속 학습시켜 수행하며, 이미 습득한 광범위한 지식을 활용하면서 새로운 데이터의 특성에 더 잘 맞도록 매개변수를 조정할 수 있게 합니다. Fine-tuning을 사용하면 새로운 모델을 처음부터 학습할 필요 없이 전문 애플리케이션에서 더 정확하고 관련성 높은 결과를 제공할 수 있습니다.

> [!TIP]
> LLM을 pre-training하는 작업은 비용이 많이 들기 때문에, 특정 작업을 위해 open-source pretrained model을 fine-tune하는 것이 일반적으로 더 쉽고 저렴합니다.

> [!TIP]
> 이 섹션에서는 classification을 위해 pretrained model을 fine-tune하는 방법을 보여 줍니다. 새로운 텍스트를 생성하는 대신, 모델은 spam 및 not spam과 같이 구성된 카테고리에 대한 **logits**를 반환합니다.<sup>[[1]](#references)[[2]](#references)</sup>

## 데이터 세트 준비

### 데이터 세트 크기

물론 모델을 fine-tune하려면 LLM을 특화하는 데 사용할 구조화된 데이터가 필요합니다. [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb)에 제시된 예제에서는 [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)의 데이터를 사용해 이메일이 spam인지 아닌지를 감지하도록 GPT2를 fine-tune합니다._._<sup>[[2]](#references)[[3]](#references)</sup>

이 데이터 세트에는 "spam" 예제보다 "not spam" 예제가 훨씬 더 많이 포함되어 있습니다. 예제에서는 각 클래스에서 동일한 수를 유지하여 클래스 간 균형을 맞춥니다. 즉, 각 클래스에서 747개의 예제를 사용합니다.<sup>[[1]](#references)[[2]](#references)</sup>

그 다음 예제에서는 균형이 맞춰진 데이터 세트의 **70%**를 **training**, **10%**를 **validation**, **20%**를 **testing**에 사용합니다.<sup>[[2]](#references)</sup>

- **validation set**은 training 단계에서 모델의 **hyperparameters**를 fine-tune하고 모델 아키텍처에 관한 결정을 내리는 데 사용됩니다. 이는 모델이 보지 못한 데이터에서 어떻게 동작하는지에 대한 피드백을 제공하여 overfitting을 방지하는 데 효과적으로 도움을 줍니다. 또한 최종 평가에 편향을 주지 않으면서 반복적으로 개선할 수 있게 합니다.
- 즉, 이 데이터 세트에 포함된 데이터는 training에 직접 사용되지는 않지만 최적의 **hyperparameters**를 조정하는 데 사용되므로, 이 세트는 testing 세트처럼 모델의 성능을 평가하는 데 사용할 수 없습니다.
- 반면 **test set**은 모델이 완전히 training되고 모든 조정이 끝난 **후에만** 사용됩니다. test set은 새롭고 보지 못한 데이터에 일반화하는 모델의 능력을 편향 없이 평가합니다. test set을 사용한 이 최종 평가는 실제 애플리케이션에서 모델이 어떻게 동작할 것으로 예상되는지 현실적인 지표를 제공합니다.

### Entry Length

training 예제에서는 동일한 길이의 항목(이 경우 이메일 텍스트)을 필요로 하므로, `<|endoftext|>`의 id를 padding으로 추가하여 모든 항목을 가장 긴 항목과 같은 크기로 만들기로 했습니다.<sup>[[2]](#references)</sup>

## Classification head

Binary spam classification에서는 더 이상 vocabulary 크기에 해당하는 output logits가 필요하지 않습니다. 최종 output head를 두 개의 class logits를 출력하는 linear layer로 교체합니다. not spam(`0`) 및 spam(`1`)입니다.<sup>[[2]](#references)</sup>
```python
# Replace the final layer with a linear layer that has two outputs
num_classes = 2
model.out_head = torch.nn.Linear(
in_features=BASE_CONFIG["emb_dim"],
out_features=num_classes,
)
```
## 조정할 Parameters

이 예제에서는 training cost를 줄이기 위해 대부분의 model parameters를 freeze하고, 마지막 transformer block, final normalization layer 및 새로 초기화된 output head만 fine-tune합니다. 이렇게 하면 이전 layer에서 학습한 일반적인 representations를 재사용하면서 trainable parameters 수를 크게 줄일 수 있습니다. 더 많은 layer를 unfreeze하면 compute 및 overfitting cost가 증가하지만 task adaptation을 향상할 수 있습니다.<sup>[[1]](#references)[[2]](#references)</sup>
```python
# Freeze all existing model parameters
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():
param.requires_grad = True
```
## 학습에 사용할 항목

이전 섹션에서는 language-model pretraining을 통해 시퀀스 전체에 걸쳐 next-token loss를 계산했으므로, 모델이 언어 구조를 학습할 수 있었습니다.

sequence classification에서는 예제에서 마지막 입력 위치의 model output을 classification head를 통해 전달되는 representation으로 사용합니다. loss는 해당 두 class logits를 message label과 비교하며, 마지막 token 자체가 spam인지 예측하는 것이 아닙니다.<sup>[[2]](#references)</sup>

이는 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb)에서 다음과 같이 구현됩니다:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
각 batch에서는 최종 입력 위치의 **class logits만** 사용됩니다.
