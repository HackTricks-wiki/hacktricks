# 7.1. Fine-Tuning για Classification

{{#include ../../banners/hacktricks-training.md}}

## Τι είναι το Fine-Tuning;

Το fine-tuning είναι η διαδικασία κατά την οποία λαμβάνεται ένα **pre-trained model** που έχει μάθει **γενικά γλωσσικά μοτίβα** από τεράστιες ποσότητες δεδομένων και **προσαρμόζεται** ώστε να εκτελεί μια **συγκεκριμένη εργασία** ή να κατανοεί γλώσσα συγκεκριμένου domain. Αυτό επιτυγχάνεται με τη συνέχιση της εκπαίδευσης του model σε ένα μικρότερο dataset ειδικά για τη συγκεκριμένη εργασία, επιτρέποντάς του να προσαρμόσει τις παραμέτρους του ώστε να ανταποκρίνεται καλύτερα στις ιδιαιτερότητες των νέων δεδομένων, αξιοποιώντας παράλληλα τις ευρείες γνώσεις που έχει ήδη αποκτήσει. Το fine-tuning επιτρέπει στο model να παρέχει ακριβέστερα και πιο σχετικά αποτελέσματα σε εξειδικευμένες εφαρμογές, χωρίς να απαιτείται η εκπαίδευση ενός νέου model από την αρχή.

> [!TIP]
> Η προ-εκπαίδευση ενός LLM είναι ακριβή, επομένως συνήθως είναι ευκολότερο και φθηνότερο να γίνει fine-tuning ενός open-source pretrained model για μια συγκεκριμένη εργασία.

> [!TIP]
> Αυτή η ενότητα δείχνει πώς γίνεται fine-tuning ενός pretrained model για classification. Αντί να παράγει νέο κείμενο, το model επιστρέφει **logits για τις ρυθμισμένες κατηγορίες**, όπως spam και not spam.<sup>[[1]](#references)[[2]](#references)</sup>

## Προετοιμασία του data set

### Μέγεθος data set

Φυσικά, για να κάνετε fine-tuning σε ένα model χρειάζεστε κάποια δομημένα δεδομένα, ώστε να εξειδικεύσετε το LLM σας. Στο παράδειγμα που προτείνεται στο [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), το GPT2 υποβάλλεται σε fine-tuning για να ανιχνεύει αν ένα email είναι spam ή not spam, χρησιμοποιώντας τα δεδομένα από το [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup>

Αυτό το dataset περιέχει πολύ περισσότερα παραδείγματα "not spam" από παραδείγματα "spam". Το παράδειγμα εξισορροπεί τις κατηγορίες, διατηρώντας τον ίδιο αριθμό από κάθε κατηγορία: 747 παραδείγματα από την καθεμία.<sup>[[1]](#references)[[2]](#references)</sup>

Στη συνέχεια, το παράδειγμα χρησιμοποιεί το **70%** του εξισορροπημένου dataset για **training**, το **10%** για **validation** και το **20%** για **testing**.<sup>[[2]](#references)</sup>

- Το **validation set** χρησιμοποιείται κατά τη φάση του training για fine-tuning των **hyperparameters** του model και για τη λήψη αποφάσεων σχετικά με την αρχιτεκτονική του model. Έτσι, βοηθά στην αποτροπή του overfitting, παρέχοντας feedback σχετικά με την απόδοση του model σε δεδομένα που δεν έχει δει. Επιτρέπει επαναληπτικές βελτιώσεις χωρίς να επηρεάζεται η τελική αξιολόγηση.
- Αυτό σημαίνει ότι, παρόλο που τα δεδομένα που περιλαμβάνονται σε αυτό το data set δεν χρησιμοποιούνται άμεσα για το training, χρησιμοποιούνται για τη ρύθμιση των βέλτιστων **hyperparameters**. Επομένως, αυτό το set δεν μπορεί να χρησιμοποιηθεί για την αξιολόγηση της απόδοσης του model, όπως το testing set.
- Αντίθετα, το **test set** χρησιμοποιείται **μόνο μετά** την πλήρη εκπαίδευση του model και την ολοκλήρωση όλων των προσαρμογών. Παρέχει μια αμερόληπτη αξιολόγηση της ικανότητας του model να γενικεύει σε νέα, άγνωστα δεδομένα. Αυτή η τελική αξιολόγηση στο test set δείχνει ρεαλιστικά τον τρόπο με τον οποίο αναμένεται να αποδίδει το model σε εφαρμογές πραγματικού κόσμου.

## Classification head

Για binary spam classification, το model δεν χρειάζεται πλέον output logits μεγέθους ίσου με το vocabulary. Αντικαταστήστε το τελικό output head με ένα linear layer που εκπέμπει δύο class logits: not spam (`0`) και spam (`1`).<sup>[[2]](#references)</sup>
```python
# Replace the final layer with a linear layer that has two outputs
num_classes = 2
model.out_head = torch.nn.Linear(
in_features=BASE_CONFIG["emb_dim"],
out_features=num_classes,
)
```
## Παράμετροι προς ρύθμιση

Για να μειώσουμε το κόστος εκπαίδευσης σε αυτό το παράδειγμα, παγώνουμε τις περισσότερες παραμέτρους του μοντέλου και κάνουμε fine-tune μόνο στο τελευταίο transformer block, στο τελικό normalization layer και στο πρόσφατα αρχικοποιημένο output head. Έτσι αξιοποιούνται ξανά οι γενικές αναπαραστάσεις που έμαθαν τα προηγούμενα layers και μειώνεται σημαντικά ο αριθμός των εκπαιδεύσιμων παραμέτρων· η αποδέσμευση περισσότερων layers μπορεί να προσφέρει μεγαλύτερη προσαρμογή στην εργασία, με υψηλότερο κόστος υπολογιστικών πόρων και overfitting.<sup>[[1]](#references)[[2]](#references)</sup>
```python
# Freeze all existing model parameters
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():
param.requires_grad = True
```
## Καταχωρίσεις για χρήση στην εκπαίδευση

Σε προηγούμενες ενότητες, η προεκπαίδευση του language model υπολόγιζε την απώλεια του επόμενου token σε ολόκληρη την ακολουθία, ώστε το μοντέλο να μπορεί να μάθει τη δομή της γλώσσας.

Για την ταξινόμηση ακολουθιών, το παράδειγμα χρησιμοποιεί την έξοδο του μοντέλου στην τελική θέση εισόδου ως αναπαράσταση που περνά από την κεφαλή ταξινόμησης. Η απώλεια συγκρίνει αυτά τα δύο logits κλάσεων με την ετικέτα του μηνύματος· δεν προβλέπει αν το ίδιο το τελικό token είναι spam.<sup>[[2]](#references)</sup>

Αυτό υλοποιείται στο [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) ως εξής:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Για κάθε batch, χρησιμοποιούνται μόνο τα **class logits στην τελική θέση εισόδου**.
