# 7.1. Fine-Tuning za klasifikaciju

## Šta je Fine-Tuning?

Fine-tuning je proces uzimanja **pretrained modela** koji je naučio **opšte jezičke obrasce** iz ogromnih količina podataka i **prilagođavanja** tog modela za obavljanje **određenog zadatka** ili razumevanje jezika specifičnog za određeni domen. To se postiže nastavkom treniranja modela na manjem skupu podataka specifičnom za zadatak, čime mu se omogućava da prilagodi svoje parametre kako bi bolje odgovarao nijansama novih podataka, uz istovremeno korišćenje širokog znanja koje je već stekao. Fine-tuning omogućava modelu da pruža preciznije i relevantnije rezultate u specijalizovanim primenama, bez potrebe za treniranjem novog modela od nule.

> [!TIP]
> Pre-training LLM-a je skup, pa je obično jednostavnije i jeftinije izvršiti fine-tuning open-source pretrained modela za određeni zadatak.

> [!TIP]
> Ovaj odeljak prikazuje kako da izvršite fine-tuning pretrained modela za klasifikaciju. Umesto generisanja novog teksta, model vraća **logits za konfigurisane kategorije**, kao što su spam i nije spam.<sup>[[1]](#references)[[2]](#references)</sup>

## Priprema skupa podataka

### Veličina skupa podataka

Naravno, da biste izvršili fine-tuning modela, potrebni su vam strukturirani podaci koje možete koristiti za specijalizaciju svog LLM-a. U primeru predloženom u [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), GPT2 je fine-tuned da detektuje da li je email spam ili nije, koristeći podatke iz [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup>

Ovaj skup podataka sadrži mnogo više primera koji nisu spam nego primera spam poruka. Obrađeni primer uravnotežava klase tako što zadržava isti broj primera iz svake klase: po 747 primera iz svake klase.<sup>[[1]](#references)[[2]](#references)</sup>

Primer zatim koristi **70%** uravnoteženog skupa podataka za **treniranje**, **10%** za **validaciju** i **20%** za **testiranje**.<sup>[[2]](#references)</sup>

- **Validacioni skup** se koristi tokom faze treniranja za fine-tuning **hiperparametara** modela i donošenje odluka o arhitekturi modela, čime efektivno pomaže u sprečavanju overfittinga pružanjem povratnih informacija o tome kako model radi na neviđenim podacima. Omogućava iterativna poboljšanja bez uticaja na konačnu evaluaciju.
- To znači da, iako podaci uključeni u ovaj skup podataka nisu direktno korišćeni za treniranje, koriste se za podešavanje najboljih **hiperparametara**, pa se ovaj skup ne može koristiti za procenu performansi modela na isti način kao testni skup.
- Nasuprot tome, **testni skup** se koristi **tek nakon** što je model u potpunosti istreniran i kada su sva podešavanja završena; on pruža nepristrasnu procenu sposobnosti modela da generalizuje na nove, neviđene podatke. Ova konačna evaluacija na testnom skupu daje realističan pokazatelj očekivanih performansi modela u primenama iz stvarnog sveta.

## Klasifikaciona glava

Za binarnu klasifikaciju spam poruka, modelu više nisu potrebni izlazni logits veličine vokabulara. Zamenite završnu izlaznu glavu linearnim slojem koji emituje dva logita klasa: nije spam (`0`) i spam (`1`).<sup>[[2]](#references)</sup>
```python
# Replace the final layer with a linear layer that has two outputs
num_classes = 2
model.out_head = torch.nn.Linear(
in_features=BASE_CONFIG["emb_dim"],
out_features=num_classes,
)
```
## Parametri za podešavanje

Da bi se smanjili troškovi treniranja u ovom primeru, zamrznite većinu parametara modela i fino podešavajte samo poslednji transformer blok, završni normalizacioni sloj i novoinicijalizovanu izlaznu glavu. Na ovaj način ponovo se koriste opšte reprezentacije naučene u ranijim slojevima i značajno se smanjuje broj parametara koji se treniraju; odmrzavanje većeg broja slojeva može omogućiti bolju adaptaciju zadatku, uz veće troškove izračunavanja i rizik od overfittinga.<sup>[[1]](#references)[[2]](#references)</sup>
```python
# Freeze all existing model parameters
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():
param.requires_grad = True
```
## Unosi koji se koriste za obuku

U prethodnim odeljcima, pretreniranje jezičkog modela izračunavalo je gubitak sledećeg tokena kroz celu sekvencu, kako bi model mogao da nauči strukturu jezika.

Za klasifikaciju sekvenci, primer koristi izlaz modela na poslednjoj poziciji ulaza kao reprezentaciju koja se prosleđuje kroz classification head. Gubitak upoređuje ta dva class logit-a sa oznakom poruke; on ne predviđa da li je sam poslednji token spam.<sup>[[2]](#references)</sup>

Ovo je implementirano u [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) na sledeći način:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Za svaki batch koriste se samo **class logits** na konačnoj poziciji ulaza.
