# 7.1. Fine-Tuning για Classification

{{#include ../../banners/hacktricks-training.md}}

## Τι είναι

Το Fine-tuning είναι η διαδικασία κατά την οποία λαμβάνεται ένα **pre-trained model** που έχει μάθει **γενικά γλωσσικά μοτίβα** από τεράστιες ποσότητες δεδομένων και **προσαρμόζεται** ώστε να εκτελεί μια **συγκεκριμένη εργασία** ή να κατανοεί γλώσσα που αφορά έναν συγκεκριμένο τομέα. Αυτό επιτυγχάνεται συνεχίζοντας την εκπαίδευση του μοντέλου σε ένα μικρότερο dataset ειδικά σχεδιασμένο για τη συγκεκριμένη εργασία, επιτρέποντάς του να προσαρμόσει τις παραμέτρους του ώστε να ανταποκρίνεται καλύτερα στις ιδιαιτερότητες των νέων δεδομένων, αξιοποιώντας παράλληλα την ευρεία γνώση που έχει ήδη αποκτήσει. Το Fine-tuning επιτρέπει στο μοντέλο να παρέχει πιο ακριβή και σχετικά αποτελέσματα σε εξειδικευμένες εφαρμογές, χωρίς να απαιτείται η εκπαίδευση ενός νέου μοντέλου από την αρχή.

> [!TIP]
> Καθώς η προ-εκπαίδευση ενός LLM που «κατανοεί» το κείμενο είναι αρκετά ακριβή, συνήθως είναι ευκολότερο και φθηνότερο να γίνει Fine-tuning σε open source pre-trained models, ώστε να εκτελούν μια συγκεκριμένη εργασία που θέλουμε.

> [!TIP]
> Ο στόχος αυτής της ενότητας είναι να δείξει πώς γίνεται Fine-tuning σε ένα ήδη pre-trained model, ώστε αντί να παράγει νέο κείμενο, το LLM να επιλέγει και να δίνει τις **πιθανότητες του δεδομένου κειμένου να κατηγοριοποιηθεί σε καθεμία από τις δεδομένες κατηγορίες** (όπως το αν ένα κείμενο είναι spam ή όχι).

## Προετοιμασία του data set

### Μέγεθος του data set

Φυσικά, για να γίνει Fine-tuning ενός μοντέλου χρειάζεστε κάποια δομημένα δεδομένα που θα χρησιμοποιήσετε για να εξειδικεύσετε το LLM σας. Στο παράδειγμα που προτείνεται στο [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), το GPT2 γίνεται fine-tuned ώστε να ανιχνεύει αν ένα email είναι spam ή όχι, χρησιμοποιώντας τα δεδομένα από το [https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip](https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip)_._<sup>[[2]](#references)[[3]](#references)</sup>

Αυτό το data set περιέχει πολύ περισσότερα παραδείγματα «not spam» από ό,τι «spam». Επομένως, το βιβλίο προτείνει να **χρησιμοποιούνται μόνο τόσα παραδείγματα «not spam» όσα και «spam»** (άρα να αφαιρούνται από τα training data όλα τα επιπλέον παραδείγματα). Σε αυτή την περίπτωση, ήταν 747 παραδείγματα από κάθε κατηγορία.<sup>[[2]](#references)[[1]](#references)</sup>

Στη συνέχεια, το **70%** του data set χρησιμοποιείται για **training**, το **10%** για **validation** και το **20%** για **testing**.

- Το **validation set** χρησιμοποιείται κατά τη φάση του training για το Fine-tuning των **hyperparameters** του μοντέλου και για τη λήψη αποφάσεων σχετικά με την αρχιτεκτονική του μοντέλου, βοηθώντας ουσιαστικά στην αποτροπή του overfitting, παρέχοντας feedback σχετικά με την απόδοση του μοντέλου σε δεδομένα που δεν έχει δει. Επιτρέπει επαναληπτικές βελτιώσεις χωρίς να επηρεάζεται η τελική αξιολόγηση.
- Αυτό σημαίνει ότι, παρόλο που τα δεδομένα που περιλαμβάνονται σε αυτό το data set δεν χρησιμοποιούνται άμεσα για το training, χρησιμοποιούνται για τη ρύθμιση των καλύτερων **hyperparameters**. Επομένως, αυτό το set δεν μπορεί να χρησιμοποιηθεί για την αξιολόγηση της απόδοσης του μοντέλου, όπως το testing set.
- Αντίθετα, το **test set** χρησιμοποιείται **μόνο αφού** το μοντέλο έχει εκπαιδευτεί πλήρως και έχουν ολοκληρωθεί όλες οι προσαρμογές. Παρέχει μια αμερόληπτη αξιολόγηση της ικανότητας του μοντέλου να γενικεύει σε νέα δεδομένα που δεν έχει δει. Αυτή η τελική αξιολόγηση στο test set παρέχει μια ρεαλιστική ένδειξη του τρόπου με τον οποίο αναμένεται να αποδίδει το μοντέλο σε εφαρμογές του πραγματικού κόσμου.

### Μήκος των entries

Καθώς το training example απαιτεί entries (σε αυτή την περίπτωση, το κείμενο των emails) ίδιου μήκους, αποφασίστηκε κάθε entry να έχει το μέγεθος του μεγαλύτερου, με την προσθήκη των ids του `<|endoftext|>` ως padding.<sup>[[2]](#references)</sup>

### Αρχικοποίηση του μοντέλου

Χρησιμοποιώντας τα open-source pre-trained weights, αρχικοποιήστε το μοντέλο για training. Το έχουμε ήδη κάνει στο παρελθόν και, ακολουθώντας τις οδηγίες του [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb), μπορείτε εύκολα να το κάνετε.<sup>[[2]](#references)</sup>

## Classification head

Σε αυτό το συγκεκριμένο παράδειγμα (πρόβλεψη για το αν ένα κείμενο είναι spam ή όχι), δεν μας ενδιαφέρει να κάνουμε Fine-tuning σύμφωνα με ολόκληρο το vocabulary του GPT2, αλλά θέλουμε το νέο μοντέλο απλώς να δηλώνει αν το email είναι spam (1) ή όχι (0). Επομένως, πρόκειται να **τροποποιήσουμε το τελικό layer που** δίνει τις πιθανότητες ανά token του vocabulary, αντικαθιστώντας το με ένα που δίνει μόνο τις πιθανότητες το email να είναι spam ή όχι (κάτι σαν vocabulary 2 λέξεων).<sup>[[2]](#references)</sup>
```python
# This code modified the final layer with a Linear one with 2 outs
num_classes = 2
model.out_head = torch.nn.Linear(

in_features=BASE_CONFIG["emb_dim"],

out_features=num_classes
)
```
## Παράμετροι προς ρύθμιση

Για να εκτελέσουμε fine tuning γρήγορα, είναι ευκολότερο να μην ρυθμίσουμε όλες τις παραμέτρους, αλλά μόνο κάποιες τελικές. Αυτό συμβαίνει επειδή είναι γνωστό ότι τα χαμηλότερα επίπεδα συνήθως αποτυπώνουν βασικές γλωσσικές δομές και εφαρμόσιμη σημασιολογία. Επομένως, **το fine tuning μόνο των τελευταίων επιπέδων είναι συνήθως αρκετό και ταχύτερο**.<sup>[[2]](#references)</sup>
```python
# This code makes all the parameters of the model unrtainable
for param in model.parameters():
param.requires_grad = False

# Allow to fine tune the last layer in the transformer block
for param in model.trf_blocks[-1].parameters():
param.requires_grad = True

# Allow to fine tune the final layer norm
for param in model.final_norm.parameters():

param.requires_grad = True
```
## Entries to use for training

Στις προηγούμενες ενότητες, το LLM εκπαιδευόταν μειώνοντας το loss κάθε προβλεπόμενου token, παρόλο που σχεδόν όλα τα προβλεπόμενα tokens βρίσκονταν ήδη στην πρόταση εισόδου (μόνο 1 στο τέλος προβλεπόταν πραγματικά), ώστε το model να κατανοεί καλύτερα τη γλώσσα.

Σε αυτή την περίπτωση, μας ενδιαφέρει μόνο το model να μπορεί να προβλέψει αν το input είναι spam ή όχι, επομένως μας ενδιαφέρει μόνο το τελευταίο προβλεπόμενο token. Συνεπώς, χρειάζεται να τροποποιήσουμε τις προηγούμενες συναρτήσεις loss ώστε να λαμβάνουν υπόψη μόνο αυτό το token.

Αυτό υλοποιείται στο [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch06/01_main-chapter-code/ch06.ipynb) ως εξής:<sup>[[2]](#references)</sup>
```python
def calc_accuracy_loader(data_loader, model, device, num_batches=None):
model.eval()
correct_predictions, num_examples = 0, 0

if num_batches is None:
num_batches = len(data_loader)
else:
num_batches = min(num_batches, len(data_loader))
for i, (input_batch, target_batch) in enumerate(data_loader):
if i < num_batches:
input_batch, target_batch = input_batch.to(device), target_batch.to(device)

with torch.no_grad():
logits = model(input_batch)[:, -1, :]  # Logits of last output token
predicted_labels = torch.argmax(logits, dim=-1)

num_examples += predicted_labels.shape[0]
correct_predictions += (predicted_labels == target_batch).sum().item()
else:
break
return correct_predictions / num_examples


def calc_loss_batch(input_batch, target_batch, model, device):
input_batch, target_batch = input_batch.to(device), target_batch.to(device)
logits = model(input_batch)[:, -1, :]  # Logits of last output token
loss = torch.nn.functional.cross_entropy(logits, target_batch)
return loss
```
Σημειώστε ότι για κάθε batch μας ενδιαφέρουν μόνο τα **logits του τελευταίου προβλεπόμενου token**.
