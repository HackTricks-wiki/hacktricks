# 7.2. Fine-Tuning za praćenje instrukcija

{{#include ../../banners/hacktricks-training.md}}

> [!TIP]
> Cilj ovog odeljka je da prikaže kako se **Fine-Tuning već pretreniranog modela može koristiti za praćenje instrukcija**, umesto samo generisanja teksta, na primer, za odgovaranje na zadatke kao chatbot.

## Dataset

Da bi se izvršio Fine-Tuning LLM-a za praćenje instrukcija, neophodno je imati dataset sa **instrukcijama i odgovorima**. Postoje različiti formati promptova za obuku LLM-a za praćenje instrukcija, na primer:<sup>[[1]](#references)</sup>

- Primer Alpaca prompt stila:
```csharp
Below is an instruction that describes a task. Write a response that appropriately completes the request.

### Instruction:
Calculate the area of a circle with a radius of 5 units.

### Response:
The area of a circle is calculated using the formula \( A = \pi r^2 \). Plugging in the radius of 5 units:

\( A = \pi (5)^2 = \pi \times 25 = 25\pi \) square units.
```
- Phi-3 / primer stila chat template-a:
```vbnet
<|User|>
Can you explain what gravity is in simple terms?

<|Assistant|>
Absolutely! Gravity is a force that pulls objects toward each other.
```
Obučavanje pomoću ovakvih skupova podataka, umesto samo sirovog teksta, pomaže modelu da razume da treba da odgovara na zadatke u **strukturisanom formatu asistenta**.

Veoma česta greška je obučavati model pomoću jednog template-a, a zatim vršiti inference pomoću drugog. Moderni instruct modeli obično očekuju **native chat template osnovnog modela** (`<|user|>`, `<|assistant|>`, `[INST]`, ChatML itd.), pa se preporučuje konvertovanje skupa podataka u tačan format koji ciljni model već koristi.

Zato je jedna od prvih stvari koje treba uraditi sa skupom podataka koji sadrži zahteve i odgovore modelovanje tih podataka u željenom prompt formatu, kao što je:<sup>[[2]](#references)</sup>
```python
# Code from https://github.com/rasbt/LLMs-from-scratch/blob/main/ch07/01_main-chapter-code/ch07.ipynb
def format_input(entry):
instruction_text = (
f"Below is an instruction that describes a task. "
f"Write a response that appropriately completes the request."
f"\n\n### Instruction:\n{entry['instruction']}"
)

input_text = f"\n\n### Input:\n{entry['input']}" if entry["input"] else ""

return instruction_text + input_text

model_input = format_input(data[50])

desired_response = f"\n\n### Response:\n{data[50]['output']}"

print(model_input + desired_response)
```
Ako osnovni model već dolazi sa chat template-om tokenizer-a, može biti bezbednije napraviti skup podataka iz lista poruka umesto ručnog pravljenja separatora:
```python
messages = [
{"role": "user", "content": entry["instruction"]},
{"role": "assistant", "content": entry["output"]},
]
text = tokenizer.apply_chat_template(messages, tokenize=False)
```
Zatim, kao i uvek, potrebno je podeliti dataset na skupove za training, validation i testing.

## Batching i Data Loaders

Zatim je potrebno formirati batch-eve od svih ulaza i očekivanih izlaza za training. Za to je potrebno:

- Tokenizovati tekstove.
- Dopuniti sve uzorke do iste dužine (obično će dužina biti jednaka dužini konteksta korišćenoj za pre-training LLM-a).
- Kreirati očekivane tokene pomeranjem inputa za 1 u prilagođenoj collate funkciji.
- Zameniti neke padding tokene sa `-100` kako bi se izuzeli iz training loss-a: nakon prvog `endoftext` tokena, zameniti sve ostale `endoftext` tokene sa `-100` (zato što korišćenje `cross_entropy(..., ignore_index=-100)` znači da će ignorisati target-e sa vrednošću `-100`).
- \[Optional] Maskirati pomoću `-100` i sve tokene koji pripadaju pitanju, kako bi LLM učio samo da generiše odgovor. U Alpaca stilu to obično znači maskiranje svega do `### Response:`.
- **Modern SFT best practice:** ako je dataset konverzacijski, loss računati samo nad **assistant completion tokenima**, a ne nad user/system promptom. Time se izbegava učenje modela da predviđa sam tekst prompta.<sup>[[3]](#references)</sup>
- **Throughput optimization:** kada dataset sadrži mnogo kratkih uzoraka, uobičajeno je **upakovati nekoliko primera u istu sekvencu** kako bi se manje prostora context window-a trošilo uzalud.<sup>[[3]](#references)</sup>

Kada je ovo kreirano, vreme je da se naprave data loader-i za svaki dataset (training, validation i test).

## Učitavanje pre-trained LLM-a, Fine-tune i provera Loss-a

Potrebno je učitati pre-trained LLM kako bi se izvršio fine-tuning. Ovo je već razmatrano na drugim stranicama. Zatim je moguće koristiti prethodno korišćenu training funkciju za fine-tuning LLM-a.

Tokom training-a moguće je pratiti kako se training loss i validation loss menjaju tokom epoha, kako bi se utvrdilo da li se loss smanjuje i da li dolazi do overfitting-a.\
Zapamtite da overfitting nastaje kada se training loss smanjuje, ali se validation loss ne smanjuje ili čak raste. Najjednostavniji način da se ovo izbegne jeste da se training zaustavi u epohi u kojoj ovo ponašanje počinje.

Ako je GPU memorija ograničenje, pogledajte [7.0. LoRA Improvements in fine-tuning](7.0.-lora-improvements-in-fine-tuning.md), jer se u praksi većina instruction-tuning poslova obavlja pomoću **LoRA/QLoRA/PEFT adaptera**, umesto ažuriranja svakog parametra base model-a.

## Moderne post-training varijante

Klasičan pristup je **supervised fine-tuning (SFT)** nad parovima `(instruction, answer)`. Međutim, savremeni instruct-model pipeline-i često dele post-training na nekoliko faza:

1. **SFT** za učenje formata izlaza, stila odgovora i distribucije zadataka.
2. **Preference optimization** kako bi model davao prednost jednom odgovoru u odnosu na drugi, bez potrebe za zasebnim reward model-om.
3. **Optional** online optimization, kao što je RLHF / PPO, za specifične proizvode ili ciljeve vezane za bezbednost.

Najčešće alternative zasnovane na preferencijama nakon SFT-a su:

- **DPO (Direct Preference Optimization):** direktno optimizuje preferirane u odnosu na odbačene odgovore.
- **ORPO / KTO / SimPO:** jednostavnije varijante koje smanjuju deo engineering overhead-a potpunih RLHF pipeline-a.

U praksi, ove metode obično koriste ili parove **chosen/rejected response** za isti prompt ili jednostavniji signal **desirable / undesirable**, pa kvalitet preference dataset-a postaje jednako važan kao i sam SFT corpus.

Ovo je korisno zato što u mnogim projektima najskuplji deo nije učenje formata modela, već učenje da **preferira stil odgovora koji ljudi žele**. Ako želite više detalja o RL strani i poisoning-u reward model-a, pogledajte [../AI-Reinforcement-Learning-Algorithms.md](../AI-Reinforcement-Learning-Algorithms.md).

## Kvalitet odgovora

Pošto ovo nije classification fine-tune kod kog je moguće više verovati promenama loss-a, važno je proveriti i kvalitet odgovora u testing set-u. Zato se preporučuje prikupljanje generisanih odgovora iz svih testing set-ova i **ručna provera njihovog kvaliteta** kako bi se utvrdilo da li postoje pogrešni odgovori (imajte na umu da je moguće da LLM ispravno generiše format i sintaksu rečenice odgovora, ali pruži potpuno pogrešan odgovor. Promena loss-a neće odražavati ovo ponašanje).\
Imajte na umu da je ovu proveru moguće obaviti i prosleđivanjem generisanih i očekivanih odgovora **drugim LLM-ovima, uz zahtev da procene odgovore**.

Savremene evaluacije instruction-following sposobnosti kojima vredi dati prioritet su:

- **IFEval:** proverava da li model zaista prati eksplicitna ograničenja iz prompta, umesto da samo zvuči dobro.
- **AlpacaEval 2 / pairwise judges:** korisno za poređenje generacija sa baseline model-om.
- **Arena-style head-to-head evals:** korisno kada je potrebno relativno rangiranje više checkpoint-a i prompt-ova.

Ostali testovi za proveru kvaliteta odgovora:

1. **Measuring Massive Multitask Language Understanding (**[**MMLU**](https://arxiv.org/abs/2009.03300)**):** MMLU procenjuje znanje modela i sposobnosti rešavanja problema kroz 57 oblasti, uključujući humanističke nauke, prirodne nauke i druge oblasti. Koristi pitanja sa višestrukim izborom za procenu razumevanja na različitim nivoima težine, od osnovnog do naprednog profesionalnog nivoa.
2. [**LMSYS Chatbot Arena**](https://arena.lmsys.org): Ova platforma omogućava korisnicima da upoređuju odgovore različitih chatbot-ova jedan pored drugog. Korisnici unose prompt, a više chatbot-ova generiše odgovore koji se mogu direktno uporediti.
3. [**AlpacaEval**](https://github.com/tatsu-lab/alpaca_eval)**:** AlpacaEval je automatizovani evaluation framework u kom napredni LLM, kao što je GPT-4, procenjuje odgovore drugih modela na različite prompt-ove.
4. **General Language Understanding Evaluation (**[**GLUE**](https://gluebenchmark.com/)**):** GLUE je skup od devet zadataka za razumevanje prirodnog jezika, uključujući sentiment analysis, textual entailment i question answering.
5. [**SuperGLUE**](https://super.gluebenchmark.com/)**:** Nadovezujući se na GLUE, SuperGLUE uključuje izazovnije zadatke koji su projektovani tako da budu teški za aktuelne modele.
6. **Beyond the Imitation Game Benchmark (**[**BIG-bench**](https://github.com/google/BIG-bench)**):** BIG-bench je benchmark velikih razmera sa više od 200 zadataka koji testiraju sposobnosti modela u oblastima kao što su reasoning, translation i question answering.
7. **Holistic Evaluation of Language Models (**[**HELM**](https://crfm.stanford.edu/helm/lite/latest/)**):** HELM pruža sveobuhvatnu evaluaciju kroz različite metrike, kao što su accuracy, robustness i fairness.
8. [**OpenAI Evals**](https://github.com/openai/evals)**:** Open-source evaluation framework kompanije OpenAI koji omogućava testiranje AI modela na prilagođenim i standardizovanim zadacima.
9. [**HumanEval**](https://github.com/openai/human-eval)**:** Skup programerskih problema koji se koristi za procenu sposobnosti language model-a za code generation.
10. **Stanford Question Answering Dataset (**[**SQuAD**](https://rajpurkar.github.io/SQuAD-explorer/)**):** SQuAD se sastoji od pitanja o Wikipedia člancima, pri čemu modeli moraju da razumeju tekst kako bi precizno odgovorili.
11. [**TriviaQA**](https://nlp.cs.washington.edu/triviaqa/)**:** Dataset velikih razmera sa trivia pitanjima i odgovorima, zajedno sa dokumentima koji sadrže dokaze.

## Bezbednosne napomene za instruction tuning

Instruction-tuning dataset-i predstavljaju i attack surface. Ako napadač može da ubaci mali broj poisoned uzoraka u SFT corpus, model može naučiti **ponašanje uslovljeno trigger-om**, a da pritom i dalje izgleda normalno na čistim prompt-ovima.<sup>[[4]](#references)</sup>

Tipični maliciozni obrasci koje treba testirati tokom red teaming-a su:

- **Instruction backdoors:** redak trigger string, role prefix, unicode obrazac ili formatting sekvenca uzrokuje da model izgeneriše sadržaj koji je odabrao napadač.<sup>[[4]](#references)</sup>
- **Sleeper-agent behaviour:** model se ponaša ispravno tokom normalnih evaluacija, ali menja ponašanje samo kada se pojavi veoma specifičan trigger.<sup>[[5]](#references)</sup>
- **Narrow-domain misalignment:** naizgled bezopasan domain fine-tune može pomeriti model u lošu oblast ponašanja izvan predviđene distribucije zadataka.

Praktične provere:

- Održavajte **canary set** sintetičkih trigger prompt-ova i pokrećite ga nad svakim checkpoint-om.
- Uklonite duplikate i proverite provenance SFT corpus-a pre training-a.
- Nikada nemojte trenirati na identičnim prompt-ovima koji se koriste u benchmark-u o kom ćete kasnije izveštavati.
- Uporedite base model sa fine-tuned model-om na security-sensitive prompt-ovima kako biste otkrili neočekivani drift ponašanja.

## Kod za fine-tuning radi praćenja instrukcija

Primer koda za ovaj fine-tuning možete pronaći na [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch07/01_main-chapter-code/gpt_instruction_finetuning.py](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch07/01_main-chapter-code/gpt_instruction_finetuning.py)<sup>[[6]](#references)</sup>

Praktična savremena alternativa jeste korišćenje trainer-a koji već podržava chat templates, assistant-only loss, packing i PEFT adaptere. Ako kasnije želite preference alignment, isti ecosystem pruža i workflow-e u stilu `DPOTrainer` za dataset-e sa poljima `prompt` / `chosen` / `rejected`:<sup>[[3]](#references)</sup>
```python
from trl import SFTConfig, SFTTrainer

trainer = SFTTrainer(
model="Qwen/Qwen2.5-0.5B-Instruct",
train_dataset=dataset,
args=SFTConfig(
learning_rate=2e-5,
packing=True,
assistant_only_loss=True,
),
)
trainer.train()
```
