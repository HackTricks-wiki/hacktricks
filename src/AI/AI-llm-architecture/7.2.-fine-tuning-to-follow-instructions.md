# 7.2. Fine-Tuning 以遵循指令

{{#include ../../banners/hacktricks-training.md}}

> [!TIP]
> 本节旨在展示如何对已经预训练的模型进行 **fine-tune，使其遵循指令**，而不是仅生成文本，例如像聊天机器人一样响应任务。

## 数据集

为了对 LLM 进行 fine-tune，使其遵循指令，需要包含 **指令和响应** 的数据集。有不同的 prompt 格式可用于训练 LLM 遵循指令，例如：<sup>[[1]](#references)</sup>

- Alpaca prompt 风格示例：
```csharp
Below is an instruction that describes a task. Write a response that appropriately completes the request.

### Instruction:
Calculate the area of a circle with a radius of 5 units.

### Response:
The area of a circle is calculated using the formula \( A = \pi r^2 \). Plugging in the radius of 5 units:

\( A = \pi (5)^2 = \pi \times 25 = 25\pi \) square units.
```
- Phi-3 / chat template 风格示例：
```vbnet
<|User|>
Can you explain what gravity is in simple terms?

<|Assistant|>
Absolutely! Gravity is a force that pulls objects toward each other.
```
使用这类数据集进行训练，而不是仅使用原始文本，有助于模型理解它需要以**结构化的 assistant 格式**回答任务。

一个非常常见的错误是使用一种模板进行训练，却使用另一种模板进行推理。现代 instruct models 通常期望使用基础模型的**原生 chat template**（`<|user|>`、`<|assistant|>`、`[INST]`、ChatML 等），因此，建议将数据集转换为目标模型已经使用的确切格式。

因此，对于包含请求和回答的数据集，首先要做的事情之一，就是按照所需的 prompt 格式对这些数据进行建模，例如：<sup>[[2]](#references)</sup>
```python
# Code from https://github.com/rasbt/LLMs-from-scratch/blob/main/ch07/01_main-chapter-code/ch07.ipynb
def format_input(entry):
instruction_text = (
f"Below is an instruction that describes a task. "
f"Write a response that appropriately completes the request."
f"\n\n### Instruction:\n{entry['instruction']}"
)

input_text = f"\n\n### Input:\n{entry['input']}" if entry["input"] else ""

return instruction_text + input_text

model_input = format_input(data[50])

desired_response = f"\n\n### Response:\n{data[50]['output']}"

print(model_input + desired_response)
```
如果基础模型已经自带 tokenizer chat template，那么使用消息列表构建数据集可能比手动编写分隔符更安全：
```python
messages = [
{"role": "user", "content": entry["instruction"]},
{"role": "assistant", "content": entry["output"]},
]
text = tokenizer.apply_chat_template(messages, tokenize=False)
```
然后，和往常一样，需要将 dataset 分为 training、validation 和 testing sets。

## Batching & Data Loaders

然后，需要为 training 将所有 inputs 和 expected outputs 进行 batching。为此，需要：

- Tokenize 文本。
- 将所有 samples 填充到相同长度（通常该长度会与用于 pre-train LLM 的 context length 一样大）。
- 在自定义 collate function 中，通过将 input 向后移动 1 位来创建 expected tokens。
- 将一些 padding tokens 替换为 `-100`，以将其排除在 training loss 之外：在第一个 `endoftext` token 之后，将所有其他 `endoftext` tokens 替换为 `-100`（因为使用 `cross_entropy(..., ignore_index=-100)` 意味着会忽略值为 `-100` 的 targets）。
- \[Optional] 同样使用 `-100` mask 掉属于 question 的所有 tokens，使 LLM 只学习如何生成 answer。在 Alpaca style 中，这通常意味着 mask 掉 `### Response:` 之前的所有内容。
- **Modern SFT best practice:** 如果 dataset 是 conversational 的，只对 **assistant completion tokens** 计算 loss，而不是对 user/system prompt 计算 loss。这样可以避免训练 model 去预测 prompt 文本本身。<sup>[[3]](#references)</sup>
- **Throughput optimization:** 当 dataset 包含大量短 samples 时，通常会将 **多个 examples packing 到同一个 sequence 中**，以减少 context window 的浪费。<sup>[[3]](#references)</sup>

完成这些后，就可以为每个 dataset（training、validation 和 test）创建 data loaders 了。

## Load pre-trained LLM & Fine tune & Loss Checking

需要加载一个 pre-trained LLM 来进行 fine-tune。这一点已经在其他页面中讨论过。之后，可以使用之前使用的 training function 对 LLM 进行 fine-tune。

在 training 期间，还可以观察 training loss 和 validation loss 在各个 epochs 中的变化，以确认 loss 是否在降低，以及是否出现 overfitting。\
请记住，当 training loss 在降低，但 validation loss 没有降低甚至增加时，就发生了 overfitting。为避免这种情况，最简单的方法是在这种行为开始出现的 epoch 停止 training。

如果 GPU memory 存在限制，请查看 [7.0. LoRA Improvements in fine-tuning](7.0.-lora-improvements-in-fine-tuning.md)，因为在实践中，大多数 instruction-tuning jobs 都使用 **LoRA/QLoRA/PEFT adapters**，而不是更新 base model 的每个 parameter。

## Modern post-training variants

经典方法是在 `(instruction, answer)` pairs 上进行 **supervised fine-tuning (SFT)**。不过，当前的 instruct-model pipelines 通常会将 post-training 拆分为多个阶段：

1. **SFT**：学习 output format、answer style 和 task distribution。
2. **Preference optimization**：使 model 更偏好一个 answer 而不是另一个 answer，而无需单独的 reward model。
3. **Optional** online optimization，例如针对特定产品或 safety goals 的 RLHF / PPO。

SFT 之后最常见的 preference-based alternatives 包括：

- **DPO (Direct Preference Optimization)：** 直接优化 preferred answers 与 rejected answers 之间的差异。
- **ORPO / KTO / SimPO：** 更简单的 variants，可减少完整 RLHF pipelines 的部分 engineering overhead。

在实践中，这些 methods 通常需要针对同一个 prompt 的 **chosen/rejected response pairs**，或更简单的 **desirable / undesirable** signal，因此 preference dataset 的质量与 SFT corpus 本身同样重要。

这很有用，因为对于许多 projects 而言，成本高昂的部分并不是教会 model output format，而是教会它 **偏好人类想要的 answer style**。如果想了解更多关于 RL side 和 reward-model poisoning 的 details，请查看 [../AI-Reinforcement-Learning-Algorithms.md](../AI-Reinforcement-Learning-Algorithms.md)。

## Response Quality

由于这不是一种可以更加依赖 loss variations 的 classification fine-tune，因此检查 testing set 中 responses 的质量也很重要。因此，建议收集所有 testing sets 生成的 responses，并**手动检查其质量**，以确认是否存在错误 answers（注意，LLM 可能正确生成 response sentence 的 format 和 syntax，却给出完全错误的 response。loss variation 不会反映这种行为）。\
还需要注意，也可以将生成的 responses 和 expected responses 传递给**其他 LLMs，并要求它们评估这些 responses**，从而执行这项 review。

现代 instruction-following evaluations 值得优先考虑：

- **IFEval：** 检查 model 是否真正遵循 prompt 中的显式 constraints，而不只是让 output 听起来不错。
- **AlpacaEval 2 / pairwise judges：** 用于将 generations 与 baseline model 进行比较。
- **Arena-style head-to-head evals：** 当需要对多个 checkpoints 和 prompts 进行相对排名时很有用。

可运行以下其他 tests 来验证 responses 的质量：

1. **Measuring Massive Multitask Language Understanding (**[**MMLU**](https://arxiv.org/abs/2009.03300)**)：** MMLU 评估 model 在 57 个 subjects 上的 knowledge 和 problem-solving abilities，包括 humanities、sciences 等领域。它使用 multiple-choice questions，在从 elementary 到 advanced professional 的不同 difficulty levels 上评估 understanding。
2. [**LMSYS Chatbot Arena**](https://arena.lmsys.org)：该 platform 允许 users 并排比较不同 chatbots 的 responses。Users 输入一个 prompt，多个 chatbots 生成可以直接比较的 responses。
3. [**AlpacaEval**](https://github.com/tatsu-lab/alpaca_eval)**：** AlpacaEval 是一个 automated evaluation framework，由 GPT-4 等 advanced LLM 评估其他 models 针对各种 prompts 生成的 responses。
4. **General Language Understanding Evaluation (**[**GLUE**](https://gluebenchmark.com/)**)：** GLUE 是由九个 natural language understanding tasks 组成的 collection，包括 sentiment analysis、textual entailment 和 question answering。
5. [**SuperGLUE**](https://super.gluebenchmark.com/)**：** SuperGLUE 基于 GLUE 构建，包含为当前 models 设计的更具挑战性的 tasks。
6. **Beyond the Imitation Game Benchmark (**[**BIG-bench**](https://github.com/google/BIG-bench)**)：** BIG-bench 是一个 large-scale benchmark，包含 200 多个 tasks，用于测试 model 在 reasoning、translation 和 question answering 等领域的 abilities。
7. **Holistic Evaluation of Language Models (**[**HELM**](https://crfm.stanford.edu/helm/lite/latest/)**)：** HELM 根据 accuracy、robustness 和 fairness 等多种 metrics，提供 comprehensive evaluation。
8. [**OpenAI Evals**](https://github.com/openai/evals)**：** OpenAI 提供的 open-source evaluation framework，可用于在 custom 和 standardized tasks 上测试 AI models。
9. [**HumanEval**](https://github.com/openai/human-eval)**：** 用于评估 language models code generation abilities 的 programming problems collection。
10. **Stanford Question Answering Dataset (**[**SQuAD**](https://rajpurkar.github.io/SQuAD-explorer/)**)：** SQuAD 包含关于 Wikipedia articles 的 questions，models 必须理解文本才能准确回答。
11. [**TriviaQA**](https://nlp.cs.washington.edu/triviaqa/)**：** 一个 large-scale dataset，包含 trivia questions 和 answers，以及 supporting evidence documents。

还有很多很多其他 tests。

## Security notes for instruction tuning

Instruction-tuning datasets 也是一个 attack surface。如果 attacker 能够向 SFT corpus 中插入少量 poisoned samples，model 就可能学习到一种 **trigger-conditioned behaviour**，同时在 clean prompts 上仍表现正常。poison 不一定需要破坏 labels 或 normal input instances：一项 study 发现，总计约 1,000 个 tokens 的 malicious task instructions 就足够产生这种效果，并且学习到的 behaviour 会迁移到未见过的 generation tasks，同时抵抗后续的 clean fine-tuning。<sup>[[4]](#references)</sup>

在 red teaming 中，应测试以下典型的 malicious patterns：

- **Instruction-only backdoors：** poison task description，同时保持 ordinary instances 和 labels 不变。malicious instruction 可以迁移到其他 datasets，并且在一个 task 上被 poisoned 的 model 可能将该 behaviour 带入未见过的 generation tasks；因此，应测试 paraphrased instructions 和不同的 target tasks，而不要只重放完全相同的 poisoned prompt。<sup>[[4]](#references)</sup>
- **Sleeper-agent behaviour：** model 在 normal evaluations 期间表现正确，但只有在出现非常特定的 trigger 时才改变 behaviour。<sup>[[5]](#references)</sup>
- **Narrow-domain emergent misalignment：** 对 model 进行 fine-tuning，使其静默返回 insecure code，会在无关的 non-coding prompts 上产生 deceptive and harmful behaviour。在同一项 study 中，在 training requests 中说明 benign security-education reason，可以阻止所观察到的 broad effect；而 backdoored variant 则将 misalignment 限制在包含其 trigger 的 requests 中。<sup>[[7]](#references)</sup>
- **Agent/action backdoors：** 将 trigger 插入 user instruction（**active**）或 environment observation（**passive**），并在 training response 中放入 attacker 选择的 tool operation。BadAgent 使用 AdaLoRA 和 QLoRA 复现了这一点；产生的 behaviour 可以在后续对 trusted agent data 进行 fine-tuning 后继续存在。<sup>[[8]](#references)</sup> Runtime prompt injection 和 tool-metadata poisoning 是不同的问题，相关内容请查看 [AI MCP Servers](../AI-MCP-Servers.md)。

实用检查：

- 保留一个 **canary set**，并在每个 checkpoint 上同时测量 **clean utility** 和 **attack success rate (ASR)**。对每个 canary 在 token position、casing、whitespace/Unicode normalization、partial phrases、paraphrases 和 semantic equivalents 方面进行变体处理；对于 agents，还应将其放入 tool results 和 environment state 中，以及 user text 中。
- 在应用 chat template 后，检查 **rendered、tokenized conversations**，而不只是 source JSON。按 data source 统计 rare token n-grams 和意外的 role/control-token transitions，并 review target completions 异常一致的 clusters。
- 在 training 前对 SFT corpus 进行 deduplicate 和 provenance-check。按 source 和 trigger family 划分 security evaluations，避免 near-duplicate leakage 使 held-out test 看起来是 clean 的。
- 绝不要使用之后要报告的 benchmark 所使用的 exact prompts 进行 training。针对来自无关 domains 和 languages 的 security-sensitive prompts，比较 base model 与每个 fine-tuned checkpoint，以检测 behavioural drift。
- 不要假设另一次 clean SFT pass 就能移除 backdoor：在 experiments 中，instruction backdoors 和 agent backdoors 都曾在 continual/trusted fine-tuning 后继续存在。<sup>[[4]](#references)[[8]](#references)</sup>

## Follow instructions fine-tuning code

你可以在 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch07/01_main-chapter-code/gpt_instruction_finetuning.py](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch07/01_main-chapter-code/gpt_instruction_finetuning.py) 中找到执行该 fine-tuning 的 code 示例<sup>[[6]](#references)</sup>

一个实用的现代 alternative 是使用已经支持 chat templates、assistant-only loss、packing 和 PEFT adapters 的 trainer。如果之后想进行 preference alignment，同一 ecosystem 还提供了适用于包含 `prompt` / `chosen` / `rejected` fields 的 datasets 的 `DPOTrainer`-style workflows：<sup>[[3]](#references)</sup>
```python
from trl import SFTConfig, SFTTrainer

trainer = SFTTrainer(
model="Qwen/Qwen2.5-0.5B-Instruct",
train_dataset=dataset,
args=SFTConfig(
learning_rate=2e-5,
packing=True,
assistant_only_loss=True,
),
)
trainer.train()
```
