# 7.2. 微调以遵循指令

{{#include ../../banners/hacktricks-training.md}}

> [!TIP]
> 本节旨在展示如何将已经预训练的模型**微调为遵循指令**，而不仅仅是生成文本，例如以 chat bot 的形式响应任务。

## 数据集

为了将 LLM 微调为遵循指令，需要包含**指令和响应**的数据集。有多种用于训练 LLM 遵循指令的 prompt 格式，例如：<sup>[[1]](#references)</sup>

- Alpaca prompt 风格示例：
```csharp
Below is an instruction that describes a task. Write a response that appropriately completes the request.

### Instruction:
Calculate the area of a circle with a radius of 5 units.

### Response:
The area of a circle is calculated using the formula \( A = \pi r^2 \). Plugging in the radius of 5 units:

\( A = \pi (5)^2 = \pi \times 25 = 25\pi \) square units.
```
- Phi-3 / chat template 风格示例：
```vbnet
<|User|>
Can you explain what gravity is in simple terms?

<|Assistant|>
Absolutely! Gravity is a force that pulls objects toward each other.
```
使用这类数据集进行训练，而不是仅使用原始文本，有助于模型理解它需要以**结构化的 assistant 格式**回答任务。

一个非常常见的错误是使用一种模板进行训练，却使用另一种模板进行推理。现代 instruct models 通常期望使用基础模型的**原生 chat template**（`<|user|>`、`<|assistant|>`、`[INST]`、ChatML 等），因此建议将数据集转换为目标模型已经使用的确切格式。

因此，对于包含请求和答案的数据集，首先要做的事情之一，就是按照所需的 prompt 格式对这些数据进行建模，例如：<sup>[[2]](#references)</sup>
```python
# Code from https://github.com/rasbt/LLMs-from-scratch/blob/main/ch07/01_main-chapter-code/ch07.ipynb
def format_input(entry):
instruction_text = (
f"Below is an instruction that describes a task. "
f"Write a response that appropriately completes the request."
f"\n\n### Instruction:\n{entry['instruction']}"
)

input_text = f"\n\n### Input:\n{entry['input']}" if entry["input"] else ""

return instruction_text + input_text

model_input = format_input(data[50])

desired_response = f"\n\n### Response:\n{data[50]['output']}"

print(model_input + desired_response)
```
如果基础模型已经自带 tokenizer chat template，那么使用消息列表构建数据集通常比手动编写分隔符更安全：
```python
messages = [
{"role": "user", "content": entry["instruction"]},
{"role": "assistant", "content": entry["output"]},
]
text = tokenizer.apply_chat_template(messages, tokenize=False)
```
然后，和往常一样，需要将数据集划分为训练集、验证集和测试集。

## 批处理与数据加载器

接下来，需要对训练所需的所有输入和预期输出进行批处理。为此，需要：

- 对文本进行 Tokenize。
- 将所有样本填充到相同长度（通常该长度会与用于预训练 LLM 的上下文长度一样大）。
- 在自定义 collate function 中将输入右移 1 位，以创建预期 tokens。
- 将部分 padding tokens 替换为 `-100`，以从训练 loss 中排除它们：在第一个 `endoftext` token 之后，将所有其他 `endoftext` tokens 替换为 `-100`（因为使用 `cross_entropy(..., ignore_index=-100)` 意味着会忽略目标值为 `-100` 的 tokens）。
- \[可选] 同样使用 `-100` 屏蔽所有属于问题的 tokens，使 LLM 仅学习生成答案。在 Alpaca 风格中，这通常意味着屏蔽 `### Response:` 之前的所有内容。
- **现代 SFT 最佳实践：** 如果数据集是对话式的，仅对 **assistant completion tokens** 计算 loss，而不是对 user/system prompt 计算 loss。这样可以避免教会模型预测 prompt 文本本身。<sup>[[3]](#references)</sup>
- **吞吐量优化：** 当数据集包含许多短样本时，通常会将 **多个示例打包到同一个序列中**，以减少上下文窗口的浪费。<sup>[[3]](#references)</sup>

完成这些操作后，就可以为每个数据集（训练集、验证集和测试集）创建 data loaders 了。

## 加载预训练 LLM、Fine-tune 与 Loss 检查

需要加载一个预训练 LLM 来对其进行 fine-tune。这一点已在其他页面中讨论过。随后，可以使用之前使用的训练函数来对 LLM 进行 fine-tune。

在训练期间，还可以观察训练 loss 和验证 loss 在各个 epoch 中的变化，以确定 loss 是否正在降低，以及是否发生了 overfitting。\
请记住，当训练 loss 正在降低，但验证 loss 没有降低甚至不断增加时，就发生了 overfitting。为避免这种情况，最简单的方法是在这种行为开始出现的 epoch 停止训练。

如果 GPU memory 是限制因素，请查看 [7.0. LoRA Improvements in fine-tuning](7.0.-lora-improvements-in-fine-tuning.md)，因为在实践中，大多数 instruction-tuning 任务都会使用 **LoRA/QLoRA/PEFT adapters**，而不是更新 base model 的每个参数。

## 现代 post-training 变体

经典方法是对 `(instruction, answer)` pairs 进行 **supervised fine-tuning (SFT)**。然而，目前的 instruct-model pipelines 通常会将 post-training 分为多个阶段：

1. **SFT**：教会模型输出格式、答案风格和任务分布。
2. **Preference optimization**：让模型偏好某个答案而非另一个答案，而无需单独的 reward model。
3. **可选的** online optimization，例如针对特定产品或安全目标使用 RLHF / PPO。

SFT 之后最常见的基于 preference 的替代方案包括：

- **DPO (Direct Preference Optimization)：** 直接优化 preferred answers 与 rejected answers 之间的差异。
- **ORPO / KTO / SimPO：** 更简单的变体，可减少完整 RLHF pipelines 的部分工程开销。

在实践中，这些方法通常需要针对同一个 prompt 提供 **chosen/rejected response pairs**，或提供更简单的 **desirable / undesirable** 信号，因此 preference dataset 的质量与 SFT corpus 本身同样重要。

这很有用，因为对于许多项目而言，最昂贵的部分并不是教会模型输出格式，而是教会模型 **偏好人类想要的答案风格**。如果想了解更多关于 RL 以及 reward-model poisoning 的细节，请查看 [../AI-Reinforcement-Learning-Algorithms.md](../AI-Reinforcement-Learning-Algorithms.md)。

## Response Quality

由于这不是一种可以更加依赖 loss 变化的 classification fine-tune，因此检查测试集中的 responses 质量也很重要。因此，建议收集所有测试集生成的 responses，并**手动检查其质量**，以确认是否存在错误答案（请注意，LLM 可能正确生成 response sentence 的格式和 syntax，却给出完全错误的回答。loss 的变化不会反映这种行为）。\
还请注意，也可以将生成的 responses 和预期 responses 传递给**其他 LLM，并要求它们评估这些 responses**，从而执行此类审查。

现代 instruction-following 评估中值得优先考虑的项目包括：

- **IFEval：** 检查模型是否真正遵循 prompt 中的明确约束，而不仅仅是生成听起来不错的内容。
- **AlpacaEval 2 / pairwise judges：** 用于将生成结果与 baseline model 进行比较。
- **Arena-style head-to-head evals：** 当需要对多个 checkpoints 和 prompts 进行相对排名时非常有用。

还可以运行以下测试来验证 responses 的质量：

1. **Measuring Massive Multitask Language Understanding (**[**MMLU**](https://arxiv.org/abs/2009.03300)**)：** MMLU 评估模型在 57 个学科中的知识和问题解决能力，包括人文学科、科学等领域。它使用 multiple-choice questions，在从基础到高级专业的各种难度级别评估理解能力。
2. [**LMSYS Chatbot Arena**](https://arena.lmsys.org)：该平台允许用户并排比较不同 chatbots 的 responses。用户输入一个 prompt，多个 chatbots 生成 responses，用户可以直接进行比较。
3. [**AlpacaEval**](https://github.com/tatsu-lab/alpaca_eval)**：** AlpacaEval 是一个 automated evaluation framework，由 GPT-4 等 advanced LLM 评估其他 models 针对各种 prompts 生成的 responses。
4. **General Language Understanding Evaluation (**[**GLUE**](https://gluebenchmark.com/)**)：** GLUE 是由九项 natural language understanding tasks 组成的集合，包括 sentiment analysis、textual entailment 和 question answering。
5. [**SuperGLUE**](https://super.gluebenchmark.com/)**：** SuperGLUE 建立在 GLUE 之上，包含专门设计为当前 models 难以完成的更具挑战性的 tasks。
6. **Beyond the Imitation Game Benchmark (**[**BIG-bench**](https://github.com/google/BIG-bench)**)：** BIG-bench 是一个 large-scale benchmark，包含 200 多项 tasks，用于测试模型在 reasoning、translation 和 question answering 等领域的能力。
7. **Holistic Evaluation of Language Models (**[**HELM**](https://crfm.stanford.edu/helm/lite/latest/)**)：** HELM 从 accuracy、robustness 和 fairness 等多个指标对模型进行全面评估。
8. [**OpenAI Evals**](https://github.com/openai/evals)**：** OpenAI 提供的 open-source evaluation framework，可用于在 custom 和 standardized tasks 上测试 AI models。
9. [**HumanEval**](https://github.com/openai/human-eval)**：** 用于评估 language models 代码生成能力的 programming problems 集合。
10. **Stanford Question Answering Dataset (**[**SQuAD**](https://rajpurkar.github.io/SQuAD-explorer/)**)：** SQuAD 包含关于 Wikipedia articles 的问题，models 必须理解文本才能准确回答。
11. [**TriviaQA**](https://nlp.cs.washington.edu/triviaqa/)**：** 一个 large-scale dataset，包含 trivia questions and answers 以及相关的 evidence documents。

以及许多许多其他测试。

## Instruction Tuning 的安全注意事项

Instruction-tuning datasets 也是一个 attack surface。如果攻击者能够向 SFT corpus 中插入少量 poisoned samples，模型就可能学习到一种 **trigger-conditioned behaviour**，同时在 clean prompts 上仍表现正常。<sup>[[4]](#references)</sup>

在 red teaming 中，通常需要测试以下恶意模式：

- **Instruction backdoors：** 某个罕见的 trigger string、role prefix、unicode pattern 或 formatting sequence 会导致模型输出攻击者指定的内容。<sup>[[4]](#references)</sup>
- **Sleeper-agent behaviour：** 模型在正常 evaluations 中表现正确，但只有在出现非常特定的 trigger 时才会改变行为。<sup>[[5]](#references)</sup>
- **Narrow-domain misalignment：** 看似无害的 domain fine-tune 可能会使模型偏离预期 task distribution，并进入不良行为区域。

实际检查措施：

- 保留一个由 synthetic trigger prompts 组成的 **canary set**，并在每个 checkpoint 上运行它。
- 在训练前对 SFT corpus 进行 deduplicate 和 provenance-check。
- 绝不要使用之后要报告的 benchmark 所使用的 exact prompts 进行训练。
- 在 security-sensitive prompts 上比较 base model 与 fine-tuned model，以检测意外的 behaviour drift。

## Follow instructions fine-tuning code

你可以在 [https://github.com/rasbt/LLMs-from-scratch/blob/main/ch07/01_main-chapter-code/gpt_instruction_finetuning.py](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch07/01_main-chapter-code/gpt_instruction_finetuning.py)<sup>[[6]](#references)</sup> 中找到执行此 fine-tuning 的代码示例。

一种实用的现代替代方案是使用已经支持 chat templates、assistant-only loss、packing 和 PEFT adapters 的 trainer。如果之后想进行 preference alignment，同一生态也为包含 `prompt` / `chosen` / `rejected` fields 的 datasets 提供类似 `DPOTrainer` 的 workflows：<sup>[[3]](#references)</sup>
```python
from trl import SFTConfig, SFTTrainer

trainer = SFTTrainer(
model="Qwen/Qwen2.5-0.5B-Instruct",
train_dataset=dataset,
args=SFTConfig(
learning_rate=2e-5,
packing=True,
assistant_only_loss=True,
),
)
trainer.train()
```
