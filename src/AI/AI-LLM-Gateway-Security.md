# Όρια εμπιστοσύνης του LLM Gateway

{{#include ../banners/hacktricks-training.md}}

Ένα LLM gateway διαχειρίζεται τη δρομολόγηση μοντέλων και συχνά διατηρεί διαπιστευτήρια παρόχων, επομένως οι συνήθεις καλούντες του API δεν πρέπει να αποκτούν εξουσίες διαχείρισης ρυθμίσεων ή εξουσίες σε επίπεδο παρόχου. Η αξιολόγηση του LiteLLM gateway στην έκδοση 1.77.7 αναδεικνύει δύο ξεχωριστά όρια: την εξουσιοδότηση συνεδρίας UI για τη διαχείριση ρυθμίσεων και τη ρύθμιση δρομολόγησης που παρέχει ο καλών για inference. Τα αναφερόμενα προβλήματα διορθώθηκαν στην έκδοση 1.83.9.<sup>[[1]](#references)</sup>

## Η ταξινόμηση των UI routes δεν αποτελεί εξουσιοδότηση

Στην αξιολογηθείσα έκδοση του LiteLLM, τα κλειδιά σύνδεσης UI ανήκαν στην ομάδα `litellm-dashboard`. Η εξουσιοδότηση ταξινομούσε ένα κλειδί ως UI token βάσει αυτού του αναγνωριστικού ομάδας, ανεξάρτητα από τον ρόλο του χρήστη. Στη συνέχεια, ο έλεγχος του UI route αποδεχόταν οποιοδήποτε route ξεκινούσε με ένα επιτρεπόμενο πρόθεμα. Ως αποτέλεσμα, η καταχώριση `/config` αντιστοιχιζόταν και στον διαχειριστικό handler `/config/update`. Αυτός ο handler απαιτούσε γενική αυθεντικοποίηση, αλλά δεν απαιτούσε ανεξάρτητα `PROXY_ADMIN`, με αποτέλεσμα μια συνεδρία UI με χαμηλότερα προνόμια να αποκτά πρόσβαση εγγραφής στις ρυθμίσεις.<sup>[[1]](#references)</sup>

Αυτό διαφέρει από μια ασυμφωνία κανονικοποίησης διαδρομής μεταξύ proxy/backend: ο κώδικας εξουσιοδότησης και ο handler διαφωνούν ως προς την εξουσία του *ίδιου* route.<sup>[[1]](#references)</sup> Κατά την αξιολόγηση ενός gateway, συγκρίνετε την ταξινόμηση των token, την ακριβή αντιστοίχιση route και method, καθώς και τον έλεγχο ρόλου του ίδιου του handler.<sup>[[1]](#references)</sup> Δείτε τα [web API authorization](../pentesting-web/web-api-pentesting.md), [401/403 bypasses](../pentesting-web/403-and-401-bypasses.md) και [proxy prefix exemptions](../pentesting-web/proxy-waf-protections-bypass.md#prefix-exemptions-become-routing-keys) για σχετικά αλλά διαφορετικά όρια.

## Οι εγγραφές ρυθμίσεων επηρεάζουν και άλλα συστήματα, πέρα από το store ρυθμίσεων

Η ίδια ενημέρωση ρυθμίσεων του LiteLLM δεχόταν τιμές μεταβλητών περιβάλλοντος και τις εφάρμοζε στη διεργασία που εκτελούνταν. Ένας καταναλωτής αντιμετώπιζε το `UI_LOGO_PATH` ως τοπική διαδρομή για ένα `FileResponse`, χωρίς να επαληθεύει ότι παρέπεμπε σε λογότυπο· ένας άλλος διάβαζε τα `UI_USERNAME` και `UI_PASSWORD` κατά τη σύνδεση εκτός SSO και απέδιδε τον ρόλο `PROXY_ADMIN` όταν τα στοιχεία ταίριαζαν. Επομένως, το δικαίωμα εγγραφής στις ρυθμίσεις μπορούσε να οδηγήσει τόσο σε αποκάλυψη τοπικών αρχείων όσο και σε αλλαγή διαχειριστικής ταυτότητας, ανάλογα με τον downstream καταναλωτή. Ο τύπος media της απόκρισης δεν αποδεικνύει ότι το αρχείο που σερβίρεται είναι εικόνα.<sup>[[1]](#references)</sup>

Η ρύθμιση του pass-through endpoint αποτελούσε ένα ακόμη downstream sink. Η αρχικοποίηση δεχόταν απομακρυσμένους προορισμούς adapter S3/GCS, κατέβαζε Python modules και τα εισήγαγε χρησιμοποιώντας την `exec_module` του `importlib`. Η εισαγωγή εκτελεί τον κώδικα ανώτατου επιπέδου πριν χρησιμοποιηθεί ένα instance του adapter· ο απλός περιορισμός της χρήσης του adapter δεν καταργεί αυτό το όριο εκτέλεσης. Αντιμετωπίστε το ως φόρτωση κώδικα ελεγχόμενη από ρυθμίσεις, όχι ως αποσειριοποίηση αρχείων μοντέλου.<sup>[[1]](#references)</sup> Για τον ξεχωριστό primitive ανάγνωσης αρχείων, δείτε το [file inclusion and path traversal](../pentesting-web/file-inclusion/).

## Η δρομολόγηση μοντέλων ανά αίτημα μπορεί να προκαλέσει leak διαπιστευτηρίων του gateway

Η λειτουργία διαπιστευτηρίων στην πλευρά του client του LiteLLM δεχόταν ένα αντικείμενο `user_config` σε ένα αίτημα LLM. Το αξιολογημένο route δημιουργούσε ένα προσωρινό `litellm.Router` από αυτό το αντικείμενο, συμπεριλαμβανομένων της λίστας μοντέλων και του `api_base` του παρόχου. Ένας προορισμός παρόχου που ελεγχόταν από τον καλούντα μπορούσε να λάβει το εξερχόμενο αίτημα completion του gateway και τις ρυθμισμένες κεφαλίδες αυθεντικοποίησης του παρόχου. Οι περιορισμοί στα πεδία `api_base` ή `api_key` ανώτατου επιπέδου δεν κάλυπταν αυτή την ξεχωριστή διαδρομή εμφωλευμένων ρυθμίσεων. Πρόκειται για όριο SSRF με χρήση διαπιστευτηρίων και όχι για ζήτημα prompt-injection.<sup>[[1]](#references)</sup>

Σε μια εξουσιοδοτημένη αξιολόγηση gateway, συγκρίνετε κάθε διαδρομή που μπορεί να δημιουργήσει router ή client παρόχου, συμπεριλαμβανομένων των ρυθμίσεων ανά αίτημα, με την πολιτική προορισμών και διαπιστευτηρίων της κανονικά ρυθμισμένης διαδρομής.<sup>[[1]](#references)</sup> Ο [SSRF guide](../pentesting-web/ssrf-server-side-request-forgery/) καλύπτει γενικά τον έλεγχο προορισμών από την πλευρά του server· το ειδικό πρόβλημα των gateway είναι ότι επιτρέπουν σε ένα αντικείμενο αιτήματος χαμηλότερης εμπιστοσύνης να επιλέγει προορισμό, ενώ επαναχρησιμοποιούν προνομιούχα εξερχόμενα διαπιστευτήρια.<sup>[[1]](#references)</sup>
