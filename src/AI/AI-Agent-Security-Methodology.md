# Μεθοδολογία Ασφάλειας AI Agent

{{#include ../banners/hacktricks-training.md}}

Μια αξιολόγηση agent πρέπει να ακολουθεί τη διαδρομή **από είσοδο ελεγχόμενη από επιτιθέμενο έως εξωτερικά παρατηρήσιμο αποτέλεσμα**. Το jailbreaking, οι αλλαγές χαρακτήρα και η αποκάλυψη system prompt αποδεικνύουν ότι ένα κανάλι συλλογισμού μπορεί να επηρεαστεί, αλλά το εύρημα υψηλού αντίκτυπου είναι η αλυσίδα που οδηγεί σε πρόσβαση σε δεδομένα, μη εξουσιοδοτημένη ενέργεια tool, sink downstream injection, persistence ή άλλον agent.<sup>[[2]](#references)</sup>

Το [OWASP Top 10 for Agentic Applications](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/) είναι χρήσιμο για την επισήμανση της κάλυψης (παραβίαση στόχου, κακή χρήση tool, κατάχρηση προνομίων, supply chain, εκτέλεση κώδικα, δηλητηρίαση μνήμης, εμπιστοσύνη μεταξύ agents, αλυσιδωτές αστοχίες, ανθρώπινη εμπιστοσύνη και rogue agents). Χρησιμοποιήστε αυτές τις ετικέτες αφού κατασκευάσετε μια end-to-end διαδρομή επίθεσης, αντί να θεωρείτε απρόσμενο κείμενο από το μοντέλο ως το τέλος της δοκιμής.<sup>[[1]](#references)[[2]](#references)</sup>

## Δημιουργία χάρτη του στόχου

Καταγράψτε αυτές τις πέντε διαστάσεις για κάθε workflow agent πριν γράψετε payloads:<sup>[[2]](#references)</sup>

| Διάσταση | Τι να απαριθμήσετε | Ερώτημα ασφάλειας |
|---|---|---|
| **Μη έμπιστη είσοδος** | Παράμετροι Chat/API, URLs, έγγραφα, email, tickets, καταχωρίσεις ημερολογίου, ανακτημένα τμήματα, μνήμη, αποτελέσματα tool και μηνύματα peer-agent | Πού μπορεί ένας επιτιθέμενος να τοποθετήσει περιεχόμενο που αργότερα θα εισαχθεί στο context του μοντέλου; |
| **Tools** | Ονόματα και schemas των tools, παρενέργειες, αυτόματη εκτέλεση, συμπεριφορά επιβεβαίωσης και tools που φορτώνονται δυναμικά | Ποιες κλήσεις διαβάζουν μυστικά, γράφουν κατάσταση, στέλνουν μηνύματα, διαγράφουν δεδομένα, εκτελούν κώδικα ή μεταφέρουν αξία; |
| **Εξουσιοδότηση** | Ανάθεση από χρήστη, service accounts, API tokens, διάρκεια ισχύος διαπιστευτηρίων, εμβέλεια tenant/resource και πρόσβαση στο δίκτυο | Με ποια ταυτότητα εκτελείται κάθε κλήση και επαναλαμβάνεται η εξουσιοδότηση στο όριο του tool; |
| **Επεξεργασία** | Query builders, shells, URL fetchers, μηχανές template, interpreters, parsers, λειτουργίες αρχείων και deserializers | Πού τα δεδομένα που παράγονται από το μοντέλο γίνονται σύνταξη για άλλον interpreter; |
| **Έξοδος** | Απαντήσεις, αποδοσμένο Markdown/HTML, links, ανακτήσεις εικόνων, webhooks, email, αρχεία, logs, αναφορές, metrics και κίνηση peer-agent | Ποιο παρατηρήσιμο κανάλι μπορεί να μεταφέρει ένα μυστικό ή να ενεργοποιήσει ένα δευτερεύον αίτημα; |

Μην το περιορίζετε σε μια λίστα διαφημιζόμενων integrations. Ένα χρήσιμο παραδοτέο αντιστοιχίζει κάθε πηγή στην ακριβή θέση context στην οποία φτάνει, στα διαθέσιμα tools σε εκείνο το σημείο, στα διαπιστευτήρια που χρησιμοποιεί κάθε tool, στον downstream interpreter και σε κάθε διαδρομή egress. Το ίδιο tool μπορεί να έχει μικρό αντίκτυπο με ένα read token ανά χρήστη και να είναι κρίσιμο με ένα κοινόχρηστο διαπιστευτήριο administrator.<sup>[[2]](#references)</sup>

## Αναγνώριση

### Χαρτογράφηση κάθε διαδρομής παράδοσης και εισαγωγής

Ξεκινήστε από την επιφάνεια παράδοσης (web, mobile, API, email, πλατφόρμα chat, browser extension) και παρακολουθήστε την κίνηση client-to-backend μέσω proxy. Επιθεωρήστε πεδία που αποκρύπτονται από το UI, παραμέτρους αναζήτησης/autocomplete/filter, αντικείμενα κατάστασης συνομιλίας, εργασίες upload και indexing, αποκρίσεις tool και κίνηση sub-agent. Για clients που είναι διαθέσιμοι μόνο σε mobile μπορεί να χρειαστεί emulator και instrumentation για παράκαμψη του certificate pinning, προτού γίνει ορατό το πραγματικό schema των αιτημάτων.<sup>[[2]](#references)</sup>

Στη συνέχεια, χαρτογραφήστε το stack κάτω από το μοντέλο: orchestration framework, συναρμολόγηση prompt, αποθήκες retrieval και μνήμης, runtime (για παράδειγμα Python, container ή WASM), προσαρτημένοι τόμοι, υπηρεσίες host, εσωτερικά APIs, δυνατότητα πρόσβασης σε cloud metadata και γειτονικά δίκτυα. Οι προεπιλεγμένες ρυθμίσεις του framework έχουν σημασία, επειδή ορισμένες «κλήσεις tool» υλοποιούνται με παραγωγή ή αξιολόγηση κώδικα· το όριο του runtime/sandbox καθορίζει αν το αποτέλεσμα παραμένει περιορισμένο.<sup>[[2]](#references)</sup>

### Αποτύπωση δρομολόγησης με μη καταστροφικά probes

Συγκρίνετε ένα αίτημα εντός του πεδίου αξιολόγησης με αρκετά άσχετα αιτήματα, διατηρώντας ολόκληρη την απόκριση, τον κωδικό κατάστασης, τον χρόνο απόκρισης και τη συμπεριφορά streaming. Μια σταθερή απόρριψη πριν από οποιονδήποτε συλλογισμό σχετικό με την εργασία μπορεί να υποδεικνύει ξεχωριστό gateway/classifier· μια άρνηση που εξαρτάται από το context υποδηλώνει ότι το αίτημα έφτασε στο μοντέλο· μια κενή ή αμιγώς εξαγωγική απάντηση μπορεί να υποδεικνύει αναζήτηση βάσει λέξεων-κλειδιών ή περιορισμένο retrieval. Αντιμετωπίστε τα ως υποθέσεις και επιβεβαιώστε τες επαναλαμβάνοντας το ίδιο probe μέσω εναλλακτικών πεδίων API και διαδρομών εισαγωγής.<sup>[[2]](#references)</sup>

Η αναγνώριση ολοκληρώνεται όταν η αξιολόγηση μπορεί να προσδιορίσει την πρωιμότερη πηγή ελεγχόμενη από επιτιθέμενο που αλλάζει τη συμπεριφορά του agent **και** τα tools, τις ταυτότητες, τους interpreters και τις εξόδους που είναι προσβάσιμα από αυτήν την πηγή.<sup>[[2]](#references)</sup>

## Exploitation: υπέρβαση ενός ορίου εμπιστοσύνης

Δοκιμάστε κανάλια, όχι μόνο τη διατύπωση του prompt. Ξεκινήστε με άμεσο injection για να διαπιστώσετε τι μπλοκάρει η ορατή είσοδος και, στη συνέχεια, επαναλάβετε ισοδύναμη πρόθεση μέσω των λιγότερο ορατών διαδρομών παρακάτω:<sup>[[2]](#references)</sup>

- **Έμμεσο περιεχόμενο:** σελίδες, αρχεία, email, tickets, metadata, alt text, σχόλια HTML, κείμενο εκτός οθόνης ή χαρακτήρες zero-width. Δείτε το [AI Prompts](AI-Prompts.md#third-party-or-indirect-prompt-injection) για τεχνικές παράδοσης payload.
- **Retrieval και μνήμη:** δηλητηριάστε περιεχόμενο που θα ανακτηθεί αργότερα ή κατάσταση που θα φορτωθεί ξανά σε μελλοντικές συνεδρίες. Καταγράψτε αν η διαγραφή της αρχικής πηγής αφαιρεί τη συμπεριφορά.
- **Έξοδος tool και peer agents:** τοποθετήστε τον δείκτη σε απόκριση tool ή σε μήνυμα agent-to-agent, για να δοκιμάσετε αν η εσωτερική κίνηση παρακάμπτει τα φίλτρα που εφαρμόζονται μόνο στην είσοδο χρήστη και στην τελική έξοδο.
- **Supply chain:** εξετάστε περιγραφές tool, plugins, συνδεδεμένους servers, skills, μοντέλα και dependencies ως έμπιστες πηγές οδηγιών. Για ειδικές δοκιμές MCP, δείτε το [MCP Servers](AI-MCP-Servers.md#mcp-vulns).
- **Ανθρώπινη έγκριση:** συγκρίνετε την πραγματική δομημένη κλήση tool με το κείμενο έγκρισης που παρήγαγε το μοντέλο. Ελέγξτε αν η επιρροή του επιτιθέμενου μπορεί να παραλείψει τον προορισμό, το πεδίο εφαρμογής, τα επηρεαζόμενα αντικείμενα ή μη αναστρέψιμες παρενέργειες.

Χρησιμοποιήστε πρώτα έναν ακίνδυνο, μοναδικό δείκτη. Διατηρήστε το αρχικό artifact, το συναρμολογημένο context αν είναι ορατό, την επιλεγμένη κλήση tool, τα δεδομένα έγκρισης, το αίτημα/την απόκριση backend και την τελική κατάσταση. Έτσι διαχωρίζεται η επιρροή από έναν ισχυρισμό του μοντέλου ότι συνέβη μια ενέργεια, ο οποίος μπορεί να είναι hallucination.<sup>[[2]](#references)</sup>

## Εκτέλεση: απόδειξη πραγματικού αντίκτυπου

Υπάρχουν δύο διακριτές διαδρομές από την επιρροή στον αντίκτυπο:<sup>[[2]](#references)</sup>

1. **Κατάχρηση δυνατότητας:** το εξουσιοδοτημένο tool εκτελεί ήδη τον επιδιωκόμενο στόχο. Παραδείγματα περιλαμβάνουν την ανάγνωση εγγραφής ενός tenant και την εγγραφή της σε αναφορά ορατή στον επιτιθέμενο, την αποστολή email, την αλλαγή εγγραφών, τη διαγραφή αρχείου ή την έναρξη πληρωμής. Δεν απαιτείται δευτερεύον software bug.
2. **Εκμετάλλευση downstream sink:** η έξοδος του μοντέλου που κατευθύνεται από τον επιτιθέμενο γίνεται σύνταξη για άλλο component. Εξετάστε τα database queries για [SQL injection](../pentesting-web/sql-injection/README.md) ή [NoSQL injection](../pentesting-web/nosql-injection.md), τα shell wrappers για [command injection](../pentesting-web/command-injection.md), τα URLs που επιλέγονται για [SSRF](../pentesting-web/ssrf-server-side-request-forgery/README.md), τις λειτουργίες αρχείων για path traversal, τους αξιολογητές template/code για RCE και τους object parsers για [unsafe deserialization](../pentesting-web/deserialization/README.md).

Για κάθε υποψήφιο εύρημα, αποδείξτε αυτήν την αλυσίδα:<sup>[[2]](#references)</sup>

```text
attacker-controlled source
  -> model/context influence
  -> selected tool and arguments
  -> effective identity/credential
  -> capability or vulnerable sink
  -> externally verified state change or data egress
```

Μια ενσωμάτωση μόνο για ανάγνωση εξακολουθεί να είναι εκμεταλλεύσιμη όταν οποιοδήποτε επόμενο στοιχείο μπορεί να δημοσιεύσει όσα διάβασε. Ελέγξτε τις συνηθισμένες απαντήσεις, καθώς και λιγότερο προφανείς οδούς εξαγωγής δεδομένων, όπως συνδέσμους που ελέγχει ο επιτιθέμενος, αυτόματη ανάκτηση εικόνων, webhooks, αρχεία καταγραφής, αναφορές, μετρητές, ειδοποιήσεις και μηνύματα προς άλλους agents.<sup>[[2]](#references)</sup>

## Ενέργειες επί των στόχων

Αφού επιβεβαιώσετε μία ενέργεια, αξιολογήστε ολόκληρο το εύρος των επιπτώσεων αντί να σταματήσετε στο πρώτο ορατό αποτέλεσμα:<sup>[[2]](#references)</sup>

- **Εξαγωγή δεδομένων:** μυστικά, εγγραφές χρηστών, εσωτερικά αρχεία, δεδομένα συνομιλιών ή περιεχόμενο prompt/context εξέρχονται μέσω παρατηρήσιμου καναλιού.
- **Μη εξουσιοδοτημένη ενέργεια:** ο agent χρησιμοποιεί νόμιμες δυνατότητες εγγραφής για τον σκοπό του επιτιθέμενου.
- **Άρνηση υπηρεσίας:** καταστροφικά εργαλεία ή επαναλαμβανόμενες δαπανηρές λειτουργίες επηρεάζουν την ακεραιότητα ή τη διαθεσιμότητα.
- **Εμμονή:** δηλητηριασμένη μνήμη, ευρετηριασμένο περιεχόμενο, έμπιστη κατάσταση ή αλλαγές χρόνου εκτέλεσης επιβιώνουν μετά τη συνεδρία ή την αφαίρεση της πηγής που τα προκάλεσε.
- **Διάδοση:** ένας έμπιστος ομότιμος καταναλώνει το μήνυμα ή την κοινόχρηστη κατάσταση του παραβιασμένου agent και επαναλαμβάνει την ενέργεια με τα δικά του εργαλεία και διαπιστευτήρια.

Η σοβαρότητα πρέπει να βασίζεται στα προσβάσιμα δεδομένα, στα πραγματικά δικαιώματα, στην εκμεταλλευσιμότητα του sink, στην εξαγωγή δεδομένων, στην εμμονή και στη διάδοση — όχι στο πόσο απροσδόκητο φαίνεται το κείμενο του μοντέλου.<sup>[[2]](#references)</sup>

## Έλεγχοι προς επικύρωση κατά την αξιολόγηση

Τα φίλτρα prompt και ένα καλύτερο system prompt μπορούν να αυξήσουν το κόστος για τον επιτιθέμενο, αλλά δεν πρέπει να θεωρούνται όρια εξουσιοδότησης. Επικυρώστε τους παρακάτω ελέγχους επαναλαμβάνοντας την ίδια αλυσίδα μέσω άμεσης εισόδου, έμμεσου περιεχομένου, μνήμης, εργαλείων και peer agents:<sup>[[2]](#references)</sup>

- Ένα ντετερμινιστικό επίπεδο πολιτικής ελέγχει τον ταυτοποιημένο χρήστη, τον tenant, το αντικείμενο, την ενέργεια και τον προορισμό σε **κάθε κλήση εργαλείου**· το μοντέλο δεν μπορεί να ορίσει ή να παρακάμψει την ταυτότητα του καλούντος.
- Οι δυνατότητες ανάγνωσης και εγγραφής χρησιμοποιούν ξεχωριστά διαπιστευτήρια ελάχιστων προνομίων, περιορισμένης διάρκειας· τα εργαλεία υψηλού αντίκτυπου παρέχονται just-in-time και δεν εκτελούνται ποτέ αυτόματα βάσει εισερχόμενου περιεχομένου.
- Η εξερχόμενη κίνηση δικτύου και οι εσωτερικοί προορισμοί βρίσκονται σε allowlist, ανεξάρτητα από τα URL που επιλέγει το μοντέλο· η πρόσβαση χρόνου εκτέλεσης σε endpoints μεταδεδομένων, προσαρτημένα μυστικά και γειτονικές υπηρεσίες αποκλείεται, εκτός αν απαιτείται.
- Το UI έγκρισης παράγεται από το κανονικό δομημένο αίτημα και εμφανίζει τα ακριβή ορίσματα, την ταυτότητα, τον προορισμό, τα επηρεαζόμενα αντικείμενα και τις παρενέργειες — όχι μια ελεύθερου κειμένου σύνοψη του μοντέλου.
- Η επιτυχία επαληθεύεται από το σύστημα προορισμού ή το σύστημα καταγραφής. Η αφήγηση του agent, ένα αίτημα κλήσης εργαλείου ή μια ανακατεύθυνση HTTP δεν αποδεικνύουν την αλλαγή κατάστασης που ισχυρίζεται.
- Οι εγγραφές μνήμης και ανάκτησης διατηρούν την προέλευση και τις ετικέτες εμπιστοσύνης, μπορούν να ακυρωθούν και επανελέγχονται ως προς την εξουσιοδότηση όταν χρησιμοποιούνται σε μεταγενέστερη ενέργεια.
- Τα μηνύματα μεταξύ agents ταυτοποιούνται και εξουσιοδοτούνται ως μη έμπιστα αιτήματα· η φήμη ενός peer ή η κάρτα agent δεν εκχωρεί σιωπηρά τα εργαλεία του παραλήπτη.
