# Μεθοδολογία Ασφάλειας AI Agent

{{#include ../banners/hacktricks-training.md}}

Μια αξιολόγηση agent πρέπει να ακολουθεί τη διαδρομή **από είσοδο ελεγχόμενη από τον επιτιθέμενο έως ένα εξωτερικά παρατηρήσιμο αποτέλεσμα**. Το jailbreaking, οι αλλαγές χαρακτήρα και η αποκάλυψη system prompt αποδεικνύουν ότι ένα κανάλι συλλογισμού μπορεί να επηρεαστεί, αλλά το εύρημα υψηλού αντίκτυπου είναι η αλυσίδα που οδηγεί σε πρόσβαση σε δεδομένα, μη εξουσιοδοτημένη ενέργεια εργαλείου, downstream injection sink, persistence ή άλλον agent.<sup>[[2]](#references)</sup>

Το [OWASP Top 10 for Agentic Applications](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/) είναι χρήσιμο για την επισήμανση της κάλυψης (παραβίαση στόχου, κακή χρήση εργαλείων, κατάχρηση προνομίων, supply chain, εκτέλεση κώδικα, δηλητηρίαση μνήμης, εμπιστοσύνη μεταξύ agent, αλυσιδωτές αστοχίες, ανθρώπινη εμπιστοσύνη και rogue agents). Χρησιμοποιήστε αυτές τις ετικέτες αφού κατασκευάσετε μια end-to-end διαδρομή επίθεσης, αντί να θεωρείτε απροσδόκητο κείμενο του μοντέλου ως το τέλος του ελέγχου.<sup>[[1]](#references)[[2]](#references)</sup>

## Χαρτογράφηση του στόχου

Καταγράψτε τις ακόλουθες πέντε διαστάσεις για κάθε workflow agent πριν γράψετε payloads:<sup>[[2]](#references)</sup>

| Διάσταση | Τι να καταγράψετε | Ερώτημα ασφάλειας |
|---|---|---|
| **Μη έμπιστη είσοδος** | Παράμετροι Chat/API, URLs, έγγραφα, email, tickets, καταχωρίσεις ημερολογίου, ανακτημένα αποσπάσματα, μνήμη, αποτελέσματα εργαλείων και μηνύματα από άλλους agent | Πού μπορεί ένας επιτιθέμενος να τοποθετήσει περιεχόμενο που αργότερα εισέρχεται στο context του μοντέλου; |
| **Εργαλεία** | Ονόματα και schemas εργαλείων, παρενέργειες, αυτόματη εκτέλεση, συμπεριφορά επιβεβαίωσης και εργαλεία που φορτώνονται δυναμικά | Ποιες κλήσεις διαβάζουν μυστικά, γράφουν κατάσταση, στέλνουν μηνύματα, διαγράφουν δεδομένα, εκτελούν κώδικα ή μεταφέρουν αξία; |
| **Εξουσιοδότηση** | Ανάθεση από χρήστη, service accounts, API tokens, διάρκεια ζωής διαπιστευτηρίων, εύρος tenant/resource και πρόσβαση στο δίκτυο | Με ποια ταυτότητα εκτελείται κάθε κλήση και επαναλαμβάνεται ο έλεγχος εξουσιοδότησης στο όριο του εργαλείου; |
| **Επεξεργασία** | Query builders, shells, URL fetchers, μηχανές template, interpreters, parsers, λειτουργίες αρχείων και deserializers | Πού τα δεδομένα που δημιουργεί το μοντέλο γίνονται σύνταξη για άλλον interpreter; |
| **Έξοδος** | Απαντήσεις, αποδιδόμενο Markdown/HTML, σύνδεσμοι, λήψεις εικόνων, webhooks, email, αρχεία, logs, αναφορές, metrics και επικοινωνία μεταξύ agent | Ποιο παρατηρήσιμο κανάλι μπορεί να μεταφέρει μυστικό ή να ενεργοποιήσει δευτερεύον αίτημα; |

Μην το περιορίζετε σε μια λίστα διαφημιζόμενων integrations. Ένα χρήσιμο τεκμήριο αντιστοιχίζει κάθε πηγή με την ακριβή θέση context στην οποία φτάνει, τα εργαλεία που είναι διαθέσιμα εκεί, τα διαπιστευτήρια που χρησιμοποιεί κάθε εργαλείο, τον downstream interpreter και κάθε διαδρομή egress. Το ίδιο εργαλείο μπορεί να έχει χαμηλό αντίκτυπο με ένα read token ανά χρήστη και να είναι κρίσιμο με κοινόχρηστο διαπιστευτήριο διαχειριστή.<sup>[[2]](#references)</sup>

## Αναγνώριση

### Χαρτογράφηση κάθε διαδρομής παράδοσης και εισαγωγής

Ξεκινήστε από την επιφάνεια παράδοσης (web, mobile, API, email, πλατφόρμα chat, browser extension) και καταγράψτε μέσω proxy την κίνηση client-to-backend. Εξετάστε πεδία που κρύβονται από το UI, παραμέτρους αναζήτησης/autocomplete/filter, αντικείμενα κατάστασης συνομιλίας, εργασίες upload και indexing, αποκρίσεις εργαλείων και κίνηση sub-agent. Οι mobile-only clients ενδέχεται να απαιτούν emulator και instrumentation για παράκαμψη του certificate pinning, πριν γίνει ορατό το πραγματικό request schema.<sup>[[2]](#references)</sup>

Στη συνέχεια, χαρτογραφήστε το stack κάτω από το μοντέλο: framework orchestration, συναρμολόγηση prompt, αποθήκες retrieval και μνήμης, runtime (για παράδειγμα Python, container ή WASM), mounted volumes, υπηρεσίες host, εσωτερικά APIs, πρόσβαση σε cloud metadata και γειτονικά δίκτυα. Οι προεπιλογές του framework έχουν σημασία, επειδή ορισμένες «κλήσεις εργαλείων» υλοποιούνται με παραγωγή ή αξιολόγηση κώδικα· το όριο runtime/sandbox καθορίζει αν το αποτέλεσμα παραμένει περιορισμένο.<sup>[[2]](#references)</sup>

### Αποτύπωση της δρομολόγησης με μη καταστροφικά probes

Συγκρίνετε ένα αίτημα εντός scope με αρκετά άσχετα αιτήματα, διατηρώντας πλήρως την απόκριση, τον κωδικό κατάστασης, την καθυστέρηση και τη συμπεριφορά streaming. Μια σταθερή απόρριψη πριν από οποιονδήποτε συλλογισμό ειδικό για την εργασία μπορεί να υποδεικνύει ξεχωριστό gateway/classifier· μια άρνηση που εξαρτάται από το context υποδηλώνει ότι το αίτημα έφτασε στο μοντέλο· μια κενή ή αμιγώς εξαγωγική απάντηση μπορεί να υποδεικνύει αναζήτηση λέξεων-κλειδιών ή περιορισμένο retrieval. Αντιμετωπίστε τα ως υποθέσεις και επιβεβαιώστε τις επαναλαμβάνοντας το ίδιο probe μέσω εναλλακτικών πεδίων API και διαδρομών εισαγωγής.<sup>[[2]](#references)</sup>

Η αναγνώριση ολοκληρώνεται όταν η αξιολόγηση μπορεί να κατονομάσει την πρώτη πηγή ελεγχόμενη από τον επιτιθέμενο που αλλάζει τη συμπεριφορά του agent **και** τα εργαλεία, τις ταυτότητες, τους interpreters και τις εξόδους που είναι προσβάσιμα από αυτή την πηγή.<sup>[[2]](#references)</sup>

## Εκμετάλλευση: υπέρβαση ορίου εμπιστοσύνης

Ελέγξτε τα κανάλια, όχι μόνο τη διατύπωση του prompt. Ξεκινήστε με άμεσο injection για να διαπιστώσετε τι αποκλείει η ορατή είσοδος και, στη συνέχεια, επαναλάβετε ισοδύναμη πρόθεση μέσω των λιγότερο ορατών διαδρομών παρακάτω:<sup>[[2]](#references)</sup>

- **Έμμεσο περιεχόμενο:** σελίδες, αρχεία, email, tickets, metadata, alt text, σχόλια HTML, κείμενο εκτός οθόνης ή χαρακτήρες μηδενικού πλάτους. Δείτε το [AI Prompts](AI-Prompts.md#third-party-or-indirect-prompt-injection) για τεχνικές παράδοσης payload.
- **Retrieval και μνήμη:** δηλητηριάστε περιεχόμενο που θα ανακτηθεί αργότερα ή κατάσταση που θα επαναφορτωθεί σε επόμενες συνεδρίες. Καταγράψτε αν η διαγραφή της αρχικής πηγής αφαιρεί τη συμπεριφορά.
- **Έξοδος εργαλείου και άλλοι agent:** τοποθετήστε τον marker σε απόκριση εργαλείου ή μήνυμα μεταξύ agent για να ελέγξετε αν η εσωτερική κίνηση παρακάμπτει τα φίλτρα που εφαρμόζονται μόνο στην είσοδο χρήστη και στην τελική έξοδο.
- **Supply chain:** εξετάστε περιγραφές εργαλείων, plugins, συνδεδεμένους servers, skills, μοντέλα και dependencies ως έμπιστες πηγές οδηγιών. Για ελέγχους ειδικά για MCP, δείτε το [MCP Servers](AI-MCP-Servers.md#mcp-vulns).
- **Ανθρώπινη έγκριση:** συγκρίνετε την πραγματική δομημένη κλήση εργαλείου με το κείμενο έγκρισης που δημιουργήθηκε από το μοντέλο. Ελέγξτε αν η επιρροή του επιτιθέμενου μπορεί να παραλείψει τον προορισμό, το scope, τα αντικείμενα που επηρεάζονται ή μη αναστρέψιμες παρενέργειες.

Χρησιμοποιήστε πρώτα έναν ακίνδυνο, μοναδικό marker. Διατηρήστε το αρχικό τεκμήριο, το συναρμολογημένο context αν είναι ορατό, την επιλεγμένη κλήση εργαλείου, τα δεδομένα έγκρισης, το αίτημα/την απόκριση του backend και την τελική κατάσταση. Έτσι διαχωρίζεται η πραγματική επιρροή από έναν hallucinated ισχυρισμό ότι πραγματοποιήθηκε κάποια ενέργεια.<sup>[[2]](#references)</sup>

### Κείμενο που μιμείται πολιτική σε κριτή αξιολόγησης κινδύνου εργαλείου

Ένα model-based tool gate μπορεί να λάβει κείμενο ελεγχόμενο από τον επιτιθέμενο μέσα σε κατά τα άλλα χρήσιμο context ταξινόμησης. Για παράδειγμα, το πειραματικό `AutoModeMiddleware` του LangChain στέλνει μια προτεινόμενη κλήση εργαλείου, τα ορίσματά της, μια προαιρετική περιγραφή εργαλείου και έως 30 πρόσφατα μηνύματα σε έναν κριτή TypeSafe `is_risky`. Αποκλείει τα ρυθμισμένα εργαλεία όταν η πιθανότητα Noul που επιστρέφεται είναι τουλάχιστον `0.5`· τα εργαλεία που δεν αναφέρονται δεν ταξινομούνται από αυτό το middleware.<sup>[[5]](#references)</sup> Το TypeSafe προειδοποιεί επίσης ότι adversarial κείμενο στην κατάσταση μπορεί να επηρεάσει μια ταξινόμηση, ακόμη κι όταν η κατάσταση προορίζεται να είναι δεδομένα.<sup>[[6]](#references)</sup>

Μια **πλαστή πολιτική** διαφέρει από έναν απλό ισχυρισμό ότι είναι system message. Τοποθετεί εναλλακτικές ετικέτες ή ορισμούς κινδύνου σε κατάσταση χαμηλότερης εμπιστοσύνης και ωθεί τον κριτή να χρησιμοποιήσει αυτούς τους ορισμούς αντί για τα κριτήρια που έχει ορίσει ο developer. Στη δοκιμή της Datadog, ένα επεξεργάσιμο από τον χρήστη `profile_description` αντιγράφηκε στα ορίσματα του εργαλείου μαζί με το `can_edit:false`. Το κείμενο που έμοιαζε με πολιτική υποστήριζε ότι μια απόπειρα εγγραφής είχε χαμηλό κίνδυνο, επειδή ξεχωριστός έλεγχος δικαιωμάτων θα την απέρριπτε πριν από οποιαδήποτε μεταβολή. Σε 40 εκτελέσεις, η μέση βαθμολογία `is_risky` μειώθηκε από `0.893` σε `0.290`, ενώ η σύγκριση με άμεσο role-spoofing είχε μέσο όρο `0.905`. Η πτώση του μέσου όρου κάτω από `0.5` δεν αποδεικνύει ότι κάθε μεμονωμένη κλήση πέρασε το gate, και το πείραμα **δεν** απέδειξε ολοκληρωμένη μη εξουσιοδοτημένη εγγραφή.<sup>[[7]](#references)</sup>

Κατά τον έλεγχο αυτού του ορίου, διακρίνετε την απόφαση του classifier από το πραγματικό αποτέλεσμα εξουσιοδότησης του εργαλείου. Ελέγξτε ποια επεξεργάσιμα πεδία φτάνουν στον κριτή, συγκρίνετε την ίδια προτεινόμενη ενέργεια με και χωρίς κείμενο που μοιάζει με πολιτική και επαληθεύστε ανεξάρτητα την τελική κατάσταση. Ένας ξεχωριστός έλεγχος δικαιωμάτων πρέπει και πάλι να χρησιμοποιεί την εξουσία του αυθεντικοποιημένου αιτούντος και όχι τα δικαιώματα του service account του connector.<sup>[[7]](#references)</sup> Δείτε το [prompt-filter bypasses](AI-Prompts.md#prompt-waf-bypass) για άλλες αστοχίες classifier· τα [LLM gateway trust boundaries](AI-LLM-Gateway-Security.md) αφορούν διαφορετικό όριο δρομολόγησης και διαπιστευτηρίων.

### Απομόνωση context subagent

Ένας subagent του Claude Agent SDK που δεν δημιουργείται με fork λαμβάνει το δικό του `AgentDefinition.prompt`, το prompt ανάθεσης και τα διαθέσιμα εργαλεία του, αλλά όχι το system prompt ή τη συνομιλία του parent. Αν παραλειφθεί το `tools` από τον ορισμό του, κληρονομεί τα εργαλεία που είναι διαθέσιμα στους subagents· το project `CLAUDE.md` ενδέχεται και πάλι να φορτωθεί. Αυτό καθιστά έναν περιορισμό prompt που ισχύει μόνο για τον parent αναξιόπιστο όριο, όταν το child μπορεί να χρησιμοποιήσει τα ίδια εργαλεία filesystem ή εκτέλεσης.<sup>[[4]](#references)</sup>

Ελέγξτε το όριο συγκρίνοντας ένα άμεσο αίτημα που ο parent αρνείται με την ίδια εργασία ανατεθειμένη σε subagent με όνομα. Η NCC Group αναφέρει ότι μια άρνηση απαρίθμησης αρχείων του λειτουργικού συστήματος πέτυχε όταν διατυπώθηκε για ένα child ως αβλαβής «χάρτης διάταξης».<sup>[[3]](#references)</sup>

Εξετάστε τις πραγματικές κλήσεις εργαλείων του child και την αποτελεσματική allowlist εργαλείων, όχι μόνο την τελική απάντηση του parent· επιβεβαιώστε αν το child προσπέλασε αρχεία που ο parent δεν θα προσπέλαζε.<sup>[[4]](#references)</sup> Πρόκειται για αστοχία κληρονόμησης guardrail, όχι για απόδειξη [Python sandbox](../generic-methodologies-and-resources/python/bypass-python-sandboxes/) ή διαφυγής από container.<sup>[[3]](#references)[[4]](#references)</sup>

## Εκτέλεση: απόδειξη πραγματικού αντίκτυπου

Υπάρχουν δύο διαφορετικές διαδρομές από την επιρροή στον αντίκτυπο:<sup>[[2]](#references)</sup>

1. **Κατάχρηση δυνατοτήτων:** το εξουσιοδοτημένο εργαλείο ήδη επιτυγχάνει τον στόχο. Παραδείγματα είναι η ανάγνωση εγγραφής ενός tenant και η εγγραφή της σε αναφορά ορατή στον επιτιθέμενο, η αποστολή email, η αλλαγή εγγραφών, η διαγραφή αρχείου ή η έναρξη πληρωμής. Δεν απαιτείται δευτερεύον software bug.
2. **Εκμετάλλευση downstream sink:** η έξοδος του μοντέλου, καθοδηγούμενη από τον επιτιθέμενο, γίνεται σύνταξη για άλλο στοιχείο. Εξετάστε τα database queries για [SQL injection](../pentesting-web/sql-injection/README.md) ή [NoSQL injection](../pentesting-web/nosql-injection.md), τα shell wrappers για [command injection](../pentesting-web/command-injection.md), τα επιλεγμένα URLs για [SSRF](../pentesting-web/ssrf-server-side-request-forgery/README.md), τις λειτουργίες αρχείων για traversal, τους template/code evaluators για RCE και τους object parsers για [unsafe deserialization](../pentesting-web/deserialization/README.md).

Για κάθε υποψήφια περίπτωση, αποδείξτε την ακόλουθη αλυσίδα:<sup>[[2]](#references)</sup>

```text
attacker-controlled source
  -> model/context influence
  -> selected tool and arguments
  -> effective identity/credential
  -> capability or vulnerable sink
  -> externally verified state change or data egress
```

Μια read-only ενσωμάτωση εξακολουθεί να είναι εκμεταλλεύσιμη όταν οποιοδήποτε μεταγενέστερο στοιχείο μπορεί να δημοσιεύσει όσα διάβασε. Δοκιμάστε τις συνηθισμένες αποκρίσεις, καθώς και λιγότερο προφανείς διαύλους egress, όπως συνδέσμους που ελέγχονται από τον εισβολέα, αυτόματη ανάκτηση εικόνων, webhooks, logs, αναφορές, μετρητές, ειδοποιήσεις και μηνύματα προς άλλους agents.<sup>[[2]](#references)</sup>

## Ενέργειες προς επίτευξη στόχων

Αφού επιβεβαιώσετε μία ενέργεια, αξιολογήστε ολόκληρο το blast radius αντί να σταματήσετε στο πρώτο ορατό αποτέλεσμα:<sup>[[2]](#references)</sup>

- **Exfiltration:** μυστικά, εγγραφές χρηστών, εσωτερικά αρχεία, δεδομένα συνομιλιών ή περιεχόμενο prompt/context διαρρέουν μέσω παρατηρήσιμου διαύλου.
- **Μη εξουσιοδοτημένη ενέργεια:** ο agent χρησιμοποιεί νόμιμες δυνατότητες εγγραφής για να εξυπηρετήσει τον στόχο του εισβολέα.
- **Denial of service:** καταστροφικά εργαλεία ή επαναλαμβανόμενες δαπανηρές λειτουργίες επηρεάζουν την ακεραιότητα ή τη διαθεσιμότητα.
- **Persistence:** δηλητηριασμένη μνήμη, ευρετηριασμένο περιεχόμενο, έμπιστη κατάσταση ή αλλαγές κατά τον χρόνο εκτέλεσης διατηρούνται μετά τη συνεδρία ή την αφαίρεση της πηγής από την οποία προήλθαν.
- **Propagation:** ένας έμπιστος peer χρησιμοποιεί το μήνυμα ή την κοινόχρηστη κατάσταση του παραβιασμένου agent και επαναλαμβάνει την ενέργεια με τα δικά του εργαλεία και διαπιστευτήρια.

Η σοβαρότητα πρέπει να βασίζεται στα προσβάσιμα δεδομένα, στα πραγματικά δικαιώματα, στη δυνατότητα εκμετάλλευσης του sink, στο egress, στο persistence και στο propagation — όχι στο πόσο απρόσμενο φαίνεται το κείμενο του μοντέλου.<sup>[[2]](#references)</sup>

## Έλεγχοι προς επικύρωση κατά την αξιολόγηση

Τα φίλτρα prompt και ένα καλύτερο system prompt μπορούν να αυξήσουν το κόστος για τον εισβολέα, αλλά δεν πρέπει να θεωρούνται όρια εξουσιοδότησης. Επικυρώστε τους παρακάτω ελέγχους επαναλαμβάνοντας την ίδια αλυσίδα μέσω άμεσης εισόδου, έμμεσου περιεχομένου, μνήμης, εργαλείων και peer agents:<sup>[[2]](#references)</sup>

- Ένα ντετερμινιστικό επίπεδο πολιτικής ελέγχει τον πιστοποιημένο χρήστη, τον tenant, το αντικείμενο, την ενέργεια και τον προορισμό σε **κάθε κλήση εργαλείου**· το μοντέλο δεν μπορεί να ορίσει ή να παρακάμψει την ταυτότητα του καλούντος.
- Οι δυνατότητες ανάγνωσης και εγγραφής χρησιμοποιούν ξεχωριστά, ελάχιστων προνομίων και βραχύβια διαπιστευτήρια· τα εργαλεία υψηλού αντίκτυπου παρέχονται just in time και δεν εκτελούνται ποτέ αυτόματα βάσει περιεχομένου που έχει εισαχθεί.
- Το egress δικτύου και οι εσωτερικοί προορισμοί επιτρέπονται βάσει λίστας επιτρεπόμενων προορισμών, ανεξάρτητα από τα URL που επιλέγει το μοντέλο· η πρόσβαση κατά τον χρόνο εκτέλεσης σε endpoints μεταδεδομένων, προσαρτημένα μυστικά και γειτονικές υπηρεσίες αποκλείεται, εκτός αν είναι απαραίτητη.
- Το UI έγκρισης δημιουργείται από το κανονικό δομημένο αίτημα και εμφανίζει τα ακριβή ορίσματα, την ταυτότητα, τον προορισμό, τα επηρεαζόμενα αντικείμενα και τις παρενέργειες — όχι μια ελεύθερη σύνοψη του μοντέλου.
- Η επιτυχία επαληθεύεται από το σύστημα προορισμού ή το σύστημα καταγραφής. Η αφήγηση του agent, ένα αίτημα κλήσης εργαλείου ή μια ανακατεύθυνση HTTP δεν αποδεικνύουν την αναφερόμενη αλλαγή κατάστασης.
- Οι εγγραφές μνήμης και ανάκτησης διατηρούν πληροφορίες προέλευσης και ετικέτες εμπιστοσύνης, μπορούν να ακυρωθούν και επανεγκρίνονται όταν χρησιμοποιούνται για μεταγενέστερη ενέργεια.
- Τα μηνύματα μεταξύ agents πιστοποιούνται και εξουσιοδοτούνται ως μη έμπιστα αιτήματα· η φήμη ενός peer ή η κάρτα agent δεν εκχωρεί σιωπηρά τα εργαλεία του παραλήπτη.
