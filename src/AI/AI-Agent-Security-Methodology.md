# Μεθοδολογία Ασφάλειας AI Agent

Μια αξιολόγηση agent πρέπει να ακολουθεί την αλυσίδα **από είσοδο ελεγχόμενη από τον επιτιθέμενο έως εξωτερικά παρατηρήσιμο αποτέλεσμα**. Το jailbreaking, οι αλλαγές χαρακτήρα και η αποκάλυψη system prompt αποδεικνύουν ότι ένα κανάλι συλλογισμού μπορεί να επηρεαστεί, αλλά το εύρημα υψηλού αντίκτυπου είναι η αλυσίδα που οδηγεί σε πρόσβαση σε δεδομένα, μη εξουσιοδοτημένη ενέργεια εργαλείου, sink downstream injection, persistence ή άλλον agent.<sup>[[2]](#references)</sup>

Το [OWASP Top 10 for Agentic Applications](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/) είναι χρήσιμο για την επισήμανση της κάλυψης (goal hijacking, tool misuse, privilege abuse, supply chain, code execution, memory poisoning, inter-agent trust, cascading failures, human trust και rogue agents). Χρησιμοποιήστε αυτές τις ετικέτες αφού κατασκευάσετε μια end-to-end διαδρομή επίθεσης, αντί να θεωρείτε ότι το απρόσμενο κείμενο ενός μοντέλου αποτελεί το τέλος της δοκιμής.<sup>[[1]](#references)[[2]](#references)</sup>

## Δημιουργία χάρτη στόχου

Καταγράψτε αυτές τις πέντε διαστάσεις για κάθε workflow agent προτού γράψετε payloads:<sup>[[2]](#references)</sup>

| Διάσταση | Τι να απαριθμήσετε | Ερώτηση ασφάλειας |
|---|---|---|
| **Μη έμπιστη είσοδος** | Παράμετροι Chat/API, URLs, έγγραφα, email, tickets, καταχωρίσεις ημερολογίου, ανακτημένα chunks, μνήμη, αποτελέσματα εργαλείων και μηνύματα peer-agent | Πού μπορεί ένας επιτιθέμενος να τοποθετήσει περιεχόμενο που αργότερα θα εισαχθεί στο context του μοντέλου; |
| **Εργαλεία** | Ονόματα και schemas εργαλείων, παρενέργειες, αυτόματη εκτέλεση, συμπεριφορά επιβεβαίωσης και εργαλεία που φορτώνονται δυναμικά | Ποιες κλήσεις διαβάζουν secrets, γράφουν κατάσταση, στέλνουν μηνύματα, διαγράφουν δεδομένα, εκτελούν κώδικα ή μεταφέρουν αξία; |
| **Εξουσιοδότηση** | Ανάθεση από χρήστη, service accounts, API tokens, διάρκεια ζωής διαπιστευτηρίων, εύρος tenant/resource και πρόσβαση δικτύου | Με ποια ταυτότητα εκτελείται κάθε κλήση και επαναλαμβάνεται η εξουσιοδότηση στο όριο του εργαλείου; |
| **Επεξεργασία** | Query builders, shells, URL fetchers, template engines, interpreters, parsers, λειτουργίες αρχείων και deserializers | Πού μετατρέπονται δεδομένα που παράγονται από το μοντέλο σε σύνταξη για άλλον interpreter; |
| **Έξοδος** | Απαντήσεις, αποδιδόμενο Markdown/HTML, links, λήψεις εικόνων, webhooks, email, αρχεία, logs, reports, metrics και κίνηση peer-agent | Ποιο παρατηρήσιμο κανάλι μπορεί να μεταφέρει ένα secret ή να ενεργοποιήσει δευτερεύον αίτημα; |

Μην το περιορίζετε σε μια λίστα διαφημιζόμενων integrations. Ένα χρήσιμο τεχνούργημα αντιστοιχίζει κάθε πηγή στην ακριβή θέση context στην οποία φτάνει, τα εργαλεία που είναι διαθέσιμα σε εκείνο το σημείο, το credential που χρησιμοποιεί κάθε εργαλείο, τον downstream interpreter και κάθε διαδρομή egress. Το ίδιο εργαλείο μπορεί να έχει μικρό αντίκτυπο με ένα read token ανά χρήστη και να είναι κρίσιμο με ένα κοινόχρηστο administrator credential.<sup>[[2]](#references)</sup>

## Αναγνώριση

### Χαρτογράφηση κάθε διαδρομής παράδοσης και εισαγωγής

Ξεκινήστε από την επιφάνεια παράδοσης (web, mobile, API, email, πλατφόρμα chat, browser extension) και καταγράψτε μέσω proxy την κίνηση client-to-backend. Εξετάστε πεδία που αποκρύπτονται από το UI, παραμέτρους αναζήτησης/autocomplete/filter, αντικείμενα conversation-state, εργασίες upload και indexing, αποκρίσεις εργαλείων και κίνηση sub-agent. Οι clients που είναι διαθέσιμοι μόνο σε mobile μπορεί να απαιτούν emulator και instrumentation για την παράκαμψη του certificate pinning, προτού γίνει ορατό το πραγματικό request schema.<sup>[[2]](#references)</sup>

Στη συνέχεια χαρτογραφήστε το stack κάτω από το μοντέλο: orchestration framework, συναρμολόγηση prompt, αποθηκευτικούς χώρους retrieval και memory, runtime (για παράδειγμα Python, container ή WASM), προσαρτημένους τόμους, υπηρεσίες host, εσωτερικά APIs, πρόσβαση σε cloud metadata και γειτονικά δίκτυα. Οι προεπιλεγμένες ρυθμίσεις του framework έχουν σημασία, επειδή ορισμένα «tool calls» υλοποιούνται με παραγωγή ή αξιολόγηση κώδικα· το όριο runtime/sandbox καθορίζει αν το αποτέλεσμα παραμένει περιορισμένο.<sup>[[2]](#references)</sup>

### Αναγνώριση routing με μη καταστροφικά probes

Συγκρίνετε ένα αίτημα εντός πεδίου εφαρμογής με αρκετά άσχετα αιτήματα, διατηρώντας πλήρη την απόκριση, τον status code, το latency και τη συμπεριφορά streaming. Μια σταθερή απόρριψη πριν από οποιονδήποτε συλλογισμό σχετικό με τη συγκεκριμένη εργασία μπορεί να υποδεικνύει ξεχωριστό gateway/classifier· μια άρνηση με βάση το context υποδηλώνει ότι το αίτημα έφτασε στο μοντέλο· μια κενή ή αποκλειστικά εξαγωγική απάντηση μπορεί να υποδεικνύει αναζήτηση λέξεων-κλειδιών ή περιορισμένο retrieval. Αντιμετωπίστε τα ως υποθέσεις και επιβεβαιώστε τις επαναλαμβάνοντας το ίδιο probe μέσω εναλλακτικών πεδίων API και διαδρομών εισαγωγής.<sup>[[2]](#references)</sup>

Η αναγνώριση ολοκληρώνεται όταν η αξιολόγηση μπορεί να κατονομάσει την πρώτη πηγή ελεγχόμενη από τον επιτιθέμενο που αλλάζει τη συμπεριφορά του agent **και** τα εργαλεία, τις ταυτότητες, τους interpreters και τις εξόδους που είναι προσβάσιμες από αυτήν την πηγή.<sup>[[2]](#references)</sup>

## Εκμετάλλευση: υπέρβαση ενός ορίου εμπιστοσύνης

Δοκιμάστε κανάλια, όχι μόνο τη διατύπωση του prompt. Ξεκινήστε με direct injection για να διαπιστώσετε τι αποκλείει η ορατή είσοδος και, στη συνέχεια, επαναλάβετε ισοδύναμη πρόθεση μέσω των λιγότερο ορατών διαδρομών παρακάτω:<sup>[[2]](#references)</sup>

- **Έμμεσο περιεχόμενο:** σελίδες, αρχεία, email, tickets, metadata, alt text, σχόλια HTML, κείμενο εκτός οθόνης ή χαρακτήρες zero-width. Δείτε το [AI Prompts](AI-Prompts.md#third-party-or-indirect-prompt-injection) για τεχνικές παράδοσης payload.
- **Retrieval και memory:** δηλητηριάστε περιεχόμενο που θα ανακτηθεί αργότερα ή κατάσταση που θα επαναφορτωθεί σε μελλοντικές συνεδρίες. Καταγράψτε αν η διαγραφή της αρχικής πηγής αφαιρεί τη συμπεριφορά.
- **Έξοδος εργαλείων και peer agents:** τοποθετήστε τον marker σε απόκριση εργαλείου ή μήνυμα agent-to-agent, για να ελέγξετε αν η εσωτερική κίνηση παρακάμπτει τα φίλτρα που εφαρμόζονται μόνο στην είσοδο χρήστη και στην τελική έξοδο.
- **Supply chain:** εξετάστε περιγραφές εργαλείων, plugins, συνδεδεμένους servers, skills, μοντέλα και dependencies ως έμπιστες πηγές οδηγιών. Για ειδικές δοκιμές MCP, δείτε το [MCP Servers](AI-MCP-Servers.md#mcp-vulns).
- **Ανθρώπινη έγκριση:** συγκρίνετε την πραγματική δομημένη κλήση εργαλείου με το κείμενο έγκρισης που παράγει το μοντέλο. Ελέγξτε αν η επιρροή του επιτιθέμενου μπορεί να παραλείψει τον προορισμό, το εύρος, τα επηρεαζόμενα αντικείμενα ή τις μη αναστρέψιμες παρενέργειες.

Χρησιμοποιήστε πρώτα έναν ακίνδυνο, μοναδικό marker. Διατηρήστε το αρχικό τεχνούργημα, το συναρμολογημένο context αν είναι ορατό, την επιλεγμένη κλήση εργαλείου, τα δεδομένα έγκρισης, το αίτημα/την απόκριση backend και την τελική κατάσταση. Έτσι διαχωρίζεται η επιρροή από έναν παραισθητικό ισχυρισμό ότι εκτελέστηκε κάποια ενέργεια.<sup>[[2]](#references)</sup>

### Κείμενο που μιμείται πολιτική σε κριτή αξιολόγησης κινδύνου εργαλείων

Ένα model-based tool gate μπορεί να λάβει κείμενο ελεγχόμενο από τον επιτιθέμενο μέσα σε κατά τα άλλα χρήσιμο context ταξινόμησης. Για παράδειγμα, το πειραματικό `AutoModeMiddleware` του LangChain στέλνει μια προτεινόμενη κλήση εργαλείου, τα ορίσματά της, μια προαιρετική περιγραφή εργαλείου και έως 30 πρόσφατα μηνύματα σε έναν κριτή TypeSafe `is_risky`. Μπλοκάρει τα διαμορφωμένα εργαλεία όταν η πιθανότητα Noul που επιστρέφεται είναι τουλάχιστον `0.5`· τα εργαλεία που δεν περιλαμβάνονται στη λίστα δεν ταξινομούνται από αυτό το middleware.<sup>[[5]](#references)</sup> Το TypeSafe προειδοποιεί επίσης ότι adversarial text στην κατάσταση μπορεί να επηρεάσει μια ταξινόμηση, ακόμη κι όταν η κατάσταση προορίζεται να είναι δεδομένα.<sup>[[6]](#references)</sup>

Μια **πλαστή πολιτική** διαφέρει από τον απλό ισχυρισμό ότι πρόκειται για system message. Τοποθετεί εναλλακτικές ετικέτες ή ορισμούς κινδύνου σε state χαμηλότερης εμπιστοσύνης και καλεί τον κριτή να χρησιμοποιήσει αυτούς τους ορισμούς αντί για τα κριτήρια που έχει ορίσει ο developer. Στη δοκιμή της Datadog, το επεξεργάσιμο από τον χρήστη `profile_description` αντιγράφηκε στα ορίσματα εργαλείου μαζί με το `can_edit:false`. Το κείμενό του, γραμμένο σαν πολιτική, υποστήριζε ότι μια απόπειρα εγγραφής είχε χαμηλό κίνδυνο, επειδή ένας ξεχωριστός έλεγχος δικαιωμάτων θα την απέρριπτε πριν από οποιαδήποτε τροποποίηση. Σε 40 εκτελέσεις, η μέση βαθμολογία `is_risky` μειώθηκε από `0.893` σε `0.290`, ενώ μια άμεση σύγκριση πλαστογράφησης ρόλου είχε μέσο όρο `0.905`. Το ότι ο μέσος όρος έπεσε κάτω από το `0.5` δεν αποδεικνύει ότι κάθε μεμονωμένη κλήση πέρασε από το gate, και το πείραμα **δεν** απέδειξε την ολοκλήρωση μη εξουσιοδοτημένης εγγραφής.<sup>[[7]](#references)</sup>

Κατά τη δοκιμή αυτού του ορίου, διακρίνετε την απόφαση του classifier από το πραγματικό αποτέλεσμα εξουσιοδότησης του εργαλείου. Ελέγξτε ποια επεξεργάσιμα πεδία φτάνουν στον κριτή, συγκρίνετε την ίδια προτεινόμενη ενέργεια με και χωρίς κείμενο που μοιάζει με πολιτική και επαληθεύστε ανεξάρτητα την τελική κατάσταση. Ένας ξεχωριστός έλεγχος δικαιωμάτων πρέπει να βασίζεται στην εξουσιοδότηση του αυθεντικοποιημένου αιτούντος και όχι στα δικαιώματα του service account του connector.<sup>[[7]](#references)</sup> Δείτε το [prompt-filter bypasses](AI-Prompts.md#prompt-waf-bypass) για άλλους τρόπους αποτυχίας classifier· τα [LLM gateway trust boundaries](AI-LLM-Gateway-Security.md) αφορούν διαφορετικό όριο routing και credentials.

### Απομόνωση context subagent

Ένας subagent του Claude Agent SDK που δεν χρησιμοποιεί fork λαμβάνει το δικό του `AgentDefinition.prompt`, το prompt ανάθεσης και τα διαθέσιμα εργαλεία του, αλλά όχι το system prompt ή τη συνομιλία του parent. Αν παραλειφθεί το `tools` από τον ορισμό του, κληρονομεί τα εργαλεία που είναι διαθέσιμα στους subagents· το project `CLAUDE.md` μπορεί και πάλι να φορτωθεί. Επομένως, ένας περιορισμός prompt που ισχύει μόνο για τον parent δεν αποτελεί αξιόπιστο όριο όταν το child μπορεί να χρησιμοποιήσει τα ίδια εργαλεία filesystem ή εκτέλεσης.<sup>[[4]](#references)</sup>

Δοκιμάστε το όριο συγκρίνοντας ένα άμεσο αίτημα που αρνείται ο parent με την ίδια εργασία ανατεθειμένη σε έναν επώνυμο subagent. Η NCC Group αναφέρει ότι μια άρνηση απαρίθμησης αρχείων του λειτουργικού συστήματος πέτυχε όταν παρουσιάστηκε στο child ως αβλαβής «χάρτης διάταξης».<sup>[[3]](#references)</sup>

Εξετάστε τις πραγματικές κλήσεις εργαλείων του child και την αποτελεσματική allowlist εργαλείων του, όχι μόνο την τελική απάντηση του parent· επιβεβαιώστε αν το child απέκτησε πρόσβαση σε αρχεία στα οποία ο parent δεν θα είχε πρόσβαση.<sup>[[4]](#references)</sup> Πρόκειται για αποτυχία κληρονόμησης guardrail, όχι για απόδειξη [Python sandbox](../generic-methodologies-and-resources/python/bypass-python-sandboxes/) ή διαφυγής από container.<sup>[[3]](#references)[[4]](#references)</sup>

### Mobile GUI agents: οδηγίες στην οθόνη και επανασύνδεση ενέργειας

Ένας phone GUI agent μπορεί να στέλνει κάθε screenshot σε cloud model προτού επιλέξει την επόμενη ενέργεια μεταξύ εφαρμογών. Για να δοκιμάσετε **έμμεσο visual injection**, τοποθετήστε κείμενο ελεγχόμενο από τον επιτιθέμενο σε SMS, email ή σελίδα που θα εξετάσει ο agent κατά τη διάρκεια εξουσιοδοτημένης εργασίας. Συγκρίνετε ένα άμεσο task prompt με την ίδια οδηγία ορατή μόνο στο screenshot, έπειτα εξετάστε την επόμενη ενέργεια και οποιαδήποτε απόφαση για λειτουργία υψηλού κινδύνου. Στον βοηθό που αξιολογήθηκε, το client-side `checkPrompt` έλεγχε το άμεσο κείμενο εργασίας, αλλά δεν εφάρμοζε ισοδύναμο φιλτράρισμα στο περιεχόμενο screenshot. Πρόκειται για mobile, cross-app παραλλαγή του [agentic-browser screenshot injection](../generic-methodologies-and-resources/phishing-methodology/ai-agent-mode-phishing-abusing-hosted-agent-browsers.md), όχι για τρόπο παράκαμψης της αυθεντικοποίησης Android component.<sup>[[9]](#references)</sup>

Μια ενδεικτική δοκιμή παρενεργειών χρησιμοποιεί μια φόρμα ελεγχόμενη από τον επιτιθέμενο, η οποία ζητά από τον agent να συμπληρώσει ευαίσθητα πεδία και στη συνέχεια ζητά από άνθρωπο να κάνει κλικ στο «upload», ενώ η σελίδα υποβάλλει τα συμπληρωμένα πεδία μόλις αλλάξουν. Η παράδοση ελέγχου σε άνθρωπο δεν μπορεί να προστατεύσει δεδομένα που έχουν ήδη σταλεί από τον κώδικα της σελίδας· επαληθεύστε την πραγματική υποβολή αντί να θεωρείτε την αφήγηση του agent ως απόδειξη. Η πηγή παρουσιάζει αυτό το μοτίβο ως πιθανό, όχι ως αποδεδειγμένη παραβίαση κάθε βοηθού.<sup>[[9]](#references)</sup>

Το **GUI TOCTOU / action rebinding** είναι ξεχωριστός τρόπος αποτυχίας: ο agent σχεδιάζει μια είσοδο βάσει οθόνης που παρατηρήθηκε στο `t0`, αλλά το UI στο προσκήνιο αλλάζει πριν εισαχθεί η είσοδος στο `t1`.<sup>[[8]](#references)</sup> Ένα μεταγενέστερο screenshot στο `t2` δεν μπορεί να αναιρέσει μια ενέργεια που έχει ήδη εκτελεστεί.<sup>[[9]](#references)</sup> Σε εξουσιοδοτημένη δοκιμή Android, η επαναχρησιμοποιήσιμη ροή εργασίας είναι:<sup>[[8]](#references)</sup>

1. Καταγράψτε τις συντεταγμένες της οθόνης του στοιχείου ελέγχου-στόχου και αποδώστε ένα ακίνδυνο στοιχείο ελέγχου στην ίδια θέση σε μια ελεγχόμενη εφαρμογή.
2. Κρατήστε ορατό αυτό το στοιχείο μέχρι να το παρατηρήσει ο agent και, στη συνέχεια, ενεργοποιήστε μια κανονική μετάβαση στο προσκήνιο κατά το διάστημα μεταξύ παρατήρησης και ενέργειας.
3. Ελέγξτε αν το προγραμματισμένο πάτημα στοχεύει το στοιχείο ελέγχου της νέας εφαρμογής και επαληθεύστε την προκύπτουσα κατάσταση στην εφαρμογή-στόχο, αντί να βασίζεστε στην αφήγηση του agent.

Η αρχική μελέτη action-rebinding το αποδεικνύει με μια εφαρμογή που δεν έχει επικίνδυνα δικαιώματα· περιγράφει επίσης την επανάληψη της μετάβασης μέσω του βρόχου ανάκαμψης εργασιών του agent για πολυβηματικές ροές.<sup>[[8]](#references)</sup>

**Μην** υποθέτετε ότι το primitive λειτουργεί αμετάβλητο σε κάθε βοηθό. Στην αξιολόγηση του Doubao, το `OpClickUI` παρέλειπε τα κλικ αν άλλαζε η Activity ανώτατου επιπέδου και συνέκρινε screenshots όταν το `OpOpenApp` είχε εμφανιστεί στα τρία προηγούμενα βήματα. Επομένως, τα απλά πατήματα, τα παρατεταμένα πατήματα και τα διπλά πατήματα προσέφεραν μικρή αξιόπιστη δυνατότητα ελέγχου του χρονισμού από τον επιτιθέμενο. Τα `OpTypeText`, `OpSwipeUI` και `OpScrollWheelAction` δεν διέθεταν αντίστοιχες προστασίες, αλλά η αναφορά αξιολόγησε τον πρακτικό τους αντίκτυπο ως πιο περιορισμένο.<sup>[[9]](#references)</sup>

## Εκτέλεση: απόδειξη πραγματικού αντίκτυπου

Υπάρχουν δύο διακριτές διαδρομές από την επιρροή στον αντίκτυπο:<sup>[[2]](#references)</sup>

1. **Κατάχρηση δυνατότητας:** το εξουσιοδοτημένο εργαλείο εκτελεί ήδη τον στόχο. Παραδείγματα είναι η ανάγνωση εγγραφής ενός tenant και η εγγραφή της σε report ορατό στον επιτιθέμενο, η αποστολή email, η αλλαγή εγγραφών, η διαγραφή αρχείου ή η έναρξη πληρωμής. Δεν απαιτείται δευτερεύον software bug.
2. **Εκμετάλλευση downstream sink:** η έξοδος του μοντέλου που κατευθύνεται από τον επιτιθέμενο γίνεται σύνταξη για άλλο στοιχείο. Εξετάστε τα database queries για [SQL injection](../pentesting-web/sql-injection/README.md) ή [NoSQL injection](../pentesting-web/nosql-injection.md), τα shell wrappers για [command injection](../pentesting-web/command-injection.md), τα επιλεγμένα URLs για [SSRF](../pentesting-web/ssrf-server-side-request-forgery/README.md), τις λειτουργίες αρχείων για traversal, τους template/code evaluators για RCE και τους object parsers για [unsafe deserialization](../pentesting-web/deserialization/README.md).

Για κάθε υποψήφιο εύρημα, αποδείξτε την ακόλουθη αλυσίδα:<sup>[[2]](#references)</sup>

```text
attacker-controlled source
  -> model/context influence
  -> selected tool and arguments
  -> effective identity/credential
  -> capability or vulnerable sink
  -> externally verified state change or data egress
```

Μια ενσωμάτωση μόνο για ανάγνωση εξακολουθεί να είναι εκμεταλλεύσιμη όταν οποιοδήποτε μεταγενέστερο στοιχείο μπορεί να δημοσιεύσει όσα διάβασε. Ελέγξτε τις συνηθισμένες αποκρίσεις, καθώς και λιγότερο προφανείς διαύλους εξόδου, όπως συνδέσμους που ελέγχει ο επιτιθέμενος, αυτόματη ανάκτηση εικόνων, webhooks, αρχεία καταγραφής, αναφορές, μετρητές, ειδοποιήσεις και μηνύματα προς άλλους agents.<sup>[[2]](#references)</sup>

## Ενέργειες επί των στόχων

Αφού επιβεβαιώσετε μία ενέργεια, αξιολογήστε ολόκληρο το blast radius αντί να σταματήσετε στο πρώτο ορατό αποτέλεσμα:<sup>[[2]](#references)</sup>

- **Exfiltration:** μυστικά, εγγραφές χρηστών, εσωτερικά αρχεία, δεδομένα συνομιλιών ή περιεχόμενο prompt/context εξέρχονται μέσω παρατηρήσιμου διαύλου.
- **Μη εξουσιοδοτημένη ενέργεια:** ο agent χρησιμοποιεί νόμιμες δυνατότητες εγγραφής για την επίτευξη του στόχου του επιτιθέμενου.
- **Denial of service:** καταστροφικά εργαλεία ή επαναλαμβανόμενες δαπανηρές λειτουργίες επηρεάζουν την ακεραιότητα ή τη διαθεσιμότητα.
- **Persistence:** δηλητηριασμένη μνήμη, ευρετηριασμένο περιεχόμενο, έμπιστη κατάσταση ή αλλαγές στο runtime επιβιώνουν από την αρχική συνεδρία ή την αφαίρεση της πηγής.
- **Propagation:** ένας έμπιστος peer καταναλώνει το μήνυμα ή την κοινόχρηστη κατάσταση του παραβιασμένου agent και επαναλαμβάνει την ενέργεια με τα δικά του εργαλεία και διαπιστευτήρια.

Η σοβαρότητα πρέπει να βασίζεται στα προσβάσιμα δεδομένα, στα πραγματικά δικαιώματα, στην εκμεταλλευσιμότητα του sink, στο egress, στην persistence και στο propagation — όχι στο πόσο απροσδόκητο φαίνεται το κείμενο του μοντέλου.<sup>[[2]](#references)</sup>

## Έλεγχοι προς επικύρωση κατά την αξιολόγηση

Τα φίλτρα prompt και ένα καλύτερο system prompt μπορούν να αυξήσουν το κόστος για τον επιτιθέμενο, αλλά δεν πρέπει να θεωρούνται όρια εξουσιοδότησης. Επικυρώστε τους παρακάτω ελέγχους επαναλαμβάνοντας την ίδια αλυσίδα μέσω άμεσης εισόδου, έμμεσου περιεχομένου, μνήμης, εργαλείων και peer agents:<sup>[[2]](#references)</sup>

- Ένα ντετερμινιστικό επίπεδο πολιτικής ελέγχει τον πιστοποιημένο χρήστη, τον tenant, το αντικείμενο, την ενέργεια και τον προορισμό σε **κάθε κλήση εργαλείου**· το μοντέλο δεν μπορεί να ορίσει ή να παρακάμψει την ταυτότητα του καλούντος.
- Οι δυνατότητες ανάγνωσης και εγγραφής χρησιμοποιούν ξεχωριστά διαπιστευτήρια ελάχιστων δικαιωμάτων και μικρής διάρκειας· τα εργαλεία υψηλού αντίκτυπου παρέχονται just in time και δεν εκτελούνται ποτέ αυτόματα βάσει περιεχομένου που έχει εισαχθεί.
- Το egress δικτύου και οι εσωτερικοί προορισμοί υπόκεινται σε allowlist ανεξάρτητα από τα URL που επιλέγει το μοντέλο· η πρόσβαση του runtime σε endpoints μεταδεδομένων, προσαρτημένα μυστικά και γειτονικές υπηρεσίες αποκλείεται, εκτός αν είναι απαραίτητη.
- Το UI έγκρισης δημιουργείται από το κανονικό δομημένο αίτημα και εμφανίζει τα ακριβή ορίσματα, την ταυτότητα, τον προορισμό, τα επηρεαζόμενα αντικείμενα και τις παρενέργειες — όχι μια ελεύθερη σύνοψη του μοντέλου.
- Η επιτυχία επαληθεύεται από το σύστημα προορισμού ή το σύστημα καταγραφής της αλήθειας. Η αφήγηση του agent, ένα αίτημα κλήσης εργαλείου ή μια ανακατεύθυνση HTTP δεν αποδεικνύουν την ισχυριζόμενη αλλαγή κατάστασης.
- Οι εγγραφές μνήμης και ανάκτησης διατηρούν πληροφορίες προέλευσης και ετικέτες εμπιστοσύνης, μπορούν να ακυρωθούν και επανεγκρίνονται όταν χρησιμοποιούνται για μεταγενέστερη ενέργεια.
- Τα μηνύματα μεταξύ agents πιστοποιούνται και εξουσιοδοτούνται ως μη έμπιστα αιτήματα· η φήμη ενός peer ή η κάρτα agent του δεν εκχωρεί σιωπηρά τα εργαλεία του παραλήπτη.

Για τις κάρτες agent A2A, τις ροές εργασιών και την επιφάνεια επίθεσής τους, δείτε το [A2A Protocol Security](AI-A2A-Protocol.md).
