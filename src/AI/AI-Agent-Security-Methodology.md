# Μεθοδολογία Ασφάλειας AI Agent

{{#include ../banners/hacktricks-training.md}}

Μια αξιολόγηση agent πρέπει να ακολουθεί τη διαδρομή **από είσοδο που ελέγχεται από τον επιτιθέμενο έως ένα εξωτερικά παρατηρήσιμο αποτέλεσμα**. Το Jailbreaking, οι αλλαγές χαρακτήρων και η αποκάλυψη system-prompt αποδεικνύουν ότι ένα κανάλι συλλογισμού μπορεί να επηρεαστεί, αλλά το εύρημα υψηλού αντίκτυπου είναι η αλυσίδα που οδηγεί σε πρόσβαση σε δεδομένα, μη εξουσιοδοτημένη ενέργεια εργαλείου, downstream injection sink, persistence ή άλλον agent.<sup>[[2]](#references)</sup>

Το [OWASP Top 10 for Agentic Applications](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/) είναι χρήσιμο για την επισήμανση της κάλυψης (χειραγώγηση στόχου, κακή χρήση εργαλείων, κατάχρηση προνομίων, supply chain, εκτέλεση κώδικα, δηλητηρίαση μνήμης, εμπιστοσύνη μεταξύ agents, αλυσιδωτές αστοχίες, ανθρώπινη εμπιστοσύνη και rogue agents). Χρησιμοποιήστε αυτές τις ετικέτες αφού κατασκευάσετε μια end-to-end διαδρομή επίθεσης, αντί να θεωρήσετε ότι το απρόσμενο κείμενο ενός μοντέλου είναι το τέλος της δοκιμής.<sup>[[1]](#references)[[2]](#references)</sup>

## Δημιουργία χάρτη στόχου

Καταγράψτε τις ακόλουθες πέντε διαστάσεις για κάθε ροή εργασίας agent πριν γράψετε payloads:<sup>[[2]](#references)</sup>

| Διάσταση | Τι να απαριθμήσετε | Ερώτημα ασφάλειας |
|---|---|---|
| **Μη έμπιστη είσοδος** | Παράμετροι Chat/API, URLs, έγγραφα, email, tickets, καταχωρίσεις ημερολογίου, ανακτημένα αποσπάσματα, μνήμη, αποτελέσματα εργαλείων και μηνύματα από peer agents | Πού μπορεί ένας επιτιθέμενος να τοποθετήσει περιεχόμενο που αργότερα θα εισέλθει στο context του μοντέλου; |
| **Εργαλεία** | Ονόματα και schemas εργαλείων, παρενέργειες, αυτόματη εκτέλεση, συμπεριφορά επιβεβαίωσης και δυναμικά φορτωμένα εργαλεία | Ποιες κλήσεις διαβάζουν μυστικά, γράφουν δεδομένα, στέλνουν μηνύματα, διαγράφουν δεδομένα, εκτελούν κώδικα ή μεταφέρουν αξία; |
| **Εξουσία** | Ανάθεση από χρήστη, λογαριασμοί υπηρεσιών, API tokens, διάρκεια ζωής διαπιστευτηρίων, εμβέλεια tenant/πόρου και πρόσβαση στο δίκτυο | Με ποια ταυτότητα εκτελείται κάθε κλήση και επαναλαμβάνεται η εξουσιοδότηση στο όριο του εργαλείου; |
| **Επεξεργασία** | Query builders, shells, URL fetchers, template engines, interpreters, parsers, λειτουργίες αρχείων και deserializers | Πού γίνεται η παραγόμενη από το μοντέλο είσοδος σύνταξη για κάποιον άλλο interpreter; |
| **Έξοδος** | Απαντήσεις, αποδιδόμενο Markdown/HTML, links, ανακτήσεις εικόνων, webhooks, email, αρχεία, logs, αναφορές, μετρικές και κίνηση μεταξύ peer agents | Ποιο παρατηρήσιμο κανάλι μπορεί να μεταφέρει ένα μυστικό ή να ενεργοποιήσει δευτερεύον αίτημα; |

Μην το περιορίζετε σε μια λίστα διαφημιζόμενων integrations. Ένα χρήσιμο τεχνούργημα αντιστοιχίζει κάθε πηγή στην ακριβή θέση του context στην οποία φτάνει, στα διαθέσιμα εργαλεία σε εκείνο το σημείο, στο διαπιστευτήριο που χρησιμοποιεί κάθε εργαλείο, στον downstream interpreter και σε κάθε διαδρομή εξερχόμενης κίνησης. Το ίδιο εργαλείο μπορεί να έχει μικρό αντίκτυπο με read token ανά χρήστη και κρίσιμο αντίκτυπο με κοινόχρηστο διαπιστευτήριο διαχειριστή.<sup>[[2]](#references)</sup>

## Αναγνώριση

### Χαρτογράφηση κάθε διαδρομής παράδοσης και εισαγωγής

Ξεκινήστε από την επιφάνεια παράδοσης (web, mobile, API, email, chat platform, browser extension) και καταγράψτε μέσω proxy την κίνηση client-to-backend. Εξετάστε πεδία που αποκρύπτονται από το UI, παραμέτρους αναζήτησης/autocomplete/filter, αντικείμενα κατάστασης συνομιλίας, εργασίες upload και indexing, αποκρίσεις εργαλείων και κίνηση sub-agent. Για clients που είναι διαθέσιμοι μόνο σε mobile μπορεί να χρειαστεί emulator και instrumentation για την παράκαμψη του certificate pinning, προτού γίνει ορατό το πραγματικό schema αιτήματος.<sup>[[2]](#references)</sup>

Στη συνέχεια χαρτογραφήστε το stack κάτω από το μοντέλο: orchestration framework, συναρμολόγηση prompt, αποθηκευτικούς χώρους retrieval και memory, runtime (για παράδειγμα Python, container ή WASM), προσαρτημένους τόμους, υπηρεσίες host, εσωτερικά APIs, πρόσβαση σε cloud metadata και γειτονικά δίκτυα. Οι προεπιλεγμένες ρυθμίσεις του framework έχουν σημασία, επειδή ορισμένες «κλήσεις εργαλείων» υλοποιούνται με παραγωγή ή αξιολόγηση κώδικα· το όριο runtime/sandbox καθορίζει αν το αποτέλεσμα παραμένει απομονωμένο.<sup>[[2]](#references)</sup>

### Αποτύπωση δρομολόγησης με μη καταστροφικά probes

Συγκρίνετε ένα αίτημα εντός πεδίου εφαρμογής με αρκετά άσχετα αιτήματα, διατηρώντας πλήρη την απόκριση, τον status code, τον χρόνο απόκρισης και τη συμπεριφορά streaming. Μια σταθερή απόρριψη πριν από οποιονδήποτε συλλογισμό ειδικό για την εκάστοτε εργασία μπορεί να υποδεικνύει ξεχωριστό gateway/classifier· μια άρνηση που εξαρτάται από το context υποδηλώνει ότι το αίτημα έφτασε στο μοντέλο· μια κενή ή αμιγώς εξαγωγική απάντηση μπορεί να υποδεικνύει αναζήτηση λέξεων-κλειδιών ή περιορισμένο retrieval. Αντιμετωπίστε τα ως υποθέσεις και επιβεβαιώστε τες επαναλαμβάνοντας το ίδιο probe μέσω εναλλακτικών πεδίων API και διαδρομών εισαγωγής.<sup>[[2]](#references)</sup>

Η αναγνώριση έχει ολοκληρωθεί όταν η αξιολόγηση μπορεί να κατονομάσει την πρωιμότερη πηγή που ελέγχεται από τον επιτιθέμενο και αλλάζει τη συμπεριφορά του agent **και** τα εργαλεία, τις ταυτότητες, τους interpreters και τις εξόδους που είναι προσβάσιμα από αυτή την πηγή.<sup>[[2]](#references)</sup>

## Εκμετάλλευση: υπέρβαση ενός ορίου εμπιστοσύνης

Δοκιμάστε κανάλια, όχι μόνο τη διατύπωση του prompt. Ξεκινήστε με άμεσο injection για να διαπιστώσετε τι αποκλείει η ορατή είσοδος και, στη συνέχεια, επαναλάβετε ισοδύναμη πρόθεση μέσω των λιγότερο ορατών διαδρομών παρακάτω:<sup>[[2]](#references)</sup>

- **Έμμεσο περιεχόμενο:** σελίδες, αρχεία, email, tickets, metadata, alt text, σχόλια HTML, κείμενο εκτός ορατής περιοχής ή χαρακτήρες μηδενικού πλάτους. Δείτε το [AI Prompts](AI-Prompts.md#third-party-or-indirect-prompt-injection) για τεχνικές παράδοσης payload.
- **Retrieval και μνήμη:** δηλητηριάστε περιεχόμενο που θα ανακτηθεί αργότερα ή κατάσταση που θα φορτωθεί ξανά σε επόμενες συνεδρίες. Καταγράψτε αν η διαγραφή της αρχικής πηγής αφαιρεί τη συμπεριφορά.
- **Έξοδος εργαλείου και peer agents:** τοποθετήστε τον δείκτη σε απόκριση εργαλείου ή μήνυμα μεταξύ agents, για να ελέγξετε αν η εσωτερική κίνηση παρακάμπτει φίλτρα που εφαρμόζονται μόνο στην είσοδο χρήστη και στην τελική έξοδο.
- **Supply chain:** εξετάστε περιγραφές εργαλείων, plugins, συνδεδεμένους servers, skills, μοντέλα και εξαρτήσεις ως έμπιστες πηγές οδηγιών. Για ειδικές δοκιμές MCP, δείτε το [MCP Servers](AI-MCP-Servers.md#mcp-vulns).
- **Ανθρώπινη έγκριση:** συγκρίνετε την πραγματική δομημένη κλήση εργαλείου με το κείμενο έγκρισης που παράγει το μοντέλο. Δοκιμάστε αν η επιρροή του επιτιθέμενου μπορεί να παραλείψει τον προορισμό, το scope, τα αντικείμενα που επηρεάζονται ή μη αναστρέψιμες παρενέργειες.

Χρησιμοποιήστε πρώτα έναν ακίνδυνο, μοναδικό δείκτη. Διατηρήστε το αρχικό τεχνούργημα, το συναρμολογημένο context αν είναι ορατό, την επιλεγμένη κλήση εργαλείου, τα δεδομένα έγκρισης, το αίτημα/την απόκριση backend και την τελική κατάσταση. Έτσι διακρίνετε την επιρροή από έναν παραισθητικό ισχυρισμό ότι πραγματοποιήθηκε κάποια ενέργεια.<sup>[[2]](#references)</sup>

### Απομόνωση context subagent

Ένα subagent του Claude Agent SDK που δεν δημιουργείται με fork λαμβάνει το δικό του `AgentDefinition.prompt`, το prompt ανάθεσης και τα διαθέσιμα εργαλεία του, αλλά όχι το system prompt ή τη συνομιλία του parent. Αν παραλειφθεί το `tools` από τον ορισμό του, κληρονομεί τα εργαλεία που είναι διαθέσιμα στα subagents· μπορεί να φορτωθεί ακόμη και το `CLAUDE.md` του project. Επομένως, ένας περιορισμός prompt που ισχύει μόνο για τον parent δεν αποτελεί αξιόπιστο όριο όταν το child μπορεί να χρησιμοποιήσει τα ίδια εργαλεία filesystem ή εκτέλεσης.<sup>[[4]](#references)</sup>

Δοκιμάστε το όριο συγκρίνοντας ένα άμεσο αίτημα που αρνείται ο parent με την ίδια εργασία ανατεθειμένη σε κατονομασμένο subagent. Η NCC Group αναφέρει ότι μια άρνηση απαρίθμησης αρχείων του λειτουργικού συστήματος πέτυχε όταν διατυπώθηκε εκ νέου για ένα child ως ακίνδυνος «χάρτης διάταξης».<sup>[[3]](#references)</sup>

Εξετάστε τις πραγματικές κλήσεις εργαλείων του child και την ενεργή allowlist εργαλείων, όχι μόνο την τελική απάντηση του parent· επιβεβαιώστε αν το child απέκτησε πρόσβαση σε αρχεία στα οποία ο parent δεν θα αποκτούσε.<sup>[[4]](#references)</sup> Πρόκειται για αστοχία στην κληρονομικότητα guardrail, όχι για απόδειξη [Python sandbox](../generic-methodologies-and-resources/python/bypass-python-sandboxes/) ή διαφυγής από container.<sup>[[3]](#references)[[4]](#references)</sup>

## Εκτέλεση: απόδειξη πραγματικού αντίκτυπου

Υπάρχουν δύο διακριτές διαδρομές από την επιρροή στον αντίκτυπο:<sup>[[2]](#references)</sup>

1. **Κατάχρηση δυνατοτήτων:** το εξουσιοδοτημένο εργαλείο εκτελεί ήδη τον στόχο. Παραδείγματα περιλαμβάνουν την ανάγνωση μιας εγγραφής tenant και την εγγραφή της σε αναφορά ορατή στον επιτιθέμενο, την αποστολή email, την αλλαγή εγγραφών, τη διαγραφή αρχείου ή την έναρξη πληρωμής. Δεν απαιτείται δευτερεύον σφάλμα λογισμικού.
2. **Εκμετάλλευση downstream sink:** η έξοδος του μοντέλου, την οποία κατευθύνει ο επιτιθέμενος, γίνεται σύνταξη για άλλο στοιχείο. Εξετάστε τα database queries για [SQL injection](../pentesting-web/sql-injection/README.md) ή [NoSQL injection](../pentesting-web/nosql-injection.md), τα shell wrappers για [command injection](../pentesting-web/command-injection.md), τα URLs που επιλέγει ο επιτιθέμενος για [SSRF](../pentesting-web/ssrf-server-side-request-forgery/README.md), τις λειτουργίες αρχείων για traversal, τους template/code evaluators για RCE και τους object parsers για [unsafe deserialization](../pentesting-web/deserialization/README.md).

Για κάθε υποψήφιο εύρημα, αποδείξτε την εξής αλυσίδα:<sup>[[2]](#references)</sup>

```text
attacker-controlled source
  -> model/context influence
  -> selected tool and arguments
  -> effective identity/credential
  -> capability or vulnerable sink
  -> externally verified state change or data egress
```

Μια read-only integration εξακολουθεί να είναι εκμεταλλεύσιμη όταν οποιοδήποτε μεταγενέστερο component μπορεί να δημοσιεύσει όσα διάβασε. Δοκιμάστε τις συνηθισμένες αποκρίσεις, καθώς και λιγότερο προφανείς διαύλους egress, όπως συνδέσμους που ελέγχει ο επιτιθέμενος, αυτόματη ανάκτηση εικόνων, webhooks, logs, αναφορές, μετρητές, ειδοποιήσεις και μηνύματα προς άλλους agents.<sup>[[2]](#references)</sup>

## Ενέργειες επί των στόχων

Αφού επιβεβαιώσετε μία ενέργεια, αξιολογήστε το πλήρες εύρος των επιπτώσεων αντί να σταματήσετε στο πρώτο ορατό αποτέλεσμα:<sup>[[2]](#references)</sup>

- **Exfiltration:** μυστικά, εγγραφές χρηστών, εσωτερικά αρχεία, δεδομένα συνομιλιών ή περιεχόμενο prompt/context διαρρέουν μέσω παρατηρήσιμου διαύλου.
- **Μη εξουσιοδοτημένη ενέργεια:** ο agent χρησιμοποιεί νόμιμες δυνατότητες εγγραφής για τον στόχο του επιτιθέμενου.
- **Denial of service:** καταστροφικά εργαλεία ή επαναλαμβανόμενες, δαπανηρές λειτουργίες επηρεάζουν την ακεραιότητα ή τη διαθεσιμότητα.
- **Persistence:** δηλητηριασμένη μνήμη, ευρετηριασμένο περιεχόμενο, έμπιστη κατάσταση ή αλλαγές στο runtime επιβιώνουν από την αρχική συνεδρία ή την αφαίρεση της πηγής.
- **Propagation:** ένας έμπιστος peer καταναλώνει το μήνυμα ή την κοινόχρηστη κατάσταση του παραβιασμένου agent και επαναλαμβάνει την ενέργεια με τα δικά του εργαλεία και διαπιστευτήρια.

Η σοβαρότητα πρέπει να βασίζεται στα προσβάσιμα δεδομένα, στα πραγματικά προνόμια, στην εκμεταλλευσιμότητα του sink, στο egress, στην persistence και στην propagation — όχι στο πόσο απρόσμενο φαίνεται το κείμενο του μοντέλου.<sup>[[2]](#references)</sup>

## Έλεγχοι προς επικύρωση κατά την αξιολόγηση

Τα φίλτρα prompt και ένα καλύτερο system prompt μπορούν να αυξήσουν το κόστος για τον επιτιθέμενο, αλλά δεν πρέπει να θεωρούνται όρια εξουσιοδότησης. Επικυρώστε τους παρακάτω ελέγχους επαναλαμβάνοντας την ίδια αλυσίδα μέσω άμεσης εισόδου, έμμεσου περιεχομένου, μνήμης, εργαλείων και peer agents:<sup>[[2]](#references)</sup>

- Ένα ντετερμινιστικό επίπεδο πολιτικής ελέγχει τον πιστοποιημένο χρήστη, τον tenant, το αντικείμενο, την ενέργεια και τον προορισμό σε **κάθε κλήση εργαλείου**· το μοντέλο δεν μπορεί να ορίσει ή να παρακάμψει την ταυτότητα του καλούντος.
- Οι δυνατότητες ανάγνωσης και εγγραφής χρησιμοποιούν ξεχωριστά, ελάχιστου προνομίου και βραχύβια διαπιστευτήρια· τα εργαλεία υψηλού αντίκτυπου διατίθενται just in time και δεν εκτελούνται ποτέ αυτόματα βάσει περιεχομένου που έχει εισαχθεί.
- Το egress δικτύου και οι εσωτερικοί προορισμοί επιτρέπονται μέσω allowlist, ανεξάρτητα από τα URL που επιλέγει το μοντέλο· η πρόσβαση του runtime σε endpoints μεταδεδομένων, προσαρτημένα μυστικά και γειτονικές υπηρεσίες αποκλείεται, εκτός αν είναι απαραίτητη.
- Το UI έγκρισης δημιουργείται από το κανονικό δομημένο αίτημα και εμφανίζει τα ακριβή ορίσματα, την ταυτότητα, τον προορισμό, τα επηρεαζόμενα αντικείμενα και τις παρενέργειες — όχι μια ελεύθερη σύνοψη του μοντέλου.
- Η επιτυχία επαληθεύεται από το σύστημα προορισμού ή το σύστημα καταγραφής. Η αφήγηση του agent, ένα αίτημα κλήσης εργαλείου ή μια ανακατεύθυνση HTTP δεν αποδεικνύουν την ισχυριζόμενη αλλαγή κατάστασης.
- Οι εγγραφές μνήμης και ανάκτησης διατηρούν την προέλευση και τις ετικέτες εμπιστοσύνης, μπορούν να ακυρωθούν και επανεξουσιοδοτούνται όταν χρησιμοποιούνται για μεταγενέστερη ενέργεια.
- Τα μηνύματα μεταξύ agents πιστοποιούνται και εξουσιοδοτούνται ως μη έμπιστα αιτήματα· η φήμη ενός peer ή η agent card του δεν εκχωρεί σιωπηρά τα εργαλεία του παραλήπτη.
