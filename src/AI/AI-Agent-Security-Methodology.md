# Μεθοδολογία Ασφάλειας AI Agent

{{#include ../banners/hacktricks-training.md}}

Μια αξιολόγηση agent πρέπει να ακολουθεί τη διαδρομή **από είσοδο ελεγχόμενη από τον επιτιθέμενο έως ένα εξωτερικά παρατηρήσιμο αποτέλεσμα**. Το jailbreaking, οι αλλαγές χαρακτήρα και η αποκάλυψη system prompt αποδεικνύουν ότι ένα κανάλι συλλογισμού μπορεί να επηρεαστεί, αλλά το εύρημα υψηλού αντίκτυπου είναι η αλυσίδα που οδηγεί σε πρόσβαση σε δεδομένα, μη εξουσιοδοτημένη ενέργεια εργαλείου, downstream injection sink, persistence ή άλλον agent.<sup>[[2]](#references)</sup>

Το [OWASP Top 10 for Agentic Applications](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/) είναι χρήσιμο για την επισήμανση της κάλυψης (παραβίαση στόχου, κακή χρήση εργαλείων, κατάχρηση δικαιωμάτων, supply chain, εκτέλεση κώδικα, δηλητηρίαση μνήμης, εμπιστοσύνη μεταξύ agents, αλυσιδωτές αστοχίες, ανθρώπινη εμπιστοσύνη και rogue agents). Χρησιμοποιήστε αυτές τις ετικέτες αφού κατασκευάσετε μια end-to-end διαδρομή επίθεσης, αντί να θεωρείτε το απρόσμενο κείμενο ενός μοντέλου ως το τέλος της δοκιμής.<sup>[[1]](#references)[[2]](#references)</sup>

## Χαρτογράφηση του στόχου

Καταγράψτε αυτές τις πέντε διαστάσεις για κάθε workflow agent προτού γράψετε payloads:<sup>[[2]](#references)</sup>

| Διάσταση | Τι να απαριθμήσετε | Ερώτημα ασφάλειας |
|---|---|---|
| **Μη έμπιστη είσοδος** | Παράμετροι Chat/API, URLs, έγγραφα, email, tickets, καταχωρίσεις ημερολογίου, ανακτημένα chunks, μνήμη, αποτελέσματα εργαλείων και μηνύματα από peer agents | Σε ποιο σημείο μπορεί ένας επιτιθέμενος να τοποθετήσει περιεχόμενο που αργότερα εισέρχεται στο context του μοντέλου; |
| **Εργαλεία** | Ονόματα και schemas εργαλείων, παρενέργειες, auto-execution, συμπεριφορά επιβεβαίωσης και εργαλεία που φορτώνονται δυναμικά | Ποιες κλήσεις διαβάζουν secrets, γράφουν κατάσταση, στέλνουν μηνύματα, διαγράφουν δεδομένα, εκτελούν κώδικα ή μεταφέρουν αξία; |
| **Δικαιώματα** | Ανάθεση από χρήστη, service accounts, API tokens, διάρκεια ζωής διαπιστευτηρίων, εύρος tenant/resource και πρόσβαση δικτύου | Με ποια ταυτότητα εκτελείται κάθε κλήση και επαναλαμβάνεται η εξουσιοδότηση στο όριο του εργαλείου; |
| **Επεξεργασία** | Query builders, shells, URL fetchers, template engines, interpreters, parsers, λειτουργίες αρχείων και deserializers | Σε ποιο σημείο τα δεδομένα που παράγονται από το μοντέλο γίνονται σύνταξη για άλλον interpreter; |
| **Έξοδος** | Απαντήσεις, αποδοσμένο Markdown/HTML, links, λήψεις εικόνων, webhooks, email, αρχεία, logs, reports, metrics και κίνηση προς peer agents | Ποιο παρατηρήσιμο κανάλι μπορεί να μεταφέρει ένα secret ή να ενεργοποιήσει δευτερεύον αίτημα; |

Μην το συμπτύσσετε σε μια λίστα διαφημιζόμενων integrations. Ένα χρήσιμο παραδοτέο αντιστοιχίζει κάθε πηγή με την ακριβή θέση context στην οποία φτάνει, τα εργαλεία που είναι διαθέσιμα σε εκείνο το σημείο, το credential που χρησιμοποιεί κάθε εργαλείο, τον downstream interpreter και κάθε διαδρομή egress. Το ίδιο εργαλείο μπορεί να έχει χαμηλό αντίκτυπο με ένα per-user read token και κρίσιμο αντίκτυπο με ένα κοινόχρηστο administrator credential.<sup>[[2]](#references)</sup>

## Αναγνώριση

### Χαρτογράφηση κάθε διαδρομής παράδοσης και εισαγωγής

Ξεκινήστε από την επιφάνεια παράδοσης (web, mobile, API, email, chat platform, browser extension) και καταγράψτε με proxy την κίνηση από τον client προς το backend. Εξετάστε πεδία που αποκρύπτονται από το UI, παραμέτρους αναζήτησης/autocomplete/filter, αντικείμενα κατάστασης συνομιλίας, εργασίες upload και indexing, απαντήσεις εργαλείων και κίνηση sub-agent. Για mobile-only clients μπορεί να χρειαστεί emulator και instrumentation για παράκαμψη του certificate pinning, προτού γίνει ορατό το πραγματικό request schema.<sup>[[2]](#references)</sup>

Έπειτα χαρτογραφήστε το stack κάτω από το μοντέλο: orchestration framework, σύνθεση prompt, αποθήκες retrieval και μνήμης, runtime (για παράδειγμα Python, container ή WASM), προσαρτημένα volumes, υπηρεσίες host, εσωτερικά APIs, προσβασιμότητα cloud metadata και γειτονικά δίκτυα. Οι προεπιλεγμένες ρυθμίσεις του framework έχουν σημασία, επειδή ορισμένα “tool calls” υλοποιούνται με παραγωγή ή αξιολόγηση κώδικα· το όριο runtime/sandbox καθορίζει αν το αποτέλεσμα παραμένει περιορισμένο.<sup>[[2]](#references)</sup>

### Αποτύπωση δρομολόγησης με μη καταστροφικά probes

Συγκρίνετε ένα αίτημα εντός πεδίου εφαρμογής με αρκετά άσχετα αιτήματα, διατηρώντας ολόκληρη την απάντηση, τον status code, την καθυστέρηση και τη συμπεριφορά streaming. Μια σταθερή απόρριψη πριν από οποιονδήποτε συλλογισμό σχετικό με την εργασία μπορεί να υποδεικνύει ξεχωριστό gateway/classifier· μια άρνηση με βάση το context υποδηλώνει ότι το αίτημα έφτασε στο μοντέλο· μια κενή ή αμιγώς εξαγωγική απάντηση μπορεί να υποδεικνύει αναζήτηση λέξεων-κλειδιών ή περιορισμένο retrieval. Αντιμετωπίστε τα ως υποθέσεις και επιβεβαιώστε τες επαναλαμβάνοντας το ίδιο probe μέσω εναλλακτικών πεδίων API και διαδρομών εισαγωγής.<sup>[[2]](#references)</sup>

Η αναγνώριση ολοκληρώνεται όταν η αξιολόγηση μπορεί να κατονομάσει την πρωιμότερη πηγή που ελέγχεται από τον επιτιθέμενο και αλλάζει τη συμπεριφορά του agent **καθώς και** τα εργαλεία, τις ταυτότητες, τους interpreters και τις εξόδους που είναι προσβάσιμα από αυτή την πηγή.<sup>[[2]](#references)</sup>

## Εκμετάλλευση: διέλευση ενός ορίου εμπιστοσύνης

Δοκιμάστε κανάλια, όχι μόνο τη διατύπωση των prompts. Ξεκινήστε με direct injection για να διαπιστώσετε τι αποκλείει η ορατή είσοδος και, στη συνέχεια, επαναλάβετε ισοδύναμη πρόθεση μέσω των λιγότερο ορατών διαδρομών παρακάτω:<sup>[[2]](#references)</sup>

- **Έμμεσο περιεχόμενο:** σελίδες, αρχεία, email, tickets, metadata, alt text, HTML comments, κείμενο εκτός οθόνης ή χαρακτήρες μηδενικού πλάτους. Δείτε το [AI Prompts](AI-Prompts.md#third-party-or-indirect-prompt-injection) για τεχνικές παράδοσης payload.
- **Retrieval και μνήμη:** δηλητηριάστε περιεχόμενο που θα ανακτηθεί αργότερα ή κατάσταση που θα επαναφορτωθεί σε επόμενες συνεδρίες. Καταγράψτε αν η διαγραφή της αρχικής πηγής σταματά τη συμπεριφορά.
- **Έξοδος εργαλείων και peer agents:** τοποθετήστε τον marker σε απάντηση εργαλείου ή σε μήνυμα μεταξύ agents, για να ελέγξετε αν η εσωτερική κίνηση παρακάμπτει φίλτρα που εφαρμόζονται μόνο στην είσοδο χρήστη και στην τελική έξοδο.
- **Supply chain:** εξετάστε περιγραφές εργαλείων, plugins, συνδεδεμένους servers, skills, models και dependencies ως έμπιστες πηγές οδηγιών. Για δοκιμές ειδικά για MCP, δείτε το [MCP Servers](AI-MCP-Servers.md#mcp-vulns).
- **Ανθρώπινη έγκριση:** συγκρίνετε την πραγματική δομημένη κλήση εργαλείου με το κείμενο έγκρισης που παρήγαγε το μοντέλο. Δοκιμάστε αν η επιρροή του επιτιθέμενου μπορεί να παραλείψει τον προορισμό, το scope, τα επηρεαζόμενα αντικείμενα ή τις μη αναστρέψιμες παρενέργειες.

Χρησιμοποιήστε πρώτα έναν ακίνδυνο, μοναδικό marker. Διατηρήστε το αρχικό τεκμήριο, το συναρμολογημένο context εφόσον είναι ορατό, την επιλεγμένη κλήση εργαλείου, τα δεδομένα έγκρισης, το backend request/response και την τελική κατάσταση. Έτσι διαχωρίζεται η επιρροή από έναν hallucinated ισχυρισμό ότι πραγματοποιήθηκε κάποια ενέργεια.<sup>[[2]](#references)</sup>

### Κείμενο που μιμείται πολιτική σε έναν κριτή κινδύνου εργαλείων

Ένα model-based tool gate μπορεί να λάβει κείμενο ελεγχόμενο από τον επιτιθέμενο μέσα σε κατά τα άλλα χρήσιμο context ταξινόμησης. Για παράδειγμα, το πειραματικό `AutoModeMiddleware` του LangChain στέλνει σε έναν κριτή TypeSafe `is_risky` μια προτεινόμενη κλήση εργαλείου, τα ορίσματά της, μια προαιρετική περιγραφή εργαλείου και έως 30 πρόσφατα μηνύματα. Αποκλείει τα διαμορφωμένα εργαλεία όταν η πιθανότητα Noul που επιστρέφεται είναι τουλάχιστον `0.5`· τα εργαλεία που δεν έχουν καταχωριστεί δεν ταξινομούνται από αυτό το middleware.<sup>[[5]](#references)</sup> Η TypeSafe προειδοποιεί επίσης ότι adversarial κείμενο στην κατάσταση μπορεί να επηρεάσει μια ταξινόμηση, ακόμη και όταν η κατάσταση προορίζεται να είναι δεδομένα.<sup>[[6]](#references)</sup>

Μια **πλαστή πολιτική** διαφέρει από έναν απλό ισχυρισμό ότι πρόκειται για system message. Τοποθετεί εναλλακτικές ετικέτες ή ορισμούς κινδύνου σε state χαμηλότερης εμπιστοσύνης και προτρέπει τον κριτή να χρησιμοποιήσει αυτούς τους ορισμούς αντί για τα κριτήρια που έχει ορίσει ο developer. Στη δοκιμή της Datadog, ένα επεξεργάσιμο από τον χρήστη `profile_description` αντιγράφηκε στα ορίσματα εργαλείου μαζί με `can_edit:false`. Το κείμενό του, διατυπωμένο σαν πολιτική, υποστήριζε ότι μια απόπειρα εγγραφής ήταν χαμηλού κινδύνου επειδή ένας ξεχωριστός έλεγχος δικαιωμάτων θα την απέρριπτε πριν από οποιαδήποτε μεταβολή. Σε 40 εκτελέσεις, η μέση βαθμολογία `is_risky` μειώθηκε από `0.893` σε `0.290`, ενώ η σύγκριση με άμεση πλαστοπροσωπία ρόλου είχε μέσο όρο `0.905`. Το ότι ο μέσος όρος έπεσε κάτω από το `0.5` δεν αποδεικνύει ότι κάθε μεμονωμένη κλήση πέρασε το gate, και το πείραμα **δεν** έδειξε ότι ολοκληρώθηκε μη εξουσιοδοτημένη εγγραφή.<sup>[[7]](#references)</sup>

Κατά τη δοκιμή αυτού του ορίου, διακρίνετε την ετυμηγορία του classifier από το πραγματικό αποτέλεσμα εξουσιοδότησης του εργαλείου. Ελέγξτε ποια επεξεργάσιμα πεδία φτάνουν στον κριτή, συγκρίνετε την ίδια προτεινόμενη ενέργεια με και χωρίς κείμενο που μοιάζει με πολιτική και επαληθεύστε ανεξάρτητα την τελική κατάσταση. Ένας ξεχωριστός έλεγχος δικαιωμάτων πρέπει να χρησιμοποιεί την εξουσία του αυθεντικοποιημένου αιτούντος και όχι τα δικαιώματα service account του connector.<sup>[[7]](#references)</sup> Δείτε τα [prompt-filter bypasses](AI-Prompts.md#prompt-waf-bypass) για άλλους τρόπους αστοχίας classifier· τα [LLM gateway trust boundaries](AI-LLM-Gateway-Security.md) αφορούν διαφορετικό όριο δρομολόγησης και διαπιστευτηρίων.

### Απομόνωση context subagent

Ένας subagent του Claude Agent SDK που δεν χρησιμοποιεί fork λαμβάνει το δικό του `AgentDefinition.prompt`, το prompt ανάθεσης και τα διαθέσιμα εργαλεία του, αλλά όχι το system prompt ή τη συνομιλία του parent. Αν παραλειφθεί το `tools` από τον ορισμό του, κληρονομεί τα εργαλεία που είναι διαθέσιμα στους subagents· το project `CLAUDE.md` ενδέχεται και πάλι να φορτωθεί. Επομένως, ένας περιορισμός prompt που ισχύει μόνο για τον parent δεν αποτελεί αξιόπιστο όριο όταν το child μπορεί να χρησιμοποιήσει τα ίδια εργαλεία filesystem ή execution.<sup>[[4]](#references)</sup>

Δοκιμάστε το όριο συγκρίνοντας ένα άμεσο αίτημα που αρνείται ο parent με την ίδια εργασία ανατεθειμένη σε έναν subagent με συγκεκριμένο όνομα. Η NCC Group αναφέρει ότι μια άρνηση καταμέτρησης αρχείων του λειτουργικού συστήματος επιτεύχθηκε όταν η εργασία αναδιατυπώθηκε για ένα child ως αβλαβής «χάρτης διάταξης».<sup>[[3]](#references)</sup>

Εξετάστε τις πραγματικές κλήσεις εργαλείων του child και την ενεργή allowlist εργαλείων, όχι μόνο την τελική απάντηση του parent· επιβεβαιώστε αν το child προσπέλασε αρχεία που ο parent δεν θα προσπέλαζε.<sup>[[4]](#references)</sup> Πρόκειται για αστοχία κληρονόμησης guardrail, όχι για απόδειξη [Python sandbox](../generic-methodologies-and-resources/python/bypass-python-sandboxes/) ή διαφυγής από container.<sup>[[3]](#references)[[4]](#references)</sup>

## Εκτέλεση: απόδειξη πραγματικού αντίκτυπου

Υπάρχουν δύο διακριτές διαδρομές από την επιρροή στον αντίκτυπο:<sup>[[2]](#references)</sup>

1. **Κατάχρηση δυνατότητας:** το εξουσιοδοτημένο εργαλείο εκτελεί ήδη τον στόχο. Παραδείγματα περιλαμβάνουν την ανάγνωση εγγραφής ενός tenant και την εγγραφή της σε αναφορά ορατή στον επιτιθέμενο, την αποστολή email, την αλλαγή εγγραφών, τη διαγραφή αρχείου ή την έναρξη πληρωμής. Δεν απαιτείται δευτερεύον software bug.
2. **Εκμετάλλευση downstream sink:** η έξοδος του μοντέλου, κατευθυνόμενη από τον επιτιθέμενο, γίνεται σύνταξη για άλλο component. Εξετάστε τα database queries για [SQL injection](../pentesting-web/sql-injection/README.md) ή [NoSQL injection](../pentesting-web/nosql-injection.md), τα shell wrappers για [command injection](../pentesting-web/command-injection.md), τα URLs που επιλέγονται για [SSRF](../pentesting-web/ssrf-server-side-request-forgery/README.md), τις λειτουργίες αρχείων για traversal, τους template/code evaluators για RCE και τους object parsers για [unsafe deserialization](../pentesting-web/deserialization/README.md).

Για κάθε υποψήφιο εύρημα, αποδείξτε την ακόλουθη αλυσίδα:<sup>[[2]](#references)</sup>

```text
attacker-controlled source
  -> model/context influence
  -> selected tool and arguments
  -> effective identity/credential
  -> capability or vulnerable sink
  -> externally verified state change or data egress
```

Μια read-only ενσωμάτωση εξακολουθεί να είναι εκμεταλλεύσιμη όταν οποιοδήποτε μεταγενέστερο στοιχείο μπορεί να δημοσιεύσει όσα διάβασε. Ελέγξτε τις συνηθισμένες απαντήσεις, καθώς και λιγότερο προφανείς τρόπους εξαγωγής δεδομένων, όπως συνδέσμους που ελέγχονται από τον επιτιθέμενο, αυτόματη ανάκτηση εικόνων, webhooks, logs, αναφορές, μετρητές, ειδοποιήσεις και μηνύματα προς άλλους agents.<sup>[[2]](#references)</sup>

## Ενέργειες για την επίτευξη στόχων

Αφού επιβεβαιώσετε μία ενέργεια, αξιολογήστε ολόκληρη την ακτίνα επιπτώσεων αντί να σταματήσετε στην πρώτη ορατή επίδραση:<sup>[[2]](#references)</sup>

- **Εξαγωγή δεδομένων:** secrets, εγγραφές χρηστών, εσωτερικά αρχεία, δεδομένα συνομιλιών ή περιεχόμενο prompt/context διαρρέουν μέσω ενός παρατηρήσιμου καναλιού.
- **Μη εξουσιοδοτημένη ενέργεια:** ο agent χρησιμοποιεί νόμιμες δυνατότητες εγγραφής για να εξυπηρετήσει τον στόχο του επιτιθέμενου.
- **Άρνηση υπηρεσίας:** καταστροφικά εργαλεία ή επαναλαμβανόμενες δαπανηρές λειτουργίες επηρεάζουν την ακεραιότητα ή τη διαθεσιμότητα.
- **Επιμονή:** δηλητηριασμένη μνήμη, περιεχόμενο στο ευρετήριο, έμπιστη κατάσταση ή αλλαγές χρόνου εκτέλεσης επιβιώνουν από την αρχική συνεδρία ή την αφαίρεση της πηγής.
- **Διάδοση:** ένας έμπιστος peer καταναλώνει το μήνυμα ή την κοινόχρηστη κατάσταση του παραβιασμένου agent και επαναλαμβάνει την ενέργεια με τα δικά του εργαλεία και διαπιστευτήρια.

Η σοβαρότητα πρέπει να βασίζεται στα προσβάσιμα δεδομένα, στα πραγματικά δικαιώματα, στην εκμεταλλευσιμότητα του sink, στο egress, στην επιμονή και στη διάδοση — όχι στο πόσο αναπάντεχο φαίνεται το κείμενο του μοντέλου.<sup>[[2]](#references)</sup>

## Έλεγχοι προς επικύρωση κατά την αξιολόγηση

Τα φίλτρα prompt και ένα καλύτερο system prompt μπορούν να αυξήσουν το κόστος για τον επιτιθέμενο, αλλά δεν πρέπει να θεωρούνται όρια εξουσιοδότησης. Επικυρώστε τους παρακάτω ελέγχους επαναλαμβάνοντας την ίδια αλυσίδα μέσω άμεσης εισόδου, έμμεσου περιεχομένου, μνήμης, εργαλείων και peer agents:<sup>[[2]](#references)</sup>

- Ένα ντετερμινιστικό επίπεδο πολιτικής ελέγχει τον πιστοποιημένο χρήστη, τον tenant, το αντικείμενο, την ενέργεια και τον προορισμό σε **κάθε κλήση εργαλείου**· το μοντέλο δεν μπορεί να ορίσει ή να παρακάμψει την ταυτότητα του καλούντος.
- Οι δυνατότητες ανάγνωσης και εγγραφής χρησιμοποιούν ξεχωριστά διαπιστευτήρια ελάχιστων δικαιωμάτων και μικρής διάρκειας· τα εργαλεία υψηλού αντίκτυπου παρέχονται just in time και δεν εκτελούνται ποτέ αυτόματα βάσει εισαγόμενου περιεχομένου.
- Το egress δικτύου και οι εσωτερικοί προορισμοί βρίσκονται σε ανεξάρτητες allowlists, ανεξάρτητα από τα URL που επιλέγει το μοντέλο· η πρόσβαση του runtime σε endpoints μεταδεδομένων, προσαρτημένα secrets και γειτονικές υπηρεσίες αποκλείεται, εκτός αν απαιτείται.
- Το περιβάλλον έγκρισης δημιουργείται από το κανονικό δομημένο αίτημα και εμφανίζει τα ακριβή ορίσματα, την ταυτότητα, τον προορισμό, τα επηρεαζόμενα αντικείμενα και τις παρενέργειες — όχι μια ελεύθερη περίληψη του μοντέλου.
- Η επιτυχία επαληθεύεται από το σύστημα προορισμού ή το σύστημα καταγραφής. Η αφήγηση του agent, ένα αίτημα κλήσης εργαλείου ή μια ανακατεύθυνση HTTP δεν αποδεικνύουν ότι πραγματοποιήθηκε η αναφερόμενη αλλαγή κατάστασης.
- Οι εγγραφές μνήμης και ανάκτησης διατηρούν την προέλευση και τις ετικέτες εμπιστοσύνης, μπορούν να ακυρωθούν και επανελέγχονται ως προς την εξουσιοδότηση όταν χρησιμοποιούνται για μεταγενέστερη ενέργεια.
- Τα μηνύματα μεταξύ agents πιστοποιούνται και εξουσιοδοτούνται ως μη έμπιστα αιτήματα· η φήμη ενός peer ή η κάρτα agent δεν εκχωρεί σιωπηρά τα εργαλεία του παραλήπτη.

Για κάρτες agent A2A, ροές εργασιών και την επιφάνεια επίθεσής τους, δείτε το [A2A Protocol Security](AI-A2A-Protocol.md).
