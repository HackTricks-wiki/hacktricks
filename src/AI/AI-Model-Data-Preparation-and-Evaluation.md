# Підготовка та оцінювання даних моделі

{{#include ../banners/hacktricks-training.md}}

Підготовка даних моделі є важливим етапом у конвеєрі машинного навчання, оскільки передбачає перетворення необроблених даних у формат, придатний для навчання моделей машинного навчання. Цей процес включає кілька ключових етапів:

1. **Збір даних**: отримання даних із різних джерел, таких як бази даних, API або файли. Дані можуть бути структурованими (наприклад, таблиці) або неструктурованими (наприклад, текст, зображення).
2. **Очищення даних**: видалення або виправлення помилкових, неповних чи нерелевантних точок даних. Цей етап може передбачати обробку пропущених значень, видалення дублікатів і фільтрацію викидів.
3. **Перетворення даних**: конвертація даних у придатний для моделювання формат. Це може включати нормалізацію, масштабування, кодування категоріальних змінних і створення нових ознак за допомогою таких методів, як feature engineering.
4. **Розподіл даних**: поділ набору даних на навчальну, валідаційну та тестову вибірки, щоб забезпечити здатність моделі добре узагальнюватися на невідомих даних.

## Збір даних

Збір даних передбачає отримання даних із різних джерел, зокрема:
- **Бази даних**: вилучення даних із реляційних баз даних (наприклад, SQL databases) або NoSQL databases (наприклад, MongoDB).
- **API**: отримання даних із веб-API, які можуть надавати дані в реальному часі або історичні дані.
- **Файли**: зчитування даних із файлів у таких форматах, як CSV, JSON або XML.
- **Web Scraping**: збір даних із вебсайтів за допомогою методів web scraping.

Залежно від мети проєкту машинного навчання дані вилучатимуться та збиратимуться з релевантних джерел, щоб забезпечити їхню репрезентативність для предметної області задачі.

## Очищення даних <sup>[[1]](#references)</sup><sup>[[2]](#references)</sup>

Очищення даних — це процес виявлення та виправлення помилок або невідповідностей у наборі даних. Цей етап є необхідним для забезпечення якості даних, які використовуються для навчання моделей машинного навчання. Ключові завдання очищення даних включають:
- **Обробка пропущених значень**: виявлення та опрацювання відсутніх точок даних. Поширені стратегії включають:
- Видалення рядків або стовпців із пропущеними значеннями.
- Заповнення пропущених значень за допомогою таких методів, як імпутація середнім, медіаною або модою.
- Використання розширених методів, таких як імпутація методом K-nearest neighbors (KNN) або регресійна імпутація.
- **Видалення дублікатів**: виявлення та видалення дубльованих записів, щоб гарантувати унікальність кожної точки даних.
- **Фільтрація викидів**: виявлення та видалення викидів, які можуть спотворювати продуктивність моделі. Для виявлення викидів можна використовувати такі методи, як Z-score, IQR (Interquartile Range) або візуалізації (наприклад, box plots).

### Приклад очищення даних
```python
import re

import numpy as np
import pandas as pd
from sklearn.impute import KNNImputer, SimpleImputer

# Load the dataset
df = pd.read_csv('data.csv')

# Finding invalid values based on a specific function
def is_valid_positive_int(num):
try:
num = int(num)
return 1 <= num <= 31
except ValueError:
return False

invalid_days = df[~df['days'].astype(str).apply(is_valid_positive_int)]

## Dropping rows with invalid days
df = df.drop(invalid_days.index, errors='ignore')



# Set "NaN" values to a specific value
## For example, setting NaN values in the 'days' column to 0
df['days'] = pd.to_numeric(df['days'], errors='coerce')

## For example, set "NaN" to not ips
def is_valid_ip(ip):
pattern = re.compile(r'^((25[0-5]|2[0-4][0-9]|[01]?\d?\d)\.){3}(25[0-5]|2[0-4]\d|[01]?\d?\d)$')
if pd.isna(ip) or not pattern.match(str(ip)):
return np.nan
return ip
df['ip'] = df['ip'].apply(is_valid_ip)

# Filling missing values based on different strategies
numeric_cols = ["days", "hours", "minutes"]
categorical_cols = ["ip", "status"]

## Filling missing values in numeric columns with the median
num_imputer = SimpleImputer(strategy='median')
df[numeric_cols] = num_imputer.fit_transform(df[numeric_cols])

## Filling missing values in categorical columns with the most frequent value
cat_imputer = SimpleImputer(strategy='most_frequent')
df[categorical_cols] = cat_imputer.fit_transform(df[categorical_cols])

## Filling missing values in numeric columns using KNN imputation
knn_imputer = KNNImputer(n_neighbors=5)
df[numeric_cols] = knn_imputer.fit_transform(df[numeric_cols])



# Filling missing values
df.fillna(df.mean(numeric_only=True), inplace=True)

# Removing duplicates
df.drop_duplicates(inplace=True)
# Filtering outliers using Z-score
from scipy import stats
z_scores = np.abs(stats.zscore(df.select_dtypes(include=['float64', 'int64']), nan_policy='omit'))
df = df[(z_scores < 3).all(axis=1)]
```
## Трансформація даних <sup>[[1]](#references)</sup>

Трансформація даних передбачає перетворення даних у формат, придатний для моделювання. Цей етап може включати:
- **Нормалізація та стандартизація**: масштабування числових ознак до спільного діапазону, зазвичай [0, 1] або [-1, 1]. Це може покращити збіжність алгоритмів оптимізації.
- **Min-Max Scaling**: масштабування ознак до фіксованого діапазону, зазвичай [0, 1]. Виконується за формулою: `X' = (X - X_{min}) / (X_{max} - X_{min})`
- **Z-Score Normalization**: стандартизація ознак шляхом віднімання середнього значення та ділення на стандартне відхилення, у результаті чого отримується розподіл із середнім значенням 0 і стандартним відхиленням 1. Виконується за формулою: `X' = (X - μ) / σ`, де μ — середнє значення, а σ — стандартне відхилення.
- **Асиметрія та ексцес**: коригування розподілів ознак за допомогою таких перетворень, як логарифмування, добування квадратного кореня або Box-Cox. Наприклад, логарифмічне перетворення може зменшити позитивну асиметрію.
- **Нормалізація рядків**: перетворення рядків до узгодженого формату, наприклад:
- Перетворення на нижній регістр
- Видалення спеціальних символів (зі збереженням релевантних)
- Видалення stop words (поширених слів, які не додають значення, таких як "the", "is", "and")
- Видалення надто частих і надто рідкісних слів (наприклад, слів, які трапляються більш ніж у 90% документів або менш ніж 5 разів у корпусі)
- Видалення зайвих пробілів
- Stemming/Lemmatization: зведення слів до їхньої базової або кореневої форми (наприклад, "running" до "run").

- **Кодування категоріальних змінних**: перетворення категоріальних змінних на числові представлення. Поширені методи включають:
- **One-Hot Encoding**: створення бінарних стовпців для кожної категорії.
- Наприклад, якщо ознака має категорії "red", "green" і "blue", її буде перетворено на три бінарні стовпці: `is_red`(100), `is_green`(010) і `is_blue`(001).
- **Label Encoding**: призначення унікального цілого числа кожній категорії.
- Наприклад, "red" = 0, "green" = 1, "blue" = 2.
- **Ordinal Encoding**: призначення цілих чисел на основі порядку категорій.
- Наприклад, якщо категоріями є "low", "medium" і "high", їм можна призначити значення 0, 1 і 2 відповідно.
- **Hashing Encoding**: використання hash function для перетворення категорій на вектори фіксованого розміру, що може бути корисним для категоріальних змінних із великою кількістю унікальних значень.
- Наприклад, якщо ознака має багато унікальних категорій, hashing може зменшити розмірність, зберігаючи частину інформації про категорії.
- **Bag of Words (BoW)**: представлення текстових даних як матриці кількості або частоти слів, де кожен рядок відповідає документу, а кожен стовпець — унікальному слову в корпусі.
- Наприклад, якщо корпус містить слова "cat", "dog" і "fish", документ, що містить "cat" і "dog", буде представлено як [1, 1, 0]. Це конкретне представлення називається "unigram" і не враховує порядок слів, тому втрачає семантичну інформацію.
- **Bigram/Trigram**: розширення BoW для захоплення послідовностей слів (біграм або триграм) із метою збереження частини контексту. Наприклад, "cat and dog" буде представлено як bigram [1, 1] для "cat and" і [1, 1] для "and dog". У цьому випадку збирається більше семантичної інформації (збільшується розмірність представлення), але лише для 2 або 3 слів одночасно.
- **TF-IDF (Term Frequency-Inverse Document Frequency)**: статистичний показник, який оцінює важливість слова в документі відносно колекції документів (корпусу). Він поєднує частоту терміна (як часто слово з’являється в документі) та зворотну частоту документа (наскільки рідкісним є слово в усіх документах).
- Наприклад, якщо слово "cat" часто трапляється в документі, але є рідкісним у всьому корпусі, воно матиме високий показник TF-IDF, що вказує на його важливість у цьому документі.

- **Feature Engineering**: створення нових ознак на основі наявних для підвищення прогнозувальної здатності моделі. Це може передбачати комбінування ознак, вилучення компонентів дати/часу або застосування предметно-специфічних перетворень.

## Розділення даних <sup>[[3]](#references)</sup>

Розділення даних передбачає поділ набору даних на окремі підмножини для навчання, валідації та тестування. Це необхідно для оцінювання продуктивності моделі на невідомих даних і запобігання перенавчанню. Поширені стратегії включають:
- **Train-Test Split**: поділ набору даних на навчальний набір (зазвичай 60–80% даних), набір валідації (10–15% даних) для налаштування гіперпараметрів і тестовий набір (10–15% даних). Модель навчається на навчальному наборі та оцінюється на тестовому наборі.
- Наприклад, якщо у вас є набір даних із 1000 зразків, можна використати 700 зразків для навчання, 150 для валідації та 150 для тестування.
- **Stratified Sampling**: забезпечення подібного розподілу класів у навчальному й тестовому наборах до розподілу в усьому наборі даних. Це особливо важливо для незбалансованих наборів даних, де деякі класи можуть мати значно менше зразків, ніж інші.
- **Time Series Split**: для даних часових рядів набір даних розділяється за часом, щоб навчальний набір містив дані з більш ранніх періодів, а тестовий — із пізніших. Це допомагає оцінити продуктивність моделі на майбутніх даних.
- **K-Fold Cross-Validation**: поділ набору даних на K підмножин (folds) і навчання моделі K разів, щоразу використовуючи іншу підмножину як тестовий набір, а решту підмножин — як навчальний набір. Це допомагає забезпечити оцінювання моделі на різних підмножинах даних, надаючи надійнішу оцінку її продуктивності.

## Оцінювання моделі <sup>[[4]](#references)</sup>

Оцінювання моделі — це процес визначення продуктивності моделі машинного навчання на невідомих даних. Він передбачає використання різних метрик для кількісного визначення того, наскільки добре модель узагальнює нові дані. Поширені метрики оцінювання включають:

### Точність

Точність — це частка правильно спрогнозованих екземплярів від загальної кількості екземплярів. Вона обчислюється так:
```plaintext
Accuracy = (Number of Correct Predictions) / (Total Number of Predictions)
```
> [!TIP]
> Accuracy є простим та інтуїтивно зрозумілим показником, але він може бути непридатним для незбалансованих датасетів, де один клас домінує над іншими, оскільки може створювати оманливе враження про продуктивність моделі. Наприклад, якщо 90% даних належать до класу A, а модель прогнозує всі екземпляри як клас A, вона досягне 90% accuracy, але не буде корисною для прогнозування класу B.

### Precision

Precision — це частка істинно позитивних прогнозів серед усіх позитивних прогнозів, зроблених моделлю. Обчислюється так:
```plaintext
Precision = (True Positives) / (True Positives + False Positives)
```
> [!TIP]
> Точність особливо важлива в сценаріях, де хибнопозитивні результати є витратними або небажаними, наприклад під час медичної діагностики чи виявлення шахрайства. Наприклад, якщо модель прогнозує 100 екземплярів як позитивні, але лише 80 із них насправді є позитивними, точність становитиме 0,8 (80%).

### Повнота (Чутливість)

Повнота, також відома як чутливість або частка істинно позитивних результатів, — це частка істинно позитивних прогнозів серед усіх фактично позитивних екземплярів. Вона обчислюється так:
```plaintext
Recall = (True Positives) / (True Positives + False Negatives)
```
> [!TIP]
> Повнота є критично важливою у сценаріях, де хибнонегативні результати є дорогими або небажаними, наприклад під час виявлення захворювань або фільтрації спаму. Наприклад, якщо модель ідентифікує 80 із 100 фактичних позитивних випадків, повнота становитиме 0,8 (80%).

### Показник F1

Показник F1 є середнім гармонійним значенням точності та повноти, забезпечуючи баланс між цими двома метриками. Він обчислюється так:
```plaintext
F1 Score = 2 * (Precision * Recall) / (Precision + Recall)
```
> [!TIP]
> Показник F1 особливо корисний під час роботи з незбалансованими наборами даних, оскільки враховує як false positives, так і false negatives. Він надає єдину метрику, що відображає компроміс між precision і recall. Наприклад, якщо precision моделі становить 0.8, а recall — 0.6, показник F1 становитиме приблизно 0.69.

### ROC-AUC (Receiver Operating Characteristic - Area Under the Curve)

Метрика ROC-AUC оцінює здатність моделі розрізняти класи, будуючи графік залежності true positive rate (чутливості) від false positive rate за різних значень порогу. Площа під ROC-кривою (AUC) кількісно оцінює продуктивність моделі: значення 1 означає ідеальну класифікацію, а значення 0.5 — випадкове вгадування.

> [!TIP]
> ROC-AUC особливо корисна для задач бінарної класифікації та надає комплексне уявлення про продуктивність моделі за різних порогів. Вона менш чутлива до дисбалансу класів порівняно з accuracy. Наприклад, модель з AUC 0.9 має високу здатність розрізняти позитивні та негативні екземпляри.

### Специфічність

Специфічність, також відома як true negative rate, — це частка true negative прогнозів серед усіх фактично негативних екземплярів. Вона обчислюється так:
```plaintext
Specificity = (True Negatives) / (True Negatives + False Positives)
```
> [!TIP]
> Специфічність важлива в сценаріях, де хибнопозитивні результати є дорогими або небажаними, наприклад під час медичного тестування чи виявлення шахрайства. Вона допомагає оцінити, наскільки добре модель ідентифікує негативні випадки. Наприклад, якщо модель правильно ідентифікує 90 із 100 фактичних негативних випадків, специфічність становитиме 0,9 (90%).

### Коефіцієнт кореляції Метьюза (MCC)
Коефіцієнт кореляції Метьюза (MCC) є показником якості бінарної класифікації. Він враховує істиннопозитивні, хибнопозитивні, істиннонегативні та хибнонегативні результати, забезпечуючи збалансовану оцінку продуктивності моделі. MCC обчислюється так:
```plaintext
MCC = (TP * TN - FP * FN) / sqrt((TP + FP) * (TP + FN) * (TN + FP) * (TN + FN))
```
де:
- **TP**: істинно позитивні
- **TN**: істинно негативні
- **FP**: хибно позитивні
- **FN**: хибно негативні

> [!TIP]
> MCC має діапазон від -1 до 1, де 1 означає ідеальну класифікацію, 0 означає випадкове вгадування, а -1 означає повну розбіжність між прогнозом і спостереженням. Він особливо корисний для незбалансованих наборів даних, оскільки враховує всі чотири компоненти матриці помилок.

### Середня абсолютна похибка (MAE)
Середня абсолютна похибка (MAE) — це метрика регресії, яка вимірює середню абсолютну різницю між прогнозованими та фактичними значеннями. Вона обчислюється так:
```plaintext
MAE = (1/n) * Σ|y_i - ŷ_i|
```
де:
- **n**: Кількість екземплярів
- **y_i**: Фактичне значення для екземпляра i
- **ŷ_i**: Передбачене значення для екземпляра i

> [!TIP]
> MAE забезпечує просту інтерпретацію середньої похибки передбачень, що полегшує її розуміння. Вона менш чутлива до викидів порівняно з іншими метриками, як-от середньоквадратична помилка (MSE). Наприклад, якщо модель має MAE, що дорівнює 5, це означає, що в середньому передбачення моделі відхиляються від фактичних значень на 5 одиниць.

### Матриця помилок

Матриця помилок — це таблиця, яка узагальнює продуктивність моделі класифікації, показуючи кількість істинно позитивних, істинно негативних, хибнопозитивних і хибнонегативних передбачень. Вона надає детальне уявлення про те, наскільки добре модель працює з кожним класом.

|               | Передбачено позитивний клас | Передбачено негативний клас |
|---------------|---------------------|---------------------|
| Фактично позитивний клас| Істинно позитивний (TP)  | Хибнонегативний (FN)  |
| Фактично негативний клас| Хибнопозитивний (FP) | Істинно негативний (TN)   |

- **Істинно позитивний (TP)**: Модель правильно передбачила позитивний клас.
- **Істинно негативний (TN)**: Модель правильно передбачила негативний клас.
- **Хибнопозитивний (FP)**: Модель помилково передбачила позитивний клас (помилка I типу).
- **Хибнонегативний (FN)**: Модель помилково передбачила негативний клас (помилка II типу).

Матрицю помилок можна використовувати для обчислення таких метрик оцінювання, як accuracy, precision, recall і F1 score.
