## Навчання без учителя

Навчання без учителя — це тип машинного навчання, у якому модель тренується на даних без розмічених відповідей. Мета полягає в пошуку закономірностей, структур або взаємозв'язків у даних. На відміну від навчання з учителем, де модель навчається на розмічених прикладах, алгоритми навчання без учителя працюють із нерозміченими даними.
Навчання без учителя часто використовується для таких завдань, як кластеризація, зменшення розмірності та виявлення аномалій. Воно допомагає знаходити приховані закономірності в даних, об'єднувати схожі елементи в групи або зменшувати складність даних, зберігаючи їхні основні характеристики.


### Кластеризація K-Means

K-Means — це алгоритм кластеризації на основі центроїдів, який розподіляє дані на K кластерів, призначаючи кожну точку до найближчого середнього значення кластера. Алгоритм працює так:
1. **Ініціалізація**: Вибрати K початкових центрів кластерів (центроїдів), часто випадковим способом або за допомогою оптимальніших методів, таких як k-means++
2. **Призначення**: Призначити кожну точку даних до найближчого центроїда на основі метрики відстані (наприклад, евклідової відстані).
3. **Оновлення**: Перерахувати центроїди, взявши середнє значення всіх точок даних, призначених кожному кластеру.
4. **Повторення**: Повторювати кроки 2–3, доки призначення до кластерів не стабілізуються (центроїди більше не зміщуються суттєво).

> [!TIP]
> *Випадки використання в кібербезпеці:* K-Means використовується для виявлення вторгнень шляхом кластеризації мережевих подій. Наприклад, дослідники застосували K-Means до набору даних про вторгнення KDD Cup 99 і виявили, що він ефективно розподіляє трафік на кластери нормального трафіку та атак. На практиці аналітики безпеки можуть кластеризувати записи журналів або дані про поведінку користувачів, щоб знаходити групи схожої активності; будь-які точки, які не належать до чітко сформованого кластера, можуть вказувати на аномалії (наприклад, новий варіант malware, що формує власний невеликий кластер). K-Means також може допомогти в класифікації сімейств malware, групуючи бінарні файли на основі профілів поведінки або векторів ознак.

#### Вибір K
Кількість кластерів (K) — це гіперпараметр, який потрібно визначити до запуску алгоритму. Такі методи, як метод ліктя або показник силуету, допомагають визначити відповідне значення K шляхом оцінювання ефективності кластеризації:

- **Метод ліктя**: Побудувати графік суми квадратів відстаней від кожної точки до призначеного їй центроїда кластера як функції K. Знайти точку «ліктя», де швидкість зменшення різко змінюється, що вказує на відповідну кількість кластерів.
- **Показник силуету**: Обчислити показник силуету для різних значень K. Вищий показник силуету вказує на краще визначені кластери.

#### Припущення та обмеження

K-Means передбачає, що **кластери мають сферичну форму та однаковий розмір**, що може бути справедливим не для всіх наборів даних. Він чутливий до початкового розташування центроїдів і може збігатися до локальних мінімумів. Крім того, K-Means не підходить для наборів даних зі змінною щільністю, не-глобулярними формами або ознаками з різними масштабами. Для забезпечення однакового внеску всіх ознак у розрахунки відстані можуть знадобитися етапи попередньої обробки, такі як нормалізація або стандартизація.

<details>
<summary>Приклад -- Кластеризація мережевих подій
</summary>
Нижче ми симулюємо дані про мережевий трафік і використовуємо K-Means для їх кластеризації. Припустімо, що ми маємо події з такими ознаками, як тривалість з'єднання та кількість байтів. Ми створюємо 3 кластери «нормального» трафіку та 1 невеликий кластер, що представляє шаблон атаки. Потім запускаємо K-Means, щоб перевірити, чи розділяє він їх.
```python
import numpy as np
from sklearn.cluster import KMeans

# Simulate synthetic network traffic data (e.g., [duration, bytes]).
# Three normal clusters and one small attack cluster.
rng = np.random.RandomState(42)
normal1 = rng.normal(loc=[50, 500], scale=[10, 100], size=(500, 2))   # Cluster 1
normal2 = rng.normal(loc=[60, 1500], scale=[8, 200], size=(500, 2))   # Cluster 2
normal3 = rng.normal(loc=[70, 3000], scale=[5, 300], size=(500, 2))   # Cluster 3
attack = rng.normal(loc=[200, 800], scale=[5, 50], size=(50, 2))      # Small attack cluster

X = np.vstack([normal1, normal2, normal3, attack])
# Run K-Means clustering into 4 clusters (we expect it to find the 4 groups)
kmeans = KMeans(n_clusters=4, random_state=0, n_init=10)
labels = kmeans.fit_predict(X)

# Analyze resulting clusters
clusters, counts = np.unique(labels, return_counts=True)
print(f"Cluster labels: {clusters}")
print(f"Cluster sizes: {counts}")
print("Cluster centers (duration, bytes):")
for idx, center in enumerate(kmeans.cluster_centers_):
print(f"  Cluster {idx}: {center}")
```
У цьому прикладі K-Means має знайти 4 кластери. Невеликий кластер атак (з незвично великою тривалістю ~200) в ідеалі утворить власний кластер завдяки його відстані від нормальних кластерів. Ми виводимо розміри та центри кластерів, щоб інтерпретувати результати. У реальному сценарії кластер із невеликою кількістю точок можна позначити як потенційні аномалії або перевірити його елементи на наявність шкідливої активності.

### Ієрархічна кластеризація

Ієрархічна кластеризація будує ієрархію кластерів за допомогою висхідного (агломеративного) або низхідного (дивізивного) підходу:

1. **Агломеративний (висхідний)**: Почати з того, що кожна точка даних є окремим кластером, і послідовно об'єднувати найближчі кластери, доки не залишиться один кластер або не буде досягнуто критерію зупинки.
2. **Дивізивний (низхідний)**: Почати з усіх точок даних в одному кластері й послідовно розділяти кластери, доки кожна точка даних не стане власним кластером або не буде досягнуто критерію зупинки.

Агломеративна кластеризація потребує визначення відстані між кластерами та критерію зв'язності, щоб вирішити, які кластери об'єднувати. Поширені методи зв'язності включають single linkage (відстань між найближчими точками двох кластерів), complete linkage (відстань між найдальшими точками), average linkage тощо, а метрикою відстані часто є евклідова відстань. Вибір зв'язності впливає на форму отриманих кластерів. Немає потреби заздалегідь визначати кількість кластерів K; можна «розрізати» дендрограму на вибраному рівні, щоб отримати бажану кількість кластерів.

Ієрархічна кластеризація створює дендрограму — деревоподібну структуру, яка показує взаємозв'язки між кластерами на різних рівнях деталізації. Дендрограму можна розрізати на бажаному рівні, щоб отримати певну кількість кластерів.

> [!TIP]
> *Застосування в кібербезпеці:* Ієрархічна кластеризація може організовувати події або сутності в дерево, щоб виявляти взаємозв'язки. Наприклад, під час аналізу malware агломеративна кластеризація може групувати зразки за схожістю поведінки, виявляючи ієрархію сімейств і варіантів malware. У мережевій безпеці можна кластеризувати потоки IP-трафіку та використовувати дендрограму для перегляду підгруп трафіку (наприклад, спочатку за протоколом, а потім за поведінкою). Оскільки не потрібно заздалегідь вибирати K, цей метод корисний під час дослідження нових даних, для яких кількість категорій атак невідома.

#### Припущення та обмеження

Ієрархічна кластеризація не припускає конкретної форми кластерів і може виявляти вкладені кластери. Вона корисна для виявлення таксономії або взаємозв'язків між групами (наприклад, для групування malware за підгрупами сімейств). Вона є детермінованою (проблеми з випадковою ініціалізацією відсутні). Ключовою перевагою є дендрограма, яка дає уявлення про структуру кластеризації даних на всіх масштабах — аналітики безпеки можуть визначити відповідний поріг для ідентифікації змістовних кластерів. Однак цей метод потребує значних обчислювальних ресурсів (зазвичай $O(n^2)$ часу або більше для наївних реалізацій) і непридатний для дуже великих наборів даних. Це також жадібна процедура: після виконання об'єднання або розділення його неможливо скасувати, що може призвести до неоптимальних кластерів, якщо помилка сталася на ранньому етапі. Викиди також можуть впливати на деякі стратегії зв'язності (single-link може спричинити ефект «ланцюжка», коли кластери з'єднуються через викиди).

</summary>

Ми повторно використаємо синтетичні дані з прикладу K-Means (3 нормальні кластери + 1 кластер атак) і застосуємо агломеративну кластеризацію. Потім покажемо, як отримати дендрограму та мітки кластерів.

agg = AgglomerativeClustering(n_clusters=None, distance_threshold=0, linkage='ward')

agg.fit(X)

print(f"Number of merge steps: {agg.n_clusters_ - 1}")  # should equal number of points - 1

Z = linkage(X, method='ward')

print(f"Labels with 3 clusters: {np.unique(clusters_3)}")

### DBSCAN (кластеризація просторових даних на основі щільності із шумом)

DBSCAN — це алгоритм кластеризації на основі щільності, який об'єднує точки, розташовані близько одна до одної, позначаючи точки в регіонах із низькою щільністю як викиди. Він особливо корисний для наборів даних зі змінною щільністю та несферичними формами.

DBSCAN працює, визначаючи два параметри:
- **Epsilon (ε)**: максимальна відстань між двома точками, за якої вони вважаються частиною одного кластера.
- **MinPts**: мінімальна кількість точок, необхідна для формування щільного регіону (центральної точки).

DBSCAN визначає центральні точки, граничні точки та шумові точки:
- **Центральна точка**: точка, яка має щонайменше MinPts сусідів у межах відстані ε.
- **Гранична точка**: точка, що розташована на відстані ε від центральної точки, але має менше ніж MinPts сусідів.
- **Шумова точка**: точка, яка не є ані центральною, ані граничною.

Кластеризація починається з вибору невідвіданої центральної точки та позначення її як нового кластера, після чого рекурсивно додаються всі точки, щільнісно досяжні з неї (центральні точки та їхні сусіди тощо). Граничні точки додаються до кластера найближчої центральної точки. Після розширення на всі досяжні точки DBSCAN переходить до іншої невідвіданої центральної точки, щоб почати новий кластер. Точки, яких не досягла жодна центральна точка, залишаються позначеними як шум.

> [!TIP]
> *Випадки використання в cybersecurity:* DBSCAN корисний для виявлення аномалій у мережевому трафіку. Наприклад, нормальна активність користувачів може формувати один або кілька щільних кластерів у просторі ознак, тоді як нові поведінкові шаблони атак з'являються як розрізнені точки, які DBSCAN позначить як шум (викиди). Його використовували для кластеризації записів мережевих потоків, де він може виявляти port scans або denial-of-service трафік як розріджені області точок. Інше застосування — групування варіантів malware: якщо більшість зразків кластеризується за сімействами, але кілька зразків не відповідають жодному кластеру, це можуть бути zero-day malware. Можливість позначати шум дає security teams змогу зосередитися на дослідженні таких викидів.

#### Припущення та обмеження

**Припущення та переваги:**: DBSCAN не припускає, що кластери є сферичними — він може знаходити кластери довільної форми (навіть ланцюжкоподібні або суміжні кластери). Він автоматично визначає кількість кластерів на основі щільності даних і може ефективно ідентифікувати викиди як шум. Це робить його потужним інструментом для реальних даних із нерегулярними формами та шумом. Він стійкий до викидів (на відміну від K-Means, який примусово розподіляє їх по кластерах). Він добре працює, коли кластери мають приблизно рівномірну щільність.

**Обмеження**: продуктивність DBSCAN залежить від вибору відповідних значень ε і MinPts. Він може мати труднощі з даними зі змінною щільністю — одне значення ε не може одночасно врахувати щільні та розріджені кластери. Якщо ε надто мале, більшість точок буде позначено як шум; якщо надто велике — кластери можуть неправильно об'єднуватися. Також DBSCAN може бути неефективним на дуже великих наборах даних (наївна складність $O(n^2)$, хоча spatial indexing може допомогти). У просторах ознак із високою розмірністю поняття «відстані в межах ε» може стати менш змістовним (прокляття розмірності), тому DBSCAN може потребувати ретельного налаштування параметрів або не знаходити інтуїтивно зрозумілі кластери. Попри це, такі розширення, як HDBSCAN, усувають деякі проблеми (наприклад, змінну щільність).

<details>
<summary>Приклад -- кластеризація із шумом
</summary>
```python
from sklearn.cluster import DBSCAN

# Generate synthetic data: 2 normal clusters and 5 outlier points
cluster1 = rng.normal(loc=[100, 1000], scale=[5, 100], size=(100, 2))
cluster2 = rng.normal(loc=[120, 2000], scale=[5, 100], size=(100, 2))
outliers = rng.uniform(low=[50, 50], high=[180, 3000], size=(5, 2))  # scattered anomalies
data = np.vstack([cluster1, cluster2, outliers])

# Run DBSCAN with chosen eps and MinPts
eps = 15.0   # radius for neighborhood
min_pts = 5  # minimum neighbors to form a dense region
db = DBSCAN(eps=eps, min_samples=min_pts).fit(data)
labels = db.labels_  # cluster labels (-1 for noise)

# Analyze clusters and noise
num_clusters = len(set(labels) - {-1})
num_noise = np.sum(labels == -1)
print(f"DBSCAN found {num_clusters} clusters and {num_noise} noise points")
print("Cluster labels for first 10 points:", labels[:10])
```
У цьому фрагменті ми налаштували `eps` і `min_samples` відповідно до масштабу наших даних (15.0 в одиницях ознак і вимога наявності 5 точок для формування кластера). DBSCAN має знайти 2 кластери (кластери нормального трафіку) і позначити 5 доданих викидів як шум. Ми виводимо кількість кластерів і точок шуму, щоб перевірити це. У реальних умовах можна ітеруватися за ε (використовуючи евристику графіка k-відстаней для вибору ε) і MinPts (часто як орієнтир задається приблизно як розмірність даних + 1), щоб знайти стабільні результати кластеризації. Можливість явно позначати шум допомагає відокремити потенційні attack data для подальшого аналізу.

</details>

### Principal Component Analysis (PCA)

PCA — це техніка **зменшення розмірності**, яка знаходить новий набір ортогональних осей (головних компонентів), що охоплюють максимальну дисперсію в даних. Простими словами, PCA обертає та проєктує дані на нову систему координат так, щоб перша головна компонента (PC1) пояснювала максимально можливу дисперсію, друга компонента (PC2) пояснювала найбільшу дисперсію, ортогональну до PC1, і так далі. Математично PCA обчислює власні вектори коваріаційної матриці даних — ці власні вектори є напрямками головних компонентів, а відповідні власні значення вказують на обсяг дисперсії, пояснений кожною з них. Її часто використовують для виділення ознак, візуалізації та зменшення шуму.

Зверніть увагу, що це корисно, якщо розмірності набору даних містять **значні лінійні залежності або кореляції**.

PCA працює шляхом визначення головних компонентів даних, які є напрямками максимальної дисперсії. Етапи PCA:
1. **Стандартизація**: Центруйте дані, віднявши середнє значення, і масштабуйте їх до одиничної дисперсії.
2. **Коваріаційна матриця**: Обчисліть коваріаційну матрицю стандартизованих даних, щоб зрозуміти взаємозв’язки між ознаками.
3. **Розклад за власними значеннями**: Виконайте розклад коваріаційної матриці за власними значеннями, щоб отримати власні значення та власні вектори.
4. **Вибір головних компонентів**: Відсортуйте власні значення за спаданням і виберіть перші K власних векторів, що відповідають найбільшим власним значенням. Ці власні вектори формують новий простір ознак.
5. **Перетворення даних**: Спроєктуйте початкові дані на новий простір ознак, використовуючи вибрані головні компоненти.
PCA широко використовують для візуалізації даних, зменшення шуму та як етап попередньої обробки для інших алгоритмів машинного навчання. Вона допомагає зменшити розмірність даних, зберігаючи їхню основну структуру.

#### Власні значення та власні вектори

Власне значення — це скаляр, який вказує на обсяг дисперсії, захоплений відповідним власним вектором. Власний вектор представляє напрямок у просторі ознак, уздовж якого дані змінюються найбільше.

Уявімо, що A — квадратна матриця, а v — ненульовий вектор, для якого: `A * v = λ * v`
де:
- A — квадратна матриця, наприклад [ [1, 2], [2, 1]] (наприклад, коваріаційна матриця)
- v — власний вектор (наприклад, [1, 1])

Тоді `A * v = [ [1, 2], [2, 1]] * [1, 1] = [3, 3]`, що буде власним значенням λ, помноженим на власний вектор v, отже власне значення λ = 3.

#### Власні значення та власні вектори в PCA

Пояснімо це на прикладі. Уявімо, що у вас є набір даних із великою кількістю чорно-білих зображень облич розміром 100x100 пікселів. Кожен піксель можна розглядати як ознаку, тому ви маєте 10 000 ознак на зображення (або вектор із 10000 компонентів для кожного зображення). Якщо ви хочете зменшити розмірність цього набору даних за допомогою PCA, потрібно виконати такі кроки:

1. **Стандартизація**: Центруйте дані, віднявши від набору даних середнє значення кожної ознаки (пікселя).
2. **Коваріаційна матриця**: Обчисліть коваріаційну матрицю стандартизованих даних, яка показує, як ознаки (пікселі) змінюються разом.
- Зверніть увагу, що коваріація між двома змінними (у цьому випадку пікселями) показує, наскільки вони змінюються разом, тому мета полягає у визначенні того, які пікселі мають тенденцію збільшуватися або зменшуватися разом у рамках лінійного взаємозв’язку.
- Наприклад, якщо пікселі 1 і 2 мають тенденцію збільшуватися разом, коваріація між ними буде додатною.
- Коваріаційна матриця матиме розмір 10,000x10,000, де кожен елемент представляє коваріацію між двома пікселями.
3. **Розв’язання рівняння власних значень**: Рівняння власних значень, яке потрібно розв’язати, має вигляд `C * v = λ * v`, де C — коваріаційна матриця, v — власний вектор, а λ — власне значення. Його можна розв’язати такими методами:
- **Розклад за власними значеннями**: Виконайте розклад коваріаційної матриці за власними значеннями, щоб отримати власні значення та власні вектори.
- **Singular Value Decomposition (SVD)**: Як альтернативу можна використати SVD для розкладання матриці даних на сингулярні значення та вектори, що також дасть змогу отримати головні компоненти.
4. **Вибір головних компонентів**: Відсортуйте власні значення за спаданням і виберіть перші K власних векторів, що відповідають найбільшим власним значенням. Ці власні вектори представляють напрямки максимальної дисперсії в даних.

> [!TIP]
> *Випадки використання в кібербезпеці:* Поширене застосування PCA у security — зменшення кількості ознак для виявлення аномалій. Наприклад, система виявлення вторгнень із понад 40 мережевими метриками (такими як ознаки NSL-KDD) може використовувати PCA для зведення їх до кількох компонентів, узагальнюючи дані для візуалізації або передавання в алгоритми кластеризації. Аналітики можуть побудувати графік мережевого трафіку в просторі перших двох головних компонентів, щоб побачити, чи відокремлюються attack data від нормального трафіку. PCA також може допомогти усунути надлишкові ознаки (наприклад, кількість надісланих і отриманих байтів, якщо вони корельовані), щоб зробити алгоритми виявлення надійнішими та швидшими.

#### Припущення та обмеження

PCA припускає, що **головні осі дисперсії мають зміст** — це лінійний метод, тому він виявляє лінійні кореляції в даних. Він є unsupervised, оскільки використовує лише коваріацію ознак. Переваги PCA включають зменшення шуму (компоненти з малою дисперсією часто відповідають шуму) та декореляцію ознак. Він є обчислювально ефективним для помірно високих розмірностей і часто використовується як корисний етап попередньої обробки для інших алгоритмів (для зменшення прокляття розмірності). Одне з обмежень полягає в тому, що PCA обмежена лінійними взаємозв’язками — вона не виявляє складну нелінійну структуру (на відміну від autoencoders або t-SNE). Крім того, компоненти PCA може бути складно інтерпретувати через початкові ознаки (вони є комбінаціями початкових ознак). У кібербезпеці потрібно бути обережними: атака, яка спричиняє лише незначну зміну ознаки з малою дисперсією, може не проявитися у провідних PC (оскільки PCA надає пріоритет дисперсії, а не обов’язково «цікавості»).

### Gaussian Mixture Models (GMM)

Gaussian Mixture Model припускає, що дані згенеровані сумішшю **кількох Gaussian (normal) розподілів із невідомими параметрами**. По суті, це probabilistic clustering model: вона намагається м’яко призначити кожну точку одному з K Gaussian-компонентів. Кожен Gaussian-компонент k має вектор середніх значень (μ_k), covariance matrix (Σ_k) і mixing weight (π_k), що відображає поширеність цього кластера. На відміну від K-Means, який виконує «жорстке» призначення, GMM надає кожній точці ймовірність належності до кожного кластера.

Навчання GMM зазвичай виконується за допомогою алгоритму Expectation-Maximization (EM):

- **Initialization**: Почати з початкових припущень щодо середніх значень, коваріацій і коефіцієнтів змішування (або використати результати K-Means як початкову точку).

- **E-step (Expectation)**: За поточними параметрами обчислити responsibility кожного кластера для кожної точки: по суті, `r_nk = P(z_k | x_n)`, де z_k — латентна змінна, що вказує на належність до кластера для точки x_n. Це виконується за допомогою теореми Байєса: обчислюється posterior probability належності кожної точки до кожного кластера на основі поточних параметрів. Responsibility обчислюються так:
```math
r_{nk} = \frac{\pi_k \mathcal{N}(x_n | \mu_k, \Sigma_k)}{\sum_{j=1}^{K} \pi_j \mathcal{N}(x_n | \mu_j, \Sigma_j)}
```
де:
- \( \pi_k \) — mixing coefficient для кластера k (prior probability кластера k),
- \( \mathcal{N}(x_n | \mu_k, \Sigma_k) \) — Gaussian probability density function для точки \( x_n \) за заданих середнього \( \mu_k \) і коваріації \( \Sigma_k \).

- **M-step (Maximization)**: Оновити параметри, використовуючи responsibility, обчислені на E-step:
- Оновити кожне середнє μ_k як weighted average точок, де вагами є responsibility.
- Оновити кожну коваріацію Σ_k як weighted covariance точок, призначених кластеру k.
- Оновити mixing coefficients π_k як average responsibility для кластера k.

- **Iterate** E- і M-steps до збіжності (стабілізації параметрів або зменшення покращення likelihood нижче порогового значення).

Результатом є набір Gaussian-розподілів, які разом моделюють загальний розподіл даних. Ми можемо використовувати навчений GMM для кластеризації, призначаючи кожну точку Gaussian із найвищою ймовірністю, або зберігати ймовірності для оцінювання невизначеності. Також можна оцінювати likelihood нових точок, щоб перевірити, наскільки вони відповідають моделі (це корисно для anomaly detection).

> [!TIP]
> *Use cases in cybersecurity:* GMM можна використовувати для anomaly detection, моделюючи розподіл нормальних даних: будь-яка точка з дуже низькою ймовірністю в межах навченої суміші позначається як аномалія. Наприклад, можна навчити GMM на ознаках легітимного мережевого трафіку; attack connection, яка не схожа на жоден навчений кластер, матиме низький likelihood. GMM також використовуються для кластеризації активностей, де кластери можуть мати різні форми — наприклад, для групування користувачів за профілями поведінки, де ознаки кожного профілю можуть бути подібними до Gaussian-розподілу, але мати власну структуру variance. Інший сценарій: у phishing detection ознаки легітимних email можуть утворювати один Gaussian-кластер, відомий phishing — інший, а нові phishing campaigns можуть проявлятися як окремий Gaussian або як точки з низьким likelihood відносно наявної суміші.

#### Assumptions and Limitations

GMM є узагальненням K-Means, яке враховує covariance, тому кластери можуть бути еліпсоїдними (а не лише сферичними). Якщо covariance є full, модель працює з кластерами різного розміру та форми. Soft clustering є перевагою, коли межі кластерів нечіткі — наприклад, у cybersecurity подія може мати ознаки кількох типів атак; GMM може відобразити цю невизначеність за допомогою ймовірностей. GMM також забезпечує probabilistic density estimation даних, що корисно для виявлення outliers (точок із низьким likelihood для всіх компонентів суміші).

Недоліком є те, що GMM потребує вказати кількість компонентів K (хоча для її вибору можна використовувати такі критерії, як BIC/AIC). EM іноді може повільно збігатися або досягати local optimum, тому initialization має важливе значення (часто EM запускають кілька разів). Якщо дані насправді не відповідають суміші Gaussian-розподілів, модель може погано їм відповідати. Також існує ризик, що один Gaussian стиснеться навколо лише одного outlier (хоча regularization або обмеження мінімальної covariance можуть це пом’якшити).

<summary>Example --  Soft Clustering & Anomaly Scores
</summary>
```python
from sklearn.mixture import GaussianMixture

# Fit a GMM with 3 components to the normal traffic data
gmm = GaussianMixture(n_components=3, covariance_type='full', random_state=0)
gmm.fit(base_data)  # using the 1500 normal data points from PCA example

# Print the learned Gaussian parameters
print("GMM means:\n", gmm.means_)
print("GMM covariance matrices:\n", gmm.covariances_)

# Take a sample attack-like point and evaluate it
sample_attack = np.array([[200, 800]])  # an outlier similar to earlier attack cluster
probs = gmm.predict_proba(sample_attack)
log_likelihood = gmm.score_samples(sample_attack)
print("Cluster membership probabilities for sample attack:", probs)
print("Log-likelihood of sample attack under GMM:", log_likelihood)
```
У цьому коді ми навчаємо GMM із 3 Gaussian на нормальному трафіку (припускаючи, що нам відомі 3 профілі легітимного трафіку). Надруковані середні та коваріації описують ці кластери (наприклад, одне середнє може бути близьким до [50,500], що відповідає центру одного з кластерів тощо). Потім ми тестуємо підозріле з’єднання [duration=200, bytes=800]. `predict_proba` повертає ймовірність належності цієї точки до кожного з 3 кластерів — очікується, що ці ймовірності будуть дуже низькими або сильно зміщеними, оскільки [200,800] розташована далеко від нормальних кластерів. Виводиться загальне значення `score_samples` (log-likelihood); дуже низьке значення вказує, що точка погано відповідає моделі, і позначає її як аномалію. На практиці можна встановити поріг для log-likelihood (або для максимальної ймовірності), щоб визначати, чи є точка достатньо малоймовірною для класифікації як malicious. Таким чином, GMM забезпечує обґрунтований спосіб виявлення аномалій, а також формує soft-кластери, які враховують невизначеність.

### Isolation Forest

**Isolation Forest** — це ensemble algorithm для виявлення аномалій, що ґрунтується на ідеї випадкової ізоляції точок. Принцип полягає в тому, що аномалій мало і вони відрізняються від інших, тому їх легше ізолювати, ніж нормальні точки. Isolation Forest будує багато бінарних isolation trees (випадкових decision trees), які випадково розділяють дані. На кожному вузлі дерева вибирається випадкова feature і випадкове значення split між мінімальним і максимальним значеннями цієї feature для даних у поточному вузлі. Цей split ділить дані на дві гілки. Дерево будується, доки кожна точка не буде ізольована у власному leaf або доки не буде досягнуто максимальної висоти дерева.

Виявлення аномалій виконується шляхом аналізу довжини шляху кожної точки у цих випадкових деревах — кількості split, необхідних для ізоляції точки. Інтуїтивно, аномалії (outliers) зазвичай ізолюються швидше, оскільки випадковий split з більшою ймовірністю відокремить outlier (який розташований у розрідженій області), ніж нормальну точку в щільному кластері. Isolation Forest обчислює anomaly score на основі середньої довжини шляху в усіх деревах: коротший середній шлях → більш аномальна точка. Scores зазвичай нормалізуються до [0,1], де 1 означає дуже ймовірну аномалію.

> [!TIP]
> *Use cases у cybersecurity:* Isolation Forest успішно застосовується для intrusion detection і fraud detection. Наприклад, навчіть Isolation Forest на network traffic logs, які переважно містять нормальну поведінку; forest створюватиме короткі шляхи для нетипового трафіку (наприклад, IP, який використовує незвичний port, або незвичний шаблон розміру пакетів), позначаючи його для перевірки. Оскільки йому не потрібні labeled attacks, він підходить для виявлення невідомих типів атак. Його також можна розгорнути для аналізу user login data, щоб виявляти account takeovers (аномальні час або місце входу швидко ізолюються). В одному з варіантів використання Isolation Forest може захищати enterprise, відстежуючи system metrics і створюючи alert, коли комбінація metrics (CPU, network, file changes) суттєво відрізняється (має короткі isolation paths) від історичних шаблонів.

#### Припущення та обмеження

**Переваги**: Isolation Forest не потребує припущення щодо розподілу; він безпосередньо орієнтований на ізоляцію. Він ефективний для high-dimensional data і великих datasets (лінійна складність $O(n\log n)$ під час побудови forest), оскільки кожне дерево ізолює точки, використовуючи лише підмножину features і splits. Він добре працює з numerical features і може бути швидшим за distance-based methods, складність яких може становити $O(n^2)$. Він також автоматично повертає anomaly score, тому можна встановити threshold для alerts (або використати параметр contamination, щоб автоматично визначити cutoff на основі очікуваної частки аномалій).

**Обмеження**: Через випадковий характер результати можуть дещо відрізнятися між запусками (хоча за достатньо великої кількості дерев ця різниця незначна). Якщо дані містять багато нерелевантних features або аномалії не мають чітких відмінностей за жодною feature, ізоляція може бути неефективною (випадкові splits можуть випадково ізолювати нормальні точки; однак усереднення результатів багатьох дерев зменшує цей ефект). Крім того, Isolation Forest зазвичай припускає, що аномалії становлять невелику меншість (що зазвичай справедливо для cybersecurity scenarios).

<summary>Приклад -- Виявлення Outliers у Network Logs
</summary>

Ми використаємо попередній тестовий dataset (який містить нормальні та деякі attack points) і запустимо Isolation Forest, щоб перевірити, чи зможе він відокремити атаки. Припустімо, що ми очікуємо, що приблизно 15% даних будуть аномальними (для демонстрації).
```python
from sklearn.ensemble import IsolationForest

# Combine normal and attack test data from autoencoder example
X_test_if = test_data  # (120 x 2 array with 100 normal and 20 attack points)
# Train Isolation Forest (unsupervised) on the test set itself for demo (in practice train on known normal)
iso_forest = IsolationForest(n_estimators=100, contamination=0.15, random_state=0)
iso_forest.fit(X_test_if)
# Predict anomalies (-1 for anomaly, 1 for normal)
preds = iso_forest.predict(X_test_if)
anomaly_scores = iso_forest.decision_function(X_test_if)  # the higher, the more normal
print("Isolation Forest predicted labels (first 20):", preds[:20])
print("Number of anomalies detected:", np.sum(preds == -1))
print("Example anomaly scores (lower means more anomalous):", anomaly_scores[:5])
```
У цьому коді ми створюємо екземпляр `IsolationForest` зі 100 деревами та встановлюємо `contamination=0.15` (тобто очікуємо приблизно 15% аномалій; модель встановить поріг оцінки так, щоб приблизно 15% точок були позначені). Ми навчаємо його на `X_test_if`, який містить суміш нормальних точок і точок атак (примітка: зазвичай модель навчають на навчальних даних, а потім використовують `predict` на нових даних, але тут для ілюстрації ми навчаємо й прогнозуємо на одному наборі, щоб безпосередньо спостерігати результати).

У виводі показано передбачені мітки для перших 20 точок (де -1 означає аномалію). Також ми виводимо загальну кількість виявлених аномалій і кілька прикладів оцінок аномальності. Ми очікуємо, що приблизно 18 із 120 точок будуть позначені як -1 (оскільки `contamination` дорівнює 15%). Якщо наші 20 зразків атак справді є найбільш віддаленими від норми, більшість із них має з’явитися серед цих передбачень -1. Оцінка аномальності (`decision function` в Isolation Forest) вища для нормальних точок і нижча (більш негативна) для аномалій — ми виводимо кілька значень, щоб побачити розділення. На практиці можна відсортувати дані за оцінкою, щоб побачити найбільш віддалені від норми точки та дослідити їх. Таким чином, Isolation Forest забезпечує ефективний спосіб перегляду великих обсягів немаркованих security-даних і відбору найбільш нерегулярних екземплярів для аналізу людиною або подальшої автоматизованої перевірки.

### t-SNE (t-Distributed Stochastic Neighbor Embedding)

**t-SNE** — це нелінійна техніка зменшення розмірності, спеціально розроблена для візуалізації багатовимірних даних у 2 або 3 вимірах. Вона перетворює схожість між точками даних на спільні розподіли ймовірностей і намагається зберегти структуру локальних околів у проєкції нижчої розмірності. Простіше кажучи, t-SNE розміщує точки (наприклад) у 2D так, щоб схожі точки в початковому просторі з високою ймовірністю опинилися поруч, а несхожі — далеко одна від одної.

Алгоритм має три основні етапи:

1. **Обчислення попарної близькості у просторі високої розмірності:** Для кожної пари точок t-SNE обчислює ймовірність того, що цю пару буде обрано як сусідів (це робиться шляхом центрування Gaussian-розподілу на кожній точці та вимірювання відстаней — параметр perplexity впливає на ефективну кількість сусідів, що враховуються).
2. **Обчислення попарної близькості у просторі низької розмірності (наприклад, 2D):** Спочатку точки випадково розміщуються у 2D. t-SNE визначає подібну ймовірність для відстаней на цій карті (використовуючи kernel на основі Student t-розподілу, який має важчі хвости, ніж Gaussian, що дає віддаленим точкам більше свободи).
3. **Gradient Descent:** Потім t-SNE ітеративно переміщує точки у 2D, щоб мінімізувати дивергенцію Kullback–Leibler (KL) між розподілом близькості у просторі високої розмірності та розподілом у просторі низької розмірності. Завдяки цьому 2D-розташування якомога краще відображає структуру даних високої розмірності — точки, які були близькими в початковому просторі, притягуються одна до одної, а віддалені точки відштовхуються, доки не буде знайдено баланс.

Результатом часто є візуально змістовний scatter plot, на якому стають помітними кластери даних.

> [!TIP]
> *Випадки використання в cybersecurity:* t-SNE часто використовують для **візуалізації багатовимірних security-даних для аналізу людиною**. Наприклад, у security operations center аналітики можуть взяти набір подій із десятками ознак (номери портів, частоти, кількість байтів тощо) і використати t-SNE для створення 2D-графіка. Атаки можуть утворювати власні кластери або відокремлюватися від нормальних даних на цьому графіку, що спрощує їх виявлення. Метод застосовували до malware-датасетів для виявлення груп malware-сімейств або до даних про network intrusion, де різні типи атак утворюють окремі кластери, допомагаючи подальшому дослідженню. По суті, t-SNE дає змогу побачити структуру cyber-даних, яка інакше була б незрозумілою.

#### Припущення та обмеження

t-SNE чудово підходить для візуального пошуку закономірностей. Він може виявляти кластери, підкластери та викиди, які інші лінійні методи (наприклад, PCA) можуть не виявити. Його використовували в дослідженнях cybersecurity для візуалізації складних даних, таких як профілі поведінки malware або шаблони network traffic. Оскільки він зберігає локальну структуру, t-SNE добре показує природні групування.

Однак t-SNE потребує значних обчислювальних ресурсів (приблизно $O(n^2)$), тому для дуже великих наборів даних може знадобитися sampling. Він також має hyperparameters (perplexity, learning rate, iterations), які можуть впливати на результат — наприклад, різні значення perplexity можуть виявляти кластери на різних масштабах. Графіки t-SNE іноді можуть бути неправильно інтерпретовані — відстані на карті не мають безпосереднього глобального значення (метод зосереджується на локальному оточенні, тому деякі кластери можуть здаватися штучно добре відокремленими). Крім того, t-SNE переважно призначений для візуалізації; він не надає простого способу проєктувати нові точки даних без повторного обчислення і не призначений для використання як preprocessing у predictive modeling (UMAP є альтернативою, яка завдяки вищій швидкості усуває деякі з цих проблем).

<details>
<summary>Приклад -- Візуалізація Network Connections
</summary>

Ми використаємо t-SNE, щоб зменшити багатофакторний набір даних до 2D. Для ілюстрації візьмемо попередні 4D-дані (які містили 3 природні кластери нормального traffic) і додамо кілька аномальних точок. Потім запустимо t-SNE та (концептуально) візуалізуємо результати.
```python
# 1 ─────────────────────────────────────────────────────────────────────
#    Create synthetic 4-D dataset
#      • Three clusters of “normal” traffic (duration, bytes)
#      • Two correlated features: packets & errors
#      • Five outlier points to simulate suspicious traffic
# ──────────────────────────────────────────────────────────────────────
import numpy as np
import matplotlib.pyplot as plt
from sklearn.manifold import TSNE
from sklearn.preprocessing import StandardScaler

rng = np.random.RandomState(42)

# Base (duration, bytes) clusters
normal1 = rng.normal(loc=[50, 500],  scale=[10, 100], size=(500, 2))
normal2 = rng.normal(loc=[60, 1500], scale=[8,  200], size=(500, 2))
normal3 = rng.normal(loc=[70, 3000], scale=[5,  300], size=(500, 2))

base_data = np.vstack([normal1, normal2, normal3])       # (1500, 2)

# Correlated features
packets = base_data[:, 1] / 50 + rng.normal(scale=0.5, size=len(base_data))
errors  = base_data[:, 0] / 10 + rng.normal(scale=0.5, size=len(base_data))

data_4d = np.column_stack([base_data, packets, errors])  # (1500, 4)

# Outlier / attack points
outliers_4d = np.column_stack([
rng.normal(250, 1, size=5),     # extreme duration
rng.normal(1000, 1, size=5),    # moderate bytes
rng.normal(5, 1, size=5),       # very low packets
rng.normal(25, 1, size=5)       # high errors
])

data_viz = np.vstack([data_4d, outliers_4d])             # (1505, 4)

# 2 ─────────────────────────────────────────────────────────────────────
#    Standardize features (recommended for t-SNE)
# ──────────────────────────────────────────────────────────────────────
scaler = StandardScaler()
data_scaled = scaler.fit_transform(data_viz)

# 3 ─────────────────────────────────────────────────────────────────────
#    Run t-SNE to project 4-D → 2-D
# ──────────────────────────────────────────────────────────────────────
tsne = TSNE(
n_components=2,
perplexity=30,
learning_rate='auto',
init='pca',
random_state=0
)
data_2d = tsne.fit_transform(data_scaled)
print("t-SNE output shape:", data_2d.shape)  # (1505, 2)

# 4 ─────────────────────────────────────────────────────────────────────
#    Visualize: normal traffic vs. outliers
# ──────────────────────────────────────────────────────────────────────
plt.figure(figsize=(8, 6))
plt.scatter(
data_2d[:-5, 0], data_2d[:-5, 1],
label="Normal traffic",
alpha=0.6,
s=10
)
plt.scatter(
data_2d[-5:, 0], data_2d[-5:, 1],
label="Outliers / attacks",
alpha=0.9,
s=40,
marker="X",
edgecolor='k'
)

plt.title("t-SNE Projection of Synthetic Network Traffic")
plt.xlabel("t-SNE component 1")
plt.ylabel("t-SNE component 2")
plt.legend()
plt.tight_layout()
plt.show()
```
Тут ми об’єднали наш попередній 4D normal dataset із кількома extreme outliers (у викидів одну ознаку (“duration”) встановлено на дуже високе значення тощо, щоб змоделювати нетиповий патерн). Ми запускаємо t-SNE з типовим значенням perplexity 30. Вихідні дані data_2d мають форму (1505, 2). У цьому тексті ми фактично не будуватимемо графік, але якби ми це зробили, то очікували б побачити, можливо, три щільні кластери, що відповідають 3 normal кластерам, а 5 outliers — як ізольовані точки далеко від цих кластерів. В інтерактивному робочому процесі ми могли б пофарбувати точки відповідно до їхніх міток (normal або належність до певного кластера, чи anomaly), щоб перевірити цю структуру. Навіть без міток аналітик міг би помітити ці 5 точок у порожньому просторі на 2D-графіку та позначити їх для подальшої перевірки. Це демонструє, як t-SNE може бути потужним засобом для візуального виявлення аномалій та аналізу кластерів у даних із cybersecurity, доповнюючи автоматизовані алгоритми, описані вище.

### HDBSCAN (Ієрархічна кластеризація просторових застосунків на основі щільності з шумом)

**HDBSCAN** — це розширення DBSCAN, яке усуває потребу вибирати єдине глобальне значення `eps` і дає змогу відновлювати кластери **різної щільності**, будуючи ієрархію компонентів, поєднаних щільністю, а потім стискаючи її.  Порівняно зі звичайним DBSCAN він зазвичай

* виділяє більш інтуїтивні кластери, коли деякі кластери є щільними, а інші — розрідженими,
* має лише один справжній hyper-parameter (`min_cluster_size`) і прийнятне значення за замовчуванням,
* надає для кожної точки *ймовірність* належності до кластера та **оцінку викиду** (`outlier_scores_`), що надзвичайно зручно для threat-hunting dashboards.<sup>[[1]](#references)</sup>

> [!TIP]
> *Випадки використання в cybersecurity:* HDBSCAN дуже популярний у сучасних threat-hunting pipelines — його часто можна побачити всередині notebook-based hunting playbooks, що постачаються з комерційними XDR suites. Один із практичних рецептів — кластеризувати HTTP beaconing traffic під час IR: user-agent, interval і URI length часто формують кілька щільних груп легітимних software updaters, тоді як C2 beacons залишаються крихітними кластерами низької щільності або чистим шумом.

from sklearn.preprocessing import StandardScaler

# df has features extracted from proxy logs
features = [
"avg_interval",      # seconds between requests

### Міркування щодо надійності та безпеки – Poisoning & Adversarial Attacks (2023-2025)

Останні дослідження показали, що **unsupervised learners *не* захищені від активних атакерів**:

* **Data-poisoning проти anomaly detectors.** Chen *et al.* (IEEE S&P 2024) продемонстрували, що додавання лише 3 % спеціально створеного трафіку може змістити decision boundary Isolation Forest і ECOD так, щоб реальні атаки виглядали нормальними. Автори опублікували open-source PoC (`udo-poison`), який автоматично синтезує poison points.<sup>[[2]](#references)</sup>
* **Backdooring clustering models.** Техніка *BadCME* (BlackHat EU 2023) вбудовує невеликий trigger pattern; щоразу, коли цей trigger з’являється, detector на основі K-Means непомітно розміщує подію всередині “benign” cluster.
* **Evasion of DBSCAN/HDBSCAN.** Академічний pre-print 2025 року від KU Leuven показав, що атакер може створювати beaconing patterns, які навмисно потрапляють у density gaps, фактично ховаючись серед міток *noise*.

Набувають популярності такі mitigation techniques:

1. **Model sanitisation / TRIM.** Перед кожною retraining epoch відкидати 1–2 % точок із найбільшим loss (trimmed maximum likelihood), щоб суттєво ускладнити poisoning.
2. **Consensus ensembling.** Об’єднувати кілька різнорідних detectors (наприклад, Isolation Forest + GMM + ECOD) і створювати alert, якщо будь-яка model flags a point. Дослідження показують, що це збільшує витрати атакера більш ніж у 10 разів.
3. **Distance-based defence for clustering.** Повторно обчислювати clusters із `k` різними random seeds і ігнорувати точки, які постійно переходять між clusters.

### Сучасні Open-Source Інструменти (2024-2025)

* **PyOD 2.x** (випущено в травні 2024 року) додав *ECOD*, *COPOD* і GPU-accelerated *AutoFormer detectors*. Тепер він містить sub-command `benchmark`, який дає змогу порівнювати понад 30 algorithms на вашому dataset за допомогою **одного рядка коду**:
```bash
pyod benchmark --input logs.csv --label attack --n_jobs 8
```
* **Anomalib v1.5** (лютий 2025 року) зосереджений на vision, але також містить generic **PatchCore** implementation – зручно для screenshot-based phishing page detection.
* **scikit-learn 1.5** (листопад 2024 року) нарешті відкриває `score_samples` для *HDBSCAN* через нову обгортку `cluster.HDBSCAN`, тому під час роботи з Python 3.12 вам більше не потрібен external contrib package.

<details>
<summary>Короткий приклад PyOD – ensemble ECOD + Isolation Forest</summary>
```python
from pyod.models import ECOD, IForest
from pyod.utils.data import generate_data, evaluate_print
from pyod.utils.example import visualize

X_train, y_train, X_test, y_test = generate_data(
n_train=5000, n_test=1000, n_features=16,
contamination=0.02, random_state=42)

models = [ECOD(), IForest()]

# majority vote – flag if any model thinks it is anomalous
anomaly_scores = sum(m.fit(X_train).decision_function(X_test) for m in models) / len(models)

evaluate_print("Ensemble", y_test, anomaly_scores)
```
