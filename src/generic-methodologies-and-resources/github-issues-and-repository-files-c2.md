# GitHub Issues και αρχεία αποθετηρίου ως κανάλι C2

{{#include ../banners/hacktricks-training.md}}

Ένα ιδιωτικό αποθετήριο μπορεί να διαχωρίζει την **κατάσταση της συνεδρίας** από τη **μεταφορά payload**: τα issues καταγράφουν κάθε host και την κατάσταση του handshake, ενώ τα αρχεία του αποθετηρίου μεταφέρουν κρυπτογραφημένα δεδομένα και προς τις δύο κατευθύνσεις. Αυτό είναι κάτι περισσότερο από την απλή περιοδική αναζήτηση εντολών στο σώμα ενός issue. Η παρατηρημένη υλοποίηση χρησιμοποιεί ένα GitHub personal access token (PAT) για πρόσβαση και στα δύο API.<sup>[[1]](#references)</sup> Για ένα fine-grained PAT, η δημιουργία ή η ενημέρωση issues απαιτεί δικαίωμα εγγραφής Issues, ενώ η μεταφόρτωση αρχείων απαιτεί δικαίωμα εγγραφής Contents. Ένα classic PAT χρειάζεται αντίθετα το scope `repo`. Όποιος αποκτήσει ένα token με επαρκή δικαιώματα μπορεί να αποκτήσει πρόσβαση στο ίδιο κανάλι.<sup>[[2]](#references)[[3]](#references)</sup>

## Handshake issue και αρχείου

Μία παρατηρημένη ροή εργασίας χρησιμοποιεί ένα σύντομο δεκαεξαδικό host ID και την ακόλουθη μηχανή καταστάσεων. Το ακριβές εύρος ID, οι συμβολοσειρές και τα προθέματα είναι δείκτες του πρωτοκόλλου, όχι απαιτήσεις του GitHub API.<sup>[[1]](#references)</sup>

1. Κατά την εκκίνηση, αναζητήστε ανοιχτά και κλειστά issues με `GET /repos/{owner}/{repo}/issues?state=open` (και `state=closed`) για να βρείτε προηγούμενη κατάσταση συνεδρίας. Δημιουργήστε ένα ανοιχτό issue με τίτλο `1[ID]` και σώμα `hel` χρησιμοποιώντας `POST /repos/{owner}/{repo}/issues`.
2. Διαβάστε ένα αρχείο του αποθετηρίου με όνομα που αρχίζει με `2[ID]`· αυτό παρέχει το δημόσιο κλειδί RSA του server. Δημιουργήστε ένα νέο κλειδί συνεδρίας 16 byte, κρυπτογραφήστε το με RSA και μεταφορτώστε το αποτέλεσμα σε ένα αρχείο με πρόθεμα `1[ID]`.
3. Παράγετε το επόμενο IV κάνοντας XOR στο ενσωματωμένο IV με αυτό το κλειδί συνεδρίας. Για κάθε αρχείο που ανταλλάσσεται, χρησιμοποιήστε το τυχαίο κλειδί 16 byte από το όνομα του αρχείου για να κρυπτογραφήσετε ή να αποκρυπτογραφήσετε το περιεχόμενο με AES. Το πρόθεμα `2` δηλώνει δεδομένα από τον server προς τον host· το πρόθεμα `1` δηλώνει δεδομένα από τον host προς τον server. Έτσι, το όνομα του αρχείου περιέχει πληροφορίες δρομολόγησης και υλικό κλειδιού ανά αρχείο, ενώ το issue περιέχει την κατάσταση.
4. Διαβάστε το επόμενο αρχείο με πρόθεμα `2` και βεβαιωθείτε ότι το αποκρυπτογραφημένο περιεχόμενό του είναι `hel`. Μεταφορτώστε κρυπτογραφημένες πληροφορίες host και, στη συνέχεια, αλλάξτε το σώμα του issue σε `hey` με `PATCH /repos/{owner}/{repo}/issues/{issue_number}`. Μόνο τότε ξεκινήστε την περιοδική αναζήτηση εντολών.

Το Contents API του GitHub διαβάζει ένα αρχείο μέσω `GET /repos/{owner}/{repo}/contents/{path}` και δημιουργεί ή αντικαθιστά ένα μέσω `PUT` σε αυτή τη διαδρομή. Για αρχεία μεγέθους έως 1 MB, η προεπιλεγμένη απόκριση JSON περιλαμβάνει περιεχόμενο κωδικοποιημένο σε Base64· για αρχεία μεγέθους από 1 έως 100 MB απαιτείται ο ακατέργαστος τύπος media για την ανάκτηση του περιεχομένου τους. Το σώμα μεταφόρτωσης χρειάζεται ένα μήνυμα commit και περιεχόμενα αρχείου κωδικοποιημένα σε Base64· για την αντικατάσταση ενός υπάρχοντος αρχείου χρειάζεται επίσης το τρέχον blob SHA του. Αυτές οι λεπτομέρειες του API διαφέρουν από το παραπάνω πρωτόκολλο κρυπτογράφησης.<sup>[[2]](#references)[[3]](#references)</sup>

Σε ένα εξουσιοδοτημένο δοκιμαστικό αποθετήριο, το τμήμα ελέγχου μέσω issue μπορεί να δοκιμαστεί με το REST API (αντικαταστήστε τα στοιχεία με ένα δοκιμαστικό αποθετήριο και ένα δοκιμαστικό PAT). Μην τοποθετείτε ενεργό token στη διεύθυνση URL, στο σώμα issue ή σε αρχείο που θα γίνει commit.<sup>[[2]](#references)</sup>

```bash
base="https://api.github.com/repos/$OWNER/$REPO"
curl -fsS -H "Authorization: Bearer $GH_TOKEN" "$base/issues?state=open"
issue_number=$(curl -fsS -X POST -H "Authorization: Bearer $GH_TOKEN" -H 'Accept: application/vnd.github+json' \
  "$base/issues" -d '{"title":"11000","body":"hel"}' | jq -r .number)
curl -fsS -X PATCH -H "Authorization: Bearer $GH_TOKEN" -H 'Accept: application/vnd.github+json' \
  "$base/issues/$issue_number" -d '{"body":"hey"}'
```

Ο μηχανισμός **δεν** απαιτεί τον τίτλο του issue, τους δείκτες `hel`/`hey` ή τις συγκεκριμένες επιλογές κρυπτογράφησης που εμφανίζονται εδώ· αυτά προσδιορίζουν μία υλοποίηση. Η επαναχρησιμοποιήσιμη ιδέα είναι να διαχωρίζεται η μεταβλητή κατάσταση του host από τα αμφίδρομα κρυπτογραφημένα αντικείμενα και να συνδέονται και τα δύο με ένα host ID.<sup>[[1]](#references)</sup> Για μια άλλη μέθοδο μεταφοράς μέσω GitHub issue, δείτε τις [σημειώσεις για custom listener του AdaptixC2](basic-forensic-methodology/adaptixc2-config-extraction-and-ttps.md#custom-listener-profiles-dont-hard-code-only-the-classic-http-schema). Για μια εναλλακτική λύση μέσω σχολίων issue, η οποία ανανεώνει τα διαπιστευτήρια του repository αντί να μεταφέρει την κατάσταση της συνεδρίας, δείτε τις [Υπηρεσίες ιστού και dead-drop resolvers](../privacy/offensive-infrastructure-and-attribution-evasion.md#web-services-and-dead-drop-resolvers).
