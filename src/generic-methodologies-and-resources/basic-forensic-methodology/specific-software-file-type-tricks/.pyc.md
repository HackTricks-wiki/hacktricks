## コンパイル済みバイナリから .pyc へ

**PyInstaller-built executable**（**ELF** executable を含む）から、埋め込まれた Python modules を次の方法で検査および抽出できます：<sup>[[6]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
**PyInstallerでビルドされた実行ファイル**から、埋め込まれたPythonバイトコードを抽出するには：<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## .pyc から Python code へ

**.pyc** ファイルを入手したら、次のツールで Python source へ逆コンパイルしてみてください:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**必ず**、バイナリに **拡張子** "**.pyc**" が付いていることを確認してください（付いていない場合、uncompyle6 は動作しません）。

**uncompyle6** の実行中に、**次のエラー**が発生することがあります：

### エラー：不明な magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
これを修正するには、そのバイトコードを生成した Python バージョンの magic number を先頭に付加します。

**Python 3.8** のターミナルで、次を実行します:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
Python 3.8 の場合、4バイトのシーケンス **`55 0d 0d 0a`** の後に12個のゼロバイトを付加して、16バイトの **.pyc** ヘッダーを作成します。<sup>[[7]](#references)</sup>

ヘッダーを追加した後、**uncompyle6** を再試行します。<sup>[[1]](#references)</sup>

正しく追加された **.pyc python3.8 magic header** は次のようになります:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### エラー: 一般的なエラーの Decompiling

**その他のエラー**として、`class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>` などが表示されることがあります。

これは、**magic number を正しく追加していない**か、**正しい magic number を使用していない**ことを意味している可能性があります。そのため、**正しいものを使用していることを確認してください**（または新しいものを試してください）。

前述のエラーに関するドキュメントを確認してください。

## Automatic Tool

[**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) は、py2exe または PyInstaller で作成された Python executable の unpacking と decompiling を行うための helper scripts を組み合わせたものです。その YARA rules は Python executable を識別し、これらの packer を区別します。<sup>[[5]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

unpacking によって Python magic bytes のない bytecode file が残された場合は、decompiling の前に tool の prepend option を使用して magic bytes を追加します。<sup>[[1]](#references)[[5]](#references)</sup>

問題の例:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Python アセンブリの解析

逆コンパイルに失敗した場合は、フォールバックとして marshaled code object を逆アセンブルします。バイトコードを生成したバージョンの interpreter を使用してください（Python 2 の **.pyc** ファイルには Python 2）。<sup>[[4]](#references)</sup>

<details>
<summary>.pyc を逆アセンブルする</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'rb') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
```

## PyInstaller raw marshal と Pyarmor v9 の static unpack workflow

以下の workflow は、Pyarmor v9 で保護された PyInstaller raw marshal payloads を対象としています。<sup>[[3]](#references)</sup>

- **埋め込まれた marshal blobs を抽出する**: `pyi-archive_viewer sample.exe` を実行し、raw objects（例: `vvs` という名前のファイル）を export します。PyInstaller は完全な `.pyc` files ではなく、`0xe3`（TYPE_CODE with FLAG_REF）で始まる bare marshal streams を保存します。decompilers が受け入れられるように、正しい **16-byte `.pyc` header**（embedded interpreter version 用の magic + zeroed timestamp/size）を先頭に付加します。Python 3.11.5 の場合は `imp.get_magic().hex()` で magic を取得し、marshal payload の前に `dd`/`printf` で patch できます。
- **version-aware tools で decompile する**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` または PyLingual を使用します。コードの一部だけが必要な場合は、AST（例: `ast.NodeVisitor`）を走査して、特定の arguments/constants を抽出できます。
- **Pyarmor v9 header を parse して crypto parameters を復元する**: `0x00` の signature `PY<license>`、`0x09/0x0a` の Python major/minor、`0x14` の protection-type field（**BCC** 使用時は `0x09`、それ以外は `0x08`）、`0x1c/0x38` の ELF start/end offsets、`0x24..0x27` と `0x2c..0x33` に分割された 12-byte AES-CTR nonce を確認します。同じ pattern は embedded ELF の後にも繰り返されます。
- **Pyarmor-modified code objects を考慮する**: `co_flags` には bit `0x20000000` が設定され、length-prefixed field が追加されています。復号失敗を避けるため、parse 中は CPython の `deopt_code()` を無効化します。
- **encrypted code regions を特定する**: bytecode は `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__` でラップされています。enclosed blob を runtime key（例: `273b1b1373cf25e054a61e2cb8a947b8`）で AES-128-CTR decrypt します。payload-specific 12-byte XOR key（Pyarmor runtime から取得）と、`__pyarmor_exit_*__` marker 内の 12 bytes を XOR して、region ごとの nonce を導出します。復号後には、`__pyarmor_assert_*__`（encrypted strings）や `__pyarmor_bcc_*__`（compiled dispatch targets）も現れることがあります。
- **Pyarmor の “mixed” strings を decrypt する**: `0x81` が prefix の constants は AES-128-CTR encrypted です（plaintext では `0x01` が使用されます）。同じ key と runtime-derived string nonce（例: `692e767673e95c45a1e6876d`）を使用して、長い string constants を復元します。
- **BCC mode を処理する**: Pyarmor の `--enable-bcc` は多くの functions を companion ELF に compile し、Python stubs を残して `__pyarmor_bcc_*__` を call させます。`bcc_info.py` などの tooling でそれらの constants を ELF symbols に map し、報告された offsets（例: `__pyarmor_bcc_58580__` → `bcc_180` at offset `0x4e70`）で ELF を decompile/analyze します。<sup>[[2]](#references)[[3]](#references)[[8]](#references)</sup>


## Python から Executable へ

以下の examples は、py2exe または PyInstaller を使用して Python script を package する方法を示します。<sup>[[1]](#references)</sup>

### py2exe を使用して payload を作成する:

1. [py2exe](http://www.py2exe.org/) を install します。
2. `hello.py` payload を作成し、次のような setup script を使用します。`bundle_files` を `1` に設定すると、Python interpreter が application とともに bundle されます。
3. `python setup.py py2exe` を実行して executable を作成します。
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```
