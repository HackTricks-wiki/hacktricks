## Von kompiliertem Binary zu .pyc

Aus einer **mit PyInstaller erstellten ausführbaren Datei** (einschließlich einer **ELF**-ausführbaren Datei) können eingebettete Python-Module mit folgendem Tool untersucht und extrahiert werden:<sup>[[6]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
Für eine **mit PyInstaller erstellte ausführbare Datei** extrahieren Sie den eingebetteten Python-Bytecode mit:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## Von .pyc zu Python-Code

Sobald du eine **.pyc**-Datei hast, versuche, sie mit folgendem Befehl zurück in Python-Quellcode zu dekompilieren:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Stelle sicher**, dass die Binärdatei die **Erweiterung** "**.pyc**" besitzt (andernfalls wird uncompyle6 nicht funktionieren).

Bei der Ausführung von **uncompyle6** können die **folgenden Fehler** auftreten:

### Fehler: Unbekannte Magic Number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Um dies zu beheben, stelle die Magic Number für die Python-Version voran, die den Bytecode erzeugt hat.

Magic Numbers unterscheiden sich je nach Python-Version. Führe in einem **Python 3.8**-Terminal Folgendes aus:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
Für Python 3.8 stelle die vier Byte umfassende Sequenz **`55 0d 0d 0a`**, gefolgt von 12 Null-Bytes, voran, um den 16-Byte-**.pyc**-Header zu erstellen.<sup>[[7]](#references)</sup>

Führe **uncompyle6** nach dem Hinzufügen des Headers erneut aus.<sup>[[1]](#references)</sup>

So sieht ein korrekt hinzugefügter **.pyc python3.8 magic header** aus:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Fehler: Allgemeine Fehler beim Dekompilieren

**Andere Fehler** wie: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>` können auftreten.

Das bedeutet wahrscheinlich, dass du die Magic Number **nicht korrekt hinzugefügt** oder nicht die **richtige Magic Number verwendet** hast. Stelle daher **sicher, dass du die richtige verwendest** (oder versuche eine neue).

Siehe die Dokumentation zum vorherigen Fehler.

## Automatisches Tool

Das [**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) kombiniert Hilfsskripte zum Entpacken und Dekompilieren von Python-Executables, die mit py2exe oder PyInstaller erstellt wurden. Seine YARA-Regeln identifizieren Python-Executables und unterscheiden diese Packer.<sup>[[5]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

Wenn beim Entpacken eine Bytecode-Datei ohne ihre Python-Magic-Bytes zurückbleibt, verwende die prepend-Option des Tools, um sie vor dem Dekompilieren hinzuzufügen.<sup>[[1]](#references)[[5]](#references)</sup>

Beispiel für das Problem:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Python-Assembly analysieren

Wenn die Dekompilierung fehlschlägt, disassembliere als Fallback das gemarshallte Codeobjekt. Verwende die Interpreter-Version, die den Bytecode erzeugt hat (Python 2 für Python-2-**.pyc**-Dateien).<sup>[[4]](#references)</sup>

<details>
<summary>Eine .pyc disassemblieren</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'rb') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)
3 MAKE_FUNCTION            0
6 STORE_NAME               0 (hello_world)
9 LOAD_CONST               1 (None)
12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])
2           0 LOAD_CONST               1 ('Hello  {0}')
3 LOAD_ATTR                0 (format)
6 LOAD_FAST                0 (name)
9 CALL_FUNCTION            1
12 PRINT_ITEM
13 PRINT_NEWLINE
14 LOAD_CONST               0 (None)
17 RETURN_VALUE
```

## Statischer Unpack-Workflow für rohe marshal-Daten und Pyarmor v9 in PyInstaller

Der folgende Workflow zielt auf rohe PyInstaller-marshal-Payloads ab, die mit Pyarmor v9 geschützt sind.<sup>[[3]](#references)</sup>

- **Eingebettete marshal-Blobs extrahieren**: `pyi-archive_viewer sample.exe` ausführen und rohe Objekte exportieren (z. B. eine Datei namens `vvs`). PyInstaller speichert reine marshal-Streams, die mit `0xe3` (TYPE_CODE mit FLAG_REF) beginnen, statt vollständiger `.pyc`-Dateien. Den korrekten **16-Byte-`.pyc`-Header** (Magic für die Version des eingebetteten Interpreters sowie auf null gesetzter Zeitstempel/Größe) voranstellen, damit Decompiler sie akzeptieren. Für Python 3.11.5 kann die Magic mit `imp.get_magic().hex()` ausgelesen und vor dem marshal-Payload mit `dd`/`printf` eingefügt werden.
- **Mit versionsabhängigen Tools decompilieren**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` oder PyLingual verwenden. Wenn nur ein Teil des Codes benötigt wird, kann der AST durchlaufen werden (z. B. mit `ast.NodeVisitor`), um bestimmte Argumente/Konstanten zu extrahieren.
- **Den Pyarmor-v9-Header parsen**, um die Krypto-Parameter wiederherzustellen: Signatur `PY<license>` bei `0x00`, Python-Major/Minor-Version bei `0x09/0x0a`, das Feld für den Protection-Typ bei `0x14` (`0x09` mit **BCC**, andernfalls `0x08`), ELF-Start-/End-Offsets bei `0x1c/0x38` sowie die über `0x24..0x27` und `0x2c..0x33` verteilte 12-Byte-AES-CTR-Nonce. Dasselbe Muster wiederholt sich nach dem eingebetteten ELF.
- **Pyarmor-modifizierte Code-Objekte berücksichtigen**: `co_flags` hat das gesetzte Bit `0x20000000` sowie ein zusätzliches längenpräfixiertes Feld. `deopt_code()` von CPython beim Parsen deaktivieren, um Entschlüsselungsfehler zu vermeiden.
- **Verschlüsselte Codebereiche identifizieren**: Bytecode wird von `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__` umschlossen. Den eingeschlossenen Blob mit AES-128-CTR und dem Runtime-Key (z. B. `273b1b1373cf25e054a61e2cb8a947b8`) entschlüsseln. Die regionsspezifische Nonce durch XOR-Verknüpfung des payload-spezifischen 12-Byte-XOR-Schlüssels (aus der Pyarmor-Runtime) mit den 12 Bytes im Marker `__pyarmor_exit_*__` ableiten. Nach der Entschlüsselung können außerdem `__pyarmor_assert_*__` (verschlüsselte Strings) und `__pyarmor_bcc_*__` (kompilierte Dispatch-Ziele) auftreten.
- **Pyarmors „mixed“-Strings entschlüsseln**: Konstanten mit dem Präfix `0x81` sind AES-128-CTR-verschlüsselt (Klartext verwendet `0x01`). Denselben Schlüssel und die aus der Runtime abgeleitete String-Nonce (z. B. `692e767673e95c45a1e6876d`) verwenden, um lange String-Konstanten wiederherzustellen.
- **BCC-Modus behandeln**: Pyarmor `--enable-bcc` kompiliert viele Funktionen in ein Companion-ELF und hinterlässt Python-Stubs, die `__pyarmor_bcc_*__` aufrufen. Diese Konstanten mit Tools wie `bcc_info.py` ELF-Symbolen zuordnen und anschließend das ELF an den angegebenen Offsets decompilieren/analysieren (z. B. `__pyarmor_bcc_58580__` → `bcc_180` am Offset `0x4e70`).<sup>[[2]](#references)[[3]](#references)[[8]](#references)</sup>


## Python zu einer ausführbaren Datei

Diese Beispiele zeigen, wie ein Python-Skript mit py2exe oder PyInstaller paketiert wird.<sup>[[1]](#references)</sup>

### Eine Payload mit py2exe erstellen:

1. [py2exe](http://www.py2exe.org/) installieren.
2. Eine `hello.py`-Payload erstellen und ein Setup-Skript wie das folgende verwenden. Wenn `bundle_files` auf `1` gesetzt wird, wird der Python-Interpreter zusammen mit der Anwendung gebündelt.
3. `python setup.py py2exe` ausführen, um die ausführbare Datei zu erstellen.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```
