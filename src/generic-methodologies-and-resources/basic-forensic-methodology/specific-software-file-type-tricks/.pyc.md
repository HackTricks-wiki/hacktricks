```bash
(15535, 2514, 4421, 1, 's', 'binary_name'),

? X binary_name
to filename? /tmp/binary.pyc
```
En un binario **python exe** compilado puedes **obtener el .pyc** ejecutando:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## De .pyc a código python

Para los datos **.pyc** (python **"compilado"**), deberías empezar intentando **extraer** el **código** **python** **original**:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Asegúrate** de que el binario tenga la **extensión** "**.pyc**" (si no, uncompyle6 no funcionará)

Al ejecutar **uncompyle6**, podrías encontrar los **siguientes errores**:

### Error: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Para solucionar esto, necesitas **añadir el magic number correcto** al principio del archivo generado.

**Los magic numbers varían según la versión de Python**; para obtener el magic number de **Python 3.8**, necesitas **abrir una terminal de Python 3.8** y ejecutar:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
El **magic number** en este caso para python3.8 es **`0x550d0d0a`**; después, para corregir este error, deberás **añadir** al **principio** del **archivo .pyc** los siguientes bytes: `0x0d550a0d000000000000000000000000`

**Una vez** que hayas **añadido** ese magic header, el **error debería estar corregido.**

Así es como se verá un **magic header .pyc de python3.8** añadido correctamente:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Error: Errores genéricos al decompilar

Pueden aparecer **otros errores**, como: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>`.

Probablemente significa que **no has añadido correctamente** el magic number o que no has **usado** el **magic number correcto**, así que **asegúrate de usar el correcto** (o prueba con uno nuevo).

Consulta la documentación del error anterior.

## Herramienta automática

La [**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) combina varias herramientas disponibles en la comunidad diseñadas para ayudar a los investigadores a desempaquetar y decompilar ejecutables escritos en Python, específicamente los creados con py2exe y pyinstaller. Incluye reglas YARA para identificar si un ejecutable está basado en Python y confirmar la herramienta utilizada para crearlo.<sup>[[4]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

Un problema común consiste en un archivo de bytecode de Python incompleto como resultado del **proceso de desempaquetado con unpy2exe o pyinstxtractor**, que después **no puede ser reconocido por uncompyle6 debido a la ausencia del número de versión del bytecode de Python**. Para solucionarlo, se ha añadido una opción prepend que agrega el número de versión del bytecode de Python necesario, facilitando el proceso de decompilación.<sup>[[4]](#references)</sup>

Ejemplo del problema:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Analizando el assembly de Python

Si no pudiste extraer el código "original" de Python siguiendo los pasos anteriores, puedes intentar **extraer** el **assembly** (pero **no es muy descriptivo**, así que **intenta** extraer **de nuevo** el código original). En [here](https://bits.theorem.co/protecting-a-python-codebase/) encontré un código muy sencillo para **desensamblar** el binario _.pyc_ (buena suerte entendiendo el flujo del código).<sup>[[3]](#references)</sup> Si el _.pyc_ proviene de Python 2, usa Python 2:

<details>
<summary>Desensamblar un .pyc</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'r') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)
3 MAKE_FUNCTION            0
6 STORE_NAME               0 (hello_world)
9 LOAD_CONST               1 (None)
12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])
2           0 LOAD_CONST               1 ('Hello  {0}')
3 LOAD_ATTR                0 (format)
6 LOAD_FAST                0 (name)
9 CALL_FUNCTION            1
12 PRINT_ITEM
13 PRINT_NEWLINE
14 LOAD_CONST               0 (None)
17 RETURN_VALUE
```

## Flujo de trabajo de static unpack de PyInstaller raw marshal y Pyarmor v9

- **Extract embedded marshal blobs**: `pyi-archive_viewer sample.exe` y exporta los objetos raw (por ejemplo, un archivo llamado `vvs`). PyInstaller almacena streams marshal sin formato que empiezan por `0xe3` (TYPE_CODE con FLAG_REF) en lugar de archivos `.pyc` completos. Anteponles el **header de 16 bytes de `.pyc`** correcto (magic de la versión del intérprete embedded + timestamp/tamaño puestos a cero) para que los decompilers los acepten. Para Python 3.11.5 puedes obtener el magic mediante `imp.get_magic().hex()` y modificarlo con `dd`/`printf` antes del payload marshal.<sup>[[2]](#references)</sup>
- **Decompile with version-aware tools**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` o PyLingual. Si solo necesitas parte del código, puedes recorrer el AST (por ejemplo, `ast.NodeVisitor`) para extraer argumentos/constantes específicos.
- **Parse the Pyarmor v9 header** para recuperar los parámetros criptográficos: signature `PY<license>` en `0x00`, Python major/minor en `0x09/0x0a`, protection type `0x09` cuando **BCC** está habilitado (`0x08` en caso contrario), offsets de inicio/final del ELF en `0x1c/0x38`, y el nonce AES-CTR de 12 bytes dividido entre `0x24..0x27` y `0x2c..0x33`. El mismo patrón se repite después del ELF embedded.
- **Account for Pyarmor-modified code objects**: `co_flags` tiene establecido el bit `0x20000000` y un campo adicional con longitud prefijada. Deshabilita `deopt_code()` de CPython durante el parsing para evitar fallos de descifrado.
- **Identify encrypted code regions**: el bytecode está envuelto por `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__`. Descifra el blob incluido con AES-128-CTR usando la runtime key (por ejemplo, `273b1b1373cf25e054a61e2cb8a947b8`). Deriva el nonce específico de cada región haciendo XOR entre la clave XOR de 12 bytes específica del payload (obtenida del runtime de Pyarmor) y los 12 bytes del marcador `__pyarmor_exit_*__`. Después del descifrado, también puedes encontrar `__pyarmor_assert_*__` (encrypted strings) y `__pyarmor_bcc_*__` (compiled dispatch targets).
- **Decrypt Pyarmor “mixed” strings**: las constantes con prefijo `0x81` están encrypted con AES-128-CTR (el plaintext usa `0x01`). Usa la misma key y el string nonce derivado del runtime (por ejemplo, `692e767673e95c45a1e6876d`) para recuperar las constantes de string largas.
- **Handle BCC mode**: Pyarmor `--enable-bcc` compila muchas funciones en un ELF companion y deja Python stubs que llaman a `__pyarmor_bcc_*__`. Asocia esas constantes con los símbolos del ELF mediante herramientas como `bcc_info.py`; después, decompile/analiza el ELF en los offsets indicados (por ejemplo, `__pyarmor_bcc_58580__` → `bcc_180` en el offset `0x4e70`).


## Python a ejecutable

Para empezar, mostraremos cómo se pueden compilar payloads con py2exe y PyInstaller.<sup>[[1]](#references)</sup>

### Para crear un payload usando py2exe:

1. Instala el paquete py2exe desde [http://www.py2exe.org/](http://www.py2exe.org)
2. Para el payload (en este caso, lo llamaremos hello.py), utiliza un script como el de la Figura 1. La opción “bundle_files” con el valor 1 empaquetará todo, incluido el intérprete de Python, en un solo exe.
3. Cuando el script esté listo, ejecutaremos el comando “python setup.py py2exe”. Esto creará el ejecutable, como se muestra en la Figura 2.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```

### Para crear un payload usando PyInstaller:

1. Instala PyInstaller usando pip (`pip install pyinstaller`).
2. Después, ejecutaremos el comando `“pyinstaller –onefile hello.py”` (recuerda que `‘hello.py’` es nuestro payload). Esto agrupará todo en un único ejecutable.
