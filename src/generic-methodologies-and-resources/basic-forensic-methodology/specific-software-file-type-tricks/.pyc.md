## コンパイル済みバイナリから .pyc へ

**ELF** コンパイル済みバイナリから、以下で **.pyc** を取得できます：<sup>[[1]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
**python exe binary** をコンパイルしたものでは、次を実行して **.pyc** を取得できます:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## .pyc から python code へ

**.pyc** データ（「コンパイル済み」python）については、まず **元の** **python** **code** の **extract** を試みるべきです：<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**必ず**バイナリに**拡張子**「**.pyc**」が付いていることを確認してください（付いていない場合、uncompyle6 は動作しません）。

**uncompyle6**の実行中に、**次のエラー**が発生することがあります。

### エラー: 不明なマジックナンバー 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
これを修正するには、生成されたファイルの先頭に**正しいマジックナンバー**を**追加**する必要があります。

**マジックナンバーは Python のバージョンによって異なる**ため、**Python 3.8**のマジックナンバーを取得するには、**Python 3.8**のターミナルを開き、次を実行します。
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
この場合の **magic number** は python3.8 では **`0x550d0d0a`** です。このエラーを修正するには、**.pyc file** の**先頭**に次の bytes を**追加**する必要があります: `0x0d550a0d000000000000000000000000`

この magic header を**追加すると**、**エラーは修正されます。**

正しく追加された **.pyc python3.8 magic header** は次のようになります:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Error: Decompiling generic errors

`class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>` のような **その他のエラー** が発生する場合があります。

これは、magic number を**正しく追加していない**か、**正しい magic number を使用していない**ことを意味している可能性があります。そのため、**正しいものを使用していることを確認してください**（または新しいものを試してください）。

前述のエラーのドキュメントを確認してください。

## Automatic Tool

[**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) は、Python で記述された実行ファイル、特に py2exe と pyinstaller で作成されたものの unpacking と decompiling を支援する、コミュニティで利用可能な複数のツールを組み合わせたものです。実行ファイルが Python ベースかどうかを識別し、作成に使用された tool を確認するための YARA rules が含まれています。<sup>[[4]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

よくある問題として、**unpacking process with unpy2exe or pyinstxtractor** の結果、Python bytecode file が不完全になり、Python bytecode version number が欠落しているため uncompyle6 で認識されないことがあります。これに対処するため、必要な Python bytecode version number を先頭に追加する prepend option が追加されており、decompiling process を可能にします。<sup>[[4]](#references)</sup>

問題の例:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Python assemblyの解析

前の手順でPythonの「original」コードを抽出できなかった場合は、**assembly**を**抽出**してみてください（ただし、**あまり説明的ではない**ため、**original**コードの抽出をもう一度**試して**ください）。[こちら](https://bits.theorem.co/protecting-a-python-codebase/)で、_.pyc_バイナリを**disassemble**する非常にシンプルなコードを見つけました（コードのフローを理解できるよう、幸運を祈ります）。<sup>[[3]](#references)</sup> _.pyc_がPython 2のものである場合は、python2を使用してください。

## PyInstaller raw marshal & Pyarmor v9 static unpack workflow

- **埋め込まれた marshal blob の抽出**: `pyi-archive_viewer sample.exe` を実行し、raw object（例: `vvs` という名前のファイル）をエクスポートします。PyInstaller は完全な `.pyc` ファイルではなく、`0xe3`（FLAG_REF 付きの TYPE_CODE）で始まる bare marshal stream を保存します。decompiler が受け入れられるように、正しい **16-byte `.pyc` header**（埋め込みインタープリターのバージョンに対応する magic + timestamp/size をゼロ化）を先頭に付加します。Python 3.11.5 では `imp.get_magic().hex()` で magic を取得し、`dd`/`printf` を使って marshal payload の前に追加できます。<sup>[[2]](#references)</sup>
- **バージョン対応ツールで Decompile**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` または PyLingual を使用します。コードの一部だけが必要な場合は、AST（例: `ast.NodeVisitor`）を走査して、特定の引数や定数を抽出できます。
- **Pyarmor v9 header の解析による crypto parameter の復元**: `0x00` の signature `PY<license>`、`0x09/0x0a` の Python major/minor、**BCC** が有効な場合は `0x09`（それ以外は `0x08>`）の protection type、`0x1c/0x38` の ELF start/end offset、さらに `0x24..0x27` と `0x2c..0x33` に分割された 12-byte AES-CTR nonce を復元します。同じパターンは埋め込まれた ELF の後にも繰り返されます。
- **Pyarmor によって変更された code object への対応**: `co_flags` には bit `0x20000000` が設定され、追加の length-prefixed field も存在します。復号失敗を避けるため、解析中は CPython の `deopt_code()` を無効化します。
- **暗号化された code region の特定**: bytecode は `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__` によってラップされています。runtime key（例: `273b1b1373cf25e054a61e2cb8a947b8`）を使い、AES-128-CTR で囲まれた blob を復号します。各 region の nonce は、payload 固有の 12-byte XOR key（Pyarmor runtime から取得）と `__pyarmor_exit_*__` marker 内の 12 bytes を XOR して導出します。復号後には、`__pyarmor_assert_*__`（暗号化された strings）や `__pyarmor_bcc_*__`（compiled dispatch targets）も現れる場合があります。
- **Pyarmor “mixed” strings の復号**: `0x81` が prefix の constants は AES-128-CTR で暗号化されています（plaintext では `0x01` が使用されます）。同じ key と runtime から導出した string nonce（例: `692e767673e95c45a1e6876d`）を使用して、長い string constants を復元します。
- **BCC mode の処理**: Pyarmor の `--enable-bcc` は多くの functions を companion ELF に compile し、`__pyarmor_bcc_*__` を呼び出す Python stub を残します。`bcc_info.py` などの tooling を使ってこれらの constants を ELF symbols に対応付け、その後、報告された offset（例: `__pyarmor_bcc_58580__` → `bcc_180` at offset `0x4e70`）にある ELF を decompile/analyze します。


## Python to Executable

ここではまず、payload を py2exe と PyInstaller で compile する方法を説明します。<sup>[[1]](#references)</sup>

### To create a payload using py2exe:

1. [http://www.py2exe.org/](http://www.py2exe.org) から py2exe package を install します。
2. payload（この場合は `hello.py` という名前にします）には、Figure 1 のような script を使用します。値が 1 の “bundle_files” option により、Python interpreter を含むすべてのものが 1 つの exe に bundle されます。
3. script の準備ができたら、“python setup.py py2exe” command を実行します。これにより、Figure 2 のように executable が作成されます。
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```

### PyInstallerを使用してpayloadを作成するには：

1. pipを使用してPyInstallerをインストールします（pip install pyinstaller）。
2. その後、コマンド「pyinstaller –onefile hello.py」を実行します（「hello.py」がpayloadであることに注意してください）。これにより、すべての内容が1つの実行可能ファイルにまとめられます。
