## Od skompilowanego pliku binarnego do .pyc

Ze skompilowanego pliku binarnego **ELF** można **uzyskać plik .pyc** za pomocą:<sup>[[1]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
W skompilowanym **python exe binary** można **uzyskać plik .pyc**, uruchamiając:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## Od .pyc do kodu Python

Dla danych **.pyc** („skompilowanego” Pythona) należy rozpocząć próbę **wyodrębnienia** **oryginalnego** **kodu** **Python**:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Upewnij się**, że plik binarny ma **rozszerzenie** "**.pyc**" (w przeciwnym razie uncompyle6 nie zadziała)

Podczas uruchamiania **uncompyle6** mogą wystąpić **następujące błędy**:

### Błąd: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Aby to naprawić, musisz **dodać prawidłową liczbę magiczną** na początku wygenerowanego pliku.

**Liczby magiczne różnią się w zależności od wersji Pythona**. Aby uzyskać liczbę magiczną dla **python 3.8**, musisz **otworzyć terminal python 3.8** i wykonać:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
**magic number** w tym przypadku dla python3.8 to **`0x550d0d0a`**, następnie, aby naprawić ten błąd, należy **dodać** na **początku** **pliku .pyc** następujące bajty: `0x0d550a0d000000000000000000000000`

**Po** dodaniu tego magic header **błąd powinien zostać naprawiony.**

Tak będzie wyglądać poprawnie dodany **magic header .pyc python3.8**:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Błąd: ogólne błędy dekompilacji

Mogą pojawić się **inne błędy**, takie jak: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>`.

Prawdopodobnie oznacza to, że **nie dodano poprawnie** liczby magicznej lub że **nie użyto** **właściwej liczby magicznej**, dlatego upewnij się, że używasz właściwej (lub spróbuj innej).

Sprawdź dokumentację poprzedniego błędu.

## Automatic Tool

Narzędzie [**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) stanowi połączenie kilku dostępnych w społeczności tools zaprojektowanych do pomagania badaczom w unpackingu i dekompilacji plików wykonywalnych napisanych w Pythonie, w szczególności utworzonych za pomocą py2exe i pyinstaller. Zawiera reguły YARA pozwalające określić, czy plik wykonywalny jest oparty na Pythonie, oraz potwierdzić użyte narzędzie do jego utworzenia.<sup>[[4]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

Częsty problem dotyczy niekompletnego pliku Python bytecode powstałego w wyniku **unpackingu za pomocą unpy2exe lub pyinstxtractor**, który następnie **nie zostaje rozpoznany przez uncompyle6 z powodu braku numeru wersji Python bytecode**. Aby temu zaradzić, dodano opcję prepend, która dołącza wymagany numer wersji Python bytecode, ułatwiając proces dekompilacji.<sup>[[4]](#references)</sup>

Przykład tego problemu:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Analizowanie python assembly

Jeśli nie udało Ci się wyodrębnić „oryginalnego” kodu python zgodnie z poprzednimi krokami, możesz spróbować **wyodrębnić** **assembly** (ale **nie jest ono zbyt opisowe**, więc **spróbuj** ponownie wyodrębnić oryginalny kod). [Tutaj](https://bits.theorem.co/protecting-a-python-codebase/) znalazłem bardzo prosty kod do **disassemble** binarnego pliku _.pyc_ (powodzenia w zrozumieniu przepływu kodu).<sup>[[3]](#references)</sup> Jeśli _.pyc_ pochodzi z python2, użyj python2:

<details>
<summary>Disassemble a .pyc</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'r') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)
3 MAKE_FUNCTION            0
6 STORE_NAME               0 (hello_world)

12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])

```

## Surowy marshal PyInstaller i statyczny workflow unpackowania Pyarmor v9

- **Extract embedded marshal blobs**: `pyi-archive_viewer sample.exe` i wyeksportuj raw objects (np. plik o nazwie `vvs`). PyInstaller przechowuje same strumienie marshal, które zaczynają się od `0xe3` (TYPE_CODE z FLAG_REF), zamiast pełnych plików `.pyc`. Dodaj poprawny **16-bajtowy nagłówek `.pyc`** (magic dla wersji embedded interpretera + wyzerowany timestamp/size), aby decompilers je zaakceptowały. W Python 3.11.5 możesz pobrać magic za pomocą `imp.get_magic().hex()` i zmodyfikować je przy użyciu `dd`/`printf` przed payloadem marshal.<sup>[[2]](#references)</sup>
- **Decompile with version-aware tools**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` lub PyLingual. Jeśli potrzebny jest tylko fragment kodu, możesz przejść po AST (np. za pomocą `ast.NodeVisitor`), aby wyciągnąć określone arguments/constants.
- **Parse the Pyarmor v9 header** to recover crypto parameters: sygnatura `PY<license>` pod `0x00`, Python major/minor pod `0x09/0x0a`, protection type `0x09`, gdy włączone jest **BCC** (`0x08` w przeciwnym razie), offsets początku/końca ELF pod `0x1c/0x38` oraz 12-bajtowy nonce AES-CTR podzielony między `0x24..0x27` i `0x2c..0x33`. Ten sam pattern powtarza się za embedded ELF.
- **Account for Pyarmor-modified code objects**: `co_flags` ma ustawiony bit `0x20000000` oraz dodatkowe pole z length prefix. Wyłącz CPython `deopt_code()` podczas parsowania, aby uniknąć błędów deszyfrowania.
- **Identify encrypted code regions**: bytecode jest opakowany przez `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__`. Odszyfruj enclosed blob za pomocą AES-128-CTR, używając runtime key (np. `273b1b1373cf25e054a61e2cb8a947b8`). Wyprowadź nonce dla każdego regionu przez wykonanie XOR payload-specific 12-byte XOR key (z Pyarmor runtime) z 12 bajtami w markerze `__pyarmor_exit_*__`. Po deszyfrowaniu możesz również zobaczyć `__pyarmor_assert_*__` (encrypted strings) oraz `__pyarmor_bcc_*__` (compiled dispatch targets).
- **Decrypt Pyarmor “mixed” strings**: constants z prefiksem `0x81` są zaszyfrowane za pomocą AES-128-CTR (plaintext używa `0x01`). Użyj tego samego key oraz runtime-derived string nonce (np. `692e767673e95c45a1e6876d`), aby odzyskać długie string constants.
- **Handle BCC mode**: Pyarmor `--enable-bcc` kompiluje wiele functions do companion ELF i pozostawia Python stubs, które wywołują `__pyarmor_bcc_*__`. Zmapuj te constants do ELF symbols za pomocą narzędzi takich jak `bcc_info.py`, a następnie wykonaj decompile/analyze ELF pod zgłoszonymi offsets (np. `__pyarmor_bcc_58580__` → `bcc_180` pod offsetem `0x4e70`).


## Python do Executable

Na początek pokażemy, jak payloads mogą być kompilowane za pomocą py2exe i PyInstaller.<sup>[[1]](#references)</sup>

### Aby utworzyć payload za pomocą py2exe:

1. Zainstaluj pakiet py2exe ze strony [http://www.py2exe.org/](http://www.py2exe.org)
2. Dla payload (w tym przypadku nazwiemy go hello.py) użyj skryptu takiego jak ten na Rysunku 1. Opcja „bundle_files” z wartością 1 spakuje wszystko, włącznie z Python interpreterem, do jednego exe.
3. Gdy skrypt będzie gotowy, wykonaj polecenie „python setup.py py2exe”. Utworzy ono executable, tak jak pokazano na Rysunku 2.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```

### Aby utworzyć payload przy użyciu PyInstaller:

1. Zainstaluj PyInstaller za pomocą pip (`pip install pyinstaller`).
2. Następnie wydaj polecenie „pyinstaller –onefile hello.py” (przypomnienie: „hello.py” to nasz payload). Spowoduje to spakowanie wszystkiego do jednego pliku wykonywalnego.
