## 컴파일된 바이너리에서 .pyc로

**PyInstaller-built executable**( **ELF** executable 포함)에서 다음을 사용하여 내장된 Python 모듈을 검사하고 추출할 수 있습니다:<sup>[[6]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
**PyInstaller로 빌드된 실행 파일**의 내장 Python bytecode를 다음과 같이 추출합니다:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## .pyc에서 Python 코드로

**.pyc** 파일이 있다면 다음을 사용해 Python 소스 코드로 다시 디컴파일해 보세요:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**반드시** binary에 **extension** "**.pyc**"가 있는지 확인하세요 (그렇지 않으면 uncompyle6이 작동하지 않습니다)

**uncompyle6**을 실행하는 동안 다음 **오류**가 발생할 수 있습니다:

### 오류: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
이를 수정하려면 해당 바이트코드를 생성한 Python 버전의 매직 넘버를 앞에 추가합니다.

**Python 3.8** 터미널에서 다음을 실행합니다:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
Python 3.8의 경우, 4바이트 시퀀스 **`55 0d 0d 0a`** 뒤에 0바이트 12개를 추가하여 16바이트 **.pyc** 헤더를 생성합니다.<sup>[[7]](#references)</sup>

헤더를 추가한 후 **uncompyle6**을 다시 시도합니다.<sup>[[1]](#references)</sup>

올바르게 추가된 **.pyc python3.8 magic header**는 다음과 같이 표시됩니다:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### 오류: 일반적인 Decompiling 오류

`class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>`와 같은 **다른 오류**도 나타날 수 있습니다.

이는 **magic number를 올바르게 추가하지 않았거나**, **올바른 magic number를 사용하지 않았다는** 의미일 가능성이 높으므로, **올바른 것을 사용하는지 확인하세요** (또는 새 magic number를 시도하세요).

이전 오류 문서를 확인하세요.

## Automatic Tool

[**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker)은 py2exe 또는 PyInstaller로 생성된 Python 실행 파일을 unpacking 및 decompiling하기 위한 helper scripts를 결합합니다. 이 도구의 YARA rules는 Python 실행 파일을 식별하고 해당 packer를 구분합니다.<sup>[[5]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

unpacking 후 Python magic bytes가 없는 bytecode file이 남는 경우, decompiling 전에 tool의 prepend option을 사용하여 magic bytes를 추가하세요.<sup>[[1]](#references)[[5]](#references)</sup>

문제의 예시는 다음과 같습니다:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Python assembly 분석

decompilation에 실패하면 대안으로 marshaled code object를 disassemble합니다. bytecode를 생성한 interpreter 버전을 사용해야 합니다(Python 2 **.pyc** 파일에는 Python 2).<sup>[[4]](#references)</sup>

<details>
<summary>.pyc disassemble</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'rb') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)
3 MAKE_FUNCTION            0
6 STORE_NAME               0 (hello_world)
9 LOAD_CONST               1 (None)
12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])
2           0 LOAD_CONST               1 ('Hello  {0}')
3 LOAD_ATTR                0 (format)
6 LOAD_FAST                0 (name)
9 CALL_FUNCTION            1
12 PRINT_ITEM
13 PRINT_NEWLINE
14 LOAD_CONST               0 (None)
17 RETURN_VALUE
```
</details>

## PyInstaller raw marshal 및 Pyarmor v9 static unpack workflow

다음 workflow는 Pyarmor v9로 보호된 PyInstaller raw marshal payload를 대상으로 합니다.<sup>[[3]](#references)</sup>

- **embedded marshal blob 추출**: `pyi-archive_viewer sample.exe`를 실행하고 raw object를 export합니다(예: `vvs`라는 파일). PyInstaller는 전체 `.pyc` 파일이 아니라 `0xe3`(`TYPE_CODE` with `FLAG_REF`)로 시작하는 bare marshal stream을 저장합니다. decompiler가 이를 인식할 수 있도록 올바른 **16-byte `.pyc` header**(embedded interpreter version에 맞는 magic + zeroed timestamp/size)를 앞에 추가합니다. Python 3.11.5의 경우 `imp.get_magic().hex()`로 magic을 가져온 다음, `dd`/`printf`를 사용해 marshal payload 앞에 삽입할 수 있습니다.
- **version-aware tool로 decompile**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` 또는 PyLingual을 사용합니다. 일부 code만 필요한 경우 AST(예: `ast.NodeVisitor`)를 순회하여 특정 argument/constant를 추출할 수 있습니다.
- **Pyarmor v9 header 파싱**으로 crypto parameter 복구: `0x00`의 `PY<license>` signature, `0x09/0x0a`의 Python major/minor, `0x14`의 protection-type field(`0x09`이면 **BCC**, 그 외에는 `0x08`), `0x1c/0x38`의 ELF start/end offset, 그리고 `0x24..0x27` 및 `0x2c..0x33`으로 나뉜 12-byte AES-CTR nonce를 확인합니다. embedded ELF 뒤에서도 동일한 pattern이 반복됩니다.
- **Pyarmor-modified code object 처리**: `co_flags`에는 bit `0x20000000`이 설정되어 있으며, 추가적인 length-prefixed field가 존재합니다. parsing 중 복호화 오류를 방지하려면 CPython `deopt_code()`를 비활성화합니다.
- **encrypted code region 식별**: bytecode는 `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__`로 감싸져 있습니다. runtime key(예: `273b1b1373cf25e054a61e2cb8a947b8`)를 사용해 AES-128-CTR로 내부 blob을 복호화합니다. payload별 12-byte XOR key(Pyarmor runtime에서 가져옴)와 `__pyarmor_exit_*__` marker의 12 bytes를 XOR하여 region별 nonce를 도출합니다. 복호화 후 `__pyarmor_assert_*__`(encrypted string)와 `__pyarmor_bcc_*__`(compiled dispatch target)도 나타날 수 있습니다.
- **Pyarmor “mixed” string 복호화**: `0x81`이 prefix인 constant는 AES-128-CTR로 암호화되어 있으며 plaintext에는 `0x01`이 사용됩니다. 동일한 key와 runtime에서 도출한 string nonce(예: `692e767673e95c45a1e6876d`)를 사용해 긴 string constant를 복구합니다.
- **BCC mode 처리**: Pyarmor `--enable-bcc`는 많은 function을 companion ELF로 compile하고, `__pyarmor_bcc_*__`를 호출하는 Python stub을 남깁니다. `bcc_info.py`와 같은 tooling으로 해당 constant를 ELF symbol에 매핑한 다음, 보고된 offset에서 ELF를 decompile/analyze합니다(예: `__pyarmor_bcc_58580__` → offset `0x4e70`의 `bcc_180`).<sup>[[2]](#references)[[3]](#references)[[8]](#references)</sup>


## Python to Executable

이 예제에서는 py2exe 또는 PyInstaller를 사용해 Python script를 package하는 방법을 보여 줍니다.<sup>[[1]](#references)</sup>

### py2exe를 사용해 payload를 생성하려면:

1. [py2exe](http://www.py2exe.org/)를 install합니다.
2. `hello.py` payload를 생성하고 다음과 같은 setup script를 사용합니다. `bundle_files`를 `1`로 설정하면 Python interpreter가 application과 함께 bundle됩니다.
3. `python setup.py py2exe`를 실행하여 executable을 생성합니다.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```
