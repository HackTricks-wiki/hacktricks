## Compiled Binary से .pyc तक

एक **ELF** compiled binary से आप **.pyc** प्राप्त कर सकते हैं:<sup>[[1]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
एक **python exe binary** में compiled होने पर आप **.pyc** प्राप्त कर सकते हैं, इसे चलाकर:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## .pyc से python code तक

**.pyc** डेटा ("compiled" python) के लिए, आपको **original** **python** **code** को **extract** करने का प्रयास शुरू करना चाहिए:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**सुनिश्चित करें** कि binary का **extension** "**.pyc**" हो (यदि ऐसा नहीं है, तो uncompyle6 काम नहीं करेगा)

**uncompyle6** चलाते समय आपको **निम्नलिखित errors** मिल सकती हैं:

### त्रुटि: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
इसे ठीक करने के लिए आपको generated file की शुरुआत में **सही magic number** जोड़ना होगा।

**Magic numbers python version के अनुसार अलग-अलग होते हैं**, **python 3.8** का magic number प्राप्त करने के लिए आपको **python 3.8** terminal खोलकर यह execute करना होगा:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
इस मामले में python3.8 के लिए **magic number** **`0x550d0d0a`** है, इसलिए इस error को ठीक करने के लिए आपको **.pyc file** के **beginning** में निम्नलिखित bytes **add** करने होंगे: `0x0d550a0d000000000000000000000000`

**Once** आपने वह magic header **add** कर दिया, तो **error ठीक हो जाना चाहिए।**

यह इस प्रकार दिखेगा जब **.pyc python3.8 magic header** सही तरीके से add किया गया हो:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Error: Decompiling generic errors

**Other errors** जैसे: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>` भी दिखाई दे सकते हैं।

इसका संभवतः अर्थ है कि आपने magic number **सही तरीके से add नहीं किया है** या आपने **सही magic number का उपयोग नहीं किया है**, इसलिए **सुनिश्चित करें कि आप सही magic number का उपयोग कर रहे हैं** (या कोई नया आज़माएँ)।

पिछले error documentation को देखें।

## Automatic Tool

[**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) कई community-available tools के संयोजन के रूप में कार्य करता है, जिन्हें Python में लिखे गए executables को unpack और decompile करने में researchers की सहायता के लिए बनाया गया है, विशेष रूप से वे जो py2exe और pyinstaller से बनाए गए हों। इसमें यह पहचानने के लिए YARA rules शामिल हैं कि कोई executable Python-based है या नहीं और creation tool की पुष्टि करने के लिए भी।<sup>[[4]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

एक सामान्य समस्या incomplete Python bytecode file से संबंधित होती है, जो **unpy2exe या pyinstxtractor के साथ unpacking process** के परिणामस्वरूप बनती है और फिर **missing Python bytecode version number के कारण uncompyle6 द्वारा recognize नहीं की जाती**। इसे ठीक करने के लिए एक prepend option जोड़ा गया है, जो आवश्यक Python bytecode version number को append करता है और decompiling process को संभव बनाता है।<sup>[[4]](#references)</sup>

समस्या का उदाहरण:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## python assembly का विश्लेषण

यदि आप पिछले steps का पालन करने के बाद python का "original" code extract नहीं कर पाए, तो आप **assembly** को **extract** करने का प्रयास कर सकते हैं (लेकिन यह **बहुत descriptive नहीं है**, इसलिए **original code** को फिर से extract करने का प्रयास करें)। [यहाँ](https://bits.theorem.co/protecting-a-python-codebase/) मुझे _.pyc_ binary को **disassemble** करने के लिए एक बहुत सरल code मिला (code flow समझने के लिए शुभकामनाएँ)।<sup>[[3]](#references)</sup> यदि _.pyc_ python2 से है, तो python2 का उपयोग करें:

<details>
<summary>एक .pyc को Disassemble करें</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'r') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)
3 MAKE_FUNCTION            0
6 STORE_NAME               0 (hello_world)
9 LOAD_CONST               1 (None)
12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])
2           0 LOAD_CONST               1 ('Hello  {0}')
3 LOAD_ATTR                0 (format)
6 LOAD_FAST                0 (name)
9 CALL_FUNCTION            1
12 PRINT_ITEM
13 PRINT_NEWLINE
14 LOAD_CONST               0 (None)
17 RETURN_VALUE
```
</details>

## PyInstaller raw marshal & Pyarmor v9 static unpack workflow

- **Extract embedded marshal blobs**: `pyi-archive_viewer sample.exe` चलाएं और raw objects export करें (जैसे, `vvs` नाम वाली file)। PyInstaller bare marshal streams store करता है, जो full `.pyc` files के बजाय `0xe3` (TYPE_CODE with FLAG_REF) से शुरू होते हैं। Decompilers द्वारा स्वीकार किए जाने के लिए सही **16-byte `.pyc` header** (embedded interpreter version के magic + zeroed timestamp/size) prepend करें। Python 3.11.5 के लिए `imp.get_magic().hex()` से magic प्राप्त कर सकते हैं और marshal payload से पहले `dd`/`printf` की सहायता से patch कर सकते हैं।<sup>[[2]](#references)</sup>
- **Decompile with version-aware tools**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` या PyLingual का उपयोग करें। यदि केवल partial code की आवश्यकता हो, तो specific arguments/constants निकालने के लिए AST (जैसे, `ast.NodeVisitor`) को walk कर सकते हैं।
- **Parse the Pyarmor v9 header** to recover crypto parameters: `0x00` पर signature `PY<license>`, `0x09/0x0a` पर Python major/minor, **BCC** enabled होने पर protection type `0x09` (`0x08` अन्यथा), `0x1c/0x38` पर ELF start/end offsets, और `0x24..0x27` तथा `0x2c..0x33` में split किया गया 12-byte AES-CTR nonce। यही pattern embedded ELF के बाद फिर दोहराया जाता है।
- **Account for Pyarmor-modified code objects**: `co_flags` में bit `0x20000000` set होता है और एक extra length-prefixed field होता है। Parsing के दौरान CPython `deopt_code()` को disable करें, ताकि decryption failures से बचा जा सके।
- **Identify encrypted code regions**: bytecode को `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__` से wrap किया जाता है। Enclosed blob को runtime key (जैसे, `273b1b1373cf25e054a61e2cb8a947b8`) का उपयोग करके AES-128-CTR से decrypt करें। Per-region nonce निकालने के लिए payload-specific 12-byte XOR key (Pyarmor runtime से) को `__pyarmor_exit_*__` marker में मौजूद 12 bytes के साथ XOR करें। Decryption के बाद आपको `__pyarmor_assert_*__` (encrypted strings) और `__pyarmor_bcc_*__` (compiled dispatch targets) भी दिखाई दे सकते हैं।
- **Decrypt Pyarmor “mixed” strings**: `0x81` से prefixed constants AES-128-CTR encrypted होते हैं (plaintext में `0x01` का उपयोग होता है)। Long string constants recover करने के लिए उसी key और runtime-derived string nonce (जैसे, `692e767673e95c45a1e6876d`) का उपयोग करें।
- **Handle BCC mode**: Pyarmor का `--enable-bcc` कई functions को companion ELF में compile करता है और Python stubs छोड़ता है, जो `__pyarmor_bcc_*__` को call करते हैं। इन constants को `bcc_info.py` जैसे tooling की सहायता से ELF symbols के साथ map करें, फिर reported offsets पर ELF को decompile/analyze करें (जैसे, `__pyarmor_bcc_58580__` → `bcc_180` at offset `0x4e70`)।


## Python से Executable

शुरुआत में, हम बताएंगे कि payloads को py2exe और PyInstaller में कैसे compile किया जा सकता है।<sup>[[1]](#references)</sup>

### py2exe का उपयोग करके payload बनाने के लिए:

1. [http://www.py2exe.org/](http://www.py2exe.org) से py2exe package install करें।
2. Payload के लिए (इस मामले में, हम इसका नाम `hello.py` रखेंगे), Figure 1 में दिए गए script जैसा script उपयोग करें। Value 1 वाला “bundle_files” option Python interpreter सहित सब कुछ एक exe में bundle कर देगा।
3. Script तैयार होने के बाद, हम command “python setup.py py2exe” चलाएंगे। इससे Figure 2 की तरह executable create होगा।
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```

### PyInstaller का उपयोग करके payload बनाने के लिए:

1. pip का उपयोग करके PyInstaller इंस्टॉल करें (`pip install pyinstaller`)।
2. इसके बाद, हम कमांड `pyinstaller –onefile hello.py` चलाएंगे (ध्यान दें कि `hello.py` हमारा payload है)। यह सब कुछ एक executable में bundle कर देगा।
