## Du binaire compilé au fichier .pyc

À partir d’un binaire **ELF** compilé, vous pouvez **obtenir le fichier .pyc** avec :<sup>[[1]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
Dans un **python exe** compilé, vous pouvez **récupérer le .pyc** en exécutant :<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## De .pyc au code Python

Pour les données **.pyc** (Python **« compilé »**), vous devriez commencer par essayer d’**extraire** le **code** **Python** **original**:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Assurez-vous** que le binaire possède l’**extension** "**.pyc**" (sinon, uncompyle6 ne fonctionnera pas)

Lors de l’exécution de **uncompyle6**, vous pouvez rencontrer les **erreurs suivantes** :

### Erreur : Numéro magique inconnu 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Pour corriger cela, vous devez **ajouter le magic number correct** au début du fichier généré.

**Les magic numbers varient selon la version de Python**. Pour obtenir le magic number de **Python 3.8**, vous devez **ouvrir un terminal Python 3.8** et exécuter :
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
Le **magic number** dans ce cas, pour python3.8, est **`0x550d0d0a`**. Ensuite, pour corriger cette erreur, vous devrez **ajouter**, au **début** du **fichier .pyc**, les octets suivants : `0x0d550a0d000000000000000000000000`

**Une fois** que vous avez **ajouté** cet en-tête magic, **l’erreur devrait être corrigée.**

Voici à quoi ressemblera un **en-tête magic .pyc python3.8** correctement ajouté :
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Erreur : erreurs génériques de décompilation

**D'autres erreurs**, comme : `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>`, peuvent apparaître.

Cela signifie probablement que vous **n'avez pas ajouté correctement** le magic number ou que vous n'avez pas **utilisé** le **bon magic number**. Assurez-vous donc d'utiliser le **bon** (ou essayez-en un nouveau).

Consultez la documentation de l'erreur précédente.

## Outil automatique

L'[**outil python-exe-unpacker**](https://github.com/countercept/python-exe-unpacker) sert de combinaison de plusieurs outils disponibles dans la communauté, conçus pour aider les chercheurs à unpacker et décompiler des exécutables écrits en Python, notamment ceux créés avec py2exe et pyinstaller. Il inclut des règles YARA permettant d'identifier si un exécutable est basé sur Python et de confirmer l'outil utilisé pour le créer.<sup>[[4]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

Un problème courant concerne un fichier de bytecode Python incomplet résultant du **processus d'unpacking avec unpy2exe ou pyinstxtractor**, qui n'est ensuite **pas reconnu par uncompyle6 en raison de l'absence du numéro de version du bytecode Python**. Pour résoudre ce problème, une option prepend a été ajoutée afin d'ajouter le numéro de version du bytecode Python nécessaire et de faciliter le processus de décompilation.<sup>[[4]](#references)</sup>

Exemple du problème :
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Analyser l’assembly Python

Si vous n’avez pas pu extraire le code « original » Python en suivant les étapes précédentes, vous pouvez essayer d’**extraire** l’**assembly** (mais **il n’est pas très descriptif**, essayez donc d’**extraire à nouveau** le code original). J’ai trouvé [ici](https://bits.theorem.co/protecting-a-python-codebase/) un code très simple pour **désassembler** le binaire _.pyc_ (bon courage pour comprendre le flux d’exécution).<sup>[[3]](#references)</sup> Si le _.pyc_ provient de Python 2, utilisez python2 :

<details>
<summary>Désassembler un .pyc</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'r') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)
3 MAKE_FUNCTION            0
6 STORE_NAME               0 (hello_world)
9 LOAD_CONST               1 (None)
12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])
2           0 LOAD_CONST               1 ('Hello  {0}')
3 LOAD_ATTR                0 (format)
6 LOAD_FAST                0 (name)
9 CALL_FUNCTION            1
12 PRINT_ITEM
13 PRINT_NEWLINE
14 LOAD_CONST               0 (None)
17 RETURN_VALUE
```
</details>

## PyInstaller raw marshal et workflow de static unpack de Pyarmor v9

- **Extraire les blobs marshal intégrés** : `pyi-archive_viewer sample.exe` et exporter les objets bruts (par exemple, dans un fichier nommé `vvs`). PyInstaller stocke des flux marshal bruts qui commencent par `0xe3` (TYPE_CODE avec FLAG_REF), plutôt que des fichiers `.pyc` complets. Ajouter le **header `.pyc` de 16 octets** correct (magic correspondant à la version de l’interpréteur intégré + timestamp/taille mis à zéro) afin que les decompilers les acceptent. Pour Python 3.11.5, récupérer le magic avec `imp.get_magic().hex()` et le modifier avec `dd`/`printf` avant le payload marshal.<sup>[[2]](#references)</sup>
- **Décompiler avec des outils adaptés à la version** : `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` ou PyLingual. Si seule une partie du code est nécessaire, il est possible de parcourir l’AST (par exemple avec `ast.NodeVisitor`) pour extraire des arguments/constantes spécifiques.
- **Analyser le header Pyarmor v9** pour récupérer les paramètres cryptographiques : signature `PY<license>` à `0x00`, version majeure/mineure de Python à `0x09/0x0a`, type de protection `0x09` lorsque **BCC** est activé (`0x08` sinon), offsets de début/fin de l’ELF à `0x1c/0x38`, et nonce AES-CTR de 12 octets réparti entre `0x24..0x27` et `0x2c..0x33`. Le même schéma se répète après l’ELF intégré.
- **Tenir compte des code objects modifiés par Pyarmor** : `co_flags` possède le bit `0x20000000` défini ainsi qu’un champ supplémentaire préfixé par sa longueur. Désactiver CPython `deopt_code()` lors de l’analyse afin d’éviter les échecs de déchiffrement.
- **Identifier les régions de code chiffrées** : le bytecode est entouré par `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__`. Déchiffrer le blob inclus avec AES-128-CTR à l’aide de la runtime key (par exemple, `273b1b1373cf25e054a61e2cb8a947b8`). Dériver le nonce propre à chaque région en effectuant un XOR entre la clé XOR de 12 octets spécifique au payload (issue de la runtime Pyarmor) et les 12 octets du marqueur `__pyarmor_exit_*__`. Après le déchiffrement, il est également possible de trouver `__pyarmor_assert_*__` (strings chiffrées) et `__pyarmor_bcc_*__` (cibles de dispatch compilées).
- **Déchiffrer les strings “mixed” de Pyarmor** : les constantes préfixées par `0x81` sont chiffrées avec AES-128-CTR (le plaintext utilise `0x01`). Utiliser la même clé et le string nonce dérivé de la runtime (par exemple, `692e767673e95c45a1e6876d`) pour récupérer les longues constantes de type string.
- **Gérer le mode BCC** : Pyarmor `--enable-bcc` compile de nombreuses fonctions dans un ELF compagnon et laisse des stubs Python qui appellent `__pyarmor_bcc_*__`. Mapper ces constantes vers les symboles ELF avec des outils tels que `bcc_info.py`, puis décompiler/analyser l’ELF aux offsets indiqués (par exemple, `__pyarmor_bcc_58580__` → `bcc_180` à l’offset `0x4e70`).


## Python vers Executable

Pour commencer, nous allons montrer comment des payloads peuvent être compilés avec py2exe et PyInstaller.<sup>[[1]](#references)</sup>

### Pour créer un payload avec py2exe :

1. Installer le package py2exe depuis [http://www.py2exe.org/](http://www.py2exe.org)
2. Pour le payload (dans ce cas, nous l’appellerons hello.py), utiliser un script comme celui présenté dans la Figure 1. L’option “bundle_files” avec la valeur 1 regroupera tout, y compris l’interpréteur Python, dans un seul exe.
3. Une fois le script prêt, exécuter la commande “python setup.py py2exe”. Cela créera l’executable, comme dans la Figure 2.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```

### Pour créer un payload à l’aide de PyInstaller :

1. Installez PyInstaller avec pip (`pip install pyinstaller`).
2. Ensuite, exécutez la commande « pyinstaller –onefile hello.py » (rappel : « hello.py » est notre payload). Cette commande regroupera tout dans un seul exécutable.
