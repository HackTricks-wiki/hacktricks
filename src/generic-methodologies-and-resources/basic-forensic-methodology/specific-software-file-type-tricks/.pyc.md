## 从已编译的二进制文件到 .pyc

从一个 **ELF** 已编译的二进制文件中，可以使用以下方法获取 **.pyc**：<sup>[[1]](#references)</sup>
```bash
pyi-archive_viewer <binary>

(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
在编译的 **python exe binary** 中，可以通过运行以下命令获取 **.pyc**：<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## 从 .pyc 到 Python 代码

对于 **.pyc** 数据（“编译后的” Python），你应该开始尝试**提取****原始**的 **Python** **代码**：<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**务必确认**该 binary 具有 **extension** "**.pyc**"（否则 uncompyle6 将无法工作）

执行 **uncompyle6** 时，可能会遇到**以下错误**：

### Error: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
要修复此问题，你需要在生成的文件开头**添加正确的 magic number**。

**Magic number 会因 Python 版本而异**。要获取 **python 3.8** 的 magic number，你需要打开一个 **python 3.8** 终端并执行：
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
本例中，python3.8 的 **magic number** 是 **`0x550d0d0a`**。要修复此错误，需要在 **.pyc file** 的**开头** **add** 以下字节：`0x0d550a0d000000000000000000000000`

**Once** 你已经 **added** 该 magic header，**error should be fixed.**

正确添加的 **.pyc python3.8 magic header** 如下所示：
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### 错误：反编译时的通用错误

可能会出现**其他错误**，例如：`class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>`。

这可能意味着你**没有正确添加** magic number，或者没有**使用正确的 magic number**，因此请**确保使用正确的 magic number**（或尝试使用新的 magic number）。

请查看之前的错误文档。

## Automatic Tool

[**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) 是多个社区可用工具的组合，旨在协助研究人员对使用 Python 编写的 executable 进行解包和反编译，尤其是使用 py2exe 和 pyinstaller 创建的 executable。它包含用于识别 executable 是否基于 Python 以及确认其创建工具的 YARA rules。<sup>[[4]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

一个常见问题是，由于使用 unpy2exe 或 pyinstxtractor 进行**解包过程**不完整，导致生成的 Python bytecode 文件不完整；随后由于缺少 Python bytecode 版本号，该文件无法被 uncompyle6 识别。为了解决此问题，新增了 prepend 选项，用于附加必要的 Python bytecode 版本号，从而完成反编译过程。<sup>[[4]](#references)</sup>

问题示例：
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## 分析 Python 汇编

如果按照前面的步骤无法提取 Python 的“原始”代码，那么可以尝试**提取**其**汇编代码**（但**描述性不强**，因此请**再次尝试**提取原始代码）。在[这里](https://bits.theorem.co/protecting-a-python-codebase/)我找到了一个非常简单的代码，用于**反汇编** _.pyc_ 二进制文件（祝你能理解其代码流程）。<sup>[[3]](#references)</sup> 如果 _.pyc_ 文件来自 Python 2，请使用 python2：

<details>
<summary>反汇编 .pyc</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'r') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)
3 MAKE_FUNCTION            0
6 STORE_NAME               0 (hello_world)
9 LOAD_CONST               1 (None)
12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])

3 LOAD_ATTR                0 (format)

```

## PyInstaller raw marshal 与 Pyarmor v9 static unpack workflow

- **Extract embedded marshal blobs**：使用 `pyi-archive_viewer sample.exe` 提取并导出 raw objects（例如名为 `vvs` 的文件）。PyInstaller 存储的是以 `0xe3`（带 FLAG_REF 的 TYPE_CODE）开头的 bare marshal streams，而不是完整的 `.pyc` 文件。在 marshal payload 前添加正确的 **16-byte `.pyc` header**（嵌入式 interpreter 版本对应的 magic，以及填零的 timestamp/size），这样 decompiler 才能接受。对于 Python 3.11.5，可以通过 `imp.get_magic().hex()` 获取 magic，然后在 marshal payload 前使用 `dd`/`printf` 进行 patch。<sup>[[2]](#references)</sup>
- **Decompile with version-aware tools**：使用 `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` 或 PyLingual。如果只需要部分 code，可以遍历 AST（例如使用 `ast.NodeVisitor`）提取特定的 arguments/constants。
- **Parse the Pyarmor v9 header** 以恢复 crypto parameters：`0x00` 处的 signature 为 `PY<license>`，`0x09/0x0a` 处为 Python major/minor，启用 **BCC** 时 protection type 为 `0x09`（否则为 `0x08`），`0x1c/0x38` 处为 ELF start/end offsets，12-byte AES-CTR nonce 分布在 `0x24..0x27` 和 `0x2c..0x33`。相同模式会在 embedded ELF 后重复出现。
- **Account for Pyarmor-modified code objects**：`co_flags` 设置了 `0x20000000` 位，并包含一个额外的 length-prefixed field。解析时禁用 CPython 的 `deopt_code()`，以避免 decryption failures。
- **Identify encrypted code regions**：bytecode 被 `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__` 包裹。使用 runtime key（例如 `273b1b1373cf25e054a61e2cb8a947b8`）通过 AES-128-CTR decrypt 被包裹的 blob。将 payload-specific 12-byte XOR key（来自 Pyarmor runtime）与 `__pyarmor_exit_*__` marker 中的 12 个 bytes 进行 XOR，以推导每个 region 的 nonce。decryption 后，还可能看到 `__pyarmor_assert_*__`（encrypted strings）和 `__pyarmor_bcc_*__`（compiled dispatch targets）。
- **Decrypt Pyarmor “mixed” strings**：以 `0x81` 开头的 constants 使用 AES-128-CTR 加密（plaintext 使用 `0x01`）。使用相同的 key 和 runtime-derived string nonce（例如 `692e767673e95c45a1e6876d`）恢复 long string constants。
- **Handle BCC mode**：Pyarmor 的 `--enable-bcc` 会将许多 functions 编译到 companion ELF 中，并留下调用 `__pyarmor_bcc_*__` 的 Python stubs。使用 `bcc_info.py` 等 tooling 将这些 constants 映射到 ELF symbols，然后根据报告的 offsets 对 ELF 进行 decompile/analyze（例如，`__pyarmor_bcc_58580__` → offset `0x4e70` 处的 `bcc_180`）。


## Python to Executable

首先，我们将介绍如何使用 py2exe 和 PyInstaller 编译 payloads。<sup>[[1]](#references)</sup>

### To create a payload using py2exe:

1. 从 [http://www.py2exe.org/](http://www.py2exe.org) 安装 py2exe package。
2. 对于 payload（本例中将其命名为 hello.py），使用类似 Figure 1 中的 script。值为 1 的 “bundle_files” option 会将所有内容（包括 Python interpreter）打包到一个 exe 中。
3. script 准备就绪后，执行 command “python setup.py py2exe”。这将创建 executable，如 Figure 2 所示。
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```

### 使用 PyInstaller 创建 payload：

1. 使用 pip 安装 PyInstaller（pip install pyinstaller）。
2. 之后，我们将执行命令“pyinstaller –onefile hello.py”（提醒一下，‘hello.py’ 是我们的 payload）。这会将所有内容打包到一个可执行文件中。
