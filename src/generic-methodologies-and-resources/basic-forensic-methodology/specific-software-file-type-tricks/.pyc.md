# Compiled python binaries (exe, elf) को Decompile करें - .pyc से Retrieve करें


## Compiled Binary से .pyc तक

एक **PyInstaller-built executable** (जिसमें **ELF** executable भी शामिल है) से आप embedded Python modules को इस command के साथ inspect और extract कर सकते हैं:<sup>[[6]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
**PyInstaller-built executable** से उसका embedded Python bytecode निकालें:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## .pyc से python code तक

जब आपके पास **.pyc** फ़ाइल हो, तो इसे निम्न के साथ वापस Python source में decompile करने का प्रयास करें:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**सुनिश्चित करें** कि binary में **extension** "**.pyc**" हो (यदि नहीं, तो uncompyle6 काम नहीं करेगा)

**uncompyle6** चलाते समय आपको **निम्न errors** मिल सकती हैं:

### Error: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
इसे ठीक करने के लिए, bytecode बनाने वाले Python version का magic number शुरुआत में जोड़ें।

Magic numbers Python version के अनुसार अलग-अलग होते हैं। **Python 3.8** terminal में चलाएँ:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
Python 3.8 के लिए, 16-बाइट **.pyc** header बनाने हेतु चार-बाइट sequence **`55 0d 0d 0a`** के आगे 12 शून्य bytes जोड़ें।<sup>[[7]](#references)</sup>

header जोड़ने के बाद **uncompyle6** को फिर से चलाएँ।<sup>[[1]](#references)</sup>

सही तरीके से जोड़ा गया **.pyc python3.8 magic header** इस प्रकार दिखाई देगा:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### त्रुटि: Generic errors को Decompiling करना

**अन्य errors** जैसे: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>` दिखाई दे सकते हैं।

इसका संभवतः अर्थ है कि आपने magic number **सही तरीके से नहीं जोड़ा है** या आपने **सही magic number का उपयोग नहीं किया है**, इसलिए **सुनिश्चित करें कि आप सही magic number का उपयोग करें** (या कोई नया आज़माएँ)।

पिछली error documentation देखें।

## Automatic Tool

[**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) py2exe या PyInstaller से बनाए गए Python executables को unpacking और decompiling करने के लिए helper scripts को combine करता है। इसके YARA rules Python executables की पहचान करते हैं और उन packers के बीच अंतर करते हैं।<sup>[[5]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

जब unpacking के बाद Python magic bytes के बिना कोई bytecode file बच जाती है, तो decompiling से पहले उन्हें जोड़ने के लिए tool के prepend option का उपयोग करें।<sup>[[1]](#references)[[5]](#references)</sup>

समस्या का उदाहरण:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Python assembly का विश्लेषण

यदि decompilation विफल हो जाए, तो fallback के रूप में marshaled code object को disassemble करें। उस interpreter version का उपयोग करें जिसने bytecode बनाया था (Python 2 **.pyc** files के लिए Python 2)।<sup>[[4]](#references)</sup>

<details>
<summary>.pyc को disassemble करें</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'rb') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)
3 MAKE_FUNCTION            0
6 STORE_NAME               0 (hello_world)
9 LOAD_CONST               1 (None)
12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])

3 LOAD_ATTR                0 (format)
6 LOAD_FAST                0 (name)

14 LOAD_CONST               0 (None)
17 RETURN_VALUE
```

## PyInstaller raw marshal और Pyarmor v9 static unpack workflow

निम्न workflow Pyarmor v9 से protected PyInstaller raw marshal payloads को target करता है।<sup>[[3]](#references)</sup>

- **Embedded marshal blobs extract करें**: `pyi-archive_viewer sample.exe` चलाएँ और raw objects export करें (जैसे, `vvs` नाम वाली file)। PyInstaller bare marshal streams store करता है, जो full `.pyc` files के बजाय `0xe3` (TYPE_CODE with FLAG_REF) से शुरू होते हैं। सही **16-byte `.pyc` header** (embedded interpreter version के लिए magic + zeroed timestamp/size) prepend करें, ताकि decompilers उन्हें accept कर सकें। Python 3.11.5 के लिए आप `imp.get_magic().hex()` से magic प्राप्त करके marshal payload से पहले `dd`/`printf` द्वारा patch कर सकते हैं।
- **Version-aware tools से decompile करें**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` या PyLingual का उपयोग करें। यदि केवल partial code की आवश्यकता हो, तो specific arguments/constants निकालने के लिए AST (जैसे, `ast.NodeVisitor`) को walk कर सकते हैं।
- **Pyarmor v9 header parse करें** और crypto parameters recover करें: `0x00` पर signature `PY<license>`, `0x09/0x0a` पर Python major/minor, `0x14` पर protection-type field (`**BCC**` के साथ `0x09`, अन्यथा `0x08`), `0x1c/0x38` पर ELF start/end offsets, और `0x24..0x27` तथा `0x2c..0x33` में split किया गया 12-byte AES-CTR nonce। Embedded ELF के बाद यही pattern दोबारा आता है।
- **Pyarmor-modified code objects को ध्यान में रखें**: `co_flags` में bit `0x20000000` set होता है और एक extra length-prefixed field मौजूद होता है। Parsing के दौरान CPython `deopt_code()` disable करें, ताकि decryption failures से बचा जा सके।
- **Encrypted code regions पहचानें**: bytecode `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__` से wrapped होता है। Enclosed blob को runtime key (जैसे, `273b1b1373cf25e054a61e2cb8a947b8`) का उपयोग करके AES-128-CTR से decrypt करें। Per-region nonce derive करने के लिए payload-specific 12-byte XOR key (Pyarmor runtime से) को `__pyarmor_exit_*__` marker में मौजूद 12 bytes के साथ XOR करें। Decryption के बाद आपको `__pyarmor_assert_*__` (encrypted strings) और `__pyarmor_bcc_*__` (compiled dispatch targets) भी दिखाई दे सकते हैं।
- **Pyarmor “mixed” strings decrypt करें**: `0x81` से prefixed constants AES-128-CTR encrypted होते हैं (plaintext में `0x01` का उपयोग होता है)। उसी key और runtime-derived string nonce (जैसे, `692e767673e95c45a1e6876d`) का उपयोग करके long string constants recover करें।
- **BCC mode handle करें**: Pyarmor का `--enable-bcc` कई functions को companion ELF में compile करता है और Python stubs छोड़ता है, जो `__pyarmor_bcc_*__` को call करते हैं। `bcc_info.py` जैसे tooling से इन constants को ELF symbols से map करें, फिर reported offsets पर ELF को decompile/analyze करें (जैसे, `__pyarmor_bcc_58580__` → `bcc_180` at offset `0x4e70`)।<sup>[[2]](#references)[[3]](#references)[[8]](#references)</sup>


## Python से Executable

ये examples py2exe या PyInstaller से Python script package करने का तरीका दिखाते हैं।<sup>[[1]](#references)</sup>

### py2exe का उपयोग करके payload बनाने के लिए:

1. [py2exe](http://www.py2exe.org/) install करें।
2. `hello.py` payload बनाएँ और निम्न जैसे setup script का उपयोग करें। `bundle_files` को `1` पर set करने से Python interpreter application के साथ bundle हो जाता है।
3. Executable बनाने के लिए `python setup.py py2exe` चलाएँ।
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```
