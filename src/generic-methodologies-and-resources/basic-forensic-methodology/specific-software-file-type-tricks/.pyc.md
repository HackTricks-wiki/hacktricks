## 从已编译的二进制文件到 .pyc

对于 **PyInstaller 构建的可执行文件**（包括 **ELF** 可执行文件），可以使用以下工具检查并提取嵌入的 Python 模块：<sup>[[6]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
对于使用 **PyInstaller** 构建的可执行文件，使用以下命令提取其中嵌入的 Python 字节码：<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## 从 .pyc 到 Python 代码

获取 **.pyc** 文件后，可以尝试使用以下工具将其反编译回 Python 源代码：<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**请务必**确认该二进制文件具有 **扩展名** "**.pyc**"（如果没有，uncompyle6 将无法工作）

运行 **uncompyle6** 时，可能会遇到**以下错误**：

### Error: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
要修复此问题，请在字节码前添加生成该字节码的 Python 版本对应的 magic number。

不同 Python 版本的 magic number 不同。在 **Python 3.8** 终端中运行：
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
对于 Python 3.8，在前面添加四字节序列 **`55 0d 0d 0a`**，随后添加 12 个零字节，以创建 16 字节的 **.pyc** header。<sup>[[7]](#references)</sup>

添加 header 后，重新尝试 **uncompyle6**。<sup>[[1]](#references)</sup>

正确添加 **.pyc python3.8 magic header** 后，其显示方式如下：
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### 错误：反编译通用错误

可能会出现**其他错误**，例如：`class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>`。

这可能意味着你**没有正确添加** magic number，或者没有**使用正确的 magic number**，因此请**确保使用正确的 magic number**（或尝试新的 magic number）。

查看之前的错误文档。

## 自动化工具

[**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker)结合了用于解包和反编译使用 py2exe 或 PyInstaller 创建的 Python 可执行文件的辅助脚本。其 YARA 规则可以识别 Python 可执行文件，并区分这些 packer。<sup>[[5]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

当解包后留下一个没有 Python magic bytes 的 bytecode 文件时，使用该工具的 prepend 选项，在反编译前为其添加 magic bytes。<sup>[[1]](#references)[[5]](#references)</sup>

问题示例：
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## 分析 Python 汇编

如果反编译失败，可以将 marshaled code object 反汇编作为备用方案。使用生成该 bytecode 的 interpreter 版本（对于 Python 2 的 **.pyc** 文件，使用 Python 2）。<sup>[[4]](#references)</sup>

<details>
<summary>反汇编 .pyc</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'rb') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)
3 MAKE_FUNCTION            0
6 STORE_NAME               0 (hello_world)
9 LOAD_CONST               1 (None)
12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])
2           0 LOAD_CONST               1 ('Hello  {0}')
3 LOAD_ATTR                0 (format)
6 LOAD_FAST                0 (name)
9 CALL_FUNCTION            1
12 PRINT_ITEM
13 PRINT_NEWLINE
14 LOAD_CONST               0 (None)
17 RETURN_VALUE
```
</details>

## PyInstaller 原始 marshal 与 Pyarmor v9 静态解包工作流

以下工作流针对受 Pyarmor v9 保护的 PyInstaller 原始 marshal payload。<sup>[[3]](#references)</sup>

- **提取嵌入的 marshal blobs**：使用 `pyi-archive_viewer sample.exe` 并导出原始对象（例如名为 `vvs` 的文件）。PyInstaller 存储的是以 `0xe3`（带 FLAG_REF 的 TYPE_CODE）开头的裸 marshal 流，而不是完整的 `.pyc` 文件。在 marshal payload 前添加正确的 **16 字节 `.pyc` header**（嵌入式解释器版本对应的 magic，以及清零的时间戳/大小），使 decompiler 能够接受。对于 Python 3.11.5，可以通过 `imp.get_magic().hex()` 获取 magic，并在 marshal payload 前使用 `dd`/`printf` 进行修补。
- **使用版本感知的工具进行反编译**：使用 `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` 或 PyLingual。如果只需要部分代码，可以遍历 AST（例如使用 `ast.NodeVisitor`）提取特定参数/常量。
- **解析 Pyarmor v9 header** 以恢复 crypto 参数：`0x00` 处的签名为 `PY<license>`，`0x09/0x0a` 处为 Python 主/次版本号，`0x14` 处为保护类型字段（使用 **BCC** 时为 `0x09`，否则为 `0x08`），`0x1c/0x38` 处为 ELF 起始/结束偏移，12 字节的 AES-CTR nonce 分割存储在 `0x24..0x27` 和 `0x2c..0x33`。嵌入的 ELF 后会重复出现相同模式。
- **处理 Pyarmor 修改过的 code objects**：`co_flags` 设置了 `0x20000000` 位，并包含一个额外的长度前缀字段。解析时禁用 CPython 的 `deopt_code()`，以避免解密失败。
- **识别加密的代码区域**：字节码由 `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__` 包裹。使用 runtime key（例如 `273b1b1373cf25e054a61e2cb8a947b8`）通过 AES-128-CTR 解密其中的 blob。将 payload 专用的 12 字节 XOR key（来自 Pyarmor runtime）与 `__pyarmor_exit_*__` 标记中的 12 字节进行 XOR，以派生每个区域的 nonce。解密后，还可能看到 `__pyarmor_assert_*__`（加密字符串）和 `__pyarmor_bcc_*__`（编译后的 dispatch targets）。
- **解密 Pyarmor 的“mixed”字符串**：以 `0x81` 为前缀的常量经过 AES-128-CTR 加密（明文使用 `0x01`）。使用相同的 key 和 runtime 派生的字符串 nonce（例如 `692e767673e95c45a1e6876d`）恢复较长的字符串常量。
- **处理 BCC 模式**：Pyarmor 的 `--enable-bcc` 会将许多函数编译到 companion ELF 中，并留下调用 `__pyarmor_bcc_*__` 的 Python stubs。使用 `bcc_info.py` 等工具将这些常量映射到 ELF symbols，然后按照报告的偏移量对 ELF 进行反编译/分析（例如，`__pyarmor_bcc_58580__` → 偏移量为 `0x4e70` 的 `bcc_180`）。<sup>[[2]](#references)[[3]](#references)[[8]](#references)</sup>


## Python 到 Executable

以下示例展示如何使用 py2exe 或 PyInstaller 打包 Python 脚本。<sup>[[1]](#references)</sup>

### 使用 py2exe 创建 payload：

1. 安装 [py2exe](http://www.py2exe.org/)。
2. 创建一个 `hello.py` payload，并使用类似以下内容的 setup script。将 `bundle_files` 设置为 `1` 会将 Python interpreter 与 application 打包在一起。
3. 运行 `python setup.py py2exe` 以创建 executable。
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```
