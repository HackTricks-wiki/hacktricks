## Da binario compilato a .pyc

Da un **eseguibile creato con PyInstaller** (incluso un eseguibile **ELF**), puoi ispezionare ed estrarre i moduli Python incorporati con:<sup>[[6]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
Per un **eseguibile creato con PyInstaller**, estrai il bytecode Python incorporato con:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## Da .pyc al codice Python

Una volta ottenuto un file **.pyc**, prova a decompilarlo nuovamente nel codice sorgente Python con:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Assicurati** che il binario abbia l'**estensione** "**.pyc**" (in caso contrario, uncompyle6 non funzionerà)

Durante l'esecuzione di **uncompyle6** potresti riscontrare i **seguenti errori**:

### Error: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Per risolvere il problema, anteponi il magic number relativo alla versione di Python che ha prodotto il bytecode.

I magic number variano in base alla versione di Python. In un terminale **Python 3.8**, esegui:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
Per Python 3.8, anteponi la sequenza di quattro byte **`55 0d 0d 0a`** seguita da 12 byte nulli per creare l'header di 16 byte **.pyc**.<sup>[[7]](#references)</sup>

Riprova **uncompyle6** dopo aver aggiunto l'header.<sup>[[1]](#references)</sup>

Ecco come apparirà un **magic header .pyc python3.8** aggiunto correttamente:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Errore: errori generici di decompilazione

Possono comparire **altri errori** come: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>`.

Probabilmente significa che **non hai aggiunto correttamente** il magic number o che non hai **utilizzato** il **magic number corretto**; quindi **assicurati di utilizzare quello corretto** (oppure provane uno nuovo).

Consulta la documentazione dell'errore precedente.

## Strumento automatico

Lo [**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) combina script di supporto per unpacking e decompilazione di eseguibili Python creati con py2exe o PyInstaller. Le sue regole YARA identificano gli eseguibili Python e distinguono questi packer.<sup>[[5]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

Quando l'unpacking lascia un file bytecode privo dei suoi magic bytes Python, utilizza l'opzione prepend dello strumento per aggiungerli prima della decompilazione.<sup>[[1]](#references)[[5]](#references)</sup>

Esempio del problema:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Analisi dell'assembly Python

Se la decompilazione non riesce, disassembla l'oggetto codice marshaled come alternativa. Usa la versione dell'interprete che ha prodotto il bytecode (Python 2 per i file **.pyc** di Python 2).<sup>[[4]](#references)</sup>

<details>
<summary>Disassembla un .pyc</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'rb') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)

6 STORE_NAME               0 (hello_world)
9 LOAD_CONST               1 (None)
12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])
```

## Workflow statico di unpack di raw marshal PyInstaller e Pyarmor v9

Il seguente workflow è destinato ai raw marshal payload di PyInstaller protetti con Pyarmor v9.<sup>[[3]](#references)</sup>

- **Estrai i blob marshal incorporati**: `pyi-archive_viewer sample.exe` ed esporta gli oggetti raw (ad esempio, un file denominato `vvs`). PyInstaller memorizza stream marshal privi di header che iniziano con `0xe3` (TYPE_CODE con FLAG_REF), anziché file `.pyc` completi. Anteponi il corretto **header `.pyc` di 16 byte** (magic della versione dell'interprete incorporato + timestamp/dimensione azzerati) in modo che i decompiler li accettino. Per Python 3.11.5 puoi recuperare il magic tramite `imp.get_magic().hex()` e applicarlo con `dd`/`printf` prima del payload marshal.
- **Decompila con strumenti compatibili con la versione**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` o PyLingual. Se serve solo una parte del codice, puoi attraversare l'AST (ad esempio, `ast.NodeVisitor`) per estrarre argomenti/constanti specifici.
- **Analizza l'header Pyarmor v9** per recuperare i parametri crittografici: firma `PY<license>` a `0x00`, versione major/minor di Python a `0x09/0x0a`, campo del tipo di protezione a `0x14` (`0x09` con **BCC**, `0x08` altrimenti), offset di inizio/fine ELF a `0x1c/0x38` e il nonce AES-CTR di 12 byte suddiviso tra `0x24..0x27` e `0x2c..0x33`. Lo stesso schema si ripete dopo l'ELF incorporato.
- **Tieni conto degli oggetti code modificati da Pyarmor**: `co_flags` ha il bit `0x20000000` impostato e un campo aggiuntivo preceduto dalla lunghezza. Disabilita `deopt_code()` di CPython durante il parsing per evitare errori di decrittazione.
- **Individua le regioni di codice cifrate**: il bytecode è racchiuso tra `LOAD_CONST __pyarmor_enter_*__` e `LOAD_CONST __pyarmor_exit_*__`. Decripta il blob contenuto con AES-128-CTR usando la runtime key (ad esempio, `273b1b1373cf25e054a61e2cb8a947b8`). Deriva il nonce specifico della regione facendo XOR tra la chiave XOR di 12 byte specifica del payload (proveniente dal runtime Pyarmor) e i 12 byte nel marker `__pyarmor_exit_*__`. Dopo la decrittazione, potresti vedere anche `__pyarmor_assert_*__` (stringhe cifrate) e `__pyarmor_bcc_*__` (target di dispatch compilati).
- **Decripta le stringhe “mixed” di Pyarmor**: le costanti precedute da `0x81` sono cifrate con AES-128-CTR (il plaintext usa `0x01`). Usa la stessa chiave e il nonce delle stringhe derivato dal runtime (ad esempio, `692e767673e95c45a1e6876d`) per recuperare le costanti stringa lunghe.
- **Gestisci la modalità BCC**: Pyarmor `--enable-bcc` compila molte funzioni in un ELF complementare e lascia stub Python che chiamano `__pyarmor_bcc_*__`. Mappa queste costanti ai simboli ELF con strumenti come `bcc_info.py`, quindi decompila/analizza l'ELF agli offset indicati (ad esempio, `__pyarmor_bcc_58580__` → `bcc_180` all'offset `0x4e70`).<sup>[[2]](#references)[[3]](#references)[[8]](#references)</sup>


## Da Python a Eseguibile

Questi esempi mostrano come impacchettare uno script Python con py2exe o PyInstaller.<sup>[[1]](#references)</sup>

### Per creare un payload usando py2exe:

1. Installa [py2exe](http://www.py2exe.org/).
2. Crea un payload `hello.py` e usa uno script setup come il seguente. Impostare `bundle_files` su `1` include l'interprete Python nell'applicazione.
3. Esegui `python setup.py py2exe` per creare l'eseguibile.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```
