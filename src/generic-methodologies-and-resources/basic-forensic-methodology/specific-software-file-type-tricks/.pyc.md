## Від скомпільованого бінарного файлу до .pyc

З **ELF** скомпільованого бінарного файлу можна **отримати .pyc** за допомогою:<sup>[[1]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
У скомпільованому **python exe binary** можна **отримати .pyc**, виконавши:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## Від .pyc до коду Python

Для даних **.pyc** ("скомпільований" Python) слід почати намагатися **витягти** **оригінальний** **код** **Python**:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Переконайтеся**, що binary має **extension** "**.pyc**" (якщо ні, uncompyle6 не працюватиме)

Під час виконання **uncompyle6** ви можете зіткнутися з **такими помилками**:

### Error: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Щоб це виправити, потрібно **додати правильне magic number** на початку згенерованого файлу.

**Magic numbers відрізняються залежно від версії python**, тому, щоб отримати magic number для **python 3.8**, потрібно **відкрити термінал python 3.8** і виконати:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
**Magic number** у цьому випадку для python3.8 — **`0x550d0d0a`**, тому, щоб виправити цю помилку, потрібно **додати** на **початку** **.pyc-файлу** такі байти: `0x0d550a0d000000000000000000000000`

**Після того як** ви **додасте** цей magic header, **помилку має бути виправлено.**

Ось як виглядатиме правильно доданий **magic header .pyc для python3.8**:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Помилка: Загальні помилки декомпіляції

**Інші помилки**, як-от: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>`, можуть виникати.

Ймовірно, це означає, що ви **неправильно додали** magic number або **не використали** **правильний magic number**, тому **переконайтеся, що використовуєте правильний** (або спробуйте новий).

Перегляньте документацію щодо попередньої помилки.

## Automatic Tool

[**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) поєднує кілька доступних спільнотних інструментів, призначених для допомоги дослідникам у розпакуванні та декомпіляції виконуваних файлів, написаних на Python, зокрема створених за допомогою py2exe та pyinstaller. Він містить правила YARA для визначення того, чи створено виконуваний файл на Python, а також підтверджує інструмент, за допомогою якого його було створено.<sup>[[4]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

Поширена проблема полягає в неповному файлі Python bytecode, що виникає внаслідок **процесу розпакування за допомогою unpy2exe або pyinstxtractor**, після чого файл **не розпізнається uncompyle6 через відсутній номер версії Python bytecode**. Для вирішення цієї проблеми було додано опцію prepend, яка додає необхідний номер версії Python bytecode і забезпечує процес декомпіляції.<sup>[[4]](#references)</sup>

Приклад проблеми:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Аналіз python assembly

Якщо вам не вдалося отримати «оригінальний» код python, дотримуючись попередніх кроків, спробуйте **отримати** **assembly** (але він **не дуже описовий**, тому **спробуйте** ще раз отримати оригінальний код). [Тут](https://bits.theorem.co/protecting-a-python-codebase/) я знайшов дуже простий код для **disassemble** бінарного файлу _.pyc_ (удачі в розумінні потоку виконання коду).<sup>[[3]](#references)</sup> Якщо _.pyc_ створено python2, використовуйте python2:

<details>
<summary>Disassemble a .pyc</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'r') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code

>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)

>>>
>>> # Also disassemble that const being loaded (our function)

```

## PyInstaller raw marshal і Pyarmor v9: статичний workflow розпакування

- **Extract embedded marshal blobs**: `pyi-archive_viewer sample.exe` і експортуйте raw objects (наприклад, файл із назвою `vvs`). PyInstaller зберігає bare marshal streams, які починаються з `0xe3` (TYPE_CODE із FLAG_REF), а не повні `.pyc`-файли. Додайте правильний **16-байтовий заголовок `.pyc`** (magic для версії вбудованого інтерпретатора + обнулені timestamp/size), щоб decompilers могли їх прийняти. Для Python 3.11.5 magic можна отримати через `imp.get_magic().hex()` і додати його за допомогою `dd`/`printf` перед marshal payload.<sup>[[2]](#references)</sup>
- **Decompile with version-aware tools**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` або PyLingual. Якщо потрібен лише partial code, можна пройти AST (наприклад, за допомогою `ast.NodeVisitor`), щоб отримати конкретні arguments/constants.
- **Parse the Pyarmor v9 header** для відновлення crypto parameters: signature `PY<license>` за адресою `0x00`, Python major/minor за адресами `0x09/0x0a`, protection type `0x09`, коли увімкнено **BCC** (`0x08` в іншому разі), початковий і кінцевий offsets ELF за адресами `0x1c/0x38`, а також 12-байтовий AES-CTR nonce, розділений між `0x24..0x27` і `0x2c..0x33`. Та сама структура повторюється після вбудованого ELF.
- **Account for Pyarmor-modified code objects**: `co_flags` має встановлений bit `0x20000000` і додаткове length-prefixed field. Вимкніть CPython `deopt_code()` під час parsing, щоб уникнути помилок decryption.
- **Identify encrypted code regions**: bytecode обгорнутий між `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__`. Розшифруйте enclosed blob за допомогою AES-128-CTR, використовуючи runtime key (наприклад, `273b1b1373cf25e054a61e2cb8a947b8`). Отримайте per-region nonce, виконавши XOR payload-specific 12-byte XOR key (із Pyarmor runtime) із 12 байтами в маркері `__pyarmor_exit_*__`. Після decryption також можуть з’явитися `__pyarmor_assert_*__` (encrypted strings) і `__pyarmor_bcc_*__` (compiled dispatch targets).
- **Decrypt Pyarmor “mixed” strings**: constants із префіксом `0x81` є AES-128-CTR encrypted (plaintext використовує `0x01`). Використайте той самий key і runtime-derived string nonce (наприклад, `692e767673e95c45a1e6876d`), щоб відновити long string constants.
- **Handle BCC mode**: Pyarmor `--enable-bcc` компілює багато functions у companion ELF і залишає Python stubs, які викликають `__pyarmor_bcc_*__`. Зіставте ці constants із ELF symbols за допомогою tools на кшталт `bcc_info.py`, а потім decompile/analyze ELF за вказаними offsets (наприклад, `__pyarmor_bcc_58580__` → `bcc_180` за offset `0x4e70`).


## Python у виконуваний файл

Для початку ми покажемо, як payloads можна скомпілювати за допомогою py2exe і PyInstaller.<sup>[[1]](#references)</sup>

### Створення payload за допомогою py2exe:

1. Встановіть пакет py2exe з [http://www.py2exe.org/](http://www.py2exe.org)
2. Для payload (у цьому випадку ми назвемо його hello.py) використайте script, як на Figure 1. Опція “bundle_files” зі значенням 1 об’єднає все, включно з Python interpreter, в один exe.
3. Коли script буде готовий, виконайте команду “python setup.py py2exe”. Це створить executable, як показано на Figure 2.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```

### Щоб створити payload за допомогою PyInstaller:

1. Встановіть PyInstaller за допомогою pip (`pip install pyinstaller`).
2. Після цього виконайте команду `pyinstaller –onefile hello.py` (нагадуємо, що `hello.py` — це наш payload). Вона об’єднає все в один виконуваний файл.
