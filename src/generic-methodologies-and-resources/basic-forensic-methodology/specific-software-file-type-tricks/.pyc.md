```bash
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),

(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
In ’n **gekompileerde python exe binary** kan jy **die .pyc kry** deur die volgende uit te voer:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## Van .pyc na Python-kode

Vir die **.pyc**-data ("gekompileerde" Python) moet jy begin probeer om die **oorspronklike** **Python**-**kode** te **onttrek**:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Maak seker** dat die binary die **uitbreiding** "**.pyc**" het (indien nie, gaan uncompyle6 nie werk nie)

Terwyl jy **uncompyle6** uitvoer, kan jy die **volgende foute** teëkom:

### Fout: Onbekende magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Om dit reg te stel, moet jy die **korrekte magic number** aan die begin van die gegenereerde lêer **byvoeg**.

**Magic numbers verskil volgens die Python-weergawe**. Om die magic number van **Python 3.8** te kry, moet jy ’n **Python 3.8**-terminaal oopmaak en uitvoer:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
Die **magic number** in hierdie geval vir python3.8 is **`0x550d0d0a`**; om hierdie fout reg te stel, moet jy die volgende grepe by die **begin** van die **.pyc-lêer** **voeg**: `0x0d550a0d000000000000000000000000`

**Sodra** jy daardie magic header **bygevoeg** het, behoort die **fout reggestel te wees.**

So sal ’n korrek bygevoegde **.pyc python3.8 magic header** lyk:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Fout: Decompiling generic errors

**Ander errors** soos: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>` mag verskyn.

Dit beteken waarskynlik dat jy nie die magic number **korrek bygevoeg** het nie, of dat jy nie die **korrekte magic number** **gebruik** het nie. Maak dus **seker dat jy die korrekte een gebruik** (of probeer ’n nuwe een).

Kyk na die vorige error-dokumentasie.

## Automatic Tool

Die [**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) dien as ’n kombinasie van verskeie community-beskikbare tools wat ontwerp is om researchers te help met die unpacking en decompiling van executables wat in Python geskryf is, spesifiek dié wat met py2exe en pyinstaller geskep is. Dit bevat YARA rules om te identifiseer of ’n executable op Python gebaseer is en bevestig watter creation tool gebruik is.<sup>[[4]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

’n Algemene probleem wat voorkom, is ’n onvolledige Python bytecode-lêer wat voortspruit uit die **unpacking process met unpy2exe of pyinstxtractor**, waarna dit **nie deur uncompyle6 herken kan word nie weens ’n ontbrekende Python bytecode version number**. Om dit op te los, is ’n prepend option bygevoeg wat die nodige Python bytecode version number aanheg en die decompiling process moontlik maak.<sup>[[4]](#references)</sup>

Voorbeeld van die probleem:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Ontleding van Python assembly

As jy nie daarin kon slaag om die Python-"original" code volgens die vorige stappe te extract nie, kan jy probeer om die **assembly** te **extract** (maar dit is **nie baie beskrywend nie**, so **probeer** om die original code **weer** te extract). Hier het ek [hierdie](https://bits.theorem.co/protecting-a-python-codebase/) baie eenvoudige code gevind om die _.pyc_-binary te **disassemble** (sterkte om die code flow te verstaan).<sup>[[3]](#references)</sup> As die _.pyc_ van python2 afkomstig is, gebruik python2:

<details>
<summary>Disassembleer 'n .pyc</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'r') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)
3 MAKE_FUNCTION            0
6 STORE_NAME               0 (hello_world)
9 LOAD_CONST               1 (None)
12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])
2           0 LOAD_CONST               1 ('Hello  {0}')
3 LOAD_ATTR                0 (format)
6 LOAD_FAST                0 (name)
9 CALL_FUNCTION            1
12 PRINT_ITEM
13 PRINT_NEWLINE
14 LOAD_CONST               0 (None)
17 RETURN_VALUE
```
</details>

## PyInstaller raw marshal & Pyarmor v9 static unpack-werkvloei

- **Extract embedded marshal blobs**: `pyi-archive_viewer sample.exe` en export raw objects (bv. 'n lêer genaamd `vvs`). PyInstaller stoor bare marshal streams wat met `0xe3` (TYPE_CODE with FLAG_REF) begin, eerder as volledige `.pyc`-lêers. Voeg die korrekte **16-byte `.pyc`-header** vooraan by (magic vir die embedded interpreter-weergawe + zeroed timestamp/size) sodat decompilers dit aanvaar. Vir Python 3.11.5 kan jy die magic kry met `imp.get_magic().hex()` en dit met `dd`/`printf` patch voor die marshal payload.<sup>[[2]](#references)</sup>
- **Decompile with version-aware tools**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` of PyLingual. Indien slegs gedeeltelike code benodig word, kan jy deur die AST loop (bv. `ast.NodeVisitor`) om spesifieke arguments/constants uit te trek.
- **Parse the Pyarmor v9 header** om crypto parameters te herstel: signature `PY<license>` by `0x00`, Python major/minor by `0x09/0x0a`, protection type `0x09` wanneer **BCC** enabled is (`0x08` andersins), ELF start/end offsets by `0x1c/0x38`, en die 12-byte AES-CTR nonce verdeel oor `0x24..0x27` en `0x2c..0x33`. Dieselfde patroon herhaal ná die embedded ELF.
- **Account for Pyarmor-modified code objects**: `co_flags` het bit `0x20000000` gestel en 'n ekstra length-prefixed field. Disable CPython `deopt_code()` tydens parsing om decryption failures te voorkom.
- **Identify encrypted code regions**: bytecode word omvou deur `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__`. Decrypt die ingeslote blob met AES-128-CTR deur die runtime key te gebruik (bv. `273b1b1373cf25e054a61e2cb8a947b8`). Derive die per-region nonce deur die payload-specific 12-byte XOR key (van die Pyarmor runtime) te XOR met die 12 bytes in die `__pyarmor_exit_*__` marker. Ná decryption kan jy ook `__pyarmor_assert_*__` (encrypted strings) en `__pyarmor_bcc_*__` (compiled dispatch targets) sien.
- **Decrypt Pyarmor “mixed” strings**: constants met prefix `0x81` is AES-128-CTR encrypted (plaintext gebruik `0x01`). Gebruik dieselfde key en die runtime-derived string nonce (bv. `692e767673e95c45a1e6876d`) om lang string constants te herstel.
- **Handle BCC mode**: Pyarmor `--enable-bcc` compile baie functions na 'n companion ELF en laat Python stubs agter wat `__pyarmor_bcc_*__` call. Map hierdie constants na ELF symbols met tooling soos `bcc_info.py`, en decompile/analyze die ELF by die gerapporteerde offsets (bv. `__pyarmor_bcc_58580__` → `bcc_180` by offset `0x4e70`).


## Python na Executable

Om te begin, gaan ons wys hoe payloads in py2exe en PyInstaller compiled kan word.<sup>[[1]](#references)</sup>

### Om 'n payload met py2exe te skep:

1. Installeer die py2exe package vanaf [http://www.py2exe.org/](http://www.py2exe.org)
2. Gebruik vir die payload (in hierdie geval sal ons dit hello.py noem) 'n script soos die een in Figure 1. Die opsie “bundle_files” met die waarde 1 sal alles, insluitend die Python interpreter, in een exe bundle.
3. Sodra die script gereed is, voer ons die command “python setup.py py2exe” uit. Dit sal die executable skep, soos in Figure 2.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```

### Om 'n payload met PyInstaller te skep:

1. Installeer PyInstaller met pip (`pip install pyinstaller`).
2. Daarna voer ons die opdrag “pyinstaller –onefile hello.py” uit ('n herinnering dat ‘hello.py’ ons payload is). Dit bundel alles in een uitvoerbare lêer.
