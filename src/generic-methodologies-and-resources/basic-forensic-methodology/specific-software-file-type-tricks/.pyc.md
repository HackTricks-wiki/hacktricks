## 컴파일된 바이너리에서 .pyc로

**ELF** 컴파일 바이너리에서 다음 명령으로 **.pyc**를 가져올 수 있습니다:<sup>[[1]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),

(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),

(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
컴파일된 **python exe binary**에서는 다음을 실행하여 **.pyc**를 추출할 수 있습니다:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## .pyc에서 python 코드로

**.pyc** 데이터("컴파일된" python)의 경우 **원본** **python** **코드**를 **추출**하기 시작해야 합니다:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**반드시** binary에 **extension** "**.pyc**"가 있는지 확인하세요 (그렇지 않으면 uncompyle6이 작동하지 않습니다)

**uncompyle6**을 실행하는 동안 다음 **errors**가 발생할 수 있습니다:

### Error: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
이 문제를 해결하려면 생성된 파일의 시작 부분에 **올바른 magic number**를 **추가해야 합니다**.

**Magic number는 Python 버전에 따라 다릅니다.** **Python 3.8**의 magic number를 확인하려면 **Python 3.8** 터미널을 열고 다음을 실행해야 합니다:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
이 경우 python3.8의 **magic number**는 **`0x550d0d0a`**입니다. 따라서 이 오류를 수정하려면 **.pyc file**의 **beginning**에 다음 bytes를 **add**해야 합니다: `0x0d550a0d000000000000000000000000`

**Once** 해당 magic header를 **add**하면 **error가 수정됩니다.**

다음은 올바르게 추가된 **.pyc python3.8 magic header**의 모습입니다:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### 오류: 일반적인 Decompiling 오류

`class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>`와 같은 **기타 오류**가 나타날 수 있습니다.

이는 **magic number를 올바르게 추가하지 않았거나** **올바른 magic number를 사용하지 않았음**을 의미할 가능성이 높으므로, **올바른 값을 사용했는지 확인**하거나 새 값을 시도하세요.

이전 오류 문서를 확인하세요.

## 자동 도구

[**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker)은 연구자가 Python으로 작성된 executable, 특히 py2exe 및 pyinstaller로 생성된 executable을 unpacking하고 decompiling할 수 있도록 여러 community-available tool을 결합한 도구입니다. 여기에는 executable이 Python 기반인지 식별하고 사용된 생성 도구를 확인하는 YARA rules가 포함되어 있습니다.<sup>[[4]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

일반적으로 발생하는 문제는 **unpy2exe 또는 pyinstxtractor를 사용한 unpacking process**의 결과로 Python bytecode file이 불완전해지고, Python bytecode version number가 누락되어 uncompyle6에서 이를 **인식하지 못하는 경우**입니다. 이를 해결하기 위해 필요한 Python bytecode version number를 추가하는 prepend option이 추가되었으며, 이로써 decompiling process가 가능해집니다.<sup>[[4]](#references)</sup>

문제 예시:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## python assembly 분석

이전 단계에 따라 python "original" code를 추출하지 못했다면, **assembly**를 **추출**해 볼 수 있습니다(하지만 **설명이 매우 부족**하므로, **original code를 다시** 추출해 보도록 **시도**하세요). [여기](https://bits.theorem.co/protecting-a-python-codebase/)에서 _.pyc_ binary를 **disassemble**하는 매우 간단한 code를 찾았습니다(code flow를 이해하기를 바랍니다).<sup>[[3]](#references)</sup> _.pyc_가 python2에서 생성된 것이라면 python2를 사용하세요:

<details>
<summary>.pyc Disassemble</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'r') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)
3 MAKE_FUNCTION            0

>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])

3 LOAD_ATTR                0 (format)
```

## PyInstaller raw marshal & Pyarmor v9 static unpack workflow

- **Extract embedded marshal blobs**: `pyi-archive_viewer sample.exe`를 사용하고 raw objects를 export합니다(예: `vvs`라는 파일). PyInstaller는 전체 `.pyc` 파일이 아닌, `0xe3`(`TYPE_CODE` with `FLAG_REF`)로 시작하는 bare marshal streams를 저장합니다. decompiler가 이를 인식할 수 있도록 올바른 **16-byte `.pyc` header**(embedded interpreter version에 맞는 magic + 0으로 채운 timestamp/size)를 앞에 추가합니다. Python 3.11.5의 경우 `imp.get_magic().hex()`로 magic을 가져온 뒤 `dd`/`printf`를 사용해 marshal payload 앞에 추가할 수 있습니다.<sup>[[2]](#references)</sup>
- **Decompile with version-aware tools**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` 또는 PyLingual을 사용합니다. 일부 code만 필요한 경우 AST(예: `ast.NodeVisitor`)를 순회하여 특정 arguments/constants를 추출할 수 있습니다.
- **Parse the Pyarmor v9 header** to recover crypto parameters: `0x00`의 `PY<license>` signature, `0x09/0x0a`의 Python major/minor, **BCC**가 활성화된 경우 `0x09`의 protection type(`그 외에는 `0x08`), `0x1c/0x38`의 ELF start/end offsets, 그리고 `0x24..0x27` 및 `0x2c..0x33`로 분할된 12-byte AES-CTR nonce를 확인합니다. 동일한 패턴은 embedded ELF 이후에도 반복됩니다.
- **Account for Pyarmor-modified code objects**: `co_flags`에는 bit `0x20000000`이 설정되어 있고, length-prefixed field가 추가되어 있습니다. parsing 중 복호화 실패를 방지하려면 CPython `deopt_code()`를 비활성화합니다.
- **Identify encrypted code regions**: bytecode는 `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__`로 감싸져 있습니다. runtime key(예: `273b1b1373cf25e054a61e2cb8a947b8`)를 사용해 AES-128-CTR로 내부 blob을 decrypt합니다. `__pyarmor_exit_*__` marker의 12 bytes와 payload-specific 12-byte XOR key(Pyarmor runtime에서 가져옴)를 XOR하여 region별 nonce를 도출합니다. 복호화 후 `__pyarmor_assert_*__`(encrypted strings)와 `__pyarmor_bcc_*__`(compiled dispatch targets)도 볼 수 있습니다.
- **Decrypt Pyarmor “mixed” strings**: `0x81`이 prefix로 붙은 constants는 AES-128-CTR로 encrypted되어 있습니다(plaintext는 `0x01`을 사용). 동일한 key와 runtime에서 도출한 string nonce(예: `692e767673e95c45a1e6876d`)를 사용해 긴 string constants를 복구합니다.
- **Handle BCC mode**: Pyarmor `--enable-bcc`는 많은 functions를 companion ELF로 compile하고, `__pyarmor_bcc_*__`를 호출하는 Python stubs를 남깁니다. `bcc_info.py`와 같은 tooling을 사용해 해당 constants를 ELF symbols에 매핑한 다음, 보고된 offsets에서 ELF를 decompile/analyze합니다(예: `__pyarmor_bcc_58580__` → offset `0x4e70`의 `bcc_180`).


## Python to Executable

시작하기에 앞서, payload를 py2exe와 PyInstaller로 compile하는 방법을 설명합니다.<sup>[[1]](#references)</sup>

### To create a payload using py2exe:

1. [http://www.py2exe.org/](http://www.py2exe.org)에서 py2exe package를 설치합니다.
2. payload(이 경우 이름을 hello.py로 지정)에는 Figure 1과 같은 script를 사용합니다. 값이 1인 “bundle_files” option은 Python interpreter를 포함한 모든 항목을 하나의 exe로 bundle합니다.
3. script가 준비되면 “python setup.py py2exe” command를 실행합니다. 그러면 Figure 2와 같이 executable이 생성됩니다.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```

### PyInstaller를 사용하여 payload를 생성하려면:

1. pip를 사용하여 PyInstaller를 설치합니다 (`pip install pyinstaller`).
2. 그런 다음 “pyinstaller –onefile hello.py” 명령을 실행합니다(‘hello.py’가 payload라는 점을 기억하세요). 이 명령은 모든 항목을 하나의 실행 파일로 번들링합니다.
