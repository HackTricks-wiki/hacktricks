# Decompilare di binari Python compilati (exe, elf) - Recuperare da .pyc


## Da binario compilato a .pyc

Da un **eseguibile creato con PyInstaller** (incluso un eseguibile **ELF**), puoi ispezionare ed estrarre i moduli Python incorporati con:<sup>[[6]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
Per un **eseguibile creato con PyInstaller**, estrai il suo bytecode Python incorporato con:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## Da .pyc al codice Python

Una volta ottenuto un file **.pyc**, prova a decompilarlo nuovamente nel codice sorgente Python con:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Assicurati** che il binario abbia l'**estensione** "**.pyc**" (in caso contrario, uncompyle6 non funzionerà)

Durante l'esecuzione di **uncompyle6** potresti riscontrare i **seguenti errori**:

### Errore: numero magic sconosciuto 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Per risolvere il problema, anteponi il magic number della versione di Python che ha prodotto il bytecode.

I magic number variano in base alla versione di Python. In un terminale **Python 3.8**, esegui:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
Per Python 3.8, anteponi la sequenza di quattro byte **`55 0d 0d 0a`** seguita da 12 byte nulli per creare l'header **.pyc** di 16 byte.<sup>[[7]](#references)</sup>

Riprova **uncompyle6** dopo aver aggiunto l'header.<sup>[[1]](#references)</sup>

Ecco come apparirà un **magic header .pyc python3.8** aggiunto correttamente:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Errore: Errori generici durante la decompilazione

Possono comparire **altri errori**, come: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>`.

Questo probabilmente significa che **non hai aggiunto correttamente** il magic number o che non hai **utilizzato** il **magic number corretto**; quindi **assicurati di utilizzare quello corretto** (oppure provane uno nuovo).

Controlla la documentazione dell'errore precedente.

## Automatic Tool

Il [**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) combina script di supporto per il decompressionamento e la decompilazione di eseguibili Python creati con py2exe o PyInstaller. Le sue regole YARA identificano gli eseguibili Python e distinguono questi packer.<sup>[[5]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

Quando il decompressionamento lascia un file bytecode privo dei suoi magic bytes Python, utilizza l'opzione prepend del tool per aggiungerli prima della decompilazione.<sup>[[1]](#references)[[5]](#references)</sup>

Esempio del problema:
```python

Traceback (most recent call last):
...

```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Analisi dell'assembly Python

Se la decompilazione non riesce, disassembla l'oggetto codice marshaled come fallback. Usa la versione dell'interprete che ha prodotto il bytecode (Python 2 per i file **.pyc** di Python 2).<sup>[[4]](#references)</sup>

<details>
<summary>Disassembla un .pyc</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'rb') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code

>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
```

## Workflow di unpacking statico di raw marshal PyInstaller e Pyarmor v9

Il seguente workflow è rivolto ai raw marshal payload di PyInstaller protetti con Pyarmor v9.<sup>[[3]](#references)</sup>

- **Extract embedded marshal blobs**: `pyi-archive_viewer sample.exe` ed esportare gli oggetti raw (ad esempio, un file denominato `vvs`). PyInstaller memorizza stream marshal privi di header che iniziano con `0xe3` (TYPE_CODE con FLAG_REF), invece di file `.pyc` completi. Anteporre il corretto **header `.pyc` di 16 byte** (magic relativo alla versione dell'interprete embedded + timestamp/dimensione azzerati) affinché i decompiler li accettino. Per Python 3.11.5 è possibile recuperare il magic tramite `imp.get_magic().hex()` e applicarlo con `dd`/`printf` prima del marshal payload.
- **Decompile with version-aware tools**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` oppure PyLingual. Se serve solo una parte del codice, è possibile attraversare l'AST (ad esempio, tramite `ast.NodeVisitor`) per estrarre argomenti/constanti specifici.
- **Parse the Pyarmor v9 header** per recuperare i parametri crittografici: la signature `PY<license>` a `0x00`, major/minor di Python a `0x09/0x0a`, il campo protection-type a `0x14` (`0x09` con **BCC**, `0x08` altrimenti), gli offset di inizio/fine ELF a `0x1c/0x38` e il nonce AES-CTR di 12 byte suddiviso tra `0x24..0x27` e `0x2c..0x33`. Lo stesso pattern si ripete dopo l'ELF embedded.
- **Account for Pyarmor-modified code objects**: `co_flags` ha il bit `0x20000000` impostato e un campo aggiuntivo prefissato dalla lunghezza. Disabilitare `deopt_code()` di CPython durante il parsing per evitare errori di decryption.
- **Identify encrypted code regions**: il bytecode è racchiuso tra `LOAD_CONST __pyarmor_enter_*__` e `LOAD_CONST __pyarmor_exit_*__`. Decryptare il blob contenuto usando AES-128-CTR con la runtime key (ad esempio, `273b1b1373cf25e054a61e2cb8a947b8`). Derivare il nonce specifico della regione eseguendo XOR tra la XOR key di 12 byte specifica del payload (dal Pyarmor runtime) e i 12 byte presenti nel marker `__pyarmor_exit_*__`. Dopo la decryption, possono comparire anche `__pyarmor_assert_*__` (stringhe encrypted) e `__pyarmor_bcc_*__` (compiled dispatch targets).
- **Decrypt Pyarmor “mixed” strings**: le constants con prefisso `0x81` sono encrypted con AES-128-CTR (il plaintext usa `0x01`). Usare la stessa key e il string nonce derivato dal runtime (ad esempio, `692e767673e95c45a1e6876d`) per recuperare le string constants lunghe.
- **Handle BCC mode**: Pyarmor `--enable-bcc` compila molte funzioni in un ELF companion e lascia Python stubs che chiamano `__pyarmor_bcc_*__`. Mappare queste constants ai simboli ELF con tool come `bcc_info.py`, quindi decompilare/analizzare l'ELF agli offset indicati (ad esempio, `__pyarmor_bcc_58580__` → `bcc_180` all'offset `0x4e70`).<sup>[[2]](#references)[[3]](#references)[[8]](#references)</sup>


## Da Python a Executable

Questi esempi mostrano come impacchettare uno script Python con py2exe o PyInstaller.<sup>[[1]](#references)</sup>

### Per creare un payload usando py2exe:

1. Installare [py2exe](http://www.py2exe.org/).
2. Creare un payload `hello.py` e usare uno setup script come il seguente. Impostare `bundle_files` su `1` raggruppa l'interprete Python con l'applicazione.
3. Eseguire `python setup.py py2exe` per creare l'executable.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```
