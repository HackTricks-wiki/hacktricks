## Od skompilowanego binarium do .pyc

Ze **skompilowanego za pomocą PyInstaller pliku wykonywalnego** (w tym pliku wykonywalnego **ELF**) można analizować i wyodrębniać osadzone moduły Pythona za pomocą:<sup>[[6]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
Dla **pliku wykonywalnego zbudowanego za pomocą PyInstaller** wyodrębnij osadzony Python bytecode:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## Z .pyc do kodu Pythona

Po uzyskaniu pliku **.pyc** spróbuj zdekompilować go z powrotem do kodu źródłowego Python za pomocą:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Upewnij się**, że plik binarny ma **rozszerzenie** "**.pyc**" (w przeciwnym razie uncompyle6 nie będzie działać)

Podczas wykonywania **uncompyle6** mogą wystąpić **następujące błędy**:

### Error: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Aby to naprawić, dodaj na początku numer magiczny dla wersji Python, która wygenerowała bytecode.

Numery magiczne różnią się w zależności od wersji Python. W terminalu **Python 3.8** uruchom:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
W Pythonie 3.8 dodaj przed kodem czterobajtową sekwencję **`55 0d 0d 0a`**, a następnie 12 bajtów o wartości zero, aby utworzyć 16-bajtowy nagłówek **.pyc**.<sup>[[7]](#references)</sup>

Ponownie uruchom **uncompyle6** po dodaniu nagłówka.<sup>[[1]](#references)</sup>

Tak będzie wyglądać poprawnie dodany **magic header .pyc python3.8**:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Błąd: Ogólne błędy dekompilacji

Mogą pojawić się **inne błędy**, takie jak: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>`.

Prawdopodobnie oznacza to, że **nie dodano poprawnie** liczby magicznej albo **użyto** **nieprawidłowej liczby magicznej**, więc upewnij się, że używasz **właściwej** (lub spróbuj użyć nowej).

Sprawdź wcześniejszą dokumentację błędów.

## Automatyczne narzędzie

Narzędzie [**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) łączy skrypty pomocnicze do rozpakowywania i dekompilowania plików wykonywalnych Python utworzonych za pomocą py2exe lub PyInstaller. Jego reguły YARA identyfikują pliki wykonywalne Python i rozróżniają te packery.<sup>[[5]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

Gdy rozpakowywanie pozostawi plik bytecode bez bajtów magicznych Python, użyj opcji `prepend` narzędzia, aby dodać je przed dekompilacją.<sup>[[1]](#references)[[5]](#references)</sup>

Przykład problemu:
```python

Traceback (most recent call last):
...

```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive

[+] Magic bytes are already appended.

# Successfully decompiled file
```

## Workflow statycznego unpackingu raw marshal i Pyarmor v9 dla PyInstaller

Poniższy workflow jest przeznaczony dla raw marshal payloads w PyInstaller chronionych za pomocą Pyarmor v9.<sup>[[3]](#references)</sup>

- **Extract embedded marshal blobs**: `pyi-archive_viewer sample.exe` i eksportuj raw objects (np. plik o nazwie `vvs`). PyInstaller przechowuje bare marshal streams rozpoczynające się od `0xe3` (TYPE_CODE z FLAG_REF), a nie pełne pliki `.pyc`. Dodaj właściwy **16-byte `.pyc` header** (magic dla wersji embedded interpretera + wyzerowany timestamp/size), aby decompilers mogły je zaakceptować. W Python 3.11.5 możesz pobrać magic za pomocą `imp.get_magic().hex()` i zmodyfikować go przy użyciu `dd`/`printf` przed marshal payload.
- **Decompile with version-aware tools**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` lub PyLingual. Jeśli potrzebny jest tylko częściowy kod, możesz przejść po AST (np. za pomocą `ast.NodeVisitor`), aby wyodrębnić konkretne argumenty/constants.
- **Parse the Pyarmor v9 header**, aby odzyskać crypto parameters: signature `PY<license>` pod `0x00`, Python major/minor pod `0x09/0x0a`, protection-type field pod `0x14` (`0x09` z **BCC**, `0x08` w pozostałych przypadkach), ELF start/end offsets pod `0x1c/0x38` oraz 12-byte AES-CTR nonce podzielony między `0x24..0x27` i `0x2c..0x33`. Ten sam pattern powtarza się za embedded ELF.
- **Account for Pyarmor-modified code objects**: `co_flags` ma ustawiony bit `0x20000000` oraz dodatkowe length-prefixed field. Wyłącz CPython `deopt_code()` podczas parsowania, aby uniknąć decryption failures.
- **Identify encrypted code regions**: bytecode jest opakowany przez `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__`. Odszyfruj enclosed blob za pomocą AES-128-CTR, używając runtime key (np. `273b1b1373cf25e054a61e2cb8a947b8`). Wyprowadź per-region nonce, wykonując XOR payload-specific 12-byte XOR key (z Pyarmor runtime) z 12 bajtami w markerze `__pyarmor_exit_*__`. Po odszyfrowaniu możesz również zobaczyć `__pyarmor_assert_*__` (encrypted strings) oraz `__pyarmor_bcc_*__` (compiled dispatch targets).
- **Decrypt Pyarmor “mixed” strings**: constants z prefiksem `0x81` są zaszyfrowane za pomocą AES-128-CTR (plaintext używa `0x01`). Użyj tego samego key oraz runtime-derived string nonce (np. `692e767673e95c45a1e6876d`), aby odzyskać long string constants.
- **Handle BCC mode**: Pyarmor `--enable-bcc` kompiluje wiele functions do companion ELF i pozostawia Python stubs wywołujące `__pyarmor_bcc_*__`. Zmapuj te constants do ELF symbols za pomocą narzędzi takich jak `bcc_info.py`, a następnie wykonaj decompile/analyze ELF pod zgłoszonymi offsets (np. `__pyarmor_bcc_58580__` → `bcc_180` pod offsetem `0x4e70`).<sup>[[2]](#references)[[3]](#references)[[8]](#references)</sup>


## Python to Executable

Te przykłady pokazują, jak spakować skrypt Python za pomocą py2exe lub PyInstaller.<sup>[[1]](#references)</sup>

### Aby utworzyć payload za pomocą py2exe:

1. Zainstaluj [py2exe](http://www.py2exe.org/).
2. Utwórz payload `hello.py` i użyj skryptu setup, takiego jak poniższy. Ustawienie `bundle_files` na `1` dołącza Python interpreter do aplikacji.
3. Uruchom `python setup.py py2exe`, aby utworzyć executable.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```
