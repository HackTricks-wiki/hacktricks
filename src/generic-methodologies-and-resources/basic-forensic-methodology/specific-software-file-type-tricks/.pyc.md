## Dal binario compilato a .pyc

```bash

(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),

(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),

(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
In un **binario exe Python** compilato puoi **ottenere il file .pyc** eseguendo:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## Da .pyc a codice Python

Per i dati **.pyc** (Python "compilato") dovresti iniziare tentando di **estrarre** il **codice** **Python** **originale**:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Assicurati** che il binary abbia l'**estensione** "**.pyc**" (altrimenti uncompyle6 non funzionerà)

Durante l'esecuzione di **uncompyle6** potresti riscontrare i **seguenti errori**:

### Errore: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Per risolvere questo problema devi **aggiungere il magic number corretto** all'inizio del file generato.

**I magic number variano in base alla versione di Python**; per ottenere il magic number di **Python 3.8** devi **aprire un terminale Python 3.8** ed eseguire:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
Il **magic number** in questo caso per python3.8 è **`0x550d0d0a`**; quindi, per correggere questo errore, dovrai **aggiungere** all'**inizio** del **file .pyc** i seguenti byte: `0x0d550a0d000000000000000000000000`

**Una volta** aggiunto quell'header magic, **l'errore dovrebbe essere risolto.**

Ecco come apparirà un **.pyc python3.8 magic header** aggiunto correttamente:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Errore: errori generici di decompilazione

Possono comparire **altri errori**, come: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>`.

Probabilmente significa che **non hai aggiunto correttamente** il magic number o che non hai **utilizzato** il **magic number corretto**; assicurati quindi di usare quello corretto (oppure provane uno nuovo).

Consulta la documentazione dell'errore precedente.

## Strumento automatico

Il [**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) combina diversi strumenti disponibili nella community, progettati per assistere i ricercatori nell'unpacking e nella decompilazione di eseguibili scritti in Python, in particolare quelli creati con py2exe e pyinstaller. Include regole YARA per identificare se un eseguibile è basato su Python e confermare lo strumento utilizzato per crearlo.<sup>[[4]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

Un problema comune riguarda un file di bytecode Python incompleto, risultante dal **processo di unpacking con unpy2exe o pyinstxtractor**, che quindi **non viene riconosciuto da uncompyle6 a causa dell'assenza del numero di versione del bytecode Python**. Per risolvere il problema, è stata aggiunta un'opzione prepend, che aggiunge il numero di versione del bytecode Python necessario, facilitando il processo di decompilazione.<sup>[[4]](#references)</sup>

Esempio del problema:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Analyzing python assembly

Se non sei riuscito a estrarre il codice python "original" seguendo i passaggi precedenti, puoi provare a **estrarre** l'**assembly** (ma **non è molto descrittivo**, quindi **prova** a estrarre **nuovamente** il codice original). In [questa pagina](https://bits.theorem.co/protecting-a-python-codebase/) ho trovato del codice molto semplice per **disassemble** il binario _.pyc_ (buona fortuna nel comprendere il flusso del codice).<sup>[[3]](#references)</sup> Se _.pyc_ proviene da python2, usa python2:

<details>
<summary>Disassemble a .pyc</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'r') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)

>>>
>>> # Also disassemble that const being loaded (our function)
```

## Flusso di lavoro per lo static unpack di raw marshal e Pyarmor v9 con PyInstaller

- **Estrai i marshal blob embedded**: `pyi-archive_viewer sample.exe` ed esporta gli oggetti raw (ad esempio, un file denominato `vvs`). PyInstaller memorizza bare marshal stream che iniziano con `0xe3` (TYPE_CODE con FLAG_REF) invece di file `.pyc` completi. Prependi il corretto **header `.pyc` di 16 byte** (magic della versione dell'interprete embedded + timestamp/size azzerati) affinché i decompiler li accettino. Per Python 3.11.5 puoi ottenere il magic tramite `imp.get_magic().hex()` e applicarlo con `dd`/`printf` prima del marshal payload.<sup>[[2]](#references)</sup>
- **Decompila con tool version-aware**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` oppure PyLingual. Se ti serve solo una parte del code, puoi attraversare l'AST (ad esempio, `ast.NodeVisitor`) per estrarre argomenti/constant specifici.
- **Analizza l'header di Pyarmor v9** per recuperare i parametri crittografici: signature `PY<license>` a `0x00`, major/minor di Python a `0x09/0x0a`, protection type `0x09` quando **BCC** è abilitato (`0x08` altrimenti), offset di inizio/fine dell'ELF a `0x1c/0x38` e il nonce AES-CTR di 12 byte suddiviso tra `0x24..0x27` e `0x2c..0x33`. Lo stesso pattern si ripete dopo l'ELF embedded.
- **Considera i code object modificati da Pyarmor**: `co_flags` ha il bit `0x20000000` impostato e un campo aggiuntivo con lunghezza prefissata. Disabilita `deopt_code()` di CPython durante il parsing per evitare errori di decryption.
- **Identifica le regioni di code encrypted**: il bytecode è racchiuso tra `LOAD_CONST __pyarmor_enter_*__` e `LOAD_CONST __pyarmor_exit_*__`. Decrypta il blob contenuto con AES-128-CTR usando la runtime key (ad esempio, `273b1b1373cf25e054a61e2cb8a947b8`). Deriva il nonce specifico della regione eseguendo XOR tra la payload-specific 12-byte XOR key (dal runtime di Pyarmor) e i 12 byte nel marker `__pyarmor_exit_*__`. Dopo la decryption, potresti vedere anche `__pyarmor_assert_*__` (stringhe encrypted) e `__pyarmor_bcc_*__` (compiled dispatch targets).
- **Decrypta le stringhe “mixed” di Pyarmor**: le constant con prefisso `0x81` sono encrypted con AES-128-CTR (il plaintext usa `0x01`). Usa la stessa key e il string nonce derivato dal runtime (ad esempio, `692e767673e95c45a1e6876d`) per recuperare le stringhe lunghe.
- **Gestisci la modalità BCC**: Pyarmor `--enable-bcc` compila molte funzioni in un ELF companion e lascia Python stub che chiamano `__pyarmor_bcc_*__`. Associa queste constant ai simboli ELF con tool come `bcc_info.py`, quindi decompila/analizza l'ELF agli offset indicati (ad esempio, `__pyarmor_bcc_58580__` → `bcc_180` all'offset `0x4e70`).


## Da Python a Eseguibile

Per iniziare, mostreremo come compilare i payload con py2exe e PyInstaller.<sup>[[1]](#references)</sup>

### Per creare un payload usando py2exe:

1. Installa il package py2exe da [http://www.py2exe.org/](http://www.py2exe.org)
2. Per il payload (in questo caso, lo chiameremo hello.py), usa uno script come quello nella Figura 1. L'opzione “bundle_files” con valore 1 includerà tutto, compreso l'interprete Python, in un unico exe.
3. Quando lo script è pronto, esegui il comando “python setup.py py2exe”. Questo creerà l'eseguibile, come mostrato nella Figura 2.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```

### Per creare un payload usando PyInstaller:

1. Installa PyInstaller usando pip (`pip install pyinstaller`).
2. Dopodiché, esegui il comando “pyinstaller –onefile hello.py” (ricorda che `hello.py` è il nostro payload). Questo raggrupperà tutto in un unico eseguibile.
