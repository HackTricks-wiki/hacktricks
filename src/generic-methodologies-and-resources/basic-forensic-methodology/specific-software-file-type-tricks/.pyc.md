# Décompiler des binaires Python compilés (exe, elf) - Récupérer depuis un .pyc


## Du binaire compilé vers .pyc

À partir d’un **exécutable construit avec PyInstaller** (y compris un exécutable **ELF**), vous pouvez inspecter et extraire les modules Python intégrés avec :<sup>[[6]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
Pour un **exécutable construit avec PyInstaller**, extrayez son bytecode Python intégré avec :<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## De .pyc vers du code Python

Une fois que vous avez un fichier **.pyc**, essayez de le décompiler en code source Python avec :<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Assurez-vous** que le fichier binaire possède l’**extension** "**.pyc**" (sinon, uncompyle6 ne fonctionnera pas)

Lors de l’exécution d’**uncompyle6**, vous pouvez rencontrer les **erreurs suivantes** :

### Erreur : Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Pour corriger cela, ajoutez au début le nombre magique correspondant à la version de Python qui a produit le bytecode.

Les nombres magiques varient selon la version de Python. Dans un terminal **Python 3.8**, exécutez :
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
Pour Python 3.8, préfixez la séquence de quatre octets **`55 0d 0d 0a`** suivie de 12 octets nuls pour créer l’en-tête **.pyc** de 16 octets.<sup>[[7]](#references)</sup>

Réessayez **uncompyle6** après avoir ajouté l’en-tête.<sup>[[1]](#references)</sup>

Voici à quoi ressemblera un **magic header .pyc python3.8** correctement ajouté :
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Erreur : erreurs génériques lors de la décompilation

**D'autres erreurs**, comme : `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>` peuvent apparaître.

Cela signifie probablement que vous **n'avez pas ajouté correctement** le nombre magique ou que vous n'avez pas **utilisé** le **bon nombre magique**. Assurez-vous donc d'utiliser **le bon** (ou essayez-en un nouveau).

Consultez la documentation de l'erreur précédente.

## Outil automatique

L'[**outil python-exe-unpacker**](https://github.com/countercept/python-exe-unpacker) combine des scripts auxiliaires pour désassembler et décompiler les exécutables Python créés avec py2exe ou PyInstaller. Ses règles YARA identifient les exécutables Python et distinguent ces packers.<sup>[[5]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

Lorsque le désassemblage laisse un fichier bytecode sans ses octets magiques Python, utilisez l'option prepend de l'outil pour les ajouter avant la décompilation.<sup>[[1]](#references)[[5]](#references)</sup>

Exemple du problème :
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Analyser l’assembly Python

Si la décompilation échoue, désassemblez l’objet de code marshaled comme solution de repli. Utilisez la version de l’interpréteur qui a produit le bytecode (Python 2 pour les fichiers **.pyc** de Python 2).<sup>[[4]](#references)</sup>

<details>
<summary>Désassembler un fichier .pyc</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'rb') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code

>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
```

## Workflow de static unpacking de raw marshal PyInstaller et Pyarmor v9

Le workflow suivant cible les payloads raw marshal de PyInstaller protégés avec Pyarmor v9.<sup>[[3]](#references)</sup>

- **Extract embedded marshal blobs** : `pyi-archive_viewer sample.exe` et exportez les objets bruts (par exemple, un fichier nommé `vvs`). PyInstaller stocke des flux marshal bruts qui commencent par `0xe3` (TYPE_CODE avec FLAG_REF), plutôt que des fichiers `.pyc` complets. Ajoutez le **header `.pyc` de 16 octets** correct (magic correspondant à la version de l’interpréteur embarqué + timestamp/taille mis à zéro) afin que les decompilers les acceptent. Pour Python 3.11.5, vous pouvez récupérer le magic avec `imp.get_magic().hex()` et le patcher avec `dd`/`printf` avant le payload marshal.
- **Decompile with version-aware tools** : `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` ou PyLingual. Si seul une partie du code est nécessaire, vous pouvez parcourir l’AST (par exemple avec `ast.NodeVisitor`) pour extraire des arguments/constantes spécifiques.
- **Parsez le header Pyarmor v9** pour récupérer les paramètres cryptographiques : signature `PY<license>` à `0x00`, version majeure/mineure de Python à `0x09/0x0a`, champ du type de protection à `0x14` (`0x09` avec **BCC**, `0x08` sinon), offsets de début/fin de l’ELF à `0x1c/0x38`, et le nonce AES-CTR de 12 octets réparti entre `0x24..0x27` et `0x2c..0x33`. Le même pattern se répète après l’ELF embarqué.
- **Prenez en compte les code objects modifiés par Pyarmor** : `co_flags` possède le bit `0x20000000` activé ainsi qu’un champ supplémentaire préfixé par sa longueur. Désactivez CPython `deopt_code()` pendant le parsing afin d’éviter les échecs de décryption.
- **Identifiez les régions de code chiffrées** : le bytecode est encapsulé par `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__`. Décryptez le blob inclus avec AES-128-CTR en utilisant la runtime key (par exemple, `273b1b1373cf25e054a61e2cb8a947b8`). Dérivez le nonce propre à chaque région en effectuant un XOR entre la clé XOR de 12 octets spécifique au payload (provenant de la runtime Pyarmor) et les 12 octets du marker `__pyarmor_exit_*__`. Après la décryption, vous pouvez également voir `__pyarmor_assert_*__` (strings chiffrées) et `__pyarmor_bcc_*__` (cibles de dispatch compilées).
- **Décryptez les strings “mixed” de Pyarmor** : les constantes préfixées par `0x81` sont chiffrées avec AES-128-CTR (le plaintext utilise `0x01`). Utilisez la même clé et le string nonce dérivé du runtime (par exemple, `692e767673e95c45a1e6876d`) pour récupérer les longues constantes string.
- **Gérez le mode BCC** : Pyarmor `--enable-bcc` compile de nombreuses fonctions dans un ELF companion et laisse des stubs Python qui appellent `__pyarmor_bcc_*__`. Mappez ces constantes vers les symboles ELF avec des outils tels que `bcc_info.py`, puis décompilez/analysez l’ELF aux offsets indiqués (par exemple, `__pyarmor_bcc_58580__` → `bcc_180` à l’offset `0x4e70`).<sup>[[2]](#references)[[3]](#references)[[8]](#references)</sup>


## Python vers Executable

Ces exemples montrent comment packager un script Python avec py2exe ou PyInstaller.<sup>[[1]](#references)</sup>

### Pour créer un payload avec py2exe :

1. Installez [py2exe](http://www.py2exe.org/).
2. Créez un payload `hello.py` et utilisez un setup script tel que le suivant. Définir `bundle_files` sur `1` bundle l’interpréteur Python avec l’application.
3. Exécutez `python setup.py py2exe` pour créer l’executable.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```
