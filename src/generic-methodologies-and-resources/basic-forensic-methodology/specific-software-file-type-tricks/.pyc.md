# Decompile saamgestelde Python-binaries (exe, elf) - Haal uit .pyc


## Van saamgestelde binêre lêer na .pyc

Van ’n **PyInstaller-built executable** (insluitend ’n **ELF**-uitvoerbare lêer) kan jy ingebedde Python-modules inspekteer en onttrek met:<sup>[[6]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
Vir 'n **PyInstaller-built executable**, onttrek sy ingebedde Python-bytecode met:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## Van .pyc na Python-kode

Sodra jy 'n **.pyc**-lêer het, probeer om dit met die volgende terug na Python-bronkode te dekompileer:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Maak seker** dat die binary die **extension** "**.pyc**" het (indien nie, gaan uncompyle6 nie werk nie)

Wanneer jy **uncompyle6** uitvoer, kan jy die **volgende foute** teëkom:

### Fout: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Om dit reg te stel, voeg die magic number vir die Python-weergawe wat die bytecode geproduseer het, vooraan.

Magic numbers verskil volgens Python-weergawe. Voer in ’n **Python 3.8**-terminal uit:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
Vir Python 3.8, voeg die viergrepevolgorde **`55 0d 0d 0a`** gevolg deur 12 nulgrepe vooraan om die 16-grepe **.pyc**-header te skep.<sup>[[7]](#references)</sup>

Probeer **uncompyle6** weer nadat die header bygevoeg is.<sup>[[1]](#references)</sup>

So sal ’n korrek bygevoegde **.pyc python3.8 magic header** lyk:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Fout: Decompiling van generiese foute

**Ander foute** soos: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>` mag voorkom.

Dit beteken waarskynlik dat jy **nie die magic number korrek bygevoeg het nie**, of dat jy **nie die korrekte magic number gebruik het nie**. Maak dus **seker dat jy die korrekte een gebruik** (of probeer ’n nuwe een).

Gaan die vorige foutdokumentasie na.

## Automatic Tool

Die [**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) kombineer helper scripts vir die unpacking en decompiling van Python-executables wat met py2exe of PyInstaller geskep is. Sy YARA-reëls identifiseer Python-executables en onderskei daardie packers.<sup>[[5]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

Wanneer unpacking ’n bytecode-lêer sonder sy Python magic bytes laat, gebruik die tool se prepend-opsie om dit by te voeg voordat jy decompiling uitvoer.<sup>[[1]](#references)[[5]](#references)</sup>

Voorbeeld van die probleem:
```python
# Error when attempting to decompile without the prepend option

Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive

[+] Magic bytes are already appended.
```

## Ontleding van python-assembly

As dekompilering misluk, disassembleer die marshaled code object as ’n terugvalopsie. Gebruik die interpreter-weergawe wat die bytecode geproduseer het (Python 2 vir Python 2 **.pyc**-lêers).<sup>[[4]](#references)</sup>

<details>
<summary>Disassembleer ’n .pyc</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'rb') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)
3 MAKE_FUNCTION            0
6 STORE_NAME               0 (hello_world)
9 LOAD_CONST               1 (None)
12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])
2           0 LOAD_CONST               1 ('Hello  {0}')
3 LOAD_ATTR                0 (format)
6 LOAD_FAST                0 (name)
9 CALL_FUNCTION            1
12 PRINT_ITEM
13 PRINT_NEWLINE
14 LOAD_CONST               0 (None)
17 RETURN_VALUE
```

## PyInstaller raw marshal & Pyarmor v9 static unpack-werkvloei

Die volgende werkvloei teiken PyInstaller raw marshal payloads wat met Pyarmor v9 beskerm word.<sup>[[3]](#references)</sup>

- **Onttrek ingebedde marshal-blobs**: `pyi-archive_viewer sample.exe` en exporteer raw objects (byvoorbeeld ’n lêer genaamd `vvs`). PyInstaller stoor bare marshal streams wat met `0xe3` (TYPE_CODE with FLAG_REF) begin, eerder as volledige `.pyc`-lêers. Voeg die korrekte **16-byte `.pyc`-header** vooraf (magic vir die ingebedde interpreter-weergawe + nulgevulde timestamp/size) sodat decompilers dit aanvaar. Vir Python 3.11.5 kan jy die magic met `imp.get_magic().hex()` verkry en dit met `dd`/`printf` patch voordat die marshal payload volg.
- **Decompile met weergawe-bewuste tools**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` of PyLingual. As slegs gedeeltelike code benodig word, kan jy deur die AST loop (byvoorbeeld `ast.NodeVisitor`) om spesifieke arguments/constants uit te trek.
- **Parse die Pyarmor v9-header** om crypto parameters te herwin: signature `PY<license>` by `0x00`, Python major/minor by `0x09/0x0a`, die protection-type-veld by `0x14` (`0x09` met **BCC**, `0x08` andersins), ELF begin/eind-offsets by `0x1c/0x38`, en die 12-byte AES-CTR nonce versprei oor `0x24..0x27` en `0x2c..0x33`. Dieselfde patroon herhaal ná die ingebedde ELF.
- **Neem Pyarmor-modified code objects in ag**: `co_flags` het bit `0x20000000` gestel en ’n ekstra length-prefixed field. Deaktiveer CPython `deopt_code()` tydens parsing om decryption failures te voorkom.
- **Identifiseer encrypted code regions**: bytecode word omvou deur `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__`. Decrypt die ingeslote blob met AES-128-CTR deur die runtime key (byvoorbeeld `273b1b1373cf25e054a61e2cb8a947b8`) te gebruik. Lei die per-region nonce af deur die payload-specific 12-byte XOR key (uit die Pyarmor runtime) te XOR met die 12 bytes in die `__pyarmor_exit_*__`-marker. Ná decryption kan jy ook `__pyarmor_assert_*__` (encrypted strings) en `__pyarmor_bcc_*__` (compiled dispatch targets) sien.
- **Decrypt Pyarmor “mixed” strings**: constants met `0x81` as prefix is AES-128-CTR encrypted (plaintext gebruik `0x01`). Gebruik dieselfde key en die runtime-derived string nonce (byvoorbeeld `692e767673e95c45a1e6876d`) om lang string constants te herwin.
- **Hanteer BCC mode**: Pyarmor `--enable-bcc` compileer baie functions na ’n companion ELF en laat Python stubs wat `__pyarmor_bcc_*__` aanroep. Map hierdie constants na ELF symbols met tooling soos `bcc_info.py`, en decompile/analyzeer dan die ELF by die gerapporteerde offsets (byvoorbeeld `__pyarmor_bcc_58580__` → `bcc_180` by offset `0x4e70`).<sup>[[2]](#references)[[3]](#references)[[8]](#references)</sup>


## Python na Executable

Hierdie examples wys hoe om ’n Python-script met py2exe of PyInstaller te package.<sup>[[1]](#references)</sup>

### Om ’n payload met py2exe te skep:

1. Installeer [py2exe](http://www.py2exe.org/).
2. Skep ’n `hello.py`-payload en gebruik ’n setup-script soos die volgende. Deur `bundle_files` op `1` te stel, word die Python-interpreter saam met die application gebundel.
3. Run `python setup.py py2exe` om die executable te skep.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```
