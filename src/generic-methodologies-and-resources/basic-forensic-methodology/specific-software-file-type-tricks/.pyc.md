## De binario compilado a .pyc

Desde un **ejecutable creado con PyInstaller** (incluido un ejecutable **ELF**), puedes inspeccionar y extraer módulos de Python integrados con:<sup>[[6]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
Para un **ejecutable creado con PyInstaller**, extrae su bytecode de Python integrado:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## De .pyc a código Python

Una vez que tengas un archivo **.pyc**, intenta descompilarlo de nuevo a código fuente de Python con:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Asegúrate** de que el binario tenga la **extensión** "**.pyc**" (si no, uncompyle6 no funcionará)

Al ejecutar **uncompyle6**, podrías encontrar los **siguientes errores**:

### Error: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Para solucionarlo, antepón el número mágico de la versión de Python que produjo el bytecode.

Los números mágicos varían según la versión de Python. En una terminal de **Python 3.8**, ejecuta:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
Para Python 3.8, antepón la secuencia de cuatro bytes **`55 0d 0d 0a`** seguida de 12 bytes cero para crear la cabecera de 16 bytes de **.pyc**.<sup>[[7]](#references)</sup>

Vuelve a ejecutar **uncompyle6** después de añadir la cabecera.<sup>[[1]](#references)</sup>

Así se verá una **cabecera mágica de .pyc de Python 3.8** añadida correctamente:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Error: Errores genéricos al descompilar

Pueden aparecer **otros errores**, como: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>`.

Esto probablemente significa que **no has añadido correctamente** el número mágico o que no has **utilizado** el **número mágico correcto**, así que **asegúrate de utilizar el correcto** (o prueba con uno nuevo).

Consulta la documentación del error anterior.

## Automatic Tool

La [**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) combina scripts auxiliares para desempaquetar y descompilar ejecutables de Python creados con py2exe o PyInstaller. Sus reglas de YARA identifican los ejecutables de Python y distinguen esos packers.<sup>[[5]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

Cuando el desempaquetado deja un archivo de bytecode sin sus bytes mágicos de Python, utiliza la opción prepend de la herramienta para añadirlos antes de descompilarlo.<sup>[[1]](#references)[[5]](#references)</sup>

Ejemplo del problema:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Análisis del assembly de Python

Si la decompilación falla, desensambla el objeto de código marshalizado como alternativa. Usa la versión del intérprete que produjo el bytecode (Python 2 para archivos **.pyc** de Python 2).<sup>[[4]](#references)</sup>

<details>
<summary>Desensamblar un .pyc</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'rb') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)

3 MAKE_FUNCTION            0

9 LOAD_CONST               1 (None)
12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])
```

## Flujo de desempaquetado estático de raw marshal de PyInstaller y Pyarmor v9

El siguiente flujo está dirigido a raw marshal payloads de PyInstaller protegidos con Pyarmor v9.<sup>[[3]](#references)</sup>

- **Extraer blobs marshal incrustados**: `pyi-archive_viewer sample.exe` y exportar objetos raw (por ejemplo, un archivo llamado `vvs`). PyInstaller almacena streams marshal sin formato que comienzan con `0xe3` (TYPE_CODE con FLAG_REF), en lugar de archivos `.pyc` completos. Anteponer el **header `.pyc` de 16 bytes** correcto (magic correspondiente a la versión del intérprete incrustado + timestamp/tamaño puestos a cero) para que los decompilers los acepten. Para Python 3.11.5, puedes obtener el magic mediante `imp.get_magic().hex()` y modificarlo con `dd`/`printf` antes del marshal payload.
- **Decompilar con herramientas que tengan en cuenta la versión**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` o PyLingual. Si solo se necesita código parcial, puedes recorrer el AST (por ejemplo, `ast.NodeVisitor`) para extraer argumentos/constantes específicos.
- **Analizar el header de Pyarmor v9** para recuperar los parámetros criptográficos: firma `PY<license>` en `0x00`, versión major/minor de Python en `0x09/0x0a`, campo de tipo de protección en `0x14` (`0x09` con **BCC**, `0x08` en caso contrario), offsets de inicio/final de ELF en `0x1c/0x38`, y el nonce AES-CTR de 12 bytes dividido entre `0x24..0x27` y `0x2c..0x33`. El mismo patrón se repite después del ELF incrustado.
- **Tener en cuenta los code objects modificados por Pyarmor**: `co_flags` tiene establecido el bit `0x20000000` y un campo adicional con longitud prefijada. Deshabilitar `deopt_code()` de CPython durante el análisis para evitar fallos de descifrado.
- **Identificar las regiones de código cifradas**: el bytecode está envuelto por `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__`. Descifrar el blob incluido con AES-128-CTR usando la runtime key (por ejemplo, `273b1b1373cf25e054a61e2cb8a947b8`). Derivar el nonce por región haciendo XOR entre la payload-specific 12-byte XOR key (del runtime de Pyarmor) y los 12 bytes del marcador `__pyarmor_exit_*__`. Después del descifrado, también pueden aparecer `__pyarmor_assert_*__` (encrypted strings) y `__pyarmor_bcc_*__` (compiled dispatch targets).
- **Descifrar los strings “mixed” de Pyarmor**: las constantes con prefijo `0x81` están cifradas con AES-128-CTR (el plaintext usa `0x01`). Usar la misma key y el string nonce derivado del runtime (por ejemplo, `692e767673e95c45a1e6876d`) para recuperar constantes string largas.
- **Gestionar el modo BCC**: Pyarmor `--enable-bcc` compila muchas funciones en un ELF complementario y deja stubs de Python que llaman a `__pyarmor_bcc_*__`. Asociar esas constantes con símbolos ELF mediante herramientas como `bcc_info.py` y, después, decompilar/analizar el ELF en los offsets indicados (por ejemplo, `__pyarmor_bcc_58580__` → `bcc_180` en el offset `0x4e70`).<sup>[[2]](#references)[[3]](#references)[[8]](#references)</sup>


## Python a ejecutable

Estos ejemplos muestran cómo empaquetar un script de Python con py2exe o PyInstaller.<sup>[[1]](#references)</sup>

### Para crear un payload usando py2exe:

1. Instalar [py2exe](http://www.py2exe.org/).
2. Crear un payload `hello.py` y usar un setup script como el siguiente. Establecer `bundle_files` en `1` empaqueta el intérprete de Python con la aplicación.
3. Ejecutar `python setup.py py2exe` para crear el ejecutable.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```
