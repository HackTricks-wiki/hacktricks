## Von der kompilierten Binary zu .pyc

Aus einer kompilierten **ELF**-Binary kannst du die **.pyc**-Datei wie folgt erhalten:<sup>[[1]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
In einer kompilierten **python exe binary** kannst du die **.pyc** erhalten, indem du Folgendes ausführst:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## Von .pyc zu Python-Code

Für die **.pyc**-Daten („kompiliertes“ Python) solltest du damit beginnen, den **ursprünglichen** **Python**-**Code** zu **extrahieren**:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Stelle sicher**, dass die Binärdatei die **Erweiterung** "**.pyc**" hat (andernfalls wird uncompyle6 nicht funktionieren).

Beim Ausführen von **uncompyle6** können die **folgenden Fehler** auftreten:

### Fehler: Unbekannte Magic Number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Um dies zu beheben, musst du am Anfang der generierten Datei die **korrekte magic number** hinzufügen.

**Magic numbers variieren je nach Python-Version**. Um die magic number von **Python 3.8** zu erhalten, musst du ein **Python-3.8**-Terminal öffnen und Folgendes ausführen:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
Die **magic number** in diesem Fall für Python 3.8 ist **`0x550d0d0a`**. Um diesen Fehler zu beheben, müssen Sie am **Anfang** der **.pyc-Datei** die folgenden Bytes **hinzufügen**: `0x0d550a0d000000000000000000000000`

**Sobald** Sie diesen magic header **hinzugefügt** haben, sollte der **Fehler behoben sein.**

So sieht ein korrekt hinzugefügter **.pyc-Python-3.8-magic-header** aus:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Fehler: Allgemeine Fehler beim Decompilieren

**Weitere Fehler** wie: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>` können auftreten.

Das bedeutet wahrscheinlich, dass du die Magic Number **nicht korrekt hinzugefügt** oder die **falsche Magic Number verwendet** hast. Stelle daher **sicher, dass du die richtige verwendest** (oder probiere eine neue aus).

Siehe die Dokumentation zum vorherigen Fehler.

## Automatisches Tool

Das [**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) kombiniert mehrere für die Community verfügbare Tools, die Forschende beim Unpacking und Decompilieren von mit Python geschriebenen Executables unterstützen, insbesondere solchen, die mit py2exe und pyinstaller erstellt wurden. Es enthält YARA-Regeln, um zu erkennen, ob ein Executable auf Python basiert, und bestätigt das verwendete Erstellungstool.<sup>[[4]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

Ein häufig auftretendes Problem ist eine unvollständige Python-Bytecode-Datei, die durch den **Unpacking-Prozess mit unpy2exe oder pyinstxtractor** entsteht und anschließend von uncompyle6 aufgrund einer fehlenden Python-Bytecode-Versionsnummer **nicht erkannt werden kann**. Um dieses Problem zu beheben, wurde eine Prepend-Option hinzugefügt, die die erforderliche Python-Bytecode-Versionsnummer anhängt und dadurch den Decompiling-Prozess ermöglicht.<sup>[[4]](#references)</sup>

Beispiel für das Problem:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Python-Assembly analysieren

Wenn du den Python-„Originalcode“ nach den vorherigen Schritten nicht extrahieren konntest, kannst du versuchen, die **Assembly** zu **extrahieren** (aber sie ist **nicht sehr aussagekräftig**, also **versuche**, den Originalcode **erneut** zu extrahieren). Unter [diesem Link](https://bits.theorem.co/protecting-a-python-codebase/) habe ich einfachen Code gefunden, um die _.pyc_-Binärdatei zu **disassemblieren** (viel Glück beim Verstehen des Code-Ablaufs).<sup>[[3]](#references)</sup> Wenn die _.pyc_-Datei von python2 stammt, verwende python2:

<details>
<summary>Eine .pyc disassemblieren</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'r') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)
3 MAKE_FUNCTION            0
6 STORE_NAME               0 (hello_world)
9 LOAD_CONST               1 (None)
12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])
2           0 LOAD_CONST               1 ('Hello  {0}')
3 LOAD_ATTR                0 (format)
6 LOAD_FAST                0 (name)
9 CALL_FUNCTION            1
12 PRINT_ITEM
13 PRINT_NEWLINE
14 LOAD_CONST               0 (None)
17 RETURN_VALUE
```

## PyInstaller raw marshal & Pyarmor v9 statischer Unpack-Workflow

- **Eingebettete marshal-Blobs extrahieren**: `pyi-archive_viewer sample.exe` ausführen und rohe Objekte exportieren (z. B. eine Datei namens `vvs`). PyInstaller speichert reine marshal-Streams, die mit `0xe3` (TYPE_CODE mit FLAG_REF) beginnen, anstatt vollständige `.pyc`-Dateien zu verwenden. Den korrekten **16-Byte-`.pyc`-Header** (Magic für die Version des eingebetteten Interpreters + auf null gesetzter Zeitstempel/Größe) voranstellen, damit Decompiler sie akzeptieren. Für Python 3.11.5 kann die Magic-Zahl mit `imp.get_magic().hex()` ausgelesen und mit `dd`/`printf` vor dem marshal-Payload eingefügt werden.<sup>[[2]](#references)</sup>
- **Mit versionsabhängigen Tools dekompilieren**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` oder PyLingual. Wenn nur ein Teil des Codes benötigt wird, kann der AST durchlaufen werden (z. B. mit `ast.NodeVisitor`), um bestimmte Argumente/Konstanten zu extrahieren.
- **Den Pyarmor-v9-Header parsen**, um die Krypto-Parameter wiederherzustellen: Signatur `PY<license>` bei `0x00`, Python-Major-/Minor-Version bei `0x09/0x0a`, Schutztyp `0x09`, wenn **BCC** aktiviert ist (`0x08` andernfalls), ELF-Start-/End-Offsets bei `0x1c/0x38` sowie die 12-Byte-AES-CTR-Nonce, aufgeteilt über `0x24..0x27` und `0x2c..0x33`. Dasselbe Muster wiederholt sich nach dem eingebetteten ELF.
- **Durch Pyarmor modifizierte Code-Objekte berücksichtigen**: `co_flags` hat das gesetzte Bit `0x20000000` sowie ein zusätzliches längenpräfixiertes Feld. CPythons `deopt_code()` beim Parsen deaktivieren, um Entschlüsselungsfehler zu vermeiden.
- **Verschlüsselte Codebereiche identifizieren**: Bytecode wird durch `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__` eingeschlossen. Den enthaltenen Blob mit AES-128-CTR unter Verwendung des Runtime-Schlüssels entschlüsseln (z. B. `273b1b1373cf25e054a61e2cb8a947b8`). Die Nonce für die jeweilige Region durch XOR-Verknüpfung des payload-spezifischen 12-Byte-XOR-Schlüssels (aus der Pyarmor-Runtime) mit den 12 Bytes im Marker `__pyarmor_exit_*__` ableiten. Nach der Entschlüsselung können auch `__pyarmor_assert_*__` (verschlüsselte Strings) und `__pyarmor_bcc_*__` (kompilierte Dispatch-Ziele) erscheinen.
- **Pyarmors „mixed“-Strings entschlüsseln**: Mit `0x81` präfixierte Konstanten sind mit AES-128-CTR verschlüsselt (Klartext verwendet `0x01`). Denselben Schlüssel und die von der Runtime abgeleitete String-Nonce (z. B. `692e767673e95c45a1e6876d`) verwenden, um lange String-Konstanten wiederherzustellen.
- **BCC-Modus behandeln**: Pyarmors `--enable-bcc` kompiliert viele Funktionen in ein Companion-ELF und hinterlässt Python-Stubs, die `__pyarmor_bcc_*__` aufrufen. Diese Konstanten mit Tools wie `bcc_info.py` ELF-Symbolen zuordnen und anschließend das ELF an den angegebenen Offsets dekompilieren/analysieren (z. B. `__pyarmor_bcc_58580__` → `bcc_180` am Offset `0x4e70`).


## Python zu Executable

Zunächst zeigen wir, wie payloads mit py2exe und PyInstaller kompiliert werden können.<sup>[[1]](#references)</sup>

### Einen payload mit py2exe erstellen:

1. Das py2exe-Paket von [http://www.py2exe.org/](http://www.py2exe.org) installieren.
2. Für den payload (in diesem Fall nennen wir ihn hello.py) ein Skript wie in Abbildung 1 verwenden. Die Option „bundle_files“ mit dem Wert 1 bündelt alles, einschließlich des Python-Interpreters, in eine einzelne exe.
3. Sobald das Skript fertig ist, den Befehl „python setup.py py2exe“ ausführen. Dadurch wird das Executable erstellt, wie in Abbildung 2 dargestellt.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```

### So erstellen Sie einen Payload mit PyInstaller:

1. Installieren Sie PyInstaller mit pip (`pip install pyinstaller`).
2. Danach führen wir den Befehl „pyinstaller –onefile hello.py“ aus (zur Erinnerung: „hello.py“ ist unser Payload). Dadurch wird alles in eine ausführbare Datei gebündelt.
