## Від скомпільованого бінарного файлу до .pyc

З **виконуваного файлу, створеного за допомогою PyInstaller** (зокрема **ELF**-виконуваного файлу), можна переглядати й видобувати вбудовані Python-модулі за допомогою:<sup>[[6]](#references)</sup>
```bash
pyi-archive_viewer <binary>
# The list of python modules will be given here:
[(0, 230, 311, 1, 'm', 'struct'),
(230, 1061, 1792, 1, 'm', 'pyimod01_os_path'),
(1291, 4071, 8907, 1, 'm', 'pyimod02_archive'),
(5362, 5609, 13152, 1, 'm', 'pyimod03_importers'),
(10971, 1473, 3468, 1, 'm', 'pyimod04_ctypes'),
(12444, 816, 1372, 1, 's', 'pyiboot01_bootstrap'),
(13260, 696, 1053, 1, 's', 'pyi_rth_pkgutil'),
(13956, 1134, 2075, 1, 's', 'pyi_rth_multiprocessing'),
(15090, 445, 672, 1, 's', 'pyi_rth_inspect'),
(15535, 2514, 4421, 1, 's', 'binary_name'),
...

? X binary_name
to filename? /tmp/binary.pyc
```
Для **виконуваного файлу, створеного за допомогою PyInstaller**, витягніть вбудований байткод Python:<sup>[[1]](#references)</sup>
```bash
python pyinstxtractor.py executable.exe
```
## Від .pyc до коду Python

Якщо у вас є файл **.pyc**, спробуйте декомпілювати його назад у вихідний код Python за допомогою:<sup>[[1]](#references)</sup>
```bash
uncompyle6 binary.pyc  > decompiled.py
```
**Переконайтеся**, що бінарний файл має **розширення** "**.pyc**" (якщо ні, uncompyle6 не працюватиме)

Під час виконання **uncompyle6** ви можете зіткнутися з **такими помилками**:

### Error: Unknown magic number 227
```bash
/kali/.local/bin/uncompyle6 /tmp/binary.pyc
Unknown magic number 227 in /tmp/binary.pyc
```
Щоб виправити це, додайте на початок magic number для версії Python, яка створила bytecode.

Magic numbers відрізняються залежно від версії Python. У терміналі **Python 3.8** виконайте:
```
>> import imp
>> imp.get_magic().hex()
'550d0d0a'
```
Для Python 3.8 додайте на початок чотирибайтову послідовність **`55 0d 0d 0a`**, після якої мають іти 12 нульових байтів, щоб створити 16-байтовий заголовок **.pyc**.<sup>[[7]](#references)</sup>

Повторно запустіть **uncompyle6** після додавання заголовка.<sup>[[1]](#references)</sup>

Ось як виглядатиме правильно доданий **.pyc python3.8 magic header**:
```bash
hexdump 'binary.pyc' | head
0000000 0d55 0a0d 0000 0000 0000 0000 0000 0000
0000010 00e3 0000 0000 0000 0000 0000 0000 0000
0000020 0700 0000 4000 0000 7300 0132 0000 0064
0000030 0164 006c 005a 0064 0164 016c 015a 0064
```
### Помилка: загальні помилки декомпіляції

**Інші помилки**, як-от: `class 'AssertionError'>; co_code should be one of the types (<class 'str'>, <class 'bytes'>, <class 'list'>, <class 'tuple'>); is type <class 'NoneType'>`, також можуть з'являтися.

Ймовірно, це означає, що ви **неправильно додали** magic number або **використали** **неправильний magic number**, тому **переконайтеся, що використовуєте правильний** (або спробуйте новий).

Перегляньте попередню документацію щодо помилки.

## Автоматичний інструмент

[**python-exe-unpacker tool**](https://github.com/countercept/python-exe-unpacker) об'єднує допоміжні скрипти для розпакування та декомпіляції Python-виконуваних файлів, створених за допомогою py2exe або PyInstaller. Його правила YARA ідентифікують Python-виконувані файли та розрізняють ці пакувальники.<sup>[[5]](#references)</sup>

### ImportError: File name: 'unpacked/malware_3.exe/**pycache**/archive.cpython-35.pyc' doesn't exist

Якщо після розпакування файл bytecode не містить Python magic bytes, використайте опцію `prepend` інструмента, щоб додати їх перед декомпіляцією.<sup>[[1]](#references)[[5]](#references)</sup>

Приклад проблеми:
```python
# Error when attempting to decompile without the prepend option
test@test: uncompyle6 unpacked/malware_3.exe/archive.py
Traceback (most recent call last):
...
ImportError: File name: 'unpacked/malware_3.exe/__pycache__/archive.cpython-35.pyc' doesn't exist
```

```python
# Successful decompilation after using the prepend option
test@test:python python_exe_unpack.py -p unpacked/malware_3.exe/archive
[*] On Python 2.7
[+] Magic bytes are already appended.

# Successfully decompiled file
[+] Successfully decompiled.
```
## Аналіз Python assembly

Якщо декомпіляція не вдалася, як запасний варіант дизасемблюйте marshaled code object. Використовуйте версію інтерпретатора, яка створила bytecode (Python 2 для файлів **.pyc** Python 2).<sup>[[4]](#references)</sup>

<details>
<summary>Дизасемблювання .pyc</summary>
```python
>>> import dis
>>> import marshal
>>> import struct
>>> import imp
>>>
>>> with open('hello.pyc', 'rb') as f:  # Read the binary file
...     magic = f.read(4)
...     timestamp = f.read(4)
...     code = f.read()
...
>>>
>>> # Unpack the structured content and un-marshal the code
>>> magic = struct.unpack('<H', magic[:2])
>>> timestamp = struct.unpack('<I', timestamp)
>>> code = marshal.loads(code)
>>> magic, timestamp, code
((62211,), (1425911959,), <code object <module> at 0x7fd54f90d5b0, file "hello.py", line 1>)
>>>
>>> # Verify if the magic number corresponds with the current python version
>>> struct.unpack('<H', imp.get_magic()[:2]) == magic
True
>>>
>>> # Disassemble the code object
>>> dis.disassemble(code)
1           0 LOAD_CONST               0 (<code object hello_world at 0x7f31b7240eb0, file "hello.py", line 1>)
3 MAKE_FUNCTION            0
6 STORE_NAME               0 (hello_world)
9 LOAD_CONST               1 (None)
12 RETURN_VALUE
>>>
>>> # Also disassemble that const being loaded (our function)
>>> dis.disassemble(code.co_consts[0])
2           0 LOAD_CONST               1 ('Hello  {0}')
3 LOAD_ATTR                0 (format)
6 LOAD_FAST                0 (name)
9 CALL_FUNCTION            1
12 PRINT_ITEM
13 PRINT_NEWLINE
14 LOAD_CONST               0 (None)
17 RETURN_VALUE
```
</details>

## PyInstaller raw marshal і статичний unpack workflow для Pyarmor v9

Наведений workflow призначений для raw marshal payloads PyInstaller, захищених Pyarmor v9.<sup>[[3]](#references)</sup>

- **Extract embedded marshal blobs**: `pyi-archive_viewer sample.exe` і export raw objects (наприклад, файл із назвою `vvs`). PyInstaller зберігає bare marshal streams, які починаються з `0xe3` (TYPE_CODE with FLAG_REF), а не повні `.pyc` files. Додайте на початок правильний **16-byte `.pyc` header** (magic для версії embedded interpreter + zeroed timestamp/size), щоб decompilers могли їх прийняти. Для Python 3.11.5 magic можна отримати через `imp.get_magic().hex()` і пропатчити його за допомогою `dd`/`printf` перед marshal payload.
- **Decompile with version-aware tools**: `pycdc -c -v 3.11.5 vvs.pyc > vvs.py` або PyLingual. Якщо потрібна лише частина коду, можна пройти AST (наприклад, за допомогою `ast.NodeVisitor`), щоб витягнути конкретні arguments/constants.
- **Parse the Pyarmor v9 header**, щоб відновити crypto parameters: signature `PY<license>` за адресою `0x00`, Python major/minor за адресами `0x09/0x0a`, protection-type field за адресою `0x14` (`0x09` з **BCC**, `0x08` в інших випадках), ELF start/end offsets за адресами `0x1c/0x38` і 12-byte AES-CTR nonce, розділений між `0x24..0x27` і `0x2c..0x33`. Та сама структура повторюється після embedded ELF.
- **Account for Pyarmor-modified code objects**: `co_flags` має встановлений bit `0x20000000` і додаткове length-prefixed field. Вимкніть CPython `deopt_code()` під час parsing, щоб уникнути decryption failures.
- **Identify encrypted code regions**: bytecode обгорнутий `LOAD_CONST __pyarmor_enter_*__` … `LOAD_CONST __pyarmor_exit_*__`. Розшифруйте enclosed blob за допомогою AES-128-CTR, використовуючи runtime key (наприклад, `273b1b1373cf25e054a61e2cb8a947b8`). Отримайте per-region nonce, виконавши XOR payload-specific 12-byte XOR key (із Pyarmor runtime) із 12 байтами в маркері `__pyarmor_exit_*__`. Після decryption також можуть зустрічатися `__pyarmor_assert_*__` (encrypted strings) і `__pyarmor_bcc_*__` (compiled dispatch targets).
- **Decrypt Pyarmor “mixed” strings**: constants із префіксом `0x81` зашифровані AES-128-CTR (plaintext використовує `0x01`). Використайте той самий key і runtime-derived string nonce (наприклад, `692e767673e95c45a1e6876d`), щоб відновити довгі string constants.
- **Handle BCC mode**: Pyarmor `--enable-bcc` компілює багато functions у companion ELF і залишає Python stubs, які викликають `__pyarmor_bcc_*__`. Зіставте ці constants із ELF symbols за допомогою tooling на кшталт `bcc_info.py`, а потім decompile/analyze ELF за вказаними offsets (наприклад, `__pyarmor_bcc_58580__` → `bcc_180` за offset `0x4e70`).<sup>[[2]](#references)[[3]](#references)[[8]](#references)</sup>


## Python to Executable

Ці приклади показують, як package Python script за допомогою py2exe або PyInstaller.<sup>[[1]](#references)</sup>

### To create a payload using py2exe:

1. Install [py2exe](http://www.py2exe.org/).
2. Створіть `hello.py` payload і використайте setup script, наприклад наведений нижче. Встановлення `bundle_files` у значення `1` bundling Python interpreter разом із application.
3. Запустіть `python setup.py py2exe`, щоб створити executable.
```python
from distutils.core import setup
import py2exe, sys, os

sys.argv.append('py2exe')

setup(
options = {'py2exe': {'bundle_files': 1}},
#windows = [{'script': "hello.py"}],
console = [{'script': "hello.py"}],
zipfile = None,
)
```

### Щоб створити payload за допомогою PyInstaller:

1. Встановіть PyInstaller: `pip install pyinstaller`.
2. Створіть виконуваний файл в одному файлі за допомогою `pyinstaller --onefile hello.py`.
