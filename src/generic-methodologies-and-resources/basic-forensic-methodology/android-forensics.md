## Κλειδωμένη συσκευή

Προτιμήστε μεθόδους απόκτησης που διατηρούν την κατάσταση της συσκευής και τεκμηριώστε κάθε ενέργεια. Αν η συσκευή είναι κλειδωμένη, οι διαθέσιμες επιλογές εξαρτώνται από το μοντέλο, την έκδοση Android, το επίπεδο ενημερώσεων ασφαλείας και το αν είχε ρυθμιστεί η πρόσβαση πριν από την κατάσχεση. Το NIST συνιστά την επιλογή μεθόδου ανάλογα με τη συσκευή και την εξουσιοδότηση για την εξέταση.<sup>[[1]](#references)</sup>

- Ελέγξτε αν ήταν ενεργοποιημένο το USB debugging και αν ο σταθμός εργασίας απόκτησης είχε ήδη εξουσιοδοτηθεί. Η πρόσβαση μέσω ADB συνήθως απαιτεί από τον χρήστη να ξεκλειδώσει τη συσκευή και να επιβεβαιώσει το RSA key του σταθμού εργασίας.<sup>[[3]](#references)</sup>
- Εξετάστε αν εξακολουθεί να είναι διαθέσιμη η βιομετρική πρόσβαση, σύμφωνα με τους ισχύοντες νομικούς και διαδικαστικούς κανόνες.
- Μια **smudge attack** μπορεί να αποκαλύψει ένα μοτίβο γραφικού ξεκλειδώματος από τα υπολείμματα στην οθόνη, αν και τα επόμενα αγγίγματα και ο καθαρισμός μειώνουν την αξιοπιστία της.<sup>[[2]](#references)</sup>
- Αν τα εξουσιοδοτημένα εργαλεία υποστηρίζουν τη συγκεκριμένη συσκευή και έκδοση λογισμικού, μπορεί να επιχειρήσουν ανάκτηση PIN, κωδικού πρόσβασης ή μοτίβου, ή brute force. Η επαλήθευση διαπιστευτηρίων με υποστήριξη υλικού, οι καθυστερήσεις επανάληψης και οι πολιτικές διαγραφής καθιστούν αυτή τη διαδικασία εξαιρετικά συγκεκριμένη για κάθε συσκευή. Επομένως, μην θεωρείτε ότι μια τεχνική ή ένα αποτέλεσμα για iPhone αποδεικνύει ότι υποστηρίζεται και μια συσκευή Android.<sup>[[1]](#references)</sup>

## Απόκτηση δεδομένων

Σε παλαιότερες συσκευές, ένα παλαιού τύπου [ADB backup](../../mobile-pentesting/android-app-pentesting/adb-commands.md#legacy-adb-backup) μπορεί να δημιουργήσει ένα αρχείο `.backup`, το οποίο μπορεί να αποσυμπιέσει το Android Backup Extractor:<sup>[[6]](#references)</sup>

```bash
java -jar abe.jar unpack file.backup file.tar
```

Μην υποθέτετε ότι αυτό καταγράφει όλες τις εφαρμογές. Το ADB επισημαίνει την εντολή ως παρωχημένη, ενώ το Android 12 εξαιρεί δεδομένα από εφαρμογές που στοχεύουν στο API level 31 ή νεότερο, εκτός αν η εφαρμογή είναι debuggable.<sup>[[4]](#references)</sup>

### Πρόσβαση root ή φυσική πρόσβαση debug

Με πρόσβαση root σε μια ενεργή συσκευή, πρώτα καταγράψτε τα partitions και τα mounts· οι παρακάτω εντολές δεν εφαρμόζονται απευθείας σε φυσική απόκτηση JTAG. Η σωστή συσκευή block εξαρτάται από το υλικό, επομένως μην υποθέτετε ότι είναι πάντα `mmcblk0`. Δημιουργήστε image μόνο από την επαληθευμένη πηγή, σε ξεχωριστό αποθηκευτικό μέσο:<sup>[[1]](#references)</sup>

Αντίθετα, η απόκτηση JTAG χρησιμοποιεί τη διεπαφή hardware test-access της συσκευής και συμβατό εξοπλισμό απόκτησης για την ανάγνωση προσβάσιμης μνήμης. Το pinout, η υποστήριξη chipset, η κατάσταση της συσκευής και η διάκριση μεταξύ volatile και non-volatile στόχων διαφέρουν ανά συσκευή· τεκμηριώστε τη διαδρομή υλικού και εφαρμόστε επικυρωμένη διαδικασία για το συγκεκριμένο μοντέλο.<sup>[[1]](#references)</sup>

```bash
cat /proc/partitions
df /data
dd if=/dev/block/<verified-device> of=/sdcard/device.img bs=4096
```

Για παράδειγμα, αν η απογραφή διαμερισμάτων επιβεβαιώνει ότι το `/dev/block/mmcblk0` είναι ολόκληρη η συσκευή flash και ο προορισμός έχει αρκετό χώρο, η αρχική εντολή απόκτησης γίνεται:<sup>[[1]](#references)</sup>

```bash
dd if=/dev/block/mmcblk0 of=/sdcard/blk0.img bs=4096
```

Εδώ, το `df /data` βοηθά να συσχετιστεί το `/data` με το προσαρτημένο filesystem· δεν πρέπει να θεωρείται απόδειξη ότι το `mmcblk0` είναι η σωστή πηγή ολόκληρης της συσκευής ή ότι το `4096` είναι το μόνο έγκυρο μέγεθος block για το `dd`.

Υπολογίστε το hash του αποτελέσματος και καταγράψτε την ακριβή εντολή, τα αναγνωριστικά συσκευών, την ώρα και τυχόν αλλαγές που έγιναν κατά τη λήψη.<sup>[[1]](#references)</sup>

### Μνήμη

Το LiME μπορεί να αποκτήσει φυσική μνήμη από Linux και ορισμένες συσκευές Android, αλλά το kernel module του πρέπει να έχει δημιουργηθεί για τον kernel-στόχο και να φορτωθεί με επαρκή δικαιώματα. Η υπογραφή modules, το kernel lockdown και οι σύγχρονες δικλείδες ασφαλείας του Android ενδέχεται να εμποδίσουν τη φόρτωσή του.<sup>[[5]](#references)</sup>

Η ροή εργασίας Android του project προωθεί το αντίστοιχο module μέσω ADB, προωθεί μια θύρα TCP, φορτώνει το module από root shell και καταγράφει τη ροή δεδομένων στον host εξέτασης:<sup>[[5]](#references)</sup>

```bash
adb push lime.ko /sdcard/lime.ko
adb forward tcp:4444 tcp:4444
adb shell
su
insmod /sdcard/lime.ko "path=tcp:4444 format=lime"
```

```bash
nc localhost 4444 > ram.lime
```

Το LiME μπορεί εναλλακτικά να γράψει στον αποθηκευτικό χώρο της συσκευής με `path=/sdcard/ram.lime`, αλλά αυτό μεταβάλλει τον αποθηκευτικό χώρο της συσκευής και απαιτεί αρκετό ελεύθερο χώρο. Καταγράψτε αυτή την παρενέργεια και υπολογίστε το hash του αποκτηθέντος image.<sup>[[1]](#references)</sup><sup>[[5]](#references)</sup>
