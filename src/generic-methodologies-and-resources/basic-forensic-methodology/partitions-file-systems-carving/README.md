## Розділи

Жорсткий диск або **SSD disk може містити різні розділи** для фізичного розділення даних.\
**Мінімальною** одиницею диска є **сектор** (зазвичай він складається з 512B). Отже, розмір кожного розділу має бути кратним цьому значенню.

### MBR (master Boot Record)

Він розташований у **першому секторі диска після 446B boot code**. Цей сектор необхідний, щоб вказати PC, який розділ і звідки потрібно змонтувати.\
Він підтримує до **4 розділів** (щонайбільше **лише 1** може бути активним/**bootable**). Однак якщо потрібно більше розділів, можна використовувати **extended partitions**. **Останніми байтами** цього першого сектора є сигнатура boot record **0x55AA**. Лише один розділ може бути позначений як активний.\
MBR підтримує **максимум 2.2TB**.

![Розділи - MBR (master Boot Record): MBR підтримує максимум 2.2TB](<../../../images/image (350).png>)

![Розділи - MBR (master Boot Record): MBR підтримує максимум 2.2TB](<../../../images/image (304).png>)

У **байтах з 440 до 443** MBR можна знайти **Windows Disk Signature** (якщо використовується Windows). Літера логічного диска жорсткого диска залежить від Windows Disk Signature. Зміна цієї сигнатури може перешкодити завантаженню Windows (tool: [**Active Disk Editor**](https://www.disk-editor.org/index.html)**)**.

| Offset    | Length   | Item                                                   |
| --------- | -------- | ------------------------------------------------------ |
| 0 (0x00)  | 1 (0x01) | Active flag (0x80 = bootable)                          |
| 1 (0x01)  | 1 (0x01) | Start head                                             |
| 2 (0x02)  | 1 (0x01) | Start sector (bits 0-5); upper bits of cylinder (6- 7) |
| 3 (0x03)  | 1 (0x01) | Start cylinder lowest 8 bits                           |

| 12 (0x0C) | 4 (0x04) | Sectors in partition                                   |

**LBA (Logical block addressing)**

**Logical block addressing** (**LBA**) — це поширена схема, яка використовується для **визначення розташування блоків** даних, що зберігаються на комп'ютерних пристроях зберігання, зазвичай у системах вторинного зберігання, таких як жорсткі диски. LBA є особливо простою схемою лінійної адресації; **розташування блоків визначається цілим числом**, причому перший блок має номер LBA 0, другий — LBA 1 і так далі.

### GPT (GUID Partition Table)

GUID Partition Table, відома як GPT, користується перевагою завдяки розширеним можливостям порівняно з MBR (Master Boot Record). Характерною особливістю GPT є **глобально унікальний ідентифікатор** розділів. GPT вирізняється такими особливостями:

- **Розташування та розмір**: GPT і MBR починаються із **сектора 0**. Однак GPT працює з **64 бітами**, на відміну від 32 бітів у MBR.
- **Обмеження розділів**: GPT підтримує до **128 розділів** у системах Windows і працює з обсягом даних до **9.4ZB**.
- **Назви розділів**: дає змогу називати розділи, використовуючи до 36 Unicode-символів.

**Стійкість даних і відновлення**:

- **Надлишковість**: на відміну від MBR, GPT не обмежує дані про розділи та завантаження одним місцем. Вона реплікує ці дані на диску, підвищуючи цілісність і стійкість даних.
- **Cyclic Redundancy Check (CRC)**: GPT використовує CRC для забезпечення цілісності даних. Вона активно перевіряє наявність пошкоджень даних, а в разі їх виявлення намагається відновити пошкоджені дані з іншого місця на диску.

**Protective MBR (LBA0)**:

- GPT зберігає зворотну сумісність за допомогою protective MBR. Ця функція розташована в області legacy MBR, але призначена для запобігання помилковому перезапису дисків GPT старими утилітами на основі MBR, тим самим захищаючи цілісність даних на дисках, відформатованих у GPT.

![https://upload.wikimedia.org/wikipedia/commons/thumb/0/07/GUID_Partition_Table_Scheme.svg/800px-GUID_Partition_Table_Scheme.svg.png](<../../../images/image (1062).png>)

**Hybrid MBR (LBA 0 + GPT)**

[З Wikipedia](https://en.wikipedia.org/wiki/GUID_Partition_Table)<sup>[[1]](#references)</sup>

В операційних системах, які підтримують завантаження на основі **GPT через BIOS** замість EFI, перший сектор також може використовуватися для зберігання коду першого етапу **bootloader**, але його має бути **модифіковано** для розпізнавання **GPT** **розділів**. Bootloader у MBR не повинен припускати, що розмір сектора становить 512 байт.

**Заголовок таблиці розділів (LBA 1)**

[З Wikipedia](https://en.wikipedia.org/wiki/GUID_Partition_Table)<sup>[[1]](#references)</sup>

| 48 (0x30) | 8 bytes  | Останній доступний LBA (перший LBA вторинної таблиці розділів − 1)                                                                                                            |
| 56 (0x38) | 16 bytes | GUID диска у mixed endian                                                                                                                                                     |
| 72 (0x48) | 8 bytes  | Початковий LBA масиву записів розділів (завжди 2 у primary copy)                                                                                                              |
| 80 (0x50) | 4 bytes  | Кількість записів розділів у масиві                                                                                                                                           |
| 84 (0x54) | 4 bytes  | Розмір одного запису розділу (зазвичай 80h або 128)                                                                                                                           |
| 88 (0x58) | 4 bytes  | CRC32 масиву записів розділів у little endian                                                                                                                                 |
| 92 (0x5C) | \*       | Зарезервовано; решта блоку має містити нулі (420 байт для розміру сектора 512 байт, але для більших секторів може бути більше)                                                 |

## Файлові системи

### Список файлових систем Windows

- **FAT12/16**: MSDOS, WIN95/98/NT/200
- **FAT32**: 95/2000/XP/2003/VISTA/7/8/10
- **ExFAT**: 2008/2012/2016/VISTA/7/8/10
- **NTFS**: XP/2003/2008/2012/VISTA/7/8/10
- **ReFS**: 2012/2016

### FAT

Файлова система **FAT (File Allocation Table)** побудована навколо свого основного компонента — таблиці розміщення файлів, яка розташована на початку тому. Ця система захищає дані, зберігаючи **дві копії** таблиці, що забезпечує цілісність даних навіть у разі пошкодження однієї з них. Таблиця разом із кореневою папкою має перебувати у **фіксованому місці**, що є важливим для процесу запуску системи.

Базовою одиницею зберігання файлової системи є **кластер, зазвичай 512B**, що складається з кількох секторів. FAT розвивалася в таких версіях:

- **FAT12**, яка підтримує 12-бітові адреси кластерів і працює з до 4078 кластерами (4084 у UNIX).
- **FAT16**, яка використовує 16-бітові адреси та підтримує до 65 517 кластерів.
- **FAT32**, яка використовує 32-бітові адреси й дає змогу зберігати до 268 435 456 кластерів на том.

Важливим обмеженням усіх версій FAT є **максимальний розмір файлу 4GB**, встановлений 32-бітовим полем, яке використовується для зберігання розміру файлу.

Ключові компоненти кореневого каталогу, особливо для FAT12 і FAT16, включають:

- **Ім'я файлу/папки** (до 8 символів)
- **Атрибути**
- **Дати створення, зміни та останнього доступу**
- **Адреса таблиці FAT** (визначає початковий кластер файлу)
- **Розмір файлу**

### EXT

**Ext2** — найпоширеніша файлова система для **розділів без журналювання** (**розділів, які майже не змінюються**), наприклад boot-розділу. **Ext3/4** підтримують **журналювання** і зазвичай використовуються для **решти розділів**.

## **Метадані**

Деякі файли містять метадані. Ця інформація стосується вмісту файлу й іноді може бути цікавою для analyst, оскільки залежно від типу файлу може містити такі дані:

- Назва
- Версія MS Office, яка використовувалася
- Автор
- Дати створення та останньої зміни
- Модель камери
- GPS-координати
- Інформація про зображення

Для отримання метаданих файлу можна використовувати такі інструменти, як [**exiftool**](https://exiftool.org) і [**Metadiver**](https://www.easymetadata.com/metadiver-2/).

## **Відновлення видалених файлів**

### Зареєстровані видалені файли

Як зазначалося раніше, існує кілька місць, де файл усе ще зберігається після того, як його було "видалено". Це відбувається тому, що зазвичай видалення файлу з файлової системи лише позначає його як видалений, але самі дані не змінюються. Тому можна перевірити реєстри файлів (наприклад, MFT) і знайти видалені файли.<sup>[[2]](#references)</sup>

Крім того, OS зазвичай зберігає багато інформації про зміни файлової системи та резервні копії, тому можна спробувати використати їх для відновлення файлу або максимально можливої кількості інформації.

### **File Carving**

**File carving** — це техніка, яка намагається **знаходити файли в масиві даних**. Існує 3 основні способи роботи таких інструментів: **на основі заголовків і завершальних частин типів файлів**, на основі **структур** типів файлів і на основі самого **вмісту**.

Зверніть увагу, що ця техніка **не працює для відновлення фрагментованих файлів**. Якщо файл **зберігається в непослідовних секторах**, ця техніка не зможе знайти його або принаймні його частину.

Існує кілька інструментів, які можна використовувати для File Carving, указавши типи файлів, які потрібно шукати.

### Data Stream **C**arving

Data Stream Carving подібний до File Carving, але **замість пошуку повних файлів він шукає цікаві фрагменти** інформації.\
Наприклад, замість пошуку повного файлу, що містить зареєстровані URL, ця техніка шукатиме URL.

### Secure Deletion

Очевидно, існують способи **"безпечно" видаляти файли та частину журналів про них**. Наприклад, можна **кілька разів перезаписати вміст** файлу сміттєвими даними, потім видалити **журнали** з **$MFT** і **$LOGFILE**, що стосуються файлу, а також **видалити Volume Shadow Copies**.<sup>[[3]](#references)</sup>\
Ви можете помітити, що навіть після виконання цієї дії можуть існувати **інші місця, де все ще зафіксовано факт існування файлу**. Це дійсно так, і частиною роботи forensic professional є їх пошук.
