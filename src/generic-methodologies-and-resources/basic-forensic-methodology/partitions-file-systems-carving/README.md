## Розділи

Жорсткий диск або **SSD-диск може містити різні розділи** для фізичного розділення даних.\
**Мінімальною** одиницею диска є **сектор** (зазвичай він складається з 512B). Отже, розмір кожного розділу має бути кратним цьому розміру.

### MBR (master Boot Record)

Він розташований у **першому секторі диска після 446B boot code**. Цей сектор необхідний, щоб вказати PC, який розділ і звідки потрібно змонтувати.\
Він підтримує до **4 розділів** (щонайбільше **лише 1** може бути активним/**bootable**). Однак, якщо потрібно більше розділів, можна використовувати **extended partitions**. **Останнім байтом** цього першого сектора є сигнатура boot record **0x55AA**. Лише один розділ може бути позначений як активний.\
MBR підтримує **максимум 2.2TB**.

![Розділи - MBR (master Boot Record): MBR підтримує максимум 2.2TB](<../../../images/image (350).png>)

У **байтах із 440 по 443** MBR можна знайти **Windows Disk Signature** (якщо використовується Windows). Логічна літера диска жорсткого диска залежить від Windows Disk Signature. Зміна цієї сигнатури може перешкодити завантаженню Windows (інструмент: [**Active Disk Editor**](https://www.disk-editor.org/index.html)**)**.

| ----------- | ---------- | ------------------- |
| 0 (0x00)    | 446(0x1BE) | Boot code           |
| 446 (0x1BE) | 16 (0x10)  | First Partition     |
| 462 (0x1CE) | 16 (0x10)  | Second Partition    |
| 478 (0x1DE) | 16 (0x10)  | Third Partition     |
| 494 (0x1EE) | 16 (0x10)  | Fourth Partition    |
| 510 (0x1FE) | 2 (0x2)    | Signature 0x55 0xAA |

**Формат запису розділу**

| Offset    | Length   | Item                                                   |
| --------- | -------- | ------------------------------------------------------ |
| 0 (0x00)  | 1 (0x01) | Active flag (0x80 = bootable)                          |
| 1 (0x01)  | 1 (0x01) | Start head                                             |
| 2 (0x02)  | 1 (0x01) | Start sector (bits 0-5); upper bits of cylinder (6- 7) |
| 3 (0x03)  | 1 (0x01) | Start cylinder lowest 8 bits                           |
| 4 (0x04)  | 1 (0x01) | Partition type code (0x83 = Linux)                     |
| 5 (0x05)  | 1 (0x01) | End head                                               |
| 6 (0x06)  | 1 (0x01) | End sector (bits 0-5); upper bits of cylinder (6- 7)   |
| 7 (0x07)  | 1 (0x01) | End cylinder lowest 8 bits                             |

| 12 (0x0C) | 4 (0x04) | Sectors in partition                                   |

**LBA (Logical block addressing)**

**Logical block addressing** (**LBA**) — це поширена схема, що використовується для **визначення розташування блоків** даних, збережених на комп'ютерних пристроях зберігання даних, зазвичай у системах вторинного зберігання, таких як жорсткі диски. LBA — це особливо проста лінійна схема адресації; **блоки визначаються цілим індексом**, де перший блок має LBA 0, другий — LBA 1 і так далі.

### GPT (GUID Partition Table)

GUID Partition Table, відома як GPT, має переваги завдяки розширеним можливостям порівняно з MBR (Master Boot Record). Відмінною особливістю GPT є **глобально унікальний ідентифікатор** розділів. GPT вирізняється такими характеристиками:

- **Розташування та розмір**: GPT і MBR починаються із **сектора 0**. Однак GPT працює з **64 бітами**, на відміну від 32 бітів у MBR.
- **Обмеження щодо розділів**: GPT підтримує до **128 розділів** у системах Windows і вміщує до **9.4ZB** даних.
- **Назви розділів**: дає змогу називати розділи, використовуючи до 36 символів Unicode.

**Стійкість даних і відновлення**:

- **Надлишковість**: на відміну від MBR, GPT не обмежує дані про розділи та завантаження одним місцем. Вона дублює ці дані на диску, підвищуючи цілісність і стійкість даних.
- **Циклічна перевірка надлишковості (CRC)**: GPT використовує CRC для забезпечення цілісності даних. Вона активно перевіряє наявність пошкоджень даних, а в разі їх виявлення намагається відновити пошкоджені дані з іншого місця на диску.

**Захисний MBR (LBA0)**:

- GPT забезпечує зворотну сумісність за допомогою захисного MBR. Ця функція розташовується в застарілому просторі MBR, але призначена для запобігання помилковому перезапису дисків GPT старими утилітами на основі MBR, тим самим захищаючи цілісність даних на дисках із форматом GPT.

![https://upload.wikimedia.org/wikipedia/commons/thumb/0/07/GUID_Partition_Table_Scheme.svg/800px-GUID_Partition_Table_Scheme.svg.png](<../../../images/image (1062).png>)

**Hybrid MBR (LBA 0 + GPT)**

[З Wikipedia](https://en.wikipedia.org/wiki/GUID_Partition_Table)<sup>[[1]](#references)</sup>

В операційних системах, які підтримують **завантаження на основі GPT через BIOS** замість EFI, перший сектор також може використовуватися для зберігання коду першого етапу **bootloader**, але він **модифікований** для розпізнавання **GPT** **розділів**. **bootloader** у MBR не повинен припускати, що розмір сектора становить 512 байт.

**Заголовок таблиці розділів (LBA 1)**

[З Wikipedia](https://en.wikipedia.org/wiki/GUID_Partition_Table)<sup>[[1]](#references)</sup>

| --------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0 (0x00)  | 8 bytes  | Сигнатура ("EFI PART", 45h 46h 49h 20h 50h 41h 52h 54h або 0x5452415020494645ULL[ ](https://en.wikipedia.org/wiki/GUID_Partition_Table#_note-8)на машинах із little-endian) |
| 8 (0x08)  | 4 bytes  | Ревізія 1.0 (00h 00h 01h 00h) для UEFI 2.8                                                                                                                                  |

| 48 (0x30) | 8 bytes  | Останній доступний LBA (перший LBA вторинної таблиці розділів − 1)                                                                                                           |
| 56 (0x38) | 16 bytes | GUID диска у mixed endian                                                                                                                                                    |
| 72 (0x48) | 8 bytes  | Початковий LBA масиву записів розділів (завжди 2 у первинній копії)                                                                                                          |
| 80 (0x50) | 4 bytes  | Кількість записів розділів у масиві                                                                                                                                           |
| 84 (0x54) | 4 bytes  | Розмір одного запису розділу (зазвичай 80h або 128)                                                                                                                         |
| 88 (0x58) | 4 bytes  | CRC32 масиву записів розділів у little endian                                                                                                                                |
| 92 (0x5C) | \*       | Зарезервовано; решта блоку має містити нулі (420 байт для розміру сектора 512 байт; але може бути більше за більших розмірів секторів)                                      |

## Файлові системи

### Список файлових систем Windows

- **FAT12/16**: MSDOS, WIN95/98/NT/200
- **FAT32**: 95/2000/XP/2003/VISTA/7/8/10
- **ExFAT**: 2008/2012/2016/VISTA/7/8/10
- **NTFS**: XP/2003/2008/2012/VISTA/7/8/10
- **ReFS**: 2012/2016

### FAT

Файлова система **FAT (File Allocation Table)** побудована навколо свого основного компонента — таблиці розміщення файлів, яка знаходиться на початку тому. Ця система захищає дані, зберігаючи **дві копії** таблиці, що забезпечує цілісність даних навіть у разі пошкодження однієї з них. Таблиця разом із кореневою папкою повинна розташовуватися у **фіксованому місці**, що є критично важливим для процесу запуску системи.

Базовою одиницею зберігання файлової системи є **кластер, зазвичай 512B**, який складається з кількох секторів. FAT розвивалася в таких версіях:

- **FAT12**, що підтримує 12-бітові адреси кластерів і працює з до 4078 кластерами (4084 з UNIX).
- **FAT16**, що розширює адресацію до 16 бітів і дає змогу використовувати до 65 517 кластерів.
- **FAT32**, що використовує 32-бітові адреси та дає змогу зберігати до 268 435 456 кластерів на томі.

Важливим обмеженням усіх версій FAT є **максимальний розмір файлу 4GB**, зумовлений 32-бітовим полем, що використовується для зберігання розміру файлу.

Основні компоненти кореневого каталогу, особливо для FAT12 і FAT16, включають:

- **Назва файлу/папки** (до 8 символів)
- **Атрибути**
- **Дати створення, зміни та останнього доступу**
- **Адреса таблиці FAT** (визначає початковий кластер файлу)
- **Розмір файлу**

### EXT

**Ext2** — найпоширеніша файлова система для **розділів без журналювання** (**розділів, які майже не змінюються**), наприклад boot-розділу. **Ext3/4** підтримують **журналювання** і зазвичай використовуються для **решти розділів**.

## **Метадані**

Деякі файли містять метадані. Ця інформація стосується вмісту файлу і іноді може бути цікавою для аналітика, оскільки залежно від типу файлу може містити такі дані:

- Назва
- Версія MS Office, що використовувалася
- Автор
- Дати створення та останньої зміни
- Модель камери
- GPS-координати
- Інформація про зображення

Для отримання метаданих файлу можна використовувати такі інструменти, як [**exiftool**](https://exiftool.org) і [**Metadiver**](https://www.easymetadata.com/metadiver-2/).

## **Відновлення видалених файлів**

### Зареєстровані видалені файли

Як зазначалося раніше, існує кілька місць, де файл все ще зберігається після його «видалення». Це відбувається тому, що зазвичай видалення файлу з файлової системи лише позначає його як видалений, але самі дані не змінюються. Тому можна перевірити реєстри файлів (наприклад, MFT) і знайти видалені файли.<sup>[[2]](#references)</sup>

Крім того, ОС зазвичай зберігає багато інформації про зміни файлової системи та резервні копії, тому можна спробувати використати її для відновлення файлу або якомога більшої кількості інформації.

### **File Carving**

**File carving** — це техніка, яка намагається **знаходити файли в масиві даних**. Існує 3 основні способи роботи таких інструментів: **на основі заголовків і футерів типів файлів**, на основі **структур** типів файлів і на основі самого **вмісту**.

Зверніть увагу, що ця техніка **не працює для отримання фрагментованих файлів**. Якщо файл **зберігається в непослідовних секторах**, ця техніка не зможе знайти його або принаймні його частину.

Існує кілька інструментів, які можна використовувати для File Carving із зазначенням типів файлів, які потрібно шукати.

### Data Stream **C**arving

Data Stream Carving подібний до File Carving, але **замість пошуку цілих файлів він шукає цікаві фрагменти** інформації.\
Наприклад, замість пошуку повного файлу, що містить зареєстровані URL-адреси, ця техніка шукатиме URL-адреси.

### Безпечне видалення

Очевидно, існують способи **«безпечного» видалення файлів і частини журналів про них**. Наприклад, можна кілька разів **перезаписати вміст** файлу сміттєвими даними, потім **видалити** **журнали** з **$MFT** і **$LOGFILE**, що стосуються файлу, а також **видалити Volume Shadow Copies**.<sup>[[3]](#references)</sup>\
Ви можете помітити, що навіть після виконання цієї дії можуть існувати **інші місця, де все ще зафіксовано факт існування файлу**, і це справді так; частиною роботи forensic-фахівця є їх пошук.
