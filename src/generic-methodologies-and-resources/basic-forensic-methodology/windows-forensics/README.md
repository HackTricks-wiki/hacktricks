## Γενικά τεχνουργήματα Windows

### Ειδοποιήσεις Windows 10

Η βάση δεδομένων ειδοποιήσεων ανά χρήστη βρίσκεται στο `%LOCALAPPDATA%\Microsoft\Windows\Notifications` (για παράδειγμα, `C:\Users\<username>\AppData\Local\Microsoft\Windows\Notifications`). Οι πρώτες εκδόσεις των Windows 10 χρησιμοποιούσαν το `appdb.dat`, ενώ η Anniversary Update (1607) εισήγαγε το `wpndatabase.db`. Η βάση δεδομένων SQLite περιλαμβάνει έναν πίνακα `Notification` με τα περιεχόμενα των ειδοποιήσεων και πεδία χρονισμού, αν και η διατήρηση και τα διαθέσιμα δεδομένα διαφέρουν ανάλογα με την έκδοση και την πολιτική εκκαθάρισης.<sup>[[3]](#references)</sup>

### Timeline

Το Windows Timeline είναι μια λειτουργία ιστορικού δραστηριοτήτων που μπορεί να περιέχει εγγραφές για υποστηριζόμενες εφαρμογές, έγγραφα και άλλες δραστηριότητες χρηστών. Η κάλυψή του εξαρτάται από την εφαρμογή και την έκδοση των Windows.<sup>[[4]](#references)</sup>

Η βάση δεδομένων βρίσκεται στη διαδρομή `\Users\<username>\AppData\Local\ConnectedDevicesPlatform\<id>\ActivitiesCache.db`. Μπορείτε να την ανοίξετε με το SQLite ή να την αναλύσετε με το [**WxTCmd**](https://github.com/EricZimmerman/WxTCmd), του οποίου τα αποτελέσματα μπορείτε να εξετάσετε με το [**Timeline Explorer**](https://ericzimmerman.github.io/#!index.md).<sup>[[4]](#references)[[5]](#references)</sup>

### Στιγμιότυπα Windows Recall (υπολογιστές Copilot+)

Το Recall είναι προαιρετικό σε υποστηριζόμενους υπολογιστές Windows 11 Copilot+. Οι τρέχουσες εκδόσεις κρυπτογραφούν τα στιγμιότυπα και το ευρετήριό τους με κλειδιά που συνδέονται με το Windows Hello και ένα VBS enclave. Μην θεωρείτε ότι ένα offline αντίγραφο του αποθηκευτικού χώρου είναι μια βάση δεδομένων SQLite σε απλό κείμενο· η preview έκδοση του 2024 και η έκδοση που κυκλοφόρησε έχουν διαφορετικές ιδιότητες πρόσβασης.<sup>[[77]](#references)</sup>

Για μια **ενεργή συνεδρία Recall**, η διεργασία απόδοσης `AIXHost.exe` του ίδιου χρήστη αποτελεί διαφορετική επιφάνεια πρόσβασης. Το proof of concept TotalRecall Reloaded εισάγει ένα DLL σε αυτή τη διεργασία και καλεί τις διεπαφές COM του Recall. Για την εξαγωγή του πλήρους ιστορικού εξακολουθεί να απαιτείται έλεγχος ταυτότητας του χρήστη με Windows Hello· αυτό δεν είναι αποκρυπτογράφηση offline ούτε παράκαμψη του Hello. Ο ερευνητής τεκμηρίωσε το εργαλείο σε Windows 11 ARM64, επομένως επαληθεύστε τη συμβατότητά του με την έκδοση-στόχο προτού βασιστείτε σε αυτό.<sup>[[78]](#references)[[77]](#references)</sup>

```powershell
totalrecall.exe --preauth  # Most recent capture and settings; no Hello prompt
totalrecall.exe --wait     # Wait for the user to open Recall and authenticate
```

`--preauth` χρησιμοποιεί το `GetRecentCaptureThumbnail` για να ζητήσει μια έκδοση υψηλής ανάλυσης της πιο πρόσφατης capture χωρίς Hello. Μετά την εξουσιοδότηση, το `--wait` μπορεί να εξαγάγει screenshots, κείμενο OCR και metadata ανά capture, συμπεριλαμβανομένων πληροφοριών για την εφαρμογή και το παράθυρο. Η έξοδος αποθηκεύεται σε έναν κατάλογο `extraction_*` με χρονοσήμανση. Αυτά είναι ευρήματα που εξαρτώνται από το build και προέρχονται από το proof of concept· δεν εγγυώνται ότι το Recall είναι ενεργοποιημένο ή ότι έχει καταγραφεί κάθε οθόνη.<sup>[[78]](#references)</sup>

### ADS (Alternate Data Streams)

Τα αρχεία που έχουν ληφθεί από το εξωτερικό όριο εμπιστοσύνης ενδέχεται να περιέχουν το **alternate data stream `Zone.Identifier`**, το οποίο καταγράφει πληροφορίες ζώνης και μπορεί να περιλαμβάνει metadata προέλευσης, όπως ένα URL. Η παρουσία και τα πεδία του εξαρτώνται από το πρόγραμμα παραγωγής και την πολιτική του συστήματος.<sup>[[6]](#references)</sup>

### Κάδος Ανακύκλωσης

Στα Vista και σε νεότερες εκδόσεις, ο **Κάδος Ανακύκλωσης** βρίσκεται στον φάκελο **`$Recycle.bin`** στη ρίζα της μονάδας δίσκου (για παράδειγμα, `C:\$Recycle.bin`).\
Όταν διαγράφεται ένα αρχείο σε αυτόν τον φάκελο, δημιουργούνται 2 συγκεκριμένα αρχεία:

- `$I{id}`: Πληροφορίες αρχείου, συμπεριλαμβανομένων της ώρας διαγραφής και της αρχικής διαδρομής
- `$R{id}`: Περιεχόμενο του αρχείου

Τα μεταδεδομένα του αντιγράφου συνήθως συσχετίζονται με το `\System Volume Information` στη ρίζα του τόμου, ενώ τα αναγνωριστικά διαφέρουν ανάλογα με το σύστημα:

Αφού προσαρτήσετε μια εικόνα με κατάλληλο forensic mounter, το [**ShadowCopyView**](https://www.nirsoft.net/utils/shadow_copy_view.html) μπορεί να απαριθμήσει τα διαθέσιμα VSS snapshots και να περιηγηθείτε σε αρχεία ή να τα αντιγράψετε από αυτά.<sup>[[9]](#references)</sup>

![Recycle Bin - Σκιώδη αντίγραφα τόμων: Αφού προσαρτήσετε την forensic εικόνα με το ArsenalImageMounter, μπορείτε να χρησιμοποιήσετε το εργαλείο ShadowCopyView για να εξετάσετε ένα σκιώδες αντίγραφο και ακόμη και να εξαγάγετε τα αρχεία...](<../../../images/image (576).png>)

Η διαμόρφωση του VSS registry writer περιλαμβάνει το `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\BackupRestore`, το οποίο μπορεί να καθορίζει αρχεία και κλειδιά που εξαιρούνται από τα αντίγραφα ασφαλείας:<sup>[[10]](#references)[[11]](#references)</sup>

![Recycle Bin - Σκιώδη αντίγραφα τόμων: Η καταχώριση μητρώου HKEY LOCAL MACHINE SYSTEM CurrentControlSet Control BackupRestore περιέχει τα αρχεία και τα κλειδιά που δεν πρέπει να συμπεριλαμβάνονται στα αντίγραφα ασφαλείας](<../../../images/image (254).png>)

Το κλειδί `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\VSS` περιέχει επίσης τη διαμόρφωση της υπηρεσίας VSS.<sup>[[8]](#references)</sup>

### Αυτόματα αποθηκευμένα αρχεία του Office

Οι θέσεις AutoRecover διαφέρουν ανάλογα με την εφαρμογή Office, την έκδοση και τη διαμόρφωση. Για το Word, η Microsoft αναφέρει το `%APPDATA%\Microsoft\Word` ως προεπιλεγμένη θέση· ελέγξτε τις ρυθμίσεις της εφαρμογής για την ενεργή διαδρομή.<sup>[[12]](#references)</sup>

## Στοιχεία Shell

Ένα στοιχείο shell περιέχει πληροφορίες σχετικά με τον τρόπο πρόσβασης σε ένα άλλο αρχείο.

### Πρόσφατα έγγραφα (LNK)

Τα Windows συνήθως δημιουργούν συντομεύσεις πρόσφατων στοιχείων όταν ένας χρήστης ανοίγει ή αποκτά με άλλο τρόπο πρόσβαση σε ένα στοιχείο:

- Win7-Win10: `%APPDATA%\Microsoft\Windows\Recent\`
- Office: `%APPDATA%\Microsoft\Office\Recent\`

Η πρόσβαση σε έναν φάκελο μπορεί επίσης να δημιουργήσει συνδέσμους για τον ίδιο τον φάκελο και τους σχετικούς γονικούς φακέλους.

Αυτά τα αρχεία συνδέσμων μπορεί να περιέχουν τον τύπο του στόχου, τις χρονικές σημάνσεις MAC του στόχου, πληροφορίες τόμου και τη διαδρομή του στόχου. Αυτά τα μεταδεδομένα μπορεί να βοηθήσουν στον εντοπισμό ενός διαγραμμένου στόχου, αλλά το τεκμήριο από μόνο του δεν αποδεικνύει ότι ο στόχος ανοίχτηκε από συγκεκριμένο χρήστη.<sup>[[13]](#references)[[14]](#references)</sup>

Οι χρονικές σημάνσεις του ίδιου του LNK στο σύστημα αρχείων διαφέρουν από τις ενσωματωμένες χρονικές σημάνσεις του στόχου. Μην θεωρείτε ότι η δημιουργία του συνδέσμου σηματοδοτεί την πρώτη χρήση ή ότι η τροποποίησή του σηματοδοτεί την τελευταία χρήση, χωρίς να επιβεβαιώσετε τα ευρήματα με άλλα τεκμήρια· η μορφή αποθηκεύει τις χρονικές σημάνσεις του στόχου ξεχωριστά από εκείνες του αρχείου συνδέσμου.<sup>[[13]](#references)[[14]](#references)</sup>

Ο υπάρχων σύνδεσμος [**LinkParser**](http://4discovery.com/our-tools/) διατηρείται ως ιστορική επιλογή, αλλά η τεκμηρίωσή του δεν ήταν διαθέσιμη κατά την ανασκόπηση. Για έναν τεκμηριωμένο parser γραμμής εντολών, χρησιμοποιήστε το [**LECmd**](https://github.com/EricZimmerman/LECmd).<sup>[[15]](#references)</sup>

Αυτά τα εργαλεία εμφανίζουν συνήθως δύο σύνολα χρονικών σημάνσεων:

- **Χρονικές σημάνσεις στόχου:**
  1. FileModifiedDate
  2. FileAccessDate
  3. FileCreationDate
- **Χρονικές σημάνσεις αρχείου συνδέσμου:**
  1. LinkModifiedDate
  2. LinkAccessDate
  3. LinkCreationDate.

Το πρώτο σύνολο αφορά τον στόχο· το δεύτερο αφορά το ίδιο το αρχείο LNK. Ερμηνεύστε και τα δύο με βάση την τεκμηρίωση του parser και το πλαίσιο του συστήματος αρχείων.<sup>[[14]](#references)[[15]](#references)</sup>

Μπορείτε να λάβετε τις ίδιες πληροφορίες εκτελώντας το εργαλείο CLI των Windows: [**LECmd.exe**](https://github.com/EricZimmerman/LECmd).<sup>[[15]](#references)</sup>

```
LECmd.exe -d C:\Users\student\Desktop\LNKs --csv C:\Users\student\Desktop\LNKs
```

Σε αυτή την περίπτωση, οι πληροφορίες θα αποθηκευτούν σε ένα αρχείο CSV.

### Jumplists

Οι Jump Lists είναι λίστες ανά εφαρμογή με πρόσφατα στοιχεία ή στοιχεία συγκεκριμένων εργασιών και μπορεί να είναι αυτόματες ή προσαρμοσμένες.<sup>[[13]](#references)</sup>

Οι αυτόματες Jump Lists αποθηκεύονται στο `C:\Users\{username}\AppData\Roaming\Microsoft\Windows\Recent\AutomaticDestinations\` και χρησιμοποιούν ονόματα όπως `{id}.automaticDestinations-ms`, όπου το ID προσδιορίζει την εφαρμογή.

Οι προσαρμοσμένες Jump Lists αποθηκεύονται στο `C:\Users\{username}\AppData\Roaming\Microsoft\Windows\Recent\CustomDestinations\`· η εφαρμογή ελέγχει ποιες εγγραφές εργασιών ή στοιχείων δημιουργεί.

Οι χρόνοι δημιουργίας και τροποποίησης του filesystem περιγράφουν το αρχείο Jump List και όχι αυτομάτως την πρώτη και τελευταία πρόσβαση σε κάθε καταχωρισμένο στόχο. Συσχετίστε τις αναλυμένες εγγραφές με τις χρονικές σημάνσεις του αρχείου και άλλα τεχνουργήματα.<sup>[[13]](#references)</sup>

Μπορείτε να εξετάσετε τις Jump Lists χρησιμοποιώντας το [**JumplistExplorer**](https://ericzimmerman.github.io/#!index.md).<sup>[[5]](#references)</sup>

## Χρήση Windows USB

Η χρήση USB μπορεί μερικές φορές να επιβεβαιωθεί από τεχνουργήματα που δημιουργούνται κατά την πρόσβαση σε αρχεία από αφαιρούμενα μέσα, όπως:

- Windows Recent Folder
- Microsoft Office Recent Folder
- Jumplists

Εργαλεία όπως το [**USBDetective**](https://usbdetective.com) συσχετίζουν αυτά τα τεχνουργήματα με εγγραφές συσκευών USB, αλλά η διαθεσιμότητα των τεχνουργημάτων εξαρτάται από την έκδοση των Windows και την εφαρμογή.<sup>[[18]](#references)</sup>

Σε δοκιμές που καταγράφηκαν για ροές εργασιών MTP σε Windows XP και Windows 7, ορισμένα LNK παρέπεμπαν σε φάκελο `WPDNSE` αντί για την αρχική διαδρομή.<sup>[[16]](#references)</sup>

![Shellbags - Χρήση Windows USB: Σημειώστε ότι ορισμένα αρχεία LNK, αντί να παραπέμπουν στην αρχική διαδρομή, παραπέμπουν στον φάκελο WPDNSE](<../../../images/image (218).png>)

Η μελέτη εντόπισε αντίγραφα στο `%LOCALAPPDATA%\Temp\WPDNSE\{FolderGUID}`· στις δοκιμές της, τα προσωρινά περιεχόμενα δεν διατηρούνταν μετά από επανεκκίνηση, ενώ το GUID μπορούσε να συσχετιστεί με δεδομένα shellbag. Αντιμετωπίστε το ως συμπεριφορά που εξαρτάται από το λειτουργικό σύστημα, τη συσκευή και την εφαρμογή, όχι ως καθολικό κανόνα.<sup>[[16]](#references)</sup>

### Εκκαθάριση Plug and Play

Η προγραμματισμένη εργασία με το όνομα `Plug and Play Cleanup` αφαιρεί παλιές εκδόσεις προγραμμάτων οδήγησης. Ένας ορισμός εργασίας των Windows 10 που κατέγραψε ο Adam Harrison στοχεύει επίσης προγράμματα οδήγησης που είναι ανενεργά για 30 ημέρες, επομένως τα στοιχεία προγραμμάτων οδήγησης αφαιρούμενων συσκευών μπορεί να διαγραφούν· επιβεβαιώστε τον τοπικό ορισμό της εργασίας και την έκδοση των Windows πριν γενικεύσετε αυτή τη συμπεριφορά.<sup>[[1]](#references)</sup>

Η εργασία βρίσκεται στην εξής διαδρομή: `C:\Windows\System32\Tasks\Microsoft\Windows\Plug and Play\Plug and Play Cleanup`.

![Ορισμός XML της προγραμματισμένης εργασίας Windows Plug and Play Cleanup](https://2.bp.blogspot.com/-wqYubtuR_W8/W19bV5S9XyI/AAAAAAAANhU/OHsBDEvjqmg9ayzdNwJ4y2DKZnhCdwSMgCLcBGAs/s1600/xml.png)

**Βασικά στοιχεία και ρυθμίσεις της εργασίας:**

- **pnpclean.dll**: Αυτή η DLL είναι υπεύθυνη για την ίδια τη διαδικασία εκκαθάρισης.
- **UseUnifiedSchedulingEngine**: Ορίζεται σε `TRUE`, υποδεικνύοντας τη χρήση της γενικής μηχανής προγραμματισμού εργασιών.
- **MaintenanceSettings**:
  - **Period ('P1M')**: Καθοδηγεί το Task Scheduler να ξεκινά την εργασία εκκαθάρισης κάθε μήνα, κατά την τακτική Αυτόματη συντήρηση.
  - **Deadline ('P2M')**: Καθοδηγεί το Task Scheduler, εάν η εργασία αποτύχει για δύο συνεχόμενους μήνες, να την εκτελέσει κατά την έκτακτη Αυτόματη συντήρηση.

Αυτή η διαμόρφωση προγραμματίζει τακτική συντήρηση και επαναλαμβάνει την προσπάθεια μετά από διαδοχικές αποτυχίες· το ακριβές XML και η συμπεριφορά εξαρτώνται από την έκδοση.<sup>[[1]](#references)</sup>

**Για περισσότερες πληροφορίες, δείτε:** [**https://blog.1234n6.com/2018/07/windows-plug-and-play-cleanup.html**](https://blog.1234n6.com/2018/07/windows-plug-and-play-cleanup.html).<sup>[[1]](#references)</sup>

## Email

Τα email περιέχουν **2 ενδιαφέροντα μέρη: τις κεφαλίδες και το περιεχόμενο** του email. Στις **κεφαλίδες** μπορείτε να βρείτε πληροφορίες όπως:

- **Ποιος** έστειλε τα email (διεύθυνση email, IP, διακομιστές email που ανακατεύθυναν το email)
- **Πότε** στάλθηκε το email

Επίσης, οι κεφαλίδες `References` και `In-Reply-To` μπορούν να περιέχουν αναγνωριστικά μηνυμάτων που χρησιμοποιούνται για τη συσχέτιση απαντήσεων με μια συνομιλία.<sup>[[76]](#references)</sup>

![Plug and Play Cleanup - Email: Πότε στάλθηκε το email](<../../../images/image (593).png>)

### Εφαρμογή Windows Mail

Αυτή η εφαρμογή αποθηκεύει το περιεχόμενο των email σε βοηθητικά αρχεία κειμένου ή HTML σε διαδρομές όπως `\Users\<username>\AppData\Local\Comms\Unistore\data\3\`· η ακριβής διάταξη αριθμημένων φακέλων και αρχείων μπορεί να διαφέρει ανάλογα με το τεχνούργημα.<sup>[[75]](#references)</sup>

Τα **metadata** των email και οι **επαφές** βρίσκονται στη **βάση δεδομένων ESE** `\Users\<username>\AppData\Local\Comms\UnistoreDB\store.vol`.<sup>[[75]](#references)</sup>

Το `store.vol` χρησιμοποιεί τη μορφή Extensible Storage Engine (ESE). Εργαστείτε σε αντίγραφο και χρησιμοποιήστε έναν parser ESE, όπως το [ESEDatabaseView](https://www.nirsoft.net/utils/ese_database_view.html)· αν ένα εργαλείο απαιτεί κατάληξη `.edb`, μετονομάστε μόνο το αντίγραφο και επαληθεύστε το σχήμα του πίνακα προτού βασιστείτε σε έναν πίνακα `Message`.<sup>[[19]](#references)[[75]](#references)</sup>

### Microsoft Outlook

Κατά την εξέταση ιδιοτήτων MAPI του Outlook, οι κανονικές ιδιότητες περιλαμβάνουν:

- `PidTagClientSubmitTime`: την ώρα UTC κατά την οποία ο client υπέβαλε το μήνυμα.
- `PidTagConversationIndex`: τη σχετική θέση του μηνύματος σε ένα νήμα συνομιλίας.
- `PidTagEntryId`: ένα αναγνωριστικό για το αντικείμενο μηνύματος.
- `PidTagMessageFlags`: σημαίες κατάστασης, όπως υποβλήθηκε, αναγνώστηκε, δεν αναγνώστηκε ή περιέχει συνημμένα.
- `PidTagLastVerbExecuted`: την τελευταία ενέργεια που καταγράφηκε για το μήνυμα, όπως άνοιγμα, απάντηση ή προώθηση.<sup>[[20]](#references)[[21]](#references)[[22]](#references)[[23]](#references)[[24]](#references)</sup>

Οι θέσεις των αρχείων δεδομένων του Outlook διαφέρουν ανάλογα με την έκδοση και τον τύπο λογαριασμού. Η Microsoft τεκμηριώνει τις εξής συνήθεις θέσεις για αρχεία PST/OST:

- `%USERPROFILE%\Local Settings\Application Data\Microsoft\Outlook` (WinXP)
- `%USERPROFILE%\AppData\Local\Microsoft\Outlook`

Η διαδρομή μητρώου `HKEY_CURRENT_USER\Software\Microsoft\Windows NT\CurrentVersion\Windows Messaging Subsystem\Profiles\Outlook` μπορεί να προσδιορίζει το προφίλ Outlook και τη σχετική διαμόρφωση αρχείων δεδομένων.

Τα αρχεία PST μπορούν να περιέχουν μηνύματα, επαφές, δεδομένα ημερολογίου και άλλα στοιχεία του Outlook. Μπορείτε να εξετάσετε ένα αντίγραφο με το [**Kernel PST Viewer**](https://www.nucleustechnologies.com/es/visor-de-pst.html).<sup>[[25]](#references)[[67]](#references)</sup>

![Εφαρμογή Windows Mail - Microsoft Outlook: Μπορείτε να ανοίξετε το αρχείο PST χρησιμοποιώντας το εργαλείο Kernel PST Viewer](<../../../images/image (498).png>)

### Αρχεία OST του Microsoft Outlook

Ένα **αρχείο OST** είναι μια τοπική cache για λογαριασμούς Exchange ή Microsoft 365· η λειτουργία Cached Exchange Mode δεν εφαρμόζεται σε λογαριασμούς POP ή IMAP. Η περίοδος offline είναι παραμετροποιήσιμη και συχνά έχει προεπιλεγμένη τιμή 12 μηνών, ενώ τα όρια μεγέθους PST/OST είναι ξεχωριστές ρυθμίσεις που μπορούν επίσης να παραμετροποιηθούν. Για να δείτε ένα αρχείο OST, μπορείτε να χρησιμοποιήσετε το [**Kernel OST viewer**](https://www.nucleustechnologies.com/ost-viewer.html).<sup>[[26]](#references)[[27]](#references)[[28]](#references)[[68]](#references)</sup>

### Μικρογραφίες εικόνων

- **Windows XP**: Οι προεπισκοπήσεις μικρογραφιών αποθηκεύονταν συνήθως σε αρχεία `thumbs.db` ανά φάκελο.
- **Φάκελοι δικτύου**: Ενδέχεται να δημιουργηθεί αρχείο `thumbs.db` για έναν φάκελο UNC όταν είναι ενεργοποιημένη η σχετική συμπεριφορά μικρογραφιών· μην υποθέτετε ότι κάθε έκδοση ή πολιτική των Windows δημιουργεί τέτοιο αρχείο.
- **Windows Vista και νεότερα**: Η cache μικρογραφιών του συστήματος συγκεντρώνεται στο `%USERPROFILE%\AppData\Local\Microsoft\Windows\Explorer` σε αρχεία όπως **thumbcache_xxx.db**. Το [**Thumbsviewer**](https://thumbsviewer.github.io) μπορεί να αναλύσει παλαιότερα αρχεία `Thumbs.db`, ενώ το [**ThumbCache Viewer**](https://thumbcacheviewer.github.io) μπορεί να αναλύσει σύγχρονες βάσεις δεδομένων cache μικρογραφιών.<sup>[[31]](#references)[[32]](#references)[[33]](#references)</sup>

### Πληροφορίες μητρώου των Windows

Το Windows Registry, όπου αποθηκεύονται δεδομένα διαμόρφωσης συστήματος και χρήστη, περιέχεται σε αρχεία hive στις εξής θέσεις:

- `%WINDIR%\System32\Config` για τα hive του μηχανήματος που υποστηρίζουν διάφορα υποκλειδιά `HKEY_LOCAL_MACHINE`.
- `%USERPROFILE%\NTUSER.DAT` για το hive `HKEY_CURRENT_USER` ενός χρήστη.
- Σε ορισμένες παλαιότερες εγκαταστάσεις Windows υπάρχουν αντίγραφα στο `%WINDIR%\System32\Config\RegBack`· τα Windows 10 έκδοση 1803 και νεότερα δεν συμπληρώνουν αυτόματα αυτόν τον κατάλογο, εκτός αν είναι ενεργοποιημένη η περιοδική δημιουργία αντιγράφων ασφαλείας.<sup>[[34]](#references)[[35]](#references)</sup>
- Τα δεδομένα shell και εγγραφής κλάσεων ανά χρήστη αποθηκεύονται επίσης συνήθως στο `%LOCALAPPDATA%\Microsoft\Windows\UsrClass.dat` στα σύγχρονα Windows.<sup>[[34]](#references)[[66]](#references)</sup>

### Εργαλεία

Ορισμένα εργαλεία είναι χρήσιμα για την ανάλυση hive μητρώου· επιβεβαιώστε τις υποστηριζόμενες μορφές hive και εκδόσεις κάθε εργαλείου προτού βασιστείτε σε κάποιο αποτέλεσμα:

- **Registry Editor**: Είναι εγκατεστημένο στα Windows. Είναι ένα GUI για την περιήγηση στο Windows Registry της τρέχουσας συνεδρίας.
- [**Registry Explorer**](https://ericzimmerman.github.io/#!index.md): Σας επιτρέπει να φορτώσετε το αρχείο μητρώου και να περιηγηθείτε σε αυτό μέσω GUI. Περιλαμβάνει επίσης σελιδοδείκτες που επισημαίνουν κλειδιά με ενδιαφέρουσες πληροφορίες.
- [**RegRipper**](https://github.com/keydet89/RegRipper3.0): Διαθέτει επίσης GUI για την περιήγηση στο φορτωμένο μητρώο, καθώς και plugins που επισημαίνουν ενδιαφέρουσες πληροφορίες μέσα σε αυτό.
- [**Windows Registry Recovery**](https://www.mitec.cz/wrr.html): Μια ακόμη εφαρμογή GUI που μπορεί να εξαγάγει πληροφορίες από ένα φορτωμένο hive μητρώου.<sup>[[5]](#references)[[36]](#references)[[37]](#references)</sup>

### Ανάκτηση διαγραμμένων στοιχείων

### Χρόνος τελευταίας εγγραφής

### SAM

Το hive **SAM** περιέχει δεδομένα τοπικών λογαριασμών χρηστών και ομάδων, συμπεριλαμβανομένων hashes κωδικών πρόσβασης που προστατεύονται από το υλικό boot-key του συστήματος.<sup>[[38]](#references)[[39]](#references)</sup>

Στο `SAM\Domains\Account\Users` μπορείτε να βρείτε αναγνωριστικά λογαριασμών και ορισμένα πεδία σύνδεσης και πολιτικής. Για την offline εξαγωγή hashes απαιτείται επίσης το hive `SYSTEM` ώστε να ανακτηθεί το σχετικό υλικό boot-key.<sup>[[38]](#references)[[39]](#references)</sup>

## Προγράμματα που εκτελέστηκαν

### Βασικές διεργασίες των Windows

Μια υπάρχουσα [ανάρτηση σχετικά με συνήθεις διεργασίες των Windows](https://jonahacks.medium.com/investigating-common-windows-processes-18dee5f97c1d) διατηρείται ως πρόσθετο υλικό για ανάγνωση· επιβεβαιώστε τους ισχυρισμούς σχετικά με τη συμπεριφορά διεργασιών με την τρέχουσα τεκμηρίωση των Windows και τοπικά στοιχεία.<sup>[[2]](#references)</sup>

### Πρόσφατες εφαρμογές των Windows

Σε εκδόσεις των Windows 10 όπου είναι διαθέσιμο, το `NTUSER.DAT\Software\Microsoft\Windows\CurrentVersion\Search\RecentApps` περιέχει υποκλειδιά ανά εφαρμογή με πεδία όπως ο χρόνος τελευταίας χρήσης και ο αριθμός εκκινήσεων· το τεχνούργημα αφαιρέθηκε από νεότερες εκδόσεις, επομένως επαληθεύστε την έκδοση-στόχο.<sup>[[64]](#references)</sup>

### BAM (Background Activity Moderator)

Σε συστήματα όπου είναι διαθέσιμο το Background Activity Moderator, εξετάστε τη διαδρομή `SYSTEM\CurrentControlSet\Services\bam\UserSettings\{SID}` ή τη νεότερη διαδρομή `...\bam\State\UserSettings\{SID}`. Οι τιμές οργανώνονται ανά SID χρήστη και μπορεί να περιέχουν παρακολουθούμενες διαδρομές εκτελέσιμων αρχείων και δεδομένα εκτέλεσης τύπου FILETIME· το τεχνούργημα εξαρτάται από την έκδοση και θα πρέπει να επιβεβαιώνεται με άλλα στοιχεία.<sup>[[63]](#references)</sup>

### Windows Prefetch

Το Prefetch αποθηκεύει προσωρινά πόρους και metadata εκκίνησης, ώστε τα προγράμματα να ξεκινούν ταχύτερα.

Τα αρχεία Prefetch αποθηκεύονται ως αρχεία `.pf` στο `C:\Windows\Prefetch`· η μορφή, η διατήρηση και τα όρια αριθμού αρχείων διαφέρουν ανάλογα με την έκδοση των Windows. Η Microsoft τεκμηριώνει τη διατήρηση των τελευταίων οκτώ χρόνων εκτέλεσης και έως 1024 αρχείων στα Windows 8 και νεότερα, επομένως οι παλαιότερες περιλήψεις με σταθερά όρια δεν πρέπει να γενικεύονται.<sup>[[13]](#references)</sup>

Το όνομα αρχείου συνήθως ακολουθεί τη μορφή `{program_name}-{hash}.pf`, όπου το hash προκύπτει από το πλαίσιο εκτέλεσης, όπως τη διαδρομή και τα ορίσματα· τα Windows 10 και νεότερα ενδέχεται να συμπιέζουν το αρχείο. Η παρουσία του αποτελεί χρήσιμο στοιχείο εκτέλεσης, αλλά από μόνη της δεν αποδεικνύει ότι το εκτέλεσε κάποιος χρήστης και θα πρέπει να συσχετίζεται με άλλα τεχνουργήματα.<sup>[[13]](#references)</sup>

Για να εξετάσετε αυτά τα αρχεία, μπορείτε να χρησιμοποιήσετε το [**PECmd.exe**](https://github.com/EricZimmerman/PECmd), το οποίο τεκμηριώνει την ανάλυση καταλόγων, την έξοδο CSV/HTML και την υποστήριξη αποσυμπίεσης για συμβατά αρχεία Prefetch των Windows 10.<sup>[[40]](#references)</sup>

```bash
.\PECmd.exe -d C:\Users\student\Desktop\Prefetch --html "C:\Users\student\Desktop\out_folder"
```

### Superprefetch

Το **Superfetch/SysMain** συμπληρώνει το Prefetch χρησιμοποιώντας ιστορικά μοτίβα χρήσης για τη βελτίωση της φόρτωσης. Στα συστήματα που τα δημιουργούν, τα αρχεία βάσης δεδομένων του βρίσκονται συνήθως στη θέση `C:\Windows\Prefetch\Ag*.db`· η μορφή και η παρουσία τους εξαρτώνται από την έκδοση.<sup>[[41]](#references)</sup>

Αυτές οι βάσεις δεδομένων ενδέχεται να περιέχουν ονόματα εφαρμογών, αριθμούς χρήσεων, αρχεία ή τόμους στους οποίους έγινε πρόσβαση, διαδρομές και χρονικά διαστήματα, αλλά δεν πρέπει να θεωρούνται ακριβές αρχείο καταγραφής εκτέλεσης.<sup>[[41]](#references)</sup>

Ο υπάρχων σύνδεσμος [**CrowdResponse**](https://www.crowdstrike.com/resources/community-tools/crowdresponse/) διατηρείται ως πιθανό εργαλείο ανάλυσης· πριν από τη χρήση, επαληθεύστε την τρέχουσα διαθεσιμότητά του και τις υποστηριζόμενες μορφές εξόδου σύμφωνα με την τεκμηρίωση του εργαλείου.

### SRUM

Το **System Resource Usage Monitor** (SRUM) καταγράφει τη χρήση πόρων από εφαρμογές και χρήστες. Εισήχθη στα Windows 8 και αποθηκεύει δεδομένα στη βάση δεδομένων ESE `C:\Windows\System32\sru\SRUDB.dat`.<sup>[[13]](#references)</sup>

Παρέχει τις ακόλουθες πληροφορίες:

- AppID and Path
- User/SID associated with the record
- Sent Bytes
- Received Bytes
- Network Interface
- Connection duration
- Process duration

Η συχνότητα συλλογής και η διατήρηση των δεδομένων εξαρτώνται από την υλοποίηση· μην υποθέτετε ότι κάθε εγγραφή αντιστοιχεί σε ακριβές διάστημα εκτέλεσης 60 λεπτών.<sup>[[13]](#references)</sup>

Μπορείτε να εξαγάγετε και να εξετάσετε δεδομένα με το [**srum_dump**](https://github.com/MarkBaggett/srum-dump), χρησιμοποιώντας τις επιλογές που τεκμηριώνονται για την τρέχουσα έκδοση του εργαλείου.<sup>[[42]](#references)</sup>

```bash
.\srum_dump.exe -i C:\Users\student\Desktop\SRUDB.dat -o C:\Users\student\Desktop\srum --NO_CONFIRM
```

### AppCompatCache (ShimCache)

Το **AppCompatCache**, γνωστό και ως **ShimCache**, αποτελεί μέρος της υποδομής συμβατότητας εφαρμογών των Windows και καταγράφει μεταδεδομένα αρχείων για αποφάσεις συμβατότητας. Η διαδρομή της hive, η μορφή των εγγραφών, η χωρητικότητα διατήρησης και τα πεδία διαφέρουν ανά έκδοση των Windows· σε σύγχρονα Windows, το ShimCache από μόνο του δεν αποδεικνύει ότι ένας χρήστης εκτέλεσε ένα αρχείο. Αναλύστε τη σχετική hive `SYSTEM` με το εργαλείο [**AppCompatCacheParser**](https://github.com/EricZimmerman/AppCompatCacheParser) και διασταυρώστε τα αποτελέσματά του με artifacts εκτέλεσης.<sup>[[13]](#references)[[43]](#references)</sup>

![SRUM - AppCompatCache (ShimCache): Για την ανάλυση των αποθηκευμένων πληροφοριών, συνιστάται η χρήση του εργαλείου AppCompatCacheParser](<../../../images/image (75).png>)

### Amcache

Το αρχείο **Amcache.hve** είναι μια hive μητρώου που καταγράφει εφαρμογές και αρχεία τα οποία εντοπίστηκαν από τα Windows. Συνήθως βρίσκεται στη διαδρομή `C:\Windows\AppCompat\Programs\Amcache.hve`.

Μπορεί να περιέχει συσχετισμένες και μη συσχετισμένες εγγραφές αρχείων, διαδρομές και τιμές SHA1, αλλά η παρουσία του αποτελεί τεκμήριο καταγραφής και δεν αποδεικνύει από μόνη της ότι εκτελέστηκε μια διεργασία.<sup>[[13]](#references)[[44]](#references)</sup>

Για να εξαγάγετε και να αναλύσετε το **Amcache.hve**, χρησιμοποιήστε το εργαλείο [**AmcacheParser**](https://github.com/EricZimmerman/AmcacheParser). Αυτή η εντολή αναλύει τη hive και γράφει τα αποτελέσματα σε μορφή CSV.<sup>[[44]](#references)</sup>

Για παράδειγμα:

```bash
AmcacheParser.exe -f C:\Users\genericUser\Desktop\Amcache.hve --csv C:\Users\genericUser\Desktop\outputFolder
```

Μεταξύ των αρχείων CSV που δημιουργούνται, το `Amcache_Unassociated file entries` μπορεί να είναι χρήσιμο κατά τη διερεύνηση αρχείων που δεν σχετίζονται με αναγνωρισμένο πρόγραμμα.<sup>[[44]](#references)</sup>

### RecentFileCache

Σε συστήματα Windows 7, το `C:\Windows\AppCompat\Programs\RecentFileCache.bcf` μπορεί να περιέχει πληροφορίες για binaries που παρατηρήθηκαν πρόσφατα· η διαθεσιμότητα και η σημασία του εξαρτώνται από την έκδοση.

Μπορείτε να χρησιμοποιήσετε το [**RecentFileCacheParser**](https://github.com/EricZimmerman/RecentFileCacheParser) για να αναλύσετε το αρχείο.<sup>[[45]](#references)</sup>

### Προγραμματισμένες εργασίες

Τα τεκμήρια προγραμματισμένων εργασιών μπορεί να βρίσκονται στο `C:\Windows\System32\Tasks` για σύγχρονες εργασίες και στο `C:\Windows\Tasks` με αρχεία `.job` για παλαιότερες εργασίες· εξετάστε τη μορφή ορισμού εργασιών που αντιστοιχεί στο λειτουργικό σύστημα.<sup>[[73]](#references)[[74]](#references)</sup>

### Υπηρεσίες

Η βάση δεδομένων του Service Control Manager βρίσκεται στο `SYSTEM\CurrentControlSet\Services` (για ένα offline SYSTEM hive, εξετάστε το αντίστοιχο κλειδί control-set)· περιέχει ρυθμίσεις υπηρεσιών και drivers, όπως διαδρομές εκτελέσιμων αρχείων και τύπους εκκίνησης.<sup>[[72]](#references)</sup>

### **Windows Store**

Οι εγκατεστημένες εφαρμογές του Windows Store μπορεί να αναπαρίστανται στο `\ProgramData\Microsoft\Windows\AppRepository\`, συμπεριλαμβανομένης της βάσης δεδομένων **`StateRepository-Machine.srd`**. Το σχήμα και οι διαδρομές διαφέρουν ανά έκδοση των Windows.<sup>[[71]](#references)</sup>

Η βάση δεδομένων μπορεί να περιέχει αναγνωριστικά εφαρμογών, αριθμούς πακέτων και εμφανιζόμενα ονόματα. Τα κενά στα αναγνωριστικά δεν αποτελούν από μόνα τους απόδειξη ότι μια εφαρμογή απεγκαταστάθηκε· επιβεβαιώστε τα με τα δεδομένα κατάστασης πακέτων και μητρώου.

Οι καταχωρίσεις πακέτων μπορεί επίσης να εμφανίζονται στο `HKLM\Software\Microsoft\Windows\CurrentVersion\Appx\AppxAllUserStore\Applications\`. Η Microsoft τεκμηριώνει ένα ειδικό για κάθε έκδοση δευτερεύον κλειδί `Deprovisioned` για εφαρμογές που αφαιρέθηκαν από την προεγκατάσταση· μην υποθέτετε ότι υπάρχει δευτερεύον κλειδί `Deleted` σε κάθε build.<sup>[[70]](#references)</sup>

## Συμβάντα Windows

Ανάλογα με τον provider, τα συμβάντα των Windows μπορεί να περιέχουν:

- Τι συνέβη
- Μια χρονική σήμανση `TimeCreated`, η οποία πρέπει να ερμηνεύεται με βάση το σχήμα του συμβάντος και το χρονικό πλαίσιο του host
- Τους χρήστες που εμπλέκονται
- Τους hosts που εμπλέκονται (hostname, IP)
- Τα στοιχεία στα οποία έγινε πρόσβαση (αρχεία, φάκελοι, εκτυπωτές ή υπηρεσίες).<sup>[[49]](#references)</sup>

Πριν από τα Windows Vista, τα αρχεία καταγραφής συμβάντων χρησιμοποιούσαν γενικά την παλαιότερη δυαδική μορφή στο `C:\Windows\System32\config`· τα Vista και οι νεότερες εκδόσεις χρησιμοποιούν τη μορφή Windows Event Log, συνήθως στο `C:\Windows\System32\winevt\Logs`, με αρχεία `.evtx` που περιέχουν δεδομένα συμβάντων αποδιδόμενα σε XML.<sup>[[46]](#references)[[47]](#references)</sup>

Το μητρώο SYSTEM αποθηκεύει τις ρυθμίσεις των καναλιών στο **`HKLM\SYSTEM\CurrentControlSet\services\EventLog\{Application|System|Security}`**, συμπεριλαμβανομένης της διαμορφωμένης διαδρομής αρχείου και των ρυθμίσεων διατήρησης.<sup>[[47]](#references)</sup>

Μπορείτε να τα προβάλετε με το Windows Event Viewer (**`eventvwr.msc`**) ή με εργαλεία όπως το [**Event Log Explorer**](https://eventlogxp.com) και το [**Evtx Explorer/EvtxECmd**](https://ericzimmerman.github.io/#!index.md).<sup>[[5]](#references)[[48]](#references)[[61]](#references)</sup>

## Κατανόηση της καταγραφής συμβάντων ασφαλείας των Windows

Στα Vista και στις νεότερες εκδόσεις, το κανάλι Security αποθηκεύεται συνήθως στο `C:\Windows\System32\winevt\Logs\Security.evtx`. Το μέγιστο μέγεθος και η πολιτική διατήρησής του είναι ρυθμιζόμενα· με κυκλική καταγραφή, παλαιότερες εγγραφές μπορεί να αντικατασταθούν όταν το αρχείο φτάσει στο όριό του. Το κανάλι μπορεί να καταγράφει συμβάντα ελέγχου ταυτότητας, αποσύνδεσης, δικαιωμάτων, πολιτικής ελέγχου και πρόσβασης σε αντικείμενα, όταν είναι ενεργοποιημένος ο σχετικός έλεγχος.<sup>[[46]](#references)[[47]](#references)</sup>

### Βασικά Event ID για έλεγχο ταυτότητας χρήστη:

- **Event ID 4624**: Επιτυχής σύνδεση λογαριασμού.<sup>[[50]](#references)</sup>
- **Event ID 4625**: Αποτυχημένη σύνδεση λογαριασμού.<sup>[[51]](#references)</sup>
- **Event ID 4634**: Τερματίστηκε μια περίοδος σύνδεσης.<sup>[[52]](#references)</sup>
- **Event ID 4647**: Ο χρήστης ξεκίνησε αποσύνδεση.<sup>[[53]](#references)</sup>
- **Event ID 4672**: Εκχωρήθηκαν ειδικά δικαιώματα σε νέα σύνδεση· αυτό είναι συνηθισμένο για λογαριασμούς συστήματος και διαχειριστών και, επομένως, δεν αποτελεί από μόνο του απόδειξη κακόβουλης δραστηριότητας.<sup>[[54]](#references)</sup>

#### Τύποι σύνδεσης που καταγράφονται συχνά στα 4624, 4625, 4634 και 4647:

- **Interactive (2)**: Τοπική διαδραστική σύνδεση.
- **Network (3)**: Πρόσβαση σε κοινόχρηστο πόρο.
- **Batch (4)**: Σύνδεση διεργασίας batch.
- **Service (5)**: Σύνδεση υπηρεσίας.
- **Unlock (7)**: Ξεκλείδωμα σταθμού εργασίας.
- **NetworkCleartext (8)**: Σύνδεση δικτύου που παρέχει διαπιστευτήρια σε μορφή απλού κειμένου στο πακέτο ελέγχου ταυτότητας.
- **NewCredentials (9)**: Σύνδεση με χρήση εναλλακτικών διαπιστευτηρίων που δόθηκαν για εξερχόμενες συνδέσεις.
- **RemoteInteractive (10)**: Σύνδεση μέσω Remote Desktop ή Terminal Services.
- **CachedInteractive (11)**: Διαδραστική σύνδεση με χρήση αποθηκευμένων διαπιστευτηρίων domain.
- **CachedRemoteInteractive (12)**: Αποθηκευμένη απομακρυσμένη διαδραστική σύνδεση.
- **CachedUnlock (13)**: Ξεκλείδωμα με χρήση αποθηκευμένων διαπιστευτηρίων.<sup>[[50]](#references)[[51]](#references)</sup>

#### Κωδικοί Status και Sub Status για το EventID 4625:

- **0xC0000064**: Δεν υπάρχει τέτοιος χρήστης.
- **0xC000006A**: Το όνομα χρήστη είναι σωστό, αλλά ο κωδικός πρόσβασης είναι λανθασμένος.
- **0xC0000234**: Ο λογαριασμός κλειδώθηκε.
- **0xC0000072**: Ο λογαριασμός είναι απενεργοποιημένος.
- **0xC000006F**: Σύνδεση εκτός των επιτρεπόμενων ωρών.
- **0xC0000070**: Παραβίαση περιορισμού σταθμού εργασίας.
- **0xC0000193**: Ο λογαριασμός έχει λήξει.
- **0xC0000071**: Ο κωδικός πρόσβασης έχει λήξει.
- **0xC0000133**: Η διαφορά ώρας μεταξύ client και server είναι υπερβολικά μεγάλη.
- **0xC0000224**: Ο λογαριασμός πρέπει να αλλάξει τον κωδικό πρόσβασής του.
- **0xC0000225**: `STATUS_NOT_FOUND`· ο κωδικός από μόνος του δεν υποδεικνύει σφάλμα συστήματος ή επίθεση.
- **0xC000015B**: Δεν έχει εκχωρηθεί στον λογαριασμό ο ζητούμενος τύπος σύνδεσης.<sup>[[51]](#references)[[55]](#references)</sup>

#### EventID 4616:

- **Αλλαγή ώρας**: Η ώρα του συστήματος άλλαξε. Πολλά συμβάντα οφείλονται σε συνήθεις διορθώσεις από την υπηρεσία ώρας, επομένως συσχετίστε τον χρήστη που έκανε την αλλαγή και την πηγή ώρας πριν τη θεωρήσετε αλλοίωση.<sup>[[56]](#references)</sup>

#### Event ID 12, 13, 1074, 6005, 6006, 6008 και 6009:

- **Πλαίσιο λειτουργίας και υπηρεσιών**: Το Event 12 καταγράφει την εκκίνηση του OS, το 13 τον τερματισμό του OS, το 1074 έναν προγραμματισμένο τερματισμό ή επανεκκίνηση, το 6008 έναν απρόσμενο τερματισμό και το 6009 καταγράφει την έκδοση των Windows κατά την εκκίνηση. Τα Events 6005 και 6006 υποδεικνύουν, αντίστοιχα, την εκκίνηση και τη διακοπή της υπηρεσίας Event Log· δεν αποτελούν από μόνα τους απόδειξη εκκίνησης και τερματισμού του OS.<sup>[[57]](#references)[[58]](#references)</sup>

#### EventID 1102:

- **Διαγραφή αρχείου καταγραφής**: Το Event 1102 καταγράφει ότι διαγράφηκε το αρχείο καταγραφής ελέγχου Security· διερευνήστε τον χρήστη που έκανε την ενέργεια και τα σχετικά συμβάντα, αντί να υποθέσετε πρόθεση μόνο από αυτό το συμβάν.<sup>[[62]](#references)</sup>

#### EventID για παρακολούθηση συσκευών USB:

- **20001 / 20003**: Συμβάντα εγκατάστασης συσκευής `UserPnp` που μπορούν να βοηθήσουν στον προσδιορισμό της πρώτης χρήσης ή της δραστηριότητας εγκατάστασης.
- **10000 / 10100**: Συμβάντα `DriverFrameworks-UserMode` που μπορεί να συνοδεύουν δραστηριότητα συσκευής.
- **Event ID 112**: Δραστηριότητα `DeviceSetupManager/Admin` που μπορεί να παρέχει χρονικές σημάνσεις σχετικές με τη σύνδεση συσκευής.
- Οι provider, τα κανάλια και η σημασία των συμβάντων διαφέρουν ανά έκδοση των Windows· εξετάστε το όνομα του provider και το payload του συμβάντος πριν του αποδώσετε σημασία.<sup>[[59]](#references)</sup>

Για πρακτικά παραδείγματα τύπων σύνδεσης και του σχετικού υλικού διαπιστευτηρίων, δείτε τον [αναλυτικό οδηγό της Altered Security](https://www.alteredsecurity.com/post/fantastic-windows-logon-types-and-where-to-find-credentials-in-them).<sup>[[60]](#references)</sup>

Οι λεπτομέρειες του συμβάντος, όπως ο τύπος σύνδεσης, το status, το substatus, η διεύθυνση προέλευσης και τα πεδία διεργασίας, παρέχουν πλαίσιο για το Event ID 4625· ένας κωδικός status ή ένα επαναλαμβανόμενο μοτίβο αποτυχιών αποτελεί αφορμή για διερεύνηση, όχι συμπέρασμα.<sup>[[51]](#references)[[55]](#references)</sup>

### Ανάκτηση συμβάντων Windows

Επειδή τα αρχεία καταγραφής συμβάντων είναι συνήθως κυκλικά, οι εγγραφές που αντικαταστάθηκαν από το logger μπορεί να μην είναι ανακτήσιμες. Διατηρήστε ένα forensic image ή ένα αντίγραφο εργασίας πριν αλληλεπιδράσετε με ενεργό σύστημα· χρησιμοποιήστε έναν επικυρωμένο parser ή carver, όπως το **Bulk_extractor**, μόνο αφού επιβεβαιώσετε ότι η έκδοση του εργαλείου υποστηρίζει τα δεδομένα `.evtx` που εξετάζετε, και μην αποσυνδέετε ένα σύστημα που λειτουργεί μόνο και μόνο για να προσπαθήσετε να ανακτήσετε συμβάντα.<sup>[[46]](#references)</sup>

### Εντοπισμός συνηθισμένων επιθέσεων μέσω συμβάντων Windows

Για μια πρακτική αναφορά σε event ID, δείτε τον υπάρχοντα σύνδεσμο [Red Team Recipe](https://redteamrecipe.com/event-codes/) και επαληθεύστε τα παραδείγματά του με βάση την παραπάνω τεκμηρίωση των provider.

#### Επιθέσεις Brute Force

Συσχετίστε επαναλαμβανόμενες αποτυχημένες προσπάθειες Event ID 4625 με μεταγενέστερη επιτυχημένη σύνδεση 4624, τον τύπο σύνδεσης, το status, την πηγή και το πλαίσιο του λογαριασμού· η ακολουθία αποτελεί ένδειξη προς διερεύνηση, όχι απόδειξη επίθεσης.<sup>[[50]](#references)[[51]](#references)</sup>

#### Αλλαγή ώρας

Το Event ID 4616 καταγράφει αλλαγές στην ώρα του συστήματος, οι οποίες μπορεί να περιπλέξουν την ανάλυση χρονολογίου· συγκρίνετέ το με τα τεκμήρια της υπηρεσίας ώρας και του host.<sup>[[56]](#references)</sup>

#### Παρακολούθηση συσκευών USB

Τα USB event ID εξαρτώνται από τον provider· συσχετίστε τα `UserPnp` 20001/20003, `DriverFrameworks-UserMode` 10000/10100 και `DeviceSetupManager/Admin` 112 με τα τεκμήρια SetupAPI και μητρώου.<sup>[[17]](#references)[[59]](#references)</sup>

#### Συμβάντα λειτουργίας συστήματος

Χρησιμοποιήστε τα 12/13/1074/6008/6009 για στοιχεία σχετικά με εκκίνηση, τερματισμό, επανεκκίνηση του OS και απρόσμενη απώλεια ισχύος· τα 6005/6006 σηματοδοτούν την εκκίνηση/διακοπή της υπηρεσίας Event Log.<sup>[[57]](#references)[[58]](#references)</sup>

#### Διαγραφή αρχείου καταγραφής

Το Security Event ID 1102 καταγράφει ότι διαγράφηκε το αρχείο καταγραφής ελέγχου Security και θα πρέπει να συσχετίζεται με τον υπεύθυνο λογαριασμό και τη διεργασία.<sup>[[62]](#references)</sup>
