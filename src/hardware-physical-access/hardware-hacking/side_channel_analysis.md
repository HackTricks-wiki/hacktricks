# Атаки side-channel analysis

{{#include ../../banners/hacktricks-training.md}}

Атаки side-channel відновлюють секрети, спостерігаючи за фізичним або мікроархітектурним «leakage», який *корелює* з внутрішнім станом, але *не є* частиною логічного інтерфейсу пристрою. Приклади варіюються від вимірювання миттєвого струму, який споживає smart card, до використання ефектів керування живленням CPU через мережу.

Для цілі з доступним апаратним налагодженням ARM трасування [CoreSight ETM через SWO](arm-coresight-instruction-tracing.md) може надати орієнтир шляху виконання разом із захопленнями сигналів живлення або EM; це налагоджувальна траса, а не канал leakage.<sup>[[17]](#references)</sup>

---

## Основні канали leakage

| Канал | Типова ціль | Інструменти |
|---------|---------------|-----------------|
| Споживання енергії | Smart cards, IoT MCU, FPGA | Осцилограф із шунтувальним резистором або диференціальним пробником; CW503 — це джерело живлення для пробників/LNA, а не сам пробник<sup>[[11]](#references)</sup> |
| Електромагнітне поле (EM) | CPU, RFID, AES-прискорювачі | H-field/near-field probe із малошумним підсилювачем та осцилографом або SDR-приймачем, як-от RTL-SDR<sup>[[13]](#references)</sup> |
| Час виконання / кеші | Настільні та хмарні CPU | Високоточні таймери (`rdtsc`/`rdtscp`) або віддалений час проходження сигналу |
| Акустичні / механічні сигнали | Клавіатури, 3-D-принтери, принтери, реле та регулятори напруги CPU | MEMS-мікрофон або лазерний віброметр<sup>[[6]](#references)[[9]](#references)[[14]](#references)[[15]](#references)</sup> |
| Оптичні та теплові сигнали | Індикаторні LED, дисплеї, DRAM і пристрої з тепловим зв’язком | Фотодіод, високошвидкісна камера або IR-камера<sup>[[7]](#references)[[16]](#references)</sup> |
| Ін’єкція збоїв | Криптографія ASIC/MCU | Глітчинг тактового сигналу/напруги, EMFI або лазерна ін’єкція |

## Аналіз енергоспоживання

### Simple Power Analysis (SPA)
Спостерігайте за *однією* трасою та зіставляйте помітні особливості з такими операціями, як розгалуження, модульне множення або різні послідовності інструкцій.<sup>[[1]](#references)</sup>

Точна конфігурація залежить від цілі. У прикладі нижче використовується актуальний високорівневий API захоплення ChipWhisperer після підключення та налаштування осцилографа й цілі:<sup>[[1]](#references)</sup>

```python
import chipwhisperer as cw

scope = cw.scope()
scope.default_setup()
target = cw.target(scope)
ktp = cw.ktp.Basic()
key, plaintext = ktp.next()
trace = cw.capture_trace(scope, target, plaintext, key)
if trace is not None:
    print(trace.wave)  # NumPy array of power samples
```

### Differential/Correlation Power Analysis (DPA/CPA)
Зберіть кілька трас, висуньте гіпотезу щодо байта ключа `k`, обчисліть модель витоку на основі ваги Геммінга (HW) або відстані Геммінга (HD) та обчисліть кореляцію з кожним відліком. Потрібна кількість трас залежить від цілі, шуму, вирівнювання, контрзаходів і моделі витоку; фіксованого порога немає.
```python
import numpy as np
corr = np.corrcoef(leakage_model(k), traces[:,sample])
```
CPA є стандартним базовим методом. Template attacks, mutual-information analysis і підходи машинного навчання можуть бути корисними, коли витік нелінійний або траси погано вирівняні.

## Електромагнітний аналіз (EMA)
Аналіз ближнього поля дає змогу спостерігати активність, залежну від даних, не вставляючи шунт у ланцюг живлення. Він не обов’язково виявляє той самий сигнал, що й трасування живлення: важливі положення та орієнтація зонда, смуга пропускання, підсилення вхідного каскаду, якість trigger і відстань.

## Атаки на час виконання та мікроархітектуру
Сучасні CPU витікають секретами через спільні ресурси:
* **Hertzbleed (2022)** — залежне від даних динамічне масштабування напруги та частоти створює віддалений канал за часом виконання. В оригінальній наскрізній демонстрації відновлення ключа атакували SIKE; у подальших роботах розглянуто інші примітиви.<sup>[[2]](#references)</sup>
* **Downfall / Gather Data Sampling (Intel, 2023)** — спекулятивне виконання може розкрити дані, що використовуються інструкціями векторного збирання, через межі безпеки.<sup>[[3]](#references)</sup>
* **Zenbleed (AMD, 2023)** — неправильна обробка стану спекулятивних векторних регістрів може розкрити дані з того самого фізичного ядра.<sup>[[4]](#references)</sup>
* **Inception (AMD, 2023)** — атака на спекулятивне виконання поєднує phantom execution із навчанням під час спекулятивного виконання, створюючи гаджети неправильного передбачення, контрольовані зловмисником.<sup>[[5]](#references)</sup>

## Акустичні та оптичні атаки
В контрольованому експерименті акустичний витік використовували для відновлення ключів RSA за шумом ноутбука, зокрема за допомогою мікрофона мобільного телефона поблизу.<sup>[[6]](#references)</sup> В окремому дослідженні клавіатур 2023 року натискання клавіш класифікували з точністю 95%, якщо модель навчали на записах із телефона поблизу, і 93% — якщо навчали на аудіо Zoom; ці показники стосуються експерименту з навчанням на конкретному пристрої, описаного в статті, а не довільної клавіатури чи жертви.<sup>[[9]](#references)</sup> Оптичні випромінювання індикаторів стану також можна корелювати з обробленими даними. Ці результати залежать від цілі та умов експерименту; не слід узагальнювати їхню дальність чи успішність для інших пристроїв.<sup>[[7]](#references)</sup>

## Ін’єкція збоїв і диференційний аналіз збоїв (DFA)
Поєднання контрольованих збоїв зі спостереженнями побічних каналів може скоротити перебір ключів для деяких алгоритмів та реалізацій. До поширених лабораторних платформ належать функції глітчингу напруги/тактового сигналу ChipWhisperer і спеціалізовані інструменти EM-ін’єкції збоїв, як-от ChipSHOUTER або PicoEMP. Не слід використовувати твердження з попередньої версії про «менше ніж 1 нс» як специфікацію: в опублікованому посібнику ChipSHOUTER вказано типову тривалість імпульсу **15–80 нс** для наконечника 1 мм і **24–480 нс** для наконечника 4 мм (хоча джиттер trigger/імпульсу вказано в пікосекундах). Необхідна роздільна здатність за часом, розміщення зонда та кількість вихідних даних зі збоями залежать від цілі й моделі збоїв.<sup>[[1]](#references)[[10]](#references)</sup>

## Неперевірені дослідницькі зачіпки, залишені з попередньої версії

У попередній версії також стверджувалося, що: EM-система **500 MHz–3 GHz** відновила ключ STM32 з відстані понад **10 cm** за допомогою RTL-SDR; світлодіод активності DDR4 розкрив ключ раунду AES менш ніж за хвилину на «Black Hat 2023»; а в 2025 році з’явилася платформа глітчингу RISC-V з відкритим кодом під назвою **GlitchKit-R5**. Під час цієї перевірки не вдалося знайти відповідну першоджерельну статтю, матеріали конференції чи репозиторій проєкту. Ці конкретні деталі залишено як зачіпки для пошуку/відтворення, а не як підтверджені результати чи рекомендації щодо інструментів.

## Типовий процес атаки
1. Визначте канал витоку й точку підключення (контакт VCC, розв’язувальний конденсатор, ділянка ближнього поля).
2. Додайте trigger (GPIO або на основі шаблону).  
3. Зберіть достатньо трас для вибраного статистичного тесту, записуючи відкритий текст/шифротекст та інші метадані.
4. Попередньо обробіть дані (вирівнювання, віднімання середнього, LP/HP-фільтр, вейвлет, PCA).
5. Відновіть ключ статистичними методами або ML (CPA, MIA, DL-SCA).
6. Перевірте результат і повторіть аналіз для викидів.

## Захист і посилення безпеки
* Реалізації із **сталим часом виконання** та алгоритми з високими вимогами до пам’яті.
* **Маскування/перемішування** — розділення секретів на випадкові частки; стійкість до атак першого порядку сертифікована за допомогою TVLA.
* **Приховування** — вбудовані регулятори напруги, рандомізований тактовий сигнал, логіка з двома шинами, EM-екрани.
* **Виявлення збоїв** — надлишкові обчислення, порогові підписи.
* **Експлуатаційні заходи** — вимкнення DVFS/turbo в криптографічних ядрах, ізоляція SMT, заборона спільного розміщення у хмарних середовищах із кількома орендарями.

## Інструменти та фреймворки
* **ChipWhisperer-Husky** (2024) — осцилограф 500 MS/s + trigger Cortex-M; API Python, як описано вище.<sup>[[1]](#references)</sup>
* **Продукти Riscure Inspector та для ін’єкції збоїв** — комерційні засоби аналізу й автоматизованого тестування.
* **scaaml** — інструменти SCA на основі TensorFlow для глибинного навчання та набори даних.<sup>[[12]](#references)</sup>
* **pyecsca** — інструментарій із відкритим кодом для зворотного проєктування реалізацій ECC «чорної скриньки» за допомогою побічних каналів.<sup>[[8]](#references)</sup>
