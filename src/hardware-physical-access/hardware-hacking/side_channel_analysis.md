# Атаки аналізу побічних каналів

{{#include ../../banners/hacktricks-training.md}}

Атаки побічними каналами дають змогу відновити секрети, спостерігаючи за фізичним або мікроархітектурним «leakage», який *корелює* з внутрішнім станом, але не є частиною логічного інтерфейсу пристрою. Приклади варіюються від вимірювання миттєвого струму, споживаного смарт-карткою, до використання ефектів керування живленням CPU через мережу.

---

## Основні канали витоку

| Канал | Типова ціль | Вимірювальне обладнання |
|---------|---------------|-----------------|
| Енергоспоживання | Смарт-картки, IoT MCU, FPGA | Осцилограф із шунтувальним резистором або диференційним пробником; CW503 — це блок живлення для пробників/LNA, а не пробник<sup>[[11]](#references)</sup> |
| Електромагнітне поле (EM) | CPU, RFID, AES-прискорювачі | H-полевий/ближньопольовий пробник із малошумним підсилювачем та осцилографом або SDR-приймачем, наприклад RTL-SDR<sup>[[13]](#references)</sup> |
| Час виконання / кеші | Настільні та хмарні CPU | Високоточні таймери (`rdtsc`/`rdtscp`) або віддалене вимірювання часу проходження сигналу |
| Акустичні / механічні | Клавіатури, 3D-принтери, принтери, реле та регулятори напруги CPU | MEMS-мікрофон або лазерний віброметр<sup>[[6]](#references)[[9]](#references)[[14]](#references)[[15]](#references)</sup> |
| Оптичні та теплові | Індикаторні LED, дисплеї, DRAM та термічно пов’язані пристрої | Фотодіод, високошвидкісна камера або ІЧ-камера<sup>[[7]](#references)[[16]](#references)</sup> |
| Ін’єкція збоїв | Криптографія ASIC/MCU | Глітч тактового сигналу/напруги, EMFI або лазерна ін’єкція |

## Аналіз енергоспоживання

### Simple Power Analysis (SPA)
Спостерігайте за *однією* трасою та зіставляйте видимі особливості з такими операціями, як розгалуження, модульне множення або різні послідовності інструкцій.<sup>[[1]](#references)</sup>

Точна конфігурація залежить від цільового пристрою. У прикладі нижче використовується актуальний високорівневий API захоплення даних ChipWhisperer після під’єднання та налаштування осцилографа й цільового пристрою:<sup>[[1]](#references)</sup>

```python
import chipwhisperer as cw

scope = cw.scope()
scope.default_setup()
target = cw.target(scope)
ktp = cw.ktp.Basic()
key, plaintext = ktp.next()
trace = cw.capture_trace(scope, target, plaintext, key)
if trace is not None:
    print(trace.wave)  # NumPy array of power samples
```

### Диференційний/кореляційний аналіз енергоспоживання (DPA/CPA)
Зберіть кілька трас, висуньте гіпотезу щодо байта ключа `k`, обчисліть модель витоку на основі ваги Геммінга (HW) або відстані Геммінга (HD) та обчисліть її кореляцію з кожним відліком. Необхідна кількість трас залежить від цілі, шуму, вирівнювання, контрзаходів і моделі витоку; фіксованого порога немає.
```python
import numpy as np
corr = np.corrcoef(leakage_model(k), traces[:,sample])
```
CPA — стандартний базовий метод. Template attacks, mutual-information analysis і підходи на основі машинного навчання можуть бути корисними, коли витік нелінійний або траси погано вирівняні.

## Електромагнітний аналіз (EMA)
Аналіз ближнього поля дає змогу спостерігати за активністю, залежною від даних, не вставляючи шунт у ланцюг живлення. Він не обов’язково виявляє той самий сигнал, що й траса живлення: важливі положення й орієнтація зонда, смуга пропускання, підсилення вхідного каскаду, якість тригера та відстань.

## Атаки на час виконання та мікроархітектуру
Сучасні CPU витікають секрети через спільні ресурси:
* **Hertzbleed (2022)** — залежне від даних динамічне масштабування напруги та частоти створює канал віддаленого вимірювання часу. Початкова демонстрація відновлення ключа від початку до кінця була націлена на SIKE; у подальших роботах розглядаються й інші примітиви.<sup>[[2]](#references)</sup>
* **Downfall / Gather Data Sampling (Intel, 2023)** — спекулятивне виконання може розкривати дані, які використовують інструкції векторного gather, долаючи межі безпеки.<sup>[[3]](#references)</sup>
* **Zenbleed (AMD, 2023)** — некоректне оброблення стану спекулятивних векторних регістрів може розкривати дані з того самого фізичного ядра.<sup>[[4]](#references)</sup>
* **Inception (AMD, 2023)** — атака на спекулятивне виконання поєднує phantom execution із навчанням у спекулятивному виконанні, створюючи гаджети помилкового передбачення, контрольовані атакувальником.<sup>[[5]](#references)</sup>

## Акустичні та оптичні атаки
Акустичний витік використовували для відновлення ключів RSA за шумом ноутбука в контрольованому експерименті, зокрема за допомогою мікрофона мобільного телефона поблизу.<sup>[[6]](#references)</sup> В окремому дослідженні клавіатур 2023 року натискання клавіш класифікували з точністю 95%, якщо модель навчали на записах із телефона поблизу, і 93% — якщо навчали на аудіо Zoom; ці показники описують експеримент із пристроями, на яких навчали модель у цій роботі, а не будь-яку клавіатуру чи жертву.<sup>[[9]](#references)</sup> Оптичні випромінювання індикаторних LED також можна корелювати з оброблюваними даними. Ці результати залежать від цілі та налаштувань експерименту; не слід узагальнювати їхню дальність чи частоту успіху на інші пристрої.<sup>[[7]](#references)</sup>

## Ін’єкція збоїв та диференційний аналіз збоїв (DFA)
Поєднання контрольованих збоїв зі спостереженнями за побічними каналами може скоротити пошук ключа для деяких алгоритмів і реалізацій. Поширені лабораторні платформи включають функції ChipWhisperer для voltage/clock glitching і спеціалізовані інструменти EM fault-injection, як-от ChipSHOUTER або PicoEMP. Не слід використовувати твердження з попередньої версії про «менше ніж 1 нс» як специфікацію: в опублікованому посібнику ChipSHOUTER наведено типову тривалість імпульсу **15–80 нс** для наконечника 1 мм і **24–480 нс** для наконечника 4 мм (хоча jitter тригера/імпульсу вказано в пікосекундах). Необхідна роздільна здатність у часі, розташування зонда та кількість несправних вихідних даних залежать від цілі й моделі збоїв.<sup>[[1]](#references)[[10]](#references)</sup>

## Неперевірені дослідницькі зачіпки, збережені з попередньої версії

У попередній версії також стверджувалося, що: EM-система **500 МГц–3 ГГц** відновила ключ STM32 з відстані понад **10 см** за допомогою RTL-SDR; світлодіод активності DDR4 розкрив ключ раунду AES менш ніж за хвилину на «Black Hat 2023»; а у 2025 році з’явилася open-source платформа для glitching RISC-V під назвою **GlitchKit-R5**. Під час цієї перевірки не вдалося знайти відповідну першоджерельну статтю, матеріали конференції чи репозиторій проєкту. Ці точні деталі збережено як зачіпки для пошуку/відтворення, а не як підтверджені результати чи рекомендації щодо інструментів.

## Типовий робочий процес атаки
1. Визначити канал витоку та точку підключення (контакт VCC, розв’язувальний конденсатор, ділянка ближнього поля).
2. Додати trigger (GPIO або на основі шаблону).  
3. Зібрати достатньо трас для вибраного статистичного тесту, записуючи plaintext/ciphertext та інші метадані.
4. Попередньо обробити дані (вирівнювання, віднімання середнього, LP/HP-фільтр, wavelet, PCA).
5. Відновити ключ статистичними методами або за допомогою ML (CPA, MIA, DL-SCA).
6. Перевірити й повторити для викидів.

## Захист і посилення безпеки
* Реалізації **constant-time** та алгоритми з великими вимогами до пам’яті.
* **Masking/shuffling** — розділення секретів на випадкові частки; стійкість першого порядку, підтверджена TVLA.
* **Hiding** — вбудовані регулятори напруги, рандомізований clock, логіка dual-rail, EM-екрани.
* **Виявлення збоїв** — надлишкові обчислення, threshold signatures.
* **Експлуатаційні заходи** — вимикати DVFS/turbo в криптографічних ядрах, ізолювати SMT, забороняти спільне розміщення в хмарах із кількома орендарями.
