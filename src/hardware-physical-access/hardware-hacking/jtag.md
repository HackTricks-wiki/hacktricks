## JTAGenum

**JTAGenum** — це інструмент, який можна завантажити на сумісний з Arduino MCU або, в експериментальному режимі, на Raspberry Pi, щоб методом перебору визначати невідомі розпіновки JTAG і перелічувати регістри інструкцій.<sup>[[3]](#references)</sup>

- Arduino: під’єднайте цифрові контакти D2–D11 до 10 підозрюваних контактних майданчиків/тестових точок JTAG, а GND Arduino — до GND цільового пристрою. Живіть цільовий пристрій окремо, якщо не впевнені в безпечності його шини живлення. Віддавайте перевагу логіці 3,3 В (наприклад, Arduino Due) або використовуйте перетворювач рівнів/послідовні резистори під час зондування пристроїв із напругою 1,8–3,3 В.
- Raspberry Pi: у версії для Pi доступно менше GPIO (тому сканування повільніше); перевірте репозиторій, щоб дізнатися актуальну схему контактів і обмеження.

Після прошивання відкрийте монітор послідовного порту зі швидкістю 115200 бод і надішліть `h`, щоб отримати довідку. Типовий порядок дій:

- `l` знайти петлі зворотного зв’язку, щоб уникнути хибнопозитивних результатів
- `r` за потреби перемкнути внутрішні підтягувальні резистори
- `s` просканувати TCK/TMS/TDI/TDO (а іноді TRST/SRST)
- `y` перебрати IR, щоб виявити недокументовані опкоди
- `x` зробити знімок станів контактів за допомогою boundary scan

Якщо виявлено дійсний TAP, з’являться рядки, що починаються з `FOUND!` і вказують на знайдені контакти.

### Рекомендації з безпеки для JTAGenum

- Завжди з’єднуйте землі та ніколи не подавайте на невідомі контакти напругу, вищу за Vtref цільового пристрою. Якщо сумніваєтеся, додайте послідовні резистори 100–470 Ω до контактів-кандидатів.
- Якщо пристрій використовує SWD/SWJ замість 4-провідного JTAG, JTAGenum може його не виявити; спробуйте інструменти для SWD або адаптер із підтримкою SWJ-DP.

## Безпечніше визначення контактів і налаштування обладнання

- Спочатку визначте Vtref і GND за допомогою мультиметра. Багатьом адаптерам потрібен Vtref для встановлення напруги вводу/виводу.
- Перетворення рівнів: віддавайте перевагу двонапрямленим перетворювачам рівнів, призначеним для push-pull сигналів (лінії JTAG не є open-drain). Не використовуйте для JTAG I2C-перетворювачі з автоматичним визначенням напрямку.
- Корисні адаптери: плати FT2232H/FT232H (наприклад, Tigard), CMSIS-DAP, J-Link, ST-LINK (залежить від виробника), ESP-USB-JTAG (на ESP32-Sx). Під’єднайте щонайменше TCK, TMS, TDI, TDO, GND і Vtref; за бажанням — TRST і SRST.

## Перше підключення до OpenOCD (сканування та IDCODE)

OpenOCD — загальноприйнятий OSS для JTAG/SWD. За допомогою сумісного адаптера можна просканувати ланцюг і зчитати IDCODE:<sup>[[1]](#references)</sup>

- Загальний приклад із J-Link:
```
openocd -f interface/jlink.cfg -c "transport select jtag; adapter speed 1000" \
  -c "init; scan_chain; shutdown"
```
- Вбудований USB-JTAG ESP32-S3 (зовнішній адаптер не потрібен):<sup>[[2]](#references)</sup>
```
openocd -f board/esp32s3-builtin.cfg -c "init; scan_chain; shutdown"
```
### Примітки

- Якщо отримуєте IDCODE, що складається лише з одиниць/нулів, перевірте підключення, живлення, Vtref і чи не заблокований порт fuse/option bytes.
- Див. низькорівневі команди OpenOCD `irscan`/`drscan` для ручної взаємодії з TAP під час налаштування невідомих ланцюгів.<sup>[[1]](#references)</sup>

## Зупинка CPU та дамп пам’яті/flash

Коли TAP розпізнано й вибрано скрипт target, можна зупинити ядро та створити дамп областей пам’яті або внутрішньої flash. Приклади (змініть target, базові адреси та розміри):<sup>[[1]](#references)</sup>

- Generic target після init:
```
openocd -f interface/jlink.cfg -f target/stm32f1x.cfg \
  -c "init; reset halt; mdw 0x08000000 4; dump_image flash.bin 0x08000000 0x00100000; shutdown"
```
- RISC‑V SoC (перевагу надавати SBA, якщо доступний):
```
openocd -f interface/ftdi/ft232h.cfg -f target/riscv.cfg \
  -c "init; riscv set_prefer_sba on; halt; dump_image sram.bin 0x80000000 0x20000; shutdown"
```
- ESP32‑S3, запрограмувати або зчитати за допомогою помічника OpenOCD:<sup>[[2]](#references)</sup>
```
openocd -f board/esp32s3-builtin.cfg \
  -c "program_esp app.bin 0x10000 verify exit"
```

### Поради щодо дампу пам’яті

- Використовуйте `mdw/mdh/mdb`, щоб перевірити пам’ять перед створенням довгих дампів.
- Для ланцюжків із кількох пристроїв увімкніть BYPASS на пристроях, які не є цільовими, або використовуйте файл плати, у якому визначено всі TAP.

## Прийоми boundary-scan (EXTEST/SAMPLE)

Навіть якщо доступ до налагодження CPU заблоковано, boundary-scan усе ще може бути доступним. За допомогою UrJTAG/OpenOCD можна:<sup>[[1]](#references)</sup>
- Використовувати SAMPLE, щоб знімати стани контактів під час роботи системи (знайти активність шини, підтвердити розташування контактів).
- Використовувати EXTEST для керування контактами (наприклад, виконувати bit-bang для ліній зовнішньої SPI flash через MCU, щоб прочитати її офлайн, якщо це дозволяє розведення плати).

Мінімальна послідовність команд UrJTAG з адаптером FT2232x:
```
jtag> cable ft2232 vid=0x0403 pid=0x6010 interface=1
jtag> frequency 100000
jtag> detect
jtag> bsdl path /path/to/bsdl/files
jtag> instruction EXTEST
jtag> shift ir
jtag> dr  <bit pattern for boundary register>
```
Потрібен BSDL пристрою, щоб визначити порядок бітів у boundary register. Зверніть увагу: деякі виробники блокують boundary-scan комірки на виробництві.

## Сучасні цілі та примітки

- ESP32‑S3/C3 мають вбудований USB‑JTAG bridge; OpenOCD може напряму взаємодіяти з пристроєм через USB без зовнішнього probe. Дуже зручно для тріажу й отримання дампів.<sup>[[2]](#references)</sup>
- Налагодження RISC‑V (v0.13+) широко підтримується OpenOCD; для доступу до пам’яті віддавайте перевагу SBA, якщо ядро не можна безпечно зупинити.
- Багато MCU реалізують автентифікацію налагодження та стани життєвого циклу. Якщо JTAG не працює, хоча живлення в нормі, можливо, пристрій заф’южено в закритий стан або потрібен автентифікований probe.

## Захист і посилення безпеки (чого очікувати на реальних пристроях)

- Назавжди вимикайте або блокуйте JTAG/SWD на виробництві (наприклад, STM32 RDP level 2, eFuse ESP, що вимикають PAD JTAG, NXP/Nordic APPROTECT/DPAP).
- Вимагайте автентифікованого налагодження (ARMv8.2‑A ADIv6 Debug Authentication, керований OEM обмін запит-відповідь), зберігаючи доступ для виробництва.
- Не прокладайте легкодоступні тестові майданчики; ховайте тестові vias, використовуйте резистори для ізоляції TAP або знімайте їх, застосовуйте роз’єми з ключем чи pogo-pin fixtures.
- Блокування налагодження під час увімкнення живлення: блокуйте TAP за допомогою раннього ROM, що забезпечує secure boot.
