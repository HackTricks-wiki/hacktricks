# Ін’єкція сигналу прямого каналу VSAT

{{#include ../../banners/hacktricks-training.md}}

Термінал VSAT зазвичай сприймає супутниковий низхідний канал як трафік від вузла оператора. У системі DVB-RCS цей прямий канал може передавати як IP-пакети користувача, так і повідомлення керування модемом. Якщо приймач обробляє повідомлення до його автентифікації, локально ін’єктований сигнал може перетнути межу довіри між радіоканалом і площиною керування. Це **ін’єкція низхідного каналу на терміналі**, а не висхідний канал до супутника чи пасивне перехоплення низхідного каналу. Результат демонстрації залежить від реалізації протоколу модемом і автентифікації повідомлень, а не лише від DVB-RCS.<sup>[[1]](#references)[[2]](#references)</sup>

## Тестування в лабораторії з ізольованим RF-середовищем

Використовуйте власний термінал, його прошивку та SDR, під’єднаний до входу приймача модема через відповідне загасання сигналу, або екрановану RF-установку. Не випромінюйте сигнал на активному супутниковому каналі. Спершу зафіксуйте налаштовані в терміналі несучу запуску, символьну швидкість та ID групи терміналів; вони допомагають налаштувати приймання прямого каналу.<sup>[[1]](#references)[[3]](#references)</sup> У ланцюжку приймання DVB-RCS таблиця Network Information Table (NIT) використовується для пошуку RCS Map Table (RMT), а потім Program Association Table (PAT) і Program Map Table (PMT) — для пошуку потоків сигналізації прямого каналу. Перш ніж досягти потоку даних, термінал може переналаштовуватися на кілька несучих транспортного потоку.<sup>[[3]](#references)</sup>

1. Декодуйте або відтворіть транспортний потік запуску цільового термінала й перевірте його NIT, RMT, ID сервісів, ID пакетів (PID) та обробку еталонного тактового сигналу. Порівняйте стандарт із парсером і журналами цільового пристрою; специфічний для виробника порядок елементів або дескриптори можуть завадити прийманню потоку, який інакше є коректним.
2. На лабораторному передавачі інкапсулюйте безпечний UDP-запит у ланцюжок `UDP/IP → MPE → MPEG-TS → DVB-S2 I/Q` і подайте його через вихід SDR до ізольованого шляху приймання. Узгодьте Program Clock Reference (PCR) транспортного потоку зі швидкістю передавання байтів, інакше модем може втратити синхронізацію, перш ніж обробить запит.
3. Переконайтеся і в **захопленні синхронізації демодулятором**, і в отриманні запиту внутрішньою кінцевою точкою, що належить вам. Саме захоплення синхронізації доводить лише те, що фізичний рівень прийняв сигнал. Потім перевірте, чи доступна незахищена *сигналізація* керування або оновлення, не встановлюючи образ і не змінюючи конфігурацію сервісу.

У опублікованому кейсі MDM2200 використовували вихідний модуль GNU Radio для DVB-RCS/MPE/MPEG-TS і `gr-dtv` для модуляції DVB-S2. Модему були потрібні специфічні для цільового пристрою деталі ініціалізації: SDT перед PAT/PMT, дескриптор вмісту RCS з ID таблиці `0x3E` і приватний байт RMT `0x01` для режиму GSE/4CPM. Не припускайте, що ці значення підійдуть для іншого термінала.<sup>[[1]](#references)</sup> Дослідники також виявили, що в їхній конфігурації багатоадресні MPE-пакети надходили на модеми-приймачі, тож для адресації не була потрібна відома одноадресна MAC-адреса.<sup>[[1]](#references)</sup> В окремому аналізі в дослідженій системі було виявлено незахищену сигналізацію керування та оновлення програмного забезпечення, але цю знахідку потрібно перевіряти для кожної реалізації окремо.<sup>[[2]](#references)</sup>

IPsec- або VPN-тунель для трафіку користувача не автентифікує попередню сигналізацію DVB-RCS чи власний парсер оновлень модема. Під час авторизованого оцінювання розрізняйте криптографічний захист **IP-трафіку користувача**, **керування прямим каналом** і трафіку **обслуговування/відновлення**, а не вважайте захищений користувацький тунель доказом того, що ін’єкцію через радіоканал заблоковано.<sup>[[1]](#references)[[2]](#references)</sup>
