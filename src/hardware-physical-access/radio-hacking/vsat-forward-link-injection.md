# VSATフォワードリンクへの信号注入

{{#include ../../banners/hacktricks-training.md}}

VSAT端末は通常、衛星ダウンリンクからのトラフィックをオペレーターのハブからのものとして扱います。DVB-RCSシステムでは、フォワードリンクでユーザーIPパケットとモデム制御メッセージの両方を伝送できます。受信機がメッセージを処理する前に認証しない場合、ローカルで注入された信号が無線から制御プレーンへの信頼境界を越える可能性があります。これは**端末へのダウンリンク注入**であり、衛星へのアップリンクでも、受動的なダウンリンク傍受でもありません。実証された結果は、DVB-RCSだけで決まるものではなく、モデムのプロトコル実装とメッセージ認証に依存します。<sup>[[1]](#references)[[2]](#references)</sup>

## RFを封じ込めたラボでのテスト

所有する端末とそのファームウェアを使用し、適切な減衰器を介してSDRをモデムの受信入力に接続するか、シールドされたRF環境を使用します。実運用中の衛星チャネルでは送信しないでください。まず、端末に設定された起動時キャリア、シンボルレート、人口IDを記録します。これらはフォワードリンクの捕捉に役立ちます。<sup>[[1]](#references)[[3]](#references)</sup> DVB-RCSの捕捉チェーンでは、Network Information Table (NIT) を使用してRCS Map Table (RMT) を特定し、続いてProgram Association Table (PAT) とProgram Map Table (PMT) を使用してフォワードリンクのシグナリングストリームを特定します。データストリームに到達するまで、端末が複数のトランスポートストリームキャリアに再同調することがあります。<sup>[[3]](#references)</sup>

1. 対象の起動時トランスポートストリームをデコードまたは再構築し、そのNIT、RMT、サービスID、パケットID (PID)、クロック参照の処理を調べます。標準仕様と対象端末のパーサーおよびログを比較します。ベンダー固有の順序や記述子があると、本来は有効なストリームでも受け入れられないことがあります。
2. ラボの送信機で、無害なUDPプローブを `UDP/IP → MPE → MPEG-TS → DVB-S2 I/Q` としてカプセル化し、SDR sinkを通して隔離された受信経路に入力します。トランスポートストリームのProgram Clock Reference (PCR) をバイトレートに合わせてください。合っていない場合、モデムがプローブを処理する前に同期を失うことがあります。
3. **復調器のロック**と、所有する内部エンドポイントでのプローブ受信の両方を確認します。ロックだけでは、物理層が波形を受け入れたことしか証明できません。次に、イメージをインストールしたりサービス設定を変更したりせずに、認証されていない管理またはアップデートの*シグナリング*が露出しているかを確認します。

公開されたMDM2200の事例では、DVB-RCS/MPE/MPEG-TS用のGNU Radio source moduleと、DVB-S2変調用の `gr-dtv` が使用されました。このモデムには、対象固有の初期化情報が必要でした。具体的には、PAT/PMTより前のSDT、table ID `0x3E` のRCS content descriptor、およびGSE/4CPMモード用の `0x01` というRMT private byteです。別の端末でもこれらの値が使えるとは限りません。<sup>[[1]](#references)</sup> また研究者らは、実験環境ではマルチキャストMPEパケットが受信モデムに届いたことも確認しており、既知のユニキャストMACアドレスだけに宛先を限定する必要はありませんでした。<sup>[[1]](#references)</sup> 別の分析では、調査対象のシステムに保護されていない制御およびソフトウェアアップデートのシグナリングが見つかりましたが、この点は実装ごとに検証する必要があります。<sup>[[2]](#references)</sup>

ユーザートラフィック用のIPsecまたはVPNトンネルは、それ以前のDVB-RCSシグナリングや、モデム独自のアップデートパーサーを認証するものではありません。許可を得た評価では、ユーザートンネルが安全だからといって無線注入が阻止されていると判断せず、**ユーザーIP**、**フォワードリンク制御**、**保守・復旧**トラフィックの暗号学的保護を区別してください。<sup>[[1]](#references)[[2]](#references)</sup>

初期のI/Q調査については、[無線信号解析](../hardware-hacking/radio.md)を参照してください。基板上でのファームウェアおよびパーサーの調査については、[ファームウェア解析](../firmware-analysis/)を参照してください。ほかのインターフェースについては、[Radio Hackingの概要](./)に戻ってください。
