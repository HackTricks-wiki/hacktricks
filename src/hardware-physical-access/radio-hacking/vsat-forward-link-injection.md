# Έγχυση σήματος στην forward link VSAT

{{#include ../../banners/hacktricks-training.md}}

Ένα τερματικό VSAT συνήθως θεωρεί ότι η δορυφορική του downlink λαμβάνει κίνηση από τον κόμβο του παρόχου. Σε ένα σύστημα DVB-RCS, αυτή η forward link μπορεί να μεταφέρει τόσο πακέτα IP χρηστών όσο και μηνύματα ελέγχου του modem. Αν ο δέκτης δεν επαληθεύει την αυθεντικότητα ενός μηνύματος πριν το επεξεργαστεί, ένα σήμα που εισάγεται τοπικά μπορεί να διασχίσει το όριο εμπιστοσύνης μεταξύ του radio και του control plane. Αυτό είναι **έγχυση downlink στο τερματικό**, όχι uplink προς τον δορυφόρο ή παθητική υποκλοπή downlink. Το αποτέλεσμα που επιδείχθηκε εξαρτάται από την υλοποίηση πρωτοκόλλου και την αυθεντικοποίηση μηνυμάτων του modem, όχι μόνο από το DVB-RCS.<sup>[[1]](#references)[[2]](#references)</sup>

## Δοκιμή σε εργαστήριο με περιορισμένη RF εκπομπή

Χρησιμοποιήστε τερματικό που σας ανήκει, το firmware του και ένα SDR συνδεδεμένο στην είσοδο λήψης του modem μέσω κατάλληλης εξασθένησης ή χρησιμοποιήστε θωρακισμένη διάταξη RF. Μην εκπέμπετε σε ενεργό δορυφορικό κανάλι. Αρχικά, καταγράψτε τη διαμορφωμένη συχνότητα εκκίνησης του τερματικού, τον ρυθμό συμβόλων και το population ID· αυτά καθοδηγούν την απόκτηση της forward link.<sup>[[1]](#references)[[3]](#references)</sup> Η αλυσίδα απόκτησης DVB-RCS χρησιμοποιεί τον Network Information Table (NIT) για να εντοπίσει τον RCS Map Table (RMT) και, στη συνέχεια, τον Program Association Table (PAT) και τον Program Map Table (PMT), ώστε να εντοπίσει τα streams σηματοδότησης της forward link. Ένα τερματικό μπορεί να συντονιστεί διαδοχικά σε πολλούς φορείς transport stream πριν φτάσει στο data stream.<sup>[[3]](#references)</sup>

1. Αποκωδικοποιήστε ή ανακατασκευάστε το transport stream εκκίνησης του στόχου και ελέγξτε τα NIT, RMT, service IDs, packet IDs (PIDs) και τη διαχείριση των αναφορών χρονισμού. Συγκρίνετε το πρότυπο με τον parser και τα logs του στόχου· η ειδική για τον κατασκευαστή σειρά ή οι περιγραφείς μπορεί να εμποδίσουν την αποδοχή ενός κατά τα άλλα έγκυρου stream.
2. Στον εργαστηριακό πομπό, ενθυλακώστε ένα ακίνδυνο UDP probe ως `UDP/IP → MPE → MPEG-TS → DVB-S2 I/Q` και τροφοδοτήστε το μέσω εξόδου SDR στην απομονωμένη διαδρομή λήψης. Διατηρήστε το Program Clock Reference (PCR) του transport stream συνεπές με τον ρυθμό byte, διαφορετικά το modem μπορεί να χάσει τον συγχρονισμό πριν επεξεργαστεί το probe.
3. Επιβεβαιώστε τόσο το **κλείδωμα του demodulator** όσο και τη λήψη του probe σε εσωτερικό endpoint που σας ανήκει. Το κλείδωμα από μόνο του αποδεικνύει μόνο ότι το φυσικό επίπεδο αποδέχτηκε την κυματομορφή. Στη συνέχεια, ελέγξτε αν εκτίθεται μη αυθεντικοποιημένη σηματοδότηση διαχείρισης ή ενημέρωσης, χωρίς να εγκαταστήσετε image ή να αλλάξετε τη διαμόρφωση υπηρεσιών.

Η δημοσιευμένη περίπτωση MDM2200 χρησιμοποίησε ένα source module GNU Radio για DVB-RCS/MPE/MPEG-TS και το `gr-dtv` για διαμόρφωση DVB-S2. Το modem απαιτούσε λεπτομέρειες αρχικοποίησης ειδικές για τον στόχο: SDT πριν από τα PAT/PMT, έναν RCS content descriptor με table ID `0x3E` και ένα RMT private byte `0x01` για τη λειτουργία GSE/4CPM. Μην υποθέσετε ότι αυτές οι τιμές λειτουργούν σε άλλο τερματικό.<sup>[[1]](#references)</sup> Οι ερευνητές παρατήρησαν επίσης ότι τα multicast MPE packets έφταναν στα modem που λάμβαναν στο περιβάλλον τους, επομένως η στόχευση δεν περιοριζόταν σε γνωστή unicast MAC address.<sup>[[1]](#references)</sup> Μια ξεχωριστή ανάλυση εντόπισε μη προστατευμένη σηματοδότηση ελέγχου και ενημέρωσης λογισμικού στο σύστημα που μελετήθηκε, αλλά αυτό το εύρημα πρέπει να επαληθεύεται για κάθε υλοποίηση.<sup>[[2]](#references)</sup>

Ένα IPsec ή VPN tunnel για την κίνηση χρηστών δεν αυθεντικοποιεί την προγενέστερη σηματοδότηση DVB-RCS ούτε τον parser ενημερώσεων του ίδιου του modem. Σε μια εξουσιοδοτημένη αξιολόγηση, διακρίνετε την κρυπτογραφική προστασία της **κίνησης IP χρηστών**, του **ελέγχου της forward link** και της κίνησης **συντήρησης/ανάκτησης**, αντί να θεωρείτε ότι ένα ασφαλές tunnel χρηστών αποδεικνύει πως έχει αποκλειστεί η έγχυση μέσω radio.<sup>[[1]](#references)[[2]](#references)</sup>

Για αρχική επιθεώρηση I/Q, δείτε την [ανάλυση ραδιοσημάτων](../hardware-hacking/radio.md). Για επιθεώρηση firmware και parser από την πλευρά της πλακέτας, δείτε την [ανάλυση firmware](../firmware-analysis/). Επιστρέψτε στην [επισκόπηση Radio Hacking](./) για άλλες διεπαφές.
