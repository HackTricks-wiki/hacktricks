## ECC / ECDSA

Якщо задіяні підписи, спочатку перевірте проблеми з nonce (повторне використання/зміщення/leaks), перш ніж припускати складну математику.

### Повторне використання / зміщення nonce ECDSA

Якщо два підписи використовують один і той самий nonce `k`, приватний ключ можна відновити.

Навіть якщо `k` не є ідентичним, **зміщення/витік** бітів nonce між підписами може бути достатнім для відновлення за допомогою lattice (поширена тема CTF).

Технічне відновлення, коли `k` повторно використовується:

Рівняння підпису ECDSA (порядок групи `n`):

- `r = (kG)_x mod n`
- `s = k^{-1}(h(m) + r*d) mod n`

Якщо один і той самий `k` повторно використовується для двох повідомлень `m1, m2`, у результаті чого отримано підписи `(r, s1)` і `(r, s2)`:

- `k = (h(m1) - h(m2)) * (s1 - s2)^{-1} mod n`
- `d = (s1*k - h(m1)) * r^{-1} mod n`

### Атаки на invalid-curve

Якщо протокол не перевіряє, що точки належать очікуваній кривій (або підгрупі), атакер може змусити виконувати операції у слабкій групі та відновити секрети.

Технічна примітка:

- Перевіряйте, що точки належать кривій і правильній підгрупі.
- У багатьох задачах CTF це моделюється як «сервер множить обрану атакером точку на секретний скаляр і повертає щось».
