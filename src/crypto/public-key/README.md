## ECC / ECDSA

Якщо задіяні підписи, перевірте повторне використання nonce, його зміщення або витік, перш ніж припускати, що потрібно розв’язати задачу дискретного логарифмування.

### Повторне використання / зміщення nonce в ECDSA

ECDSA вимагає нового секретного числа `k` для кожного повідомлення. Якщо те саме `k` підписує хеші двох різних повідомлень, приватний ключ можна відновити з публічних значень підписів.<sup>[[4]](#references)</sup>

Навіть коли `k` не є ідентичним, зміщення або витік бітів nonce у багатьох підписах може уможливити відновлення на основі ґраток.<sup>[[5]](#references)</sup>

Технічне відновлення, коли `k` використовується повторно:<sup>[[4]](#references)</sup>

Рівняння підпису ECDSA (порядок групи `n`):

- `r = (kG)_x mod n`
- `s = k^{-1}(h(m) + r*d) mod n`

Якщо те саме `k` використовується повторно для двох повідомлень `m1, m2`, у результаті чого утворюються підписи `(r, s1)` і `(r, s2)`:

- `k = (h(m1) - h(m2)) * (s1 - s2)^{-1} mod n`
- `d = (s1*k - h(m1)) * r^{-1} mod n`

### Атаки на недійсні криві

Якщо протокол не перевіряє, що вхідна точка належить очікуваній кривій і правильній підгрупі, attacker може змусити виконувати операції у слабшій групі та відновити інформацію про секретний скаляр. SEC 1 визначає перевірки відкритого ключа, призначені для запобігання таким вхідним даним.<sup>[[6]](#references)</sup>

Технічна примітка:

- Перевіряйте, що точки не є точкою на нескінченності, мають дійсні координати, задовольняють рівняння кривої та належать до необхідної підгрупи.<sup>[[6]](#references)</sup>
- У задачах CTF це часто моделюється як server, що множить обрану attacker точку на секретний скаляр і повертає похідне значення.
