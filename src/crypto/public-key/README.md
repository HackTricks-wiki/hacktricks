# Κρυπτογραφία δημόσιου κλειδιού

{{#include ../../banners/hacktricks-training.md}}

Πολλές προχωρημένες προκλήσεις κρυπτογραφίας CTF περιλαμβάνουν RSA, κρυπτογραφία ελλειπτικών καμπυλών (ECC), ECDSA, πλέγματα ή αδύναμη τυχαιότητα.

## Προτεινόμενα εργαλεία

- [SageMath](https://www.sagemath.org/) για modular αριθμητική, ελλειπτικές καμπύλες και αναγωγή πλεγμάτων<sup>[[1]](#references)</sup>
- [RsaCtfTool](https://github.com/RsaCtfTool/RsaCtfTool) για τον έλεγχο συνηθισμένων αδυναμιών του RSA<sup>[[2]](#references)</sup>
- [FactorDB](https://factordb.com/) για να ελέγχετε αν ένας ακέραιος έχει γνωστούς παράγοντες<sup>[[3]](#references)</sup>
- Η Python [`ecdsa` library](https://ecdsa.readthedocs.io/) για ανάλυση κλειδιών, υπογραφή και επαλήθευση<sup>[[7]](#references)</sup>

## ECC / ECDSA

Αν εμπλέκονται υπογραφές, ελέγξτε για επαναχρησιμοποίηση, μεροληψία ή διαρροή nonce προτού υποθέσετε ότι πρέπει να λυθεί το υποκείμενο πρόβλημα διακριτού λογαρίθμου.

### Επαναχρησιμοποίηση / μεροληψία nonce στο ECDSA

Το ECDSA απαιτεί έναν νέο μυστικό αριθμό `k` για κάθε μήνυμα. Αν το ίδιο `k` υπογράψει δύο διαφορετικά hash μηνυμάτων, το ιδιωτικό κλειδί μπορεί να ανακτηθεί από τις δημόσιες τιμές των υπογραφών.<sup>[[4]](#references)</sup>

Ακόμα κι όταν το `k` δεν είναι ίδιο, η μεροληψία ή η διαρροή bit του nonce σε πολλές υπογραφές μπορεί να επιτρέψει ανάκτηση με χρήση πλεγμάτων.<sup>[[5]](#references)</sup>

Τεχνική ανάκτηση όταν το `k` επαναχρησιμοποιείται:<sup>[[4]](#references)</sup>

Εξισώσεις υπογραφής ECDSA (τάξη ομάδας `n`):

- `r = (kG)_x mod n`
- `s = k^{-1}(h(m) + r*d) mod n`

Αν το ίδιο `k` επαναχρησιμοποιηθεί για δύο μηνύματα `m1, m2`, παράγοντας τις υπογραφές `(r, s1)` και `(r, s2)`:

- `k = (h(m1) - h(m2)) * (s1 - s2)^{-1} mod n`
- `d = (s1*k - h(m1)) * r^{-1} mod n`

### Επιθέσεις invalid-curve

Αν ένα πρωτόκολλο δεν επαληθεύει ότι ένα σημείο εισόδου ανήκει στην αναμενόμενη καμπύλη και στη σωστή υποομάδα, ένας επιτιθέμενος μπορεί να εξαναγκάσει πράξεις σε ασθενέστερη ομάδα και να ανακτήσει πληροφορίες για έναν μυστικό scalar. Το SEC 1 ορίζει ελέγχους επικύρωσης δημόσιου κλειδιού, οι οποίοι αποσκοπούν στην αποτροπή τέτοιων εισόδων.<sup>[[6]](#references)</sup>

Τεχνική σημείωση:

- Επαληθεύστε ότι τα σημεία δεν είναι το σημείο στο άπειρο, έχουν έγκυρες συντεταγμένες, ικανοποιούν την εξίσωση της καμπύλης και ανήκουν στην απαιτούμενη υποομάδα.<sup>[[6]](#references)</sup>
- Σε προκλήσεις CTF, αυτό συχνά μοντελοποιείται ως ένας server που πολλαπλασιάζει ένα σημείο, επιλεγμένο από τον επιτιθέμενο, με έναν μυστικό scalar και επιστρέφει μια παράγωγη τιμή.

## Διαρροή μέσω rejection sampling από κακοσχηματισμένα κλειδιά υπογραφής ML-DSA

Το expanded private key του ML-DSA κωδικοποιεί τα πολυωνυμικά διανύσματα `s1` και `s2` με συντελεστές στο `[-η, η]`. Το FIPS 204 επισημαίνει ότι η αποκωδικοποίηση κακοσχηματισμένων bytes μυστικού κλειδιού μπορεί να παράγει συντελεστές εκτός αυτού του εύρους. Ο αλγόριθμος υπογραφής δεν απαιτεί από μόνος του πρόσθετο έλεγχο συνέπειας του ιδιωτικού κλειδιού.<sup>[[8]](#references)</sup>

Η σχετική προϋπόθεση είναι να έχει κάποιος τον έλεγχο ενός **expanded signing key πριν από την εισαγωγή του ή τη χρήση του για υπογραφή**, όχι ενός κακοσχηματισμένου δημόσιου κλειδιού που υποβάλλεται σε verifier. Μια permissive διαδρομή εισαγωγής μπορεί να αποδεχτεί τροποποιημένους packed συντελεστές και παρ' όλα αυτά να παράγει υπογραφές που επαληθεύονται. Συγκρίνετε την αποδοχή κατά την εισαγωγή και την υπογραφή και, στη συνέχεια, ελέγξτε τις παραγόμενες υπογραφές, χρησιμοποιώντας τη [ροή εργασίας fuzzing κωδικοποιήσεων κρυπτογραφικών κλειδιών](../../generic-methodologies-and-resources/fuzzing.md#differential-fuzzing-of-cryptographic-key-encodings).<sup>[[9]](#references)[[10]](#references)</sup>

Η υπογραφή υπολογίζει τα `z = y + c·s1` και `r0 = LowBits(w − c·s2)`, απορρίπτοντας ένα υποψήφιο αποτέλεσμα όταν `||z||∞ ≥ γ1 − β` ή `||r0||∞ ≥ γ2 − β`. Αυτοί οι έλεγχοι καθιστούν τις αποδεκτές εξόδους ανεξάρτητες από τα έγκυρα μικρά μυστικά. Συντελεστές μυστικού κλειδιού εκτός εύρους μπορούν να διαταράξουν αυτό το επιχείρημα για το rejection sampling και να εισαγάγουν μεροληψία που εξαρτάται από το μυστικό. Πρόκειται για έναν υπό όρους μηχανισμό διαρροής, **όχι** για αποδεδειγμένη ανάκτηση ολόκληρου του κλειδιού βάσει της αναφερθείσας απόκλισης μεταξύ βιβλιοθηκών.<sup>[[8]](#references)[[10]](#references)</sup>

Η επικύρωση ιδιωτικού κλειδιού είναι διαφορετική από την επαλήθευση υπογραφής. Στη σύγκριση που αναφέρθηκε, τα OpenSSL, BoringSSL και SymCrypt εφάρμοζαν πρόσθετους ελέγχους ιδιωτικού κλειδιού, ενώ το liboqs δεχόταν κακοσχηματισμένα expanded keys κατά την υπογραφή· το υποκείμενο `mldsa-native` παρέχει validator `pk_from_sk()`, τον οποίο το liboqs δεν εξέθετε. Το FIPS 204 δεν επιβάλλει αυτούς τους πρόσθετους ελέγχους επικύρωσης.<sup>[[9]](#references)[[10]](#references)</sup>
