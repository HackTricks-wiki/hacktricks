# Криптографія з відкритим ключем

{{#include ../../banners/hacktricks-training.md}}

У багатьох складних криптографічних CTF-завданнях використовуються RSA, криптографія на еліптичних кривих (ECC), ECDSA, ґратки або слабка випадковість.

## Рекомендовані інструменти

- [SageMath](https://www.sagemath.org/) для модульної арифметики, еліптичних кривих і редукції ґраток<sup>[[1]](#references)</sup>
- [RsaCtfTool](https://github.com/RsaCtfTool/RsaCtfTool) для перевірки поширених слабкостей RSA<sup>[[2]](#references)</sup>
- [FactorDB](https://factordb.com/) для перевірки, чи має ціле число відомі множники<sup>[[3]](#references)</sup>
- Бібліотека Python [`ecdsa`](https://ecdsa.readthedocs.io/) для розбору ключів, підписування та перевірки підписів<sup>[[7]](#references)</sup>

## ECC / ECDSA

Якщо йдеться про підписи, перевірте повторне використання nonce, упередженість або витік даних, перш ніж вважати, що потрібно розв’язати задачу дискретного логарифмування.

### ECDSA nonce reuse / bias

Для кожного повідомлення ECDSA потрібне нове секретне число `k`. Якщо те саме `k` використовується для підпису хешів двох різних повідомлень, приватний ключ можна відновити за значеннями відкритих підписів.<sup>[[4]](#references)</sup>

Навіть якщо `k` не збігаються, упередженість або витік бітів nonce у багатьох підписах можуть уможливити відновлення на основі ґраток.<sup>[[5]](#references)</sup>

Технічне відновлення у разі повторного використання `k`:<sup>[[4]](#references)</sup>

Рівняння підпису ECDSA (порядок групи `n`):

- `r = (kG)_x mod n`
- `s = k^{-1}(h(m) + r*d) mod n`

Якщо те саме `k` повторно використано для двох повідомлень `m1, m2`, що дають підписи `(r, s1)` і `(r, s2)`:

- `k = (h(m1) - h(m2)) * (s1 - s2)^{-1} mod n`
- `d = (s1*k - h(m1)) * r^{-1} mod n`

### Invalid-curve attacks

Якщо протокол не перевіряє, що вхідна точка лежить на очікуваній кривій і належить до правильної підгрупи, зловмисник може змусити виконувати операції у слабшій групі й отримати інформацію про секретний скаляр. У стандарті SEC 1 визначено перевірки відкритих ключів, призначені для запобігання таким атакам.<sup>[[6]](#references)</sup>

Технічна примітка:

- Перевірте, що точки не є точкою на нескінченності, мають коректні координати, задовольняють рівняння кривої та належать до потрібної підгрупи.<sup>[[6]](#references)</sup>
- У CTF-завданнях це часто моделюється як сервер, що множить вибрану зловмисником точку на секретний скаляр і повертає похідне значення.
