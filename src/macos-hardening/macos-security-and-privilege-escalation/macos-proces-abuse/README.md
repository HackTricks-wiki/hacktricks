## Βασικές πληροφορίες για τις διεργασίες

Μια διεργασία είναι ένα στιγμιότυπο ενός εκτελέσιμου προγράμματος που εκτελείται. Ωστόσο, οι διεργασίες δεν εκτελούν κώδικα· αυτό το κάνουν τα νήματα. Επομένως, **οι διεργασίες είναι απλώς περιέκτες για νήματα που εκτελούνται**, οι οποίοι παρέχουν μνήμη, descriptors, θύρες, δικαιώματα...

Παραδοσιακά, οι διεργασίες ξεκινούσαν μέσα από άλλες διεργασίες (εκτός από την PID 1) με την κλήση της **`fork`**, η οποία δημιουργούσε ένα ακριβές αντίγραφο της τρέχουσας διεργασίας. Έπειτα, η **θυγατρική διεργασία** καλούσε συνήθως την **`execve`** για να φορτώσει το νέο εκτελέσιμο πρόγραμμα και να το εκτελέσει. Στη συνέχεια, εισήχθη η **`vfork`** για να επιταχύνει αυτή τη διαδικασία χωρίς αντιγραφή μνήμης.\
Έπειτα, εισήχθη η **`posix_spawn`**, που συνδύαζε τις **`vfork`** και **`execve`** σε μία κλήση και δεχόταν σημαίες:

- `POSIX_SPAWN_RESETIDS`: Επαναφορά των effective ids στα real ids
- `POSIX_SPAWN_SETPGROUP`: Ορισμός της ένταξης σε ομάδα διεργασιών
- `POSUX_SPAWN_SETSIGDEF`: Ορισμός της προεπιλεγμένης συμπεριφοράς των σημάτων
- `POSIX_SPAWN_SETSIGMASK`: Ορισμός της μάσκας σημάτων
- `POSIX_SPAWN_SETEXEC`: Εκτέλεση στην ίδια διεργασία (όπως η `execve`, με περισσότερες επιλογές)
- `POSIX_SPAWN_START_SUSPENDED`: Εκκίνηση σε αναστολή
- `_POSIX_SPAWN_DISABLE_ASLR`: Εκκίνηση χωρίς ASLR
- `_POSIX_SPAWN_NANO_ALLOCATOR:` Χρήση του Nano allocator του libmalloc
- `_POSIX_SPAWN_ALLOW_DATA_EXEC:` Να επιτρέπεται `rwx` στα τμήματα δεδομένων
- `POSIX_SPAWN_CLOEXEC_DEFAULT`: Κλείσιμο όλων των file descriptions κατά το exec(2) από προεπιλογή
- `_POSIX_SPAWN_HIGH_BITS_ASLR:` Τυχαιοποίηση των υψηλών bits της μετατόπισης ASLR

Επιπλέον, η `posix_spawn` δέχεται ρυθμίσεις **`posix_spawnattr`** που ελέγχουν πτυχές της διεργασίας που δημιουργείται, καθώς και εγγραφές **`posix_spawn_file_actions`** που τροποποιούν τους file descriptors.

Όταν μια διεργασία τερματίζεται, στέλνει τον **κωδικό επιστροφής στη γονική διεργασία** (αν η γονική διεργασία έχει τερματιστεί, νέα γονική διεργασία είναι η PID 1) με το σήμα `SIGCHLD`. Η γονική διεργασία πρέπει να λάβει αυτή την τιμή καλώντας τις `wait4()` ή `waitid()`. Μέχρι να συμβεί αυτό, η θυγατρική διεργασία παραμένει σε κατάσταση zombie: εξακολουθεί να εμφανίζεται στη λίστα, αλλά δεν καταναλώνει πόρους.

### PIDs

Τα PIDs (αναγνωριστικά διεργασιών) προσδιορίζουν μια μοναδική διεργασία. Στο XNU, τα **PIDs** είναι **64 bit**, αυξάνονται μονότονα και **δεν ανακυκλώνονται ποτέ** (για την αποφυγή καταχρήσεων).

### Ομάδες διεργασιών, συνεδρίες και coalations

Οι **διεργασίες** μπορούν να ενταχθούν σε **ομάδες**, ώστε να είναι ευκολότερη η διαχείρισή τους. Για παράδειγμα, οι εντολές σε ένα shell script ανήκουν στην ίδια ομάδα διεργασιών, επομένως είναι δυνατή η **αποστολή σήματος σε όλες μαζί**, για παράδειγμα με το kill.\
Είναι επίσης δυνατό να **ομαδοποιηθούν διεργασίες σε συνεδρίες**. Όταν μια διεργασία ξεκινά μια συνεδρία (`setsid(2)`), οι θυγατρικές διεργασίες εντάσσονται σε αυτήν, εκτός αν ξεκινήσουν τη δική τους συνεδρία.

Το Coalition είναι ένας ακόμη τρόπος ομαδοποίησης διεργασιών στο Darwin. Όταν μια διεργασία εντάσσεται σε ένα coalition, μπορεί να έχει πρόσβαση σε κοινόχρηστους πόρους, να μοιράζεται ένα ledger ή να αντιμετωπίζει το Jetsam. Τα coalitions έχουν διαφορετικούς ρόλους: Leader, XPC service, Extension.

### Διαπιστευτήρια και personae

Κάθε διεργασία διατηρεί **διαπιστευτήρια** που **προσδιορίζουν τα δικαιώματά της** στο σύστημα. Κάθε διεργασία έχει ένα κύριο `uid` και ένα κύριο `gid` (αν και μπορεί να ανήκει σε πολλές ομάδες).\
Είναι επίσης δυνατό να αλλάξουν τα user και group id, αν το binary έχει το bit `setuid/setgid`.\
Υπάρχουν διάφορες συναρτήσεις για τον **ορισμό νέων uids/gids**.

Η syscall **`persona`** παρέχει ένα **εναλλακτικό** σύνολο **διαπιστευτηρίων**. Η υιοθέτηση μιας persona εφαρμόζει τα uid, gid και τις συμμετοχές σε ομάδες της **ταυτόχρονα**. Στον [**πηγαίο κώδικα**](https://github.com/apple/darwin-xnu/blob/main/bsd/sys/persona.h) μπορείτε να βρείτε το struct:

```c
struct kpersona_info { uint32_t persona_info_version;
    uid_t    persona_id; /* overlaps with UID */
    int      persona_type;
    gid_t    persona_gid;
    uint32_t persona_ngroups;
    gid_t    persona_groups[NGROUPS];
    uid_t    persona_gmuid;
    char     persona_name[MAXLOGNAME + 1];

    /* TODO: MAC policies?! */
}
```

## Βασικές πληροφορίες για τα νήματα

1. **POSIX Threads (pthreads):** Το macOS υποστηρίζει POSIX threads (`pthreads`), τα οποία αποτελούν μέρος ενός τυπικού API διαχείρισης νημάτων για C/C++. Η υλοποίηση των pthreads στο macOS βρίσκεται στο `/usr/lib/system/libsystem_pthread.dylib`, το οποίο προέρχεται από το δημόσια διαθέσιμο έργο `libpthread`. Αυτή η βιβλιοθήκη παρέχει τις απαραίτητες συναρτήσεις για τη δημιουργία και τη διαχείριση νημάτων.
2. **Δημιουργία νημάτων:** Η συνάρτηση `pthread_create()` χρησιμοποιείται για τη δημιουργία νέων νημάτων. Εσωτερικά, αυτή η συνάρτηση καλεί τη `bsdthread_create()`, μια κλήση συστήματος χαμηλότερου επιπέδου, ειδική για τον πυρήνα XNU (τον πυρήνα στον οποίο βασίζεται το macOS). Αυτή η κλήση συστήματος δέχεται διάφορες σημαίες που προκύπτουν από το `pthread_attr` (χαρακτηριστικά) και καθορίζουν τη συμπεριφορά του νήματος, συμπεριλαμβανομένων των πολιτικών χρονοπρογραμματισμού και του μεγέθους της στοίβας.
   - **Προεπιλεγμένο μέγεθος στοίβας:** Το προεπιλεγμένο μέγεθος στοίβας για νέα νήματα είναι 512 KB, επαρκές για συνήθεις λειτουργίες, αλλά μπορεί να προσαρμοστεί μέσω των χαρακτηριστικών του νήματος, αν χρειάζεται περισσότερος ή λιγότερος χώρος.
3. **Αρχικοποίηση νημάτων:** Η συνάρτηση `__pthread_init()` είναι καθοριστική κατά τη ρύθμιση του νήματος, καθώς χρησιμοποιεί το όρισμα `env[]` για να αναλύσει μεταβλητές περιβάλλοντος, οι οποίες μπορεί να περιλαμβάνουν λεπτομέρειες σχετικά με τη θέση και το μέγεθος της στοίβας.

#### Τερματισμός νημάτων στο macOS

1. **Έξοδος νημάτων:** Τα νήματα συνήθως τερματίζονται με την κλήση της `pthread_exit()`. Αυτή η συνάρτηση επιτρέπει σε ένα νήμα να τερματιστεί ομαλά, εκτελώντας τις απαραίτητες εργασίες καθαρισμού και επιστρέφοντας μια τιμή σε όσα νήματα αναμένουν τον τερματισμό του.
2. **Καθαρισμός νημάτων:** Κατά την κλήση της `pthread_exit()`, εκτελείται η συνάρτηση `pthread_terminate()`, η οποία αναλαμβάνει την αφαίρεση όλων των σχετικών δομών του νήματος. Αποδεσμεύει τις θύρες νημάτων Mach (το Mach είναι το υποσύστημα επικοινωνίας στον πυρήνα XNU) και καλεί τη `bsdthread_terminate`, μια κλήση συστήματος που αφαιρεί τις δομές του πυρήνα οι οποίες σχετίζονται με το νήμα.

#### Μηχανισμοί συγχρονισμού

Για τη διαχείριση της πρόσβασης σε κοινόχρηστους πόρους και την αποφυγή συνθηκών ανταγωνισμού, το macOS παρέχει αρκετά πρωτόγονα στοιχεία συγχρονισμού. Είναι κρίσιμα σε περιβάλλοντα πολυνηματισμού, ώστε να διασφαλίζεται η ακεραιότητα των δεδομένων και η σταθερότητα του συστήματος:

1. **Mutexes:**
   - **Κανονικό mutex (υπογραφή: 0x4D555458):** Τυπικό mutex με αποτύπωμα μνήμης 60 byte (56 byte για το mutex και 4 byte για την υπογραφή).
   - **Fast mutex (υπογραφή: 0x4d55545A):** Παρόμοιο με το κανονικό mutex, αλλά βελτιστοποιημένο για ταχύτερες λειτουργίες, επίσης μεγέθους 60 byte.
2. **Μεταβλητές συνθήκης:**
   - Χρησιμοποιούνται για την αναμονή μέχρι να ισχύσουν ορισμένες συνθήκες και έχουν μέγεθος 44 byte (40 byte συν υπογραφή 4 byte).
   - **Χαρακτηριστικά μεταβλητών συνθήκης (υπογραφή: 0x434e4441):** Χαρακτηριστικά ρύθμισης μεταβλητών συνθήκης, μεγέθους 12 byte.
3. **Μεταβλητή Once (υπογραφή: 0x4f4e4345):**
   - Διασφαλίζει ότι ένα τμήμα κώδικα αρχικοποίησης εκτελείται μόνο μία φορά. Έχει μέγεθος 12 byte.
4. **Read-write locks:**
   - Επιτρέπουν την ταυτόχρονη πρόσβαση πολλών αναγνωστών ή την πρόσβαση ενός μόνο εγγραφέα, διευκολύνοντας την αποδοτική πρόσβαση σε κοινόχρηστα δεδομένα.
   - **Read-write lock (υπογραφή: 0x52574c4b):** Μεγέθους 196 byte.
   - **Χαρακτηριστικά read-write lock (υπογραφή: 0x52574c41):** Χαρακτηριστικά για read-write locks, μεγέθους 20 byte.

> [!TIP]
> Τα τελευταία 4 byte αυτών των αντικειμένων χρησιμοποιούνται για τον εντοπισμό υπερχειλίσεων.

### Τοπικές μεταβλητές νημάτων (TLV)

Οι **τοπικές μεταβλητές νημάτων (TLV)** στο πλαίσιο αρχείων Mach-O (της μορφής εκτελέσιμων αρχείων στο macOS) χρησιμοποιούνται για τη δήλωση μεταβλητών που είναι ειδικές για **κάθε νήμα** σε μια πολυνηματική εφαρμογή. Έτσι, κάθε νήμα έχει τη δική του ξεχωριστή παρουσία μιας μεταβλητής, γεγονός που βοηθά στην αποφυγή συγκρούσεων και στη διατήρηση της ακεραιότητας των δεδομένων, χωρίς να απαιτούνται ρητοί μηχανισμοί συγχρονισμού, όπως τα mutexes.

Στη C και σε συναφείς γλώσσες, μπορείτε να δηλώσετε μια τοπική μεταβλητή νήματος χρησιμοποιώντας τη λέξη-κλειδί **`__thread`**. Δείτε πώς λειτουργεί στο παράδειγμά σας:

```c
cCopy code__thread int tlv_var;

void main (int argc, char **argv){
    tlv_var = 10;
}
```

This απόσπασμα ορίζει το `tlv_var` ως μεταβλητή τοπική στο νήμα. Κάθε νήμα που εκτελεί αυτόν τον κώδικα θα έχει το δικό του `tlv_var`, και οι αλλαγές που κάνει ένα νήμα στο `tlv_var` δεν θα επηρεάζουν το `tlv_var` κάποιου άλλου νήματος.

Στο δυαδικό αρχείο Mach-O, τα δεδομένα που σχετίζονται με τις μεταβλητές τοπικές στο νήμα οργανώνονται σε συγκεκριμένες ενότητες:

- **`__DATA.__thread_vars`**: Αυτή η ενότητα περιέχει μεταδεδομένα σχετικά με τις μεταβλητές τοπικές στο νήμα, όπως τους τύπους τους και την κατάσταση αρχικοποίησής τους.
- **`__DATA.__thread_bss`**: Αυτή η ενότητα χρησιμοποιείται για μεταβλητές τοπικές στο νήμα που δεν έχουν αρχικοποιηθεί ρητά. Είναι τμήμα της μνήμης που δεσμεύεται για δεδομένα αρχικοποιημένα με μηδενικές τιμές.

Το Mach-O παρέχει επίσης ένα συγκεκριμένο API με την ονομασία **`tlv_atexit`** για τη διαχείριση των μεταβλητών τοπικών στο νήμα κατά τον τερματισμό ενός νήματος. Αυτό το API επιτρέπει την **καταχώριση destructors**—ειδικών συναρτήσεων που καθαρίζουν τα δεδομένα τοπικά στο νήμα όταν αυτό τερματίζεται.

### Προτεραιότητες νημάτων

Για να κατανοήσουμε τις προτεραιότητες νημάτων, πρέπει να εξετάσουμε πώς το λειτουργικό σύστημα αποφασίζει ποια νήματα θα εκτελούνται και πότε. Η απόφαση αυτή επηρεάζεται από το επίπεδο προτεραιότητας που έχει εκχωρηθεί σε κάθε νήμα. Στα macOS και στα συστήματα τύπου Unix, αυτό γίνεται με έννοιες όπως οι `nice`, `renice` και οι κλάσεις Quality of Service (QoS).

#### Nice και Renice

1. **Nice:**
   - Η τιμή `nice` μιας διεργασίας είναι ένας αριθμός που επηρεάζει την προτεραιότητά της. Κάθε διεργασία έχει τιμή `nice` από -20 (υψηλότερη προτεραιότητα) έως 19 (χαμηλότερη προτεραιότητα). Η προεπιλεγμένη τιμή `nice` κατά τη δημιουργία μιας διεργασίας είναι συνήθως 0.
   - Μια χαμηλότερη τιμή `nice` (πιο κοντά στο -20) κάνει μια διεργασία πιο «εγωιστική», εξασφαλίζοντάς της περισσότερο χρόνο CPU σε σχέση με άλλες διεργασίες που έχουν υψηλότερες τιμές `nice`.
2. **Renice:**
   - Το `renice` είναι μια εντολή που χρησιμοποιείται για να αλλάξει την τιμή `nice` μιας διεργασίας που εκτελείται ήδη. Μπορεί να χρησιμοποιηθεί για τη δυναμική προσαρμογή της προτεραιότητας των διεργασιών, αυξάνοντας ή μειώνοντας τον χρόνο CPU που τους εκχωρείται με βάση τις νέες τιμές `nice`.
   - Για παράδειγμα, αν μια διεργασία χρειάζεται προσωρινά περισσότερους πόρους CPU, μπορείτε να μειώσετε την τιμή `nice` της χρησιμοποιώντας το `renice`.

#### Κλάσεις Quality of Service (QoS)

Οι κλάσεις QoS είναι μια πιο σύγχρονη προσέγγιση στη διαχείριση των προτεραιοτήτων νημάτων, ιδίως σε συστήματα όπως το macOS που υποστηρίζουν το **Grand Central Dispatch (GCD)**. Οι κλάσεις QoS επιτρέπουν στους προγραμματιστές να **κατηγοριοποιούν** τις εργασίες σε διαφορετικά επίπεδα ανάλογα με τη σημασία ή τον επείγοντα χαρακτήρα τους. Το macOS διαχειρίζεται αυτόματα την προτεραιοποίηση νημάτων με βάση αυτές τις κλάσεις QoS:

1. **User Interactive:**
   - Αυτή η κλάση προορίζεται για εργασίες που αλληλεπιδρούν εκείνη τη στιγμή με τον χρήστη ή απαιτούν άμεσα αποτελέσματα για καλή εμπειρία χρήσης. Σε αυτές τις εργασίες δίνεται η υψηλότερη προτεραιότητα ώστε το περιβάλλον εργασίας να παραμένει αποκρίσιμο (π.χ. animations ή χειρισμός συμβάντων).
2. **User Initiated:**
   - Εργασίες που ξεκινά ο χρήστης και για τις οποίες αναμένει άμεσα αποτελέσματα, όπως το άνοιγμα ενός εγγράφου ή το πάτημα ενός κουμπιού που απαιτεί υπολογισμούς. Έχουν υψηλή προτεραιότητα, αλλά χαμηλότερη από τις εργασίες User Interactive.
3. **Utility:**
   - Αυτές οι εργασίες διαρκούν πολλή ώρα και συνήθως εμφανίζουν ένδειξη προόδου (π.χ. λήψη αρχείων, εισαγωγή δεδομένων). Έχουν χαμηλότερη προτεραιότητα από τις εργασίες User Initiated και δεν χρειάζεται να ολοκληρωθούν αμέσως.
4. **Background:**
   - Αυτή η κλάση προορίζεται για εργασίες που εκτελούνται στο παρασκήνιο και δεν είναι ορατές στον χρήστη. Μπορεί να περιλαμβάνουν ευρετηρίαση, συγχρονισμό ή δημιουργία αντιγράφων ασφαλείας. Έχουν τη χαμηλότερη προτεραιότητα και ελάχιστη επίδραση στην απόδοση του συστήματος.

Χρησιμοποιώντας τις κλάσεις QoS, οι προγραμματιστές δεν χρειάζεται να διαχειρίζονται συγκεκριμένους αριθμούς προτεραιότητας, αλλά μπορούν να επικεντρώνονται στη φύση της εργασίας, ενώ το σύστημα βελτιστοποιεί ανάλογα τους πόρους CPU.

Επιπλέον, υπάρχουν διαφορετικές **πολιτικές χρονοπρογραμματισμού νημάτων** που καθορίζουν ένα σύνολο παραμέτρων χρονοπρογραμματισμού τις οποίες θα λαμβάνει υπόψη ο scheduler. Αυτό μπορεί να γίνει με τη χρήση των `thread_policy_[set/get]`. Μπορεί να φανεί χρήσιμο σε επιθέσεις race condition.

## Κατάχρηση διεργασιών macOS

Το macOS παρέχει πολλούς μηχανισμούς ώστε οι **διεργασίες να αλληλεπιδρούν, να επικοινωνούν και να μοιράζονται δεδομένα**. Παρότι αυτοί οι μηχανισμοί είναι απαραίτητοι για την κανονική λειτουργία του συστήματος, οι επιτιθέμενοι μπορούν να τους καταχραστούν για injection, εκτέλεση κώδικα ή πρόσβαση σε δεδομένα.

### Library Injection

Το Library Injection είναι μια τεχνική κατά την οποία ένας επιτιθέμενος **αναγκάζει μια διεργασία να φορτώσει μια κακόβουλη βιβλιοθήκη**. Μετά το injection, η βιβλιοθήκη εκτελείται στο πλαίσιο της διεργασίας-στόχου, παρέχοντας στον επιτιθέμενο τα ίδια δικαιώματα και την ίδια πρόσβαση με τη διεργασία.

### Function Hooking

Το Function Hooking περιλαμβάνει την **παρεμβολή σε κλήσεις συναρτήσεων** ή μηνύματα μέσα στον κώδικα ενός λογισμικού. Κάνοντας hooking σε συναρτήσεις, ένας επιτιθέμενος μπορεί να **τροποποιήσει τη συμπεριφορά** μιας διεργασίας, να παρατηρήσει ευαίσθητα δεδομένα ή ακόμη και να αποκτήσει τον έλεγχο της ροής εκτέλεσης.

### Inter Process Communication

Το Inter Process Communication (IPC) αναφέρεται σε διαφορετικές μεθόδους με τις οποίες ξεχωριστές διεργασίες **μοιράζονται και ανταλλάσσουν δεδομένα**. Παρότι το IPC είναι θεμελιώδες για πολλές νόμιμες εφαρμογές, μπορεί επίσης να χρησιμοποιηθεί καταχρηστικά για την παράκαμψη της απομόνωσης διεργασιών, τη διαρροή ευαίσθητων πληροφοριών ή την εκτέλεση μη εξουσιοδοτημένων ενεργειών.

### Dirty NIB

Τα αρχεία NIB **ορίζουν στοιχεία του user interface (UI)** και τις αλληλεπιδράσεις τους μέσα σε μια εφαρμογή. Ωστόσο, μπορούν να **εκτελέσουν αυθαίρετες εντολές**, ενώ το **Gatekeeper δεν εμποδίζει** την επανεκτέλεση μιας εφαρμογής που έχει ήδη εκτελεστεί, αν **τροποποιηθεί ένα αρχείο NIB**. Επομένως, θα μπορούσαν να χρησιμοποιηθούν ώστε αυθαίρετα προγράμματα να εκτελούν αυθαίρετες εντολές:

### Shell Injection

### PowerShell Injection

Το `pwsh` είναι μια cross-platform εφαρμογή .NET, επομένως αρκετές μεταβλητές περιβάλλοντος επιτρέπουν την εκτέλεση κώδικα πριν από την εντολή: το **`XDG_CONFIG_HOME`** ανακατευθύνει τα profile scripts που εκτελούνται κατά την εκκίνηση, το **`PSModulePath`** επιτρέπει την παραβίαση της αυτόματης φόρτωσης modules (ένα τοποθετημένο `.psm1` εκτελείται κατά την εισαγωγή και μπορεί να υποκαταστήσει ενσωματωμένα cmdlets), ενώ οι μεταβλητές .NET **`CORECLR_PROFILER`**/**`COR_PROFILER`** και **`DOTNET_STARTUP_HOOKS`** φορτώνουν κώδικα του επιτιθέμενου στη διεργασία πριν από τη `Main`.

### Python Injection

Η αλυσίδα της standard library **`PYTHONWARNINGS`** και **`BROWSER`** μπορεί να εκτελέσει μια εντολή κατά την ανάλυση των φίλτρων προειδοποιήσεων. Μια εναλλακτική που βασίζεται σε αρχείο τοποθετεί το `sitecustomize.py` στο **`PYTHONPATH`**, ώστε η κανονική αρχικοποίηση του `site` να το εισαγάγει πριν από το script-στόχο. Το **`PYTHONBREAKPOINT`** εκτελεί ένα επιλεγμένο callable/module όταν ο κώδικας φτάσει στη `breakpoint()`. Μεταβλητές που ισχύουν μόνο για διαδραστική χρήση, όπως το **`PYTHONSTARTUP`**, έχουν πιο περιορισμένη εφαρμογή.

Σημειώστε ότι τα εκτελέσιμα αρχεία που έχουν μεταγλωττιστεί με **`pyinstaller`** δεν χρησιμοποιούν αυτές τις μεταβλητές περιβάλλοντος, ακόμη κι αν εκτελούνται με ενσωματωμένο python.

{{#ref}}

{{#endref}}

{{#ref}}

Ξεχωριστά, το Homebrew εγκαθιστά συχνά την Python κάτω από το `/opt/homebrew`, όπου τα μέλη της τοπικής ομάδας `admin` ενδέχεται να μπορούν να αντικαταστήσουν τον launcher. Αυτό είναι παραβίαση εγγράψιμου δυαδικού αρχείου και όχι injection μέσω μεταβλητής περιβάλλοντος· επαληθεύστε την ιδιοκτησία και τα ACL πριν το θεωρήσετε εκμεταλλεύσιμο.


## Ανίχνευση

### Shield

Το [**Shield**](https://github.com/theevilbit/Shield) είναι μια εφαρμογή ανοιχτού κώδικα που βασίζεται στο **EndpointSecurity** και ανιχνεύει και αποκλείει process injection. Αποτελεί καλή αναφορά για τα σήματα που είναι παρατηρήσιμα μέσω του Endpoint Security, καθώς ειδοποιεί για τα εξής:<sup>[[1]](#references)</sup><sup>[[2]](#references)</sup>

- **Μεταβλητές περιβάλλοντος injection** κατά την εκτέλεση διεργασιών: `DYLD_INSERT_LIBRARIES`, `CFNETWORK_LIBRARY_PATH`, `RAWCAMERA_BUNDLE_PATH` και `ELECTRON_RUN_AS_NODE`.
- Κλήσεις **`task_for_pid`** — μία διεργασία ζητά το task port μιας άλλης, κάτι που αποτελεί προϋπόθεση για την εισαγωγή κώδικα σε αυτήν.
- **Ορίσματα debugging του Electron** — `--inspect`, `--inspect-brk` και `--remote-debugging-port`, τα οποία εκκινούν μια εφαρμογή Electron σε λειτουργία debug και επιτρέπουν σε οποιονδήποτε να συνδεθεί και να εκτελέσει κώδικα σε αυτήν.<sup>[[3]](#references)</sup>
- **Δημιουργία symlink/hardlink μεταξύ διαφορετικών επιπέδων προνομίων** — το κλασικό primitive «δημιουργείς έναν σύνδεσμο ως κανονικός χρήστης και τον δείχνεις σε μια προνομιούχα τοποθεσία». Σημειώστε ότι **τα symlink μπορούν να προκαλέσουν ειδοποίηση, αλλά δεν μπορούν να αποκλειστούν**: το EndpointSecurity δεν αποκαλύπτει τον προορισμό του συνδέσμου πριν από τη δημιουργία του.

### Κλήσεις που γίνονται από άλλες διεργασίες

Στο [**αυτήν την ανάρτηση ιστολογίου**](https://knight.sc/reverse%20engineering/2019/04/15/detecting-task-modifications.html) μπορείτε να βρείτε πώς μπορεί να χρησιμοποιηθεί η συνάρτηση **`task_name_for_pid`** για την ανάκτηση πληροφοριών σχετικά με άλλες **διεργασίες που εισάγουν κώδικα σε μια διεργασία** και, στη συνέχεια, για την ανάκτηση πληροφοριών σχετικά με εκείνη τη διεργασία.<sup>[[4]](#references)</sup>

Σημειώστε ότι για να καλέσετε αυτήν τη συνάρτηση πρέπει να έχετε **το ίδιο uid** με τον χρήστη που εκτελεί τη διεργασία ή να είστε **root** (και επιστρέφει πληροφορίες για τη διεργασία, όχι τρόπο εισαγωγής κώδικα).
