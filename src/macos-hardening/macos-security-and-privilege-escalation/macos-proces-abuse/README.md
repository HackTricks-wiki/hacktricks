## Βασικές πληροφορίες για τις διεργασίες

Μια διεργασία είναι ένα στιγμιότυπο ενός εκτελέσιμου αρχείου που εκτελείται. Ωστόσο, οι διεργασίες δεν εκτελούν κώδικα· αυτό το κάνουν τα threads. Επομένως, **οι διεργασίες είναι απλώς περιέκτες για threads που εκτελούνται**, παρέχοντας μνήμη, περιγραφείς, θύρες, δικαιώματα...

Παραδοσιακά, οι διεργασίες ξεκινούσαν μέσα από άλλες διεργασίες (εκτός από την PID 1) με την κλήση της **`fork`**, η οποία δημιουργούσε ένα ακριβές αντίγραφο της τρέχουσας διεργασίας. Στη συνέχεια, η **θυγατρική διεργασία** συνήθως καλούσε την **`execve`** για να φορτώσει το νέο εκτελέσιμο αρχείο και να το εκτελέσει. Έπειτα, εισήχθη η **`vfork`**, για να επιταχύνει αυτή τη διαδικασία χωρίς αντιγραφή μνήμης.\
Στη συνέχεια, εισήχθη η **`posix_spawn`**, η οποία συνδυάζει τις **`vfork`** και **`execve`** σε μία κλήση και δέχεται flags:

- `POSIX_SPAWN_RESETIDS`: Επαναφορά των effective ids στα real ids
- `POSIX_SPAWN_SETPGROUP`: Ορισμός της ένταξης σε process group
- `POSUX_SPAWN_SETSIGDEF`: Ορισμός της προεπιλεγμένης συμπεριφοράς των signals
- `POSIX_SPAWN_SETSIGMASK`: Ορισμός της μάσκας signals
- `POSIX_SPAWN_SETEXEC`: Εκτέλεση στην ίδια διεργασία (όπως η `execve`, αλλά με περισσότερες επιλογές)
- `POSIX_SPAWN_START_SUSPENDED`: Εκκίνηση σε αναστολή
- `_POSIX_SPAWN_DISABLE_ASLR`: Εκκίνηση χωρίς ASLR
- `_POSIX_SPAWN_NANO_ALLOCATOR:` Χρήση του Nano allocator του libmalloc
- `_POSIX_SPAWN_ALLOW_DATA_EXEC:` Επίτρεψη `rwx` στα data segments
- `POSIX_SPAWN_CLOEXEC_DEFAULT`: Κλείσιμο όλων των file descriptions κατά το exec(2) από προεπιλογή
- `_POSIX_SPAWN_HIGH_BITS_ASLR:` Τυχαιοποίηση των high bits του ASLR slide

Επιπλέον, η `posix_spawn` δέχεται ρυθμίσεις **`posix_spawnattr`**, οι οποίες ελέγχουν πτυχές της διεργασίας που δημιουργείται, καθώς και καταχωρίσεις **`posix_spawn_file_actions`**, οι οποίες τροποποιούν τους file descriptors.

Όταν μια διεργασία τερματίζεται, στέλνει τον **κωδικό επιστροφής στη γονική διεργασία** (αν η γονική διεργασία έχει τερματιστεί, νέα γονική διεργασία γίνεται η PID 1) με το signal `SIGCHLD`. Η γονική διεργασία πρέπει να λάβει αυτή την τιμή καλώντας την `wait4()` ή την `waitid()`. Μέχρι να συμβεί αυτό, η θυγατρική διεργασία παραμένει σε κατάσταση zombie: εξακολουθεί να εμφανίζεται στη λίστα, αλλά δεν καταναλώνει πόρους.

### PIDs

Τα PIDs (process identifiers) προσδιορίζουν μια μοναδική διεργασία. Στο XNU, τα **PIDs** έχουν μέγεθος **64 bits**, αυξάνονται μονότονα και **δεν κάνουν ποτέ wrap** (για την αποφυγή abuse).

### Ομάδες διεργασιών, συνεδρίες και Coalitions

Οι **διεργασίες** μπορούν να οργανωθούν σε **ομάδες** για ευκολότερη διαχείριση. Για παράδειγμα, οι εντολές σε ένα shell script ανήκουν στην ίδια process group, ώστε να είναι δυνατή η **αποστολή signal σε όλες μαζί**, για παράδειγμα με τη χρήση της kill.\
Είναι επίσης δυνατό να **οργανωθούν διεργασίες σε συνεδρίες**. Όταν μια διεργασία ξεκινά μια συνεδρία (`setsid(2)`), οι θυγατρικές διεργασίες εντάσσονται σε αυτήν, εκτός αν ξεκινήσουν τη δική τους συνεδρία.

Το Coalition είναι ένας ακόμη τρόπος ομαδοποίησης διεργασιών στο Darwin. Μια διεργασία που εντάσσεται σε ένα Coalition μπορεί να έχει πρόσβαση σε κοινόχρηστους πόρους pool, να μοιράζεται ένα ledger ή να υπόκειται σε Jetsam. Τα Coalitions έχουν διαφορετικούς ρόλους: Leader, XPC service, Extension.

### Διαπιστευτήρια και personae

Κάθε διεργασία διατηρεί **διαπιστευτήρια** που **προσδιορίζουν τα δικαιώματά της** στο σύστημα. Κάθε διεργασία έχει ένα κύριο `uid` και ένα κύριο `gid` (αν και μπορεί να ανήκει σε πολλές ομάδες).\
Είναι επίσης δυνατό να αλλάξει το user και group id, αν το binary έχει το bit `setuid/setgid`.\
Υπάρχουν διάφορες συναρτήσεις για τον **ορισμό νέων uids/gids**.

Το syscall **`persona`** παρέχει ένα **εναλλακτικό** σύνολο **διαπιστευτηρίων**. Η υιοθέτηση μιας persona συνεπάγεται την ταυτόχρονη χρήση του uid, του gid και των συμμετοχών της σε ομάδες. Στον [**πηγαίο κώδικα**](https://github.com/apple/darwin-xnu/blob/main/bsd/sys/persona.h) μπορείτε να βρείτε το struct:

```c
struct kpersona_info { uint32_t persona_info_version;
    uid_t    persona_id; /* overlaps with UID */
    int      persona_type;
    gid_t    persona_gid;
    uint32_t persona_ngroups;
    gid_t    persona_groups[NGROUPS];
    uid_t    persona_gmuid;
    char     persona_name[MAXLOGNAME + 1];

    /* TODO: MAC policies?! */
}
```

## Βασικές πληροφορίες για τα νήματα

1. **Νήματα POSIX (pthreads):** Το macOS υποστηρίζει νήματα POSIX (`pthreads`), τα οποία αποτελούν μέρος ενός τυπικού API νημάτων για C/C++. Η υλοποίηση των pthreads στο macOS βρίσκεται στο `/usr/lib/system/libsystem_pthread.dylib`, το οποίο προέρχεται από το δημόσια διαθέσιμο project `libpthread`. Αυτή η βιβλιοθήκη παρέχει τις απαραίτητες συναρτήσεις για τη δημιουργία και τη διαχείριση νημάτων.
2. **Δημιουργία νημάτων:** Η συνάρτηση `pthread_create()` χρησιμοποιείται για τη δημιουργία νέων νημάτων. Εσωτερικά, αυτή η συνάρτηση καλεί την `bsdthread_create()`, μια κλήση συστήματος χαμηλότερου επιπέδου, ειδική για τον πυρήνα XNU (τον πυρήνα στον οποίο βασίζεται το macOS). Αυτή η κλήση συστήματος δέχεται διάφορες σημαίες που προκύπτουν από το `pthread_attr` (χαρακτηριστικά) και καθορίζουν τη συμπεριφορά του νήματος, συμπεριλαμβανομένων των πολιτικών χρονοπρογραμματισμού και του μεγέθους της στοίβας.
   - **Προεπιλεγμένο μέγεθος στοίβας:** Το προεπιλεγμένο μέγεθος στοίβας για νέα νήματα είναι 512 KB, ποσότητα επαρκής για τυπικές λειτουργίες. Μπορεί να προσαρμοστεί μέσω των χαρακτηριστικών του νήματος, αν χρειάζεται περισσότερος ή λιγότερος χώρος.
3. **Αρχικοποίηση νημάτων:** Η συνάρτηση `__pthread_init()` είναι κρίσιμη κατά τη ρύθμιση του νήματος, καθώς χρησιμοποιεί το όρισμα `env[]` για την ανάλυση μεταβλητών περιβάλλοντος, οι οποίες μπορεί να περιλαμβάνουν πληροφορίες για τη θέση και το μέγεθος της στοίβας.

#### Τερματισμός νημάτων στο macOS

1. **Έξοδος από νήματα:** Τα νήματα τερματίζονται συνήθως με την κλήση της `pthread_exit()`. Αυτή η συνάρτηση επιτρέπει σε ένα νήμα να τερματιστεί ομαλά, εκτελώντας τις απαραίτητες εργασίες καθαρισμού και επιστρέφοντας μια τιμή σε όσα νήματα περιμένουν την ολοκλήρωσή του.
2. **Καθαρισμός νημάτων:** Κατά την κλήση της `pthread_exit()`, εκτελείται η συνάρτηση `pthread_terminate()`, η οποία διαχειρίζεται την αφαίρεση όλων των σχετικών δομών του νήματος. Αποδεσμεύει τις θύρες νημάτων Mach (το Mach είναι το υποσύστημα επικοινωνίας του πυρήνα XNU) και καλεί την `bsdthread_terminate`, ένα syscall που αφαιρεί τις δομές του πυρήνα που σχετίζονται με το νήμα.

#### Μηχανισμοί συγχρονισμού

Για τη διαχείριση της πρόσβασης σε κοινόχρηστους πόρους και την αποφυγή συνθηκών ανταγωνισμού, το macOS παρέχει διάφορα primitives συγχρονισμού. Είναι κρίσιμα σε περιβάλλοντα πολυνηματικής εκτέλεσης, ώστε να διασφαλίζονται η ακεραιότητα των δεδομένων και η σταθερότητα του συστήματος:

1. **Mutexes:**
   - **Κανονικό Mutex (Signature: 0x4D555458):** Τυπικό mutex με αποτύπωμα μνήμης 60 bytes (56 bytes για το mutex και 4 bytes για την υπογραφή).
   - **Fast Mutex (Signature: 0x4d55545A):** Παρόμοιο με ένα κανονικό mutex, αλλά βελτιστοποιημένο για ταχύτερες λειτουργίες· έχει επίσης μέγεθος 60 bytes.
2. **Μεταβλητές συνθήκης:**
   - Χρησιμοποιούνται για αναμονή μέχρι να προκύψουν συγκεκριμένες συνθήκες και έχουν μέγεθος 44 bytes (40 bytes συν υπογραφή 4 bytes).
   - **Χαρακτηριστικά μεταβλητών συνθήκης (Signature: 0x434e4441):** Χαρακτηριστικά ρύθμισης για μεταβλητές συνθήκης, μεγέθους 12 bytes.
3. **Μεταβλητή Once (Signature: 0x4f4e4345):**
   - Διασφαλίζει ότι ένα τμήμα κώδικα αρχικοποίησης εκτελείται μόνο μία φορά. Έχει μέγεθος 12 bytes.
4. **Κλειδώματα ανάγνωσης-εγγραφής:**
   - Επιτρέπουν ταυτόχρονα πολλούς αναγνώστες ή έναν εγγραφέα, διευκολύνοντας την αποδοτική πρόσβαση σε κοινόχρηστα δεδομένα.
   - **Κλείδωμα ανάγνωσης-εγγραφής (Signature: 0x52574c4b):** Έχει μέγεθος 196 bytes.
   - **Χαρακτηριστικά κλειδώματος ανάγνωσης-εγγραφής (Signature: 0x52574c41):** Χαρακτηριστικά για κλειδώματα ανάγνωσης-εγγραφής, μεγέθους 20 bytes.

> [!TIP]
> Τα τελευταία 4 bytes αυτών των αντικειμένων χρησιμοποιούνται για τον εντοπισμό υπερχειλίσεων.

### Μεταβλητές τοπικές σε νήμα (TLV)

Οι **μεταβλητές τοπικές σε νήμα (TLV)**, στο πλαίσιο των αρχείων Mach-O (της μορφής εκτελέσιμων αρχείων στο macOS), χρησιμοποιούνται για τη δήλωση μεταβλητών που είναι ειδικές για **κάθε νήμα** σε μια πολυνηματική εφαρμογή. Έτσι, κάθε νήμα έχει τη δική του ξεχωριστή παρουσία μιας μεταβλητής, αποφεύγοντας τις διενέξεις και διατηρώντας την ακεραιότητα των δεδομένων χωρίς να απαιτούνται ρητοί μηχανισμοί συγχρονισμού, όπως τα mutexes.

Στη C και σε συναφείς γλώσσες, μπορείτε να δηλώσετε μια μεταβλητή τοπική σε νήμα χρησιμοποιώντας τη λέξη-κλειδί **`__thread`**. Δείτε πώς λειτουργεί στο παράδειγμά σας:

```c
cCopy code__thread int tlv_var;

void main (int argc, char **argv){
    tlv_var = 10;
}
```

Αυτό το απόσπασμα ορίζει το `tlv_var` ως μεταβλητή τοπική στο νήμα. Κάθε νήμα που εκτελεί αυτόν τον κώδικα θα έχει το δικό του `tlv_var`, και οι αλλαγές που κάνει ένα νήμα στο `tlv_var` δεν θα επηρεάζουν το `tlv_var` κάποιου άλλου νήματος.

Στο δυαδικό αρχείο Mach-O, τα δεδομένα που σχετίζονται με τις μεταβλητές τοπικές στο νήμα οργανώνονται σε συγκεκριμένες ενότητες:

- **`__DATA.__thread_vars`**: Αυτή η ενότητα περιέχει μεταδεδομένα σχετικά με τις μεταβλητές τοπικές στο νήμα, όπως τους τύπους τους και την κατάσταση αρχικοποίησής τους.
- **`__DATA.__thread_bss`**: Αυτή η ενότητα χρησιμοποιείται για μεταβλητές τοπικές στο νήμα που δεν αρχικοποιούνται ρητά. Είναι ένα τμήμα μνήμης που προορίζεται για δεδομένα αρχικοποιημένα με μηδενικές τιμές.

Το Mach-O παρέχει επίσης ένα συγκεκριμένο API, το **`tlv_atexit`**, για τη διαχείριση των μεταβλητών τοπικών στο νήμα όταν ένα νήμα τερματίζεται. Αυτό το API επιτρέπει την **καταχώριση destructors** —ειδικών συναρτήσεων που καθαρίζουν τα δεδομένα τοπικά στο νήμα όταν αυτό τερματιστεί.

### Προτεραιότητες Νημάτων

Για να κατανοήσουμε τις προτεραιότητες των νημάτων, πρέπει να εξετάσουμε πώς το λειτουργικό σύστημα αποφασίζει ποια νήματα θα εκτελέσει και πότε. Η απόφαση αυτή επηρεάζεται από το επίπεδο προτεραιότητας που έχει εκχωρηθεί σε κάθε νήμα. Στα macOS και στα συστήματα τύπου Unix, αυτό γίνεται με έννοιες όπως οι `nice`, `renice` και οι κλάσεις Quality of Service (QoS).

#### Nice και Renice

1. **Nice:**
   - Η τιμή `nice` μιας διεργασίας είναι ένας αριθμός που επηρεάζει την προτεραιότητά της. Κάθε διεργασία έχει τιμή `nice` από -20 (η υψηλότερη προτεραιότητα) έως 19 (η χαμηλότερη προτεραιότητα). Η προεπιλεγμένη τιμή `nice` κατά τη δημιουργία μιας διεργασίας είναι συνήθως 0.
   - Μια χαμηλότερη τιμή `nice` (πιο κοντά στο -20) κάνει μια διεργασία πιο «εγωιστική», δίνοντάς της περισσότερο χρόνο CPU σε σύγκριση με άλλες διεργασίες που έχουν υψηλότερες τιμές `nice`.
2. **Renice:**
   - Το `renice` είναι μια εντολή που χρησιμοποιείται για την αλλαγή της τιμής `nice` μιας διεργασίας που εκτελείται ήδη. Μπορεί να χρησιμοποιηθεί για τη δυναμική προσαρμογή της προτεραιότητας των διεργασιών, αυξάνοντας ή μειώνοντας τον χρόνο CPU που τους εκχωρείται ανάλογα με τις νέες τιμές `nice`.
   - Για παράδειγμα, αν μια διεργασία χρειάζεται προσωρινά περισσότερους πόρους CPU, μπορείτε να μειώσετε την τιμή `nice` της χρησιμοποιώντας το `renice`.

#### Κλάσεις Quality of Service (QoS)

Οι κλάσεις QoS αποτελούν μια πιο σύγχρονη προσέγγιση για τη διαχείριση των προτεραιοτήτων νημάτων, ιδίως σε συστήματα όπως το macOS που υποστηρίζουν το **Grand Central Dispatch (GCD)**. Οι κλάσεις QoS επιτρέπουν στους developers να **κατηγοριοποιούν** την εργασία σε διαφορετικά επίπεδα, ανάλογα με τη σημασία ή τον επείγοντα χαρακτήρα της. Το macOS διαχειρίζεται αυτόματα την προτεραιοποίηση των νημάτων με βάση αυτές τις κλάσεις QoS:

1. **User Interactive:**
   - Αυτή η κλάση αφορά εργασίες που αλληλεπιδρούν εκείνη τη στιγμή με τον χρήστη ή απαιτούν άμεσα αποτελέσματα για καλή εμπειρία χρήσης. Σε αυτές τις εργασίες δίνεται η υψηλότερη προτεραιότητα, ώστε η διεπαφή να παραμένει αποκρίσιμη (π.χ. animations ή διαχείριση συμβάντων).
2. **User Initiated:**
   - Εργασίες που ξεκινά ο χρήστης και για τις οποίες αναμένει άμεσα αποτελέσματα, όπως το άνοιγμα ενός εγγράφου ή το πάτημα ενός κουμπιού που απαιτεί υπολογισμούς. Έχουν υψηλή προτεραιότητα, αλλά χαμηλότερη από την User Interactive.
3. **Utility:**
   - Αυτές οι εργασίες διαρκούν πολύ και συνήθως εμφανίζουν μια ένδειξη προόδου (π.χ. λήψη αρχείων, εισαγωγή δεδομένων). Έχουν χαμηλότερη προτεραιότητα από τις εργασίες που ξεκινούν οι χρήστες και δεν χρειάζεται να ολοκληρωθούν αμέσως.
4. **Background:**
   - Αυτή η κλάση αφορά εργασίες που εκτελούνται στο παρασκήνιο και δεν είναι ορατές στον χρήστη. Τέτοιες εργασίες μπορεί να είναι η δημιουργία ευρετηρίου, ο συγχρονισμός ή τα αντίγραφα ασφαλείας. Έχουν τη χαμηλότερη προτεραιότητα και ελάχιστη επίδραση στην απόδοση του συστήματος.

Χρησιμοποιώντας τις κλάσεις QoS, οι developers δεν χρειάζεται να διαχειρίζονται τις ακριβείς τιμές προτεραιότητας, αλλά μπορούν να επικεντρώνονται στη φύση της εργασίας, ενώ το σύστημα βελτιστοποιεί ανάλογα τους πόρους CPU.

Επιπλέον, υπάρχουν διαφορετικές **πολιτικές χρονοπρογραμματισμού νημάτων** που επιτρέπουν στις ροές να καθορίζουν ένα σύνολο παραμέτρων χρονοπρογραμματισμού, τις οποίες θα λαμβάνει υπόψη ο scheduler. Αυτό μπορεί να γίνει με τη χρήση του `thread_policy_[set/get]`. Μπορεί να φανεί χρήσιμο σε επιθέσεις race condition.

## Κατάχρηση Διεργασιών macOS

Το macOS παρέχει πολλούς μηχανισμούς για να **αλληλεπιδρούν, να επικοινωνούν και να μοιράζονται δεδομένα οι διεργασίες**. Παρότι αυτοί οι μηχανισμοί είναι απαραίτητοι για την κανονική λειτουργία του συστήματος, οι attackers μπορούν να τους καταχραστούν για injection, εκτέλεση κώδικα ή πρόσβαση σε δεδομένα.

### Injection Βιβλιοθηκών

Το Library Injection είναι μια τεχνική κατά την οποία ένας attacker **αναγκάζει μια διεργασία να φορτώσει μια κακόβουλη βιβλιοθήκη**. Μόλις γίνει inject, η βιβλιοθήκη εκτελείται στο πλαίσιο της διεργασίας-στόχου, παρέχοντας στον attacker τα ίδια δικαιώματα και την ίδια πρόσβαση με τη διεργασία.

### Function Hooking

Το Function Hooking περιλαμβάνει την **παρακολούθηση κλήσεων συναρτήσεων** ή μηνυμάτων μέσα σε κώδικα λογισμικού. Κάνοντας hooking σε συναρτήσεις, ένας attacker μπορεί να **τροποποιήσει τη συμπεριφορά** μιας διεργασίας, να παρατηρήσει ευαίσθητα δεδομένα ή ακόμη και να αποκτήσει τον έλεγχο της ροής εκτέλεσης.

### Inter Process Communication

Το Inter Process Communication (IPC) αναφέρεται σε διαφορετικές μεθόδους με τις οποίες χωριστές διεργασίες **μοιράζονται και ανταλλάσσουν δεδομένα**. Παρότι το IPC είναι θεμελιώδες για πολλές νόμιμες εφαρμογές, μπορεί επίσης να χρησιμοποιηθεί καταχρηστικά για την υπονόμευση της απομόνωσης διεργασιών, τη διαρροή ευαίσθητων πληροφοριών ή την εκτέλεση μη εξουσιοδοτημένων ενεργειών.

### Dirty NIB

Τα αρχεία NIB **ορίζουν στοιχεία διεπαφής χρήστη (UI)** και τις αλληλεπιδράσεις τους μέσα σε μια εφαρμογή. Ωστόσο, μπορούν να **εκτελέσουν αυθαίρετες εντολές**, ενώ το **Gatekeeper δεν εμποδίζει** την εκ νέου εκτέλεση μιας εφαρμογής που έχει ήδη εκτελεστεί, αν **τροποποιηθεί ένα αρχείο NIB**. Επομένως, μπορούν να χρησιμοποιηθούν για να κάνουν αυθαίρετα προγράμματα να εκτελέσουν αυθαίρετες εντολές:

### Shell Injection

Το μη διαδραστικό Bash διαβάζει το **`BASH_ENV`**· τα διαδραστικά POSIX shells διαβάζουν το **`ENV`**· το zsh διαβάζει το **`$ZDOTDIR/.zshenv`**· και το fish διαβάζει ρυθμίσεις από τις τοποθεσίες κάτω από τα **`XDG_CONFIG_HOME`** ή **`XDG_DATA_DIRS`**. Καθένα από αυτά μπορεί να εκτελέσει ένα ελεγχόμενο αρχείο εκκίνησης πριν από την προβλεπόμενη εντολή. Το Bash εκτελεί επίσης command substitution που έχει τοποθετηθεί στο **`PS4`** κάθε φορά που είναι ενεργοποιημένο το xtrace (π.χ. μέσω κληρονομημένου **`SHELLOPTS=xtrace`**):

### Παρεμβολή εντολών μέσω stdin του Shell

Η εκκίνηση του `/bin/zsh -s` κάνει το shell να διαβάζει ένα πρόγραμμα από το standard input. Επομένως, αν ένας downloader αντιγράψει ένα μη έμπιστο δομημένο έγγραφο στο stdin της child διεργασίας χωρίς να το αναλύσει πρώτα, έχει μετατρέψει ολόκληρο το έγγραφο σε κώδικα shell. Ένας loader που παρατηρήθηκε διοχέτευε ένα δημόσιο αρχείο iCalendar μέσω ενός anonymous pipe, γραμμή προς γραμμή. Τα metadata του ημερολογίου δεν εκτελούνταν ως εντολές, αλλά το zsh συνέχιζε μέχρι να φτάσει σε εκτελέσιμες γραμμές μετά το `DESCRIPTION:`. Αυτές οι γραμμές κατέβαζαν και εκκινούσαν το επόμενο application bundle. Ο αναμενόμενος τύπος περιεχομένου του φορέα και η έμπιστη φιλοξενία δεν το καθιστούσαν ασφαλές· το επικίνδυνο όριο ήταν η παράδοση των bytes του σε έναν interpreter.<sup>[[5]](#references)</sup>

Σχετικά στάδια καλύπτονται στις ενότητες [Mach-O overlays](../macos-files-folders-and-binaries/universal-binaries-and-mach-o-format.md), [Gatekeeper and quarantine](../macos-security-protections/macos-gatekeeper.md) και [macOS auto-start locations](../../macos-auto-start-locations.md).

### PowerShell Injection

### Python Injection

Η αλυσίδα της standard library **`PYTHONWARNINGS`** και **`BROWSER`** μπορεί να εκτελέσει μια εντολή κατά την ανάλυση των warning filters. Μια εναλλακτική που βασίζεται σε αρχείο τοποθετεί το `sitecustomize.py` στο **`PYTHONPATH`**, ώστε η κανονική αρχικοποίηση του `site` να το κάνει import πριν από το script-στόχο. Το **`PYTHONBREAKPOINT`** εκτελεί μια επιλεγμένη callable/module όταν ο κώδικας φτάσει στη `breakpoint()`. Μεταβλητές που αφορούν μόνο διαδραστικές συνεδρίες, όπως η **`PYTHONSTARTUP`**, έχουν πιο περιορισμένη εφαρμογή.

Σημειώστε ότι τα executables που έχουν μεταγλωττιστεί με **`pyinstaller`** δεν χρησιμοποιούν αυτές τις μεταβλητές περιβάλλοντος, ακόμη κι αν εκτελούνται με embedded Python.

{{#ref}}

Ξεχωριστά, το Homebrew εγκαθιστά συχνά την Python κάτω από το `/opt/homebrew`, όπου τα μέλη της τοπικής ομάδας `admin` ενδέχεται να μπορούν να αντικαταστήσουν τον launcher. Αυτό αποτελεί hijack εκτελέσιμου αρχείου με δυνατότητα εγγραφής, όχι injection μέσω μεταβλητής περιβάλλοντος· ελέγξτε την ιδιοκτησία και τα ACL πριν θεωρήσετε ότι είναι εκμεταλλεύσιμο.


## Ανίχνευση

### Shield

Το [**Shield**](https://github.com/theevilbit/Shield) είναι μια εφαρμογή ανοιχτού κώδικα που βασίζεται στο **EndpointSecurity** και ανιχνεύει και αποκλείει process injection. Αποτελεί καλή αναφορά για τα σήματα που είναι ορατά μέσω του Endpoint Security, καθώς ειδοποιεί για:<sup>[[1]](#references)</sup><sup>[[2]](#references)</sup>

- **Μεταβλητές περιβάλλοντος injection** κατά την εκτέλεση διεργασιών: `DYLD_INSERT_LIBRARIES`, `CFNETWORK_LIBRARY_PATH`, `RAWCAMERA_BUNDLE_PATH` και `ELECTRON_RUN_AS_NODE`.
- Κλήσεις **`task_for_pid`** — όταν μια διεργασία ζητά το task port μιας άλλης διεργασίας, κάτι που αποτελεί προϋπόθεση για injection σε αυτήν.
- **Ορίσματα debugging του Electron** — `--inspect`, `--inspect-brk` και `--remote-debugging-port`, τα οποία εκκινούν μια εφαρμογή Electron σε λειτουργία debug και επιτρέπουν σε οποιονδήποτε να συνδεθεί και να εκτελέσει κώδικα σε αυτήν.<sup>[[3]](#references)</sup>
- **Δημιουργία symlink/hardlink μεταξύ διαφορετικών επιπέδων προνομίων** — το κλασικό primitive «δημιούργησε έναν σύνδεσμο ως κανονικός χρήστης και στόχευσέ τον σε μια προνομιούχα τοποθεσία». Σημειώστε ότι τα **symlinks μπορούν να προκαλέσουν ειδοποίηση, αλλά όχι να αποκλειστούν**: το EndpointSecurity δεν αποκαλύπτει τον προορισμό του συνδέσμου πριν από τη δημιουργία του.

### Κλήσεις από άλλες διεργασίες

Στο [**αυτό το blog post**](https://knight.sc/reverse%20engineering/2019/04/15/detecting-task-modifications.html) μπορείτε να δείτε πώς είναι δυνατό να χρησιμοποιηθεί η συνάρτηση **`task_name_for_pid`** για να λάβετε πληροφορίες σχετικά με άλλες **διεργασίες που κάνουν injection κώδικα σε μια διεργασία** και στη συνέχεια να λάβετε πληροφορίες για εκείνη την άλλη διεργασία.<sup>[[4]](#references)</sup>

Σημειώστε ότι για να καλέσετε αυτή τη συνάρτηση πρέπει να έχετε **το ίδιο uid** με εκείνο που εκτελεί τη διεργασία ή να είστε **root** (και επιστρέφει πληροφορίες για τη διεργασία, όχι τρόπο για να κάνετε inject κώδικα).
