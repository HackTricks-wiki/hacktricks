## Βασικές πληροφορίες για τις διεργασίες

Μια διεργασία είναι ένα στιγμιότυπο ενός εκτελέσιμου αρχείου που εκτελείται. Ωστόσο, οι διεργασίες δεν εκτελούν κώδικα· αυτό το κάνουν τα νήματα. Επομένως, **οι διεργασίες είναι απλώς περιέκτες για νήματα που εκτελούνται**, παρέχοντας μνήμη, περιγραφείς, θύρες, δικαιώματα...

Παραδοσιακά, οι διεργασίες ξεκινούσαν μέσα από άλλες διεργασίες (εκτός από την PID 1) με κλήση της **`fork`**, η οποία δημιουργούσε ένα ακριβές αντίγραφο της τρέχουσας διεργασίας. Στη συνέχεια, η **θυγατρική διεργασία** συνήθως καλούσε την **`execve`** για να φορτώσει το νέο εκτελέσιμο αρχείο και να το εκτελέσει. Έπειτα, εισήχθη η **`vfork`** για να επιταχύνει αυτή τη διαδικασία χωρίς αντιγραφή μνήμης.\
Στη συνέχεια, εισήχθη η **`posix_spawn`**, η οποία συνδυάζει τις **`vfork`** και **`execve`** σε μία κλήση και δέχεται flags:

- `POSIX_SPAWN_RESETIDS`: Επαναφορά των αποτελεσματικών IDs στα πραγματικά IDs
- `POSIX_SPAWN_SETPGROUP`: Ορισμός συμμετοχής σε ομάδα διεργασιών
- `POSUX_SPAWN_SETSIGDEF`: Ορισμός της προεπιλεγμένης συμπεριφοράς σημάτων
- `POSIX_SPAWN_SETSIGMASK`: Ορισμός της μάσκας σημάτων
- `POSIX_SPAWN_SETEXEC`: Εκτέλεση στην ίδια διεργασία (όπως η `execve` με περισσότερες επιλογές)
- `POSIX_SPAWN_START_SUSPENDED`: Έναρξη σε αναστολή
- `_POSIX_SPAWN_DISABLE_ASLR`: Έναρξη χωρίς ASLR
- `_POSIX_SPAWN_NANO_ALLOCATOR:` Χρήση του Nano allocator της libmalloc
- `_POSIX_SPAWN_ALLOW_DATA_EXEC:` Να επιτρέπεται `rwx` σε τμήματα δεδομένων
- `POSIX_SPAWN_CLOEXEC_DEFAULT`: Κλείσιμο όλων των περιγραφών αρχείων κατά την exec(2), από προεπιλογή
- `_POSIX_SPAWN_HIGH_BITS_ASLR:` Τυχαιοποίηση των υψηλών bits της μετατόπισης ASLR

Επιπλέον, η `posix_spawn` δέχεται ρυθμίσεις **`posix_spawnattr`** που ελέγχουν πτυχές της διεργασίας που δημιουργείται και καταχωρίσεις **`posix_spawn_file_actions`** που τροποποιούν τους περιγραφείς αρχείων.

Όταν μια διεργασία τερματίζεται, στέλνει τον **κωδικό επιστροφής στη γονική διεργασία** (αν η γονική διεργασία έχει τερματιστεί, νέος γονέας είναι η PID 1) με το σήμα `SIGCHLD`. Η γονική διεργασία πρέπει να λάβει αυτή την τιμή καλώντας τις `wait4()` ή `waitid()`. Μέχρι να συμβεί αυτό, η θυγατρική διεργασία παραμένει σε κατάσταση zombie, όπου εξακολουθεί να εμφανίζεται στη λίστα αλλά δεν καταναλώνει πόρους.

### PIDs

Τα PIDs, δηλαδή τα αναγνωριστικά διεργασιών, προσδιορίζουν μία μοναδική διεργασία. Στο XNU, τα **PIDs** είναι **64-bit**, αυξάνονται μονοτονικά και **δεν ανακυκλώνονται** (για την αποφυγή καταχρήσεων).

### Ομάδες διεργασιών, συνεδρίες και coalitions

Οι **διεργασίες** μπορούν να ενταχθούν σε **ομάδες**, ώστε να είναι ευκολότερος ο χειρισμός τους. Για παράδειγμα, οι εντολές σε ένα shell script ανήκουν στην ίδια ομάδα διεργασιών, οπότε είναι δυνατό να **σταλούν σήματα σε όλες μαζί**, για παράδειγμα με τη χρήση της kill.\
Είναι επίσης δυνατό να **ομαδοποιηθούν διεργασίες σε συνεδρίες**. Όταν μια διεργασία ξεκινά μια συνεδρία (`setsid(2)`), οι θυγατρικές διεργασίες εντάσσονται σε αυτήν, εκτός αν ξεκινήσουν τη δική τους συνεδρία.

Το Coalition είναι ένας ακόμη τρόπος ομαδοποίησης διεργασιών στο Darwin. Η ένταξη μιας διεργασίας σε ένα coalition της επιτρέπει να έχει πρόσβαση σε κοινόχρηστους πόρους pool, να μοιράζεται ένα ledger ή να υπόκειται σε Jetsam. Τα coalitions έχουν διαφορετικούς ρόλους: Leader, XPC service, Extension.

### Διαπιστευτήρια και Personae

Κάθε διεργασία διατηρεί **διαπιστευτήρια** που **προσδιορίζουν τα δικαιώματά της** στο σύστημα. Κάθε διεργασία έχει ένα κύριο `uid` και ένα κύριο `gid` (αν και μπορεί να ανήκει σε πολλές ομάδες).\
Είναι επίσης δυνατό να αλλάξει το αναγνωριστικό χρήστη και ομάδας, αν το binary έχει το bit `setuid/setgid`.\
Υπάρχουν διάφορες συναρτήσεις για τον **ορισμό νέων uids/gids**.

Το syscall **`persona`** παρέχει ένα **εναλλακτικό** σύνολο **διαπιστευτηρίων**. Η υιοθέτηση μιας persona αναλαμβάνει ταυτόχρονα το uid, το gid και τις συμμετοχές της σε ομάδες. Στον [**πηγαίο κώδικα**](https://github.com/apple/darwin-xnu/blob/main/bsd/sys/persona.h) μπορείτε να βρείτε τη δομή:

```c
struct kpersona_info { uint32_t persona_info_version;
    uid_t    persona_id; /* overlaps with UID */
    int      persona_type;
    gid_t    persona_gid;
    uint32_t persona_ngroups;
    gid_t    persona_groups[NGROUPS];
    uid_t    persona_gmuid;
    char     persona_name[MAXLOGNAME + 1];

    /* TODO: MAC policies?! */
}
```

## Βασικές πληροφορίες για τα νήματα

1. **Νήματα POSIX (pthreads):** Το macOS υποστηρίζει νήματα POSIX (`pthreads`), τα οποία αποτελούν μέρος ενός τυπικού API νημάτων για C/C++. Η υλοποίηση των pthreads στο macOS βρίσκεται στο `/usr/lib/system/libsystem_pthread.dylib` και προέρχεται από το δημόσια διαθέσιμο project `libpthread`. Αυτή η βιβλιοθήκη παρέχει τις απαραίτητες λειτουργίες για τη δημιουργία και τη διαχείριση νημάτων.
2. **Δημιουργία νημάτων:** Η συνάρτηση `pthread_create()` χρησιμοποιείται για τη δημιουργία νέων νημάτων. Εσωτερικά, αυτή η συνάρτηση καλεί την `bsdthread_create()`, μια κλήση συστήματος χαμηλότερου επιπέδου, ειδική για τον πυρήνα XNU (τον πυρήνα στον οποίο βασίζεται το macOS). Αυτή η κλήση συστήματος δέχεται διάφορες σημαίες που προκύπτουν από το `pthread_attr` (χαρακτηριστικά) και καθορίζουν τη συμπεριφορά των νημάτων, συμπεριλαμβανομένων των πολιτικών χρονοπρογραμματισμού και του μεγέθους της στοίβας.
   - **Προεπιλεγμένο μέγεθος στοίβας:** Το προεπιλεγμένο μέγεθος στοίβας για νέα νήματα είναι 512 KB, ποσό επαρκές για συνήθεις λειτουργίες, το οποίο μπορεί να προσαρμοστεί μέσω των χαρακτηριστικών του νήματος, αν χρειάζεται περισσότερος ή λιγότερος χώρος.
3. **Αρχικοποίηση νημάτων:** Η συνάρτηση `__pthread_init()` είναι καθοριστική κατά τη ρύθμιση του νήματος. Χρησιμοποιεί το όρισμα `env[]` για να αναλύσει μεταβλητές περιβάλλοντος που μπορεί να περιλαμβάνουν πληροφορίες για τη θέση και το μέγεθος της στοίβας.

#### Τερματισμός νημάτων στο macOS

1. **Έξοδος από νήματα:** Τα νήματα συνήθως τερματίζονται με την κλήση της `pthread_exit()`. Αυτή η συνάρτηση επιτρέπει σε ένα νήμα να τερματιστεί ομαλά, εκτελώντας τον απαραίτητο καθαρισμό και επιτρέποντάς του να επιστρέψει μια τιμή σε όποια νήματα αναμένουν τη λήξη του μέσω join.
2. **Καθαρισμός νημάτων:** Κατά την κλήση της `pthread_exit()`, καλείται η συνάρτηση `pthread_terminate()`, η οποία διαχειρίζεται την αφαίρεση όλων των σχετικών δομών του νήματος. Αποδεσμεύει τις θύρες νημάτων Mach (το Mach είναι το υποσύστημα επικοινωνίας στον πυρήνα XNU) και καλεί την `bsdthread_terminate`, μια κλήση συστήματος που αφαιρεί τις δομές σε επίπεδο πυρήνα οι οποίες σχετίζονται με το νήμα.

#### Μηχανισμοί συγχρονισμού

Για τη διαχείριση της πρόσβασης σε κοινόχρηστους πόρους και την αποφυγή συνθηκών ανταγωνισμού, το macOS παρέχει διάφορα πρωτόγονα στοιχεία συγχρονισμού. Είναι κρίσιμα σε περιβάλλοντα πολυνηματισμού, ώστε να διασφαλίζονται η ακεραιότητα των δεδομένων και η σταθερότητα του συστήματος:

1. **Mutexes:**
   - **Κανονικό Mutex (Υπογραφή: 0x4D555458):** Τυπικό mutex με αποτύπωμα μνήμης 60 byte (56 byte για το mutex και 4 byte για την υπογραφή).
   - **Γρήγορο Mutex (Υπογραφή: 0x4d55545A):** Παρόμοιο με ένα κανονικό mutex, αλλά βελτιστοποιημένο για ταχύτερες λειτουργίες, επίσης μεγέθους 60 byte.
2. **Μεταβλητές συνθήκης:**
   - Χρησιμοποιούνται για αναμονή μέχρι να ισχύσουν ορισμένες συνθήκες και έχουν μέγεθος 44 byte (40 byte συν μια υπογραφή 4 byte).
   - **Χαρακτηριστικά μεταβλητών συνθήκης (Υπογραφή: 0x434e4441):** Χαρακτηριστικά ρύθμισης για μεταβλητές συνθήκης, μεγέθους 12 byte.
3. **Μεταβλητή Once (Υπογραφή: 0x4f4e4345):**
   - Διασφαλίζει ότι ένα τμήμα κώδικα αρχικοποίησης εκτελείται μόνο μία φορά. Έχει μέγεθος 12 byte.
4. **Κλειδώματα ανάγνωσης-εγγραφής:**
   - Επιτρέπουν ταυτόχρονα πολλούς αναγνώστες ή έναν εγγραφέα, διευκολύνοντας την αποδοτική πρόσβαση σε κοινόχρηστα δεδομένα.
   - **Κλείδωμα ανάγνωσης-εγγραφής (Υπογραφή: 0x52574c4b):** Έχει μέγεθος 196 byte.
   - **Χαρακτηριστικά κλειδώματος ανάγνωσης-εγγραφής (Υπογραφή: 0x52574c41):** Χαρακτηριστικά για κλειδώματα ανάγνωσης-εγγραφής, μεγέθους 20 byte.

> [!TIP]
> Τα τελευταία 4 byte αυτών των αντικειμένων χρησιμοποιούνται για τον εντοπισμό υπερχειλίσεων.

### Μεταβλητές τοπικές σε νήματα (TLV)

Οι **μεταβλητές τοπικές σε νήματα (TLV)**, στο πλαίσιο αρχείων Mach-O (της μορφής εκτελέσιμων αρχείων στο macOS), χρησιμοποιούνται για τη δήλωση μεταβλητών που αφορούν **κάθε νήμα ξεχωριστά** σε μια πολυνηματική εφαρμογή. Έτσι, κάθε νήμα έχει τη δική του ξεχωριστή παρουσία μιας μεταβλητής, αποφεύγονται οι διενέξεις και διατηρείται η ακεραιότητα των δεδομένων χωρίς να απαιτούνται ρητοί μηχανισμοί συγχρονισμού, όπως τα mutexes.

Στη C και σε συναφείς γλώσσες, μπορείτε να δηλώσετε μια μεταβλητή τοπική σε νήμα χρησιμοποιώντας τη λέξη-κλειδί **`__thread`**. Δείτε πώς λειτουργεί στο παράδειγμά σας:

```c
cCopy code__thread int tlv_var;

void main (int argc, char **argv){
    tlv_var = 10;
}
```

Αυτό το απόσπασμα ορίζει το `tlv_var` ως μεταβλητή τοπική σε νήμα. Κάθε νήμα που εκτελεί αυτόν τον κώδικα θα έχει το δικό του `tlv_var`, και οι αλλαγές που κάνει ένα νήμα στο `tlv_var` δεν θα επηρεάζουν το `tlv_var` κάποιου άλλου νήματος.

Στο δυαδικό αρχείο Mach-O, τα δεδομένα που σχετίζονται με τις μεταβλητές τοπικές σε νήμα οργανώνονται σε συγκεκριμένες ενότητες:

- **`__DATA.__thread_vars`**: Αυτή η ενότητα περιέχει μεταδεδομένα σχετικά με τις μεταβλητές τοπικές σε νήμα, όπως τους τύπους τους και την κατάσταση αρχικοποίησής τους.
- **`__DATA.__thread_bss`**: Αυτή η ενότητα χρησιμοποιείται για μεταβλητές τοπικές σε νήμα που δεν έχουν αρχικοποιηθεί ρητά. Αποτελεί τμήμα της μνήμης που έχει δεσμευτεί για δεδομένα αρχικοποιημένα με μηδενικές τιμές.

Το Mach-O παρέχει επίσης ένα ειδικό API, το **`tlv_atexit`**, για τη διαχείριση μεταβλητών τοπικών σε νήμα κατά τον τερματισμό ενός νήματος. Αυτό το API επιτρέπει την **καταχώριση destructors** — ειδικών συναρτήσεων που καθαρίζουν τα δεδομένα τοπικά σε νήμα όταν τερματίζεται ένα νήμα.

### Προτεραιότητες νημάτων

Για να κατανοήσουμε τις προτεραιότητες νημάτων, πρέπει να δούμε πώς το λειτουργικό σύστημα αποφασίζει ποια νήματα θα εκτελεστούν και πότε. Αυτή η απόφαση επηρεάζεται από το επίπεδο προτεραιότητας που έχει εκχωρηθεί σε κάθε νήμα. Στο macOS και σε συστήματα τύπου Unix, αυτό γίνεται με έννοιες όπως `nice`, `renice` και οι κλάσεις Quality of Service (QoS).

#### Nice και Renice

1. **Nice:**
   - Η τιμή `nice` μιας διεργασίας είναι ένας αριθμός που επηρεάζει την προτεραιότητά της. Κάθε διεργασία έχει τιμή nice από -20 (υψηλότερη προτεραιότητα) έως 19 (χαμηλότερη προτεραιότητα). Η προεπιλεγμένη τιμή nice κατά τη δημιουργία μιας διεργασίας είναι συνήθως 0.
   - Μια χαμηλότερη τιμή nice (πιο κοντά στο -20) κάνει μια διεργασία πιο «εγωιστική», δίνοντάς της περισσότερο χρόνο CPU σε σύγκριση με άλλες διεργασίες που έχουν υψηλότερες τιμές nice.
2. **Renice:**
   - Το `renice` είναι μια εντολή που χρησιμοποιείται για να αλλάξει την τιμή nice μιας διεργασίας που εκτελείται ήδη. Μπορεί να χρησιμοποιηθεί για τη δυναμική προσαρμογή της προτεραιότητας των διεργασιών, αυξάνοντας ή μειώνοντας τον χρόνο CPU που τους αναλογεί με βάση τις νέες τιμές nice.
   - Για παράδειγμα, αν μια διεργασία χρειάζεται προσωρινά περισσότερους πόρους CPU, μπορείτε να μειώσετε την τιμή nice της χρησιμοποιώντας το `renice`.

#### Κλάσεις Quality of Service (QoS)

Οι κλάσεις QoS αποτελούν μια πιο σύγχρονη προσέγγιση στη διαχείριση των προτεραιοτήτων νημάτων, ιδιαίτερα σε συστήματα όπως το macOS που υποστηρίζουν το **Grand Central Dispatch (GCD)**. Οι κλάσεις QoS επιτρέπουν στους προγραμματιστές να **κατηγοριοποιούν** τις εργασίες σε διαφορετικά επίπεδα με βάση τη σημασία ή τον επείγοντα χαρακτήρα τους. Το macOS διαχειρίζεται αυτόματα την ιεράρχηση των νημάτων με βάση αυτές τις κλάσεις QoS:

1. **User Interactive:**
   - Αυτή η κλάση προορίζεται για εργασίες που αλληλεπιδρούν εκείνη τη στιγμή με τον χρήστη ή απαιτούν άμεσα αποτελέσματα για να προσφέρουν καλή εμπειρία χρήσης. Αυτές οι εργασίες έχουν την υψηλότερη προτεραιότητα, ώστε η διεπαφή να παραμένει αποκρίσιμη (π.χ. κινούμενα σχέδια ή χειρισμός συμβάντων).
2. **User Initiated:**
   - Εργασίες που ξεκινά ο χρήστης και για τις οποίες αναμένει άμεσα αποτελέσματα, όπως το άνοιγμα ενός εγγράφου ή το πάτημα ενός κουμπιού που απαιτεί υπολογισμούς. Έχουν υψηλή προτεραιότητα, αλλά χαμηλότερη από τις εργασίες User Interactive.
3. **Utility:**
   - Αυτές οι εργασίες διαρκούν αρκετά και συνήθως εμφανίζουν μια ένδειξη προόδου (π.χ. λήψη αρχείων, εισαγωγή δεδομένων). Έχουν χαμηλότερη προτεραιότητα από τις εργασίες User Initiated και δεν χρειάζεται να ολοκληρωθούν άμεσα.
4. **Background:**
   - Αυτή η κλάση προορίζεται για εργασίες που εκτελούνται στο παρασκήνιο και δεν είναι ορατές στον χρήστη. Τέτοιες εργασίες μπορεί να είναι η ευρετηρίαση, ο συγχρονισμός ή η δημιουργία αντιγράφων ασφαλείας. Έχουν τη χαμηλότερη προτεραιότητα και ελάχιστη επίδραση στην απόδοση του συστήματος.

Με τις κλάσεις QoS, οι προγραμματιστές δεν χρειάζεται να διαχειρίζονται συγκεκριμένους αριθμούς προτεραιότητας, αλλά μπορούν να επικεντρώνονται στη φύση της εργασίας, ενώ το σύστημα βελτιστοποιεί ανάλογα τους πόρους CPU.

Επιπλέον, υπάρχουν διαφορετικές **πολιτικές προγραμματισμού νημάτων**, οι οποίες καθορίζουν ένα σύνολο παραμέτρων προγραμματισμού που θα λαμβάνει υπόψη ο scheduler. Αυτό μπορεί να γίνει με το `thread_policy_[set/get]`. Μπορεί να είναι χρήσιμο σε επιθέσεις race condition.

## Κατάχρηση διεργασιών macOS

Το macOS παρέχει πολλούς μηχανισμούς ώστε οι **διεργασίες να αλληλεπιδρούν, να επικοινωνούν και να μοιράζονται δεδομένα**. Παρόλο που αυτοί οι μηχανισμοί είναι απαραίτητοι για την κανονική λειτουργία του συστήματος, οι επιτιθέμενοι μπορούν να τους καταχραστούν για injection, εκτέλεση κώδικα ή πρόσβαση σε δεδομένα.

### Library Injection

Το Library Injection είναι μια τεχνική κατά την οποία ένας επιτιθέμενος **αναγκάζει μια διεργασία να φορτώσει μια κακόβουλη βιβλιοθήκη**. Μετά την εισαγωγή της, η βιβλιοθήκη εκτελείται στο πλαίσιο της διεργασίας-στόχου, παρέχοντας στον επιτιθέμενο τα ίδια δικαιώματα και την ίδια πρόσβαση με τη διεργασία.

### Επικοινωνία μεταξύ διεργασιών

Η επικοινωνία μεταξύ διεργασιών (IPC) αναφέρεται σε διαφορετικές μεθόδους με τις οποίες ξεχωριστές διεργασίες **μοιράζονται και ανταλλάσσουν δεδομένα**. ### Shell Injection

Το μη διαδραστικό Bash διαβάζει το **`BASH_ENV`**· τα διαδραστικά POSIX shells διαβάζουν το **`ENV`**· το zsh διαβάζει το **`$ZDOTDIR/.zshenv`**· και το fish διαβάζει ρυθμίσεις από το **`XDG_CONFIG_HOME`** ή το **`XDG_DATA_DIRS`**. Καθένα από αυτά μπορεί να εκτελέσει ένα ελεγχόμενο αρχείο εκκίνησης πριν από την προβλεπόμενη εντολή. Το Bash εκτελεί επίσης μια command substitution που βρίσκεται στο **`PS4`** κάθε φορά που είναι ενεργοποιημένο το xtrace (π.χ. μέσω κληρονομημένου **`SHELLOPTS=xtrace`**):

### Λαθραία εισαγωγή εντολών μέσω του stdin του shell

Η εκκίνηση του `/bin/zsh -s` κάνει το shell να διαβάζει ένα πρόγραμμα από το standard input. Επομένως, αν ένας downloader αντιγράψει ένα μη έμπιστο δομημένο έγγραφο στο stdin της θυγατρικής διεργασίας χωρίς πρώτα να το αναλύσει, μετατρέπει ολόκληρο το έγγραφο σε πηγαίο κώδικα shell. Σε ένα περιστατικό, ένας loader διάβασε ένα δημόσιο αρχείο iCalendar μέσω μιας ανώνυμης pipe, γραμμή προς γραμμή. Τα metadata του ημερολογίου απέτυχαν ως εντολές, αλλά το zsh συνέχισε μέχρι να φτάσει σε εκτελέσιμες γραμμές που είχαν τοποθετηθεί μετά το `DESCRIPTION:`. Αυτές οι γραμμές κατέβασαν και εκκίνησαν το επόμενο application bundle. Ο αναμενόμενος τύπος περιεχομένου και η έμπιστη φιλοξενία του αρχείου δεν το καθιστούσαν ασφαλές· το επικίνδυνο σημείο ήταν η παράδοση των bytes του σε έναν interpreter.<sup>[[5]](#references)</sup>

Σχετικά στάδια καλύπτονται στα [Mach-O overlays](../macos-files-folders-and-binaries/universal-binaries-and-mach-o-format.md), [Gatekeeper and quarantine](../macos-security-protections/macos-gatekeeper.md) και [macOS auto-start locations](../../macos-auto-start-locations.md).

### Python Injection

Η αλυσίδα **`PYTHONWARNINGS`** και **`BROWSER`** της standard library μπορεί να εκτελέσει μια εντολή κατά την ανάλυση των warning filters. Μια εναλλακτική που βασίζεται σε αρχείο τοποθετεί το `sitecustomize.py` στο **`PYTHONPATH`**, ώστε η κανονική αρχικοποίηση του `site` να το εισαγάγει πριν από το script-στόχο. Το **`PYTHONBREAKPOINT`** εκτελεί μια επιλεγμένη callable/module όταν ο κώδικας φτάσει στο `breakpoint()`. Μεταβλητές που χρησιμοποιούνται μόνο σε διαδραστική λειτουργία, όπως το **`PYTHONSTARTUP`**, έχουν πιο περιορισμένη εφαρμογή.

Σημειώστε ότι τα εκτελέσιμα αρχεία που έχουν μεταγλωττιστεί με **`pyinstaller`** δεν χρησιμοποιούν αυτές τις μεταβλητές περιβάλλοντος, ακόμη κι αν εκτελούνται με ενσωματωμένο Python.

Ξεχωριστά, το Homebrew συνήθως εγκαθιστά το Python κάτω από το `/opt/homebrew`, όπου μέλη της τοπικής ομάδας `admin` ενδέχεται να μπορούν να αντικαταστήσουν τον launcher. ## Εντοπισμός

### Shield

Το [**Shield**](https://github.com/theevilbit/Shield) είναι μια εφαρμογή ανοιχτού κώδικα που βασίζεται στο **EndpointSecurity** και εντοπίζει και αποκλείει process injection. Αποτελεί καλό σημείο αναφοράς για τα σήματα που είναι ορατά μέσω του Endpoint Security, καθώς ειδοποιεί για τα εξής:<sup>[[1]](#references)</sup><sup>[[2]](#references)</sup>

- **Μεταβλητές περιβάλλοντος injection** κατά την εκτέλεση μιας διεργασίας: `DYLD_INSERT_LIBRARIES`, `CFNETWORK_LIBRARY_PATH`, `RAWCAMERA_BUNDLE_PATH` και `ELECTRON_RUN_AS_NODE`.
- Κλήσεις **`task_for_pid`** — μια διεργασία ζητά το task port μιας άλλης, προϋπόθεση για την εισαγωγή κώδικα σε αυτήν.
- **Ορίσματα debugging του Electron** — `--inspect`, `--inspect-brk` και `--remote-debugging-port`, τα οποία εκκινούν μια εφαρμογή Electron σε λειτουργία debugging και επιτρέπουν σε οποιονδήποτε να συνδεθεί και να εκτελέσει κώδικα σε αυτήν.<sup>[[3]](#references)</sup>
- **Δημιουργία symlink/hardlink μεταξύ διαφορετικών επιπέδων δικαιωμάτων** — το κλασικό primitive «δημιούργησε έναν σύνδεσμο ως κανονικός χρήστης και στόχευσέ τον σε μια προνομιούχα τοποθεσία». Σημειώστε ότι **για τα symlink μπορούν να σταλούν ειδοποιήσεις, αλλά δεν μπορούν να αποκλειστούν**: το EndpointSecurity δεν εκθέτει τον προορισμό του συνδέσμου πριν από τη δημιουργία του.

### Κλήσεις από άλλες διεργασίες

Στο [**άρθρο ιστολογίου**](https://knight.sc/reverse%20engineering/2019/04/15/detecting-task-modifications.html) μπορείτε να δείτε πώς είναι δυνατό να χρησιμοποιηθεί η συνάρτηση **`task_name_for_pid`** για τη λήψη πληροφοριών σχετικά με άλλες **διεργασίες που εισάγουν κώδικα σε μια διεργασία**, και στη συνέχεια για τη λήψη πληροφοριών σχετικά με εκείνη την άλλη διεργασία.<sup>[[4]](#references)</sup>

Σημειώστε ότι για να καλέσετε αυτή τη συνάρτηση πρέπει να έχετε **το ίδιο uid** με τον χρήστη που εκτελεί τη διεργασία ή να είστε **root** (και επιστρέφει πληροφορίες για τη διεργασία, όχι τρόπο εισαγωγής κώδικα).
