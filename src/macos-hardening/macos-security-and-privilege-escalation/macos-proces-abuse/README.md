## Βασικές πληροφορίες για τις διεργασίες

Μια διεργασία είναι ένα στιγμιότυπο ενός εκτελέσιμου αρχείου που εκτελείται. Ωστόσο, οι διεργασίες δεν εκτελούν κώδικα· αυτό το κάνουν τα νήματα. Επομένως, **οι διεργασίες είναι απλώς περιέκτες για νήματα που εκτελούνται**, οι οποίοι παρέχουν μνήμη, descriptors, θύρες, δικαιώματα...

Παραδοσιακά, οι διεργασίες ξεκινούσαν μέσα από άλλες διεργασίες (εκτός από την PID 1), με την κλήση της **`fork`**, η οποία δημιουργούσε ένα ακριβές αντίγραφο της τρέχουσας διεργασίας. Στη συνέχεια, η **θυγατρική διεργασία** συνήθως καλούσε την **`execve`** για να φορτώσει το νέο εκτελέσιμο αρχείο και να το εκτελέσει. Έπειτα, εισήχθη η **`vfork`** για να επιταχύνει αυτή τη διαδικασία χωρίς αντιγραφή μνήμης.\
Στη συνέχεια, εισήχθη η **`posix_spawn`**, η οποία συνδυάζει τις **`vfork`** και **`execve`** σε μία κλήση και δέχεται flags:

- `POSIX_SPAWN_RESETIDS`: Επαναφορά των effective ids στα real ids
- `POSIX_SPAWN_SETPGROUP`: Ορισμός της συμμετοχής σε process group
- `POSUX_SPAWN_SETSIGDEF`: Ορισμός της προεπιλεγμένης συμπεριφοράς των signals
- `POSIX_SPAWN_SETSIGMASK`: Ορισμός της μάσκας signals
- `POSIX_SPAWN_SETEXEC`: Εκτέλεση στην ίδια διεργασία (όπως η `execve`, με περισσότερες επιλογές)
- `POSIX_SPAWN_START_SUSPENDED`: Εκκίνηση σε αναστολή
- `_POSIX_SPAWN_DISABLE_ASLR`: Εκκίνηση χωρίς ASLR
- `_POSIX_SPAWN_NANO_ALLOCATOR:` Χρήση του Nano allocator της libmalloc
- `_POSIX_SPAWN_ALLOW_DATA_EXEC:` Επιτρέπεται `rwx` στα data segments
- `POSIX_SPAWN_CLOEXEC_DEFAULT`: Κλείσιμο όλων των file descriptions κατά την εκτέλεση της exec(2), από προεπιλογή
- `_POSIX_SPAWN_HIGH_BITS_ASLR:` Τυχαιοποίηση των υψηλών bits του ASLR slide

Επιπλέον, η `posix_spawn` δέχεται ρυθμίσεις **`posix_spawnattr`**, οι οποίες ελέγχουν πτυχές της διεργασίας που δημιουργείται, και καταχωρίσεις **`posix_spawn_file_actions`**, οι οποίες τροποποιούν τα file descriptors.

Όταν μια διεργασία τερματίζεται, στέλνει τον **κωδικό επιστροφής στη γονική διεργασία** (αν η γονική διεργασία έχει τερματιστεί, νέα γονική διεργασία είναι η PID 1) με το signal `SIGCHLD`. Η γονική διεργασία πρέπει να λάβει αυτή την τιμή καλώντας τις `wait4()` ή `waitid()`. Μέχρι να συμβεί αυτό, η θυγατρική διεργασία παραμένει σε κατάσταση zombie, όπου εξακολουθεί να εμφανίζεται στη λίστα, αλλά δεν καταναλώνει πόρους.

### PIDs

Τα PIDs, δηλαδή τα αναγνωριστικά διεργασιών, προσδιορίζουν μια μοναδική διεργασία. Στο XNU, τα **PIDs** είναι **64 bits**, αυξάνονται μονοτονικά και **δεν κάνουν ποτέ wrap** (για την αποφυγή καταχρήσεων).

### Process Groups, Sessions & Coalitions

Οι **διεργασίες** μπορούν να ενταχθούν σε **groups**, ώστε να είναι ευκολότερη η διαχείρισή τους. Για παράδειγμα, οι εντολές ενός shell script ανήκουν στην ίδια process group, επομένως είναι δυνατό να **σταλούν signals σε όλες μαζί**, χρησιμοποιώντας, για παράδειγμα, την kill.\
Είναι επίσης δυνατό να **ομαδοποιηθούν διεργασίες σε sessions**. Όταν μια διεργασία ξεκινά μια session (`setsid(2)`), οι θυγατρικές διεργασίες της εντάσσονται σε αυτήν, εκτός αν ξεκινήσουν τη δική τους session.

Το Coalition είναι ένας ακόμη τρόπος ομαδοποίησης διεργασιών στο Darwin. Όταν μια διεργασία εντάσσεται σε ένα Coalition, μπορεί να έχει πρόσβαση σε κοινόχρηστους πόρους, να μοιράζεται ένα ledger ή να υπόκειται στο Jetsam. Τα Coalitions έχουν διαφορετικούς ρόλους: Leader, XPC service, Extension.

### Διαπιστευτήρια & Personae

Κάθε διεργασία διατηρεί **διαπιστευτήρια** που **καθορίζουν τα δικαιώματά της** στο σύστημα. Κάθε διεργασία έχει ένα κύριο `uid` και ένα κύριο `gid` (αν και μπορεί να ανήκει σε πολλές ομάδες).\
Είναι επίσης δυνατό να αλλάξουν τα user και group ids, αν το binary έχει το bit `setuid/setgid`.\
Υπάρχουν αρκετές συναρτήσεις για τον **ορισμό νέων uids/gids**.

Η syscall **`persona`** παρέχει ένα **εναλλακτικό** σύνολο **διαπιστευτηρίων**. Η υιοθέτηση μιας persona σημαίνει την ταυτόχρονη χρήση του uid, του gid και των μελών των ομάδων της. Στον [**πηγαίο κώδικα**](https://github.com/apple/darwin-xnu/blob/main/bsd/sys/persona.h) μπορείτε να βρείτε το struct:

```c
struct kpersona_info { uint32_t persona_info_version;
    uid_t    persona_id; /* overlaps with UID */
    int      persona_type;
    gid_t    persona_gid;
    uint32_t persona_ngroups;
    gid_t    persona_groups[NGROUPS];
    uid_t    persona_gmuid;
    char     persona_name[MAXLOGNAME + 1];

    /* TODO: MAC policies?! */
}
```

## Βασικές πληροφορίες για τα threads

1. **POSIX Threads (pthreads):** Το macOS υποστηρίζει POSIX threads (`pthreads`), τα οποία αποτελούν μέρος ενός τυπικού API διαχείρισης threads για C/C++. Η υλοποίηση των pthreads στο macOS βρίσκεται στο `/usr/lib/system/libsystem_pthread.dylib`, το οποίο προέρχεται από το δημόσια διαθέσιμο project `libpthread`. Αυτή η βιβλιοθήκη παρέχει τις απαραίτητες συναρτήσεις για τη δημιουργία και τη διαχείριση threads.
2. **Δημιουργία threads:** Η συνάρτηση `pthread_create()` χρησιμοποιείται για τη δημιουργία νέων threads. Εσωτερικά, αυτή η συνάρτηση καλεί τη `bsdthread_create()`, μια κλήση συστήματος χαμηλότερου επιπέδου, ειδική για τον πυρήνα XNU (τον πυρήνα στον οποίο βασίζεται το macOS). Αυτή η κλήση συστήματος λαμβάνει διάφορες σημαίες που προκύπτουν από το `pthread_attr` (attributes) και καθορίζουν τη συμπεριφορά των threads, συμπεριλαμβανομένων των πολιτικών χρονοπρογραμματισμού και του μεγέθους της στοίβας.
   - **Προεπιλεγμένο μέγεθος στοίβας:** Το προεπιλεγμένο μέγεθος στοίβας για νέα threads είναι 512 KB, ποσότητα επαρκής για τυπικές λειτουργίες, αλλά μπορεί να προσαρμοστεί μέσω των thread attributes, αν χρειάζεται περισσότερος ή λιγότερος χώρος.
3. **Αρχικοποίηση thread:** Η συνάρτηση `__pthread_init()` είναι κρίσιμη κατά τη ρύθμιση ενός thread, καθώς χρησιμοποιεί το όρισμα `env[]` για την ανάλυση μεταβλητών περιβάλλοντος, οι οποίες μπορεί να περιλαμβάνουν πληροφορίες σχετικά με τη θέση και το μέγεθος της στοίβας.

#### Τερματισμός threads στο macOS

1. **Έξοδος από threads:** Τα threads συνήθως τερματίζονται με κλήση της `pthread_exit()`. Αυτή η συνάρτηση επιτρέπει σε ένα thread να τερματιστεί ομαλά, εκτελώντας τον απαραίτητο καθαρισμό και επιτρέποντάς του να επιστρέψει μια τιμή σε όσα threads περιμένουν τη συνένωσή του.
2. **Καθαρισμός thread:** Κατά την κλήση της `pthread_exit()`, καλείται η συνάρτηση `pthread_terminate()`, η οποία διαχειρίζεται την αφαίρεση όλων των σχετικών δομών του thread. Αποδεσμεύει τις θύρες thread του Mach (το Mach είναι το υποσύστημα επικοινωνίας στον πυρήνα XNU) και καλεί την `bsdthread_terminate`, μια κλήση συστήματος που αφαιρεί τις δομές σε επίπεδο πυρήνα οι οποίες σχετίζονται με το thread.

#### Μηχανισμοί συγχρονισμού

Για τη διαχείριση της πρόσβασης σε κοινόχρηστους πόρους και την αποφυγή race conditions, το macOS παρέχει διάφορα primitives συγχρονισμού. Είναι κρίσιμα σε περιβάλλοντα πολλαπλών threads, ώστε να διασφαλίζεται η ακεραιότητα των δεδομένων και η σταθερότητα του συστήματος:

1. **Mutexes:**
   - **Κανονικό Mutex (Signature: 0x4D555458):** Τυπικό mutex με αποτύπωμα μνήμης 60 bytes (56 bytes για το mutex και 4 bytes για την υπογραφή).
   - **Fast Mutex (Signature: 0x4d55545A):** Παρόμοιο με ένα κανονικό mutex, αλλά βελτιστοποιημένο για ταχύτερες λειτουργίες· έχει επίσης μέγεθος 60 bytes.
2. **Condition Variables:**
   - Χρησιμοποιούνται για την αναμονή μέχρι να προκύψουν ορισμένες συνθήκες και έχουν μέγεθος 44 bytes (40 bytes συν υπογραφή 4 bytes).
   - **Condition Variable Attributes (Signature: 0x434e4441):** Attributes διαμόρφωσης για condition variables, μεγέθους 12 bytes.
3. **Once Variable (Signature: 0x4f4e4345):**
   - Διασφαλίζει ότι ένα τμήμα κώδικα αρχικοποίησης εκτελείται μόνο μία φορά. Έχει μέγεθος 12 bytes.
4. **Read-Write Locks:**
   - Επιτρέπουν σε πολλούς readers ή σε έναν writer κάθε φορά, διευκολύνοντας την αποδοτική πρόσβαση σε κοινόχρηστα δεδομένα.
   - **Read Write Lock (Signature: 0x52574c4b):** Έχει μέγεθος 196 bytes.
   - **Read Write Lock Attributes (Signature: 0x52574c41):** Attributes για read-write locks, μεγέθους 20 bytes.

> [!TIP]
> Τα τελευταία 4 bytes αυτών των αντικειμένων χρησιμοποιούνται για την ανίχνευση υπερχειλίσεων.

### Thread Local Variables (TLV)

Οι **Thread Local Variables (TLV)** στο πλαίσιο αρχείων Mach-O (της μορφής εκτελέσιμων αρχείων στο macOS) χρησιμοποιούνται για τη δήλωση μεταβλητών που είναι ειδικές για **κάθε thread** σε μια εφαρμογή πολλαπλών threads. Έτσι διασφαλίζεται ότι κάθε thread έχει τη δική του ξεχωριστή παρουσία μιας μεταβλητής, παρέχοντας έναν τρόπο αποφυγής συγκρούσεων και διατήρησης της ακεραιότητας των δεδομένων χωρίς να απαιτούνται ρητοί μηχανισμοί συγχρονισμού, όπως τα mutexes.

Στις γλώσσες C και σε συγγενείς γλώσσες, μπορείτε να δηλώσετε μια μεταβλητή τοπική σε thread χρησιμοποιώντας τη λέξη-κλειδί **`__thread`**. Δείτε πώς λειτουργεί στο παράδειγμά σας:

```c
cCopy code__thread int tlv_var;

void main (int argc, char **argv){
    tlv_var = 10;
}
```

Αυτό το απόσπασμα ορίζει το `tlv_var` ως μεταβλητή thread-local. Κάθε νήμα που εκτελεί αυτόν τον κώδικα θα έχει το δικό του `tlv_var`, και οι αλλαγές που κάνει ένα νήμα στο `tlv_var` δεν θα επηρεάζουν το `tlv_var` κάποιου άλλου νήματος.

Στο δυαδικό αρχείο Mach-O, τα δεδομένα που σχετίζονται με τις μεταβλητές thread-local οργανώνονται σε συγκεκριμένες ενότητες:

- **`__DATA.__thread_vars`**: Αυτή η ενότητα περιέχει μεταδεδομένα σχετικά με τις μεταβλητές thread-local, όπως τους τύπους τους και την κατάσταση αρχικοποίησής τους.
- **`__DATA.__thread_bss`**: Αυτή η ενότητα χρησιμοποιείται για μεταβλητές thread-local που δεν έχουν αρχικοποιηθεί ρητά. Είναι ένα τμήμα μνήμης που προορίζεται για δεδομένα αρχικοποιημένα με μηδενικές τιμές.

Το Mach-O παρέχει επίσης ένα ειδικό API, το **`tlv_atexit`**, για τη διαχείριση των μεταβλητών thread-local κατά τον τερματισμό ενός νήματος. Αυτό το API επιτρέπει την **καταχώριση destructors**—ειδικών συναρτήσεων που καθαρίζουν τα δεδομένα thread-local όταν τερματίζεται ένα νήμα.

### Προτεραιότητες νημάτων

Για να κατανοήσουμε τις προτεραιότητες των νημάτων, πρέπει να εξετάσουμε πώς το λειτουργικό σύστημα αποφασίζει ποια νήματα θα εκτελούνται και πότε. Η απόφαση αυτή επηρεάζεται από το επίπεδο προτεραιότητας που έχει εκχωρηθεί σε κάθε νήμα. Στο macOS και σε συστήματα τύπου Unix, αυτό γίνεται με έννοιες όπως οι `nice`, `renice` και οι κλάσεις Quality of Service (QoS).

#### Nice και Renice

1. **Nice:**
   - Η τιμή `nice` μιας διεργασίας είναι ένας αριθμός που επηρεάζει την προτεραιότητά της. Κάθε διεργασία έχει τιμή nice από -20 (υψηλότερη προτεραιότητα) έως 19 (χαμηλότερη προτεραιότητα). Η προεπιλεγμένη τιμή nice κατά τη δημιουργία μιας διεργασίας είναι συνήθως 0.
   - Μια χαμηλότερη τιμή nice (πιο κοντά στο -20) κάνει μια διεργασία πιο «εγωκεντρική», δίνοντάς της περισσότερο χρόνο CPU σε σύγκριση με άλλες διεργασίες που έχουν υψηλότερες τιμές nice.
2. **Renice:**
   - Το `renice` είναι εντολή που χρησιμοποιείται για να αλλάξει την τιμή nice μιας διεργασίας που εκτελείται ήδη. Μπορεί να χρησιμοποιηθεί για τη δυναμική προσαρμογή της προτεραιότητας των διεργασιών, αυξάνοντας ή μειώνοντας τον χρόνο CPU που τους εκχωρείται, ανάλογα με τις νέες τιμές nice.
   - Για παράδειγμα, αν μια διεργασία χρειάζεται προσωρινά περισσότερους πόρους CPU, μπορείτε να μειώσετε την τιμή nice της χρησιμοποιώντας το `renice`.

#### Κλάσεις Quality of Service (QoS)

Οι κλάσεις QoS είναι μια πιο σύγχρονη προσέγγιση στη διαχείριση των προτεραιοτήτων των νημάτων, ιδιαίτερα σε συστήματα όπως το macOS που υποστηρίζουν το **Grand Central Dispatch (GCD)**. Οι κλάσεις QoS επιτρέπουν στους developers να **κατηγοριοποιούν** τις εργασίες σε διαφορετικά επίπεδα, ανάλογα με τη σημασία ή τον επείγοντα χαρακτήρα τους. Το macOS διαχειρίζεται αυτόματα την προτεραιοποίηση των νημάτων με βάση αυτές τις κλάσεις QoS:

1. **User Interactive:**
   - Αυτή η κλάση αφορά εργασίες που αλληλεπιδρούν εκείνη τη στιγμή με τον χρήστη ή απαιτούν άμεσα αποτελέσματα για μια καλή εμπειρία χρήσης. Σε αυτές τις εργασίες δίνεται η υψηλότερη προτεραιότητα, ώστε η διεπαφή να παραμένει αποκρίσιμη (π.χ. animations ή χειρισμός συμβάντων).
2. **User Initiated:**
   - Εργασίες που ξεκινά ο χρήστης και για τις οποίες αναμένει άμεσα αποτελέσματα, όπως το άνοιγμα ενός εγγράφου ή το πάτημα ενός κουμπιού που απαιτεί υπολογισμούς. Έχουν υψηλή προτεραιότητα, αλλά χαμηλότερη από τις εργασίες User Interactive.
3. **Utility:**
   - Αυτές οι εργασίες διαρκούν πολύ και συνήθως εμφανίζουν ένδειξη προόδου (π.χ. λήψη αρχείων, εισαγωγή δεδομένων). Έχουν χαμηλότερη προτεραιότητα από τις εργασίες User Initiated και δεν χρειάζεται να ολοκληρωθούν άμεσα.
4. **Background:**
   - Αυτή η κλάση αφορά εργασίες που εκτελούνται στο παρασκήνιο και δεν είναι ορατές στον χρήστη. Μπορεί να είναι εργασίες όπως η δημιουργία ευρετηρίου, ο συγχρονισμός ή η δημιουργία αντιγράφων ασφαλείας. Έχουν τη χαμηλότερη προτεραιότητα και ελάχιστη επίδραση στην απόδοση του συστήματος.

Χρησιμοποιώντας τις κλάσεις QoS, οι developers δεν χρειάζεται να διαχειρίζονται συγκεκριμένες τιμές προτεραιότητας, αλλά μπορούν να εστιάζουν στη φύση της εργασίας, ενώ το σύστημα βελτιστοποιεί ανάλογα τους πόρους CPU.

Επιπλέον, υπάρχουν διαφορετικές **πολιτικές χρονοπρογραμματισμού νημάτων**, οι οποίες επιτρέπουν στις ροές εκτέλεσης να καθορίζουν ένα σύνολο παραμέτρων χρονοπρογραμματισμού που θα λαμβάνει υπόψη ο χρονοπρογραμματιστής. Αυτό μπορεί να γίνει μέσω του `thread_policy_[set/get]`. Μπορεί να είναι χρήσιμο σε επιθέσεις race condition.

## Κατάχρηση διεργασιών στο macOS

Το macOS παρέχει πολλούς μηχανισμούς που επιτρέπουν στις **διεργασίες να αλληλεπιδρούν, να επικοινωνούν και να μοιράζονται δεδομένα**. Αν και αυτοί οι μηχανισμοί είναι απαραίτητοι για την κανονική λειτουργία του συστήματος, οι επιτιθέμενοι μπορούν να τους εκμεταλλευτούν για injection, εκτέλεση κώδικα ή πρόσβαση σε δεδομένα.

### Library Injection

Το Library Injection είναι μια τεχνική κατά την οποία ένας επιτιθέμενος **αναγκάζει μια διεργασία να φορτώσει μια κακόβουλη βιβλιοθήκη**. Μόλις γίνει inject, η βιβλιοθήκη εκτελείται στο πλαίσιο της διεργασίας-στόχου, παρέχοντας στον επιτιθέμενο τα ίδια δικαιώματα και την ίδια πρόσβαση με τη διεργασία.

Το Function Hooking περιλαμβάνει την **παρεμβολή σε κλήσεις συναρτήσεων** ή μηνύματα μέσα σε κώδικα λογισμικού. Κάνοντας hooking σε συναρτήσεις, ένας επιτιθέμενος μπορεί να **τροποποιήσει τη συμπεριφορά** μιας διεργασίας, να παρατηρήσει ευαίσθητα δεδομένα ή ακόμα και να αποκτήσει τον έλεγχο της ροής εκτέλεσης.

Αν και το IPC είναι θεμελιώδες για πολλές νόμιμες εφαρμογές, μπορεί επίσης να χρησιμοποιηθεί καταχρηστικά για την παράκαμψη της απομόνωσης διεργασιών, τη διαρροή ευαίσθητων πληροφοριών ή την εκτέλεση μη εξουσιοδοτημένων ενεργειών.

### Dirty NIB

Τα αρχεία NIB **ορίζουν στοιχεία διεπαφής χρήστη (UI)** και τις αλληλεπιδράσεις τους μέσα σε μια εφαρμογή. Ωστόσο, μπορούν να **εκτελέσουν αυθαίρετες εντολές**, ενώ το **Gatekeeper δεν εμποδίζει** την εκ νέου εκτέλεση μιας εφαρμογής που έχει ήδη εκτελεστεί, αν **τροποποιηθεί ένα αρχείο NIB**. Επομένως, μπορούν να χρησιμοποιηθούν ώστε αυθαίρετα προγράμματα να εκτελούν αυθαίρετες εντολές:

### Shell Injection

Το μη διαδραστικό Bash διαβάζει το **`BASH_ENV`**· τα διαδραστικά POSIX shells διαβάζουν το **`ENV`**· το zsh διαβάζει το **`$ZDOTDIR/.zshenv`**· και το fish διαβάζει αρχεία ρυθμίσεων από τις διαδρομές **`XDG_CONFIG_HOME`** ή **`XDG_DATA_DIRS`**. Το Bash εκτελεί επίσης μια command substitution που έχει τοποθετηθεί στο **`PS4`** κάθε φορά που είναι ενεργοποιημένο το xtrace (π.χ. μέσω του κληρονομημένου **`SHELLOPTS=xtrace`**):

### PowerShell Injection

### Python Injection

Η αλυσίδα της standard library **`PYTHONWARNINGS`** και **`BROWSER`** μπορεί να εκτελέσει μια εντολή κατά την ανάλυση των φίλτρων προειδοποιήσεων. Μια εναλλακτική που βασίζεται σε αρχείο τοποθετεί το `sitecustomize.py` στο **`PYTHONPATH`**, ώστε η κανονική αρχικοποίηση του `site` να το εισαγάγει πριν από το script-στόχο. Το **`PYTHONBREAKPOINT`** εκτελεί μια επιλεγμένη callable/module όταν ο κώδικας φτάσει στο `breakpoint()`. Μεταβλητές που αφορούν μόνο διαδραστική χρήση, όπως το **`PYTHONSTARTUP`**, έχουν πιο περιορισμένη εφαρμογή.

Σημειώστε ότι τα εκτελέσιμα αρχεία που έχουν μεταγλωττιστεί με **`pyinstaller`** δεν χρησιμοποιούν αυτές τις μεταβλητές περιβάλλοντος, ακόμη και όταν εκτελούνται με ενσωματωμένο python.

{{#ref}}

## Ανίχνευση

### Shield

Το [**Shield**](https://github.com/theevilbit/Shield) είναι μια εφαρμογή ανοιχτού κώδικα που βασίζεται στο **EndpointSecurity** και ανιχνεύει και αποκλείει το process injection. Αποτελεί καλή αναφορά για τα σήματα που μπορούν να παρατηρηθούν μέσω του Endpoint Security, καθώς ειδοποιεί για:<sup>[[1]](#references)</sup><sup>[[2]](#references)</sup>

- **Μεταβλητές περιβάλλοντος injection** κατά το process exec: `DYLD_INSERT_LIBRARIES`, `CFNETWORK_LIBRARY_PATH`, `RAWCAMERA_BUNDLE_PATH` και `ELECTRON_RUN_AS_NODE`.
- Κλήσεις **`task_for_pid`** — όταν μια διεργασία ζητά το task port μιας άλλης διεργασίας, προϋπόθεση για να γίνει injection σε αυτή.
- **Ορίσματα debugging του Electron** — τα `--inspect`, `--inspect-brk` και `--remote-debugging-port`, τα οποία εκκινούν μια εφαρμογή Electron σε λειτουργία debugging και επιτρέπουν σε οποιονδήποτε να συνδεθεί και να εκτελέσει κώδικα σε αυτήν.<sup>[[3]](#references)</sup>
- **Δημιουργία symlink/hardlink μεταξύ διαφορετικών επιπέδων προνομίων** — το κλασικό primitive «δημιούργησε έναν σύνδεσμο ως απλός χρήστης και στόχευσέ τον σε μια προνομιούχα τοποθεσία». Σημειώστε ότι **τα symlinks μπορούν να προκαλέσουν ειδοποίηση, αλλά δεν μπορούν να αποκλειστούν**: το EndpointSecurity δεν αποκαλύπτει τον προορισμό του συνδέσμου πριν από τη δημιουργία του.

### Κλήσεις από άλλες διεργασίες

Στο [**this blog post**](https://knight.sc/reverse%20engineering/2019/04/15/detecting-task-modifications.html) μπορείτε να βρείτε πώς είναι δυνατή η χρήση της συνάρτησης **`task_name_for_pid`** για τη λήψη πληροφοριών σχετικά με άλλες **διεργασίες που εισάγουν κώδικα σε μια διεργασία** και, στη συνέχεια, τη λήψη πληροφοριών για αυτή την άλλη διεργασία.<sup>[[4]](#references)</sup>

Σημειώστε ότι για να καλέσετε αυτή τη συνάρτηση πρέπει να έχετε **το ίδιο uid** με τον χρήστη που εκτελεί τη διεργασία ή να είστε **root** (και η συνάρτηση επιστρέφει πληροφορίες για τη διεργασία, όχι τρόπο εισαγωγής κώδικα).
