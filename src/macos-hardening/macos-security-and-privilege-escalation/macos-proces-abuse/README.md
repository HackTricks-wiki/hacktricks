## Βασικές πληροφορίες για τις διεργασίες

Μια διεργασία είναι ένα στιγμιότυπο ενός εκτελέσιμου αρχείου που εκτελείται. Ωστόσο, οι διεργασίες δεν εκτελούν κώδικα· αυτό το κάνουν τα threads. Επομένως, **οι διεργασίες είναι απλώς περιέκτες για την εκτέλεση threads**, οι οποίοι παρέχουν μνήμη, descriptors, ports, δικαιώματα...

Παραδοσιακά, οι διεργασίες ξεκινούσαν μέσα από άλλες διεργασίες (εκτός από το PID 1) καλώντας τη **`fork`**, η οποία δημιουργούσε ένα ακριβές αντίγραφο της τρέχουσας διεργασίας. Στη συνέχεια, η **child process** συνήθως καλούσε τη **`execve`** για να φορτώσει το νέο εκτελέσιμο αρχείο και να το εκτελέσει. Έπειτα, εισήχθη η **`vfork`** για να επιταχύνει αυτή τη διαδικασία χωρίς αντιγραφή μνήμης.\
Στη συνέχεια, εισήχθη η **`posix_spawn`**, συνδυάζοντας τις **`vfork`** και **`execve`** σε μία κλήση και δεχόμενη flags:

- `POSIX_SPAWN_RESETIDS`: Επαναφορά των effective ids στα πραγματικά ids
- `POSIX_SPAWN_SETPGROUP`: Ορισμός της ένταξης σε process group
- `POSUX_SPAWN_SETSIGDEF`: Ορισμός της προεπιλεγμένης συμπεριφοράς των signals
- `POSIX_SPAWN_SETSIGMASK`: Ορισμός της μάσκας signals
- `POSIX_SPAWN_SETEXEC`: Εκτέλεση στην ίδια διεργασία (όπως η `execve`, με περισσότερες επιλογές)
- `POSIX_SPAWN_START_SUSPENDED`: Εκκίνηση σε αναστολή
- `_POSIX_SPAWN_DISABLE_ASLR`: Εκκίνηση χωρίς ASLR
- `_POSIX_SPAWN_NANO_ALLOCATOR:` Χρήση του Nano allocator του libmalloc
- `_POSIX_SPAWN_ALLOW_DATA_EXEC:` Ενεργοποίηση `rwx` στα segments δεδομένων
- `POSIX_SPAWN_CLOEXEC_DEFAULT`: Κλείσιμο όλων των file descriptions κατά το exec(2) από προεπιλογή
- `_POSIX_SPAWN_HIGH_BITS_ASLR:` Τυχαιοποίηση των υψηλών bits του ASLR slide

Επιπλέον, η `posix_spawn` δέχεται ρυθμίσεις **`posix_spawnattr`** που ελέγχουν πτυχές της διεργασίας που δημιουργείται, καθώς και καταχωρίσεις **`posix_spawn_file_actions`** που τροποποιούν τα file descriptors.

Όταν μια διεργασία τερματίζεται, στέλνει τον **κωδικό επιστροφής στη γονική διεργασία** (αν η γονική διεργασία έχει τερματιστεί, η νέα γονική διεργασία είναι το PID 1) με το signal `SIGCHLD`. Η γονική διεργασία πρέπει να λάβει αυτή την τιμή καλώντας τη `wait4()` ή τη `waitid()`. Μέχρι να συμβεί αυτό, η child παραμένει σε κατάσταση zombie: εξακολουθεί να εμφανίζεται στη λίστα, αλλά δεν καταναλώνει πόρους.

### PIDs

Τα PIDs (process identifiers, αναγνωριστικά διεργασιών) προσδιορίζουν μία μοναδική διεργασία. Στο XNU, τα **PIDs** είναι **64-bit**, αυξάνονται μονοτονικά και **δεν κάνουν ποτέ επαναφορά** (για την αποτροπή καταχρήσεων).

### Process Groups, Sessions & Coalations

Οι **διεργασίες** μπορούν να ενταχθούν σε **groups** για να είναι ευκολότερη η διαχείρισή τους. Για παράδειγμα, οι εντολές σε ένα shell script ανήκουν στο ίδιο process group, ώστε να μπορούν να **λάβουν signal όλες μαζί**, για παράδειγμα μέσω του kill.\
Είναι επίσης δυνατό να **ομαδοποιηθούν διεργασίες σε sessions**. Όταν μια διεργασία ξεκινά μια session (`setsid(2)`), οι child processes εντάσσονται σε αυτήν, εκτός αν ξεκινήσουν δική τους session.

Το Coalition είναι ένας ακόμη τρόπος ομαδοποίησης διεργασιών στο Darwin. Μια διεργασία που εντάσσεται σε ένα coalition αποκτά πρόσβαση σε κοινούς πόρους, μοιράζεται ένα ledger ή υπόκειται σε Jetsam. Τα coalitions έχουν διαφορετικούς ρόλους: Leader, XPC service, Extension.

### Credentials & Personae

Κάθε διεργασία διατηρεί **credentials** που **προσδιορίζουν τα δικαιώματά της** στο σύστημα. Κάθε διεργασία έχει ένα κύριο `uid` και ένα κύριο `gid` (αν και μπορεί να ανήκει σε πολλές ομάδες).\
Είναι επίσης δυνατό να αλλάξουν τα user και group id αν το binary έχει το bit `setuid/setgid`.\
Υπάρχουν διάφορες συναρτήσεις για τον **ορισμό νέων uids/gids**.

Το syscall **`persona`** παρέχει ένα **εναλλακτικό** σύνολο **credentials**. Η υιοθέτηση μιας persona συνεπάγεται ταυτόχρονα τη χρήση του uid, του gid και των συμμετοχών της σε ομάδες. Στον [**πηγαίο κώδικα**](https://github.com/apple/darwin-xnu/blob/main/bsd/sys/persona.h) μπορείτε να βρείτε το struct:

```c
struct kpersona_info { uint32_t persona_info_version;
    uid_t    persona_id; /* overlaps with UID */
    int      persona_type;
    gid_t    persona_gid;
    uint32_t persona_ngroups;
    gid_t    persona_groups[NGROUPS];
    uid_t    persona_gmuid;
    char     persona_name[MAXLOGNAME + 1];

    /* TODO: MAC policies?! */
}
```

## Βασικές πληροφορίες για τα Threads

1. **POSIX Threads (pthreads):** Το macOS υποστηρίζει POSIX threads (`pthreads`), τα οποία αποτελούν μέρος ενός τυπικού API διαχείρισης threads για C/C++. Η υλοποίηση των pthreads στο macOS βρίσκεται στο `/usr/lib/system/libsystem_pthread.dylib` και προέρχεται από το δημόσια διαθέσιμο project `libpthread`. Αυτή η βιβλιοθήκη παρέχει τις απαραίτητες συναρτήσεις για τη δημιουργία και τη διαχείριση threads.
2. **Δημιουργία Threads:** Η συνάρτηση `pthread_create()` χρησιμοποιείται για τη δημιουργία νέων threads. Εσωτερικά, καλεί την `bsdthread_create()`, η οποία είναι μια κλήση συστήματος χαμηλότερου επιπέδου, ειδική για τον πυρήνα XNU (τον πυρήνα στον οποίο βασίζεται το macOS). Αυτή η κλήση συστήματος δέχεται διάφορες σημαίες που προκύπτουν από το `pthread_attr` (attributes) και καθορίζουν τη συμπεριφορά του thread, συμπεριλαμβανομένων των πολιτικών scheduling και του μεγέθους της στοίβας.
   - **Προεπιλεγμένο μέγεθος στοίβας:** Το προεπιλεγμένο μέγεθος στοίβας για νέα threads είναι 512 KB, το οποίο επαρκεί για τυπικές λειτουργίες, αλλά μπορεί να προσαρμοστεί μέσω των attributes του thread, αν χρειάζεται περισσότερος ή λιγότερος χώρος.
3. **Αρχικοποίηση Thread:** Η συνάρτηση `__pthread_init()` είναι κρίσιμη κατά τη ρύθμιση του thread και χρησιμοποιεί το όρισμα `env[]` για να αναλύσει μεταβλητές περιβάλλοντος, οι οποίες μπορεί να περιλαμβάνουν πληροφορίες για τη θέση και το μέγεθος της στοίβας.

#### Τερματισμός Thread στο macOS

1. **Έξοδος από Threads:** Τα threads συνήθως τερματίζονται με κλήση της `pthread_exit()`. Αυτή η συνάρτηση επιτρέπει σε ένα thread να τερματιστεί ομαλά, εκτελώντας τις απαραίτητες ενέργειες καθαρισμού και επιτρέποντάς του να επιστρέψει μια τιμή σε όσα threads αναμένουν την ολοκλήρωσή του.
2. **Καθαρισμός Thread:** Κατά την κλήση της `pthread_exit()`, καλείται η συνάρτηση `pthread_terminate()`, η οποία φροντίζει για την αφαίρεση όλων των σχετικών δομών του thread. Αποδεσμεύει τις θύρες thread Mach (το Mach είναι το υποσύστημα επικοινωνίας στον πυρήνα XNU) και καλεί την `bsdthread_terminate`, μια κλήση συστήματος που αφαιρεί τις δομές του πυρήνα που σχετίζονται με το thread.

#### Μηχανισμοί συγχρονισμού

Για τη διαχείριση της πρόσβασης σε κοινόχρηστους πόρους και την αποφυγή race conditions, το macOS παρέχει διάφορα primitives συγχρονισμού. Αυτά είναι κρίσιμα σε περιβάλλοντα με πολλαπλά threads, ώστε να διασφαλίζεται η ακεραιότητα των δεδομένων και η σταθερότητα του συστήματος:

1. **Mutexes:**
   - **Κανονικό Mutex (Signature: 0x4D555458):** Τυπικό mutex με αποτύπωμα μνήμης 60 bytes (56 bytes για το mutex και 4 bytes για την υπογραφή).
   - **Fast Mutex (Signature: 0x4d55545A):** Παρόμοιο με ένα κανονικό mutex, αλλά βελτιστοποιημένο για ταχύτερες λειτουργίες· έχει επίσης μέγεθος 60 bytes.
2. **Μεταβλητές συνθήκης:**
   - Χρησιμοποιούνται για την αναμονή συγκεκριμένων συνθηκών και έχουν μέγεθος 44 bytes (40 bytes συν μια υπογραφή 4 bytes).
   - **Attributes μεταβλητών συνθήκης (Signature: 0x434e4441):** Attributes ρύθμισης μεταβλητών συνθήκης, μεγέθους 12 bytes.
3. **Μεταβλητή Once (Signature: 0x4f4e4345):**
   - Διασφαλίζει ότι ένα τμήμα κώδικα αρχικοποίησης εκτελείται μόνο μία φορά. Έχει μέγεθος 12 bytes.
4. **Κλειδώματα ανάγνωσης-εγγραφής:**
   - Επιτρέπουν ταυτόχρονα πολλούς αναγνώστες ή έναν εγγραφέα, διευκολύνοντας την αποδοτική πρόσβαση σε κοινόχρηστα δεδομένα.
   - **Κλείδωμα ανάγνωσης-εγγραφής (Signature: 0x52574c4b):** Έχει μέγεθος 196 bytes.
   - **Attributes κλειδώματος ανάγνωσης-εγγραφής (Signature: 0x52574c41):** Attributes για κλειδώματα ανάγνωσης-εγγραφής, μεγέθους 20 bytes.

> [!TIP]
> Τα τελευταία 4 bytes αυτών των αντικειμένων χρησιμοποιούνται για τον εντοπισμό υπερχειλίσεων.

### Μεταβλητές τοπικές σε Thread (TLV)

Οι **μεταβλητές τοπικές σε Thread (TLV)** στο πλαίσιο των αρχείων Mach-O (η μορφή των εκτελέσιμων αρχείων στο macOS) χρησιμοποιούνται για να δηλώνουν μεταβλητές που είναι ξεχωριστές για **κάθε thread** σε μια εφαρμογή με πολλαπλά threads. Έτσι, κάθε thread έχει τη δική του ξεχωριστή παρουσία μιας μεταβλητής, κάτι που αποτρέπει τις συγκρούσεις και διατηρεί την ακεραιότητα των δεδομένων χωρίς να απαιτούνται ρητοί μηχανισμοί συγχρονισμού, όπως τα mutexes.

Στις γλώσσες C και σε σχετικές γλώσσες, μπορείτε να δηλώσετε μια μεταβλητή τοπική σε thread χρησιμοποιώντας τη λέξη-κλειδί **`__thread`**. Δείτε πώς λειτουργεί στο παράδειγμά σας:

```c
cCopy code__thread int tlv_var;

void main (int argc, char **argv){
    tlv_var = 10;
}
```

Αυτό το απόσπασμα ορίζει το `tlv_var` ως μεταβλητή τοπική σε κάθε thread. Κάθε thread που εκτελεί αυτόν τον κώδικα έχει τη δική του `tlv_var`, και οι αλλαγές που κάνει ένα thread στην `tlv_var` δεν επηρεάζουν την `tlv_var` κάποιου άλλου thread.

Στο δυαδικό αρχείο Mach-O, τα δεδομένα που σχετίζονται με τις τοπικές σε κάθε thread μεταβλητές οργανώνονται σε συγκεκριμένα sections:

- **`__DATA.__thread_vars`**: Αυτό το section περιέχει τα μεταδεδομένα των τοπικών σε κάθε thread μεταβλητών, όπως τους τύπους τους και την κατάσταση αρχικοποίησής τους.
- **`__DATA.__thread_bss`**: Αυτό το section χρησιμοποιείται για τοπικές σε κάθε thread μεταβλητές που δεν έχουν αρχικοποιηθεί ρητά. Είναι ένα τμήμα μνήμης που προορίζεται για δεδομένα αρχικοποιημένα με μηδενικά.

Το Mach-O παρέχει επίσης ένα ειδικό API, το **`tlv_atexit`**, για τη διαχείριση των τοπικών σε κάθε thread μεταβλητών κατά τον τερματισμό ενός thread. Αυτό το API επιτρέπει την **καταχώριση destructors** — ειδικών συναρτήσεων που καθαρίζουν τα δεδομένα του thread όταν αυτό τερματίζεται.

### Προτεραιότητες Thread

Για να κατανοήσουμε τις προτεραιότητες των thread, πρέπει να εξετάσουμε πώς το λειτουργικό σύστημα αποφασίζει ποια thread θα εκτελέσει και πότε. Η απόφαση αυτή επηρεάζεται από το επίπεδο προτεραιότητας που έχει εκχωρηθεί σε κάθε thread. Σε macOS και συστήματα τύπου Unix, η διαχείριση γίνεται με έννοιες όπως οι `nice`, `renice` και οι κλάσεις Quality of Service (QoS).

#### Nice και Renice

1. **Nice:**
   - Η τιμή `nice` μιας διεργασίας είναι ένας αριθμός που επηρεάζει την προτεραιότητά της. Κάθε διεργασία έχει τιμή nice από -20 (η υψηλότερη προτεραιότητα) έως 19 (η χαμηλότερη προτεραιότητα). Η προεπιλεγμένη τιμή nice κατά τη δημιουργία μιας διεργασίας είναι συνήθως 0.
   - Μια χαμηλότερη τιμή nice (πιο κοντά στο -20) κάνει τη διεργασία πιο «εγωιστική», δίνοντάς της περισσότερο χρόνο CPU σε σύγκριση με διεργασίες που έχουν υψηλότερες τιμές nice.
2. **Renice:**
   - Το `renice` είναι εντολή που χρησιμοποιείται για να αλλάξει την τιμή nice μιας διεργασίας που εκτελείται ήδη. Μπορεί να χρησιμοποιηθεί για τη δυναμική προσαρμογή της προτεραιότητας των διεργασιών, αυξάνοντας ή μειώνοντας τον χρόνο CPU που τους αναλογεί, ανάλογα με τις νέες τιμές nice.
   - Για παράδειγμα, αν μια διεργασία χρειάζεται προσωρινά περισσότερους πόρους CPU, μπορείτε να μειώσετε την τιμή nice χρησιμοποιώντας το `renice`.

#### Κλάσεις Quality of Service (QoS)

Οι κλάσεις QoS είναι μια πιο σύγχρονη προσέγγιση στη διαχείριση των προτεραιοτήτων των thread, ιδιαίτερα σε συστήματα όπως το macOS που υποστηρίζουν το **Grand Central Dispatch (GCD)**. Οι κλάσεις QoS επιτρέπουν στους developers να **κατηγοριοποιούν** τις εργασίες σε διαφορετικά επίπεδα, με βάση τη σημασία ή τον επείγοντα χαρακτήρα τους. Το macOS διαχειρίζεται αυτόματα την προτεραιοποίηση των thread με βάση αυτές τις κλάσεις QoS:

1. **User Interactive:**
   - Αυτή η κλάση προορίζεται για εργασίες που αλληλεπιδρούν εκείνη τη στιγμή με τον χρήστη ή απαιτούν άμεσα αποτελέσματα, ώστε να προσφέρουν καλή εμπειρία χρήσης. Σε αυτές τις εργασίες δίνεται η υψηλότερη προτεραιότητα, για να παραμένει η διεπαφή αποκρίσιμη (π.χ. animations ή διαχείριση συμβάντων).
2. **User Initiated:**
   - Εργασίες που ξεκινά ο χρήστης και για τις οποίες αναμένει άμεσα αποτελέσματα, όπως το άνοιγμα ενός εγγράφου ή το πάτημα ενός κουμπιού που απαιτεί υπολογισμούς. Έχουν υψηλή προτεραιότητα, αλλά χαμηλότερη από τις εργασίες User Interactive.
3. **Utility:**
   - Αυτές οι εργασίες διαρκούν πολύ και συνήθως εμφανίζουν ένδειξη προόδου (π.χ. λήψη αρχείων ή εισαγωγή δεδομένων). Έχουν χαμηλότερη προτεραιότητα από τις εργασίες User Initiated και δεν χρειάζεται να ολοκληρωθούν αμέσως.
4. **Background:**
   - Αυτή η κλάση προορίζεται για εργασίες που εκτελούνται στο παρασκήνιο και δεν είναι ορατές στον χρήστη. Μπορεί να περιλαμβάνουν εργασίες όπως ευρετηρίαση, συγχρονισμό ή δημιουργία αντιγράφων ασφαλείας. Έχουν τη χαμηλότερη προτεραιότητα και ελάχιστη επίδραση στην απόδοση του συστήματος.

Χρησιμοποιώντας τις κλάσεις QoS, οι developers δεν χρειάζεται να διαχειρίζονται συγκεκριμένους αριθμούς προτεραιότητας, αλλά μπορούν να εστιάζουν στη φύση της εργασίας. Το σύστημα βελτιστοποιεί αντίστοιχα τους πόρους CPU.

Επιπλέον, υπάρχουν διαφορετικές **πολιτικές χρονοδρομολόγησης thread**, οι οποίες επιτρέπουν τον καθορισμό ενός συνόλου παραμέτρων χρονοδρομολόγησης που θα λαμβάνει υπόψη ο scheduler. Αυτό μπορεί να γίνει με το `thread_policy_[set/get]`. Μπορεί να είναι χρήσιμο σε επιθέσεις race condition.

## Κατάχρηση διεργασιών macOS

Το macOS παρέχει πολλούς μηχανισμούς για **αλληλεπίδραση, επικοινωνία και κοινή χρήση δεδομένων μεταξύ διεργασιών**. Παρόλο που αυτοί οι μηχανισμοί είναι απαραίτητοι για την κανονική λειτουργία του συστήματος, οι επιτιθέμενοι μπορούν να τους καταχραστούν για injection, εκτέλεση κώδικα ή πρόσβαση σε δεδομένα.

### Library Injection

Το Library Injection είναι τεχνική κατά την οποία ένας επιτιθέμενος **αναγκάζει μια διεργασία να φορτώσει μια κακόβουλη βιβλιοθήκη**. Μόλις γίνει injection, η βιβλιοθήκη εκτελείται στο πλαίσιο της διεργασίας-στόχου, παρέχοντας στον επιτιθέμενο τα ίδια δικαιώματα και την ίδια πρόσβαση με τη διεργασία.

Με το hooking συναρτήσεων, ένας επιτιθέμενος μπορεί να **αλλάξει τη συμπεριφορά** μιας διεργασίας, να παρατηρήσει ευαίσθητα δεδομένα ή ακόμη και να αποκτήσει τον έλεγχο της ροής εκτέλεσης.

Παρόλο που το IPC είναι θεμελιώδες για πολλές νόμιμες εφαρμογές, μπορεί επίσης να χρησιμοποιηθεί καταχρηστικά για την υπονόμευση της απομόνωσης διεργασιών, τη διαρροή ευαίσθητων πληροφοριών ή την εκτέλεση μη εξουσιοδοτημένων ενεργειών.

### Dirty NIB

Τα αρχεία NIB **ορίζουν στοιχεία διεπαφής χρήστη (UI)** και τις αλληλεπιδράσεις τους μέσα σε μια εφαρμογή. Ωστόσο, μπορούν να **εκτελέσουν αυθαίρετες εντολές**, ενώ το **Gatekeeper δεν εμποδίζει** την εκτέλεση μιας εφαρμογής που έχει ήδη εκτελεστεί, αν **τροποποιηθεί ένα αρχείο NIB**. Επομένως, μπορούν να χρησιμοποιηθούν ώστε αυθαίρετα προγράμματα να εκτελούν αυθαίρετες εντολές:


{{#ref}}
macos-dirty-nib.md
{{#endref}}

### Shell Injection

Το μη διαδραστικό Bash διαβάζει το **`BASH_ENV`**· τα διαδραστικά POSIX shells διαβάζουν το **`ENV`**· το zsh διαβάζει το **`$ZDOTDIR/.zshenv`**· και το fish διαβάζει ρυθμίσεις από το **`XDG_CONFIG_HOME`** ή το **`XDG_DATA_DIRS`**. Καθένα από αυτά μπορεί να εκτελέσει ένα ελεγχόμενο αρχείο εκκίνησης πριν από την προβλεπόμενη εντολή. Το Bash εκτελεί επίσης μια command substitution που έχει τοποθετηθεί στο **`PS4`** κάθε φορά που είναι ενεργοποιημένο το xtrace (π.χ. μέσω του κληρονομημένου **`SHELLOPTS=xtrace`**):

{{#ref}}

{{#endref}}

### Shell stdin command smuggling

Η εκκίνηση του `/bin/zsh -s` κάνει το shell να διαβάσει ένα πρόγραμμα από το standard input. Επομένως, ένας downloader που αντιγράφει ένα μη έμπιστο δομημένο έγγραφο στο stdin της θυγατρικής διεργασίας χωρίς να το αναλύσει πρώτα, μετατρέπει ολόκληρο το έγγραφο σε κώδικα shell. Ένας loader που παρατηρήθηκε διοχέτευε γραμμή προς γραμμή ένα δημόσιο αρχείο iCalendar μέσω ανώνυμου pipe. Τα metadata ημερολογίου αποτύγχαναν ως εντολές, αλλά το zsh συνέχιζε μέχρι να συναντήσει εκτελέσιμες γραμμές μετά το `DESCRIPTION:`. Αυτές οι γραμμές κατέβαζαν και εκκινούσαν το επόμενο application bundle. Ο αναμενόμενος τύπος περιεχομένου και η αξιόπιστη φιλοξενία του αρχείου δεν το καθιστούσαν ασφαλές· το επικίνδυνο όριο ήταν η παράδοση των bytes του σε έναν interpreter.<sup>[[5]](#references)</sup>

Σχετικά στάδια καλύπτονται στα [Mach-O overlays](../macos-files-folders-and-binaries/universal-binaries-and-mach-o-format.md), [Gatekeeper and quarantine](../macos-security-protections/macos-gatekeeper.md) και [macOS auto-start locations](../../macos-auto-start-locations.md).

### Python Injection

Η αλυσίδα της standard library **`PYTHONWARNINGS`** και **`BROWSER`** μπορεί να εκτελέσει μια εντολή κατά την ανάλυση των φίλτρων προειδοποιήσεων. Μια εναλλακτική που βασίζεται σε αρχείο τοποθετεί το `sitecustomize.py` στο **`PYTHONPATH`**, ώστε η κανονική αρχικοποίηση του `site` να το εισαγάγει πριν από το script-στόχο. Το **`PYTHONBREAKPOINT`** εκτελεί ένα επιλεγμένο callable/module όταν ο κώδικας φτάσει στο `breakpoint()`. Μεταβλητές που αφορούν μόνο τη διαδραστική λειτουργία, όπως το **`PYTHONSTARTUP`**, έχουν πιο περιορισμένη εφαρμογή.

Σημειώστε ότι τα εκτελέσιμα αρχεία που έχουν μεταγλωττιστεί με το **`pyinstaller`** δεν χρησιμοποιούν αυτές τις μεταβλητές περιβάλλοντος, ακόμη κι αν εκτελούνται με ενσωματωμένη Python.

{{#endref}}

{{#ref}}

Ξεχωριστά, το Homebrew εγκαθιστά συχνά την Python κάτω από το `/opt/homebrew`, όπου μέλη της τοπικής ομάδας `admin` ενδέχεται να μπορούν να αντικαταστήσουν τον launcher. Αυτό αποτελεί hijack εγγράψιμου δυαδικού αρχείου και όχι injection μέσω μεταβλητής περιβάλλοντος· επαληθεύστε τον ιδιοκτήτη και τα ACL πριν το θεωρήσετε εκμεταλλεύσιμο.


## Ανίχνευση

### Shield

Το [**Shield**](https://github.com/theevilbit/Shield) είναι μια εφαρμογή ανοιχτού κώδικα που βασίζεται στο **EndpointSecurity** και ανιχνεύει και αποκλείει το process injection. Αποτελεί καλή αναφορά για τα σήματα που είναι ορατά μέσω του Endpoint Security, καθώς ειδοποιεί για:<sup>[[1]](#references)</sup><sup>[[2]](#references)</sup>

- **Μεταβλητές περιβάλλοντος injection** κατά το process exec: `DYLD_INSERT_LIBRARIES`, `CFNETWORK_LIBRARY_PATH`, `RAWCAMERA_BUNDLE_PATH` και `ELECTRON_RUN_AS_NODE`.
- Κλήσεις **`task_for_pid`** — όταν μια διεργασία ζητά το task port μιας άλλης διεργασίας, κάτι που αποτελεί προϋπόθεση για injection σε αυτήν.
- **Ορίσματα debugging του Electron** — `--inspect`, `--inspect-brk` και `--remote-debugging-port`, τα οποία εκκινούν μια εφαρμογή Electron σε λειτουργία debug και επιτρέπουν σε οποιονδήποτε να συνδεθεί και να εκτελέσει κώδικα σε αυτήν.<sup>[[3]](#references)</sup>
- **Δημιουργία symlink/hardlink μεταξύ διαφορετικών επιπέδων προνομίων** — το κλασικό primitive «δημιούργησε έναν σύνδεσμο ως κανονικός χρήστης και δείξ’ τον σε μια προνομιούχα τοποθεσία». Σημειώστε ότι **οι symlinks μπορούν να προκαλέσουν ειδοποίηση, αλλά δεν μπορούν να αποκλειστούν**: το EndpointSecurity δεν αποκαλύπτει τον προορισμό του συνδέσμου πριν από τη δημιουργία του.

### Κλήσεις από άλλες διεργασίες

Σε [**αυτήν την ανάρτηση ιστολογίου**](https://knight.sc/reverse%20engineering/2019/04/15/detecting-task-modifications.html) μπορείτε να μάθετε πώς είναι δυνατό να χρησιμοποιηθεί η συνάρτηση **`task_name_for_pid`** για να ληφθούν πληροφορίες σχετικά με άλλες **διεργασίες που κάνουν injection κώδικα σε μια διεργασία** και στη συνέχεια να αντληθούν πληροφορίες για εκείνη τη διεργασία.<sup>[[4]](#references)</sup>

Σημειώστε ότι για να καλέσετε αυτήν τη συνάρτηση πρέπει να είστε **ο ίδιος uid** με τον χρήστη που εκτελεί τη διεργασία ή **root** (και επιστρέφει πληροφορίες για τη διεργασία, όχι τρόπο για injection κώδικα).
