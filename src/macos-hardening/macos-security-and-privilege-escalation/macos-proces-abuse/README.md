## Βασικές πληροφορίες για τις διεργασίες

Μια διεργασία είναι ένα στιγμιότυπο ενός εκτελέσιμου αρχείου που εκτελείται. Ωστόσο, οι διεργασίες δεν εκτελούν κώδικα· αυτό το κάνουν τα νήματα. Επομένως, **οι διεργασίες είναι απλώς κοντέινερ για νήματα που εκτελούνται**, τα οποία παρέχουν μνήμη, περιγραφείς, θύρες, δικαιώματα...

Παραδοσιακά, οι διεργασίες ξεκινούσαν μέσα από άλλες διεργασίες (εκτός από την PID 1) με την κλήση της **`fork`**, η οποία δημιουργούσε ένα ακριβές αντίγραφο της τρέχουσας διεργασίας. Στη συνέχεια, η **θυγατρική διεργασία** συνήθως καλούσε την **`execve`** για να φορτώσει το νέο εκτελέσιμο αρχείο και να το εκτελέσει. Έπειτα, εισήχθη η **`vfork`** για να επιταχύνει αυτή τη διαδικασία χωρίς αντιγραφή μνήμης.\
Στη συνέχεια, εισήχθη η **`posix_spawn`**, η οποία συνδύασε τις **`vfork`** και **`execve`** σε μία κλήση και δέχεται flags:

- `POSIX_SPAWN_RESETIDS`: Επαναφορά των effective ids στα real ids
- `POSIX_SPAWN_SETPGROUP`: Ορισμός της συμμετοχής σε ομάδα διεργασιών
- `POSUX_SPAWN_SETSIGDEF`: Ορισμός της προεπιλεγμένης συμπεριφοράς των σημάτων
- `POSIX_SPAWN_SETSIGMASK`: Ορισμός της μάσκας σημάτων
- `POSIX_SPAWN_SETEXEC`: Εκτέλεση στην ίδια διεργασία (όπως η `execve`, με περισσότερες επιλογές)
- `POSIX_SPAWN_START_SUSPENDED`: Εκκίνηση σε αναστολή
- `_POSIX_SPAWN_DISABLE_ASLR`: Εκκίνηση χωρίς ASLR
- `_POSIX_SPAWN_NANO_ALLOCATOR:` Χρήση του Nano allocator της libmalloc
- `_POSIX_SPAWN_ALLOW_DATA_EXEC:` Επιτρέπει `rwx` στα τμήματα δεδομένων
- `POSIX_SPAWN_CLOEXEC_DEFAULT`: Κλείσιμο όλων των περιγραφών αρχείων κατά την exec(2), από προεπιλογή
- `_POSIX_SPAWN_HIGH_BITS_ASLR:` Τυχαιοποίηση των υψηλών bits της μετατόπισης ASLR

Επιπλέον, η `posix_spawn` δέχεται ρυθμίσεις **`posix_spawnattr`** που ελέγχουν πτυχές της διεργασίας που δημιουργείται, καθώς και εγγραφές **`posix_spawn_file_actions`** που τροποποιούν τους περιγραφείς αρχείων.

Όταν μια διεργασία τερματίζεται, στέλνει τον **κωδικό επιστροφής στη γονική διεργασία** (αν η γονική διεργασία έχει τερματιστεί, νέος γονέας γίνεται η PID 1) με το σήμα `SIGCHLD`. Η γονική διεργασία πρέπει να λάβει αυτή την τιμή καλώντας την `wait4()` ή την `waitid()`. Μέχρι να συμβεί αυτό, η θυγατρική διεργασία παραμένει σε κατάσταση zombie, όπου εξακολουθεί να εμφανίζεται στη λίστα αλλά δεν καταναλώνει πόρους.

### PIDs

Τα PIDs, δηλαδή τα αναγνωριστικά διεργασιών, προσδιορίζουν μια μοναδική διεργασία. Στο XNU, τα **PIDs** έχουν μέγεθος **64 bits**, αυξάνονται μονοτονικά και **δεν επανεκκινούν ποτέ από την αρχή** (για την αποτροπή καταχρήσεων).

### Ομάδες διεργασιών, συνεδρίες και Coalitions

Οι **διεργασίες** μπορούν να εντάσσονται σε **ομάδες**, ώστε να είναι ευκολότερη η διαχείρισή τους. Για παράδειγμα, οι εντολές σε ένα shell script ανήκουν στην ίδια ομάδα διεργασιών, ώστε να είναι δυνατή η **αποστολή σήματος σε όλες μαζί**, για παράδειγμα με την εντολή kill.\
Είναι επίσης δυνατή η **ομαδοποίηση διεργασιών σε συνεδρίες**. Όταν μια διεργασία ξεκινά μια συνεδρία (`setsid(2)`), οι θυγατρικές διεργασίες εντάσσονται σε αυτήν, εκτός αν ξεκινήσουν τη δική τους συνεδρία.

Η Coalition είναι ένας ακόμη τρόπος ομαδοποίησης διεργασιών στο Darwin. Μια διεργασία που συμμετέχει σε μια Coalition μπορεί να έχει πρόσβαση σε πόρους pool, να μοιράζεται ένα ledger ή να υπόκειται σε Jetsam. Οι Coalitions έχουν διαφορετικούς ρόλους: Leader, XPC service, Extension.

### Διαπιστευτήρια και Personae

Κάθε διεργασία διατηρεί **διαπιστευτήρια** που **προσδιορίζουν τα δικαιώματά της** στο σύστημα. Κάθε διεργασία έχει ένα κύριο `uid` και ένα κύριο `gid` (αν και μπορεί να ανήκει σε πολλές ομάδες).\
Είναι επίσης δυνατή η αλλαγή του user ID και του group ID, αν το binary έχει το bit `setuid/setgid`.\
Υπάρχουν διάφορες συναρτήσεις για τον **ορισμό νέων uids/gids**.

Το syscall **`persona`** παρέχει ένα **εναλλακτικό** σύνολο **διαπιστευτηρίων**. Η υιοθέτηση μιας persona σημαίνει ταυτόχρονη ανάληψη του uid, του gid και των συμμετοχών σε ομάδες της. Στον [**πηγαίο κώδικα**](https://github.com/apple/darwin-xnu/blob/main/bsd/sys/persona.h) μπορείτε να βρείτε το struct:

```c
struct kpersona_info { uint32_t persona_info_version;
    uid_t    persona_id; /* overlaps with UID */
    int      persona_type;
    gid_t    persona_gid;
    uint32_t persona_ngroups;
    gid_t    persona_groups[NGROUPS];
    uid_t    persona_gmuid;
    char     persona_name[MAXLOGNAME + 1];

    /* TODO: MAC policies?! */
}
```

## Βασικές πληροφορίες για τα Threads

1. **POSIX Threads (pthreads):** Το macOS υποστηρίζει POSIX threads (`pthreads`), τα οποία αποτελούν μέρος ενός τυπικού API για threads σε C/C++. Η υλοποίηση των pthreads στο macOS βρίσκεται στο `/usr/lib/system/libsystem_pthread.dylib` και προέρχεται από το δημόσια διαθέσιμο project `libpthread`. Αυτή η βιβλιοθήκη παρέχει τις απαραίτητες συναρτήσεις για τη δημιουργία και τη διαχείριση threads.
2. **Δημιουργία Threads:** Η συνάρτηση `pthread_create()` χρησιμοποιείται για τη δημιουργία νέων threads. Εσωτερικά, αυτή η συνάρτηση καλεί την `bsdthread_create()`, μια κλήση συστήματος χαμηλότερου επιπέδου, συγκεκριμένη για τον πυρήνα XNU (τον πυρήνα στον οποίο βασίζεται το macOS). Αυτή η κλήση συστήματος δέχεται διάφορες σημαίες που προκύπτουν από το `pthread_attr` (attributes) και καθορίζουν τη συμπεριφορά των threads, όπως τις πολιτικές scheduling και το μέγεθος της στοίβας.
   - **Προεπιλεγμένο μέγεθος στοίβας:** Το προεπιλεγμένο μέγεθος στοίβας για νέα threads είναι 512 KB, ποσότητα επαρκής για τυπικές λειτουργίες, η οποία μπορεί να προσαρμοστεί μέσω των attributes των threads, αν χρειάζεται περισσότερος ή λιγότερος χώρος.
3. **Αρχικοποίηση Thread:** Η συνάρτηση `__pthread_init()` είναι κρίσιμη κατά τη ρύθμιση ενός thread, καθώς χρησιμοποιεί το όρισμα `env[]` για την ανάλυση μεταβλητών περιβάλλοντος, οι οποίες μπορούν να περιλαμβάνουν πληροφορίες σχετικά με τη θέση και το μέγεθος της στοίβας.

#### Τερματισμός Thread στο macOS

1. **Έξοδος από Threads:** Τα threads συνήθως τερματίζονται με την κλήση της `pthread_exit()`. Αυτή η συνάρτηση επιτρέπει σε ένα thread να τερματιστεί κανονικά, εκτελώντας τον απαραίτητο καθαρισμό και επιτρέποντάς του να επιστρέψει μια τιμή σε όσα threads κάνουν join.
2. **Καθαρισμός Thread:** Κατά την κλήση της `pthread_exit()`, καλείται η συνάρτηση `pthread_terminate()`, η οποία αναλαμβάνει την αφαίρεση όλων των σχετικών δομών του thread. Αποδεσμεύει τις θύρες threads του Mach (το Mach είναι το υποσύστημα επικοινωνίας στον πυρήνα XNU) και καλεί την `bsdthread_terminate`, μια κλήση συστήματος που αφαιρεί τις δομές του πυρήνα οι οποίες σχετίζονται με το thread.

#### Μηχανισμοί Συγχρονισμού

Για τη διαχείριση της πρόσβασης σε κοινόχρηστους πόρους και την αποφυγή race conditions, το macOS παρέχει διάφορα primitives συγχρονισμού. Είναι απαραίτητα σε περιβάλλοντα πολλαπλών threads, ώστε να διασφαλίζονται η ακεραιότητα των δεδομένων και η σταθερότητα του συστήματος:

1. **Mutexes:**
   - **Κανονικό Mutex (Signature: 0x4D555458):** Τυπικό mutex με αποτύπωμα μνήμης 60 bytes (56 bytes για το mutex και 4 bytes για το signature).
   - **Fast Mutex (Signature: 0x4d55545A):** Παρόμοιο με το κανονικό mutex, αλλά βελτιστοποιημένο για ταχύτερες λειτουργίες, επίσης μεγέθους 60 bytes.
2. **Condition Variables:**
   - Χρησιμοποιούνται για την αναμονή μέχρι να ισχύσουν ορισμένες συνθήκες και έχουν μέγεθος 44 bytes (40 bytes συν ένα signature 4 bytes).
   - **Attributes Condition Variable (Signature: 0x434e4441):** Attributes ρύθμισης για condition variables, μεγέθους 12 bytes.
3. **Once Variable (Signature: 0x4f4e4345):**
   - Διασφαλίζει ότι ένα τμήμα κώδικα αρχικοποίησης εκτελείται μόνο μία φορά. Έχει μέγεθος 12 bytes.
4. **Read-Write Locks:**
   - Επιτρέπουν την ταυτόχρονη πρόσβαση σε πολλούς readers ή σε έναν writer κάθε φορά, διευκολύνοντας την αποδοτική πρόσβαση σε κοινόχρηστα δεδομένα.
   - **Read Write Lock (Signature: 0x52574c4b):** Έχει μέγεθος 196 bytes.
   - **Read Write Lock Attributes (Signature: 0x52574c41):** Attributes για read-write locks, μεγέθους 20 bytes.

> [!TIP]
> Τα τελευταία 4 bytes αυτών των αντικειμένων χρησιμοποιούνται για τον εντοπισμό υπερχειλίσεων.

### Thread Local Variables (TLV)

Οι **Thread Local Variables (TLV)** στο πλαίσιο αρχείων Mach-O (η μορφή εκτελέσιμων αρχείων στο macOS) χρησιμοποιούνται για τη δήλωση μεταβλητών που είναι ειδικές για **κάθε thread** σε μια εφαρμογή πολλαπλών threads. Έτσι, κάθε thread έχει τη δική του ξεχωριστή παρουσία μιας μεταβλητής, αποφεύγονται οι διενέξεις και διατηρείται η ακεραιότητα των δεδομένων χωρίς να απαιτούνται ρητοί μηχανισμοί συγχρονισμού, όπως τα mutexes.

Στη C και σε σχετικές γλώσσες, μπορείτε να δηλώσετε μια thread-local μεταβλητή χρησιμοποιώντας τη λέξη-κλειδί **`__thread`**. Δείτε πώς λειτουργεί στο παράδειγμά σας:

```c
cCopy code__thread int tlv_var;

void main (int argc, char **argv){
    tlv_var = 10;
}
```

Αυτό το απόσπασμα ορίζει το `tlv_var` ως μεταβλητή τοπική στο νήμα. Κάθε νήμα που εκτελεί αυτόν τον κώδικα θα έχει το δικό του `tlv_var`, και οι αλλαγές που κάνει ένα νήμα στο `tlv_var` δεν θα επηρεάζουν το `tlv_var` κάποιου άλλου νήματος.

Στο δυαδικό αρχείο Mach-O, τα δεδομένα που σχετίζονται με τις μεταβλητές τοπικές στο νήμα οργανώνονται σε συγκεκριμένες ενότητες:

- **`__DATA.__thread_vars`**: Αυτή η ενότητα περιέχει μεταδεδομένα για τις μεταβλητές τοπικές στο νήμα, όπως τους τύπους και την κατάσταση αρχικοποίησής τους.
- **`__DATA.__thread_bss`**: Αυτή η ενότητα χρησιμοποιείται για μεταβλητές τοπικές στο νήμα που δεν αρχικοποιούνται ρητά. Αποτελεί τμήμα μνήμης που προορίζεται για δεδομένα αρχικοποιημένα με μηδενικά.

Το Mach-O παρέχει επίσης ένα ειδικό API με το όνομα **`tlv_atexit`** για τη διαχείριση των μεταβλητών τοπικών στο νήμα κατά τον τερματισμό ενός νήματος. Αυτό το API επιτρέπει την **καταχώριση destructors** — ειδικών συναρτήσεων που καθαρίζουν τα δεδομένα τοπικά στο νήμα όταν αυτό τερματιστεί.

### Προτεραιότητες νημάτων

Για να κατανοήσουμε τις προτεραιότητες των νημάτων, πρέπει να εξετάσουμε πώς το λειτουργικό σύστημα αποφασίζει ποια νήματα θα εκτελεστούν και πότε. Η απόφαση αυτή επηρεάζεται από το επίπεδο προτεραιότητας που έχει εκχωρηθεί σε κάθε νήμα. Στο macOS και σε συστήματα τύπου Unix, αυτό γίνεται με έννοιες όπως `nice`, `renice` και οι κλάσεις Quality of Service (QoS).

#### Nice και Renice

1. **Nice:**
   - Η τιμή `nice` μιας διεργασίας είναι ένας αριθμός που επηρεάζει την προτεραιότητά της. Κάθε διεργασία έχει τιμή `nice` από -20 (η υψηλότερη προτεραιότητα) έως 19 (η χαμηλότερη προτεραιότητα). Η προεπιλεγμένη τιμή `nice` κατά τη δημιουργία μιας διεργασίας είναι συνήθως 0.
   - Μια χαμηλότερη τιμή `nice` (πιο κοντά στο -20) κάνει μια διεργασία πιο «εγωιστική», δίνοντάς της περισσότερο χρόνο CPU σε σύγκριση με άλλες διεργασίες που έχουν υψηλότερες τιμές `nice`.
2. **Renice:**
   - Το `renice` είναι εντολή που χρησιμοποιείται για την αλλαγή της τιμής `nice` μιας διεργασίας που εκτελείται ήδη. Μπορεί να χρησιμοποιηθεί για δυναμική προσαρμογή της προτεραιότητας των διεργασιών, αυξάνοντας ή μειώνοντας τον χρόνο CPU που τους διατίθεται με βάση τις νέες τιμές `nice`.
   - Για παράδειγμα, αν μια διεργασία χρειάζεται προσωρινά περισσότερους πόρους CPU, μπορείτε να μειώσετε την τιμή `nice` της χρησιμοποιώντας το `renice`.

#### Κλάσεις Quality of Service (QoS)

Οι κλάσεις QoS είναι μια πιο σύγχρονη προσέγγιση στη διαχείριση των προτεραιοτήτων νημάτων, ιδιαίτερα σε συστήματα όπως το macOS που υποστηρίζουν το **Grand Central Dispatch (GCD)**. Οι κλάσεις QoS επιτρέπουν στους προγραμματιστές να **κατηγοριοποιούν** τις εργασίες σε διαφορετικά επίπεδα με βάση τη σημασία ή τον επείγοντα χαρακτήρα τους. Το macOS διαχειρίζεται αυτόματα την ιεράρχηση των νημάτων με βάση αυτές τις κλάσεις QoS:

1. **User Interactive:**
   - Αυτή η κλάση αφορά εργασίες που αλληλεπιδρούν εκείνη τη στιγμή με τον χρήστη ή απαιτούν άμεσα αποτελέσματα για καλή εμπειρία χρήσης. Αυτές οι εργασίες έχουν την υψηλότερη προτεραιότητα, ώστε η διεπαφή να παραμένει αποκρίσιμη (π.χ. κινούμενα γραφικά ή διαχείριση συμβάντων).
2. **User Initiated:**
   - Εργασίες που ξεκινά ο χρήστης και για τις οποίες αναμένει άμεσα αποτελέσματα, όπως το άνοιγμα ενός εγγράφου ή το πάτημα ενός κουμπιού που απαιτεί υπολογισμούς. Έχουν υψηλή προτεραιότητα, αλλά χαμηλότερη από την User Interactive.
3. **Utility:**
   - Αυτές οι εργασίες διαρκούν πολύ και συνήθως εμφανίζουν ένδειξη προόδου (π.χ. λήψη αρχείων, εισαγωγή δεδομένων). Έχουν χαμηλότερη προτεραιότητα από τις εργασίες που ξεκίνησε ο χρήστης και δεν χρειάζεται να ολοκληρωθούν αμέσως.
4. **Background:**
   - Αυτή η κλάση αφορά εργασίες που εκτελούνται στο παρασκήνιο και δεν είναι ορατές στον χρήστη. Παραδείγματα είναι η δημιουργία ευρετηρίου, ο συγχρονισμός ή τα αντίγραφα ασφαλείας. Έχουν τη χαμηλότερη προτεραιότητα και ελάχιστη επίδραση στην απόδοση του συστήματος.

Χρησιμοποιώντας τις κλάσεις QoS, οι προγραμματιστές δεν χρειάζεται να διαχειρίζονται συγκεκριμένους αριθμούς προτεραιότητας, αλλά μπορούν να επικεντρωθούν στη φύση της εργασίας, ενώ το σύστημα βελτιστοποιεί ανάλογα τους πόρους CPU.

Επιπλέον, υπάρχουν διαφορετικές **πολιτικές χρονοπρογραμματισμού νημάτων** που καθορίζουν ένα σύνολο παραμέτρων χρονοπρογραμματισμού τις οποίες θα λαμβάνει υπόψη ο χρονοπρογραμματιστής. Αυτό μπορεί να γίνει με το `thread_policy_[set/get]`. Μπορεί να φανεί χρήσιμο σε επιθέσεις με συνθήκες ανταγωνισμού.

## Κατάχρηση διεργασιών macOS

Το macOS παρέχει πολλούς μηχανισμούς για **την αλληλεπίδραση, την επικοινωνία και την κοινή χρήση δεδομένων μεταξύ διεργασιών**. Παρόλο που αυτοί οι μηχανισμοί είναι απαραίτητοι για την κανονική λειτουργία του συστήματος, οι επιτιθέμενοι μπορούν να τους καταχραστούν για injection, εκτέλεση κώδικα ή πρόσβαση σε δεδομένα.

Η Library Injection είναι μια τεχνική κατά την οποία ένας επιτιθέμενος **αναγκάζει μια διεργασία να φορτώσει μια κακόβουλη βιβλιοθήκη**. Μετά την εισαγωγή της, η βιβλιοθήκη εκτελείται στο πλαίσιο της διεργασίας-στόχου, παρέχοντας στον επιτιθέμενο τα ίδια δικαιώματα και την ίδια πρόσβαση με τη διεργασία.

Τα αρχεία NIB **ορίζουν στοιχεία διεπαφής χρήστη (UI)** και τις αλληλεπιδράσεις τους μέσα σε μια εφαρμογή. Ωστόσο, μπορούν να **εκτελέσουν αυθαίρετες εντολές**, ενώ το **Gatekeeper δεν εμποδίζει** την εκ νέου εκτέλεση μιας εφαρμογής που έχει ήδη εκτελεστεί, αν **τροποποιηθεί ένα αρχείο NIB**. Επομένως, μπορούν να χρησιμοποιηθούν ώστε αυθαίρετα προγράμματα να εκτελούν αυθαίρετες εντολές:

### Shell Injection

Το Bash εκτελεί επίσης μια αντικατάσταση εντολής που τοποθετείται στο **`PS4`** κάθε φορά που είναι ενεργοποιημένο το xtrace (π.χ. μέσω του κληρονομημένου **`SHELLOPTS=xtrace`**):

### Shell stdin command smuggling

Η εκκίνηση του `/bin/zsh -s` κάνει το shell να διαβάσει ένα πρόγραμμα από την τυπική είσοδο. Επομένως, αν ένα πρόγραμμα λήψης αντιγράψει ένα μη έμπιστο δομημένο έγγραφο στην τυπική είσοδο της θυγατρικής διεργασίας χωρίς να το αναλύσει πρώτα, μετατρέπει ολόκληρο το έγγραφο σε πηγαίο κώδικα shell. Ένας loader που παρατηρήθηκε διοχέτευε ένα δημόσιο αρχείο iCalendar μέσω ανώνυμου pipe, γραμμή προς γραμμή. Τα μεταδεδομένα του ημερολογίου απέτυχαν ως εντολές, αλλά το zsh συνέχισε μέχρι να φτάσει σε εκτελέσιμες γραμμές τοποθετημένες μετά το `DESCRIPTION:`. Αυτές οι γραμμές κατέβαζαν και εκκινούσαν το επόμενο application bundle. Ο αναμενόμενος τύπος περιεχομένου και η αξιόπιστη φιλοξενία του αρχείου δεν το καθιστούσαν ασφαλές· το επικίνδυνο σημείο ήταν η παράδοση των bytes του σε έναν interpreter.<sup>[[5]](#references)</sup>

Σχετικά στάδια καλύπτονται στις ενότητες [Mach-O overlays](../macos-files-folders-and-binaries/universal-binaries-and-mach-o-format.md), [Gatekeeper and quarantine](../macos-security-protections/macos-gatekeeper.md) και [macOS auto-start locations](../../macos-auto-start-locations.md).

### Python Injection

Η αλυσίδα standard library **`PYTHONWARNINGS`** και **`BROWSER`** μπορεί να εκτελέσει μια εντολή κατά την ανάλυση των φίλτρων προειδοποιήσεων. Μια εναλλακτική που βασίζεται σε αρχείο τοποθετεί το `sitecustomize.py` στο **`PYTHONPATH`**, ώστε η κανονική αρχικοποίηση του `site` να το εισαγάγει πριν από το script-στόχο. Το **`PYTHONBREAKPOINT`** εκτελεί ένα επιλεγμένο callable/module όταν ο κώδικας φτάσει στο `breakpoint()`. Μεταβλητές που αφορούν μόνο τη διαδραστική λειτουργία, όπως το **`PYTHONSTARTUP`**, έχουν πιο περιορισμένη εφαρμογή.

Σημειώστε ότι τα εκτελέσιμα αρχεία που έχουν μεταγλωττιστεί με το **`pyinstaller`** δεν χρησιμοποιούν αυτές τις μεταβλητές περιβάλλοντος, ακόμη κι αν εκτελούνται με ενσωματωμένο Python.

## Εντοπισμός

### Shield

Το [**Shield**](https://github.com/theevilbit/Shield) είναι μια εφαρμογή ανοιχτού κώδικα που βασίζεται στο **EndpointSecurity** και εντοπίζει και αποκλείει το process injection. Αποτελεί καλό σημείο αναφοράς για τα σήματα που είναι ορατά μέσω του Endpoint Security, καθώς ειδοποιεί για τα εξής:<sup>[[1]](#references)</sup><sup>[[2]](#references)</sup>

- **Μεταβλητές περιβάλλοντος για injection** κατά την εκτέλεση διεργασίας: `DYLD_INSERT_LIBRARIES`, `CFNETWORK_LIBRARY_PATH`, `RAWCAMERA_BUNDLE_PATH` και `ELECTRON_RUN_AS_NODE`.
- Κλήσεις **`task_for_pid`** — μία διεργασία ζητά το task port μιας άλλης, προϋπόθεση για την εισαγωγή κώδικα σε αυτήν.
- **Ορίσματα debugging του Electron** — `--inspect`, `--inspect-brk` και `--remote-debugging-port`, τα οποία εκκινούν μια εφαρμογή Electron σε λειτουργία debug και επιτρέπουν σε οποιονδήποτε να συνδεθεί και να εκτελέσει κώδικα σε αυτήν.<sup>[[3]](#references)</sup>
- **Δημιουργία symlink/hardlink μεταξύ διαφορετικών επιπέδων προνομίων** — η κλασική τεχνική «τοποθέτησε έναν σύνδεσμο ως κανονικός χρήστης και κατεύθυνέ τον σε μια προνομιούχα τοποθεσία». Σημειώστε ότι **τα symlink μπορούν να προκαλέσουν ειδοποίηση, αλλά όχι να αποκλειστούν**: το EndpointSecurity δεν παρέχει τον προορισμό του συνδέσμου πριν από τη δημιουργία του.

### Κλήσεις από άλλες διεργασίες

Στο [**αυτήν την ανάρτηση ιστολογίου**](https://knight.sc/reverse%20engineering/2019/04/15/detecting-task-modifications.html) μπορείτε να δείτε πώς είναι δυνατό να χρησιμοποιηθεί η συνάρτηση **`task_name_for_pid`** για να ληφθούν πληροφορίες σχετικά με άλλες **διεργασίες που εισάγουν κώδικα σε μια διεργασία** και στη συνέχεια να ληφθούν πληροφορίες για εκείνη την άλλη διεργασία.<sup>[[4]](#references)</sup>

Σημειώστε ότι για να καλέσετε αυτήν τη συνάρτηση πρέπει να έχετε **το ίδιο uid** με τη διεργασία ή να είστε **root** (και επιστρέφει πληροφορίες για τη διεργασία, όχι τρόπο εισαγωγής κώδικα).
