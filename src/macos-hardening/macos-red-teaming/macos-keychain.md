# macOS Keychain

{{#include ../../banners/hacktricks-training.md}}

## Основні Keychain

- **User Keychain** (`~/Library/Keychains/login.keychain-db`), який використовується для зберігання **облікових даних користувача**, як-от паролі застосунків, інтернет-паролі, сертифікати, створені користувачем, мережеві паролі та відкриті/закриті ключі, створені користувачем.
- **System Keychain** (`/Library/Keychains/System.keychain`), у якому зберігаються **загальносистемні облікові дані**, як-от паролі WiFi, системні кореневі сертифікати, системні закриті ключі та паролі системних застосунків.<sup>[1]</sup>
- Інші компоненти, як-от сертифікати, можна знайти в `/System/Library/Keychains/*`
- В **iOS** є лише один **Keychain**, розташований у `/private/var/Keychains/`. Ця папка також містить бази даних для `TrustStore`, центрів сертифікації (`caissuercache`) і записів OSCP (`ocspache`).
- Доступ застосунків у Keychain обмежений лише їхньою приватною областю на основі ідентифікатора застосунку.

### Доступ до Keychain за паролем

Ці файли, хоча й не мають вбудованого захисту та можуть бути **завантажені**, зашифровані й потребують **пароля користувача у відкритому вигляді для розшифрування**. Для розшифрування можна використати такий інструмент, як [**Chainbreaker**](https://github.com/n0fate/chainbreaker).<sup>[1]</sup>

## Захист записів Keychain

### ACL

Кожен запис у Keychain регулюється **списками контролю доступу (ACL)**, які визначають, хто може виконувати різні дії із записом Keychain, зокрема:<sup>[1]</sup>

- **ACLAuhtorizationExportClear**: дозволяє власнику отримати секрет у відкритому вигляді.
- **ACLAuhtorizationExportWrapped**: дозволяє власнику отримати секрет у відкритому вигляді, зашифрований за допомогою іншого наданого пароля.
- **ACLAuhtorizationAny**: дозволяє власнику виконувати будь-яку дію.

ACL також супроводжується **списком довірених застосунків**, які можуть виконувати ці дії без запиту. Це може бути:<sup>[1]</sup>

- **N`il`** (авторизація не потрібна, **довірені всі**)
- **Порожній** список (**ніхто** не має довіри)
- **Список** конкретних **застосунків**.

Запис також може містити ключ **`ACLAuthorizationPartitionID`,** який використовується для ідентифікації **teamid, apple** і **cdhash**.<sup>[1]</sup>

- Якщо вказано **teamid**, то для **доступу до значення запису** **без запиту** використаний застосунок повинен мати **такий самий teamid**.
- Якщо вказано **apple**, застосунок має бути **підписаний** **Apple**.
- Якщо вказано **cdhash**, **застосунок** повинен мати відповідний **cdhash**.

### Створення запису Keychain

Коли за допомогою **`Keychain Access.app`** створюється **новий** **запис**, застосовуються такі правила:<sup>[1]</sup>

- Усі застосунки можуть шифрувати.
- **Жоден застосунок** не може експортувати/розшифровувати (без запиту до користувача).
- Усі застосунки можуть бачити перевірку цілісності.
- Жоден застосунок не може змінювати ACL.
- **partitionID** встановлюється як **`apple`**.

Коли **застосунок створює запис у Keychain**, правила дещо відрізняються:<sup>[1]</sup>

- Усі застосунки можуть шифрувати.
- Лише **застосунок, який створив запис** (або будь-які інші застосунки, додані явно) може експортувати/розшифровувати (без запиту до користувача).
- Усі застосунки можуть бачити перевірку цілісності.
- Жоден застосунок не може змінювати ACL.
- **partitionID** встановлюється як **`teamid:[teamID here]`**.

## Доступ до Keychain

### `security`
```bash
# List keychains
security list-keychains

# Dump all metadata and decrypted secrets (a lot of pop-ups)
security dump-keychain -a -d

# Find generic password for the "Slack" account and print the secrets
security find-generic-password -a "Slack" -g

# Change the specified entrys PartitionID entry
security set-generic-password-parition-list -s "test service" -a "test acount" -S

# Dump specifically the user keychain
security dump-keychain ~/Library/Keychains/login.keychain-db
```
### APIs

> [!TIP]
> **Перерахування та dump** секретів із **keychain**, які **не генерують prompt**, можна виконати за допомогою інструмента [**LockSmith**](https://github.com/its-a-feature/LockSmith)
>
> Інші API endpoints можна знайти у вихідному коді [**SecKeyChain.h**](https://opensource.apple.com/source/libsecurity_keychain/libsecurity_keychain-55017/lib/SecKeychain.h.auto.html).

Перелічити та отримати **інформацію** про кожен запис у keychain можна за допомогою **Security Framework** або перевірити CLI-інструмент Apple з відкритим кодом [**security**](https://opensource.apple.com/source/Security/Security-59306.61.1/SecurityTool/macOS/security.c.auto.html)**.** Деякі приклади API:<sup>[1]</sup>

- API **`SecItemCopyMatching`** надає інформацію про кожен запис, і під час його використання можна встановити такі атрибути:
- **`kSecReturnData`**: Якщо true, буде виконано спробу розшифрувати дані (встановіть false, щоб уникнути потенційних pop-up)
- **`kSecReturnRef`**: Також отримати reference на елемент keychain (встановіть true, якщо пізніше ви побачите, що його можна розшифрувати без pop-up)
- **`kSecReturnAttributes`**: Отримати metadata про записи
- **`kSecMatchLimit`**: Кількість результатів для повернення
- **`kSecClass`**: Тип запису keychain

Отримати **ACL** кожного запису:<sup>[1]</sup>

- За допомогою API **`SecAccessCopyACLList`** можна отримати **ACL для елемента keychain**; він поверне список ACL (наприклад, `ACLAuhtorizationExportClear` та інші згадані раніше), де кожен список містить:
- Опис
- **Список довірених застосунків**. Це може бути:
- Застосунок: /Applications/Slack.app
- Бінарний файл: /usr/libexec/airportd
- Група: group://AirPort

Експортувати дані:<sup>[1]</sup>

- API **`SecKeychainItemCopyContent`** отримує дані у відкритому вигляді
- API **`SecItemExport`** експортує ключі та сертифікати, але для експорту зашифрованого вмісту може знадобитися встановити паролі

Існують такі **вимоги**, щоб мати змогу **експортувати секрет без prompt**:<sup>[1]</sup>

- Якщо перелічено **1+ довірених** застосунків:
- Потрібні відповідні **авторизації** (**`Nil`** або ви маєте бути **частиною** дозволеного списку застосунків в авторизації для доступу до конфіденційної інформації)
- Підпис коду має відповідати **PartitionID**
- Підпис коду має відповідати підпису одного **довіреного застосунку** (або ви маєте бути членом відповідної KeychainAccessGroup)
- Якщо **всі застосунки довірені**:
- Потрібні відповідні **авторизації**
- Підпис коду має відповідати **PartitionID**
- Якщо **PartitionID** відсутній, це не потрібно

> [!CAUTION]
> Тому, якщо перелічено **1 застосунок**, потрібно **інжектувати код у цей застосунок**.
>
> Якщо в **partitionID** вказано **apple**, до нього можна отримати доступ за допомогою **`osascript`**, тобто це стосується всього, що довіряє всім застосункам із apple у partitionID. Для цього також можна використати **`Python`**.

### Два додаткові атрибути

- **Invisible**: Булевий прапорець, який **приховує** запис від застосунку keychain<sup>[1]</sup>
- **General**: Використовується для зберігання **metadata** (тобто вони НЕ ЗАШИФРОВАНІ)<sup>[1]</sup>
- Microsoft зберігала у відкритому вигляді всі refresh tokens для доступу до конфіденційного endpoint.<sup>[1]</sup>
