# Зв'язка ключів macOS

{{#include ../../banners/hacktricks-training.md}}

## Основні зв'язки ключів

- **Зв'язка ключів користувача** (`~/Library/Keychains/login.keychain-db`), яка використовується для зберігання **облікових даних користувача**, як-от паролів застосунків, інтернет-паролів, сертифікатів, створених користувачем, мережевих паролів і відкритих/закритих ключів, створених користувачем.
- **Системна зв'язка ключів** (`/Library/Keychains/System.keychain`), у якій зберігаються **загальносистемні облікові дані**, як-от паролі Wi-Fi, системні кореневі сертифікати, системні закриті ключі та паролі системних застосунків.<sup>[[1]](#references)</sup>
  - Інші компоненти, як-от сертифікати, можна знайти в `/System/Library/Keychains/*`
- В **iOS** є лише одна **зв'язка ключів**, розташована в `/private/var/Keychains/`. Ця папка також містить бази даних `TrustStore`, центрів сертифікації (`caissuercache`) і записів OSCP (`ocspache`).
  - Доступ застосунків у зв'язці ключів обмежений їхньою приватною областю відповідно до ідентифікатора застосунку.

### Доступ до зв'язки ключів за паролем

Ці файли, хоч і не мають вбудованого захисту та можуть бути **завантажені**, зашифровані, і для їх розшифрування потрібен **пароль користувача у відкритому вигляді**. Для розшифрування можна скористатися таким інструментом, як [**Chainbreaker**](https://github.com/n0fate/chainbreaker).<sup>[[1]](#references)</sup>

## Захист записів зв'язки ключів

### ACL

Кожен запис у зв'язці ключів регулюється **списками керування доступом (ACL)**, які визначають, хто може виконувати різні дії із записом, зокрема:<sup>[[1]](#references)[[2]](#references)</sup>

- **`kSecACLAuthorizationExportClear`**: Дозволяє власнику отримати секрет у відкритому вигляді.
- **`kSecACLAuthorizationExportWrapped`**: Дозволяє власнику отримати секрет у відкритому вигляді, зашифрований іншим наданим паролем.
- **`kSecACLAuthorizationAny`**: Дозволяє власнику виконувати будь-які дії.

ACL також містять **список довірених застосунків**, які можуть виконувати ці дії без запиту підтвердження. Це може бути:<sup>[[1]](#references)</sup>

- **N`il`** (авторизація не потрібна, **довірені всі**)
- **Порожній** список (**нікому** не довірено)
- **Список** конкретних **застосунків**.

Запис також може містити ключ **`kSecACLAuthorizationPartitionID`,** який використовується для визначення **teamid, apple** і **cdhash**.<sup>[[1]](#references)[[2]](#references)</sup>

- Якщо вказано **teamid**, застосунок має мати **такий самий teamid**, щоб **отримати доступ до значення запису** **без** **запиту підтвердження**.
- Якщо вказано **apple**, застосунок має бути **підписаний** **Apple**.
- Якщо вказано **cdhash**, **застосунок** має мати відповідний **cdhash**.

### Створення запису у зв'язці ключів

Під час створення **нового** **запису** за допомогою **`Keychain Access.app`** діють такі правила:<sup>[[1]](#references)</sup>

- Усі застосунки можуть шифрувати.
- **Жоден застосунок** не може експортувати/розшифровувати дані (без запиту підтвердження користувача).
- Усі застосунки можуть бачити перевірку цілісності.
- Жоден застосунок не може змінювати ACL.
- Для **partitionID** встановлюється значення **`apple`**.

Коли **застосунок створює запис у зв'язці ключів**, правила дещо відрізняються:<sup>[[1]](#references)</sup>

- Усі застосунки можуть шифрувати.
- Лише **застосунок, що створив запис** (або будь-які інші застосунки, додані явно), може експортувати/розшифровувати дані (без запиту підтвердження користувача).
- Усі застосунки можуть бачити перевірку цілісності.
- Жоден застосунок не може змінювати ACL.
- Для **partitionID** встановлюється значення **`teamid:[teamID here]`**.

## Доступ до зв'язки ключів

### `security`

```bash
# List keychains
security list-keychains

# Dump all metadata and decrypted secrets (a lot of pop-ups)
security dump-keychain -a -d

# Find generic password for the "Slack" account and print the secrets
security find-generic-password -a "Slack" -g

# Change the specified entry's PartitionID value
security set-generic-password-partition-list \
  -s "test service" -a "test account" \
  -S 'apple-tool:,apple:,teamid:TEAMID' \
  -k 'KEYCHAIN_PASSWORD' ~/Library/Keychains/login.keychain-db

# Dump specifically the user keychain
security dump-keychain ~/Library/Keychains/login.keychain-db
```

`-S` задає список розділів для елемента, а `-k` передає поточний пароль Keychain, потрібний для внесення цієї зміни; прапорець для передавання пароля застарів.<sup>[[4]](#references)</sup> Успішне оновлення не гарантує, що наступне читання відбудеться без попередження: один спостережуваний вимкнений прототип усе одно викликав запит на підтвердження, коли він звертався до елемента через `Security.framework`. Відповідний ідентифікатор розділу — лише одна з умов ACL і перевірок довірених програм, описаних вище, тому перевірте фактичний шлях читання.<sup>[[3]](#references)</sup>

### APIs

> [!TIP]
> **Перелік елементів Keychain і дамп** секретів, які **не викликають запиту**, можна виконати за допомогою інструмента [**LockSmith**](https://github.com/its-a-feature/LockSmith)
>
> Інші кінцеві точки API можна знайти у вихідному коді [**SecKeyChain.h**](https://opensource.apple.com/source/libsecurity_keychain/libsecurity_keychain-55017/lib/SecKeychain.h.auto.html).

Перелічити й отримати **інформацію** про кожен запис у Keychain можна за допомогою **Security Framework** або перевірити інструмент командного рядка Apple з відкритим вихідним кодом [**security**](https://opensource.apple.com/source/Security/Security-59306.61.1/SecurityTool/macOS/security.c.auto.html)**.** Ось кілька прикладів API:<sup>[[1]](#references)</sup>

- API **`SecItemCopyMatching`** повертає інформацію про кожен запис; під час його використання можна задати такі атрибути:
  - **`kSecReturnData`**: якщо true, спробує розшифрувати дані (задайте false, щоб уникнути можливих спливних вікон)
  - **`kSecReturnRef`**: також отримати посилання на елемент Keychain (задайте true, якщо згодом виявиться, що елемент можна розшифрувати без спливного вікна)
  - **`kSecReturnAttributes`**: отримати метадані записів
  - **`kSecMatchLimit`**: кількість результатів, які потрібно повернути
  - **`kSecClass`**: тип запису Keychain

Отримати **ACL** кожного запису:<sup>[[1]](#references)</sup>

- За допомогою API **`SecAccessCopyACLList`** можна отримати **ACL елемента Keychain**. Він повертає список ACL (наприклад, `kSecACLAuthorizationExportClear` та інші згадані раніше), де кожен запис містить:<sup>[[1]](#references)[[2]](#references)</sup>
  - Опис
  - **Список довірених програм**. Це може бути:
    - Програма: /Applications/Slack.app
    - Бінарний файл: /usr/libexec/airportd
    - Група: group://AirPort

Експортувати дані:<sup>[[1]](#references)</sup>

- API **`SecKeychainItemCopyContent`** отримує відкритий текст
- API **`SecItemExport`** експортує ключі та сертифікати, але для експорту зашифрованого вмісту може знадобитися задати паролі

А ось **вимоги**, які потрібно виконати, щоб **експортувати секрет без запиту**:<sup>[[1]](#references)</sup>

- Якщо вказано одну або більше **довірених** програм:
  - Потрібні відповідні **авторизації** (**`Nil`** або входження до **списку дозволених програм** в авторизації на доступ до інформації про секрет)
  - Підпис коду має відповідати **PartitionID**
  - Підпис коду має відповідати підпису однієї з **довірених програм** (або програма має бути учасником відповідної KeychainAccessGroup)
- Якщо довірені **всі програми**:
  - Потрібні відповідні **авторизації**
  - Підпис коду має відповідати **PartitionID**
    - Якщо **PartitionID** відсутній, ця умова не потрібна

> [!CAUTION]
> Тому, якщо **вказано одну програму**, потрібно **впровадити код у цю програму**.
>
> Якщо в **partitionID** зазначено **apple**, можна отримати доступ за допомогою **`osascript`** до будь-якого елемента, який довіряє всім програмам і містить apple у partitionID. Для цього також можна використати **`Python`**.

### Два додаткові атрибути

- **Невидимий**: булевий прапорець, що **приховує** запис у програмі Keychain з **UI**<sup>[[1]](#references)</sup>
- **Загальний**: використовується для зберігання **метаданих** (отже, вони НЕ ЗАШИФРОВАНІ)<sup>[[1]](#references)</sup>
  - Microsoft зберігала у відкритому тексті всі refresh-токени для доступу до чутливої кінцевої точки.<sup>[[1]](#references)</sup>
